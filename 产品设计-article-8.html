讲讲 UI 设计师必不可少的产品思维。

5/26/2026, 2:34:00 PM

📌 一句话摘要

本文通过一个徒步 App 的改版案例，深入浅出地解释了 UI 设计师应具备的产品思维，即通过规划产品形式（而非仅视觉调整）来解决产品问题的思考模式。

📝 详细摘要

文章首先定义了产品思维的核心：通过规划产品形式来解决产品问题，并区分了「技术方案」（如视觉优化）和「产品方案」（如调整功能与信息结构）。作者指出，在真实项目中，设计师不能仅依赖产品经理，而应主动运用产品思维，在力所能及的范围内解决体验、交互等问题，以提高项目效率和质量。随后，文章以「两步路」App 的路线详情页改版为例，详细展示了产品思维的应用过程。作者分析了顶部大图区域存在的多个问题（如浏览效率低、图片质量参差不齐、信息层级混乱），并指出仅靠视觉调整无法解决。因此，他提出了产品层面的改动：缩小图片尺寸、改为左右滑动列表、整合用户信息与操作按钮，并进一步构想引入路线生成图等更多图片类型，以丰富信息展示。文章强调，产品方案需要逻辑清晰、有理有据，才能说服团队通过。最终，作者总结道，产品思维是 UI 设计师从「只做视觉」到「提供方案并说服他人」的关键能力。

💡 主要观点

  1. 产品思维的核心是「通过规划产品形式来解决产品问题」，而非仅依赖视觉或技术方案。 产品问题涵盖功能、交互、体验、技术等多个领域。解决方式分为技术方案（如视觉优化）和产品方案（如调整功能与信息结构），后者往往能更根本地解决问题并降低成本。
  2. UI 设计师需要主动运用产品思维，填补产品经理的空白，提升项目效率和质量。 在真实项目中，产品经理无法处理所有与体验、交互相关的问题。设计师若能自主提出合理的产品方案，不仅能提高产品质量，还能在视觉要求不高的环境中凸显自身价值。
  3. 产品方案需要基于深入的问题分析，并具备逻辑性，才能有效说服团队。 方案不能仅停留在视觉效果，而应从问题分析出发，阐述如何通过产品层面的调整来解决问题。逻辑清晰是方案被采纳的关键，也是设计师在作品集和面试中需要展现的能力。

💬 文章金句

  • 产品思维一句话总结，就是——通过规划产品形式来解决产品问题的思考模式。
  • 设计师需要在自己力所能及的范围里，尽量自己去解决这些问题，提高项目整体运转的效率和质量。
  • 产品方案不是你们想怎么输出就怎么输出，这些方案还需要再后续经过团队的评审...即不希望 UI 设计师只做视觉还需要提供一定的产品方案，且出完产品方案还需要有理有据地说服他们！
