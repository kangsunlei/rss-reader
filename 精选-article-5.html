【第 3579 期】OODA 循环与 Git Worktrees：来自 AI 辅助开发的九个启示

9/1/2025, 12:03:00 AM

📌 一句话摘要

文章探讨了 AI 辅助开发中过度提供上下文导致效率低下的“喂养野兽”问题，并提出了基于 OODA 循环、探索-规划-执行流程及 Git Worktrees 等实践来高效驾驭 AI。

📝 详细摘要

本文深入剖析了 AI 辅助开发中一个常见但被忽视的问题：过度提供上下文（即“喂养野兽”）反而导致 AI 生成复杂、冗余甚至错误的产出。作者通过个人经历指出，向 AI 灌输过多信息并非最优解，反而会放大“幻觉”并降低开发效率。文章引入了约翰·博伊德上校的 OODA 循环（观察-定位-决策-行动）理论，强调在 AI 光速运行下，开发者需扮演闭合决策回路的关键角色。作者提出了“探索 → 规划 → 执行”的工作流，主张在编码前先让 AI 探索、规划，然后小步快跑地执行，以对抗“一次性提示”的赌徒心态。文章还分享了九个惨痛教训，涵盖上下文窗口管理、智能体专精化、并行开发（利用 Git Worktrees）和主智能体指挥而非执行的理念。最终，文章将开发者角色从“流水线厨师”提升为“主厨”，倡导智能地喂养 AI，而非无止境地堆砌信息，并提供了具体的行动建议。

💡 主要观点

  1. 过度提供上下文给 AI 会导致其过度复杂化和“幻觉”，降低开发效率。 AI 在接收过多信息时，倾向于构建其认为“应该”的复杂系统，而非用户实际所需，每次新增上下文都可能引入“创造性误读”。
  2. 采用“探索 → 规划 → 执行”流程和 OODA 循环能有效驾驭 AI，实现高效迭代。 通过引导 AI 先探索问题、再进行细致规划，最后小步执行并频繁验证，可避免“一次性提示”的弊端，确保 AI 产出与目标一致。
  3. 智能体应专精于特定任务，并通过 Git Worktrees 等工具实现并行与隔离。 将宽泛指令拆解为具体任务，分配给专精智能体，并通过 Git Worktrees 隔离工作环境，可减少冲突，提高效率和代码质量。
