如何让 Agent 更符合预期？基于上下文工程和多智能体构建云小二 Aivis 的十大实战经验

10/31/2025, 12:31:00 AM

📌 一句话摘要

文章基于阿里云云小二 Aivis 项目实践，总结了通过上下文工程和多智能体架构优化 Agent 表现的十大实战经验。

📝 详细摘要

文章深入探讨了如何构建和调优高性能 Agent 的复杂课题，特别聚焦于上下文工程和多智能体架构的优化实践。作者结合阿里云“云小二 Aivis”项目的真实踩坑经验，总结了十大关键实战建议，旨在解决 Agent 常见的运行不稳定、产生幻觉、不按预期输出等问题。核心经验包括清晰化预期、精准投喂上下文、明确身份和历史执行、结构化表达逻辑、自定义工具协议、合理使用 Few-Shot、保持上下文“苗条”、记忆管理、Multi-Agent 平衡可控性与灵活性，以及坚持人在回路（HITL）的重要性。文章提供了具体案例和解决方案，为 Agent 开发者提供了宝贵的实践指导。

💡 主要观点

  1. 清晰化预期是 Agent 优化的基石，需将模糊需求转化为具体、可衡量的标准。 通过明确任务要求、输出格式和风格语气，消除大模型对指令的困惑和歧义，确保其按预期执行，从而提升 Agent 的稳定性。
  2. 上下文精准投喂与“瘦身”是提升 Agent 效果的关键策略，强调“给其所需，去其所扰”。 确保只提供模型所需的相关信息，剔除不相关的干扰内容，并尽可能压缩上下文长度，以提高模型对指令的遵循度和稳定性。
  3. 身份和历史执行清晰化对 Agent 的准确性和稳定性至关重要，避免角色混淆和信息丢失。 明确区分对话中的多方角色，并完整保留大模型自身的动作历史，防止模型因学习历史对话而产生幻觉或行为错乱，确保模型对自身行为有清晰认知。
  4. 善用结构化形式表达复杂逻辑能显著提高大模型对指令的理解和遵循能力。 相比纯自然语言，使用 JSON、YAML、伪代码或 Markdown 等结构化语言向模型传递复杂的业务逻辑或流程，能更有效地消除歧义，提升 Agent 的执行准确性。
  5. 尝试自定义工具协议在特定领域任务中，可能比通用标准协议更具准确性和稳定性。 针对领域独特需求，自定义包含特定要求和提示词指令的工具调用协议，可以有效避免模型因通用训练语料影响而无法完全遵循指令的问题。
  6. 记忆管理对于 Agent 保持长期一致性和个性化体验至关重要。 采用多次增强提示、上下文压缩和外部记忆存储等策略，避免模型遗忘关键信息，使其在多轮对话中更具“记性”和上下文感知能力。
  7. Multi-Agent 架构是平衡 Agent 可控性与灵活性的有效手段，而人在回路（HITL）则是持续优化和构建优秀 Agent 的根本保障。 Multi-Agent 架构通过主 Agent 调度决策与子 Agent 执行诊断相结合，实现复杂任务的高效处理；同时，坚持人在回路，深入理解人类行为并持续根据反馈迭代优化，确保 Agent 能够真实模拟人类思考和解决问题。

💬 文章金句

  • "提示词工程"的重点在于"工程"两个字，也就是说在实际生产和应用的过程中，并不是像我们做测试或实验 Demo 一样，针对一个任务要求写一段提示词，模型去完成一个单次调用的任务即可。
  • 核心原则："给其所需，去其所扰"。模型需要且关心的信息，一定要给到；模型不需要且不相关的干扰信息，一定要想办法剔除。
  • Manus 的经验里也提到过一个原则"Mask， Don't Remove"，比如在工具调用的时候，如果当先前的动作和观察仍然引用当前上下文中不再定义的工具时，模型会感到困惑；以及"Keep the Wrong Stuff In"，也就是"擦除失败会移除证据"。
  • 虽然现在的大模型都号称支持百万甚至千万级 Token 上下文，但实际测试会发现，当上下文长度超过一定长度（例如 1 万 Token 以上），模型对历史信息的遗忘率会显著增加。
  • 只有坚持人在回路（HITL），深入业务场景中，才能做出好的 Agent。
