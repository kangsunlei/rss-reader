LangChain 和 LangGraph 1.0 版本发布

10/22/2025, 2:57:36 PM

📌 一句话摘要

LangChain 和 LangGraph 1.0 融合了易用性和生产级智能体能力，通过引入中间件和标准化模型输出，为构建可靠的 AI 应用提供清晰的指导。

📝 详细摘要

本文是与 LangChain 的 CEO 和核心工程师进行的一次技术讨论，深入探讨了 LangChain 和 LangGraph 的 1.0 版本。它追溯了 LangChain 从简单的原型设计到稳健的、可用于生产的智能体框架的演变。LangGraph 的开发源于对更强可控性和持久运行时的需求，这对于需要持久执行和流式传输等功能的长期运行 AI 智能体至关重要。LangChain 1.0 现在利用 LangGraph 的底层运行时，提供了一个更简单的 `create_agent` 抽象，以便更容易采用，同时保留了高级的生产能力。一项重要的创新是新的中间件系统，使开发人员能够在智能体的执行循环中的任何点注入自定义逻辑，例如动态模型选择、聊天历史的总结或人工干预。讨论还通过“内容块”标准化了模型输出，解决了模型输出格式不统一的问题，从而简化了多模型应用程序的开发。该团队提供了明确的指导，说明何时选择 LangChain（用于简单的智能体循环）与 LangGraph（用于结合确定性和智能体组件的复杂、高度可定制的工作流），并强调了 LangGraph 的可组合性。未来的计划包括促进社区驱动的中间件开发，并探索智能体应用程序的 UX/UI。

💡 主要观点

  1. LangChain 1.0 融合了易用性和 LangGraph 的生产就绪特性，旨在帮助开发者构建强大的 AI 智能体。 通过在 LangGraph 上重建 LangChain，1.0 版本提供了一个更简单的 `create_agent` 抽象，同时继承了持久执行、流式传输和人工参与功能，这些对于生产 AI 应用程序至关重要。
  2. 新的中间件系统为智能体行为提供了广泛的定制性，从而满足了复杂的生产需求。 中间件允许开发人员在智能体的执行循环中的任何节点注入自定义逻辑（例如，动态模型选择、总结、人工批准），从而显著增强了对各种用例的控制和适应性。
  3. 内容块标准化了不同 LLM 提供商的模型输出，从而简化了多模型应用程序的开发。 这种标准化解决了各种 LLM 如何表示多模态和工具调用输出的碎片化问题，使开发人员可以更轻松地切换模型而不会破坏其应用程序，并确保一致性。
  4. 提供了明确的指南，用于在 LangChain（简单智能体循环）和 LangGraph（复杂、可定制的工作流）之间进行选择。 建议使用 LangChain 开始使用智能体循环，因为它很简单，而 LangGraph 则非常适合高度定制、可组合的工作流，这些工作流结合了确定性和智能体组件以用于高级方案。
