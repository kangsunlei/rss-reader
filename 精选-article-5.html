充分利用 Copilot 代码审查：指令文件编写指南

11/14/2025, 9:00:00 AM

📌 一句话摘要

本指南旨在帮助开发者通过优化自定义指令文件，更好地控制 GitHub Copilot 代码审查的行为。

📝 详细摘要

本文为开发者提供全面的指南，旨在帮助他们掌握 GitHub Copilot 代码审查 (CCR) 的自定义指令文件（`copilot-instructions.md` 和 `*.instructions.md`）。文章解答了用户常见的疑问，例如指令何时被读取、为何有时不被遵循，以及如何确保 Copilot 遵循指导。本文提供实用技巧，强调简洁性、使用标题和项目符号的结构化格式、直接的命令式规则以及代码示例。文章阐明了仓库范围与路径特定指令文件的不同用途，并提供了有效应用策略。此外，还概述了应避免的陷阱，如尝试修改 Copilot 的 UI/UX、请求代码审查范围外的任务、包含外部链接或使用模糊指令。文章提供了一个推荐的、可复制粘贴的指令文件结构，以及一个演示这些指南的 TypeScript 示例。最后，文章还指导用户如何开始使用 CCR，以及如何利用 Copilot 编程助手生成和编辑自定义指令文件，从而简化使用流程。

💡 主要观点

  1. 定制代码审查：使用指令文件 通过使用 `copilot-instructions.md` 为仓库范围的标准提供精确指导，以及使用路径特定的 `*.instructions.md` 文件指导特定语言或主题的规则，GitHub Copilot 代码审查的行为可以得到精确控制，从而确保始终遵守团队标准并提高自动化审查的质量。
  2. 优化指令：清晰、结构化 为了使 Copilot 更好地理解和应用指令，指令应简洁、直接，并使用标题和项目符号进行良好组织。包含具体的代码示例可以显著提高清晰度，因为模糊或过长的指令可能导致不一致的行为。
  3. 了解并避免不支持的指令类型 应避免某些请求，例如更改 Copilot 的 UI/UX、修改“Pull Request 概览”、要求 Copilot 执行非代码审查任务、包含外部链接或使用通用的“更准确”指令，以防止混淆并确保有效指导。
  4. 推荐结构与示例：快速上手 本文提供了一个即用型 Markdown 模板，用于指令文件，包含目的、命名约定、代码风格、错误处理和测试等部分，以及一个详细的 TypeScript 示例，方便团队轻松采纳最佳实践并提高一致性。
  5. 利用 Copilot 编程助手进行指令文件管理 Copilot 编程助手可以帮助生成或修改指令文件，应用最佳实践，移除不支持的内容，并重新格式化以提高清晰度，从而简化自定义指令的设置和维护过程。

💬 文章金句

  • 力求简洁：Copilot 在处理重点突出、简短的指令时效果最佳。从小处着手并迭代。
  • 表达清晰：简短的命令式规则比长段落更有效。
  • 提供示例：使用示例代码或解释来演示概念，就像你与队友一样。
  • 将不同的主题（例如，安全性、特定于语言的指南等）组织到单独的 `*.instructions.md` 文件中。
