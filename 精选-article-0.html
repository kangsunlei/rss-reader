📝 详细摘要

本文深度解析了 Anthropic 内部被誉为“Claude Code 之父”的 Boris Cherny 使用 Claude Code 的 9 条实战技巧。不同于普遍认为的复杂配置，Boris 的方法强调“朴实无华”和高效工作流。核心观点包括：没有放之四海而皆准的最佳实践，应根据需求调整；通过多实例并行处理任务，提升并发效率；坚持使用 Opus 模型以保证质量和综合效率；利用 CLAUDE.md 在团队内共享项目知识和纠错经验，形成“复利工程”；重视 Plan 模式，先规划后执行以减少返工；通过斜杠命令和子 Agent 自动化重复工作；严格配置权限并集成外部工具以扩展能力；针对长任务提供自主验证机制使其无需人工干预；最重要的，是赋予 Claude 验证自身工作的能力，以形成反馈闭环，显著提升产出质量。文章指出，理解这些功能背后的逻辑并将其组合成高效工作流，远比追求复杂配置更有价值。

💡 主要观点

  1. 没有唯一的“最佳实践”，重要的是找到适合自身节奏和团队需求的方法。 Claude Code 团队故意设计其为高度可定制化，鼓励用户探索适合自己的开发模式，不应盲目追求他人所谓的“最佳实践”。
  2. 通过多实例并行处理任务，充分利用 Claude Code 的自主执行能力。 Boris 通过在终端和网页同时运行多个 Claude Code 实例，并利用工具在它们之间切换任务，实现“多线程”工作，将 AI 作为可自主运行的 Agent，而非传统的“人敲一行、AI 补几行”模式。
  3. 优先选择质量更高的 Opus 模型，以提升整体效率并减少纠正成本。 尽管 Opus 模型单次响应可能较慢，但其更高的准确性和更少的纠错需求，最终能节省大量人工精力和时间，将焦点从速度转向最终产出的质量。
  4. 利用 CLAUDE.md 作为团队共享的项目记忆，实现“复利工程”。 通过将 CLAUDE.md 放在项目根目录并提交到 Git，团队可以集体维护和更新项目规范、注意事项及纠错经验，让 AI 持续学习并适应团队工作方式，优化协作效率。
  5. 在开始编码前，先通过 Plan 模式与 Claude 充分讨论和规划执行方案。 采纳“先设计再编码”的经典软件开发智慧，利用 Claude Code 的 Plan 模式先行确定执行计划，避免因方向错误导致的高昂返工成本，确保 AI 的工作方向与预期一致。
  6. 最重要的技巧是赋予 Claude 验证自身工作的能力，形成反馈闭环。 类似于人类工程师的“写代码-测试-修改”循环，让 AI 能够自主验证产出（如运行测试套件、模拟浏览器交互），是提升其最终工作质量和准确性的最关键因素，投资于验证机制将获得高回报。

💬 文章金句

  • My setup might be surprisingly vanilla! Claude Code works great out of the box， so I personally don't customize it much. 我的配置可能出乎你意料地"原装"。Claude Code 开箱即用效果就很好，我个人没做太多定制。
  • 但你也对使用者有更高的要求，你需要擅长给 Agent 分配任务，并且能随时在多个任务之间切换。
  • Boris 的回答是：虽然单次响应慢一点，但你需要纠正它的次数少得多，工具调用也更准确，最终算下来反而更快。
  • 每一次纠错都变成团队资产，让 AI 越来越懂你们的项目。
  • 如果 Claude 能验证自己的工作，最终产出质量能提升 2 到 3 倍。
