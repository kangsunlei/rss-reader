从榜单走向真实业务负载：Kernel Agent 刷新 Qwen3.8-Max 核心推理算子性能

9/28/2026, 10:54:00 AM

📌 一句话摘要

阿里开源 Atrex Kernel Agent (AKA)，在 Qwen3.8-Max 真实生产负载上实现 GPU 算子性能超越专家手工优化，最高加速 1.55×，标志着 AI 驱动的系统级性能工程从 Benchmark 走向生产交付。

📝 详细摘要

本文介绍了阿里巴巴 TRE AI 系统工程团队研发的 Atrex Kernel Agent (AKA)。针对现有 Kernel Agent 仅在公开 Benchmark 验证、难以直接替换生产环境高性能实现的痛点，AKA 构建了包含编码 Agent、性能 Profiling、GPU 评测与正确性门禁的持续优化闭环。文章详细展示了 AKA 在 Qwen3.8-Max 的 FlashAttention-4 和 Gated DeltaNet 三条关键算子线上的实测结果：在 60 个真实业务 Shape 上，AKA 生成的 Kernel 几何平均时延均低于专家手工版本，相对生产基线最高加速 1.55×。通过 FA4 prefill 的持久化调度重构、decode 的原生 page128 适配以及 GDN 的自主流水设计三个案例，揭示了 AKA 不仅优化代码，更搜索接口边界和结构假设的能力。此外，文章还探讨了 Harness 自进化机制，即利用历史优化轨迹改进 Agent 自身的提示词和策略，进一步降低 Token 成本并提升搜索效率。目前相关算子库和 Agent 框架已开源。

💡 主要观点

  1. Kernel Agent 的验证标准正从公开 Benchmark 转向真实生产负载 Benchmark 通常仅覆盖有限 Shape 和简单接口，而生产环境要求处理复杂 Shape 分布、混合精度及严格的上下游协议。AKA 通过在 Qwen3.8-Max 真实业务负载上的测试，证明了其能生成可直接替换现有高性能实现的 Kernel，解决了从‘会做题’到‘能交付’的工程鸿沟。
  2. AKA 通过联合重构调度、数据搬运和流水设计，性能超越专家手工优化 在 FA4 prefill 中引入 persistent grid 摊薄开销；在 decode 中原生适配 page128 并对 q_len=4 MTP 专项调度；在 GDN 中独立发现新的标量-TMA warp 流水设计。实验数据显示，在三条关键算子线的 60 个 Shape 上，AKA 的几何平均时延均低于专家版本，最高加速比达 1.55×。
  3. 系统架构强调“结构搜索”与“工程验证闭环”的结合 AKA 不仅仅是一个代码生成器，而是一个包含 Plan（结构推演）、Agent（编码）、Agate（隔离执行与评测）、Profiler（细粒度反馈）和 Supervisor（门禁与回退）的完整系统。这种设计确保了候选 Kernel 必须经过数值正确性硬门和完整 Workload 复测才能晋级，保证了生产环境的稳定性。
  4. Harness 自进化机制显著提升了优化效率 AKA 开始将进化对象扩展到承载优化流程的 Harness 本身。通过汇总历史优化轨迹，提炼高价值上下文和有效操作序列来改进提示词和预算分配。实验表明，进化后的 Harness 能以更少的 Token 成本和更短的轮次越过专家性能线，实现了“优化寻找算子的流程”。

💬 文章金句

  • 在 60 个真实 shape 上，AKA 三条关键算子线的平均时延均低于专家版本；较生产/官方基线最高加速 1.55×。
  • 专家优化"这个接口下怎么最快"，AKA 进一步搜索"这个接口本身该长什么样"。
  • NCU 回答"哪里慢"，细粒度 profiler 可以进一步回答"哪个 warp 在什么同步点等待"。
  • AKA 不只优化算子，也开始优化寻找算子的流程。
