#716.Stripe：企业 AI 的关键是治理

9/10/2026, 6:38:39 PM

📌 一句话摘要

Stripe 工程经理 Sharadh 拆解公司级 Agent Kai 的构建逻辑：企业 AI 的难点不是提供工具而是治理，靠 Project 划定权限与成本边界、靠 skill 平台把一次性对话变成可复用工作流，不到 10 人团队服务超 1 万名员工。

📝 详细摘要

本期 How I AI 由主持人 Claire Vo 对话 Stripe 工程经理 Sharadh，拆解内部公司级 Agent Kai 的构建与治理实践。Kai 不是聊天工具，而是一套结合个性化上下文、组织架构、数据平台、沙盒、skill 与治理机制的企业级 AI 系统，每周有超 1 万名 Stripe 员工使用，采用率超过 86%。Sharadh 强调，Stripe 最初面对的不是「要不要给员工 AI 工具」，而是如何让复杂组织中的每个人都能放心使用：重点在于提供正确的治理结构，让人确信 AI 会把事情办对。上下文层面，Kai 开箱即知员工身份与组织位置，可通过项目管理系统读取 OKR、邮件与项目，Google Drive、Slack、私信等敏感内容则由员工自行授权开关。治理核心是 Project：它既是上下文引擎，也是配置与治理层，可指定默认模型、工具策略、数据访问权限与 human in the loop 审批流程，让少数懂成本与延迟权衡的人搭好台子，其余员工在边界内使用。数据路径上，Kai 通过 ask data skill 做三层分流：优先分析层，其次标准仪表盘查询，最后退到数据目录自写查询；Hubble、Trino 与分析层等面向人类建设的基础设施成为 Agent 的杠杆，Sharadh 因此建议企业把 devex 与数据团队人数翻倍。Sharadh 也坦言 Agent 会放大所有故障模式，需要加固高并发韧性、界定 Agent 身份与降级机制。skill 层面，Kai 可把一次会话打包成可复用、可编辑、可测试、可共享的工作流，公司已有约 2000 个 skill，并通过遥测与 ETL 管道判断推广、降级、归档或删除，因为无关上下文越多结果越差，数量几乎就是质量的侧面。该项目以约一个半人力两周上线 V0，经 GTM 试点后全公司推广，核心团队至今不到 10 人。

💡 主要观点

  1. 企业 AI 的第一性问题不是提供工具，而是提供正确的治理结构。 Stripe 面对的是如何在业务遍布全球、流程繁多的复杂组织里让每个人放心用 AI。Kai 的价值在于把权限、上下文、模型、工具和审批机制组织起来，让员工不必每天自行处理复杂配置，同时确信 AI 会把事情办对。
  2. Project 不是文件夹，而是可配置的治理单元与上下文引擎。 Project 可围绕团队或工作流划定上下文边界，并规定默认模型、工具策略、数据访问权限和 human in the loop 流程。少数熟悉成本、性能与延迟权衡的人提前搭好规则，其他人直接在边界内使用，从而降低管理成本与阻力。
  3. 面向人类建设的平台投入，最终成为 Agent 发挥作用的杠杆。 Stripe 在 AI 之前持续建设开发者体验、开发者平台、数据平台与分析层。ask data skill 按分析层、标准仪表盘、数据目录三层分流查询，Agent 因此能快速找到正确数据；Sharadh 由此建议企业把 devex 和数据团队人数翻倍，而不是只盯着模型和产品开发。
  4. Agent 会成倍放大基础设施的故障模式，韧性与身份界定是前提。 Agent 能高并发地调用工具、查询数据、执行操作，原本不明显的问题会被迅速放大。Stripe 因此投入数据仓库高并发弹性、界定 Agent 身份与用例、设计优先级与降级机制，并承认早期曾出现 Agent 失控甚至差点搞垮核心系统的情况。
  5. skill 把一次性对话变成可复用工作流，但企业级 skill 库必须同时管理质量和数量。 Kai 可从一次完整会话中提取步骤、上下文和操作，打包成可编辑、测试、共享和治理的 skill，使 AI 从聊天工具变成可交付工作流的协作者。公司约有 2000 个 skill，需要通过遥测和 ETL 管道判断哪些该推广、降级、归档或删除，因为塞给 AI 的无关上下文越多，结果越差。

💬 文章金句

  • 重点不是提供 AI 而是提供正确的治理结构，让每个人都能直接去用 AI 而且确信他会帮你把事情办对。
  • 项目首先是一种治理机制，但他也能让你就像你说的，你有了这个上下文引擎。
  • 事实证明，Agent 会直接放大你所有的故障模式，就好像它把你可能遇到的问题幅度给成倍放大了。
  • 把精力花在平台投入上，对人类好，对 agent 也好，这才是能让你跑起来的东西。
  • 你塞给 AI 的无关上下文越多，你的结果就会变得越差。所以数量几乎就是质量的一个侧面。
