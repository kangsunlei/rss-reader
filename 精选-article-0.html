#714.Tibo 谈 Codex：harness 总比模型快一步

9/9/2026, 6:25:08 PM

📌 一句话摘要

OpenAI 的 Tibo Sottiaux 详述 Codex 从内部研究项目走向产品的过程：核心用 Rust 编写并全面开源、不绑定自家模型，强调 harness 比模型领先一步并逐渐变薄，以及 AI 正在把 code review 从语法检查推向意图讨论、让代码维护和重构成本大幅下降。

📝 详细摘要

本期 The Pragmatic Engineer 对话 OpenAI Core Products & Platform 负责人 Tibo Sottiaux，他回顾了自己从比利时乡村、应用数学、创业（医药供应链优化）到谷歌、DeepMind，再到 OpenAI 的职业轨迹，并重点拆解 Codex 的诞生与演进。Tibo 解释了为何用 Rust 而非 TypeScript 编写 Agent 核心——不只是性能，更是正确性、安全性与可扩展性，并强调将 Agent 与产品界面清晰隔离的重要性。Codex 全面开源 CLI、SDK 和应用服务器，是为了身处代码 Agent 社区、获得外部贡献并共同探索优秀 harness 的形态；同时 Codex 刻意不绑定 OpenAI 模型，希望靠真本事而非绑定去赢得用户。Tibo 提出“harness 总比模型领先一步”的观点：harness 通过护栏、工具、developer message 让模型能力更可靠，随着模型变强 harness 与 developer message 会变薄。他也谈到 AI 对软件工程的深刻影响：code review 正从正确性检查转向意图与设计讨论，正确性、安全性、复杂依赖检查可由 Agent 自动完成；依赖升级、安全补丁和架构重构的维护成本大幅下降，但良好的抽象与边界仍决定系统能否快速变化；软件生命周期被压缩，一个周末 100 个 Agent 就可能同时为系统贡献代码，团队需更早考虑协作与架构。最后他建议工程师保持对事物运作方式的好奇心、训练快速理解能力，并与社区同频。

💡 主要观点

  1. Codex 选用 Rust 并非为性能，而是为了 Agent 核心的正确性、安全性与可扩展性。 Tibo 认为把 Agent 与产品解耦、让 Agent 核心独立存在是关键原则。Rust 的编译期静态校验等特性很适合 Agent，也有助于避免与产品界面过度耦合从而阻碍后续创新。
  2. Codex 全面开源是为了进入代码 Agent 社区，而非单纯获取贡献。 开源使新成员入职几乎零门槛（之前已看过仓库）、能直接获得社区优秀贡献；但也有代价：跨仓库维护、别人抢先抄走、处理杂乱贡献。团队认为这些成本值得，因为开源本身会改变代码的作用。
  3. Codex 不绑定 OpenAI 模型，目的是靠产品实力而非捆绑赢得市场。 支持多模型供应商既降低用户尝试新模型的迁移成本，也迫使团队同时在模型、harness 和产品体验上保持竞争力。Tibo 强调“我喜欢靠真本事去赢，而不是靠绑定去赢”。
  4. Harness 总是比模型领先一步，但随着模型变强会逐渐变薄。 harness 通过护栏、工具、developer message 让模型已有的能力更可靠、高效、符合预期。早期需提醒模型跑测试，后来模型能自动做；未来 developer message 会更小，harness 所承担的引导逻辑会减少。
  5. AI 正将 code review 从正确性检查推向意图与设计讨论。 正确性、安全性和复杂依赖检查越来越可由 Agent 自动完成（OpenAI 所有 PR 都需过安全拦截）。人类更应聚焦讨论功能是否值得做、架构意图与系统不变式，而且这种讨论可以脱离 PR 进行。
