InfoQ 2025 年 Java 趋势报告

12/11/2025, 9:00:00 AM

📌 一句话摘要

这份 InfoQ 报告总结了 2025 年 Java 生态系统的主要趋势，着重介绍了 JVM 上 AI 采用的加速、Java 25 作为现代基线的确立、激增的现代化工作以及企业级 Java 的持续进步和云部署策略的转变。

📝 详细摘要

这份 InfoQ 报告全面概述了 2025 年 Java 生态系统内新兴趋势和技术采用情况。主要关注领域包括由 Embabel、Koog、Spring AI 和 LangChain4j 等新框架推动的 JVM 上 AI 应用的快速发展。Java 25 被确定为新的长期支持 (LTS) 版本，它通过提高可读性、并发性和性能，促使框架以 Java 17+ 为标准。报告还指出遗留 Java 应用现代化是一个显著趋势，OpenRewrite 成为升级的主要自动化工具。企业级 Java 随着 Jakarta EE 11 的稳定和 Jakarta EE 12（特别是 Jakarta Query）的早期工作而持续进步。最后，讨论了社区参与和企业部署策略向混合或本地部署解决方案的转变。本报告旨在指导技术负责人进行投资决策和开发者进行技能开发。

💡 主要观点

  1. JVM 上 AI 的采用正在迅速加速，由新框架以及对可靠、可扩展 AI 应用的需求驱动。 Embabel、Koog、Spring AI 和 LangChain4j 等新框架使 Java 开发者能够构建和运行 AI 代理，凭借 Java 强大的类型系统和成熟的生态系统，满足了对健壮、业务关键型 AI 解决方案的需求。
  2. Java 25 确立了新的现代基线，具有语言改进和广泛的框架普及。 Java 25 作为最新的 LTS 版本，通过紧凑源代码文件和结构化并发等特性增强了可读性、并发性和性能，而 Spring 和 JUnit 等主要框架现在要求使用 Java 17+。
  3. 遗留 Java 应用的现代化是一个显著趋势，OpenRewrite 是一个关键的自动化工具。 组织积极升级过时的 Java 版本和框架，以解决技术债、提高安全性并简化开发，OpenRewrite 在其中扮演关键的自动化工具角色，使这些升级具有确定性和高效性。
  4. 企业级 Java，特别是 Jakarta EE，持续发展和稳定。 Jakarta EE 11 已获得广泛采用和认证，Jakarta EE 12 正在积极开发中，Jakarta Query 等新规范推动平台在数据管理方面向前发展。
  5. 由于对主权和合规性的担忧，云部署策略正在转向混合、区域或本地部署解决方案。 尽管“云原生”之前占据主导地位，但公司越来越多地重新评估其策略，强调数据隐私、监管要求以及对基础设施更大的控制权，尤其是在欧洲。

💬 文章金句

  • AI 不再仅仅是一个流行词，它已成为一个实际现实，我们看到了两种非常不同的使用方式。
  • Python 也许开启了故事，但许多这些 AI 应用真正在 Java 中真正落地并发挥作用。
  • 很高兴看到框架和库正在支持甚至要求使用更新的 Java 版本。Java 17 似乎是一个新的基线。
  • 几年前，一切都围绕着迁移到云和云原生。但如今，情况已大不相同。我更多地听到有公司迁回本地部署，或者选择欧洲云提供商和数据中心，而不是仅仅依赖大型全球平台。
  • 自动化现代化工具真的令人兴奋。以前，升级 Java、升级主要框架和库的工作是枯燥无味的。无聊的工作浪费了聪明人的时间来更改代码、测试一切，实际上在多月的项目结束后，得到的东西在功能上与之前相同。
