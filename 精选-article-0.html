动态计算：我们如何构建无服务器服务器 - Vercel

📌 一句话摘要

Vercel 的“动态计算”通过自定义 TCP 隧道和智能路由重新构建无服务器架构，实现高效的请求多路复用，减少冷启动并启用动态 CPU 定价。

📝 详细摘要

本文详细介绍了 Vercel 为构建“动态计算”而进行的为期两年的工程努力。这是一项无服务器创新，旨在克服传统无服务器平台（如 AWS Lambda）的局限性，最初的驱动力是支持 React 服务端组件 (RSC) 和 Next.js 应用路由的流式传输能力。文章解释了如何开发基于自定义 TCP 的传输层以实现流式响应和双向通信，打破了传统的每个实例一次调用的模型。文章介绍了 `compute-resolver` 服务，这是一个分布式系统组件，负责智能地将请求路由到多个区域中现有的空闲函数实例，以最大限度地重用资源并最大限度地减少冷启动。此外，它还描述了一个复杂的基于 Rust 的健康监控系统，该系统动态适应实例负载，确保最佳性能和资源利用率。这些基础性的改变为“动态 CPU 定价”铺平了道路，使客户只需为活跃的计算时间付费，从而为 I/O 密集型工作负载节省高达 95% 的成本。使客户只需为活跃的计算时间付费，从而显著降低成本。对于 I/O 密集型工作负载，成本节省高达 95%。

💡 主要观点

  1. 基于自定义 TCP 的传输层是实现流式传输和双向通信的基础。 这项创新使 Vercel 能够克服 AWS Lambda 最初的局限性，并促进了 React 服务端组件等功能。它也为超越简单请求-响应模型的高级功能奠定了基础。
  2. 在单个 Lambda 实例上多路复用请求可显著提高资源利用率并降低成本。 通过将多个并发请求发送到空闲函数实例，Vercel 打破了传统的每个实例一次调用的模型，大大降低了空闲计算成本，特别是对于像 LLM (大型语言模型) 这样的 I/O 密集型工作负载。
  3. 智能路由和精密的健康监控可确保最佳性能和资源分配。 `compute-resolver` 服务和基于 Rust 的核心动态管理流量和实例健康状况，防止过载和冷启动，自动适应工作负载配置文件，以在分布式区域实现最大效率。

💬 文章金句

  • 具有动态 CPU 定价的动态计算为每周超过 450 亿个请求提供支持，为客户节省高达 95% 的成本，并且从不收取空闲时间的 CPU 费用。
  • 答案是引入 Lambda 简单事件响应模型之外的一种新的安全传输方式，该传输方式将每个实例安全地连接回我们的基础设施。换句话说，我们在 Vercel 和 AWS Lambda 函数之间创建了一个隧道。
  • 重用已打开的隧道，将更多流量发送到空闲函数实例，可以避免浪费资源，减少冷启动，并降低成本。特别是对于请求并发高于 1 的 I/O 密集型工作负载，效果更明显。
  • 我们的解决方案是构建一个名为 `compute-resolver` 的新服务，该服务充当 Vercel 代理 Pod（Pod 是 Kubernetes 中的最小部署单元）的类似 DNS 的解析器，以解析为 Vercel 函数路由 Pod。
  • 您现在只需为您使用的实际资源付费：每个函数实例使用的活跃 CPU 时间（以毫秒为单位）以及每个函数实例使用的预配置内存（以 GB-小时为单位）。
