构建 RAG 流程的有效实践

9/3/2025, 9:00:00 AM

📌 一句话摘要

本文详细介绍了构建 RAG 流程的有效实践和经验教训，重点关注文档导入、混合搜索和相关性，以实现高质量的 LLM 响应。

📝 详细摘要

本文深入分析了构建 RAG (Retrieval Augmented Generation) 流程的有效实践，从一个实际的软件架构支持项目中总结经验教训。首先回顾了 RAG 的基础知识，强调通过提供精心策划的上下文来降低 LLM 产生错误信息的可能性。文章的核心深入探讨了文档导入、搜索和检索方面的实际挑战和解决方案。主要见解包括混合搜索方法（向量和基于关键词的）的必要性，基于内容和媒体类型（例如，散文、代码、图表、PDF 、网页）的细致分块策略，作者通常选择自定义实现（例如，`pypdf` 用于 PDF ，`Beautiful Soup` 用于网页抓取），以便更好地控制分块和内容提取，并选择在代码中实现结果合并和重新排序（例如，RRF ），而不是依赖数据库默认设置以获得更高质量的响应。它还强调了搜索结果中的“相似性”与 LLM 所需“相关性”之间的关键区别，以及上下文窗口限制和“上下文信息衰减 (context rot) ”对响应质量的影响，主张谨慎的重新排序。作者分享了具体的工具建议，如用于安全审查的 Guardrails 和用于各种 NLP 任务的 HuggingFace （例如，词性标注、句子转换器），以及数据库选择（仅向量与基于 Lucene 的）和嵌入算法。总的来说，本文为旨在构建强大而准确的 RAG 系统的开发人员和架构师提供了实用的指南。

💡 主要观点

  1. 混合搜索（向量 + 基于关键词的）对于有效的 RAG 流程至关重要。 结合向量搜索和基于关键词的搜索，能够更全面地检索信息，从而提高 LLM 答案的准确性和完整性。
  2. 分块策略必须根据内容和媒体类型进行定制。 对于不同的内容（散文、代码、图表）和媒体（PDF 、网页），最佳分块大小和方法差异很大，直接影响搜索准确性和检索信息的相关性。
  3. 相似性不等于 LLM 答案的相关性。 数据库搜索产生相似的结果，但 LLM 需要真正相关的信息。重新排序对于消除“上下文信息衰减”并确保通过过滤掉不太相关的数据来获得高质量的响应至关重要。
  4. 上下文窗口限制和“上下文信息衰减”需要仔细构建 prompt 。 即使使用更大的上下文窗口，包含过多或不相关的 tokens 也会降低 LLM 响应质量。只有最相关的搜索结果才应包含在 prompt (提示语) 中。
  5. 专用工具和算法可增强 RAG 流程的性能。 利用 Guardrails （用于安全性），HuggingFace （用于 NLP 任务，例如，词性标注、句子转换器）以及具有适当嵌入 / 距离函数的特定向量 / Lucene 数据库等工具可优化流程。

💬 文章金句

  • 对于回答用户关于文档问题的 RAG 流程，向量和基于关键词的混合搜索是最有效的策略。
  • 当领域足够复杂，问题足够复杂和细致时，相似性（这是你从文档搜索中得到的）与相关性（这是 LLM 需要回答问题的）是不一样的。
  • 分块的基础应该根据知识领域以及用于传递它的内容和媒体类型而有所不同。
  • 尽管每次新的 LLM 发布都会变得更大，但上下文窗口仍然是一个关键的考虑因素。在 RAG prompt 中仅包含最相关的搜索结果可确保最高的响应质量。
  • 对于大多数非平凡的用例，*相似性*并不等同于*相关性*。
