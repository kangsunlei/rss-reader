构建 LangGraph：一种面向生产环境的 Agent 运行时设计

9/4/2025, 5:23:46 PM

📌 一句话摘要

本文详细介绍了 LangGraph 的设计原则，旨在构建可用于生产环境的 AI 代理。文章重点关注底层控制、持久性以及解决 LLM 系统固有的挑战。

📝 详细摘要

本文介绍了 LangGraph，它是一个底层代理框架，旨在解决 LangChain 在生产环境 AI 代理应用中的不足。它强调了基于 LLM 的代理的三个核心挑战：高延迟、长时间运行任务的可靠性问题以及 LLM 的非确定性。为了应对这些挑战，LangGraph 整合了并行化、流式传输、检查点、人在回路中 (Human-in-the-Loop) 和追踪 (Tracing) 等功能，并将低延迟作为最终的总体要求。作者解释了为什么现有的 DAG 框架和持久执行引擎无法很好地支持循环、低延迟的 Agent 图。LangGraph 的设计理念优先考虑灵活性和贴近原生代码的开发体验，将运行时 (PregelLoop) 与开发者 SDK 分离开来。它利用结构化代理和受 BSP/Pregel 启发的执行算法来实现安全并行化、高效流式传输、强大的检查点以及无缝的人工干预，最终旨在为复杂的 AI 代理部署提供高性能、可扩展的解决方案。虽然任务队列被认为是必要的功能，但它由更广泛的 LangGraph 平台处理，而不是 Python 库本身。

💡 主要观点

  1. LLM 代理引入了独特的挑战，需要专门的框架设计才能用于生产环境。 高延迟、非确定性和长时间运行的任务需要并行化、流式传输、检查点和人在回路中等功能，以确保生产环境中的可靠性和用户体验。
  2. LangGraph 的设计强调底层控制和使用受 BSP/Pregel 启发算法的结构化代理。 这种方法实现了确定性并发、对循环的完全支持，以及高效实现关键功能（如安全并行化、流式传输和强大的检查点），这对于 Agent 的可扩展性和调试至关重要。
  3. 该框架的架构将运行时与 SDK 分离开来，从而可以独立发展和构建功能模块。 这种模块化确保了未来的适应性、无需 API 更改的性能优化，并使开发人员能够根据需要选择性地采用功能，从而避免采用过于死板的高级抽象。

💬 文章金句

  • 我们听到的最主要的事情是 `langchain` 很容易上手，但很难定制和扩展。
  • LLM 具有延迟高、稳定性差和输入输出开放等特点。
  • 任何代码框架的最大竞争对手始终是没有框架。
  • 我们最终构建在 BSP/Pregel 算法之上，因为它提供了确定性并发，并完全支持循环。
  • 同样的检查点机制不仅实现了容错，还可以支持 Agent 的“预期中断”，即 Agent 可以在继续执行之前暂停并请求用户或开发者的输入。
