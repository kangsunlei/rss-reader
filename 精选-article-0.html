Notion Custom Agents 复盘：三年重写 5 次，Notion 历史上最成功的新功能之一

4/15/2026, 12:50:00 PM

📌 一句话摘要

本文通过 Notion AI 工程负责人 Sarah Sachs 和技术负责人 Simon Last 的访谈，深度复盘了 Notion Custom Agents 功能从 2022 年至今的曲折开发历程、核心设计理念、团队管理哲学以及对 AI Agent 未来发展的前瞻性思考。

📝 详细摘要

文章是对 Notion AI 工程负责人 Sarah Sachs 和技术负责人 Simon Last 一次深度访谈的精华整理。内容聚焦于 Notion Custom Agents 这一成功功能的幕后故事，揭示了其在三年内推翻重写五次的曲折历程。核心观点包括：1）产品设计应迁就模型而非系统复杂度，例如将数据库查询抽象为 SQLite；2）Coding Agent 是通往 AGI 的核心路径，未来软件工程师的角色将转向管理和维护 Agent 系统；3）Evals 不仅是测试，更是理解模型能力边界和演进方向的工具；4）在 MCP 与 CLI 的工具选择上，CLI 因其自举和调试能力被视为未来方向；5）Notion 通过 Credits 定价模型和 Auto 模式，致力于引导用户使用“对的工具”而非“最贵的工具”。文章还分享了 Notion 独特的团队文化、项目管理方式以及对未来流量将主要来自 Agent 而非人类的判断。

💡 主要观点

  1. 产品设计应迁就模型认知，而非暴露系统内部复杂度。 Notion 早期将复杂的内部数据模型（XML/JSON）暴露给模型导致失败，后来转向使用模型熟悉的 Markdown 和 SQLite，效果立竿见影。核心教训是尽可能给模型它想要的东西。
  2. Coding Agent 是通往 AGI 的核心，将重塑软件工程角色。 Notion 认为一切 Agent 最终都是 Coding Agent，因为它们可以自举、调试和维护自身。未来软件工程师的角色将更多转向设计、观察和维护由 Agent 构成的自动化系统。
  3. Evals 体系分为三层，最高层旨在探索模型能力的“天花板”。 除了回归测试和发布质量评估，Notion 设立了“frontier/headroom evals”，目标通过率仅 30%，旨在主动探索模型在 Notion 特定场景下的极限能力，为产品方向和模型合作提供洞察。
  4. CLI 因其自举和调试能力，比 MCP 更具长期潜力。 CLI 环境允许 Agent 在出错时自行修复（如写代码调用 API），而 MCP 一旦传输层出问题则 Agent 能力尽失。但 MCP 在权限控制清晰的轻量级场景下依然有效。
  5. 定价与模型选择的核心是引导用户使用“对的工具”，并自动化 Agent 自身的工作。 Notion 通过 Credits 抽象层和 Auto 模式，旨在根据任务智能选择最合适的模型，而非最贵的。终极目标是让 Agent 能将其确定性任务自动化，减少不必要的 LLM 调用和成本。

💬 文章金句

  • 别把你系统里不必要的复杂度暴露给模型，尽一切可能给它它想要的东西。
  • Coding agent 是通往 AGI 的核心，一切都是 coding agent。
  • Evals 不只是「测试」，是要理解模型往哪里走。理解模型能做什么、不能做什么，怎么定义 headroom，怎么定义好的用户旅程，这需要一种很难被定义的直觉和品味。
  • 能力和语言模型的使用要对齐。用语言来执行确定性任务，是一种浪费。
  • 随着时间推移，我们大部分的流量会来自使用我们界面的 Agent，而不是人类。我们的目标是让整个产品 org 都在为 Agent 而建。
