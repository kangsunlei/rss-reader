Codex GPT-6 Astra 额度掉得太快？我用一段提示词，把上下文消耗大幅降低了！

9/14/2026, 9:08:31 AM

📌 一句话摘要

作者发现 Codex GPT-6 Astra 额度快速消耗主要由于上下文累积，通过精简 AGENTS.md 并设置自动压缩与工具输出限制，显著降低了 token 用量。

📝 详细摘要

文章作者在使用 Codex GPT-6 Astra 时发现额度消耗异常快，原本可用三天的额度在半天内耗尽。通过检查使用记录发现，问题并非模型本身变贵，而是每次调用都携带越来越多的上下文，包括聊天记录、工具返回、Skill 描述和全局 AGENTS.md 等，导致单轮输入 token 持续增长。作者于是进行了三类调整：一是将全局 AGENTS.md 从 5284 字节压缩到 1705 字节，保留关键规则而删除重复内容；二是在 config.toml 中设置 model_auto_compact_token_limit=160000、model_auto_compact_token_limit_scope="total"、tool_output_token_limit=8000，并在 skills 配置中加入 max_context_tokens=4000，以限制单轮输入和工具输出的大小；三是避免无限续任务，完成一个阶段后新建任务，并从默认推理强度起步，仅在真正需要深度分析时提升。文章还提供了一个可直接复制给 Codex 的提示词，用于自动检查并备份配置、执行上述优化，并在完成后给出使用建议。整体内容结构清晰，兼具理论解释与实操步骤，适合希望降低 AI 工具使用成本的开发者和产品经理参考。

💡 主要观点

  1. 上下文累积导致额度快速消耗 长时间任务会携带越来越多的聊天记录、工具返回、Skill 描述等，使每次调用的输入 token 持续增长，进而耗尽额度。
  2. 精简全局 AGENTS.md 并设置自动压缩阈值 将 AGENTS.md 从 5284 字节压缩到 1705 字节，保留关键规则；在 config.toml 中设置 model_auto_compact_token_limit、tool_output_token_limit 和 skills 的 max_context_tokens，防止单轮输入无限膨胀。
  3. 避免无限续任务，适当拆分并控制推理强度 完成一个阶段后应新建任务，不必带着全部试错记录继续工作；同时从默认推理强度起步，仅在真正需要深度分析时提升，以减少不必要的 token 消耗。
  4. 验证与备份确保配置更改安全可回滚 在修改前为原文件创建时间戳备份，确保 config.toml 可被 TOML 解析、Codex 能正常启动，并检查关键规则未丢失，最后给出使用建议和是否需要重启。

💬 文章金句

  • 额度不是突然消失，而是被上下文一点点吃掉
  • 第一，把全局 `AGENTS.md` 从 **5284 字节压缩到 1705 字节**。品牌名、公众号发布规则、飞书操作方式这些关键约束都保留，只删掉重复说明和不需要每轮都出现的内容。
  • model_auto_compact_token_limit = 160000
  • 第三，没有看到插件多就直接卸载。插件、MCP 和 Skills 都可能承载真实工作流，粗暴关闭很容易把原本能用的能力弄坏。
  • 驾驭 AI 的首要前提是，跟随 AI 的变化而变化！
