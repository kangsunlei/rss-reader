DeepSeek 故意做了一个难用的 Agent

8/16/2026, 2:00:00 AM

📌 一句话摘要

本文分析 DeepSeek 推出 Harness 框架的战略意图：从低价模型竞争转向争夺 Agent 运行时基础设施，通过开放插件生态和允许接入竞品模型，构建 Agent 时代的操作系统。

📝 详细摘要

文章从 DeepSeek V4 Pro 涨价与 Harness 上线两个动作切入，分析其战略转向。过去 DeepSeek 的逻辑是做强模型、打低价格、开放能力；现在它开始争夺模型之外的运行环境。Harness 将 Agent 拆分为模型、工具、Skills、工作流等可替换模块，底层 Cordis 内核负责插件的动态加载与卸载，实现时间可组合性与空间可组合性。DeepSeek 允许使用竞品模型，说明其真正想控制的是运行时而非模型本身，类比 Windows/Android 的平台逻辑。V4 Pro 涨价意味着模型从获客工具变为现金流引擎，生态循环正在成型。文章认为 Harness 的难用是刻意为之——它面向的是早期建设者而非普通用户，判断其成功与否的标准是插件和 Agent 生态的繁荣程度。

💡 主要观点

  1. DeepSeek 战略从低价模型竞争转向争夺 Agent 运行时基础设施。 V4 Pro 涨价与 Harness 上线同时出现，说明 DeepSeek 不再只争模型调用量，而是争调用发生在哪里——即 Agent 的运行环境。
  2. Harness 将 Agent 拆分为可替换模块，重新定义封装边界。 与 Claude Code 等产品把复杂性封装成产品不同，Harness 把复杂性拆成模块，把修改权交给开发者，类比苹果'复杂性替用户承担'的反向逻辑。
  3. Cordis 内核实现插件的时间与空间可组合性，让 Agent 能在运行中自我进化。 插件卸载后影响可撤销（时间可组合），依赖变化时能自动重接（空间可组合），Agent 可现场生成能力并挂载，无需人工预先配置。
  4. 允许接入竞品模型，说明 DeepSeek 真正想控制的是运行时而非模型。 类比 Windows/Android 的平台逻辑：操作系统不自己做所有软件，而是让别人在其上开发。DeepSeek 想复制这一逻辑，控制 Agent 时代的运行时环境。
  5. V4 Pro 涨价意味着模型从获客工具变为现金流引擎。 过去靠低价带来更多调用和开发者，现在通过 Harness 生态让 Agent 持续消耗模型，模型位置从终点变为发动机。

💬 文章金句

  • 过去 DeepSeek 在争模型调用量；现在，它开始争调用发生在哪里。这是两场完全不同的仗。
  • 苹果的逻辑是我替你把复杂性封装成产品。Harness 则是把复杂性拆成模块，再把修改权交给你。
  • 它真正想控制的，可能不是模型，是模型之下那层 Agent 的运行时环境。
  • 判断 Harness 成没成功，甚至不应该先看下载量。看插件，看 Agent，看谁在上面建东西。
