让问题不过夜：交易领域“问诊”Agent 实践

3/4/2026, 12:30:00 AM

📌 一句话摘要

本文介绍了阿里巴巴交易领域通过“排查文档技能化”构建可运营问诊 Agent 的实践，旨在将研发支持中的重复性排障工作自动化。

📝 详细摘要

文章深入探讨了在研发支持场景下，如何构建一个可持续进化的智能 Agent 系统以解决业务答疑和问题诊断的痛点。作者详细阐述了 Agent 构建范式的演进过程：从最初的 Java 编码驱动流程，到提示词内嵌 SOP，最终进化为“排查文档技能化（SOP Doc as a Skill）”的新范式。该范式通过 RAG 动态注入结构化的排查手册，使 Agent 成为严格的手册执行者，有效降低了模型幻觉并提升了系统的可维护性。此外，文章还介绍了四层架构设计、双层知识召回机制以及基于 Q-score 的质量评估与闭环运营体系，并展示了在订单、物流、逆向等多个业务领域的显著实战成效。

💡 主要观点

  1. 将研发支持问题抽象为业务答疑与问题诊断两类形态。 业务答疑侧重规则解释与口径说明，问题诊断侧重证据链定位与动作建议，针对不同形态采用差异化的 Agent 构建范式。
  2. 提出“排查文档技能化”范式，实现文档即技能闭包。 放弃复杂的 Workflow 编排，将排查流程封装在 SOP 文档中并由 RAG 动态注入，使 Agent 成为手册执行者，降低了维护成本。
  3. 构建“公共知识库 + 场景技能文档”的双层召回机制。 通过分离通用概念与特定场景流程，解决知识冗余与跨域共享问题，优先命中强约束的场景文档，提升了召回的精准度。
  4. 引入 Q-score 评分体系与自动化闭环运营机制。 利用评分 Agent 识别低分坏样本，驱动人工复核与知识库持续迭代，使 Agent 从静态工具演变为持续生长的“有机体”。

💬 文章金句

  • 我们要解决的不是一个具体的技术问题，而是：如何让研发支持变得可规模化、可复用、可运营？
  • 新范式：把排查能力封装成‘可召回的排查文档（SOP Doc）’。
  • 你不是诊断专家，你是手册执行者。手册是唯一的真理来源。
  • Agent 不再是静态部署的一次性产物，而是一个依托数据反馈持续生长的‘有机体’。
  • 让新人也能像老将一样从容应对复杂问题，这才是真正的工程提效。
