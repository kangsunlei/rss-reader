StrongDM 的 AI 团队如何在不看代码的情况下构建严肃软件

2/7/2026, 3:40:48 PM

📌 一句话摘要

StrongDM 的 AI 团队开创了一种“软件工厂”模式，通过“数字孪生”模拟和基于场景的留出集，让 AI 智能体自主编写并验证代码，从而消除了人工代码审查。

📝 详细摘要

本文探讨了 StrongDM 在软件开发中采取的激进“暗工厂”方法，其核心指令是人类既不编写也不审查代码。通过利用高 Token 消耗的智能体工作流，该团队通过“场景测试”解决了 LLM 的可靠性差距——将用户故事视为留出集，以防止智能体在测试中“作弊”。一项核心创新是“数字孪生宇宙”（DTU），它利用 AI 创建 Okta 和 Slack 等第三方 API 的高保真克隆。这使得在模拟环境中对智能体生成的代码进行详尽、大量的自动化验证成为可能。文章还介绍了“基因输血”和“Semports”等特定的智能体技术，标志着开发者的角色从代码编写者转变为 AI 驱动工厂的系统架构师。

💡 主要观点

  1. “暗工厂”模式要求人类既不编写也不审查代码，完全依赖 AI 智能体。 这种激进的方法将 LLM 不仅仅视为助手，而是作为主要劳动力。通过取消人工审查，团队被迫开发强大的自动化验证系统，其扩展能力远超人力极限。
  2. 场景测试充当“留出集”，在智能体看不到测试标准的情况下验证代码。 为了防止智能体生成“作弊”测试（如 assert true），StrongDM 将端到端的用户故事存储在代码库之外。这确保了 AI 生成的实现是根据独立的、概率性的“满意度”指标进行评估，而非简单的布尔值通过。
  3. “数字孪生宇宙”实现了第三方 API 的高保真模拟，用于详尽测试。 通过使用智能体构建 Okta 和 Jira 等服务的克隆，团队每小时可以运行数千个场景。这绕过了生产环境的速率限制和成本，允许以史无前例的规模验证复杂的安全软件。
  4. 软件工程师的角色正在从编写代码转变为设计构建代码的系统。 在这种模式下，工程师专注于细致的规范、场景设计以及监控“工厂”输出。这种转变代表了更高层次的抽象，人类充当自我纠错智能体集群的监督者。

💬 文章金句

  • 代码不得由人类编写；代码不得由人类审查。
  • 如果你今天在每个工程师身上花费的 Token 费用还没达到 1，000 美元，那么你的软件工厂还有改进空间。
  • 我们从成功的布尔定义（“测试套件通过”）转变为概率性和经验性的定义。
  • 创建一个大型 SaaS 应用的高保真克隆一直是可能的，但在经济上从未可行过。
  • 这感觉像是窥见了软件开发的一个潜在未来，软件工程师从构建代码转变为构建并半监控那些构建代码的系统。
