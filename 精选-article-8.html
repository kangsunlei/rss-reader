让改进有迹可循：Storage Agent Family Eval 工程实践

11/3/2026, 10:00:00 AM

📌 一句话摘要

文章介绍了火山引擎存储团队构建的 Storage Agent Family 评测体系，通过离线回归实验、Trace 调用链分析和线上真实问题回流，实现了 Agent 持续迭代和质量提升，确保其在云存储场景下的准确性与安全性。

📝 详细摘要

文章详细阐述了 Storage Agent Family 评测体系的构建实践，包括如何设计覆盖任务、行为和安全的评测集，采用 LLM 评估器与 Code 评估器相结合的方式进行多维度打分。通过评测工作台、云端隔离沙箱和 TLS AgentLoop 的协同，实现了每次 Agent 改动的可追溯性与可量化。以 EBS Agent 为例，展示了从定位到具体 Skill 问题、修复后任务完成度提升的完整闭环。同时，文章强调了将线上真实用户问题持续回流至评测集，推动 Agent 持续进化的重要性。

💡 主要观点

  1. 构建多维度评测体系 从用户意图、Skill 链路和边界条件三个维度设计评测集，确保覆盖任务完成、数据真实和操作安全三个核心目标。
  2. 采用双层评估器机制 结合 LLM 评估器和 Code 评估器，前者评估语义与过程质量，后者进行程序化验证，提高评分准确性。
  3. 实现改动可追溯 通过评测工作台、云端隔离沙箱和 TLS AgentLoop 的协同，确保每次 Agent 改动都有据可查，可量化地评估改动效果。
  4. 从失分定位到具体问题 通过 Trace 调用链分析，定位问题源于知识库、Skill、CLI 工具或执行框架，针对性修复后显著提升任务完成度。
  5. 线上问题持续推动迭代 将线上真实用户会话和典型运维工单筛选、去重、脱敏后回流至评测集，形成闭环推动 Agent 持续进化。

💬 文章金句

  • 为此，我们围绕 Storage Agent Family 建立了一套持续评测与改进机制：通过离线回归实验检验每次改动后的回答与工具调用过程，结合调用链（Trace）定位具体模块的问题，再将线上真实对话中暴露的典型问题持续沉淀至评测集。
  • 评测采用 LLM 评估器与 Code 评估器相结合的方式：前者围绕任务理解与回应聚焦、事实依据与可信度、任务完成度、能力边界与操作安全、表达清晰度与可行动性五个维度，评估语义与过程质量。
  • 以块存储 EBS Agent 的一轮版本迭代为例，综合得分由 88.7 分提升至 95.1 分（+6.4），任务完成度由 55.4 分提升至 92.2 分。
  • 衡量一个云存储 Agent 的质量，关键看它能否基于真实资源状态做出判断、选对工具与执行路径，并严格遵守权限和安全边界。
