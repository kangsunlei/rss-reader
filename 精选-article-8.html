让 AI 真正懂旅行：飞猪「问一问」的架构与实战演进

12/20/2025, 2:15:00 AM

📌 一句话摘要

飞猪「问一问」通过多智能体协作、Function Call 及对实时数据和用户体验的优化，将 AI 从旅游咨询工具升级为可闭环交易的智能行程管家，大幅提升行程规划效率超 90%并获得用户高度认可。

📝 详细摘要

文章详细介绍了飞猪「问一问」从最初的地图规划工具，如何逐步演进为基于多智能体协作、直连实时价库的 AI 智能旅行管家。面对旅游场景高非标、决策链路长、实时库存要求高的挑战，飞猪团队提出“懂行、能算、能做”的核心理念，设计了由意图识别 Agent 和多个场景 Agent 协同工作的多智能体架构。为解决大模型幻觉和效率问题，特别优化了上下文管理（Query 改写、记忆裁剪）并全面转向 Function Call 实现实时数据查询。文章创新性地介绍了双轮工具调用策略，即先生成行程骨架再填充实时数据，有效降低了大模型幻觉率，并结合双通道渲染协议、并行处理、断点续传机制等多维度优化，显著提升了用户体验。最终实践成果显示，该系统将行程规划效率提升了 90%以上，用户满意度高达 95%，并已开放至荣耀、VIVO 等外部生态。

💡 主要观点

  1. 飞猪「问一问」从“咨询”型 AI 进化为“能干活”的 Agent，实现旅游交易闭环。 通过整合高质量行业数据、实时价库查询和商品挂载能力，AI 能够解决从行程规划到下单交易的全链路问题，而非仅限于提供信息，满足了用户从了解到决策再到行动的全部需求。
  2. 采用多智能体协作架构，有效应对旅游场景的复杂性和不确定性。 通过意图识别 Agent 分流和抽槽，结合行程、交通、酒店等 N 个场景 Agent 及 Function Call 工具调用，将复杂的旅游问题拆解成可管理的子任务，并通过 COT 和 Prompt Chaining 等编排方式，显著提升了处理精度和效率，降低了幻觉率。
  3. 创新性双轮工具调用策略，确保了行程规划的合理性与实时数据的真实性。 分两步调用工具：首先查询关联线路库生成“行程骨架”，然后基于骨架再次调用工具精准查询具体的交通班次、酒店实时价格、景点门票等，有效平衡了生成速度、准确性与现实数据的同步。
  4. 多重技术优化显著提升用户体验，有效解决大模型“慢”与“呆”的痛点。 通过并行双通道渲染协议实现图文流式输出、极致的并行处理提升响应速度、以及序号化续接机制保障弱网环境下的体验连贯性，大幅优化了移动端的用户感知和流畅度。
  5. AI Agent 的核心在于高质量的 Context Engineering 和 Calling Tool 的能力。 文章强调，模型表现的关键在于提供精准的行业专有数据（Context）作为输入，并具备调用真实世界工具（Function Call）的能力，这使得大模型从“玩具”真正转变为能够解决实际问题的“工具”，为行业带来革命性效率提升。

💬 文章金句

  • 用户需要的不是一个陪聊的网友，而是一个能干活的 Agent（智能体）。它需要具备三个核心素质：懂行、能算、能做。
  • 简单的 RAG 无法承接复杂的旅游场景，于是，我们构建了一套意图识别 Agent + N 个场景 Agent（行程、交通、酒店、讲解等）的多智能体架构。
  • Function Call。把“查询线路”、“查询机票”、“查询酒店库存”等功能封装成工具，让模型自己决定：“为了回答这个问题，我现在需要调用哪个工具？需要什么参数？”。
  • 大模型生成内容通常较慢，且默认是 Markdown 文本，这对于需要展示丰富图文卡片的旅游场景来说体验很差。
  • AI Agent 的核心不在于 Prompt 写得有多好，而在于上下文工程师（Context Engineering）做得有多细。
  • 只有给模型提供高质量的行业专有数据（Context），并让它具备调用真实世界工具的能力（Function Call），大模型才能真正从“玩具”变成“工具”。
