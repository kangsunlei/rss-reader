动态上下文发现 (Dynamic Context Discovery)

1/7/2026, 3:19:24 AM

📌 一句话摘要

本文介绍了 Cursor 平台针对 AI Agent 提出的“动态上下文发现”技术，通过将多源信息视为文件并按需加载，从而高效优化上下文管理，提升了 AI Agent 的性能和 Token 利用率。

📝 详细摘要

文章深入探讨了 AI Agent 在软件开发中，尤其是在 Context Engineering 方面的优化实践。作者提出了“动态上下文发现”（Dynamic Context Discovery）的概念，旨在解决传统静态上下文（Static Context）低效利用 Token、容易引起混淆等问题。通过将冗长的工具返回结果、聊天记录、Agent Skills 定义、MCP 工具描述以及集成终端会话等都视为文件，并在需要时通过搜索、引用等方式动态加载，大大提高了 Token 的使用效率和 AI Agent 的回答质量。文章详细介绍了 Cursor 如何在五个具体场景中应用这一模式，并强调了文件作为一种简单而强大的基元在 AI Agent 交互中的重要性。这种方法的实施显著减少了不必要的对话总结，提升了模型对历史信息的利用，并能有效降低 AI Agent 消耗的总 Token 数。

💡 主要观点

  1. AI Agent 的高效运行依赖于优化的上下文工程（Context Engineering）。 在 AI Agent 发展中，除了模型自身的进步，如何高效构建提示词和环境，特别是如何有效管理上下文信息，是提升 Agent 性能的关键。
  2. “动态上下文发现”模式能够显著提升 Token 使用效率和智能体响应质量。 通过按需加载所需信息而非一股脑塞入所有上下文，可以避免不必要的 Token 消耗，减少混淆信息，从而提高 AI Agent 的准确性和效率。
  3. 将多样化的输入和中间结果抽象为文件是实现动态上下文发现的有效方式。 Cursor 实践证明，将工具返回结果、聊天记录、Agent Skills 定义、MCP 工具描述以及终端会话输出等都视为文件并提供搜索机制，能让 AI Agent 灵活地获取所需信息。
  4. 该方法通过减少冗余信息，有效解决了上下文窗口溢出和模型“遗忘”问题。 通过智能地处理长输出和历史信息，AI Agent 可以在上下文限制下更好地保留关键细节，并根据需要主动检索，提升了长期任务处理能力。
  5. 文件作为一种通用且强大的基元，为 AI Agent 的未来交互提供了可靠基础。 尽管针对 LLM 的最终交互接口仍未确定，但文件这种简单、适应性强的抽象，在当前和未来的 AI Agent 开发中展现出巨大的价值和稳定性。

💬 文章金句

  • 我们在最开始提供给模型的细节越少，效果反而越好，因为这让智能体能够更轻松地自行抓取相关的上下文。
  • 我们将这种模式称为 **Dynamic Context Discovery** （**动态上下文发现** ），这与通常那种不管用不用得上都一股脑塞进去的 *Static Context* （*静态上下文*）形成了鲜明对比。
  • **动态上下文发现** 在 Token 的使用上要高效得多，因为它只把真正需要的数据拉入 **Context Window**（上下文窗口，即模型一次能处理的信息量上限）。
  • 即使这些工具总是被包含在提示词中，绝大多数时候它们根本不会被用到。如果你使用了多个 MCP 服务器，情况会变得更糟。
  • 对于基于大语言模型（LLM）的工具来说，文件是否是最终的交互接口尚无定论。但随着编程智能体的快速进化，“文件”已被证明是一种既简单又强大的基元（Primitive）。
