LLM 代理防提示注入设计模式

6/13/2025, 1:26:43 PM

📌 一句话摘要

新论文提出通过约束动作，保障 LLM 代理免受提示注入的设计模式。

📝 详细摘要

本文分析了一篇重要的最新研究论文，该论文提出了六种设计模式，以减轻 LLM 代理中的提示注入风险。该论文认识到实现通用代理安全性的难度，提倡在摄取不受信任的输入后，主动约束代理行为。讨论的六种模式包括：动作选择器（防止反馈循环）、先计划后执行（在不受信任的输入之前计划动作）、LLM Map-Reduce (LLM 映射归约)（通过隔离子代理实现）、双 LLM（协调隔离和特权模型）、先编码后执行（生成沙盒代码）和上下文最小化。该论文详细介绍了这些模式，并提供了十个实际案例研究，用于将它们应用于 SQL 代理和客户服务聊天机器人等实际场景，为构建更鲁棒的代理系统提供了有价值的、实用的策略。

💡 主要观点

  1. 通用代理在面对提示注入时，难以提供可靠的安全保障，例如完整性和机密性。 作者认为，当前的 LLM 使得高度灵活的代理不太可能可靠地安全，因此有必要专注于构建受约束但有用的代理。
  2. 核心安全原则是在接收不可信输入后约束代理行为。 一旦摄取了不受信任的输入，必须限制代理，以防止其采取可能损害系统完整性或机密性的重要或任意操作。
  3. 多种设计模式提供了实用的缓解策略。 该论文介绍了六种模式 - 包括双 LLM 和代码生成的变体 - 提供了具体的架构方法来限制恶意提示的影响。
  4. 实际案例研究说明了模式在实际系统中的应用。 十个详细的案例研究演示了如何在各种代理类型（如 SQL 代理和助手）中实施这些安全模式，面临复杂的注入挑战。

💬 文章金句

  • 只要代理及其防御都依赖于当前类别的语言模型，我们认为通用代理不太可能提供有意义且可靠的安全保证。
  • 我们 今天 可以构建哪些类型的代理，在提供抵御提示注入攻击的同时，产生有用的工作？
  • 一旦 LLM 代理摄取了不受信任的输入，就必须对其进行约束，使其 不可能 让该输入触发任何重要的操作
