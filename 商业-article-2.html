Claude Code 工程师：为什么使用 HTML 文件作为 AI 规范丨 How I AI

5/18/2026, 2:02:00 PM

📌 一句话摘要

Claude Code 工程师 Thariq Shihipar 提出用 HTML 文件替代 Markdown 作为 AI 规范文档，以提升人类对 AI 计划的参与度和可读性，并重新定义了人在 AI 工作流中的角色。

📝 详细摘要

本文基于对 Anthropic 工程师 Thariq Shihipar 的播客访谈，深入探讨了在 AI 能够生成超长、复杂计划的背景下，人类如何保持有效参与的问题。Thariq 的核心观点是，传统的 Markdown 格式文档已无法满足人类快速浏览、理解和修改的需求，而 HTML 文件因其丰富的视觉层级（卡片、表格、颜色、交互按钮等），能成为人与 AI 之间更高效的沟通媒介。他提出，当 AI 运行成本高昂（如 8 小时消耗 500 美元）时，人类必须扮演「计算资源分配者」的角色，通过更清晰的计划来决定计算资源的投向。文章详细展示了 Thariq 的工作流：从用 HTML 进行头脑风暴，到将 PRD 和技术 spec 合并为可交互的页面，再到为局部问题生成临时 UI 进行微调，最后将设计系统也封装为 HTML 文件。其核心思想是，AI 生成内容的能力越强，人类就越需要重新设计自己介入工作的界面，从「顺序阅读」转向「空间浏览」，从而做出更明智的决策。

💡 主要观点

  1. 用 HTML 替代 Markdown 作为 AI 规范文档，能显著提升人类的参与度和决策质量。 AI 生成的计划越来越长，人类已无法逐行阅读 Markdown。HTML 通过卡片、表格、颜色等视觉元素，将信息从「文本墙」转化为可扫读的界面，让人能快速抓住重点、风险和取舍，从而更积极地参与计划评审。
  2. AI 时代的产品和工程负责人将转变为「计算资源分配者」。 当 AI 运行成本高昂时，编写计划的目的不再仅仅是「说服同事」，而是决定昂贵的计算资源（token）如何分配。清晰的计划能确保 AI 的工作方向正确，避免因目标不明确导致的返工和资源浪费。
  3. 为局部问题生成一次性 UI，是高效修改 AI 计划的有效方法。 当对 AI 生成的计划某部分不满意时，不必通过冗长的对话来修改。可以要求 Claude 为这个具体问题生成一个临时、可交互的小工具，通过更直观的界面来调整规则，再将结果写回原计划，极大提升了沟通效率。

💬 文章金句

  • Markdown 计划太长了，我老实说已经不读了。
  • 你说 Claude 可以跑 8 小时，其实是在说 Claude 可以花掉 500 美元。
  • HTML 更容易读，是你和 Claude 之间更丰富的沟通媒介。
  • 所有人都在变成 compute allocator，你要决定什么值得花计算资源。
  • 当 spec 像一个网站，人更愿意停下来比较、选择、删改和追问。
