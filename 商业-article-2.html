Clay AI 负责人：增长团队开始像工程团队一样跑 Agent 丨 LangChain 丨

6/27/2026, 1:53:00 PM

📌 一句话摘要

本文基于 Clay AI 负责人的分享，阐述 AI Agent 已根本改变增长团队的工作方式——增长从文案活转为工程活，关键在于构建数据闭环、信号筛选和可扩展的 Agent 基础设施。

📝 详细摘要

文章总结自 LangChain 播客对 Clay AI 负责人 Jeff Barg 的采访，核心观点是：当 AI 能写出像人一样的邮件后，冷邮件的胜负不再押在文案上，而在于目标选择和市场信号。Clay 每月运行超 3.5 亿个增长 Agent，连接 4000 多万家公司、9 亿联系人。作者详细拆解了增长 AI 的三个层次：个人使用、集中部署、自有数据+业务逻辑的不可复制组合；工程底座上的挑战——Lambda 迁移至 ECS、带背压的调度、缓存策略节省 70%费用、限制 Agent 步数保证质量；以及 Audiences 功能如何将分散数据聚合成 Agent 记忆底座。文章强调增长团队应先从小闭环开始：选细分市场、定义三类信号、限制研究步数、记录回信与误判，逐步将 Agent 从个人提效工具升级为团队增长引擎。

💡 主要观点

  1. 增长从根本上已变成工程挑战，胜负在于目标选择和信号数据。 当 AI 能轻松写出高质量冷邮件后，创意优势消失；决定回信率的是找对了谁、在什么时候以什么理由触达，而非邮件文案本身。
  2. Clay 将增长动作接成闭环：扫描市场→叠加信号→Agent 打分→触达→反馈循环。 100 多个数据源集成提供方和 AI Agent 做补全，使团队能批量运行“找谁、什么时候找、用什么理由找”这些步骤，每次活动积累的数据参与下一轮优化。
  3. 三层 AI 落地中，自有数据与业务逻辑的组合才是不可复制的优势。 第一层个人使用 AI 工具、第二层集中部署都易被模仿；第三层将公司专有客户数据、市场信号和购买触发点压进 Agent 系统，形成竞争对手难以复制的壁垒。
  4. Agent 生产级部署需要重视持久化工作流、缓存策略和评估边界。 Clay 从 Lambda 迁到 ECS 解决了等待计费问题；带背压的调度提升 4-10 倍吞吐；围绕 Anthropic 缓存设计最高省 70%费用；用评估卡住步数减少无效工具调用。

💬 文章金句

  • 没有任何创意优势会永远存在。
  • 赢的人，是迭代最快的人。
  • 第三层是创造竞争对手无法复制的优势。
  • 正确的架构看起来更像持久化工作流执行。
