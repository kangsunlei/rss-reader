Codex 负责人：Codex 不只是写代码，Agent 正在进入日常工作丨 OpenAI

5/21/2026, 12:41:00 PM

📌 一句话摘要

OpenAI Codex 负责人 Thibault 在访谈中揭示了 Codex 正从编码工具演变为覆盖研究、运营、财务等日常工作的通用 Agent，其核心价值在于将知识工作拆解为可委托的小任务，并释放工程师和知识工作者被琐事占据的注意力。

📝 详细摘要

本文是对 OpenAI Codex 负责人 Thibault 在 OpenAI Forum 上访谈的深度总结。Thibault 指出，软件工程师每天只有 20%-30% 的时间在写代码，其余时间被沟通、排期、查 bug 等非编码任务占据。Codex 的演进路径印证了这一点：它从云端 PR 工具转向贴近用户本地环境，并接入 Notion、文档等更多上下文，从而自然跨越代码边界，开始处理发布计划追踪、信息汇总、数据分析等知识工作。文章通过 OpenAI 内部案例（如产品负责人用多个 Codex Agent 协同更新发布计划）和 Thibault 的个人实践（如每天委托上百个小任务、制作面包地图网页），展示了 Agent 如何将协调、信息搬运等重复劳动拆解为可委托的小任务。文章还讨论了企业采用 Agent 的关键阻力在于权限与信任，并给出了非技术用户用好 Codex 的三个习惯：保持创造性、指令具体化、连接更多信息源。核心启示是，Agent 的价值不在于替代人，而在于让每个人都能快速创建和维护属于自己的「个人软件」，从而将注意力从琐事中解放出来。

💡 主要观点

  1. 软件工程师的大部分时间并不在写代码，Codex 因此自然跨越代码边界。 工程师每天只有 20%-30% 的时间在编码，其余时间用于沟通、排期、查 bug 等。Codex 通过接入 Notion、文档等上下文，开始处理这些非编码的知识工作，其服务对象从代码文件扩展到整个工作流程。
  2. Agent 的核心价值在于将协调与信息搬运拆解为可委托的小任务。 OpenAI 内部案例显示，产品负责人用多个 Codex Agent 分别追人、汇总信息、更新文档，将过去需要人工在 Slack、文档和 GitHub 间来回翻找的协调工作，变成一组可并行执行的小任务，释放了人的判断力。
  3. Agent 让「个人软件」成为可能，降低了软件创建的门槛。 Thibault 用 10 分钟让 Codex 将旧金山面包店信息做成表格并生成网页地图。这展示了非程序员也能快速为自己创建一次性工具，解决了过去因不值得投入工程资源而被搁置的个性化需求。
  4. 企业采用 Agent 的最大阻力是权限与信任，而非模型能力。 Thibault 强调，Agent 必须默认在沙盒中运行，并设置严格的读写和网络访问控制。OpenAI 还引入了 auto review 机制，让另一个 Agent 审查主 Agent 的动作，以确保安全合规。

💬 文章金句

  • 软件工程师一天里大部分时间并不在写代码。
  • 当工具能读懂工作上下文，它服务的对象就不再只是代码文件。
  • 每个人都能拥有自己的个人软件，并维护它，让它刚好做自己需要的事。
  • 我每天会丢给 Codex 可能超过一百个小任务。
  • 如果你能描述好什么叫完成，Codex 就更容易判断自己做得怎样。
