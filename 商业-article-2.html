E251｜推理芯片之战：聊聊 Groq、Cerebras 与 OpenAI 三大路径

9/16/2026, 12:00:00 AM

📌 一句话摘要

两位 AI 芯片创业者拆解 Groq、Cerebras 与 OpenAI 三条推理芯片路径的技术取舍，指出推理时代核心矛盾从算力转向带宽性价比，SRAM 与系统级异构是主要解法，而静态编译调度与晶圆级良率成本是各自软肋。

📝 详细摘要

本期硅谷 101 聚焦推理芯片赛道。嘉宾 Mark（斯坦福博士、前国内芯片大厂通用 GPU 研发）与徐子扬（前亚马逊 Annapurna Labs 训练芯片软件栈科学家）从训练与推理的本质差异切入：训练追求算力与并行度，推理的 decode 阶段必须逐 token 自回归生成，每产出一个 token 都要把整个模型权重从存储读入计算单元，因此瓶颈是内存带宽而非算力。围绕如何获得高性价比带宽，二人对比 SRAM、DRAM、HBM 三种介质，认为 SRAM 带宽性价比高出 HBM 两到三个数量级，但容量低两个数量级，须靠上千颗芯片组成大系统弥补，于是通信调度成为新瓶颈。Groq 选择静态编译调度以换确定性，但在 MoE 动态专家选择上失配；Cerebras 用整片晶圆缩短物理距离，代价是良率与系统适配成本。节目还分析英伟达约 200 亿美元 acqui-hire Groq 的动机、Cuda 在推理时代被绕过的逻辑、OpenAI 自研芯片 Jalapeño 选择 HBM4 与通用性设计的考量，以及 Bill Dally 关于局部性与跳出 local minimum 的设计哲学。

💡 主要观点

  1. 训练看算力、推理看带宽，是两条产品逻辑的根本分野 训练没有直接商业回报，目标是赌最强模型，做的是算力驱动的重资产投资；推理则可以清楚算账——用户为每百万 token 付多少钱、系统产出这些 token 花多少钱。技术上，prefill 阶段 token 已知、并行度高，GPU 算力能跑满；decode 阶段逐 token 自回归，每生成一个词都要把整个模型权重从存储读一遍，瓶颈落在内存带宽。
  2. SRAM 的带宽性价比高出 HBM 两到三个数量级，但容量低两个数量级，必须用大系统来补偿 SRAM 用 6 个晶体管存 1 bit、延迟仅 0.3–3ns，且可做进计算芯片内部，把封装走线换成光刻线，在线密度、成本、能耗上都是质的提升；代价是单芯片容量比 HBM 低约两个数量级。一个 1T 参数模型按 FP8 量化约需 1TB 容量，而单颗芯片只有几百 MB SRAM，所以要上千颗芯片互联，此时通信调度成为新的效率瓶颈。
  3. Groq 与 Cerebras 用两种方式解决大集群通信，各带时代局限 Groq 把调度前移到编译器，静态规划每个时钟周期做计算还是通信，追求确定性，但 2016 年创业时无法预知 Transformer 与 MoE 带来的动态性，MoE 在运行时才决定激活哪些专家，静态调度要么保守地广播导致空转，要么难以高效切分模型。Cerebras 直接把一个机柜的芯片做成整片晶圆以缩短物理距离，挑战在于整片良率与成本，一旦达不到要求整片作废。
  4. 英伟达 acqui-hire Groq，买的是带宽能力而非团队规模 黄仁勋清楚未来推理里算力不是唯一瓶颈，需要补齐带宽技术。而即便英伟达研究院早有架构创新，把研究想法颠覆式推入成熟产品团队难度极大，不如收购一支与既有体系无关的新团队。嘉宾认为推理时代绕过 Cuda 是必然，因为用户愿意为更好的性价比而非软件易用性买单，且单一 Transformer 应用加 AI 辅助写 kernel，使软件栈门槛显著降低。
  5. 推理速度是智能的约束条件，速度决定单位时间内模型能用多少 token 自我思考 人读 token 约 100 token/s 已足够，但 agent 与思维链产生的 token 是给模型和其他 agent 读的。交互时间固定为一分钟时，十倍推理速度意味着模型能在同样的时间里用十倍 token 做内部推理与实验，从而更聪明，这正是黄仁勋演讲中横轴被称为 smart AI 的原因。
