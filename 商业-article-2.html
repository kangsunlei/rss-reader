YC 如何进行 AI-Native 组织改造：Agent 能力要向所有人开放

6/2/2026, 12:33:00 PM

📌 一句话摘要

YC 合伙人 Pete Koomen 详细拆解了 YC 内部构建 AI-Native 组织的经验，包括全员可见的 Agent 系统、350+ 工具注册表、夜间自我进化的 Dream Cycle，以及「默认信任」和「平等主义」两大文化前提。

📝 详细摘要

本文是 Founder Park 对 YC 合伙人 Pete Koomen 播客对谈的精华编译。Pete 分享了 YC 过去一年多内部构建 AI Agent 基础设施的完整历程。从最初为财务团队搭建 SQL 查询 Agent 开始，系统已演化为包含 350+ 工具的内部注册表、一个全员可见的 Agent 对话系统，以及每晚自动读取所有对话、改进自身技能的 Dream Cycle。文章深入探讨了 AI-Native 组织与「把 AI 当 Copilot 用」的本质差异：前者将 AI 作为组织运转的建设层，系统性记录所有 artifacts（会议录音、Agent 对话、决策文档），让这些成为 Agent 学习的原材料。Pete 和 Gary 强调，实现这一目标需要两个文化前提：Egalitarian（AI 能力向所有人开放）和 Trust by default（默认信任，所有 Agent 对话对全员可见）。此外，文章还讨论了工具注册表与技能体系的设计哲学、成本下降带来的需求爆发（杰文斯悖论）、以及「Agent 包裹确定性工具」的未来软件形态。

💡 主要观点

  1. AI-Native 组织的核心是将 AI 作为建设层，系统性记录所有 artifacts。 与 Copilot 模式不同，AI-Native 组织要求会议录音、Agent 对话、决策文档等全部被记录，成为 Agent 可学习、检索、利用的原材料，而非仅停留在个人头脑中。
  2. 全员可见的 Agent 对话系统是知识传播与安全控制的巧妙设计。 所有 Agent 对话默认广播到内部 Slack 频道，既促进了知识传播和新人上手，又通过社会性控制替代了严格的技术访问控制，使 Agent 能获得更广泛的上下文。
  3. Dream Cycle 让 Agent 每晚通过分析对话记录实现自我进化。 系统每晚自动读取员工当天的 Agent 对话，识别技能不足之处并自动优化相关提示词，使 Agent 的某些能力（如「两句话描述」）已超越任何一位合伙人单独的水平。
  4. 成本下降带来需求爆发，统一数据源是 Agent 发挥威力的前提。 YC 所有自研软件跑在同一个 Postgres 数据库上，使 Agent 能回答关于业务的任何问题。杰文斯悖论在此体现：当查询成本降为零，提问的数量和复杂度都会爆炸。
  5. 未来软件形态应是 Agent 包裹确定性工具，而非确定性软件包裹 AI。 AI 最大的潜力在于将软件控制权从开发者转移到用户手中。最好的 AI 软件往往是最小的，只在模型能力之上加最少量的预写代码，让模型做最多的工作。

💬 文章金句

  • 真正的 AI-Native 做法是把 AI 作为整个组织运转的建设层（building layer），并且系统性地记录所有 artifacts。
  • 在家里用 Claude Code 或 OpenClaw 什么都能做，到了公司就被塞进一个狭窄的框里。我们一直在试图缩小这个差距。
  • 成本下降带来的不是需求减少，而是需求爆发。
  • 当 AI 越来越成熟，正确方向是 Agent 包裹确定性工具（agent wrapping deterministic tools），而不是确定性软件包裹 AI。
  • 最好的 AI 软件往往是最小的，只在模型能力之上加最少量的预写代码，让模型做最多的工作。
