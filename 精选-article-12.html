Multi-Agent 多智能体架构解析--DeerFlow

8/19/2025, 10:25:00 AM

📌 一句话摘要

深入解析了字节跳动开源的多智能体协同框架 DeerFlow 的架构、核心 Agent 职责及数据流转逻辑，并提炼了关键 Prompt 设计。

📝 详细摘要

文章详细剖析了 Multi-Agent 架构在解决复杂任务中的优势，并以字节跳动开源的 DeerFlow 框架为例，深入探讨了其多智能体协同工作机制。文章系统介绍了 DeerFlow 的四大核心 Agent：coordinator（协调器）、planner（规划器）、research_team（研究团队）和 reporter（报告员），并结合代码实现，详细阐述了每个 Agent 的职责、工作流程及关键 Prompt 设计。特别强调了 planner 在信息充足性判断中的严格标准以及 research_team 通过工具进行信息检索的机制。此外，文章还提及了 DeerFlow 中集成的其他工具类 Agent（如 coder、ppt_composer）及其在整个工作流中的协作方式。本文对于理解多智能体系统设计、Agent 间协作原理以及 Prompt 工程实践具有重要的参考价值，适合技术研究者、开发工程师和 Prompt 工程师阅读。

💡 主要观点

  1. Multi-Agent 架构通过分工协作有效解决大模型在复杂任务中的局限性 大语言模型虽擅长单一场景，但面对跨领域、多步骤任务时，多智能体系统能通过并行处理和动态协作提升效率和鲁棒性。
  2. DeerFlow 通过核心 Agent 协同实现通用 Agent 功能，简化科研和内容创作流程 Coordinator、Planner、Research Team 和 Reporter 各司其职，形成完整工作流，处理用户请求、规划任务、收集信息并生成报告。
  3. Prompt 设计是 Multi-Agent 系统各 Agent 职能和行为的关键 文章通过展示每个 Agent 的核心 Prompt 内容，清晰揭示了其在任务处理、信息判断和输出风格调整中的具体作用和行为逻辑。
  4. Planner 严格判断信息充足性，确保报告质量并支持多轮交互 Planner 在生成计划前会严格评估现有信息，若不足则引导用户补全或启动研究团队进行数据收集，保障输出内容的全面性。
  5. Research Team 通过工具检索信息，避免“幻觉”并确保数据有效性 研究员被要求不使用自有知识，而是依赖本地或网络搜索工具进行信息检索和整合，有效提升了信息准确性和可靠性。

💬 文章金句

  • 尽管大模型在单一场景表现优异，但面对跨领域、多步骤的现实任务时，仍需通过多智能体的分工协作实现突破。
  • DeerFlow 是字节跳动于 2025 年 5 月 9 日开源的多智能体深度研究框架，旨在通过人工智能技术简化科研和内容创作流程。
  • planner 被要求，在出具计划之前，必须要严格了解用户的问题，有充足的信息支撑才可以出具计划，否则的话，会通过与用户的多轮对话来进行信息的补全。
  • 你是由 "监督者" 代理管理的 "研究员" 代理。你致力于使用搜索工具开展全面调查，并通过系统运用可用工具（包括内置工具和动态加载工具）提供全面的解决方案。
  • 进入 reporter 以后，就算进入了整个流程的最后阶段。reporter 会将所有的信息，包括用户问题、执行计划、搜索结果全部进行整合，然后按照 reporter prompt 的任务要求，给与用户反馈。
