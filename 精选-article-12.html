《Agent 评测白皮书》系列 02：商家 AI 助手的评测与优化闭环实践

11/18/2026, 12:02:06 AM

📌 一句话摘要

本文详解了如何构建商家 AI 助手的评测闭环体系，从业务 SOP 拆解评测场景、收集 Bad Case 补齐边界、定义成功标准，到校准评测器、定位问题、验证优化，并借助图灵平台实现离线到线上的持续迭代。

📝 详细摘要

本文聚焦商家 AI 助手的评测与优化闭环实践。作者从业务 SOP 自顶向下拆解评测场景，将每个 Skill 转化为业务状态图，明确六类要素；同时从线上 Bad Case 自底向上补齐边界与回归。为 KA 每日巡检设计了 41 个评测场景，定义了成功判定的 Rubric，形成五维评测指标。通过校准评测器（包括确定性 Grader 和 LLM Grader），确保尺子可信。随后结合分层指标定位问题，转化为系统优化动作，验证后 Pass@k 提升显著。文章还阐述了如何借助图灵平台实现评测准备、执行判定和分析回归的可重复流程，支持离线到线上的持续迭代。

💡 主要观点

  1. 从业务 SOP 拆解评测场景，确保核心流程覆盖 将每个 Skill 还原为业务状态图，明确业务状态、数据依赖、条件分支、提前停止点、能力边界及跨 Skill 转交点，形成行为规范，为评测场景提供明确依据。
  2. 从真实 Bad Case 自底向上补齐边界与回归 收集线上使用和离线测试中的错误案例，抽象为可复用的失效模式，扩展为边界、异常和回归场景，避免评测集只覆盖预期行为。
  3. 通过校准评测器确保尺子可信 建立由业务专家确认的校准集，分别验证 Trace 解析、确定性 Grader 和 LLM Rubric 的准确性，避免用总体一致率掩盖不同环节的问题。
  4. 借助图灵平台实现评测的持续迭代闭环 将评测准备、执行判定和分析回归组织为可重复运行的流程，支持 Task 集管理、环境配置、人工质检，减少重复配置和人工操作。
  5. 从定位问题到验证优化，形成闭环改进 通过分层指标定位问题根因，转化为系统优化动作；回归验证后，Pass@k 提升显著，证明评测体系有效驱动 Agent 持续提升。

💬 文章金句

  • 我们希望这套评测体系做到三件事：可测、可信、可优化。
  • 评测器本身也会出错。OpenAI 审计 138 道难以攻克的 S[WE-bench Verified] 任务时，发现其中 59.4%存在任务描述或测试设计缺陷。
  • 只有当指标与 Trace 结论冲突、局部证据不足、同一问题随机出现，或者仍无法区分 Skill 与模型问题时，才进一步查看完整 Trace、重复执行或补充控制变量验证。
  • 一套真正有价值的业务 Agent 评测体系，不以 Task 数量、指标数量或自动化程度为终点。它的价值在于：业务问题能够被稳定复现，失败能够被快速定位，优化能够被可信验证，线上变化又能持续反哺下一轮评测和业务迭代。
