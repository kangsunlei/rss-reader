📌 一句话摘要

本期 The Batch 探讨了语音 UI 的未来，分析了泄露的 Claude Code 架构，报道了 OpenAI 退出视频生成领域的消息，并重点介绍了关于恒定延迟长上下文推理的研究。

📝 详细摘要

本期通讯刊登了吴恩达（Andrew Ng）关于语音 UI 普及化的社论，主张采用平衡低延迟与高智能的双智能体架构。深入剖析了泄露的 Claude Code 源码，揭示了一种具备三层记忆管理的复杂多智能体“操作系统”设计。此外，还涵盖了 OpenAI 决定停止 Sora 项目以专注于更具盈利能力的业务的战略决策、谷歌发布的 Lyria 3 音乐生成器，以及 Test-Time Training (TTT-E2E) 的突破性进展，该技术允许 LLM 通过实时更新权重，在恒定推理时间内处理海量上下文。

💡 主要观点

  1. 语音 UI 正转向双智能体架构，以解决延迟与智能之间的权衡问题。 通过使用前台智能体进行实时对话，后台智能体进行复杂推理和工具调用，应用程序可以同时实现响应速度和高质量输出。
  2. Claude Code 的泄露揭示了一个高度结构化的多智能体系统，旨在实现高效的上下文处理。 它利用子智能体集群、控制器智能体以及三层记忆系统（指针、Markdown 文件和转录文本）来防止上下文膨胀并保持准确性。
  3. OpenAI 停止 Sora 项目标志着从演示驱动的炒作向可持续商业价值的转变。 视频生成的高昂成本以及低于预期的订阅转化率，促使 OpenAI 将资源重新分配到世界模型和机器人技术上。
  4. 测试时训练 (TTT-E2E) 实现了长上下文的恒定时间推理。 模型不再关注整个上下文，而是在推理过程中将信息压缩到权重中，从而使其能够在不增加延迟的情况下处理多达 128k 的 token。

💬 文章金句

  • 绝大多数人发现说和听比写和读容易得多。
  • Claude Code 的构建方式与其说是一个聊天机器人外壳，不如说是一个小型、专用的操作系统。
  • 仅仅依靠 AI 演示——无论多么令人印象深刻——就足以确立领导地位的时代可能即将结束。
  • TTT-E2E……通过在推理过程中进行训练，将上下文压缩到 Transformer 的权重中。
