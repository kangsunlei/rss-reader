Codex 想让 Harness 消失，Claude Code 却要把它做成“承重墙”

9/12/2026, 3:35:00 AM

📌 一句话摘要

OpenAI 与 Anthropic 工程师就模型进步对 Harness 的影响展开辩论，揭示 AI Agent 系统中 Harness 从轻量到承重结构的演变。

📝 详细摘要

文章通过对 OpenAI Codex 团队的 Tibo 和 Anthropic Claude Code 团队的 Thariq 两位工程师的访谈，探讨了随着模型能力提升，Harness（即模型外围的工程系统）是趋于轻量还是趋于复杂。Tibo 认为 Harness 会随模型变强而变轻，因为模型能够自行理解和完成更多任务；而 Thariq 则指出，随着模型能够承担更长时间、更高自主度的工作，Harness 需要提供更复杂的安全、编排和可观测机制，如自动模式、沙箱、工作流和 Artifacts，这些正成为整个系统的“承重结构”。访谈还涵盖了 Prompting 的价值、系统提示词的精简、让模型产出“有品位”结果的方法、大规模代码审查的实践、测试与验证的重要性、算力使用的策略、以及 Anthropic 内部对知识工作、Loop Engineering 和生成式界面的探索。整体呈现了一线 AI 工程师对 Agent 系统演变的深度观察和实践经验。

💡 主要观点

  1. 模型能力提升时，Harness 呈现两极化趋势：教模型“怎么做事”的部分会变轻，而保证模型安全、长期、并行地做更多事的部分会变重。 Tibo 认为随着模型理解力增强，过去依赖 Harness 的约束和示例可以被模型自身学习取代；Thariq 则强调，当模型能够连续运行数小时并执行复杂任务时，需要更复杂的自动模式、沙箱、工作流等机制来确保安全和可控，这些正成为系统的承重结构。
  2. Prompting 的核心在于上下文准备和验证，而不仅是最后输入的那一句话。 Thariq 指出，模型看到的 Prompt 实际上包含了之前在 Harness、验证和 Skills 上投入的工作；因此，短 Prompt 能工作是因为前置工作已经完成。持续提高 Prompting 能力仍然有价值，因为它本质上是学习如何适应新模型并与模型协作。
  3. 为了让模型产出具有设计品位的结果，需要人在闭环中提供结构化参考，并提升自身的审美判断力。 Thariq 建议使用 HTML 或 Figma 等结构化文件作为参考，因为模型能直接读取其中的属性（如 border radius），而非从截图中猜测。同时，首先要成为“高品位用户”，自己能判断什么是好结果，才能有效地引导模型。
  4. 大规模代码生成需要同步的测试、验证和上下文记录，以保证可维护性和可追溯性。 Thariq 主张为每个 PR 附带 Artifact，列出所有使用的 Prompt 包括失败尝试；他认为测试代码量应比过去多约 100 倍，利用 Fixtures、Storybook 等多种验证方式，才能真正提高系统的可维护性和安全性。

💬 文章金句

  • 模型越来越强，Harness 反而需要越来越复杂，因为你要让模型能够做更多事情。
  • 自动模式、沙箱、工作流这些东西，本身都是很复杂的软件，但正在变成整个系统的承重结构。
  • Prompting 不只是你最后输入的那一句 Prompt。有时大家看到我们的 Prompt 很短，是因为我们已经在 Harness、验证和 Skills 上花了很多时间。
  • 我们发现以前必须放进工具描述里的很多示例，现在反而会产生负作用。
  • 人类得在闭环里，而且要给它参考。HTML 比截图更好，Figma 比栅格图更好，因为模型可以直接读里面的结构。
