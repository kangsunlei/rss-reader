业务逻辑的“坍塌”：当应用层只剩下胶水代码，在 AI Agent 时代，我们该构建什么

3/24/2026, 12:32:00 AM

📌 一句话摘要

本文深度探讨了 AI Agent 时代下软件架构的范式转移，分析了 LLM 不确定性的物理根源，提出 AI 开发本质上是围绕 Context 的状态管理，并预判了传统业务逻辑向模型内部「坍塌」的趋势。

📝 详细摘要

作者通过从怀疑 AI 到驾驭 AI 的心路历程，系统梳理了 AI Agent 开发的核心逻辑。文章指出 LLM 的不确定性是硬件精度、异构计算与推理成本博弈的必然结果，开发者应将其视为物理特性而非 Bug。在架构层面，AI 应用正从「无状态应用 + 有状态数据库」转向「有状态 Agent + 无状态 LLM」，开发重心由编写复杂的控制流转向 Context 管理（涉及状态压缩、显现化与结构化知识注入）。通过手搓 Agent 实践与伪代码示例，作者展示了 Prompt 工程、工具编排及异常处理的工程细节，并评价 LangChain 为 AI 界的 SSH 框架。最后，文章思考了传统微服务与 LLM 混合架构的差异，认为应用层逻辑正因模型能力的泛化而趋于「胶水化」，工程挑战正从低延迟响应转向持续交付高质量的确定性。

💡 主要观点

  1. LLM 的不确定性是换取推理效率的物理 Feature。 不确定性源于硬件浮点运算误差、MoE 路由策略及采样算法，是基座模型厂商在成本、吞吐与精确性之间博弈的结果，开发者应将其视为系统特性并在此基础上构建鲁棒性。
  2. AI 应用开发本质上是 Context 的状态管理。 LLM 是无状态的推理节点，Agent 应用则承担了有状态存储节点的角色。通过状态压缩、显现化和结构化知识注入，开发者在有限的 Token 窗口内平衡推理质量、成本与记忆深度。
  3. 业务逻辑正从应用层向模型内部「坍塌」。 传统架构靠成千上万行代码实现控制流，而 LLM 通过预训练内化了通用逻辑，导致应用层代码变得像「胶水」一样薄，工程重心从低延迟响应转向持续交付高质量的确定性。
  4. LangChain 的价值在于定义了 AI Agent 开发的语义标准化。 类比 Java 时代的 SSH 框架，LangChain 规范了 Message 定义、RAG 流程和工具调用接口，尽管其编排能力可能随基础模型演进而面临挑战，但其组件标准化贡献显著。

💬 文章金句

  • 不确定性 = f(数值精度，硬件异构，运行时架构，采样策略 等) 在物理上不可消除，也是基座模型厂商的主动选择，是一种在推理阶段为换取低成本和高吞吐而主动让渡的精确性。
  • 应用层 Agent 应用，成了有状态的存储节点，而 LLM 则是无状态的推理计算节点。
  • 在 AI Agent 时代，业务逻辑的复杂性被模型权重内化，应用层代码正变得像胶水一样薄。
  • 我们无法消除一个无法被消除的东西，只能理解并接受。
  • 所谓业务编排，本质是业务对不确定性的容忍程度 ✖️ LLM 本身能力差异整体的理解。
