从 Prompt Engineering 到 Context Engineering

12/14/2025, 12:40:00 PM

📌 一句话摘要

文章从 Prompt Engineering 进化到 Context Engineering，深度剖析 AI Agent 生态中的 MPC、Skills 和入口层，强调 Agent 从“对话”到“可靠执行”所需突破的工程化瓶颈。

📝 详细摘要

文章指出大模型的两大进步点并非语言理解与知识背诵，而是行业开始意识到聊天交互模式不足以满足 AI 作为“同事”的需求。核心矛盾在于通用大模型的静态知识与特定场景动态需求之间的错位，模型被“关在上下文窗口里”，缺乏与现实世界交互的“手脚”。为解决这一痛点，文章详细介绍了 Anthropic 的 Model Context Protocol (MCP) 和 Skills，以及 Agentic AI Foundation (AAIF) 提出的 AGENTS.md，构建了一个三层（协议层、技能层、入口层）加一个可选层（仓库/项目层）的 Agent 系统解法地图。其中，MCP 旨在统一模型与外部工具的连接，解决“M x N”集成难题；Skills 则将专家经验和流程固化为可复用、可审计的工作包，实现从“提示词工程”到“上下文工程”的转变；而 IDE、CLI、AI 浏览器等入口层则争夺“默认上下文”的主导权，确保 Agent 在一个受控、可审计的环境中高效执行任务。文章还提供了详细的 Skills 编写指南和 OpenAI 的 Skills 实际案例。

💡 主要观点

  1. AI Agent 的核心瓶颈在于模型缺乏与现实世界交互的“手脚” 大模型在现实任务中，无法直接访问、执行外部系统操作或验证结果，导致效率瓶颈，需要打破“上下文围墙”。
  2. MCP、Skills 和入口层构成了 AI Agent 解决现实世界问题的三层架构 MCP 统一连接外部工具，Skills 固化专家流程资产，入口层主导上下文和权限，三者共同将 Agent 从“对话”提升到“可靠执行”。
  3. Skills 将专家经验转化为可版本化、可复用、可审计的工程资产 通过“渐进式披露”原则，Skills 以文件夹形式组织指令、资料和脚本，实现“概率推理”与“确定执行”分离，并明确权限边界，提升 Agent 交付的可靠性。
  4. 入口层（IDE/CLI/浏览器）是 AI Agent 能力落地和控制的关键 入口层争夺的是“默认上下文”（信息采样、外部信息归档、工具调用、风险拦截、审计方式）的主导权，它决定了 Agent 与用户日常工作流的无缝集成程度和执行质量。
  5. 高质量 Skills 的编写需遵循“召回、执行、审计”三层原则 Skills 不仅仅是长提示词，更是产品级的 SOP，要求 description 精准作为索引，正文写成可执行 SOP，结合确定性工具，并内嵌风控与可维护性机制。

💬 文章金句

  • 大模型这两年最大的进步，不是多会写段子、也不是能背多少知识点，而是产品和工程开始逐渐意识到：聊天框不够用了。
  • MCP 负责把世界接进来（连接与挂载）：解决规模化集成与互操作问题。
  • Skills 负责把方法装进去（流程与边界）：解决规模化交付与可靠性问题。
  • Skill 之所以像个“小项目”，不像“提示词”，是因为它要同时服务三件事：召回、执行、审计。
  • Skill 不是“你对模型说的话”，而是“你为模型搭的环境与规矩”。
