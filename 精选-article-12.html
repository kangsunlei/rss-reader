前端仔如何在公司搭建 AI Review 系统

8/20/2025, 12:31:00 AM

📌 一句话摘要

文章详细介绍了前端开发者如何利用 Node.js 和大语言模型（LLM）从零开始搭建一个企业级的 AI 代码审查系统，涵盖了从需求分析到具体实现的全过程。

📝 详细摘要

本文旨在解决传统 Code Review 流程中效率低下和质量不高的问题，提出了一种利用 Node.js 结合大语言模型（LLM）实现自动化 AI Code Review 系统的方案。作者首先深入分析了人工 Code Review 的流程，并将其简化为程序可执行的步骤。核心实现包括：通过 GitLab Webhook 感知合并请求（MR）事件；利用 GitLab API 获取代码 Diff 内容；以及精心设计结构化提示词以指导 LLM 分析代码并输出规范的审查结果。文章还详细阐述了如何对原始 Diff 进行扩展和组装，增加文件路径和行号信息，以供 LLM 进行精确识别和定位。文中强调了提示词设计的重要性，并分享了实用的调试技巧和选择 YAML 作为结构化输出格式的优势。该系统已在作者团队内部实际应用，并取得了显著效果，有效提升了代码质量和团队效率。

💡 主要观点

  1. 自动化 AI Code Review 能有效解决人工评审的效率与质量瓶颈 在团队资源紧张、项目周期压力大时，AI 能够承担耗时且需要高度专注的 Code Review 工作，不仅提高评审效率，还能发现人工易忽略的安全、性能和逻辑问题。
  2. AI Code Review 系统核心技术栈包括 Node.js 服务、Webhook 监听 GitLab 事件，并集成 GitLab API 与 LLM 文章详细阐述了如何利用 Node.js 构建后端服务，通过配置 GitLab Webhook 实时感知 MR 提交，并调用 GitLab API 获取代码 Diff。这一技术架构是实现 AI Code Review 自动化的基础，确保了系统能高效地集成到现有开发流程中。
  3. AI 应用设计需将人为流程转化为程序步骤，并依赖提示词工程指导 LLM 核心在于模仿人工评审逻辑，梳理出 AI 可执行的流程，并通过角色设定、输入格式规范、输出限制及示例等方式，确保 LLM 准确理解任务并输出期望的结构化结果。
  4. 扩展原始 Git Diff 信息对于 LLM 进行精确代码审查至关重要 通过在 Diff 内容中加入新旧文件路径和精确行号，能帮助 LLM 准确定位问题代码，并生成可直接用于 GitLab 评论的结构化数据，提高审查的准确性和可操作性。
  5. 实践中 YAML 格式在 LLM 结构化输出方面比 JSON 更稳定可靠 作者团队发现，YAML 在处理包含特殊字符（如引号）的代码内容时，相较 JSON 更不易出现解析异常，提升了 LLM 输出数据处理的鲁棒性。

💬 文章金句

  • 让 AI 帮你做事的本质，就是让它模仿你做事。
  • 如果连你自己都不清楚具体的执行流程，就更别期待 AI 能把这个事情做好了。
  • 有时候一些很细微的安全隐患、性能、业务逻辑等问题，AI 都能比人更容易发现。
  • 我们希望 LLM 返回的是一个数组，数组的每一项是对每一个问题的描述，里面包含标题、文件路径、行号、具体的内容等，以便后续调用 GitLab API 发送评论时使用。
  • 在实践的过程中，我们发现 json 解析异常的概率会比 yaml 高很多，因为 json 的 key 和 value 是需要双引号 (" ") 包裹的，如果 issueContent 中包含了代码相关的内容且存在一些双引号、单引号之类的符号，就很容易导致报错，而且比较难通过一些替换规则进行兜底处理。
