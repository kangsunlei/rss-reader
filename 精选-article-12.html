Token 不经济

6/29/2026, 9:30:00 AM

📌 一句话摘要

文章深度剖析「Token 不经济」现象，从模型定价策略、智能体技术损耗、应用场景局限到产业链风险，系统论证了当前 AI token 投入与产出严重失衡的成因，并提出了从技术精细化管理到商业价值锚定的解决路径。

📝 详细摘要

本文以微软收回 Claude Code 许可、Uber 耗尽全年 AI 预算等事件为引，提出「Token 不经济」概念，系统分析了其多重成因。供给端方面，头部模型厂商通过分层定价抬高 token 价格，中低端模型在需求爆发中量价齐升；技术端方面，上下文陷阱、分词器黑箱、技能无效调用、多 Agent 沟通税与长程熵增等结构性损耗呈指数级叠加；应用端方面，token 的有效场景目前高度局限于编程等数字化领域，向物理世界跨越面临非对称验证成本的巨大障碍。文章进一步指出产业链风险向中游模型厂商聚集，并通过循环融资与影子信贷形成潜在泡沫，同时算力扩张对民生资源产生挤出效应。最后，文章从上下文压缩、技能优化、模型路由、预算硬约束等技术侧，以及成本纪律、配给制、场景发现等商业侧，提出回归 ROI 的价值方程式。

💡 主要观点

  1. Token 不经济由模型定价上涨、技术结构性损耗、应用场景局限三重因素叠加而成。 供给端好货不便宜，中低端模型量价齐升；技术端上下文陷阱、分词器黑箱、技能冗余、多 Agent 沟通税等导致 token 乘积性浪费；应用端 token 有效场景局限于编程等数字化领域，向物理世界跨越艰难。
  2. Agent 技能调用存在大量无效加载，绝大多数技能未带来性能提升。 研究表明近 80%的开源软件工程技能无任何通过率增益，而 token 开销最高增加 451%；技能的效用高度依赖场景匹配度，盲目调用徒增成本。
  3. 编程是大模型目前最好的应用场景，但却是一个「通用性的特例」。 编程拥有编译器提供的确定信号反馈和自动后训练闭环，而传统商业场景和物理世界缺乏这种低成本验证机制，导致 token 经济难以复制。
  4. 产业链风险向中游模型厂商集中，循环融资和私人信贷可能隐藏估值泡沫。 上游硬件厂商利润丰厚，下游企业开始控成本，中游模型厂商营收增长但深陷亏损，循环融资模式类似互联网泡沫，私人信贷市场的不透明可能放大下行风险。
  5. 解决 Token 不经济需从技术精细化管理和商业价值锚定两端入手，回归 ROI。 技术侧包括上下文压缩、技能减法、模型路由、多 Agent 预算硬约束；商业侧建立配给制与成本纪律，并寻找数字化与物理世界之间的桥梁场景。

💬 文章金句

  • 任何所创造价值超过所花费成本的投入，无论技术多么先进，终将不可持续。
  • 最有价值的 Agent，不是思维链最复杂的 Agent，而是用最少 token 把事做成的 Agent。
  • Token 不经济不是技术失败，而是技术走向大规模生产时经常遭遇的暂时困境。
  • 算法不是万能的，token 也不是。
  • Less is more 在此处不仅符合代码之美，也让 token 更经济。
