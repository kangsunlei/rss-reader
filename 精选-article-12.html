📝 详细摘要

本文详细介绍了可扩展的实时聊天系统的设计。设计借鉴了 WhatsApp 等平台的思路。它涵盖了从通信协议选择（倾向于使用混合 HTTP 进行发送，WebSocket 进行接收）到包括无状态、有状态和第三方服务的多层系统架构等基本方面。一个关键的关注点是通过“收件箱”模式以及确认机制来实现可靠的离线消息传递。讨论扩展到使用在线状态服务 (Presence Service) 和直接 RPC 调用在多个服务器之间进行高效的消息路由，以及通过扇出模型（Fan-out），即将一条消息分发给多个接收者的模式，实现群聊。在线状态跟踪是通过心跳机制实现的。本文还解决了可扩展性挑战，例如管理大量 WebSocket 连接和数据库分片，并简要介绍了消息排序、安全性、媒体处理和滥用预防等高级功能，为构建大规模聊天应用程序提供了强大的基础。

💡 主要观点

  1. 混合通信，实现高效和实时传递 使用 HTTP 发送消息、WebSocket 接收消息，有助于优化系统的可扩展性和消息的即时推送，从而有效平衡资源利用。
  2. 分层架构，实现可扩展性和弹性 系统采用分层架构，包括无状态层、有状态层和第三方集成层。这种架构允许独立扩展各个组件，并能利用外部服务来执行推送通知等特定任务。
  3. 收件箱模式，实现可靠的离线消息传递 离线用户的消息存储在专用的收件箱队列中。用户重新连接后，系统会传递这些消息，并结合确认机制，保证消息的持久性和可靠性。
  4. 服务发现和直接 RPC，实现多服务器路由 在线状态服务跟踪用户与服务器的映射关系。这使得大规模分布式系统中，聊天服务器之间能够进行高效的直接通信，从而实现低延迟的消息转发。
  5. 心跳机制，实现准确的在线状态跟踪 客户端定期发送 ping 帧。服务器通过记录时间戳来判断用户在线状态，从而有效过滤临时网络中断。

💬 文章金句

  • WebSocket 提供了更优化的解决方案。在 HTTP 握手之后，连接升级为持久的双向通道，从而使服务器可以随时将消息推送到客户端。
  • 每个用户都有一个专用的收件箱队列，用于存储待处理的消息。当用户离线时，发送给他们的消息会暂时存储在其收件箱中。
  • 最具可扩展性的方法是将服务发现与直接服务器到服务器的通信相结合。
  • 对于在线成员，服务器使用 RPC 调用立即将消息扇出到其各自连接的服务器；对于离线成员，该消息存储在其各自的收件箱中。
  • 如果服务器在 60 秒内未收到任何 ping，则会将用户标记为离线。此方法有效地过滤掉了由网络波动引起的临时断开连接。
