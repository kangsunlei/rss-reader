DeepSeek Harness 实测：模型之外的 Agent 平台脚手架

8/15/2026, 1:30:00 AM

📌 一句话摘要

本文深度测评了开源 Agent 框架 DeepSeek Harness，分析其作为可重组 Agent 运行时的架构优势、插件机制及与竞品 Kimi Code 的差异，并探讨了其在生产环境中的应用边界。

📝 详细摘要

文章对 DeepSeek 最新开源的 Agent 框架 DeepSeek Harness (DSH) 进行了深度技术测评。作者通过本机实测与对比分析，指出 DSH 目前更像是一个开放的 Agent 平台脚手架，而非开箱即用的终端编码工具。文中详细拆解了 DSH 的核心架构，包括基于 Cordis 的插件生命周期管理、基于事件流的 Trajectory 可观测性设计以及灵活的 Preset 机制。通过与 Kimi Code 的对比测试，作者展示了两者在运行时组织与扩展性上的不同侧重，并结合实际开发案例（跳一跳游戏）验证了 DSH 在复杂长任务中的表现。文章最后为开发者提供了关于如何利用 DSH 进行领域 Agent 定制、模型评测及生产环境治理的建议。

💡 主要观点

  1. DeepSeek Harness 本质是可重组的 Agent 运行时。 DSH 采用插件化架构，将 Agent Loop、工具、会话管理与 UI 拆解为可替换的模块，适合开发者构建定制化领域 Agent，而非单纯的编码辅助工具。
  2. Trajectory 与事件流设计提升了可观测性。 DSH 通过追加式事件日志重建模型请求，使得开发者能清晰追踪模型上下文、工具调用轨迹及 token 消耗，解决了 Agent 运行过程中的“黑盒”问题。
  3. 与 Kimi Code 在定位上存在显著差异。 Kimi Code 侧重于开箱即用的终端编码体验，而 DSH 侧重于底层架构的开放性与可编程性，允许开发者深度定制执行环境与工具链。
  4. 生产接入需补全治理能力。 尽管 DSH 架构先进，但插件来源、凭证边界、日志保留及数据外发等治理工作仍需部署方自行承担，目前更适合研究与小范围实验。

💬 文章金句

  • DSH 现在更像是一个开放的 Agent 平台脚手架，默认产品还带着预览版的毛边，留待社区的打磨。
  • DSH 要求模型看见的内容必须已经记进日志，Trajectory 直接从 session event log 投影。它没有另埋一套监控数据，所以看见的轨迹更接近模型当时收到的真实请求。
  • 如果目标是日常终端编码，Kimi Code 的安装和默认工具更省事。如果目标是研究上下文、替换 provider、定制领域 Agent 或复现实验，DSH 的插件树与事件日志更好用。
