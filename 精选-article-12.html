国产算力·昇腾 910C 大模型推理优化（上）：镜像更新与参数调优，提速 40%

10/21/2026, 10:30:00 AM

📌 一句话摘要

本文总结了在华为昇腾 910C 上对大模型进行推理优化的实践经验，通过镜像升级、参数调优和源码修改等 20 余项措施，显著降低 TPOT 延迟，为国产算力在线推理提供可复用的工程参考。

📝 详细摘要

文章围绕华为昇腾 910C 国产算力的大模型在线推理优化展开，首先对比了昇腾 NPU 与英伟达 GPU 的架构差异，并建立 Qwen3.5-35B-A3B 等模型的性能基线。通过 MindStudio 性能剖析，识别出 host 调度、集合通信、HBM 带宽、图模式编译等六大瓶颈。优化实践从易到难逐层推进：升级 vllm-ascend 与 CANN 版本，设置 HCCL_OP_EXPANSION_MODE=AIV、开启静态 kernel 预编译、调优 HBM 分配器、替换 jemalloc、配置算子缓存与 batch memcpy、实现 MoE 权重预取、调整 HCCL 通信参数与 CPU 绑定，以及优化 cudagraph 模式与 warmup 次数。文章还详细记录了十余项实测无效或负向的尝试，强调“每模型必实测”的方法论。最终在 910C-560t 上，TPOT 较基线下降 45%以上，开启 MTP 投机解码后 c=1 TPOT 达 5.0ms，验证了国产算力在在线推理场景的可行性。

💡 主要观点

  1. 昇腾 910C 与英伟达 GPU 的架构差异及在线推理瓶颈 文章对比了昇腾 NPU 与英伟达 GPU 的软硬件架构，指出昇腾在 prefill 阶段占优，但 decode 阶段 TPOT 较高，是在线场景的主要瓶颈。通过 Profile 分析，识别出 host 侧调度开销、集合通信、HBM 带宽、图模式编译等六大类性能瓶颈。
  2. 镜像升级与基础参数调优的快速收益 升级 vllm-ascend 至 0.23.0rc1 和 CANN 至 9.1.0，直接获得 15%以上的性能提升。通过设置 HCCL_OP_EXPANSION_MODE=AIV 将集合通信下沉到 AIVector、开启静态 kernel 预编译、调优 HBM 分配器（虚拟内存映射+大页+pin_memory）、替换 jemalloc、配置 ACLNN_CACHE_LIMIT 和批量 memcpy 等措施，在不修改源码的情况下显著降低 TPOT。
  3. 针对 MoE 模型的专项优化 针对 Qwen3.5-35B-A3B 的 MoE 架构，将权重预取阈值从 96 改为 1，使低并发 decode 也能触发预取；扩展 shared expert 预取，利用计算时间掩盖权重加载延迟；结合多流重叠，改善 c=4/8 时的 TTFT 和 TPOT。
  4. cudagraph 配置与通信参数的精细调优 采用 FULL_DECODE_ONLY 模式，针对 MTP 投机解码调整捕获尺寸；将 cudagraph warmup 次数从 1 提升至 3，减少首次执行开销。固化 HCCL 参数（如 HCCL_BUFFSIZE=128、关闭确定性归约）和 CPU 绑定，提升通信效率。
  5. 实测避坑与方法论总结 文章记录了多项实测无效或负向的参数尝试（如 MatmulAllReduce、FlashComm 在 910C 上支持不完整），指出昇腾环境变量与 SoC 型号、CANN 版本强耦合，文档推荐值不能替代实测，强调建立“每模型必实测”流程的重要性。

💬 文章金句

  • 当前国内 NVIDIA GPU 供给持续紧张，H20 已无新增算力供给，核心业务算力的国产化替代已迫在眉睫。
  • 在线实时推理场景中，由于业务对响应时间（RT）要求较为严苛，直接部署大参数模型会导致 RT 无法满足 SLA，因此 910C 暂时无法直接替换现有在线服务。
  • c=1 decode 时 MoE 层的 GroupedMatmul 是带宽受限的：专家权重体量远大于激活数据，每个 step 都要从 HBM 读取。
  • 优化的另一半工作是证伪。
  • 建立「每模型必实测」的流程比记住任何具体参数都重要。
