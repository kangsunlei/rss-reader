YC CEO：顶级 Builder 已经开始用 AI 做 400 个工程师的活丨 Y Combinator

5/10/2026, 12:46:00 PM

📌 一句话摘要

YC CEO Gary Tan 分享了他如何通过 Claude Code、GStack 和 Agent 工作流，以 200 美元和 5 天时间完成过去需要 400 万美元和 18 个月的项目，并详细拆解了 tokenmaxxing、多模型分工、浏览器 QA 等核心实践。

📝 详细摘要

本文是对 YC CEO Gary Tan 在 Y Combinator 播客中分享的 AI 工作法的深度总结。Gary 详细阐述了他如何利用 Claude Code、Codex 和自建的 GStack 工具链，在 13 年未写代码后，重新成为一名高效的 Builder。他提出了「tokenmaxxing」理念，主张在关键环节不惜 token 成本以获取更完整的上下文和更高质量的输出。文章核心内容包括：将复杂任务拆解为可自动化的环节（如 Gary's List 的写作流程）、通过多模型分工（Claude 做 CEO，Codex 做 CTO）提升效率、强制要求 80%-90% 的测试覆盖率、以及用浏览器 QA 工具消灭手动验证瓶颈。Gary 强调，AI 工具如同法拉利，需要懂技术的机械师来驾驭，而个人对 AI 工具的控制权将成为未来的分水岭。

💡 主要观点

  1. Tokenmaxxing 是核心方法论，主张在关键环节不惜 token 成本以获取更完整上下文。 Gary 认为，节省 token 可能意味着丢失关键上下文、测试和质量。他将 token 花费类比为 YC 创始人租房的「房租」，是能放大判断力的必要投资，而非可省的办公成本。
  2. 多模型分工协作，Claude Code 与 Codex 分别扮演 CEO 和 CTO 角色。 Claude Code 擅长发散、组织和推进产品，如同 ADHD CEO；Codex 则擅长处理硬核复杂问题，如同 200 IQ 的 CTO。通过 GStack 工具链，两者可以互相调用，实现优势互补。
  3. 强制测试覆盖率达到 80%-90%，避免 AI 生成代码的「slop」风险。 Gary 指出，Vibe Coding 容易让 80% 的场景跑通，但边界情况极易崩溃。没有充分测试的 AI 代码比人类写的烂代码更危险，因为其失败边界不可预测。
  4. 通过浏览器 QA 工具消灭手动验证瓶颈，实现全流程自动化。 面对 15 个功能排队等待手动测试的瓶颈，Gary 让 Claude Code 封装 Microsoft Playwright，自动检查 UI 或数据变更，将人工从重复的浏览器验证中解放出来。

💬 文章金句

  • 第一次花了 400 万美元和一年半，这次花了 200 美元和 5 天。
  • 如果有增量工作能让东西更完整、更好，你就应该 token max。
  • Claude Code 适合 ADHD CEO，Codex 像 200 IQ 的 CTO。
  • 这像一辆法拉利，但你最好也是个机械师。
  • 问题是，你控制工具，还是工具控制你。
