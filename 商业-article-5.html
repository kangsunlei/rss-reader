AI Agent 时代的「AWS」：Manus 背后的重要功臣 E2B 是何来头？

5/19/2025, 12:18:00 PM

📌 一句话摘要

深入分析 AI Agent 基础设施提供商 E2B 如何构建安全沙盒环境，旨在成为 Agent 时代的"AWS"。

📝 详细摘要

文章详细介绍了 E2B 公司及其核心产品，一个为 AI Agent 提供安全、隔离云端沙盒环境的基础设施平台。E2B 起源于开发者工具，因应 Agent 发展趋势，从代码解释器转型为更通用的 Agent 运行时环境。它基于类似于 AWS Firecracker 的 MicroVM 技术，提供快速启动的沙盒，Agent 可在其中运行代码、使用浏览器、调用操作系统工具。文章探讨了 Agent 需要专属运行环境的原因，E2B 如何解决安全性、权限自由度、隔离性等挑战，并重点介绍了数据分析、AI 应用运行平台及模型训练等核心使用场景。E2B 旨在成为 AI Agent 基础设施领域的领导者，提供中立于特定 LLM 的解决方案，并通过 Persistence、Forking、Checkpointing 等功能增强 Agent 能力。最后，文章还分析了 Agent 框架的选择以及在硅谷创业的考量。

💡 主要观点

  1. AI Agent 执行动态代码和复杂任务需要安全隔离的云端环境。 Agent 运行代码和操作电脑存在安全风险，E2B 提供快速启动、安全隔离的 MicroVM 沙盒，解决 Agent 执行环境的安全性与灵活性需求。
  2. E2B 从代码解释器演进为通用 Agent 运行时，支持多样化应用场景。 随着 Agent 能力提升和落地，E2B 拓展功能，支持数据分析、AI 应用生成、甚至是 AI 模型训练等复杂任务，成为更通用的 Agent 执行平台。
  3. E2B 愿景是成为 Agent 时代的 AWS，提供基础设施而非绑定特定 LLM。 专注于 Agent 所需的计算、存储、治理等底层能力，保持对不同 LLM 的中立性，提升开发者体验和应用的可迁移性。
  4. 实现 Agent 对电脑的 Computer Use 功能面临多重技术挑战。 模拟鼠标点击、理解屏幕画面（视觉推理）、安全隔离、部署小众模型及实时画面流传输等是关键挑战，API 控制优先于视觉模拟。
  5. 持久化、分叉和检查点功能是提升 Agent 能力和体验的关键。 通过 Persistence 保留 Agent 中间状态，未来的 Forking 和 Checkpointing 将支持 Agent 并行探索不同路径，提高任务完成效率和可靠性。

💬 文章金句

  • E2B 本质上是一个可以快速启动（~150 毫秒）的 microVM，它的底层类似于 AWS Firecracker 这个代表性的 MicroVM。
  • Vasek 表示，团队一开始就意识到了代码执行是 agent 技术栈中至关重要的一环。代码就像是一种通用语言，可以作为连接一切的粘合剂...
  • Vasek 希望 E2B 能成为 AI agent 时代的 AWS，成为一个自动化的 infra 平台，未来可以提供 GPU 支持，满足更复杂的数据分析、小模型训练、游戏生成等需求，并可以托管 agent 构建的应用，覆盖 agent 从开发到部署的完整生命周期。
  • Vasek 认为，下一个 agent 真正能工作起来的场景是：让 agents 控制电脑或者浏览器。
  • James 在整个开发过程中一直在思考一个问题：AI agent 到底应该尽量通过 API 控制，还是靠视觉去模拟人类点击？答案其实很清楚：有 API 的时候，尽量用 API。
