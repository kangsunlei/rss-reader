系统设计 Day 21：短链接服务架构解析

10/18/2026, 2:02:41 AM

📌 一句话摘要

深入解析短链接服务的分布式 ID 生成、Base62 编码原理、读写分离策略及面试官常考的技术权衡点。

📝 详细摘要

作为「60 天学系统设计」系列的第 21 部分，本文详细拆解了短链接服务（如 TinyURL）的系统设计。核心内容包括：1. API 定义（生成与重定向）；2. 唯一 ID 生成与 Base62 转换逻辑，解释为何 7 位 Base62 足以支撑海量数据；3. 技术选型对比：哈希冲突处理 vs Base62 唯一性、301 vs 302 重定向的利弊、读多写少场景下的缓存策略；4. 存储估算与安全漏洞（ID 枚举攻击）。最后提出了关于自定义短码冲突的思考题。

💡 主要观点

  1. Base62 编码在短链生成中的应用 利用 Base62 将分布式 ID 转换为短码，相比哈希方法避免了碰撞问题，且能保持短码长度随 ID 增长的自然规律。
  2. 高并发读写场景的优化策略 针对读远多于写的特征，采用缓存热点短链、数据库回源的架构，并讨论了 301/302 状态码对业务统计的影响。
  3. 安全与扩展性考量 指出了连续 ID 带来的枚举安全风险，并提出了加盐或随机化解决方案，同时探讨了自定义短码的冲突处理机制。
