有人每月烧掉 1 万美元，嫌 Claude 太贵，这家公司改用 GLM：56 张 B200 扛起 2000 名工程师，AI 成本直降 90%

11/5/2026, 4:08:32 AM

📌 一句话摘要

Revolut 通过自托管智谱 GLM 模型替代 Claude 和 Gemini，AI 编程成本直降 90%，为 2000 名工程师提供持久成本控制的解决方案。

📝 详细摘要

英国金融科技公司 Revolut 起初尝试了 Gemini 和 Claude Code 等商业 AI 编程工具，但部分工程师月支出高达 1 万美元，效率提升不明显。为控制成本，Revolut 转向自托管智谱 GLM 系列模型（GLM-5.1 升级至 GLM-5.3），部署 56 张英伟达 B200 GPU 支撑约 2000 名工程师使用。实施后，AI 编程推理成本下降约 90%，编码时间缩短 60%，交付周期缩短 70%。通过推理系统优化（NVFP4 量化、Prefill-Decode 分离、KV Cache 优化等），首 Token 延迟从 14.26 秒降至 1.68 秒，提升 76%。Revolut 认为 25.6 万 Token 上下文足够实际需求，避免浪费。同时采用模型路由机制，将文本任务交给 GLM，视觉任务交给 GPT/Gemini。

💡 主要观点

  1. Revolut 通过自托管 GLM 模型将 AI 编程成本降低 90%。 相较于 Claude Code 等商业服务，GLM-5.1 的输入输出 Token 成本仅为商业服务的十分之一，整体推理支出降至约 1/10，为 2000 名工程师提供持久的成本控制。
  2. GPU 部署规模与推理优化是支撑大规模使用的关键。 部署 56 张 B200 GPU 支撑 GLM-5.3（约 7540 亿参数）的 7540 亿参数模型，通过 NVFP4 量化、Prefill-Decode 分离等优化，将首 Token 延迟从 14.26 秒降至 1.68 秒，提升 76%。
  3. 实际工程师时间消耗不仅限于编码，AI 需覆盖更多琐碎工作。 Revolut 数据显示，编码时间缩短 60%、交付周期缩短 70%，这不仅源于模型写代码更快，更因 AI 接管 Bug 排查、Jira 工单、Confluence 文档等零散任务，释放了工程师的核心产出时间。
  4. 模型路由实现不同任务的最优模型分配。 Revolut 构建模型路由机制，将代码生成、文本处理等任务优先交给自托管 GLM，图片识别、视觉理解等任务交给 GPT/Gemini，充分发挥不同模型的专长。
  5. 超长上下文并非生产力必需，实际需求决定配置。 Revolut 认为 25.6 万 Token 上下文足够实际需求，避免为 100 万 Token 预留资源导致 KV Cache 浪费，更关注上下文复用和实际任务匹配。
