BSave - 数据切面工程在字节的大规模实践

2/10/2026, 9:02:00 AM

📌 一句话摘要

字节跳动通过 BSave 系统落地“数据切面工程”，在存储边界构建透明操作层，实现大规模、零侵入的数据加解密、压缩及治理能力。

📝 详细摘要

本文深入探讨了字节跳动自研的数据切面工程系统 BSave 的设计理念与大规模实践。该系统核心思想是在业务与存储之间建立透明的操作层，将加解密、压缩、审计等通用逻辑从业务代码中剥离，实现“零代码改造”的数据治理。文章详细介绍了基于 Sidecar 模式的在线切面（BSaveAgent）、流批一体的数据同步切面（BTube）以及基于计算引擎改写的离线切面。同时，分享了在超大规模 QPS 场景下，如何通过对象池化、流式处理、Fast Path 等技术手段将 P99 延迟控制在 1ms 以内，并构建了自动化的插件管理体系以保障上千个服务的发布一致性与稳定性。

💡 主要观点

  1. 数据切面工程的核心是存储边界的透明化处理。 通过在业务与存储间引入透明层，将加解密、压缩等通用操作从业务逻辑中剥离，使业务无需投入编码即可实现合规与成本治理。
  2. 在线切面采用 Sidecar 模式实现语言无关的统一治理。 借鉴 Service Mesh 理念，通过 Sidecar 劫持流量并进行协议解析与插件编排，在不改动业务代码的前提下增强了存储访问的安全性与可控性。
  3. 针对超大规模场景实施了深度的架构级性能优化。 通过 Recycle 架构回收对象、Channel 流式化及 Fast Path 过滤，成功将 Sidecar 引入的 P99 延迟增量控制在 1ms 以内。
  4. 构建了标准化的插件管理体系以保障发布稳定性。 将插件变更收敛为自动化基建，通过事前拦截、事中监控、事后应急三道防线，解决了上千个服务在大规模发布时的一致性与容量风险。
  5. 离线切面通过计算引擎插件机制实现透明加解密。 在 Spark/Flink 等计算层构建 Plan 改写层与 Data 处理层，利用执行计划优化避免重复计算，显著提升了数仓敏感数据的处理时效。

💬 文章金句

  • 数据切面工程的核心思想是在数据存储的边界引入对业务透明的操作层，将原本需要业务关注的通用数据操作，转移到一系列透明操作层中。
  • Sidecar 的‘与业务隔离、语言无关、统一治理’优势，远大于 SDK 方案的‘信息完整度’优势。
  • 数据访问层的本质，是在业务效率与数据治理之间寻找平衡点。过去，这两者常常对立；BSave Agent 试图证明：通过架构创新，治理与效率可以兼得。
  • 将插件的接入、发布、升级从分散的手工流程，统一收敛为一套自动化、可灰度、可回滚的标准化基建，让插件的变更像‘配置开关’一样简单可控。
  • 数据流动的终点，是业务价值的起点。BTube 的故事，是一个在安全、效率、成本‘不可能三角’中寻找最优解的工程故事。
