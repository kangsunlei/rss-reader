AI 有了“工号”，数据平台长出了手：Snowflake World Tour 上的三个变化

9/22/2026, 11:48:00 AM

📌 一句话摘要

作者以 Snowflake World Tour 参会者视角，从 Agent Identity、数据平台从记录走向行动、Snowflake 拥抱开源三个细节，判断数据平台正重新定义自身在 Agent 时代的边界。

📝 详细摘要

本文是白鲸开源创始人郭炜参加 Snowflake World Tour Shanghai 后的参会观察。作者指出，Agent、Semantic、Ontology 等概念已让行业大会高度同质化，但本次有三个细节值得记录。第一，AI 开始有「工号」：Agent 需要 Agent Identity、Agent Policy、预算与审计，成为可识别、授权、限制、计费和审计的执行主体，这是 Agent 真正进入企业的分水岭。第二，数据平台开始「动手」：链路从 Reality→Data→Analytics→Human→Action 变为 Reality→Data→Agent→Action→Reality，数据平台从 System of Record 走向 System of Action，产品边界向 Application 层蔓延，Identity、Policy、Governance 因此变得关键。第三，Snowflake 主动拥抱开源：通过 Apache Polaris 拆 Catalog 的墙、Apache Ossie 拆 Semantic 的墙，平台护城河逻辑可能从 Lock-in 转向 Interoperability。作者认为三者指向同一方向：数据平台公司的边界正在变化。

💡 主要观点

  1. Agent Identity 让 AI 从匿名模型变成企业正式管理的执行主体。 Agent 可读 Inbox 却未必能写、可访问数据却不能外搬，企业需要配置 Agent Identity、Agent Policy、预算与成本控制。过去 Copilot 由人按下按钮、责任在人，而 Agent 代表企业行动后必须可识别、授权、限制、计费和审计，因此作者认为其进入企业的分水岭是 IAM、FinOps、Security、Audit 系统中第一次出现它的名字。
  2. 数据平台正从记录世界走向修改世界，链路从人做决定变为 Agent 闭环行动。 传统链路是 Reality→Data→Analytics→Human→Action，数据仓库本质是记忆系统；当 Agent 能读取企业数据并反过来调用业务系统，链路变为 Reality→Data→Agent→Action→Reality。这使数据平台产品边界向 Application 层蔓延，与 Salesforce、Workday 等 SaaS 的边界被冲淡，人的角色从每步参与变为关键节点授权与处理例外。
  3. Snowflake 主动拥抱开源，用 Polaris 和 Ossie 拆掉 Catalog 与 Semantic 的墙。 Christian Kleinerman 明确表示不希望客户因技术无法离开而留下。Apache Polaris 是面向 Iceberg 的开放 Catalog，2026 年从 Apache Incubator 毕业，让 Snowflake、Spark、Trino、Flink 围绕同一套 Catalog 协作；Apache Ossie 前身 Open Semantic Interchange，2026 年进入 Apache Incubator，开放的是「数据是什么意思」，让不同 BI、AI、Data 工具交换同一套业务语义。
  4. 平台护城河逻辑可能从 Lock-in 转向 Interoperability。 上一代平台靠「我拥有的数据越多，你越难离开我」建立护城河；下一代可能靠「即使数据不属于我，我依然能连接、理解、治理它，并让 Agent 安全工作」。作者认为当客户随时可以走却依然选择留下，才是更强的平台能力，Snowflake 是在赌这一新逻辑。

💬 文章金句

  • 「工号」不是 AI 的拟人化，而是 AI 的制度化。
  • Data Warehouse 过去负责记录世界，Agent 开始让数据平台有能力修改世界。
  • Agent 时代，平台越想成为中心，越不能成为孤岛。
  • 上一代平台靠 Lock-in 建护城河，下一代平台可能靠 Interoperability 建护城河。
  • 当 Agent 真正进入企业以后，Data Platform 到底还会不会只是 Data Platform？
