梁神变牢梁的原因找到了！疑似 DeepSeek 发错模型，HF 配置和 API 后台紧急切换

8/16/2026, 2:15:00 AM

📌 一句话摘要

DeepSeek-v4-pro-0813 上线一天内口碑两极分化，通过 Hugging Face 仓库记录与 API 指纹变化，揭示其前端接口、后端推理栈与权重配置出现严重错位，疑似发布流程事故。

📝 详细摘要

DeepSeek-v4-pro-0813 正式版于 8 月 13 日凌晨上线，官方跑分显示 Terminal-Bench 2.1 得分 87.9，逼近 Claude Fable 5 的 88.0 分，引发全网期待。然而实测党接入真实业务流后发现体验极不稳定，Artificial Analysis 综合得分仅 53 分，与 V4 Flash 差距微弱，网络安全扫描等场景误报率偏高。当天下午官网撤下公告，疑似回滚。文章通过 Hugging Face 仓库提交记录发现：初始 config.json 中 hidden_size、路由专家数等参数与 V4 Flash 完全一致，后被修正；SHA256 校验码变化表明二进制权重文件也被替换；API 后台 system_fingerprint 从可读格式突变为纯 32 位 Hash，对应推理后端的热切换。结论认为，此次混乱并非单纯性能翻车，而是前端接口、后端推理栈与权重配置三者错位所致，对万亿参数模型的 Infra 能力提出警示。

💡 主要观点

  1. 官方跑分与实测体验严重脱节。 Terminal-Bench 2.1 跑分 87.9 接近 Fable 5，但 Artificial Analysis 实测仅 53 分，真实业务流中稳定性不足，误报率偏高。
  2. HF 仓库记录显示配置与权重均被紧急修正。 初始 config.json 参数与 V4 Flash 一致，后被修正为 V4 Pro 架构；SHA256 校验码变化表明二进制权重文件也被重新上传。
  3. API 指纹突变印证推理后端热切换。 system_fingerprint 从可读格式突变为纯 32 位 Hash，对应线上推理栈、部署版本或算力调度策略的彻底重构。
  4. 发布混乱本质是前端、后端与配置的三重错位。 不同时间、不同入口的开发者拿到体验不在同一频道，反映万亿参数模型对 Infra 能力的极限考验。

💬 文章金句

  • 有理由相信，昨天的发版混乱并非简单的模型翻车，极有可能是因为 DeepSeek 的前端接口、后端推理栈与权重配置三者出现了严重的错位。
  • 当模型体量迈入万亿参数级别，任何微小的配置错位都可能在 Infra 层被无限放大，最终在前端体验上砸出巨大的坑。
