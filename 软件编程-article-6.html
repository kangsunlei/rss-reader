两个 Token 就让 Kimi“变成”Claude？前 Google DeepMind 研究员意外撞上中国大模型的蒸馏疑云

9/8/2026, 4:04:00 AM

📌 一句话摘要

前 Google DeepMind 研究员发现前沿大模型的加密推理可被重放和窃取，两个 token 前缀即可让 Kimi 的答案风格变为 Opus，导致隐私泄露和蒸馏攻击风险。

📝 详细摘要

文章基于 Ilia Shumailov 与 Alexander Panfilov 在 Machine Learning Street Talk 的访谈，揭示了前沿大模型在返回加密推理块后可被解码并在同家族小模型中重放的漏洞。研究者从公开的 GitHub 与 Hugging Face 轨迹中解码出约 31.5 万条隐藏推理，发现其中包含 API 密钥、邮箱、内部 IP 等敏感信息。更为诡异的是，仅在 Kimi‑K3 推理开头预填充两个来自 Opus 的 token，即可让可见答案的风格与 Opus 完全相似，暗示模型间可能存在蒸馏或共享机制。文章讨论了该漏洞的危害、可能的防御措施（如不向用户返回推理块、链式加密等），并说明研究者已向相关实验室负责任披露。

💡 主要观点

  1. 加密的推理轨迹可以被解码并在小模型中重放，导致跨模型信息泄露。 研究者从公开的 Agent 轨迹中提取约 31.5 万条加密推理块，解码后发现其中包含 API 密钥、邮箱、内部 IP 等敏感信息，说明加密并未阻止信息泄露。
  2. 仅预填充两个 token 即可让 Kimi‑K3 的答案风格变为 Opus，暗示模型间共享或蒸馏痕迹。 实验表明，在 Kimi 推理开头注入 2 个来自 Opus 的 token，生成的可见答案在风格和长度上与 Opus 完全一致，而其他模型（GLM、DeepSeek 等）未出现此现象。
  3. 泄露的推理块包含用户隐私和内部系统信息，构成严重安全风险。 案例显示，模型在思考阶段会“想”出 API 密钥、内部 IP 等信息，即使对话明文已被清理，攻击者仍可通过解码推理块恢复这些秘密。
  4. 修复的最直接手段是停止向用户返回推理块或采用链式加密等机制。 作者建议若不需要推理可视化，直接不返回；若必须返回，则使用只能一次性使用的链式加密，防止在随机上下文中被重放。
  5. 研究者已向相关实验室负责任披露，厂商正在评估并部署缓解措施。 访谈中提到，OpenAI、Anthropic、Google 等已收到报告并在考虑系统层面、模型层面的防御方案。

💬 文章金句

  • 只预填充 2 个推理 token 就足以让可见部分的答案发生变化——答案开始看起来像 Opus 模型的回答。
  • 这些模型把思考过程加密，像密封信封一样交还给你。
  • 只要加密推理块还在，我可以从 GitHub 下载，解码，看到模型当时在想什么密码。
  • 最简单的办法：干脆别把推理过程发给用户。
  • 我们只需要使用同一模型家族中较小的 LLM 就能做到。
