保障 SaaS to SaaS 应用数据安全

9/24/2025, 2:00:01 PM

📌 一句话摘要

Cloudflare 提出基于代理和密钥拆分的解决方案，保护 SaaS to SaaS 集成，解决安全漏洞和数据泄露风险。

📝 详细摘要

本文着重强调了 SaaS to SaaS 集成带来的关键安全漏洞，Salesloft 漏洞事件便是例证。Cloudflare 提出通过单一代理整合所有 SaaS 连接的方案。讨论了两种部署方式：一是数据所有者通过自定义主机名控制访问；二是 SaaS 平台集成 Cloudflare 以增强 API 安全性。“密钥拆分”技术将授权令牌加密拆分为不可用的片段，确保所有 API 调用都经过 Cloudflare 的监控，从而实现安全的令牌管理和即时撤销。该方案旨在提供对第三方集成访问数据的前所未有的可见性和控制力，最大限度地降低大规模数据泄露风险。

💡 主要观点

  1. SaaS to SaaS 集成带来显著的安全漏洞和数据泄露风险。 SaaS 应用及其市场的激增导致数据流复杂化，安全团队难以有效监控，使其容易遭受如 Salesloft 事件的攻击。
  2. Cloudflare 提出基于代理的解决方案，以集中监控和控制 SaaS to SaaS 流量。 Cloudflare 作为 SaaS 连接的反向代理，为数据所有者和 SaaS 平台提供可见性、异常检测和即时访问撤销能力。
  3. 密钥拆分技术实现了安全的令牌管理，并在不存储完整凭据的情况下增强了控制。 授权令牌被拆分为两个片段，需要 Cloudflare 的代理进行重组。这确保所有 API 调用都受到监控，并通过删除其中一个片段实现即时撤销。

💬 文章金句

  • Salesloft 漏洞事件表明，SaaS 应用间的连接难以监控，给安全团队带来盲区和灾难性后果。
  • Cloudflare 能够代理客户控制的 *任何* 主机名。
  • 密钥拆分以加密方式将授权令牌分成两个数学上相互依赖的片段，分别称为 Part A 和 Part B 。
  • 这创建了一个无法绕过的控制点。集成在不通过 Cloudflare 代理的情况下无法发起 API 调用，因为它们只拥有 Part A 。
  • 这从根本上改变了安全模式，从保护完整令牌转变为管理独立的无用片段。
