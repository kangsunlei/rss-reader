面向人机交互设计 Harness：构建以产物为中心的 Agent Loop

8/23/2026, 2:51:00 AM

📌 一句话摘要

本文探讨了在人机协作中，当工作对象从代码扩展到多种可执行产物（如 PPT、网页、3D 模型）时，如何将交互重心从对话转移到产物本身，构建一个以产物为中心的 Agent Loop，使人与智能体能够围绕同一份可持续演化的工作现场展开协作。

📝 详细摘要

文章首先分析了当前以对话为中心的智能体闭环的局限性，指出当用户开始直接操作产物时，对话无法完整记录工作现场。随后，作者提出了以产物为中心的 Agent Loop 概念，强调产物本身应成为协作的中心，并以网页和 Canvas 示例说明了这一转变。最后，文章详细阐述了 Harness 在这一新模式中的角色，包括维护任务意图、绑定操作版本、支持多元产物运行时，以及保留可检查的验证证据，从而构建一个统一的协作环境。

💡 主要观点

  1. 对话无法完整记录工作现场 在以对话为中心的模式中，一旦用户开始直接操作产物（如修改 PPT 或移动网页元素），这些变化不会被对话记录，导致智能体在下一轮交互时无法准确理解当前状态。
  2. 产物本身成为协作中心 以产物为中心的 Agent Loop 意味着人与智能体围绕同一份可执行的产物展开协作。产物不仅是最终结果，更是承载工作现场的载体，允许双方直接修改和验证。
  3. Harness 的核心功能 Harness 需要维护持续变化的任务意图、将操作绑定到具体的产物版本、支持不同领域的产物运行时，并记录可检查的验证证据，从而确保协作的连贯性和准确性。

💬 文章金句

  • 当人与智能体共同面对的是一份会被持续修改、审阅和交付的工作产物时，我们还应该把对话当作人机交互的中心吗？
  • 一旦人开始直接操作产物，对话就不再拥有完整的工作现场。
  • Harness 要维护的，正是这些操作背后的意图、版本和验证关系。
