Grafana 11 主要版本发布幕后：通往 Grafana 11 的历程及未来展望

6/30/2025, 3:06:01 PM

📌 一句话摘要

本文深入剖析 Grafana 11 的开发历程及核心功能，并展望 Grafana 12 的未来发展方向。

📝 详细摘要

本文深入探讨了 Grafana Labs 重大版本发布 Grafana 11 的幕后开发历程，其主要目标有三：增强数据探索与可视化能力、提升可扩展性以及通过插件增强可扩展性。关键功能包括 Explore Metrics 和 Explore Logs，它们简化了查询流程，无需深入了解 PromQL 或 LogQL 即可轻松进行数据查询和可视化；此外，新增的子文件夹功能也提升了仪表盘管理效率。云迁移应用则简化了向 Grafana Cloud 的迁移过程。文章还阐述了这些功能背后的挑战和应对策略，例如专注于特定数据源和进行广泛的后端重构。社区反馈和内部黑客马拉松是创新的重要驱动力，而从 Angular 迁移到 React 也使 Grafana 的前端架构焕然一新。展望未来，文章还预告了 Grafana 12 的潜在功能，以及持续改进用户体验和功能的努力。

💡 主要观点

  1. 通过 Explore Metrics 和 Logs 增强用户体验 全新的 Explore Metrics 和 Explore Logs 功能通过自动化复杂查询，显著降低了新用户的学习门槛，从而更轻松地进行故障排除和数据可视化。
  2. 提升可扩展性和管理效率 Grafana 11 引入了子文件夹和云迁移应用等功能，简化了大规模部署的管理，并实现了向 Grafana Cloud 的平滑过渡。
  3. 专注于可扩展性和插件开发 该版本着重强调 Grafana 的可扩展性，通过后端改进支持与 Grafana 核心功能无缝集成的插件（应用程序扩展）和应用程序的开发。
  4. 社区和黑客马拉松是创新的关键驱动力 Grafana 团队认为社区反馈和内部黑客马拉松对于识别和开发新功能至关重要，这体现了其协作式产品开发理念。
  5. 从 Angular 迁移到 React 从 Angular 迁移到 React 是对 Grafana 前端架构的一次重大技术升级，旨在实现现代化，同时确保与现有插件和仪表盘的兼容性。

💬 文章金句

  • Grafana 自动完成所有这些操作，这真是令人印象深刻。
  • 有趣的是，我们经常讨论新功能和引人注目的特性，但在发布沟通中，数据可视化团队和数据源团队的工作才是核心所在。
  • 我们非常努力地避免破坏现有的设置、插件和仪表盘，因为我们希望用户能够自信地进行升级。
  • 最大的变化在于我们现在如何将软件交付到云端。我们几乎每天都在进行此操作，这取决于我们所做的更改，并且这已成为我们构建软件的方式。
  • Grafana OSS 与我们在 Grafana Cloud 中构建的一些新应用之间一直存在一些内部差异，即 Grafana OSS 遵循每月或每六周的发布周期。
