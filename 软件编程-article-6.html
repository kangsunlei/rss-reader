grok build 简单心得（和 claude code 对比）

7/7/2026, 9:49:44 AM

📌 一句话摘要

本文分享 Grok Build 的使用心得，对比 Claude Code，指出其模型能力尚可但 TUI 体验差、工程习惯理解弱，建议当 CLI 使用。

📝 详细摘要

作者为完成优化画图 prompt 的任务，试用 Grok Build 并与 Claude Code 对比。主要发现：Grok Build 调用的模型文字输出尺度比 Claude 大，但图片生成限制严格；意图理解能力尚可，但对用户工程习惯的理解较弱，常放错文件位置；TUI 界面设计反人类，输出区小且历史记录被清除，无法回滚；Ctrl+C 终止不灵敏。结论是 Grok Build 更适合作为 CLI 工具使用，其模型能力值得利用，但 TUI 体验糟糕。

💡 主要观点

  1. Grok Build 模型文字输出尺度大，但图片生成限制严格。 相比 Claude，Grok 的文字输出更开放，但 imggen 仍严防死守，比 Grok imagine API 版还严格。
  2. 意图理解能力尚可，但对用户工程习惯的理解较弱。 Claude 能快速识别目录结构和命名习惯，而 Grok 常放错文件位置，甚至将应 gitignore 的内容提交到 tracked 目录。
  3. TUI 设计反人类，输出区小且历史被清除。 TUI 有过多无意义 padding，输出区仅约 20 行，每次新指令会 flush 历史输出，无法像 Claude Code 那样回滚查看。
  4. 建议将 Grok Build 作为 CLI 使用，利用其模型能力。 作者认为 Grok Build 的模型能力值得利用，但 TUI 体验差，更适合让其他终端白嫖 Grok 模型。

💬 文章金句

  • grok build 是设计给「不懂代码只在意结果的小白」，不是「需要 human-in-loop 的程序员」。
  • grok build 最好是当 cli 用，让其他终端白嫖 grok 模型。
