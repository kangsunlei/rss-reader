Computer Use 与 Browser Use：揭秘 Agent 如何操作电脑和浏览器｜得物技术

📌 一句话摘要

本文系统阐述了 Agent 如何通过 Computer Use 与 Browser Use 两种机制操作桌面应用和浏览器，详细解释了模型与工具的协作流程、观察、执行、实现及接入方式。

📝 详细摘要

本文从 RPA 到 Agent 的演进切入，阐释了模型如何根据目标和当前观察实时决策，再借助工具完成操作。文章分为两大部分：Computer Use 与 Browser Use。Computer Use 部分解释了如何通过操作系统接口（截图、可访问性接口、键鼠模拟）操作桌面应用，介绍了借助 PyAutoGUI、pywinauto 等自动化库的实现方式，以及通过脚本串联连续操作。Browser Use 部分阐述了利用浏览器的 DOM 结构和 DevTools Protocol 操作网页，介绍了 Playwright 等自动化库的使用方法，以及浏览器扩展实现已有标签页接入的方案。文章最后总结了三点核心：界面信息可复用、操作可直接调用、结果需验证。

💡 主要观点

  1. Agent 通过模型判断与工具执行相分工，实现从观察到操作的闭环 模型负责判断下一步操作，执行器负责实际操作，两者通过 CLI 或 MCP 等接口连接，形成看界面、做操作、查结果的循环流程。
  2. Computer Use 借助操作系统接口和自动化库实现桌面应用控制 通过截图、可访问性接口获取界面信息，利用 PyAutoGUI、pywinauto 等库完成鼠标键盘操作，脚本可串联连续步骤，提高执行效率。
  3. Browser Use 利用 DOM 结构和浏览器自动化库实现网页操作 通过浏览器的 DOM 和可访问性信息定位元素，借助 Playwright 等库执行点击、填写等操作，支持通过浏览器扩展接入已有标签页。
  4. 结果验证是 Agent 完成任务的关键环节 操作成功不等于任务完成，需检查文件生成、页面变化等结果，确保目标达成，必要时调整策略。

💬 文章金句

  • 从 RPA 到 Agent，截图、点击、输入这些基础动作并没有突然变成黑科技。
  • 模型加入以后，可以根据目标和当前观察决定下一步，再借用现有工具把动作做出来。
  • 把这样的调用包装成 Agent 能使用的命令或工具，就是一种接入办法。
