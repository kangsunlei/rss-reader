Firestore 新增流水线操作，引入 100 多项查询新特性

2/14/2026, 10:11:00 AM

📌 一句话摘要

Google 为 Firestore Enterprise 引入了流水线操作，支持复杂聚合、数组展开和可选索引，使其功能与主流 NoSQL 数据库齐平。

📝 详细摘要

Google 通过引入流水线操作，大幅升级了 Firestore Enterprise 版的查询引擎。此次更新允许开发者链接多个查询阶段，以处理数组展开、正则匹配和多阶段聚合等复杂任务，有效消除了长期存在的查询限制。该版本的一个重大架构转变是索引现在变为可选；虽然这提高了写入性能并减少了存储开销，但也要求开发者使用新的 Query Explain 和 Query Insights 工具来管理性能。文章还介绍了从标准版到企业版的迁移过程、修订后的定价模型，以及当前的预览版限制，如缺乏模拟器支持和离线持久化。

💡 主要观点

  1. 引入用于复杂数据转换的顺序流水线阶段。 开发者现在可以在单个请求中链接展开、分组和过滤等操作，类似于 MongoDB 中的聚合流水线，从而在数据库内部处理复杂的数据处理任务。
  2. 企业版从强制索引转向可选索引模型。 与要求所有查询都必须有索引的标准版不同，企业版允许无索引查询。这优化了写入速度并降低了存储成本，但需要进行细致的性能监控。
  3. 通过 Query Explain 和 Query Insights 工具增强数据库可观测性。 为了管理可选索引带来的风险，Google 提供了相关工具来揭示查询是命中索引还是回退到全表扫描，帮助开发者识别哪些地方的索引最为关键。
  4. 系统复杂性与数据层逻辑之间的架构权衡。 新引擎允许将复杂逻辑推向更靠近数据的一端，这可以简化应用代码，但需要权衡数据库是否应该成为主要的数据处理层。
  5. 迁移到企业版需要完整的数据导出和导入。 从标准版切换到企业版不是简单的开关切换；它涉及使用 Firestore 的导入/导出服务将数据迁移到新数据库，并需要手动重新创建安全规则和索引。

💬 文章金句

  • 此次更新消除了 Firestore 长期存在的查询限制，并使索引变为可选，使该数据库与其它主流 NoSQL 平台并驾齐驱。
  • 这颠覆了标准版的模式，即默认构建单字段索引并依赖它们执行查询。
  • 随着应用的发展，数据库往往会无意中变成数据处理层，而 Firestore 的新引擎使这一点变得明确，而不是强迫团队在应用代码中处理复杂性。
