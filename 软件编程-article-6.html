从 Data Lake 到 State Lake：面向 Agent 时代的存储基础设施重构

7/16/2026, 10:59:00 AM

📌 一句话摘要

本文详细阐述了火山引擎存储团队如何围绕 Sandbox Store、Artifact Store 和 Agent 观测与评测三大能力，将存储从 Data Lake 演进为 State Lake，以支撑 AI Agent 的全生命周期。

📝 详细摘要

文章从 AI 应用形态的演进切入，指出 AI 正从“回答问题”转向“完成任务”，这对存储提出了新需求。接着梳理了 AI 工作负载在训练、推理和 Agent 三个阶段的特点，并由此推导出存储范式从 Content Storage（面向数据集、文档等）向 State Storage（面向检查点、KVCache、环境状态等）的演进。核心部分围绕火山引擎存储团队的 Storage Agent Infra 展开，详细介绍了三大能力方向：Sandbox Store 通过 EBS、EFS 和 MQ LiteTopic 实现沙箱快速启动、状态快照与跨沙箱通信；Artifact Store 结合 EFS 与 TOS（含 Agent Bucket、SenseFlow、ContextBucket）提供任务产物的持久化、共享、智能检索与长期保存；Agent 观测与评测则依托 TLS AgentLoop 实现运行过程的可观测、可分析、可评测，形成持续优化闭环。文中还通过研发测试类、多模态创作类和智能办公类三个典型场景展示了这些能力如何落地，并提出存储角色已从被动的数据底座升级为主动的状态底座，即从 Data Lake 走向 State Lake，强调存储需要在 Agent 全生命周期中始终在场、理解任务、承接状态并参与闭环。全文结构清晰、图文并茂，兼具技术深度与实践指导价值。

💡 主要观点

  1. Sandbox Store 通过 EBS、EFS、MQ LiteTopic 实现沙箱快速启动、状态快照与跨沙箱通信。 EBS 负责沙箱本地状态的快速启动与快照恢复；EFS 提供共享、弹性及 POSIX 文件能力，支持多沙箱协作；MQ LiteTopic 提供会话级隔离与弹性调度，保障 Agent 通信的顺序与高并发。
  2. Artifact Store 结合 EFS 和 TOS（含 Agent Bucket、SenseFlow、ContextBucket）实现任务产物的持久化、共享、智能检索与长期保存。 EFS 适用于对 POSIX 语义和高并发读写有强需求的场景；TOS 提供海量、弹性、低成本的对象存储，配合 Agent Bucket 实现亿级租户隔离，SenseFlow 实现多模态理解，ContextBucket 实现上下文与工作区的持久化。
  3. Agent 观测与评测通过 TLS AgentLoop 将运行过程可观测、可分析、可评测，形成持续优化闭环。 TLS AgentLoop 收集 Agent 执行过程的日志、Trace、Session 等数据，支持回流、分析与评测，帮助研发、平台和业务团队发现瓶颈、优化工具调用并提升任务完成质量。
  4. 存储角色从 Data Lake 升级为 State Lake，强调存储需承载状态、上下文与产物，参与 Agent 全生命周期闭环。 这一范式转变体现在数据形态（文件 vs 短生命周期状态块）、IO 模式（带宽敏感顺序批扫 vs 延迟敏感随机流转）、SLO 要求（秒级可用 vs 毫秒/微秒级不可失）及成本结构四个维度上的演进，使存储成为主动的状态底座。

💬 文章金句

  • 存储的角色因此从'数据底座'升级为'状态底座'，从 Data Lake 走向 State Lake。
  • Agent 时代，技术平权，开发方式在变化，借助大模型、Serverless 架构，可快速搭建 AI Agent。但从 demo 迈向'生产级应用'，用户数演进到万级、百万级甚至亿级，存储管理复杂度指数级提升。
