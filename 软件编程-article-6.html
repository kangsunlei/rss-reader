如何构建和部署生产级 MCP 服务器

4/25/2025, 9:04:21 AM

📌 一句话摘要

Docker 通过容器化运行时、集中式工具目录和安全密钥管理，简化 MCP 服务器的构建、分发和安全使用。这尤其解决了 LLM 直接访问主机系统带来的安全风险。

📝 详细摘要

本文探讨了 Agentic AI 应用中模型上下文协议 (MCP) 面临的挑战，包括运行时环境管理、安全、工具发现和信任。Docker 通过为 MCP 服务器提供容器化的运行时来解决这些问题。Docker 作为 MCP 网关，允许 LLM 动态发现和运行工具，而无需修改配置文件。Docker MCP Catalog 提供了一个可信的、集中式的中心，用于发现和分发工具。Docker Desktop 管理密钥，允许安全地将访问令牌和其他密钥传递给容器，从而降低数据泄露的风险。Docker 是构建和交付生产级 MCP 服务器的理想之选，能够有效解决现有挑战。

💡 主要观点

  1. Docker 简化 MCP 服务器运行时环境的管理 通过容器化，开发人员无需管理多个 Node 或 Python 版本；Docker Engine 足以运行 MCP 服务器，避免了环境依赖问题。
  2. Docker 为 MCP 工具提供沙箱隔离，增强了安全性 除非显式绑定 MCP 容器，否则 LLM 无法直接访问主机文件系统，从而防止恶意行为或不正确的输出损坏主机。
  3. Docker MCP Catalog 提供了一个集中式的工具发现和分发平台 开发人员可以在可信的中心发现工具，工具作者可以接触到更多用户，并确保与 Claude、Cursor、OpenAI 和 VS Code 等平台的兼容性。
  4. Docker Secrets 提供安全的密钥管理和传递机制 密钥仅暴露给 MCP 的容器进程，即使在检查运行中的容器时也不会出现，从而降低了数据泄露的风险。
  5. Docker 作为 MCP 网关，实现动态工具管理 Docker 允许 LLM 动态发现和运行工具，而无需修改配置文件，从而简化了添加或删除工具的过程。

💬 文章金句

  • 在非业余开发环境中，不允许 LLM 直接访问主机系统运行软件。
  • Docker 是一个经过验证的运行时，可以稳定工具运行的环境。
  • 密钥仅暴露给 MCP 的容器进程。这意味着即使在**检查运行中的容器**时，密钥也不会出现。
