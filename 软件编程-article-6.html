GitHub 可用性报告：2025 年 8 月

9/11/2025, 12:53:44 PM

📌 一句话摘要

GitHub 2025 年 8 月的可用性报告详细描述了三起事件，包括影响 ORM 的数据库迁移问题和因负载均衡器连接性导致的搜索基础设施问题。

📝 详细摘要

GitHub 在 2025 年 8 月发布了可用性报告，详细描述了导致其服务性能下降的三起独立事件。8 月 5 日和 27 日发生的两次事件都源于生产数据库迁移，其中删除了列。尽管这些列已不再直接使用，但对象关系映射 (ORM) 仍然引用它们，导致拉取请求、推送、网络钩子、通知和 Copilot 功能的错误率升高。GitHub 通过部署 ORM 修复程序来缓解这些问题，并作为一项更广泛的措施，暂时阻止《删除列》操作，并为 Copilot 实施优雅降级。8 月 12 日发生的第三起事件涉及 GitHub 搜索性能下降，原因是负载均衡器和搜索主机之间的间歇性连接问题。重试逻辑最终导致负载均衡器过载，导致查询失败和更新延迟。缓解措施包括限制搜索索引管道和自动重启。对于所有事件，GitHub 都发现了监控漏洞，改进了内部流程，并实施了安全措施以防止再次发生，强调了对系统可靠性和透明度的承诺。

💡 主要观点

  1. 数据库模式更改，特别是删除列，如果未通过应用程序 ORM 仔细管理，则会带来重大风险。 两次事件是由 ORM 引用删除的列引起的，突显了在模式修改期间，强大的迁移策略和应用层面考量对于防止广泛错误的关键需求。
  2. 全面的监控和简化的部署流程对于所有生产和金丝雀环境至关重要。 由于未完全部署修复程序而发生了第二起事件，揭示了监控方面的差距，以及为防止局部故障升级而需要一致的自动化变更传播。
  3. 分布式搜索基础设施中的负载平衡和重试机制需要仔细调整，以防止级联故障。 由于激进的重试逻辑，间歇性连接问题导致负载均衡器过载，突显了对关键服务（如搜索）进行强大的负载平衡、断路器和限制的重要性。
  4. 实施优雅降级对于隔离特定于服务的故障并最大限度地减少对整体平台功能的影响至关重要。 Copilot 事件导致了更广泛的服务降级，强调了架构系统以隔离故障并确保不相关的功能在中断期间保持运行的价值。

💬 文章金句

  • 虽然该列已不再直接使用，但我们的 ORM 继续在部分拉取请求查询中引用已删除的列。
  • 此事件发现了一个应用程序监控漏洞，该漏洞本可以防止在观察到影响时继续推出。
  • 虽然重试逻辑最初掩盖了这些问题，但重试队列最终导致负载均衡器过载，导致失败。
  • 我们现在已经实施了针对所有《删除列》操作的临时阻止，作为一种立即解决方案，同时我们添加了更多安全措施，以防止将来发生类似问题。
  • 我们还在实施优雅降级，以便 Copilot 问题不会影响我们产品的其他功能。
