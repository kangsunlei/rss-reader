千亿级请求下，飞猪如何将广告外投系统超时率爆降至 0.01%

1/24/2026, 2:16:00 AM

📌 一句话摘要

飞猪通过应用架构解耦、JDK21 升级、全链路网络优化及设备标识标准化，成功解决千亿级请求下的高延迟问题，将 RTA 系统超时率降至 0.01%。

📝 详细摘要

本文详细介绍了飞猪广告外投（RTA）系统在面对日均千亿级请求、百万级 QPS 挑战时的架构演进与性能优化实践。针对早期系统耦合度高、跨地域网络延迟大、研发效能低等痛点，飞猪技术团队实施了系统性变革：首先通过应用独立拆分并升级 JDK21 虚拟线程与 SpringBoot 3.x 提升单机吞吐；其次利用 HTTP 长连接复用、单元化部署及 Tengine 深度调优，根治了跨地域调用的网络毛刺；最后通过日志异步化、主动熔断机制及设备标识标准化治理，在降低 30%机器成本的同时，实现了接口 RT 下降 20%及极致的稳定性保障。

💡 主要观点

  1. 通过应用架构解耦与技术栈升级，释放单机潜能并提升研发效能。 将 RTA 独立拆分，升级 JDK21 虚拟线程和 SpringBoot 3，利用新技术红利降低 I/O 开销，使服务器资源消耗降低 30%。
  2. 实施单元化部署与长连接复用，根治跨地域网络延迟引起的超时。 通过物理距离就近部署和改造 HTTP 客户端保留超时后的 TCP 连接，打破建连耗时死循环，使直连超时率从 30%降至 0.01%。
  3. 对网关层与应用层进行深度调优，消除系统非核心路径的性能瓶颈。 优化 Tengine 长连接配置减少 TIME_WAIT，并对日志系统进行协议精简与异步刷盘，使 CPU 使用率显著下降。
  4. 构建多维身份并行召回引擎，解决设备识别不一致导致的参竞失败。 定义分层标识体系消除哈希碰撞，统一离线与实时决策的 ID 格式，将身份识别准确率提升至 99.99%。

💬 文章金句

  • RTA（Real-Time API）= 实时竞价接口，就是广告平台在每次广告曝光前，实时问飞猪'这个用户要不要投、出多少钱'的关键技术。
  • 当 HTTP 协议层超时时，TCP 连接往往已建立完成，若底层 TCP 连接已成功建立，则保留该连接供后续请求复用，打破'超时 → 关连接 → 无法长建连'的恶性循环。
  • 通过应用拆分、架构升级与网关调优等，在整体 QPS 提升 60%+ 的前提下，服务器资源消耗降低约 30%。
  • 发布不仅是功能上线的终点，更是系统韧性的起点。尤其当单次故障恢复时间直接影响业务收入时，应用重启速度、发布流程确定性、回滚敏捷性，就成为了衡量工程成熟度的关键指标。
