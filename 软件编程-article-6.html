别把 Agent 当同事！黄仁勋最新访谈：程序员应该开始“造 Agent”，公司未来将建在 Harness 之上

7/11/2026, 7:34:00 AM

📌 一句话摘要

本文基于黄仁勋最新访谈，阐述 Agent 落地关键在于模型外部的 Harness 系统（Prompt、工具、记忆、评测等），并指出程序员应从写代码转向构建 Agent，企业应建立自己的 Agent 工程资产。

📝 详细摘要

文章整理自黄仁勋的一次深度访谈，核心观点是生产级 Agent 的上限越来越取决于模型外部的 Harness 系统——包括 Prompt、工具描述、记忆、上下文管理、任务拆分、重试、评测和权限控制，而非模型本身。黄仁勋以 LangChain 团队在不重训模型、仅调整 Harness 的情况下将 Nemotron 3 Ultra 的 Deep Agents 评测成绩从 0.86 提升至接近最高分模型 0.87（成本从 43.48 美元降至 4.48 美元）为例，说明工程优化的价值。他进一步指出，成本下降会改变开发方法，使团队能多试、常测、大规模部署 Agent。企业应先利用前沿模型探路，将高频任务收敛到低成本模型与专用 Agent。他还强调 Agent 安全——运行时应在沙箱中临时注入权限，避免直接暴露长期凭证。最后，黄仁勋认为程序员的工作将从写代码转向构建 Agent 的角色定义、工具边界、评测与退出机制，公司的核心资产将是围绕业务数据构建的 Harness。

💡 主要观点

  1. Agent 工程的关键在于模型外部的 Harness 系统。 黄仁勋指出，模型负责推理，但决定 Agent 能否进入生产环境的是 Prompt、工具描述、记忆、任务拆分、重试、评测和权限控制等工程组件。LangChain 通过调整 Harness 而非模型权重，使开源模型成绩追平闭源模型。
  2. 降低推理成本会改变 Agent 的开发方法。 当一次 Agent 评测的成本从 43.48 美元降至 4.48 美元，团队可以更频繁地跑评测、比较不同变量，将 Agent 从少量高价值任务扩展到更多细分流程。
  3. 企业应先用前沿模型探路，再将高频任务专门化。 对于新问题先用顶级闭源模型探索可用的轨迹与验证标准，待任务形态稳定后，将规则、上下文和评测固化到低成本开放模型或专用 Agent 上。
  4. Agent 安全需要在沙箱中临时注入权限。 Agent 不应直接持有长期密钥，而应由运行时根据当前任务和策略动态授予临时权限，并在沙箱中执行，同时记录完整轨迹供审计。
  5. 程序员工作从写代码转向构建 Agent 的角色、工具、边界和评测。 黄仁勋认为，需求不会因编程效率提高而减少，但工程师的交付物将从函数和服务扩展到 Agent 的角色定义、工具说明、权限边界、异常处理和验收标准。

💬 文章金句

  • 少写一些重复代码，多造一些能把事情做完的 Agent。
  • 模型只是原料，Harness 才把它变成能交付的系统。
  • Agent 不应直接拿到长期密钥。更合理的方式是由运行时根据当前任务和策略临时注入权限。
  • 当每一次试验都昂贵，团队就会主动减少评测和探索。
