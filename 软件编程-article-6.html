DataGrip：查询控制台的终结与查询文件的新生 | DataGrip 博客

9/16/2025, 4:46:20 PM

📌 一句话摘要

DataGrip 和 JetBrains IDEs 使用“查询文件”替换“查询控制台”，旨在简化 SQL 工作流程，提高发现性与灵活性。

📝 详细摘要

JetBrains 宣布，DataGrip 及其他支持数据库的 IDE 将从 2025.3 版本开始，停用“查询控制台”并过渡到“查询文件”。此举旨在解决控制台长期存在的问题，例如：控制台最初是未集成到项目结构中的临时 SQL 文件，难以查找且上下文管理不便。现在，基于文件的新方法让查询脚本在项目中清晰可见，易于在专门的“查询”文件夹中找到，并且可以像管理普通项目文件一样进行管理，方便地更改 SQL 方言、数据源等属性。本文详细介绍了新的工作流程，包括可自定义的文件命名、更新的 UI 图标以及现有控制台的迁移对话框。此次增强旨在为 JetBrains IDEs 中的数据库交互提供更直观、更易于发现且更一致的体验，并计划未来在数据库浏览器中添加“查询文件”节点。

💡 主要观点

  1. JetBrains IDEs 正在从“查询控制台”过渡到“查询文件”。 DataGrip 2025.3 版本开始，将查询脚本视为标准项目文件，简化了 SQL 编辑体验，并解决了之前的可用性问题。
  2. 新的基于文件的工作流程显著提高了发现性和灵活性。 查询文件现在是项目结构的一部分，易于定位，并且可以直接在 UI 中无缝切换上下文（方言、数据源），这与之前的控制台不同。
  3. 现有控制台将被迁移，并且此更改将扩展到其他 JetBrains IDEs。 用户将通过迁移过程获得指导，以确保不会丢失现有工作。新逻辑将成为所有启用数据库的 JetBrains IDEs 的标准配置。

💬 文章金句

  • 从现在开始，我们将使用 *查询文件* —— 因为控制台本质上就是文件，现在是 UI 做出相应改变的时候了。
  • 控制台的设计理念是好的，但在实际使用中却不够方便。我们必须做出改变。
  • 之前控制台的所有限制都已解除！您现在可以重新附加查询文件，更改其方言和数据源，并像管理普通项目文件一样管理它们。
  • 当您升级 DataGrip 时，迁移对话框将帮助您将所有控制台迁移到文件，并指导您完成新的工作流程。
  • 我们将在首个 EAP 版本中推出此更改，以收集社区的反馈。
