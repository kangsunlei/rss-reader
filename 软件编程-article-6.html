当 human in the loop 变成“闭着眼睛点确认”，企业 Agent 安全还能靠谁？

8/7/2026, 7:52:00 AM

📌 一句话摘要

本文深入剖析 AI Agent 从内容安全到行为安全的转变，指出 human in the loop 的局限，并提出可视、可管、可追溯的三板斧及最小权限等企业级安全实践。

📝 详细摘要

文章基于 InfoQ 极客有约 X AICon 直播，邀请腾讯、百度、Cloudflare 的安全专家讨论企业 Agent 安全挑战与应对。指出 Agent 获得工具、记忆和执行权限后，安全焦点从“内容对不对”转向“行为可不可控”。human in the loop 易因确认疲劳退化为安慰剂，真正安全应把人只用在关键决策点，依赖可视、可管、可追溯的护栏。专家提出三板斧（可视、可管、可追溯）的落地路径：先做资产盘点、最小权限和保底策略，再通过全链路日志实现渐进式安全管理；同时警告工具和 skill 的过度授权是主要风险，需采用最小权限、沙箱隔离、网关防护和日志溯源。责任方面，业务团队为第一责任人，安全团队需共同参与并提供可用资源。整体内容信息密度高、案例真实、观点丰富，为企业级 Agent 安全提供了可操作的方法论。

💡 主要观点

  1. Agent 安全已从内容防错转向行为可控，因其获得了工具调用、记忆和执行权限。 过去只需防止模型说错话，而现在 Agent 能调用工具、访问数据并自主执行，一旦被恶意指令劫持，可能导致删库、转账等实际损害，安全边界由此发生根本性变化。
  2. human in the loop 易因确认疲劳退化为安慰剂，真正安全需把人只用在关键决策点，依赖可视、可管、可追溯的护栏。 频繁的确认弹窗会导致操作机械化，失去实质审查作用；因此应将人工干预限制在高风险决策环节，其余交由自动化的策略和日志监控来完成。
  3. 企业应先做资产盘点、最小权限和保底策略，再通过全链路日志实现可视、可管、可追溯的渐进式安全管理。 首先明确 Agent 拥有的身份、可调工具、可触数据和对外通道；然后采用最小权限原则并设置保底防线；最后在输入、调用和产出全链路记录日志，以便事后追溯和威慑。
  4. 工具和 skill 的过度授权是主要风险，需采用最小权限、沙箱隔离、网关防护和日志溯源来降低被滥用的可能性。 每新增一个工具相当于给 Agent 和潜在攻击者多一把钥匙，若权限过大易被滥用；因此应给予临时 token、最小 API 权限，并在网关和沙箱层面加防护，同时确保完整日志以便溯源。

💬 文章金句

  • 安全不是刹车，是护栏------有了护栏，你在山路上反而敢开得更快。
  • 很多人把 human in the loop 当万能解药，但它正在成为 Agent 安全里最大的'安慰剂'。因为人是会确认疲劳的，弹窗越多、越频繁，human in the loop 就退化成了 human clicking the button ------ 说白了，就是'闭着眼睛点确认'。
  • 每接入一个工具，就等于给 Agent、也给黑客多发了一把万能钥匙。危险的从来不是工具，而是我们给它的权限，远超任务真正的需要。
