Claude Code 的创始人揭秘工作流程：开 5 个智能体“玩编程游戏”，不看的程序员就落后了？

1/10/2026, 4:04:00 AM

📌 一句话摘要

本文揭示了 Anthropic Claude Code 创始人 Boris Cherny 如何通过并行运行多个 AI 智能体、采用慢速大模型以及维护共享知识库等创新实践，将编程转变为高效的战略游戏，大幅提升个人工程师的产出效能。

📝 详细摘要

Anthropic Claude Code 创始人 Boris Cherny 分享了一套颠覆性的 AI 辅助编程工作流，它能让一名工程师发挥出小型工程团队的产出效能。该工作流的核心是同时并行运行多达五个 Claude 智能体，将编程视为战略游戏，开发者从编写代码转变为指挥智能单元。Cherny 意外地选择使用 Anthropic 体量最大、速度最慢的 Opus 4.5 模型，因为其更高的干预效率和工具调用能力能带来整体效率提升。为解决 AI“健忘症”，他的团队维护一个 CLAUDE.md 文件，将 AI 的错误记录下来，通过这种方式让代码库成为一个自我修正的有机体。此外，Cherny 的工作流还实现了极致的自动化，通过浏览器扩展、Shell 命令和自定义斜杠指令，使 AI 能自主验证工作成果，并执行版本控制等重复性任务，显著提升了开发效率和代码质量。

💡 主要观点

  1. 并行使用多个 AI 智能体，将编程变为战略指挥而非线性编码。 Cherny 同时并行管理五个 Claude 智能体处理测试、重构、文档等多任务流，显著提升了个人工程师的综合产出效率，类似指挥舰队。
  2. 选择性能更强但速度较慢的 AI 大模型，以减少干预和提高整体效率。 尽管 Opus 4.5 模型速度较慢，但其工具调用能力和较低的干预需求使其在长期维度上比小型模型更高效，能产生更高质量的代码。
  3. 通过构建共享知识库 CLAUDE.md 解决 AI 的“健忘症”，实现模型的自我修正。 将 Claude 在特定任务中发生的错误记录到 CLAUDE.md 文件中，使得 AI 能够学习并避免重复犯错，将每一次失误转化为提升规则，形成自我优化的代码库。
  4. 极致自动化重复性任务，赋予 AI 自主验证和版本控制能力。 利用浏览器自动化、运行 Shell 命令和自定义斜杠指令，实现了代码自动测试、UI 验证和 Git 提交/PR 等操作，将 AI 打造为驱动整个工作流程的“操作系统”，大幅提升代码质量和开发效率。

💬 文章金句

  • 我在终端里并行运行五个 Claude 智能体，把标签页按 1 到 5 编号，借助系统通知来判断哪个 Claude 需要输入指令。
  • 我做任何任务都用开启思考模式的 Opus 4.5，它是我用过的最好用的编程模型。尽管它比 Sonnet 模型体积更大、速度更慢，但因为你需要对它的干预更少，而且它的工具调用能力更强，最终整体效率几乎总是比使用小型模型更高。
  • 每当我们发现 Claude 执行任务出错，就把问题记录到 CLAUDE.md 里，这样 Claude 下次就不会再犯同样的错误了。
  • 人工智能不只是编写代码，更能主动验证代码的有效性。
  • 将重复性任务进行了极致的自动化改造。
