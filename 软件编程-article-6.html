📌 一句话摘要

本文详细介绍了如何从零开始构建一个 Web 前端监控 SDK，包括异常监控、数据上报以及关键技术实现。

📝 详细摘要

本文深入讲解了前端监控 SDK 的构建过程，从设计 SDK 的整体架构开始，详细阐述了如何使用 Rollup 搭建构建环境，并对各种前端异常进行监控，包括 JS 代码执行错误、Promise 未处理的错误、资源加载错误和 API 请求报错。文章还介绍了数据上报的几种方式，重点讲解了使用 img GIF 图片进行上报的实现方法。通过重写 XMLHttpRequest 原型方法，实现了 API 请求的监控，提供了可直接落地的代码示例和配置方法，方便开发者实践。

💡 主要观点

  1. 通过 Rollup 构建工具，可以方便地打包 SDK 代码。 Rollup 非常适合构建工具库和组件库，可以方便地将 SDK 代码打包成 JS 脚本文件，供业务项目使用。
  2. 通过监听 error 和 unhandledrejection 事件，可以捕获 JS 代码执行错误和 Promise 未处理的错误。 window.addEventListener('error') 可以监听全局未被 try/catch 捕获的错误，window.addEventListener('unhandledrejection') 可以监听未被捕获的 Promise 错误。
  3. 通过重写 XMLHttpRequest 原型方法，可以监控 API 请求的状态。 通过重写 setRequestHeader、open 和 send 方法，可以记录请求头、请求方法和 URL，并在请求出错时进行数据上报。
  4. 对错误信息进行数据建模，可以更有效地描述和定位错误。 通过对不同类型的错误进行数据建模，可以更清晰地了解错误的类型、发生位置和上下文信息，从而更有效地进行错误分析和修复。

💬 文章金句

  • 在大型项目中，「前端监控」是不可或缺的一部分。
  • 在服务器上放置一个非常小的 gif 图片（1kb），将日志数据作为图片 url queryString 参数，访问这个图片来达成数据上报至服务器
  • 通过重写 XMLHttpRequest 原型方法，实现 API 请求的监控，是保障前后端交互稳定性的重要手段。
