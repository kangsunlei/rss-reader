想要成功实施 OpenTelemetry 项目？试试这一招

4/4/2026, 2:00:24 PM

📌 一句话摘要

本文提倡在采用 OpenTelemetry 时采取“最小化变更”策略，并演示了如何使用 JMX Metric Scraper 在不修改应用程序代码的情况下摄取现有的 JMX 指标。

📝 详细摘要

迁移到 OpenTelemetry 往往会因为改变现有基础设施的开销而面临阻力。作者提出了一种务实的方法：最小化变更以提高采用成功率。通过利用 JMX Metric Scraper，团队可以将现有的 JMX 指标摄取到 OpenTelemetry 流水线中，而无需注入 Java Agent 或修改应用程序代码。本文提供了实用的指南，包括配置示例以及涉及 OpenTelemetry Collector、Prometheus 和 Grafana 的参考架构，为实现现代化可观测性提供了一条低摩擦的路径。

💡 主要观点

  1. 最小化变更以提高采用成功率。 组织阻力是采用新可观测性标准的主要障碍。从非侵入式方法入手可以减少变更管理的开销，并显著提高项目成功的可能性。
  2. 通过 JMX Metric Scraper 利用现有的 JMX 指标。 无需立即进行代码插桩或注入 Java Agent（这可能需要跨团队协调），而是使用 JMX Metric Scraper 轮询现有的 MBean 并将其导出到 OTLP，从而保持当前应用程序的稳定性。
  3. 实施标准化的可观测性流水线以实现平滑过渡。 作者概述了一个稳健的架构（JMX Scraper -> OTel Collector -> Prometheus -> Grafana），使团队能够在无需重构的情况下将遗留指标集成到现代可观测性技术栈中。

💬 文章金句

  • 变更越少，成功的几率就越高。
  • 在信息系统中引入 OpenTelemetry 不需要进行不必要的过度变更。
  • 你可以，而且可能应该，尽可能保留现有的资产，以便将精力集中在必要的环节上。
