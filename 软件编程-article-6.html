“我初学编程，只是为了考试作弊”，CC 之父自曝经历，揭秘 Claude Code 狂删超 80%系统提示词真相！

7/29/2026, 7:50:00 AM

📌 一句话摘要

本文编译整理 Claude Code 之父 Boris Cherny 在 Y Combinator 访谈中的核心观点，揭示 Opus 5 发布后 Claude Code 删掉 80% 系统提示词的幕后逻辑，以及 AI 时代开发者应如何重新定位自身价值。

📝 详细摘要

本文是 CSDN 对 Anthropic Claude Code 之父 Boris Cherny 在 Y Combinator 最新一期访谈的编译整理。围绕 Opus 5 的发布，Boris 分享了多个关键洞察：Claude Code 删掉超过 80% 系统提示词是因为新模型已足够智能，不再需要大量行为纠正；提示注入攻击通过三层机制（对齐训练、基于 Crysola 机制可解释性的分类器、Auto Mode 分类器）已变得几乎无法复现；Boris 提出「解除 Claude 束缚」与「产品过剩空间」概念，强调 Claude Code 的诞生正是源于 Sonnet 3.5 时代产品对模型能力的束缚。他还以 Bun 团队用 11 天将 10 万行 Zig 代码重写为 Rust、自己用 Claude Tag 持续两周把 Electron 桌面应用重写为 Swift 原生应用为例，展示模型在长程任务上的能力跃迁。在方法论层面，Boris 主张「实证优先」：先删掉提示词让模型跑起来，观察失败再加回；动态工作流、Loop、Routine 等机制可同时编排数千个 Agent；区分普通用户与顶级 1% 用户的关键在于是否过度指定需求、是否给模型验证工具。最后，Boris 坦言「编程已被解决」仅适用于其工作范畴，并建议新一代开发者从解决真实问题出发，重视产品、设计与商业判断，而非追逐所谓的神奇 Prompt。

💡 主要观点

  1. Claude Code 删掉 80% 系统提示词，是因为新模型已足够智能。 过去系统提示词承担了大量行为纠正功能，Opus 5 已能自行理解并完成任务，不再需要这些额外提醒；消融实验甚至显示去掉提示词后模型表现略好。
  2. 「解除束缚」与「产品过剩空间」是构建 AI Agent 产品的核心方法论。 模型已具备大量未被释放的隐藏能力，Claude Code 正是通过给 Sonnet 3.5 一个极简 Harness 才释放出完整文件生成能力；创业者应寻找模型已能做到但产品仍在阻碍的场景。
  3. 构建 AI 产品应采用「实证优先」而非「架构先行」的工程范式。 每代模型都像有机体一样有不同个性，应先删掉提示词让模型跑起来，观察失败再加回；评测的生命周期比 Harness 长但也有限，需持续迭代。
  4. 动态工作流、Loop 与 Routine 可同时编排数千 Agent 完成长程任务。 Bun 用 11 天重写 10 万行 Zig 到 Rust、Claude Tag 持续两周重写 Electron 到 Swift，都是通过编排大量 Agent 实现的；Anthropic 内部已有 20-30 个 Routine 每天自动维护代码库。
  5. 区分普通用户与顶级 1% 用户的关键是「不过度指定」与「提供验证工具」。 不要给模型过于细致的步骤指令，而应在高层描述目标与约束，并让模型能验证自己的工作结果；放下既有认知、保持开放心态比任何 Prompt 技巧都重要。

💬 文章金句

  • 所有人都在寻找那个一招制胜的技巧，但实际上，它并不存在。
  • 不要只学习计算机科学本身，更重要的是要学会如何应用它。
  • 模型每一次被使用时，都会读取这些指令。所以，你必须非常确定：模型真的需要这条指令。
  • 理解模型的方式，应该更像是在理解一个有生命的东西，或者说，一个更加有机的系统。
  • 「编程已经被解决」，只适用于我所从事的那类编程。
