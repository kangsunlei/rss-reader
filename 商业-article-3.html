老码农眼中的 Agent Skill

7/26/2026, 12:26:00 PM

📌 一句话摘要

本文深入解析了 Agent Skill 的本质、工作原理及构建方法，重点介绍了其三级加载系统与 MCP 的融合应用。

📝 详细摘要

文章从“入门指南”的角度重新定义了 Agent Skill，指出其核心在于通过结构化的 SKILL.md 文件引导 Agent。作者详细拆解了 Skill 的三级加载机制（元数据、指令、参考文件），解释了如何通过渐进式披露来优化上下文成本与触发效率。此外，文章探讨了 Skill 的调用模式（显式与隐式）、与 MCP 协议的协同作用，并对安装社区 Skill 时的安全性提出了警示，为开发者构建可靠的 Agent 工作流提供了理论与实践指导。

💡 主要观点

  1. Agent Skill 的本质是结构化的“入门指南”。 它不是简单的 API 脚本，而是通过 SKILL.md 提供上下文指导，让 Agent 决定何时及如何执行特定任务，而非强制执行。
  2. 核心在于高效的“三级加载系统”。 通过元数据（始终加载）、指令（触发加载）和参考文件（按需加载）的渐进式披露，在保证 Agent 能力的同时最小化了上下文成本。
  3. Skill 是增强 MCP 能力的关键手段。 MCP 提供 API 访问权限，而 Skill 则定义了如何可靠、一致地使用这些权限，实现了从“连接工具”到“完成工作流”的跨越。
  4. 必须警惕 Skill 带来的安全风险。 恶意 Skill 可能通过提示注入导致数据泄露，开发者应严格审核 scripts/ 中的脚本及出站网络调用。

💬 文章金句

  • Skill 不是插件，也不是你连接到 API 的脚本，可以把它想象成为新团队成员编写入门指南。
  • 问题从来就不在于你在 Skill 内部写了什么，而是 Agent 用来决定是否要激活它的最上面两行。
