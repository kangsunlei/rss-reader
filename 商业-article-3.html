创始人真实复盘：AI 应用创业 300 天，我做过的 10 个关键选择

5/26/2026, 1:30:00 PM

📌 一句话摘要

本文是 SophiaPro 创始人程梦琪的真实创业复盘，详细讲述了 AI 应用创业 300 天内从垂直 Agent 转向 C 端产品的 10 个关键选择与踩坑经历。

📝 详细摘要

本文是 SophiaPro 创始人程梦琪在锦秋小饭桌活动上的真实分享，完整复盘了其 AI 应用创业近 300 天的心路历程。文章以 10 个关键选择为线索，讲述了团队从最初选择垂直 Agent 方向、选定营销场景、在 Agent 与 Workflow 间做技术决策，到最终从 ToB 转向 C 端产品的全过程。创始人坦诚地剖析了每个决策背后的思考逻辑与事后反思，包括因「技术虚荣心」选择 Agent 而非 Workflow、因「想装一下」而偏离市场需求、以及做客户端产品时面临的巨大工程挑战。文章还分享了从浏览器插件 Clico 到桌面端产品 Invoko 的转型经验，以及如何通过 Reddit 做用户研究、如何找到正确的 ToB 商业模式等实战心得。最后，创始人提出了对 OPC 趋势、软件出路、公司组织等问题的个人判断，强调「所有落到生产级别的事，都比讲概念难 100 倍」。

💡 主要观点

  1. 垂直 Agent 方向存在结构性困局：客户不用产品，创业公司被迫变成 agency。 创始人复盘发现，大部分垂直 Agent 公司面临客户不真正使用产品、最终靠服务赚钱的困境，建议不如做 general Agent 积累用户 query。
  2. 技术决策应基于客户需求而非「技术虚荣心」，ToB 产品应选 Workflow 而非 Agent。 Agent 虽先进但不稳定，ToB 客户需要结果一致性；Workflow 在成本、速度、交付稳定性上更适合企业场景。
  3. C 端用户要的不是差异化壁垒，而是「好用、快、在我手边」的朴素体验。 创始人从浏览器插件 Clico 的成功中领悟到，缩短用户意图与解决方案之间的距离比追求技术壁垒更重要。
  4. 做客户端产品虽难，但由 15000 个细节组成的壁垒让团队不再焦虑。 Invoko 客户端开发了 49 个版本，适配不同 Mac 芯片型号，这种「没有捷径」的工程积累反而成为核心竞争力。
  5. 正确的 ToB 产品路径是「自己先用好，再外溢给别人」，而非大跃进式 rush 版本。 团队在自用过程中打磨出的 skill 比之前正式 ToB 产品更好用，因为自己的需求最完整、最直接、每天都在用。

💬 文章金句

  • 大部分纯应用的创业公司不要招算法。你用不上。快放人家去训模型吧，你让人家在你这干什么？纯属给投资人看阵容。
  • 我不是在基于市场需求做决策，是在基于「我得装一下」做决策。刚拿到融资都是创始人的愚昧之巅。
  • C 端用户要的东西很朴素：好用、快、在我手边。
  • 所有落到生产级别的事，都比讲概念难 100 倍。
  • 软件更像一块草坪，修剪费用比当初买草皮还贵。
