Web3 秘密存储定义

9/18/2026, 11:09:05 PM

📌 一句话摘要

以太坊官方技术文档，定义了 Web3 秘密存储第 3 版规范，详细说明密钥文件结构、PBKDF2/Scrypt 密钥派生、AES-128-CTR 加密及 MAC 验证的完整实现要求，并提供测试向量与版本演进背景。

📝 详细摘要

本文档是 ethereum.org 发布的 Web3 秘密存储（Web3 Secret Storage）第 3 版技术规范。内容涵盖密钥文件的目录约定、JSON 结构字段定义、密码派生流程、MAC 验证方法以及对称加密算法参数。规范强制要求实现支持 PBKDF2-HMAC-SHA256 与 AES-128-CTR 组合，同时兼容 Scrypt KDF。文档提供了完整的测试向量，包括中间值验证数据。此外还列出了与第 1 版的关键变更：修正大小写不一致、移除地址字段保护隐私、将 salt 移至 kdfparams、统一版本字段类型等。该规范旨在为以太坊客户端实现提供统一的密钥存储互操作标准。

💡 主要观点

  1. Web3 秘密存储 v3 规范定义了密钥文件的完整结构与加密流程 文件存储于 ~/.web3/keystore 或 Windows 对应目录，命名建议采用 UUID.json 格式。核心字段包括 crypto 块（含 cipher、cipherparams、ciphertext、kdf、kdfparams、mac）、id（UUID）、version（数字型）。密码通过 KDF 派生密钥，再用 MAC 验证，最后解密 ciphertext。
  2. 最低合规要求强制支持 PBKDF2 + AES-128-CTR 组合 PBKDF2 使用 hmac-sha256 PRF，迭代次数 c 可配置，dklen 必须 >= 32。AES-128-CTR 需 128 位 IV。若派生密钥长度不匹配算法要求，截断至左侧 16 字节。这种强制基线确保所有实现至少达到同等安全强度。
  3. MAC 计算方式在第 3 版中明确定义，避免歧义 MAC = KECCAK-256(DK[16..31] ++ ciphertext)，其中 DK[16..31] 是派生密钥的第 17-32 字节，与密文拼接后哈希。这种设计使 MAC 同时绑定密钥后半段与密文，防止密文篡改。
  4. 相比第 1 版的变更聚焦于结构一致性与隐私保护 主要改进包括：统一字段大小写（kdf/cipher/mac 全小写）、移除 address 字段以避免泄露账户信息、将 salt 从顶层移至 kdfparams 内（使其成为 KDF 的参数而非全局字段）、将 version 改为数字而非字符串、修正 MAC 计算中对空格的处理问题。
  5. 文档提供完整的测试向量便于实现验证 包含 PBKDF2 和 Scrypt 两种 KDF 的完整 JSON 文件示例及中间值（Derived key、MAC Body、MAC、Cipher key），方便开发者对照实现。这些测试向量基于固定密码 testpassword 和明文 7a28b5ba...，确保跨实现的可复现性。
