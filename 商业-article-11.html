Clawdbot 开发者：未来一大批应用都会消失，提示词就是新的 interface

1/29/2026, 12:39:00 PM

📌 一句话摘要

Clawdbot 开发者 Peter Steinberger 提出 2026 年将是个人助理之年，主张以 CLI 为核心的 AI 交互范式将取代 GUI，导致大量传统应用消失。

📝 详细摘要

本文是对爆火 AI 项目 Clawdbot（现改名 Maltbot）开发者 Peter Steinberger 的深度访谈。Steinberger 结合其资深开发经验，分享了 Agentic Engineering（智能体工程）的核心理念。他认为，当前的 GUI 扩展性差，而 CLI（命令行界面）才是 AI 智能体最天然、最高效的交互界面。他尖锐地指出 MCP 协议存在严重的“上下文税”问题，主张通过 CLI 工具实现更高效的工具调用。此外，他预测未来大量通用型 App 将被简化为 API，用户将通过提示词直接驱动超个性化的软件服务。文章还详细介绍了“Just Talk To It”的开发范式，强调人机协作中的迭代与直觉培养。

💡 主要观点

  1. CLI 是比 GUI 更适合 AI 智能体的交互界面。 GUI 扩展性差且难以被模型高效理解，而 CLI 具备天然的可组合性，智能体能通过阅读帮助菜单快速掌握工具使用，降低开发门槛。
  2. MCP 协议存在过度营销和上下文冗余的问题。 MCP 往往是对 API 的重包装，会消耗大量 Token（上下文税）。相比之下，CLI 配合管道符（Pipe）能更精准地过滤信息，节省模型上下文空间。
  3. 未来软件将从“通用 App”转向“超个性化 API”。 随着智能体能力的提升，传统应用的功能将被拆解为 API，提示词将成为新的交互界面，用户不再需要订阅通用软件，而是按需构建解决方案。
  4. 提倡“Agentic Engineering”而非过度依赖复杂框架。 开发者应学会“直接与 AI 交谈”，通过小步快跑、实时反馈和人机协作来构建软件，而非试图设计完美的、长时间运行的自动化工作流。

💬 文章金句

  • Apps will melt away. The prompt is your new interface.（应用将会消融，提示词就是你的新界面。）
  • 如果聪明一点，就应该按照模型已经习惯的方式去构建工具，为模型设计，别为人类设计。
  • MCP 的存在更多是为了让市场部门高兴。几乎所有的 MCPs 其实都应该是 CLI 工具。
  • 不要把时间浪费在 RAG、子智能体、Agents 2.0 或其他大多只是『花架子』的东西上。直接跟它对话。去把玩它。培养直觉。
  • 智能体天生就懂 Unix 系统，你可以在电脑上放一千个小程序，它们只需要知道程序的名字，调用一下帮助菜单，就知道该怎么用了。
