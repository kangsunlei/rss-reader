每天省 5000 美元、18PB 数据大迁徙！Ruby On Rails 之父冲刺“下云”的最后 49 天

5/12/2025, 11:01:00 AM

📌 一句话摘要

经过多年努力，37signals 公司通过将 18PB 数据从 AWS 迁移到自建数据中心，每年节省 200 万美元云服务费用

📝 详细摘要

文章详细介绍了 37signals 公司（Ruby on Rails 之父 DHH 所在公司）从 AWS 云服务迁移到自建数据中心的完整过程。该公司通过采购 Dell 服务器和 Pure Storage 设备，成功将 18PB 数据从 AWS S3 迁移到本地存储，预计每年可节省约 200 万美元的云服务费用，云账单从 320 万降至 100 万以下。AWS 免除 25 万美元数据传出费用，《欧洲数据法案》的实施为迁移提供了政策支持。文章分析了迁移的技术方案、成本对比和实际效果，包括 Pure Storage 设备兼容 S3 API 简化迁移过程，运维团队规模未增加等细节。同时也深入讨论了'下云'策略的争议点，包括机会成本、运维负担和创新瓶颈等问题，并以 Dropbox 案例作为对比参考。

💡 主要观点

  1. 大规模云迁移可显著降低企业 IT 成本 37signals 通过将 18PB 数据从 AWS 迁移到自建数据中心，预计每年节省 200 万美元，云账单从 320 万降至 100 万以下，且运维团队规模未增加
  2. Pure Storage 设备兼容 S3 API 简化迁移 选择兼容 S3 API 的 Pure Storage 系统避免了复杂的对象存储软件改造，降低了迁移技术难度，18PB 数据迁移在 49 天 deadline 内完成
  3. 政策环境促进云迁移可行性 《欧洲数据法案》实施推动 AWS 免除 25 万美元数据传出费用，降低了迁移壁垒
  4. 云迁移存在隐性成本和机会成本 批评者指出迁移需要投入大量工程资源，可能影响产品创新(如 AI 功能缺失)，且硬件更新、运维等长期成本未完全体现，Dropbox 案例显示可能影响市值增长
  5. 企业规模决定云战略适用性 文章强调不同规模、阶段的企业需要根据自身情况权衡云与本地部署的利弊，37signals 作为中型 SaaS 公司的案例具有参考价值但不可简单复制
