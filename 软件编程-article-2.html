DeepSeek Harness 拆解：一套能拼装的 Agent 架构

8/14/2026, 9:20:00 AM

📌 一句话摘要

本文深度拆解 DeepSeek Harness 的运行时架构，重点分析其基于 Cordis 的插件机制、可逆副作用设计、双层 Scope 继承链及 Code Mode 隔离方案。

📝 详细摘要

文章详细剖析了 DeepSeek 首款 Agent 产品 DeepSeek Harness 的核心设计。其架构基于 Cordis 插件框架，践行「一切皆插件」理念，通过 Fiber 状态机和 effect 机制实现了可逆副作用管理，确保插件在卸载或热重载时能完整逆转对环境的修改。文章深入探讨了其独特的双层 Scope 链设计，通过逻辑绑定而非重复加载实现预设（Preset）的高效复用；分析了基于 node:worker_threads 的 Code Mode 隔离方案，提供了比传统 vm 沙箱更可靠的安全性；并介绍了分层遮蔽的工具注册算法。最后，作者对比了 DeepSeek Harness 与 OpenAI Codex 在核心循环可替换性、沙箱位置及隔离技术选型上的工程差异。

💡 主要观点

  1. 基于 Cordis 的可逆副作用机制是架构地基。 通过 ctx.effect 追踪所有资源分配、事件注册和状态变更，确保插件卸载时能按 LIFO 顺序完整逆转副作用，实现无需重启宿主进程的动态演化。
  2. 双层 Scope 链设计平衡了配置复用与隔离。 将预设（Preset）的真实继承与会话（Session）的逻辑绑定拆分，使得一份预设实例可被多个会话同步复用，避免了重复解析配置的开销。
  3. Code Mode 采用 worker_threads 实现强隔离。 放弃易逃逸的 vm 沙箱，选择独立的工作线程以获得独立的 V8 堆和强制终止能力，并将模型生成的代码视为「敌对」输入进行严格的通信校验。
  4. 工具注册采用分层遮蔽算法实现就近覆盖。 工具可见性由 Scope 链实时计算，当前作用域注册的工具可覆盖祖先节点的同名条目，并硬编码预留核心指令以防止命名冲突。

💬 文章金句

  • 「everything is a plugin」的重点放在了运行时架构上，官方给的关键词是全部走插件机制。
  • 有没有一种 programming model，能让动态本身具备类似进程那样的生命周期隔离？
  • 副作用和它的逆写在一起，销毁由框架触发。两边共享同一个核心约定：副作用和它的逆写在一起，销毁由框架触发。
  • 卸载一个插件，会连带把它下面挂的子插件一起按栈的顺序拆干净，不需要单独维护一张「谁依赖谁」的清理表。
