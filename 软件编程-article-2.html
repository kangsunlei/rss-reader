DongSQL V1.2.0 发布：持续深耕零售数据库内核，性能与稳定性双重跃升

5/27/2026, 11:27:00 AM

📌 一句话摘要

京东自研数据库内核 DongSQL V1.2.0 正式发布，在热点行更新、主从复制、执行计划缓存、海量表启动及 SIMD 加速等核心维度实现重大性能突破，为零售场景提供更坚实的技术底座。

📝 详细摘要

本文由京东零售数据库团队发布，详细介绍了自研数据库内核 DongSQL V1.2.0 版本的核心技术升级。新版本在多个关键领域实现了重大突破：通过组提交单播通知和半同步复制优化，大幅提升了高并发写入和主从复制性能；引入执行计划缓存功能，避免重复生成执行计划，显著提升 OLTP 查询性能；扩展了单点查询优化的支持范围，新增对唯一索引和 VARCHAR/CHAR 类型的支持；创新性地利用文件扩展属性（xattr）实现海量表极速启动，将百万级表的启动时间从分钟级降至秒级；使用 AVX2 指令集加速 SQL 摘要计算；最引人注目的是热点行更新优化，通过 SQL 层缓存的更新批量合并机制，在高并发场景下实现了最高 9 倍的 TPS 提升和 95% 的延迟降低；此外还新增了带量压测支持、Statement Outline 功能移植（5.7 版本）以及多项监控和性能优化。文章提供了详尽的性能测试数据和最佳实践建议，展示了京东在数据库内核技术领域的深厚积累。

💡 主要观点

  1. DongSQL V1.2.0 通过组提交单播通知和半同步复制优化，显著提升高并发写入和主从复制性能。 将传统广播唤醒改为逐个单播唤醒，避免惊群效应和锁竞争；优化 binlog 位点更新时机和 ACK 时中继日志刷新，8.0 版本半同步复制性能最高提升 25%。
  2. 引入执行计划缓存（Plan Cache），避免重复生成执行计划，显著提升 OLTP 查询性能。 缓存 SELECT 语句的执行计划，特别适用于频繁执行相同 SQL 模式的高并发短查询场景，有效降低 CPU 消耗。
  3. 热点行更新优化通过 SQL 层缓存的更新批量合并机制，在高并发场景下实现最高 9 倍 TPS 提升。 摒弃传统串行等锁思路，采用 Leader-Follower 模式，Follower 线程直接从 SQL 层缓存读取数据，减少 B+ 树遍历和死锁检测开销，平摊网络延迟，128 线程峰值达 34，127 TPS。
  4. 利用文件扩展属性（xattr）实现海量表极速启动，大幅缩短故障恢复时间。 将表空间文件的 space id 信息保存在文件扩展属性中，启动时无需解析每个文件的第一个页，100 万张表的启动时间从分钟级降至秒级。
  5. 新增带量压测支持，通过低优先级队列确保压测期间业务 SQL 优先执行。 利用 MSG_PEEK 预读技术和自动开关机制，将带有 DONGSQL_LOW_PRIO Hint 的压测 SQL 路由到低优先级队列，512 并发压测下用户流量 TPS 提升高达 911 倍。

💬 文章金句

  • DongSQL V1.2.0 在热点行更新优化、主从复制性能、执行计划缓存、带量压测支持、海量表启动速度、SIMD 加速等多个维度实现了重大突破。
  • 摒弃'串行等锁'传统思路，引入 SQL 层缓存的更新批量合并机制，从根本上打破 UPDATE 串行执行和网络延迟的物理瓶颈。
  • 开启 hotspot 后，高并发下平均延迟从 72.69ms 降至 3.78ms，降低 95%。
  • 512 并发压测场景下，用户流量 TPS 提升高达 911 倍，平均延迟降低 90%，tp99 延迟降低 66～71%。
  • 京东零售数据库团队始终以'业务价值驱动技术创新'为核心理念，持续深耕数据库内核技术。
