Airbnb 如何在 Kubernetes 上规模化、可靠地运行分布式数据库

10/1/2025, 3:30:18 PM

📌 一句话摘要

Airbnb 的工程团队分享了在 Kubernetes 上大规模、可靠运行分布式数据库的独特方法。该方法利用自定义 Operator 和 EBS，并横跨多个 AWS 可用区。

📝 详细摘要

本文探讨了 Airbnb 如何在 Kubernetes 上大规模部署分布式 SQL 数据库，以应对有状态工作负载带来的挑战。与常见的模式不同，Airbnb 将数据库集群部署在多个 Kubernetes 集群上，每个集群映射到一个不同的 AWS 可用区，以提高可靠性和容错隔离。关键技术包括使用 AWS EBS 卷，并结合 Kubernetes 持久卷声明（PVCs），以实现持久化存储。这种方式支持快速重新挂载，并使用自定义 Kubernetes Operator 精细化地管理节点更换，确保数据库仲裁和数据一致性。本文还详细介绍了应对策略，包括使用准入钩子和序列化替换来处理计划内事件、主动基础设施事件和计划外故障。此外，Airbnb 采用自管理 Kubernetes，并实施分阶段的跨集群升级策略。结合多集群部署和过度配置，实现了高容错性，并有效降低了故障的爆炸半径。实施了高级读取策略，例如存储读取超时、副本读取和过期读取，以缓解 EBS 尾部延迟峰值。这种全面的方法使 Airbnb 能够以高可用性和可扩展性处理每秒数百万个查询。

💡 主要观点

  1. Airbnb 在 AWS 可用区上的多 Kubernetes 集群部署确保了分布式数据库的卓越容错隔离。 这种不常见的设计选择可以防止单点故障，将问题限制在一个区域或集群中，并显著减少基础设施故障或不当部署的爆炸半径。
  2. 自定义 Kubernetes Operator 对于在 Kubernetes 上安全地管理有状态分布式数据库至关重要。 该 Operator 协调节点更换，与存储（EBS/PVCs）集成，并处理各种故障场景，以维持数据一致性和可用性，克服 Kubernetes 默认的无状态特性。
  3. 持久存储 (EBS) 和高级读取策略的结合减轻了高吞吐量分布式数据库中的延迟挑战。 EBS 提供数据持久性和快速重新挂载能力，而读取超时、副本读取和过期读取等技术可最大限度地减少存储延迟峰值对系统性能和可用性的影响。

💬 文章金句

  • 他们没有将数据库集群限制在一个 Kubernetes 环境中，而是选择将分布式数据库集群部署在多个 Kubernetes 集群上，每个集群都映射到不同的 AWS 可用区。
  • Airbnb 为其分布式数据库构建了一个自定义 Operator。它的工作是仔细管理节点更换。它确保新节点上线时，在发生另一次更换之前，它已与集群完全同步。
  • 通过将集群分布在三个可用区中，Airbnb 确保单个可用区的故障不会影响整个数据库的正常运行。
  • 如果 EBS 出现延迟，查询可以自动在集群中的其他节点上重试，避免无限期等待。
  • 关键在于，当与周密的工程设计相结合时，开源分布式数据库可以在 Kubernetes 上取得成功。
