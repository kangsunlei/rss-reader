我把我的 AI 编程助手变成了一个架构魔怔人——7 行 FizzBuzz 变成 560 行，它居然还能跑

7/5/2026, 4:08:16 PM

📌 一句话摘要

一个 Claude Code 插件使 AI 助手极端过度工程化代码，将 7 行 FizzBuzz 膨胀为 560 行 22 文件仍能正常运行，展示了设计模式的夸张应用，兼具恶搞与反模式教学价值。

📝 详细摘要

文章介绍了作者开发的 Claude Code 插件 Manbun，它强制 AI 助手在写代码前经历九步「架构天梯」检查（封装接口、工厂、单一职责、依赖注入等），导致代码量膨胀 30-80 倍，文件数增加 15-22 倍，但所有代码都能编译通过并运行测试。通过计数器、FizzBuzz、邮箱验证、防抖函数、Todo API 五个任务的对比表展示了膨胀效果。作者表示初衷是整活，但生成的代码让设计模式变得直观可理解，具有一定的反模式教学价值。文章还提到作为对 Ponytail 项目的镜像回应，两者分别代表代码最小化与架构最大化的极端。最后给出了插件的安装与使用说明。

💡 主要观点

  1. Manbun 插件通过九步检查让 AI 助手极端过度工程化代码。 插件在生成代码前自动执行接口封装、工厂模式、单一职责等检查，导致代码量膨胀 30-80 倍，但代码仍能通过测试。
  2. 膨胀后的代码展示了设计模式在极端情况下的应用。 五个示例任务在加持后分别应用了策略、观察者、工厂、责任链等 5-7 个设计模式，让读者直观感受过度工程化的效果。
  3. 该项目与追求最小代码的 Ponytail 形成镜像对比。 Manbun 代表极致的架构派，Ponytail 代表极致的极简派，两者展示了编程哲学的两端。
  4. 项目主要目的是娱乐，但意外具有反模式教学意义。 通过夸张的代码膨胀，反而帮助理解设计模式的实际运用，提示过度工程化的陷阱。
