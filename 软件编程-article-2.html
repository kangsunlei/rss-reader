LiteLLM 主密钥泄露，攻击者窃取 GitHub 令牌劫持发布流水线

10/25/2026, 10:00:00 AM

📌 一句话摘要

LiteLLM 因主密钥泄露，攻击者利用该密钥访问 Agent Platform，窃取 GitHub CLI OAuth 令牌，进而劫持发布流水线，推送恶意版本至 PyPI 和 Docker Hub。

📝 详细摘要

2026 年 5 月，LiteLLM 的主密钥被意外发布到 GitHub，随后被攻击者利用。攻击者在 10 月 10 日获取了 GitHub CLI OAuth 令牌，并于 10 月 21 日篡改发布流水线，将代码源替换为恶意仓库，成功发布了包含后门的 LiteLLM 1.107.0 版本。该版本不仅窃取开发者凭证，还包含一个每小时执行恶意代码的 Unix 后门。

💡 主要观点

  1. 主密钥泄露导致权限被盗 2026 年 5 月，LiteLLM 的主密钥被意外提交到公开仓库。虽然密钥被立即删除，但攻击者在 10 月 10 日利用该密钥访问了 Agent Platform，并提取了具有组织所有者权限的 GitHub CLI OAuth 令牌。
  2. 发布流水线被劫持 攻击者利用窃取的令牌，于 10 月 21 日绕过分支保护，将发布流水线的代码源从官方仓库替换为仿冒仓库。这导致恶意代码被编译并发布为 LiteLLM 1.107.0 版本。
  3. 恶意包包含后门和窃密功能 发布的 1.107.0 版本包含一个窃密模块，用于收集系统和开发者的敏感信息（如 API 密钥和 SSH 文件），并包含一个每小时执行恶意代码的 Unix 后门。该版本已在 PyPI 和 Docker Hub 上被隔离。

💬 文章金句

  • 2026 年 5 月 27 日，公开仓库 LiteLLM-Labs/lite-harness 收到一份配置文件提交，文件意外包含 LiteLLM Agent Platform 部署环境的主密钥。
  • 攻击者获取该令牌后，获得了组织内所有仓库的所有者级权限，进而窃取了更多凭证。
  • 该恶意程序包含两条执行路径：一是凭证窃取模块，针对开发者工具、AI 应用、云环境、网页浏览器中的认证信息；二是面向 Unix 系统的后门，以后台进程运行，每小时拉取并执行攻击者下发的任意代码。
