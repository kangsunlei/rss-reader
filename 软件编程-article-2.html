Flipkart 高可用 MySQL 集群构建实践：支撑 1.5 亿用户

10/7/2025, 3:30:42 PM

📌 一句话摘要

Flipkart 通过内部 MySQL 高可用服务 Altair，利用强大的故障转移机制，为高流量电商工作负载提供持续可用性并减少数据丢失。

📝 详细摘要

本文详细介绍了 Flipkart 的 Altair 系统，这是一个定制解决方案，旨在提供高可用性 MySQL 集群，以支持其大规模的电子商务运营。面对管理数千个微服务和极端流量激增的挑战，Flipkart 采用 Altair 实现标准化，以确保依赖 MySQL 的关键事务域保持持久性并保障 ACID 特性。该系统采用主从设置与异步复制，优先考虑写入可用性。关键设计考虑因素包括可靠的故障检测、强大的故障转移工作流程、网络分区处理和脑裂预防。Altair 的多层监控（代理、监控器、协调器）和复杂的误报筛选机制确保了准确的故障检测。故障转移涉及结构化的过程，包括隔离旧主节点、提升从节点，并通过 DNS 更新实现应用无缝切换。本文还讨论了异步复制中一致性和可用性之间的权衡，并强调了 Altair 的可扩展监控和简化的服务发现。

💡 主要观点

  1. Flipkart 的 Altair 为关键事务系统标准化了 MySQL 高可用性。 Altair 通过标准化的内部管理服务，解决了大规模 MySQL 管理的难题。这使得工程团队能够专注于业务逻辑，提升效率。
  2. 该系统使用主从模型与异步复制，优先考虑写入可用性。 该系统采用主从模型和异步复制，在主节点故障时快速提升健康从节点，确保写入操作的连续性，并在一定程度上降低数据丢失的风险，从而保证高可用性。
  3. Altair 采用三层监控系统来实现强大而准确的故障检测。 Altair 采用三层监控系统，由节点上的代理、Go 语言实现的监控器以及中央协调器协同工作，以实现强大而准确的故障检测，筛选误报并可靠地启动故障转移过程。
  4. 全面的故障转移工作流程和保障措施可防止脑裂情况。 系统通过隔离旧主节点、更新基于 DNS 的服务发现和精细化的网络分区管理，全面避免数据不一致，保障数据安全。

💬 文章金句

  • Flipkart 工程团队构建了内部管理服务 Altair，旨在提供高可用性 (HA) MySQL 作为标准功能，解决现有问题。
  • 此设置的目标明确：在主节点发生故障时，系统快速提升健康的从节点作为新的主节点。
  • Altair 使用三层监控系统来检测故障：代理、监控器和协调器。
  • 在任何高可用架构中，最大的风险之一是脑裂，即两个不同的节点同时认为自己是主节点。
  • Flipkart 选择优先考虑可用性。在实践中，这意味着在故障转移期间，旧主节点上的最后几个事务可能无法到达新的主节点。
