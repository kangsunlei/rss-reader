ChatGPT 文件下载漏洞，攻击者可窃取本地系统文件

7/3/2026, 10:00:00 AM

📌 一句话摘要

安全研究员发现 ChatGPT 文件下载流程中的漏洞链，结合防护机制绕过与路径遍历攻击，可访问受限系统文件；OpenAI 已修复。

📝 详细摘要

本文报道了 ChatGPT 中存在的一个概念验证漏洞链，涉及防护机制绕过与路径遍历缺陷。研究员 zer0dac 通过四步操作（文件上传、防护绕过、LLM 社会工程、端点拦截）获取有效下载 URL，并利用路径规范化不一致的缺陷，在 sandbox_path 参数后附加遍历序列，成功读取沙盒外的/etc/passwd 文件。文章指出，虽然 ChatGPT 沙盒化环境限制了实际影响，但该漏洞链展示了 AI 安全中提示操控与传统 Web 漏洞交汇的风险。OpenAI 已通过重新设计 URL 下载流程修复问题。文章来源于 FreeBuf，编译自外媒报道。

💡 主要观点

  1. 漏洞利用链包含四步：文件上传、防护绕过、LLM 社会工程、端点拦截。 研究员先上传虚拟 HTML 文件建立沙盒路径，再通过诱导 ChatGPT 声称文件被删除生成有效下载 URL，最后从生成的端点中发现后端 API 结构。
  2. 关键突破在于利用路径规范化不一致绕过验证。 直接使用../../遍历会被阻止，但保留合法路径后附加遍历序列（如/mnt/data/test.html/../../../../etc/passwd）可欺骗验证逻辑，成功读取系统文件。
  3. 漏洞现实影响有限，但对 Agent 和工具增强型 LLM 架构有警示意义。 ChatGPT 沙盒环境限制了数据泄露，但该技术可成为更大规模攻击链的构建模块，提示安全测试需同时覆盖 AI 特定红队测试和传统 Web 应用安全测试。

💬 文章金句

  • 单独发现的 LFI 和路径遍历原语可能成为更大规模漏洞利用链的构建模块，特别是在具有更广泛文件访问权限或与其他服务交互的 Agent 或工具增强型 LLM 架构中。
  • 需要同时对这些系统应用 AI 特定的红队测试和传统 Web 应用安全测试。
