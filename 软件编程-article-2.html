构建安全的 AI 代理 - Vercel

6/9/2025, 1:00:00 PM

📌 一句话摘要

确保 AI 代理安全需要假设 Prompt 受控 并对工具进行权限限定。

📝 详细摘要

这篇来自 Vercel 博客的文章讨论了构建 AI 代理时的关键安全风险，特别是关注 Prompt 注入 和数据泄露。它强调，核心设计原则是假设攻击者控制所有输入，包括检索到的数据。文章重点强调的一种主要防御机制是根据调用者的权限严格限定代理可用的工具范围，以防止未经授权的操作。文章使用经典的“Little Bobby Tables”类比来说明 Prompt 注入 本质上是一个数据问题，类似于 SQL 注入。它还警告通过模型输出进行数据泄露，例如注入恶意 Markdown，并建议清理输出 并避免直接渲染。文章总结说，安全关乎遏制和最大限度地减少模型错误行为造成的损害，而不是信任它会遵守规则。

💡 主要观点

  1. 在 AI 代理设计中假设 Prompt 完全受控。 在构建代理时，工程师必须假设攻击者控制所有输入，包括检索到的数据，以便预测和减轻潜在的攻击向量。
  2. 根据调用者权限限定代理工具范围。 仅授予代理用户已有的权限，通常通过绑定参数（如 租户 ID），可以防止权限提升 和数据泄露。
  3. 将模型输出视为不可信，以防止数据泄露。 在渲染或处理模型输出之前对其进行清理或仔细处理至关重要，以防止攻击者嵌入恶意负载，如 图像 URL。
  4. 安全侧重于限制损害，而非信任模型。 Prompt 注入 是 LLM 固有的特性；强大的安全性依赖于遏制和最大限度地减少代理执行攻击者指令的后果。

💬 文章金句

  • 最关键的安全风险是 Prompt 注入。
  • 假设攻击者控制整个 Prompt。
  • 工具必须根据调用者的权限限定范围。不要让模型访问用户本来就无法做到的任何事情。
  • 模型无法区分用户意图 和注入的内容。
  • 安全不是关于信任模型。它关乎在模型行为不正确时最大限度地减少损害。
