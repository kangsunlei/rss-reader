使用 Python 数据源 API 提速 7 倍的医学影像导入

8/7/2025, 8:00:00 PM

📌 一句话摘要

Databricks 引入 Python 数据源 API，以 7 倍的速度和经济高效的方式将复杂的医学影像（如压缩的 DICOM）导入到 Spark 中。

📝 详细摘要

本文探讨了医疗机构在导入各种专业医学影像数据（例如通常存储在压缩 ZIP 存档中的 DICOM 文件）时面临的重大挑战。文章强调，由于多步骤 ETL（抽取、转换、加载）管道涉及大量的磁盘 I/O（输入/输出）进行提取，传统的 Spark 处理方法速度慢且成本高。提出的核心解决方案是新的 Python 数据源 API，它能够将医疗保健特定的 Python 库（如 pydicom）直接集成到 Spark 的分布式框架中。这种方法以自定义“zipdcm”数据源为例，通过一步处理压缩文件而无需事先提取，实现了高达 7 倍的更快处理速度和惊人的 57 倍云存储成本降低。文章概述了实现原理，展示了该 API 如何简化大规模医学影像数据导入。这从而提高了效率和成本效益。

💡 主要观点

  1. 由于多步骤 ETL（抽取、转换、加载），Spark 中传统的医学影像处理速度慢且成本高。 现有方法需要在处理之前将压缩的医学影像（例如，压缩的 DICOM）提取到临时存储，从而导致显著的磁盘 I/O（输入/输出）开销和性能瓶颈。
  2. Python 数据源 API 能够在 Spark 中直接、单步处理复杂格式。 这个新的 API 允许将专业的 Python 库无缝集成到 Spark 的分布式框架中，从而消除了中间提取步骤和复杂的 UDF 的需求。
  3. 像“zipdcm”这样的自定义数据源实现了显著的性能和成本优势。 通过利用 Python 数据源 API，“zipdcm”读取器展示了压缩 DICOM 文件高达 7 倍的更快处理速度和 57 倍更低的云存储成本，从而优化了大规模数据导入。

💬 文章金句

  • 虽然 Apache Spark™ 为大约 10 种标准数据源类型提供了强大的支持，但医疗保健领域需要访问数百种专门的格式和协议。
  • 新的 Python 数据源 API 通过将医疗保健特定的 Python 库直接集成到 Spark 的分布式处理框架中来解决这个问题。
  • 使用 Python 数据源 API 实现的自定义数据源，将 ZIP 文件提取与 DICOM 处理相结合，可提供令人印象深刻的结果：与传统方法相比，处理速度提高了 7 倍。
  • 通过保持源数据压缩状态，而不解压 zip 存档，我们实现了惊人的（4TB 解压缩与 70GB 压缩相比）降低了 57 倍的云存储成本。
