Localhost 潜藏的危机：CORS 与 DNS 重绑定攻击

📌 一句话摘要

本文剖析 CORS 错误配置与 DNS 重绑定攻击的风险，结合实例提供安全建议，强调正确配置 CORS 策略和验证 Host 标头的重要性。

📝 详细摘要

本文深入分析了跨域资源共享 (CORS) 错误配置和 DNS 重绑定攻击的原理、常见错误和潜在风险。通过真实世界的案例研究，展示了不当 CORS 设置导致的安全问题，如通过文件写入实现的远程代码执行 (RCE) 和未授权访问。本文还解释了 DNS 重绑定攻击的机制，并强调了正确配置 CORS 策略和验证 Host 标头以防止潜在安全风险的重要性。它进一步建议开发人员关注 CORS 机制，避免常见的配置错误，必要时验证 Host 标头，并利用 GitHub 代码安全功能来增强 Web 应用程序的安全性。

💡 主要观点

  1. CORS 配置错误可能导致严重的安全漏洞 错误的 CORS 配置允许攻击者代表用户执行操作，可能导致严重的漏洞，例如远程代码执行 (RCE)。
  2. 像 endsWith 和 startsWith 这样的字符串比较函数对于 CORS 验证是不安全的 使用这些函数进行域验证很容易被攻击者利用；应采用 exactMatch，或结合 endsWith 进行子域验证。
  3. 验证 Host 标头是防止 DNS 重绑定攻击的有效方法 检查 Host 标头是否与批准的主机名或本地名称匹配可以有效地防止 DNS 重绑定攻击。
  4. DNS 重绑定攻击可以绕过同源策略 攻击者控制 DNS 服务器以使浏览器连接到本地地址，从而利用未受保护的 API 端点。

💬 文章金句

  • CORS 问题可能赋予用户 Web 应用管理员权限，其影响取决于具体应用。
  • DNS 重绑定不需要开发人员或用户的错误配置或错误。相反，它是对 DNS 系统工作方式的攻击。
  • 在发布包含安全关键信息或执行特权操作的软件时，我们强烈建议开发人员编写代码来检查 Origin 标头是否与 Host 匹配，或存在于允许列表中。
