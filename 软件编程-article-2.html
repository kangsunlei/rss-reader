Netflix 如何运行在 Java 上？

6/3/2025, 3:30:52 PM

📌 一句话摘要

分析 Netflix 如何利用虚拟线程和 ZGC 等现代 Java 特性，结合 Spring Boot 和 GraphQL 联邦，构建其大规模后端。

📝 详细摘要

本文探讨了 Netflix 庞大后端基础设施背后的战略技术选择，主要聚焦于 Java。文章强调了 Netflix 使用的 GraphQL 联邦架构，该架构使客户端能够与数十个基于定制 'Spring Boot Netflix' 技术栈构建的独立 Java 后端服务进行交互。文中讨论了 JDK 17+、用于低暂停垃圾回收的分代 ZGC 以及用于改进并发性的虚拟线程等关键现代 Java 特性，认为它们是实现性能和可伸缩性的重要要素。文章还提到了公司从旧版 JDK 和定制框架迁移到标准化使用 Spring Boot 的策略，以及他们放弃 RxJava 等响应式编程范式，转而倾向于在大多数后端用例中使用虚拟线程的理由。还概述了协议选择（客户端-网关使用 GraphQL/HTTP，内部服务通信使用 gRPC）。本文取材于 Netflix 工程团队公开分享的信息。

💡 主要观点

  1. Netflix 利用基于 Spring Boot DGS 构建的 GraphQL 联邦架构。 这使得独立的后端服务（域图服务，DGS）能够拥有各自的 Schema 片段，通过中央 API 网关实现灵活的客户端查询和独立的服务演进。
  2. ZGC 等现代 Java 特性显著改进了性能和可靠性。 升级到 JDK 17+ 并采用分代 ZGC 极大地减少了高负载下的 GC 暂停时间和错误率，提高了 CPU 利用率。
  3. 虚拟线程简化了 Java 中的高并发编程。 它们使得 Spring Boot DGS 等框架中的阻塞 I/O 代码能够高效扩展，无需复杂的响应式模式，从而提高了扇出查询的性能。
  4. Netflix 通过迁移数千个服务标准化使用 Spring Boot。 从遗留框架迁移到统一的 Spring Boot Netflix 技术栈，加速了平台演进和公司范围内基础设施组件的集成。
  5. 内部服务通过 gRPC 进行通信以实现高性能。 虽然 GraphQL 用于外部通信，但 gRPC 在后端微服务之间提供了高效、强类型、低延迟的通信。

💬 文章金句

  • Netflix 的大多数后端服务运行在 Java 上。
  • 随着虚拟线程和结构化并发的到来，Java 在高吞吐、低延迟系统设计中重新占据了重要地位，且没有响应式带来的复杂性开销。
  • Netflix 的每个域图服务 (DGS) 都是一个 Spring Boot 应用。
  • 在 JDK 21 中，分代 ZGC 终于到来。它带来了一个现代的、低暂停的垃圾回收器，并且理解对象生命周期。效果立竿见影。
  • 随着 Java 21+ 的推出，Netflix 开始推广使用虚拟线程。这些轻量级线程由 JVM 而非 OS 调度，使得阻塞代码可以在不独占资源的情况下进行扩展。
