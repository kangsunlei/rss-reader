将 Prometheus 告警规则迁移至 Grafana

7/14/2025, 1:18:28 PM

📌 一句话摘要

Grafana 12 引入新的用户界面和 API，简化 Prometheus 告警规则的迁移。

📝 详细摘要

本文详细介绍了 Grafana 12 中新的**批量**告警和记录规则导入功能。这项功能旨在解决将现有 Prometheus 告警规则迁移到 Grafana 的问题，这些规则通常使用 `mimirtool` 或 `cortextool` 等工具进行管理。解决的核心问题是 Prometheus（将空结果视为健康）和 Grafana（使用“无数据”状态）之间告警评估行为的差异。Grafana 12 通过提供与 Prometheus 工具兼容的 API，并引入用于**批量**导入的用户界面来解决这个问题。在幕后，Grafana 向导入的规则添加了一个数学表达式，以确保评估行为与 Prometheus 保持一致。本文还介绍了为导入的规则启用 Grafana 的高级功能（基于角色的访问控制、可视化、路由），并引用了有关实际迁移步骤的文档。

💡 主要观点

  1. Grafana 12 通过用户界面和 API 简化了 Prometheus 告警的迁移。 新功能支持批量导入 Prometheus 告警和记录规则到 Grafana，减少手动工作和潜在错误。
  2. 导入尊重 Prometheus 的评估行为，尽管存在差异。 Grafana 在导入过程中添加了一个查询后数学表达式，以确保规则的行为与在 Prometheus 中一样，一致地处理空查询结果。
  3. 现有的 Prometheus 工具可以与 Grafana API 一起使用。 兼容的 API 允许使用 `mimirtool` 或 `cortextool` 的工作流直接指向 Grafana 实例，保留已建立的 CI/CD 管道。
  4. 迁移的规则可以访问高级 Grafana 告警功能。 导入后，规则可以利用 Grafana 的基于角色的访问控制、状态历史记录、版本控制、增强的路由和可视化功能。

💬 文章金句

  • 如果我们可以在不重写 Prometheus 风格告警的情况下轻松地将其迁移到 Grafana 中呢？
  • 为了使这成为可能，我们向 Grafana 添加了与 Mimir 和 Loki 兼容的 API，因此如果您的工作流程已经使用 `mimirtool` 或 `cortextool`，则只需将它们指向您的 Grafana 实例，一切都会继续工作。
  • 但是，将告警从 Prometheus 转换为 Grafana 并不总是像看起来那么简单。
  • 为了保留类似 Prometheus 的行为，导入程序在 Prometheus 查询之后向规则处理流程添加了一个小的数学表达式。
