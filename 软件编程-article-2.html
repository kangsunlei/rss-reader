📌 一句话摘要

本文系统解读 Claude Code 的 7 种配置方式，结合官方文档与作者实践，给出事实/流程分离、按需加载、Hook 兜底等关键原则。

📝 详细摘要

文章基于 Anthropic 官方博文《Steering Claude Code》，结合作者自身使用经验，详细介绍了 Claude Code 的 7 种配置方式：CLAUDE.md、Rules、Skills、Subagents、Hooks、Output Styles 和 Append System Prompt。每种方式从加载时机、令牌占用、适用场景等维度进行了对比，并给出了具体建议（如 CLAUDE.md 只放事实、Skills 放流程、用 Hook 实现确定性自动化）。作者还分享了索引式 CLAUDE.md、Skills 封装重复工作流、Subagent 调研型任务等实操心得，最后总结了这套配置体系的设计思想：事实与流程分离、按需加载、确定性优于概率性、隔离执行避免上下文污染。

💡 主要观点

  1. CLAUDE.md 只放「事实」，不放「流程」。 构建命令、目录结构、代码规范等事实性信息应放在 CLAUDE.md 中，且控制在 200 行内；部署流程、审查清单等流程性内容应封装为 Skills 按需加载，避免浪费令牌。
  2. Skills 是被低估的按需加载机制。 Skills 的渐进式加载设计使其可以在不占令牌的情况下定义数十个技能，仅在需要时完整加载，适合封装重复性工作流，如部署、代码审查等。
  3. 安全约束不能依赖 AI 的自觉性，需 Hook + 权限双重保障。 在 CLAUDE.md 中写「永远不要删除迁移文件」仍可能被 AI 违反，应使用 PreToolUse Hook 拦截危险操作，再配合组织级权限实现确定性安全。
  4. Subagent 用于消耗大但只需要最终结果的调研型任务。 Subagent 运行在独立上下文中，中间过程不污染主会话，适合代码审计、日志分析、依赖检查等场景，可嵌套最多 5 层。

💬 文章金句

  • CLAUDE.md 只放「事实」，不放「流程」。
  • 安全这件事，不能指望 AI 的自觉性。
  • 事实和流程分离、按需加载降低成本、确定性保障优于概率性指令、隔离执行避免上下文污染。
  • 如果指令放错了地方，AI 可能直接忽略掉你的指令，白白浪费 tokens。
