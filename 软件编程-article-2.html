Google 发布 AppFunctions，旨在连接 AI 智能体与 Android 应用

3/29/2026, 8:00:00 PM

📌 一句话摘要

Google 推出了 AppFunctions，这是一个 Jetpack API，使 Android 应用能够向 AI 智能体开放功能，以实现设备端任务执行，并辅以 UI 自动化作为备选方案。

📝 详细摘要

Google 正在通过引入 AppFunctions 和 UI 自动化平台，将 Android 系统向「智能体优先」的操作系统转型。AppFunctions 是一个 Jetpack API，允许开发者将应用功能作为自描述模块开放给 Gemini 等 AI 智能体进行本地调用。这种设备端方案通过最小化网络延迟，优先保障了隐私和速度。对于尚未进行原生集成的应用，全新的 UI 自动化层可作为备选方案，使智能体无需开发者额外工作，即可通过与现有应用 UI 交互来执行复杂任务，例如订餐或协调拼车。目前这些功能已在 Galaxy S26 上进行测试，计划在 Android 17 中进行更广泛的推广。

💡 主要观点

  1. 引入 AppFunctions 以实现智能体与应用的协同。 一个新的 Jetpack API，让 Android 应用能够向 AI 智能体开放功能模块，使其能够无缝且以编程方式在应用内执行特定任务。
  2. 基于设备端执行，兼顾隐私与性能。 与基于云的解决方案不同，AppFunctions 在设备本地运行，这减少了网络延迟，并确保敏感的用户交互保持私密。
  3. 作为零代码备选机制的 UI 自动化。 对于尚未集成 AppFunctions API 的应用，Android 提供了一个平台级的自动化层，允许智能体导航应用 UI 以完成复杂的用户请求。
  4. 聚焦用户控制与透明度。 该架构包含针对敏感操作的强制确认机制，并通过通知提供智能体活动的实时可见性，以确保用户始终掌握控制权。

💬 文章金句

  • 为了将 Android 转变为「智能体优先」的操作系统，Google 引入了新的早期测试功能，以支持以任务为中心的操作模式。
  • AppFunctions 是一个 Jetpack API，允许开发者在应用内开放自描述功能，从而与 AI 智能体实现无缝集成。
  • 这一自动化层使得用户能够通过 Gemini 助手「下单复杂的披萨订单……协调多站拼车……或重新购买上次的杂货商品」，而无需开发者进行额外的工作。
  • 所有交互均基于设备端执行构建，并通过实时视图和/或通知为用户提供完全的可见性。
