Cosmos3-Super 512 卡 Scaling，百度百舸 AI Infra 工程优化实践

8/3/2026, 10:00:00 AM

📌 一句话摘要

本文详述百度百舸在无 NVLink、无 HPN 的通用 GPU 集群上，通过 FSDP2、ERI 网络及编译优化，实现 64B 世界模型从 4 节点到 64 节点的近线性扩展，吞吐提升至 530.227 samples/s，扩展效率达 97.48%。

📝 详细摘要

文章以百度百舸 hpas.lgn7ib 实例为基础，详细记录了将 Cosmos3-Super（64B 参数）世界模型从 4 节点 32 GPU 扩展至 64 节点 512 GPU 的全过程。通过弱伸缩实验展示了在固定单卡 batch size 的情况下，随节点数增加吞吐近乎线性增长， median step time 仅从 30.12s 增至 30.90s，吞吐从 33.997 提升至 530.227 samples/s，扩展效率保持在 97.48%。文章深入剖析了所采用的技术手段：使用 FSDP2 进行全量参数、梯度和优化器状态分片；利用百度智能云的 ERI（弹性 RDMA 互联）网络进行跨节点通信；开启 VAE 与 Language Compile 以释放算力；并在扩展过程中修复了 FSDP2 在空分片情况下 NormMonitor 和 FusedAdam 的兼容性问题。通过对比 4 节点与 64 节点的 Loss 曲线，验证了工程优化对训练收敛无影响。文章结论强调，即使在缺乏专用高性能互联（NVLink/HPN）的通用 GPU 集群上，通过训练框架、通信网络与基础设施的系统协同，同样可以实现大规模世界模型的高效、稳定训练。

💡 主要观点

  1. 在无 NVLink、无 HPN 的通用 GPU 集群上实现近线性弱伸缩 从 4 节点 32 GPU 扩展至 64 节点 512 GPU，median step time 仅增加 0.78s，吞吐提升近 16 倍，扩展效率保持在 97.48%。
  2. 关键技术：FSDP2 全量分片 + ERI 网络 + 编译优化 使用 PyTorch FSDP2 对参数、梯度和优化器状态进行全量分片；依托百度智能云的 ERI 进行跨节点 RDMA 通信；开启 VAE 与 Language Compile 以释放算力，并修复空分片下 NormMonitor 和 FusedAdam 的兼容性问题。
  3. 工程优化不影响训练收敛 4 节点与 64 节点的 Loss 曲线基本重合，均从约 26 下降至 1.7–2.1 区间，表明系统优化仅提升效率而未改变训练动态。
