📝 详细摘要

本文介绍了一个名为 Refresh 的开源项目，它是一个自托管的个人账号 Feed API。核心思路是利用 Chrome DevTools Protocol 操控一个独立的 Chrome profile，使用用户自己的浏览器登录态，从 X/Twitter、知乎、B 站等平台抓取推荐流和动态，并将其归一化为结构化资源。项目提供了 React 前端阅读界面、RSS 订阅和 JSON API 三种消费方式，并强调了隐私边界，所有登录态、抓取数据和媒体缓存均保存在本地运行态目录，不提交到仓库。文章详细说明了本地运行、部署、环境变量配置和验证方法，适合对自建信息流聚合、数据所有权有需求的开发者。

💡 主要观点

  1. 通过 CDP 操控浏览器，利用用户自有登录态抓取多平台推荐流。 项目不依赖第三方 API 或账号密码，而是通过 Chrome DevTools Protocol 控制本地浏览器，使用用户已登录的会话抓取 X/Twitter、知乎、B 站的推荐内容，实现数据所有权归用户。
  2. 提供网页、RSS 和 JSON API 三种消费方式。 抓取的内容被归一化为统一资源模型，用户可以通过 React 前端阅读、订阅 RSS 源或直接调用 JSON API 进行二次开发，满足不同场景下的信息消费需求。
  3. 严格区分应用代码与运行态数据，保障隐私。 项目通过 .gitignore 将 Chrome profile、抓取数据、媒体缓存和日志等运行态路径排除在仓库之外，确保用户登录态和私人数据不会因代码公开而泄露。
