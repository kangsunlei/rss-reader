HTTP 演进：从 HTTP/1 到 HTTP/3

5/29/2025, 3:30:46 PM

📌 一句话摘要

本文概述了 HTTP 从 1.1 到 3 的演进历程，着重探讨了性能方面的权衡。

📝 详细摘要

本文深入探讨了超文本传输协议 (HTTP) 从其主力 HTTP/1.1 版本到现代 HTTP/3 的演变，其目的是为了解决早期版本（如 TCP）的性能瓶颈。它追溯了该协议的历程，讨论了 HTTP/1.1 如何面临诸如队头阻塞等挑战，HTTP/2 如何引入多路复用和头部压缩来提高基于 TCP 的效率，以及 HTTP/3 如何利用基于 UDP 的 QUIC 来缓解这些问题并针对现代互联网使用案例进行优化。文章将探讨各版本的性能权衡和关键技术变革，包括 TCP 的设计如何影响性能、队头阻塞问题，以及 HTTP/3 在哪些方面表现出色以及仍然面临哪些问题。

💡 主要观点

  1. HTTP 的演变（1.1 到 3）主要由提高性能和克服限制的需求驱动。 每个主要版本都引入了旨在解决先前版本和底层传输协议中固有的性能瓶颈的更改。
  2. HTTP/1.1 和 HTTP/2 依赖于 TCP，面临诸如队头阻塞之类的性能挑战。 尽管 HTTP/2 引入了诸如多路复用和头部压缩之类的功能，但对 TCP 基于流的性质的依赖仍然会导致队头阻塞问题，从而影响性能，尤其是在有损网络上。
  3. HTTP/3 利用基于 UDP 的 QUIC 从根本上解决了与 TCP 相关的限制。 通过构建在 QUIC 之上，HTTP/3 缓解了传输层的队头阻塞等问题，从而实现了更快的连接建立和更高的性能，这在高延迟或移动环境中尤其有益。

💬 文章金句

  • 理解 HTTP 更多的是内化协议演变过程中融入的性能权衡，而不是记住状态代码。
  • HTTP/2 通过在单个 TCP 连接上多路复用流来提高效率。
  • 而 HTTP/3 构建于基于 UDP 的 QUIC 之上，最终摆脱了数十年之久的限制。
