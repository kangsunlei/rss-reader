Grab 如何构建 Vision LLM 来扫描图像

2/3/2026, 4:30:36 PM

📌 一句话摘要

Grab 通过结合优化的编码器和解码器，开发了一个定制的 1B 参数 Vision LLM，在实现东南亚文字高准确率的同时，延迟显著低于大型模型。

📝 详细摘要

本文详细介绍了 Grab 如何通过专门的 Vision LLM 替代传统 OCR 系统进行 eKYC 文档处理的工程历程。在发现闭源模型速度太慢且开源模型缺乏地区语言支持后，Grab 尝试了对 Qwen2-VL 进行 LoRA 和全参数微调。最终，他们通过将 Qwen2-VL 视觉编码器与 Qwen2.5 语言解码器配对，构建了一个定制的 1B 模型。该模型通过包含合成数据和内部自动标注框架（Documint）的严格四阶段过程进行训练，最终系统的速度比大型替代方案快 50% 以上，同时对泰语和越南语等复杂文字保持了高准确率。

💡 主要观点

  1. 全参数微调对于专门的非拉丁文字领域至关重要。 虽然 LoRA 很高效，但它无法弥补泰语和越南语等文字的差距。全参数微调是必要的，因为视觉编码器需要学习这些字符的特定视觉模式，而这些模式在基础模型的训练中是缺失的。
  2. 通过混合组件定制模型架构可以优化性价比。 Grab 通过将强大的 Qwen2-VL 视觉编码器与紧凑的 Qwen2.5 语言解码器相结合，构建了一个“弗兰肯斯坦”式的 1B 模型。这种混合方法为生产环境提供了一个“甜点位”，在提供高准确率的同时显著降低了计算开销。
  3. 合成数据和自动标注框架解决了地区数据稀缺问题。 通过利用 Common Crawl 生成合成文本图像，并构建“Documint”对真实文档进行自动标注，Grab 创建了一个高质量的训练流水线。这使他们能够生成无限变体的地区文字，从而提高模型的鲁棒性。
  4. 动态分辨率支持是准确 OCR 任务的关键技术要求。 与需要固定大小输入的模型不同，原生分辨率支持可以防止因缩放或裁剪导致的文本字符失真。这种对文本完整性的保护是文档密集型工作流中高准确率提取的主要驱动力。
  5. 生产级 AI 需要在所有百分位数上保持一致的延迟性能。 与大型模型相比，定制的 1B 模型在 P99 延迟上快了 56%。这种一致性对于大规模推广至关重要，因为外部 API 经常受到高延迟波动的影响，这可能会在实时验证期间破坏用户体验。

💬 文章金句

  • 语言模型可能理解泰语文本，但视觉编码器从未学习过如何识别图像中的泰语字符。
  • 能够处理动态图像分辨率的模型可以保持文本完整性，并显著提高 OCR 能力。
  • 事实证明，在专门的非拉丁文字领域，全参数微调优于 LoRA。
  • 1B 模型在 P50 延迟下处理速度快了 48%... 在 P99 延迟下快了 56%。
  • 专门的 Vision LLM 可以通过单一、统一、高准确率的模型有效地替代传统的 OCR 流水线。
