[开源] CCL：我做了一个 Claude Code 启动器，把 ccswitch 干掉了

6/15/2026, 12:05:52 PM

📌 一句话摘要

CCL 是一个 Claude Code 启动器，通过统一管理 Provider、API Key、Base URL、模型映射和内置 Proxy，解决多模型切换时的环境变量混乱问题。

📝 详细摘要

文章介绍了作者为解决 Claude Code 在多模型、多 API Key、多账号场景下的环境变量管理痛点，而开发的 CCL（Claude Code Launcher）工具。作者指出，现有方案如 ccswitch 仅解决 Proxy 切换，未覆盖 Key 管理、Base URL、模型映射、多账号切换和团队配置同步等完整需求。CCL 将 OpenAI、Anthropic、Gemini、OpenRouter、Azure 及自建 API 等 Provider 收敛到统一配置，支持一键切换个人/公司/测试账号，核心功能是模型映射（如将 Opus 映射到 GPT/Gemini/DeepSeek），并内置 Proxy 层接管请求转发，无需额外 Gateway。工具通过 npm 安装，启动命令为 `ccl`，支持会话恢复。

💡 主要观点

  1. CCL 统一管理多 Provider、多 Key、多账号，解决环境变量混乱。 将 OpenAI、Claude、Gemini、OpenRouter、Azure 等 Provider 收敛到单一配置，支持一键切换个人/公司/测试账号，无需手动 export 环境变量。
  2. 模型映射功能允许 Claude Code 底层调用非 Anthropic 模型。 用户可将 Opus/Sonnet/Haiku 等模型名映射到 GPT、Gemini、DeepSeek 等模型，在不改变 Claude Code 工作流的前提下灵活选择底层模型。
  3. 内置 Proxy 层接管请求转发，无需额外 Gateway。 CCL 直接处理请求转发，替代 ccswitch 等独立 Proxy 工具，降低运维复杂度。

💬 文章金句

  • CCL = Claude Code + 统一 Provider + 内置 Proxy + 启动器
  • ccswitch 只解决「切 proxy」，没解决「运行时管理」。
