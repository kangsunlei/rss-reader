不再做 SQL 苦力！Claude 在得物 App 数仓的深度集成与效能演进

5/5/2026, 11:15:00 PM

📌 一句话摘要

本文深入探讨了得物 App 如何通过 Claude Code 与 Galaxy MCP 的深度集成，以规范化输入输出为核心，在数仓开发中实现从 SQL 编码到业务逻辑抽象的效能演进。

📝 详细摘要

文章以得物 App 数仓的真实实践为背景，系统阐述了 Code LLM 在企业级数据仓库中的深度集成逻辑与工程实践。核心论点围绕两大支柱展开：一是明确数据确权中管理审批与技术实现的人机边界，二是构建规范化的输入输出（Standardized I/O）契约以抑制大模型幻觉。文章详细介绍了基于 Galaxy MCP 的基础设施集成方案，并深入分析了智能视觉埋点、AI OneData 建模、智能周报生成、策略孵化中心、智能测试与 Spark UI 调优等典型场景的架构设计与运行逻辑。最后，针对幻觉风险与数据安全合规，提出了一套系统性的治理与管控机制。文章强调，大模型的引入推动了数仓研发范式从被动式 SaaS 向 Agentic 工作流演进，数据工程师的核心职责正从繁重的 SQL 编码转向业务逻辑抽象与系统架构决策。

💡 主要观点

  1. 数据确权需严格区分管理审批与技术实现。 数据接入涉及合规与责任归属，管理审批（如权限、口径确认）必须由人类主导，AI 仅辅助完成 DDL 编写、任务配置等技术执行工作，确保合规前提。
  2. 规范化输入输出是 AI 在数仓规模化落地的安全底座。 通过结构化模板、CSV、JSON 等规范输入，并强制模型按预设模板输出，将大模型不可控的自由文本生成转化为基于规范契约的受限定向编译，从根源上压缩幻觉空间。
  3. Galaxy MCP 作为桥梁，实现了大模型与数仓环境的标准化集成。 基于 MCP 协议，大模型能安全地调用底层数据平台 API，自动获取表结构、血缘、日志等上下文，为 Agent 执行复杂任务提供标准化的环境感知能力。
  4. 认知运行时与执行运行时解耦，是 AI 与数仓融合的架构范式。 LLM 作为认知运行时处理语义解析与逻辑推演，不直接触碰物理数据；传统计算引擎作为执行运行时负责确定性算力调度，两者解耦兼顾了语义理解与高吞吐特性。
  5. 智能周报生成通过将数值计算与语义叙事分离，规避了计算幻觉。 由 LLM 编译的 Python 模块负责所有确定性运算，LLM 仅基于预渲染的结构化文本进行趋势判断与归因叙述，将不确定性严格限制在语义层。

💬 文章金句

  • 大模型在企业级数据仓库中的落地核心，主要体现在两大维度：一是数据确权，二是规范化输入输出。
  • 剥离掉「AI 写代码」的表层形式，触碰数仓与 AI 融合的本质，其核心在于构建规范化的输入与输出契约。
  • 将 LLM 的不确定性严格限制在语义层，将数值精度的责任锁定在代码层，两者各自处于自身最可控的能力边界内。
  • 从繁重的 SQL 编码与基础排错，转向业务逻辑的抽象、规范契约的制定以及系统架构的最终决策。
  • 提示词不再是简单的自然语言对话，而是演变为了系统架构的一部分。
