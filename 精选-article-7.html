我们如何在保证任务质量的同时提高 AI 编程的成本效率

9/2/2026, 6:00:00 PM

📌 One-Sentence Summary

GitHub Copilot 通过优化端到端任务效率（压缩噪音、去除无效格式化、安全缩短提示词、批量处理后台结果）来降低 AI 编程成本，而非追求单次工具调用的 token 节省。

📝 Summary

GitHub Copilot 团队介绍了四项工程变更，在不下滑任务质量的前提下降低了 AI 积分成本。他们首先直面「本地指标陷阱」：激进压缩工具输出虽节省了单次调用 token，却导致智能体反复重跑命令或重读文件，反而推高总成本。解决方案是选择性压缩器——保留类源码输出不变、重组搜索结果但不丢失内容，仅在收益显著时压缩可预测的重复性噪音，并设置恢复路径作为安全网。其次，他们移除了 view 工具的行号前缀，在不损失质量的情况下将离线推理成本削减约 5%、在线日成本削减约 3%。对于提示词压缩，元提示循环将任务工具提示词减半，但早期一次实验将谨慎的并行化指导改写为硬性调度策略，引入了回归；一句修复语句恢复了行为，同时每轮节省约 1，300 token。最后， Harness 现在对符合条件的后台任务完成结果进行批量处理并直接返回，消除了仅用于检索的模型回合。四项变更在离线基准和在线实验中均显示可测量的成本下降，且无实质性质量倒退。文章总结了构建高效 AI 编程智能体的五条经验。

💡 Main Points

  1. 优化完成的任务，而非单个工具调用。 激进的截断工具输出虽在本地节省 token，却触发恢复步骤——重读文件或重跑命令——推高了总成本和延迟。效率必须跨完整任务端到端衡量，而非仅看单次工具调用。
  2. 选择性压缩噪音，同时保留有用信息。 已上线的压缩器保持类源码输出（cat、git diff、git show）和任意脚本原样保留，重组 grep/匹配结果但不丢失内容，仅在节省显著时才压缩重复的安装/构建/测试输出。恢复路径允许智能体按需获取完整原文，频繁恢复也可作为评估信号。
  3. 在删除信息之前，先去除无效的格式化。 view 工具曾为每次文件读取都添加行号前缀，但当前编辑工作流依赖上下文代码而非行号匹配。移除后离线推理成本降低约 5%、在线日成本降低约 3%，且无质量倒退——纯粹的效率提升，零信息损失。
  4. 提示词压缩需要行为回归测试。 元提示循环将任务工具提示词缩减近半，但早期实验暗中将谨慎的并行化指导改写为硬性调度策略，导致独立子智能体串行化。修复方式是用一句话替换显式的白名单/黑名单：「独立智能体可并行运行；请考虑副作用」。提示词缩短若不经过测试，可能悄无声息地移除行为。
  5. 批量处理后台完成结果，消除检索绕路。 当后台任务（Shell 命令、子智能体）完成后，旧设计要求智能体额外消耗一次工具调用去拉取本已完成的結果。Harness 现在对符合条件的完成结果批量处理，并直接以现有工具结果格式交付，AI 积分使用量减少约 2.3%。

💬 Key Quotes

  • 我们在本地节省了 token，却在全局花费更多。
  • 任何效率变更都必须跨完整任务评估，从用户请求到最终结果。
  • 提示词行为必须经过测试。未被测试的行为，缩短提示词可能悄无声息地将其移除。
  • 这些变更并未让模型变得更聪明，只是移除了模型本不需要做的工作。
