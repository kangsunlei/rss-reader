代理模式正式发布，并支持模型上下文协议 (MCP)

6/17/2025, 6:24:08 PM

📌 一句话摘要

Visual Studio 新的 GitHub Copilot 代理模式现已正式发布，它通过工具调用和模型上下文协议 (MCP) 实现自主的多步骤开发任务。

📝 详细摘要

Visual Studio 六月更新推出了正式发布的 GitHub Copilot 代理模式，该模式就像一个可以自主编程的同事。与对话式的“询问”模式不同，“代理模式”接受高级目标，规划、执行和自我纠正多步骤开发任务，通过分析代码、应用编辑、运行命令和修复错误。它利用“工具调用”机制与 Visual Studio 中的功能进行交互。通过与开源模型上下文协议 (MCP) 集成，其功能得到显著扩展，该协议通过标准化协议，将 AI 代理与外部工具连接起来，如 GitHub 仓库、CI/CD 流水线和监控系统。这允许代理执行具有真实世界背景的更复杂操作。文章还简要提到了六月版本中的其他更新，包括可重用的提示文件以及 Gemini 2.5 Pro 和 GPT-4.1 的支持。

💡 主要观点

  1. 代理模式让 GitHub Copilot 可以自动完成多步骤的编码工作。 这种新模式超越了对话式帮助，通过规划、行动和自我纠正来端到端地执行开发目标，从而提高开发人员的效率。
  2. 代理模式的核心是“工具调用”，用于访问 IDE 功能和外部服务。 通过与 Visual Studio 的内部工具以及通过 MCP 与外部系统集成，代理可以执行诸如代码编辑、运行构建或与 GitHub 交互等操作。
  3. 模型上下文协议 (MCP) 通过连接到外部工具来扩展代理模式的功能。 MCP 提供了一种标准化方式，供 AI 代理与外部服务（如 GitHub、Azure 等）交互，使代理具有上下文感知能力和高度可扩展性。

💬 文章金句

  • 代理模式将 GitHub Copilot 转变为能够端到端处理多步骤开发任务的自主结对编程助手。
  • 代理模式的核心是使用工具调用来访问 Visual Studio 中不断增长的功能集。
  • 模型上下文协议 (MCP) 是一种旨在将 AI 代理与各种外部工具和服务无缝连接的协议，就像 HTTP 协议统一了 Web 通信一样。
  • 这使得代理模式真正具有可扩展性：它可以插入到您的环境中，并以对您的工具、系统和工作流程的真正理解来执行操作。
