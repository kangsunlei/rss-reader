AI 编程能力边界探索：基于 Claude Code 的 Spec Coding 项目实战｜得物技术

3/11/2026, 10:30:00 AM

📌 一句话摘要

得物技术通过 10 天 2.5 万行代码的 Claude Code 实战，复盘了“规格驱动编码”（Spec Coding）工作流，并构建出“约束+示范+视觉”三层规范体系，深度拆解 AI 编程的能力边界。

📝 详细摘要

本文是得物技术团队基于 Claude Code 进行企业级中后台项目开发的深度实战总结。文章详细记录了在 10 天内通过 2，754 次工具调用完成 2.5 万行代码的演进过程。核心贡献在于提出了 Spec Coding（规格驱动编码）工作流，通过“先设计、后编码”的模式消除 AI 的不确定性。作者构建了由约束层（Rules）、示范层（Code Design）和视觉层（UI Design）组成的三层规范体系，并利用 MCP（Model Context Protocol）工具打通了接口文档与云文档的信息断层。文章还深入分析了 AI 在复杂排障场景下的局限性，总结了 AI 失效的三种模式，并重新定义了 AI 时代开发者应具备的规范设计与系统思维能力。

💡 主要观点

  1. 构建“约束+示范+视觉”三层规范体系以提升 AI 输出质量。 通过 Rules 限制禁止行为，Code Design 提供标准代码模板，UI Design 提供 HTML 视觉参考，确保 AI 输出不仅合法而且“地道”。
  2. 推行 Spec Coding（规格驱动编码）工作流，实现先设计后编码。 在动代码前明确 Proposal、Design 和 Tasks，通过结构化文档让 AI 聚焦当前步骤，有效减少复杂功能开发中的返工和需求偏移。
  3. 利用 MCP 工具链消除 AI 与外部业务信息之间的断层。 通过 MCP 直连 API 平台和飞书文档，使 AI 能自动拉取接口字段和 PRD 内容，大幅提升前后端联调效率并减少人工复制错误。
  4. 深刻识别 AI 编程在复杂环境和隐性知识下的能力边界。 分析了 AI 在处理云环境构建失败等“信息孤岛”问题时的无力感，指出 AI 缺乏内部业务常识和对多根因掩盖问题的全局洞察力。

💬 文章金句

  • AI Coding 的本质不仅仅是用 AI 写代码，而是用结构化的规范和工作流把不确定性消除在执行之前。
  • 规范文件只是「约束」而非「能力」——只有「约束层」时，AI 知道不能做什么，但遇到复杂场景仍可能生成不够地道的代码。
  • AI 是一个极度服从、无限耐心、但没有内部业务知识常识的「顶级执行者」。
  • 规范是杠杆，AI 是力，Spec 工作流是支点。
  • 规范设计能力成为 AI 时代开发者的核心竞争力——能写出让 AI 可靠执行的规范，价值比能写出同等功能代码更高。
