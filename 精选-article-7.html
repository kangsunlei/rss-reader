Super-agent 设计探索：迈向更自主的 Agent 系统

10/31/2026, 12:29:00 PM

📌 一句话摘要

本文提出了 Super-agent 的架构设计，通过双层架构、事件驱动、全双工交互、存算分离及 Watchdog 机制，构建了一个跨会话连续、高效并发、主动响应且持久运行的自主 Agent 系统。

📝 详细摘要

本文是一篇探讨下一代 Agent 系统形态——Super-agent 的架构设计文章。作者指出，现有的单 Session Agent 模型在多任务和团队协作中受限于人类注意力，而 Super-agent 旨在打破 Agent 与单次手动会话的绑定，使其成为跨会话保持上下文、并行推进复杂任务的连续实体。文章详细阐述了支撑 Super-agent 的五大核心模块：通过 Router 与 Worker 双层架构兼顾连续交互与高效并发；通过程序与模型结合的两级过滤、订阅直通、Inline & Spill 上下文组织实现事件驱动与主动响应；通过异步 ReAct Loop 和多信道定制实现面向人的全双工交互；通过计算、状态与环境的分离实现云端持久在线与 BYOM 支持；以及引入独立 Watchdog 作为外部控制回路实现异常自愈。最后，作者分享了基于 DeepSeek Harness 的初步实验，验证了双层架构在任务完成时间、系统开销及 Router 批处理吞吐量上的显著优势。

💡 主要观点

  1. 提出 Super-agent 概念，定义了连续、高效、主动、持久四个核心基础特征。 Super-agent 旨在打破传统 Session 的孤立性，使 Agent 能在 IM、GitHub 等多信道间保持连续上下文，同时并行、高质量地主动处理多项复杂任务，并在异常时自动恢复。
  2. 设计了 Router 与 Worker 的双层架构以解耦全局协调与具体执行。 Router 层常驻并统一承接人类交互与任务分派，不直接执行具体任务以避免瓶颈；Worker 层上下文隔离，并发执行具体任务，从而在系统层面淡化了 Session 的存在，降低用户认知负担。
  3. 构建了事件驱动的 Trigger 过滤、路由与上下文管理机制。 采用程序层（Fast Path）与语义层（Slow Path）两级策略过滤环境噪音；通过 Thread 订阅与直通机制将事件路由给 Worker；利用 Inline & Spill 与链式召回（Chain of Recall）高效管理上下文窗口，并引入投机执行在后台提前尝试。
  4. 实现了计算、状态与环境的分离，支持云端持久在线与 BYOM。 将 Agent Loop 计算放入云端无状态容器，会话状态存入数据库；通过端侧轻量 daemon 接入用户本地环境，使 Agent 摆脱单机生命周期限制，可在不同执行设备间按需切换。
  5. 通过初步消融实验与压力测试验证了架构的优越性与批处理机制。 实验表明，Super-agent 的 p50 与 p95 任务完成时间显著优于单 Session 方案；在 Trigger 密集涌入时，Router 层通过自动合并积压事件，使单个决定分摊的推理时间大幅降低。

💬 文章金句

  • 单个 ReAct Loop 无法同时支持上述四个特征，底层需要一套相应的架构。
  • 让用户手动管理 Session，在很大程度上是从底层 LLM API 延续下来的设计惯性；Session 应当是系统的实现细节，而不应是用户的认知负担。
  • 浪费上下文窗口，就是浪费模型的智能。
  • 从任务完成时间看，Super-agent 的 p50 与 p95 分别为 12.4 分钟与 15.7 分钟，显著优于带 Subagent 工具的单 Session。
