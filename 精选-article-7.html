Spring AI 智能体模式（第四部分）：子智能体编排

1/27/2026, 12:00:00 AM

📌 一句话摘要

本文介绍了 Spring AI 中的 “Task” 工具，通过层级化子智能体编排实现上下文隔离和专业任务委派，从而提升 LLM 的性能。

📝 详细摘要

文章探讨了 Spring AI 生态系统中的层级化子智能体模式，重点介绍了 spring-ai-agent-utils 工具包中的 “Task” 工具。该模式告别了单体通用智能体，转向基于委派的架构，由主编排器管理专业化的子智能体。每个子智能体在各自独立的上下文窗口中运行，有效防止了上下文混乱和性能下降。核心特性包括多模型路由（根据复杂度将任务分配给不同的 LLM）、基于 Markdown 的子智能体配置以及对后台执行的支持。该框架提供了用于探索、规划和 Bash 执行的内置子智能体，同时允许开发者通过特定工具和系统提示词定义自定义智能体。

💡 主要观点

  1. 将任务委派给专业智能体以保持专注的上下文窗口 子智能体在隔离的窗口中运行，而不是由单个智能体处理所有逻辑，这防止了通常会降低 LLM 推理性能的上下文混乱。
  2. Task 工具实现了包含编排器和注册表的层级架构 主智能体使用智能体注册表（Agent Registry）根据描述识别并调用专业子智能体，管理信息流和结果。
  3. 多模型路由优化了不同任务的成本和性能 该框架允许将简单任务路由到成本更低的模型（如 Claude Haiku），而将复杂的分析任务留给能力更强的模型（如 Claude Opus）。
  4. 子智能体使用便携的基于 Markdown 的配置格式定义 通过在 Markdown 文件中使用 YAML 前置内容（frontmatter），开发者可以轻松定义子智能体名称、描述、允许的工具和特定的系统提示词，无需编写复杂代码。

💬 文章金句

  • 与其让一个通用智能体处理所有事情，不如委派给专业智能体。这能保持上下文窗口的专注——防止因混乱导致的性能下降。
  • 主智能体会根据每个子智能体的描述字段自动决定何时进行委派。
  • 子智能体在独立的智能体实例中运行，并在隔离的上下文窗口中执行。
  • LLM 是助手，而不是自主可靠的程序员。我是高级开发人员；LLM 的存在是为了加速我的工作，而不是取代我的判断。
  • 子智能体不能再产生自己的子智能体。不要在子智能体的工具列表中包含 Task。
