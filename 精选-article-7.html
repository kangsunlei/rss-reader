单个机柜到底能跑多少个 Agent？答案不在 GPU 身上

9/19/2026, 2:15:00 AM

📌 一句话摘要

英特尔基于实际工作量公式，指出数据中心优化应聚焦调度有效性、资源平衡度和计算卸载效益，以提升单机柜 Agent 交付量，而非仅关注理论算力参数。

📝 详细摘要

本文探讨了 AI Agent 时代数据中心面临的基础设施挑战。作者指出，现有数据中心为大模型单次推理设计，难以应对 Agent 高频、突发、有状态的工作负载。通过拆解 Agent 任务时间，发现主机端 CPU 开销占 60%，其中沙箱调度和排队成为性能瓶颈。英特尔提出“每机柜可交付智能体数”公式，通过调度优化（如核心类型分工）、资源平衡（Flat Memory 模式结合 CXL 与 DDR5）和计算卸载（硬件加速引擎）三大策略，将系统膝点从 235 个并发 Agent 提升至 300 个，证明实际交付能力比理论参数更重要。文章最后指出，行业竞争正从芯片参数比拼转向系统转换效率的较量。

💡 主要观点

  1. Agent 工作负载与传统推理不同，数据中心基础设施面临延迟和并发挑战。 Agent 执行过程包含规划、推理、工具调用、状态保持等多轮循环，现有为单次推理优化的架构难以适应其高频、突发、有状态的特性，导致延迟和排队问题严重。
  2. 主机端 CPU 成为瓶颈，沙箱调度和队列排队导致性能急剧下降。 英特尔白皮书拆解显示，主机端 CPU 开销占 Agent 总任务时间的 60%，其中工具执行（沙箱）占 35%。并发会话时，调度与队列排队占主机端 CPU 时间的增长部分达 94%，单个请求的 CPU 占比从 0.4%-0.6%飙升至 11%-15%。
  3. 英特尔提出实际工作量公式，通过调度优化、内存平衡和计算卸载提升交付能力。 公式为“每机柜可交付智能体数 = 理论每机柜智能体数 × 调度有效性 × 资源平衡度 × 计算卸载效益”。通过采样状态并路由至合适节点、利用 Flat Memory 模式融合 CXL 与 DDR5、以及将压缩与数据搬运卸载至 QAT/IAA 等加速引擎，系统膝点从 235 个并发 Agent 推至 300 个，提升 28%。
  4. 实际交付能力成为竞争新维度，行业从理论参数转向实际效能。 企业采购决策正从关注峰值吞吐和核心数，转向追问在目标延迟和并发下的实际交付量。竞争维度从“谁的芯片参数更高”转向“谁的系统转换效率更好”，包括调度策略、内存架构和软硬件协同等工程细节。

💬 文章金句

  • 去计算数据中心的实际工作量，而不是理论的性能上限。
  • 任务越多，隐藏的等待越长
  • 单个请求任务时，这一比例几乎看不出来。但是并发到 32 个会话时，这个比例突然跳到了 11%～15%
  • 每机柜可交付智能体数 = 理论每机柜智能体数 × 调度有效性 × 资源平衡度 × 计算卸载效益
  • 提升并非来自更强的 GPU、CPU 芯片或更大的显存与内存，而是来自对系统内部'转换损耗'的压缩。
