谈谈如何超越 Nvidia

11/21/2026, 8:04:00 AM

📌 一句话摘要

作者从 GPU 架构、互联和 CPU/DPU 等技术层面系统性分析了如何构建超越 Nvidia 的芯片方案，强调全栈理解和工程实践的重要性。

📝 详细摘要

本文从 GPU 架构、互联技术、CPU/DPU 以及模型预测四个维度，系统性地探讨了如何构建超越 Nvidia 的芯片方案。文章指出，单纯模仿跟随 Nvidia 的产品迭代是无法超越的，必须深刻理解其技术瓶颈和供应链优势。作者详细分析了从 Volta 到 Blackwell 再到 Rubin 的 GPU 演进脉络，阐述了 Tensor Core、SM 数量、L2 Cache 和 NOC 等关键架构权衡。对于互联层面，作者基于自身在 Cisco 的 NetDAM 项目经验，提出了 ScaleUP/ScaleOut 融合的可靠传输方案，并预测了 NVLink 的演进方向。最后，作者指出 Nvidia 在 CPU/DPU 和 Agentic 基础设施方面的短板，强调构建超级芯片平台需要从算法到芯片的端到端协同设计。

💡 主要观点

  1. 要超越 Nvidia 必须全栈理解其技术体系 仅仅跟随产品迭代发布无法赶上，必须深入理解 GPU 微架构、互联设计、供应链人脉等全链路技术，才能在关键瓶颈处实现突破。
  2. GPU 架构演进需要掌握每个代际的技术权衡 从 Volta 引入 Tensor Core 到 Blackwell 的 SM 数量减少、Rubin 的 I/O Die 分离，都涉及寄存器压力、SM 数量、L2 Cache 和 NOC 等关键指标的权衡，需要全面理解这些约束才能设计更优方案。
  3. 互联层面的 ScaleUP/ScaleOut 融合是关键突破口 基于作者在 Cisco 的 NetDAM 项目经验，提出了解决内存 Capacity 和 Bandwidth 瓶颈的方案，通过可靠传输和负载均衡机制，构建比 NVLink 更高效的大规模 GPU 互联网络。
  4. CPU/DPU 和 Agentic Infra 是 Nvidia 的短板 Nvidia 在理解 Hyperscalar cloud workload 和网络安全方面薄弱，构建完整的 AI 基础设施平台需要在 CPU/DPU 领域实现突破，形成与 GPU 的深度协同。
  5. 模型规模扩张需要算法与芯片协同设计 随着 10T/20T/50T 参数规模的模型发展，计算易扩缩放而内存难扩缩，必须在稀疏化算法和芯片微架构上进行深度协同设计，才能支撑更大规模的模型训练。

💬 文章金句

  • 要想超越 NV， 那么你就必须在微架构上充分理解 NV 架构师的难处... 而不是它出一代你抄一代
  • NV 在整个基础设施上有 CPU / DPU / AI-NIC / NVLink Switch / ScaleOut Switch 等多个芯片。我想说的是**超越 NV 你必须要深刻的理解 NV， 并具有全栈的从算法到模型结构再到算子和芯片以及互联的完整的知识结构**
  • 背后的逻辑很简单， 关于内存的 Capacity 和 Bandwidth 的两个墙如何解决?
  • 计算非常容易 Scale，但是内存非常难
  • 全球领先并不是一句口号一个 PR， 也不是一两篇完全没法工程落地的论文， 而是实实在在有记录的长达数年的工程实践
