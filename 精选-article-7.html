从提示词优化到决策模型：Jev 辅助业务 Agent 技能路由的探索与落地

11/24/2026, 2:07:00 AM

📌 一句话摘要

文章探讨了如何通过 Jev 决策模型辅助业务 Agent 实现技能路由优化，结合实验数据验证了候选推荐与主 Agent 决策的协同作用，最终选定 Jevify 方案以提升路由准确率和响应速度。

📝 详细摘要

本文从业务 Agent 技能路由的痛点出发，介绍了利用 Jev 决策模型进行候选推荐的探索与落地实践。文章首先阐述了技能路由在多业务域场景下的挑战，以及传统提示词和专用分类器的局限性。随后介绍了 Jev 的核心能力——将判断任务封装为可调用的决策函数，并通过 Choice、Score、Noul 三种输出类型实现结构化结果。实验部分对比了 Jev、Luna、Haiku 等模型在单选、Top3、Top5 命中率及调用耗时上的表现，发现 Jev 在 Top5 命中率（104/105）和耗时（1.433 秒）之间取得了良好平衡。后续通过 KEV 验证业务边界提示词优化，Top5 命中率从 92.42% 提升至 99.42%，首次路由命中率达 97.38%。最终选型 Jevify readout-coh 4B 模型，验证其在 vLLM 部署下的 99.71% 配置回归命中率和 292ms 平均响应时间。线上多轮对话验证显示首轮和多轮能力选择正确率分别达 97.39% 和 97.80%，证明方案在实际业务场景中具有稳定性。

💡 主要观点

  1. 技能路由需要结合上下文判断用户诉求，而非仅凭关键词匹配 在营销场景中，用户提到'审批'可能是排查活动未生效，而非办理审批流程，路由必须区分具体业务对象和动作
  2. Jev 提供将判断任务封装为可调用函数的能力，输出 Choice/Score/Noul 三种结构化结果 通过定义 state、instructions、criteria 等输入，Jev 可返回候选选项及概率分布，便于程序消费，兼具提示词的灵活性与分类器的结构化优势
  3. 实验验证 Jev 在技能路由中的有效性：Top5 命中率 104/105，调用耗时 1.433 秒 与 Luna、Haiku 等模型对比，Jev 在候选覆盖和响应速度之间取得平衡，支持后续的两阶段分工：决策模型提供候选，主 Agent 完成最终选择
  4. KEV 验证业务边界提示词优化显著提升路由准确率 未使用提示词时 KEV Top5 命中率为 92.42%，补充业务判断提示词后提升至 99.42%，首次正确路由率达 97.38%
  5. 最终选定 Jevify readout-coh 4B 方案，满足 90%+ 命中率、4B 规模、8192+ token 长输入及 vLLM 部署要求 通过离线配置回归（99.71%）、服务网关回放（99.42%）和平台路由回归（99.13% Top5，96.50% 首次正确路由）验证其业务可行性

💬 文章金句

  • 技能路由需要结合上下文，判断用户正在处理什么对象、希望完成什么动作，以及哪项能力能够承接当前诉求。
  • Jev 提供了一种结合两者特点的思路：像提示词一样描述当前任务，又像分类器一样返回便于程序消费的结果。
  • Jev 的 Top5 平均调用耗时为 1.433 秒，包含请求、解析与重试等待。
  • KEV 在未补充业务判断提示词时，Top5 候选命中率为 92.42%（317/343），经过优化后提升至 99.42%（341/343）。
  • 平台回归中，普通确认后累计命中为 335/343，较主 Agent 直接选择增加 39 条，提升 11.37 个百分点。
