OpenAI 内部揭秘：我们如何使用 Codex

9/18/2025, 5:34:14 AM

📌 一句话摘要

OpenAI 工程师如何利用 Codex 提升代码理解、重构、优化、测试及开发效率的内部实践与最佳指南。

📝 详细摘要

文章详细揭示了 OpenAI 内部团队如何利用其 AI 编码助手 Codex，覆盖了从安全到基础设施的多个工程领域。它总结了七大核心应用场景，包括加速代码理解、高效重构与迁移、性能瓶颈识别与优化、提升测试覆盖率、加快开发速度、帮助工程师保持心流，以及辅助探索与构思。此外，文章还分享了六项实用的最佳实践，如从“提问模式”开始、像写 GitHub Issue 一样组织提示、逐步完善 Codex 环境等，旨在帮助其他开发者最大化 Codex 的效用。文章强调 Codex 已显著改变 OpenAI 的构建方式，并展望了 AI 在软件开发中更深度的集成潜力。

💡 主要观点

  1. Codex 能显著提升工程师在代码理解、重构、性能优化和测试覆盖方面的效率 通过其多场景应用，工程师能快速熟悉代码、自动化重复任务、识别瓶颈并生成测试，从而高质量完成工作。
  2. Codex 帮助工程师在碎片化工作中保持心流，并辅助探索与构思，提升开发灵活性 它能暂存未完成任务、将想法转化为原型，并协助探索设计方案和发现潜在问题，确保工作连续性。
  3. 通过结构化提示、完善环境和利用“最佳 N 个”功能等最佳实践，可最大化 Codex 的效用 OpenAI 内部总结的习惯为开发者提供了清晰指导，确保 Codex 输出质量并深度融入开发流程。

💬 文章金句

  • 我在修复一个 bug 时，会用"提问模式" (Ask mode) 来检查代码库里其他地方是否可能出现同样的问题。
  • Codex 把我们代码里所有旧版的 `getUserById()` 函数都换成了新的服务模式，还自动提交了 PR (合并请求)。这事儿本来要花好几个小时，它几分钟就搞定了。
  • Codex 在快速发现性能问题上表现出色------我只要花 5 分钟写一个提示，就能省下 30 分钟的工作量。
  • 我虽然开了一整天的会，但还是合并了 4 个 PR，因为 Codex 在后台帮我干活。
  • 要想让 Codex 发挥最大效用，你需要给它清晰的结构、充足的上下文，以及迭代的空间。
