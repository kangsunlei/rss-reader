真正零丢失！小红书基于 Binlog Server 的 MySQL 数据一致性实践

8/31/2025, 11:16:00 PM

📌 一句话摘要

小红书自研 Binlog Server 通过优化 MySQL 半同步复制性能并与 ORC 高可用方案集成，实现了核心数据库故障切换时的 RPO=0 数据零丢失。

📝 详细摘要

文章详细介绍了小红书为解决核心数据库在故障切换时数据丢失和恢复耗时问题，提出的基于 Binlog Server 的数据一致性解决方案。该方案旨在提升 MySQL 半同步复制性能，加速日志传输，并在故障时无侵入地自动补数据，实现 RPO=0（零丢失）。通过自研 Binlog Server，小红书将复制速度提升至 300MB/s+，且资源消耗极低（1C1G）。方案还优化了故障切换效率，结合 ORC 高可用组件，确保在新主库选举时，Binlog Server 能作为数据源提供最新日志，有效降低运维成本和业务风险。文章深入分析了 MySQL 复制延迟原因、行业现有方案，并详细阐述了自研 Binlog Server 的架构设计，涵盖了 MySQL 协议支持、SQL 语法解析、节点注册、半同步机制及文件管理与数据一致性等关键模块。该方案已 100%部署于小红书半同步复制集群，并成功在多次切换中守护了核心数据库数据安全。

💡 主要观点

  1. 自研 Binlog Server 显著提升 MySQL 半同步复制性能，实现 RPO=0。 通过自研 Binlog Server，小红书将 MySQL 半同步复制速度提升至 300MB/s+，同时保持极低的资源消耗，确保在主库发生故障时，数据能够做到零丢失。
  2. Binlog Server 与 ORC 高可用方案无缝集成，简化故障切换流程。 该方案与现有 ORC 高可用组件结合，在主库宕机时，Binlog Server 能作为临时主库为新主库补齐数据，实现自动化、无人工介入的快速数据恢复。
  3. 深度定制化支持 MySQL 协议和 SQL 语法，确保兼容性和易用性。 Binlog Server 实现了对 MySQL 复制协议和特定 SQL 语法的支持，使其能够无侵入地融入现有 MySQL 生态，降低了集成和运维成本。

💬 文章金句

  • 异常情况下的数据丢失问题将极大地影响业务的可用性，尤其在一些核心场景的数据恢复过程更是耗时耗力。
  • RPO=0 意味着在任何切换或灾难发生后，数据一条都不丢！如果实现了 RPO=0，当数据库发生宕机时，新的数据库能够 100% 自动补齐所有数据。
  • 相对于社区 MySQL 半同步+开源 ORC 高可用组件，自研 Binlog Server+自研 ORC 高可用在半同步复制速度、轻量化部署、数据一致性优先和运维便捷性等场景进行优化，保证 RPO=0。
  • Binlog Server 是一个消耗资源极少的轻量化 Binlog 存储节点（1C1G 即可）。除了提供一致性解决方案以外，未来也可以在其他使用 Binlog 的场景中发挥作用。
