Skill 自进化：基于执行轨迹与评测反馈的多代优化实践

11/13/2026, 7:09:00 AM

📌 一句话摘要

本文介绍了基于执行轨迹与评测反馈的 Skill 自进化方法，采用 GEPA 框架构建可追溯的搜索闭环，通过候选池、父子入池判定和活动前沿计算实现多代优化，最终选出在黄金评测集上表现最佳的 Skill 版本。

📝 详细摘要

文章聚焦业务 Skill 的自进化问题，指出传统修复方式难以追踪和比较不同版本。作者采用 GEPA 方法，构建以黄金评测集、Ground Truth、执行轨迹和 rubric 为核心的反馈闭环。整体流程包括进化准备、初始版本评测、生成反思反馈、变异生成、有效性校验、全量评测、父子入池判定、更新迭代和最终版本确认。候选池设计区分为全局候选池、活动前沿、失败尝试集和当前冠军。入池规则基于父子逐 Case 分数比较，保留整体优于父代或在部分 Case 有新优势的版本。活动前沿计算采用确定性贪心覆盖，确保探索效率。文章详细阐述了候选数据结构、入池规则、前沿计算算法及其数学公式，为业务 Skill 的持续优化提供了系统化方法论。

💡 主要观点

  1. GEPA 方法选择理由 作者通过横向对比 GEPA、SkillOpt、EvoSkill、Trace2Skill 四篇论文，发现 GEPA 能有效利用现有黄金评测集、Ground Truth、Trace 和 rubric 链路，实现反思与验证闭环，同时候选池设计保留不同 Case 上的互补优势。
  2. 全局进化流程设计 流程分为 10 步：进化准备、初始版本评测、选择父版本、生成反思反馈、反思生成子版本、有效性校验、子版本评测、父子入池判定、更新迭代、最终版本确认。全过程冻结黄金 Case、rubric、执行模型等，确保版本间可比。
  3. 候选池与活动前沿机制 候选池分为全局候选池、活动前沿、失败尝试集和当前冠军。活动前沿通过确定性贪心覆盖算法计算：先找每个 case 最高分，再找领先候选集合，最后按覆盖数、均分、最差分、创建时间和 ID 排序选出。
  4. 父子入池判定规则 子版本与直接父版本逐 Case 比较，若父版本在所有 case 上都不差且至少一个严格优于，则子版本不入池；若子版本支配父版本或两者互不支配，则子版本入池。完全相同则视为无效提升。
  5. 采样权重与父代选择 父代采样概率与候选在活动前沿中领先的 case 数量成正比，确保探索更关注在特定 case 上表现突出的版本，避免整体平均分主导。
