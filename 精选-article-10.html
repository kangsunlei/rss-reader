从需求到研发全自动：如何基于 Multi-Agent 架构打造 AI 前端工程师

8/22/2025, 12:31:00 AM

📌 一句话摘要

蚂蚁消金前端团队基于 Multi-Agent 架构、LangGraph 和 ReAct 范式，打造了“天工万象”平台，旨在通过 AI 实现前端自动化开发和数据分析，提升研发效能。

📝 详细摘要

文章深入介绍了蚂蚁消金前端团队开发的 Multi-Agent 智能体平台“天工万象”，该平台底层基于 LangGraph 实现，每个子 Agent 遵循 ReAct 范式，支持自我反思和自主规划工具使用。文章首先阐述了 Multi-Agent 架构相比统一型 Agent 在上下文管理和扩展性上的显著优势，以及 ReAct 范式相比固定工作流在动态决策和按需调用工具上的核心价值。接着，详细探讨了系统整体架构、交互时序图，并重点介绍了创新的上下文工程，包括跨 Agent 共享记忆机制和基于 Zcache 的跨机房多轮对话记忆管理，解决了复杂长周期任务的连贯性问题。最后，文章以“网页开发专家”为例，详细展示了 AI 生成中后台 React 页面和静态 HTML 网页的技术实践，并反思了从生成低代码 JSON 到直接生成代码的演进过程，强调了直接生成代码在减少幻觉方面的优势和生产可用性。

💡 主要观点

  1. Multi-Agent 架构通过分布式任务拆解和独立上下文管理，有效解决了复杂 AI 任务的上下文瓶颈和扩展性挑战。 相比中心化调度的统一型 Agent，多 Agent 架构能将任务分配给特定领域的 Agent，减少单个 Agent 的上下文压力，并提供优秀的扩展能力。
  2. ReAct 范式结合反思机制，赋予 Agent 动态决策和按需调用工具的能力，显著提升了复杂任务处理的准确性和灵活性。 ReAct 的 Reasoning-Action-Observation 循环使其能够自主规划和修正行动，尤其适用于高准确性要求的代码生成和数据分析等场景，克服了固定工作流的局限。
  3. “天工万象”在前端代码生成实践中，从低代码 JSON 转向直接生成 React/HTML 代码，有效解决了 AI 幻觉问题，提升了生成代码的生产可用性。 实践经验表明，由于大模型在代码数据上的训练更充分，直接生成通用代码比生成特定低代码协议 JSON 能更准确地满足生产级页面需求。

💬 文章金句

  • 如果模型进步是上涨的潮水，我们希望 Manus 成为那条船。
  • 多 Agent 架构通过意图识别和分布式任务拆解，将不同的细分任务分配给不同的 Agent，在复杂的长周期任务，单 Agent 只需要关注自己领域的上下文。
  • ReAct 的核心价值：通过 Reasoning-Action-Observation 循环实现动态决策。
  • 最核心的其实是 ReAct 支持按需调用工具，而 Dify 需在画布预先连接不同节点的工具，需要实现很多复杂的判断逻辑来实现工具的按需调用，这对于 Agent 的实现来说，成本是很高的。
  • 在不做模型微调的情况下，生成代码的幻觉问题肯定更少。
