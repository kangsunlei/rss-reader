📌 一句话摘要

携程机票前端团队将 SSE 技术从 Web 扩展到 APP，通过预建连、预请求、Brotli 压缩等优化手段，显著提升了列表加载性能，并为 AI Agent 流式改造铺平道路。

📝 详细摘要

本文详细介绍了携程机票 APP 采用 SSE（Server-Sent Events）进行全栈流式通信的实践。通过对比轮询和 SSE 的优劣，阐述了 SSE 在移动平台上的适配性和低功耗优势。文章重点讲解了 SSE 的实现方案，包括云端、Native 层和 RN 业务层的协同工作，以及如何通过预建连、预请求和报文压缩来优化性能。实验数据表明，SSE 显著减少了网络请求次数，简化了前端代码结构，并提升了数据加载速度。此外，文章还探讨了 SSE 在异构数据聚合和 AI Agent 应用中的潜力。

💡 主要观点

  1. SSE 相比轮询的优势 SSE 允许服务器主动推送数据，减少了客户端的轮询次数，从而降低了网络负载和功耗。它还简化了前端代码，因为不需要再处理复杂的串行请求逻辑。
  2. APP 上的实现架构 在 APP 中，SSE 的实现涉及三个层次：云端服务、Native 框架（如 iOS/Android）和 RN 业务层。Native 框架负责底层网络通信，而 RN 插件则提供了高层的事件处理接口。
  3. 性能优化策略 为了提升 SSE 的性能，文章介绍了三种主要策略：预建连（提前建立 TCP 连接）、预请求（提前加载数据）和报文压缩（使用 Brotli 算法）。这些优化显著减少了数据传输时间和加载延迟。
  4. 异构数据聚合的应用 SSE 可以用于聚合不同类型的 API 请求，将它们作为多个批次的数据流返回。这种方法可以解决前端视图与后端资源模型不匹配的问题，简化前端的渲染逻辑。
  5. 对 AI Agent 的影响 SSE 的落地为 AI Agent 的流式改造提供了基础。通过 SSE，可以实时推送 Agent 的思考过程和结果，而不需要等待整个计算完成，从而提升了用户体验。

💬 文章金句

  • 用最小的改造成本，获得最广泛的业务收益。
  • SSE 的典型应用场景包括实时通知、新闻推送、股票行情更新等，适合那些需要服务器主动向客户端推送数据的场合。
  • 通过引入 SSE 方式，相比于原有的轮询方式存在以下优势：减少网络链路请求次数，提升查询性能；简化各端代码结构，减少串行请求的回调监听，时序控制；简化前端预搜索多批处理逻辑，对比串行查询机制，仅需处理一次预搜索即可完成所有批次的数据预请求；轻量灵活便于下沉，多端复用，灵活调整业务查询流程，便于引入更丰富的查询机制。
  • SSE 在查询上的应用价值不是为了比 WebSocket 等其他方式更快，而在于用标准 HTTP 的最小代价，获得服务端主动推送、全链路复用以及原生重连异常处理的组合能力，通过最小的改造成本获得最广泛的业务收益。
