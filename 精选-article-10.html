我发现了渗透 Agent 长程任务的秘密

9/28/2026, 10:00:00 AM

📌 一句话摘要

Sonic Harness 通过 MEA 三角色物理隔离、零信任叙述审计及代码级完成态铁律，从工程层面解决单会话 Agent 长程任务的上下文膨胀与幻觉自证问题，实现 100 小时不间断渗透测试。

📝 详细摘要

文章深度解析了 Sonic Harness 在「蛙池 AI Desktop」100 小时不间断 Agent 渗透测试挑战中的技术架构。针对单会话 Agent 在长程任务中面临的上下文膨胀、幻觉自证和中断即回零三大瓶颈，Sonic Harness 摒弃了单纯依赖模型能力的思路，转而构建严谨的执行框架。其核心设计包括：1）MEA（Manager/Executor/Auditor）三角色循环，三者在工具集、上下文和会话 ID 上完全物理隔离，确保决策、执行与复核的独立性；2）ZTNA 零信任叙述审计，Auditor 仅采信独立复现的证据，不采信 Executor 的自然语言转述；3）双准入判据与 CSWI 完整性栅栏，Harness 强制校验工作区哈希与审计状态，任何未经校验的完成提议均被拦截；4）原子写与断点续跑机制保障进程稳定性。消融实验数据显示，移除关键校验机制会导致完成率大幅下降，证明了该架构在防止 Agent 自我欺骗和维持长程稳定性方面的有效性。

💡 主要观点

  1. 单会话 Agent 难以支撑长程任务的核心原因在于架构缺陷而非模型能力不足 长程运行会遭遇上下文膨胀导致的注意力衰减与成本激增、缺乏外部校验导致的幻觉自证累积，以及内存状态丢失导致的中断即回零。Sonic Harness 通过工程手段将 LLM 的“声称完成”降级为“提议”，由 Harness 掌握最终写入权。
  2. MEA 三角色物理隔离实现了决策、执行与复核的相互制衡 Manager 无工具权限仅负责规划，Executor 每轮新建会话负责执行，Auditor 仅挂载只读工具负责复核。三者工具面积严格递增且物理隔离，防止 Manager 越权执行或 Auditor 参与执行，从代码层面锁死职责边界。
  3. 零信任叙述审计与双准入判据是防止 Agent 幻觉的关键机制 Auditor 必须使用工具独立复现 Executor 的成果，且在出具裁决时撤离工具以确保证据固化。只有当审计报告为 verified 且工作区完整性检查为 clean 时，Harness 才允许状态翻转，否则强制标记为 untrusted 并记录伪造尝试。
  4. 消融实验证实了执行框架对长程稳定性的决定性作用 移除完成态拦截后，因幻觉累积导致完成率从 68% 降至 41%；若让 Manager 直接执行操作（还原单 Agent 模式），完成率仅剩 33% 且伴随大量完整性违规。这表明严格的流程控制比模型本身的聪明程度更能决定长程任务的成功率。

💬 文章金句

  • 它是怎么撑住超长进程任务的？毕竟大多数单会话 Agent 跑几十轮 tool call 就开始出现注意力衰减和事实误判。
  • LLM 说的话不作数，harness 观察到的才作数。
  • 不是依赖 prompt 层面的诚实性约束，而是在代码层面确保任何未经校验的完成提议都无法生效的物理级信任隔离。
  • 当基础模型的能力逐渐趋同，Agent 长程稳定性的竞争，已经从 "谁的模型更聪明" 转向 "谁的执行框架更严谨"。
