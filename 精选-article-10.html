Token 降本 50%：Harness 工作流的成本优化实践

7/24/2026, 12:45:00 AM

📌 一句话摘要

本文介绍了基于‘让 AI 只看到当前需要的上下文、减少无关的上下文、减少重复的上下文’三原则的十项优化措施，使 AI Agent 工作流 token 成本降低 50%~65%。

📝 详细摘要

文章详细阐述了腾讯云开发者团队在 AI Agent 驱动的前后端全流程开发中，如何通过测量工具 AgentLens 定位 token 消耗热点，围绕‘让 AI 只看到当前需要的上下文、减少无关上下文、减少重复上下文’三条原则，分别从渐进式披露、条件性内容外移、步骤详情外移、确定性操作脚本化、CLI 替代 MCP、MCP 数据获取子 Agent 化、长期记忆按需索引、单 Agent 拆分为多角色子 Agent、Agent 专属工具白名单、代码图谱替代盲搜、稳定前缀设计、避免重复加载 Skill、rtk 压缩 CLI 输出以及工具调用并行化等十个方向进行系统优化。实测表明单轮会话 input token 从 1，030，000 降至 634，905（-38.4%），全流程中等需求的 token 成本可降低 50%~65%。文末提供了可复用的检查清单和落地优先级建议。

💡 主要观点

  1. 渐进式披露与资源层外移：将条件性内容和步骤详情从 Skill 正文移至 references，按需加载，显著降低常驻 context。 例如自动化测试 Skill 的 spec 模板代码和 DB 前置操作规则被外置，仅在需要时读取；技术领导 Skill 只保留骨架，具体执行细节通过 read_file 按需载入，使初始加载从数千 token 下降至 1000-2000 token。
  2. 确定性操作脚本化与 CLI 替代 MCP：把数据库迁移、编译、服务启动等确定性命令封装到脚本，用 CLI 替代 MCP 工具，避免每次操作触发 LLM 推理。 原本通过 MCP 控制浏览器的每一步都需要一次模型推理；改为由 LLM 生成 Playwright spec，再由 CLI 批量执行，测试/视觉 Agent 的成本因修复轮次而显著下降（测试/视觉 Agent 成本 -64%）。
  3. 数据获取子 Agent 化与长期记忆按需索引：为 TAPD/Figma 等 MCP 调用建专属子 Agent 仅返回结构化摘要；引入 INDEX.md 目录索引，按需加载历史文档，减少重复载入。 主 Agent 不再直接承载几千字需求描述或上万行设计稿节点树，单轮会话 input token 从 1，030，000 降到 634，905（-38.4%），后续多轮不会因历史累积而越滚越大。
  4. 架构拆分与工具白名单：单 Agent 拆分为多角色子 Agent，并为每个子 Agent 配置工具白名单，降低无关工具 Schema 常驻 context，并可按角色做模型分层。 后端开发 Agent 只保留文件读写等基础工具，不可见 Figma/TAPD 等 MCP 工具；同时可将测试/视觉等规则强、轮次多的角色切换至低成本模型（如 GLM-5v），进一步削减 token 消耗。
  5. 代码图谱、稳定前缀、并行工具调用：使用 graphify 代码图谱减少探索轮次；设计稳定前缀以利用 KV Cache；无依赖的工具调用并行发起，避免历史滚雪球。 代码图谱使单次查询直接定位文件，总 token 节省 22.7%；稳定前缀让派发子 Agent 的提示词命中 Prompt Cache，费用降至正常价格的约 10%；并行获取 TAPD 与 Figma 摘要省去一轮历史打包。
