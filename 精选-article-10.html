你可能不再需要 workflow，大部分场景 skills 足矣——五步框架把 Workflow 变成可进化的 Skill

1/10/2026, 12:00:00 AM

📌 一句话摘要

本文提出一个五步框架，旨在证明在大部分自动化场景中，AI Agent 与 Skill 架构能取代传统 Workflow，实现流程的灵活性、可进化性及跨平台复用，并通过混合架构解决稳定性与成本问题。

📝 详细摘要

文章深入探讨了 AI Agent 与 Skill 架构相较于传统 Workflow 编排的优势，并提出了一个“五步框架”来阐明如何将复杂的 Workflow 转化为可进化的 Skill。作者认为，传统 Workflow 编排虽有确定性、可排查性等优势，但在灵活性、可扩展性和可移植性方面存在硬伤。反之，Skill 应被视为可组合模块，能通过自然语言进行编排。该框架包括：将工作流拆分为单一职责的 Skill 或 Subagent；在主 Skill 中用自然语言编排流程；将所有中间结果保存为本地文件以实现可追溯、可断点续传和人工干预；Subagent 之间仅传递文件路径而非内容以节省上下文并支持并行；以及持续迭代优化 Skill，甚至让 Subagent 自我进化。文章还正面回应了稳定性、成本和门槛三大质疑，强调了代码与 Agent 的混合架构、效率提升带来的总成本降低以及 AI 辅助 Skill 创建的能力。最终，文章指出 Agent+Skills 更适合输入多变、复杂协调、频繁迭代和需要复用的场景，而 Workflow 仍适用于严格审计、超高频简单任务和非技术用户可视化需求。

💡 主要观点

  1. 大部分传统 Workflow 编排场景可被 AI Agent+Skills 架构取代，实现更高的灵活性和可进化性。 传统 Workflow 在确定性上表现良好，但在逻辑复杂、输入多变、移植困难时暴露出局限，而 Skill 作为可组合模块能通过自然语言编排，适应更复杂的自动化需求。
  2. “五步框架”指导 Workflow 向可进化 Skill 转化，核心是模块化、自然语言编排和中间结果持久化。 框架包括拆分单一职责 Skill、自然语言编排流程、存储中间结果、Subagent 间传递文件路径以及持续迭代优化，这些步骤共同提高了流程的透明度和可维护性。
  3. Agent+Skills 架构通过混合编程实现稳定性，并通过整体效率提升抵消 Token 成本，同时降低门槛。 确定性逻辑可由代码实现，与 Agent 结合形成混合架构；高效率带来的总收益远超 Token 成本；AI 可辅助创建 Skill，降低普通用户上手难度。
  4. Skill 架构最大的被低估优势是其“可进化性”，能通过 AI 自我学习和迭代，持续提升流程效率。 与固定不变的 Workflow 不同，基于 Agent 的 Skill 可以记录修正、优化 Prompt，甚至实现 Subagent 自我迭代，使自动化资产越用越好。

💬 文章金句

  • 大部分 workflow 编排场景，都可以被 Agent + Skills 取代。
  • Skill 应该被看作可组合的模块。你可以把多个 skill 串起来，用自然语言描述它们之间的协作关系。
  • 所有中间结果都保存成本地文件。
  • 确定性逻辑不一定要交给 Agent。你可以把需要确定性的部分写成脚本。
  • Skill 架构有个经常被忽略的好处：它是活的，可以不断进化。
