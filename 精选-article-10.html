模型上下文协议：促进自主型 AI 协作

9/11/2025, 4:00:00 PM

📌 一句话摘要

本文介绍了“工具空间干扰”作为自主型 AI 协作中的一个关键挑战，它源于模型上下文协议（MCP）的横向工具集成，并提出了实证分析，旨在解决这一问题。

📝 详细摘要

本文深入探讨了扩展自主型 AI 系统面临的挑战，特别是当来自不同开发者的各种智能体和工具进行协作时。文章强调，虽然纵向集成（协同设计智能体和工具）是有效的，但它无法在“智能体社会”中扩展。模型上下文协议（MCP）被认为是一种有前景的横向集成解决方案，已经在 Zapier、Hugging Face 和 Shopify 等平台上得到广泛采用。然而，这种横向集成引入了新的故障模式，称为“工具空间干扰”，可能导致效率降低、操作序列延长、成本增加和任务失败。通过使用自定义的“MCP 采访器”工具对 1，470 个 MCP 服务器进行的调查，本文识别了关键的干扰模式：MCP 服务器的“一刀切”性质，未能充分考虑不同 LLM 的能力；过多的工具数量（某些服务器提供超过 256 个工具）；过长的工具调用响应，淹没了 LLM 上下文窗口；复杂的工具参数模式；显著的命名歧义和冲突；以及不充分的错误消息。分析强调需要更好的设计和标准化，以确保可扩展和可靠的多智能体系统。

💡 主要观点

  1. 自主型 AI 的纵向集成在规模上是不可持续的；通过 MCP 进行的横向集成引入了“工具空间干扰”。 随着智能体数量增长，且需要在不同提供商之间协作，传统的协同设计方法变得不切实际。MCP 促进了横向集成，但创造了新的挑战，即工具或智能体之间相互阻碍。
  2. MCP 对工具暴露的“一刀切”方法与不同的 LLM 能力相冲突，从而降低了性能。 服务器提供了一组通用的工具，而不管客户端 LLM 如何，由于模型处理上下文长度、工具数量和提示模式的差异，导致效率低下，并且常常降低性能。
  3. 实证调查揭示了关键的干扰模式：过多的工具数量、过长的响应、复杂的参数和命名问题。 对 MCP 服务器的分析发现，工具超出了 LLM 的限制，参数模式嵌套层级过深，频繁出现名称冲突和较差的错误处理，所有这些都导致了智能体性能下降和任务失败。

💬 文章金句

  • 但是，随着智能体的激增，我们预计过度依赖纵向集成的策略将难以适应发展。来自不同开发者或公司的智能体将越来越多地相遇，并且必须协同工作才能完成任务，这就是我们所说的 *智能体社会*。
  • 工具空间干扰描述的是，当原本合理的工具或智能体共同存在时，会降低端到端性能的情况。
  • MCP 服务器不知道它们正在与哪些客户端或模型一起工作，并且向所有人提供一组通用的工具、提示和资源。
  • 虽然模型在工具调用方面的熟练程度通常有所不同，但总体趋势是，随着工具数量的增加，性能会下降。
  • 虽然 MCP 提供了一个“IsError”标志来指示错误，但我们发现服务器通常通过返回字符串并将此标志设置为 false 来处理错误，表示正常退出。
