📝 详细摘要

本文是一份详尽的 MCP（Model Context Protocol）规范中译稿，旨在帮助 LLM 应用程序实现与外部数据源和工具的无缝集成。文章首先概述了 MCP 作为开放协议的核心价值，及其如何借鉴语言服务器协议（LSP）的思想。接着，详细阐述了 MCP 的基本协议（基于 JSON-RPC 2.0）、有状态连接和能力协商机制。文章还着重强调了协议强制要求的安全性考量，包括用户明确同意、数据隐私保护、工具安全管理和采样严格控制。此外，文中列举了自 2024 年 11 月以来协议的关键变更，并深入剖析了 MCP 的客户端-主机-服务器架构、设计原则（如服务器易于构建和高度可组合性），以及生命周期管理（初始化、操作、关闭）。最后，详细介绍了 STDIO 和 Streamable HTTP 两种传输机制，并深入探讨了基于 OAuth 2.1 的鉴权框架，为构建安全可靠的 AI 应用集成提供了全面指导。

💡 主要观点

  1. MCP 作为开放协议，标准化 LLM 应用与外部数据和工具的集成，提升 AI 应用的可组合性和扩展性 MCP 提供了一种标准化的方法，使 AI 应用能够与所需上下文（如资源、提示词、工具）无缝连接，极大提升了 AI 应用的可组合性和扩展性。
  2. MCP 采用客户端-主机-服务器架构，基于 JSON-RPC 2.0 构建有状态通信，确保组件协同与安全边界 这种架构模式清晰定义了主机、客户端和服务器的角色与职责，利用 JSON-RPC 2.0 消息格式实现有状态通信，确保了各组件间的协同工作和安全边界。
  3. 协议强制要求用户同意、数据隐私、工具安全和采样控制等安全原则，以应对其强大的功能带来的信任问题 MCP 通过规定用户明确同意数据访问和操作、保护数据隐私、并对工具执行和 LLM 采样进行严格控制，旨在解决协议强大功能背后存在的重大安全与信任问题。
  4. MCP 协议持续演进，引入了更灵活的 Streamable HTTP 传输机制，并基于 OAuth 2.1 构建了全面的鉴权框架 协议通过替换旧的 HTTP+SSE 传输为 Streamable HTTP，提高了通信效率；同时，引入基于 OAuth 2.1 的鉴权框架，为协议的传输层面提供了强大的授权安全保障，体现了协议的不断完善和对安全性的重视。

💬 文章金句

  • 模型上下文协议 (Model Context Protocol，MCP) 是一个开放的协议，支持 LLM 应用程序与外部数据源和工具之间的无缝集成。
  • MCP 从语言服务器协议 (Language Server Protocol) 中获得了一些灵感，该协议标准化了如何在整个开发工具生态系统中添加对编程语言的支持。
  • 模型上下文协议通过任意的数据访问和代码执行路径实现了强大的功能。这种能力带来了重大的安全和信任问题，所有实现者都必须仔细考虑这些问题。
  • MCP 建立在几个关键设计原则的基础上，这些原则为其架构和实施提供了参考信息：服务器应该非常容易构建、高度可组合，且不能够读取整个会话，也不能 '看到' 其他服务器。
  • MCP 鉴权实现必须实现 OAuth 2.1，并为私密客户端和公共客户端提供适当的安全措施。
