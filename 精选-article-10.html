Super-agent 设计探索：迈向更自主的 Agent 系统

11/1/2026, 11:15:48 AM

📌 一句话摘要

文章探讨了基于双层架构、事件驱动、存算分离和 Watchdog 的 Super-agent 设计，旨在构建持续在线、可并发推进多任务的自主 Agent 系统。

📝 详细摘要

本文从 DeepSeek Harness 团队的实践出发，系统性地探讨了如何突破传统单 Session Agent 的局限，构建一种称为 Super-agent 的新型 Agent 系统。文章首先分析了当前 Agent 在多任务并发和跨会话连续性方面的不足，提出 Super-agent 具备连续、高效、主动、持久四个核心特征。随后详细阐述了五个关键模块：双层架构（Router 层与 Worker 层）实现跨信道连续交互与高效并发；事件驱动机制通过 Trigger 和订阅直通实现主动响应；异步 ReAct Loop 和多信道交互解决了前台阻塞和跨渠道输出匹配问题；存算分离设计使 Agent 得以云端持久在线并灵活接入各种执行环境；Watchdog 外部控制回路确保长期运行中的异常自愈。文章还通过消融实验验证了双层架构和批处理机制的有效性，指出在团队规模下单 Router Session 足以应对，直通机制显著节省了 token 消耗。最后，文章探讨了架构扩展、跨 Agent 协作、上下文边界划分以及安全隐私等开放问题，认为这套系统设计思路具有更长期的参考价值。

💡 主要观点

  1. Super-agent 具备连续、高效、主动、持久四个核心特征 这些特征构成了 Agent 向更自主形态演进的目标：连续指跨信道无缝交互，高效指并发处理多任务，主动指自动响应环境事件，持久指长期在线运行并自愈。
  2. 双层架构通过 Router 层与 Worker 层解耦连续性与吞吐 Router 层负责全局协调和人类交互，Worker 层并发执行具体任务，两者通过订阅直通机制实现事件路由，有效缓解了单 Session 的上下文混乱和阻塞问题。
  3. 存算分离使 Agent 摆脱单机限制，实现云端持久在线 将计算、状态和执行环境解耦，Agent Loop 部署在云端，状态持久化存储，而执行环境留在端侧，通过轻量 daemon 按需接入，支持 BYOM 和跨设备协作。
  4. Watchdog 外部控制回路确保长期运行的可靠性 独立的 Watchdog Session 通过定时消息驱动，监控 Worker 进展和系统健康，及时介入修复异常，同时支持人类询问故障原因并在线调整系统行为。
  5. 实验验证了双层架构和批处理机制的有效性 消融实验显示 Super-agent 在任务完成时间上显著优于单 Session 方案，直通机制虽增加 token 消耗，但显著降低 Router 的决策负载；批处理机制在事件拥堵时能提高吞吐效率。

💬 文章金句

  • 我们把这种 Agent 形态及其系统架构称为 Super-agent。
  • Super-agent 具备以下四个基础特征：连续、高效、主动、持久。
  • 通过这一双层架构，系统在底层接管了上下文管理与并发执行，从而在用户侧淡化了 Session 的存在。
  • 借鉴计算机系统中的存算分离思想，分两步解耦计算、状态与环境的绑定。
  • 我们在主系统外部配置了一个独立的 Watchdog Session，用定时消息驱动它，构成外部的 Control Loop。
