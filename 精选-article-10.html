让 Agent 像人一样记忆：本地长期记忆系统 HL-Mem 的设计与取舍

9/11/2026, 8:32:00 AM

📌 一句话摘要

淘天直播技术团队开源本地长期记忆系统 HL-Mem，借鉴认知科学将记忆视为受治理的认知系统，用事实与经验双通道架构、双时间模型和生命周期管理，在 SQLite 单文件上实现可追溯、可修正、可遗忘的 Agent 长期记忆。

📝 详细摘要

文章介绍开源 Agent 长期记忆系统 HL-Mem（Apache-2.0，v1.1）的设计与取舍。作者先指出长上下文与 RAG 都无法解决长期记忆问题：长上下文只解决单次请求的容量，RAG 的数据是静态文档而记忆是活的，会重复、矛盾、过期、被要求删除，因此记忆系统本质是在检索之上加一层治理。HL-Mem 借鉴认知科学，采用事实通道（Event→Claim→Observation→Mental Model）与经验通道（Event→Episode→Trace/Reward→Policy→Procedure）双通道架构，共享不可变 Event 起点。核心设计包括：Event 不可篡改、Claim 可被 supersede 链修正、valid time 与 recorded time 双时间模型、三层遗忘机制（自然衰减、归档、显式遗忘）、确定性规则优先的去重漏斗与实体约束召回、中文 FTS5 与向量融合检索。工程上坚持运行时独立、本地优先，默认仅依赖 SQLite，后台 Worker 异步处理维护。评测显示 LongMemEval 达 86%，与全上下文和 Native RAG 仅差 3 题和 2 题。

💡 主要观点

  1. 长上下文和 RAG 都无法解决 Agent 的长期记忆问题，记忆系统本质是在检索之上加一层治理。 长上下文只解决单次请求能带多少材料，LongMemEval 显示长上下文 LLM 在持续交互记忆任务上有精度衰减；RAG 的数据是静态文档，而记忆会重复、矛盾、过期、被要求删除，需要去重、冲突消解、生命周期和可追溯。
  2. HL-Mem 采用事实与经验双通道架构，共享不可变 Event 起点但按不同规则演化。 事实通道 Event→Claim→Observation→Mental Model 维护认知，经验通道 Event→Episode→Trace/Reward→Policy→Procedure 积累经验。把两者压成同一种记忆文本，系统既解释不了为什么相信一件事，也解释不了为什么选择一种做法。
  3. Event 不可修改、Claim 可被修正，配合双时间模型实现可追溯、可回放的历史。 原始事件作为案发现场永久保留，Claim 只是系统对 Event 的解读，可被 supersede 链替代而不删除历史。valid time 记录事情何时为真，recorded time 记录系统何时知道，使系统能回答「你当时以为我在哪」和「我实际在哪」两类不同问题。
  4. 遗忘被设计成三层新陈代谢机制，而非一个 Delete API。 自然衰减按 TTL 和激活度降低召回优先级但不改置信度；归档退出普通召回但保留事实与证据；显式遗忘沿依赖关系物理删除并让派生理解失效，tombstone 账本阻止备份恢复让旧记忆复活。遗忘直接保护检索带宽。
  5. 去重与召回采用确定性规则优先的漏斗设计，用实体约束隔离相似对象。 精确哈希处理完全重复，确定性安全门检查主体、数字、版本、极性等 protected atoms，只有灰区才交给 LLM 审计。召回时高置信实体约束隔离其他实体记忆，v1.1 冻结门禁中 15 个高置信实体案例全部进入 Top-5，跨实体错误 Top-1 从 15 降到 0。
  6. HL-Mem 坚持运行时独立与本地优先，把复杂度关进明确边界。 默认仅依赖 SQLite WAL + FTS5 + 向量 BLOB，不依赖外部向量库或图数据库；关系发现默认关闭，避免错误关系沿多跳检索扩散；Provider 通过 allowlist 插件接入，hl-mem ops report 可统计调用量、Token、费用与失败率。
