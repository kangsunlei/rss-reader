改变世界前先认识世界 : Ontology 决策结构化实践

9/28/2026, 6:47:00 AM

📌 一句话摘要

文章提出通过 Ontology（本体）与决策结构化，让 Agent 动态生成工作流以实现业务全托管，强调结构化业务知识是 AI 稳定产出的核心壁垒。

📝 详细摘要

本文分享了商家财务团队利用 Ontology 和 decision_function 实现 Agent 工作全托管的实践。团队摒弃预设 workflow 或打包 Skill 的传统模式，将业务知识建模为包含业务、系统、交付和治理四层的 Ontology 图谱，并将专家判断固化为可执行的决策函数。Agent 遵循“先取证、再决策、后行动”的闭环，根据证据动态生成工作流，完成了 120+ 项任务。文章指出，模型和编排工具会迭代，但结构化的业务知识才是决定 AI 能否稳定高质量决策的核心壁垒，并详细阐述了如何通过碎片化知识积累产生复利，以及人与 Agent 的边界划分。

💡 主要观点

  1. 工作全托管的本质是每一步都能被结构化决策约束 传统 workflow 无法应对真实工作的动态变化。通过 decision_function，Agent 在每一轮执行中回答业务对象、所需证据、拒绝路径、可执行动作等问题，形成 Observe-Decide-Act-Verify-Next 的闭环，确保流程可审计、可复现。
  2. Ontology 是决策遍历的可执行业务世界模型 区别于非结构化的文档知识库，Ontology 将知识拆分为 Business、System、Delivery、Governance 四层。它定义了对象、属性、关系和状态，使 Agent 能定位对象、补齐证据槽并沿关系图遍历，从而解决“黑话”理解和隐含上下文缺失的问题。
  3. 碎片化知识积累优于预打包 Skill Skill 本质是 ontology 碎片的固定打包，存在维护成本高、互相干扰等问题。采用碎片化存储（decision route， reject route， golden case），由 decision_function 按任务当场组装，实现了知识的可复用、可组合和独立演进，产生时间复利。
  4. 结构化业务知识是 AI 长期稳定的核心壁垒 模型层和 harness 层快速迭代替换，但垂直场景的业务判断逻辑（如红冲工单证据、发布门禁）不在模型权重或编排中，而在 Ontology 和 decision_function 里。这一层只能由业务专家沉淀，训练不出来，也编排不出来。
