2 分钟到 20 秒！AI Agent 让工单处理可提效 9 倍

9/11/2026, 12:45:00 AM

📌 一句话摘要

基于 AI Agent 的智能诊断系统通过配置驱动的并发取数、规则+LLM 双通道标签、分层决策 Trace 与 SSE 实时推送，将工单处理时间从 2-3 分钟压缩到 20-40 秒，实现 3-9× 提效。

📝 详细摘要

本文详细介绍了一套基于 AI Agent 的智能诊断辅助决策系统，用于将传统工单处理从人工跨系统切换、手动比对、经验判断的 2-3 分钟流程压缩到 20-40 秒。系统围绕五个核心模块展开：配置驱动的取数编排（Domain as Config）实现零代码增删数据维度、进程内并发合并+分布式锁去重、缓存可信度校验防止错误结果入缓存；规则+LLM 双通道标签评估引擎区分结构化判断与语义模糊标签，并显式区分数据缺失与条件不满足；分层决策引擎（P0-P4）带完整 Trace，既可向操作人员展示决策依据，也作为 AI Agent 总结生成的输入；SSE 事件流+Redis 持久化回放实现边算边看与断线续读；Agent 框架封装模型管理、会话隔离与流式输出，支持 Prompt 热更新并在模型不可用时降级为规则引擎结论。此外，文章提出双层权限模型、全链路可观测性、五条可复用工程准则（配置即代码、数据缺失独立状态、决策即 Trace、降级即设计、实时即持续），并讨论了适用边界、已知局限以及演进规划。整体呈现了一次从经验黑箱到规则透明、可解释、可追溯的人机协同工作方式的重构。

💡 主要观点

  1. 配置驱动的取数编排（Domain as Config）实现零代码增删数据维度、并发调度与依赖自处理。 将每一次底层数据查询抽象为由 JSON 配置完全驱动的取数单元，新增维度只需改配置，编排器通过进程内并发合并+分布式锁去重以及缓存可信度校验（仅命中白名单才写缓存）确保取数正确、高效且可伸缩。
  2. 规则+LLM 双通道标签评估引擎区分结构化判断与语义模糊标签，并显式区分数据缺失与条件不满足。 规则通道处理明确的数值比较、时长等结构化判断；LLM 通道处理登录地点等语义模糊标签。两通道均输出三种状态（正向、负向、未知），避免把「没有数据」误判为「不满足」，从而将因数据缺失导致的误判率降为零。
  3. 分层决策引擎（P0-P4）带完整 Trace，既向操作人员展示决策依据，也作为 AI Agent 总结的输入。 决策引擎采用优先级命中即返回的五层结构，每层记录 Level、Name、Passed、Reason、Facts、HitTags、MissingTags。Trace 可直接在前端展示建立信任，亦被 AI Agent 用于生成有针对性的自然语言解释，实现决策的可解释与可追溯。
  4. SSE 事件流+Redis 持久化回放实现边算边看与断线续读，保证实时感与可靠性兼得。 进程内事件总线负责实时推送，Redis 事件流持久化所有事件并支持通过 Last-Event-ID 进行历史回放与序号去重。订阅必须早于编排器启动，以免错过早期事件；幂等处理防止重复请求产生额外下游压力。
  5. Agent 框架封装模型管理、会话隔离与流式输出，支持 Prompt 热更新并在模型不可用时降级为规则引擎结论。 服务启动时创建一次全局复用的 Runner，标签评估与最终总结共享同一 Runner，Prompt 通过远程配置中心热更新。Agent 以事件流方式输出，解析失败时自动降级为规则引擎结论，确保核心决策流程不中断。

💬 文章金句

  • 一次查询，跨系统多模块数据并发聚合；规则引擎评估标签，AI Agent 生成可读结论；LLM 增强，规则兜底。我们用这套架构把单次工单处理从 2-3 分钟压缩到 20-40 秒，并让操作人员不再依赖「经验直觉」做判断。
  • 把人工研判经验**结构化沉淀** 为规则引擎，而不是锁在个人经验里；
  • 决策即 Trace：决策引擎的输出不是一个结果，而是一条证据链。
  • 配置即代码，声明即执行。新增数据维度的成本从「改代码+发版」降为「改 JSON 配置文件」。
  • 机器给出建议，人负责决策，专业的交给专业的来，模型天然适合做各类信息整理，合并聚类等重复机械式任务，这些都交给模型处理完，最终由人来决策应该怎么处理，怎么安抚用户等等，各司其职才是最和谐的人机协同方式。
