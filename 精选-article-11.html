📝 详细摘要

基于对 1400 多篇论文的系统综述，文章深入探讨了“Context Engineering”这一新兴概念，指出其是 Prompt Engineering 的延伸，旨在通过在有限的上下文窗口内精确构建信息，以优化大型语言模型（LLM）的行为。作者首先通过类比搜索引擎的历史，反驳了 Prompt Engineering 将被弱化的观点，并引入了 Context Engineering。文章将 LLM 比作操作系统，把 Context Engineering 定义为 LLM OS 时代的“用户程序开发工程”，通过精心设计输入、调用资源和构造上下文来“编程”模型行为。随后，文章详细分析了 Context Poisoning、Context Distraction、Context Confusion 和 Context Clash 等四种 Context 处理不当导致的问题。最后，文章从内容类型（指令、知识、工具、记忆）和处理管理过程（写入、选择、压缩、隔离）两个维度对 Context Engineering 进行了分类讨论，并结合实际案例提供了多个最佳实践，为 LLM 应用开发者提供了系统性的指导和深刻见解。

💡 主要观点

  1. Context Engineering 是 LLM OS 时代的软件工程核心 通过将 LLM 比作操作系统，Context Engineering 作为不改动内核，但通过精心设计输入和上下文来“编程”模型行为的关键实践，是 Software 3.0 阶段的开发核心。
  2. Context 处理不当会导致多种严重问题 文章详述了上下文中毒、干扰、混淆和冲突等问题，这些问题会降低 LLM 的推理准确性、影响其能力发挥，并导致低质量或错误的回应。
  3. Context Engineering 涵盖内容类型与管理过程 文章从指令、知识、工具、短期/长期记忆等内容类型，以及写入、选择、压缩、隔离等处理过程，系统性地分类和阐述了 Context Engineering 的范畴与实践。

  • Writing context means saving it outside the context window to help an agent perform a task.
  • 上下文隔离，本质上是对 LLM 进行信息隐藏和上下文封装的策略，它与软件工程中的信息隐藏原则和最小知识原则非常相似：只暴露最少必要的信息，以保持系统的模块性、稳定性和可控性。
