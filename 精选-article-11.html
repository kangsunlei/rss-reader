【AI 创新实践】“架构师 Agent” 系统化落地

9/9/2026, 5:48:00 AM

📌 一句话摘要

本文系统阐述了让 AI Agent 真正承担复杂存量分布式系统架构师职能的实践路径，核心是以强结构化分层知识库替代 RAG 作为知识骨架，并通过渐进式披露与 Agent Runtime 设计，使 AI 能独立完成跨系统的技术方案设计。

📝 详细摘要

文章指出 AI 在大型存量分布式系统中效果不稳定的根源，并非模型能力不足，而是复杂系统的关键知识散落在代码、文档、配置与经验中，彼此断裂，导致 AI 只能依据局部代码推断，出现『局部正确、整体错误』。作者提出让 AI 成为『架构师』的系统性方案，核心是知识库建设与 Agent Runtime 设计。知识库建设强调以『领域』为第一层，采用强结构化设计（business-knowledge 含 meta、principle、scenario、practice、reference 等），而非首推 RAG，因为 RAG 无法保证知识集合的完整性与工程相关性。知识正确性依赖日常增量维护与周期性校准（如大促复盘）。技术方案设计 Agent 的落地包括 PRD 准入（prd-digest）、产品需求增强、分层知识渐进式披露、以及由业务理解层（KBase MCP）、系统分析层（AITOM）、架构推理层（Skill）、服务知识层、事实验证层（Git）构成的 Agent Runtime。最终 AI 能独立完成调研、链路推理、代码核查与方案生成，人类则从『替 AI 收集资料』转为『裁决事实缺口与承担关键决策』。

💡 主要观点

  1. AI 在复杂存量系统中表现不稳定的根源是知识断裂，而非模型能力不足 复杂系统的关键知识（如字段为何不能删、历史分支为何保留）散落在代码、文档、配置、经验中，AI 若未被提供这些事实，只能依据局部代码推断，导致『局部正确、整体错误』。
  2. 知识库建设应以『领域』为第一层，采用强结构化设计，而非首推 RAG RAG 解决的是『找出可能相关内容』，不保证 AI 获得做出完整工程判断所需的知识集合；固定结构知识库（如 business-knowledge 的 meta、principle、scenario 等）提供『知识覆盖约束』，给 AI 确定的阅读路径。
  3. 知识正确性需要维护机制，而非一次性生成 知识库最大风险是文档过期后误导 AI，需通过日常增量维护（关联 Git Push、PR、发布）与周期性校准（如大促复盘）保证知识及时准确，且高风险知识变更需人工确认语义。
  4. 技术方案设计 Agent 的核心是渐进式披露与 Agent Runtime 设计 通过分层知识（业务层→架构层→系统层→基建层）按需加载，配合由业务理解层、系统分析层、架构推理层、服务知识层、事实验证层构成的 Runtime，让 AI 沿最短认知路径完成跨系统方案设计，而非一次性加载所有知识。
  5. 人类在 AI 方案设计中的角色从『资料收集者』转变为『决策裁决者』 AI 独立完成调研、检索、推理与方案生成，但当涉及业务取舍、跨团队接口承诺、合规等高风险决策时，AI 应停止猜测并发起问题，由人类负责裁决事实缺口与承担关键决策。

💬 文章金句

  • AI 在复杂存量系统中最容易出现的错误，往往不是代码语法错误，也不是编译器或单测能直接发现的错误，而是『局部正确、整体错误』
  • 知识是有结构的，更适合被结构化的索引和理解。信息（比如新闻类内容）是结构化松散的，更适合被平行/平铺化检索。
  • 固定结构提供的是『知识覆盖约束』。它告诉 AI：解决一个业务问题，至少要理解哪些方面；而 RAG 只能告诉 AI：这里有一些可能相关的资料。
  • 知识库最大的风险不是缺少文档，而是文档过期后以『看起来很可信』的方式误导 AI。
  • 人不再是系统知识的唯一检索器，而是知识质量和决策权的最终负责人。
