深度思考：架构腐朽 & Loop Engineering

6/12/2026, 12:27:00 AM

📌 一句话摘要

本文从软件工程实践出发，深入剖析系统架构腐朽的本质、成因与应对策略，并提出在 AI Agent 时代通过 Loop Engineering 建立持续排熵能力的工程框架。

📝 详细摘要

文章以「屎山」这一工程现象为切入点，系统性地探讨了软件架构腐朽的根源、表现与治理方法。作者首先给出一个工程上可用的判别标准：屎山不是代码质量差，而是「删除任何东西的风险都大于保留它的成本」。在此基础上，文章从经济、认识、组织三个维度归纳了七条腐朽路径，包括定价倒挂、例外累积、真相分裂、概念通胀、治理自腐、组织断层和重写引力。 作者进一步提出「架构 = 被持续执行的约束 × 能被追溯的理由链」这一工作定义，并引入适应度函数、类型系统约束等可操作工具。文章还重点讨论了时间边界问题，指出许多工程问题不发生在空间边界上，而发生在时间边界上。 通过对 Linux、PostgreSQL、SQLite 三个长寿系统的分析，作者提炼出边界分级、所有权显式、变化制度化、不变量下沉、删除合法化等共同机制。在此基础上，给出七个具体的排熵机制：定价对齐、棘轮、守卫自检、熵增仪表、生命周期、不对称稳定性和理由保鲜。 最后，文章将讨论延伸到 AI Agent 时代，提出 Loop Engineering 的概念——把反馈环路设计成可观察、可约束、可验证的工程机制，并强调循环不会替代判断，只会放大判断。

💡 主要观点

  1. 屎山的本质不是代码质量差，而是系统失去了删除能力。 作者给出的判别标准是：删除任何东西的风险都大于保留它的成本。系统只进不出，导致局部性丧失、承重 bug 和疤痕组织三个症状，形成自我强化的正反馈环。
  2. 架构不是蓝图，而是被持续执行的约束网络。 作者提出「架构 = 被持续执行的约束 × 能被追溯的理由链」的工作定义。只有能通过 CI、类型系统等工具验证的规则才是真正存在的架构，否则只是文档里的愿望清单。
  3. 治理路径必须是最便宜的路径，否则每道墙都在为翻墙者训练肌肉。 当合规路径比绕行路径更贵时，腐败不需要任何人主观为恶。作者建议定期审计合规路径与绕行路径的成本差，优先投资降低正门价格，而不是加高墙。
  4. 长寿系统的秘密不是从不腐朽，而是代谢率长期高于腐朽率。 通过对 Linux、PostgreSQL、SQLite 的分析，作者提炼出边界分级、所有权显式、变化制度化、不变量下沉、删除合法化等共同机制。
  5. Loop Engineering 不是让 AI 替你思考，而是把工程判断变成系统可反复执行的循环。 在 AI Agent 时代，工程师的价值从推动每一步执行转向设计目标、上下文、动作、反馈、停止条件和责任边界。循环会放大设计者的认知质量，好的循环积累秩序，坏的循环放大混乱。

💬 文章金句

  • 屎山源于不敢删，架构活于持续排熵。
  • 治理路径必须是最便宜的路径，否则你建的每一道墙，都在为翻墙者训练肌肉。
  • 架构 = 被持续执行的约束 × 能被追溯的理由链
  • 一个 prompt 给 Agent 一条指令；一个 loop 给 Agent 一套工作机制。
  • 循环不会替代判断，只会放大判断。
