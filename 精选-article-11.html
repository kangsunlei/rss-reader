为什么 Agent 时代，大家都在做 CLI？

7/6/2026, 10:08:00 AM

📌 一句话摘要

本文深入分析 AI Agent 时代 CLI 复兴的结构性原因，阐释其与 MCP、SKILL 的分层关系，并提出 AI 友好的产品设计原则。

📝 详细摘要

文章从 CLI 的四十年演进切入，指出 Agent 时代 CLI 重新崛起不是因为复古，而是因为 CLI 与 LLM 天然同构：text-in/text-out、自描述（--help 即可上手）、符合 Unix 管道组合哲学、原生支持并行、上下文开销低。作者进一步将未来产品划分为面向人、面向 Agent 和人机协作三层，认为协作界面的可观测性——计划可观测性与过程可观测性——是解决信任问题的关键。对于 CLI、MCP、SKILL 三者，作者提出分层模型：CLI 是指令层（食材），MCP 是工具层（预制菜），SKILL 是技能层（菜谱），三者应根据场景灵活切换而非二选一。最后总结出 AI 友好的四个特征：可调用、可理解、可组合、可恢复，并指出真正的 Agent First 不是加一个 CLI，而是围绕人+Agent 协作重新设计产品的能力暴露、数据流动与协作边界。

💡 主要观点

  1. CLI 与 LLM 天然同构，是 Agent 调用数字世界的高效入口。 LLM 是 text-in/text-out 的机器，终端也是 text-in/text-out 的界面，二者之间无需视觉识别和模拟操作，一条命令即可完成操作，路径最短。
  2. CLI 的自描述性（--help）使其对 AI 比 API 更友好。 AI 遇到陌生 CLI 只需敲 --help 即可了解全部能力与参数，而 API 需要预先注入文档、弄清端点和认证方式，CLI 本身即是文档。
  3. 未来产品应分为面向人、面向 Agent、人机协作三层，协作界面是下一个范式。 面向人的 GUI 追求易用，面向 Agent 的 CLI 追求效率，而人机协作界面需要双向设计：让人高效表达意图并保持掌控，同时让 Agent 流畅展示状态和接收反馈，其中可观测性是关键。
  4. AI 友好的产品应具备可调用、可理解、可组合、可恢复四个特征。 每个有价值操作都应有编程接口（CLI/API/MCP），接口语义化且错误提示可指导下一步，操作可原子化串联，且幂等、状态可追溯、失败可回退。
  5. Agent First 不是加一个 CLI，而是围绕人+Agent 重构能力暴露、数据流动和协作边界。 产品需要同时提供人类操作和 Agent 调用的两种界面，数据层从展示给人看转变为同时喂给 Agent，协作边界动态可调，类似 Mobile First 对交互范式的根本性重塑。

💬 文章金句

  • CLI 的胜出不是审美偏好，是结构性优势。
  • 真正需要的并非在 CLI、MCP、SKILL 之间三选一，是根据场景在三层之间自由切换。
  • AI 友好不是单纯在产品旁边套一个 CLI，就像当年「移动友好」不是给网页加个二维码就可以一样。
  • 人不需要看到 Agent 的每一行日志，但需要在关键节点上有决策权。好的产品应该为这种协作模式提供原生支持。
