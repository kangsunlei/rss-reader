一个 AI 智能体编程怀疑论者对 AI 智能体编程的深度尝试

2/27/2026, 10:00:00 AM

📌 一句话摘要

深入探讨一位曾经的 AI 怀疑论者如何转向使用 Claude Opus 4.5、结构化规范和 Rust 构建复杂软件的高效工作流。

📝 详细摘要

知名数据科学家、长期 AI 怀疑论者 Max Woolf 详细描述了他在 Claude Opus 4.5 发布后对 AI 智能体态度的转变。他认为，使用智能体成功的关键不在于“魔法”，而在于严谨的工程方法。这包括使用 AGENTS.md 文件严格定义编码标准，以及采用“规范优先”的工作流，即在执行前将复杂需求记录在 Markdown 文件中。文章重点介绍了几个雄心勃勃的项目，尤其是利用 AI 通过 PyO3 crate 桥接 Python 和 Rust。通过利用智能体处理 Rust 严格编译器的能力，Woolf 能够创建高性能工具——例如图标渲染器、基于终端的 MIDI 作曲器和物理引擎——而这些工具如果手动编写将极其困难。他总结道，虽然智能体仍需要严格的人工 QA，但它们已成为经验丰富的开发者的真正战力倍增器。

💡 主要观点

  1. AGENTS.md 文件是确保 AI 输出质量一致的关键差异化因素。 通过定义格式、库偏好和反模式（如不必要的表情符号或注释）的严格规则，开发者可以使智能体的行为符合专业标准和个人偏好。
  2. 通过为复杂任务编写详细的 Markdown 文件，采用“规范优先”的工作流。 与其使用模糊的对话提示词，不如在版本控制的 Markdown 文件中记录完整的功能需求，为智能体提供全面的路线图，从而减少幻觉和逻辑错误。
  3. AI 智能体使 Python 开发者能够利用 Rust 构建高性能模块。 使用智能体来处理 Rust 严格的借用检查器和 PyO3 桥接，允许开发者在不是专家的情况下“用 Rust 重写”，从而获得显著更快且更安全的软件。
  4. 开发者的角色正在演变为高级“黑盒” QA 工程师。 随着智能体处理大部分实现工作，人类的主要价值转向识别边缘情况、测试逻辑回归以及提供 AI 目前缺乏的关键监督。

💬 文章金句

  • 如果 AGENTS.md 文件是那些在使用智能体时获得好结果和坏结果的人之间的主要区别，我一点也不觉得奇怪。
  • 我的提示词方法是将可能非常庞大的单个提示词写在它自己的 Markdown 文件中……然后用该提示词标记智能体，并告诉它实现该 Markdown 文件。
  • 从历史上看，由于 Rust 的小众性，LLM 在生成 Rust 代码方面表现不佳……然而，由于现代 LLM 的后训练范式，全新的 LLM 完全有可能是经过专门的 RLHF 训练来编写更好的 Rust 代码。
  • 作为一个做了 5 年无法审查底层代码的黑盒软件 QA 工程师，这种情况正是我的专长。
  • 在这个工作流中仅使用智能体编程的一个后果是，我无法构建一个最小可复现测试用例来提交回归 Bug 报告。
