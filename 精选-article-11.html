我的 AI 原生开发流程：一个真实案例的完整复盘

8/24/2026, 12:00:00 AM

📌 一句话摘要

本文以宝玉为例，完整复盘 AI 原生开发流程，阐述人从编码者转为指挥官、文档作为关键中介、以及瓶颈转移到设计与测试环节的核心变化。

📝 详细摘要

本文通过作者宝玉在其字幕转译翻译应用 BaoCut 上添加远程转录功能的真实案例，完整复盘了 AI 原生开发的五个关键阶段：可行性分析、设计文档、高精度原型设计、编码实现及测试验证。文章指出，AI 原生开发并未改变传统软件开发流程，而是将执行主体从人转移到 Agent，人成为指挥官只在关键节点做判断与决策。文档在人与 Agent、Agent 之间的会话中充当上下文传递的桥梁，确保信息不丢失。瓶颈从编码转移到代码两侧——左侧的设计与确认、右侧的测试、验证与部署。文章进一步说明，大部分编码类 Skills 已非必需，核心价值在于流程设计而非 prompt 调优，强调人应把精力放在判断、原型打磨及用户视角的黑盒测试上。

💡 主要观点

  1. 可行性分析是决定要不要做的第一关，避免盲目开发 作者让 Agent 给出技术方案，基于产品判断选择最优方案，强调人在关键路径上的决策作用，避免因缺乏前期分析而浪费时间与资源。
  2. 设计文档作为人与 Agent、Agent 之间的桥梁，固化需求与技术方案 文档用于人的确认与修改，同时作为会话间上下文传递的载体，使后续 Agent 能直接基于文档执行，减少重复解释和信息损耗。
  3. 高精度原型设计将需求、原型、UI 三合一，降低后期修改成本 通过自然语言让 Agent 快速迭代界面，原型阶段修改成本低，而进入开发后改动涉及代码、样式、状态管理及测试，成本呈指数级上升。
  4. 瓶颈转移到设计与测试两端，编码已非瓶颈，人应聚焦判断与验证 Agent 的编码能力已很强，真正需要人类投入的是可行性判断、原型打磨及用户角度的黑盒测试，这两端才是当前需要优化的环节。

💬 文章金句

  • 先说结论：流程没变，角色变了
  • 文档在 AI 时代有了全新的角色，它是人和 Agent 之间、以及 Agent 和 Agent 之间的桥梁。
  • 瓶颈转移到了代码两侧：左边是设计和确认，右边是测试、验证和部署。
  • 大部分开发类 Skills 是没必要的。
  • 把精力花在流程设计上，比花在 prompt 优化上回报大得多。
