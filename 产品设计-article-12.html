AI 编程助手总在“失忆”？试试这个开源记忆层 AgentMemory

9/9/2026, 8:11:39 AM

📌 一句话摘要

本文介绍开源项目 agentmemory，它通过四层记忆模型、MCP 与 hooks 自动捕获 AI 编程助手的会话过程，将项目交互沉淀为可检索的工作记忆，解决跨会话失忆问题，并对比了 OpenViking 的定位差异。

📝 详细摘要

文章针对 AI 编程助手跨会话失忆的痛点，介绍开源项目 agentmemory。该项目在 GitHub 获得 28k Star，通过 hooks 捕获会话中的提示词、工具调用、文件访问、命令执行结果和错误信息，经压缩、索引后在新会话中召回相关内容。其记忆分为四个层级：从工作记录到长期经验，支持 BM25 关键词检索、向量语义检索和知识图谱关系检索。文章对比了 agentmemory 与 OpenViking 的定位差异，指出前者是持久化记忆层，后者是更广的上下文管理系统。安装体验方面，一条命令可启动，但 Windows 原生环境需手动配置 iii-engine，存在部署门槛。文章还澄清了 MCP 与 hooks 的分工，以及 OpenAI 兼容接口的含义。作者认为该项目最有价值之处在于将记忆变成完整的工程管线，强调召回质量与记忆治理的重要性，并提醒用户注意隐私和错误记忆的清理。

💡 主要观点

  1. agentmemory 通过捕获、压缩、索引和召回将 Agent 的工作过程转化为可检索的记忆，解决跨会话失忆问题。 它利用 hooks 自动记录会话中的工具调用、文件访问等原始观察，再提炼为长期记忆，并在新会话开始时只注入与当前项目相关的内容，避免重复解释项目背景。
  2. agentmemory 采用四层记忆模型，从工作记录逐步整理成稳定的项目知识。 单次工具调用是局部动作，多个动作组合后才能体现 bug 根因、实现原因等有价值信息，项目通过版本关系、来源追踪和过期处理来治理记忆。
  3. agentmemory 与 OpenViking 定位不同：前者是持久化记忆层，后者是上下文管理系统。 agentmemory 专注于会话捕获与工作记忆召回，OpenViking 则将记忆、资料和技能统一组织成虚拟文件系统，覆盖范围更广，用户可根据需求选择。
  4. MCP 与 hooks 分工不同：MCP 让 Agent 能调用记忆服务，hooks 负责自动采集会话信息。 只接通 MCP 通常只能手动保存和查询，要实现自动记录还需安装对应插件或 hooks，例如 Claude Code 的插件安装方式。
  5. Agent 长期记忆的关键在于召回质量与记忆治理，而非单纯增加存储容量。 记忆保存过多可能引入过时或错误信息，agentmemory 提供版本、来源、相似项和删除能力，作者提醒用户需定期清理错误记忆并谨慎开启自动采集。

💬 文章金句

  • 让 Agent 不只记住当前对话，也逐渐记住项目的工作方式。
  • 记忆保存得越多，未必越好。
  • 它保存的是长期信息，服务的却是每天的开发过程：项目为什么采用某种方案，某个 bug 曾经如何解决，一条命令为什么不能直接执行，某个文件里已经有哪些约定。
