分享一个大幅节省 Codex 额度的邪修方法，不要浪费了你的 ChatGPT Pro 会员

9/17/2026, 7:41:47 AM

📌 一句话摘要

作者通过将服务器封装为 MCP 插件，利用 ChatGPT Pro 网页版 GPT-6 Pro 模型进行低成本的生产数据分析与规划，再交由 Codex 执行，从而大幅降低 Token 额度消耗并提升优化效率。

📝 详细摘要

本文分享了一种利用 MCP (Model Context Protocol) 协议优化 AI 开发工作流的实战方法。作者在运营 AIHOT 产品时面临高昂的 Codex 额度成本，通过将服务器封装成只读的 MCP Server 插件，使网页版 GPT-6 Pro 能直接读取真实生产数据、日志和 GitHub PR 记录，从而在不消耗 Codex 额度的情况下完成高质量的分析与架构规划。最后，将规划方案一键同步至 Codex，由 GPT-6 Astra 执行具体开发。这套「分析规划（GPT-6 Pro）+ 具体执行（Codex）」的组合拳将周额度消耗从 10% 降至 4%，实现了合规且高效的降本增效。

💡 主要观点

  1. 利用 MCP 协议打破 AI 的数据孤岛 通过将服务器封装为 MCP Server 插件，让 AI 能够访问真实生产数据（而非仅靠代码推测），实现了「代码定义理论运行 $\rightarrow$ 数据定义实际运行 $\rightarrow$ PR 历史定义演进过程」的完整信息闭环。
  2. 构建「规划」与「执行」的分离工作流 使用额度独立且强大的网页版 GPT-6 Pro 进行深度分析和方案规划，随后将结果同步至 Codex 由 GPT-6 Astra 执行，有效避免了在分析阶段浪费昂贵的 Codex Token。
  3. 确保生产环境的安全与合规 在实现 MCP 插件时采用最小权限原则（只读）、引入飞书 OAuth 鉴权，确保数据安全且不影响生产性能，避免使用高风险的第三方反代桥接工具。

💬 文章金句

  • 代码告诉 AI，这套系统理论上应该怎么运行。生产数据告诉 AI，这套系统实际上是怎么运行的。PR 历史，则告诉 AI，它为什么一路变成了今天这个屎山。
  • 万物皆可 MCP，你可以把你任何本地电脑上、服务器上的东西封装成 MCP，然后做成你的私有插件。
  • ChatGPT 上的 GPT-6 Pro 通过 MCP 的方式把真实世界接入进来，进行详细分析做规划和架构。然后 Codex 的 GPT-6 Astra high 负责具体的开发执行。
