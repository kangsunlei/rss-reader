阻止我过度设计 Claude Code 的可扩展性三角

3/12/2026, 7:01:52 AM

📌 一句话摘要

本文介绍了 Claude Code 的“可扩展性三角”，这是一个在 MCP 服务器、子智能体和技能之间进行选择的框架，旨在优化 AI 开发工作流的成本、质量和架构清晰度。

📝 详细摘要

本文探讨了 Claude Code 三大核心扩展机制背后的架构哲学：模型上下文协议（MCP）服务器、子智能体（subagents）和技能（skills）。作者认为，当开发者无法区分这些层级时，往往会出现过度设计。MCP 服务器被定义为使用 JSON-RPC 进行外部系统访问（如数据库、API）的独立进程。子智能体是隔离的 Claude 会话，允许进行模型路由（例如使用 Haiku 处理常规任务）和上下文管理，以减少噪音和成本。技能是基于 Markdown 的简单提示词注入，用于可复用的团队知识。通过将这些工具归类为“三角形”，作者提供了一个决策矩阵，帮助开发者避免常见的反模式——例如将 MCP 用于静态内容，或在 Opus 等昂贵模型上运行常规检查。文章最后提出了一个生产级的组合模型，这三个层级协同工作，构建出一个安全、经济且高度专业化的 AI 编程环境。

💡 主要观点

  1. MCP 服务器应保留用于有状态的进程间通信和外部系统访问。 通过 JSON-RPC 运行，MCP 服务器允许 Claude 与数据库和 API 交互。当任务需要持久连接、安全边界或无法通过简单 CLI 命令处理的实时数据时，最适合使用它们。
  2. 子智能体通过提供隔离的上下文窗口和模型路由来优化性能和成本。 通过使用 Haiku 等特定模型启动新会话，子智能体消除了对话噪音并大幅减少了 Token 使用量。这种隔离确保了代码审查或调试等专业任务的高质量输出。
  3. 技能是注入可复用团队知识和工作流模板的最简单层级。 技能以 Markdown 文件形式实现，是直接将文本注入当前会话的斜杠命令。它们非常适合处理编码标准或 SQL 命名规范等静态信息，且无需独立进程的开销。
  4. 有效的 AI 工程需要针对生产环境对这三种机制进行分层组合。 一个稳健的配置使用技能来传递知识，使用子智能体处理专业行为，并使用 MCP 服务器获取外部数据。这种分层方法确保了最小权限访问，并将任务复杂度与最具成本效益的模型层级相匹配。
  5. 避免反模式对于防止过度设计和不必要的运营成本至关重要。 开发者应避免为静态内容构建 MCP 服务器、将简单任务路由到昂贵模型，或创建深度嵌套的子智能体链，因为这些做法会增加延迟并掩盖实际的工程工作。

💬 文章金句

  • 10 分钟对比 40 小时。同样的输出。
  • 隔离本身就是特性。
  • MCP 服务器处理通信，但你的服务器处理策略。
  • 更小的上下文和更便宜的模型相结合，通常能将代码审查成本降低 85-95%。
  • 可扩展性三角不是一个理论框架。它是一个防止你构建错误事物的实用工具。
