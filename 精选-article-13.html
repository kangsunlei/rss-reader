重新思考研发基础设施：当 Agent 成为第一公民

6/3/2026, 10:09:00 AM

📌 一句话摘要

本文提出「意图驱动 + 代码沉淀」的统一框架，论证 Agent 并未改变软件进化的基本结构，而是将「意图 → 代码」的循环速度从月/周级压缩到分钟级，并由此推导出研发基础设施必须从 People-Oriented 转向 Agent-Oriented 的设计原则。

📝 详细摘要

文章从作者自建的一个周报系统切入，观察到 Agent 时代代码生命周期从「月/年」缩短到「分钟」，基础设施变得「不可见」。作者进而提出一个更本质的观察：软件系统一直是「意图（不确定性）驱动 + 代码（确定性）沉淀」的进化体，Agent 没有改变这个模式，只是将「意图 → 代码」的桥梁从人换成了 Agent，循环速度提升了几个数量级。 基于此框架，作者分析了三个关键变量的变化：桥梁带宽（从人到 Agent）、沉淀粒度（持久代码与瞬态代码的分化）、循环频率（从发布周期到运行时反馈）。随后通过三个内部实践案例（多角色 Agent 研发系统、配置推送、身份鉴权碎片化），揭示了现有基础设施在 Agent 时代面临的系统性失配。 文章的核心贡献在于提出了从 People-Oriented 到 Agent-Oriented 的设计原则，即把安全模型从「依赖人的自我约束」重建为「依赖 infra 的机制保证」，并在四个层次（可理解、可操作、可感知、可追溯）上给出了具体的能力要求。最后结合行业趋势（Superset、Google gws、Credential Brokering），提出了 Harness 平台化、统一身份体系、Dry-run 基础设施、验证体系演进、Agent 行为驱动的 Infra 质量度量等高杠杆行动方向。

💡 主要观点

  1. Agent 没有改变软件进化的基本结构，只是加速了「意图 → 代码」的循环。 传统研发中，人是意图到代码的桥梁，循环周期是周/月级；Agent 参与后，桥梁变为 Agent，循环周期压缩到分钟级。这个判断意味着不需要推翻已有认知框架，只需追问速度变化后哪些假设失效。
  2. Agent 时代代码分化为瞬态代码与沉淀代码，基础设施的设计假设需要重构。 瞬态代码是 on the fly 生成的一次性中间产物（生命周期分钟级），沉淀代码是经过验证后固化的逻辑。Git、CI/CD、Code Review 等传统基础设施假设「每次变更都值得 commit」「代码是稳定的」，在快循环下全部失效。
  3. Agent 的自主程度是基础设施安全能力的函数，而非 Agent 智能的函数。 阻碍 Agent 自主操作（如配置推送）的瓶颈不在 Agent 侧，而在 Infra 侧缺乏资源归属治理、dry-run、分级策略和回滚能力。Infra 的安全能力越强，Agent 的自主空间越大。
  4. 面向 Agent 的基础设施设计应遵循从 People-Oriented 到 Agent-Oriented 的转变。 People-Oriented 的安全靠人的自我约束加事后审计；Agent-Oriented 的安全靠机制化保证。具体需要在可理解、可操作、可感知、可追溯四个层次上提供能力，把原来隐式依赖人的认知、常识和责任心显式化为系统机制。
  5. 身份鉴权碎片化在 Agent 时代被两个乘法因子放大为瓶颈。 角色融合导致身份体系数量膨胀（从每人 2-3 套到每 Agent 5-8 套），乘以工作频率导致切换次数膨胀（人一天切换几次，Agent 一分钟内连续切换多次）。理想状态是 Agent 拿到一个身份，在所有 Infra 上通用。

💬 文章金句

  • Agent 不是革命，是加速。它没有改变软件进化的基本结构，只是把「意图 → 代码」的循环速度提高了几个数量级。
  • Agent 能不能自主操作，不取决于 agent 有多聪明，而取决于 infra 提供了多强的安全护栏。
  • 从 People-Oriented 到 Agent-Oriented，本质上是把安全模型从「依赖人的自我约束」重建为「依赖 infra 的机制保证」。
  • 复杂度不是问题，不一致才是。
  • Infra 的能力边界，就是 agent 的自主边界。
