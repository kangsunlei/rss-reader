📝 详细摘要

这篇文章详细介绍了 Simon Willison 成功的逆向工程工作，主要通过提示 Claude 并检查其行为，以揭示 Anthropic 的 Claude 消费者应用的两个未宣布的功能更新。首先，它探讨了 Claude 移动应用中新的原生日历事件创建和消息撰写工具。Willison 演示了这些工具（`event_create_v0` 和 `message_compose_v0`）是如何作为 Claude 的内部工具实现的。他还提供了提取的 JSON 模式。其次，文章调查了增强的 Claude Artifacts，它现在支持完整的 Claude API 功能，包括图像和 PDF 附件。Willison 揭示了这是通过 Anthropic 对 Artifacts 中的 `fetch()` 函数进行猴子补丁来实现的，以代理 API 调用，从而实现与 Claude API 的直接交互，而无需显式的 API 密钥。文章赞扬了这些功能的巧妙实现，将 AI 功能与原生平台交互集成，并展示了深刻的技术见解。

💡 主要观点

  1. Claude 移动应用现在通过内部工具集成原生日历和消息撰写。 Claude 新的 `event_create_v0` 和 `message_compose_v0` 工具允许直接创建日历事件和消息，通过将非结构化的信息转换为结构化的日历/消息操作来简化用户工作流程。
  2. Claude Artifacts 现在支持完整的 Claude API 功能，包括多模态输入。 这项重大升级使 Artifacts 能够利用完整的 Claude API，从而实现高级功能，如图像和 PDF 附件，极大地扩展了 AI 驱动的 Web 应用的潜力。
  3. 增强的 Artifacts API 集成通过 `fetch()` 猴子补丁巧妙地实现。 Anthropic 没有使用复杂的自定义代理，而是将代码注入到 Artifacts 中的 `fetch()` 函数中，无缝地重定向 API 调用并处理身份验证。这简化了 Artifact 创建者的开发。

💬 文章金句

  • 遗憾的是，这些应用程序的发行说明没有得到及时更新——这两个版本均未提供任何文档，仅在 Twitter 上发布了简短公告。
  • 这似乎是通过一个新的**工具**实现的：Claude 现在可以调用该工具，向用户显示包含指定详细信息的事件，并提供“添加到日历”按钮，点击后将触发原生平台的添加事件对话框。
  • 看起来 Anthropic 已经升级了该功能，以支持 Claude API 的完整实现。你可以使用 Claude API 做的任何事情——附加图像和 PDF，输入对话历史记录，甚至可以连接到他们的代码解释器机制——现在都应该可以被 Artifact 中运行的代码访问。
  • 据我所知，他们的实现方式更为简单：他们允许 Artifacts 针对 `https://api.anthropic.com/` 运行 `fetch()` 调用。这是 Anthropic 的常规 API，Claude 4 现在可以熟练使用，而之前的 Claude 模型则不具备此能力。
  • 这是一个非常巧妙的解决方案，它允许在 Artifacts 中启用完整的 Claude API，而无需构建自定义代理函数（该函数需要不断更新以反映未来的改进）。与许多其他功能一样，关键细节都体现在系统提示中。
