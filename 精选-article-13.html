从进化到泛化，RSI 四大前沿框架如何实现 Agent 自动调优

11/9/2026, 10:08:00 AM

📌 一句话摘要

本文系统梳理了 Google 提出的四大 RSI 框架（Harness²、Evo²、RRSI、OO-Harness），从无金标进化、进化机制自优化、正则化防过拟合及面向对象架构解耦四个维度，阐述了实现 Agent 自动调优的完整方法论。

📝 详细摘要

文章聚焦 Google 在 2026 年 10 月短短一个月内发布的四篇 RSI（递归自我改进）相关论文，解析了实现 Agent 自动调优的四大核心框架。Harness² 解决无金标场景下的 Harness 自进化问题，通过冻结模型参数、六步流程（Baseline 跑测、提出修改、验证、组合、整体跑、保存经验）实现无参考答案的优化；Evo² 探索让进化机制本身进化，通过 Trace 生成、改进分析、经验沉淀、模型训练四步，训练出更懂提出修改的 AI；RRSI 采用正则化约束防止过拟合，七步流程（测试基线、规定改动幅度、提出候选、检查合规性、运行评估、决定保留回滚、记录验证泛化）确保通用能力沉淀；OO-Harness 则借鉴面向对象思想，通过封装、继承、多态设计，将通用 Harness 与专有 Harness 分离，配合路由实现架构复用与分化。文章最后通过表格对比四框架定位，强调应根据业务痛点选择组合使用，没有绝对最好的方案。

💡 主要观点

  1. Harness² 实现无金标场景下的 Agent 自进化 通过冻结模型参数、六步流程（Baseline 跑测、提出修改、验证、组合、整体跑、保存经验），从 Trace 中挖掘优化点，实现对 System Prompt、Skill、Tool、Memory 等 Harness 组件的自主改进。
  2. Evo² 让负责进化的机制本身也能进化 通过生成 Trace、分析改进、保存经验、训练迭代五步，将改进过程的成功案例和失败教训转化为可迁移的经验，训练出更擅长提出有效修改的「改进模型」，实现进化机制的套娃式提升。
  3. RRSI 通过正则化约束防止进化过拟合 七步流程加入改动幅度规定、合规性检查、验证集泛化测试等约束，阻止 Agent 为特定评测集刷高分，确保进化内容具备更强的通用性和可复用性。
  4. OO-Harness 采用面向对象思想解决架构复用难题 通过封装、继承、多态设计，将通用 Harness 作为父类，特殊场景的专有 Harness 作为子类，配合路由分发实现「基础兜底 + 专有增强」的解耦组织，避免「一套打天下」或「重复造轮子」的两难。
