【轻量化复刻大模型 / KIMI K3】K3 并行机制交互式演示

📌 一句话摘要

本文通过交互式演示验证了 KIMI K3 预训练中六大并行维度（进程网格、KCP 上下文并行、MoonEP 专家并行、ZeRO 梯度分片、流水线、激活管理）的正确性和实现细节，提供了从数学原理到可运行代码的完整技术路径。

📝 详细摘要

本文系统性解构了 KIMI K3 预训练并行机制的核心实现原理。文章首先构建了六大并行维度的完整框架：进程网格（PP×EP×CP×DP 四维 mesh 布局）、KCP 上下文并行（delta rule 前缀扫描）、MoonEP 专家并行（复制换完美均衡）、ZeRO 梯度分片（CPU offload）、流水线（1F1B 调度）和激活管理（显存账本）。随后通过 19 个交互式实验 Tab 验证了每个机制的数学等价性和工程可行性：KCP 三段式计算与完整递推等价、通信量与序列长度无关、MoonEP 完美负载均衡、附录 E 定理 M(I) ≤ ⌈E/R⌉ 成立、ZeRO world=1 精确还原等。文章最后提供了 Gradio 演示和可视化脚本，所有实验均在 CPU 上运行，结果与 tests/ 目录下的 45 条单元测试一致，确保了实现的正确性。

💡 主要观点

  1. K3 预训练采用六大并行维度的组合：进程网格、KCP 上下文并行、MoonEP 专家并行、ZeRO 梯度分片、流水线 1F1B 调度和激活管理 这些维度分别拆解了序列、专家、数据、层、激活存储和优化器状态，叠加后实现了 28B 参数模型在单卡显存下的可训练。
  2. KCP 通过前缀扫描实现上下文并行，通信量与序列长度 T 无关，满足 incoming[i+1] = M_i @ incoming[i] + Stilde_i 的仿射递推等价 相比标准 KV 并行随 T 增长的线性通信，KCP 只交换 Dk² + Dk·Dv 大小的矩阵，长上下文下显著降低通信开销。
  3. MoonEP 采用专家复制换方案，实现完美负载均衡，每个 rank 的 token 数严格等于目标 S·K 通过复制热点专家到多个 rank，消除了路由不均导致的热点问题，同时满足 M(I) ≤ ⌈E/R⌉ 的理论上界，保证静态缓冲和预分配。
  4. ZeRO-2+offload 将梯度从 GPU 移至 CPU，显存占用从 num_params * 4 bytes / world 降至 0，world=1 时可精确还原完整梯度 反向传播后立即 offload 梯度，GPU 上腾出整片显存空间，优化器 step 前异步取回，实现显存与计算的解耦。
  5. 1F1B 流水线调度通过 warm-up、稳态 fwd/bwd 交替和 drain 三个阶段实现层切分，AttnRes 增量通信只传输新增 block 相比全量传输，增量通信显著降低跨 stage 的数据搬运，micro-batch 结束即 retire 释放，节省比随 stage 数指数增长。

💬 文章金句

  • K3 预训练的并行全景可以用一条恒等式串起来：world_size = pp * ep * cp * dp
  • KCP 每 rank 每 KDA 层只交换两个张量：M（Dk×Dk）和 Stilde（Dk×Dv），大小只由状态维度决定，与 T 完全无关
  • MoonEP 的解法：允许每个 rank 多持几个专家副本（redundant expert），通过重新规划让每个 rank 的 token 数严格相等
  • 附录 E 定理：M(I) ≤ ⌈E/R⌉，对任意路由分布恒成立
  • ZeRO-2 + offload：GPU_memory(gradients) = 0 bytes，显存占用从 num_params * 4 bytes / world 降至 0
