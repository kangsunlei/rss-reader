从 Harness 到 Loop：真正决定 Agent 落地的，从来不是更强的模型

10/13/2026, 11:40:00 AM

📌 一句话摘要

行业共识已转向：模型能力正在商品化，竞争壁垒转移到工程系统。本文探讨如何设计模型外的系统，让 Agent 在生产环境中可靠并自进化，包括 Harness、Loop、自动化、反馈机制，以及未来研发团队的角色变化。

📝 详细摘要

本文基于 QCon 直播，由蚂蚁、腾讯、京东专家共同探讨 Agent 生产环境中的自进化。核心观点：Harness 解决任务完成，Loop 解决持续优化；模型能力不等于系统能力；工程化体系决定交付下限；Loop 自动化执行，人负责决策验收；最大缺口是 Agent 缺乏人的上下文。未来，工程师将从写代码转向设计 Agent 的 Loop，并设置其边界与底线。

💡 主要观点

  1. 生产关系的变化 从人找 AI 处理事情，到 AI 完成任务后找人做决策，这是从 Harness 到 Loop 最本质的变化。人从执行职责中解放，专注于高层决策和验收。
  2. 模型能力 vs. 系统能力 模型能力是锯齿式的，且不等于 Agent 系统能力。很多'更强的模型'只是叙事更强，实际表现未必优于工程优化后的弱模型。模型决定上限，工程化体系决定下限。
  3. 自动化与人机协作 Loop 中，执行环节可以自动化（如 badcase 修复、评测），但方案决策和验收必须由人把控。工程师的角色正在从写代码转向设计和优化 Agent 的进化循环。
  4. 上下文与自进化 最大的缺口是 Agent 缺乏人的上下文（如业务背景、决策依据）。要实现真正自进化，需要改变团队协作方式，记录并共享隐性知识，让 AI 拥有完整的决策背景。

💬 文章金句

  • 从 Harness 到 Loop 最本质的变化，是生产关系的变化：人从执行职责里解放出来，变成 AI 干完活来找人做决策。
  • 模型能力不等于 Agent 系统能力，能力是锯齿式的，很多'更强的模型'只是叙事更强，不是能力更强。
  • 模型决定能力上限，工程化体系决定交付下限，代码生成率做到 90% 不解决问题，成本只是从开发转移到测试和线上。
  • 离'真正的自进化'还很远，最大的缺口是 Agent 没有人的上下文。
