构建 Claude Code 的经验：我们如何使用 Skills

3/17/2026, 12:00:00 AM

📌 一句话摘要

Anthropic 工程师分享了构建 Claude Code Skills 的实战经验，系统性地提出了九大技能类别及编写、分发和衡量 AI 智能体技能的核心技巧。

📝 详细摘要

本文由 Anthropic 内部工程师 Thariq Shihipar 撰写，深入探讨了 Claude Code 中“Skills”（技能扩展）的本质与应用。作者指出 Skills 不仅仅是 Markdown 文件，而是包含脚本、资源和配置的文件夹，是 AI 智能体发现和使用工具的核心载体。文章将 Skills 划分为库与 API 参考、产品验证、数据获取、业务自动化等九大类别，并分享了关键编写技巧：避免陈述显而易见的信息、建立“踩坑点”章节、利用文件系统实现渐进式披露、以及通过 description 字段精准引导模型触发。此外，文章还讨论了 Skills 的分发机制及如何通过钩子衡量其使用效果，为开发者构建高效 AI 辅助开发流提供了系统化指南。

💡 主要观点

  1. Skills 的本质是结构化的文件夹而非单纯的文本文件。 Skills 可以包含脚本、资源文件和数据，允许 AI 智能体通过探索文件系统来执行复杂任务，而不仅仅是读取一段提示词。
  2. 建立“踩坑点（Gotchas）”章节是提升 Skill 价值的关键。 记录 Claude 在使用特定库或工具时容易犯的错误，能有效打破模型的常规思维惯性，是 Skill 中信息量和实用性最高的部分。
  3. 利用文件系统实现上下文工程与渐进式披露。 通过将详细 API 或模板拆分到子文件夹，让 AI 在需要时才读取，既节省了上下文窗口空间，又提高了模型处理信息的效率。
  4. Skill 的描述字段（description）应作为触发条件而非功能摘要。 该字段是给模型看的，应明确描述在什么场景下该调用此技能，其逻辑更接近于编程中的 if-then 条件判断。
  5. 通过提供脚本库让 AI 专注于逻辑编排而非样板代码生成。 给 AI 提供现成的辅助函数和工具脚本，使其能通过即时组合这些功能来完成高级分析，从而大幅提升任务执行的成功率。

💬 文章金句

  • Skills 最有意思的地方恰恰在于它们不只是文本文件——它们是文件夹，可以包含脚本、资源文件、数据等等。
  • 任何 Skill 中信息量最大的部分就是踩坑点章节。这些章节应该根据 Claude 在使用你的 Skill 时遇到的常见失败点逐步积累起来。
  • 把整个文件系统当作上下文工程（Context Engineering）和渐进式披露（progressive disclosure）的工具。
  • description 字段不是摘要——它描述的是何时该触发这个 Skill。
  • 给 Claude 提供脚本和库，让它把精力花在组合编排上——决定下一步做什么，而不是重新构造样板代码。
