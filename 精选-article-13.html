美团多业务落地复盘：由浅入深拆解 Agent 评测体系

9/15/2026, 11:15:00 PM

📌 一句话摘要

美团技术团队分享其 Agent 评测体系的实践经验，探讨评测如何从简单的结果打分演进为覆盖行为、过程与任务系统的基础设施能力。

📝 详细摘要

本文由美团图灵 Agent 评测团队撰写，系统性地拆解了 Agent 评测的方法论与演进路径。文章首先定义了 Agent 评测的核心目的在于通过「观测 + 评测」驱动持续迭代，强调评测对象已从单一模型扩展为「模型+系统+工具+流程」的复杂系统。在方法论层面，提出了通过「指标下钻」和「Rubric 二元化」实现人机一致性的具体路径，并主张以 Bad Case 驱动的实践科学而非复杂的理论体系。最后，文章分析了从短程 ChatAgent 向长程 Agent 演进带来的范式转移，即从关注「说得好不好」转向关注「事情做成没有以及怎么做成的」，并提出了支撑大规模 Agent 生态所需的评测基础设施能力清单。

💡 主要观点

  1. Agent 评测的核心是行为评测而非单纯的结果评测 由于 Agent 涉及工具调用、规划和状态管理，仅看最终答案会掩盖路径混乱或不可复现的问题。评测必须覆盖结果层、过程层、效率层和风险层，通过 Trace 系统将黑盒推理过程透明化。
  2. 通过「指标下钻」与「Rubric 二元化」解决主观评测的不一致性 为了实现「人人一致」和「人机一致」，应将模糊的评价指标拆解为具体的、二元化（是/否/未知）的判定规则（Rubric），从而将主观感受转化为可判断的事实依据。
  3. 评测体系的构建应遵循「实践科学」而非「理论先行」 建议从高频核心场景起步，通过收集生产环境中的 Bad Case 和沉淀 Good Case 来喂养评测体系，形成「采集-清洗-评测-质检-分析」的数据飞轮。
  4. 长程 Agent 驱动评测范式从 Response Evaluation 转向 Trajectory Evaluation 长程 Agent 处理的是复杂任务而非简单问答，评测重点变为任务完成度、执行轨迹质量及 Skill 的全生命周期管理，评测逻辑由「Query-Answer」变为「Prompt-Expected Behavior-Trace」。
  5. 评测能力需从「打分动作」升级为「基础设施能力」 为了支撑大规模生态，基础设施需具备全链路回放、执行沙箱、AI 评测引擎、回归机制及准入准出门禁等能力，使评测真正嵌入研发发布流程。

💬 文章金句

  • 观测 + 评测 = 持续迭代
  • 看不见的问题，几乎不可能被稳定解决。
  • Agent 评测正在从"答案评测"走向"行为评测"。
  • 从"主观的模糊感受"转向"可判断的事实依据"，用下钻降低模糊度。
  • ChatAgent 评测关心"说得好不好"，长程 Agent 评测关心"事情做成没有，以及是怎么做成的"。
