剖析 Cloudflare Workers CPU 性能基准测试

10/14/2025, 8:00:25 PM

📌 一句话摘要

Cloudflare 针对一项独立基准测试中 Workers 在 CPU 密集型任务中性能低于 Vercel 的问题，详细阐述了其调查过程、平台修复方案，并分享了对基准测试复杂性的深入见解。

📝 详细摘要

Theo Browne 的一项独立基准测试初步显示，在 CPU 密集型 JavaScript 工作负载中，Cloudflare Workers 的性能比 Vercel (AWS Lambda 上的 Node.js) 慢 3.5 倍。由于 Cloudflare Workers 和 Vercel 均基于 V8 引擎，因此 Cloudflare 积极主动地对这一性能差异进行了深入调查，并保持信息透明。他们的调查确定了几个促成因素：次优的内部基础设施调整 (调度策略、V8 引擎垃圾回收器设置)、JavaScript 库 (OpenNext、Next.js、React) 的效率低下以及基准测试方法本身的问题 (例如，测量首字节时间、Next.js 配置差异、本地执行偏差、CPU 差异)。Cloudflare 实施了多项修复，包括更新其调度算法和 V8 引擎垃圾回收器调整，并为 OpenNext、Node.js 和 V8 提交了代码补丁，以优化 `JSON.parse` 和三角函数，从而使更广泛的 JavaScript 生态系统受益。这些努力显著缩小了性能差距，使 Workers 在大多数基准测试中与 Vercel 竞争，并提高了全球所有 Workers 用户的性能。该文章还强调了创建真正具有代表性的基准测试的内在困难。

💡 主要观点

  1. 最初的基准测试显示 Cloudflare Workers 在 CPU 密集型 JavaScript 任务中明显慢于 Vercel。 一位独立开发者的基准测试表明 Workers 速度慢了 3.5 倍，这出乎意料，因为两个平台都使用相同的 V8 引擎 JavaScript 引擎。
  2. Cloudflare 发现并修复了影响调度和 V8 引擎垃圾回收的内部平台调整问题。 Cloudflare 发现其基础设施中的次优调整，特别是在热隔离路由策略和历史 V8 引擎新生代内存大小配置中，解决了主要的性能差异，并使 Workers 在 CPU 密集型场景中更加高效。
  3. OpenNext、Next.js 和 React 等 JavaScript 框架的效率低下导致了性能瓶颈。 调查显示 JavaScript 框架及其适配器效率低下，包括不必要的内存分配、次优的流处理以及带有 reviver 函数的慢速 `JSON.parse`，导致 Cloudflare 为 OpenNext、Node.js 和 V8 提交了代码补丁。
  4. 基准测试方法存在不足，例如客户端指标采集和配置差异，导致了最初的结果出现偏差。 最初的基准测试结果因方法上的不足而产生偏差，例如客户端指标采集假设、网络延迟影响、CPU 可变性和 Next.js 配置差异，Cloudflare 通过标准化其测试环境解决了这些问题。
  5. Cloudflare 的努力显著缩小了性能差距，展示了对平台优化和开源贡献的承诺。 在实施修复并为上游代码库做出贡献后，Workers 现在在大多数基准测试案例中的性能与 Vercel 相当，从而使更广泛的 JavaScript 生态系统受益。
