解剖小龍蝦 — 以 OpenClaw 為例介紹 AI Agent 的運作原理

3/9/2026, 1:19:21 AM

📌 一句话摘要

本文通过剖析开源项目 OpenClaw，揭示了 AI Agent 如何利用系统提示词、工具调用、记忆管理及心跳机制，将单纯的“文字接龙”模型转化为具备自主任务执行能力的智能系统。

📝 详细摘要

文章以李宏毅教授的课程内容为核心，深入浅出地拆解了 AI Agent 的底层运作逻辑。作者指出，尽管底层大语言模型（LLM）本质上只是缺乏记忆的“文字接龙”机器，但通过 AI Agent 框架（如 OpenClaw），可以为其构建身份认知、工具调用、记忆管理和自主排程等核心能力。文章详细介绍了如何利用 System Prompt 赋予模型目标，通过 Function Calling 实现物理世界交互，利用 RAG 与上下文压缩技术克服 Token 限制，以及通过心跳机制实现主动任务触发。最后，文章严肃探讨了 Agent 自主运行带来的安全风险，并提出了权限隔离与物理隔离等实用的防范策略。

💡 主要观点

  1. AI Agent 的本质是为“失忆”的语言模型提供持续的身份设定与环境感知。 通过在每次对话前附加系统提示词（System Prompt）和历史记录，Agent 框架让模型在“文字接龙”时能维持一致的身份认知和任务目标，弥补了模型本身的无状态特性。
  2. 通过工具调用（Function Calling）与子代理机制实现复杂任务的分解与执行。 Agent 能根据需求生成特定指令调用本地工具或创建子代理（Sub-Agent），通过上下文工程将繁琐的执行细节屏蔽，让主代理专注于高层级的决策与规划。
  3. 采用上下文压缩与 RAG 技术在有限的窗口内模拟长期记忆能力。 针对 Token 限制，Agent 通过摘要提取、日志裁剪以及基于向量检索的 RAG 技术，确保关键信息能常驻上下文，同时实现对海量历史数据的精准回溯。
  4. 心跳机制与任务排程系统是实现 AI Agent 从“被动响应”转向“主动执行”的关键。 引入定时触发的固定指令（心跳）和 Cronjob，使 Agent 能够像人类员工一样定时检查进度、等待异步任务结果并自主推进目标，而非仅仅等待用户提问。
  5. AI Agent 的高度自主性带来了严峻的安全挑战，需通过隔离环境进行管控。 由于 Agent 具备执行命令行指令的能力，提示词注入或指令误解可能导致系统性灾难。建议采用权限隔离、物理隔离及人工流程审计来降低失控风险。

💬 文章金句

  • 语言模型的本质仅为「文字接龙」，而 AI Agent 则是通过一系列工程化手段，赋予了模型身份认知、长期运作与物理世界交互的能力。
  • 你可以将语言模型想象成一个关在黑盒子里的失忆者，它唯一知道的就是从小缝里递进来的未完成句子。
  • AI Agent 每次对话都在重复这个阅读历史记录的过程，从而让你感觉它是一个拥有连贯记忆的个人助理。
  • 为了让它成长，我们应该为其提供一个安全的执行环境，而不是彻底禁用它。
  • 不要只看 AI 的最终执行结果，应当定期检查它在执行过程中具体调用了哪些工具、做出了哪些决策。
