Boris Cherny：我们如何打造 Claude Code

2/17/2026, 3:00:42 PM

📌 一句话摘要

Claude Code 创始人 Boris Cherny 探讨了该工具在 Anthropic 的演进过程，强调了“为未来构建”的理念、多智能体编排，以及 AI 原生工程中 150% 的激进生产力提升。

📝 详细摘要

在这期 Y Combinator 播客中，Boris Cherny 揭秘了 Anthropic 基于终端的 AI 助手 Claude Code 背后的工程哲学和开发历程。他解释说，该工具的构建原则是“不为今天的模型构建，而是为六个月后的模型构建”，从而避免了随着模型改进而过时的过度“脚手架”开发。讨论重点介绍了向多智能体系统的转变——主智能体（Mama Claude）递归地调用子智能体来解决复杂任务，如调试内存泄漏或自动化 PR 工作流。Cherny 分享了令人震惊的数据：Anthropic 的开发者生产力提高了 150%，Cherny 本人现在已经不再手动编写任何代码。文章还涵盖了终端作为高杠杆接口的战略重要性、“ClaudeMD”在管理持久上下文中的作用，以及 AI 安全的更广泛愿景和软件工程师向高层级“构建者”的转型。

💡 主要观点

  1. 为未来模型的能力而构建，而非针对当前的局限性进行优化。 Cherny 主张开发者应该瞄准模型在六个月后能达到的“前沿”水平。这可以防止产品在模型更新时因自定义“脚手架”和复杂的提示词工程变得多余而过时。
  2. 多智能体“Mama Claude”架构实现了涌现的问题解决能力。 通过允许主智能体递归地生成具有新鲜上下文窗口的专用子智能体，Claude Code 可以处理复杂的并行任务，如同时进行日志分析和代码路径追踪，而单个上下文窗口可能难以处理这些任务。
  3. AI 原生工作流使 Anthropic 的工程生产力提升了 150%。 Claude Code 的集成从根本上改变了内部开发，工程师提交的 PR 增加了 70%，包括 Cherny 在内的一些人已完全从手动编码转向高层级的系统编排和审查。
  4. 保持精简的“ClaudeMD”以提供核心上下文，避免过度设计指令。 Cherny 建议使用简短、迭代的 ClaudeMD 文件，而不是庞大、静态的指令文件。随着模型的改进，它们需要的明确指令越来越少，通过“删除并重启”文件通常会发现模型已经突破了之前的限制。
  5. “软件工程师”的角色正在演变为高层级的“构建者”。 随着 AI 解决了编程的基础工作，工程师、设计师和产品经理之间的界限变得模糊。现在的成功取决于“初心”、科学思维以及编排 AI 智能体的能力，而非对特定语法的深度掌握。

💬 文章金句

  • 我们不为今天的模型构建；我们为六个月后的模型构建。
  • 自从 Opus 4.5 发布以来，我已经卸载了 IDE，不再亲手编写任何一行代码。
  • 永远不要赌模型赢不了。每当我们把工程时间花在脚手架上，下一次模型发布通常就会让它过时。
  • “软件工程师”这个头衔可能会消失……现在我们都只是构建者或产品经理。
  • 终端本应是起点，但我没想到它会成为终点。
