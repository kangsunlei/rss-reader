YC 最新判断：Harness 比模型更重要

9/20/2026, 11:00:00 AM

📌 一句话摘要

AI 竞争的胜负手正从模型能力转向 Harness（运行框架），Harness 通过优化提示词、工具调用、记忆管理及权限运维，能显著提升模型表现并弥补模型间的能力差距。

📝 详细摘要

本文基于 YC 的最新分享，深入探讨了 AI Harness（模型运行框架）的重要性。作者指出，模型决定能力上限，而 Harness 决定了能否触达上限。通过对 ARC-AGI-3 测试成绩对比、Prime Agent 的信息分层设计、OpenJarvis 的本地化优化实验以及 YC 内部的 QM 系统分析，文章论证了 Harness 在提升 Agent 表现、弥补小模型与大模型差距、以及解决企业级规模化运维与权限管理方面的核心价值。Harness 与模型的边界正在模糊，未来的竞争将聚焦于如何更好地组织、管理和迭代模型之外的运行体系。

💡 主要观点

  1. Harness 是模型能力的放大器 模型决定了智能的上限，而 Harness 通过管理系统提示词、上下文组织、工具调用、记忆管理及子 Agent 分工，决定了模型在实际任务中的表现。ARC-AGI-3 的测试证明，同样的模型在不同 Harness 下得分可差出 35.9 个百分点。
  2. Harness 与模型的边界正在融合 优化的路径正从单纯的提示词工程转向 Harness 代码优化，并进一步通过 Agent 运行产生的经验数据，实现对模型权重的持续学习，使两者形成闭环。
  3. 非硬编码设计是长周期任务的关键 通过“信息分层”设计（将信息分布在上下文、REPL 编程环境和外部存储中），Harness 可以为 Agent 提供连续的状态保持能力，使其在面对复杂、长周期的任务时不会因流程写死而失效。
  4. Harness 可以弥补模型间的性能差距 通过系统层面的优化，本地小模型可以显著追回与云端大模型之间的能力损失。OpenJarvis 的实验显示，优化后的本地方案在性能损失追回上表现出色，且运行成本极低。
  5. 企业级场景下 Harness 的重心转向运维与权限 当 Agent 进入企业环境，Harness 的角色演变为负责 Agent 的规模化部署、状态集中管理（如 YC 的 QM 系统）以及严格的权限边界控制，以解决“主角综合征”和信息泄露风险。

💬 文章金句

  • 模型决定上限，Harness 决定你能不能摸到这个上限。
  • AI 竞争的胜负手，正在从"谁的模型更强"，转向"谁能把模型更好地组织起来"。
  • 模型决定你能走多快，Harness 决定你能不能一直走下去、走多远。
