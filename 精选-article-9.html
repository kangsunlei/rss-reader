为什么大模型的缓存命中率能到 90%？

7/3/2026, 11:19:00 AM

📌 一句话摘要

本文从 KV Cache 原理出发，分析 Prefix Caching 技术方向与主流模型落地实践，解释 agent 式调用导致缓存命中率常达 90% 的必然性，并给出反直觉提醒。

📝 详细摘要

文章以「Model A/B/C/D」模糊化处理主流商用模型，围绕大模型推理中缓存命中率为何常驻 90% 这一观察，系统梳理了 KV Cache 原理、Prefix Caching 的跨请求复用机制、当前四大技术方向（PagedAttention、APC/RadixAttention、位置无关缓存），并结合 GPT、Claude、Gemini、DeepSeek 等模型的定价与 TTL 策略说明落地细节。作者提出简化模型 (T−1)/(T+1) 估算命中率，指出 agent 式多轮对话「只追加不插改」的特性是命中率高的主因，同时警示高命中率不等于绝对省钱——命中读虽便宜但绝对输入量也被撑大，真正的优化杠杆在低命中流量上。文章引用了 SOSP、MLSys、EuroSys 等顶会论文和官方文档，技术分析与工程实践结合紧密。

💡 主要观点

  1. KV Cache 是 Transformer 自回归生成的地基，将每步计算量从平方级降到线性。 历史 token 的 Key/Value 一旦算出不再变化，缓存后新 token 只需计算自身 Query 及与已缓存 KV 的注意力，避免重复计算整个序列。
  2. Prefix Caching 实现跨请求复用，但要求前缀逐字完全一致，不支持插入或修改。 位置编码和因果注意力使某个 token 的 K/V 依赖其之前的所有内容，前缀中任何变更都会导致后续缓存集体失效，只能追加。
  3. 当前技术方向从纯前缀缓存向位置无关缓存演进，以突破逐字前缀约束。 PagedAttention 按页管理 KV 减少碎片，APC/RadixAttention 实现高效前缀匹配，Prompt Cache、CacheBlend、EPIC 则尝试复用非前缀位置或任意片段。
  4. agent 式多轮对话天然适配前缀缓存，随着轮数增加命中率快速趋近 90% 以上。 每一轮请求将完整历史原封不动重发并末尾追加新内容，前面绝大部分前缀缓存命中；简化模型显示 20 轮命中率即达 90.5%。
  5. 高命中率是「每轮重发大上下文」的副产物，不代表绝对成本最优。 命中读虽有折扣，但绝对输入量被重发模式撑大；真正的成本优化往往在导致低命中率的少数流量上，而非已高命中的主力模型。

💬 文章金句

  • 命中率 90% 是好事，说明缓存机制在替用户省钱、降延迟；但真要压成本，杠杆往往在那 掉到 50% 的少数流量上
  • 把缓存当成一种「奖励只追加、惩罚乱插改」的契约——顺着它的脾气用，命中率自然就上去了
  • 高命中率 ≠ 一定省钱、一定高效
