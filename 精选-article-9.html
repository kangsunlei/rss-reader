Personal Agent 怎么从尝鲜变成常用？｜对谈千问蒋冠军

11/5/2026, 3:14:53 AM

📌 一句话摘要

千问算法负责人蒋冠军拆解 Personal Agent 落地的三个支点——模型思考与工具调用、按因果关系组织的分层记忆、生态工具链，并给出用 Skill 约束与成本优化换取留存的具体做法。

📝 详细摘要

千问事业部 AI 算法负责人蒋冠军与徐文浩、Mars 对谈 Personal Agent 的产品与工程条件。他复盘千问从 2023 年 11 月提出「能聊天会办事」的思路：模型先具备思考与自我鉴别能力、代码与工具调用变强，单点能力被串联成任务，再加上围绕模型生长的工具生态，才构成 personal agent 的三要素——模型、个性化数据与记忆、生态工具体系。他用代码场景作对照：代码库本身就是完整上下文、工具只需编辑器与 bash，所以 coding agent 效果好；生活场景的上下文与生态则要额外补齐。 在可靠性上，他主张模型必然出错，靠 Skill 约定接口行为、在系统框架层做强约束做双保险，涉及订单、交易、数据修改的关键操作必须由用户确认，agent 以助理而非本人身份对外沟通；航空公司延误险最终退回 70 元现金即为案例。记忆上，千问不做复杂知识图谱，仍以纯文本存储，但用客观事件的因果关系定义 schema，分层并处理时效，在事实之上做抽象，并从产品功能反向推导该记什么。他区分上限与下限：尝鲜型产品探索上限但留存低，能长期服务的产品下限能力更强；过去三个月单任务平均 token 用量增至 1.6 倍。成本靠模型路由、Skill 分层、轨迹固化、量化、大小模型切换与记忆压缩，使上下文规模降低约 40%；后训练围绕 30 多个行业、8000 多项原子能力保证覆盖率与稳定性。

💡 主要观点

  1. Personal Agent 的能力分水岭是「模型能思考 + 代码与工具调用」，生态工具成熟是第二步。 模型具备思考能力后才能判断自己的路径规划与工具调用是否合理，把单点功能串成任务；代码能力不只是写代码，更是调用工具、规划执行流程的载体。第二步是整个市场围绕模型能力建设可调用工具与服务，信息类 agent 因此先跑出来，personal agent 才具备起点。
  2. 模型必然出错，靠 Skill 与系统框架兜底，而不是把任务全交给模型。 千问在 Skill 体系里定义接口会产生什么行为、什么情况下必须与用户交互，并在系统框架层做强约束做双保险；涉及订单、交易、个人数据修改的操作必须由用户确认。对外以「助理」而非「本人」身份行动，责任与边界更清晰。航空公司延误险案例中，agent 拒绝代金券、坚持退现金，最终退回 70 元到用户账户。
  3. 记忆的难点不是存多少，而是用因果关系定义 schema、再分层与处理时效。 千问仍以纯文本存储记忆，但先分析客观事件之间的因果关联，据此判断记什么、记到什么粒度；再分层区分核心与长期短期、处理时效，并在事实之上做抽象（如从「孩子没工作、养老」抽象出「家庭焦虑」）。同时从产品功能反向推导该存哪些事实。他举看《金刚经》后被扯到佛教、聊烤肉也扯回佛教，说明召回失衡要么过多要么过少的取舍。
  4. 上限吸引尝鲜，下限决定常用；留存靠单点任务的稳定性与完成率。 以 OpenClaw、Muse 一类产品为例，它们探索的是 AI 产品上限，用户尝鲜后因任务完成度不高而流失；真正提供服务的产品下限能力高、稳定。千问侧用户在财经、教育、医疗等找到合适场景后会持续使用，过去三个月单任务平均 token 消耗增至 1.6 倍，说明用户任务在变复杂，也带来「花 20 块抢 10 块券」的成本倒挂问题。
  5. 成本与能力靠工程手段叠加：Skill 分层、轨迹固化、模型路由与针对性后训练。 Skill 平铺还是分层、相似工具如何取舍，直接影响调用精度与 token 消耗；常见轨迹固化成 Skill 可减少模型重复推理。配合模型路由、量化、大小模型切换与记忆压缩，上下文规模下降约 40%。后训练围绕 30 多个行业、8000 多项原子能力做覆盖与稳定性对齐，并做训推一体化以贴合线上环境。

💬 文章金句

  • Agent 其实它就是把这样的单点的功能，就是我发现单点功能不好，我就再重新去做一个规划，重新再去做一个判断。我把几步串联起来，它其实就变成一个完成任务的 agent 了。
  • 但是其实真正在市场上提供服务的产品，它其实是下限能力很高。
  • 我们不是说我们看了金刚经我们就去记金刚经。而是说我站在客观世界的整个事，站在世界知识的整个因果关联关系里面，我先去分析它的因果关系在哪里
  • 因为如果说大家对于 personal agent 的功能都实现的比较好，我觉得 personal agent 一定是个越用越好的一个产品。
