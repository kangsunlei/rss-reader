给 Agent 做“CT”：大规模 Agent 的可观测与质量保障体系

8/20/2026, 8:26:00 AM

📌 一句话摘要

火山引擎技术负责人钱世俊在 QCon 2026 分享如何构建统一观测基座，实现大规模 Agent 的白盒化透视、根因定界与观测-评测-优化的工程化闭环。

📝 详细摘要

文章系统记录了火山引擎应用观测技术负责人钱世俊在 QCon 2026 北京站的演讲实录。针对 Agent 时代带来的“黑盒”困境（链路断、语义断、因果断），作者详细阐述了基于 OpenTelemetry 标准与自研 OneAgent 构建统一观测基座的五大支柱（门户、集成、加工、看板、告警），并深入介绍了 AI 通用观测与 AgentKit 深度集成的实践，包括精细时延拆解、Token 消耗监控、会话诊断、记忆与 RAG 监控等白盒化能力。进一步，文章揭示了从观测数据回流构建评测集、离线/在线评测体系、多实验对比及人工标注协同的工程化闭环路径。最后以 OpenClaw 落地为例，展示了多层 SLI 体系、自研插件采集及三个典型排障案例（下游 API 慢、Token 爆炸、模型幻觉），实现 MTTR 降低 80% 以上。展望未来，旨在从“全面体检”迈向“自动驾驶”，实现智能根因定位、主动治愈与开放生态。

💡 主要观点

  1. Agent 观测面临链路、语义、因果三大断层，传统监控手段失效。 Agent 非确定性编排导致四层架构（业务、框架、推理、基建）观测数据割裂，无法关联底层 GPU 波动与上层推理异常，需构建统一观测基座打通全栈数据。
  2. 基于 OpenTelemetry 与自研 OneAgent 构建统一观测基座，解决高性能采集与数据融合。 拥抱 OTel 标准实现跨栈兼容，自研 OneAgent 通过自适应并发、预排序增强、内存优化等手段，在 200K QPS 下吞吐量超开源 Collector 一倍，负载降低 50%+，支撑大规模数据采集。
  3. 白盒化链路诊断与多维 SLI 体系实现从‘可见’到‘可解释’的跨越。 提供会话级 Trace 聚合、规划/工具/模型/记忆多维拓扑分析，配合六层任务型 SLI（接入、会话、调度、执行、工具、定时任务），精准定界慢在哪、错在哪、成本消耗在哪。
  4. 观测-评测-优化闭环将被动排障转为数据驱动持续进化。 高价值 Trace 回流形成评测集，支持离线回归与在线监控，引入 Token 效率、规划轨迹等 Agent 专有指标，结合自动化评测与人工标注协同，指导 Prompt、检索、路由策略迭代。
  5. OpenClaw 实战验证体系有效性，MTTR 降低 80%+，总结通用修复模式。 通过自研插件深度 Hook 运行时，结合 SLI 大盘与告警，快速定位下游 API 超时（加超时重试降级）、Token 爆炸（Prompt 终止指令+迭代围栏+预算早停）、长对话幻觉（查询重写+摘要记忆+轨迹评测）三类典型顽疾。

💬 文章金句

  • 我们要做的，就是为 Agent 构建一套类似的'CT 系统'，让研发者能够看清其内部一步步的判断与决策轨迹。
  • 在 Agent 场景中，由于内部编排响应的不确定性，一旦出现逻辑偏差，可能在极短时间内触发巨量的大模型调用，导致 Token 消耗呈指数级激增。
  • 最终我们实现了三个核心效果：可见——能够清晰看到大模型过程中每一步是如何具体执行的；可解释——通过白盒化的诊断与因果边界定界定位；可行动——通过告警联动、数据回流与优化闭环，能够持续对 Agent 进行迭代更新优化。
  • 我们希望能从当前全面的 Agent 体检，迈向某种程度的自动驾驶。
