[开源] LLM-Bridge：把 Claude Code / Codex / Antigravity 三个订阅统一成一个 OpenAI 兼容 API

7/6/2026, 8:12:53 AM

📌 一句话摘要

LLM-Bridge 是一个开源本地网关，将 Claude、Codex 和 Antigravity 三个 CLI 封装成统一的 OpenAI 兼容 API，并提供聊天 UI，解决多订阅额度分散与交互不一致的问题。

📝 详细摘要

本文介绍了作者开发的开源工具 LLM-Bridge，旨在统一三个主流 AI CLI（Claude、Codex、Antigravity）的订阅额度与交互方式。核心功能包括：一个 base_url 通吃三家模型，鉴权直接复用各 CLI 登录态（不触碰 OAuth token），模型列表动态获取，自带多会话流式 UI。文章详细阐述了几个实现亮点：通过 `--ignore-user-config` 隔离 Codex 的全局配置以大幅降低 token 消耗与延迟，透传 `reasoning_effort` 字段以节省深度推理额度，以及修复子进程流式中的僵尸进程、管道死锁、截断误报等坑。作者坦诚列出了限制：仅聊天（不支持 tool calling/多模态），延迟比直连高 3-8 秒，单用户定位，以及使用 Claude Agent SDK credit 的合规提示。项目使用 Python+FastAPI 后端和纯 vanilla JS 前端，已在 GitHub 以 MIT 协议开源。

💡 主要观点

  1. LLM-Bridge 通过复用各 CLI 的登录态实现鉴权，不存储或重放 OAuth token，避免被封禁。 2025 年初 Anthropic 封杀第三方 token 复用的背景下，作者设计上只走官方 CLI harness（claude-agent-sdk / codex exec / agy -p），从架构上规避被封风险。
  2. 隔离 Codex 全局配置后，单次请求的输入 token 从 2.8 万降至 1 万，延迟从 37 秒降至 7 秒。 作者实测一句 'hello world' 若不隔离，全局安装的技能/插件会被注入每个请求，造成巨大浪费；通过 `--ignore-user-config` 有效隔离。
  3. 子进程流式处理中踩过的坑（僵尸进程、管道死锁、截断误报）都有对应修复。 这些修复确保了长时间对话的稳定性，对于实现类似网关的开发者有直接参考价值。

💬 文章金句

  • 不碰、不提取、不重放任何 OAuth token
  • 不加的话你全局装的技能/插件会被灌进每个请求——我实测一句 'hello world' 烧了 2.8 万 input token 、等 37 秒；隔离后 1 万 token 、7 秒
  • 子进程流式的坑都踩过了：客户端断连的僵尸进程、stderr 管道写满死锁、截断误报 finish_reason=stop，修复都在提交历史里
