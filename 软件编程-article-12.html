微软宣布 AKS 自动版正式发布

10/2/2025, 9:00:00 AM

📌 一句话摘要

微软发布 AKS 自动版，这是一种完全托管的 Kubernetes 服务，旨在通过自动化、智能默认配置和集成安全特性来降低运营开销。

📝 详细摘要

微软宣布 Azure Kubernetes Service (AKS) 自动版正式发布，这是一种完全托管的 Kubernetes 产品，旨在显著减少 “Kubernetes 运维成本（传统上配置、保护和维护生产级集群所需的大量时间和专业知识）”。此服务通过智能默认配置提供可直接用于生产环境的集群，使用已建立的最佳实践自动执行节点设置、网络配置和服务集成，因此无需前期进行架构决策。它具有使用水平 Pod 自动扩缩器 (HPA)、垂直 Pod 自动扩缩器 (VPA) 和 KEDA 进行事件驱动扩展的 Pod 和节点动态缩放功能，所有这些功能默认启用，并引入了 Karpenter 用于动态节点配置。安全性和可靠性从创建时就已嵌入，包括微软 Entra ID 集成、基于角色的访问控制、自动安全补丁和预配置的 Azure 监视器。AKS 自动版保持完全的 Kubernetes API 兼容性和 CNCF 一致性，从而可以与现有工具和 CI / CD 流水线无缝集成。它面向资源受限的初创公司和企业平台团队，与 AWS EKS 自动模式和 Google GKE Autopilot 等竞争对手相比，它在自动化和灵活性之间取得了平衡。

💡 主要观点

  1. AKS 自动版通过全面的自动化显著减少了 Kubernetes 的运营开销。 该服务可自动执行集群设置、动态缩放（通过 HPA、VPA、KEDA、Karpenter 进行 Pod / 节点缩放）、控制平面维护、补丁更新和升级，从而使开发团队摆脱日常运营任务。
  2. 它默认从集群创建时就嵌入了生产就绪的安全性和可靠性功能。 包括微软 Entra ID 集成、RBAC、网络策略、自动节点安全补丁、预配置的 Azure 监视器、部署保护措施和自动节点修复，以确保安全可靠的工作负载。
  3. AKS 自动版在固有的默认配置与完全的 Kubernetes 灵活性和开源对齐之间取得了平衡。 在提供智能默认配置的同时，它保留了完全的 Kubernetes API 兼容性、CNCF 一致性，并支持现有工具，并以 KEDA 和 Karpenter 等开源项目为基础。

💬 文章金句

  • AKS 自动版通过智能默认设置和自动化操作脱颖而出。它能够提供可直接用于生产环境的集群。
  • 自动化贯穿整个集群生命周期。AKS 自动版使用水平 Pod 自动扩缩器 (HPA)、垂直 Pod 自动扩缩器 (VPA) 和 KEDA 进行事件驱动扩展来实现 Pod 和节点的动态缩放，所有这些功能默认启用。
  • 每个 AKS 自动版集群都包括微软 Entra ID 集成，用于身份验证、基于角色的访问控制和网络策略，而无需额外设置。
  • 尽管采用了固有的方法，但 AKS 自动版仍保持完全的 Kubernetes API 兼容性和 CNCF 一致性。
  • 虽然这三种服务都旨在减轻 Kubernetes 的运营负担，但它们反映了不同的理念：Google GKE Autopilot 强调基于消费的定价和更严格的防护措施，AWS EKS 自动模式在自动化与 AWS 生态系统集成之间取得平衡，而 AKS 自动版则侧重于智能默认配置，同时最大限度地保持 Kubernetes 的灵活性。
