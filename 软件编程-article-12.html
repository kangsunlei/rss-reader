开源 | 我将用最优雅的方式在 Vue 中渲染 AI 应用返回的 Markdown 数据

9/28/2025, 1:01:00 AM

📌 一句话摘要

文章详细阐述了如何在 Vue 应用中优雅地渲染 AI 返回的 Markdown 数据，通过解析 Markdown 为树状结构并结合 Vue 插槽实现高度可定制和响应式的组件化渲染。

📝 详细摘要

本文解决了 AI 应用返回的 Markdown 数据在 Vue 中渲染时，使用`v-html`导致的响应式缺失和无法使用 Vue 组件的问题。作者提出了一种优雅的解决方案：首先，将 Markdown 文本解析为扁平的`markdown-it tokens`，进而转换为与 Vue vDOM 结构对应的嵌套树状结构。然后，通过一个自定义渲染器`VkRenderer`，利用 Vue 的插槽机制，允许开发者根据解析出的`templateType`字段，为不同的 Markdown 元素（如表格、图表）提供自定义的 Vue 组件进行渲染。这种策略不仅解决了`v-html`的局限性，还实现了高度的交互性、第三方库集成（如 ECharts、Mermaid）和保持 Vue 响应式的能力。文章还介绍了作者开发的开源库`vunk-markdown`，提供了具体的实现思路和使用示例。

💡 主要观点

  1. 传统`v-html`渲染 Markdown 存在性能和功能限制 `v-html`仅进行全量 HTML 字符串渲染，无法利用 Vue 的 diff 算法优化，也失去了使用 Vue 组件和保持响应式的能力，不适用于复杂交互场景。
  2. 通过 Markdown 解析与树状结构构建实现组件化渲染 将 Markdown 文本解析为`markdown-it tokens`，并进一步构建成嵌套树状结构，为后续的 Vue 组件化渲染奠定基础，使其与 vDOM 结构对应。
  3. 利用 Vue 插槽机制实现高度可定制的策略渲染 自定义渲染器结合 Vue 插槽，允许开发者根据 Markdown 元素的类型（`templateType`）替换默认渲染逻辑，集成第三方库，实现动态更新和交互性。

💬 文章金句

  • v-html 是一个全量渲染的过程， 并且他仅仅渲染 html 字符串。
  • 这意味着，你不再享有 Vue DOM 更新时的 diff 算法优化， 同时也失去了使用 Vue 组件的权力。
  • 无论你使用何种 Markdown 工具 (markdown-it、marked、remark)， 要想在渲染之前提取数据， 必然绕不开对 markdown 原文本的解析。
  • 要想让 markdown 解析成 Vue 组件关键是构建嵌套树状结构， 与 vDOM 结构对应。
  • 解析 和 策略渲染 就是 vunk-markdown 的核心。
