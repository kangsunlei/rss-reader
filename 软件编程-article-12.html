在 Docker 沙箱中安全运行 OpenClaw

2/23/2026, 6:00:07 AM

📌 一句话摘要

本指南演示了如何使用 Docker Sandboxes 和 Docker Model Runner 在安全、隔离且具有成本效益的本地环境中运行 OpenClaw AI 编程智能体。

📝 详细摘要

本文介绍了 Docker Sandboxes，这是一种为 AI 工作负载提供微型虚拟机（micro VM）隔离的新原语，确保了强大的安全边界和受控的网络访问。文章详细说明了如何通过 Docker Model Runner 在本地完全运行开源 AI 编程智能体 OpenClaw，从而消除云端成本和 API 密钥泄露风险。针对 Node.js 处理代理环境变量等关键技术挑战，文中提供了一个自定义桥接脚本作为解决方案。最后，文章提供了关于构建、配置和共享自定义沙箱镜像的分步教程，以实现标准化的 AI 开发环境。

💡 主要观点

  1. Docker Sandboxes 利用微型虚拟机为 AI 智能体和敏感工作负载提供高级别隔离。 通过在具有可配置网络代理的隔离微型虚拟机中运行工作负载，Docker 确保 AI 智能体无法访问任意互联网主机或泄露敏感的主机信息，从而提供坚固的安全边界。
  2. 将 OpenClaw 与 Docker Model Runner 结合使用，可以实现完全私密且本地化的 AI 编程体验。 这种设置允许开发人员在自己的机器上本地运行 LLM，无需外部 API 密钥和云端订阅，同时在沙箱环境中保持完整的数据隐私。
  3. 为了克服 Node.js 在 HTTP 代理支持方面的局限性，需要一个自定义网络桥接。 由于 Node.js 原生不支持本地请求的标准代理环境变量，因此实现了一个小型桥接脚本，用于将流量从沙箱显式转发到主机的 Model Runner。
  4. 沙箱代理架构有助于为基于云的 AI 模型安全地注入凭据。 使用云端模型时，代理会自动将主机环境中的 API 密钥注入网络流，确保智能体永远无法直接访问原始密钥。
  5. 自定义沙箱环境可以保存为可重用的镜像，以确保开发团队之间的一致性。 “docker sandbox save” 命令允许开发人员将配置好的环境（包括 Node.js 和 OpenClaw 等特定工具）捕获到标准镜像中，并可以通过镜像仓库进行共享。

💬 文章金句

  • Docker Sandboxes 是 Docker 生态系统中的一个新原语，允许你在隔离的微型虚拟机中运行 AI 智能体或其他任何工作负载。
  • 无需 API 密钥，没有云端成本，完全私密。而且只需大约两条命令即可完成。
  • 网络代理还会方便地注入 API 密钥……这样智能体就完全无法访问它们，也就无法泄露它们。
  • 问题在于 OpenClaw 是基于 Node.js 的，而 Node.js 不遵循 HTTP_PROXY 环境变量。
  • 使用 Docker Model Runner，你可以获得一个完全本地的 AI 编程环境：没有云端依赖，没有 API 成本，且拥有完整的隐私保护。
