重磅！鸿蒙平台首个全跨端 APP ——腾讯视频 ovCompose 框架发布

6/13/2025, 9:36:00 AM

📌 一句话摘要

腾讯发布 ovCompose 和 KuiklyBase 框架，实现鸿蒙平台首个 Compose 全跨端 APP 并开源。

📝 详细摘要

文章详细介绍了腾讯视频团队基于 Compose Multiplatform 生态构建的 ovCompose 和 KuiklyBase 跨平台开发框架。针对 JetBrains Compose Multiplatform 对鸿蒙和 iOS 平台的限制，提出了鸿蒙 Kotlin Native 适配、高性能优化、iOS 多模态渲染等解决方案。ovCompose 已在腾讯视频鸿蒙版落地，KuiklyBase 基础能力已在腾讯多款 APP 应用。文章深入阐述了鸿蒙平台的 KN 适配策略、性能瓶颈分析及优化措施（内联、ThreadLocal、协程、调试）、鸿蒙绘制不同步解决办法，以及 iOS 端指令映射多模态渲染方案。最后对比了 ovCompose 与 KuiklyUI 两种跨端框架的差异，并公布了开源计划，旨在推动 Compose 跨端生态发展。

💡 主要观点

  1. ovCompose 和 KuiklyBase 实现鸿蒙 Compose 支持 框架弥补了原生 Compose Multiplatform 对鸿蒙平台的支持空白，并通过 Kotlin/Native 方案提升性能和三端一致性，满足鸿蒙全跨端需求。
  2. 攻克 Kotlin Native 在鸿蒙平台的性能挑战 通过针对性优化（LLVM 内联、硬件 ThreadLocal、协程异常处理、调试效率），显著提升 KN 在鸿蒙平台的运行效率，接近原生性能。
  3. 解决鸿蒙平台原生 UI 与 Compose 的混排和绘制同步问题 利用鸿蒙的 XComponent Texture 模式，将 Compose 内容绘制到 FBO 中，使其与 ArkUI 绘制节奏同步，解决混合渲染时的不同步割裂感。
  4. 解决 iOS 平台 Compose 与原生 UI 混排受限及渲染性能问题 采用基于 UIKit 的指令映射自研方案，实现 Compose 在 iOS 的多模态渲染，克服官方 Skia 方案混排能力弱、内存占用高的问题，并在复杂页面回迁中优化性能。
  5. 提供丰富的 KuiklyBase 基础组件和工具链 涵盖 Kotlin 异常堆栈还原、跨语言互调、资源管理、并发控制等，降低开发者在鸿蒙适配和跨平台开发中的门槛。
  6. 框架已在腾讯多款 APP 落地并开源 ovCompose 已在腾讯视频鸿蒙版全面落地，KuiklyBase 在 10+APP 应用，并已开源，为行业提供实际解决方案和参考。

💬 文章金句

  • ovCompose...旨在弥补 JetBrains Compose Multiplatform 不支持鸿蒙平台的遗憾与解决 iOS 平台原生 UI 混排受限的问题，便于业务构建全跨端 App。
  • Kotlin Multiplatform 还具备高性能，与原生交互更灵活等优点。因此腾讯视频选择了 Compose Multiplatform 作为全跨端 APP 的基础。
  • 由于在鸿蒙平台采取 Kotlin-Native 方案，解决了 Kotlin-JS 使用 TaskPool 时，Kotlin 语法无法约束跨线程访问的问题，保持了高度的三端一致性。
  • 经技术架构分析与处理，在 KDS 与 LLDB 上运用流程合并、复用、缓存、预加载潜在下一跳、局部调试的可容错优化等手段提高其通信和处理效率。
  • 目前 ovCompose 和 KuiklyBase 已开源，包含 5 个仓库，包含了。仓库 Group 地址为:github.com/Tencent-TDS
