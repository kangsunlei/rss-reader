📝 详细摘要

文章介绍了 GitHub 开发者 mycroftsnm（Armas）用 C 语言开发的五款运行在 UEFI 启动阶段的小游戏。这些游戏将电脑开机变成了一场挑战，玩家必须通过游戏才能成功启动系统，否则电脑会直接关机。文章详细讲解了 UEFI 的工作原理以及这些游戏如何利用 UEFI 的特殊权限在操作系统启动前运行并控制电源。作者指出，这些游戏更像是技术能力的展示，因为运行它们可能需要关闭或修改安全启动设置，存在一定的安全风险。该项目在 GitHub 和 Reddit 上引发了热烈讨论，网友们对其创意和实用性褒贬不一，但也激发了大量有趣的“脑洞”建议。整体而言，这篇文章展示了程序员独特的创造力以及对技术边界的探索精神。

💡 主要观点

  1. UEFI 游戏将电脑开机变为互动挑战，需通关方能启动系统。 开发者 Armas 创作了五款在 UEFI 启动阶段运行的游戏，用户必须通过这些游戏才能正常启动电脑，否则电脑会直接关机，为枯燥的开机过程增加了趣味性和挑战性。
  2. 游戏利用 UEFI 的特殊权限，在操作系统启动前运行并控制电源。 UEFI 作为电脑启动的第一程序，拥有比操作系统更高的权限，能够控制图形、键盘输入以及电源管理功能，使得这些游戏能在系统加载前实现交互和关机操作。
  3. UEFI 游戏更多是技术可能性的展示，存在安全启动兼容性问题。 由于需要关闭安全启动或手动注册密钥才能运行未签名的 UEFI 程序，这可能降低电脑安全性，因此该项目主要在于展现技术创意而非广泛实用性。
  4. 项目引发社区热议，展现程序员的独特创意与探索精神。 该项目在 GitHub 和 Reddit 上引起广泛讨论，支持者赞赏其创意和“趣味安全”，反对者担忧其实用性和潜在风险，但普遍认可其揭示了技术玩法的无限可能。

💬 文章金句

  • 他前后花了大约 10 个月，用 C 语言开发了五款运行在 UEFI 启动阶段的小游戏，直接把“开电脑”变成了一场必须通关的挑战。
  • 赢了，系统正常启动；输了，电脑有时“嘲讽”一句后当场关机。
  • UEFI 会先检查硬件是否正常，然后把控制权交给操作系统。而 UEFI 应用（包括这些游戏），就是能在这个“交接过程” 中运行的程序，它们拥有比操作系统更高的权限。
  • 关闭安全启动会降低电脑的安全性，可能让恶意软件有机可乘。所以从实用角度看，这套 UEFI 游戏更像是一次“技术可能性的展示”，而不是推荐所有人照着安装。
  • 在程序员眼里，连开机这件事，都还有无数种玩法。而有时候，这种“不为了什么，只是觉得好玩”的探索，本身就已经足够有价值了。
