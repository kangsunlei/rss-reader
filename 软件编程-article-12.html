将 Elasticsearch 升级到新的 AWS Java SDK

7/30/2025, 1:26:22 AM

📌 一句话摘要

Elasticsearch 成功迁移到 AWS Java SDK v2，原因是 v1 达到生命周期终点。为了最大限度地减少用户影响，Elasticsearch 实施了广泛的兼容性逻辑，并建议未来进行配置调整。

📝 详细摘要

本文详细介绍了 Elastic 将 Elasticsearch 的 AWS 集成从已弃用的 AWS Java SDK v1 升级到较新的 SDK v2 的关键过程，这是由 SDK v1 在 2025 年 12 月 31 日终止支持所驱动的。它透彻地解释了此次升级的必要性，以确保 Elasticsearch 用户的持续安全和支持。核心叙述强调了升级过程中遇到的工程挑战，特别是管理 SDK 版本之间的行为差异和调整测试方法。Elastic 的解决方案包括开发强大的兼容性层，并转向与 SDK 无关的端到端测试，旨在使大多数用户无感升级。文章最后建议用户进行潜在的、虽然很小的配置调整（例如显式设置 AWS 区域并确保 IMDSv2 支持），作为保持与未来 Elasticsearch 版本兼容性的最佳实践。

💡 主要观点

  1. Elastic 主动迁移到 AWS Java SDK v2，确保了 Elasticsearch 用户的安全性和稳定性。 尽管面临复杂性和潜在的用户可见变更，但 Elastic 通过从已弃用的 SDKv1 迁移，优先考虑了安全性和长期支持，从而确保了其用户的持续可靠性和补丁可用性。
  2. 广泛的兼容性逻辑和强大的测试最大限度地减少了 SDK 升级对大多数用户的影响。 Elastic 在构建兼容性处理逻辑和发展与 SDK 无关的测试方面投入了大量资金，从而使大多数用户无需立即进行配置更改即可升级到基于 SDKv2 的 Elasticsearch 版本。
  3. 建议用户采用新的 AWS 配置最佳实践，以实现未来的兼容性。 虽然通过启发式（即通过试错和经验规则）方法维护了初始向后兼容性，但显式配置诸如 AWS 区域和完整端点 URLs 之类的设置将防止潜在的问题，并确保未来 Elasticsearch 版本的长期稳定性。

💬 文章金句

  • 在 Elastic，我们有责任让我们的用户仅依赖于受支持的组件，因此我们不得不在此日期之前迁移到较新的 AWS SDK for Java v2。
  • 相反，我们找到了一条不同的路径，使我们能够在次要版本中迁移到 SDKv2，并引入兼容性逻辑来解决许多行为差异。
  • 我们期望大多数集群升级到 SDKv2 版本后，无需修改配置即可继续正常运行，这是因为我们添加到 Elasticsearch 中的兼容性机制可以支持用户完成此类升级。
  • 尽管如此，我们建议您为每个 S3 客户端配置 s3.client.${CLIENT_NAME}.region 设置，而不是依赖启发式方法。
  • 在升级任何生产集群之前，请务必升级您的测试集群并验证它们是否正常工作。
