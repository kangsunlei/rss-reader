从埋点需求到规则资产：Hermes Agent 重构得物数仓工作流

6/17/2026, 10:30:00 AM

📌 一句话摘要

得物技术团队分享如何基于 Hermes Agent 框架，将埋点需求承接从一次对话转化为可回放、可确认、可复用的工程化工作流，核心在于规则资产化、结构化工具接口与人工确认点。

📝 详细摘要

本文详细介绍了得物数据团队如何利用 Hermes Agent 框架重构埋点与指标需求的工作流。核心思路不是让 AI 直接生成最终结论，而是将一次需求拆解为工作区、看板、规则包和结构化工具接口四个工程构件。文章重点阐述了单 Agent 编排 + 多能力模块的选型逻辑，以及如何通过规则资产化、协作可见、上下文与事实源管理、结构化工具接口等能力底座，将分散的信息拼装、历史口径对齐、下游影响识别和发布确认等环节固化。最后强调了风险治理的三道门（事实源、预演、责任），以及下一步通过连续样本验证链路效果的规划。

💡 主要观点

  1. AI 在数仓流程中的边界是整理到可判断，而非直接给出结论。 Hermes Agent 负责组织材料、历史、候选方案和预演证据，人负责业务语义、口径判断和生产放行，避免模型给出看似完整但缺乏依据的方案。
  2. 采用单 Agent 编排 + 多能力模块，而非多智能体协作。 单 Agent 保持统一上下文，能力模块固化输入、动作边界、输出产物和停顿条件，确保流程稳定可复现，不会因提示词变化而漂移。
  3. 规则资产化是沉淀团队经验的关键。 将历史口径、检查清单等隐性知识写成可执行的规则包，通过 Hermes Agent 的长期记忆和技能沉淀机制，实现专家经验的资产化复用。
  4. 靠近生产系统的动作必须走结构化工具接口。 将查询、绑定、发布等操作包装成参数明确、返回结构化、过程可审计的接口，先预演、再确认、最后留痕，避免依赖页面识别和临场点击。
  5. 风险治理通过三道门实现：事实源、预演、责任。 任何一道门缺证据，Agent 只能停在候选或待确认状态，不能继续推进生产写入，确保人的精力放在真正的判断点上。

💬 文章金句

  • Hermes Agent 的边界是把问题整理到足够可判断。
  • Hermes Agent 真正承担的是判断前的工程化准备。
  • 规则资产化：先决定什么值得记住。
  • 越靠近生产，越要把资产和治理连起来：规则给出判断边界，命令提供验证证据，看板承接人工确认。
  • 治理的目标不是让数据承接方把系统做过的事再手工复查，而是让系统在关键位置停下来，把证据、预演结果和责任人摆到台面上。
