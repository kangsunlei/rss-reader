工程卓越始于前沿探索

9/6/2025, 9:02:10 AM

📌 一句话摘要

本文提倡工程团队在工具的“Edge 版本”（未发布的版本）上运行生产代码，以促进与开源的共同创造，提高质量并提高团队积极性。

📝 详细摘要

David Heinemeier Hansson 认为，真正的工程卓越源于团队积极参与并塑造他们所依赖的工具，特别是通过在生产环境中运行框架和库的未发布的“Edge”版本。虽然最初看起来有风险，但这种做法（例如 Shopify 和 GitHub 在其 Beta 版本发布前近一年运行 Rails 8.1）使团队能够主动识别和修复 Bug，从而成为开源软件的实时共同创造者，而不仅仅是消费者。这种方法不仅提高了底层工具的质量和稳定性，而且还极大地提高了程序员的积极性，加深了他们的理解，并在专家社区内建立了联系。DHH 鼓励更多公司采用这种“创新精神”，以提高其工程能力和实力，无论具体的技术栈如何。

💡 主要观点

  1. 在前沿版本上运行生产代码，培养积极的共创工程文化 通过积极使用未发布的版本，团队直接为工具开发做出贡献，尽早识别和解决 Bug，从而将他们从消费者转变为开源软件的共同创造者。
  2. 早期采用 Edge 版本可以显著提高依赖工具的质量和稳定性。 像 Shopify 和 GitHub 这样的公司已经证明，严格的测试和勤奋的程序员可以在关键 Bug 影响广泛发布之前发现它们，从而形成更强大的框架。
  3. 直接参与工具开发可以提高程序员的积极性和专业知识。 当工程师可以立即影响和改进他们的日常工具时，他们会变得更投入，学得更深入，并在更广泛的社区中与专家建立有价值的联系。

💬 文章金句

  • 最好的工程团队会掌控他们的工具。他们帮助开发他们所依赖的框架和库，他们通过运行前沿版本的生产代码来实现这一点。
  • 如果你想要没有 Bug 的框架和库，你必须为此努力，但如果你这样做了，你承担责任的回报是提高工程卓越。
  • 这使得他们以及其他少数有同样创新精神的人能够培养一种真正卓越的工程文化。这种文化不仅仅是开源软件的消费者，而是实时的共同创造者。
  • 当你的程序员能够直接影响他们正在使用的工具时，他们更有可能这样做，因此他们会更深入，学得更多，并在其他地方与处于相同情况的专家建立联系。
  • 更多的公司可以这样做。更多的公司*应该*这样做。
