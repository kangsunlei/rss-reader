OpenTofu 1.10 发布，支持 OCI 仓库和面向 AI 基础设施即代码 的 MCP 服务器

7/11/2025, 12:00:00 AM

📌 一句话摘要

OpenTofu 1.10 引入了 OCI 仓库、原生 S3 状态锁定和对 AI 基础设施即代码 的支持。

📝 详细摘要

OpenTofu 1.10 是一个开源 IaC 项目，本次发布是其最全面的更新，引入了对提供商和模块分发的原生 OCI 仓库支持，这对于高安全性和气隙环境至关重要，也是与 Terraform 的一个重要区别。它还具有原生的 S3 状态锁定，无需 DynamoDB 和外部密钥提供商集成，以增强安全性和合规性。新的规划选项、全局提供商缓存锁定和 OpenTelemetry 跟踪等功能，均旨在提高开发者生产力。一个值得注意的补充是 MCP 服务器，旨在促进 AI 编码助手生成准确、最佳实践的资源配置，用于 AI 基础设施即代码，并辅以 VS Code 扩展和语言服务器协议支持。此版本巩固了 OpenTofu 作为强大、社区驱动的替代方案的地位，尤其受到独立开发者和小型团队的青睐。

💡 主要观点

  1. OpenTofu 1.10 增加了 OCI 仓库 支持。 支持通过 OCI 仓库进行分发，这对于气隙/高安全性环境至关重要，是与 Terraform 的一个关键区别。
  2. 增强状态管理和安全性。 原生 S3 状态锁定移除了 DynamoDB。外部密钥提供商为合规性提供灵活的状态加密。
  3. 用于 AI IaC 和 DX 的 MCP 服务器和工具。 MCP 服务器帮助 AI 助手生成准确的配置。VS Code 和 LSP 支持增强了开发者体验。
  4. 作为社区驱动的替代方案的战略定位。 OpenTofu 将自己定位为 Terraform 的完全开源、供应商中立的替代品，特别适合独立开发者和小型团队，同时保持与现有 Terraform 配置的兼容性。

💬 文章金句

  • OpenTofu 1.10 中最突出的功能是对开放容器计划 (OCI) 仓库的原生支持。
  • 此功能与 HashiCorp 的 Terraform 不同，后者目前未为模块和提供商提供等效的 OCI 仓库集成。
  • OpenTofu 1.10.0 引入了原生的 S3 状态锁定，无需 AWS DynamoDB，解决了基于 Terraform 的工作流程中长期存在的复杂性。
  • 为了致力于改善开发者体验，OpenTofu 还发布了 MCP 服务器。这可以直接访问提供商和模块文档。因此 AI 编码助手可以生成准确的最佳实践资源配置。
  • 1.10 版本是该项目开始以来最显着的功能差异。
