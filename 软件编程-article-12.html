Manus 高溢价收购背后，是 Agent 开发落地困境

1/9/2026, 5:31:00 AM

📌 一句话摘要

Meta 高溢价收购 Manus 凸显 Agent 开发落地困境，阿里云百炼升级“1+2+N”体系，通过组件化、新开发范式及模型服务工程化，旨在为企业提供工业级 Agent 解决方案，推动 Agent 应用从概念走向生产。

📝 详细摘要

Meta 以 20 亿美元收购 Manus 的事件，揭示了当前 Agent 开发面临的严峻落地挑战，尤其在 ToC 和 ToB 场景中对任务连通性、容错、安全合规、数据接入、评估优化等工程能力要求极高。文章指出，约 95%生成式 AI 试点项目难以进入生产环境，症结在于缺乏成熟的开发范式和工程化解决方案。对此，阿里云百炼将“1+2+N”体系（稳底座+定范式+理杂活）进行了升级。 “N”代表通用高手组件，如多模态 RAG、数据连接器、Agent Identity 权限管理、Sandbox 沙盒安全、Trace 与 Evaluate 可观测评估等，旨在解决数据管理、安全合规、持续优化等落地难题，大幅缩短开发周期。“2”代表两种开发模式（低代码+高代码），支持 AgentScope，旨在提升 Agent2.0 的主动规划与闭环执行能力，实现“规划-执行-反思”的新范式。“1”代表模型与云服务底座，通过异步调用、闲时调度、模型后训练、专属模型单元部署、机密推理等，确保模型调用稳定、成本可控、安全合规。阿里云百炼企业版的发布，预示着 Agent 应用将进入“拼效率、拼落地”的竞争元年，企业将倾向于基于成熟技术中台而非从零开始建设 AI 能力。

💡 主要观点

  1. Agent 开发面临严重的落地困境，尤其在企业级场景中对工程化能力要求极高。 Agent 在 ToC 和 ToB 场景中易遇到任务连通性、容错、安全权限、数据管理及评估优化等挑战，导致大量试点项目难以进入生产环境。
  2. 阿里云百炼推出“1+2+N”体系升级，旨在解决 Agent 落地中的核心工程难题。 该体系通过“稳底座”（模型与云服务）、“定范式”（Agent 开发模式）和“理杂活”（可插拔组件），提供了一套工业级的 Agent 开发与运营解决方案。
  3. “N”层提供模块化组件，用于解决数据、安全、评估优化等“脏活累活”。 包括多模态 RAG 激活非结构化数据、Connector 连接器打通异构系统、Agent Identity 进行权限管理、Sandbox 提升执行安全、Trace/Evaluate 实现 Agent 行为可观测与持续优化。
  4. “2”层引入低代码与高代码双模式及 AgentScope，支持 Agent2.0 新开发范式。 旨在实现 Agent 的“规划-执行-反思”闭环能力，支持多智能体编排、长期记忆、工具调用等，推动 Agent 从被动执行到主动思考的转变。
  5. “1”层强化模型与云服务底座，确保模型调用稳定、高效、安全。 通过异步调用、闲时调度优化成本与性能，推出模型后训练、专属模型单元部署、机密推理服务，解决企业在模型调用中的性能、成本与合规痛点。

💬 文章金句

  • Manus 整体架构和理念不算颠覆式“新”，但在任务连通性、容错、回退机制等实现上，极度考验工程能力，远不是“换个皮”那么简单。
  • 问题出在哪？就在于这些一连串的工程难题。说到底，并不是模型不行，也不是工程师不会做，而是整个 Agent 开发还不够成熟，大家还在摸索阶段，没有提前规划一套更清晰、更稳定的“做法”。
  • 要用更工业化的方式，让企业的 Agent 在真实业务里跑起来。
  • Agent 不应仅“被告知怎么做”，而是“应该主动思考怎么做”。
  • 核心链路是“规划---执行---反思”。
