RSPack 2.0：性能提升、更精简的依赖项和 ESM 核心

7/29/2026, 6:24:00 AM

📌 一句话摘要

Rspack 2.0 发布，实现性能提升、依赖大幅精简并转向纯 ESM 核心，同时保持与 Webpack 高度兼容。

📝 详细摘要

InfoQ 中文报道了字节跳动研发的 Rust 基础打包工具 Rspack 2.0 发布的主要进展：整体构建性能较 1.7 提升约 10%、较 1.0 提升达 100%；在包含 10000 个组件的 React 项目中，生产构建时间从 5.6 秒降至 1.4 秒，HMR 时间降至 118 毫秒，启用缓存后构建速度再提约 50%、内存降低超 20%。依赖方面，@rspack/dev-server 依赖从 192 个降至 1 个，安装体积从 15 MB 降至 1.4 MB。核心模块 @rspack/core 已改为纯 ESM 包，移除 CommonJS 构建，支持 import.meta 和 stage-3 import defer 提案，改进 tree shaking 并在生产环境默认启用无副作用函数分析。升级需 Node.js 20.19+ 或 22.12+，不再支持 Node.js 18，需将相关包统一升至 ^2.0.0。文章还引用了社区反馈，认为 Rspack 正成为 Webpack 的可靠替代方案，并在与 Rolldown、Turbopack 的竞争中受益于约 95% 的 Webpack 配置兼容性。

💡 主要观点

  1. 性能显著提升，构建时间和内存占用大幅下降 相比 1.7 版本整体构建快约 10%，相比 1.0 快达 100%；在 10000 组件 React 项目中，生产构建从 5.6 秒降至 1.4 秒，HMR 降至 118 毫秒，启用缓存后构建再提约 50%、内存降低超 20%。
  2. 依赖体积和数量被极度精简 @rspack/dev-server 依赖从 192 个降至 1 个，安装大小从 15 MB 缩减至 1.4 MB，社区称此为理念的转变而非仅基准提升。
  3. 核心模块转为纯 ESM，兼容现代 Node.js 并改进模块特性 @rspack/core 以纯 ESM 形式发布，移除 CommonJS 构建；支持 import.meta 和 stage-3 import defer，改进 tree shaking 并在生产环境默认启用无副作用函数分析。
  4. 与 Webpack 高度兼容，降低迁移成本，但要求更高的 Node 版本 配置与 Webpack 约 95% 兼容，具备迁移优势；升级需 Node.js 20.19+ 或 22.12+，不再支持 Node.js 18，需将相关包统一升至 ^2.0.0。
  5. 社区认为 Rspack 正成为 Webpack 的可靠替代方案 Reddit 用户称其为“非常可靠的替代方案”，另一位用户认为只有在性能和生态更优时才会考虑切换，显示其在打包工具竞争中的定位。

💬 文章金句

  • 与性能数据相比，依赖项减少的数字更让我印象深刻，并称其为“一种理念的转变，而不仅仅是基准测试”，以及“在现阶段采取了比大多数打包工具更强硬的供应链立场”。
  • Rspack 正逐渐成为 Webpack 的一个非常可靠的替代方案。很高兴看到 2.0 版本带着这些改进问世。
