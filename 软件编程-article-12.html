Muse 上线，扎克伯格再谈开源：开源模型只是第一步，每个人都该拥有自己的 Agent，强大的 AI 不能只服务少数公司

9/9/2026, 9:30:00 AM

📌 一句话摘要

扎克伯格在访谈中强调，仅开源模型不足，必须让每个人拥有可自行控制的 AI Agent，Meta 推出的 Muse 通过独立虚拟机和安全机制实现了这一目标，并警示单一模型依赖的风险。

📝 详细摘要

文章围绕 Meta CEO 扎克伯格近期的公开访谈与 Muse 产品发布展开，指出开源模型只是让更多人获取强大 AI 的第一步，真正的拥有需要完整的 Agent 运行环境。为此，Meta 为 Muse 提供了独立的虚拟机、浏览器以及每周 1 亿 Token 的免费额度，使得个人 Agent 能在用户离线后继续工作。文章进一步分析了单一闭源 API 带来的成本、能力和可持续性风险，阐述了三层控制权（模型、运行环境、账号数据）以及 Meta 为 Muse 设计的隔离虚拟机和 Sentinel Agent 两道安全防线，确保用户可审计、撤销授权，甚至连 Meta 本身也看不到内部内容。最后，作者提醒开发者在选择 AI 方案时应关注模型可替换性、数据导出、权限收回和过程回放，以防平台失信导致的控制权丧失。

💡 主要观点

  1. 开源模型是第一步，真正的拥有需要个人可运行的 Agent 扎克伯格认为仅发布模型权重不足，必须提供完整的运行环境，让个人和小团队能够自行部署、控制并验证 AI 能力。
  2. Muse 提供独立虚拟机、浏览器和每周 1 亿 Token 免费额度，实现持续工作 产品让每个人拥有自己的 Agent，即使关闭应用也能继续搜索、整理资料和调用已授权的服务，降低了部署门槛。
  3. 单一闭源 API 存在成本、能力和可持续性三重风险 依赖单一供应商会导致价格、调用规则或地区限制变化时，迁移成本全部落到开发团队，影响产品的长期可控性。
  4. Meta 为 Muse 设计了隔离虚拟机和 Sentinel Agent 两道安全防线 隔离运行确保 Meta 看不到任务内容，Sentinel Agent 检测提示词注入、异常数据流并要求用户确认关键操作，提升了安全可审计性。
  5. 评估 AI Agent 时应关注模型可替换、数据导出、权限收回和过程回放 作者建议开发者以这些标准判断平台是否真正让用户保有控制权，防止未来平台失信导致的锁定风险。
