自建一个 Agent 很难吗？一语道破，万语难明

1/29/2026, 12:32:00 AM

📌 一句话摘要

本文详细介绍了如何在传统研发平台中从零构建一个基于 LangGraph 的 AI Coding Agent，重点分享了上下文工程优化、知识库建设及工具调用的实战经验。

📝 详细摘要

作者分享了为阿里云内部传统研发平台“奥德赛”接入 BFF Agent（小 D 同学）的全过程。技术选型上采用了宿主页面 Iframe 嵌入、Next.js + React 前后端一体化框架以及 LangGraph 状态图流转。文章核心聚焦于“上下文工程”的深度优化：通过 Anthropic 官方推荐的 XML 标签和角色设定优化系统提示词；利用 RAG 技术整合线上热门脚本、系统内置字段及服务端源码构建私域知识库；针对 FaaS 环境不支持长连接的问题，设计了基于 SSE 和隐藏消息触发的 UI 工具调用链路；最后通过工具响应结果压缩和上下文自动摘要机制，将 Token 消耗降低至原来的十分之一，有效解决了长对话下的幻觉与窗口超限问题。

💡 主要观点

  1. 采用 LangGraph 状态图构建 Agent 的核心逻辑，实现自主决策与工具调用。 通过定义节点（Agent、Tools）和条件边，将复杂的对话流转抽象为有向有环图，降低了开发门槛并提升了逻辑可控性。
  2. 针对私域知识缺失问题，构建了多维度的 RAG 知识库体系。 整合了线上热门脚本、自省生成的系统指令集及服务端源码，通过人工清洗和预切分提高召回质量，解决模型不理解特定语法（TQL）的问题。
  3. 设计了基于“中断-恢复”机制的 UI 工具调用链路，适配 Serverless 环境。 利用 SSE 流式输出和前端隐藏消息回传，在不支持长连接的 FaaS 平台上实现了 Agent 与用户界面的深度交互。
  4. 通过双重压缩策略（工具响应压缩与上下文摘要）优化 Token 使用效率。 使用轻量模型对工具返回的海量数据进行 XML 格式化提取，并在窗口接近阈值时触发有损摘要，显著缓解了注意力稀疏和成本问题。

💬 文章金句

  • 如果你遇到不确定或无法实现的需求，可充分用工具查询相关知识。
  • 上下文工程是一个综合命题，不同类型的上下文往往是交叉影响的，要根据具体场景做甄别。
  • 用第一条指令弱化了模型的信心，模型才开始谨慎地调用知识库了解更多上下文信息。
  • 对工具响应做优化后，主 Agent 的上下文窗口占用只需要花不到原来 1/10 的 token 就能解决问题了。
  • 压缩时我默认会完整保留自用户近 3 轮开始对话后的消息列表，避免一旦压缩节点就瞬间遗忘。
