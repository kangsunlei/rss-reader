Next.js 15.5 发布 - Turbopack 生产环境构建、Node.js 中间件与更优的 TypeScript DX

9/12/2025, 8:00:00 AM

📌 一句话摘要

Next.js 15.5 专注于使用 Turbopack 加速生产环境构建，稳定 Node.js 中间件，并显著改进 TypeScript 开发者体验。

📝 详细摘要

Next.js 15.5 是由 Vercel 发布的新版本，为开发者引入了多项关键增强功能。其中最引人注目的功能是可选择使用 Turbopack 进行生产环境构建，据称能将编译速度提升 2 到 5 倍，并优化资源分发。此外，该版本还稳定了 Node.js 中间件运行时，允许完全访问 Node.js API，从而实现以前在 Edge 运行时中难以实现的更复杂的服务器端逻辑。TypeScript 用户受益于稳定的类型化路由、路由导出验证、新的辅助类型以及 `next typegen` 命令，以更早地捕获错误。同时，Next.js 正在弃用 `next lint`，转而支持明确的 linter 配置，并针对 Next.js 16 中即将到来的变更提供警告，指导开发者遵循未来的最佳实践。社区反馈总体积极，并强调了这些更新带来的实际好处。

💡 主要观点

  1. Turbopack 现已可用于生产环境构建，能显著提高编译速度。 开发者可以使用一个简单的标志启用基于 Rust 的 Turbopack，从而将构建速度提升 2 到 5 倍，并可能减少 JavaScript/CSS 资源，进而提高开发效率和部署速度。
  2. Node.js 中间件运行时稳定化，扩展了服务器端功能。 中间件现在可以利用完整的 Node.js API，从而实现更复杂的服务器端操作，例如原生文件系统访问或更重的身份验证流程，这些操作在 Edge 运行时中以前极具挑战性。
  3. TypeScript 开发者体验通过新功能和验证得到增强。 稳定的类型化路由、路由导出验证和辅助类型减少了运行时意外情况，并在编译时捕获导航/导出错误，从而提高代码质量和开发者生产力。
  4. Next.js 转向明确的 linter 配置，并为 Next.js 16 做好准备。 弃用 `next lint` 旨在鼓励开发者选择明确的工具链，而新的弃用警告有助于团队主动应对重大变更，从而确保更平滑地过渡到下一个主要版本。

💬 文章金句

  • Turbopack 用于生产环境构建是 15.5 版本的重点。开发者现在只需一个标志即可选择启用生产环境 Turbopack 构建。
  • 中间件现在可以在拥有完整 Node API 的情况下运行，从而开启了在 Edge 运行时中难以或无法实现的模式。
  • 15.5 版本使类型化路由更加稳定（因此链接目标将在编译时得到验证），并引入了路由导出验证和辅助类型。
  • 此版本还正式改变了 Next.js 项目处理 linting 的方式，`next lint` 命令已被弃用，转而支持明确的 linter 配置。
  • 来自 r/nextjs subreddit 的一条评论称 15.5 是一个非常棒的更新，并对类型化路由和 next lint 的移除表示欢迎。
