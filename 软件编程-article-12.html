“AI 写的 C++ 代码，客观上比人类更烂”，吴咏炜对话 Adobe 首席科学家 David Sankel｜近匠

2/12/2026, 8:22:00 AM

📌 一句话摘要

本文是 Adobe 首席科学家 David Sankel 与吴咏炜的深度对话，探讨了 C++ 在 Rust 崛起与 AI 时代下的内存安全、工具链困境、极致性能权衡及 AI 生成代码的潜在风险。

📝 详细摘要

在这场深度访谈中，C++ 标准委员会资深委员 David Sankel 剖析了 C++ 的现状与未来。他指出内存安全漏洞多发于新代码而非遗留系统，是因为旧代码经过了长期的“对抗性硬化”。尽管 C++ 拥有现代特性，但因继承了 C 的底层基因且缺乏强制安全约束，漏洞依然难以根除。对比 Rust，C++ 的核心优势在于允许开发者利用“未定义行为”换取物理极限性能，但其碎片化的工具链和包管理缺失已成为生产力的巨大阻碍。关于 AI 编程，Sankel 警告称 AI 生成的 C++ 代码在安全性上客观差于人类，且开发者易产生过度自信。最后，他讨论了 C++26 对未定义行为的治理，认为现代 CPU 架构已使安全检查的性能成本大幅降低，C++ 正在向更安全的方向演进。

💡 主要观点

  1. 内存安全漏洞主要源于新编写的代码，而非经过长期验证的遗留系统。 代码硬化需要时间。旧代码在长期的对抗性压力和安全审查下，绝大多数漏洞已被修复；而新代码尚未经历这种历练，因此更显脆弱。
  2. C++ 的核心价值在于通过承担“未定义行为”的风险来换取极致的性能表现。 在游戏引擎或高频交易等领域，开发者愿意接受程序崩溃的风险以换取最精简的汇编指令，这是 Rust 等安全语言难以在不增加代码复杂度的情况下实现的。
  3. C++ 生产力落后于 Rust 的根源在于工具链和包管理系统的碎片化。 Rust 的 Cargo 提供了降维打击般的体验，而 C++ 仅标准化了语言规格，未标准化工具链，导致依赖管理和版本升级成为极其昂贵的工程活动。
  4. AI 生成的 C++ 代码在安全性上客观差于人类，且存在心理学上的过度自信陷阱。 研究表明 AI 生成的代码包含更多内存漏洞，但开发者往往对其正确性表现出盲目自信，这种“人机协作”模式在 C++ 领域可能引入更多隐患。
  5. 现代 CPU 架构的演进正在改变“安全与性能”的权衡逻辑。 得益于超标量架构和指令预取技术，许多以前昂贵的边界检查现在可以被硬件并行能力“免费”消化，未定义行为作为优化手段的必要性正在降低。

💬 文章金句

  • 如果我们必须用对底层的绝对掌控来换取物理极限的性能，那么 C++ 依然是这个星球上无可替代的语言。
  • 在 C++ 生态中，依赖管理和版本升级是一项昂贵的工程活动。用户往往因为升级成本过高而停留在有漏洞的旧版本上。
  • Cargo 对于 C++ 开发者来说，简直是降维打击般的体验提升。
  • AI 生成的 C++ 代码在客观上比人类编写的代码更差，尤其是在内存安全漏洞方面。
  • 开发者往往对 AI 生成代码的正确性过度自信，其信心程度甚至超过对自己亲手编写代码的信心。
