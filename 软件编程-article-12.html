AI 工具订阅额度的高效利用与产品化实践

9/26/2026, 10:09:26 AM

📌 一句话摘要

作者分享了在账号重置前高效利用 Claude、Codex 和 Cursor 等 AI 工具的实际经验，强调将 Token 用于解决真实问题而非制作 Demo，并批评了单纯追求 Token 使用量的考核方式。

📝 详细摘要

作者详细记录了如何利用 Claude Code (Opus 5.5)、Codex (GPT-6 Astra Medium)和 Cursor (Grok Bot)的周额度进行实际产品开发。通过对比不同模型在代码审查、需求分析和开源 Issue 处理上的表现，作者认为 Opus 5.5 在复杂任务中极具价值，而 Codex 虽快但消耗大。作者还提及为测试 Windows 版本购买 Parallels Desktop 的经历，并强烈反对以 Token 用量作为工程师绩效指标的做法，主张 AI 应服务于实质性的产品构建。

💡 主要观点

  1. AI 工具的核心价值在于解决实际问题而非生成 Demo 作者通过在重置前极限使用额度，验证了各模型在处理真实业务逻辑（如 Mole Windows 版开发）时的效能，强调了「物尽其用」的工程导向。
  2. 不同 AI 模型在工程场景中存在显著的能力差异 Opus 5.5 被评价为耐用且适合深度开发，Codex 速度快但消耗大，Cursor 结合 Grok 在增长和开源协作中表现良好，三者形成了互补的工作流。
  3. 反对以 Token 用量衡量工程师产出 作者指出单纯追求 Token 使用量是本末倒置的，容易引导不良风气，真正的价值在于利用 AI 完成了多少有质量的产品功能。

💬 文章金句

  • 用 AI 最快乐的事情，莫过于在重置前的几分钟，把所有订阅的两个 200 刀账号周额度物尽其用的用完，用来做有解决问题的东西，而非 Demo 是最爽的。
  • 当你能够把你订阅的 AI 模型在重置前一滴不剩的不浪费的用到实际场景，真的是一个非常有意思的事情
  • 我非常反感之前有些公司或者团队所谓的 Token 使用排名，看谁用的多少 Token，而不看他用这些 Token 做了什么
