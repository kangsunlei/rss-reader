在机架级超级计算机上运行 AI 工作负载：从硬件到拓扑感知调度

4/7/2026, 6:51:24 PM

📌 一句话摘要

本文探讨了管理 NVIDIA GB200 NVL72 等机架级 AI 超级计算机的运营挑战，详细介绍了 NVIDIA Mission Control、Slurm 和 Kubernetes 等软件栈如何将硬件拓扑与工作负载调度相结合。

📝 详细摘要

管理机架级超级计算机需要弥合物理硬件拓扑（如 NVLink 结构和 IMEX 域）与工作负载调度程序所用抽象之间的鸿沟。本文解释了 NVIDIA Mission Control、Slurm 和 Kubernetes（通过 NVIDIA Run:ai 和 ComputeDomains）如何将复杂的硬件结构转化为可管理、高性能的资源。通过利用集群 UUID 和 Clique ID 等系统级标识符，并借助 Topograph 等工具进行自动化拓扑发现，平台工程师可以确保分布式 AI 工作负载得到最优部署，从而在不向最终用户暴露底层基础设施复杂性的前提下，保持高带宽、低延迟的连接。

💡 主要观点

  1. 弥合机架级硬件与调度程序抽象之间的鸿沟。 标准调度程序通常将 GPU 视为一个扁平的资源池，忽略了分层的 NVLink 结构。有效的管理需要将硬件拓扑暴露给软件栈，以确保高性能的任务部署。
  2. 利用集群 UUID 和 Clique ID 进行拓扑感知调度。 这些标识符将物理 NVLink 域和分区映射到软件级的原语，使 Slurm 和 Kubernetes 等调度程序能够识别 GPU 的邻近性和通信能力。
  3. 利用 Topograph 实现拓扑发现自动化。 手动建模大规模基础设施是不可持续的。Topograph 自动发现节点关系和网络层次结构，为集群提供了一种动态的、可供调度程序使用的视图。
  4. 为 Kubernetes 原生 NVLink 支持实现 ComputeDomains。 通过使用 NVIDIA DRA 驱动程序和 ComputeDomain 对象，Kubernetes 可以将多节点 NVLink 结构视为一等资源，确保 Pod 被共同部署在同一个高带宽域内。

💬 文章金句

  • 机架级硬件拓扑与调度程序抽象之间的不匹配，正是大多数运营复杂性的根源所在。
  • 一旦开始在基于 Blackwell 的 NVL72 系统上运行多节点工作负载，部署位置的重要性就等同于 GPU 数量。
  • Topograph 通过收集节点级和基础设施元数据，并将其转化为调度程序可用的表示形式，从而自动发现集群拓扑。
