Docker Sandboxes 曝严重逃逸漏洞，恶意代码可读写 macOS 主机文件

9/18/2026, 10:00:00 AM

📌 一句话摘要

Docker Sandboxes 在 macOS 平台曝出严重沙箱逃逸漏洞（CVE-2026-77179），恶意代码可通过符号链接操纵主机文件，Docker 已发布 0.42.0 版本修复。

📝 详细摘要

Docker 近期披露了 macOS 平台 Docker Sandboxes 的两项安全漏洞。核心漏洞 CVE-2026-77179（严重）允许沙箱内恶意代码通过 virtio-fs 组件的符号链接处理缺陷，逃逸至主机并以 VMM 用户权限读写任意文件。另一项高危漏洞 CVE-2026-79994 则涉及中继组件的套接字路径校验绕过，可能导致主机侧能力暴露。这些漏洞主要威胁 AI coding Agent 等在沙箱内运行的程序。Docker 已在 0.42.0 版本中修复上述问题，并建议用户尽快升级或采用克隆模式进行临时缓解。

💡 主要观点

  1. macOS 版 Docker Sandboxes 存在严重沙箱逃逸漏洞 CVE-2026-77179 允许沙箱内程序利用符号链接跳转，突破项目目录限制，以主机 VMM 用户权限读写主机任意文件。
  2. 中继组件存在高危路径校验绕过漏洞 CVE-2026-79994 允许攻击者在校验间隙通过符号链接替换路径，诱导主机连接到工作区外的任意 Unix 域套接字。
  3. 漏洞主要针对 AI Agent 运行环境 Docker Sandboxes 为 AI Agent 提供隔离环境，但若 Agent 被诱导执行恶意代码，沙箱边界即被突破，威胁主机安全。
  4. 官方修复方案与缓解措施 Docker 已在 0.42.0 版本修复漏洞；临时缓解措施包括使用克隆模式挂载项目，但克隆模式仅能防止文件被修改，无法阻止读取。

💬 文章金句

  • Docker Sandboxes 会为每个 AI coding Agent 分配独立的轻量虚拟机，仅将项目目录共享至虚拟机内部。
  • Guest（即虚拟机内运行的任意程序）可将父目录替换为符号链接，随后以 VMM 用户（即运行虚拟机监控器的主机账户）身份读取或修改文件，"可能导致主机上的代码执行"。
  • 如果 Guest 在校验完成到建立连接的间隙，将路径上的某个目录替换为符号链接，就能让主机连接到工作区外的任意 AF_UNIX 套接字。
  • Docker 目前未监测到任何在野利用案例。
