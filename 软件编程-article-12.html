如何像 Manus 交付业务需求-- OneAgent + MCPs 范式

6/13/2025, 12:31:00 AM

📌 一句话摘要

文章介绍了基于 Loop 框架的 OneAgent+MCPs 范式，一种面向企业内部复杂业务需求的 AI Agent 开发和落地方法。

📝 详细摘要

文章追溯了 Agent 的发展历程，从单一 LLM 调用到 Workflow 编排，再到 Multi-Agent 系统。着重介绍了基于 Loop 框架的 Agent 概念，并以 Manus 为例，提出 OneAgent+MCPs（Micro Capability Providers）的企业级 Agent 开发范式。该范式通过通用 Agent 与领域特定 MCP 交互，旨在解决长尾业务场景的自动化交付。文章详细阐述了 OneAgent+MCPs 系统的组成部分（Registry， Bridge， MCP0， KnowledgeMCP 等）和执行流程，讨论了 MCP 的封装理念，强调其应封装闭环业务操作而非仅原子能力，体现了从“软件即服务”到“服务即软件”的转变。最后，分析了当前该范式面临的挑战，包括 to-do 质量依赖、MCP 管理、状态管理和知识整合等，并展望了标准化、鲁棒性提升以及通过强化学习提高 Agent 智能的未来发展方向。

💡 主要观点

  1. OneAgent+MCPs 是面向企业内部复杂业务需求的 Agent 开发新范式。 结合通用 Agent 和领域特定 MCP，解决 Workflows 和多 Agent 系统在企业长尾场景的局限性，实现更灵活的自动化交付。
  2. Loop 框架是 OneAgent 自主决策和行动的核心机制。 通过循环调用工具与环境交互，Agent 能根据反馈迭代推进任务，是实现 Manus 等智能体自主性的基础。
  3. MCP 应封装闭环业务操作而非仅原子能力，实现“服务即软件”。 将多个原子能力组合成服务化的 MCP，能避免 Tool 膨胀，简化 Agent 调用，促使企业服务更易被 Agent 消费和组合。
  4. 强化学习是提升 Agent 调用工具智能和鲁棒性的关键。 通过 RFT 等方法训练模型自主学习何时、如何调用 MCP，能增强 Agent 的推理能力，应对复杂和探索性任务。

💬 文章金句

  • Manus 交付(Deliver) 业务需求其实是一种新的单领域 Agent 开发范式
  • Agent 更简洁的概念，即在循环（Loop）中使用工具的模型
  • 基于一个强大的基础 Agent 派生领域 Agent ，结合知识类 MCP/Planner 的帮助，是完全有可能将 Manus 范式在企业落地的。
  • MCP 本身可以封装 Agent，Agent 本身也会调用 MCP， 当然 Agent 和 Agent 之间也会交互。
  • 通过强化微调，可以做到让模型将 MCP 作为推理链的一部分来使用。
