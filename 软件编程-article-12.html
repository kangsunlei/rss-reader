Cloudflare 2025 年 9 月 12 日仪表盘及 API 中断事件深度分析

9/12/2025, 11:19:08 PM

📌 一句话摘要

Cloudflare 经历了一次仪表盘和 API 中断，原因是 React 的一个 Bug 导致对过载的租户服务 API 的过度调用。同时进行的服务更新进一步加剧了 API 的过载，导致关键的授权失败。

📝 详细摘要

Cloudflare 2025 年 9 月 12 日的中断源于一个级联故障，该故障由仪表盘中 React 的 `useEffect` Hook 中的一个 Bug 引发。这个 Bug 导致其依赖项列表中的一个对象不断被重新创建，从而触发对租户服务 API 的重复、不必要的调用。这与租户服务 API 的新版本部署同时发生，新版本存在性能问题，导致服务过载并导致其失败。由于租户服务处理 API 请求授权，其失败导致 Cloudflare 的仪表盘和其他 API 出现大范围的 5xx 错误。Cloudflare 的应对措施包括增加租户服务 API 的计算资源，并对租户服务实施临时速率限制。随后，团队尝试通过修复部分错误代码来恢复服务，但该操作无意中使情况进一步恶化，之后全面回滚有问题的更改，最终恢复了服务。该事件突显了自动部署回滚的重要性，缓解了服务恢复时可能出现的“惊群效应”，充分的容量规划以及增强的可观察性，以区分中断期间的新请求和重试请求。由于控制平面与数据平面严格分离，数据平面未受到影响。

💡 主要观点

  1. 仪表盘中 React 的 `useEffect` 错误导致对租户服务 API 的过度重复调用。 React 的 `useEffect` Hook 的配置不正确的依赖项列表导致对象被视为“始终是新的”，从而导致 Hook（及其 API 调用）在每次仪表盘渲染时多次重新运行。
  2. 过高的 API 负载，以及同时进行的服务更新，导致关键的租户服务 API 过载。 API 请求的激增恰逢租户服务 API 的新版本部署，新版本存在性能问题，导致它变得过载且无法恢复，从而导致 Cloudflare 的 API 出现大范围的授权失败。
  3. 最初的恢复工作包括增加计算资源和实施速率限制，但由于信息不足而进行的补丁操作加剧了中断。 Cloudflare 增加了租户服务 API 的计算资源，并对租户服务实施速率限制。但是，团队尝试通过修复部分错误代码来恢复服务，但该操作无意中使情况进一步恶化，因此需要快速回滚以恢复稳定性。
  4. 吸取的关键教训包括实施自动回滚和缓解潜在的“惊群效应”。 未来的改进侧重于将服务迁移到 Argo Rollouts 以进行自动回滚，引入随机延迟以分散重试请求，从而避免“惊群效应”，并增加服务容量。
  5. 提升可观测性对于快速诊断涉及大量重试的复杂事件至关重要。 Cloudflare 计划在仪表盘发起的 API 调用中添加更详细的信息，例如标记请求是否为重试请求，以便更好地区分中断期间的流量模式。

💬 文章金句

  • 本次事件的影响由多个因素导致，但直接触发因素是仪表盘中的一个 Bug。
  • 当租户服务过载时，它影响了其他 API 和仪表盘，因为租户服务负责 API 请求的授权逻辑。
  • 事件发生后，我们的首要目标是恢复服务。通常，这意味着直接修复根本问题，但有时并非如此。
  • 这种模式通常被称为‘惊群效应’，指的是当资源或服务恢复可用时，所有客户端同时尝试访问它。
  • 我们认为从错误中吸取教训非常重要，并且此事件是进行一些改进的机会。
