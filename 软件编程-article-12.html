Agent 评测漫谈 —— 由浅入深讲解 Agent 评测

📌 一句话摘要

本文由美团图灵评测团队基于两年业务实践，系统讲解 Agent 评测的定义、核心方法论与演进趋势，提出观测驱动、人人一致人机一致、数据飞轮等关键实践认知。

📝 详细摘要

文章由美团图灵 Agent 评测团队基于两年 BP 各业务线的实践总结而成，系统阐述 Agent 评测的完整认知框架。第一章从核心目的出发，说明评测要回答「Agent 好不好、哪里好哪里不好」，并区分 Agent 评测与模型评测的差异，强调行为与过程观测的重要性。第二章提出评测核心方法论：指标体系要在业务指标与模型能力之间「搭桥」，客观与主观评测并行，通过「人人一致、人机一致」的对齐方法（指标下钻加 Rubric 二元化）提升评测置信度，并指出评测是一门实践科学，应从高频场景、Bad/Good Case 出发让数据飞轮运转。第三章分析短程与长程 Agent 评测的范式差异，讨论 Skill 评测兴起、面向 Task 的评测以及人评走向机评的趋势，给出评测基础设施应具备的能力清单。附录调研了开源长程 Agent 评测生态的术语与代表性项目。

💡 主要观点

  1. Agent 评测的核心是回答好不好，且必须同时看结果与行为过程。 两个 Agent 同样做对任务，工程价值可能差别巨大；评测需覆盖结果、过程、效率、风险四层，避免把偶然命中误判为真实能力。
  2. 评测体系的核心不是堆指标，而是在业务指标与模型能力之间搭桥。 模型能力指标与业务结果指标之间存在天然鸿沟，需要面向任务系统的桥梁指标串联，才能回答业务指标为何变差或模型能力提升为何没带来收益。
  3. 主观评测应通过人人一致、人机一致来对齐标准。 关键做法是让权威角色拉齐各方标准、将模糊指标下钻并二元化为 Rubric，用一致率阈值反查定义是否合理；数字站长案例人机一致率达 99%。
  4. Agent 评测是实践科学，起步阶段应让数据飞轮高效运转。 采集、清洗、评测、质检、分析五环节构成迭代飞轮；先定义少量关键指标，用 Bad Case 暴露短板、Good Case 定义范式，逐步沉淀评测资产。
  5. 长程 Agent 时代，评测从答案评测走向行为评测，从人评主导走向机评主导。 评测对象从单一模型变为模型加系统、工具、流程的复杂系统，关注任务完成度与轨迹质量；人工聚焦标准设计与 Rubric 对齐，AI 承担规模化评测。

💬 文章金句

  • 观测 + 评测 = 持续迭代
  • ChatAgent 评测关心“说得好不好”，长程 Agent 评测关心“事情做成没有，以及是怎么做成的”。
  • 起步阶段“让数据飞轮高效运转起来”的意义远大于“设计一个复杂精妙的评测体系”。
  • 看不见的问题，几乎不可能被稳定解决。
  • 1 个“独裁者”好过 10 个“民主者”。
