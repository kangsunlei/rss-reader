Stripe 工程师部署 Minions，每周生成数千个 Pull Request 的自主智能体

3/20/2026, 2:26:00 PM

📌 一句话摘要

Stripe 成功部署了「Minions」，这是一种自主 AI 智能体，使用「一次性」工作流和混合「蓝图」每周生成超过 1300 个生产就绪的 Pull Request。

📝 详细摘要

文章详细介绍了 Stripe 实施的「Minions」，这是一个端到端处理软件开发任务的自主编码智能体系统。与 GitHub Copilot 等交互式助手不同，Minions 以「一次性」模式运行，从 Slack 或错误报告等来源获取单一指令，并生成完整的 Pull Request。该系统基于「Goose」智能体框架的分支构建，并利用「蓝图」——将确定性代码与灵活的 LLM 循环结合的结构化工作流，以确保可靠性和适应性。目前，这些智能体每周为处理每年 1 万亿美元支付的系统生成超过 1300 个 PR。尽管代码完全由 AI 生成，Stripe 仍保持严格的「人工介入」政策，要求在部署前进行人工审查并通过严格的 CI/CD 检查。

💡 主要观点

  1. Stripe 的 Minions 从交互式 AI 辅助转变为自主的一次性任务执行。 与传统需要持续人工提示的 AI 编辑器不同，Minions 接收高级指令后独立导航复杂依赖关系，提交完成待审核的 Pull Request。
  2. 「蓝图」框架为智能体的可靠性和灵活性提供了混合方法。 通过将确定性代码与灵活的智能体循环交织，Stripe 确保智能体遵循既定工程标准，同时保留处理复杂编码任务所需的推理能力。
  3. 自主智能体在高风险金融生产环境中可以实现规模化部署。 每周为处理每年 1 万亿美元的平台生成超过 1300 个 PR，表明 AI 智能体在稳健的 CI/CD 和人工监督支持下能够处理关键基础设施。
  4. 人工审核仍是 AI 驱动开发生命周期中的最终保障。 尽管自主输出量很大，Stripe 强制要求所有变更都经过人工审核，确保工程师将焦点从编写代码转向定义任务和审核结果。

💬 文章金句

  • Minions 已从概念验证发展为每周生成超过一千个 Pull Request。所有代码都经过人工审核，但智能体正越来越多地端到端地产生变更。
  • Minions 不同于交互式编码助手……通过执行一次性、端到端的任务。
  • Stripe 工程师将蓝图描述为智能体技能与代码的集合，相互交织以确保效率同时保留适应性。
  • 该系统反映了智能体驱动软件开发的大趋势，其中基于 LLM 的智能体与开发环境紧密集成。
