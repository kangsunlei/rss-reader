Node 中文周刊 #236 - 我们无法在 Node.js 中防御原型污染

📌 一句话摘要

本期 Node.js 中文周刊汇总了原型污染防御争论、Domenic 的开发环境设置、npm 供应链安全研究以及多个工具与库的版本更新。

📝 详细摘要

本期周刊以「我们无法在 Node.js 中防御原型污染」为首篇，解释了 Node 团队拒绝相关 CVE 报告的原因，认为攻击者能写入 Object.prototype 时已无法防御，真正的修复应在 JSON 解析边界。还介绍了 Domenic Denicola 基于临时虚拟机、Tailscale 和 worktree 的代理编码工作流。快讯包括 Node.js 安全发布轮次预告、OpenJS 贡献榜、Bun 1.4 重大兼容改进、pnpm 引入原生 workspace 管理、ESLint 迁移 codemod 等。安全方面，Microsoft 披露 AsyncAPI npm 投毒采用 import-time 绕过 post-install 限制，Socket 研究发现多个 LLM 编造出 53 个虚假 npm 包名。文章部分还介绍了 BullMQ 后台任务教程。工具方面，better-sqlite3 v13 迁移至 N-API 以提升跨版本兼容，Execa v10 精简 API 并新增流转换与 killDescendants，eslint-package-json 可校验 package.json 错误，BotKit 支持构建 ActivityPub 机器人。版本发布涉及 Nub、odiff、node-html-to-image、find-my-way、Gitify、Verdaccio、Piscina、Prisma 等。

💡 主要观点

  1. Node 团队拒绝修复核心模块的原型污染漏洞。 认为攻击者能写入 Object.prototype 时已无法防御，真正的修复应在 JSON 解析边界。
  2. AsyncAPI npm 投毒利用 import-time 加载恶意包。 攻击者绕过后安装脚本限制，在包导入时执行恶意代码。
  3. better-sqlite3 迁移至 N-API 提升跨版本兼容性。 v13.0 通过 N-API 使得预编译二进制包可在不同 Node 和 Electron 版本间正常工作。

💬 文章金句

  • 每份报告都假设攻击者已经能够写入 Object.prototype，到那时游戏已经结束。
