开源版 Grok Bot，来了！

8/27/2026, 9:05:00 AM

📌 一句话摘要

OpenBot 是由 CopilotKit 开源的 Grok Bot 替代方案，通过 Docker 实现自托管，为每个 AI Agent 提供独立容器环境并引入严格的动作审计网关，旨在解决 Agent 应用中的隐私与信任痛点。

📝 详细摘要

本文介绍了由 CopilotKit 团队开源的 OpenBot 项目，该项目旨在提供一个可自托管的 AI Agent 运行环境。OpenBot 模拟了 Grok Bot 的「每个 AI 同事一台电脑」模式，通过 Docker 为每个 Bot 分配独立的浏览器、登录态和 Shell 终端，并支持接入 OpenAI、Claude 等主流模型。其核心竞争力在于构建了动作管控网关，所有操作必须经过策略审核与审计记录，且支持人类在遇到 2FA 等验证墙时实时接管操作，将 Agent 的竞争维度从单纯的「智能」提升到了「信任」与「安全」。

💡 主要观点

  1. 自托管架构解决隐私信任危机 通过 Docker 一键部署和本地 PostgreSQL 存储，将数据和账号控制权完全交还用户，解决了云端 Agent 方案中敏感信息上传的信任问题。
  2. 独立容器化的「AI 同事」形态 每个 Bot 运行在独立容器中，拥有专属的浏览器、登录态和工作目录，用户可通过面板实时监控其屏幕操作和命令执行记录。
  3. 基于网关的严格动作管控 所有 Bot 动作（如点击按钮、修改文件）必须通过统一网关，匹配策略规则并记录审计日志后方可执行，默认拒绝未授权操作。
  4. 灵活的人机协作接管机制 当 Bot 遇到登录墙或 2FA 验证等无法独立处理的场景时，支持人类接管操作权完成验证后再归还，确保工作流的连续性。

💬 文章金句

  • OpenBot 把同样的形态搬回了自己机器，数据和账号都攥在自己手里，还制定了安全规则。
  • 在我看来，Agent 下半场的竞争比得不再是模型聪不聪明，而是比谁让人用的放心。
  • 容器里的 Bot 每一个动作，点击网页按钮、修改文件、调 MCP 工具，都要过同一道网关。
