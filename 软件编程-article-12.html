GKE 如何扩展至 13 万节点集群

11/22/2025, 12:00:00 AM

📌 一句话摘要

谷歌成功将 GKE 扩展至实验性的 13 万节点集群，并详细介绍了 API 服务器读取优化、分布式存储以及 Kueue 等架构创新，以支持极端 AI/ML 工作负载。

📝 详细摘要

本文详细介绍了谷歌云在将 Google Kubernetes Engine (GKE) 扩展到实验性的 13 万节点集群方面取得的成就，达到当前官方支持上限的两倍，主要目的是为了满足大规模 AI/ML 工作负载不断增长的需求。文章讨论了转向功率受限环境的挑战，以及对强大的多集群解决方案（如 MultiKueue）的需求。实现这种前所未有的规模的关键架构创新包括：通过一致性缓存读取和可快照 API 服务器缓存实现 API 服务器读取优化，构建在谷歌 Spanner 上的优化分布式存储后端，以及集成 Kueue 以实现高级任务队列、整体调度和抢占等功能。文章概述了一个四阶段的基准测试，模拟具有不同优先级的动态混合 AI 工作负载，证明了 GKE 能够维持 1，000 Pod/秒的吞吐量，管理超过 100 万个 Kubernetes 对象，并在极端负载下保持低 Pod 启动延迟和控制平面稳定性。这些进步不仅促进了超大规模集群的实现，还增强了所有 GKE 客户的弹性和性能。

💡 主要观点

  1. GKE 通过重大的控制平面和存储创新实现了实验性的 13 万节点可扩展性。 这种极端的规模是通过优化 API 服务器读取路径（使用一致性缓存和可快照缓存）以及利用基于 Spanner 的分布式存储后端实现的，这对于处理大量的对象数量和 API 请求量至关重要。
  2. Kueue 为高效的 AI/ML 工作负载管理提供高级任务队列和抢占。 Kueue 允许基于优先级和配额进行复杂的作业级调度，从而能够快速抢占和整体调度复杂的 AI 工作负载。这显著提高了资源利用率和响应能力。
  3. 该基准测试验证了 GKE 针对混合 AI 工作负载的动态资源管理和高吞吐量。 一个四阶段的模拟演示了 GKE 处理波动需求、优先处理关键服务以及维持 1，000 Pod/秒的创建/绑定吞吐量以及稳定的控制平面性能的能力，证明了其弹性。

💬 文章金句

  • 在谷歌云，我们不断提高 Google Kubernetes Engine (GKE) 的可扩展性，以便它可以跟上日益增长的工作负载——尤其是 AI。
  • 这种扩展不仅仅是增加节点的数量；它还需要扩展其他关键维度，例如 Pod 创建和调度吞吐量。
  • Kueue 是一个作业排队控制器，它将批处理系统功能带到 Kubernetes。它根据公平共享策略、优先级和资源配额来决定 *何时* 应允许作业进入，并为整个作业启用“全有或全无”的调度。
  • Kubernetes 控制平面性能的关键衡量标准是其快速创建和调度 Pod 的能力。在整个基准测试中，尤其是在最密集的阶段，GKE 始终如一地实现了并保持了高达每秒 1，000 次操作的 Pod 创建和 Pod 绑定吞吐量。
  • 总而言之，这项实验表明，GKE 可以支持超出当前公共限制范围的 AI 和 ML 工作负载。
