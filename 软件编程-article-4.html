提升全球运营：通过 Fleet 掌握多集群 Elastic 部署

1/16/2026, 4:46:24 PM

📌 一句话摘要

Elastic Fleet (9.1+) 现在通过全局 Fleet 管理、集成同步和空间感知功能提供多集群管理，实现对分布式 Elastic Agent 的集中控制，同时保持数据主权并优化成本。

📝 详细摘要

本文讨论了 Elastic Fleet 如何解决全球企业中多集群 Elastic 部署的复杂性。文章重点介绍了多集群架构的驱动因素：数据主权、性能/成本优化以及弹性/本地自治。核心创新在于将 Agent 的数据目的地与其管理控制平面分离，实现集中管理的同时保持数据本地化。Elastic 9.1 引入的关键功能包括：全局 Fleet 管理提供 Agent 的统一视图，集成同步确保跨集群的一致安全和可观测性标准，以及具有细粒度角色权限的空间感知功能，支持多租户企业用例。这些增强功能使组织能够扩展 Elastic Agent 部署、一致地执行策略、遵守数据主权并最小化跨区域数据传输成本，为全球运营提供真正的"单一管理平台"。

💡 主要观点

  1. 多集群部署由数据主权、性能/成本和弹性需求驱动 全球企业采用分散式数据存储以遵守法规、减少昂贵的跨区域数据传输、最小化延迟并增强系统对中断的弹性
  2. Elastic Fleet (9.1+) 通过将 Agent 数据目的地与控制平面解耦实现全局管理 这种分离允许 Elastic Agent 将数据发送到本地集群以实现主权，同时其状态和管理检查被路由到中央控制平面，提供统一的全局视图而无需集中批量数据
  3. 集成同步确保所有集群间的一致安全和可观测性 操作员可以在中央管理集群中一次性安装集成，Fleet 会自动将它们同步到所有远程集群，保持统一标准并简化安全和可观测性分析
  4. 空间感知和细粒度权限支持多租户企业用例 Fleet 现在允许定义特定角色并通过 Kibana Spaces 分割资源，为不同团队或租户提供隔离管理，同时保持整体中央控制

💬 文章金句

  • 分散数据存储的决定通常由三个关键因素驱动：数据主权和法规遵从性、性能、延迟和成本优化、弹性和本地自治
  • 核心创新简单而强大：将 Agent 的数据目的地与其管理控制平面分离
  • 中央管理集群中的 Fleet 维护着全球部署的每个 Agent 的全局视图，尽管大部分摄入的数据都驻留在本地
  • 集成同步通过确保所有远程集群自动接收与管理集群相同的集成内容来直接解决这个问题
  • Elastic 在 Fleet 中的新多集群功能直接解决了分布式数据对于合规性和成本的必要性，与运营上对集中管理以简化一致性的需求之间的长期紧张关系
