一次建模，处处表示：Netflix 的 UDA ( 统一数据架构 )

6/12/2025, 3:27:35 PM

📌 一句话摘要

Netflix 的 UDA 利用知识图谱 和 元模型 解决数据不一致性问题。

📝 详细摘要

Netflix 开发了 UDA ( 统一数据架构 ) 来应对其日益增长的服务中复杂、孤立的系统 和 不一致数据模型 带来的挑战。UDA 通过允许团队使用知识图谱方法 在概念层面一次性定义核心业务概念，为连接的 数据 奠定了基础。该图谱通过表示 和 映射 将领域模型连接到各种数据容器 ( 如 GraphQL、 Avro、 Iceberg )。一个关键组件是 Upper 元模型，它正式描述领域并允许将模型自动化生成到不同的模式中。这种方法提高了数据可发现性、 一致性、 语义互操作性，并实现了数据移动的 基于意图的自动化，例如通过像 PDM 和 Sphere 这样的内部系统来实现。

💡 主要观点

  1. UDA 解决 了分布式系统 中 数据模型 的 不一致性问题。 通过允许 在概念层面一次性对概念进行建模 并 将其连接到实际系统，UDA 减少了重复 和 冲突的定义。
  2. 知识图谱 将概念模型连接到 物理数据容器。 利用 RDF 和 SHACL 基础，UDA 将领域模型映射到模式 和 数据源，使数据位置 和 结构 可发现。
  3. Upper 元模型 实现 了正式的领域描述 和 自动化 模式生成。 Upper 定义了用于建模领域的语言，并将这些模型生成到各种模式 ( GraphQL、 Avro ) 中，确保系统之间的一致性。
  4. 映射 将领域概念链接到 它们 在数据容器中 的 物理表示。 这些映射允许用户 和 系统 从抽象概念导航到具体数据位置，从而促进数据发现 和 自动化。

💬 文章金句

  • 因此，出现了一些挑战：模型重复和不一致、术语不一致、数据质量问题、连接性有限。
  • 这些是促使我们构建 UDA 的核心思想。
  • UDA ( 统一数据架构 ) 是内容工程中连接 数据 的基础。
  • Upper 是一种用于正式描述领域 ( 业务或系统 ) 及其概念的语言。
  • 数据并非总是可在消费者所需的系统中获得。由于映射编码了意义 和 位置，UDA 可以推断 数据 应如何移动，从而保留语义，而无需消费者指定具体做法。
