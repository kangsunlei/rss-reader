双开 Claude Code + Codex 好几个月，受不了人肉传话，写了个桥让它俩自己聊

7/4/2026, 12:06:21 PM

📌 一句话摘要

作者为解决双开 Claude Code 和 Codex 时手动传话的低效问题，编写了 agent-bridge 实现双向通信，让两个 AI agent 自动分工、互相 review，项目大部分功能由 agent 自举开发。

📝 详细摘要

作者在使用 Claude Code（规划）和 Codex（执行）双开工作模式时，需要频繁手动在两者间搬运信息，一天数十次且需等待同步，效率极低。为此，他构建了 agent-bridge：通过 MCP 通道连接 Claude、逆向 Codex 协议实现代理，中间以常驻进程管理状态与重连。桥接后，两个 agent 可双向实时对话，自动分配任务、互相审查代码，并在任一方订阅额度耗尽时自动存档并切换。文章还提到，该工具的后续功能大多由两个 agent 通过早期版本自行开发、提 PR 和 review，实现了自我孵化。项目基于 MIT 协议，本地运行，仅支持 macOS/Linux，已知 Codex 在 .git 目录下有卡死问题。

💡 主要观点

  1. 双开 AI 编程工具导致手动传话效率极低。 作者同时使用 Claude Code（规划）和 Codex（执行）时，需手动复制粘贴回复，每天几十次，且需等待一方完成后才能继续，严重影响工作流。
  2. agent-bridge 实现了双向实时通信，agent 可自动分工和互相 review。 桥接后两个 agent 在同一会话中交流，自动派发任务、审查代码，还能中途打断或接力处理长时间任务，大幅减少人工干预。
  3. 实现难点在于逆向 Codex 协议，adapter 超两千行。 Claude 通过 MCP channel 接入，Codex 需逆向其 app-server 协议，中间进程管理连接和重连，协议适配层代码量巨大。
  4. 项目大部分功能由 agent 自举开发。 开发过程中，两个 agent 通过工具早期版本自行提交 PR、互相 review，提交记录全程可查，展示了 AI agent 协作完成自身进化的潜力。
