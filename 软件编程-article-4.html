Whale 的坦白书：一个 DeepSeek Coding Agent

6/25/2026, 10:00:10 AM

📌 一句话摘要

本文是一位开发者对自己开源的 DeepSeek Coding Agent 项目 Whale 的开发历程与技术反思，分享了工具调用、数据处理、工程质量、用户需求判断等方面的经验与教训。

📝 详细摘要

文章以坦白自述的方式，记录了作者从五一假期一时兴起开发 Whale（基于 DeepSeek 的 Coding Agent）到持续维护的心路历程。内容覆盖多个关键主题：工具调用的复用与偏差、用户会话数据对优化的核心作用、优化应基于真实基准而非抄袭特性、所有 Agent 项目都难以避免变成围绕 loop 的「屎山」、用户需求需根据项目阶段取舍、语言选择应考虑 TUI 生态等。作者还从使用者角度进行了反思：不要因 AI 提升产能就随意增加功能、LLM 不擅长复制已有实现（代码是信息压缩产物）、国产模型在进步但仍有差距、建议尽量使用官方 harness 以及在生产环境中做好隔离与预算管理。全文是坦诚的实践总结，对开发者与 AI Agent 使用者均有参考价值。

💡 主要观点

  1. 好的工具调用应该尽量复用业界成熟的方案。 复用 CC 等主流 coding agent 的工具命名与参数可降低 LLM 的困惑，减少 token 浪费与极端路径；Whale 在这方面已背上技术债。
  2. 用户会话数据是优化 Agent 的核心资源。 有了用户数据，工具调用错误可被充分复现与修复；作者认为应保留用户数据（在合规前提下）来提升 Agent 流畅度。
  3. 不要因为 AI 提升了产能就随意增加功能。 开源项目缺少企业约束时容易过度依赖 AI 引入新功能，但每个功能都有隐藏代价（如 /rewind 导致的磁盘暴涨），应优先把核心功能做顺。
  4. LLM 不擅长复制已有高质量实现。 代码是大量决策与踩坑后的信息压缩产物，LLM 能搭框架但无法补全细节密度，需要大量人工打磨。
  5. 尽量使用官方 harness，尤其是在生产环境。 官方团队有更多人力与数据，掌控模型训练，能调优工具调用与可靠性；个人主导的 Agent 项目可能存在安全与稳定性隐患。

💬 文章金句

  • 代码是「信息压缩」的产物。那些高质量开源项目的每一行代码都是大量决策、踩坑、重构后压缩成的最小表达。
  • LLM 并不擅长复制某个功能的实现。
  • 不要因为 AI 提高了产出能力就多做。
  • 尽量用官方的 harness。
