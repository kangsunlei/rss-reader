Elastic 构建 Elastic Cloud Serverless 的架构之旅

6/26/2025, 8:23:07 AM

📌 一句话摘要

Elastic 在主流云平台构建 Serverless Elasticsearch 的架构演进。

📝 详细摘要

本文详细介绍了 Elastic 如何将 Elasticsearch 这样的有状态系统转化为无状态、自动扩缩容的无服务器平台。文章概述了从本地存储到云原生对象存储的转变，旨在提升数据持久性和效率。同时，采用缓冲机制以应对对象存储 API 成本等挑战。该演进过程包括采用托管的 Kubernetes 服务，并利用 Crossplane 进行多云基础设施管理。文章重点介绍了诸如单元化架构等架构模式，以实现隔离和扩展，以及采用推送模型进行控制平面通信的决策。此外，还涉及采用 Cilium 进行网络连接以及调整现有入口代理等特定技术选择。文章还介绍了为索引和搜索工作负载定制的智能自动扩缩容控制器的开发，以及基于使用量的定价模型的实施。这些都突显了构建 Elastic Cloud Serverless 所涉及的技术复杂性和解决方案。

💡 主要观点

  1. 使用云原生对象存储从有状态架构转变为无状态架构。 将持久存储从计算节点卸载到对象存储，降低了基础设施开销，实现了搜索 / 索引分离，并通过 CSP 冗余提高了数据持久性。
  2. 通过缓冲和分离刷新操作来解决对象存储成本问题。 实施每个节点的事务日志缓冲以合并写入并将刷新与对象存储写入分离，从而在不牺牲持久性的前提下显著降低了 API 调用放大。
  3. 采用托管的 Kubernetes 和 Crossplane 进行基础设施管理。 利用 CSP 管理的 Kubernetes 和 Crossplane 标准化的 API，简化了操作，并通过 Kubernetes 原生工具实现了跨多云的一致的基础设施管理。
  4. 实施单元化架构和用于控制平面通信的推送模型。 使用独立的单元可提供故障隔离和可伸缩单元，而推送模型可简化控制平面逻辑并增强故障期间的数据平面弹性，从而提高运营稳健性。
  5. 为工作负载开发了智能自动扩缩容控制器。 构建特定于工作负载的自动扩缩器，分析实时指标以有效地为不同的 Elasticsearch 层（索引，搜索）动态调整计算和内存资源。

💬 文章金句

  • 如何采用像 Elasticsearch 这样的有状态、对性能至关重要的系统并使其无服务器化？
  • 关键的转变是将持久存储从计算节点卸载到云原生对象存储。
  • 通过采用 Kubernetes，我们降低了运营复杂性，标准化了 API 以提高可伸缩性，并将 Elastic 云定位为长期创新。
  • Crossplane 是一个开源项目，它扩展了 Kubernetes API，以支持使用 Kubernetes 原生工具和实践来配置和管理云基础设施和服务。
  • 为了提供真正的 Serverless 体验，我们需要一种智能的自动扩缩容机制，该机制可以根据工作负载需求动态调整资源。
