📝 详细摘要

本文深入探讨了在 Django 项目中如何正确获取和使用用户模型，旨在解决 Django 开发者在项目开发中常遇到的用户模型获取问题，以应对未来定制需求。文章强调了使用 ``get_user_model()`` 函数的重要性，以确保代码在默认用户模型和自定义用户模型之间切换时的兼容性。此外，还解释了何时以及如何使用 ``settings.AUTH_USER_MODEL`` 变量在数据库关系中引用用户模型。文章通过示例代码和常见问题解答，帮助开发者避免在处理 Django 用户模型时可能出现的错误，并提供了进一步学习的资源。

💡 主要观点

  1. ``get_user_model()`` 用于在 Python 代码中获取用户模型 此函数返回当前 Django 项目中配置的正确用户模型，无论是默认模型还是自定义模型，确保代码的灵活性和可维护性。
  2. ``settings.AUTH_USER_MODEL`` 用于在模型中引用用户模型 在定义 ForeignKey、OneToOneField 或 ManyToManyField 等数据库关系时，使用此变量可以确保关系始终指向正确的用户模型。
  3. 避免直接导入 ``from django.contrib.auth.models import User`` 模型以确保代码的未来兼容性 直接导入 `from django.contrib.auth.models import User` 会使代码依赖于默认用户模型，当切换到自定义模型时会导致代码中断。
  4. 尽早创建自定义用户模型 如果项目需要额外的用户信息（例如电话号码、生日等），建议尽早创建自定义用户模型，避免后期迁移的复杂性。
