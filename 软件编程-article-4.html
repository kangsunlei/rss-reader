AI UITester：AI Native 的 UI 自动化测试新范式｜得物技术

7/1/2026, 10:30:00 AM

📌 一句话摘要

本文介绍得物技术团队自研的 AI 原生 UI 测试工具 ai_uitester，通过 VLM 视觉驱动、LLM 用例自动生成和 AI 自愈调试，实现三端统一运维，大幅降低测试维护成本。

📝 详细摘要

文章首先分析传统 UI 自动化测试的三大痛点：用例迁移成本高、调试效率低、三端（iOS/Android/HarmonyOS）维护成本翻倍。然后介绍得物自研的 AI Native 方案 ai_uitester，其三大核心能力包括：基于 LLM 的用例平台数据自动转化（从描述性用例自动生成可执行脚本，结合 Wiki 知识库优化）；AI 智能调试与用例自愈（失败分类器过滤，VLM 诊断五类根因，自动修复并加入置信度机制确保安全）；VLM 驱动的跨平台统一执行（“截图→理解→执行”闭环，同一套脚本三端通用，天然免疫 UI 变更）。文章还讨论了设计取舍（逐步执行 vs 一次规划、置信度阈值 0.5、返回完整步骤列表而非增量 Diff），并与行业方案（Appium、Test.ai 等）进行对比，指出 AI Native 是测试范式的根本转变：从“代码驱动”到“视觉驱动”，从“人工调试”到“AI 自愈”，从“三端分离”到“统一抽象”。最后给出业务成果数据：测试执行效率提升 X 倍、自愈成功率 Y%等实测指标。

💡 主要观点

  1. AI UITester 以 VLM 为核心执行引擎，用“截图-理解-执行”闭环替代传统元素定位。 VLM 直接识别像素级截图，无需 DOM 结构，使跨平台天然统一，且能适应 UI 变更，按钮位置移动也能自动找到。
  2. LLM 自动将描述性用例转化为可执行脚本，结合 Wiki 知识库大幅降低迁移成本。 通过精心设计的 Prompt 工程和并行增强，Pipeline 可将平台 JSON 导出自动转化为包含 Tap、Assertion 等步骤的可执行脚本，人力投入从数人天降至分钟级。
  3. AI 智能调试实现流程级自愈，通过失败分类器和 VLM 诊断自动修复用例。 系统先过滤设备/网络等非业务失败，再对业务失败进行五类根因诊断，置信度高于阈值则自动修复并重新执行，低于阈值则弹出人工审核，遵循“宁可漏点，不可误点”原则。
  4. 设计取舍体现克制与稳健：逐步执行、置信度 0.5、自愈返回完整步骤列表。 逐步执行避免基于过时信息决策，置信度 0.5 经实测平衡召回与精度，完整步骤列表避免增量 Diff 的索引偏移风险，这些设计确保方案在真实场景中可靠落地。

💬 文章金句

  • 从“代码驱动”转向“视觉驱动”，从“人工调试”转向“AI 自愈”，从“三端分离”转向“统一抽象”。
  • 宁可漏点，不可误点。
  • AI Native 方案的假设是“UI 一定会变”，所以让 AI 理解变化并适应变化。这是测试哲学的根本转变——从“抵抗变化”到“拥抱变化”。
