OpenJDK 和 JCP 专家组的最新进展：Simon Ritter 的见解

12/22/2025, 11:00:00 AM

📌 一句话摘要

本播客邀请到 Simon Ritter 讨论了 Java 的演进，重点关注了六个月发布周期、JCP 专家组的角色以及 Leyden、JFR 和 CRaC 等关键 OpenJDK 项目。

📝 详细摘要

这期 InfoQ 播客邀请了 Azul 的副首席技术官 Simon Ritter，讨论了 OpenJDK 的最新发展以及他在 JCP 专家组的经验。主要议题包括成功的六个月发布周期，这种周期性使得功能交付和迭代更为迅速，例如“字符串模板”的撤回和重新评估，就体现了这一优势。对话强调了对 Java Flight Recorder 日益增长的关注，以增强 Java 应用程序的可观测性，包括用于方法计时和追踪的新 JDK 增强提案（JEPs），以及监控时面临的海森堡不确定性原理的挑战。Leyden 项目被介绍为 GraalVM 的替代方案，用于在不牺牲 Java 动态特性的前提下提高启动性能和减少预热时间。此外，Ritter 详细介绍了 Azul 开发的 CRaC 项目（协调检查点恢复），它提供了一种互补的解决方案，通过允许应用程序快照和恢复其状态（包括数据库连接）来实现快速应用程序启动，此功能现已集成到 Spring Boot 中并对 AWS SnapStart 的设计产生了影响。他还讨论了由于跨平台兼容性和架构阻力，将 CRaC 更广泛地集成到 OpenJDK 中所面临的挑战。

💡 主要观点

  1. 六个月发布周期显著加速了 Java 的演进和功能集成。 这种节奏可以实现更快的迭代，允许在最终确定之前完善甚至移除功能，这在更长的发布周期中是不可能的，“字符串模板”的被移除就是一个例证。
  2. Java Flight Recorder (JFR) 对于改进 Java 应用程序可观测性至关重要。 最新的 JDK 增强提案（JEPs）增强了 JFR 用于方法计时和追踪的能力，帮助开发者诊断性能瓶颈，同时注意监控中海森堡不确定性原理的影响。
  3. Leyden 项目通过优化类加载和代码编译来解决 Java 的预热时间问题。 Leyden 旨在实现快速启动和峰值性能，同时保留 Java 的动态特性，如反射和动态类加载，为 GraalVM 的封闭世界方法提供了一种替代方案。
  4. CRaC 项目提供了一种协调机制，用于快照和恢复 Java 应用程序状态。 由 Azul 开发的 CRaC 使应用程序能够通过在检查点之前优雅地处理初始化任务（如数据库连接）来实现即时启动，从而提高动态环境中的效率。

💬 文章金句

  • 六个月发布周期运行得非常好，特别是在少数情况下，比如在 Rampdown Phase One（特性冻结第一阶段）后移除某个功能，或者某个功能被撤回以进行进一步评估。
  • Java Flight Recorder 是一个非常棒的工具，因为它实际上利用了 JVM 已经收集的大部分信息。
  • Leyden 项目非常有意思，它允许你不必处于封闭的世界。你仍然可以用完全相同的方式进行反射。你可以进行动态类加载、动态字节码生成，所有这些都运行得非常好。
  • CRaC 的目标是说，‘好吧，超越那个’。并且与其只考虑初始启动，不如考虑一旦你到达主入口点，你就会开始执行应用程序特定的初始化。
