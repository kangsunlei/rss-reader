📝 详细摘要

本文是《打造高性能、低 CPU 消耗系统》系列的下篇，延续上篇的实战风格，聚焦后 18 种编码避坑技巧。内容涵盖避免 void/null 出参以减少异常和判空开销、避免多重否定以简化逻辑、严禁深层代码嵌套以提升 CPU 效率和可维护性、合理使用 final 和静态方法以利用 JVM 优化、优先使用 char/byte 原生类型进行底层操作以降低 GC 压力、集合初始化时指定容量以避免扩容开销、以及及时清空大集合和解除强引用以防止内存泄漏。每个技巧均配有核心原理、实现方式、注意事项和代码示例，基于真实高并发场景，具有很强的实用性和可操作性。

💡 主要观点

  1. 通过返回值优化减少运行时开销 避免 void 和 null 返回，使用空集合或布尔值，减少异常处理和条件判断的 CPU 消耗。例如，void 返回导致必须抛异常，增加重量级 CPU 操作；null 强制判空引发分支预测失败和 NPE 风险。空集合如 Collections.emptyList()是单例零 GC 方案。
  2. 简化条件逻辑和代码结构 避免多重否定和深层嵌套，采用正向判断和扁平化结构，提升代码可读性和执行效率。多重否定增加阅读成本易出 BUG；深层嵌套破坏 CPU 流水线，JIT 优化困难。通过卫语句、条件反转和 Map 分发实现扁平化。
  3. 利用 JVM 特性优化方法调用 优先使用 final 和静态方法，实现早期绑定和 100%内联，降低调用开销。静态和 final 方法在编译期确定目标，无需动态分派和方法表查找，减少 CPU 指令。适用于工具类、无状态方法，但需注意 Spring AOP 代理限制。
  4. 底层数据操作使用原生类型 在 IO 和文本处理中优先使用 char/byte，避免 String 封装，减少 GC 和指令开销。char/byte 直接存储在栈或数组中，无对象头，速度比 String 快 5-50 倍。适用于网络协议、文件操作等场景。
  5. 集合和内存管理优化 集合初始化时指定容量避免扩容，及时清空大集合释放内存，防止 GC 压力。扩容涉及数组复制和 GC 垃圾；大集合强引用导致对象滞留老年代。使用 addAll 前预估容量，业务完成后调用 clear()或置空引用。

💬 文章金句

  • void = 无状态反馈 → 必须抛异常 → CPU + GC 开销剧增
  • null = 强制调用方判空 → 大量 if 分支 → CPU 分支预测失败
  • final 方法、静态方法，是 JVM 唯一可以在编译期 / 类加载期就确定调用目标的方法，完全不需要动态分派、多态查找、虚方法表搜索，性能是最高的。
  • char/byte 是栈上 / 连续内存直接访问，速度比 String 快 5~50 倍。
  • 集合初始化指定预估容量，避免集合在添加元素时自动触发扩容机制。
