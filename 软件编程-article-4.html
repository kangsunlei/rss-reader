日志采集效能跃迁：iLogtail 到 LoongCollector 的全面升级

5/14/2025, 12:31:00 AM

📌 一句话摘要

介绍了阿里云日志采集工具 iLogtail 升级为 LoongCollector 的背景、架构优化、性能提升、稳定性改进以及迁移方案，旨在提升日志采集效能。

📝 详细摘要

本文详细介绍了阿里云日志采集工具 iLogtail 升级为 LoongCollector 的背景和技术演进。LoongCollector 采用总线模式架构，通过高性能 Pipeline 流水线，实现了输入、处理和输出能力的彻底插件化，支持多种 Pipeline 形态，满足不同场景需求，并在多租户隔离方面做了优化。在性能方面，LoongCollector 显著降低了 CPU 和内存占用，提升了核心场景的采集速率。同时，LoongCollector 提供了全面的实例监控、文件采集监控和 Pipeline 详情监控，增强了自监控能力，并扩展了可观测性，例如支持 Prometheus 指标采集和 eBPF 采集。此外，LoongCollector 还通过流量分配机制和网络质量自动探测，提高了网络异常隔离能力和数据发送稳定性。为方便用户迁移，LoongCollector 提供了完整的、无中断存量迁移方案，并优化了 Tag 标签处理能力。最后，文章展望了 LoongCollector 在可观测数据全栈采集方面的未来发展。

💡 主要观点

  1. LoongCollector 通过插件化的 Pipeline 流水线架构提升了灵活性和性能 插件化的输入、处理和输出能力，支持自由组合，满足不同场景需求，同时降低了 CPU 和内存占用。
  2. 总线模式下的流量控制和网络质量探测增强了稳定性 通过 AZ、Project 和 Logstore 三个维度的流量控制，以及自动切换 SLS 域名，提高了网络异常隔离能力和数据发送稳定性。
  3. LoongCollector 提供全面的监控功能，增强了可观测性 提供实例监控、文件采集监控和 Pipeline 详情监控，帮助用户清晰掌握系统资源占用和实例异常信息。
  4. 无中断迁移方案和优化的 Tag 处理能力提升了用户体验 支持从 iLogtail 无缝升级到 LoongCollector，并对标签数据进行统一处理，方便用户使用。

💬 文章金句

  • LoongCollector 在日志场景中实现了全面的重磅升级，从功能、性能、稳定性等各个方面均进行了深度优化和提升
  • CPU 平均降低 35%，内存平均降低 10%
  • LoongCollecoter 以 iLogtail 高性能 Pipeline 为底座，将 Prometheus 指标采集、eBPF 采集等融入 iLogtail 采集流水线中，实现采集能力的全面升级，做到可观测采集的 OneAgent 化。
  • LoongCollector 对流水线的生命周期管理进行了进一步优化，只对于有变化的 Pipeline 采用新旧替换的方式，其他没有变化的 Pipeline 保持不变，最大程度上保证采集配置变更影响最小化，避免 Stop The World 对整体的影响。
