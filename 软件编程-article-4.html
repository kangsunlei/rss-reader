在 SLO 不达标重复发生前修复：一款用于应用工作负载的 SRE AI 代理

12/29/2025, 3:09:00 PM

📌 一句话摘要

本文提出 SRE AI 代理，利用现有性能工具与方法论，结合 AI/LLM，自动化 SLO 不达标的诊断与解决，显著缩短平均恢复时间（MTTR）。

📝 详细摘要

本文介绍了一款 SRE AI 代理，旨在自动化应用工作负载中 SLO 不达标的诊断和潜在解决方案，尤其适用于 Java 和.NET 环境。文章强调，性能关乎满足期望，平衡速度、成本和客户满意度，而不仅仅是原始速度。作者详细阐述了性能诊断的方法论，使用诸如 USE 方法和 Kirk Pepperdine 的 Java 性能诊断模型（jPDM）等概念，系统地识别瓶颈。核心思想是利用 AI 和大型语言模型（LLM）与现有监控和性能工具（MCP 工具）结合，将平均恢复时间（MTTR）从数小时乃至数天大幅缩短至数秒乃至数分钟。提议的 SRE 代理将持续监控系统，对瓶颈进行分类（系统侧瓶颈与应用侧瓶颈），对问题进行详细诊断（例如 GC 暂停、内存泄漏），甚至自动提出或应用纠正措施，从而提高效率和可靠性，同时减少人工干预。

💡 主要观点

  1. 性能是速度、成本和客户期望之间的平衡，而不仅仅是原始速度。 有效的系统性能在于优化效率和可靠性，确保应用持续达成目标，避免资源过度消耗及频繁故障，而非仅追求运行速度。
  2. 系统化方法对于性能诊断和瓶颈识别至关重要。 利用像 USE 方法和 Java 性能诊断模型（jPDM）这样的结构化方法来分类现有瓶颈（系统侧瓶颈与应用侧瓶颈），使诊断过程一致且高效。
  3. SRE AI 代理可通过自动化诊断显著缩短平均恢复时间（MTTR）。 通过将 AI 和大型语言模型（LLM）与现有监控和性能工具（MCP 工具）集成，SRE 代理可以自动分析 SLO 不达标问题，识别根本原因，并能在数分钟（而非数小时或数天）内生成或实施修复方案。
  4. 超越观察和警报，深入诊断和修复的自动化是 SRE 的下一个前沿。 尽管许多团队自动化了警报和缓解措施，但通过 AI 在诊断复杂问题和提供可操作建议方面进行更深层次的自动化，SRE 和开发人员能够更主动地解决性能问题。
