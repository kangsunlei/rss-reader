通过具有成本意识的 AWS KMS 密钥策略简化多租户加密 | 亚马逊云服务

8/21/2025, 2:54:51 PM

📌 一句话摘要

本文详细介绍了一种经济高效的 AWS KMS 策略，用于多租户 SaaS 环境。该策略集中密钥管理，并利用跨账户 IAM 来简化加密并降低运营成本。

📝 详细摘要

本文旨在解决在 AWS 上，多租户、多服务 SaaS 架构中管理加密密钥时，面临的复杂且高成本挑战。文章指出了为每个租户和服务配置独立的 AWS KMS 客户托管密钥，会导致运营开销和成本增加。为此，提出了一种集中式密钥管理策略：每个租户在多个服务和 AWS 账户中使用单个对称客户托管密钥。这种方法将密钥生命周期管理（创建、别名、策略、删除）集中在专用账户（服务 A）中，并允许其他服务（服务 B）通过跨账户 IAM 角色委托安全地访问租户特定的密钥。本文提供详细的步骤，包括 IAM 策略示例和 Python 代码片段，演示了服务 B 如何动态地承担具有会话范围策略的角色，从而为特定租户加密数据。该方案的优势包括严格的租户隔离，通过减少密钥激增实现的显著成本优化，以及通过一致的密钥生命周期管理和改进的审计能力实现的精简运营和提升治理水平。

💡 主要观点

  1. 在服务之间集中每个租户的 KMS 密钥管理可以显著降低成本和复杂性。 每个租户从使用多个服务特定密钥转为使用单个共享密钥，能够优化 AWS KMS 成本，并简化密钥管理。
  2. 跨账户 IAM 角色委托可以通过细粒度的控制实现安全且可扩展的密钥访问。 通过承担具有会话范围 IAM 策略的角色，服务仅能访问特定租户的 KMS 密钥，从而确保数据隔离，同时保持密钥管理的集中化。
  3. 尽管使用集中的密钥管理方法，但此策略仍保持严格的租户数据隔离。 每个租户的数据都使用其专用密钥加密，并通过唯一的别名标识。同时，通过 IAM 采用最小权限原则严格控制访问。

💬 文章金句

  • 在本文中，我们揭示了一种策略，该策略在服务之间为每个租户使用单个客户托管密钥（对称）。
  • 解决方案在于实施集中的密钥管理策略：每个租户一个 KMS 密钥，保存在中央 AWS 账户中。
  • 服务 B 临时承担账户 A 中的 `ServiceARole` 角色，获得该租户 KMS 密钥的细粒度、范围受限的权限。
  • 为了安全且大规模地加密租户机密，我们授予应用程序角色通过别名对 KMS 密钥的跨账户访问权限。该别名映射到 JWT 身份验证令牌中的租户标识符，从而加强隔离。
  • 尽管减少了 KMS 密钥的总数，但我们仍保持严格的租户隔离。
