Node.js — 为 React、Next.js 和 APM 用户缓解不可恢复栈空间耗尽导致的拒绝服务漏洞

1/13/2026, 5:00:00 PM

📌 一句话摘要

一个关键的 Node.js 漏洞在使用 `async_hooks`（被 React、Next.js 和 APM 使用）时会导致不可恢复的崩溃，由于栈耗尽将 `RangeError` 转变为立即的进程退出。

📝 详细摘要

这篇来自 Node.js 博客的文章讨论了一个关键的拒绝服务漏洞，源于不可恢复的栈空间耗尽。当启用 `async_hooks`（或基于它构建的 `AsyncLocalStorage`）时，用户代码中的深度递归，特别是在创建 Promise 时，可能导致 Node.js 立即退出并返回代码 7，而不是抛出可捕获的 `RangeError`。这意味着应用程序无法优雅地处理栈溢出，使其容易受到通过恶意构造输入（例如深度嵌套的 JSON）的 DoS 攻击。这个问题广泛影响了像 React Server Components 和 Next.js 这样的框架，以及几乎所有广泛使用 `async_hooks` 进行上下文跟踪的应用性能监控（APM）工具。文章解释了该 bug 的技术细节，展示了 `async_hooks` 机制中的 `TryCatchScope::kFatal` 如何意外捕获用户发起的栈溢出。已实施修复以将栈溢出错误重新抛出到用户代码。虽然修复缓解了立即崩溃，但文章强调依赖未指定的栈溢出行为进行安全保护是不可靠的，并建议开发人员实施强大的输入清理和递归深度限制。

💡 主要观点

  1. 当 `async_hooks` 或 `AsyncLocalStorage` 处于活动状态时，Node.js 漏洞会导致立即进程退出（退出代码 7），而不是在栈溢出期间抛出可捕获的错误。 此 bug 阻止应用程序优雅处理 `RangeError: Maximum call stack size exceeded`，使其容易受到通过精心构造的递归输入进行的拒绝服务攻击，因为 Node.js 进程会直接崩溃。
  2. 该漏洞广泛影响了 Node.js 生态系统的很大一部分，包括 React Server Components、Next.js 和所有主要的 APM 工具。 `AsyncLocalStorage`（被 React/Next.js 用于上下文跟踪）和直接的 `async_hooks` 使用（在 APM 中常见）会触发此行为，使许多广泛部署的应用程序易受攻击。
  3. 问题源于 `async_hooks` 回调在与用户代码相同的调用栈上运行，其中 `TryCatchScope::kFatal` 意外地将用户发起的栈溢出视为致命的钩子错误。 当栈耗尽发生在 `async_hooks` 回调处于活动状态时（例如在 `new Promise()` 期间），`TryCatchScope` 的 `kFatal` 模式将用户代码产生的错误误解为不可恢复的内部钩子错误，强制进程退出。
  4. 通过将栈溢出错误重新抛出到用户代码的修复缓解了问题，但强大的输入清理和递归深度限制仍然是关键的防御措施。 虽然 Node.js 现在修补了此特定行为（针对 20+ 版本），但文章强调底层的 `RangeError` 是未指定的 ECMAScript 行为；因此，应用程序不得依赖它进行安全保护，应实施自己的防御措施来应对递归输入攻击。
  5. 使用 `AsyncContextFrame` 的现代 Node.js 版本（24+）不受此特定 bug 影响，但直接使用 `async_hooks` 的 APM 工具仍然受影响。 `AsyncContextFrame` 将 `AsyncLocalStorage` 与有问题的 `async_hooks.createHook()` 机制解耦，提高了性能并为使用它的框架避免了此 bug。然而，直接与原始 `async_hooks` 集成的 APM 工具在所有 Node.js 版本中仍然易受攻击。

💬 文章金句

  • 一个仅在启用 `async_hooks` 时重现的 bug 会破坏此尝试，导致 Node.js 直接退出并返回代码 7，而不会在用户代码中的递归耗尽栈空间时抛出可捕获的错误。
  • 讽刺的是：您安装用于监控和调试崩溃的工具可能会使一类崩溃表现不同。
  • 对于必须防御无限递归或来自攻击者可控制深度的递归导致的栈溢出的关键任务路径，始终清理输入或通过其他方式限制递归深度。
  • 错误源于用户代码（递归模式），但由于它在钩子回调是活动帧时表现出来，因此被视为致命的钩子错误。
  • 此 bug 突显了 `async_hooks` 在 Node.js 生态系统中嵌入的深度。
