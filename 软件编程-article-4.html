得物推荐系统诊断 Agent：从 “调接口” 到 “会思考”｜AICon 演讲整理

7/13/2026, 10:30:00 AM

📌 一句话摘要

得物通过自研的 “推查查” 系统，结合 Highway 高速剧本流水线与 ATV ReAct 智能体，实现推荐异常的自动化、可追溯且可进化的诊断。

📝 详细摘要

本文是得物技术在 AICon 上海大会的演讲实录，系统化阐述了推荐系统诊断平台 “推查查” 的整体架构与实现细节。文章首先回顾了从人工排查到平台工具的演进，指出传统方案的线性脚本、纯 Agent 效率低和知识孤岛三大局限。随后介绍了基于 OpenClaw 的混合智能体架构：Highway 负责 80% 常规问题的标准 Story 流水线，ATV 采用 ReAct 循环处理 20% 长尾复杂异常，并通过智能调度器实现无缝切换。核心技术包括原子化 Skill、Story 编排、ReAct 约束（迭代上限、工具白名单、置信度阈值）以及 OpenViking+Graphify 的本地向量检索与知识图谱。文章进一步描述了进化层的“反思‑抽象‑验证”闭环，实现从排查记录到可复用方法论的自动蒸馏与上线审核。最后通过商品重复推荐案例展示了系统的端到端诊断与修复建议，强调 AI 诊断从工具向具备学习与预防能力的智能体转变。

💡 主要观点

  1. 传统推荐诊断方案存在脚本僵化、效率鸿沟和知识孤岛三大局限。 固定 SOP 脚本难以适配业务快速迭代，纯 LLM Agent 成本高且易出现幻觉，经验沉淀缺乏机制导致人员更迭时知识流失。
  2. “推查查” 采用 Highway 与 ATV 双轨混合智能体，实现快速与深度的互补。 Highway 通过标准 Story 流水线处理常规异常，ATV 基于 ReAct 循环自主推理处理长尾复杂问题，并通过智能调度器实现无缝切换。
  3. 原子化 Skill 与 Story 编排提供了可热插拔、确定性的治理框架。 Skill 作为插件化的底层能力，Story 将其按顺序编排为确定性剧本，支持条件分支、版本控制和自动降级到 ATV。
  4. 进化层通过反思‑抽象‑验证闭环将排查经验自动蒸馏为可复用的 Skill/Story。 系统回放历史案例，压缩思考路径，抽象出业务变量并生成结构化技能，经过 Dry‑Run 与 90% 以上一致性校验后上线 Highway。

💬 文章金句

  • 它是推荐系统领域的 "自动驾驶诊断专家"，让复杂的算法逻辑变得透明、可追踪、可预测。
  • Highway 负责处理 80% 的常见问题，ATV 则是我们的王牌侦察兵，专啃 20% 的长尾、复杂硬骨头。
  • 每步推理都要自问 '这个结论靠谱吗'，不靠谱就换思路，拒绝盲目自信。
