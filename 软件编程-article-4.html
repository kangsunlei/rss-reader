打破“人月神话”，Agent 重塑风控场景产运研职能

7/20/2026, 9:57:00 AM

📌 一句话摘要

本文基于快手风控团队半年实践，系统分享了通过 AI Agent 重塑产品、运营、研发职能、构建液态组织的转型经验与教训。

📝 详细摘要

文章是快手磁力引擎风控技术负责人在 QCon 2026 的分享实录，从 AIGC 时代安全、效率、体验的不可能三角被推向极限出发，指出传统固态组织已被“协调税”压垮，必须向“液态组织”转型。在产品层面提出 P2P（Prompt to Product）模式，让产品经理直接交付原型；运营层面从规则配置升级为 Prompt Engineer、RAG 运营再到模型教练；研发层面经历了 IDE、Vibe Coding 到 CLI 模式的演进，并对算法团队强调向下深耕模型与构建数据飞轮。文章还坦诚复盘了 Vibe Coding 工程落地坑（Demo 惊艳、生产崩塌）、增量与存量项目差异、团队管理面面俱到引发冲突三大教训，最后给出推行 Token 经济学与 Skills 贡献度考核、应用逆康威定律、做“眼高手低”技术人三条组织行动建议。

💡 主要观点

  1. 传统产运研固态组织已被“协调税”压垮，必须向以数据为中心的液态组织转型。 技术已进入 AI Native 阶段，但组织仍停留在软件 1.0 分工范式中。产品、运营、研发、算法应打破部门墙，每个人都向价值链上游升级。
  2. 产品经理可通过 P2P 模式直接用 Prompt 交付原型，运营角色从规则配置跃升为模型教练。 P2P（Prompt to Product）让产品绕过研发排期独立完成原型；运营经历 Prompt Engineer、RAG 运营、模型教练三个阶段，将领域知识注入大模型。
  3. 研发需逃离“职业阶梯中空化”的 Danger Zone，用 Code Agent 把自己武装成小军团。 初级研发被大模型和资深同事挤压，必须掌握 CLI 模式下的 Agent 开发，以 Token 消耗量和 Skills 贡献度衡量效能。
  4. Vibe Coding 在工程落地中存在确定性要求与概率性输出的根本矛盾，需转向 Spec-Driven Development。 Demo 表现惊艳但生产环境常因上下文腐化而崩塌，SDD 通过从提议、设计、Spec 到测试的严密封装来控质。
  5. 组织转型切忌面面俱到，应遵循“试、推、升”三步走。 先试点局部成功，再小范围推广，最后全面重塑；管理上需调整汇报线、降低层级深度，避免冲突。

💬 文章金句

  • 唯一的护城河，是你和你的组织进化的速度。
  • Demo 惊艳全场，生产一塌糊涂。
  • 做‘眼高手低’的技术人——眼高在于洞察，手低在于手不能离开一线。
  • 低代码平台正在消亡……它实际上是限制了优秀产品经理的想象力。
