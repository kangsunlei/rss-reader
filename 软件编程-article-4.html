Harness Inspector：让 Agent 交付过程可观察、可检查、可追溯

8/14/2026, 8:53:00 AM

📌 一句话摘要

本文介绍 Harness Inspector，一个将需求、Agent Session、文件活动与 Git Commit 连接在同一界面的本地只读工作台，用于观察和追溯 AI Agent 的完整交付链路，并为 SKILL 自动沉淀提供基础。

📝 详细摘要

文章介绍 Harness Inspector 的设计动机与核心功能。作者团队在优化 Better Harness 的 SKILL 自动沉淀能力时发现，仅分析 Agent Session 无法判断行为背后的意图与最终产出之间的关系，因此将一次交付拆分为意图（Intent）、过程（Process）和产出（Output）三段，并通过 Workbench、Trace、Replay 三种观察方式将其连接。Workbench 展示需求、Session 与 Commit 之间的整体关系；Trace 按 Turn 组织 Session 内部的工作轨迹；Replay 沿事件顺序回看任务展开过程。文章强调，只有先看清交付证据，才能区分噪声与值得沉淀的经验路径，SKILL 自动沉淀的真正基础是完整的交付可追溯性，而非简单的 Session 总结。

💡 主要观点

  1. Agent 交付是一条从意图到产出的连续链路，Session 只是中间环节。 一次软件开发任务从需求出发，经过 Agent 的理解、探索、修改和验证，最终形成代码 Commit。只看 Session 无法判断行为动机与最终产出之间的关系。
  2. Harness Inspector 提供三种观察方式：Workbench 看关系、Trace 看结构、Replay 看顺序。 Workbench 连接需求、Session 与 Commit 的整体视图；Trace 按 Turn 组织 Session 内部的工作轨迹；Replay 沿事件顺序回看任务展开过程，三者互补。
  3. SKILL 自动沉淀的基础是可追溯的交付证据，而非 Session 总结。 频繁出现的 Tool Call 可能是噪声而非经验，只有将行为放回 Story、Session 和 Commit 中，才能判断其是否为稳定可迁移的工作方式。
  4. 关系证据不足时保留为候选，不自动拼接完整路径。 Workbench 强调展示已观察到的关系，而非推断出看起来完整的交付路径，避免产生误导性结论。

💬 文章金句

  • Session 只是这条链路的中间部分。真正需要观察的并不是会话本身，而是一次软件变更如何从一个意图出发，经过 Agent 的执行，最终形成可以进入工程系统的产出。
  • 能够把一次交付连接起来，并不意味着我们已经能够读懂它。
  • 答案显然不是出现次数最多的 Tool Call。Agent 可能因为上下文不足而反复读取同一个文件，也可能因为命令失败不断重试；这些行为虽然频繁出现，却更可能是一次交付中的噪声。
