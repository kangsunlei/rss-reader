Claude Code 里遇到“用户没说过的话”被当成用户输入，排查后像是 tool_result / user turn 边界错乱

6/13/2026, 4:31:16 PM

📌 一句话摘要

本文作者在 Claude Code 长会话中遇到模型将工具输出和自身推理误判为用户输入，并据此自动修改文件的严重问题，经排查后怀疑是 harness 层 user/tool 边界错乱所致。

📝 详细摘要

作者在使用 Claude Code 2.1.177 进行 Flutter 项目安全加固时，多次发现模型将其未说过的话当作用户输入，并基于这些「输入」继续分析甚至自动写入文件。典型现象包括：模型引用一段来自 shell 工具输出的版本号作为「用户原话」；模型在内部思考中提及的「用户消息」经查原始 JSONL 记录实为 tool_result。作者排除了本机被黑、代理/MITM 等外部因素，并引用了多个 GitHub issue 证实该问题并非孤例。文章详细记录了排查过程、临时处理措施（降级、关闭自动编辑、移除通配符权限等），并提出了关于 agent 工具中 user/tool/system/harness 边界安全的深层思考。

💡 主要观点

  1. Claude Code 在长会话中会将 tool_result 或模型自身推理误判为用户输入。 作者通过对比本地 JSONL transcript 发现，模型声称的「用户原话」实际来自 shell 工具输出或 tool_result，而非真实用户消息。
  2. 该问题在开启 acceptEdits 时可能导致模型擅自修改文件。 由于模型将错误归因的用户指令与自动写权限结合，作者遭遇了模型自行写入 memory 文件的情况，构成实际安全风险。
  3. 问题根源在于 harness 层 user/tool/system 边界不够硬。 作者认为，当 agent 工具的上下文管理机制无法严格区分消息来源时，模型容易产生归因漂移，进而将非用户指令当作指令执行。

💬 文章金句

  • Claude 多次把我没有说过的话当成我的输入，并基于这些「输入」继续分析、写文件。
  • 这个问题危险点不在于「模型胡说」本身，而在于 Claude Code 这种 agent 工具会把模型判断连接到真实文件操作。
  • 如果 user/tool/system/harness 的边界不够硬，模型把 tool_result 或自己的推理当成用户指令，再叠加自动写权限，就可能真的改文件。
