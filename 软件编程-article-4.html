Discord 如何利用高性能技术存储数万亿条消息

7/8/2025, 3:30:51 PM

📌 一句话摘要

本文详细介绍了 Discord 如何成功地对其消息存储进行重新架构，从 Apache Cassandra 过渡到 ScyllaDB。通过实施基于 Rust 的数据服务层，实现了高性能和稳定的运维，成功处理了数万亿条消息。

📝 详细摘要

本文深入分析了 Discord 如何扩展其消息存储以处理数万亿条消息，解决了其最初基于 Apache Cassandra 的架构所面临的挑战。文章重点介绍了诸如热分区、读取延迟高、由于压缩导致的高运营开销以及在极端规模下出现的 JVM 垃圾回收问题。为了克服这些问题，Discord 迁移到 ScyllaDB，利用其 C++ 实现获得更好的性能和无 GC 停顿，并利用其基于单核分片的架构来提高隔离性。至关重要的是，他们引入了一个基于 Rust 的数据服务层，作为中间层来控制并发、保护数据库免受过载影响，并实施请求合并。迁移过程涉及双写和一个基于 Rust 实现的自定义回填工具，在零停机前提下快速完成。迁移后，Discord 取得了显著的改进，包括减少了节点数量、降低了延迟并增强了运营稳定性，成功经受住了 2022 年 FIFA 世界杯决赛期间的严峻考验。

💡 主要观点

  1. Apache Cassandra 在 Discord 的大规模应用中面临着严重的运营和性能问题。 由于热分区、压缩滞后导致的读取速度慢以及频繁的 JVM 垃圾回收暂停等问题，Cassandra 逐渐成为瓶颈，需要不断的人工干预并阻碍了系统增长。
  2. ScyllaDB 提供了一种兼容但性能更高且更稳定的数据库解决方案。 通过切换到 ScyllaDB（基于 C++，单核分片），Discord 消除了 GC 问题并实现了可预测的性能，同时保持了与其现有数据模型和查询语言的兼容性。
  3. 基于 Rust 的数据服务层对于保护数据库和提高并发性至关重要。 这个中间层使用 Rust 构建，具有原生性能和并发安全性，实现了请求合并和一致性哈希路由，从而显著降低了数据库负载并提高了整体系统弹性。

💬 文章金句

  • 在这个规模下，即使是最小的架构选择也会产生很大的影响。
  • 最终，旨在随 Discord 扩展的数据库已成为瓶颈。
  • ScyllaDB 作为一种自然的替代方案进入视野。它保留了与 Apache Cassandra 的查询语言和数据模型的兼容性，这意味着周围的应用程序逻辑可以基本保持不变。
  • 它们背后的目标很简单：隔离高吞吐量操作、控制并发并保护数据库免受意外过载。
  • 自定义迁移器实现了每秒 320 万条消息的吞吐量，从而将总迁移时间从几个月减少到仅 9 天。
