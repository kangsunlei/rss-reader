加强供应链安全：为下一次恶意软件攻击做好准备

12/23/2025, 3:52:08 PM

📌 一句话摘要

文章详细介绍了针对 JavaScript 供应链的 Shai-Hulud 恶意软件攻击活动，概述了攻击者的策略，并为维护者和用户提供了可操作的建议，同时介绍了 npm 未来的安全路线图。

📝 详细摘要

这篇来自 GitHub 博客的文章分析了 Shai-Hulud 恶意软件攻击活动，这些活动代表了对开源 JavaScript 供应链不断演变的威胁。文章解释了攻击者如何快速迭代，利用维护者工作流，并通过受损凭据和恶意软件包生命周期脚本，在发布管道中利用信任边界。文章强调了这些攻击的关键特征，包括凭据关联泄露、模糊化处理的安装时执行、针对受信任命名空间以及快速迭代以绕过防御。然后，文章概述了 npm 的安全路线图，重点是批量 OIDC 接入、扩展 OIDC 供应商支持和分阶段发布。最后，它为所有用户和维护者提供了实用建议，强调了抗钓鱼 多因素认证 (MFA)、令牌过期、审计 GitHub/OAuth 应用、使用沙盒、启用分支保护、利用可信发布、固定 CI 依赖项以及监控软件包工件，以增强供应链安全性。

💡 主要观点

  1. Shai-Hulud 攻击活动利用受损凭据和恶意脚本感染 JavaScript 供应链。 攻击者通过窃取的凭据获得初始访问权限，然后使用恶意的安装后脚本来窃取秘密并传播恶意软件，目标是软件发布过程中的关键点。
  2. 攻击者的手段迅速适应，需要主动和持久的防御策略。 恶意软件变体之间的时间间隔很短，且规避技术复杂，这要求防御者专注于加强发布模型和凭据流程，而不是被动应对特定的攻击模式。
  3. npm 正在通过 OIDC 支持和分阶段发布增强其安全功能。 未来的 npm 开发旨在通过 OIDC 接入简化安全发布，并为维护者提供软件包上线前的审查期，从而提供更强的防止恶意插入的控制。
  4. 实施安全最佳实践对所有用户和维护者至关重要。 建议包括启用抗钓鱼 多因素认证、设置令牌过期、审计应用、使用沙盒、启用分支保护以及利用可信发布来缓解供应链风险。

💬 文章金句

  • 虽然各个事件在机制和速度上有所不同，但模式是一致的：攻击者学习迅速，瞄准维护者工作流，并利用发布管道中的信任边界。
  • Shai-Hulud 攻击活动并非孤立的入侵，而是针对维护者工作流和 CI 发布管道中的信任边界，重点是凭证收集和安装时执行。
  • 变体之间的时间缩短表明有组织的攻击者正在研究社区防御措施并迅速对其进行迭代。
  • 这使团队能够在意外更改影响到下游用户之前发现它们——社区多年来一直要求具备这项功能。
