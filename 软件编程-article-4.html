Markdown 已过时？Claude Code 工程师、卡帕西纷纷力挺 HTML

5/14/2026, 5:46:00 AM

📌 一句话摘要

本文编译自 Claude Code 工程师 Thariq Shihipar 的观点，他认为在 AI Agent 时代，HTML 比 Markdown 更适合作为 AI 的默认输出格式，因其能承载更高信息密度、提供更佳视觉体验和交互能力。

📝 详细摘要

文章围绕「AI 输出格式从 Markdown 转向 HTML」这一趋势展开。核心观点来自 Anthropic 旗下 Claude Code 工程师 Thariq Shihipar，他公开表示自己已几乎完全放弃 Markdown，转而让 AI 直接输出 HTML。Andrej Karpathy 也公开支持这一做法，并提出了 AI 输出形式的演化路径：纯文本 → Markdown → HTML → 交互式视频/模拟系统。文章详细列举了 HTML 相比 Markdown 的五大优势：更高的信息密度（可嵌入表格、SVG、交互元素）、更好的视觉清晰度与阅读体验、便于分享（直接生成链接）、支持双向交互（滑块、调节旋钮等）、以及更愉悦的创作体验。同时，文章也展示了 HTML 在规范规划、代码评审、设计原型、报告研究和自定义编辑界面等场景的具体应用案例。最后，文章也客观讨论了 HTML 的缺点，包括 Token 消耗更大、生成时间更长（约 2-4 倍）、版本控制差异对比杂乱等，并呈现了社区中关于「HTML 是否会削弱人机共同编辑能力」的争议。

💡 主要观点

  1. Claude Code 工程师 Thariq Shihipar 主张用 HTML 替代 Markdown 作为 AI 默认输出格式。 他认为 Markdown 难以承载 AI Agent 时代的高信息密度，而 HTML 能提供更灵活的布局、更丰富的视觉层次和交互能力，让 AI 输出从「文档」变成「界面」。
  2. HTML 相比 Markdown 有五大核心优势：信息密度、视觉清晰度、便于分享、双向交互和创作体验。 HTML 可嵌入表格、SVG、交互元素等，阅读体验远优于长 Markdown 文档；可直接生成链接分享；支持滑块、旋钮等交互控件；且创作过程更有乐趣。
  3. HTML 在规范规划、代码评审、设计原型、报告研究和自定义编辑界面等场景有广泛应用。 Thariq 展示了多个具体案例，如用 HTML 生成多方案对比页面、PR 代码说明、交互动效原型、多源信息整合报告，以及一次性专用编辑器等。
  4. HTML 方案也存在 Token 消耗大、生成时间长、版本控制困难等缺点。 HTML 生成时间约为 Markdown 的 2-4 倍，版本差异对比杂乱，且社区担忧 HTML 可能削弱开发者直接编辑内容的能力，增加协作复杂度。

💬 文章金句

  • 说实话，我现在几乎完全不用 Markdown 了。
  • 动辄上百行的 Markdown 文件，读起来其实很吃力。
  • HTML 则开始让 AI 输出从「文档」变成「界面」。
  • 用 HTML 时，我比以往任何时候都更有掌控感。
  • HTML 表达力更强，我也更愿意去读，整体产出效果反而更好。
