Apache HTTP/2 炸弹漏洞 PoC 公开，可远程耗尽服务器内存

6/19/2026, 11:18:00 AM

📌 一句话摘要

Apache HTTP 服务器 HTTP/2 炸弹漏洞（CVE-2026-49975）PoC 已公开，攻击者可远程耗尽服务器内存导致拒绝服务，影响 2.4.17 至 2.4.67 版本，建议立即升级至 2.4.68。

📝 详细摘要

本文报道了 Apache HTTP 服务器中一个名为「HTTP/2 炸弹」的关键拒绝服务漏洞（CVE-2026-49975），其 PoC 利用代码已在 GitHub 公开。文章详细解释了漏洞的技术原理：漏洞存在于 HTTP/2 请求处理路径中，当处理多个 Cookie 头字段时，系统合并字段但未正确计入 LimitRequestFields 指令限制，从而绕过资源保护。攻击者可构造一个经 HPACK 编码的小型请求，解压缩后生成大量 Cookie 头字段，迫使服务器重复分配内存，并利用 HTTP/2 流量控制机制（初始窗口设为零）使流保持开放，阻止内存释放，最终导致内存耗尽。文章指出该漏洞影响 Apache HTTP 服务器 2.4.17 至 2.4.67 版本，已在 2.4.68 中修复。PoC 使用 Python 脚本，可在 Docker 化环境中复现，支持配置连接与流数量、HPACK 引用、流量控制保持和滴灌式传输等参数。最后给出了升级、临时禁用 HTTP/2 和监控内存增长等缓解措施建议。

💡 主要观点

  1. Apache HTTP/2 炸弹漏洞（CVE-2026-49975）PoC 已公开，可远程耗尽服务器内存。 漏洞存在于 HTTP/2 请求处理路径中，通过构造特殊请求绕过 LimitRequestFields 限制，利用流量控制机制阻止内存释放，导致拒绝服务。
  2. 影响 Apache HTTP 服务器 2.4.17 至 2.4.67 版本，2.4.68 已修复。 PoC 利用代码已在 GitHub 的 EQSTLab/CVE-2026-49975 仓库公开，支持在 Docker 化环境中复现攻击过程。
  3. 建议立即升级至 2.4.68，或临时禁用 HTTP/2 并监控内存异常增长。 在无法升级的服务器上，临时禁用非必需 HTTP/2 功能可作为临时缓解措施，同时监控内存使用模式有助于早期检测。
