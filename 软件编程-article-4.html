Atlassian 如何将 400 万个 Jira 数据库迁移至 AWS Aurora

8/12/2025, 3:30:34 PM

📌 一句话摘要

本文详细介绍了 Atlassian 将 400 万个 Jira PostgreSQL 数据库大规模迁移到 AWS Aurora 的过程，通过创新的“数据清理 (Draining)”方法克服了 PostgreSQL 文件数量限制等重大挑战。

📝 详细摘要

本文介绍了 Atlassian 将 400 万个 Jira 数据库从 AWS RDS PostgreSQL 迁移到 AWS Aurora PostgreSQL 的大型项目。该项目旨在提高成本效益、改善可靠性并增强性能。此次迁移面临着严格的限制，包括每个租户的停机时间少于 3 分钟，以及时间表为数月而非数年。Atlassian 最初采用了使用 AWS RDS 只读副本和 AWS Step Functions 进行编排的“迁移”策略，从而最大限度地减少了停机时间。然而，一个关键挑战出现了：由于 Jira 复杂的模式和多租户设置，Aurora 无法启动具有极高文件数量（每个集群超过 2000 万个文件）的实例。为了解决这个问题，Atlassian 开发了一种创新的“数据清理 (Draining)”解决方案，在迁移之前暂时减少每个集群的数据库数量，然后再重新填充新的 Aurora 集群。这种“链式迁移 (Daisy Chain)”方法最大限度地减少了临时基础设施的需求，并实现了每天高达 90，000 个数据库的惊人迁移速度。该项目成功地在迁移期间迁移了 260 万个数据库，在数据清理期间迁移了 180 万个数据库，处理了 274 亿个文件。最终的结果是更具成本效益、更可靠（99.99% SLA）且性能更高的 Aurora 基础设施，展示了大规模云数据库迁移的典范。

💡 主要观点

  1. Atlassian 迁移到 AWS Aurora 旨在显著提高成本、可靠性和性能。 从 RDS PostgreSQL 迁移到 Aurora 承诺更高的正常运行时间 (99.99%)、通过实例缩减和自动扩展提高成本效益，以及通过最多 15 个读取器实例增强性能。
  2. PostgreSQL/Aurora 中的“文件数量上限”对大型多租户集群构成了关键且不可预见的挑战。 Jira 复杂的模式和每个租户一个数据库的模型导致每个集群数千万个文件，导致 Aurora 实例由于文件枚举延迟而在启动期间超时。
  3. “数据清理 (Draining)”和“链式迁移 (Daisy Chain)”解决方案是克服文件数量限制问题的创新方法。 通过在迁移之前暂时减少每个集群的租户数据库数量，然后再重新填充，Atlassian 有效地管理了迁移，最大限度地减少了基础设施开销并实现了高吞吐量。

💬 文章金句

  • 大多数公司都在努力迁移少量数据库而不会导致停机。Atlassian 每天都会定期迁移大约 1，000 个数据库，作为其日常运营的一部分，并且其用户永远不会注意到。
  • 他们的目标是将所有内容从 AWS RDS PostgreSQL 迁移到 AWS Aurora PostgreSQL。其优势包括：更高的成本效益、更高的可靠性（从 99.95% 升级到 99.99% 的正常运行时间）、通过 Aurora 自动扩展到峰值负载期间最多 15 个读取器实例的能力来增强性能。
  • 当 Aurora 实例启动时，它会执行各种状态检查以确保一切正常。其中一项检查包括枚举（清点）集群卷中的所有文件。
  • 他们开发的解决方案被称为“数据清理 (Draining)”。
  • 这个三步流程创建了 Atlassian 所谓的“链式迁移 (Daisy Chain)”。
