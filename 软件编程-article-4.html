设计系统注解，第一部分：组件中可访问性缺失的原因

5/9/2025, 4:56:41 PM

📌 一句话摘要

GitHub 通过预设注解改进 Primer 设计系统，解决组件在实际应用中可访问性不足的问题，并简化设计流程。

📝 详细摘要

本文探讨了设计系统中可访问性注解的重要性，以及 GitHub 如何通过其 Primer 设计系统解决组件可访问性问题。文章指出，即使使用可访问的组件，也可能产生不可访问的设计。为了解决这个问题，GitHub 引入了预设注解，这是一种针对特定 Primer 组件的注解方法，通过预设标题级别、语义等关键细节，确保组件在不同场景下的可访问性，旨在减少冗余注解，提高设计系统采用率，并降低设计师在无障碍设计方面的专业要求，使更多人能够参与其中。文章还介绍了 GitHub 的 Figma 库——GitHub 注解工具包，该工具旨在简化注解过程，并使所有设计师都能轻松使用。最后，文章鼓励读者查看本系列文章的第二部分，了解如何为自己的设计系统构建预设注解。

💡 主要观点

  1. 可访问的组件并不总是能保证可访问的设计 即使设计系统中的组件是可访问的，但在实际应用中，组件的组合和使用方式可能会导致可访问性问题。
  2. 预设注解可以减少冗余注解，提高设计系统采用率 通过预设组件的细节，预设注解可以避免在每个实例中重复添加相同的注解，从而简化设计流程。
  3. GitHub 的注解工具包旨在简化注解过程，使所有设计师都能轻松使用 该工具包通过提供易于使用的注解组件和内联文档，降低了设计师使用注解的门槛。
  4. WCAG 标准是基础，但用户测试对于确保真正的可访问性至关重要 Web 内容可访问性指南（Web Content Accessibility Guidelines，WCAG）提供了可访问性的基础标准，但要确保真正的可访问性，必须进行用户测试，以满足特定用户的需求。

💬 文章金句

  • 可访问的 *组件* 不一定能保证 *设计* 的可访问性
  • 在创建新组件时，一组详细的注解对于它们的健壮性和可访问性至关重要。
  • 我们所有的预设注解都与组件文档和 Storybook 演示相关联。
  • 对这些问题置之不理，寄希望于他人发现并猜测正确答案，是十分冒险的。
