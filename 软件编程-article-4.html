如何使用文件系统和 Bash 构建智能体 - Vercel

📌 一句话摘要

本文提出了一种简化、高效且稳健的智能体架构，利用文件系统和 Bash 命令（如 grep、cat、ls）进行上下文管理，显著降低成本并提高质量。

📝 详细摘要

Vercel 的这篇文章倡导一种简化的智能体架构，用标准文件系统和 Bash 命令替代自定义上下文工具。核心观点是：由于 LLM 在大量代码库上训练过，它们天生理解文件系统导航。通过将智能体数据构建为文件并在沙盒中提供 Bash 访问权限，智能体可以自主探索、搜索和按需精确检索上下文，模拟它们与代码交互的方式。这种方法克服了提示词填充和模糊向量搜索的局限性，实现了精确检索、最小上下文加载和自然领域映射到目录结构。Vercel 的案例研究，包括销售通话摘要智能体，展示了显著的成本降低和输出质量提升。文章强调了原生模型能力、面向未来的架构、可调试性以及通过隔离增强的安全性。

💡 主要观点

  1. 利用 LLM 对文件系统和 Bash 的固有理解进行智能体上下文管理 由于 LLM 在广泛的代码库上训练过，它们精通文件系统操作（ls、grep、cat），使这些成为上下文探索和检索的原生工具
  2. 将领域数据构建为分层文件并授予智能体沙盒化的 Bash 访问权限 将客户记录或文档等复杂数据映射到目录和文件，允许智能体精确导航并按需检索相关信息，就像开发者导航代码库一样
  3. 该架构提供精确检索和最小上下文加载，优于其他方法 与提示词填充（令牌限制）或向量搜索（对结构化数据不精确）不同，文件系统支持精确搜索（如 grep）并仅将必要数据加载到提示中，降低成本和提高相关性
  4. 该方法显著降低智能体成本并提高输出质量 Vercel 的内部销售通话摘要智能体采用这种基于文件系统/Bash 的架构后，由于高效的上下文处理，成本降低了 75% 且质量更好
  5. 关键优势包括原生模型能力、面向未来、可调试性和安全性 该架构与 LLM 的训练保持一致，随着模型编码能力提升而改进，提供清晰的执行路径用于调试，并通过隔离沙盒确保安全性，同时减少维护代码

💬 文章金句

  • 最好的智能体架构已经存在于你的终端中
  • 我们用文件系统工具和 bash 工具替换了内部智能体中的大部分自定义工具
  • 如果智能体擅长代码的文件系统操作，它们就会擅长任何事物的文件系统操作。智能体已经理解文件系统
  • 检索是精确的。`grep -r "pricing objection" transcripts/` 返回精确匹配。当你需要一个特定值时，你就能得到那个值
  • 随着模型编码能力变得更好，你的智能体也会变得更好。代码理解的每一次改进都会直接转化。你是在利用训练分布而不是与之对抗
