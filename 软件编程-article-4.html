通过 GitHub 的依赖图掌握软件供应链

7/1/2025, 4:00:00 PM

📌 一句话摘要

GitHub 依赖图可直观展示软件供应链，揭示传递依赖关系，从而提升安全性和管理效率。

📝 详细摘要

本文介绍 GitHub 的依赖图功能，该可视化工具能够展示软件项目中的直接依赖和传递依赖——作者将依赖关系比作冰山，指出大部分依赖处于隐藏状态。文章阐述了该工具如何为软件供应链提供完整可视化支持，这正是 Dependabot 安全警报功能的基础。文中特别列举了典型案例（21 个直接依赖 vs 1000 个总依赖）并给出实用建议（优先处理直接依赖）。值得注意的是，依赖图对公开代码库免费开放，还能通过 GitHub Actions 生成 SBOM，是现代软件供应链安全的重要工具。

💡 主要观点

  1. 完整呈现依赖冰山 依赖图能揭示隐藏的传递依赖（通常占代码基底的 95%～97%），通过点-边表示法为安全维护提供关键可视化支持。
  2. 实现主动漏洞管理 通过全面映射依赖关系，开发者可以追踪问题源头（如 Log4j 漏洞）并优先处理可控的直接依赖。
  3. 为 Dependabot 自动化安全功能提供支持 该功能支持自动漏洞警报和修复建议，对公开代码库免费开放，并能通过 GitHub Actions 生成 SBOM。
  4. 实用的实施指导 文章提供了实用实施指导，例如优先处理直接依赖，并展示了极端案例（21 个直接依赖 vs 1000 个总依赖）。

💬 文章金句

  • 在某些情况下，您 95%～97% 的代码实际上来自他人。依赖图帮助您认清这一现实。
  • 您无法保护不可见的部分。GitHub 依赖图让您清楚了解代码基底中 90% 以上来自开源库的内容。
  • 每个软件包是一个点，每个依赖关系是一条边。最终呈现的是您软件外部代码基底的完整可视化结构。
  • 借助依赖图，您终于可以追踪像 Log4j 这样的软件包是如何进入代码基底的。（提示：通常是通过其他依赖间接引入）
