Codex 与 ChatGPT 合并后，work 和 codex 两种模式有什么区别?

7/23/2026, 11:45:00 PM

📌 一句话摘要

本文详解 OpenAI 将 Codex 并入 ChatGPT 桌面后新增的 Work 与 Codex 两种模式的核心能力、适用场景及选择方法，揭示其向 AI 工作平台转型的意义。

📝 详细摘要

文章指出，OpenAI 已把 Codex 整合到 ChatGPT 桌面端，新增 Work 与 Codex 两种使用模式。Work 模式面向所有知识工作者，能够跨工具读取邮件、日历、Google Drive、Slack、GitHub 等信息，自主拆解目标并长时间执行，最终交付可编辑的文档、表格、PPT 或交互式网站；Codex 模式则保留原有的 AI 编程能力，深度理解整个代码仓库，可操作终端、跑测试、管理 Git，完成从需求到代码 diff 的完整开发流程。文中还列出了三类常见误区，并给出根据最终产出、所需资料类型以及是否需要本地环境操作的三个决策问题，以及简单粗暴的对应判断（交给运营/产品/助理用 Work，交给开发用 Codex）。最后强调此次合并标志着 OpenAI 从聊天机器人向 AI 工作平台的战略转型。

💡 主要观点

  1. Work 模式面向知识工作者，实现跨工具连接、长流程自主执行并交付成品级文档。 它能读取邮件、日历、云存储等多源信息，自行规划多步任务，持续运行数十分钟甚至几小时，最终输出可直接使用的 PPT、表格或网页，适合产品经理、运营、市场等非技术岗位。
  2. Codex 模式专注程序员，提供深度代码库理解、终端环境操作以及完整开发工作流。 它可加载整个仓库理解依赖与规范，直接在本地终端跑命令、安装依赖、执行测试，完成从需求到代码 diff、PR 审查的一条龙流程，交付可直接提交的代码。
  3. 常见误区包括将 Work 等同于文案工具、认为 Work 更高级会替代 Codex、以及认为两模式无差别可随意切换。 文章指出 Work 的能力远超文案，Codex 也不只是写代码；两者基于同一智能体但针对不同场景深度优化，互不替代，选错模式会导致输出不符合预期。
  4. 选择模式的三个问题：最终产出类型、所需资料类型、是否需要本地环境操作；并提供简单粗暴的对应判断。 若产出是文档、PPT、表格等，选 Work；若产出是代码、功能或 bug 修复，选 Codex。若需读取邮件、业务数据等，选 Work；若需读取代码仓库、日志等，选 Codex。若需要操作文件系统或跑命令，倾向 Codex；仅需信息处理则选 Work。

💬 文章金句

  • Work 模式让非技术人员也能实现复杂任务自动化，Codex 则专注完整开发流程。
  • 这次合并不是简单的界面整合，是 OpenAI 从聊天机器人向 AI 工作平台转型的标志。
