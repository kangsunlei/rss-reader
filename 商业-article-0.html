我给 AI 做了个「第二大脑」—— Claude、Cursor、Windsurf 共享记忆，开源免费

6/2/2026, 8:50:15 PM

📌 一句话摘要

作者为解决多 AI 工具间上下文不共享的痛点，开发了一款本地运行的 AI 记忆引擎 KeepThinking，支持语义搜索、认知图谱和 MCP 协议，并已开源。

📝 详细摘要

文章作者分享了在同时使用 Claude、Cursor、Windsurf 等 AI 工具时遇到的痛点：每个工具互不相识，每次切换或新会话都需要重复交代上下文，效率低下。作者尝试了 Mem0、MemGPT、Cursor Rules、Continue.dev 等现有方案，均因云端存储、工具局限或无法跨平台等原因未能满足需求。于是，作者利用业余时间开发了 KeepThinking——一个 100% 本地运行的 AI 记忆引擎。它通过 ONNX 运行多语言语义模型进行本地语义搜索，自动构建认知图谱关联决策，内置 Bug 诊断模式，并通过 MCP 协议实现与 Claude Desktop、Cursor、VS Code 等工具的标准化接入。项目基于 Node.js + Express + SQLite + ONNX Runtime，采用 MIT 协议开源，支持 macOS 和 Linux，无需注册和 Token。文章最后提供了安装命令、GitHub 和官网链接。

💡 主要观点

  1. 多 AI 工具间上下文不共享是当前工作流的核心痛点。 作者指出，在 Claude 中分析的架构决策，切换到 Cursor 写代码时完全丢失，每次新会话都需要重复交代技术决策和规范，导致大量时间浪费在「教育 AI」上。
  2. KeepThinking 通过本地运行和 MCP 协议实现跨工具记忆共享。 项目使用 ONNX 运行多语言语义模型进行本地语义搜索，自动构建认知图谱关联决策，并通过 MCP 协议标准化接入 Claude Desktop、Cursor、VS Code 等工具，实现记忆的跨工具共享。
  3. 100% 本地运行是解决数据隐私问题的关键设计。 作者明确拒绝云端存储方案，所有数据存储在本地 ~/.keepthinking/memory/ 目录，不采集不上传不联网，并使用 PBKDF2 加密保护，解决了公司代码不能上传云端的合规问题。
