Matt Puckett：用一份检查清单，终结 AI Agent 的“技能地狱”

7/4/2026, 7:54:35 PM

📌 一句话摘要

Matt Puckett 系统性地分享了 AI Agent 技能的构建框架，通过触发、结构、引导、剪枝四步检查清单，帮助开发者走出无法评判好坏的“技能地狱”。

📝 详细摘要

本期节目由 Matt Puckett 主讲，源于他未能在 AI Engineer World‘s Fair 上发表的演讲。他提出了“技能地狱”的概念，即开发者面对大量 Agent 技能却缺乏评判标准，导致拼凑出的效果不佳。为解决此问题，他给出了一份系统性的技能构建框架。框架分为四大支柱：一是“触发”，深入探讨了用户调用与模型调用的权衡，指出模型调用带来上下文负载和不可预测性，而用户调用增加认知负载，决策需平衡两者成本；二是“结构”，主张将技能分为“步骤”和“参考”两个单元，并极力让主 skill.md 文件尽可能小，通过识别技能的不同分支并将分支参考资料隐藏在上下文指针后实现；三是“引导”，核心技巧是使用“引导词”，将复杂意图压缩进简短术语并在技能中反复使用，从而影响 Agent 的推理轨迹以改变其行为，同时可通过拆分技能隐藏未来步骤，来增加当前步骤的基础工作量；四是“剪枝”，即排查“不要重复自己”、“冗余沉积”、“无效操作”等失败模式，通过删除测试精简技能。

💡 主要观点

  1. “技能地狱”的本质是缺乏评判标准，而非技能太少。 开发者盲目拼凑技能却无法区分好坏，根本原因是没有一个共享的框架来审视和改进技能。
  2. 技能设计需在“模型调用”的上下文负载和“用户调用”的认知负载间做取舍。 模型调用虽灵活但引入不可预测性且消耗 token；用户调用完全可控但要求用户深入理解技能。Matt 更偏好用户调用以求完全掌控。
  3. 使用“引导词”是将复杂指令压缩为短术语，以引导 Agent 行为。 例如用“垂直切片”代替冗长的说教，Agent 会在推理轨迹中自我强化，从而改变编码习惯。反复使用观察其是否出现是验证方法。
  4. 通过拆分技能隐藏未来步骤，能强制 Agent 在当前阶段投入更多基础工作。 在计划模式中，Agent 常急于跳到下一步。将“问澄清性问题”独立成一个技能，可以迫使其做足基础研究。
  5. 技能优化可通过“删除测试”来剔除无效操作。 如果删除技能中的某段内容后 Agent 行为并未改变，说明这段内容是无效的，可以被精简掉。

💬 文章金句

  • 没有一个共享的评判标准，没有一个框架来审视技能并把它变得更好。
  • 每次你有一个模型调用技能，基本上你就要付出不可预测性的代价。
  • 引导词的概念...就是有些词能把一大堆意思压缩到很小的空间里。
  • 通过隐藏未来的目标、隐藏未来的步骤，来增加当前步骤的基础工作量。
  • 如果你把那段话直接删掉会怎样？Agent 大概率还是会写出一份像样的提交信息。
