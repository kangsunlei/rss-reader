Anthropic 工程与产品负责人：如何打造 Opus 5.5

10/29/2026, 3:33:31 AM

📌 一句话摘要

Anthropic 工程与产品负责人拆解 Opus 5.5 与 Claude 平台：从效率数据、托管 Agent 安全架构，到防蒸馏、Rust 重写和 Evals 实践。

📝 详细摘要

本期是 Latent Space 一期访谈的 AI 翻译克隆，嘉宾为 Anthropic 工程负责人 Katelyn Lesse 与产品负责人 Angela Jiang。节目以 Anthropic 提交 S-1、筹备 IPO 为引子，主持人引用文件称其估值约 2 万亿美元、累计融资超 1000 亿美元而累计支出不足 100 亿美元，过去一年人均收入从 140 万美元升至 660 万美元，并首次实现约 19% 利润率的 GAAP 盈利；这些数字均为节目自述，需谨慎看待。主体围绕 Claude 平台如何把模型能力产品化：Claude Code 与平台共享基础组件，Claude Managed Agents 提供更高层 API，并用「大脑—双手」分离的持久 harness 与沙箱、凭证注入和出站白名单实现默认安全。安全部分讨论防蒸馏与体验的权衡、前缀锁定、思考 token 重放、压缩 API、访问授权和双重用途能力验证。工程部分讲用 Claude 协助把 Messages API 从 Python 重写为 Rust，人以镜像流量验证，CPU 节省 40%–50%。此外还涉及个性化、Evals、产品与工程协作及多 Agent 策略。

💡 主要观点

  1. Anthropic 正把 Claude 从模型 API 扩展为综合 Agent 开发平台，效率与平台化是这期访谈的主线。 主持人引用 S-1 称其估值约 2 万亿美元、累计融资超 1000 亿美元而累计支出不足 100 亿美元，过去 12 个月人均收入由 140 万美元升至 660 万美元，并首次实现约 19% 利润率的 GAAP 盈利；超过半数年付 10 万美元以上客户使用 Claude 平台。数字均为节目自述，未经第三方核验。
  2. Claude Managed Agents 的关键设计是把持续运行的 harness 与执行沙箱拆开，并把凭证隔离在 Agent 之外。 节目把它概括为「大脑—双手」分离：harness 在独立服务器保存状态，沙箱只负责执行；凭证由代理在请求发出时注入，Agent 不直接接触，出站流量受白名单控制。这样沙箱停止后任务仍可继续，也把默认安全做进架构。CMA 相比 Messages API 是更高层抽象，共用沙箱和 API 基础设施，但不共用 harness。
  3. 防蒸馏是安全使命、开发者集成成本和模型能力之间的细粒度权衡，而不只涉及商业利益。 Anthropic 通过前缀锁定、跨轮保留思考块、重放思考 token 和 API 压缩功能，降低思维链提取风险；同时主动联系开源 harness 维护者和客户，尽量只增加迁移成本，不直接剥夺原有能力。对网络安全、生物等双重用途能力，则用访问项目、验证和通用信任授权机制限定使用范围。
  4. 用 Claude 重写核心 API 显示「AI 写代码、人负责设计与验证」的分工可以落地到大规模系统。 团队没有 Rust 开发者，仍把 Python 单体 Messages API 重写为 Rust；人负责分布式系统设计、迁移计划和结果验证，用镜像流量对比新旧系统输出。节目称上线后 CPU 节省 40%–50%、首 Token 延迟降低 10%–20%，并实现多区域部署。该结果来自受访者自述，缺乏独立基准。
  5. 个性化、Evals 与多 Agent 仍是开放问题，产品侧更强调克制默认值、负面反馈和把工程当研究。 同一模型很难同时满足「更主动」和「别擅自行动」等冲突偏好，Anthropic 目前靠 effort、预算、模型大小等参数与分群默认值缓解，但自认做得不够好。Evals 方面建议多建、持续迭代，并让 Agent 辅助生成评测；多 Agent 则以共享状态、异步并行和主 Agent 拆分子任务为核心。
