双 11：当 AI 接管支付宝大促交付，模型之外还要建什么？

11/5/2026, 10:12:00 AM

📌 一句话摘要

文章系统阐述了支付宝通过 AI Harness 从工程化走向 AI 全链路交付的实践方法，回答了当 AI 接管大促交付时，模型之外还需构建的关键运行框架问题。

📝 详细摘要

本文回顾了支付宝大促技术团队近三年的演进历程，介绍了如何通过 AI Harness 体系实现从工程化到 AI 全链路交付的跃迁。文章梳理了大促研发的四个关键阶段：2024 年实现「又好又快」的交付模式，2025 年通过组件化沉淀和 AI 补全获得效率杠杆，2026 年上半年 Claude Code 引爆 Agent Coding，以及 618 大促中 AI Coding 主导交付的实战验证。文章详细构建了大促 Harness 体系，包括上下文精细化、执行编排、工具能力资产、记忆与状态、评估与观测、约束与恢复六大层次，并结合 Aflow 平台和 Multica 平台实践，展示了从人工串联到多 Agent 协同的交付模式。通过 L3 小队实践，将「后端全自动」升级为「全链路全自动」，并构建了系分、编码、测试工具的 Loop 机制。文章最后探讨了 Harness 自进化能力和从 Harness Engineering 到 Loop Engineering 的演进路径，阐述了工程师角色从「澄清需求」到「设计约束与改进循环」的转变。

💡 主要观点

  1. AI Harness 是实现 AI 全链路交付的关键运行框架 文章指出，单纯依赖更强的模型是不够的，必须在模型之外构建环境、工具、上下文、编排、可观测、验证、治理等整套运行框架（Harness），才能让 AI 在可控范围内稳定产出高质量交付物。业界共识是，同一个基座模型，套上不同的 Harness，表现天差地别，决定上限的是模型，但把上限稳定兑现的，是模型之外的那一层。
  2. 从「裸用 AI」到「Harness 约束」是交付质量的关键跃迁 2026 年 618 大促中，AI Coding 主导交付 32 个需求，但代价是人工澄清 1332 次，证明裸用 AI 不可行。文章通过构建大促 Harness 体系，将人工串联的环节收进编排，用约束、门禁、恢复机制等手段，让 AI 产物质量可控，交付效率提升。
  3. Harness 自进化闭环实现从「交付→观测→改进→交付」的持续优化 文章构建了需求完结自动采集、指标提取问题清单化、定时分析分类归属、分支路由改进自动化、人工裁决、回流生效的闭环机制。通过 35 轮自进化，产出 51 个有效 issue，落地优化 PR 12 个，验证了 Harness 体系的可持续改进能力。
  4. 从 Harness Engineering 到 Loop Engineering 是 Agent 工程的演进方向 文章阐述了业界正在形成的五层叠加模型：Prompt → Context → Harness → Loop → Graph。Harness 解决「活得稳」的问题，Loop 解决的是「持续地跑、越跑越好」的问题。当前支付宝已构建完善的 Harness 体系，正在探索将「发现—修复—验证—回归」的闭环链起来，实现高风险代码问题以小时级被发现并修复。
