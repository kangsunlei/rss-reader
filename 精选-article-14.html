静态界面的终结：构建意图驱动的 UX｜Gus Iwanaga 与 commercetools

9/1/2026, 8:00:01 PM

📌 One-Sentence Summary

Gus Iwanaga 说明，意图驱动的软件可通过声明式 UI、经策展的组件契约和明确的信息架构适应用户需求，同时不把产品与 UX 控制权交给不可预测的 LLM。

📝 Summary

Gus Iwanaga 从密集的企业软件界面给用户带来的认知负担出发，阐述产品和 UX 为什么需要超越静态页面。他回顾了早期生成式 UI 实验：相近提示会生成不一致且不适合生产环境的界面。演讲随后比较了严格受控的组件选择模式与开放式 LLM 组合，并主张采用两者之间的声明式路径。在这套模式中，编排器识别意图、检索工具和数据、把符合条件的组件映射到实体、依据组件目录和 Zod schema 校验 UI 规范，最后渲染为原生 React UI。最有价值的部分是界面背后的系统视角：受原子设计启发的模板、布局、插槽、子插槽和组件分类，会在生成前编码 UX 判断。他也明确指出组织层面的变化：产品与设计团队会更多地策展 schema、规则、合成数据和交互模式，而不再逐页指定每一个界面。

💡 Main Points

  1. 静态企业界面把认知工作转移给用户 演讲将功能密集的 SaaS 界面、反复培训和割裂的应用心智模型联系起来，指出软件应更好地适应用户意图。
  2. 不受约束的生成式 UI 不适合生产环境 早期实验表明，请求措辞的微小差异就可能改变时间范围、卡片、文案和布局，使个性化输出相互矛盾且难以信任。
  3. 声明式 UI 在适应性与产品控制之间取得平衡 经过校验的 UI 规范让编排器能组合意图、工具、数据和可用组件，同时保留原生渲染与设计系统的一致性。
  4. 信息架构必须成为可执行的指导规则 模板、布局、插槽、子插槽和受约束的组件分类编码了摆放规则，避免智能体任意决定页面如何组合。
  5. 产品与 UX 工作转向策展和治理 讲者将组件属性、schema、合成数据、映射查询和交互模式视为团队构建受 AI 影响体验时新的核心工作面。

💬 Key Quotes

  • 结果既让系统能适应用户意图，也始终遵守整个产品的设计系统。
  • 第一个重大挑战是信息架构。
  • Iwanaga 将组件目录称为智能体与 UI 之间的契约：每一个属性都很重要。
  • 产品与 UX 工作的重心将转向 schema、目录策展、规则、合成数据、组件映射查询和交互模式。
