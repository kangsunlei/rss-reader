#713.Grok Bot：AI 应该像真正的同事一样工作

9/9/2026, 12:00:00 AM

📌 一句话摘要

Roman Ugarte 复盘 Grok Bot 从零到发布的历程：小团队隔离开发、人工导入数百早期用户、彻底从零构建而非在 Cursor 上叠加，并强调让每个 Bot 拥有云端电脑、像可信赖同事一样被委托整块工作，而非做成实时汇报的聊天工具。

📝 详细摘要

本期 Lenny 对话 Roman Ugarte，他是 Cursor 第 15 号员工，现任 SpaceXAI 旗下 Grok Bot 产品负责人。Roman 详述了 Grok Bot 的诞生过程：一个小团队在公司内部隔离区域闭关约一个月，从第一行代码做到可用的原型，再通过全员大会推向全公司，取得超预期反响后，又在三周内完成内部测试、砍功能、打磨后台，最终公开上线。核心决策包括：不把知识工作功能塞进 Cursor 或 Codex 等现有界面，而是从零构建全新产品，以获得一致的体验并掌控每个像素；让每个 Bot 拥有自己的云端电脑，使其能像人一样点击屏幕、登录网站、操作缺乏良好 API 的工具，而非局限于 MCP 或现有 API。Roman 强调，团队通过人工带领数百名早期用户上线，包括咖啡馆老板等非技术人群，从而避免硅谷信息茧房的误导，发现并验证了如「幕僚长」Bot 管理模式等真实使用模式。产品设计刻意隐藏工具调用、点击路径等内部细节，因为用户不需要像监控程序一样观察 AI 的每一步，而是更关注能交付完整成果的信任感。在更宏观的策略上，Roman 认为 Cursor 的持续胜出并非靠规划护城河，而是不断将当下还做不到的事变成可用产品，再随模型进步继续重构；公司文化的关键则是快速执行、全员冲刺，以及一种「colleague pilled」的产品思维——在决策中不断追问「你希望人类队友怎么做」。

💡 主要观点

  1. 从零构建独立产品是 Grok Bot 成功的关键决策。 Roman 团队没有把知识工作功能拼进 Cursor，而是彻底从零开始打造新体验。这让他们能掌控每一个像素、对产品有连贯设想，并避免将不同形态的工作方式硬塞进同一界面，这种『组织架构式』的产品堆叠往往让用户感觉杂乱，削弱产品一致性。
  2. 人工带领数百名早期用户上手是宝贵的产品研究方法。 团队花约两周时间亲自帮助数百名用户完成引导，包括咖啡馆老板等非技术用户。这能直接暴露用户困惑点和无法完成的任务，并冲破硅谷 AI 信息茧房，观察真实的使用模式，比如用户自发形成『幕僚长』Bot 来管理其他 Bot 的用法，从而避免预设用户行为。
  3. 将 AI 视为可信赖的同事，而不是需要实时监控的执行器。 Grok Bot 刻意隐藏工具调用、点击路径等内部细节，因为用户不需要像监控程序一样观察 AI 的每一步。Roman 用『你不会要求人类同事每分钟汇报自己点了哪些按钮』来类比，强调心理负担的消除是提升信任感和可用性的关键。
  4. 让每个 Bot 拥有自己的云端电脑，是产品能通用的核心基础设施。 不同于仅依赖 MCP 或 API，Grok Bot 让 Bot 像人一样拥有独立的、完全在云端的电脑，能登录网站、点击屏幕、操作没有良好接口的工具。这种设计解决了大量任务的实际卡点，也避免用户需要本地开着电脑或依赖繁琐配置。
  5. 持续把『当下做不到的事』变成可用产品，比规划护城河更重要。 Roman 认为 Cursor 的持续胜出并非源于精心的护城河设计，而是死磕在今天做出有用的东西，随着模型能力进步再删掉临时脚手架，继续追逐下一个前沿。这种快速迭代能力是企业文化中的核心，同时需要保持小团队的专注与隔离。

💬 文章金句

  • 你不可能要求他们每分每秒都汇报自己点了哪个按钮、打开了哪个网站，我觉得对你的 Bot 提出这种要求也过分了。
  • 不仅要让它成为一个在云端运行、你能通过各种方式与之交互的 agent 循环，更重要的是这些 bot 必须拥有自己的电脑。
  • 你其实还是在自己做这件事，感觉上是这样，心理负担也一点没少；这跟真正给同事来个不看人传球完全是两码事。
  • 往产品里加东西并不是目标。那并不是能真正推动这款产品向前、让它对更多人更有用的东西。
  • Cursor 真正的魔力所在，是死磕在今天做出一件有用的东西。
