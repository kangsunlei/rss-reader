AI coding 智能体设计

12/29/2025, 12:31:00 AM

📌 一句话摘要

本文通过对 Gemini-CLI 源代码的深度解析，揭示了 AI Coding 智能体的设计原理，包括提示词预处理、工具注册调用、多级 ReAct 架构及记忆压缩机制，为开发者提供了深入理解和使用 AI 编程工具的指南。

📝 详细摘要

本文深度解析了 AI Coding 智能体 Gemini-CLI 的设计，旨在帮助开发者更好地理解和使用 AI 辅助编码工具。文章详细阐述了用户提示词的预处理机制，包括内置命令、MCP Server 提供的命令、扩展包命令以及自定义命令，并强调了 `@` 路径扩展在减少对话轮次中的作用。其次，文章聚焦于工具注册与调用机制，涵盖了核心工具、子智能体作为工具的封装、用户自定义工具以及 MCP 注册为工具的全流程，并深入探讨了工具列表作为上下文传递给大模型时可能面临的 Token 爆炸问题及其解决方案。最后，文章结合流程图和源码分析，详细剖析了 Gemini-CLI 的架构设计，特别是意图识别、主流程 ReAct 框架、子智能体的 ReAct 框架、编码完成机制以及重要的记忆压缩策略，并通过多个预置系统提示词示例，揭示了其意图理解和智能路由的核心实现原理。

💡 主要观点

  1. AI Coding 智能体的核心机制包含用户提示词预处理。 系统通过斜线 `/` 识别内置或扩展命令，通过 `@` 字符引入文件/目录作为上下文，有效减少会话轮次，提升与大型模型的交互效率。
  2. 工具注册与调用是实现 AI 编码的关键，需解决 Token 效率问题。 Gemini-CLI 允许注册核心工具、子智能体、用户自定义工具和 MCP 工具。文章详细解析了工具如何作为上下文提供给大模型，并指出过多工具可能导致 Token 爆炸，Claude Code 的 Skills 扩展和编码调用机制是解决之道。
  3. AI 智能体采用多级 ReAct 框架实现复杂任务处理。 文章通过主流程和子智能体的 ReAct 框架，阐述了智能体如何进行 Reasoning、Acting、Observing 和 Updating。特别是 CodebaseInvestigatorAgent 子智能体，针对复杂任务提供隔离上下文，以降低系统复杂度。
  4. 意图识别和智能路由主要通过精巧的系统提示词工程实现。 Gemini-CLI 通过预置的系统提示词（如 Preamble、CoreMandates 和 PrimaryWorkflows）指导大模型理解用户意图、规划任务并选择合适的工具或子智能体，而非硬编码的路由逻辑。
  5. 为优化对话效率，智能体包含记忆压缩机制。 当对话历史超过一定 Token 阈值时，Gemini-CLI 会自动触发记忆压缩，通过大模型总结或部分保留最新历史，以节省 Token 并确保会话的延续性。

💬 文章金句

  • 理解 AI coding 智能体的设计，可以帮助开发者更好地使用 AI coding 工具，实现开发提效。
  • 规约驱动开发（spec-driven development）成为 AI coding 的最佳实践。
  • 子智能体在执行时有隔离的上下文空间，不会污染主智能体的上下文，通过高内聚松耦合的子智能体，有效降低智能体设计的复杂度。
  • 即使少量配置的 MCP server，对于大部分场景用不到的 tools，会大量消耗大模型 token，非常不经济。
  • Gemini-CLI 的意图理解、智能路由能力，大部分是通过提示词实现的。
