Next.js 16

10/21/2025, 8:00:00 PM

📌 一句话摘要

Next.js 16 稳定了 Turbopack，引入了显式声明的缓存组件，增强了路由并更新了缓存 API，通过集成 React 19.2，显著提升了性能和开发者体验。

📝 详细摘要

Next.js 16 是一个重要的版本，专注于性能、开发者体验和架构清晰性。主要亮点包括：Turbopack 稳定版成为默认模块打包工具，生产构建速度提升 2-5 倍，快速刷新速度提升高达 10 倍。它引入了缓存组件，这是一种使用 `"use cache"` 指令的显式缓存模型，该模型还完成了部分预渲染 (PPR)，以实现更灵活和可选的缓存。此版本将 `middleware.ts` 重命名为 `proxy.ts`，以更清晰地定义网络边界。同时，改进了开发和构建过程的日志记录。此外，Next.js 16 通过布局去重和增量预取改进了路由和导航，并通过需要 `cacheLife` 配置方案的 `revalidateTag()` 以及用于精细控制的新 `updateTag()` 和 `refresh()` API 改进了缓存 API。与 React 19.2 的集成带来了诸如 View Transitions 之类的功能。此更新还详细说明了重要的重大更改、删除和弃用，要求开发人员更新 Node.js 和 TypeScript 版本。

💡 主要观点

  1. Turbopack 现在稳定且是默认模块打包工具，从而显著提高了构建和刷新性能。 Turbopack 提供 2-5 倍的生产构建速度和高达 10 倍的快速刷新速度，成为所有新 Next.js 项目的默认设置，从而在无需额外配置的情况下提升开发人员的效率。
  2. 缓存组件引入了一种显式的、可选的缓存模型，从而完成了部分预渲染 (PPR)。 新的 `"use cache"` 指令允许对页面、组件和函数的缓存进行精细控制，更好地符合全栈开发期望并提高静态页面性能。
  3. 增强的路由、导航和改进的缓存 API 提供了对数据新鲜度和用户体验的更精细控制。 布局去重、增量预取和新的 `updateTag()`/`refresh()` API 等功能优化了网络传输，确保用户操作后立即反映数据，并提供显式缓存失效策略。

💬 文章金句

  • 此版本提供了对 Turbopack、缓存和 Next.js 架构的最新改进。
  • 缓存组件是一组新功能，旨在使 Next.js 中的缓存更加显式和灵活。
  • Turbopack 已经达到了开发和生产构建的稳定性，现在是所有新 Next.js 项目的默认模块打包工具。
  • Next.js 16 包括对路由和导航系统的全面改进，使页面过渡更精简、更快速。
  • `updateTag()` 是一个新的仅 Actions API，提供读写一致性语义，确保在同一请求中过期后立即读取新数据。
