谷歌借助 AI 与差分模糊测试将 C 语言依赖库改写为 Rust

10/13/2026, 11:40:00 AM

📌 一句话摘要

谷歌安全团队利用 Gemini 4 将 giflib 图像处理库从 C 语言翻译为 Rust，通过自动化差异测试和大规模回归验证，成功修复了未打补丁的零日漏洞，并实现了与原版性能持平的内存安全替代方案。

📝 详细摘要

面对成熟 C/C++ 代码栈中高达 70% 的内存损坏漏洞，谷歌安全团队探索了自动化语言迁移路径。他们将约 3000 行的 giflib 库移植到 Rust，保留原有 ABI 兼容性，并利用差异模糊测试和对抗性 LLM 评估确保语义等价。该项目不仅修复了 CVE-2026-26740 漏洞，还展示了 AI 辅助翻译在消除底层内存漏洞方面的潜力，尽管仍需领域专家介入处理 FFI 边界和维护分叉。

💡 主要观点

  1. 自动化迁移流程显著加速了漏洞修复 团队在 6 天内完成了对 giflib 的 Rust 移植，并成功修复了尚未打补丁的堆写入零日漏洞（CVE-2026-26740）。这一速度远超手动审计和打补丁的传统流程，证明了 AI 辅助翻译在快速消除安全风险方面的潜力。
  2. 差异模糊测试确保了语义等价 为了验证自动生成的 Rust 代码是否与原始 C 实现一致，团队进行了大规模回归测试（3000 万个 GIF 文件）和差异模糊测试（2 亿次迭代）。这些测试确保了两个版本在功能上完全一致，避免了因翻译错误而引入新的 bug。
  3. 架构级语言迁移提供了根本的内存安全保障 将代码从 C 语言迁移到 Rust，意味着将内存安全检查从运行时转移到了编译时。这不仅消除了特定漏洞，还从根本上预防了未来类似内存损坏问题的发生，提高了系统的整体安全性。

💬 文章金句

  • 团队用 Rust 编写了一个 ABI 兼容、可直接替换的库，停用了进程隔离沙箱、保持原有延迟不变，并在漏洞 CVE-2026-26740 被公开编目之前修复了一个尚未打补丁的堆写入零日漏洞。
  • 为了避免跨 C 语言边界传递指针时产生未定义行为，FFI 封装层会从裸指针重建安全的 Rust 句柄。
  • 该项目最有力的验证出现在预发布阶段。一位外部安全研究人员在上游 giflib 中发现了一个越界堆写入漏洞，后被编目为 CVE-2026-26740。在漏洞公开披露前，谷歌这套 Rust 替代版本的生产节点从底层就不受该漏洞影响，这表明架构级的语言迁移能够从根本上预先杜绝一整类漏洞。
