Build Hour：代理记忆模式

12/4/2025, 8:28:02 PM

📌 一句话摘要

本次 OpenAI Build Hour 探讨了上下文工程和记忆模式，介绍了重塑、隔离和提取等策略，以构建可靠的 AI 代理并避免常见问题。

📝 详细摘要

本次 Build Hour 课程由 OpenAI 的 Michaela 和 Emre Okcular 主持，重点关注上下文工程，将其作为构建强大、长期运行的 AI 代理的关键学科。Emre 将上下文工程定义为一门艺术和一门科学，强调其在优化 LLM 性能方面的作用，而不仅仅是模型质量或提示词工程。本次课程确定了长期运行代理的四种常见失败模式：上下文突发、冲突、投毒和噪声。为了解决这些问题，引入了三个核心策略：重塑 + 拟合（通过修剪、压缩、总结来调整上下文窗口）、隔离 + 路由（将上下文定向到特定的子代理）以及提取 + 检索（创建高质量、可检索的记忆）。Emre 使用基于 Next.js 和 OpenAI Agents SDK 的 IT 故障排除代理演示了这些技术，展示了如何通过总结为个性化交互创建持久的跨会话记忆。本次课程总结了代理记忆设计的最佳实践，包括理解典型上下文、决定何时记住和忘记，以及实施特定于记忆的评估，为开发者构建有状态的智能 AI 应用提供了宝贵见解。

💡 主要观点

  1. 上下文工程是一项综合性学科，对构建强大的 LLM 代理至关重要。 它是一个包含提示词工程、RAG 和记忆管理的生态系统，系统地优化了 LLM 感知的信息，这直接影响了其在复杂、长期运行任务中的可靠性和输出质量。
  2. 三个核心策略用于管理代理记忆，防止上下文突发、投毒等常见问题。 重塑 + 拟合、隔离 + 路由和提取 + 检索是旨在对抗上下文突发、投毒、噪声和冲突的模式，确保代理有效地利用有限的上下文窗口并在一段时间内保持连贯性。
  3. 区分短期（会话内）和长期（跨会话）记忆技术。 修剪和总结等短期方法优化当前交互，而记忆提取和检索等长期策略则在多个会话中建立连续性和个性化。
  4. 总结是创建结构化持久代理记忆的有效技术。 通过将过去的交互压缩成带有防护栏的结构化摘要，代理可以保留关键信息，实现跨会话的连续性，并提供个性化的、上下文感知的响应，而不会使上下文窗口溢出。

💬 文章金句

  • 上下文工程既是一门艺术，也是一门科学。
  • 现代 LLM 性能不仅仅与模型质量有关，还与您提供的上下文有关。
  • 长期运行、工具繁重的代理容易因投毒、噪声、混乱和突发问题而性能下降。
  • 我们的北极星指标：旨在通过最小的、高信号的上下文最大化实现所需结果的可能性。
  • 即使代理变得更强大并且可以计划复杂的、多步骤的工作流程，仍然存在一个瓶颈：上下文是有限的。
