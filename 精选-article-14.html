别再造 Agent 了！关于 Agent Skills 的详细总结来了

12/22/2025, 2:16:00 PM

📌 一句话摘要

文章深度剖析了 AI Agent 技术栈中的 MCP 与 Agent Skills，阐明了它们在连接性与能力上的分层定位，并提出渐进式披露机制有效解决上下文爆炸问题，为构建高效 Agent 系统提供了理论与实践指导。

📝 详细摘要

本文详细探讨了 AI Agent 领域中 MCP（Model Context Protocol）和 Agent Skills 两种核心概念。文章指出，MCP 主要解决 Agent 与外部工具/资源的连接性问题，而 Agent Skills 则专注于封装领域知识和操作流程，解决 Agent“知道如何使用”工具的能力问题。核心亮点在于 Agent Skills 引入的“渐进式披露”机制，通过三层架构（元数据、技能主体、附加资源）按需加载信息，有效缓解了传统 MCP 因工具 JSON Schema 过大导致的上下文爆炸和成本高昂问题。文章强调 MCP 和 Skills 是互补而非竞争关系，提出了一种结合两者的分层混合架构，能优化成本、提高可维护性和复用性。最后，文章详细介绍了 SKILL.md 规范、编写高质量 Skills 的原则，并展望了行业标准化、生态系统构建和自动化能力发现的未来趋势，同时也警示了安全性和碎片化等潜在风险。

💡 主要观点

  1. Agent Skills 的核心理念是连接性与能力分离，弥补了 MCP 在“如何使用”工具方面的不足。 MCP 提供标准接口让 Agent“够得着”外部工具，而 Skills 提供操作手册和专业知识，指导 Agent“如何正确使用”这些工具，两者职责清晰，架构更优。例如，在代码审查场景中，MCP 提供 GitHub API 访问能力，而 Skills 则指导 Agent 如何基于这些 API 进行代码风格、安全性和测试覆盖率检查。
  2. 渐进式披露机制是 Agent Skills 解决上下文爆炸问题的关键创新。 通过三层架构（元数据、技能主体、附加资源）按需逐步加载信息，将 Agent 初始上下文消耗从传统方式的 16，000 token 大幅降低到 500 token，显著优化了成本和推理效率。这种机制在处理复杂领域知识和众多工具时尤为重要，确保了 Agent 的高效运作。
  3. Skills 与 MCP 是互补关系，结合使用能构建高效、可维护的智能体分层架构。 MCP 作为传输层提供标准化接口，Skills 作为应用层封装领域知识和工作流，实现关注点分离、成本优化和高复用性，特别适合企业级 Agent 应用。例如，在医疗领域，MCP 可连接电子病历系统，而 Skills 则封装疾病诊断流程或药物推荐逻辑，共同服务于智能诊疗助手。
  4. 未来 Agent 技术将趋向标准化、生态化，并发展出自动化能力发现机制。 行业内已出现类似 GPTs 的“知识库”功能及 Google 的“Function Packages”，预示着 Agent 能力描述协议将融合连接性与知识表达。未来可能出现类似 NPM 的 Agent 能力包管理系统，甚至 Agent 能自主学习并安装所需 Skills，这将极大拓展 AI 应用边界。
  5. 尽管 Agent Skills 带来显著优势，仍需警惕安全性、上下文污染和碎片化风险。 Skills 包含可执行脚本可能带来代码注入风险，MCP 接口可能暴露敏感数据，以及不同厂商可能推出不兼容的 Skills 规范。应对策略包括对 Skills 内容进行严格的安全审计，实施细粒度的权限控制，并积极参与行业标准制定，促进互操作性。

💬 文章金句

  • Skill 和 MCP 是两种东西，Skill 是领域知识，告诉模型该如何做，本质上是高级 Prompt；而 MCP 对接外部工具和数据。
  • 连接性（Connectivity）与能力（Capability）应该分离。
  • Agent Skills 最核心的创新是渐进式披露（Progressive Disclosure）机制。
  • Skills 和 MCP 不是竞争关系，而是互补关系。
  • 分层架构是必然趋势：随着智能体系统复杂度增加，'连接层'和'知识层'的分离是不可避免的。
