让项目管理也 AI Native —— 两个 Git 仓库干掉了周报、洞察和效能报表

5/28/2026, 11:06:00 AM

📌 一句话摘要

本文详细介绍了如何利用两个 Git 仓库、AI 编码助手和 Shell 脚本，构建一套替代传统项目管理中周报、洞察和效能报表的 AI Native 方案，核心思路是让 AI 做信息搬运，人只做输入和决策。

📝 详细摘要

文章提出了一种极简的 AI Native 项目管理实践，通过两个独立的 Git 仓库分别管理业务进展跟踪和效能度量。业务跟踪仓库采用三层数据架构：第一层让团队成员用自由文本 Markdown 文件输入进展，降低填写门槛；第二层通过 AI 编码助手将自由文本语义整合为结构化场景文档；第三层生成静态 HTML Dashboard 进行可视化展示。效能度量仓库则通过 CLI 工具从大数据平台并行拉取数据，用 Python 脚本聚合计算，生成交互式 HTML 报表，并特别强调了数据验证的重要性。文章深入剖析了五个关键设计决策：以 Git 为唯一数据源、降低输入门槛优先、静态 HTML 作为 Dashboard、定性与定量分离、SQL 即度量定义。此外，文章还介绍了基于结构化数据的横切分析能力，以及正在进行的对接需求管理和代码仓库的实践，最终将 AI 参与项目管理分为三个层次：格式转换与数据搬运、信息整合与客观数据采集、决策辅助。

💡 主要观点

  1. 用两个 Git 仓库分别管理业务进展和效能度量，实现定性与定量分离。 一个仓库负责跟踪定性进展（做了什么、卡在哪），另一个负责定量效能（交付了多少、质量如何），避免混在一起导致两边都做不好。
  2. 降低输入门槛是提升数据质量的关键，让 AI 做结构化转换而非让人填写模板。 团队成员用自由文本 Markdown 或即时通讯文档输入，AI 编码助手负责将自由文本语义整合为结构化场景文档，大幅降低填写阻力。
  3. 静态 HTML 是最高效的 Dashboard 方案，部署成本几乎为零。 使用 Chart.js 生成静态 HTML 页面，无需后端、数据库、登录鉴权，通过 Git Push 和 CI/CD 即可完成部署和分发。
  4. 数据验证是度量系统迭代的核心，没有验证的优化就是冒险。 每次修改 SQL 或聚合逻辑前，需快照基线、对比 diff、多周回测，避免因口径调整导致数据异常，这是从多次踩坑中总结的教训。
  5. 结构化数据带来的横切分析能力是 AI Native 项目管理的真正杠杆点。 当所有场景数据统一结构后，AI 可以自动进行基建依赖分析、共性风险识别、协同复杂度对比等横向模式识别，这是传统纵向汇报模式难以做到的。

💬 文章金句

  • 降低填写门槛是第一生产力。你让人填 10 个结构化字段，他就不想填。你让人自由写，他反而能写出有价值的信息。
  • 不编造、不美化、不用上周的信息凑数。
  • 没有验证手段的优化不叫优化，叫冒险。
  • 项目管理本质上是一个信息工程问题，而不是一个流程管理问题。
  • 之所以 work，不是因为技术多先进，而是因为顺应了工程师的工作习惯，而不是对抗它。
