📝 详细摘要

本文针对开发者在使用 Git 过程中经常遇到的 8 个实际问题，提供了详细的解决方案和操作指南。文章首先介绍了 `cherry-pick` 命令，用于将特定 `commit` 从一个分支转移到另一个分支。接着讲解了 `revert` 命令，用于撤销已经合并到 `master` 分支的功能。然后介绍了 `stash` 命令，用于保存当前工作状态，以便切换到其他任务。此外，还讲解了 `amend` 命令，用于修改最近一次的 `commit message`。最后，重点介绍了 `rebase` 命令，用于修改历史 `commit`、合并 `commit`，以及解决多人协作中的代码冲突。通过这些实用技巧，开发者可以更高效地管理代码，解决实际开发中的问题。文章还介绍了 `git reflog` 命令，用于查看 `git` 操作历史，以便在 `rebase` 出错时进行回退。

💡 主要观点

  1. 解决线上 commit message 错误问题，revert 后重新提交更稳妥 对于已推送到远程仓库的 commit message 错误，revert 该 commit 再重新提交是比 rebase 更安全可靠的方案，避免不必要的代码冲突。
  2. cherry-pick 可将任意分支的 commit 挑拣到当前分支 cherry-pick 命令能够方便地将其他分支的 commit 应用到当前分支，解决 commit 提交错误分支的问题，但 cherry-pick 应避免挑选本分支的 commit。
  3. git stash 用于在不 commit 代码的情况下保存当前工作状态 git stash 命令可以保存当前工作目录和暂存区的修改，方便切换到其他任务，之后可以恢复之前的工作状态。
  4. git rebase -i 可用于修改历史 commit 和合并 commit git rebase -i 命令能够修改历史 commit 的内容和 message，还可以将多个 commit 合并为一个，方便代码 review 和版本管理。
  5. git reflog 可以查看 git 操作历史，用于错误回退 git reflog 命令可以查看包括 commit、reset 等所有历史操作，方便在误操作后，快速找到之前的 commit 状态并恢复。

💬 文章金句

  • git cherry-pick 的作用，就是将任意分支的 commit 挑拣到当前分支，但是这个挑拣不会删除原分支的 commit。
  • git stash apply 是应用最近一次 stash 的代码，如果你存了很多个，就必须指定。
  • edit 的意思就是编辑该 commit。务必记得，在 vim 编辑器里，需要先键入 i 才能进入编辑模式。
  • 解决办法就是先对其 revert，然后重新 commit，这是最稳妥的解决办法。
  • git 其实为我们保存了所有的历史记录。
