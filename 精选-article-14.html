别再只卷 Prompt 了，真正拉开 Agent 差距的是 Context Engineering

9/14/2026, 9:36:00 AM

📌 一句话摘要

文章梳理了从 Prompt Engineering 到 ReAct 再到 Context Engineering 的范式演进，结合 Anthropic、CoALA 与 Lost in the Middle 等研究，系统讲解上下文窗口的物理约束与七类构成要素的设计原则。

📝 详细摘要

本文是腾讯程序员的原创技术综述，主张 AI 工程的重心已从「写好单条提示词」转向「管理整个上下文信息空间」。文章先给出三阶段演进：Prompt Engineering（2020—2022，优化单次 LLM 调用）、ReAct（2022—2024，Thought-Action-Observation 多轮循环，但上下文隐式累积不做管理）、Context Engineering（2025 至今，显式工程化、动态维护 Agent 全生命周期），并强调三者是叠加关系而非替代。随后以 Anthropic 的定义「策展、最优、演化」为骨架，借助 Karpathy 的 LLM OS 类比说明上下文窗口即工作内存，用 CoALA 框架把记忆分为工作记忆与情节、语义、程序三类长期记忆。第三章用三篇实证研究论证「信息精准供给优于信息堆砌」：Lost in the Middle 的 U 型曲线（答案在中间时正确率可低至 35%，甚至低于闭卷基线）、Context Rot（Token 越多召回率线性下降）、Attention Budget（O(n²) 计算代价），并给出关键信息置于首尾等实践规则。第四章按 Philipp Schmid 的七类要素逐一展开设计原则，重点讲解 System Prompt 的 Goldilocks Zone、User Prompt 的近因效应、State/History 的三种管理策略（滑动窗口、Compaction、Structured Note-Taking）以及长期记忆的按需检索与少样本示例选取。

💡 主要观点

  1. Prompt Engineering、ReAct、Context Engineering 是叠加关系而非替代关系，后者包含前两者的全部技巧并新增信息生命周期管理维度。 Prompt Engineering 优化单次 LLM 调用的措辞，ReAct 解决多轮工具调用但上下文隐式累积不做管理，Context Engineering 则显式工程化地维护 Agent 完整生命周期内的信息空间。作者用「Context Engineering ⊇ ReAct ⊇ Prompt Engineering」概括这一关系。
  2. 「上下文窗口越大越好、信息越多越好」是错误直觉，三篇实证研究从位置、长度、计算量三个角度证明信息堆砌会主动损害性能。 Lost in the Middle 显示答案文档位于中间时正确率约 35%，低于 56.1% 的闭卷基线；Context Rot 表明 Token 增加时召回能力线性下降；Attention Budget 指出自注意力 O(n²) 带来计算、延迟、金钱三重代价。核心公式是「最优上下文 = 最小 Token 数量 × 最高信噪比」。
  3. System Prompt 应落在 Goldilocks Zone：既不能枚举式地写 180 条脆性规则，也不能只写「你是一个有帮助的助手」这类空洞指令，而应给出可推理的原则与高风险边界。 太精细的规则维护成本高、遇未覆盖场景无法处理且浪费 Token；太宽泛则无法保证行为一致性。适中方案用「角色 / 核心原则 / 工具使用原则」分区，对资金安全等高风险行为设明确边界，未知场景可由原则推理出合理行为。
  4. State / History 是上下文增长最快、Context Rot 的主要来源，生产级 Agent 通常组合使用上下文压缩与结构化外部化两种策略。 代码重构 Agent 到第 35 轮累计约 90，000 Token，已超 128K 窗口的 55%。滑动窗口简单但信息损失大；Compaction 用 LLM 摘要保留关键信息；Structured Note-Taking 把信息卸载到上下文之外的持久存储，理论上支持无限长任务。任务状态同样应只注入决策必需的最小字段，用引用代替内容。
  5. 长期记忆与检索信息都不应全量预加载，而应按需检索、精准注入，少样本示例也需精简并优先覆盖易混淆场景。 CoALA 把记忆分为工作记忆与情节、语义、程序三类长期记忆，只有工作记忆始终在场。少样本示例 2～5 个通常足够，应优先挑选容易出错、容易混淆的情形以起到消歧作用，而非最简单直白的情形。

💬 文章金句

  • 现在大多数 Agent 的失败已经不再是模型的失败，而是上下文的失败（Most agent failures are not model failures anymore， they are context failures）。
  • Context Engineering 是设计和构建动态系统的学科，其目标是在正确的时机、以正确的格式，向 LLM 提供正确的信息和工具，使其能够完成任务。
  • Context engineering is the art and science of curating what will go into the limited context window from that constantly evolving universe of possible information.
  • 注意力是稀缺资源。每一个进入上下文的 Token 都在消耗注意力预算，增加无关内容不是中性操作，而是主动损害有效信息的信号强度。
  • 最优上下文 = 最小 Token 数量 × 最高信噪比
