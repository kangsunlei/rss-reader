Claude Sonnet 5.5 发布：干活更快，单价不变

9/29/2026, 12:23:00 AM

📌 一句话摘要

Anthropic 发布 Claude Sonnet 5.5，API 单价不变但生成速度提升 30% 以上、单任务成本最多降低 30%，低 effort 档位即可超越上代最高档，同时官方建议重新评估 effort 档位以避免过度推理。

📝 详细摘要

Anthropic 发布 Claude 5.5 家族第二款模型 Sonnet 5.5，面向日常编程、修 bug 及文档、幻灯片、表格等工作。官方称输出生成速度提升 30% 以上，多数任务单任务成本最多降低 30%，API 单价维持每百万输入 token 2 美元、输出 token 10 美元不变。文章引用 CursorBench 4.0 数据说明：Sonnet 5.5 在 Low effort 下得分 35.8%、成本 0.50 美元，已略高于 Sonnet 5 Max 的 34.1%、7.17 美元，平均步骤从 140 降到 18；但 Xhigh 到 Max 得分仅从 53.1% 升到 55.5%，成本却从 3.88 美元涨到 9.67 美元，而 Opus 5.5 High 以不到一半花费取得接近 Sonnet 5.5 Max 的得分。文章还分析了效率来源（更常合并工具调用、缩短行动链）、effort 拉满可能做过头（FrontierCode 上 Xhigh 52.1% 反超 Max 46.2%，因 code-review skill 触发子 Agent 导致超时或超范围修改），以及 GDPval-AA 办公设计评测表现和 API 迁移注意事项。

💡 主要观点

  1. Sonnet 5.5 的核心卖点是低档位效率跃升，而非刷新最高分 CursorBench 4.0 中 Sonnet 5.5 Low 得分 35.8%、成本 0.50 美元，已略高于 Sonnet 5 Max 的 34.1%、7.17 美元，平均步骤从 140 降到 18；对每天反复读代码、改代码、跑工具的工作流，这种变化比单独刷新最高分更有用。
  2. effort 越高收益递减，跨模型比较中高档位比一路推到 Max 更划算 Sonnet 5.5 从 Xhigh 到 Max，得分仅从 53.1% 升到 55.5%，费用却从 3.88 美元涨到 9.67 美元；同一张表里 Opus 5.5 High 得分接近 Sonnet 5.5 Max，花费不到后者一半。
  3. 效率提升来自更短的行动链和更常合并的工具调用 Sonnet 5.5 比 Sonnet 5 更常把可并行获取信息的工具调用合在一起执行，交互链缩短、需携带的历史减少；Base44 的 118 次应用构建测试中，Sonnet 5.5 平均 3.6 轮迭代，Opus 5 用了 7.7 轮，成品评分相当。
  4. 把 effort 拉满可能做过头，反而降低任务完成质量 FrontierCode 评估代码修改能否不经人工改动就合并并惩罚超范围修改，Sonnet 5.5 Xhigh 得分 52.1%，Max 反而 46.2%；原因是 Max 更常触发 Claude Code 的 code-review skill，把检查拆给多个子 Agent，在 Cognition 检查的两个案例中导致超时或任务范围外的额外修改。
  5. 官方建议重新评估 effort 档位，同名档位不代表与上代相同的推理量 迁移指南建议较明确的编程和多步工具任务从 Medium 开始，更难或更长的任务再用 High；Claude Code 和应用默认 Medium，Claude API 默认 High。此外原用 thinking: {"type": "disabled"} 关闭推理的请求需改为 between_tools。

💬 文章金句

  • 需要更多推理时，也值得比较另一款模型的中高档位，而不只是把当前模型一路推到 Max。
  • 新模型不需要用上一代那么长的行动链，便能达到相近的结果。
  • 多做检查原本是为了提高质量，可检查链条本身也要服从当前任务。
  • 各档位已经重新校准，同名档位不代表与 Sonnet 5 投入相同的推理量。
