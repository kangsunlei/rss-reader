介绍 Showboat 和 Rodney：让智能体能够演示其构建的成果

2/10/2026, 5:45:29 PM

📌 一句话摘要

Simon Willison 介绍了 Showboat 和 Rodney，这是两款旨在帮助 AI 编程智能体对其构建的软件提供可验证演示和基于浏览器的测试的 CLI 工具。

📝 详细摘要

本文探讨了 AI 辅助开发中的一个关键挑战：确保编程智能体不仅能编写代码，还能证明代码有效。作者 Simon Willison 介绍了两款新工具：Showboat 允许智能体通过 CLI 命令构建基于 Markdown 的演示文档；Rodney 是一个用于浏览器自动化的 CLI 封装工具，使智能体能够与 Web 界面进行交互。作者认为，虽然测试驱动开发 (TDD) 在引导智能体方面非常有效，但手动或视觉验证仍然必不可少。通过提供具有详尽帮助文本的工具，开发者可以赋能智能体自主记录进度并执行无障碍审计或 UI 测试，最终在增强对 AI 生成产物信心的同时，减轻人工监督的负担。

💡 主要观点

  1. 软件工程的定义是交付经过验证的代码，而不仅仅是生成文本。 作者强调，随着 AI 智能体代码产量的增加，瓶颈转向了验证环节。工具必须不断演进，以帮助智能体向人类监督者证明其工作表现符合预期。
  2. Showboat 使智能体能够构建结构化的 Markdown 演示，以可视化其进度。 通过使用一系列如 'exec' 和 'image' 的 CLI 命令，智能体可以在 VS Code 中创建实时更新的文档，让用户能够实时见证软件的功能。
  3. Rodney 提供了一个专门为 AI 智能体优化的基于 CLI 的浏览器自动化接口。 Rodney 基于 Rod Go 库构建，允许智能体管理多轮浏览器会话、截取屏幕截图并执行 JavaScript，填补了智能体在处理 Web 项目时的空白。
  4. “技能”模式涉及使用详尽的帮助文本来引导智能体行为。 通过设计 CLI 工具，使其 '--help' 输出包含所有必要的指令，开发者可以将这些工具视为智能体可以自主发现并使用的“技能”，而无需人工提示。
  5. TDD 对智能体来说是一个强大的约束，但需要补充手动验证。 虽然“红/绿 TDD”有助于智能体编写专注且必要的代码，但即使软件出现故障，自动化测试也可能通过，因此需要通过 Showboat 和 Rodney 等工具进行视觉验证。

💬 文章金句

  • 软件工程师的工作不是编写代码，而是交付能够运行的代码。
  • 我需要能够让智能体向我清晰演示其工作的工具，同时尽量减少它们在工作成果上作弊的机会。
  • --help 文本的作用有点像一种“技能”。你的智能体可以阅读帮助文本，并利用 Showboat 的每一项功能来创建一个文档，演示任何你需要演示的内容。
  • 我现在仍然对自己能在手机上完成这么多编程工作感到有些吃惊，但我估计目前我推送到 GitHub 的大部分代码都是由编程智能体为我编写的。
  • 任何做过测试的人都知道，自动化测试通过并不意味着软件真的能正常工作！
