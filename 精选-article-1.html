云平台已扛不住？得物自建大数据研发与管理平台的破局之道

11/6/2025, 11:16:00 PM

📌 一句话摘要

得物详细介绍了其自建大数据研发与管理平台 Galaxy 的破局之道，涵盖数据研发、架构、质量和智能化能力，以应对云平台瓶颈并支持业务长期发展。

📝 详细摘要

文章深入阐述了得物公司为何从依赖云平台转向自建大数据研发与管理平台“Galaxy”的历程与实践。面对云平台在数据使用效率、质量、成本及架构合理性方面日益凸显的局限性，得物于 2024 年启动了自建大数据系统项目。Galaxy 平台旨在为数据生产用户提供离线和实时数据采集同步、研发运维、加工生产、数据资产管理及安全合规能力。文章详细介绍了平台已落地的四大核心能力：作为“驾驶舱”的数据研发套件，包括数据同步技术和任务平滑迁移方案；作为“底盘”的数据架构技术，核心是 Onedata 方法论，实现了统一 ODS 自动化入仓和规范数据建模与自动化指标研发；作为“刹车片”的数据质量技术，建立了质量校验规则和变更管控流水线；以及作为“辅助驾驶”的智能化数据研发，包括智能 SQL 代码续写等 Copilot 应用。文章还展望了未来的规划，包括智能 ETL Agent、Data Fabric 和数据逻辑化，旨在进一步提升效率、降低成本和门槛。

💡 主要观点

  1. 得物自建大数据平台以应对云平台瓶颈 面对云平台在数据效率、质量、成本和架构合理性方面的不足，得物选择自建 Galaxy 平台，以满足长期业务发展需求，提升核心竞争力。
  2. 构建 Onedata 数据架构体系解决数据资产混乱问题 通过 Onedata 方法论，建立统一数据采集、规范数据建模与自动化指标研发，有效解决数据二义性、冗余和成本控制难题，提升数据复用度和研发效率。
  3. 建立完善的数据质量保障体系降低业务风险 针对数据质量问题引发的业务风险，Galaxy 平台建设了数据质量校验规则和数据变更管控流水线，确保数据准确性和稳定性，防止 P0 级资损。
  4. 智能化数据研发提升效率并降低使用门槛 通过智能 SQL 代码续写、任务诊断等 Copilot 应用，以及未来规划的智能 ETL Agent，降低数据研发门槛，实现“数据平权”，大幅提升数据团队交付效率。
  5. 数据架构演进方向聚焦于成本优化与效率提升 长期规划 Data Fabric 和数据逻辑化，旨在通过“不移动数据，移动计算”和视图物化等技术，减少非必要的离线存储成本，进一步提升数据研发与运维效率。

💬 文章金句

  • 数据研发平台则决定了数据的交付效率、数据质量以及数据架构合理性。
  • Galaxy 数据研发与管理平台为其中一个重要项目，负责面向参与数据生产的用户，提供离线和实时数据的采集同步、研发运维、加工生产、数据资产管理以及安全合规的能力，满足业务长期发展对于数据架构、数据质量、数据交付效率的诉求。
  • Onedata 的核心理念之一是所有的数据采集有统一的规范和入口。因为随意的从在线库进行采集同步会导致大量重复的数据存储，以及过长浪费的表存储生命周期。
  • Data Fabric（数据编织）是一种全新的数据集成架构方案，核心理念是 '不移动数据，移动计算'。
  • ETL Agent 核心能力是需要将用户的自然语言业务需求翻译成数据表的 SQL 加工逻辑，其本质上就是'NL2SQL'的传统命题。
