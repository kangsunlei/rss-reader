三个月，一场必然失败的 Tokenmaxxing

6/20/2026, 3:54:00 AM

📌 一句话摘要

本文以 Tokenmaxxing 现象为切入点，系统分析了 AI Agent 在企业应用中因成本失控、能力错配与组织瓶颈而必然失败的过程，并指出其本质是生产率悖论在 AI 时代的重演。

📝 详细摘要

文章从 2026 年初硅谷兴起的 Tokenmaxxing（token 利用最大化）现象入手，追踪了其从 OpenAI、Anthropic 等前沿公司蔓延至整个互联网产业，再到 Amazon、Uber、微软等巨头在三个月内相继叫停的完整过程。作者从三个层面剖析了其必然失败的原因：一是 Agent 成本过高，包括模型公司 IPO 压力下的涨价、订阅制被重度用户打穿、以及 Agent 自身低效（1000 倍 token 消耗、EFC 转化率仅 0.1）；二是组织层面的混乱，包括 AI 能力参差不齐（Agents' Last Exam 显示主流系统完整通过率仅 2.6%）、脆弱链转移（MIT 论文显示 commit 到 release 的转化率从 180%降至 30%）、简单任务上的效率幻觉、以及重复造轮子导致的浪费；三是需求天花板，图书市场和 App 商店的数据表明，供给增加并未带来需求同步扩大。文章最后将这一现象置于经济学框架中，指出 Tokenmaxxing 本质上是企业在支付 J 型增长曲线的下探成本，其失败并非毫无意义，而是为真正的生产力爆发积累必要的基础设施与组织经验。

💡 主要观点

  1. Tokenmaxxing 的失败直接源于 Agent 成本失控。 Agentic coding 的 token 消耗是普通代码问答的约 1000 倍，且 EFC 转化率仅 0.1，意味着 90%以上的 token 花在了无效反馈上；同时模型公司 IPO 压力导致定价上涨，订阅制被自动化工具打穿，进一步推高了实际使用成本。
  2. 组织层面的能力错配与流程瓶颈是更深层原因。 AI 能力参差不齐，在商业、法律等高频领域表现不佳；上游代码生产效率提升 180%后，下游审核、测试、发布环节成为新瓶颈，导致 commit 到 release 的转化率仅剩 30%；简单任务上 AI 反而降低效率，且重复造轮子现象严重。
  3. 需求天花板限制了 AI 创造新市场的空间。 图书市场和 App 商店的数据表明，AI 大幅增加了供给，但并未带来需求同步扩大；软件开发虽能通过降本释放新需求，但 Agent 识别和满足真实用户需求的能力仍然不足。
  4. Tokenmaxxing 本质上是 J 型增长曲线的下探阶段。 技术进步带来的生产率提升需要企业同步改变设备、流程、技能和组织结构后才能显现；Tokenmaxxing 是企业支付组织改造成本、趟出瓶颈的过程，其失败是必然的，但并非毫无意义。

💬 文章金句

  • Tokenmaxxing 关注的是上游，看 Agent 跑了多少 token、写了多少代码。但从数据上看，它确实和下游，产品有没有发布，客户有没有使用，收入有没有增加是脱钩的。
  • Agent 不是「手脚不灵」，是「脑子里没有行业 know-how」。
  • AI 把写代码这一步加速了，但设计、审核、测试、产品决策、发布流程、应用商店审核、用户采用这些环节没有同步加速。上游红利在下游被稀释。
  • 我们离真正能转化成生产力爆发，还需要一些时间。或者等待着 AI 能力突破人的瓶颈、或者等待组织吸纳 AI，真正落地。而在这之前，激进的 Tokenmaxxing 必然失败。
