纯 Vibe Coding 做大项目，一定会塌掉

7/7/2026, 12:38:00 PM

📌 一句话摘要

AI 创业者徐文浩深度拆解其团队如何搭建一整套工程化「Harness」，让 AI Agent 在大型项目中高效协作而不失控，并指出纯 Vibe Coding 必然崩溃，关键在于用机制而非人力去治理复杂度。

📝 详细摘要

本期节目是「AI 炼金术」的一次深度技术复盘。嘉宾徐文浩回应了「AI 只能写小项目，做大项目必塌」的流行观点，他同意前半句，但认为解决之道不是放弃 AI，而是搭建并持续迭代一整套管理复杂度的「Harness」。他首次投屏分享了三层基建：第一层是个人开发基建，包括使用 Cmax 终端并行管理多任务、通过远程 Linux 服务器和 Dev Container 沙盒让 Agent 在后台持续安全运行、利用 Worktree 分支互不干扰，实现让 AI「不辞辛苦又炸不到你」；第二层是对话层基建，将一排 AI Agent 挂在 Discord 的不同频道上，利用其服务器/频道/线程的三层结构完美管理不同任务的上下文，避免串扰；第三层是工程团队基建，代码提交后自动触发 Codex 和 Claude Code 进行双重代码审查、再加上几十道涵盖格式、重复率、依赖关系的质量门禁和带录屏的自动化测试，确保 AI 产出代码的质量。此外，他还分享了两个独特的实用技巧：一是编写一个 Skill，专门扫描并优化 Agent 在工作中遇到的权限、库缺失等「摩擦」，让 AI 自己把自己磨快；二是将定期任务拆解到每周的不同日子，每天只让 AI 汇报一类问题，以适应人类有限的注意力带宽。

💡 主要观点

  1. 纯 Vibe Coding 做大项目必然崩溃，根本原因是缺乏工程化治理机制 放任 AI 随心所欲写代码会导致项目充斥着 Bug，变成一个需要不断维护的「公共厕所」。解决问题的关键在于，要像管理人类团队一样，为 AI 建立一套自动化的质量门禁和规范体系。
  2. 构建个人「Harness」的两大目标：让 AI 持续干活且不破坏现有成果 通过远程服务器实现「合上笔记本 AI 接着干」，使用 Dev Container 沙盒和 Worktree 并行分支，确保 AI 在独立环境中运行，即使执行高危删库操作或任务失败，也不会影响主项目和其它任务。
  3. 利用 Discord 的分层结构是实现多 Agent 协作的最佳对话界面 Discord 的「服务器-频道-线程」三层架构，完美解决了多任务上下文管理难题。每个频道绑定一个配备特定技能和人设的 Agent，线程则用于 Agent 内并行处理子任务，有效防止了上下文混乱。
  4. 自动化质量门禁是 AI 在大型项目中不「塌」的团队级保障 在代码合并前，必须通过 Codex 和 Claude Code 的双重 Review、几十道代码规范、重复率和依赖关系检查，以及带录屏的自动化 E2E 测试。这套流程将代码质量的把关工作从人转移给了 AI 和自动化工具。
  5. 「让 AI 自己把自己磨快」是提升效率的进阶技巧 AI 常因环境权限不足而用低效方法迂回完成任务，显得很慢。通过编写一个 Skill 去分析 AI 执行日志中的摩擦点（如缺失的命令、库），并主动为其优化环境，可直接提升 Agent 的执行速度和 Token 使用效率。
