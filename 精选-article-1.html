上下文工程(Context Engineering)

7/2/2025, 3:53:16 PM

📌 一句话摘要

探讨优化 AI 智能体性能的上下文工程策略（写入、选择、压缩、隔离），并获得 LangGraph 框架的实践支持。

📝 详细摘要

本文将上下文工程定位为 AI 智能体开发的关键学科，将大语言模型(LLM)比作操作系统，其中上下文窗口的功能类似于随机存取存储器(RAM)。详细阐述了四种核心策略：写入（通过暂存器/记忆模块外部保存上下文）、选择（检索相关上下文如工具/记忆）、压缩（通过摘要生成/修剪减少 token 数量）、隔离（将上下文拆分到子智能体或沙箱环境）。每种方法都针对特定挑战，如 token 限制和性能退化。文章重点介绍了 LangGraph 如何为这些策略提供框架级支持，为开发者提供有效的上下文管理工具。实际案例包括 Claude Code 的自动压缩功能和 Anthropic 的多智能体研究系统。

💡 主要观点

  1. 上下文工程通过战略性内存管理优化智能体性能。 平衡上下文窗口使用可减少 token 过载，兼顾任务效能的同时优化成本/延迟。
  2. 四种互补策略应对不同挑战。 写入（暂存器/记忆模块）保存上下文；选择（RAG/嵌入向量）检索相关内容；压缩（摘要生成/修剪）最小化 token；隔离（多智能体/沙箱）防止干扰。
  3. 实际应用需要谨慎权衡。 挑战包括内存选择错误（如 ChatGPT 位置泄露）、摘要保真度损失和多智能体协调开销（15 倍 token 使用量）。
  4. LangGraph 提供框架原生支持。 状态对象（编程实体）和持久化 API 等特性支持写入/隔离策略，内置摘要功能辅助压缩。
  5. 实际系统验证了这些方法的有效性。 Claude Code 的自动压缩、Anthropic 的子智能体并行和 HuggingFace 的 CodeAgent 验证了经过生产测试的实现方案。
