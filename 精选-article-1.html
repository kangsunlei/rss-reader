从 RAG 到 Context：2025 年 RAG 技术年终总结

12/21/2025, 2:16:00 AM

📌 一句话摘要

本文深入分析了 2025 年 RAG 技术的发展，从“创可贴”到企业 AI 核心基石的演进，预见 RAG 将从“检索增强生成”升级为以智能检索为核心的“上下文引擎”，成为 AI Agent 时代不可或缺的数据底座。

📝 详细摘要

文章对 2025 年 RAG 技术的发展进行了年终总结，指出尽管面临长上下文和 Agent 分流的质疑，RAG 仍在企业级 AI 落地中展现出不可替代的数据基础设施地位。文章详细探讨了 RAG 的技术改进，包括将检索解耦为“搜索”与“检索”两阶段、TreeRAG 与 GraphRAG 的融合，以应对传统 RAG 在处理复杂查询时的痛点。文章强调了 RAG 从知识库向通用 Agent 数据基座演进的趋势，并引入“上下文工程”概念，分析了领域知识、工具数据和会话状态数据在 Agent 上下文组装中的关键作用，最终提出 RAG 将升级为“上下文引擎”或“上下文平台”的未来展望。同时，文章也审视了多模态 RAG 的进展及其工程化挑战。

💡 主要观点

  1. RAG 技术虽受质疑，但已在企业级 AI 落地中成为不可替代的数据基础设施。 2025 年 RAG 并未被取代，反而在中大型企业对 AI 能力建设的投入中，愈发稳固地扮演核心角色，成为企业智能能力的坚实底座，超越了仅作为模型知识缺陷“创可贴”的定位。
  2. RAG 的改进方向是解耦搜索与检索，并结合 TreeRAG 和 GraphRAG 提升效果。 为了解决 RAG 的“易用难精”问题，文章提出 RAG 流程应解耦为精准“搜索”和完整“检索”两阶段，并结合 TreeRAG 的结构化摘要和 GraphRAG 的图谱关联，提供更连贯、全面的上下文给 LLM。
  3. RAG 正在从知识库升级为 Agent 时代通用的数据基座，成为“上下文引擎”。 随着 AI Agent 的兴起，RAG 不再是单一的问答知识库，而是通过强大的 Ingestion pipeline，统一处理企业多样化的非结构化数据，为 Agent 提供可信、实时的知识来源。
  4. 上下文工程的核心是智能组装领域知识、工具和会话数据，而检索是其核心。 Agent 决策质量取决于上下文相关性，上下文工程通过检索高效筛选、组装领域知识、工具描述和会话状态数据，避免信息过载，提升 LLM 的理解和推理能力。
  5. 多模态 RAG 面临存储与计算瓶颈，成熟产品化依赖技术突破和工程化。 尽管多模态 RAG 在图文结合任务中表现出色，但其在工程化落地中遭遇 Token 爆炸导致的存储和计算开销问题，需要张量量化压缩、Token 剪枝及专用多模态 Embedding 模型等技术进步。

💬 文章金句

  • 纵观全年发展轨迹，RAG 并未如部分激进观点所预言的那样黯然退场，反而在企业级 AI 落地的深水区中，愈发彰显出其作为数据基础设施的不可替代性。
  • 一个根本性的改进思路是将 RAG 流程从"一步走"解耦为两个逻辑阶段------"搜索（Search）"与"检索（Retrieve）"------并允许它们采用不同的文本粒度。
  • RAG 技术在 AI Agent 时代将无可争议地升级，它不再仅仅是"检索增强生成"中的一个环节，而是以"检索"为核心能力，扩展其数据范畴，演进为支撑所有上下文组装需求的上下文引擎（Context Engine），真正成为服务于 LLM 应用的、统一的上下文层（Context Layer）与数据底座。
  • 上下文的质量、实时性、动态组装能力和产品化水平，将直接决定下一代企业 AI 应用的竞争力。
  • RAG 将完成其自身的深刻蜕变，从"检索增强生成"的特定模式，升维为以"智能检索"为核心能力的"上下文引擎（Context Engine）"。
