Supabase 创始人：Personal Agent 的下一步，是给每个人一个 Personal Database

11/3/2026, 10:50:00 AM

📌 一句话摘要

Supabase 创始人阐述了 Personal Agent 时代的关键趋势：每个人都需要一个 Personal Database，这将重塑数据库的扩展架构和产品定位。

📝 详细摘要

本文围绕 Supabase 如何适应 AI Agent 爆发的核心问题——为每个人提供 Personal Database——进行深度剖析。首先，数据显示 Supabase 的注册用户从 300 万增至 1300 万，数据库数量从 800 万跃升至 5000 万，其中约 70% 新增来自 Agent。随后，作者通过 YC 创始人 Garry Tan、Harj Taggar 等人的访谈，阐明 Personal Agent 需要 Personal Database 来存储个人财务、健康等数据。文章进一步探讨了架构挑战：若 12 亿用户都创建数据库，传统 Postgres 将无法支撑，Supabase 通过收购 Turso、推出轻量级 Spark 产品，实现「从原型到 PB」的弹性扩展。最后，创始人 Paul Copplestone 强调，Supabase 必须全面转向 Code-First，重构错误信息以便 Agent 自我修复，并坚持为下一波 AI 工具浪潮保持适应性。

💡 主要观点

  1. Agent 主导的增长模式重塑了 Supabase 的用户画像 过去主要是开发者和创业公司使用，现在 70% 新增来自没有工程背景的普通用户和 Agent，这标志着 AI 时代个人化数据需求的爆发。
  2. Personal Database 成为 Personal Agent 的底层支柱 个人财务、健康等 N-of-1 软件需要持久化、可迁移的数据存储，Personal Database 解决了数据孤岛和 Agent 锁定风险。
  3. 架构从「单体」向「双端」弹性扩展转型 通过收购 Turso 提供轻量级 SQLite 方案，同时维持企业级多实例 Postgres，实现「从原型到 PB」的无缝跨尺度。
  4. 产品从 Dashboard 到 API 再到 Code-First 全链路重构 随着人类不再直接访问 Dashboard，Supabase 必须为 CLI 和纯代码优化，重写错误信息以便 Agent 自我修复。
  5. 选址 50 年品类、保持适应力是长期竞争的关键 数据库作为 50 年耐久品类，Supabase 通过持续监测 AI 工具浪潮、内部 Dogfooding 和生态联合实验，确保始终抢占下一波技术浪潮的入口。

💬 文章金句

  • Personal Database 可能会成为 Personal Agent 的重要一环，而 Supabase 正好站在这个位置上。
  • 现在的模型在构建应用这件事上已经超过了临界点。
  • 数据库已经存在了 50 年，我确信它还会再存在 50 年。
  • 我们必须全面转向 Code-First 和 Git-Native。
  • 选一个能活 50 年的品类，做适应变化最快的公司。
