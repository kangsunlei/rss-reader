快手 AB 场景提速 145 倍，从 Spark 到 Apache Doris 的加速实践

7/8/2026, 5:29:00 AM

📌 一句话摘要

快手将 AB 指标计算从 Spark 迁移至 Apache Doris，通过存储、计算和调度的深度优化实现 145 倍性能提升、资源下降 72%。

📝 详细摘要

文章详细介绍了快手 AB 实验平台从 Spark 迁移到 Apache Doris 的全过程。首先阐述了 Spark 时代的性能与成本瓶颈：单链路计算耗时约 21 分钟、全量流量下计算成本呈线性增长。接着分析了 Doris 在 Pipeline 执行引擎、向量化执行和 C++ 运行时方面的三大架构优势。随后重点讲解了四项落地优化：使用 Colocate Join 消除跨节点 Shuffle、通过 Local Distinct Grouping Sets 前置去重计算、将 Java UDF 改写为 C++ Native UDF 降低 CPU 热路径开销、以及通过物理隔离与组内调度（并发上限、上游反压、优先级队列）保障高优先级任务 SLA。最后介绍了元数据治理与结构压缩措施，使 FE 内存峰值从 370 GB 降至 270 GB，恢复时间从 27 分钟缩短至 10 分钟。整体实现了 145 倍性能提升和 72% 资源消耗下降，并刷新了单机 Doris 集群规模纪录（2000 节点、10 万核）。

💡 主要观点

  1. Colocate Join 消除跨节点 Shuffle，显著降低网络开销 按照 UID 哈希分桶存储，使相同 UID 的数据落在同一机器，查询时可在本地完成 Join 与聚合，仅传输少量结果集，网络传输量下降约 95%。
  2. Local Distinct Grouping Sets 将去重计算前移至节点本地 在 Colocate 前提下，先在各节点完成局部 Distinct，再进行全局聚合，避免全局 Shuffle，适用于大基数 Grouping Sets + Distinct 场景。
  3. Java UDF 改写为 C++ Native UDF，CPU 开销下降约 3 倍 通过 ThreadLocal 复用 Buffer、数组化配置访问、直接读取列原始值等优化，消除 JVM 调用、对象创建和 GC 开销，显著提升热路径执行效率。
  4. 物理隔离与组内调度保障高优先级任务 SLA 将集群划分为 12 个独立计算组，内部实施并发上限控制、上游反压和四级优先级队列，确保低优任务不会抢占高优资源，维持系统稳定性。
  5. 元数据容量建模与结构压缩降低 FE 内存占用并缩短恢复时间 基于每个 Tablet 约 11KB 的经验模型进行容量预测，引入 Cloud Table Inverted Index 并调优 G1 GC 参数，使 FE 内存峰值从 370 GB 降至 270 GB，恢复窗口从 27 分钟缩短至 10 分钟。
