AI Agent 要变强：两条路径（Skills vs SubAgent）

12/24/2025, 7:11:49 AM

📌 一句话摘要

文章深度探讨了 AI Agent 增强能力的两种核心路径：Skills（内化技能）和 SubAgent（外包子代理），并分析了它们在上下文管理、适用场景及进阶结合策略。

📝 详细摘要

作者详细阐述了提升 AI Agent 能力的两种不同模式：Skills 和 SubAgent。Skills 模式通过将能力直接植入主 Agent 的上下文，使其能够自主执行任务，适用于任务不复杂或需要全程掌控的场景，但易造成上下文污染。SubAgent 模式则将复杂子任务委托给独立的子代理，主 Agent 仅负责分派和验收，保持自身上下文清洁，适用于重度、耗时的子任务。文章强调了上下文管理对 Agent 性能的重要性，并提供了三种进阶玩法，包括“先展开再压缩”、“文件系统中转”和“利用 Rewind 功能”，以优化上下文使用。最后指出 Agent 架构设计与传统软件架构有共通之处，强调合理选择和组合这两种模式对提升 Agent 能力的决定性作用。

💡 主要观点

  1. Skills 模式通过内化技能增强 Agent 能力，但易导致上下文污染，适用于简单任务。 将能力描述和调用方式直接置入主 Agent 上下文，实现其自主执行。优点是信息互通、推理连贯，缺点是上下文长度受限和易混乱，适合任务简单或需主 Agent 全面掌控的场景。
  2. SubAgent 模式通过外包子任务保持主 Agent 上下文清洁，适用于复杂重度任务。 主 Agent 将任务派发给独立运行的子代理，子代理完成任务后返回结果。优点是主 Agent 上下文精简，缺点是信息传递需精心设计，适合子任务复杂、耗时且中间过程繁琐的场景。
  3. 上下文管理是 AI Agent 能力提升的关键工程瓶颈。 无论是 Skills 还是 SubAgent，核心挑战都在于如何高效管理有限的上下文。上下文过长会降低 Agent 推理效率，甚至导致“糊涂”现象。
  4. Skills 和 SubAgent 可结合使用，通过“先展开再压缩”等策略优化上下文。 文章提出利用文件系统做中转站、借助 Rewind 功能等进阶玩法，能有效在保留关键信息的同时，精简 Agent 的实时工作上下文，提升效率。
  5. AI Agent 架构设计与传统软件架构设计理念相通，需权衡取舍。 Agent 能力的提升并非单纯追求工具数量，更在于优雅的工具管理和架构设计，如模块化、状态隔离等，这些原则在软件工程领域已有成熟实践。

💬 文章金句

  • AI Agent 要变强，有两条完全不同的路。
  • Skills 就像是给主 Agent 装插件。
  • SubAgent，就像是委托外包。
  • 区别在上下文管理，上下文就是 AI 的记忆。
  • Agent 的竞争正在从"能调用多少工具"转向"怎么优雅地管理这些工具"。
