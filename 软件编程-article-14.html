📝 详细摘要

文章以阿里巴巴一次 Agent 岗位的面试为叙事线索，通过面试官老王与候选人的一问一答，串联起 AI Agent 开发中的关键技术和概念。内容涵盖 LangChain 的三层架构（抽象层、能力层、应用层）及其与 LangGraph 的关系、Agent 开发的四种模式（ReAct、Plan-and-Execute、Multi-Agent 协作、状态图编排）、LangChain 的六大核心模块详解、Multi-Agent 系统设计中工作流编排与传统 Multi-Agent 的区别、Agent 间通信协议 A2A 与工具扩展协议 MCP 的对比及实战应用、Transformer 架构的整体结构与关键组件、Self-Attention 与 Multi-Head Attention 的计算原理、主流大模型（文本、代码、音频、图像生成）的对比选型、AI 编程工具的使用经验、以及大模型预训练→SFT→RLHF/DPO 三阶段训练流程。文章语言轻松幽默，融入了面试互动的戏剧化场景，技术讲解清晰，适合面试准备和学习 AI Agent 技术栈的读者。

💡 主要观点

  1. LangGraph 通过图式编排解决了 LangChain 线性链的局限性。 LangChain 的 Chain 是 A→B→C 的线性执行，无法处理条件分支、循环和并行；LangGraph 将工作流升级为有向图，节点代表处理步骤，边可带条件，支持循环，更适合复杂 Agent 场景。
  2. Agent 开发方式可分为 ReAct、Plan-and-Execute、Multi-Agent 协作和状态图编排四种。 ReAct 交替推理与执行；Plan-and-Execute 先规划后执行；Multi-Agent 多个独立 Agent 通过消息协作；状态图编排由开发者定义图工作流，执行路径更可控。
  3. A2A 解决 Agent 间协作，MCP 解决 Agent 与工具间的能力扩展。 A2A 是 Agent to Agent 协议，通过统一的能力名片和 HTTP API 实现跨框架互操作；MCP 是 Agent to Tool 协议，将工具能力封装为标准接口，便于发现和调用。
  4. Multi-Agent 设计的关键在于状态同步与低耦合。 每个 Agent 应有独立的状态图，通过消息总线通信，订阅关心的消息类型，处理完发布结果，新增 Agent 不影响其他。

💬 文章金句

  • 两者的区别：A2A 是 Agent 对 Agent，MCP 是 Agent 对工具。一个解决 Agent 协作，一个解决 Agent 能力扩展。
