oRPC 发布 1.0 版本：原生支持 OpenAPI 与全链路类型安全

12/19/2025, 4:00:00 PM

📌 一句话摘要

oRPC 1.0 版本正式发布，它通过全面的 OpenAPI 集成和全链路类型安全，为 TypeScript API 开发带来了高效且功能强大的新选择，成功融合了 tRPC 和 ts-rest 的诸多优势。

📝 详细摘要

oRPC 1.0 正式发布，它是一个用于构建全链路类型安全 API 的 TypeScript 库，旨在为开发者提供一个融合了现有 RPC 和 REST 解决方案优势的综合替代方案。该版本提供了对 OpenAPI 的原生支持、端到端类型安全（包括输入、输出和错误）、对复杂类型（如 Date 和 File）的内置支持，并能与 React、Vue、Solid 和 Svelte 等主流前端框架通过 TanStack Query 无缝集成。oRPC 的核心设计理念是“强大而简洁”，允许开发者用类似标准函数的语法定义 API 端点，同时自动获得 OpenAPI 规范生成、服务器动作（Server Actions）兼容性和契约优先（Contract-first）的工作流支持。其性能基准测试显示，oRPC 在类型检查和运行时性能方面均优于 tRPC，并且 bundle 大小和内存占用均更低。尽管 Next.js 的服务器动作在简单 CRUD 操作中提供类型安全，但 oRPC 凭借其内置的 OpenAPI 支持，在复杂场景和特定用例（如服务器发送事件）中展现出独特价值。

💡 主要观点

  1. oRPC 1.0 版本通过原生 OpenAPI 集成和全链路类型安全，显著简化了 API 开发。 该版本内置 OpenAPI 支持，确保输入、输出和错误的全面类型安全，提高了开发效率和 API 质量，避免了额外配置和插件依赖。
  2. oRPC 在性能上超越了现有流行的解决方案（如 tRPC），提供更快的类型检查和运行时性能。 基准测试显示 oRPC 在类型检查速度、运行时性能以及资源占用（bundle 大小和内存）方面均优于 tRPC，为大型项目提供了更优选择。
  3. oRPC 独特地融合了 tRPC 的类型安全和 ts-rest 的契约优先特性，提供了全面且无需权衡的 API 解决方案。 它不仅兼容多种运行时环境（如 Cloudflare Workers、Deno、Bun、Node.js），还通过独特功能（如 WebSocket 休眠和 Pinia Colada 集成）满足了更广泛的开发需求。oRPC 独特地结合了 tRPC 的类型安全和 ts-rest 的契约优先特性（即通过预先定义接口实现前后端高效率协同开发），提供了全面而非权衡的 API 解决方案。

💬 文章金句

  • oRPC 引入了一系列旨在简化 API 开发，同时又保持企业级类型安全的功能。
  • 与需要第三方插件或已弃用 OpenAPI 支持的竞品不同，oRPC 将 OpenAPI 的合规性直接构建到其核心架构中。
  • 此次发布同时公布的性能基准测试显示，oRPC 相较于 tRPC 有显著提升，其类型检查速度快 1.6 倍，运行时性能快 2.8 倍，且 bundle 大小约为 tRPC 等效设置的一半。
