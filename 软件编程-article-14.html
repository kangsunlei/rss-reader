【第 3525 期】架起桥梁：在 Dart 中运行 JavaScript 模块

6/10/2025, 12:01:00 AM

📌 一句话摘要

文章详述了如何利用 Deno、Rust 和 Dart FFI，构建桥梁在 Dart 中高性能运行 JavaScript 模块。

📝 详细摘要

文章 addressing Dart 生态系统在特定领域（如现代 AI SDK）库相对缺乏的问题。作者团队提出并实现了一种方案，通过构建一个“桥梁”，使得 Dart 应用能够直接运行 JavaScript/TypeScript 模块。该方案核心在于利用 Rust 调用 V8 引擎（借助 Deno 的 V8 绑定）构建一个嵌入式 JS 运行时，并通过 Dart 的 FFI 与之通信。为了解决跨语言调用中的数据传递问题，特别是流式和复杂数据结构，方案采用了 Protobuf 进行高效且类型安全的序列化。文章展示了调用示例，并强调了方案带来的优势，包括节省开发时间、面向未来、接口一致性以及同进程调用带来的高性能。文末提供了相关的开源项目链接。

💡 主要观点

  1. Dart 生态在特定领域库不足，影响开发效率。 尽管 Dart 本身性能和特性优秀，但在 AI、云 API 等现代技术领域缺乏成熟的第三方 SDK，开发者需寻找替代方案。
  2. 利用 Deno、Rust 和 V8 构建嵌入式 JS 运行时是可行方案。 结合现有成熟技术栈（Deno 对 V8 的封装、Rust 的原生编译、Dart FFI）可以高效地实现跨语言模块调用，避免复杂封装或移植。
  3. Protobuf 确保跨语言数据传输的类型安全和效率。 使用 Protobuf 定义严格的数据协议，解决了 Dart 与 JS 之间流、回调和复杂结构传递的序列化问题，增强了系统稳定性。

💬 文章金句

  • 我们架起了一座桥 —— 一种无缝、低延迟、可嵌入的方式，让 TypeScript/JavaScript 模块可以在 Dart 中运行，就像它们本来就是 Dart 代码一样。
  • 我们没有选择嵌入 Node.js 或拼凑一个 JS 解释器，而是转向了 Deno。
  • 在 Dart 端，我们通过 FFI（外部函数接口）与这段原生代码进行交互，搭建了一个运行时入口点，能够加载模块、传递函数参数，并将响应流式传回 Dart。
  • Protobuf 给我们带来了两个巨大优势：1、在 Dart 和 TypeScript 之间通过生成类型建立了严格共享的协议；2、对兼容性的高度信任，尤其是在处理流式更新、增量数据或错误对象时。
  • 对 JavaScript 的调用发生在同一个进程中，避免了 IPC（进程间通信）带来的性能瓶颈。
