📌 一句话摘要

介绍 Bilibili 推荐系统优化批量 KV 查询的实践，包括创新的 NeighborHash 数据结构、访存优化和分布式架构。

📝 详细摘要

文章详细阐述了 Bilibili 在推荐系统中为解决海量数据、高吞吐批量查询和一致性问题而设计的分布式 KV 查询系统。核心创新是 NeighborHash 哈希表，通过 Lodger Relocation、Cacheline-aware 探测和 inline-chaining 等优化，显著减少缓存行访问次数，提升查询性能。在此基础上，结合异步内存访问链 (AMAC) 和 SIMD 指令并行化，进一步提高了大数据集下的查询吞吐。系统架构采用分布式设计，包含更新子系统和批量查询子系统，支持多分片、多副本和滚动更新期间的一致性。此外，通过集成 NVMe 存储冷数据，实现了成本效益与性能的平衡。该工作已发表于 CIKM'24。

💡 主要观点

  1. 创新的 NeighborHash 数据结构优化缓存访问 NeighborHash 通过 Lodger Relocation、Bidirectional Cacheline-aware 探测和 inline-chaining 设计，在高负载下有效减少缓存行访问，提升哈希表查询效率。
  2. 结合 AMAC 和 SIMD 进一步加速批量查询 引入异步内存访问链 (AMAC) 克服内存访问依赖，利用 SIMD 并行处理多个 Key 的探测，显著提高了 NeighborHash 在大数据集上的查询吞吐。
  3. 分布式架构确保系统可扩展性和数据一致性 系统采用分布式设计，通过多分片、多副本和优化的更新协议，在海量数据和频繁更新环境下，保证了系统的水平扩展能力和数据一致性。
  4. 集成 NVMe 存储方案实现成本效益 通过将冷数据存储在 NVMe，内存仅存储键和偏移/长度，结合 io_uring，在保持性能的同时显著降低了存储成本。

💬 文章金句

  • NeighborHash 最大限度的减少了每个查询对缓存行的访问次数，从而在有限的内存带宽约束下实现更大的查询吞吐量。
  • 由于现代体系结构下，CPU 性能的增速远大于内存访问延迟的增速，a.k.a memory wall，因此更快的 hashmap 实现往往都是基于 Linear Probing 进行优化...
  • 我们在批量查询情况下，对每一次查找建立状态机，查找期间维护其状态。
  • 与将所有数据存储在内存中相比，将冷数据存储在 NVMe 中，热数据存储在内存中更具成本效益。
