📝 详细摘要

本文介绍了小红书 Lab1327 的 QE Agent，它将 AI 引入测试流程，实现从需求理解到结果判断的自动化。通过上下文工程，Agent 能够高效管理测试记录；利用多端质量知识图谱，准确识别业务关系；通过动态执行 DAG，灵活调整测试计划；并使用联合断言，确保结果判断的准确性。这些技术结合，使得 QE Agent 能够自主推进测试，显著提升了测试效率和覆盖率。

💡 主要观点

  1. QE Agent 实现自主验证 QE Agent 能够理解需求、设计用例、执行测试，并判断结果，将测试人员从重复性工作中解放出来，专注于业务分析和异常处理。
  2. 上下文工程提升效率 通过按用例组织上下文，并结合检索和隔离，QE Agent 避免了重复读取历史记录，显著降低了 Token 消耗和执行时间，同时保持了信息的完整性。
  3. 多端质量知识图谱明确业务关系 知识图谱显式保存了页面、路由和接口之间的关系，帮助 Agent 快速定位测试入口和数据前置，避免了因业务理解不足导致的漏测或误判。
  4. 动态执行 DAG 灵活调整计划 动态执行 DAG 允许 Agent 根据现场执行结果实时调整测试计划，追加取证或跳过已完成步骤，确保测试流程的灵活性和适应性。
  5. 联合断言确保结果准确 通过联合断言，Agent 能够同时核对页面表现、对象关系和服务端数据，确保测试结果的全面性和准确性，避免单一维度的误判。

💬 文章金句

  • 我们希望，Agent 能理解需求，自己决定该测什么、怎么测，根据现场变化推进测试，并判断实际测试结果是否符合业务预期。
  • 上下文管理的常见方法包括上下文压缩、外置记忆、按需检索和上下文隔离。为减少重复读取，同时保留可回查的原始记录，我们结合后三种方法：需求、用例和执行记录完整保存在对话之外，Agent 按当前用例读取前置、步骤、预期和进度，截图与日志按需补读。
  • 我们采用多端质量知识图谱，显式保存已确认的入口、数据前置和跨端调用关系，供 Agent 在后续测试中沿关系查询页面、路由与接口，并追溯源码和版本。
  • 我们用逻辑 DAG（有向无环图）表达 Agent 的验证计划：节点表示准备、操作、取证等任务，边表示依赖。执行中可能出现新的证据缺口，原计划也需要随实际结果调整。为跟踪计划在执行中的变化，我们用动态执行 DAG 记录任务依赖和执行状态。
  • 取得证据后，Agent 进行联合断言，核对用例、账号和操作归属，逐项比较预期与实际结果。证据充分且符合预期则通过，明确不符则失败；不足或矛盾则记为待补证，再重新规划取证（Replanning）。
