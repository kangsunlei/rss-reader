基于本体的 AI 数据研发落地：淘宝行业经营分析实战

11/13/2026, 10:01:00 AM

📌 一句话摘要

本文提出构建企业级 AI 数据研发本体（Ontology），从生产代码自动抽取业务规则，为 AI SQL 生成提供精确上下文，显著提升数据开发效率并实现组织协作模式转变。

📝 详细摘要

文章聚焦企业级 AI 数据研发落地难题，指出通用大模型写 SQL 时缺乏业务知识导致选表、字段、口径等错误。作者提出本体方法论：从生产代码自动抽取隐性业务规则，构建结构化知识资产。本体包含表本体、业务规则、指标定义、血缘、值域等五类知识，采用三层架构实现业务理解结构化。通过自动化抽取、指纹校验、回溯验证等技术，降低人工维护成本。随后构建 OntSQL Agent 系统，实现按需召回与飞轮迭代。实测表明，引入本体后字段维度提升显著，AI 代码行占比提升至八成以上，需求交付周期缩短，团队从执行者转向规则定义者与质量把关者。

💡 主要观点

  1. AI 生成 SQL 的核心问题在于缺乏业务知识，而非模型能力 文章通过「店铺类型」和「品牌归一」案例说明，AI 无法获取业务规则、指标口径等隐性知识，导致选错表、用错字段、口径不对等错误。实测更强模型只能提升选表语法稳定性，无法解决业务规则偏差。
  2. 本体通过自动抽取生产代码，将隐性业务知识结构化为可复用的资产 本体包含表本体、业务规则、指标定义、血缘、值域等五类知识，采用三层架构。通过结构化三元组抽取规则，实现与 SQL 分支逐条对上，支持指纹校验、回溯验证，确保规则与生产代码一致。
  3. OntSQL Agent 采用按需召回与飞轮迭代，提升 AI SQL 生成的准确性 召回机制模拟人工思维过程，仅提供需求相关材料而非硬规则，避免注意力稀释。飞轮迭代通过研发修改 diff、评测集驱动、线上日志三条反馈链路，将真实使用中的修正持续回注本体，实现「生成 → 评测 → 归因 → 修正」的自动闭环。
  4. 引入本体后，AI 从辅助工具升级为数据开发的实际生产力 实测显示，AI 代码行占比从个位数提升至八成以上，需求交付周期显著缩短，团队从「逐行手写」转向「审核兜底」。人负责规则定义与质量把关，AI 负责确定性执行，实现「执行」转向「定义与判断」的角色分工升级。
