📝 详细摘要

本文由一位微信后台程序员撰写，详细介绍了其个人开发环境的搭建与优化方案。内容从基础的 Windows Terminal 与 WSL2（选择 Arch Linux）配置开始，逐步深入到 zsh（搭配 Oh My Zsh、tmux）的命令行环境定制，以及 Neovim 编辑器的 LSP 集成（使用 coc.nvim）。文章提供了详细的配置文件示例，包括 Windows Terminal 配色、SSH 连接配置、zsh 插件与别名设置以及 tmux 会话管理。此外，文章还重点推荐了一系列提升开发效率的命令行工具，如 protobuf-language-server、starpls、bat、fzf、delta、dust、eza、procs、ripgrep 和 tlrc，并提供了相应的配置代码和 GitHub 链接。作者旨在通过分享自己的实践经验，帮助读者搭建个性化且高效的后台开发工作流。

💡 主要观点

  1. 高度定制化的终端环境能显著提升开发效率 通过 WSL2、Arch Linux 和 Windows Terminal 的组合，配合字体和配色方案，为开发者提供简洁高效的跨平台命令行体验。
  2. zsh 和 tmux 是构建高效命令行工作流的核心 Oh My Zsh 插件（如 autosuggestions， syntax-highlighting， autojump）和 tmux 的会话管理能力，极大地简化了命令输入和多任务切换。
  3. Neovim 配合 LSP 可实现代码高效编写与管理 利用 coc.nvim 管理多种语言的 LSP 插件，实现代码补全、格式化和跳转，提升了在 Vim 系编辑器中的开发体验。
  4. 一系列精选小工具能进一步优化开发体验 如 bat（增强 cat）、fzf（模糊查找）、delta（Git Diff 增强）等工具，从文件浏览到代码审查，全方位提升了命令行操作的直观性和效率。

💬 文章金句

  • 本文详细分享了作者的后台开发环境配置方案及常用效率工具，旨在帮助读者搭建个性化、高效的开发工作流。
  • 使用 Arch 的一个原因是它可以滚动更新，使用最新的软件包，Ubuntu 每隔 2 年发布一个版本，升级太费事了。
  • tmux attach || exec tmux new-session && exit; 可以在 ssh 连接的时候自动打开 tmux，如果已经有 tmux 了，自动 attach 上去。
  • 使用 coc 的好处就是如果需要临时写个其他语言，找一下对应的插件 CocInstall 一下就行了。
  • fzf 用过的都说好。
