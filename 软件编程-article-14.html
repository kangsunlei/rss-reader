GitHub CLI 如何启用三角形工作流

4/25/2025, 4:00:37 PM

📌 一句话摘要

GitHub CLI 通过增强对三角形工作流的支持，并与 Git 配置保持一致，简化代码同步流程。

📝 详细摘要

本文介绍了 GitHub CLI v2.71.0 版本中对三角形工作流的增强支持，该工作流允许开发者从一个分支拉取更改，然后推送到另一个分支，常见于派生仓库场景。文章详细解释了 Git 引用、推送和拉取操作，以及如何在 Git 配置文件中设置三角形工作流（包括 `pushremote` 和 `remote.pushDefault` 选项）。更新后的 GitHub CLI 能够自动解析这些配置，使 `gh pr` 命令与 Git 配置一致，简化拉取请求的创建和管理。

💡 主要观点

  1. GitHub CLI 通过更好地支持三角形工作流和与 Git 配置保持一致，简化了跨分支的代码同步。 开发者可以更灵活地保持其功能分支与主分支同步，无需频繁地合并或变基 (rebase)，同时 `gh pr` 命令与 Git 行为保持一致。

💬 文章金句

  • 当你 fork 一个仓库，为你的 fork 做出贡献，然后发起一个拉取请求回到原始仓库，你就是在三角形工作流中工作。（When you fork a repo， contribute to your fork， then open a pull request back to the original repo， you're working in a triangular workflow.）
  • 如果你已经配置好了 `git pull` 和 `git push`，那么 `gh pr` 命令应该可以直接使用。（If you've configured `git pull` and `git push` to work， then `gh pr` commands should just work.）
  • 我们不断努力改进 GitHub CLI，并且我们希望 GitHub CLI 的行为能够合理地反映 Git 的行为。（We're constantly working to improve the GitHub CLI， and we'd like the behavior of the GitHub CLI to reasonably reflect the behavior of Git.）
