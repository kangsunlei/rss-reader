📌 一句话摘要

本文通过携程员工的满足感引入，深入探讨 AI Agent 的工作原理，包括 Prompt 分层、上下文压缩、Tool 与 Skill 区别、多 Agent 编排等技术细节。

📝 详细摘要

文章开头以携程员工在公司四年、月薪约三万且基本未涨薪却感到满足的感受为切入点，指出在快节奏的 AI 时代保持稳定心态的重要性。随后呈现一系列 Agent 面试题及详细回答，内容涵盖：Claude Code 与 Codex 的特点对比；Prompt 的九层分层结构及静态内容前置以利用 Prompt Caching 的原因；自研 coding agent 的三层上下文压缩机制（工具结果截断、对话历史摘要、紧急降级）；Tool 与 Skill 的本质、调用方式、返回内容及生命周期的区别及其互补关系；Skill 的渐进式加载设计（索引、正文、参考文档）以及避免系统 prompt 过长导致缓存命中率下降的原因；工具调用流程（LLM 生成 tool_call、策略审批、执行、结果回环）以及 Tool 调用频率远高于 Skill 加载的比例；多 Agent 编排中的规划器、Worker、审查器角色分工、系统提示词与对话历史隔离以及职责边界的设计 rationale；最后强调在 AI 快速变化的环境中保持稳定心态和持续学习的重要性。

💡 主要观点

  1. Prompt 分层设计与缓存机制 Prompt 被划分为 9 层：前 4 层为静态内容（身份定义、人格层、模式层、审批层），后 5 层为动态内容（运行时上下文、项目记忆、Skills 索引、上下文管理策略、收尾指令）。静态内容放在最前方可利用 Prompt Caching 的最长公共前缀特性，使每轮请求前缀保持一致，从而显著提高缓存命中率、降低 token 消耗。
  2. 三层上下文压缩策略 第一层对单次工具返回结果进行截断，超阈值时保留首尾及关键信息，成本几乎为零；第二层在对话总 token 接近窗口上限（约 80%）时对早期历史进行摘要，保留用户核心诉求、已完成操作、达成共识及待办事项；第三层为紧急降级，在前两层仍不足时按优先级丢弃非核心辅助上下文（如 Skills 索引、低优先级项目记忆），以保证核心对话不被误删。三层粒度从细到粗、触发条件从宽到严，避免过早或过晚压缩导致的信息丢失或溢出。
  3. Tool 与 Skill 的区别及协作关系 Tool 是可执行能力，如读文件、跑命令、搜代码，通过 tool_call 协议调用，返回结构化结果，生命周期为单次调用；Skill 是决策知识，即怎么用工具、什么策略、什么规范，通过 load_skill 工具注入下一轮消息，返回 Markdown 指令，加载后驻留在上下文中持续影响决策。两者互补而非替代：Tool 相当于手，Skill 相当于脑子里的经验，缺一不可。实际使用中 Tool 调用频率远高于 Skill 加载，比例约为 10:1~20:1。
  4. 多 Agent 编排中的角色划分与职责隔离 团队模式下包含规划器、Worker 和审查器三种角色。规划器仅负责将任务拆解为带依赖关系的执行计划，不调用任何工具；Worker 拥有完整工具集和独立对话历史，负责具体步骤的执行，可并行；审查器负责质量把关，检查 Worker 产出，不合格则打回重做（最多两次）。每个角色有专属系统提示词和完全隔离的对话历史，避免信息交叉干扰，使问题定位清晰：代码错误找 Worker，计划不合理找规划器，漏检找审查器。

💬 文章金句

  • 在如今这个快节奏的 AI 时代，能说出'满足'两个字的人，我是真的佩服。
  • 要我说，稳定才是最好的学习姿势。
  • Claude Code 是 Anthropic 做的终端 Agent，最大的特点是实时交互，和 AI 时代完美契合，不需要 IDE 就可以完成 Coding 工作。
  • Prompt Caching 会按最长公共前缀命中。前 4 层是静态内容，放在提示词最前面，每轮请求的前缀都一样，缓存命中率能拉到最高。
  • 三层压缩的内容完全不一样。第一层压的是工具输出，第二层压的是对话历史，第三层丢的是辅助上下文。
  • Tool 是手，Skill 是脑子里的经验。你不能用经验代替手去拧螺丝，也不能用手代替经验去判断该拧哪颗。
  • 工具调用频率远高于 Skill 加载，差不多 10:1 到 20:1 的比例。
  • 规划器负责把任务拆解成带依赖关系的执行计划，只动脑子不动手，不调任何工具。
  • 工具执行权集中在 Worker 手里，规划器和审查器只做判断。出了问题也好定位------代码写得不对找 Worker，计划拆得不合理找规划器，漏检了找审查器，职责边界清清楚楚。
