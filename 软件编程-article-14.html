程序员的新岗位是监工！Codex 负责人：我不想再同时盯 10 个 Agent 了，未来让系统接手分工，人只在关键时刻拍板

8/26/2026, 9:37:00 AM

📌 一句话摘要

本文通过访谈 OpenAI Codex 负责人 Tibo，探讨了多 Agent 并行工作模式下人类注意力的瓶颈，并提出未来 AI 编程应从「管理多个 Agent」转向「由系统自动调度与分工」的范式转移。

📝 详细摘要

文章基于对 OpenAI Codex 负责人 Tibo 的深度访谈，揭示了当前 AI 编程工具的一个核心痛点：当用户同时运行十几个 Agent 时，人类的注意力会被频繁的上下文切换、权限审批和任务状态监控所耗尽。Tibo 指出，下一代 AI 产品不应只是增加 Agent 的并行度，而应致力于「注意力管理」。他设想了一种理想的架构：底层由统一的 Agent 执行系统驱动，由系统自动处理 Skill、Memory 和 Subagent 的分工与维护，仅在涉及高风险动作（如生产环境变更、密钥访问）时才请求人类介入。这种转变意味着程序员的角色将从「操作员」进化为「决策者」或「监工」。

💡 主要观点

  1. 多 Agent 并行导致人类注意力过载。 当用户同时管理十几个 Agent 时，频繁的上下文切换和任务状态追踪会成为新的认知负担，使人陷入「消息分拣员」的窘境。
  2. 下一代 AI 产品应实现「注意力管理」。 产品设计应从单纯追求模型速度转向管理用户注意力，通过系统自动调度任务顺序、补充上下文，仅在关键节点打断用户。
  3. 从「手动维护配置」转向「系统自动消化细节」。 目前的 Skill、Memory 和 Subagent 维护成本极高，未来系统应能自动理解用户目标与团队背景，减少人工维护规则文件的「配置债」。
  4. 基于风险等级的自动化审批机制。 系统应区分低风险（如读取、测试）与高风险（如写入生产、删除数据）动作，实现「默认放行、高危审批」的智能化工作流。

  • 应该由技术来适应你。
  • 只把高风险动作交给人确认。
