Canvas 高性能 K 线图的架构方案

10/3/2025, 8:42:34 PM

📌 一句话摘要

文章详细阐述了基于纯 Canvas 实现高性能 K 线图的架构方案，涵盖像素优化、分层渲染、数据缓冲区和交互解耦等关键技术。

📝 详细摘要

本文深入探讨了如何利用纯 Canvas 构建高性能 K 线图的架构方案。作者作为证券行业的前端从业者，分享了其项目经验，旨在实现支持无限滑动、样式定制且不依赖第三方库的 K 线图。文章首先介绍了 Canvas 绘图中的常见像素模糊问题及其解决方案，如 `cxt.translate(0.5， 0.5)` 应对整数坐标模糊，以及高像素比 (DPR) 设备的适配。随后，详细阐述了 K 线图的样式配置、均线计算逻辑（包括优化计算方法），并重点介绍了通过“不动层、变动层、交互层”三层 Canvas 实现分层渲染以提升性能的策略。文章还涵盖了网格线、均线、蜡烛柱体和文字的基础几何绘制技巧，以及移动端触摸事件（快速拖拽与长按滑动）的解耦设计，并引入了“数据缓冲区”（类似虚拟列表）机制来控制数据量和优化加载体验。最后，总结了分层渲染、离屏渲染、数据缓冲区和节流防抖等性能优化手段，并提供了部署到 GitHub Pages 的简要指南。

💡 主要观点

  1. Canvas 像素级优化是高性能绘图的基础 解释了 Canvas 绘制直线时整数坐标导致的模糊问题，并通过 `cxt.translate(0.5， 0.5)` 偏移半像素进行修正。同时，强调了高像素比 (DPR) 设备下 Canvas 尺寸设置的正确方法，避免拉伸模糊。
  2. 分层渲染和数据缓冲区是提升复杂图表性能的关键 通过将 K 线图拆分为“不动层、变动层、交互层”三个 Canvas 进行分层渲染，显著减少了重绘开销。结合类似虚拟列表的“数据缓冲区”机制，有效管理了海量数据，提升了滑动流畅度。
  3. 精细的交互解耦设计保障了用户体验 针对移动端触摸事件，文章提出了通过定时器判断“快速拖拽”与“长按滑动”的解耦方案，使得 K 线图的左右滑动和十字交叉浮层显示能够平滑切换，优化了用户交互体验。

💬 文章金句

  • canvas 默认线条会与整数对齐，从而横线的粗度看起来不是 1px，而是 2px。并且由于粗度被拉伸，颜色也会被淡化。
  • 处理方式也很简单， 通过 cxt.translate(0.5， 0.5) 将坐标往下移动 0.5 个像素，然后接下来的所有点， 都保证是整数即可， 这样就能保证不会被拉伸。
  • 不要随便通过 css 去设置 canvas 的宽高， 容易被拉伸变形或者导致模糊。
  • 为了减少重绘，提高性能，可以将 K 线图做分层渲染。那分几层合适？我认为是三层。
  • 总体思想是， 从 startIndex 开始渲染屏幕的第一条柱体， 当前屏幕的左右两边， 都预留 2 屏数据，防止用户拖拽频繁调用接口， 导致卡顿； 同时也控制了 arraylist 的长度， 这是虚拟列表的变形，这样设计，可以做一个 **高性能** 的 k 线图。
