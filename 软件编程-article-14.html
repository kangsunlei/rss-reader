ARMO 研究揭示：io_uring Rootkit 技术绕过 Linux 安全工具

9/16/2025, 10:00:00 AM

📌 一句话摘要

ARMO 研究揭示了一个关键的 Linux 漏洞，概念验证 Rootkit 能够绕过主要安全工具的检测，利用 io_uring 绕过传统系统调用监控。

📝 详细摘要

ARMO 安全研究人员发现 Linux 运行时安全工具中的一个重大漏洞。该漏洞演示了如何利用 `io_uring` 异步 I/O 接口绕过传统的系统调用监控。他们开发了 "Curing"，这是一个完全通过 `io_uring` 操作运行的概念验证 Rootkit，成功逃避了 Falco 和 Linux 版 Microsoft Defender for Endpoint 等主要解决方案的检测。这种绕过利用了 `io_uring` 的共享环形缓冲区，这些缓冲区创建了一个替代通信路径。通常情况下，基于 eBPF 的安全代理不会监控此路径。该研究强调了当前仅依赖系统调用钩子的安全方法存在根本局限性，暴露了开源和商业工具中的广泛漏洞。文章提出了检测策略，包括内核运行时安全检测（KRSI），以实现更全面的安全防护，监控异常的 `io_uring` 使用情况，并识别替代内核钩子点，借鉴了 Windows 安全模型从不可靠的 SSDT 钩子转向结构化通知例程的演变思路。对于云原生环境而言，此漏洞尤为关键，强调了安全解决方案需要适应不断发展的内核接口。

💡 主要观点

  1. io_uring 接口使得一种新型 Rootkit 技术能够绕过传统的 Linux 安全工具。 io_uring 机制专为高性能 I/O 而设计，它通过使用共享环形缓冲区进行内核 - 用户通信来创建一个盲点，从而规避了标准系统调用监控。
  2. 由于现有安全解决方案主要依赖以系统调用为中心的监控，因此基于 eBPF 的方案在很大程度上无法有效防御 io_uring 绕过。 许多安全供应商依赖于钩取系统调用进行检测，但 io_uring 操作不会调用这些系统调用，从而在 Falco 和 Microsoft Defender for Endpoint 等工具的保护中留下了一个关键缺口。
  3. 解决 io_uring Rootkit 需要超越系统调用监控，转向更深入的内核集成，如 KRSI。 长期检测策略涉及内核运行时安全检测（KRSI），以实现更强大的基于 LSM 的钩子，或监控异常的 io_uring 使用模式以适应不断发展的内核接口。

💬 文章金句

  • 我们介绍了关于如何有效绕过 Linux 运行时检测工具的研究。这项研究与任何 Linux 环境相关，尤其是在现代云原生环境中
  • io_uring 绕过表明，随着内核接口的发展，这种假设越来越不可靠。
  • 研究人员强调，安全供应商需要超越简单的系统调用监控，以保持对现代规避技术的有效性。
  • 此漏洞对于 Linux 构成容器化基础架构基础的云原生环境具有特殊意义。
  • 随着内核接口继续通过新的异步机制和性能优化进行扩展，未能适应的安全工具将留下越来越大的保护缺口。
