Cloudflare Workers 新增 Node.js HTTP 服务器支持

9/20/2025, 2:26:00 PM

📌 一句话摘要

Cloudflare Workers 现在支持 Node.js HTTP 客户端和服务器 API，从而能够将现有的 Node.js 应用程序直接迁移至其无服务器边缘平台。

📝 详细摘要

Cloudflare 已将 `node:http` 客户端和服务器 API 集成到其 Workers 平台中，允许开发者将现有的 Node.js 应用程序（包括使用 Express.js 和 Koa.js 等框架构建的应用）直接部署到边缘。这提供了零冷启动、自动扩展和降低延迟等优势，而无需进行大量的代码重写。客户端 API 使用原生 `fetch()` API 重新实现，而服务器端操作则利用独特的「桥接系统」，通过基于端口的路由将 Node.js 服务器连接到 Workers 的请求处理模型。虽然这提供了实质性的兼容性，但由于托管的无服务器环境，某些 Node.js API（例如 Agent API（作为空操作）、尾部标头、提前提示和 TLS 特定的选项）未得到完全支持。这一战略性增强旨在简化 Node.js 开发者向无服务器边缘计算的过渡，与其他超大规模厂商的类似产品形成呼应。

💡 主要观点

  1. Cloudflare Workers 现在支持 Node.js HTTP 客户端和服务器 API，从而能够直接进行应用程序迁移。 这种集成允许开发者在 Cloudflare 的无服务器边缘上运行现有的 Node.js 应用程序和流行的框架（如 Express.js），从而最大程度地减少部署所需的代码更改。
  2. 该实现利用了原生 Workers 功能和一个独特的「桥接系统」来进行服务器端操作。 客户端 API 构建在 `fetch()` 之上，而服务器端 `listen()` 调用在内部注册服务器，通过端口号路由请求，从而确保在无服务器环境中的兼容性。
  3. 尽管存在一些 API 限制，但这种增强为开发者提供了显著的优势。 用户可以获得零冷启动、自动扩展和更低的应用程序延迟，但由于托管环境，某些 Node.js API（例如，Agent，TLS 选项）未得到完全支持。

💬 文章金句

  • 这项重要补充将大家熟悉的 Node.js HTTP 接口引入边缘计算，使您能够在全球范围内以零冷启动、自动扩展和显著降低用户延迟的方式部署现有的 Express.js、Koa 和其他 Node.js 应用程序，而无需重写您的代码库。
  • 服务器端实现尤其值得关注。由于 Workers 无法创建监听特定端口的传统 TCP 服务器，因此我们创建了一个桥接系统，将 Node.js 风格的服务器连接到 Workers 请求处理模型。
  • 这为无服务器 Node.js 释放了令人兴奋的可能性。更平滑的过渡意味着更广泛的采用和更快的创新。
