解构 Clawdbot：本地架构、记忆管理、Agent 编排与上下文组装原理

2/3/2026, 12:45:00 AM

📌 一句话摘要

本文深度解构了本地优先 AI Agent 运行时 Clawdbot 的核心架构、分层记忆管理机制及基于 ReAct 的动态编排原理。

📝 详细摘要

文章详细介绍了 Clawdbot（现名 OpenClaw）的技术实现方案。作为一个本地优先（Local-First）的 AI Agent 环境，它通过守护进程、Node.js 运行时和系统原生工具链，实现了对本地文件、浏览器及 Shell 的深度控制。核心亮点在于其仿生学的记忆管理系统，将记忆分为工作记忆（Session）、情景记忆（Daily Logs）和语义记忆（Curated Memory），并利用 USER.md 和 MEMORY.md 区分用户画像与知识积累。此外，文章还展示了其复杂的 System Prompt 分区组装逻辑，以及如何通过 ReAct 模式和子智能体（Sub-Agents）处理复杂任务，并指出了本地 Agent 在 Token 消耗和模型依赖方面的挑战。

💡 主要观点

  1. Clawdbot 采用本地优先架构，赋予 Agent 系统级操作特权。 通过直接运行在 Host 机器并接管浏览器实例，Agent 能够突破沙盒限制，执行文件管理、脚本运行及绕过反爬虫验证的网页自动化任务。
  2. 设计了仿生学的三层记忆模型，实现隐私与长期记忆的平衡。 将记忆分为高频变动的 Session、用户可见的 Daily Logs 和提炼后的 MEMORY.md，模拟人类从海马体到皮层的记忆固化过程。
  3. 利用 USER.md 与 MEMORY.md 实现了用户画像与知识库的解耦。 USER.md 存储用户偏好和价值观（你是谁），MEMORY.md 存储项目决策和客观知识（我们知道什么），确保 Agent 既专业又懂用户。
  4. 采用分区组装的 System Prompt 设计，支持动态环境感知。 提示词根据当前工作区、工具集、时间及 promptMode 动态生成，确保 Agent 在不同场景（如主会话或子 Agent）下拥有最适宜的指令上下文。

💬 文章金句

  • USER.md = 'Who you are' (你是谁)；MEMORY.md = 'What we know' (我们知道什么)。
  • Text > Brain：如果想记住某事，就把它写进文件。‘脑内笔记’无法在会话重启后存活。
  • Be genuinely helpful， not performatively helpful. 跳过‘很高兴为您服务’之类的废话，直接行动。
  • 它不是黑盒 SaaS，而是全透明、可魔改的本地运行时。你可以像写代码一样定制自己的‘第二大脑’。
