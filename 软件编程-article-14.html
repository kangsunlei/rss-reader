Airbnb 如何利用 LLM 加速测试迁移

3/28/2025, 12:00:00 AM

📌 一句话摘要

Airbnb 利用大规模语言模型和自动化工作流程，显著加速了 React 测试用例从 Enzyme 到 React Testing Library 的迁移。

📝 详细摘要

Airbnb 通过结合 LLM 和自动化工作流程，加速了近 3.5K 个 React 测试文件从 Enzyme 到 React Testing Library (RTL) 的迁移。工程师们发现，相比于提示词工程，多次重试直至转换成功的方法更为有效。他们将迁移过程分解为多个步骤，包括将 Enzyme 重构为 RTL，修复 Jest 测试中的错误，运行 linter 和 TypeScript 编译器。在每个步骤中，如果验证失败，LLM 会被提示所有发现的错误，并要求在源文件中修复它们。对于复杂的文件，工程师们采用了一种“分析、优化、迭代”的策略，即分析每个失败的案例，更新提示和脚本，然后重新运行该过程。这种迭代方法，加上专注于为任务选择合适的 LLM，将原本估计需要 1.5 年的工程项目压缩到短短六周，同时保留了原始的测试意图和代码覆盖率。

💡 主要观点

  1. 多次重试比提示词工程更有效 Airbnb 工程师发现，在代码生成任务中，多次重试直至成功比优化提示词更有效；这种“暴力破解”方法在实践中表现良好。
  2. 分步骤迁移有助于提高效率和可追踪性 通过将迁移过程分解为多个步骤，可以跟踪进度，提高特定步骤的成功率，并根据需要重新运行文件或步骤。
  3. LLM 在简化测试迁移方面非常有效 通过利用 LLM 进行测试迁移，Airbnb 将一个估计需要 1.5 年的项目压缩到短短六周，同时保留了原始的测试意图和代码覆盖率。该团队还专注于选择合适的 LLM 以最大限度地提高效率。

💬 文章金句

  • Airbnb 工程师学到的最重要的一课是，提示词工程不如多次重试转换直至成功有效，Airbnb 员工软件工程师 Charles Covey-Brandt 将这种方法描述为“暴力破解”。
  • 这种基于步骤的方法为我们的自动化管道提供了坚实的基础。它使我们能够跟踪进度，提高特定步骤的成功率，并在需要时重新运行文件或步骤。
  • 总的来说，利用 LLM 进行测试迁移将原本估计需要 1.5 年的工程项目压缩到短短六周，同时保留了原始的测试意图和代码覆盖率。
