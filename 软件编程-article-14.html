使用 OpenAI 和 Cloudflare 的 Agent SDK 构建智能体

6/25/2025, 2:00:00 PM

📌 一句话摘要

结合 OpenAI 和 Cloudflare 的 Agent SDK，使用 Durable Objects 构建持久化、可扩展和可寻址的 AI 智能体。

📝 详细摘要

本文探讨了 OpenAI 的 Agent SDK 与 Cloudflare 的 Agent SDK（利用 Durable Objects）相结合构建高级 AI 智能体的协同作用。它阐明了 OpenAI 的 SDK 提供了智能体的“大脑”（认知、规划、工具），而 Cloudflare 提供了“环境”（持久化执行、身份标识、状态管理）。这种关注点分离使开发者能够专注于智能体逻辑。文章介绍了持久化智能体实现的三种架构模式：多智能体系统、人在回路工作流以及通过 WebSockets 等各种接口可寻址的智能体（通过 Twilio 演示）。主要经验教训包括：Cloudflare 的持久化对于 OpenAI 的无状态 SDK 是必需的；Durable Object 的路由作为控制身份和状态的“智能体工厂”的作用；以及智能体可组合性的强大之处。作者总结说，这种结合能够构建智能、分布式且能力强大的智能体，鼓励开发者探索这些工具。

💡 主要观点

  1. 结合 OpenAI 和 Cloudflare 的 SDK 可创建兼具智能和持久化的智能体。 OpenAI 提供推理和工具，而 Cloudflare 的 Durable Objects 提供状态、身份标识和可扩展执行，使智能体能够随时间推移记住和适应。
  2. Cloudflare Durable Objects 是使 OpenAI 智能体具备状态的关键。 OpenAI 的 SDK 默认是无状态的。Durable Objects 提供了必需的持久化存储，以在交互过程中维护智能体的记忆和状态。
  3. 持久化智能体实现了高级架构模式。 得益于由 Durable Objects 支持的状态化智能体，多智能体系统、人在回路流程以及通过非 HTTP 接口可寻址的智能体变得可行。
  4. Durable Object 路由管理智能体的身份标识和生命周期。 使用 `idFromName` 可确保重复调用时智能体实例及其状态的一致性，有效地作为根据用户或任务划分智能体范围的工厂。

💬 文章金句

  • 虽然编排框架定义了智能体如何思考，但我们的 SDK 专注于它们在哪里运行，抽象掉了基础设施，以实现在我们的全球网络上的持久化、可扩展执行。
  • OpenAI 的 Agent SDK 给你的是*智能体*：一个推理循环、工具定义和记忆抽象。但它假设你提供自己的运行时和状态。
  • Cloudflare 的 Agent SDK 给你的是*环境*：我们网络上具有身份标识、状态和内置并发控制的持久化对象。但它不告诉你智能体应该如何行为。
  • OpenAI 的 SDK 默认是无状态的……相比之下，Cloudflare 的 Durable Objects *是*持久化的——这就是重点所在。
  • 智能体是可组合的——这非常强大。
