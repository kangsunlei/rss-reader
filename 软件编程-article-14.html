📌 一句话摘要

通过在多个 Claude Code Agent 协作时使用共享状态文件，可将重复沟通导致的 Token 消耗降低约 42%。

📝 详细摘要

本文介绍了一项使用 Claude Code 进行多 Agent 协作的研究：研究人员通过 1902 次实验发现，当 8 个 Agent 频繁沟通时，将重复信息写入共享状态文件（如 AGENT_STATUS.md）可使输出 Token 减少约 42%。文章解释了 Token 浪费的根源在于消息中的来回确认和信息重复，提出在项目根目录建立状态文件，记录任务分配、接口约定、已完成事项和当前阻塞，并约定所有 Agent 通过读取此文件获取进度，以减少不必要的交流。同时提醒状态文件应保持简洁，仅保留最新状态；两 Agent 直接交流或 Agent 自行写入结果时可省略该文件。研究还表明，当 Agent 数量过多且交接不明确时，协作成功率会显著下降，提示协作规模需与任务复杂度匹配。

💡 主要观点

  1. 共享状态文件可显著降低多 Agent 协作时的 Token 消耗 研究表明，在 8 个 Agent 频繁沟通的场景下，将重复信息写入共享文件后输出 Token 减少约 42%，因为避免了消息中的重复讲述和确认。
  2. Token 浪费主要来源于消息中的重复讲解和确认 当 Agent 需要通知其他方接口变更时，往往需要重复说明背景、等待对方确认，这些来回都消耗 Token；写入文件后只需一次写入、多次读取，大幅减少交流轮次。
  3. 使用方法：在项目根目录创建 AGENT_STATUS.md 并约定查看规则 文件应记录要做什么、谁负责哪部分、接口怎么约定、哪些事已经定了、现在卡在哪里；所有参与协作的 Agent 需要提前约定，后续查询进度或接口时直接读取此文件，免除额外消息。
  4. 保持状态文件简洁，仅保留最新状态；特殊情况下可省略 文件不应累积聊天记录，否则会变长且失效；只有两 Agent 时直接消息更高效；若 Agent 本来就把结果写入文件，其他 Agent 可直接读取，无需额外状态文件。
  5. Agent 数量过多且交接不明确会导致协作失败 研究中，将八步骤任务分配给 8 个 Agent（每人一步）导致十次全失败，原因是拆分后中间交接不到位；这提示协作规模需匹配任务复杂度，并保证清晰的交接机制。

💬 文章金句

  • 把大家反复要用的信息，写进同一份文件。
  • 在项目根目录建一份状态文件，比如 AGENT_STATUS.md，把要做什么、谁负责哪部分、接口怎么约定、哪些事已经定了、现在卡在哪里，都写进去。
  • 写进文件以后，谁需要谁去看，就能少来回说几轮，token 自然就省下来了。
  • 要注意的是，这份状态文件也别越写越长，只留最新状态，别把聊天记录全塞进去了。
  • 同一个八步骤任务，交给 2 个或 4 个 Agent，十次能做对九次。换成 8 个 Agent，每个负责一步，十次全失败了。
