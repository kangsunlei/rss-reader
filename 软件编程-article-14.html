【第 3655 期】浏览器即运行时：一个零后端 AI 应用的前端架构实践

2/6/2026, 1:03:00 AM

📌 一句话摘要

本文探讨了如何利用 WebLLM、Yjs 和 WebGPU 等前沿技术，构建一个完全在浏览器端运行、零后端、隐私优先的 AI 财富规划系统架构。

📝 详细摘要

文章详细介绍了名为 Meridian 的财富规划平台的架构实践，提出“浏览器即运行时”模式。作者通过 WebLLM 在浏览器端直接运行量化的 Llama 3.2 模型实现边缘 AI 推理，利用 Yjs 和 IndexedDB 构建本地优先（Local-first）的分布式状态管理系统，并使用 React Three Fiber 结合 WebGPU 进行高性能金融数据可视化。该架构旨在解决金融数据隐私、云端计算成本和 API 延迟问题，同时也客观分析了模型下载冷启动和硬件依赖等必然的权衡，展示了“主权云”应用的新范式。

💡 主要观点

  1. 提出“浏览器即运行时”模式，将浏览器从展示终端转变为真正的计算节点。 该模式主张将计算负载从云端转移到用户的边缘硬件，符合 FinOps 理念，让计算发生在数据所在地，从而消除后端成本并提升隐私性。
  2. 利用 WebLLM 实现边缘原生 AI 推理，平衡延迟、成本与隐私。 通过在本地运行 4-bit 量化的 Llama 3.2 模型，生成速度可达 40 tokens/s，在保护敏感金融数据不外流的同时，提供了优于云端 API 的响应体验。
  3. 采用 Yjs 与 IndexedDB 构建本地优先的分布式状态管理层。 利用 CRDT 技术解决多标签页或离线状态下的数据冲突，实现异步、增量的持久化存储，其可靠性足以媲美传统的服务端数据库。
  4. 通过 WebGPU 加速的 3D 渲染技术解决复杂金融数据的可视化疲劳。 使用 React Three Fiber 的 InstancedMesh 技术，在一次 draw call 中渲染上万个数据点，实现流畅的蒙特卡洛模拟展示，提升了专业工具的交互深度。
  5. 明确了零后端架构在冷启动成本与硬件依赖方面的必然权衡。 移除后端意味着用户需承担首次加载模型的大流量下载成本，且设备必须支持 WebGPU，这决定了该架构更适合专业工具而非轻量消费应用。

💬 文章金句

  • 最安全的数据，是你从未持有过的数据。
  • “浏览器即运行时”模式，将其视为一个真正的计算节点。这种方式把计算负载从云端转移到边缘端。
  • 金融数据是一种“放射性负债”。
  • 架构设计本质上是一门权衡的艺术。移除后端之后，我们也接受了两个主要代价：“冷启动”成本和硬件依赖。
  • Meridian 不只是一个财富规划工具，它是一个主权云（Sovereign Cloud）应用的概念验证。
