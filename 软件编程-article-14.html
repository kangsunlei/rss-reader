【早阅】LLM 时代的前端革命：React 不再是框架，而是平台

12/12/2025, 1:02:00 AM

📌 一句话摘要

文章探讨了在 LLM 时代，React 如何从一个前端框架演变为事实上的“平台级标准”，并分析了这种趋势对新框架、Web 平台特性以及整个前端生态的影响。

📝 详细摘要

在 LLM（大语言模型）与前端生态深度交织的背景下，文章指出 React 已不再仅仅是前端框架，而是演变成了平台级标准。由于 LLM 主要学习现有网站数据并默认输出 React 代码，以及各种 AI 工具和 IDE 也将 React 硬编码到系统提示中，这形成了一个“LLM 学习-输出-新网站采用”的自我强化循环。这导致新框架和 Web 平台特性即使技术上更优，也难以被采用，面临作者提出的“死框架理论”困境，因为它们不在 LLM 的训练语料中，缺乏成熟的生态系统，也难以对抗开发者对 React 的熟悉和信任。文章深入分析了数据统计差异，并提出了两种强化循环机制。最后，作者给出了对框架作者、平台开发者和工具创造者的建议，强调了创新仍需进行，但必须正视 LLM 时代的生态阻力，并呼吁将竞争重心从“开发者体验”转向“用户体验”。

💡 主要观点

  1. LLM 的训练和输出偏好使 React 成为事实上的前端“平台级标准” LLM 从现有海量 React 网站中学习，并默认输出 React 代码，AI 工具为迎合开发者需求也硬编码 React，形成自我强化循环，巩固了 React 的主导地位。
  2. 新框架和 Web 平台特性在 LLM 时代面临“死框架理论”的巨大推广挑战 由于不在 LLM 训练语料中、缺乏生态系统支持和开发者惯性，即使技术更优的新框架和平台特性也难以被工具输出和开发者采纳，面临“生而即死”的困境，这被称为“死框架理论”的核心。新框架需要突破 LLM 训练数据滞后、工具默认设置以及开发者认知惯性等多重障碍。
  3. 文章呼吁将竞争重心从“开发者体验”转向“用户体验” 当所有工具都默认输出 React，竞争将聚焦于输出质量和用户结果。未来应关注 Core Web Vitals 等用户体验指标，推动生态系统为用户优化，而不是仅仅为开发者提供便利。
  4. Web 平台应专注于“无法在用户层实现的核心能力” 对于平台开发者而言，投入仅提升开发者体验的特性意义不大，应转向开发多页面视图过渡、WebGPU、WebAuthN 等能带来显著用户价值的底层能力，这些是用户层无法构建或难以高效实现的。

💬 文章金句

  • LLM 学习现有网站 → 默认输出 React → 新网站用 React → React 网站更多 → 下次训练再学到 React。
  • 如果你今天要打造一个能吸引开发者的工具，你必须让生成的代码是 "可维护的"。而对于绝大多数的 Web 开发者来说，"能够维护的代码" 如今就意味着 "React"。
  • 如果某样东西不在 LLM 的训练数据中，那它就等于不存在。至少在 12--18 个月内不会被 "看到"。
  • 这不是因为 React 是最好的工具，也不是因为它更适合 LLM... 而是因为 React 已经跨过了 "网络效应让替代品难以生存" 的那条线。
  • 当工具为了吸引用户而竞争时，输出能带来更好体验的工具将获胜。这样的竞争压力会推动整个生态系统为用户优化，而不仅仅是为开发者。
