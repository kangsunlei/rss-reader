GhostAction 供应链攻击卷土重来，恶意 GitHub Actions 窃取 CI/CD 凭证

10/9/2026, 10:00:00 AM

📌 一句话摘要

新一轮 GhostAction 供应链攻击已攻陷 772 个公共 GitHub 仓库，攻击者通过伪造 GitHub Actions 工作流文件，窃取 CI/CD 环境中的各类敏感凭证，包括云密钥、SSH 凭证和数据库密码。

📝 详细摘要

GhostAction 供应链攻击再次爆发，从 2026 年 8 月 31 日至 9 月 30 日，攻击者成功攻陷 772 个公共 GitHub 仓库，并窃取了 2577 个敏感凭证。攻击手法是通过伪造 GitHub Actions 工作流文件，将其注入受害者的仓库，这些恶意文件会在 CI/CD 运行过程中读取并窃取环境变量中的凭证，包括 AWS 密钥、Docker 注册表登录信息和 GitHub 令牌。调查显示，攻击者不仅创建新的恶意工作流，还更新了之前残留的恶意文件，表明该攻击活动具有长期持久性。防御方需要加强身份管理、启用多因素认证，并严格审核工作流变更，以防止凭证泄露。

💡 主要观点

  1. 攻击者通过伪造 GitHub Actions 工作流文件窃取敏感凭证 攻击者利用窃取的 GitHub 账号权限，向受害者的仓库添加恶意工作流文件（如 github_actions_security.yml）。这些文件会在 CI/CD 运行过程中读取环境变量，将敏感凭证（如 SSH 私钥、云服务密钥）通过 HTTP 请求发送到攻击者控制的服务器。
  2. 攻击活动具有长期持久性，涉及多个攻击波次 调查发现，本次攻击并非一次性事件，而是持续数月的活动。攻击者不仅在 8 月和 9 月发起新的攻击，还更新了之前残留的恶意工作流文件，将数据发送到新的收集端点。这表明攻击者在不断优化其基础设施，并利用已攻陷的账号进行后续攻击。
  3. 防御方需加强身份管理和工作流审核 为了应对这种攻击，组织需要采取多项安全措施，包括删除可疑工作流文件、轮换泄露的凭证、启用多因素认证，并严格审核所有工作流变更。此外，应限制工作流的权限，确保它们只能访问必要的资源，从而降低凭证泄露的风险。

💬 文章金句

  • 新一轮 GhostAction 供应链攻击已攻陷 772 个公共 GitHub 仓库。
  • 攻击者通过伪造 GitHub Actions 工作流文件，窃取 CI/CD 环境中的各类凭证。
  • 这些恶意文件伪装成常规自动化更新，快速代码审查过程中很容易被忽略。
  • 该工作流会等待仓库正常推送事件触发，读取指定的 GitHub Actions 敏感凭证，再通过 curl POST 请求将数据发送到攻击者控制的基础设施。
  • 攻击者最常针对 SSH 私钥和部署服务器凭证，相关凭证引用共 446 条；针对 Azure 凭证的攻击共 218 次，针对 Docker Hub 和 GitHub 容器注册表凭证的攻击有 142 次。
