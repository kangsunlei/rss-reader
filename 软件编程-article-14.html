📌 一句话摘要

DataBuddy 通过数据语义驱动的 Agent Runtime 实现执行可控、语义可信、系统可进化，彭锦文在 AICon 深圳站详细阐述其架构与落地经验。

📝 详细摘要

文章围绕腾讯 DataBuddy Harness 工程负责人彭锦文在 AICon 2026 深圳站的演讲展开，详细介绍了 DataBuddy 如何围绕『执行可控、语义可信、系统可进化』三个核心问题设计企业级 Agent Runtime。内容包括：为什么企业数据 Agent 更难；端到端案例——接入 MySQL 销售库、建 ODS/DWD/DWS 三层、配置每日增量同步的完整链路；总体架构（控制面与数据面分离、五层分层、能力与安全解耦）；Agent Runtime 的生命周期、可观测性和能力组织；语义可信的工程主线（冷热启动、抽象沉淀、语义 coverage、Text-to-SQL 兜底）；知识与记忆的分层结构及数据图谱；安全体系的风险三要素、纵深防御和敏感隔离；以及离线回归+在线观测的评测体系。演讲强调了语义正确性难验证、知识冷启动悖论、安全与体验平衡、动作可控性和组织信任等痛点，并给出听众可复用的架构心智、语义可信工程主线、数据 Agent 安全方法论以及知识经验闭环的收益。全文结构清晰、信息密度高，适合对数据治理、AI Agent 工程感兴趣的技术读者。

💡 主要观点

  1. 三个核心设计问题：执行可控、语义可信、系统可进化。 文章指出企业数据 Agent 不仅是 Text-to-SQL 封装，还需在有权限环境中避免错误动作，因而围绕执行可控、语义可信、系统可进化展开架构设计。
  2. 端到端案例：接入 MySQL 销售库、建 ODS/DWD/DWS 三层、配置每日增量同步的完整链路。 通过一个具体的数据集成诉求，演示了 Agent 的自主规划、能力契约、Hook Guardrail 和 Trace 产物，直观体现其可控、可信、可进化的特性。
  3. 语义可信的工程主线：冷热启动、抽象沉淀、语义 coverage、Text-to-SQL 兜底。 语义从冷启动的元数据缺失靠约定兜底，到热启动后资产累积提升准确率；通过抽象沉淀形成可复用语义；利用 coverage 判定可信边界；未覆盖时降级至受约束的 Text-to-SQL 并经过静态分析、语义对齐、权限收敛的防护链路。
  4. 知识与记忆分层及数据图谱：Session、Personal、Team、Enterprise 四层记忆，表/列、指标/维度、血缘、质量规则、SQL 模板互连成资产关系图。 知识按作用域×生命周期分层，权威性逐层增强；横向通过多种资产互连形成图谱，检索融合文本相关性、资产热度、血缘中心度和权威性，实现使用‑修正‑沉淀‑审核‑复用的经验复利闭环。
  5. 安全体系与评测方法：风险三要素、多层纵深防御、敏感隔离以及离线回归+在线观测的三层评判。 安全采用 Prompt、Text-to-SQL、静态分析、语义对齐、权限、改写、HITL、执行、结果脱敏、审计的多段防护；敏感信息不进入对话、上下文或记忆；评测离线回归与在线观测结合，使用确定性校验、LLM-as-Judge 和人工标准三层判断，聚焦语义正确性、确认门自动化和防作弊三难题。
