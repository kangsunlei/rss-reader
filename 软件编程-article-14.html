企业中的混合云原生网络 - 需略加整合

12/5/2025, 9:17:00 AM

📌 一句话摘要

本文倡导企业网络进行根本性变革，强调以应用为中心的设计，具备可验证的身份、可组合的策略以及可重复的基础设施，以适应混合云环境。

📝 详细摘要

本文是 Louis Ryan（一位应用程序和 API 专家，而非传统的网络工程师）的演讲稿，旨在批判当前的企业网络状态，尤其是在混合云原生环境中。Ryan 认为，网络过于基础，应“增强”其功能，以便更好地服务于应用程序，从以 IP 为中心的视角转变为以每个服务的可验证身份为基础的视角。他以“罗密欧与朱丽叶”为例，强调传统防火墙规则的局限性，以及对基于身份的安全的需求。演讲随后探讨了网络应如何“组合”以构建更高级别的系统，分析了集中式代理和策略存储的常见“发夹模式”，指出了其优势和重大缺陷，例如单点故障和组织摩擦。在此基础上，Ryan 强调了“可重复性”的重要性，即通过通用基础设施和与组织结构（而非基础设施细节）对齐的面向身份的策略，在所有环境（本地、多云）中实现一致的功能和控制。核心信息是呼吁企业从根本上转变设计和管理网络的方式，从而更好地支持现代分布式应用程序。

💡 主要观点

  1. 网络必须增强功能以服务于应用程序，超越原始的以 IP 为中心的模型。 当前的网络过度关注 IP 地址，导致配置复杂且不稳定。应用程序关注的是服务和 API，而非 IP 地址，因此需要一种能够抽象基础设施并为应用程序层提供实用功能的网络。
  2. 每个网络实体的可验证身份对于现代安全和策略执行至关重要。 由于 IP 地址频繁变更和缺乏对等身份验证，传统防火墙会失效。普遍实施 PKI、mTLS 或类似的身份验证机制将彻底改变安全性，并支持更强大、可审计的策略执行。
  3. 采用大型代理的常见“发夹模式”会引入显著的单点故障和组织摩擦。 通过单个代理集中所有流量可以提供控制，但会造成单点故障、不成比例的成本以及工单驱动的运维模式，从而阻碍敏捷性，并导致开发者倾向于寻找变通方案。
  4. 策略必须可组合，并在混合环境中可重复执行，并植根于组织结构。 策略应根据组织角色和关系（而非基础设施细节）来定义。这种方法可以减少工单驱动的运维模式和组织摩擦，支持在不同环境中保持应用程序一致性，并提高灵活性和可审计性。

💬 文章金句

  • 应用程序并不关心这些。他们为什么要关心？我真的不在乎你的电话号码是多少，我关心的是我正在与人通信。应用程序调用服务和 API。
  • 想象一下，如果网络上运行的所有组件都拥有可验证的身份，并且可以被与之通信的所有其他组件验证和证明，反之亦然，那么网络和网络安全将会是什么样子。
  • 组织迁移的最大障碍是其在策略方面的投入，这代表着巨大的商业价值。
  • 策略必须可组合。这意味着什么？我是一名管理员，我编写了一条策略：蒙太古家族的成员不能与凯普莱特家族的成员交谈，反之亦然。很好，这是一条非常宽泛的策略。我还希望各个团队能够编写比这更具体的策略。
