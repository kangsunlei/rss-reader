小红书发布 SWE-Bench Mobile：当 AI Agent 面对亿级用户 App 代码库，最高通过率仅 12%？

2/14/2026, 4:36:00 AM

📌 一句话摘要

小红书联合高校发布首个工业级移动端 AI 编程基准 SWE-Bench Mobile，揭示了当前 AI Agent 在处理真实复杂 App 代码库时仅 12% 的极低通过率。

📝 详细摘要

本文介绍了由小红书 Nexus AI 团队联合多所顶尖高校发布的 SWE-Bench Mobile 评测基准。该基准填补了移动端 AI 编码评估的空白，采用小红书真实的亿级用户 App 代码库（14GB Mono Repo）作为测试环境，涵盖了 PRD 和 Figma 设计稿等真实多模态输入。评测结果显示，目前最强的 AI Agent 组合在真实移动端任务中的成功率仅为 12%，且随着任务复杂度增加，表现呈断崖式下跌。研究进一步发现，Agent 的工程化框架设计对性能的影响远超底层模型，且简单的防御性编程提示策略在代码生成中比复杂的思维链更有效。文章强调，现阶段 AI Agent 的定位应为人类开发者的 Copilot，而非独立开发者。

💡 主要观点

  1. 移动端编码任务存在语料稀缺、多模态耦合及复杂的性能优化等独特挑战。 相比 Web 和后端，移动端使用的 Swift/Kotlin 语料较少，且涉及 UI 布局、手势交互与底层数据的深度结合，对模型的综合能力要求极高。
  2. Agent 的工程化框架（Scaffolding）设计对性能的影响甚至超过了底层模型本身。 实验显示同款模型在不同 Agent 框架下成功率差异可达 3 倍，证明工具调用、上下文管理和迭代策略是决定 AI 编码能力的关键因素。
  3. AI Agent 在处理大型代码库时缺乏全局观，跨文件推理能力仍是核心瓶颈。 约 45% 的失败源于实现不完整，Agent 往往只能修改部分文件而忽略了关联模块，导致其在复杂工业级任务中表现不佳。
  4. 代码生成任务中，简单的防御性编程提示词比复杂的思维链（CoT）更有效。 研究发现复杂的 Prompt 可能导致模型过度解读而跑偏，而强调边缘情况处理的防御性编程策略能显著提升测试通过率。

💬 文章金句

  • 在面对真实的企业级大型 App 开发任务时，目前能够达到的任务成功率也仅为 12%。
  • Agent 的架构设计比模型本身更重要。同样的模型，在不同框架下能产生 3 倍的性能差距。
  • 大多数失败源于‘顾头不顾腚’。Agent 修改了部分但并非所有必需的文件，缺乏全局观。
  • 目前的 Agent 只能做‘copilots’，且必须有人工监督才能可靠落地。
  • 简单的‘防御性编程’策略效果最佳。通过强调边缘情况处理，测试通过率提升了 7.4%。
