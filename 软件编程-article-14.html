谷歌曾说“不是秘密”的东西，Gemini 时代成了提款机：三人创业团队 48 小时濒临破产

3/5/2026, 5:57:00 AM

📌 一句话摘要

文章报道了一家初创公司因 Gemini API 密钥泄露在 48 小时内产生 8 万美元账单的惨剧，揭示了谷歌云 API 密钥架构中公共标识符与敏感凭证混用的深层安全隐患。

📝 详细摘要

本文详细记录了一家墨西哥三人创业团队的真实遭遇：其 Google Cloud API 密钥被盗用，导致 Gemini 调用费用在 48 小时内从月均 180 美元飙升至 8.2 万美元。文章深入探讨了该事件背后的技术根源，即谷歌云长期以来将 API 密钥（AIza...格式）视为可嵌入前端代码的非秘密标识符，但在 Gemini 时代，这些密钥被静默赋予了高额计费和敏感数据访问权限。安全研究机构 Truffle Security 的调查证实，这种“隐式权限提升”漏洞广泛存在。文章最后引发了关于云服务商“共享责任模式”与系统风控机制缺失的深度讨论。

💡 主要观点

  1. 谷歌云 API 密钥存在“身份识别”与“身份验证”的功能混淆。 长期以来 API 密钥被设计为前端可公开的计费标识符，但 Gemini 接口的启用将其转变为可访问敏感数据并产生巨额费用的核心凭证，导致安全边界模糊。
  2. “隐式权限提升”是导致旧密钥变成高危漏洞的核心机制。 当开发者在项目中启用 Gemini 后，原本部署在前端（如地图插件）的旧密钥会自动获得调用 AI 接口的权限，且系统没有任何警告或二次确认流程。
  3. 谷歌云默认的安全设置（CWE-1188）存在严重的设计缺陷。 新创建的 API 密钥默认状态为“不受限制”，意味着它对项目中所有已启用的服务有效。这种开放式架构在 AI 时代极易导致非预期的资源滥用和账单爆炸。
  4. 开发者质疑云平台在极端异常消费场景下缺乏硬性防护机制。 在费用飙升数百倍的极端情况下，系统未能触发自动封顶或强制确认，暴露出云服务商在实时风控和灾难性使用防护方面的功能缺失。
