AWS Lambda 现原生支持 Avro 和 Protobuf 格式的 Kafka 事件，并集成 Schema Registry

6/27/2025, 12:00:00 AM

📌 一句话摘要

AWS Lambda 现原生支持 Avro 和 Protobuf 处理 Kafka 事件，集成 Schema Registry 简化事件处理

📝 详细摘要

AWS 宣布，当在预配置模式下使用 Apache Kafka 事件源映射(ESM)时，AWS Lambda 现已原生支持 Apache Avro 和 Protocol Buffers (Protobuf) 格式的事件。这一增强功能通过直接与 AWS Glue Schema Registry、Confluent Cloud Schema Registry 及自托管 Confluent Schema Registry 等主流 Schema Registry 集成，简化了高效二进制 Kafka 事件的处理流程。 此前需要编写自定义代码来处理这些事件，现在 Lambda 的 ESM 原生支持 Schema Registry 集成，既降低了复杂度又提高了效率。开发者现在可以直接使用 Kafka 的开源 ConsumerRecords 接口构建函数，无需编写自定义反序列化代码即可访问 Avro 或 Protobuf 生成的业务对象。 此外，还可以设置事件过滤规则，在函数调用前自动过滤无关事件，优化计算成本。这一新功能同时适用于 Amazon Managed Streaming for Apache Kafka (Amazon MSK)、Confluent Cloud 和自托管 Kafka 集群。

💡 主要观点

  1. AWS Lambda 原生支持 Avro 和 Protobuf AWS Lambda 现在原生支持处理 Avro 和 Protobuf 格式的 Kafka 事件，无需编写自定义反序列化代码
  2. 与主流 Schema Registry 集成 新功能集成了 AWS Glue Schema Registry、Confluent Cloud Schema Registry 和自托管 Confluent Schema Registry
  3. 跨平台兼容性 支持 Amazon MSK、Confluent Cloud 和自托管 Kafka 集群
  4. 通过 ConsumerRecords 接口简化开发 开发者现在可以直接使用 Kafka 的 ConsumerRecords 接口访问 Avro 或 Protobuf 生成的业务对象
  5. 事件过滤实现成本节约 支持设置事件过滤规则，在函数调用前自动过滤无关事件，减少不必要的 Lambda 执行

💬 文章金句

  • 不再需要编写复杂的反序列化器或在函数内部处理模式解析。只需完成配置，Lambda 就会在代码运行前完成后续所有操作——模式获取、验证和解码
  • 最重要的是它允许在 ESM 层面(而非代码内部)过滤事件，因此能通过减少不必要的 Lambda 调用来实现成本节约
  • 这一新功能同时适用于 Amazon Managed Streaming for Apache Kafka (Amazon MSK)、Confluent Cloud 和自托管 Kafka 集群
