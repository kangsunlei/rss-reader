【开源】一个用于 Codex 和 Claude Code 的通用 LLM 代理中间件：opencodex

7/24/2026, 1:00:00 AM

📌 一句话摘要

opencodex 是一个通用 LLM 代理中间件，让 Codex 和 Claude Code 能自由使用任何大语言模型，并提供账号池管理与多模型协作。

📝 详细摘要

文章介绍了一个开源项目 opencodex，旨在解决 OpenAI Codex（CLI、App、SDK）和 Claude Code 默认只能绑定特定模型提供商的限制。通过在本地构建 Response/Messages 协议适配层，opencodex 实现了对 40+ 种 LLM（如 Anthropic Claude、Google Gemini、xAI Grok、DeepSeek、Ollama 等）的零成本适配。它还提供 ChatGPT 账号池管理，自动根据 5 小时/周度/月度额度分配会话，并保持长会话的亲和性（Affinity）。项目支持无缝集成与静默启动（可通过系统服务或按需 Shim 模式），并在 Codex 子代理选择器中实现多模型协作，允许将复杂任务路由给推理模型、简单任务路由给轻量模型。文中给出了快速安装方式（npm install -g @bitkyc08/opencodex）以及通过 ocx gui 启动本地 Dashboard 进行可视化配置的步骤。

💡 主要观点

  1. opencodex 解决了 Codex 和 Claude Code 绑定特定模型的问题。 通过本地协议适配层，用户可以在不修改原有工具的情况下接入任意 LLM 提供商，突破了原生工具的模型锁定限制。
  2. 提供 ChatGPT 账号池管理与会话亲和性功能。 系统能自动识别账号的使用额度，新会话分配至低用量账号，长时间会话则保持在同一账号上，避免额度耗尽导致的中断。
  3. 支持多模型协作（Subagent），可在 Codex 中为不同任务选择不同模型。 用户可以在子代理选择器中同时配置推理模型和轻量模型，根据任务复杂度自动路由，提升使用效率和成本效益。

💬 文章金句

  • 解决 Codex CLI / App 和 Claude Code 默认绑定/限制特定底层模型提供商的问题。
  • 通过在本地构建 Response / Messages 协议适配层，实现了零成本适配 40+ 种 LLM 提供商。
  • ChatGPT 账号池管理：自动识别 5 小时 / 周度 / 月度额度，新会话自动分发至低用量账号，长会话自动保持（Affinity）不中断。
  • 支持在 Codex 子代理选择器中同时配置多种不同模型（如复杂任务路由给推理模型、简单任务路由给轻量模型）。
  • 运行 ocx gui 启动本地 Dashboard，在可视化界面中一键添加并配置需要的 LLM Provider。
