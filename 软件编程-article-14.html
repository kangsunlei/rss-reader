被曝上传用户代码后，马斯克官宣开源 Grok Build，GitHub 上线即斩获 7.7k Star

7/16/2026, 8:53:00 AM

📌 一句话摘要

马斯克旗下 xAI 在隐私风波后开源代码智能体 Grok Build，支持本地运行与自行编译，GitHub 上线获 7.7k Star。

📝 详细摘要

文章报道了 xAI 开源其代码智能体工具 Grok Build 的事件，并梳理了此前被安全研究员曝光的上传用户完整代码仓库的隐私争议。文章详细引用了研究者 @cereblab 的抓包分析结果：Grok Build CLI 默认会将整个工作目录（包括 .env 密钥文件、Git 历史）上传至 Google Cloud Storage，且即便关闭“改进模型”选项也不会停止。马斯克随后承认该问题并承诺彻底删除数据。为平息争议，xAI 全面开源 Grok Build 的 Rust 代码，覆盖 Agent 主循环、工具系统、终端 UI 及扩展机制，并允许用户配置本地推理模型，实现完全本地运行，不再受云端额度限制。文章还对比了该工具与 Cursor、Copilot 等 IDE 类助手的差异，指出其定位更接近 Claude Code 和 Codex CLI 的命令行 Agent 路线。

💡 主要观点

  1. Grok Build 被曝默认将整个代码仓库上传至 xAI 服务器，包含敏感文件。 安全研究员通过抓包发现，Grok Build CLI 在默认配置下会通过 /v1/storage 接口上传整个工作目录的 Git Bundle，即使 Agent 未读取的文件也会被传输，且不脱敏 .env 等密钥文件。
  2. 马斯克承认隐私问题并承诺彻底清除数据。 在争议发酵后，马斯克公开承认“确有此事”，并表示“任何数据都不会留下”，xAI 随后宣称已永久删除此前上传的所有用户数据，并关闭数据留存机制。
  3. xAI 为回应争议全面开源 Grok Build，支持本地运行。 开源内容包括 Agent 循环、工具系统、终端 UI、扩展系统（Skills/Plugins/MCP 等），开发者可通过 config.toml 配置本地模型，实现数据不经过第三方服务器的完全本地化部署。
  4. Grok Build 定位为命令行原生的代码智能体，与 IDE 类编程助手形成差异化。 与 Cursor、GitHub Copilot 不同，Grok Build 强调终端 + Agent 自主完成开发流程，采用 Rust 编写，基于 Grok 4.5 模型，提供读取代码、修改文件、执行命令等能力。
