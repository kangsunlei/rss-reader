PlanetScale Vectors 正式发布：补全 MySQL 的关键特性？

4/12/2025, 12:00:00 AM

📌 一句话摘要

PlanetScale 将向量搜索深度集成到 MySQL 中，简化了 AI 应用的数据管理流程，无需额外的向量数据库。

📝 详细摘要

PlanetScale 向量支持的正式发布增强了 MySQL，允许向量数据与关系型数据一同存储，从而不再需要专用向量数据库。此功能基于微软研究院的 SPANN 和 SPFresh 算法，支持超出 RAM 容量的索引，并将事务操作直接集成到 MySQL 中。它专为推荐系统、语义搜索和 RAG 工作负载量身定制。索引创建和数据查询使用标准 SQL 命令。PlanetScale 的向量支持具有可扩展性和与 MySQL 查询优化器紧密集成的优势，但 Oracle 将该功能集成到 MySQL 社区版的可能性较低，突显了 PlanetScale 独特的价值主张。但是，PlanetScale 的文档中列出了一些兼容性限制。

💡 主要观点

  1. PlanetScale 的向量支持降低了对单独向量数据库的需求。 通过将向量数据存储与关系型 MySQL 数据集成，PlanetScale 简化了架构，降低了复杂性，并支持推荐系统和语义搜索等应用。
  2. SPANN 和 SPFresh 算法支持超出 RAM 容量的索引。 PlanetScale 的实现基于微软研究院的 SPANN 和 SPFresh 算法，允许索引扩展到 RAM 限制之外，从而增强了可扩展性。
  3. 与 MySQL 的深度集成简化了向量数据管理和查询。 与 MySQL 的深度集成意味着，插入、更新和删除向量数据后，更改会立即反映在索引中，作为事务提交的一部分，从而简化了数据管理并确保一致性。

💬 文章金句

  • 自从公开测试开始以来，我们将查询性能翻了一番，将内存效率提高了八倍，并专注于稳健性，以确保向量支持与 MySQL 支持的每种其他数据类型一样可靠。
  • 我们还构建了高级向量索引功能，以满足各种嵌入向量和用例。索引可以通过欧几里得距离 (L2)、内积或余弦距离对向量进行排序。它可以存储任何最高 16，383 维的向量。它支持定点量化和乘积量化。
  • 这种深度集成意味着，在 MySQL 中插入、更新和删除向量数据后，更改会立即反映在索引中，作为事务提交的一部分。此外，索引完全被 MySQL 二进制日志覆盖，从而能够可靠地从硬崩溃中恢复。索引还由 MySQL 的缓冲池管理，因此可以像其他表一样扩展到 TB 级别。更重要的是，它们与查询优化器完全集成，可以在任何查询中使用，包括 JOIN 和 WHERE 子句。
