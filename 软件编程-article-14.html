Redis 在 AGPL 许可下重回开源：是否为时已晚？

5/24/2025, 12:00:00 AM

📌 一句话摘要

Redis 8 在 SSPL 许可下发布一年后，以 AGPLv3 许可证重回开源，面临社区的质疑和来自 Valkey 分支的竞争。

📝 详细摘要

本文报道了 Redis 决定以 AGPLv3 开源许可证发布 Redis 8 的重要决定，标志着在使用更具限制性的 SSPLv1 许可证约一年后重回开源。之前的许可证变更导致了由主要云提供商支持的成功的 Valkey 分支的创建。文章强调了 Redis 的创建者 Salvatore Sanfilippo 的回归，他影响了改回 AGPL 的决定。Redis 8 引入了性能改进，并将以前非开源的模块（如 JSON、时间序列）以新许可证集成到核心中。然而，它也讨论了社区的复杂反应，许多人认为对信任的损害是巨大的，可能难以重新吸引已迁移至 Valkey 的用户。这种情况与 Elastic 类似的许可证变更以及随后重回 AGPL 的事件进行了比较。

💡 主要观点

  1. Redis 8 采用 AGPLv3 许可证，恢复到开源状态。 在 SSPLv1 许可下发布一年后，Redis 以其新的主要版本回归到 OSI 批准的许可证，以回应社区反馈和竞争。
  2. 该决定是在 Redis 的成功分支 Valkey 获得重要行业支持后做出的。 SSPL 的变更促使了 Valkey 的创建，Valkey 吸引了用户和支持，创造了一个影响 Redis 采取行动的竞争环境。
  3. Redis 8 将以前的专有模块集成到开源核心中。 像 RedisJSON 和时间序列这样的模块现在包含在 Redis 8 的 AGPLv3 许可证下，增加了开源产品的特性集。
  4. 社区的反应不一，人们担心失去信任和用户留存。 尽管回归开源，但社区中的许多人认为，之前的行为已经无可挽回地损害了信任，使得赢回迁移到像 Valkey 这样的分支的用户变得具有挑战性。

  • 编写开源软件已经融入我的灵魂：我的职业生涯几乎都在写开源。现在才改行，年纪太大了。

  • 虽然关于 Redis 通过 AGPLv3 许可证回归开源已经说了很多，但我认为人们已经忘记了它与几年前在 BSD 许可证下提供的 Redis 不同 - 许多扩展，例如自 2018 年以来一直没有开源的 RedisJSON，现在都包含在 Redis 中，并使用相同的 AGPLv3 许可证。
