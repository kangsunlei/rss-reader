天猫技术大型 AI 项目的研发协同实践

9/7/2026, 12:09:00 PM

📌 一句话摘要

天猫技术团队以新品 MDI 项目为例，分享大型 AI 项目研发协同从超级个体到全员赋能的四阶段实践，涵盖结构化知识库、站点地图分工、上下文缝补、技术哨兵机及 NekoCollar 平台等关键方法。

📝 详细摘要

本文以天猫新品 MDI 项目为案例，阐述大型 AI 项目研发协同的四个进化阶段。在单兵攻坚期，通过 AGENTS.md 入口地图、六个 Skill 与知识库六模块，构建结构化知识库，让 AI 深度理解项目上下文，打造超级个体。在加人提速期，借鉴站点地图思路进行物理隔离分工，利用四种变更类型（feature/patch/sunset/blueprint）管理需求演进，并通过双向指针、代码到 spec 的反向提醒及上下文缝补机制（MCP 与 skill）解决多人协作冲突与推理链断裂，实现效率横向复刻。在高速迭代期，部署独立技术哨兵机（collar-daemon）还原预发合并态，通过云端 Agent 检测隐形业务逻辑冲突并闭环告警，保障研发质量不劣化。在稳定运作期，推出 NekoCollar 云端协作平台，通过沙箱环境、所见即所得的真实页面代理及 Git 软硬双锁，让非研发角色也能安全高效参与协同，最终实现 AI 研发能力从个人到团队再到组织全员的规模化放大。文章强调 AI 上下文是效率关键，任何导致上下文异常的架构变动都需缝补，并记录了失败尝试（Agent Manage）以说明介入时机的重要性。

💡 主要观点

  1. AI 研发能力放大需经历从超级个体到全员赋能的四阶段演进 项目从单兵攻坚、加人提速、高速迭代到稳定运作，分别解决新领域探索、效率复刻、质量劣化和非研发角色参与问题，形成个体→团队→可持续→全员的放大路径。
  2. 结构化知识库与入口地图是打造超级个体的基础 通过 AGENTS.md 作为唯一入口（≤120 行只导航不堆细节），配合六个 Skill 管理 specs/changelog/architecture/runbook/vendor/wiki 六模块，并利用 git commit 作为统一触发关卡，实现知识自动沉淀与强制门禁，让 AI 从第一天起就懂项目。
  3. 站点地图与四种变更类型实现多人物理隔离分工 将 specs 按业务地图横向铺开，目录即认领单元，patch 支持并行提交，sunset 实现旧功能优雅日落，双向指针解决主文档与补丁的语义二义性，从而最小化冲突面。
  4. 上下文缝补机制是 AI 时代研发架构变动的必要配套 将提示词等逻辑外置到 DB 或平台会导致推理链断裂，需通过 MCP 提供只读可达通道、skill 提供何时/如何取用的协议，将外置上下文拉回 AI 视野，并保留声明式注释锚点。
  5. 技术哨兵机通过还原预发合并态检测隐形冲突 在独立机器上持续同步各仓最新 release 分支，模拟出预发合并态，由云端 Agent 分析提交上下文与完整代码，发现冲突后钉钉告警并沉淀 AI 表格闭环，以周冲突有效发现率为北极星指标。

💬 文章金句

  • 对 Agent 来说，看不到的知识等于不存在。
  • 任何导致上下文异常的研发架构变动，都必须用适合的方式缝补缺损的上下文。
  • Spec 是意图源，比代码更早期。代码偏离 Spec 不一定是错误------可能是编码过程中发现了更好的方案。
  • 编码态是'意图尚未定型'的阶段，此时的信息熵最高、确定性最低，用它做冲突检测成本过高。
  • release 集成分支是'冲突唯一会现形的地方'，哨兵机就是 24 小时盯着这个地方的人。
