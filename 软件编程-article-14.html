TigerFS 将 PostgreSQL 数据库挂载为开发者和 AI 智能体的文件系统

4/4/2026, 8:18:00 AM

📌 一句话摘要

TigerFS 是一个实验性的开源文件系统，它将 PostgreSQL 数据库挂载为目录，使开发者和 AI 智能体能够使用标准的 Unix 工具与结构化数据进行交互。

📝 详细摘要

TigerFS 通过允许将 PostgreSQL 通过 FUSE (Linux) 或 NFS (macOS) 挂载为本地目录，弥合了关系型数据库与文件系统之间的鸿沟。它主要旨在为 AI 智能体提供可靠的共享状态，采用了“文件系统即 API”的理念，将数据库行暴露为文件。该项目支持两种主要的工作流：一种是用于原子化、版本化文档管理的“文件优先”模型，另一种是使用 ls、cat 和 grep 等标准命令行工具查询现有数据库的“数据优先”模型。通过以事务型数据库作为文件系统的后端，它确保了并发文件操作的完全 ACID 保障。

💡 主要观点

  1. TigerFS 通过标准文件系统接口暴露 PostgreSQL 数据。 这使得 AI 智能体和开发者可以使用熟悉的 Unix 工具（如 ls、cat 和 grep）与结构化数据进行交互，而无需专门的 SDK 或复杂的 SQL 查询。
  2. 它为文件操作提供了事务保障和并发访问能力。 通过以 PostgreSQL 作为文件系统的后端，TigerFS 确保了 ACID 合规性、原子写入和自动版本控制，有效地解决了多智能体工作流中的共享状态问题。
  3. 该工具同时支持“文件优先”和“数据优先”两种使用模型。 用户既可以直接在数据库中管理带有自动版本控制的文件，也可以挂载现有数据库，将行数据作为文件进行探索，其中文件系统路径可以转换为数据库查询。

💬 文章金句

  • 智能体不需要花哨的 API 或 SDK，它们喜欢文件系统。ls、cat、find、grep。流水线化的 UNIX 工具。
  • 每个文件都是真实的 PostgreSQL 行。多个智能体和人类可以并发读写，并享有完整的 ACID 保障。
  • 文件系统 /就是/ API（……）我构建它主要是为了智能体工作流，但很好奇人们还会用它来做什么。
