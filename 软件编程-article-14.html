【第 3631 期】No-Vary-Search：用一个新 HTTP 头拯救你的缓存性能！

12/25/2025, 1:02:00 AM

📌 一句话摘要

No-Vary-Search 是一个新的 HTTP 响应头，旨在解决因 URL 参数导致的缓存问题，通过明确哪些参数不影响内容，从而提升网站性能和用户体验。

📝 详细摘要

文章深入探讨了 URL 参数对网页性能的负面影响，特别是如何通过一个新的 HTTP 响应头 No-Vary-Search 来解决由追踪参数等导致的缓存效率低下问题。作者详细解释了即使内容相同的页面因 URL 参数不同导致缓存失效的三个常见情境，强调了缓存对性能的重要性。接着，文章介绍了以往 CDN 的非标准化解决方案及其局限性，并引出了 No-Vary-Search 这一标准化方案，它允许服务器告知缓存系统哪些查询参数不影响页面内容。文章还详细讲解了 No-Vary-Search 的四种工作模式（忽略参数顺序、忽略所有参数、忽略特定参数、指定例外参数）以及其当前的支持情况和推荐使用方法，最后通过测试案例展示了其性能提升效果。

💡 主要观点

  1. URL 参数导致传统缓存机制失效，严重影响网站性能和用户体验。 追踪参数如 UTM 等虽然不改变页面内容，但导致 URL 不同，使得浏览器和 CDN 无法有效缓存，造成大量重复请求和资源浪费。
  2. No-Vary-Search HTTP 响应头提供标准化方案，解决 URL 参数引起的缓存问题。 服务器通过 No-Vary-Search 明确哪些查询参数不影响内容，浏览器和 CDN 可据此更智能地进行缓存，减少不必要的重新加载。
  3. No-Vary-Search 具有灵活配置，可忽略参数顺序、所有参数、特定参数或指定例外参数。 通过配置 key-order、params、params=(...) 或 except=(...)，网站可以根据自身需求精细化控制缓存行为，避免错误复用。
  4. 尽管支持度尚不广泛，提前部署 No-Vary-Search 仍是值得的实践。 Chrome 浏览器已开始支持，且添加该头部几乎没有副作用，有助于为未来的广泛支持和性能提升做好准备，尤其能立即改善 Chrome 用户的体验。

💬 文章金句

  • 最大的问题在于：我们没办法确定一个 URL 的内容是否会因为参数不同而变化。所以默认情况下，缓存系统只能假定它们的内容不一样。
  • 我们不是要告诉缓存 "内容可能会变化"，而是要告诉它 "内容不会变化"。
  • 一个标准化的解决方案......一个新的 HTTP 响应头诞生了：👉 No-Vary-Search。
  • 我的结论是： 对 No-Vary-Search 感到非常兴奋（甚至可以说 "vary excited" 😄）。它有潜力减少海量不必要的网络请求和源服务器压力。
