遗留系统现代化：围绕 大型机 构建实时系统

6/3/2025, 12:00:00 AM

📌 一句话摘要

利用 CDC、EDA、DDD、GraphQL 和 Team Topologies 解耦 大型机，构建实时系统。

📝 详细摘要

本文是 InfoQ 的一次演讲实录，详细介绍了 National Grid 为其客户门户网站（UWP 2.0）改造遗留 大型机 系统的方法。文章对比了失败的 UWP 1.0 同步、基于 ETL 的架构（存在数据新鲜度问题、单点故障和组织孤岛），与新的解耦方法。新方案利用 变更数据捕获（CDC）将 大型机 变更异步流式传输到 事件驱动架构（EDA）。使用 领域驱动设计（DDD）将这些数据建模成对业务友好的 限界上下文，有效地创建了一个区别于 大型机 “记录系统”的“参考系统”。GraphQL 提供了一个灵活的 API 层，用于跨这些 领域驱动的 上下文进行查询，专门设计用于避免需要大量的 BFF（前端后端）。Team Topologies 将组织结构与领域边界对齐，从而实现更快的交付。这种结合旨在提高系统的 韧性、数据新鲜度、客户体验 和 团队自主性。

💡 主要观点

  1. 遗留 大型机 系统导致紧耦合、数据新鲜度问题和可靠性问题。 UWP 1.0 中对 大型机 的同步调用和基于 ETL 的 批处理 过程导致了系统故障、数据过时和糟糕的客户体验。
  2. 通过 CDC 和 EDA 进行解耦是围绕 大型机 进行现代化的关键。 通过 CDC 将 大型机 中的变更异步流式传输到事件架构中，创建了一个有韧性的、接近实时的数据流。
  3. DDD 创建了一个独立于 大型机 的、对业务友好的参考系统。 在 限界上下文 内对数据和事件进行建模，使团队能够使用与遗留源解耦的、一致的、对开发者友好的数据视图。
  4. GraphQL 统一了 领域驱动的 API 并解决了数据获取难题。 通过 GraphQL 拼接将 领域驱动的 API 组合成一个 超图，避免了 BFF 的复杂性，并允许前端高效地跨领域查询数据。
  5. 组织结构必须与 架构领域 对齐。 结合 DDD 使用 Team Topologies 有助于将 流对齐团队 与 限界上下文 对齐，从而提高自主性和交付速度。

💬 文章金句

  • 归根结底，这是一个关于 解耦 的故事。
  • ETL 的 批处理 特性不适合为客户提供其账户的最新信息。
  • 变更数据捕获 就是一种捕获 数据存储 中变更的方式，仅此而已。
  • 我们所认为的 限界上下文 与 Eric Evans 书中定义的原始定义非常接近。
  • 组织设计 是 架构 的一部分。
