RAG 的概念很糟糕，让大家忽略了应用构建中最关键的问题

9/14/2025, 4:42:00 AM

📌 一句话摘要

文章批判了 RAG 概念的局限性，提出 Context Engineering 才是构建高效 AI 应用的核心，并探讨了未来检索系统和记忆机制的发展方向。

📝 详细摘要

本文通过对 Chroma 创始人 Jeff Huber 的访谈，深入探讨了当前 AI 应用开发中的关键挑战。Jeff Huber 批判 RAG 概念的局限性，指出 Context Engineering（上下文工程）才是构建高效 AI 应用的核心，旨在解决 LLM 因上下文过长导致性能下降的“上下文腐烂”问题。文章详细阐述了多阶段检索和利用大模型进行重排的策略，并强调了生成式基准测试在构建高质量检索系统中的关键作用。同时，展望了未来检索系统向持续检索和直接在 Embedding 空间内工作的方向发展。Jeff Huber 还指出 AI 记忆的本质是 Context Engineering，并分享了 Chroma 作为 AI 检索引擎的创业理念，其产品设计秉持极致开发者体验、零配置和按使用量计费的原则，体现了创始人对影响力、长期主义和价值观的追求。

💡 主要观点

  1. RAG 概念模糊且肤浅，误导了 LLM 应用开发的核心。 RAG 将检索、生成、结合硬拼，并常被误解为仅是向量搜索，未能触及 LLM 应用中上下文管理这一更深层、更关键的问题。
  2. Context Engineering 是 AI 工程学核心，旨在优化 LLM 上下文窗口利用。 面对 LLM 上下文腐烂（Context Rot）问题，Context Engineering 通过策略性选择和放置信息，显著提升模型推理能力与性能。
  3. 多阶段检索与 LLM 重排是当前高效解决上下文问题的范式。 结合向量、全文搜索进行初筛，再利用廉价大模型进行重排，能有效从海量数据中挑选最相关信息，提升检索质量。
  4. 持续检索和潜在空间内工作是未来检索系统的重要方向。 未来的检索系统将实现边生成边检索，并在 Embedding 空间直接工作，避免反复在自然语言和向量间转换，提高效率。
  5. AI 的记忆本质是高效的 Context Engineering。 模型的记忆能力并非拟人化的复杂结构，而是如何精准地将最相关信息送入上下文窗口，实现学习与应用。

💬 文章金句

  • 我觉得 RAG 本质上只是检索。它把检索、生成、结合三个不同的概念硬拼在一起，结果特别让人困惑。而且 RAG 后来在市场上被包装成拿 Embedding 做一次向量搜索，这其实是误解，也很肤浅。
  • 因为存在 Context Rot（上下文腐烂），所以我们需要 Context Engineering（上下文工程）。
  • 坦白讲，现在所有你能想到的，做得比较好的 AI 初创公司，他们真正擅长、最核心的一件事就是 Context Engineering。
  • 我觉得记忆这个词很好，大家一听就能明白。这其实就是继续把 LLM 拟人化的一种方式。但记忆的本质是什么，还是 Context Engineering，说到底就是如何把合适的信息放进上下文窗口。
  • 小而高质量的标注数据集回报特别高。大家总觉得必须要有上百万条数据，其实不需要。就算只有几百条高质量的样本，也能带来非常大的价值。
