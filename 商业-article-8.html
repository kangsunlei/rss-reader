Anthropic 工程负责人：工程师的变化才真正开始丨 Sequoia

5/8/2026, 12:56:00 PM

📌 一句话摘要

Anthropic 工程负责人 Boris Cherny 在 Sequoia 的对话中，分享了 Claude Code 的诞生历程、个人工作流（一天 150 个 PR、数百个 Agent 并行），并预测软件构建将像「发短信」一样普遍，工程师的角色将从写代码转向编排 Agent。

📝 详细摘要

本文是对 Sequoia Capital 与 Anthropic 工程负责人 Boris Cherny 对话的深度编译。Boris 是 Claude Code 的创建者，他在对话中分享了多个极具冲击力的观点和实践。首先，他透露自己今年未写过一行代码，工作方式已转变为在手机上同时运行数百个 Agent，曾创下一天 150 个 PR 的记录。他详细介绍了 Claude Code 的诞生源于「产品过剩」——模型能力已远超现有产品形态，并经历了前 6 个月的失败期，直到模型能力追上产品想象力。Boris 重点推荐了「loop」功能，即让 Agent 定时执行任务（如自动修复 CI、处理 PR、抓取反馈），认为这是提升工作密度的未来方向。他预测，随着模型能力增强，当前围绕安全、权限搭建的「外壳」会变轻，产品护城河不能只押注在 prompt 和 wrapper 上。在团队组织层面，他认为未来会出现更多跨学科通才，团队中所有人（包括 PM、设计师、财务）都会写代码。他将软件构建的普及类比为 15 世纪的印刷机，认为 Agent 将大幅降低「生成软件」的成本，使其成为像「发短信」一样的日常表达。最后，他强调 MCP 是连接知识工作与工具的关键，并认为大公司因流程僵化将受到冲击，当前是创业的最佳时机。

💡 主要观点

  1. Claude Code 的成功源于「产品过剩」与模型能力的追赶。 Boris 认为，2024 年底模型能力已远超现有产品形态（如 IDE 逐行补全），Claude Code 诞生于这种「产品过剩」。产品经历了前 6 个月的失败期，直到模型能力逐步追上产品想象力才迎来转折，这对 AI 产品团队有重要参考价值。
  2. 工程师角色正从「写代码」转向「编排 Agent」。 Boris 本人今年未写一行代码，工作方式是在手机上同时运行数百个 Agent，曾一天完成 150 个 PR。他推荐「loop」功能，让 Agent 定时自动执行任务（如修 CI、处理 PR），认为这种后台持续推进才是提升工作密度的关键。
  3. 未来团队将出现更多跨学科通才，代码成为表达手段。 Boris 指出，Claude Code 团队中所有人（包括 PM、设计师、财务）都写代码。代码不再是工程师的专属技能，而是跨学科成员将想法转化为可运行软件的表达手段，专业边界正在模糊。
  4. 软件构建将像「发短信」一样普遍，大公司面临流程挑战。 Boris 以 15 世纪印刷机类比，认为 Agent 将大幅降低软件生成成本，使其成为日常表达。大公司因需改变业务流程、面临内部阻力而受冲击，新公司可从第一天按 AI native 方式构建，这是创业的最佳时机。

  • 我们团队里的每个人都写代码，工程经理、产品经理、设计师、数据科学家、财务、用户研究员，全都写。
