好用的 Agent Skill 到底怎么构建？丨 AI Engineer

7/1/2026, 1:23:00 PM

📌 一句话摘要

本文基于 AI Engineer 演讲，系统阐述了构建高质量 Agent Skill 的方法论，涵盖触发方式选择、文件结构精简、短词引导行为、流程拆分与删除无用指令等核心实践。

📝 详细摘要

文章从 Agent Skill 的实际困境出发，指出当前团队容易陷入「Skill Hell」——免费 Skill 看似丰富却难以复用，规则越加越多效果却未必提升。作者援引 AI Engineer 演讲者 Matt Pocock 的框架，给出了一套可落地的构建方法：首先决定 Skill 的触发方式，高频低风险任务可模型自动触发，低频高风险任务应由用户手动调用，避免上下文被大量描述拖累；其次，Skill.md 应保持简短，只留公共入口，模板、样例、术语等参考材料放到独立文件中，按需读取；第三，使用「leading words」如 vertical slice 压缩整组规则，让 Agent 行为更稳定；第四，将复杂流程拆分为独立 Skill，防止 Agent 为赶最终输出而偷懒前置步骤；最后，通过「删除测试」去掉那些看似有用却不改变实际行为的 no-op 语言。文章还给出了具体检查清单：合并重复、挪走放错分支的内容、清理过期、杀掉无效指令。整体密度高、可操作性强，对 AI 工程团队有直接参考价值。

💡 主要观点

  1. Agent Skill 应区分用户触发与模型自动触发两种入口。 自动触发增加上下文负担，每多一个可触发的 Skill，Agent 每次请求就得多背一条描述。高频低风险用自动，低频高风险用手动。
  2. Skill.md 应保持简短，只留公共入口，参考材料放到外部文件。 主文件只写使用时机、顺序和分支指引，模板、ADR、glossary 等单独存放，Agent 按需读取，团队也敢删改。
  3. 使用「leading words」压缩规则，引导 Agent 行为。 如 vertical slice、deletion test 等短词，将一整套工程习惯打包，反复出现可稳定 Agent 动作，避免近义词混乱。
  4. 将复杂流程拆分为独立 Skill，防止 Agent 偷懒。 例如把「问清楚」和「写计划」拆成两个 Skill，Agent 只看到当前阶段，不会因终点驱动而压缩前期工作。
  5. 通过「删除测试」去掉不改变结果的 no-op 语言。 删掉一段文字后运行 Agent，如果输出无变化，这段就是无效占用。合并重复、挪走分支、清理过期，让 Skill 变轻才敢改。

💬 文章金句

  • 区分好 Skill 和坏 Skill 的能力，只会越来越重要。
  • 每增加一个模型可触发的 Skill，Agent 都要多背一份上下文负担。
  • 每删掉一个词，都是从 Skill 成本里刮掉一个 token。
  • No-op 是 Skill 里看起来有用、实际不会改变 Agent 行为的东西。
  • 先让一份 Skill 变好，比收集一堆 Skill 更可靠。
