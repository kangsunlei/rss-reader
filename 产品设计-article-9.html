只会搜关键词还不够，Agent 需要一套更聪明的本地搜索

9/15/2026, 8:17:52 AM

📌 一句话摘要

本文介绍了 zvec-grep 这款本地向量搜索工具，阐述其多路检索、三阶段流程以及如何让 Agent 与 CLI 共享索引，帮助开发者高效定位代码与文档。

📝 详细摘要

本文以 zvec-grep 为例，阐述了如何将语义检索、BM25 全文检索、正则搜索与混合检索整合到同一接口，形成三阶段检索流程，帮助 Agent 在本地代码和文档中快速定位信息。文章详细介绍了 zvec-grep 的架构、部署步骤、使用场景以及局限性，并给出多种实际案例，展示了 CLI 与 Agent 共享同一索引的优势。

💡 主要观点

  1. zvec-grep 将多种本地检索方式整合到单一接口 它将语义检索、BM25 全文检索、正则搜索和混合检索统一暴露，Agent 可以根据意图、结果排序和验证需求灵活调用。
  2. 三阶段检索流程降低检索税 探索阶段使用语义检索理解意图；收敛阶段用 BM25 或混合检索缩小范围；验证阶段用精确搜索确认实现，显著减少时间、工具调用次数、上下文窗口和模型 Token 的消耗。
  3. CLI 与 Agent 共享同一本地索引 zvec-grep 基于 zvec 向量数据库，索引存放在项目目录下，CLI 与 Agent 通过 MCP 自动发现并共用，避免重复索引并提升效率。
  4. 适用于代码理解、故障定位和本地知识库搜索 可索引代码仓库、项目文档、研究资料等文本，但对 PDF、Office 文档或图片需先转换为文本，了解其局限性对使用至关重要。
  5. 部署简单，命令行即完成安装、配置与索引 通过 npm 安装、zg install 配置 MCP、zg index 构建索引，随后可使用 zg query 或 Agent 直接调用，文中提供多种使用案例与命令示例。

💬 文章金句

  • 这个过程可以称为「检索税」
  • 它消耗的不只是时间，还有工具调用次数、上下文窗口和模型 Token。
  • zvec-grep 把几种不同的本地搜索方式放到了同一个接口里
  • 它不是取代 rg， 而是让本地搜索覆盖更多场景。
  • Agent 可以先阅读这些证据，确认方向后再读取完整文件，从而减少无关内容进入上下文。
