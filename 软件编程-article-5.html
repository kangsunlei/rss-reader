实时模式：无需第二引擎，在 Spark API 上实现超低延迟流处理

3/2/2026, 5:30:00 PM

📌 一句话摘要

Databricks 为 Spark Structured Streaming 推出了实时模式（Real-Time Mode），通过架构创新实现了亚秒级延迟，并消除了对 Flink 等独立流引擎的需求。

📝 详细摘要

本文介绍了 Apache Spark Structured Streaming 的“实时模式”（RTM），这是一项重大的架构演进，旨在消除对 Apache Flink 等第二流引擎的需求。通过从微批处理转向连续执行模型，Spark 现在可以处理欺诈检测、个性化和 AI 上下文交付等关键任务用例的亚秒级延迟需求。作者详细介绍了三个关键技术支柱：连续数据流、非阻塞流水线调度和低延迟流式 Shuffle。Databricks 提供的基准测试结果表明，在常见的特征工程任务中，RTM 的速度比 Flink 快高达 92%，允许数据团队在单一且熟悉的 API 下统一其技术栈。

💡 主要观点

  1. Spark 实时模式消除了维护两个独立数据处理栈的运维复杂性。 通过在原生 Spark API 中实现亚秒级延迟，团队不再需要为实时任务管理 Flink、为批处理 ETL 管理 Spark 等独立系统，从而统一了治理和代码库。
  2. 新的执行引擎利用三项根本性的技术创新来实现高性能流处理。 创新包括采用连续数据流而非微批处理、同步流水线调度以防止阻塞，以及绕过传统磁盘瓶颈的流式 Shuffle，从而实现更快的任务间通信。
  3. 基准测试表明，Spark RTM 在常见的特征工程工作负载中可以超越专门的流处理框架。 与 Apache Flink 的对比显示，Spark 演进后的架构在欺诈检测和个性化中典型的无状态转换、连接和聚合方面，处理速度提高了 92%。

💬 文章金句

  • Apache Spark Structured Streaming 的实时模式（RTM）旨在消除这种摩擦……从而不再需要第二个系统。
  • 数据在到达时即被处理，而不是被切分为离散的、周期性的块。
  • 这一转变使工程师能够使用他们已经熟悉的相同 Spark API，处理从高吞吐量 ETL 到低延迟实时应用的全谱系用例。
  • 流水线调度：各阶段同步运行而不阻塞，允许下游任务立即处理数据，无需等待上游阶段完成。
