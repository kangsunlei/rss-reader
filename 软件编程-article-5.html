Reddit 将评论后端从 Python 迁移到 Go 微服务，延迟降低 50%

11/28/2025, 3:00:00 PM

📌 一句话摘要

Reddit 成功地将其评论后端从 Python 迁移到 Go 微服务，采用了多阶段《流量对比》和《双写》策略。关键写操作的 p99 延迟因此降低 50%。

📝 详细摘要

本文详细介绍了 Reddit 为实现评论后端现代化而做出的重大工程努力，从遗留的 Python 单体应用迁移到特定领域的 Go 微服务。此次变更的主要驱动因素是解决 Reddit 高负载写入系统之一中长期存在的延迟和可扩展性问题。迁移采用了复杂的多阶段策略，首先使用《流量对比》方法在 Go 中实现和验证读取端点，即将来自新服务的实时流量响应与遗留系统进行比较。对于更复杂的写操作，Reddit 利用《双写》来镜像数据存储，以安全地验证行为，而不会冒生产数据损坏的风险。迁移过程发现并解决了几个关键的边缘情况，包括序列化不匹配、由于不同的数据访问模式（ORM（对象关系映射）与直接写入）导致的数据库压力以及竞态条件。最终，新的基于 Go 的架构简化了依赖链，保持了事件传递保证，并显著降低了关键写操作的 p99 延迟，展示了 Go 在高吞吐量系统中的效率，并为后续核心服务现代化奠定基础。

💡 主要观点

  1. Reddit 的多阶段迁移策略，包括《流量对比》和《双写》，确保了正确性并最大限度地减少了用户中断。 通过逐步转移流量并在生产环境中针对遗留 Python 系统验证新的 Go 服务，Reddit 在完全切换之前安全地识别并解决了问题，这对于高流量、高写入系统至关重要。
  2. 迁移到 Go 显著提高了性能和吞吐量，关键写操作的 p99 延迟降低 50%。 与 Python 相比，Go 卓越的并发模型使 Reddit 能够以更少的资源实现更高的吞吐量，从而直接解决了长期存在的延迟和可扩展性挑战。
  3. 迁移过程突出了大规模系统重写中常见的挑战，例如数据序列化和数据库交互差异。 遇到并解决诸如 Python/Go 序列化不匹配以及由于 ORM（对象关系映射）与直接写入导致的数据库负载差异等问题，为类似的现代化项目提供了宝贵的经验教训。

💬 文章金句

  • 此更改解决了 Reddit 高负载写入系统之一中长期存在的延迟和可扩展性挑战，同时为其他核心模型现代化奠定了基础。
  • 这使工程师能够在完全切换流量之前安全地检测生产中的差异。
  • 创建、更新和递增等关键写操作的 p99 延迟与遗留 Python 系统相比降低 50%，该系统之前曾出现高达 15 秒的峰值。
  • Reddit 基础设施团队补充说，Go 的并发性允许更少的 Pod 实现比 Python 更高的吞吐量，使其成为首选。
