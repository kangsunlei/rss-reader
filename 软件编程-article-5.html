企业级 MultiAgent 落地：Plan 模式与主子 Agent 协作｜得物技术

📌 一句话摘要

本文介绍得物技术基于 AgentScope Java 的企业级 MultiAgent 平台，重点阐述 Plan 模式的全生命周期、主/子 Agent 协作、A2A 跨服务通信及多租户隔离、全链路追踪等企业级能力保障，并给出典型应用场景。

📝 详细摘要

文章承接上一篇关于平台基础运行时的介绍，聚焦复杂任务的规划与多 Agent 协作。作者指出 ReAct 循环在处理多步骤任务时的局限，引入 Plan-and-Execute 模式，将计划作为有状态、可持久化、可观察的运行对象。Plan 生命周期涵盖创建、Hint 注入、持久化与断点恢复、SSE 过程可见。主/子 Agent 协作通过声明式配置实现职责分离，子 Agent 拥有独立记忆与工具，并支持异步调度与中断传播。A2A 协议支持跨服务 Agent Teams，强调会话归属与租户身份绑定。企业级能力保障包括多租户全链路隔离、双模式认证与 API Key、全链路追踪、SSE 分层消息协议、异常保护四道防线及双检索引擎。文章最后给出研究报告生成、多系统数据聚合、跨部门协作三个典型场景，并总结平台从演示到生产系统的关键能力。

💡 主要观点

  1. Plan-and-Execute 模式将复杂任务拆解为可审计、可恢复、可观察的运行对象 相比 ReAct 循环，Plan 模式将“要做什么”与“怎么做”分离，计划成为有状态对象，支持持久化、断点恢复和 SSE 过程可见，解决了前置步骤缺失、过程不可审计、Token 消耗不可预估等问题。
  2. 主/子 Agent 协作通过声明式配置实现职责分离与专业能力组合 子 Agent 拥有独立记忆、工具集和系统提示，通过配置描述名称、职责、工具和模型，平台将其包装为主 Agent 可调用的工具，支持同步/异步、并行执行，并具备查询、取消、超时和回收能力。
  3. A2A 协议实现跨服务 Agent Teams，但会话归属与租户身份绑定是关键 A2A 调用分为发现、调用、执行适配三层，典型时序涉及 Agent Card 发现、会话创建与 contextId 延续。最易忽略的是 contextId 必须与发起方身份绑定，异步恢复时需重新注入租户条件，否则存在越权风险。
  4. 企业级平台的核心在于可靠性保障而非功能列表 多租户全链路隔离通过 ORM 层强制注入租户条件实现，双模式认证与 API Key 支持不同接入场景，全链路追踪提供多层调用树，SSE 分层消息协议实现执行过程可见性，异常保护四道防线涵盖工具超时、迭代上限、状态合法性约束与协作式中断传播。
  5. 平台集成向量与全文双检索引擎，并原生支持 MCP，扩展 Agent 知识获取能力 向量检索适合开放式问答，全文检索适合精确查找，LLM 可根据任务类型自主选择。MCP 支持任意标准工具服务动态挂载，无需定制开发即可接入。

💬 文章金句

  • Plan-and-Execute 把“要做什么”和“怎么做”拆开：先生成结构化计划，再逐项执行。
  • Hint 是软约束，不替模型决策。框架负责硬约束，例如同一时刻只允许一个任务进行中，不能跳过未完成的前置任务。
  • 子 Agent 不应成为黑盒。
  • 把这两条规则前置到协议适配层，业务 Agent 就不必每处都重写鉴权逻辑。
  • 当这些能力被统一封装后，Agent 才从演示程序变成能够长期运行、持续演进的软件系统。
