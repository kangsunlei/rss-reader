2026.1 版本中面向远程开发的平台调试器架构重新设计 | JetBrains 平台博客

1/19/2026, 11:15:50 AM

📌 一句话摘要

JetBrains 为支持远程开发重新设计了 IntelliJ 平台调试器，将其拆分为前端和后端，需要插件 API 在 2026.1 版本进行迁移。

📝 详细摘要

本文详细介绍了 IntelliJ 平台调试器为支持远程开发而进行的架构重新设计，特别是针对 2026.1 版本及之后的版本。核心变化是将调试器拆分为前端（UI）和后端（会话逻辑），以提高远程场景下的响应性和稳定性。这种拆分修改了现有的调试器 API 契约，由于异步 UI 创建以及前端与插件提供实体的交互方式变化，使得之前的多个方法被弃用或不安全。文章为插件开发者概述了两种迁移路径：一种是仅支持本地模式，处理已弃用的 API；另一种是支持完整的远程开发，需要使用新的替代 API，如 `createTabLayouter` 和 `XDebuggerTreeBackendOnlyActionBase`。文章提供了具体的 API 示例、变通方案，并强调使用 2026.1 EAP 进行测试以识别受影响区域，特别是 UI 组件和操作。

💡 主要观点

  1. IntelliJ 平台调试器经过重新架构以支持远程开发场景 这种重新设计将调试器拆分为前端（UI）和后端（会话逻辑），即使在代码在远程服务器上执行时也能提供无缝且响应迅速的调试体验。
  2. 现有的调试器 API 契约已更改，需要插件迁移 由于前端/后端的拆分，不再建议从后端直接访问 UI 元素，前端现在使用包装实体进行操作，这破坏了依赖直接转换到其自定义实现的插件的兼容性。
  3. 插件需要更新以支持 2026.1 版本中的新调试器架构 开发者必须使用 2026.1 EAP 测试他们的插件，并选择迁移到“仅本地模式”或采用新的 API 以实现完整的“本地 + 远程开发模式”兼容性。
  4. 特定的 API 已被弃用或不安全使用，特别是那些从后端访问调试器 UI 的 API 像 `XDebugSession#getRunContentDescriptor` 和 `XDebugSession#getUI` 这样的方法受到影响，有变通方案或替代 API 可用，如 `com.intellij.xdebugger.impl.XDebugSessionImpl.runWhenUiReady`。
  5. 为远程开发兼容性提供了新的替代 API 对于远程开发，插件必须使用替代方案，如用于自定义标签页的 `XDebugProcess.createTabLayouter` 和用于与调试器节点交互的操作的 `XDebuggerTreeBackendOnlyActionBase`。

💬 文章金句

  • 为了支持远程开发场景——即 IDE 界面在本地机器上运行，而代码在远程服务器上执行——我们重新设计了调试器架构。
  • 为了在远程开发和本地 IDE 模式下提供相同的体验，我们对两者使用单一实现。因此，本指南中描述的更改可能会影响两种模式下的插件。
  • 前端实现不再直接与插件通过 `XDebugProcess` 和 `XSuspendContext` 提供的实体一起工作。
  • 使用 2026.1 EAP 测试你的插件。UI 组件和操作是最可能受影响的区域。
  • 以下 API 在远程开发模式下将无法工作：UI 和调试器标签页访问 [...] 与调试器节点一起工作的基本操作类 [...]。
