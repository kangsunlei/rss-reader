Lyft 如何构建每秒处理数百万预测的机器学习平台

1/13/2026, 4:30:57 PM

📌 一句话摘要

Lyft 构建了 LyftLearn Serving 机器学习平台，为每个团队使用独立的微服务，以处理每秒数百万的实时预测，简化部署并确保可扩展性和灵活性。

📝 详细摘要

本文详细介绍了 Lyft 如何设计 LyftLearn Serving 机器学习平台，该平台旨在处理每秒数百万的实时预测，同时解决数据平面和控制平面的复杂性。面对不同团队的需求和单体遗留系统的局限性，Lyft 采用了独特的微服务方法。该平台不是构建单一共享服务，而是为每个机器学习团队生成专用的独立微服务，实现自主部署、库版本控制和更清晰的所有权。文章概述了平台的运行时架构，包括 Flask、Gunicorn、Envoy 和核心服务库，允许机器学习工程师注入自定义的加载和预测函数。一个关键创新是配置生成器，它可以搭建完整的微服务仓库，极大简化了机器学习工程师的入门流程。系统还集成了模型自测试功能，用于早期问题检测。结论部分强调了经验教训，如清晰术语的重要性、长期模型稳定性、强文档支持以及采用成熟技术。

💡 主要观点

  1. Lyft 的机器学习平台 LyftLearn Serving 解决了数据平面（运行时性能）和控制平面（模型生命周期管理）的双重复杂性。 为了大规模管理实时预测，该平台旨在高效处理即时执行需求（低延迟、高吞吐量）和机器学习模型的长期运营方面（部署、重新训练、版本控制）。
  2. 该平台采用独特的微服务架构，为每个机器学习团队生成独立的微服务。 这种方法克服了单体系统的局限性，允许每个团队对其模型部署、库版本和运营所有权拥有完全自主权，促进独立开发并减少冲突。
  3. 配置生成器简化了机器学习工程师的入门流程。 使用 Yeoman，该生成器自动化创建完整的 GitHub 仓库，包含所有必要的基础设施配置和示例代码，使机器学习工程师能够快速部署模型而无需深入了解基础设施。
  4. 集成模型自测试以确保持续模型完整性并早期检测问题。 机器学习工程师在其模型代码中定义测试数据，平台在模型加载期间和 CI/CD 过程中自动执行这些测试，为模型兼容性和行为变化提供即时反馈。
  5. 运行时架构采用分层设计，支持多样化的机器学习库并与 Lyft 现有基础设施集成。 基于 Flask、Gunicorn、Envoy 和 Kubernetes 构建，该系统提供了一个灵活的环境，机器学习工程师可以使用他们偏好的库，同时受益于集中式监控、日志记录和追踪。

💬 文章金句

  • 在这种规模下提供机器学习服务的工程挑战是巨大的。
  • Lyft 选择使用微服务架构构建 LyftLearn Serving，其中小型独立服务各自处理特定职责。
  • 他们没有构建一个所有团队共享的单一微服务，而是创建了一个为每个团队生成完全独立微服务的平台。
  • 生成器通过简单的问答流程工作...然后自动创建一个完整的 GitHub 仓库，包含运行 LyftLearn Serving 微服务所需的一切。
  • 他们拥抱了成熟技术。与其追逐最新趋势，他们选择了经过验证的稳定工具，如 Flask、Kubernetes 和 Python。
