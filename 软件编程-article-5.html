如何使用 Next.js 构建一个简单的作品集博客

5/30/2025, 2:44:09 PM

📌 一句话摘要

学习如何通过抓取外部 URL 的文章元数据，使用 Next.js 构建一个服务器端渲染的作品集博客。

📝 详细摘要

本文提供了一个使用 Next.js 构建简单、无数据库的作品集博客的分步指南。关键创新在于通过简单地在 JSON 文件中列出各种外部平台的 URL 来整合文章。该应用程序利用 Next.js 服务端组件来获取这些 URL 中的元数据（特别是 Open Graph 和 JSON-LD），从而有效地绕过客户端 CORS 问题。该指南详细介绍了项目结构，涵盖了关键组件，如导航栏 (Navbar)、带搜索的头部区域 (Hero) 和用于文章展示的主要内容区域 (MainBody)，并解释了使用 React Hooks 实现客户端搜索和标签过滤的方法。构建过程涉及像 Cheerio 这样的库来进行数据抓取，展示了一种创建动态内容聚合器的实用方法，可以展示各种已发布的作品。

💡 主要观点

  1. 使用 Next.js 服务端组件来获取外部数据。 直接在浏览器中从不同来源获取元数据会被 CORS 阻止。在服务端组件上运行数据获取逻辑可以绕过此限制，从而可以从各种站点进行聚合。
  2. 使用 Open Graph 和 JSON-LD 自动提取文章元数据。 该应用程序读取嵌入在外部文章页面的 HTML 中的标准元数据格式，自动提取标题、图像和描述等详细信息，而无需手动数据输入。
  3. 通过在 JSON 文件中列出文章 URL 来构建一个无数据库的系统。 简化内容管理；更新博客仅需将新的文章 URL 添加到本地 JSON 文件中，从而降低了复杂性和外部依赖性。
  4. 在客户端实现搜索和标签过滤。 服务端获取的文章数据被传递到客户端组件，从而可以使用标准的 React 和 JavaScript 技术根据用户搜索词或所选标签进行动态过滤。

💬 文章金句

  • 我只是希望能够将新文章的 URL 添加到 JSON 文件中，网站就会提取标题、日期、封面图像和描述等信息，然后自行更新。无需数据库。
  • 该项目由客户端组件和服务端组件构成。由于 CORS 限制，客户端组件无法直接从 URL 获取数据，因此必须在服务端运行数据获取逻辑。
  • 为了了解我是如何实现的，我检查了 HTML 文本的元数据，发现它们中的大多数都使用了 Open Graph 元数据，这使得抓取变得容易。我还发现一些信息不在 meta 标签中，而是在 JSON-LD 中。
  • 搜索功能主要是通过根据所选标签或输入的搜索词过滤文章数组来实现的。
