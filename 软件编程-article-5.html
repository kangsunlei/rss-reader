腾讯 Kuikly 框架鸿蒙版正式开源 —— 揭秘卓越性能适配之旅

6/3/2025, 8:02:00 AM

📌 一句话摘要

腾讯开源 Kuikly 跨端框架鸿蒙版，基于 KMP 实现高性能原生体验，并支持 Compose DSL。

📝 详细摘要

文章详细介绍了腾讯自研跨端开发框架 Kuikly 的鸿蒙平台适配与开源。Kuikly 基于 Kotlin Multiplatform，旨在提供统一技术栈、高性能、动态化及原生体验。在适配鸿蒙 Next 过程中，Kuikly 团队解决了 ArkUI 声明式 UI 映射性能低下的问题，最终转向高性能的 CAPI 命令式实现。文章深入阐述了渲染层（如 C 节点与 ArkTS 嵌套、文本渲染性能优化）和 KuiklyBase 层（Kotlin Native 适配、调试效率提升）的关键技术挑战与解决方案。Kuikly 鸿蒙版已在腾讯多款业务落地并达到原生性能。此外，文章还宣布开源了 Kuikly 对标准 Compose DSL 的 Beta 版本支持，并展望了未来技术方向。框架强调通过 KMP 实现高性能、原生体验，并提供全面的工具链支持。

💡 主要观点

  1. Kuikly 鸿蒙版基于 KMP 实现原生级高性能 利用 KMP 将 Kotlin 代码编译为原生产物，结合鸿蒙原生渲染能力，实现接近原生应用的启动速度和流畅体验，远超部分现有跨端方案。
  2. 框架支持页面级动态化和热更新 Kuikly 将动态化作为核心目标，支持按需更新页面 UI 和逻辑，尤其在 Android 上已验证高性能动态化能力，提升业务灵活性和迭代效率。
  3. 采用鸿蒙 CAPI 解决渲染层性能瓶颈 针对 ArkUI 声明式接口在高性能场景下的局限性，Kuikly 深入系统底层，通过命令式 CAPI 实现渲染指令映射，显著提升了渲染效率。
  4. 攻克 C 节点与 ArkTS 组件混合嵌套难题 设计影子节点和利用 API 12 的内容插槽机制，有效解决了 Kuikly 内置 C 节点与业务自定义 ArkTS 组件混合使用的兼容性问题。
  5. 优化 Kotlin Native 在鸿蒙上的运行时和调试体验 通过定制 LLVM 编译、运行时性能调优和开发 IDE 插件，大幅提升了 KMP 在鸿蒙平台的执行效率和开发者的调试便利性。
  6. 同步开源对 Compose DSL 的 Beta 支持 在原有自研 DSL 基础上，新增对 Compose 标准语法的支持，降低新开发者上手门槛，并保留 Kuikly 高性能、动态化和原生渲染优势。

💬 文章金句

  • 本次开源鸿蒙平台支持和 Compose DSL 支持，进一步提升业务多端适配和鸿蒙开发效率。
  • 经过持续的迭代和打磨优化，Kuikly 鸿蒙版完整适配，并取得了原生性能表现。
  • Kuikly 是一个一码多端、追求极致性能、动态化、原生体验的开发框架，技术上以 Kotlin Multiplatform 为依托...
  • 为了追求极致性能表现，我们最终决定采用 CAPI 方案。
  • 通过对 Kotlin 的调试插件以及配套运行时进行了优化...实现了 40 倍的速度提升，使插件从基本不可用状态变得基本可满足日常开发调试需求。
