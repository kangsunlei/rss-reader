.NET 10 预览版 5 带来 Blazor 可观测性(Observability)、XAML 简化等新特性

6/28/2025, 12:00:00 AM

📌 一句话摘要

.NET 10 预览版 5 引入了 Blazor 增强的可观测性(Observability)、.NET MAUI 中简化的 XAML 语法，以及 ASP.NET Core、WPF 和 Entity Framework Core 中的其他开发效率提升。

📝 详细摘要

微软的 .NET 10 预览版 5 为其生态系统带来了重大更新，重点关注开发者生产力和应用可观测性(Observability)。主要改进包括 Blazor 的新指标(Metrics)和追踪(Tracing)功能以提升监控能力、.NET MAUI 的 XAML 全局和隐式命名空间以简化 XAML 代码，以及 WPF 中网格(Grid)定义的简写语法。ASP.NET Core 增强了对 OpenAPI 3.1 的支持和安全配置，而 Entity Framework Core 引入了默认约束(Default Constraints)的自定义命名。这些更新共同提升了 .NET 平台构建现代应用的能力，尤其有利于使用 Web、移动和桌面技术的全栈开发者。

💡 主要观点

  1. Blazor 新增详细指标和追踪功能以增强可观测性(Observability) 基于 OpenTelemetry 的新指标(Metrics)和追踪(Tracing)功能提供了对组件、生命周期事件和服务器回路(Server Circuits)的细粒度可见性，显著改善了 Blazor 应用的调试和性能监控。
  2. .NET MAUI 通过全局和隐式命名空间革新 XAML 开发 这些特性消除了冗长的 xmlns 声明，使 XAML 代码更简洁且更易维护，特别是在跨平台移动开发中使用自定义视图和第三方库时。
  3. WPF 通过网格简写和主题改进提升开发者体验 网格(Grid)定义的新简洁语法简化了 XAML 编写，同时 Fluent 主题的改进解决了从右到左布局(RTL)问题并减少了内存分配，提升了开发效率和性能。
  4. Entity Framework Core 引入可自定义的默认约束(Default Constraints)命名 此更新让开发者能够精确控制数据库架构(Schema)生成，支持通过 UseNamedDefaultConstraints 进行显式命名或自动约定，提高了数据库的可维护性。
  5. ASP.NET Core 通过 OpenAPI 3.1 和安全增强推进 API 开发 改进的 OpenAPI 生成现在可以从 XML 文档标签中提取元数据，而 HTTP.sys 的自定义安全描述符提供了操作系统级别的访问控制，增强了 API 文档和安全性。
  6. ASP.NET Core 中的 XML 文档处理改进 对 XML 文档中 和 标签的增强识别实现了更好的自动 API 文档生成，提升了 API 使用者的开发体验。

💬 文章金句

  • 指标(Metrics)通过专用于组件、生命周期事件和服务器回路(Server Circuits)的指标收集器(Meter)发布。
  • 追踪(Tracing)使用新的 Microsoft.AspNetCore.Components 活动源(ActivitySource)，包含导航、事件处理和回路生命周期(Circuit Lifecycles)的详细检测。
  • 这些特性通过允许开发者使用控件而无需指定多个 xmlns 声明来简化 XAML 代码。
  • 开发者现在可以直接在模型配置(Model Configuration)中分配约束名称，或使用 UseNamedDefaultConstraints 为所有默认约束(Default Constraints)启用自动命名。
  • builder.Services.ConfigureOpenTelemetryMeterProvider(meterProvider => { meterProvider.AddMeter('Microsoft.AspNetCore.Components');...});
  • Fluent 主题已优化，解决了崩溃问题并改进了从右到左布局(RTL)的样式。
