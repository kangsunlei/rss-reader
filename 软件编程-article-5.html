📌 一句话摘要

TeamCity 2025 年路线图侧重于用户界面更新、新功能引入和 Jenkins 迁移，旨在全面增强持续集成/持续交付体验。

📝 详细摘要

TeamCity 2025 年路线图包含旨在构建更高效、用户友好和安全的持续集成/持续交付平台的重大更新。它实现了 TeamCity Enterprise 界面的现代化，简化项目设置，并通过 YAML 支持和完整分支管理增强构建链编辑，从而可能将构建时间缩短高达 40%。版本控制系统集成得到改进，简化了连接；TeamCity 新功能简化了构建配置。依赖缓存得到增强，可自动管理通用构建系统目录，从而减少构建持续时间和成本。Jenkins 迁移工具简化了从 Jenkins 的迁移过程。此外，还探索了用于灵活构建链的动态管道，并使用 K2 编译器增强了 Kotlin 领域特定语言。通过从 Git 读取多节点设置的配置，改进了配置管理，解决了多节点环境下配置同步和一致性问题。新增阿里云支持，代理自动缩放优化了基于云的构建代理管理。TeamCity 管道通过作业调试、改进的版本控制系统集成、个人通知和 IntelliJ IDEA 集成得到增强。通过限制传入依赖项，提高了安全性。

💡 主要观点

  1. 现代化的用户界面简化了项目设置和构建链编辑，提供 YAML 支持和完整的分支管理，从而提高用户效率并降低上手难度。 新的用户界面旨在增强用户体验，简化项目设置，使构建链配置更直观，并支持 YAML 和完整的分支管理，从而提高开发效率。
  2. TeamCity 功能通过可重用的 YAML 操作简化了构建配置。 新功能允许用户搜索和应用预定义的构建步骤，从而加快构建配置过程，提高灵活性和可共享性。
  3. 代理自动缩放优化了基于云的构建代理的管理并降低了成本。 通过自动调整代理的数量，它可以确保始终有足够的代理可用，并根据预定义的计划动态调整代理的最大数量，从而提高持续集成/持续交付性能。
  4. 在 Git 中存储配置可解决多节点环境下配置同步和一致性问题。 在 Git 中存储和同步配置文件可确保跨多个节点的可靠、无冲突的配置管理，同时无需专用共享磁盘。
