去哪儿网 C 端研发 AI Coding 探索及落地

2/10/2026, 10:02:00 AM

📌 一句话摘要

去哪儿网通过“规则算法+AI”融合架构与多 Agent 协作，攻克了 C 端研发中 UI 像素级还原与逻辑代码生成的难题，实现了从设计稿到可运行代码的全链路 AI 辅助流程。

📝 详细摘要

本文详述了去哪儿网在大前端领域落地 AI Coding 的实战经验。针对 C 端研发对 UI 像素级还原和复杂业务逻辑的高要求，团队放弃了单一的 AI 或规则方案，构建了“规则+AI”的 D2C 融合架构，利用规则保障样式精准，AI 提升代码语义化。在逻辑生成（P2C）方面，通过飞书文档授权解析、多 Agent 并发分片生成以及引入 MCP 协议结合私有知识库，有效解决了长文档上下文丢失和 API 幻觉问题。最后，通过开发 IDE 插件实现了从设计稿到代码生成的闭环体验，将开发模式从“0 到 1”转变为“0.7 到 1”的 AI 辅助模式。

💡 主要观点

  1. 采用“规则算法+AI”融合架构解决 D2C 还原度与语义化的对冲矛盾。 规则算法负责对 Figma 原始数据进行清洗与标准化，确保像素级视觉还原；AI 模型则负责意图理解与组件化拆分，避免生成冗余的“div 海”，输出符合工程规范的语义化代码。
  2. 利用多 Agent 并发架构破解长 PRD 文档导致的逻辑生成不稳定问题。 针对复杂业务需求，系统根据 PRD 复杂度动态启动多 Agent，通过语义分片和模块级路由，让子 Agent 聚焦特定功能模块，有效解决了大模型上下文窗口限制导致的细节丢失。
  3. 引入 MCP 协议与私有知识库增强，替代传统 RAG 方案以消除 API 幻觉。 团队发现向量检索不适用于 SDK 调用场景，转而通过 MCP 协议将完整的内部 SDK 定义直接提供给模型，确保生成的 API 调用、参数结构与内部规范完全一致，使代码具备直接运行的能力。
  4. 通过 IDE 插件化与“Fix Error”机制巧妙实现研发流程的无缝衔接。 将代码生成能力集成至 IDE 插件，并利用 IDE 原生的错误修复指令作为 Prompt 注入通道，解决了 Web 平台与开发环境割裂的问题，实现了物料准备、规范匹配到代码生成的全链路闭环。

💬 文章金句

  • C 端直接面向海量用户，业务逻辑高度复杂，需应对多样化场景与频繁迭代，这些特性让 C 端成为 AI Coding 领域中极具攻克价值的 '深水区'。
  • D2C 的核心难点并非单一技术问题，而是 '视觉精准性' 与 '代码语义化' 的天然对冲：规则算法的优势是还原精准，却无复用价值；纯 AI 模型的优势是复用适配，却无还原精度。
  • 在尝试解决 API 幻觉问题时，我们抛弃了原有的向量知识库方式的 RAG 方案，主要原因是向量知识库不适用于这一具体场景。
  • 开发人员 coding 的工作，从以往 0 到 1 的完整开发，变为了可基于 ai 生成产物，从 0.7 到 1 的部分开发，大大提升了开发效率。
