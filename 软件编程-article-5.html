React 中文周刊 #266 - Cloudflare 自研 Vite 驱动的 Next.js

3/1/2026, 2:47:00 AM

📌 一句话摘要

本期 React 周刊聚焦 Cloudflare 利用 AI 实验性重写 Next.js、React 基金会正式成立以及 Expo SDK 55 发布等生态重大动态。

📝 详细摘要

《React 中文周刊 #266》汇总了近期前端及 React 生态的核心资讯。重点介绍了 Cloudflare 开发的基于 Vite 的 Next.js 替代方案 vinext，该项目利用 AI 在短时间内完成重写，旨在优化边缘运行环境。另一里程碑事件是 React 基金会正式脱离 Meta 移交 Linux 基金会托管，标志着治理模式的独立。此外，周刊还涵盖了 Expo SDK 55 对 React 19 的支持、React Native 适配 Meta Quest、React Query 的抽象最佳实践，以及 Bun 新增的自包含 HTML 打包功能。

💡 主要观点

  1. Cloudflare 利用 AI 辅助开发了基于 Vite 的 Next.js 实验性实现 vinext。 vinext 旨在复刻 Next.js 的 API，使其能在 Cloudflare Workers 等边缘环境更高效运行，展示了 AI 在重构复杂框架中的潜力。
  2. React 基金会正式成立并由 Linux 基金会托管，实现治理权的去中心化。 React、React Native 和 JSX 不再由 Meta 独占，而是由包括微软、Vercel 在内的多家公司共同治理，增强了生态的开放性与稳定性。
  3. Expo SDK 55 发布，全面拥抱 React 19 并弃用 React Native 旧架构。 此次更新将底层升级至 React Native 0.83，重做了默认模板并引入 Hermes v1 支持，标志着移动端开发向新架构的全面转型。
  4. React Query 专家建议避免使用自定义 Hook 包装 useQuery，推荐 queryOptions。 通过 queryOptions API 可以更好地解决类型推断问题，并使数据获取逻辑在非组件场景下更易于复用和维护。
  5. Bun v1.3.10 支持将 React 应用打包为单个自包含的 HTML 文件。 新增的编译目标允许将所有资源内联，极大简化了纯客户端应用的部署流程，为轻量级工具开发提供了新思路。

💬 文章金句

  • Cloudflare 用 AI 在一周内重写了 Next.js —— vinext 是基于 Vite 的实验性实现，复刻 Next.js 的 API 表面。
  • React、React Native 和 JSX 不再由 Meta 拥有，而是由 Linux 基金会托管的一家独立基金会所有。
  • 为什么用自定义 hook 包装 useQuery 是错误抽象，以及 queryOptions API 如何同时解决类型推断和非组件场景的问题。
  • Bun v1.3.10 新增 build --compile --target=browser 功能，可生成内联所有资源的自包含 HTML 文件。
