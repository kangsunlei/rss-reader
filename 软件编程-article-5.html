Flipkart 通过分层联邦将 Prometheus 扩展至 8000 万指标

10/18/2025, 12:00:00 PM

📌 一句话摘要

Flipkart 采用分层联邦设计将 Prometheus 扩展到 8000 万个指标，有效降低了云原生环境大规模监控的基数和负载。

📝 详细摘要

本文详细介绍了 Flipkart 如何通过实施分层联邦架构成功地扩展 Prometheus 以处理 8000 万个指标。由于 2，000 个 API 网关实例生成的高基数指标带来的严重可扩展性限制，Flipkart 从 StatsD 转型到 Prometheus。他们的解决方案包括本地 Prometheus 服务器接收指标，应用记录规则以删除高基数标签，并公开聚合序列以供联邦服务器抓取。这种分层设计，结合实例标签修剪和延迟指标的摘要统计等策略，显著降低了指标基数和中心服务器负载。文章还将 Flipkart 的方法与 Thanos、Cortex/Mimir 和 VictoriaMetrics 等其他分布式监控系统进行了对比，突出了复杂性、全局可见性和运营开销方面的权衡。Flipkart 的选择优先考虑简单性、控制和增量可扩展性，为管理爆炸性指标增长的组织提供了一个实用的蓝图。

💡 主要观点

  1. Flipkart 通过分层联邦和积极的基数降低将 Prometheus 扩展到 8000 万个指标。 本地 Prometheus 服务器聚合指标，使用记录规则删除高基数标签，并将聚合数据向上联合，从而显著降低了中央监控系统的负载，并实现了高规模的可观测性。
  2. 有效的基数降低包括删除实例标签和发布高容量指标的摘要统计信息。 这种方法将数百万个原始序列转换为数千个集群级指标，这对于管理数据量、提高查询性能以及使生产环境中大规模的可观测性可管理至关重要。
  3. 分层联邦提供了简单性和原生的 Prometheus 对齐，与更复杂的分布式监控解决方案形成对比。 虽然 Thanos、Cortex/Mimir 和 VictoriaMetrics 等替代方案提供全局查询或大规模扩展，但 Flipkart 优先考虑控制、简单性和增量可扩展性，使 Prometheus 在很大程度上是无状态的，并避免了外部依赖性。

💬 文章金句

  • 此次迁移是由他们的 API 网关层驱动的，其中大约 2，000 个实例每个发出大约 40，000 个指标，导致同时产生惊人的 8000 万个时序数据点。
  • 他们扩展解决方案的核心在于分层联邦：本地 Prometheus 服务器从服务中获取指标，应用记录规则以删除高基数实例标签，并通过 /federate 端点公开聚合序列。
  • 这种分层设计显著降低了指标基数和中央服务器的负载。
  • Flipkart 的经验强调了平面监控架构在规模上的限制，并说明了联邦、聚合规则和标签修剪如何使大规模的可观测性变得可管理。
  • Flipkart 选择依赖分层联邦而不是这些分布式后端，反映了控制、简单性和增量可扩展性之间的平衡。
