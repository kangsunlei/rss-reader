写 HTML 就能做视频？HeyGen 开源的这个工具有点意思

4/23/2026, 10:30:00 AM

📌 一句话摘要

HeyGen 开源了 HyperFrames 框架，允许开发者使用 HTML、CSS 和 GSAP 编写代码来生成视频，通过 Seek-and-Capture 机制和 Chrome DevTools Protocol 实现高效渲染。

📝 详细摘要

本文详细介绍了 HeyGen 开源的 HyperFrames 框架，该框架允许开发者使用 HTML、CSS 和 GSAP 动画库来创建视频。文章深入解析了其核心原理，包括基于 Seek-and-Capture 的帧渲染机制、通过 Chrome DevTools Protocol 的 HeadlessExperimental.beginFrame API 进行高效像素捕获、以及 FrameAdapter 协议和 window.__hf 通信桥的实现细节。文章还涵盖了音频的独立处理、并行渲染、确定性保证等关键技术点，并提供了从安装、项目结构到具体代码示例的完整实践指南。作者通过一个智能手表产品介绍视频的案例，展示了如何使用 GSAP 动画、字幕同步和 CSS 毛玻璃效果来构建多场景视频。文章最后指出，HyperFrames 适合前端开发者制作产品介绍、数据可视化等视频，但不适用于电影级特效。

💡 主要观点

  1. HyperFrames 将视频制作转化为代码编写，利用 HTML、CSS 和 GSAP 定义动画。 该框架颠覆了传统视频编辑的图形界面操作模式，让熟悉前端技术的开发者能够通过编写代码来精确控制视频的每一个元素和动画，实现版本控制和自动化生成。
  2. 核心渲染机制是 Seek-and-Capture，通过逐帧定位并捕获静态快照来生成视频。 不同于实时播放录制，HyperFrames 使用整数帧号计算时间，通过 Chrome DevTools Protocol 的 beginFrame API 直接命令渲染器输出像素，避免了时序问题和半渲染状态，确保了渲染的确定性和高效性。
  3. 框架通过 FrameAdapter 协议和 window.__hf 通信桥实现了动画库无关性和引擎-页面解耦。 FrameAdapter 定义了标准接口，使得任何支持按帧跳转的动画库（如 GSAP）都能接入；window.__hf 协议则作为 Node.js 引擎与浏览器页面之间的通信桥梁，实现了帧跳转命令的传递。

💬 文章金句

  • HyperFrames 的思路很简单：既然前端开发都是写代码，视频为什么不能也写代码？
  • HyperFrames 的做法：不播放，只 seek。每一帧都是独立的静态快照。
  • seekFrame 必须是幂等的（同一帧调两次结果相同），且必须支持随机 seek（可以先 seek 第 90 帧再 seek 第 10 帧），不能有顺序依赖。
  • 同一份 HTML，任意时间在任意机器上渲染，输出的 MP4 应该二进制相同（Docker 模式下严格成立）。
