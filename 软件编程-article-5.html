通过内容协商构建智能体友好型页面 - Vercel

2/3/2026, 1:00:00 PM

📌 一句话摘要

Vercel 推出了一种通过 HTTP 内容协商向 AI 智能体提供 Markdown 的方法，在为人类保留 HTML 的同时，显著降低了负载大小和 Token 消耗。

📝 详细摘要

本文讨论了针对 AI 智能体的网页优化，这些智能体优先考虑结构化文本而非视觉样式。通过利用 HTTP “Accept” 请求头，Vercel 的博客现在可以检测客户端（如 Claude Code）是否偏好 “text/markdown”，并提供轻量级版本的内容。这种方法将负载大小降低了 99% 以上，节省了 LLM Token 并提高了处理速度。该实现使用 Next.js 中间件和路由处理器将富文本转换为 Markdown，并通过 Next.js 16 远程缓存确保版本间的同步。此外，它还引入了智能体友好型站点地图，以便更好地进行内容发现。

💡 主要观点

  1. AI 智能体受益于 Markdown 而非 HTML，从而节省上下文窗口空间和 Token。 与人类不同，智能体不需要 CSS 或 JavaScript。提供简洁的 Markdown 移除了不必要的标记，使 LLM 能够在有限的 Token 预算内更高效地处理信息。
  2. HTTP 内容协商允许根据客户端请求头从同一 URL 提供不同格式。 通过使用 “Accept” 请求头，服务器可以检测客户端是否偏好 Markdown 或 HTML。这避免了重复内容问题，并为人类和 AI 维持了单一事实来源。
  3. 性能提升巨大，典型文章的负载大小减少了 99.6%。 一个 500KB 的 HTML 页面可以缩减为 2KB 的 Markdown 文件。这种大幅缩减使智能体能够运行得更快，触发频率限制的次数更少，并且每次请求可以消耗更多内容。
  4. 通过智能体优化的站点地图和特定的 URL 扩展名促进内容发现。 实现带有元数据的 Markdown 专用站点地图有助于智能体有效地导航可用内容，而向 URL 添加 “.md” 则提供了访问结构化文本版本的手动方式。

💬 文章金句

  • 智能体浏览网页，但它们的阅读方式与人类不同。它们不需要 CSS、客户端 JavaScript 或图像。
  • 智能体需要的是干净、结构化的文本。
  • 一篇典型的博客文章包含所有 HTML、CSS 和 JavaScript 时重达 500KB。然而，同样的 Markdown 内容仅为 2KB。这意味着负载大小减少了 99.6%。
  • 对于在 Token 限制下运行的智能体，更小的负载意味着它们每次请求可以消耗更多内容，并将预算花在实际信息而非标记语言上。
  • 我们更新了博客和更新日志页面，使智能体可以访问 Markdown，同时仍为人类读者提供完整的 HTML 和 CSS 体验。
