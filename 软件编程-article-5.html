IntelliJ IDEA 2025.1.1 正式发布

5/7/2025, 2:01:40 PM

📌 一句话摘要

IntelliJ IDEA 2025.1.1 首个补丁版本发布，包含 11 项具体问题修复与功能改进

📝 详细摘要

本文宣布 IntelliJ IDEA 2025.1 系列的首个补丁版本 2025.1.1 正式发布。本次更新包含 11 项重要修复与改进，主要涉及：通过 JetBrains 账户进行设置备份与同步的修复、Gradle 7.x.x 测试调试支持、含多个 --add-exports 参数的 Maven 项目导入优化，以及 Zsh 终端功能修复。值得关注的新特性包括：HTTP Client 工具新增禁用 URL 特殊字符编码功能（通过 @no-auto-encoding 注解实现），以及 @Nullable 注解处理机制的改进。用户可查看完整发布说明和问题追踪系统获取详细信息。

💡 主要观点

  1. HTTP Client 新增禁用 URL 特殊字符编码功能 新增 @no-auto-encoding 注解支持，允许直接发送 URL 中的特殊字符（如 +、@、% 等），提供更精细的 HTTP 请求控制能力。
  2. 设置备份与同步功能已修复 修复授权验证问题，确保 IDE 设置能够通过 JetBrains 账户实现可靠的跨设备备份与同步。
  3. Zsh 终端自定义配置支持已完善 优化 shell 集成支持，解决自定义配置文件导致的兼容性问题，显著提升 Zsh 用户的使用体验。
  4. Gradle 7.x.x 测试调试问题已解决 修复调试器兼容性问题，确保基于 Gradle 7.x.x 构建的项目能够正常进行测试调试。
  5. Maven 项目导入机制改进 优化编译器参数生成逻辑，确保包含多个 --add-exports 参数的复杂 Maven 项目能够正确导入。

💬 文章金句

  • 通过「备份与同步」功能进行的设置备份，在完成 JetBrains 账户授权后现已恢复正常工作。
  • 使用 Gradle 7.x.x 进行测试调试时不再出现失败情况。
  • IDE 终端现已完全支持使用自定义配置文件的 Zsh 环境。
  • 现在可通过在请求前添加 @no-auto-encoding 注解，使 HTTP Client 保持 URL 中的特殊字符（如 +、@、% 等）原样发送，而不进行编码处理。
  • 当使用默认限定符时，IDE 现已能正确处理局部变量上的 @Nullable 注解。
