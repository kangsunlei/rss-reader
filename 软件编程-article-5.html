AutoJack 暗藏致命攻击链路，一个网页可劫持 AI Agent 执行任意代码

6/20/2026, 10:00:00 AM

📌 一句话摘要

微软披露 AutoJack 攻击链，利用 AutoGen Studio 预发布版中 MCP WebSocket 的漏洞，使单个恶意网页即可劫持 AI Agent 在主机上执行任意代码。

📝 详细摘要

本文报道了微软研究人员披露的 AutoJack 攻击链。该漏洞存在于微软 AutoGen 多 Agent 框架的开源原型界面 AutoGen Studio 的预发布版本（0.4.3.dev1 和 0.4.3.dev2）中。攻击者通过诱导 Agent 加载恶意网页，利用 MCP WebSocket 的未验证命令执行、缺乏认证和跨域访问缺陷，可在主机上以 Agent 运行账户权限执行任意代码。文章详细说明了漏洞根源、受影响版本、攻击链运作原理（三重缺陷），并给出了修复方案（拉取 GitHub 主分支修复代码）和缓解措施（隔离运行、使用低权限账户）。最后，文章指出此类模式在 Agent 框架中普遍存在，并强调了超越 localhost 检查的安全实践。

💡 主要观点

  1. AutoJack 攻击利用 AutoGen Studio 预发布版 MCP WebSocket 的漏洞实现 RCE。 攻击链利用 MCP WebSocket 的未验证命令执行、缺乏认证和跨域访问三重缺陷，使恶意网页能以 Agent 权限在主机上执行任意代码。
  2. 漏洞仅影响 AutoGen Studio 的预发布版本，稳定版不受影响。 通过 pip install autogenstudio 安装的稳定版 0.4.2.2 不包含有漏洞的 MCP 路由，而预发布版本 0.4.3.dev1 和 0.4.3.dev2 存在该问题。
  3. 微软已修复主分支代码，但 PyPI 尚未发布修复版本。 修复方案包括不再从 URL 读取命令、采用一次性会话 ID 和强制认证流程。预发布版本用户需手动拉取 GitHub 主分支修复代码。
  4. 此类漏洞模式在 Agent 框架中具有普遍性，localhost 不再是可信边界。 当 Agent 既能浏览开放网络又能访问特权本地服务时，简单的 localhost 检查不足以作为安全边界，需要实施控制平面认证和进程执行白名单。

💬 文章金句
