程序员只写代码的时代结束了！OpenAI 工程负责人：开发者要重新定义什么叫“任务完成”

10/10/2026, 9:45:00 AM

📌 一句话摘要

OpenAI 电脑操作 Agent 负责人指出，Computer Use 正在打通写代码到软件端到端验收的闭环，开发者的核心交付物正从代码 Diff 转向包含权限、回滚与业务结果的完整任务完成度。

📝 详细摘要

本文基于 Latent Space 对 OpenAI 电脑操作 Agent（Computer Use）产品与工程负责人 Ari Weinstein 的深度访谈，探讨了 AI 如何重塑软件工程工作流。随着 Agent 获得操作 Linux 虚拟桌面与浏览器的能力，AI 编程不再局限于编辑器内的代码生成，而是延伸至自动打开软件、模拟真实用户操作、捕获报错并闭环修复代码的完整流程。技术实现上，模型结合截图像素、无障碍树（Accessibility Tree）与 Playwright 提升操作准确性，使得无障碍语义成为机器可读的新型界面协议。同时，这也为没有 API 的遗留企业系统提供了自动化入口。Ari 指出，可靠 Agent 的核心在于失败后的自我排错与恢复循环，而开发者的职责正从编写代码转变为定义严格的验收边界、权限控制与人工接管机制，交付物从 Diff 彻底转向端到端的任务结果。

💡 主要观点

  1. 打通代码生成与功能验收，终结人替 Agent 做测试的怪圈 过去开发者写好代码或由 Agent 生成代码后，人往往沦为最琐碎的手动点按测试人员（QA）。Computer Use 赋予 Agent 直接操作真实界面的能力，实现输入数据、观察界面反馈、读取控制台报错并自动返回修改代码的闭环。
  2. 融合多源信息，无障碍语义成为机器界面的协议标准 早期的 Computer Use 单纯依靠视觉截图找按钮，速度慢且易出错。新架构结合屏幕截图、无障碍信息树和 Playwright，使前端界面的规范性（如语义标签、明确状态）直接决定了 Agent 操作的稳定性。
  3. 为缺少 API 的企业遗留系统提供低成本自动化入口 大量采购、财务与内部系统缺乏 API 接口，重构成本极高。Agent 能够模拟人工登录并跨页面流转，使遗留系统无需重新开放接口即可接入自动化工作流，与高一致性要求的稳定 API 形成互补。
  4. 工程核心从单次执行成功率转向失败恢复循环与安全权限 真实的工程环境充满超时与改版变数，可靠的 Agent 依赖自我排错与重试机制。随着 Agent 能触碰真实业务（如下单付款），开发者必须在底层显式定义用户授权确认、重试阈值、异常回滚及人工接管逻辑。

💬 文章金句

  • Agent 可以直接使用人类正在使用的软件。
  • 开发者就像在给 Agent 做测试。
  • 它可以结合截图、无障碍信息和 Playwright 完成操作。
  • 在不少任务上，Computer Use 的速度已经接近或超过普通用户。
  • 执行付款等重要操作前，需要取得用户同意。
