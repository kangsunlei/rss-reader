Cloudflare Workers 上的下一代证书透明度日志 Azul

4/11/2025, 2:00:01 PM

📌 一句话摘要

Cloudflare Azul：基于 Cloudflare Workers 的下一代证书透明度日志，利用静态 CT API 提升性能、降低成本。

📝 详细摘要

本文探讨了证书透明度 (CT) 的演变和 CT 日志的运营挑战，介绍了 Cloudflare 基于静态 CT API 的下一代 CT 日志 Azul。Azul 是一个开源的 Rust 实现，利用 Cloudflare 的分布式全球网络和无服务器平台，提高了效率，降低了运营成本，并增强了可靠性。新的设计通过静态、可缓存的分片来组织日志数据。文章详细介绍了 Azul 的设计决策、实现和优势，强调了其降低 CT 日志运营商门槛并确保 WebPKI 安全的潜力。

💡 主要观点

  1. 静态 CT API 通过静态分片与去重显著降低了运营成本和复杂性。 静态 CT API 通过静态、可缓存的分片组织日志数据，并对颁发者证书进行去重，从而减少了对动态 API 服务器的需求，并提高了数据检索效率。
  2. Azul 利用 Cloudflare 的分布式网络来实现高可用性和弹性。 在 Cloudflare 的全球网络上运行 CT 日志可确保即使在集中式数据中心发生中断时，日志仍然可访问且可用。
  3. 静态 CT API 中延迟的 SCT 颁发减少了合并延迟问题。 静态 CT API 仅在条目合并到日志后才使用 SCT 响应，从而消除了与确保及时合并证书相关的痛点。
  4. Azul 的 Rust 实现和 Cloudflare Workers 部署展示了 Cloudflare 的技术堆栈优势以及对开发者体验的关注。 Azul 在 Cloudflare Workers 上使用 Rust 实现，突显了 Cloudflare 对现代技术的承诺以及改善开发者体验的决心。

💬 文章金句

  • CT 确保所有网站证书公开可见且可审计，从而帮助网站运营商免受不诚实 CA 错误颁发证书的影响。
  • CT 日志运营的高门槛将运营 CT 日志的组织限制为只有 Cloudflare 和其他五个！丢失一两个日志足以危及 CT 生态系统的稳定性。显然，需要改变。
  • Dogfooding 使我们有机会发现我们产品中的痛点，并向我们的开发团队提供反馈，以改善每个人的开发者体验。
  • 静态 CT API 要求日志仅在条目合并到日志后才使用 SCT 响应，从而消除了运营 CT 日志的一个主要痛点——合并延迟。
