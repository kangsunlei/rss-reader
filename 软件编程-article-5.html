别再用 100vh 了！移动端视口高度的终极解决方案

6/28/2025, 9:48:48 AM

📌 一句话摘要

介绍移动端视口高度的终极解决方案，推荐使用 CSS 动态视口单位(dvh)替代传统的 100vh

📝 详细摘要

文章详细分析了在移动端使用`100vh`导致的问题根源，即移动端浏览器地址栏和底部工具栏的动态变化导致`100vh`计算高度大于实际可见区域高度。作者回顾了传统的 JavaScript 动态计算解决方案的缺点，如性能开销大、逻辑耦合等，并最终推荐使用 CSS 新引入的动态视口单位`svh`、`lvh`和`dvh`，特别是`100dvh`，它能根据浏览器 UI 的变化自动调整高度，完美解决移动端全屏布局问题。新解决方案无需 JavaScript、性能更优且能平滑动态调整。文章还提供了最新的浏览器兼容性数据，显示这些新单位在现代浏览器中已得到良好支持。

💡 主要观点

  1. 移动端 100vh 问题的根源是浏览器 UI 的动态变化 移动端浏览器的地址栏和工具栏会动态收起和展开，导致 100vh 计算高度大于实际可见区域高度，产生滚动条问题，这在欢迎页、弹窗蒙层等实际场景中尤为明显
  2. 传统 JavaScript 解决方案存在性能和维护问题 通过 window.innerHeight 动态计算高度的方法会导致性能开销大、逻辑耦合和时机控制问题，不是理想的解决方案
  3. CSS 动态视口单位是终极解决方案 新引入的 svh、lvh 和 dvh 单位，特别是 dvh，能根据浏览器 UI 变化自动调整高度，无需 JavaScript、性能更优且能平滑动态调整，完美解决移动端全屏布局问题
  4. 不同场景下可选择不同视口单位 svh 适合需要固定高度且不被遮挡的场景，dvh 适合需要动态适应浏览器 UI 变化的场景，开发者可根据具体需求选择
  5. 新单位在现代浏览器中已得到良好支持 截至 2025 年 6 月，所有主流现代浏览器都已支持这些新的动态视口单位，可以放心在生产环境中使用

💬 文章金句

  • 大多数移动端浏览器将`100vh`定义为'最大视口高度'，也就是当地址栏和工具栏完全收起时的高度
  • 使用`100dvh`，当地址栏收起时，元素高度会平滑地增加以填满屏幕；当地址栏滑出时，元素高度又会平滑地减小
  • 动态视口单位无需 JavaScript、性能更优且能平滑动态调整
  • 当需要实现移动端全屏布局时，请大胆地告别`100vh`，拥抱`100dvh`！
