全栈 AI Agent 从 0 到 1 ：智能播客平台开发全记录

8/25/2026, 12:20:00 PM

📌 一句话摘要

本文以智能播客平台开发为例，完整记录了一个基于 Vue 3 + FastAPI + LangGraph 的全栈 AI Agent 应用从框架搭建到多模态音频处理的全过程，覆盖技术选型、架构设计、流式通信与踩坑经验。

📝 详细摘要

文章以作者独立开发的 Smart Podcast Platform 为案例，系统分享了全栈 AI Agent 应用从 0 到 1 的完整开发过程。项目核心能力是用户上传视频或音频后，AI 自动完成内容理解、音色设计、语音合成与专业混音，全程无需人工干预。技术栈涵盖 Vue 3 + TypeScript + Vite 前端、FastAPI 后端、LangChain 1.0 + LangGraph Agent 编排、AG-UI 协议实现前后端流式通信，以及阿里云 DashScope 语音引擎与 pydub 音频处理。文章详细拆解了 LLM 工厂模式、Prompt 动态注入、LangGraph 多轮记忆机制、SSE 流式响应等关键设计，并分享了 LangChain 1.0 API 变化、SSE 缓冲、跨域配置等实战踩坑经验。第二阶段重点介绍了音频混音工具模块，包括音频拼接、智能 BGM 选择与专业混音三个核心工具的实现逻辑，以及音频资源管理 API 与索引系统的设计。

💡 主要观点

  1. 全栈 AI Agent 应用的关键在于打通从内容理解到音频输出的完整链路。 项目通过 LangGraph 编排 Agent，将内容理解、音色设计、语音合成与混音等环节串联，实现端到端自动化，而非停留在生成文字脚本的层面。
  2. LangChain 1.0 的 API 变化巨大，旧版教程代码已无法直接使用。 initialize_agent、AgentExecutor 等旧 API 全部废弃，统一改为 create_agent 方式，作者建议开发者直接查阅官方 1.0 Changelog 而非依赖网络教程。
  3. LLM 工厂模式与 Prompt 动态注入是提升 Agent 可维护性的关键设计。 通过工厂函数统一管理模型实例创建，切换模型只需改环境变量；Prompt 动态注入工具列表描述，避免提示词与代码不一致的问题。
  4. SSE 比 WebSocket 更适合 AI 对话场景，但需注意缓冲问题。 SSE 基于普通 HTTP 连接，轻量且无需额外握手，适合用户发一条、AI 持续回复的场景；但需添加 X-Accel-Buffering: no 响应头避免数据被缓冲。
  5. LangGraph 的 InMemorySaver 按 thread_id 隔离多轮对话记忆，简化前端状态管理。 前端无需维护对话历史或每次发送全量消息，后端自动从 checkpoint 恢复上下文，但作者提示该方案仅适合本地尝试，真实业务需用数据库持久化。

💬 文章金句

  • LangChain 1.0 版本变化大：旧版的 initialize_agent、AgentExecutor 等 API 全部废弃，新版统一用 create_agent，网上大部分教程代码无法直接用，建议直接看官方 1.0 Changelog。
  • SSE 响应被缓冲：后端加了 gzip 压缩中间件后，SSE 数据会被缓冲等凑满再发，导致前端收不到流式效果。解决方式是给 SSE 响应添加 X-Accel-Buffering: no 响应头。
