Claude Opus 4.8 刚上线，我的 Claude Code + DeepSeek 直接跪了...

5/30/2026, 6:12:00 AM

📌 一句话摘要

Claude Opus 4.8 上线后，Claude Code 因协议升级引入 mid-conversation system 消息格式，导致 DeepSeek 等国产模型兼容性崩溃，并意外揭露了部分中转站用国产模型冒充 Claude 的造假行为。

📝 详细摘要

文章以 Claude Opus 4.8 上线为引子，详细分析了 Claude Code 用户在使用 DeepSeek 等国产大模型时遭遇 400 报错的技术原因。核心原因是 Anthropic 为支持 dynamic workflows 新能力，在协议中引入了 mid-conversation system 消息格式，允许在 messages 数组中间插入 role: system 的消息。这一改动破坏了与国产模型的兼容性，因为后者只识别 user 和 assistant 两种角色。文章还揭示了这一事件意外揭露的行业乱象：部分中转站用国产模型冒充 Claude 服务。最后提供了两种解决方案：降级 Claude Code 版本或关闭实验性特性。文章以轻松幽默的笔调，将技术问题、行业观察和产品推广有机结合。

💡 主要观点

  1. Claude Code 升级引入 mid-conversation system 消息格式，导致国产模型兼容性崩溃。 Anthropic 为支持 dynamic workflows 新能力，允许在 messages 数组中间插入 role: system 的消息，但 DeepSeek 等国产模型只识别 user 和 assistant 角色，收到 system 角色后直接返回 400 错误。
  2. 协议升级的核心动机是保护 prompt cache 机制，降低 dynamic workflows 的运行成本。 dynamic workflows 需要 Agent 中途反复插入新指令，如果每次都修改顶层 system 字段，会导致 prompt cache 频繁失效。将新指令追加到 messages 末尾可以保持前缀不变，确保 cache 命中率。
  3. 此次事件意外揭露了部分中转站用国产模型冒充 Claude 的造假行为。 由于只有接第三方模型的 Claude Code 用户才会触发此报错，那些声称提供 Claude 模型的中转站也出现相同错误，说明其背后实际运行的是国产模型。

💬 文章金句

  • Anthropic 这次升级在自家协议里动了个小手脚，第三方模型当场就接不住了。
  • 你买的所谓「Claude」其实是个假的。中转站给你套了一层 Claude 的皮，里头装的是国产大模型。
  • Anthropic 给这种「半路杀出」的 system 块起了个名字，叫 mid-conversation-system。
  • 前缀原封不动，cache 稳稳命中，新指令也照常生效，两边都不耽误。
  • 可惜它建立在「全世界都得跟我用同一套新协议」这个假设上。
