Agoda 的 API Agent 实现零代码、零部署将任意 API 转换为 MCP

2/16/2026, 3:14:00 PM

📌 一句话摘要

Agoda 开源了 API Agent，这是一个通用的 MCP 服务端，通过模式内省和基于 DuckDB 的 SQL 后处理，实现了将 REST 和 GraphQL API 零代码集成到 AI 工作流中。

📝 详细摘要

Agoda 的工程师开发了 “API Agent”，该系统旨在利用模型上下文协议（MCP）弥合内部企业 API 与 AI 助手之间的鸿沟。传统上，团队必须为每个单独的 API 编写自定义 MCP 服务端，这产生了巨大的运营开销。API Agent 通过充当通用网关解决了这一问题，它能够自动内省 API 模式（对 REST 使用 OpenAPI，对 GraphQL 使用原生内省），从而动态地为 LLM 生成工具。其核心亮点是使用 DuckDB 作为内存 SQL 层；这允许系统在将庞大的 API 响应发送给 LLM 之前对其进行过滤和聚合，从而有效地管理上下文窗口限制并防止数据截断。该项目已开源，并通过默认只读的架构强调安全性。

💡 主要观点

  1. 系统实现了通用的 MCP 服务端架构，消除了对自定义编码适配器的需求。 通过使用单个部署并结合配置而非代码来处理多个 API，Agoda 降低了使内部工具可供 AI 智能体和 LLM 访问所需的工程量。
  2. 动态模式内省允许智能体自动将 API 端点映射为 LLM 可读的工具。 智能体获取 REST 的 OpenAPI 规范或执行 GraphQL 内省以理解类型和字段，使其能够根据自然语言构建有效的查询，而无需手动映射或预建适配器。
  3. DuckDB 作为关键的上下文管理层，在 LLM 交互前处理大型数据集。 系统不是将原始的、可能非常庞大的 API 响应发送给 LLM，而是将数据存储在进程内的 DuckDB 实例中，使用 SQL 聚合和过滤结果，以适应上下文窗口限制。
  4. 安全优先的设计确保内部工具免受 AI 智能体的未经授权修改。 API Agent 默认以只读模式运行，任何变更操作（mutation）都需要明确的白名单和配置，从而降低了与内部基础设施上的自主 AI 行为相关的风险。
  5. 基于 SQL 的后处理为 AI 辅助的数据转换提供了一种安全且声明式的方法。 使用 SQL 进行数据操作避免了任意代码执行（沙箱化）的安全风险，同时与现代大语言模型的查询生成能力保持高度兼容。

💬 文章金句

  • API Agent 采用了一种新颖、零投入的方法来实现这种转换，据我们所知，它是同类产品中的首创。
  • 单个部署可以同时为多个 API 提供服务。每个 API 对客户端而言都表现为独立的 MCP 服务端，同时共享同一个实例。
  • 完整的 API 响应在 SQL 中进行存储、过滤和聚合，然后仅将简洁的结果发送给模型。
  • 使用 SQL 进行后处理避免了任意代码执行，并与 LLM 查询生成保持兼容。
  • 该系统的设计旨在减少管理具有不同模式和身份验证方法的多个 API 的运营开销。
