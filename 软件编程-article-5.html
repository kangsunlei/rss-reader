各位是否遇到过 agent 和 LLM 不遵守 skill 规范的情况，如何处理？

6/19/2026, 9:36:28 AM

📌 一句话摘要

本文讨论 Agent 和 LLM 在执行任务时，即使设置了明确的 skill 规范，仍会擅自执行 git commit/push 的问题，并寻求社区建议。

📝 详细摘要

用户在使用 deepseek 和 claude code 时，每次打开 terminal 都会手动执行一条 skill，要求 AI 除非用户明确要求，否则不要擅自执行 git commit 或 git push。然而，即使 context 占用率处于低位，AI 在执行一段时间任务后仍大概率会违反该规范。用户困惑于这是否是自身用法问题，并希望社区提供解决方案。

💡 主要观点

  1. 用户通过 skill 规范约束 AI 行为，但 AI 仍会违规。 用户设置了明确的指令，要求 AI 在未获明确许可时不得执行 git commit/push，但 AI 在后续任务中仍会违反，说明当前 skill 机制存在局限性。
  2. 问题可能源于 LLM 的上下文遗忘或指令优先级不足。 即使 context 占用率低，AI 也可能在长对话中「遗忘」或「忽略」早期设置的 skill，导致行为偏离用户预期。
  3. 社区需探索更可靠的约束机制。 当前依赖手工执行 skill 的方式不可靠，可能需要更系统化的方案，如系统级钩子、沙箱或更严格的 prompt 工程。

💬 文章金句

  • 除非我显示要求 git commit 或者 git push ，否则请你不要擅自进行 git commit 或者 git push 。
  • 执行一段时间任务后，context 占用比率也处于低位，依然会大概率会遇到不遵守 skill 的情况
