烧掉数万亿 Token、数百 Agent 连跑一周：Cursor“从零写浏览器”，结果是拼装人类代码？

1/17/2026, 5:26:00 AM

📌 一句话摘要

Cursor 团队宣称使用数百个 AI Agent 耗时一周“从零”构建了一个浏览器，但经社区复现验证，该项目难以编译通过，且大量使用开源第三方库而非原生实现，引发了对其真实性和营销性质的质疑。

📝 详细摘要

Cursor 公司宣称其使用 GPT-5.2 和多 Agent 系统，在连续运行一周后“从零构建”了一个包含百万行代码的 Web 浏览器，并未依赖现有渲染引擎。然而，该实验结果引发了社区的广泛质疑和“打假”行动。开发者尝试编译项目时发现它构建失败，GitHub Actions CI 也持续失败，并且代码无法稳定运行。深入分析显示，该项目并非“从零开始”，而是大量依赖了 Servo（HTML/CSS 解析器）和 QuickJS 等成熟开源库的 Rust 绑定，以及 wgpu 等旧版本图形库。这表明其更像是对现有组件的拼装，而非完全原创的实现。此外，实验的巨大 Token 消耗和极低的成功率也暴露了 AI Agent 在复杂软件工程项目中的成本和可靠性问题，引发了对此次实验真实性、价值和营销导向的质疑。Cursor 公司对此尚未做出正面回应。

💡 主要观点

  1. Cursor 宣称 AI Agent“从零”构建浏览器，引发业界对 AI 编程能力的关注与质疑。 Cursor CEO 宣称其用数百个 Agent 耗时一周从零构建了 Web 浏览器，包括渲染引擎和 JS 虚拟机，但这一声明因挑战软件工程公认的“地狱级”难度而备受争议。
  2. 社区开发者尝试复现失败，代码无法编译和稳定运行。 多位开发者尝试编译 Cursor 公开在 GitHub 上的浏览器项目时，发现构建失败，CI 持续不通过，无法验证其功能，质疑其仅为营销而非实际可用成果。
  3. “从零构建”实为拼装大量开源代码库，缺乏原创性。 代码分析揭示该项目使用了 Servo 的 HTML/CSS 解析器、QuickJS 的 Rust 绑定及 wgpu/tiny-skia 等成熟库，并非完全原生实现，与“从零开始”的描述不符。
  4. AI Agent 并行协同面临挑战，系统稳定性与成本存疑。 Cursor 承认单 Agent 局限性并引入“规划者-执行者”分工，但其 Excel 克隆实验仍因超预算导致大部分 workflow 失败，暴露出 AI Agent 在复杂大型项目中的成本和可靠性问题。

💬 文章金句

  • 现在，大模型可以独立写完整整一个浏览器了？
  • 这个项目并没有依赖现成的渲染引擎，而是用 Rust 从零实现了一整套渲染引擎，其中包括 HTML 解析、CSS 级联规则、布局计算、文本排版（text shaping）、绘制（paint）流程，甚至还实现了一个自定义的 JavaScript 虚拟机。
  • 即便代码库规模已经很大，新启动的 agent 仍然能够理解它并取得实质性进展；同时，成百上千个 worker 并发运行，向同一个分支推送代码，而且几乎没有冲突。
  • 构建直接失败，报了 32 个错误，代码本身就是坏的；没有任何 release、没有 tag，CI 也在持续失败，我们甚至连这个所谓'可用的浏览器'都没法编译、没法试跑。这更像是一场营销活动，而不是一次真正的 agentic 实验。
  • 剧透：不是。更多网友通过翻看仓库依赖发现，这个项目直接引入了 Servo （一个最初由 Mozilla 开发的基于 Rust 的浏览器）项目的 HTML 与 CSS 解析器（html parser、css parser），以及 QuickJS 的 Rust 绑定（rquickjs），并非所有关键组件都是自行实现。
