我把刘备一生做成了可播放的高德地图，还把整套方法封装成了 Skill

7/19/2026, 11:12:20 AM

📌 一句话摘要

作者分享了如何将刘备一生做成可播放的高德地图，并将其封装为 AI Skill 的完整方法论，核心在于用 Skill 替代网页，实现「交付能力而非结果」的理念。

📝 详细摘要

文章详细记录了作者开发 LifeTrace 项目的全过程：以刘备人生轨迹为案例，探索如何将历史人物的一生在真实高德地图上可视化播放。作者在地图开发经验为零的情况下，借助高德官方 Skill 和 CLI 工具完成技术路线梳理，最终选择 JS API 2.0 实现。项目核心创新在于将网页封装为 Skill，使任何用户只需提供时间、地点和故事，即可由 Agent 自动生成可播放的人生地图。文章还深入讨论了历史地名映射现代坐标的准确性处理、数据可信度分级（confirmed/inferred/disputed/literary），以及「网页交付结果、Skill 交付能力」的产品哲学。

💡 主要观点

  1. Skill 和 CLI 是地图开发新范式：先描述需求，Agent 借助 Skill 理解能力，CLI 快速验证调用方式。 作者在零地图开发经验下，通过高德 Skill 理解需要哪些 API（Marker、Polyline、地理编码等），用 CLI 快速验证坐标和 Key 配置，最终确认 JS API 2.0 是正确选择。这一过程解决了「不知道自己该用哪个接口」的核心痛点。
  2. 网页交付结果，Skill 交付持续生成结果的能力。 如果只做刘备网页，用户换成自己需要手动修改代码、查询经纬度、配置 Key。Skill 则让用户只需提供 CSV 数据和自然语言描述，Agent 自动完成资料整理、地点处理、页面构建和预览。两者本质区别在于可复用性和用户门槛。
  3. 历史人物地图需要可信度分级，不能简单将古代地名映射为现代精确坐标。 古代地名与现代行政区不完全对应，战争区域可能覆盖较大范围，文学典故与正史事件性质不同。项目为每个事件标注 confidence 级别（confirmed/inferred/disputed/literary），地图同时展示信息来源和可信度，而非制造虚假精确感。
  4. 历史路线不能使用现代导航：事件关系线而非导航路径。 直接调用现代驾车路线会沿今天的高速和桥梁生成路径，但历史人物不会沿现代道路行军，且很多行军路线资料不足。LifeTrace 的历史人物模式只绘制「事件关系线」，不生成导航路径。

💬 文章金句

  • 对一个不熟悉地图开发的人来说，真正困难的往往不是写出某一行 API 代码，而是先知道自己应该使用什么能力。
  • 把项目包装成 Skill，本质上是把一次性的开发结果，转化成任何人都能重复调用的能力。
  • 网页交付的是一个结果，Skill 交付的是持续生成结果的能力。
