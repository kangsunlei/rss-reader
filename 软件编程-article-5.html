阿里开源 skill-up：让 Agent Skill 可评测可回归

7/23/2026, 10:18:00 AM

📌 一句话摘要

阿里开源 skill-up 框架，通过声明式 YAML 配置和 expect+judge 分层判定，让 Agent Skill 的评测可验证、可回归、可接入 CI。

📝 详细摘要

文章介绍了阿里巴巴开源的 skill-up 命令行评测框架，专门解决 Agent Skill 难以稳定验证和回归的问题。它采用声明式的 eval.yaml 与 case YAML 描述评测环境、引擎、用例和判定策略；把断言分为本地零成本的 expect 和按需调用模型的 judge 两层，以减少大模型抖动对 CI 的影响；内置多种 Agent 引擎支持，同一份评测集可在不同引擎上回放以检验行为一致性；输出结构化报告（JUnit XML、HTML）并通过退出码反馈结果，可直接作为 CI 步骤和 PR 合并门禁。文中还详细说明了多分轮会话评测、重型端到端评测的设计，并分享了框架在集团内部的落地案例，展示了从手搓脚本到声明式框架的迁移带来的协作与效率提升。

💡 主要观点

  1. 声明式评测配置，环境、引擎、用例全部写在 YAML 中，提升可读性和复用性。 读者打开 eval.yaml 和对应的 case YAML 即可理解用例要做什么以及整体如何判定，无需从脚本控制流中反推评测语义；新增用例通常只需新增一份几十行的 YAML 文件。
  2. expect+judge 分层判定，先进行零成本的确定性检查，再按需调用模型进行语义判断，降低 LLM 抖动对 CI 的影响。 只有 expect 通过后才执行 judge，支持 rule_based、script 或 agent_judge 三种策略；明显的失败在本地阶段被拦截，避免因大模型偶发抖动导致构建被无端阻断。
  3. 多引擎支持与跨引擎回归，同一份评测集可在 claude_code、codex、qodercli、qwen_code 等引擎上运行，帮助验证 Skill 在不同 Agent 上的行为一致性。 通过切换引擎参数即可完成回归测试，框架处理 Skill 安装、CLI 调用与产物收集；取多引擎结果的最大公约数即为该 Skill 真正稳定的行为边界。
  4. 结构化报告与 CI 友好，输出 JUnit XML、HTML 可视化报告及退出码，可直接作为流水线步骤和 PR 合并门禁，降低评测结果查看门槛。 报告与 Anthropic 格式兼容，HTML 报告可通过链接直接访问，评审、验收和争议解决只需共享链接，无需下载制品或解压文件，显著提升团队协作效率。

💬 文章金句

  • 让 Agent Skill 的每一次迭代都可被验证、可被回归
  • skill-up 把断言拆成 expect（本地零成本）+ judge（按需调模型）两层，避免大模型偶发抖动直接阻断构建
  • skill-up 已经在集团内部承接了真实业务 Skill 的评测落地
