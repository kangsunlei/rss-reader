Spring 团队谈 AOT 缓存处理、空值安全性和支持政策

6/5/2025, 7:27:00 AM

📌 一句话摘要

Spring 团队访谈，涵盖 Java AOT 缓存处理、空值安全性 JSpecify 应用及最新支持政策。

📝 详细摘要

文章通过对 Spring 核心成员的访谈，讨论了 Spring 生态系统的几个重要议题。针对 Project Leyden 和 JEP 483 相关的 AOT 缓存，探讨了其最佳实践、分发方式（如容器镜像层）以及与平台（如 Tanzu）的集成。在空值安全性方面，介绍了 JSpecify 标准注解在 Spring 和第三方库中的采用情况、多样的空值类型以及逐步引入空值安全性的方法。最后，详细解读了 Spring 新的统一 LTS 支持政策，包括其与 Spring Boot 版本对齐以及为长期支持版本（如 3.5）提供的更长企业支持期限，旨在简化流程并满足社区对更长支持周期的需求。

💡 主要观点

  1. AOT 缓存可灵活分发，未来平台集成是方向。 Spring Boot 支持通过解包 JAR 或 Buildpacks 分发 AOT 缓存，分析数据应来自生产负载，平台级自动化集成是重要趋势。
  2. JSpecify 定义标准空值注解，可逐步应用于库代码。 JSpecify 提供可空、非空、未指定三种类型，库可在包、类、方法级别逐步采用注解，与现有代码良好兼容。
  3. Spring 采用统一 LTS 政策，提供超 7 年总支持。 新的支持政策与 Spring Boot 版本对齐，最后一个次要版本享受额外企业支持，大幅延长了 LTS 版本的总支持周期。

💬 文章金句

  • AOT 缓存不一定需要包含在容器镜像中，这种集成很可能会发生在平台级别。
  • JSPECIFY 计划为 Java 静态分析提供了标准注解。
  • JSPECIFY 定义了三种空值类型：可空（@Nullable 注解）、非空（@NonNull 注解）和未指定（Java 默认行为）。
  • 我们制定了一个统一的 LTS 政策，而不是像以往那样每个项目各自为政：每个主要版本的最后一个次要版本（如 3.5）在 13 个月的开源支持和一年常规企业支持的基础上，额外获得五年的企业支持。
  • 通过提供更多的支持和简化流程，我们以最可持续的方式满足了社区的需求。
