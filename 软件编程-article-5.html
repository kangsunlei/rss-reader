Qoder CLI 上运行 Qwen3.8-Max：5 个硬核任务实测

8/12/2026, 10:18:00 AM

📌 一句话摘要

本文通过五个长程硬核任务，横向实测 Qwen3.8-Max 与三款外部模型在 Qoder CLI 上的自主执行表现，覆盖三维重建、Rust KV 存储、前端设计、数据分析与叙事动画，给出量化结果与工程洞察。

📝 详细摘要

本文是阿里技术关于 Qwen3.8-Max 在 Qoder CLI 上的长程任务实测。文章设置五个高难度任务：清明上河图三维重建、Rust 高性能 KV 存储、四道前端设计题、OpenAlex 数据分析与《指环王》开篇叙事动画，并引入 Claude Opus 4.8、GPT-5.6 Sol、Claude Fable 5 进行同条件横向对比。四个模型均在单轮提示词后自主完成数小时、数百次工具调用的执行，无一中途失控。结果显示不同任务各有领先者：KV 吞吐上限由 Qwen3.8-Max 领跑，批处理增益是稳定分档指标；OpenAlex 分析中证据可追溯性拉开差距；长程任务真正考验模型在无人规定标准时的自我要求。文章强调所有结果产生于 Qoder CLI 单一 harness，单次运行小分差无排名意义，并开源全部提示词、产物与脚本。

💡 主要观点

  1. Qoder CLI 使四个模型在单轮提示词后自主完成数小时长程任务。 五个任务中所有模型均独立走完数百次工具调用全程，无中途失控，验证了模型与 Agent Harness 组合的自主执行能力。
  2. 吞吐、延迟与过载稳定性呈现不同维度的领先者。 Qwen3.8-Max 极限吞吐领先，Opus 4.8 低负载延迟最低，Fable 5 过载最稳，不存在单一最优方案，单指标选型容易出错。
  3. KV 任务吞吐差距主因是写路径批处理策略。 批处理增益是稳定分档指标，GPT-5.6 Sol 因逐条 write 落后，引入 writev 后明显改善；同机同码的比值可消除跨轮波动。
  4. OpenAlex 分析中证据可追溯性才是真正分水岭。 Qwen3.8-Max 将 PDF 页面嵌入图表、逐页标注论文 ID 与页码，并明确区分样本与总体、统一使用相关而非因果表述，44 项验证全部通过。
  5. 长程任务真正考验模型在空白处如何自我要求。 当无人规定「好」的标准，模型只能依赖自身标准决定完成度；Qwen 为贴近相似度指标损伤画质，正是这种自我取舍的体现。

💬 文章金句

  • 这一代模型+Harness 之间比的，已经不是能不能达到要求，而是在无人要求时，它对自己的要求是什么。
  • 在没有人规定「好」是什么的空白处，模型只能依靠自己的标准决定做到什么程度才算完成。
  • 指标确实上去了，肉眼看到的画质反而变差。
  • 仅凭一项指标选型容易得出错误结论。
