DuckDB 的 WebAssembly 客户端支持在浏览器中查询 Iceberg 数据集

1/4/2026, 1:00:00 PM

📌 一句话摘要

DuckDB-Wasm 现在支持在浏览器中直接、零配置地查询和交互 Apache Iceberg REST Catalog，为 Amazon S3 等对象存储上的数据分析提供了一种无服务器解决方案。

📝 详细摘要

DuckDB 推出了一项新功能，允许用户使用 DuckDB-Wasm 直接在 Web 浏览器中与 Iceberg REST Catalog 进行端到端交互。作为 DuckDB 的 WebAssembly 移植版本，该功能实现了在无服务器、零基础设施设置下对 Iceberg 表的查询、读取和写入。团队重新设计了 HTTP 交互，实现了 JavaScript 网络封装层，并将所有 Iceberg 网络请求路由通过通用接口，以确保原生版本和浏览器版本之间的逻辑一致性。该功能支持与 REST API 交互、处理对象存储上的 Avro 和 Parquet 文件，以及在浏览器内进行身份验证。目前已提供针对 Amazon S3 Tables 的演示可视化工具，用户可以连接自己的 S3 存储桶凭据，所有计算均在浏览器本地运行，确保敏感数据安全。这一进展基于早期对 Apache Iceberg REST Catalog 的支持，并获得了社区的积极反馈，尽管部分用户希望增加对其他云服务商的支持。

💡 主要观点

  1. DuckDB-Wasm 现在支持在浏览器中与 Iceberg REST Catalog 进行直接的端到端交互。 此功能允许用户在无需任何基础设施设置的情况下查询、读取和写入 Iceberg 表，直接在浏览器标签页中运行无服务器分析型数据库。
  2. 该实现涉及对 DuckDB-Wasm 内部 HTTP 交互和网络机制的全面重新设计。 JavaScript 网络封装层和统一接口确保了原生 DuckDB 及其浏览器版本在 REST API 通信、文件处理和身份验证方面执行完全相同的逻辑。
  3. 新功能推动了数据交互的“客户端即服务器”模式。 这种方法提供了对 Iceberg Catalog 的零设置、无基础设施访问，计算在浏览器本地执行，增强了数据隐私和安全性。
  4. 敏感数据和计算保留在用户的浏览器本地。 凭据仅发送到指定的 Catalog 端点，SQL 查询安全地嵌入在 URL 的 hash 段中，确保隐私并防止数据传输到 duckdb.org。

💬 文章金句

  • 因此，我们问自己：我们能否直接在浏览器标签页中支持‘客户端即服务器’模式？这可以为与 Iceberg Catalog 的交互提供一种零设置、无基础设施、真正的无服务器选项。
  • 与 Iceberg REST Catalog 交互需要多项功能：通过 HTTP(S) 与 REST API 通信的能力、在对象存储上读写 Avro 和 Parquet 文件的能力，以及代表用户协商身份验证以访问这些资源的能力。所有这些都必须在浏览器内完成，而不调用任何原生组件。
  • 来自 DuckDB 的一篇非常有趣的博客文章，介绍了如何使用 Duck 构建基于浏览器的应用，并直接操作 S3 Tables 中的 Iceberg 表。表可视化演示（...）针对 S3 中的实时表数据运行——超级酷！
  • 这意味着：没有任何敏感数据被处理或发送到 duckdb.org。计算是本地的，完全在您的浏览器中。您可以使用熟悉的 SQL 接口，以及可以在运行 DuckDB 的任何地方运行的相同代码片段。
