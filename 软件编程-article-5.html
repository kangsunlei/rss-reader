Grab 通过从 Go 迁移到 Rust 降低了 70% 的成本

9/29/2025, 3:30:36 PM

📌 一句话摘要

Grab 成功地将其高吞吐量的计数器服务从 Go 迁移到 Rust，通过显著提高 CPU 效率，实现了 70% 的基础设施成本降低。

📝 详细摘要

本文详细介绍了 Grab 将其核心计数器服务从 Golang 迁移到 Rust 的战略决策。最初，Go 因其开发速度而受到青睐，但 Rust 的内存安全、无垃圾回收以及类似 C 的性能为提高效率提供了机会。该团队为选择服务建立了明确的标准：功能简单、流量大以及工程师愿意学习 Rust。计数器服务对于欺诈检测和机器学习至关重要，由于其高 QPS（每秒查询数）和直接的计数逻辑，非常符合这些标准。此次重写采用了“黑盒”方法，侧重于 GRPC 接口，而不是直接的代码翻译，从而可以实现符合 Rust 编程规范的实现，并仔细选择开源库。关键的技术挑战包括掌握 Rust 的借用检查器和异步并发模型，这与 Go 的 Goroutines 存在显著差异。尽管最初存在障碍，但迁移带来了相似的延迟，但 CPU 效率提高了近五倍，从而使基础设施成本降低了 70%。经验表明，Rust 并不总是比 Go 快。但对于高流量、对成本敏感的服务来说，其效率非常宝贵。

💡 主要观点

  1. Grab 的 Go 到 Rust 迁移策略优先选择简单且流量大的服务，以最大限度地提高影响并最大限度地降低风险。 计数器服务因其高 QPS（每秒查询数）和简单的计数逻辑，成为理想的候选服务，可确保有意义的效率提升并降低重写的复杂性。
  2. 此次迁移采用了“黑盒”重写方法，侧重于 GRPC 接口以实现更地道的 Rust 实现。 该策略使团队能够更好地发挥 Rust 的优势，仔细选择成熟的开源库，并避免直接翻译 Go 代码可能导致的问题。
  3. 克服 Rust 的借用检查器和异步并发模型对于成功实施和性能至关重要。 工程师们通过使用临时解决方法（如数据克隆）并深入了解 Rust 的协作式调度来适应，从而解决了异步上下文中阻塞调用引起的初始性能问题。
  4. 由于 Rust 出色的 CPU 效率，此次迁移使成本降低了 70%，尽管延迟与 Go 相似。 这一结果证明了 Rust 对于高流量、资源密集型服务的重大价值，在这些服务中，效率的提高直接转化为显著的基础设施成本节省，即使原始速度提升不明显。

💬 文章金句

  • Rust 通常因其强大的内存安全性、无垃圾回收以及接近 C 的性能而受到称赞。
  • 为了谨慎地对待这一决定，Grab 工程团队为选择要重写的服务设定了明确的标准。
  • 相反，他们将现有服务视为黑盒。这意味着他们只关注服务 GRPC 接口定义的输入和输出。
  • Rust 的一个关键特性是借用检查器，它严格控制内存访问方式。
  • 这转化为近五倍的效率提升，并且在相同工作负载下，基础设施成本降低了约 70%。
