开放 AI 安全联盟：英伟达携 36 家产业链巨头发布全球倡议

7/28/2026, 10:00:00 AM

📌 一句话摘要

本文报道 NVIDIA 牵头成立开放安全 AI 联盟并发布 NOOA 框架，同时深度剖析了该联盟在治理结构、成员承诺及实际交付物方面的透明度不足与潜在风险。

📝 详细摘要

文章详细记录了 NVIDIA 联合 Microsoft、Cisco 等 36 家企业组建开放安全 AI 联盟（OSAI）的事件，并重点介绍了其首个开源项目 NOOA。作者不仅描述了联盟旨在通过本地部署模型提升 Agent 安全性的初衷，还结合 Hugging Face 安全事故案例，深入探讨了开放模型在应急响应中的实际作用边界。文章核心在于批判性分析：尽管联盟声势浩大，但缺乏公开的章程、理事会、技术工作组及联合路线图，治理结构模糊，且主要贡献者仅为 NVIDIA 单方面维护的单一代码库，行业协作的深度存疑。

💡 主要观点

  1. 联盟发布 NOOA 框架以增强 Agent 的可测试性与审计能力。 NOOA 是一个基于 Apache 2.0 的研究框架，允许开发者使用熟悉的 Python 工作流来测试和追踪 LLM 驱动的 Agent 行为，并在 CyberrGym 基准测试中取得高分，但强调需配合 OS 级沙箱作为遏制边界。
  2. Hugging Face 入侵事件成为联盟倡导本地化防御模型的论据。 文章指出攻击者利用恶意数据集渗透 Hugging Face，后者借助自有基础设施运行的开放权重模型 GLM 5.2 重建了攻击时间线，证明了拥有模型控制权对取证的重要性，但未证明模型本身能独立阻止攻击。
  3. 联盟存在治理不透明与协作深度存疑的问题。 尽管成员众多且包含 OpenAI、Google 等签署过公开信的企业，但联盟缺乏正式的章程、联合治理结构或共享仓库，目前仅体现为 NVIDIA 维护的单方项目，行业实质性协同尚未显现。

💬 文章金句

  • 网络防御者需要能够自行读取、修改并在自有硬件上运行的 AI 模型，而非仅能通过供应商应用程序编程接口（API）访问的封闭系统。
  • NOOA 可配置为执行 LLM 生成的 Python 代码，这可能传输私密数据、删除文件或修改运行环境。其抽象语法树检查和模块拒绝列表被描述为纵深防御控制手段，而非"遏制边界"。
  • 优势在于运营控制权。该事件并未证明模型开放性可以替代身份、隔离或遏制措施。
  • 目前，公开记录显示的是一个联盟、一个政策立场、若干成员承诺，以及一个可识别的、由 NVIDIA 维护的新代码发布------NOOA。联盟的治理结构、联合路线图、首个多成员交付物，以及 NVIDIA 承诺提供的模型、权重和数据集，目前均未公开。
