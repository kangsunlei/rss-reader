React 被指“沦为 Vercel 打工仔”，力推框架只为圈钱？核心成员亲自下场回应却遭群嘲

6/25/2025, 8:30:00 AM

📌 一句话摘要

分析了 React 与 Vercel/Next.js 的关系争议，并探讨 React 团队力推框架的原因及社区担忧。

📝 详细摘要

文章深入探讨了当前 React 社区关于其与 Vercel 及 Next.js 框架关系的争议。Redux Toolkit 创建者 Mark Erikson 认为，“Vercel 主导 React 发展”的观点颠倒了因果，指出 React 核心开发仍在 Meta 主导下进行，Vercel 更多是 RSC 的首个重要合作试验场。他解释了 React 团队之所以强调使用框架，是出于提升应用性能、解决数据获取瀑布效应、简化开发流程和拥抱 RSC 等技术考量。然而，文章也承认 React 生态存在分裂，社区担忧框架带来的额外复杂性、性能问题以及对纯客户端应用需求多样性的忽视。文章引用社区反馈，反映开发者在处理框架特定问题上花费时间增多。

💡 主要观点

  1. Vercel 主导 React 发展的说法颠倒因果 React 核心开发主要由 Meta 团队负责，Vercel 作为重要赞助商和 RSC 试验场，更像是 React 团队主动选择的合作方，而非主导者。
  2. React 团队推崇框架是出于技术和性能考量 强调使用框架旨在通过内置 SSR、优化数据获取、拥抱 RSC 等方式，解决纯客户端应用性能和开发效率问题。
  3. 社区对框架带来的复杂性存在担忧 部分开发者认为框架增加了不必要的学习曲线和特定问题，且并非所有应用都需要全栈或 SSR 能力，纯客户端应用仍有市场。

💬 文章金句

  • Vercel 在主导 React 的发展，目标是通过托管网站赚取更多利润。
  • 我也没有看到证据表明 Vercel 在主导 React 的设计，或者对框架和 RSC 的强调是为了让 Vercel 盈利。
  • 如果现有应用未使用框架，应逐步迁移；如果创建新项目，应从一开始就使用框架。
  • 现实是，2025 年的 React 前景堪忧。尽管经过了三年多的开发和上述 SPA 改进，它仍是最慢的前端框架...
  • React 团队期望框架的使用方式与社区实际使用方式之间的分歧日益扩大。
