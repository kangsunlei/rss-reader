DeepSeek 给大模型划出的「斩杀线」，斩的到底是什么

8/3/2026, 8:26:00 AM

📌 一句话摘要

DeepSeek V4 Flash 以极低价格和强大 Agent 能力，重新定义模型性价比，将中间定价模型挤出默认使用位置。

📝 详细摘要

文章详细阐述了 DeepSeek V4 Flash 模型在单日消耗 8 万亿 Token 的现象，并将其与 OpenRouter 全平台日均 6.6 万亿 Token 进行对比。通过价格对比（DeepSeek 每百万输出 Token 仅 2 元人民币，而 Claude Opus 4.8 为 25 美元），技术分析（MoE 架构、仅激约 130 亿参数、KV Cache 大幅降低、后训练侧重代码与 Agent 能力），以及 Agent 任务导致 Token 消耗指数增长的案例（如 Claude Opus 5 制作 3D 游戏消耗 6.9 亿 Token），解释了为什么低价模型能够在性能仅略低的情况下，通过极高的性价比把更贵的旗舰模型挤出默认调用位置。文中还探讨了本地部署的可能性、模型定价背后的商业考量，以及未来模型竞争将更看重完成率、调用次数和最终账单而非单纯的智能榜单。

💡 主要观点

  1. DeepSeek V4 Flash 以极低价格实现高 Token 吞吐 模型每百万输出 Token 仅收 2 元人民币，而 Claude Opus 4.8 为 25 元，价格相差约 85 倍；在 OpenCode 平台单日消耗 8 万亿 Token，超过 OpenRouter 全平台日均规模。
  2. Agent 任务导致单次任务 Token 消耗呈指数级增长 Agent 会反复读文件、修改代码、运行程序、检查结果，一次任务可能持续数小时并调用数十次工具；例如 Claude Opus 5 制作单页 3D 游戏消耗 6.9 亿 Token，费用近 3000 元。
  3. 技术架构与后训练使模型在保持参数规模的同时大幅降低激活成本 V4 Flash 总参数 2840 亿，但每 Token 仅激活约 130 亿；采用混合注意力结构、低精度权重、KV Cache 优化及 CSA/HCA 机制；后训练重点强化代码和 Agent 能力，未增加新参数却显著降低失败率。
  4. 低价模型形成斩杀线，迫使昂贵模型证明微小性能提升的价值 当便宜 50‑80 倍的模型已能完成大多数编码和 Agent 任务，昂贵旗舰模型必须证明剩余几分能力是否值得付几十倍的价格；中间定价模型因而被挤出默认使用位置。

💬 文章金句

  • 模型写出的代码未必比过去多很多，消耗的 Token 却可能翻上几十倍、几百倍。
  • 换句话说，Opus 多拿了 6 分，但跑完同一套评测的调用费高出了约 52 倍。
  • 当一个便宜 50 倍甚至 80 倍的模型，已经能够完成大多数编码和 Agent 任务，昂贵模型就必须反过来证明：剩下那几分能力，究竟值不值得多付几十倍的钱。
  • DeepSeek 几乎是以免费的价格提供大模型
