#536. 五种多智能体架构类型

5/13/2026, 10:56:22 AM

📌 一句话摘要

Factory 核心 Agent 框架负责人 Luke Alvoeiro 深度解析五种多 Agent 通信模式与 Missions 系统，揭示软件工程瓶颈从智能转向人类注意力，并通过三角色架构与验证合约实现长周期自主开发。

📝 详细摘要

本期播客克隆自 Factory 播客，嘉宾 Luke Alvoeiro（Goose 创始成员、Factory 核心 Agent 框架负责人）系统讲解了五种多 Agent 通信模式（委派、创作者-验证者、直接通信、协商、广播），以及如何将这些模式组合到 Missions 系统中实现长周期自主软件开发。他提出软件工程的核心瓶颈已从模型智能转向人的注意力——模型已足够完成数十个任务，但人类缺乏监督带宽。Missions 系统采用三角色架构（编排者负责规划、工作者负责实现、验证者负责检测），通过验证合约在编码前定义正确性，采用串行执行规避并行冲突，并通过模型无关架构确保每次模型升级系统自动获益。实际案例显示克隆 Slack 项目测试占比达 50%、代码覆盖 90% 以上，最长任务持续 16 天超过敏捷冲刺。

💡 主要观点

  1. 软件工程瓶颈从模型智能转向人类注意力 当前模型已足够聪明完成数十个任务，但工程师无法同时监督所有实现，Missions 系统通过结构化协作解放人类注意力，让工程师聚焦架构与产品决策。
  2. 五种多 Agent 通信模式构成基础构建块 委派模式、创作者-验证者模式、直接通信、协商和广播五种模式可灵活组合，创作者-验证者通过关注点分离避免沉没成本偏见，广播用于维持长任务一致性。
  3. 验证合约在编码前定义正确性实现防偏离 在规划阶段写入成百上千条独立于实现的断言，使用对抗性验证涉及代码审查和端到端用户测试，从根本上防止系统跑偏，区别于传统事后补测试的做法。
  4. 串行执行配合针对性并行实现长周期高正确性 在任务层面串行执行功能避免 Agent 冲突和重复工，在只读操作内部并行化加速搜索和审查，错误率骤降的同时最长任务可达 16 天超过完整敏捷冲刺。
  5. 模型无关架构让系统随模型升级自动获益 编排逻辑写在提示词和技能中而非硬编码状态机，每个角色选择最适合的模型（编排用慢速推理、实现用快速代码流畅度、验证用精准指令遵循），架构随每一次模型升级而增强。

💬 文章金句

  • 现在软件工程的瓶颈不是智能，而是受限于人的注意力。哪怕最优秀的工程师，一次也只能同时推进几个任务。
  • 验证合约在规划阶段就写好了，早于任何代码，它用与实现无关的方式定义正确性。对于复杂项目，这可能是成百上千个断言。
  • 我们跑过最长的任务持续了 16 天，这比一个完整的敏捷冲刺还要长很多。
  • 规划受益于慢速仔细的推理，实现受益于快速的代码流畅度和创造力，没有哪个单一模型或模型提供商能在所有方面都做到最好。
  • 几乎所有的编排逻辑都定义在提示词和技能里，而不是硬编码的状态机。这个系统必须做到每一次模型升级它都能跟着变得更好。
