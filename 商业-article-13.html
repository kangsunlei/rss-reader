算力革命与云厂商三重进化：Agent 云的架构升级与“度量衡革命”

7/22/2026, 7:46:00 AM

📌 一句话摘要

文章梳理了 AI Agent 时代云产业从互联网云到 GPU 云再到 Agent 云的三重演进，并解析了全栈 AI 云架构及价值评估的转变。

📝 详细摘要

文章追溯了云计算从互联网时代的 IaaS/PaaS/SaaS 到 GPU 云阶段的演变，指出随着大模型和 Agent 的兴起，云产业正进入 Agent 云阶段。文章详细阐述了 Agent 对云基础设施的新需求——不仅需要 GPU 算力，还需要 CPU、HBM、光互联等协同，以及 Agent Harness 这一提供工具调用、长期记忆、沙箱和安全的运行环境。接着描述了云厂商如何围绕 AI Infra、Agent Infra 和智能体应用构建“AI 原生云”或“Agent 原生云”的全栈架构，以支撑企业级 Agent 的落地。文中还提到 NeoCloud 的崛起以及中国超大云厂商通过 AI 原生云演进的路径，并指出价值评估正从算力投入转向智能产出，百度提出的 DAA（日活智能体数）成为新的衡量标准。整体内容兼具技术深度与产业洞察，适合关注 AI 基础设施与云计算趋势的读者。

💡 主要观点

  1. 云产业经历互联网云→GPU 云→Agent 云三次架构演进，核心围绕 AI 模型训练、推理及智能体运行需求重构基础设施。 文章指出，随着大模型和 Agent 的兴起，云不仅要提供 GPU 算力，还需 CPU、HBM、光互联等协同，以支持复杂的 Agent 任务执行。
  2. Agent 时代要求云提供完整的 Agent 运行环境（Agent Harness），包括工具调用、长期记忆、沙箱与安全，木桶效应决定系统整体能力。 文章引用郑然的观点，强调 Agent 需要稳定的执行环境，任何环节的短板都会导致任务执行效果下降。
  3. 云厂商正构建 AI Infra + Agent Infra + 智能体应用的全栈架构，以实现 AI 原生云或 Agent 原生云，支撑企业级 Agent 落地。 以百度智能云的“芯、云、模、体”四层布局为例，说明从芯片到智能体的协同优化是实现全栈 AI 云的关键。
  4. NeoCloud 公司快速崛起，而中国主要通过超大云厂商向 AI 原生云演进，实现算力、模型与智能体的协同。 文章对比美国 NeoCloud 的独立崛起与中国超大云厂商在现有平台基础上直接完成 AI 升级的不同路径。
  5. 价值评估从算力投入转向智能产出，百度提出 DAA（日活智能体数）作为衡量 AI 云价值的新指标。 DAO 强调关注 Agent 的实际产出而非仅 token 消耗，反映 AI 云竞争重点从效率向价值转移。

💬 文章金句

  • 原来的 Chatbot，用户的诉求，或者说用户对它的预期，有点像搜索一样：你提交一个问题，它需要很快速地回应。而在 Agent 时代，核心目标不是快速地完成任务，而是高质量地完成任务，这会是完全不一样的预期。
  • 为了完成任务，还需要给 Harness 一个执行的环境。它需要存储一些临时文件，需要调用工具，比如下载一些网页，需要用 Skill，需要调用 MCP。这些都需要一个环境，同时有工具、有记忆，再加上安全，帮助 Agent 的任务具备隔离性和稳定性。所以这背后，就对整个工程层面提出了完全不一样的要求。
  • 我们希望能够四层布局、全栈布局，消除任何一层的短板，最终服务好企业 Agent 的落地和 AI 转型的整个过程。
  • 百度智能云不是一个单点能力的堆叠，我们选择的是一条工程化、系统化的路线。
  • 我们整个具身智能体和互联网智能体，实际上是有一定 overlap（重叠）的。比如 FaceID 相关的一些功能，包括记忆的功能，百度智能云已经具备了非常完善的面向互联网服务的能力，这个时候我们没有必要重复造轮子、重复开发。
