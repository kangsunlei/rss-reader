怎么用上一夜爆火的 Clawdbot，详细配置教程

1/27/2026, 8:41:00 AM

📌 一句话摘要

本文详细介绍了开源 AI 助手 Clawdbot 的核心功能、架构原理，并提供了手把手式的云服务器部署教程及常见坑点解决方案。

📝 详细摘要

文章聚焦于近期在 GitHub 爆火的开源项目 Clawdbot，这是一款支持多端部署、7*24 小时在线的个人主动式 AI 助手。其核心优势在于能通过 Telegram、iMessage 等通讯软件进行交互，并具备操作本地文件和浏览器的能力。作者详细阐述了为何推荐使用云服务器（VPS）而非 Mac mini 进行部署，并提供了从购买服务器、创建 Telegram 机器人、获取 API Key 到安装配置、启动服务的完整 8 步教学。此外，文章还特别总结了第三方 API 配置、缓存清理及服务持久化（Linger）等实战中极易遇到的技术坑点，并展示了其在选题抓取、文档整理等场景下的实测效果。

💡 主要观点

  1. Clawdbot 的核心价值在于将 AI 助手集成进主流通讯软件。 不同于传统的浏览器对话框，它支持通过 Telegram、iMessage 等平台交互，让用户像给朋友发消息一样指挥 AI 完成任务，实现了真正的随时随地调用。
  2. 采用云服务器部署是实现 7*24 小时主动式服务的最佳方案。 相比本地电脑，云服务器能保证设备永不关机，且能有效隔离本地文件权限风险，同时在成本和稳定性上具有明显优势。
  3. 部署过程中的环境持久化与缓存管理是运行成功的关键。 必须启用 Linger 模式以确保 SSH 断开后服务不被杀死，且在修改配置后需手动清理 session 缓存，否则会导致新配置无法生效或服务循环重启。

💬 文章金句

  • Clawdbot 是一个个人 AI 助手，完全本地化、7*24 小时不停歇干活的 Claude。
  • 它成了一个主动式助手（Proactive AI），区别于被动的聊天机器人。
  • 为了保护你本地的文件，还是不要部署在自己的笔记本电脑上。
  • Clawdbot 会缓存会话状态，包括模型配置、API 连接等。不清缓存，它继续用旧的。
  • Claude Code 能干的事它基本都能干，区别只是你在手机上发消息它在服务器上执行。
