撞名 Anthropic 的“外挂”刷屏：让“DeepSeek V4‑Pro 碾压 Fable 5”但无人能复现，Token 开销反而翻倍

8/19/2026, 6:33:00 AM

📌 一句话摘要

本文梳理 J-Space Cognition Suite 项目传播事件，指出其性能提升数据缺乏独立复现，澄清与 Anthropic J-space 研究无关，并延伸至 Agent Harness 在长任务状态管理、过早停止与 Token 成本等方面的行业共性挑战。

📝 详细摘要

文章围绕 X 平台快速传播的 J-Space Cognition Suite 项目展开分析。该项目声称不改 DeepSeek V4-Pro 权重，仅通过推理时 Harness 即可显著提升 Agent Benchmark 表现，甚至超过 Fable 5，但截至 8 月 18 日尚无第三方独立复现。文章明确区分了该项目与 Anthropic 的 J-space 可解释性研究，指出两者技术对象与用途完全不同。随后，文章将讨论延伸至 Agent Harness 领域的共性问题：长任务状态管理、过早停止、Compaction 风险、权限边界等，并引用 LongHorizon-Harness 与 StateM 研究说明行业正在补课。最后对比了通用 Harness（如 OpenCode）与模型原生 Harness（如 DeepSeek DSH、OpenAI Agents SDK）的分化趋势。

💡 主要观点

  1. J-Space Cognition Suite 的性能提升数据缺乏独立复现，仍属项目方主张。 ExplainX 梳理显示，Terminal-Bench、NL2Repo 等基准的提升数据均来自项目方自测，尚无独立团队在相同条件下复现。开发者实测反馈 Token 消耗反而翻倍，未观察到声称的性能提升。
  2. 此 J-Space 与 Anthropic J-space 研究无关，命名造成误解。 Anthropic 的 J-space 是 2026 年 7 月发布的 Claude 内部神经表征可解释性研究，而 J-Space Cognition Suite 是运行在 DeepSeek V4 Pro 外部的 Agent Harness，两者技术对象与用途完全不同。
  3. Agent Harness 正进入补短板阶段，长任务状态管理是核心难题。 现有 Harness 将任务执行、状态和完成判断放在持续膨胀的上下文中，导致遗忘、偏离与过早停止。J-Space 引入外部持久化设计，但 Compaction 可能丢失权限约束，状态外置并未彻底解决问题。
  4. 通用 Harness 与模型原生 Harness 正在分化。 OpenCode 等通用方案通过多 Subagent 分工与权限体系实现兼容，但权限管理复杂；DeepSeek DSH、OpenAI Agents SDK 则围绕自身模型特性设计原生 Harness，在隔离性、持久性与扩展性上更深入。

💬 文章金句

  • 真正重要的问题发生在改造后：目前这些提升后的数字全部来自项目方自己运行的 Benchmark，尚未发现独立团队按照相同模型、Prompt、Harness、工具权限和推理预算重新跑出类似结果。
  • 上下文不压缩，Agent 会越来越臃肿；压缩以后，又可能丢失任务目标、状态甚至权限边界。
  • 让模型适配 Harness，还是让 Harness 适配模型？目前并没有标准答案。
