时间设置 23:59:59，数据库存的却是第二天 00:00:00，什么情况？！

11/2/2025, 12:02:00 AM

📌 一句话摘要

文章详细分析了 Java 日期时间精度与数据库 TIMESTAMP 字段不匹配，导致时间存储偏差 1 秒的常见问题及解决方案。

📝 详细摘要

文章深入分析了 Java 应用中，将`LocalDateTime`转换为`java.util.Date`并存入 PostgreSQL 数据库的`TIMESTAMP`类型时，因精度不匹配导致部分时间数据自动进位到下一天 00:00:00 的问题。作者通过详细的排查过程，包括代码复查、AI 咨询及批量数据测试，最终定位到`java.util.Date`的毫秒精度与数据库`TIMESTAMP`默认的秒精度之间存在的四舍五入机制。文章提供了两种解决方案：在 Java 代码中清空纳秒部分（`withNano(0)`），或调整数据库`TIMESTAMP`字段的精度。同时，文章还扩展对比了`java.util.Date`与`LocalDateTime`、MySQL `DATETIME`与`TIMESTAMP`的特性及适用场景，为开发者提供了全面的时间处理实践指导。

💡 主要观点

  1. Java `Date`毫秒精度与数据库`TIMESTAMP`秒精度不匹配是时间存储偏差的根本原因 当 Java `Date`的毫秒部分大于等于 500 时，在存入默认秒级精度的`TIMESTAMP`字段时会被四舍五入进位，导致时间增加 1 秒。
  2. 解决时间精度不一致问题可从代码端或数据库端双向入手 可以在 Java 代码中清空纳秒部分（`withNano(0)`），或调整数据库`TIMESTAMP`字段精度至毫秒级，确保两者精度匹配。
  3. 深入理解 Java 和数据库时间类型特性是避免类似问题的关键 文章对比了`Date`与`LocalDateTime`、`DATETIME`与`TIMESTAMP`的优劣和适用场景，强调了时区、可变性、精度等因素在选型中的重要性。
