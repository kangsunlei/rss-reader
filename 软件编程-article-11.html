Claude Code 创始人 Boris Cherny 建议开发者定期清空 CLAUDE.md 等旧规则，让新模型自主发挥，并强调验证闭环与长任务拆解的重要性。

📝 详细摘要

本文翻译整理了 Claude Code 创始人 Boris Cherny 的访谈核心观点。面对模型快速迭代，Boris 提出一个反直觉的建议：每隔 6 个月清空 CLAUDE.md、Skills 和 Hooks，让新模型在无旧规则约束下重新测试，仅保留模型反复出错时才需补充的规则。文章详细阐述了 Claude Code 团队删除 80%系统提示词后的实践效果，指出过多旧指令会挤占上下文并限制模型能力。此外，文章重点讨论了 Agent 开发的三大原则：验收方法比 Prompt 长度更重要（如用截图逐像素比对验证 UI 迁移）、长任务需拆解为多轮 Agent 接力（如 15 天的桌面端重写任务）、应从低风险维护任务（如死代码清理）开始引入自动化。最后，Boris 强调编码虽已接近解决，但架构取舍与系统理解仍是人类开发者的核心壁垒。

💡 主要观点

  1. 定期清空旧规则释放新模型潜力 Boris 建议每 6 个月清空 CLAUDE.md 等配置，避免旧指令挤占上下文，让新模型在无约束下测试表现，仅保留反复出错的规则。
  2. 验证闭环是 Agent 任务的核心 Prompt 只需明确目标与边界，必须提供可自动判断结果的验收方法（如测试套件、截图比对），否则模型无法知道何时完成任务。
  3. 长任务需拆解为多轮 Agent 接力 15 天的桌面端重写任务并非单轮 Prompt，而是分阶段执行，不同 Agent 负责修改、检查与进度管理，人类在关键节点确认方向。
  4. 从低风险任务引入自动化 团队先让 Agent 处理死代码清理、测试补全等可回滚的日常维护，生成待审核 PR 后再由人工决定合并，逐步建立信任。
  5. 编码解决后人类价值转向系统理解 Boris 指出代码生成已接近解决，但架构取舍、业务判断与系统理解仍是人类开发者的核心壁垒，需培养设计与沟通能力。
