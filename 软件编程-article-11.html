Cloudflare Wallets 迟来入局 x402：支出控制仅能约束单笔支付

9/10/2026, 11:08:00 AM

📌 一句话摘要

Cloudflare 推出面向 AI 智能体的 Wallets 钱包与 cloudflare.pay 标识，复用 x402 协议实现机器原生小额支付，但其支出控制仅提供额度上限、商户白名单和单笔限额三项原语，无法表达多笔支付间的策略关系，并发扣减逻辑也未公开。

📝 详细摘要

文章报道 Cloudflare 在智能体周发布 Cloudflare Wallets，为 AI 智能体提供稳定币余额和 cloudflare.pay 标识，用于向 API、数据和内容服务付费。目前仅标识认领功能可用，充值与支付将在未来几个月推出，且已出现品牌名被抢注的投诉。支付基于 x402 协议实现，该协议复用 HTTP 402 状态码，由 Coinbase 发起、现由 Linux 基金会托管，成员包括 Cloudflare、Stripe、Visa、Mastercard、Google 和 AWS。作者认为基金会托管解决了协议归属问题，但未解决市场竞争，Cloudflare 入局较晚，优势在于分发能力——Wallets 与其 7 月推出的变现网关构成买卖两端。文章重点剖析其管控模型：主账户钱包加每个智能体的虚拟钱包，受额度上限、商户白名单、单笔交易最大金额三项规则约束。作者指出这些原语只是预算额度而非策略语言，无法表达交易间关系（如官方目录核验、同一服务限购、新商户首单审批），并发场景下多笔支付同时校验额度可能导致总额超预算，而 Cloudflare 尚未公开该实现逻辑。

💡 主要观点

  1. Cloudflare Wallets 目前仅开放标识认领，充值与支付功能尚未上线，且已引发品牌名抢注投诉 Hacker News 评论者 merek 发现公司名称及多个变体被他人抢占注册，且有人冒用其品牌搭建网站误导客户；评论者 nikolay 将其与 Meta 预留用户名的做法对比，认为 Cloudflare 缺少域名验证和公平注册机制。
  2. x402 协议由 Coinbase 发起并移交 Linux 基金会托管，解决了协议归属问题，但没有解决市场竞争问题 x402 复用 HTTP 402 状态码，约 40 个成员包括 Cloudflare、Stripe、Visa、Mastercard、Google 和 AWS。作者类比 MCP 移交智能体 AI 基金会，认为当协议要求所有竞争对手实现时，交由基金会治理比独自掌控更有价值。
  3. Cloudflare 的竞争优势在于分发能力，Wallets 与其变现网关构成智能体支付的买卖两端 变现网关允许网站与 API 基于同一协议体系向智能体按请求收费，Wallets 则是买方配套产品。同时持有两端意味着商家可向智能体收费、智能体也可向商家付款，覆盖 337 个城市、约五分之一网站的网络。
  4. 当前支出控制只是预算额度而非策略语言，无法表达多笔支付之间的关系 额度上限是累计消耗总额、商户白名单只校验是否在允许集合内、单笔上限只约束单次请求，三者都只将当前支付与固定阈值比对。平台团队真正需要的规则（官方目录核验、同一服务限购、新商户首单审批）需要对交易时序序列做逻辑判断。
  5. 并发执行下额度校验存在超预算风险，Cloudflare 尚未公开具体实现逻辑 智能体并行发起操作时，多笔支付可能同时校验额度且均未扣减余额，单笔都未触顶但总额超出预算。在放开智能体免逐笔审批交易之前，这一点必须明确。该问题并非 Cloudflare 独有，领域内服务商普遍只提供限额能力而非完整策略语言。

💬 文章金句

  • 这些原语描述的是预算额度而非策略。
  • 以上三者都只是将当前这笔支付和固定阈值做比对，无法表达多笔支付之间的关系。
  • x402 是一个可用的通道，由谁来治理这个协议的问题已经得到解决，但智能体在多笔支付中可以花费多少的问题尚未得到解决。
  • 该领域的各类服务商，推出的都只是限额管控能力而非完整的策略语言，并且把这些限制条件的组合逻辑全部丢给上层应用。
