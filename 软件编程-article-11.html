支撑亿级流量：小红书 2025 MySQL 内核做了哪些关键改造？

📌 一句话摘要

小红书自研 MySQL 内核 RedSQL 通过合并秒杀、Binlog Server 一致性方案及秒级加列等关键改造，成功支撑亿级流量并实现核心业务 RPO=0。

📝 详细摘要

本文深入解析了小红书自研 MySQL 内核 RedSQL 在支撑亿级流量过程中的核心技术演进。针对高并发秒杀、数据一致性诉求及大表 DDL 耗时等痛点，RedSQL 实现了三大突破：首先，通过“合并秒杀”优化事务与锁系统，将热点更新性能提升至 1.5W+ TPS，且对业务透明；其次，利用自研 Binlog Server 配合 ORC 组件，实现 300MB/s+ 高速复制与全自动补数，达成 RPO=0；最后，采用元数据与物理存储解耦技术实现秒级加列，将大表变更周期从周级缩短至秒级。此外，文章还介绍了精准限流、SQL 语法扩展及 Buffer Pool 并行加载等稳定性优化手段。

💡 主要观点

  1. 合并秒杀方案通过修改事务模型，将多个 SQL 事务合并提交以突破热点行更新瓶颈。 该方案对执行器、锁系统及日志提交进行深度优化，实现了秒杀线程并行执行，性能较排队秒杀提升 5 倍，且保持了对业务 SQL 和生态组件的完全透明。
  2. 自研 Binlog Server 结合 ORC 高可用组件，构建了 RPO=0 的数据一致性保障体系。 通过轻量化资源实现 300MB/s+ 的高速复制，并设计了自动补数机制，确保主备切换过程中数据零丢失，将传统人工干预的分钟级 RPO 缩短至零。
  3. 秒级加列技术通过元数据与物理存储解耦，规避了传统 DDL 繁重的数据搬迁过程。 RedSQL 通过修改数据字典记录列版本链，利用 Header 标志位区分新旧数据行，使大表加列操作仅需原子化更新元数据，将变更耗时从天级缩短至秒级。
  4. 通过 SQL 语法扩展和 Buffer Pool 并行加载等细节优化，进一步压榨内核性能。 支持 SELECT FROM UPDATE 语法减少网络交互使 TPS 提升 20%，同时将 Buffer Pool 加载速度提升 3.3 倍，有效解决了实例重启后的预热延迟问题。

💬 文章金句

  • 底层内核优化杠杆效应更强、价值更大。
  • 合并秒杀方案相对排队秒杀方案，将秒杀写入能力再提升 5 倍，相对 MySQL 开源社区版本更有百倍的性能提升。
  • 在主备切换过程中，以数据一致性优先为原则设计自动补数机制，最终实现全流程自动化的一致性解决方案。
  • 秒级加列的核心挑战，是元数据与物理存储解耦：需原子化更新元数据且不改动原数据存储。
  • 数据库内存（Buffer Pool）加载速度从 300MB/s 提升至 1GB/s，提升 3.3 倍。
