Cloudflare：Rust 赋能，速度与安全双重提升

9/26/2025, 2:00:00 PM

📌 一句话摘要

Cloudflare 通过 Rust 和 Oxy 框架升级核心网络系统 FL1 到 FL2，性能提升 25%，安全增强，加速产品开发。

📝 详细摘要

Cloudflare 对其核心网络处理系统 FL 进行了重大架构调整，从原有的 FL1（NGINX、OpenResty、LuaJIT）迁移到使用 Rust 和内部 Oxy 框架构建的 FL2。此次迁移是由于 FL1 维护日益复杂、处理速度滞缓以及集成困难所驱动。此次升级带来了 25% 的性能提升（中值响应时间减少 10 毫秒），得益于 Rust 的内存安全特性，安全性得到增强，并将产品开发速度从几周缩短到 48 小时。此次过渡涉及细致的分阶段推广：将 Rust 模块集成到 FL1 中，使用回退进行广泛的自动化测试，以及逐步监控的客户入驻。与 FL1 相比，FL2 严格的模块化设计和 Rust 的性能也显著降低了 50% 以上的 CPU 和内存消耗。

💡 主要观点

  1. Cloudflare 将其遗留的 FL1 系统 (NGINX/LuaJIT) 迁移到 FL2 (Rust / Oxy)，以克服在维护、性能和产品集成方面的严重限制。 最初的 FL1 系统在 15 年后，由于日益增长的复杂性、缓慢的处理速度以及扩展新功能的困难，成为了瓶颈，因此需要用 Rust 完全重写。
  2. FL2 迁移带来了 25% 的性能提升和增强的安全性，这得益于 Rust 的强大功能。 转向 Rust 和 Oxy 框架后，中值响应时间减少了 10 毫秒，并通过 Rust 的编译时内存安全和类型系统提高了安全性。
  3. FL2 严格的模块化架构大大加快了产品开发并优化了资源使用。 严格的模块定义和选择性执行允许在 48 小时内交付新功能，比 FL1 中的几周快得多，并减少了 50% 以上的 CPU / 内存消耗。
  4. Oxy 框架提供了诸如优雅重启和灵活的流量处理等关键功能，从而确保了高可用性和适应性。 Oxy 的内置机制可防止更新期间的连接断开，并允许全面的流量操作 (L3-L7)，这对于在 Cloudflare 的规模上保持服务可靠性至关重要。
  5. 一种细致的、多阶段的迁移策略，包括回退和自动化测试，确保了平稳可靠的过渡。 分阶段推广包括将 Rust 模块集成到 FL1 中，进行广泛的自动化端到端测试 (Flamingo) 以及回退到 FL1 的机制，从而最大程度地减少了客户影响，并在整个过程中验证了正确性。

💬 文章金句

  • Rust 严格的编译时保证与 FL2 的模块化架构相得益彰。在这一架构中，我们对产品模块及其输入输出实施明确的约定。
  • Oxy 包含内置的优雅重启机制，使我们能够在尽可能不中断连接的情况下发布新版本。
  • 这样做的好处是，我们可以立即知道哪些其他产品可能会相互影响。
  • 结果，我们的内部测量表明，FL2 使用的 CPU 不到 FL1 的一半，并且内存远小于一半。
