【第 3509 期】Mobile Bridge：让 WebView 拥有原生体验

5/15/2025, 12:01:00 AM

📌 一句话摘要

Shopify 通过 Mobile Bridge 框架优化 WebView，大幅提升性能、外观和集成性，实现接近原生的混合应用体验，尤其适用于重要但非关键的界面。

📝 详细摘要

文章详细介绍了 Shopify 如何利用自研的 Mobile Bridge 框架，解决在移动应用中高效集成**重要但非关键**界面的挑战，克服传统 WebView 在性能、外观和集成性方面的不足。为解决加载缓慢问题，文章提出在后台预加载 WebView 并缓存复用，将加载时间缩短约 6 倍。外观方面，通过注入 JS/CSS 禁用缩放和文本选择，并调整组件样式使其与原生统一。集成方面，Mobile Bridge 基于 RPC 实现了 Web 与原生端的双向通信，解决了页面标题、操作按钮在原生导航栏的渲染问题，并创新性地通过 TransportableView 组件实现了 WebView 实例在不同屏幕间的移动，解决导航时状态丢失问题。针对返回导航，采用快照技术保证平滑过渡。此外，Mobile Bridge 还实现了原生功能的无缝调用（如日期选择器、条码扫描）。文章最后探讨了利用 remote-dom 技术进一步在原生端渲染 Web 组件的未来方向。Mobile Bridge 已成为 Shopify 关键的移动开发工具，显著提升了混合应用的体验和开发效率，并已开源。

💡 主要观点

  1. 通过后台预加载和缓存复用 WebView，显著提升加载性能。 传统 WebView 加载慢主要是认证流程耗时，在应用启动时后台完成认证并缓存，避免重复等待，大幅缩短了加载时间。
  2. 通过 CSS/JS 注入和样式覆盖，使 WebView 外观更接近原生应用。 禁用页面缩放和文本选择，隐藏不必要的 Web 元素，并调整 UI 组件样式，消除 WebView 与原生界面视觉上的差异感。
  3. Mobile Bridge 通过 RPC 实现 Web 与原生端的双向通信。 建立稳定的通信通道，使得 Web 内容可以控制原生导航栏的标题和操作，调用原生功能，并实现数据共享和事件追踪。
  4. 创新性地使用 TransportableView 组件解决 WebView 导航状态丢失问题。 允许 WebView 实例在页面间转移而非重新创建，保留会话状态和动态内容，提供流畅的原生式导航体验。
  5. 通过快照技术优化返回导航体验。 在 WebView 移动前拍摄当前界面快照，返回时先展示静态图，待 WebView 加载完毕再移除，避免出现空白或损坏界面。
  6. Mobile Bridge 成为 Shopify 重要的移动开发战略工具，平衡了开发效率与用户体验。 作为高效集成重要但非关键界面的解决方案，Mobile Bridge 使得 Shopify 能在保留 Web 开发灵活性的同时，提供接近原生的体验，释放资源专注于关键原生界面的开发。

💬 文章金句

  • 我们需要一种高效的方式，把这些 "非关键" 界面集成到移动应用中，而不需要再为 Web 和移动端分别开发。
  • 我们将 WebView 的加载时间提升了大约 6 倍 ------ P75（75% 用户体验到的加载时间）从 6 秒缩短到 1.4 秒。
  • 想要让 WebView 真正 "用起来像原生应用"，关键是要实现 Web 与移动端之间的简单通信。
  • TransportableView 可以让我们在屏幕之间 "移动" 现有的 WebView，而不丢失任何状态或数据。
  • Mobile Bridge 彻底改变了我们对 Web 与移动集成方式的看法 ------ 它让我们可以拥有 Web 开发的灵活性与速度，同时为用户提供接近原生的流畅体验。
