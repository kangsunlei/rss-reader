做了个免费追剧资源导航，每天自动检测资源是否还活着，开源的，求反馈

📌 一句话摘要

本文介绍了一个开源的免费追剧资源导航项目，其核心特色是通过 GitHub Actions 每日自动检测链接可用性，并公开标注结果。

📝 详细摘要

作者因频繁遇到追剧资源站失效的痛点，开发并开源了一个名为 awesome-zhuiju-free 的导航项目。该项目收录了在线影视、APP、网盘搜索、磁力、字幕等 62 个资源，核心功能是利用 GitHub Actions 每日自动检测所有链接的可访问性，并在 README 中将失效链接标红、受限链接标黄。项目设计上强调数据透明（所有资源在 JSON 文件中）、多维度的资源评分（多/快/净/稳/易）与风险标注（版权/安全等），并提供了简化的 Issue 模板方便非技术用户提交新资源。项目上线一周多已获得 1000+ Star，作者在文末向社区征求关于收录类型、信息呈现和共同维护的反馈。

💡 主要观点

  1. 核心价值在于用自动化检测解决了资源站频繁失效的信息滞后问题。 通过 GitHub Actions 每日自动检测，将链接状态直观地标红或标黄，让用户一目了然，避免了手动逐个验证的麻烦。
  2. 项目设计遵循开放和透明的原则，区别于黑盒导航站。 所有资源数据存储在公开的 JSON 文件中，有 schema 验证，并支持通过 PR 贡献，确保了数据的可审查性和社区共建的便利性。
  3. 对资源进行了多维度的实用评估和风险提示。 除了可用性，还从资源丰富度、速度、纯净度、稳定性、易用性五个维度评分，并如实标注版权、安全等高风险项，体现了对用户负责的态度。

💬 文章金句

  • GitHub Actions 每天早上自动跑一遍，检测里面每个资源能不能访问，结果直接标在 README 里。不能用的标红，访问受限的标黄。
  • 数据全部在 resources.json 里，有 schema 验证，PR 合进来会自动跑检测。不想做成一个黑盒的导航站。
