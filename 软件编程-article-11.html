上下文是稀缺资源，Agent 的上下文里，究竟要放哪些东西？（3/12）

10/20/2026, 4:10:00 AM

📌 一句话摘要

本文基于 Anthropic 上下文工程原则，系统阐述了 Agent 上下文管理的核心策略：因注意力平方级摊薄与成本考量，仅喂入信号最强的最小 Token 集合，并通过“常驻与按需加载”二分法落地到 SDD Agent 实践中。

📝 详细摘要

文章作为《Agent 原理，架构与实践》系列第三讲，深入探讨了 Agent 上下文窗口的管理策略。首先指出大窗口不等于可随意堆砌：Transformer 注意力机制呈平方级摊薄，且每轮调用需重复付费。核心原则遵循 Anthropic 定义的“找到能让目标达成的、信号最强的、最小 Token 集合”。实操上提出二分法：每一步必需的角色定义、输出格式、当前任务指令常驻上下文（判断标准：删掉它每一步都会出错）；特定任务才需的规范细则、历史决策等按需加载，上下文仅放轻量指针。文中以自研 sdd-site-agent 为例，演示了需求/原型/架构规范按需加载、输出格式与任务描述常驻的分层设计。最后预告下一讲将解决长任务上下文写满后的记忆管理问题。

💡 主要观点

  1. 上下文窗口大不代表可随意塞入，注意力与成本是核心约束 Transformer 注意力计算复杂度为 O(n²)，Token 增加 10 倍注意力摊薄 100 倍；且每轮 Agent 交互需重发全量上下文，成本随轮次线性放大。模型效果随上下文增长渐变下降，非断崖式。
  2. 上下文工程核心原则：最小化、高信号、目标导向 引用 Anthropic 官方指南，强调上下文只应包含对当前步骤任务成功率有直接帮助的最小 Token 集合。任何脱离任务的信息堆积都是有害稀释而非无害冗余。
  3. 常驻与按需加载二分法：以“删掉它每一步会不会出错”为判断标准 常驻上下文：Agent 角色、输出格式约定、当前任务描述——每一轮必需。按需加载：特定规范细则、表结构、历史决策——仅在特定步骤通过工具检索指针获取，即 Just-in-time 检索。
  4. 实战落地：sdd-site-agent 的三层规范分层加载策略 需求规范、原型规范、架构规范均按需加载（仅在写需求、画原型、出方案时触发）；输出格式约定与当前任务描述常驻。该分层表为后续代码实现的核心产出。

💬 文章金句

  • 房间越大，东西越不能乱扔，找东西的时间是平方级涨的。
  • 任何脱离任务的上下文堆积，都是耍流氓。
  • 我们的判断标准是：删掉它，每一步都会出错。
  • 按需加载的官方叫法是：just-in-time 检索：上下文里只放轻量的"指针"。
