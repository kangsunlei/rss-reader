当智能体不再编写 Shell：语言即沙箱

8/28/2026, 4:04:00 AM

📌 一句话摘要

本文探讨了智能体在执行过程中面临的权限管理和跨平台兼容性问题，并介绍了 SeekMoon——一个基于 MoonBit 的智能体编程环境，通过语言级沙箱和细粒度权限控制，实现了更安全、更高效的智能体运行。

📝 详细摘要

智能体在执行任务时，往往需要调用底层系统命令，这带来了权限边界模糊和环境依赖复杂的风险。SeekMoon 通过将智能体代码编译为 WASM 模块，并使用细粒度的 policy 进行权限约束，解决了这些问题。同时，MoonBit 语言的跨平台特性和高效编译速度，使得 SeekMoon 成为一个理想的智能体开发平台。

💡 主要观点

  1. 智能体普遍依赖 Shell 和临时 Python，权限边界粗、环境依赖多。 现有的智能体框架通常使用 Shell 脚本或临时 Python 文件来执行任务，这种方式难以精确控制权限，容易导致误删文件或环境污染。此外，不同的操作系统（如 Windows 和 Linux）对这些脚本的解读也可能不同，导致兼容性问题。
  2. SeekMoon 使用 MoonBit 语言，通过 '语言即沙箱' 实现细粒度权限控制。 SeekMoon 将智能体代码编译成 WASM 模块，并由一个专门的运行时执行。这个运行时可以对每个 API 调用（如文件访问、网络请求）进行细粒度的权限检查，而不是像传统沙箱那样只能进行粗粒度的进程隔离。这样，即使智能体代码有漏洞，也不会对宿主系统造成太大损害。
  3. MoonBit 具有高效编译和跨平台特性，适合智能体现场生成工具。 MoonBit 的编译速度非常快，可以在毫秒级完成，这使得它非常适合在智能体运行过程中动态生成和执行代码。同时，MoonBit 的跨平台特性意味着同一份代码可以在 Windows、Linux 和 macOS 上运行，解决了智能体在不同操作系统上的兼容性问题。

💬 文章金句

  • 如果智能体处于 '完整访问权限'，提示词中的'不要误删'并不是可靠的安全边界。真正的保护应该是沙箱、审批、备份和最小权限。
