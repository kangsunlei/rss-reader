使用托管服务为 Amazon EKS 实施监控 | Amazon Web Services

7/18/2025, 8:47:13 AM

📌 一句话摘要

本文详细介绍了如何使用 AWS 托管服务（如 Prometheus、OpenTelemetry、X-Ray 和 CloudWatch）为 Amazon EKS 工作负载实施全面的可观测性，以实现基于指标的自动伸缩。

📝 详细摘要

本文全面介绍了如何为 Amazon EKS 建立强大的监控，解决了现代容器化环境的复杂性。它强调使用 AWS 托管服务，如 Amazon Managed Service for Prometheus、AWS Distro for OpenTelemetry (ADOT)、Amazon CloudWatch 和 AWS X-Ray，以创建一个完整的可观测性管道，包括指标、追踪和日志。该解决方案演示了如何结合 EKS 自动模式和 AWS Fargate 以实现灵活的计算选项，从而针对不同的用例（如成本优化和增强隔离性）进行优化。一个关键的重点是使用自定义 Prometheus 指标启用基于指标的自动伸缩，从而超越基本的基础设施利用率。本文提供了架构概述、详细的先决条件以及使用 AWS CDK、Kubernetes 配置和应用程序检测示例（适用于 Python Flask 和 Java Spring Boot）的实际代码片段，最终实现了使用自定义指标在 Amazon Managed Grafana 中设置 HPA 和可视化。本文有效地演示了如何为 EKS 构建企业级可观测性解决方案。

💡 主要观点

  1. 全面的 EKS 可观测性需要一个统一的指标、追踪和日志管道。 通过 ADOT 集成 Amazon Managed Service for Prometheus、AWS X-Ray 和 Amazon CloudWatch 提供了端到端的可视性，这对于在复杂的微服务环境中进行调试和性能分析至关重要。
  2. 基于应用程序需求的指标驱动的自动伸缩提高了资源效率。 利用带有 Kubernetes HPA 的自定义 Prometheus 指标，允许 EKS 工作负载基于实际应用程序负载（例如，请求率）动态伸缩，从而优化成本和性能，超越简单的 CPU/内存利用率。
  3. AWS 托管服务简化了企业级可观测性的实施。 利用完全托管的服务（如 Amazon Managed Service for Prometheus 和 ADOT）显著降低了运营开销，为 EKS 工作负载提供高可用性、可扩展性以及与 AWS 生态系统的深度集成。

💬 文章金句

  • 现代容器化环境需要超越基本 CPU 和内存指标的可观测性。
  • 我们的解决方案解决了三个关键挑战：降低计算管理复杂性、弥补可观测性差距以及实现基于指标的自动伸缩，从而响应实际应用程序需求，而不仅仅是基础设施利用率。
  • EKS 自动模式代表了 AWS 最新的托管 Kubernetes 计算方法。它消除了节点管理的需要，不再需要配置节点组或实例类型。
  • 该可观测性架构使用 AWS 原生服务实现了可观测性的三大支柱。
  • Prometheus 适配器将来自 Prometheus 的自定义指标公开给 Kubernetes 自定义指标 API，使 HPA 能够使用特定于应用程序的指标。
