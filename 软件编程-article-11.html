攻击者全网扫描 MCP 服务器与 Claude 凭据，AI 系统面临数据泄露风险

7/14/2026, 10:00:00 AM

📌 一句话摘要

文章披露全网扫描发现攻击者利用有效的 MCP 初始化请求探测 AI 服务、窃取 Claude 凭据并利用 SSRF 攻击云元数据，对 AI 系统构成数据泄露风险，并提出安全加固建议。

📝 详细摘要

文章基于互联网风暴中心与 Cyber Security News 的报告，详细描述了近期对外部 AI 部署的大规模侦察活动。攻击者通过发送符合 JSON‑RPC 规范的 MCP 握手请求，验证目标是否为真实的 MCP 服务器，进而枚举可用工具、数据源及 Agent 权限。与此同时，他们还检测到对 AI 助手配置文件和未授权模型端点的存在性探测，并利用服务器端请求伪造（SSRF）手段攻击云元数据服务。文中提供了具体的入侵指标、防御措施建议，如加强身份验证、限制公网访问以及启用云元数据保护等，提醒组织审查日志并及时阻断可疑流量。

💡 主要观点

  1. 攻击者利用有效的 MCP 初始化请求实施全网扫描，验证目标是否为真实的 MCP 服务器。 该方式使攻击者能够判断服务是否具备 MCP 功能，进而识别可用工具、数据源及 Agent 可执行的操作，为后续渗透提供情报。
  2. 扫描同时搜索 AI 助手配置文件及未授权的模型端点。 通过轻量级存在性检查，攻击者快速定位潜在的凭据文件和模型服务，避免下载大量无用文件，仅聚焦可能带来价值的资源。
  3. 利用 SSRF 等技术攻击云元数据服务。 该技术针对 AI 工具常见的内容抓取功能，可用于进一步在环境中立足，获取内部资源或执行更深层攻击。
  4. 文中给出组织防御建议。 建议审查访问日志、加强身份验证、限制公网访问 MCP 服务，并启用云元数据保护（如 GCP 头部强制、AWS IMDSv2），降低被扫描风险。

💬 文章金句

  • 面向互联网的 AI 系统正成为机会主义攻击者的新目标。
  • 这些扫描反映出 AI 部署领域日益严重的安全问题。
  • 攻击者已经在寻找这些配置失误。
  • 组织应审查访问日志中可疑的 MCP 流量。
  • 限制网络访问还能降低扫描器首先发现服务的可能性。
