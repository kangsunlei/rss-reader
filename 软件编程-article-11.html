CVE-2025-57822 - Vercel

8/29/2025, 1:00:00 PM

📌 一句话摘要

Next.js 中间件（版本低于 v14.2.32 和 v15.4.7）中一个关键的服务器端请求伪造 (SSRF) 漏洞已修复，该漏洞由不当使用 `NextResponse.next()` 引起。

📝 详细摘要

本文详细介绍了 Next.js 中间件中发现的 CVE-2025-57822 服务器端请求伪造 (SSRF) 漏洞。具体来说，当开发者不正确地使用 `NextResponse.next()`，而没有显式传递 `request` 请求对象时，低于 v14.2.32 和 v15.4.7 的版本会受到影响。这种错误配置可能允许攻击者操纵服务器端请求，从而可能访问内部基础设施或敏感资源。Vercel 已经修补了其基础设施。但是，如果自托管部署未更新到最新版本，或者自定义中间件逻辑不符合最佳实践，仍然存在安全风险。解决方案包括将 Next.js 更新到已修复的版本，或确保正确使用 `NextResponse.next({ request })` 并仔细进行请求头验证作为解决方法。

💡 主要观点

  1. 在 Next.js 中间件中不当使用 `NextResponse.next()` 引入了 SSRF 风险。 当 `NextResponse.next()` 直接使用用户控制的请求头，而没有显式传递 `request` 请求对象时，服务器可能会被诱骗向攻击者指定的内部目标发出请求。
  2. 该漏洞允许攻击者对自托管部署中的内部基础设施执行 SSRF。 对于未遵循文档中 `NextResponse.next({ request })` 用法的自托管 Next.js 应用程序来说，此问题至关重要，可能会导致内部网络侦察或数据泄露。
  3. 解决方案包括升级 Next.js 或坚持显式使用 `NextResponse.next({ request })`。 开发人员应升级到 Next.js v14.2.32 或 v15.4.7，或实施解决方法，例如显式传递 `request` 请求对象并验证用户控制的请求头，以降低风险。

💬 文章金句

  • 一个影响 **Next.js 中间件** 的漏洞已得到解决。它影响了 **v14.2.32** 和 **v15.4.7** 之前的版本，该漏洞是由于中间件中 `NextResponse.next()` 函数的错误配置使用引入的**服务器端请求伪造 (SSRF)** 风险。
  • 此问题在自托管部署中可以被利用，在这些部署中，开发人员使用自定义中间件逻辑，并且不遵循文档中 `NextResponse.next({ request })` 的用法。
  • 此问题通过更新内部中间件逻辑来解决，以防止在调用 `next()` 时省略 `request` 对象导致的不安全回退行为。
  • 确保中间件遵循官方指南：使用 `NextResponse.next({ request })` 显式传递 `request` 请求对象。
