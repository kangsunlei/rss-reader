十年没正经写代码后，我靠 AI 把公司工作流重新搭了一遍

6/25/2026, 12:57:19 AM

📌 一句话摘要

一位十年没写代码的前端转创业者，通过反复试错不同 AI 模型，总结出便宜模型负责拆细的简单任务、强模型负责复杂协作的经验，成功搭建公司跨境进口工作流。

📝 详细摘要

作者是 87 年的前前端开发，转产品创业做跨境进口，十年没碰代码。因业务需要，用 AI 重新搭建公司内部工作流。文章记录了从 OpenClaw、Hermes 开始，到 DeepSeek、Qwen-Plus、GLM、Kimi，最终稳定在 Claude/Codex 的选型历程。核心痛点包括多 agent 记忆窜乱、上下文失控、成本陷阱（如 GLM 出人意料的两百多账单）、账号稳定问题等。最终形成分工策略：最细的基础任务（类目识别、字段提取）交给便宜模型；部门级业务用按 skill 拆分的架构；复杂多 agent 协作和跨部门流程用 Claude/Codex。作者强调稳定比单次便宜重要，便宜模型必须把任务拆到极细才划算，并坦言自己已经不再直接写代码，而是描述需求、拆流程、验收结果。最后抛出一个未完全解决的问题：便宜模型和省心模型之间的分界线。

💡 主要观点

  1. 便宜模型适合拆得极细的简单任务，但必须确保输入输出窄、规则死。 类目识别、违规词识别、简单字段提取等任务，用 DeepSeek/Qwen-Plus 等便宜模型又快又便宜，出错也好兜底。
  2. 复杂多 agent 协作和跨部门流程需要更强的模型（Claude/Codex），贵但省心。 便宜模型在多 agent 场景下容易串记忆、上下文失控，而 Claude 在记忆分配和任务交接上明显更顺，减少了后者的大量 debug 时间。
  3. 稳定性比单次便宜更重要，账号中断的成本远大于 token 费用节省。 作者曾因使用不稳定的 Claude 渠道省钱导致账号出问题，工作流中断带来的损失远超省下的费用，最终选择正规付费方式。
  4. AI 让非全职工程师也能重新“造东西”，工作模式变为描述需求+验收结果。 作者十年没写代码，现在通过 Claude Code 和 Codex，中间代码几乎全是 AI 写的，自己的核心工作是拆业务流程和验收。

💬 文章金句

  • 有些便宜不能硬占。尤其是工具已经接进日常工作之后，稳定比单次便宜重要得多。
  • 一个十年没正经碰代码的人，靠这套又开始造东西，这事我自己都觉得有点魔幻。
  • 便宜模型也不是闭眼省钱，用不对，一样肉疼。
