打破“人月神话”，Agent 重塑风控场景产运研职能

6/1/2026, 8:03:00 AM

📌 一句话摘要

本文是快手风控技术负责人在 QCon 大会的演讲实录，系统阐述了如何通过 Agent 和 AI 原生转型，重塑风控场景中产品、运营、研发三大职能的角色与协作模式。

📝 详细摘要

本文是快手磁力引擎风控技术负责人王东旭在 QCon 2026 北京站的演讲实录。文章从 AIGC 时代「安全、效率、体验」不可能三角被推向极限的现实困境出发，提出传统固态组织必须向「液态组织」转型。作者详细分享了团队在过去半年推动的三大职能重塑实践：产品经理采用 Prompt to Product 模式直接交付原型，运营从规则配置者升级为 Prompt Engineer、RAG 运营乃至模型教练，研发则通过 CLI 模式武装自己逃离职业阶梯中空化。文章还坦诚复盘了 Vibe Coding 工程落地坑（Demo 惊艳但生产一塌糊涂）、增量与存量项目差异、以及组织变革中的管理冲突教训。最后，作者提出了 Token 经济学与 Skills 贡献度考核、逆康威定律应用、以及做「眼高手低」技术人三点组织行动建议。

💡 主要观点

  1. 传统产运研固态组织面临 AIGC 时代的效能瓶颈，需向液态组织转型。 产品、运营、研发之间的部门墙导致沟通摩擦和信息对齐成本高，技术已进入 AI Native 阶段，但组织仍停留在旧范式，必须打破职能边界，让每个角色向价值链上游升级。
  2. 产品经理可通过 Prompt to Product 模式直接交付原型，提升产能。 利用 Figma、Lovable、Bolt.new 等 Vibe Coding 工具，产品经理可绕过研发排期，独立完成原型设计，甚至替代部分低水平研发工作，成为研发的「搭子」。
  3. 运营角色从规则配置者升级为 Prompt Engineer、RAG 运营和模型教练。 运营利用对业务的深度理解，直接编写结构化 prompt、构建 RAG 知识库，甚至通过线上化平台完成模型微调 pipeline 的运维，实现了面向 AI 原生的职能跃迁。
  4. 研发需通过 CLI 模式武装自己，逃离职业阶梯中空化的 Danger Zone。 初级研发面临被资深同学和大模型双重挤压的困境，必须掌握 Code Agent 和 CLI 模式，成为能独立交付的小军团，同时通过 Spec-Driven Development 解决 Vibe Coding 的工程落地问题。
  5. 组织转型需遵循「试、推、升」三步法，避免面面俱到。 先在小范围试点成功，再推广让一部分人先信起来，最后全面重塑。管理者应避免追求全员同步，而是通过局部成功案例带动整体变革。

💬 文章金句

  • 技术已经发展得很快，但人的组织方式还没有跟上。
  • 执行力本身已经商品化。写代码变成了一件相对简单的事，真正的困难在于跨部门之间的沟通摩擦和信息对齐。
  • 低代码平台正在消亡。过去产品经理做原型设计时，经常会借助低代码平台...但今天，每一个产品经理都可以使用 Vibe Coding。
  • Demo 惊艳全场，生产一塌糊涂。
  • 唯一的护城河，是你和你的组织进化的速度。
