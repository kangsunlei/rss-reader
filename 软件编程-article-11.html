AI Coding 生死局：Spec 正在蚕食人类编码，Agent 造轮子拖垮效率，Token 成本失控后上下文工程成胜负手

12/30/2025, 6:31:00 AM

📌 一句话摘要

文章分析了 2025 年 AI 编程从补全到 Agent 主导的范式转变，强调 Spec 和上下文工程是驾驭 AI Agent、控制 Token 成本、解决软件工程复杂性的核心。

📝 详细摘要

文章深入探讨了 2025 年 AI Coding 生态的演进，指出 AI 编程已从以人为中心的“补全”范式转向以 Agent 为主导的任务接管范式。文章强调了 Spec（契约）在驱动 Agent 工作中的核心作用，讨论了 Spec 的真实含义、标准化难度以及它与上下文工程的关联。同时，文章揭示了 Token 成本在 Agent 范式下失控的原因，以及上下文管理在 AI 编程中的关键作用。通过与两位业内专家的对话，文章围绕模型、工具、IDE 和上下文管理四个维度，分析了 AI 编程的系统性工程挑战，并强调了有效组织和管理上下文是决定 AI 编程长期可靠性和效率的关键。最终，文章预测未来 AI 编程的竞争将是工程体系与模型能力综合作用的结果。

💡 主要观点

  1. AI Coding 范式已从以“补全”为核心的人机协作转向以“Agent”主导的全任务接管。 第一波 AI Coding 以 Copilot 为代表，专注于局部提效；第二波 Agent 的崛起实现了从需求分析到代码生成，工具调用到结果验证的全任务接管，成为 AI 编程的主流程。
  2. Spec（契约）成为解决 AI Agent 复杂性、确保长期任务稳定性的核心机制。 随着执行权转移到 Agent，软件工程的隐性复杂度需前置显性规则。Spec 作为指导性 Context，定义目标、约束与验收标准，但其形态和标准化仍在探索。
  3. Token 成本在 Agent 范式下迅速膨胀，上下文管理成为 AI 编程的胜负手。 Agent 多轮交互、工具调用和中间产物生成导致 Token 消耗失控。有效的上下文工程（如 KV Cache 利用、信息过滤、渐进式披露）是控制成本、提升效率和稳定性的关键。
  4. AI 编码的未来竞争在于工程体系与模型能力的协同作用，而非单一模型能力。 AI 编程是一个系统工程，涉及模型、工具、IDE 和上下文管理。将隐性工程约束转化为模型可理解、可执行的上下文结构，是提升 AI 编程长期可靠性的关键。

💬 文章金句

  • 用一套契约，逼 Agent 真的干活。
  • IDE 正在从“给人用的工具箱”，变成“给 AI 和人一起共用的工具箱”。
  • Spec 是**一切用于指导代码生成的契约总和**：产品文档、设计稿、接口定义、边界条件、验收标准、执行计划。
  • Token 已经从“计费单位”变成了**生死线**。
  • 真正稀缺的不是上下文长度，而是**有效 Context 的组织能力**。
