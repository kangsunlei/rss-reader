Spanner 上的 Cassandra 查询语言 (CQL) API

2/20/2026, 12:00:00 AM

📌 一句话摘要

Google Cloud Spanner 现在提供原生 CQL API，使 Cassandra 用户能够以极少的代码更改进行迁移，同时获得全球 ACID 事务和简化的托管数据库生态系统。

📝 详细摘要

本文宣布 Google Cloud Spanner 上的 Cassandra 查询语言 (CQL) API 正式发布。文章强调了这一原生端点如何允许开发人员以近乎零的代码修改将现有的 Cassandra 应用程序迁移到 Spanner。除了简单的兼容性，文章还详细介绍了 Spanner 如何通过提供全球 ACID 事务、99.999% 的可用性和强一致性来克服传统 NoSQL 的局限性。它还提供了优化 Spanner 工作负载的技术路线图——涵盖吞吐量优化写入、自动扩缩容和分层存储——并解释了如何通过使用 Spanner 的集成原生功能替换 Reaper 和 Medusa 等外部 sidecar 工具来消除“Cassandra 税”。

💡 主要观点

  1. 原生 CQL 支持实现了从 Cassandra 到 Spanner 的无缝迁移，且只需极少的代码更改。 通过提供原生 CQL 端点，Spanner 允许现有的 Cassandra 应用程序利用其企业级特性（如强一致性和全球规模），而无需重写应用程序逻辑。
  2. Spanner 通过将维护和运营工具集成到核心服务中，消除了“Cassandra 税”。 传统的 Cassandra 部署需要复杂的 sidecar 工具，如用于修复的 Reaper 和用于备份的 Medusa；Spanner 使用基于 Paxos 的原生复制和时间点恢复 (PITR) 替换了这些工具。
  3. 高级优化功能允许在迁移后对性能和成本进行微调。 用户可以利用吞吐量优化写入将容量提升 6 倍，使用自动扩缩容来匹配波动的流量，并利用分层 HDD 存储显著降低长期数据保留费用。
  4. Spanner 的多模型架构统一了关系型、键值、图和搜索功能。 转型到 Spanner 允许团队将碎片化的数据库堆栈整合到单个互操作平台中，支持全文搜索和图分析，而无需复杂的 ETL 流水线。

💬 文章金句

  • 使用 CQL 接口将应用程序迁移到 Spanner 通常只需要更改一行代码，因为您现有的 CQL 语句仍然有效。
  • 真正的价值在于将运营层面的“Cassandra 税”整合进一个统一的、托管的多模型生态系统中。
  • Spanner 在读取和写入操作中始终提供低于 5ms 的延迟。
  • 停用旧的维护工具并解锁 Spanner 的高级功能。
