Agent 上岗之后，企业如何治理硅基团队？

7/3/2026, 8:54:00 AM

📌 一句话摘要

本文报道一场关于企业如何治理 AI Agent 的论坛，从记忆工程、研发协作与组织治理等角度，探讨 Agent 从个人工具走向生产流程后需要构建的系统能力。

📝 详细摘要

文章基于张江 AI 小镇与 InfoQ 联合举办的「塔尖会」专场论坛，聚焦 AI Agent 进入企业核心流程后的治理问题。质变科技周祥分享了 Agent 长期记忆工程，提出 Token 真实成本由任务成功率决定，并介绍记忆蒸馏、记忆计算和记忆堆叠三层架构，以及 Workspace/Actor/Project 的组织级框架。华为董鑫从研发实践出发，介绍 ACE Harness 系统，实现 Agent 自动分析 Issue、定位根因并通过 Human on the Loop 与 Human in the Loop 保障可控，同时提出 ATM 动态匹配机制。圆桌环节，嘉宾围绕 Agent 上限与下限、个人 Agent 到团队协作的挑战展开讨论，指出统一语言、思维对齐、小型尖刀队等关键。文章总结指出，AI 价值不会自动转化为组织效率，需要嵌入可运行、可验证、可治理的工作体系，硅基团队治理仍是探索中的命题。

💡 主要观点

  1. Agent 进入生产环境后，记忆工程是基础能力，Token 真实成本由任务成功率决定。 周祥在分享中给出公式：Token 成本 = Token 单价 ÷ 任务成功率。成功率越低，企业为无效试错支付的隐性成本越高，记忆系统（蒸馏、计算、堆叠）是降低试错成本的关键。
  2. AI 研发下半场的关键是让 Agent 在团队流程中自主运转，需要 Human on the Loop 与 Human in the Loop 结合。 董鑫介绍的 ACE Harness 系统实现 Agent 自动分析 Issue、定位根因，并通过「蓝军」Agent 挑战、「裁判」Agent 仲裁，人工在异常节点介入，实现了约 50%到 1 倍的效率提升。
  3. Agent 能力上限由模型和记忆共同决定，下限由人和治理框架决定；过度 Harness 可能限制 AI 潜力。 圆桌中不同嘉宾给出视角：曹偲认为 Memory 决定上限，蒋烁淼则认为人的框架可能限制模型，给予粗粒度目标让 AI 先长出来再修剪可能效果更好。
  4. 个人 Agent 走向团队协作需要统一语言、思维对齐和边界清晰的小型尖刀队。 曹偲指出同样工具在不同人手中变成 50 种工具，统一 Prompt 和交付标准是第一步；蒋烁淼建议 2-3 人小队围绕清晰模块闭环推进，避免多人与 AI 对话产生的混乱。

💬 文章金句

  • Token 成本等于 Token 单价除以任务成功率。
  • 真正稀缺的并不是代码本身，而是人能否提出值得做的问题。
  • AI 的价值不会自动转化为组织效率。
