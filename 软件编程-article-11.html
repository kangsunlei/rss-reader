给 Agent 装上方向盘和刹车，Harness 时代的工程新范式

7/31/2026, 3:28:00 AM

📌 一句话摘要

本文记录了 InfoQ 与 AICon 专家关于 Agent 工程化（Harness Engineering）的讨论，阐述了构建可靠 Agent 工作环境的关键要素。

📝 详细摘要

文章整理了 InfoQ《极客有约》×AICon 直播中阿里云技术专家张鑫、NoDesk AI CTO 王仿以及腾讯高级后台开发工程师任磊达的观点。讨论围绕 Agent 在真实业务环境中的可靠性挑战展开，提出 Harness 不是为了消灭幻觉，而是用工程系统承接和约束不确定性，核心在于让 Agent“做正确的事”和“正确地做事”。文章进一步阐述了为 Agent 构建工作环境需要解决的四个问题（理解系统、清晰的工具描述、可证明的改动以及可回滚的关键步骤），强调本体论在将人类可读的上下文转化为 Agent 可理解的结构化知识中的关键作用。同时指出人在 Agent 工作中的角色是提供判断力和监督，而非被取消，并强调可观测性与反馈循环对提升 Agent 可靠性的重要性。整体内容为技术领域提供了系统化的工程思路径。

💡 主要观点

  1. Harness 的核心是让 Agent 做正确的事并正确地做事。 通过工程系统承接不确定性，强调可观测性形成闭环学习，从数据中学习错误原因并持续改进。
  2. 为 Agent 构建工作环境需解决理解、可执行、可证明、可回滚四个问题。 类比新员工入职，需要清晰的业务对象、工具描述、测试夹具以及关键步骤的人工介入以确保可控。
  3. 本体论是让 Agent 能理解企业上下文的关键，即将人类可读信息翻译为结构化知识。 包括业务对象关系、状态和证据，使 Agent 能主动感知而非仅被动响应。
  4. 人在 Agent 工作中的角色是提供判断力和监督，而非被取代。 Agent 缺乏判断力，人需在关键节点介入，保证专业性和可控性，避免盲目执行。
  5. 可观测性与反馈循环是提升 Agent 可靠性的基础，通过日志、看板和闭环学习形成持续改进。 使团队能看到 Agent 执行细节，从数据中学习错误并优化流程与工具使用。

💬 文章金句

  • 就像发动机马力不大的时候不需要方向盘和刹车，马力强了才需要配套安全防护。
  • Harness 不是消灭幻觉，而是用工程系统承接和约束不确定性。核心两点：让 Agent 做正确的事，以及正确地做事。可观测也很关键，只有观测到 Agent 的执行逻辑，才能从数据中学习它为什么错、错在哪，形成飞轮效应。
  • 企业内部的数据、知识、系统都是给人构建的，现在要让数字员工上岗，首先要把给人看的上下文翻译成 Agent 能理解的语言，这就是本体论。
  • Agent 只会道歉，没办法背锅。专业性是人的核心价值，也就是判断力。
  • 人更多是提供判断力。Agent 什么活都能干，但唯独缺判断力。它在我现在看来就是一个工具，可以增加人效，以前一天干一个活，现在拆成十个 Agent 去干不同的活。但这里面对人的消耗也非常巨大，人会在里面疯狂做上下文切换。
