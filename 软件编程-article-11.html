构建智能体化 MLOps：结合 A2A 与 MCP 的分层协议策略

2/16/2026, 9:00:00 AM

📌 一句话摘要

本文通过结合用于智能体间通信的 Agent-to-Agent (A2A) 协议与用于标准化工具和数据访问的 Model Context Protocol (MCP)，提出了一种 MLOps 的分层架构策略。

📝 详细摘要

本文介绍了一种专为软件开发“智能体时代”设计的复杂架构模式，并将其具体应用于 MLOps。文章提倡采用分层方法，将智能体通信与能力执行解耦。Agent-to-Agent (A2A) 协议作为通信总线，使专业智能体能够通过“智能体卡片”进行发现和协作，而无需硬编码依赖。同时，Model Context Protocol (MCP) 充当通用接口——即“AI 界的 USB-C”——允许智能体通过标准化的服务器-客户端模型访问工具、数据和资源。通过将此模式应用于包含编排、验证和部署智能体的 MLOps 工作流，作者展示了如何从僵化的单体流水线转向敏捷的多智能体系统。提供的 Python 样板代码展示了 MCP 服务器和客户端的实现，以及智能体将自然语言查询转换为结构化任务列表和工具使用计划的逻辑，最终促进了一个更具扩展性和互操作性的 AI 生态系统。

💡 主要观点

  1. 分层 A2A 和 MCP 协议为多智能体自动化创建了一个稳健且具有互操作性的框架。 通过将 A2A 作为通信层，MCP 作为能力层，架构师可以构建智能体能够动态发现彼此及其所需工具的系统，从而减少供应商锁定并提高系统灵活性。
  2. 将编排逻辑与执行逻辑解耦对于构建可扩展的智能体系统至关重要。 该架构将编排智能体执行的高层规划与专业智能体处理的底层工具执行分开，允许更复杂的工作流在不重写核心通信逻辑的情况下进行演进。
  3. 智能体卡片和标准化原语实现了多供应商环境下的无缝发现和交互。 A2A 使用智能体卡片来描述能力和请求类型，而 MCP 则标准化了工具、资源和提示词。两者结合，使来自不同系统的智能体能够利用 JSON-RPC 和 SSE 等标准 Web 技术进行有效协作。
  4. 从静态流水线向动态智能体团队的转变增强了 MLOps 工作流的适应性。 传统的 MLOps 流水线通常是僵化且难以修改的。智能体驱动的方法允许动态协调，智能体可以通过组合不同的能力来适应新需求，而不需要对流水线进行全面重新部署。

💬 文章金句

  • A2A 提供了通信总线，而 MCP 则充当了智能体能力的通用语言。
  • 分层智能体架构的力量在于其适应和演进的能力，它超越了僵化的单体系统，转向敏捷的智能体驱动运营。
  • MCP 常被描述为“AI 集成的 USB-C”，它提供了一个通用接口，允许 AI 应用在无需自定义胶水代码的情况下接入外部数据源和工具。
  • 随着 AI 智能体的演进，这种从静态执行到动态协调的转变是我们旨在展示的核心原则。
  • 使用分层 A2A-MCP 模式并不局限于 MLOps；其原则适用于任何需要动态协作和灵活访问能力的领域。
