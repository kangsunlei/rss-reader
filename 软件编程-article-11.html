基于 Claude Code Workflow 的 Loop Engineering 流水线 - Claude-lights-out

6/10/2026, 9:54:38 AM

📌 一句话摘要

本文介绍了一个基于 Claude Code Workflow 构建的强制流水线工具，通过 9 个阶段（含独立审查、文档先行、自动修复循环）解决 AI 编程中的质量不可控、黑盒与失忆问题。

📝 详细摘要

作者分享了自己开发的 Claude-lights-out 工具，旨在解决使用 AI 写代码时常见的四大痛点：人肉 QA、黑盒运行、上下文失忆和偷工减料。该工具基于 Claude Code 的 dynamic workflow，将开发流程强制拆分为 9 个阶段：需求编写、交互设计、技术架构、一致性检查、测试用例设计、写代码、QA、E2E 验证和最终检查。核心设计原则包括：写代码与审查由不同 agent 承担以保证质量、文档先行代码最后、复杂项目自动拆分并行开发、每个环节自带修复循环。实测 4 个全新项目（Python CLI、全栈应用等）均一次或少量修复后通过，但代价是每次运行需 30-50 个 agent call，耗时 45 分钟到 2 小时。

💡 主要观点

  1. 强制流水线将 AI 编程从自由对话转为结构化交付流程。 通过 9 个阶段的强制顺序执行，确保需求、设计、架构、测试在写代码前完成，并由独立 agent 审查，大幅提升最终交付质量。
  2. 写与审分离是质量提升的关键设计。 作者强调「写的人和审的人必须是不同 agent」，自己审自己会放水，独立 reviewer 能发现 writer 自身忽略的问题，这是实践中验证的有效策略。
  3. 文档先行解决了 AI 的「失忆」问题。 生成的 spec.md、design.md、architecture.md 等文档作为项目的持久记忆，新 session 的 agent 读取后即可了解项目全貌，无需用户重新解释上下文。
  4. 工具以 token 换时间，适合注意力比 token 更值钱的场景。 每次运行消耗大量 token（30-50 个 agent call，45 分钟到 2 小时），但用户无需介入调试，适合有预算或认为自身时间更宝贵的开发者。

💬 文章金句

  • 写的人和审的人必须是不同 agent。自己审自己肯定放水。拆开之后质量真的不一样——reviewer 会挑出 writer 自己看不到的问题。
  • 文档先行，代码最后。不是先写代码再补文档，而是需求、设计、架构全部写完审完了再动手。
  • 本质上这东西是拿 token 换你的时间和精力。
