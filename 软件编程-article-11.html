Claude 性价比之王 Sonnet 5 来了！Claude Code 终于补上最缺的“执行者”

7/1/2026, 4:30:00 AM

📌 一句话摘要

本文报道 Claude Sonnet 5 的发布与性能定位，结合基准测试、安全性分析和社区争议，探讨其作为高频执行模型的性价比与适用场景。

📝 详细摘要

文章完整报道了 Anthropic 发布 Claude Sonnet 5 的消息，官方定位为“接近 Opus 4.8 的思考能力，同时保留 Sonnet 系列的速度”。文章引用 SWE-bench、Terminal-Bench、Humanity's Last Exam 等基准测试数据，展示其在多数指标上接近 Opus 4.8 但仍有差距。重点分析了 Sonnet 5 的 1M 上下文窗口、128K 最大输出、5 档 effort 控制等执行层能力，指出其更适合高频开发任务而非高风险判断。同时给出了 Cursor 的接入情况、System Card 中的安全性测试数据（Shade 间接提示注入攻击成功率仅 0.31%）。文章还重点报道了社区对性价比的争议：有用户认为代币效率差，Max 档成本几乎与 Opus 4.8 持平，但得分更低，质疑其“Sonnet”定位。作者最终给出使用建议：将 Sonnet 5 作为执行模型配合 Claude Code Dynamic Workflows 使用，而非 Opus 的廉价替身，并展望 Fable 5 回归后的分工模式。

💡 主要观点

  1. Claude Sonnet 5 性能接近 Opus 4.8，但多数指标仍有差距。 在 SWE-bench Pro 得分为 63.2%（Opus 4.8 为 69.2%），Terminal-Bench 2.1 为 80.4%（Opus 4.8 为 82.7%），差距已经缩小。
  2. Sonnet 5 更适合作为高频执行模型，而非 Opus 的廉价替身。 低 effort 下性价比突出，但 Max 档成本接近 Opus 4.8 而得分更低，因此开发者应将其定位为执行层模型，用于修 bug、补测试、迁移等常规任务。
  3. 安全性提升显著，间接提示注入防护优于 Opus 4.8。 在编码环境的 Shade 测试中，带 thinking 时无防护攻击成功率 0.31%（Opus 4.8 为 7.03%），加上安全缓解后进一步降至 0.09%。
  4. 社区对性价比的负面反馈集中在代币效率上。 用户指出 Sonnet 5 Max 档消耗 token 更多，实际成本仅比 Opus 4.8 便宜 0.72 美元，得分却更低，质疑其 Sonnet 定位。

💬 文章金句

  • 接近 Claude Opus 4.8 的思考能力，同时保留 Sonnet 系列的速度。
  • Built to run， not just respond（模型不能只会聊天，还得能真正把任务跑下去。）
  • Sonnet 这一档，原本就应该更快、更便宜、更能干。
  • 在开发者每天反复调用的那些任务里，它能不能稳定地省时间、省 token、省钱。
