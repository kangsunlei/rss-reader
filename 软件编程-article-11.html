企业内 Agent 工具落地实践：统一 Harness、Skill 与虚拟文件系统

8/14/2026, 12:45:00 AM

📌 一句话摘要

本文提出企业 Agent 落地应以统一 harness 承载执行与安全、以 skill 分发领域能力、以虚拟文件系统管理长任务上下文，并给出架构分层、安全模型与四阶段演进路径。

📝 详细摘要

文章结合 Stripe Knowledge AI Platform（Kai）与 Deep Agents 的公开实践，系统论述企业 Agent 从演示走向生产的核心架构问题。作者认为分水岭不是模型而是运行时，提出四层架构：入口层、控制面、企业 harness 与通用 runtime；harness 负责执行编排、权限、检查点与审计，skill 负责把分散的领域经验变成可治理的软件资产，虚拟文件系统则承担长任务的上下文、证据与交付产物。文章进一步给出 skill 的两阶段路由、联邦所有权、最小数据模型与控制面设计，强调 "prompt 不是安全边界"，提出有效能力等于用户授权、Agent 配置、skill 策略、会话 scope 与工具端执行的交集。落地路径上建议先建资产与风险基线，再接入统一 harness，逐步引入两阶段路由和 trace-to-skill 改进闭环，并以四组指标衡量真实落地效果。整体是一份面向企业 AI 平台建设者的架构实践笔记，兼具行业案例佐证与可操作建议。

💡 主要观点

  1. 企业 Agent 的分水岭不是模型，而是运行时 harness。 模型决定单次推理上限，harness 决定能力能否稳定、可控地进入企业流程；统一 harness 负责执行、安全、检查点与审计，避免各 Agent 各搞一套。
  2. Skill 是把领域经验变成可治理软件资产的合适边界。 工具解决能做什么，skill 解决按什么流程与标准完成；大规模目录需要用检索或分类器预筛加 LLM 最终判断的两阶段路由，并由领域团队联邦维护。
  3. 虚拟文件系统为长任务提供上下文平面与交付平面。 VFS 用 ls/read/write 等熟悉语义管理 evidence、working、artifacts 与 checkpoints，与 sandbox 分离，避免上下文膨胀并让产物可追溯、可接管。
  4. 安全上要从用户权限收缩到会话能力，prompt 不是安全边界。 有效能力应是用户授权、Agent 配置、skill 策略、会话 scope 与工具端执行的交集；必须用工具可见性、参数策略、执行隔离、人工审批四道门兜底。
  5. 落地应从现有工具体系渐进演进，而不是重写一切。 先建 registry、lint 与 eval 基线，再统一 session API 接入 harness，最后做两阶段路由与 trace-to-skill 闭环，避免一次性建设复杂 RAG 或多 Agent。

💬 文章金句

  • 模型决定一次推理的上限，harness 决定这份能力能否稳定、可控地进入企业流程。
  • Prompt 不是安全边界。
  • Sandbox 保护的是宿主环境，不代表 sandbox 内的数据天然安全。
  • 一个只能在所有依赖正常时完成任务的 Agent，仍然只是演示。
  • 框架可以替换，模型可以升级；只要这些边界清楚，企业能力就不会随着某次技术选型一起重写。
