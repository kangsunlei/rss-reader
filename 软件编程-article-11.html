Yelp 发布大规模管理 S3 服务器访问日志的方案

12/27/2025, 3:51:00 AM

📌 一句话摘要

Yelp 通过自动化流程将大规模 S3 服务器访问日志压缩、转换并优化查询，成功解决了存储成本和查询效率瓶颈，并为云存储可观测性提供了工程范式。

📝 详细摘要

Yelp 详细介绍了其如何构建一套可扩展且成本效率高的日志处理流水线，用于处理大规模 Amazon S3 服务器访问日志（SAL）。面对 TB 级的日常日志量，传统方案在高存储成本和低查询效率方面存在瓶颈。Yelp 通过将原始日志转换为紧凑的 Parquet 格式，并采用“压缩”流程将小文件合并为大文件，实现了存储空间约 85% 的减少和对象数量 99.99% 以上的削减，显著降低了成本并提升了查询性能。底层架构上，系统利用 AWS Glue Data Catalog 统一管理 schema，结合定时批处理、Lambda 函数和分区投影实现自动化摄取，并采用幂等设计处理延迟和重复日志。这套系统支持权限排查、成本归因、事故调查和数据保留分析等关键场景。文章还对比了 Upsolver、AWS 官方方案以及 Apache Druid、Presto/Trino 和 OpenSearch 等业界类似解决方案，证明了 S3 对象级访问日志规模化落地的可行性，为提升云存储环境的可观测性、合规能力和审计能力提供了工程范式。

💡 主要观点

  1. Yelp 成功构建了可扩展的 S3 服务器访问日志处理流水线，解决了大规模日志的存储成本和查询效率问题。 通过将海量纯文本日志转换为 Parquet 格式并进行“压缩”合并，存储空间减少 85%，对象数量削减 99.99%，大幅降低了 TCO 并加速了查询速度。
  2. 核心技术方案包括使用 AWS Glue Data Catalog、定时批处理、Lambda 函数和分区投影，并采用幂等设计处理日志。 这种架构确保了跨账号日志的统一管理、自动化的摄取流程，并通过幂等性避免了数据重复，提升了系统的稳定性和可靠性。
  3. 该系统支撑了多种关键运维和治理场景，如权限排查、成本归因和数据保留管理。 工程师可以高效查询对象访问情况，分析 IAM 角色成本，并识别长期未访问对象进行清理，提升了安全、合规性和成本效益。
  4. Yelp 的实践证明了 S3 对象级访问日志规模化落地的可行性，并为行业提供了可参考的工程范式。 该方案为企业在提升云存储可观测性、合规审计能力时，提供了一种在不显著增加存储成本前提下，实现良好查询能力的现实路径，并与业界其他类似方案进行了对比分析。

💬 文章金句

  • Yelp 详细介绍了他们如何构建一套可扩展且具备成本效率的日志处理流水线，用于在全公司范围内处理 Amazon S3 的服务器访问日志（SAL），并成功突破了原始日志在高规模场景下面临的存储成本高、查询效率低等传统瓶颈。
  • 通过定期执行的“压缩”流程，原本分散的大量纯文本日志对象会被合并为数量更少、体积更大的 Parquet 文件，这一过程将整体存储空间减少了约 85%，同时将对象数量削减了 99.99% 以上。
  • Yelp 的这项工作具有双重意义。一方面，它证明了长期以来被认为“过于昂贵或难以运维”的 S3 对象级访问日志，在合理的架构设计下完全可以实现规模化落地；另一方面，它为希望提升云存储环境中可观测性、合规能力和审计能力的组织，提供了一套可参考的工程范式。
  • AWS 官方同样 发布 过一套基于 Glue 作业处理 S3 服务器访问日志的参考架构，本质上复现了 Yelp 所采用的“压缩 + 表结构 + 数据目录 + 查询”的整体模式，只不过是以 AWS 托管方案的形式提供。
