QConSF 2025 - Anthropic 以 AI 驱动的速度开发 Claude Code

11/20/2025, 6:00:00 PM

📌 一句话摘要

Anthropic 利用 AI 编码助手加速 Claude Code 的开发，将瓶颈从实现转移到快速迭代和反馈。

📝 详细摘要

InfoQ 的这篇文章总结了 Adam Wolff 在 QCon San Francisco 2025 大会上关于 Anthropic 如何以“AI 驱动”的速度开发 Claude Code 的演讲。核心观点是，像 Claude Code 这样的 AI 编码助手改变了开发工作流程，使实现不再是瓶颈，并提升了快速反馈、观察和调整的重要性。Wolff 通过三个真实案例说明了这一点：成功地“战略决策”构建自定义终端输入以实现完全控制；在最初的挑战之后，迭代地发现最佳的 shell 交互设计；以及使用 SQLite 进行持久化的“无效方案”实验，最终回归到更简单的 JSONL 存储。文章强调，持续交付、愿意回退以及从“弯路”和“富有成效的失败”中学习，是这种 AI 驱动的开发模式的核心，在这种模式中，设计通常是通过实验而不是前期规划来发现的。

💡 主要观点

  1. AI 编码助手将开发瓶颈从实现转移到快速反馈环。 随着 AI 快速生成和重构代码，限制因素变成了团队交付、观察生产环境中的行为以及更新他们对需求理解的速度，从而强调了持续学习。
  2. 自定义工具决策可能是通过迭代改进获得回报的战略决策。 Anthropic 决定完全控制终端输入，这是一个大胆的决定，因为传统观点并不建议这样做。但这一决策最终被证明是成功的，因为它支持了高级功能和快速、复杂的更改，例如 Vim 模式和 Unicode 处理。
  3. 迭代实验和愿意回退对于发现最佳设计至关重要。 对于 shell 交互或持久化等复杂问题，最佳的解决方案是进行频繁的小更改和观察，并勇于撤销没有带来改进的更改。这样可以帮助我们区分有价值的探索和无效的尝试。

💬 文章金句

  • “实现曾经是循环中昂贵的部分。在工作流程中使用 AI 后，限制因素是你收集和响应反馈的速度。”
  • “你无法计划这种设计，而是通过实验发现它。”
  • “频繁地交付小更改，并且愿意在需要时取消交付，是我们使用 AI 进行开发的核心。构建、交付、观察和调整的循环是大部分价值出现的地方。”
