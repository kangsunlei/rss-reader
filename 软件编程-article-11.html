在 Cloudflare Workers 上运行 Node.js HTTP 服务器：全新支持

9/8/2025, 2:00:01 PM

📌 一句话摘要

Cloudflare Workers 现在支持 Node.js `node:http` 客户端和服务器 API，无需重写代码库即可便捷地迁移现有 Node.js 应用程序并将其部署到边缘。

📝 详细摘要

本文宣布 Cloudflare Workers 新增对 Node.js `node:http` 客户端和服务器 API 的支持，方便开发者将现有应用（如 Express.js、Koa）部署到边缘，无需大幅修改代码。它强调了零冷启动、自动缩放和更低延迟的优势。文章阐述了在 Workers 这种无服务器环境中适配 Node.js 基于 TCP 的 HTTP 模型的挑战。解决方案包括在 `fetch()` API 上构建客户端 API，并为服务器 API 创建桥接系统，其中 `listen()` 在内部注册服务器。它详细介绍了服务器 API 的两种集成方法：用于手动控制的 `handleAsNodeRequest` 和用于自动设置的 `httpServerHandler`，并为两者以及 Express.js 和 Koa.js 提供了代码示例。最后，它指出此功能通过 `nodejs_compat` 标志启用。

💡 主要观点

  1. Cloudflare Workers 现在支持 Node.js `node:http` 客户端和服务器 API。 这使得开发者能够将现有的 Node.js 应用程序（如 Express.js 和 Koa）部署到边缘，从而受益于零冷启动、自动缩放和更低延迟，而无需重写其代码库。
  2. 一种独特的桥接系统在无服务器环境中启用 Node.js HTTP 服务器。 由于 Workers 缺乏直接 TCP 连接，因此独特的桥接系统会在内部注册 `http.createServer()` 实例，将它们连接到 Workers 的请求处理模型，从而保持 Node.js 兼容性。
  3. 为 Node.js HTTP 服务器提供了灵活的集成选项。 开发人员可以选择 `handleAsNodeRequest` 进行手动集成以与其他 Worker 功能结合使用，或者选择 `httpServerHandler` 来自动、直接地部署 Node.js HTTP 服务器。
  4. Workers 上的 `node:http` 支持具有特定的当前限制。 虽然功能强大，但该功能具有局限性，例如 Agent API 实际不执行任何操作，并且缺乏对 Trailers、early hints、1xx 响应和 TLS 特定选项的支持，开发人员应该意识到这些限制。

💬 文章金句

  • 我们通过增加对 `node:http` 客户端和服务器 API 的支持，让在 Cloudflare Workers 上运行 Node.js 应用程序变得更加简单。
  • 这项重要补充将大家熟悉的 Node.js HTTP 接口带到边缘，让您能够以零冷启动、自动扩展和显著降低用户延迟的优势，在全球部署现有的 Express.js、Koa 等 Node.js 应用程序，无需重写代码。
  • 我们基于 Workers 原生 `fetch()` API 构建了这些 API，在保证 Node.js 兼容性的同时，实现了卓越的性能。
  • 由于 Workers 无法创建监听特定端口的传统 TCP 服务器，我们设计了一个桥接系统，将 Node.js 风格的服务器连接到 Workers 的请求处理模型。
  • 增加对 `node:http` 的支持，让我们更接近于将 Cloudflare Workers 打造成在边缘运行 JavaScript 的最佳平台的目标，无论您是构建全新应用还是迁移现有应用。
