真正的可编程 SASE 平台

3/2/2026, 2:00:08 PM

📌 一句话摘要

Cloudflare 推出“可编程 SASE”概念，将其安全平台与开发者平台集成，从而实现针对安全和网络策略的实时自定义逻辑。

📝 详细摘要

本文探讨了 SASE（安全访问服务边缘）从静态配置到可编程环境的演进。Cloudflare 认为，仅限于 API 和 Webhook 的传统可编程性已无法满足现代安全需求。相反，“真正的”可编程性涉及实时拦截安全事件，利用外部数据对其进行丰富，并在边缘执行自定义逻辑。通过利用 Cloudflare One 和 Cloudflare Workers 的统一架构，企业可以构建定制化的安全工作流，例如动态会话撤销或外部风险验证，而无需等待厂商特定的功能更新。文章包含了一个用于自动化设备会话管理的实际代码示例，并概述了到 2026 年深度集成的路线图。

💡 主要观点

  1. 真正的可编程性实现了由外部上下文增强的实时安全决策。 除了标准的 API 和 Webhook，真正的可编程性允许平台拦截请求并查询外部系统（如学习管理数据库），在请求完成前的毫秒内做出访问决策。
  2. SASE 与开发者平台之间的统一架构消除了系统断连带来的延迟。 由于 Cloudflare 的安全服务和计算平台运行在同一个全球网络和硬件上，自定义逻辑可以内联执行，无需将流量路由到独立云环境的额外开销。
  3. 可编程操作使安全团队能够超越二元的“允许或阻止”决策。 通过直接在安全策略中调用自定义代码（Workers），企业可以实现复杂的行为，如动态请求头注入、基于位置的控制，或根据特定业务逻辑定制的指导页面。
  4. 可编程平台解决了企业安全团队的“功能需求”瓶颈。 开发人员和安全架构师可以使用提供的构建块，按照自己的时间表构建和部署定制化解决方案，而无需等待厂商花费数月时间来实现某个小众集成。

💬 文章金句

  • 可编程性的真正价值在于能够拦截安全事件，利用外部上下文对其进行丰富，并实时采取行动。
  • 没有自有计算平台的独立 SASE 供应商要求你在单独的云中部署自动化，并接受往返延迟。
  • 企业安全的未来不是一个试图包揽一切的单体平台，而是一个可组合且可编程的平台。
  • 你的代码在边缘实时运行，并拥有对请求上下文的完整访问权限。
  • 安全性应该极其易于使用，但我们也知道“简单”并不意味着“一劳永逸”。
