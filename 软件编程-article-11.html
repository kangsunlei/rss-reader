Elastic 开源了基于认知科学的 Atlas Agent Memory

7/11/2026, 3:37:00 AM

📌 一句话摘要

Elastic 开源 Atlas，基于 Elasticsearch 实现智能代理的情景、语义、程序三类记忆，通过 MCP 集成及混合检索实现长期记忆存储与检索。

📝 详细摘要

文章介绍了 Elastic 开源的 Atlas 系统，这是一个构建在 Elasticsearch 上的智能代理记忆解决方案。Atlas 将记忆分为情景记忆（记录“发生了什么”）、语义记忆（记录“什么是真实的”）和程序性记忆（记录“什么有效”），并为每种类型维护独立的 Elasticsearch 索引。记忆的生成过程是把用户输入作为情景事件存储，部分经由 LLM 整合转化为持久的语义事实，同时更新程序性记忆的操作指南及其成功/失败计数。检索时采用 BM25 词汇搜索与 Jina v5 语义搜索的混合，再通过互逆排名融合（RRF）和跨编码器重排序器进行排序，并利用文档级安全（DLS）确保只检索属于当前用户的记忆。在问答评估中，Atlas 的 Recall@10 达到 0.89。文中还引用了 Hacker News 上关于使用 Elasticsearch 作为向量存储是否“大材小用”的讨论，指出在需要脚本评分等高级功能时，纯向量数据库可能力不从心，而 Elasticsearch 虽有维护成本但在复杂查询场景下更具优势。

💡 主要观点

  1. Atlas 将记忆分为情景、语义、程序三类，并分别存储在独立的 Elasticsearch 索引中。 这种分离使得每种记忆类型能够按照其自身的更新规则和生命周期进行管理，避免相互干扰。
  2. 记忆的生成依赖 LLM 进行整合：情景事件被转化为持久的语义事实，并更新程序性记忆的操作指南及其成功/失败计数。 通过这种机制，系统能够把短暂的交互转化为可检索的知识，并根据操作指南的历史表现动态调整检索优先级。
  3. 检索采用 BM25 + Jina v5 语义搜索的混合，再经 RRF 融合和跨编码器重排序，并通过文档级安全确保用户记忆隔离。 这种多阶段检索策略兼顾了关键词匹配与语义理解，提高了相关性排序的准确性，同时保证了多用户环境下的数据隔离。

💬 文章金句

  • 标准的解决方法是将先前的上下文塞入上下文窗口。但这种方法在成本、延迟以及“中间遗忘”效应（有广泛的记录）等方面都存在缺陷，即模型会忽略远离提示词边缘的事实。100 万令牌的上下文窗口只是一个临时记事本，而非存储系统......真正缺失的是长期记忆：一种能够跨越会话终点、支持长达数年的交互，并允许按内容、时间和用户检索事实的持久化存储。
  • 一旦需要脚本评分之类的功能，‘任何其他向量数据库’就会开始力不从心......这时问题就变成：‘为了性能，你是否需要[近似最近邻]？'...... 诚然，对于数量远超大多数人预期的向量而言，暴力搜索的性能表现确实不错，但如果你希望其延迟达到网页级水平，那么在数量远低于 100 万时，它肯定会遇到瓶颈。维护 Elasticsearch 固然需要成本，但选择一个性能不足的数据库，随后又不得不将其移植到合适的数据库上，同样会耗费大量的时间。
