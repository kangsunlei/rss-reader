别再迷信 Agent 的自主性了

10/29/2026, 5:30:00 AM

📌 一句话摘要

飞猪、货拉拉、江苏移动三位技术专家在 QCon 圆桌中共识：企业级 Agent 的核心壁垒不在模型自主性，而在于通过 Harness 划定确定性边界、构建双闭环迭代体系、萃取业务知识并对接存量系统，实现可验证、可追责的生产级落地。

📝 详细摘要

本文记录了 QCon 2026 上海站直播圆桌实录，NoDesk AI CTO 王仿主持，飞猪算法专家吕德涛、货拉拉技术总监亓隆基、江苏移动 AI 方向 CTO 王上淇共同探讨企业级 Agent 的边界与生产实践。核心观点包括：1) 模型能力越强越需明确边界，业务需确定性而非概率输出；2) 跨越聊天助手到执行任务的门槛是校验、权限控制、可追溯闭环；3) 边界划分原则：确定有解用工程/规则，开放性规划用 Agent，关键权益人工确认；4) 准率靠 Harness、评测体系、业务知识萃取保障，非单靠大模型；5) 自我优化需业务指标外环与 Agent 能力内环双闭环，离线黄金数据集回测防偷懒；6) 自主性非越强越好，需在受限工具集内发挥，防失控；7) 未来竞争力：模型定起点，Harness 定下限，双 Loop 定方向，业务知识萃取与系统对接定上限。

💡 主要观点

  1. 企业级 Agent 必须在确定性边界内运行，而非追求无限自主性 模型本质是概率预测，天然存在幻觉。真实业务（下单、支付、审批）要求确定性与可靠性，需通过 Harness 将模型不确定性限制在明确边界内：确定性环节（价格计算、库存校验、规则执行）用工程/求解器/规则引擎，开放性环节（意图理解、长尾表达、方案生成）交给模型，关键权益（钱包、盖章、合规）保留人工确认。
  2. 从演示到生产的关键跨越在于校验闭环、权限体系与可观测性 Agent 调用工具不等于能上线。飞猪用混合整数规划求解器保证组票可验证、可复算；货拉拉通过 AI 外呼实时规划解决长尾撮合，但需红线检测防错话；江苏移动要求所有 AI 操作保留原 GUI 兜底，且接口权限、MCP 能力权限显式管控，责任落人。可撤回性非充分条件，还需考虑恢复成本、可解释性、可复现性。
  3. 准确率靠业务知识萃取与 Harness 工程化，而非单纯依赖大模型 复杂场景（报关 200+ 字段、包材审核 60-70 项跨国法规）中，模型无法学到企业私有规则。实践路径：业务专家用 AI Coding 将规则固化为代码，主流程用 AI 串联，关键节点走确定性代码；建立评测体系（强代码校验+价值模型）、黄金数据集离线回测，防止自进化 hacking；技术人员需成半个业务专家才能落地。
  4. Agent 自我优化需双闭环：业务指标外环确保做功方向，Agent 能力内环提升执行质量 外环：建立业务指标漏斗（如撮合的接通率、成单率），定位掉点环节；内环：全链路可观测记录 Trace，人工标注+LLM-as-Judge 加速 Badcase 分析，萃取金牌销售话术策略。通用场景可尝试 Trace 自动优化 Harness/Skill，专一业务场景仍靠人工评估与测试集迭代。
  5. 企业 Agent 核心壁垒在于业务知识萃取深度、存量系统对接能力与流程责任对齐 模型是起点，Harness 定下限。上限取决于：能萃取多少隐性业务知识、找到哪个环节做功；能否用通用方式（类 Palantir 平台）梳理暴露信息化薄弱企业的能力；能否将智能体与原有业务流程挂钩，使责权清晰。飞猪强调垂类供给与行业知识可执行化，江苏移动强调数据资产自动化萃取与流程关联。

💬 文章金句

  • 业务场景更需要确定性和可靠性，这是模型天然不具备的，所以我们得有一个明确的边界，让模型的不确定性在确定的业务边界内进行。
  • 关键环节还是用规则的方式做，只是描述和生成规则用 AI，成本、边界、准确性都解决了，可解释、可撤回、可控也更强。
  • 涉及用户钱包权益的一定放在人这边；自由度高的，比如生成回复、澄清模糊意图、处理长尾表达，可以交给模型。
  • 企业 Agent 的壁垒，不是生成一份看起来不错的答案，而是企业自己的数据、工具、算法、业务规则、评测体系在真实世界里能不能成立。
  • 自主性是用来解决原来解决不了的问题的。所以自主性的上限，就是你希望它解决问题的灵活度，但要有门槛，没门槛就是失控。
