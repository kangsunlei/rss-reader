从 JS 云函数到 MCP：打造跨平台 AI Agent 工具的工程实践

12/12/2025, 4:01:00 AM

📌 一句话摘要

B 站团队通过构建在线 JS 云函数平台和接入 MCP 协议，实现了从 JS 云函数到跨平台 AI Agent 工具的演进，有效解决了 AI 工具开发中的重复工作、接口与能力不匹配等痛点。

📝 详细摘要

文章详细讲述了 B 站在构建 AI Agent 工具生态方面的工程实践，团队将内部的 AI 工具能力层划分为三个演进阶段：从 Flowise 中的 LangChain StructuredTool 扩展，到在线 JS 云函数 IDE 平台，再到最终接入 MCP 协议，实现跨平台 AI Agent 能力。核心痛点在于现有工具重复开发、AI 无法直接理解业务接口、JSON 响应对 AI 不友好以及工具缺乏资产化管理。解决方案是构建一个统一的 AI 工具能力层，通过 NodeVM 沙箱提供安全可控的 JS 运行环境，并自动化内网调用和 AI 友好结果转换。最后，为了实现工具的跨平台、跨模型、跨框架调用，引入了 MCP 作为统一插线板，并设计了代理层和身份鉴权机制，确保工具的复用性和安全性。

💡 主要观点

  1. 构建统一的 AI 工具能力层是解决 AI 应用开发痛点（重复开发、接口非能力化、JSON 非 AI 友好、工具非资产化）的关键。 文章指出，业务接口与 AI 所需能力之间存在语义鸿沟，且传统 JSON 返回格式对 AI 不友好，导致工具重复开发和管理混乱。统一能力层通过封装和标准化，将接口转化为 AI 可理解的能力，并提供 AI 友好的输出，从而提高开发效率和工具复用性。
  2. JS 云函数平台作为核心载体，利用 NodeVM 沙箱提供安全可控的 JS 执行环境和丰富的内网能力注入。 平台解决了早期 StructuredTool 的局限性，允许开发者在线编写 JS 函数，并通过 NodeVM 进行安全隔离和依赖白名单控制。同时，注入的`$yuumi`（内网调用）、`$json2MarkdownTable`（结果转换）等能力，极大地简化了 AI 工具的开发流程和输出优化。
  3. MCP 协议的引入实现了 AI Agent 工具的跨平台、跨模型、跨框架调用，提升了工具的互操作性和共享能力。 MCP 作为“大模型+工具调用”的统一插线板，解决了工具与特定 AI 工作流绑定、无法复用的问题。B 站通过构建 MCP 网关和 Server，将 JS 云函数平台上的工具代理到 MCP 协议上，使其能被任何支持 MCP 的 Agent 或 Studio 调用，形成企业内部的 AI 工具市场。
  4. 严密的安全鉴权机制（注册阶段签名、调用阶段统一 Proxy）是跨平台 AI 工具平台稳定运行的重要保障。 考虑到 MCP 作为外部服务访问入口的特性，B 站设计了注册时`sign`校验和调用时通过 Proxy 层进行鉴权、注入会话信息（如`$cookie`）的机制，确保工具的对外暴露在受控的安全体系内，避免风险。
  5. 从 JS 云函数到 MCP 的演进路径，将“接 AI”转换为“写一个云函数”，极大降低了业务方开发 AI 能力的门槛。 文章总结了这一路径带来的统一工具定义、执行、调用协议和共享方式，最终让业务同学只需关注如何以 JS 函数形式提供能力，而无需关心复杂的 AI 集成细节，显著提升了 AI 工具的生产效率和生态建设。

💬 文章金句

  • 缺少一个可以写工具、管理工具、发布工具、复用工具的统一能力层。而我们做的，就是让这件事：只需写一段 JS 函数。
  • AI 友好的格式是：Markdown 表格、简洁的自然语言、提炼过的信息，而不是整包 JSON。
  • MCP 全称 Model Context Protocol，可以简单理解为：给'大模型 + 工具调用'定义了一个'统一插线板'。
  • 我们最终得到了：一个统一的工具定义方式：元信息；一个统一的执行方式：NodeVM；一个统一的调用协议：MCP；一个统一的共享方式：工具市场；一个统一的安全体系：sign + cookie。
  • 让业务同学不再关心'怎么接 AI'，而是只需要关心'我能给 AI 提供什么能力'。把写一个 JS 函数，变成给 AI 加一个新能力。
