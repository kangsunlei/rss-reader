AI Agent & Skill 测评方案及落地实践

6/16/2026, 9:33:00 AM

📌 一句话摘要

本文系统化地介绍了腾讯 TEG 团队在 AI Agent 测评领域的体系化实践，提出了一套由确定性评分器、Rubric 评分器和人工评分器三类组合的完整测评框架，覆盖功能正确性、过程质量、效率成本、鲁棒性安全、体验对齐五大维度，并已在 TPerf 性能分析 Agent 项目中落地验证。

📝 详细摘要

文章从 AI Agent 在生产环境中面临的非确定性、黑盒化、错误级联放大三大痛点出发，论证了建立自动化评估体系的必要性。核心贡献在于提出了一套完整的测评框架：首先定义了「确定性评分器 + Rubric 评分器 + 人工评分器」三类评委的组合策略，明确各自的适用场景与优先级；其次将评估维度拆解为功能正确性、过程质量、效率与成本、鲁棒性与安全、体验与对齐五个大类，并给出每个维度的子项、评测方法与典型指标。在实施层面，文章详细介绍了用例集设计的四大场景（触发、核心逻辑、产物质量、异常容错）、评分规则的负分制设计、基线的建立与更新机制，以及工程落地的关键问题（Trace 输出、环境隔离、稳定性评估、报告输出）。最后以 TPerf 性能 AI 分析 Agent 为实战案例，展示了如何将通用方法论落地为具体的评分标准、用例组织和基线管理流程。全文结构清晰、案例详实，是一份可直接复用的 Agent 测评实践指南。

💡 主要观点

  1. Agent 测评必须采用「确定性评分器 + Rubric 评分器 + 人工评分器」三类组合。 单一评分手段无法兼顾 Agent 输出的硬指标（文件存在、调用正确）和软指标（推理合理性、建议质量），三类评委各有侧重，优先级为确定性 > Rubric > 人工。
  2. 评估维度应覆盖功能正确性、过程质量、效率成本、鲁棒性安全、体验对齐五大类。 这五个维度从「做对了吗」到「好用吗」逐层递进，P0 优先保证功能正确性和鲁棒性安全，P1 覆盖过程质量和效率成本，P2 按需补充体验与对齐。
  3. 用例集设计需覆盖触发、核心逻辑、产物质量、异常容错四大场景，且核心逻辑用例量最大。 每个场景都包含正向和负向用例，核心逻辑用例需根据业务分支流程图逐一覆盖，数量通常是其他三类场景之和的 2-3 倍。
  4. 基线管理是测评体系的核心，通过「先跑出来，再确认」的方式建立预期过程和结果。 基线是单个用例执行一次后经人工确认的预期快照，后续每次执行都与基线对比，同时服务于确定性评分器和 Rubric 评分器。
  5. 测评体系需区分能力测评和回归测评，能力用例通过率稳定后「毕业」到回归套件。 能力测评用于指导优化方向，回归测评用于防御漂移，回归用例集只增不减，CI 每次运行。

💬 文章金句

  • Eval（评估）= Agent 输入 → 执行 → 捕获执行过程（Trace + 产物） → 一组检查规则 → 可对比的分数
  • 能用代码判断的绝不用模型，必要时用模型，人工用于校准。
  • 每次变更都能快速跑出一个可比较的分数，用数据代替直觉，用全量代替抽查。
