AIGC 原生视频的双螺旋 Loop Engineering 实践

11/25/2026, 10:00:00 AM

📌 一句话摘要

本文介绍了百度基于 Hermes Agent 构建的 Loopy 双螺旋系统，通过分离产线修复与标准演进两条路径，解决了 AIGC 视频产线中裁判成长与被收买的难题，提升了视频可用率至 100%。

📝 详细摘要

文章聚焦 AIGC 视频产线的质量治理挑战，指出传统自我改进 Agent 易陷入 Goodhart 定律——学会讨好固定评估标准。为此，Loopy 系统将产线和裁判拆为两条螺旋：效果螺旋在冻结标准下修复产线，标准螺旋从 Good/Bad Case 中迭代出新标准。两者共享证据但隔离写权限，确保修复 Agent 无法篡改评估。实现上，Loopy 采用服务端质量合同强制约束，Hermes Agent 提供长期记忆与技能进化。通过实际案验，分镜位置问题在标准先行、产线后修的流程下，综合视频可用率从 92% 提升至 100%。

💡 主要观点

  1. 双螺旋架构分离产线修复与标准演进 效果螺旋在冻结的验收标准下修复产线，标准螺旋则从真实案例中迭代出新标准，两者共享证据但不共享修改权限，防止修复 Agent 通过放宽标准获取虚假成功。
  2. 服务端质量合同强制权限隔离 所有冻结、写权限、版本约束通过服务端合同实现，Agent 无法绕过，确保每轮修复基于固定、可审计的前置条件。
  3. 先补标准再修产线的 Evaluator Evolution 流程 当现有标准无法判定 Bad Case 时，Loopy 先生成 Good Case 样本、草拟评分细则、经元评估检验并人工晋升为新标准，方可进入产线修复。
  4. 持续的 Agent 学习能力支撑长期迭代 Hermes Agent 提供会话延续、长期记忆和行为进化，使同一 Agent 能跨轮保持产线语境，逐步积累有效方法形成可复用技能。
  5. 严格的证据驱动循环防止无效重复 每轮修复必须提出可证伪的因果假设，工程审查与固定评估双重通过后方可结束；否则继续循环，避免沿同一改法无效跑轮。

💬 文章金句

  • 模型不写文本，只输出概率。
  • 约束越少，系统在自己的考卷上越成功，换一份考卷越失败，花的钱还更多。
  • 裁判可以变，但只能在下一轮生效，修复 Agent 永远无法在看到结果之后再挑一把对自己有利的尺子。
  • 先造尺子，再修产线。
  • 按证据循环，不按信心循环。
