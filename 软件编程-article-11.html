JavaOne 2025：全 Java 中的函数和内存访问

4/4/2025, 12:00:00 AM

📌 一句话摘要

介绍了 JDK 22 中外部函数与内存访问 API (FFM API) 的设计、使用方法和优势，该 API 旨在更安全高效地替代 JNI，实现 Java 与原生代码互操作。

📝 详细摘要

本文详细介绍了 JavaOne 2025 上关于外部函数与内存访问 API (FFM API) 的演讲内容。FFM API 在 JDK 22 中发布，是 Project Panama 的重要组成部分，旨在替代传统的 Java 本地接口 (JNI)。文章首先回顾了 JNI 的不足，例如需要编写和维护 C 代码、数据传递效率低等问题。随后，详细介绍了 FFM API 的核心接口，包括 MemorySegment、Arena（内存管理区域）和 ValueLayout（值类型布局），并通过代码示例展示了如何使用这些接口进行内存访问和管理。其中，通过 Arena 接口实现自动或确定性的内存释放，提高了内存管理的效率和安全性。此外，文章还介绍了 jextract 工具，它可以根据原生库头文件自动生成 Java 绑定代码。最后，总结了 FFM API 的优势，包括安全高效的内存访问、无需编写原生代码以及为 Project Panama 互操作性奠定基础。

💡 主要观点

  1. FFM API 旨在替代 JNI，解决 JNI 在内存安全、性能和开发效率方面的不足 JNI 存在编程模型复杂、维护成本高昂、数据传输效率低下以及内存安全性不足等问题，FFM API 通过纯 Java 方式提供更安全高效的互操作方案。
  2. MemorySegment、Arena 和 ValueLayout 是 FFM API 的核心接口 MemorySegment 用于访问连续内存区域，Arena 用于管理内存生命周期，ValueLayout 用于描述基本数据类型的值布局，三者协同实现内存的安全访问。
  3. jextract 工具可以简化原生库的 Java 绑定过程 jextract 可以根据原生库头文件自动生成 Java 绑定代码，减少了手动编写 JNI 代码的工作量，提高了开发效率。
