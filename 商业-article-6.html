对话腾讯「龙虾」负责人：没用一行 OpenClaw 代码

3/13/2026, 6:13:34 PM

📌 一句话摘要

腾讯 WorkBuddy 负责人详述了其 AI Agent 产品的自研路径、安全架构及产品哲学，强调「龙虾」应被视为一种安全可控的自动化概念而非单一工具。

📝 详细摘要

本文通过对腾讯 WorkBuddy 负责人汪晟杰的深度访谈，揭示了腾讯在 AI Agent（俗称「龙虾」）领域的战略布局与技术思考。文章明确了 WorkBuddy 是基于腾讯 CodeBuddy 基建的完全自研产品，未采用 OpenClaw 源码，从而规避了 AGPL 协议风险。在产品逻辑上，WorkBuddy 选择了介于人工与全托管之间的半自动化路径，重点通过「非透传」架构解决 Agent 的安全隐私隐患。汪晟杰认为「龙虾」代表的是一种自动化概念，未来的核心竞争力不在于单一的全能大脑，而在于不同触点间知识上下文的无缝流动，以及与具体行业场景的深度结合。

💡 主要观点

  1. WorkBuddy 坚持完全自研路径，规避开源协议约束与技术依赖。 产品基于腾讯 CSIG 已有的 CodeBuddy 技术底座构建，未引用 OpenClaw 源码，从而在法律层面不受 AGPL 协议限制，确保了商业化路径的独立性与自主性。
  2. 采用「非透传」架构设计，针对性解决 AI Agent 的安全预警风险。 针对 Agent 获取本地权限可能导致的数据泄露风险，WorkBuddy 弃用透传模式，改用安全的机器人推送和企业级权限分级配置，确保数据流向在可控范围内。
  3. 产品定位倾向于「半自动化」，在自主性与安全性之间寻找平衡点。 不同于追求完全托管的激进方案，WorkBuddy 认为当前用户核心需求是搜索与内容重组，通过引入用户确认环节，避免 AI 在未经授权的情况下执行高风险操作。
  4. 提出「上下文流动」概念，认为 Agent 的未来在于知识体系的连续性。 未来 AI 不会由单一产品统领，而是由多个垂类 Agent 触点组成，核心价值在于用户个人偏好和记忆（上下文）能在不同 Agent 之间流动，实现场景聚焦且好用。

💬 文章金句

  • 龙虾这个词，是中国用户给这类 AI Agent 产品起的外号……更像一个能接管鼠标键盘的数字雇员。
  • 百分之百自研，没有用过任何一行 OpenClaw 的源码。能做到这一点，是因为我们本身就有 CodeBuddy 的整套基建。
  • 龙虾产品的安全隐患，核心是「透传」——你的本地工作环境和远端发生连接，数据走向不可控。
  • 龙虾不是个产品，龙虾 (Claw) 是一种概念。而且，龙虾不等于 OpenClaw。
  • 连接的不是 AI 本身，而是 AI 大脑里的知识体系——上下文工程是流动的。
