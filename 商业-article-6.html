“我在 GitHub Actions 里运行的代码，到底是谁的？”

3/31/2025, 10:33:08 AM

📌 一句话摘要

文章揭示了 GitHub Actions 中可变引用带来的安全隐患，并提供了通过脚本排查和使用不可变引用的解决方案。

📝 详细摘要

文章指出了 GitHub Actions 中使用可变 Git 标签作为 Action 版本引用时存在的安全隐患，攻击者可能通过修改标签指向的 commit，在不知情的情况下更改工作流执行的代码，导致敏感信息泄露。文章建议使用不可变的 Git 提交 ID 来引用 Action，以确保代码的安全性。同时，作者提供了一个 Shell 脚本，该脚本不仅用于检查本地仓库中工作流文件使用的 Action 依赖，还可以帮助开发者评估 Action 的来源和安全性。文章还强调了掌握 Unix 文本处理工具的重要性，以便快速分析和处理数据。

💡 主要观点

  1. GitHub Actions 的可变引用存在安全风险 使用 Git 标签作为 Action 版本引用，可能被恶意修改，导致工作流执行的代码发生变化，存在安全隐患。
  2. 使用不可变引用（Git 提交 ID）可提高安全性 直接指定 Git 提交 ID，确保每次运行的代码一致，避免因标签变更导致的安全问题。
  3. 脚本检查 Action 依赖可及时发现安全风险 通过脚本分析工作流文件，统计使用的 Action，并评估其来源和安全性，降低潜在风险。
  4. 通过掌握 Unix 工具和管道可以更灵活地处理数据并构建一次性脚本 掌握 Unix 文本处理工具和管道，即使在 AI 时代，依然是处理数据的一种强大而灵活的方式，可以快速拼凑出一次性的数据处理脚本。

💬 文章金句

  • 你在 GitHub Actions 里运行的代码，到底是谁的？它们真的安全吗？
  • 如果你在工作流（workflow）中使用了这个受影响的 Action，它就会把你的敏感信息泄露到构建日志中。
  • 指定确切的提交 ID 能确保代码不会意外更改，可提高安全性。
  • 即使在 AI 时代，它们依然是处理数据的一种强大而灵活的方式，可以快速拼凑出一次性的数据处理脚本。
  • 我强烈推荐你掌握 Unix 文本处理工具和管道。
