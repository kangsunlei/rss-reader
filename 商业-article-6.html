Box CEO：未来 SaaS 的用户，可能不再是人，而是成千上万个 Agent 丨 a16z

4/30/2026, 1:58:00 PM

📌 一句话摘要

本文基于 a16z 播客对话，分析了 AI Agent 进入企业软件面临的真实摩擦，指出 Agent 将重塑 SaaS 产品设计、权限模型和成本结构，但扩散速度受制于组织惯性。

📝 详细摘要

本文整理自 a16z 播客，嘉宾包括 Box CEO Aaron Levie、前微软 Windows 负责人 Steven Sinofsky 和 a16z 合伙人 Martin Casado。核心观点是：AI Agent 进入企业软件的速度会比硅谷乐观预期更慢，因为 SAP、Workday 等系统沉淀了多年业务经验，无法被简单重写。未来软件的用户将从人扩展到成百上千个 Agent，产品设计需优先考虑机器调用的稳定性、权限和审计。普通员工难以将工作流程算法化，Agent 的普及需要系统型人才先行搭建模板。企业最担心失控的集成和权限问题，Agent 会选择后端而非界面，成本管理将成为工程新常态。文章最后指出，中间层不会轻易消失，新公司仍有机会从第一天起将 Agent 作为劳动力。

💡 主要观点

  1. AI Agent 进入企业系统的速度会比预期慢，因为核心系统无法被简单重写。 SAP、Workday 等企业软件沉淀了多年业务经验、审批流程和组织规则，数据接口只是其中一部分，无法靠 vibe coding 替换。
  2. 未来软件的用户将从人扩展到成百上千个 Agent，产品设计需为机器用户优化。 Agent 通过 API、CLI、MCP 等入口工作，产品需考虑任务权限、速率限制、回滚机制和审计日志，机器用户的体验将像前台一样重要。
  3. 普通员工难以将工作流程算法化，Agent 普及需要系统型人才先行搭建模板。 大多数岗位不要求算法式思考，组织内需先出现少数人将工作拆解为可复用动作，其他人再调用这些能力。
  4. 企业最担心失控的集成和权限问题，Agent 的行为需要完整审计和可撤销。 Agent 创建新集成可能破坏核心记录系统，企业需要比员工账号更细的身份隔离和可观察性，权限模型将变得复杂。
  5. Agent 会选择后端而非界面，成本管理将成为工程新常态。 Agent 看重语义、成本、耐久性和可靠性，而非 UI 体验。工程计算预算将成为管理重点，token 浪费是探索的代价。

💬 文章金句

  • AI 能力扩散会比硅谷很多人想得更慢。
  • 如果 Agent 比人多一百倍或一千倍，软件就必须为 Agent 而建。
  • 以为可以靠 vibe coding 搞出一个 SAP，实在太荒唐了。
  • 算法式思考，对绝大多数有工作的人来说都非常非常难。
  • Agent 不会说这个界面很好；它会看成本参数、耐久性和可靠性。
