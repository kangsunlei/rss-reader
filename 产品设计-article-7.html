模型越聪明，为什么 Prompt 和 Skill 越要做减法？

9/12/2026, 6:40:15 AM

📌 一句话摘要

随着大模型能力的跃升，Prompt 与 Skill 的设计逻辑正从“能力补丁”转向“背景与边界定义”，开发者应通过删除失效规则、采用渐进式加载及明确决策边界来为 AI 工作流科学瘦身。

📝 详细摘要

本文探讨了在模型能力持续增强的背景下，传统的冗长 Prompt 和复杂的 Skill 规则如何从“助力”转变为“负担”。通过分析 Claude Code 适配新模型时删除 80% 系统提示词的案例，以及 ETH Zurich 关于上下文文件增加成本却未显著提升成功率的研究，文章指出：旧有的“能力补丁”类指令（如强制执行步骤、情绪化鼓励）会诱发模型执行无效行动并增加推理成本。作者提出了 Prompt 瘦身的三个核心保留维度：模型无从知晓的内部信息、必须由人做出的决策、以及不可允许临场发挥的安全与合规边界。文章建议采用“最小版本测试”的方法，通过移除旧规则并逐条恢复的方式，实现 AI 工作流的优化。

💡 主要观点

  1. Prompt 的构成正发生从“能力补丁”到“任务定义”的范式转移 过去需要大量指令来纠正模型“不会做”的行为（能力补丁），而新一代模型已能自然完成这些动作；现在的重点应转向提供模型“无从知晓”的业务背景与任务定义。
  2. 冗余指令会通过诱发无效行动增加 AI 的执行成本 模型执行能力越强，对指令越敏感。含糊或冲突的规则、过度的测试要求会触发模型执行额外的探索、测试或推理步骤，导致成本上升（如研究显示增加上下文文件可能使成本增加 20% 以上）却不一定提升成功率。
  3. 有效的 Prompt 与 Skill 应聚焦于三个核心维度 应保留：1. 组织内部事实与项目背景；2. 必须由人做出的目标、优先级与验收标准；3. 安全、权限与合规等硬边界。其余泛泛的角色设定和僵硬步骤应优先清理。
  4. 采用“渐进式加载”与“消融测试”进行工作流优化 Skill 应设计为按需加载的路由器，而非一次性塞入全部资料；优化过程应模仿 Claude Code 的做法，先移除原有提示，再根据实际失败情况逐条恢复必要指令。

💬 文章金句

  • 模型越聪明，人越需要说清目标、背景和边界，也越需要克制自己规定每一个步骤的冲动。
  • 过去需要人一步步教模型如何做，现在更需要人说清楚做什么、为什么做、哪些边界不能越过，以及做到什么程度才算完成。
  • 好的 Prompt 不以长度取胜，好的 Skill 也不以规则数量取胜。
  • 模型已经能够处理的判断，继续被步骤锁死，反而会压缩它寻找更短路径的空间。
