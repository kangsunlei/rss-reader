📌 一句话摘要

本文以 OpenClaw 创始人斯坦伯格的争议推文为引，系统介绍 AI Agent 领域的新概念「loop 工程」，解释其与提示词工程的区别，并拆解设计有效 loop 的五大核心组件。

📝 详细摘要

文章从 OpenClaw 创始人斯坦伯格一条引发 800 万次浏览的推文切入，引出 AI Agent 领域关于「提示词已死」的争议话题。作者首先澄清 loop 工程的概念：不同于传统编程中执行固定指令的循环，Agent loop 是执行「目标」的闭环机制（目标→行动→观察→评估→修正→下一轮行动），让 Agent 在动态环境中自主迭代。文章对比了提示词工程与 loop 工程的工作方式差异，指出后者更适合处理开放性任务。随后，作者详细拆解设计有效 loop 的五大组件：清晰可验证的目标、上下文管理（以 Ralph loop 的锚点文件重置为例）、匹配任务的工具集、自动化评估机制、以及多种停止条件（成功/失败/资源限制/风险检查点）。文章还介绍了斯坦伯格提出的「loop 监督 loop」的多层架构，以及 Codex 和 Claude Code 对 /goal 命令的产品化实践。整体上，本文是对 loop 工程这一新兴概念的系统性科普与解读。

💡 主要观点

  1. Loop 工程的核心是让 Agent 在闭环中自主迭代，而非依赖单次提示词的完美性。 Agent loop 通过目标→行动→观察→评估→修正的循环，让 Agent 在多次迭代中逼近正确答案，适合处理没有唯一正确路径的开放性任务。
  2. 设计有效 loop 需要五大组件：目标、上下文管理、工具、评估、停止条件。 清晰可验证的目标是锚点；上下文管理需解决脏/少/随机问题；工具集需精挑细选；自动化评估是灵魂；多种停止条件防止死循环或无限改进。
  3. Loop 工程不是取代提示词工程，而是将提示词从核心降级为输入之一。 提示词仍然是表达意图的主要方式，但 Agent 的核心能力转向在 loop 框架中自主决策和迭代，而非依赖单次提示词的完美性。
  4. 斯坦伯格提出「loop 监督 loop」的多层架构，实现自动调度与协调。 总 loop 负责观察全局、分发任务、检查进度，子 loop 各自运行，形成可长期运行、互相协作的 AI 工作系统。

💬 文章金句

  • 你不应该再给编程 Agent 写提示词了。你应该设计循环来提示词你的 Agent。
  • Agent loop，其实和编程里的循环（loop）差不多。在传统编程里，循环的本质是让机器重复执行明确的指令序列。在 AI Agent 的语境里，loop 也是重复执行。但 Agent 里的 loop 并非执行'指令'，它执行的是'目标'。
  • loop 工程就是给 Agent 加一个框架，让它知道每一轮应该看什么、做什么、怎么判断、什么时候停。
