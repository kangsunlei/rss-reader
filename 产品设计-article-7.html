设计系统中的本地化集成实践 — Smashing Magazine

📌 一句话摘要

案例研究展示如何运用 Figma 变量和设计标记解决多语言设计中的文本溢出和右向排版等挑战

📝 详细摘要

本文详细介绍了 SAS 两位设计师构建全球化设计系统的实践经验。他们利用 Figma 变量和设计标记解决了文本溢出、右向排版布局和字体适配等问题。文章系统性地记录了从使用 JSON 文件和 Tokens Studio 插件进行初始化配置，到实现界面密度调节，以及克服 Figma 在文字样式变量和孤立变量方面的技术限制的全过程。核心解决方案包括按语言区域重构 JSON 文件结构（西欧、中文、中东等分组）以及手动计算行高等技术细节。本文为处理设计系统国际化和本地化的从业者提供了极具参考价值的实践指南。

💡 主要观点

  1. 设计标记和 Figma 变量实现动态多语言适配 使用语义化设计标记和变量可以使设计动态适配不同语言环境、主题和显示密度，同时保持视觉一致性
  2. 语言特性文字样式需要专业化的标记管理 不同语言需要特定的字体系列、字重和行高设置，这需要精细化的标记管理和大量手动计算工作
  3. 基于语言区域的 JSON 结构优化提升本地化效率 在 JSON 文件中采用区域分组策略（西欧、中文、中东等）可简化管理复杂度，同时保留必要的区域本地化定制
  4. 应对 Figma 平台限制的创新解决方案 文字样式变量和孤立变量的技术限制需要通过像素级行高计算等手动方案和插件集成来解决
  5. 本地化考量应前置到设计系统规划阶段 在设计系统架构阶段就内置本地化能力可避免后期重构成本，界面密度调节的实现就是典型案例

💬 文章金句

  • 随着 Figma 变量的推出和设计标记技术的发展，我们为设计师开拓了新的可能性。我们构建了一个可以动态切换主题、显示密度甚至语言环境的 Figma 设计系统。
  • 本地化（L10n）是指针对特定语言、地区或文化进行设计适配的过程，包括文本翻译、布局调整以及确保视觉元素的文化适宜性。
  • 国际化（I18n）是前期准备阶段，确保设计方案能够灵活适应不同语言和地区的需求。
  • 文字样式变量虽然在理论上很有前景，但实际应用效果欠佳。例如 Figma 默认的'auto'行高系数为 1.2，低于 WCAG（网页内容可访问性指南）规定的 1.5 最低标准。
  • 孤立变量会导致变量列表冗长且难以管理。设计师很难区分哪些是有效变量，哪些是废弃变量。
