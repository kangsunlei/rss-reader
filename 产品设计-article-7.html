关于 T3 Code 和 Amp 的可靠性比较

11/20/2026, 1:39:57 AM

📌 一句话摘要

作者认为 T3 Code 的第三方 agent 链接方式（ACP）不够可靠，相比之下 Amp 提供了更为稳定、安全的集成，且不会进行违规的第三方接入，例如已移除的 omp 接入 Cursor 功能。

📝 详细摘要

这条推文针对 AI 编程辅助工具的可靠性进行了分析。作者提到了一些用户关于 T3 Code 性能和稳定性的质疑，而自己则对 Amp（可能指 Thought 或其他 AI 助手）的本地化处理（hardness）表示满意。文中明确指出，Amp 不会进行违规的第三方接入，并举例说明了之前被移除的违规行为（如 omp 接入 Cursor），以此来强调平台的安全和合规性。

💡 主要观点

  1. T3 Code 的第三方 agent 链接方式（ACP）存在可靠性问题。 作者观察到许多用户对 T3 Code 的表现持怀疑态度，认为它在链接第三方服务方面不够稳定或安全，无法满足开发者的需求。
  2. Amp 提供了更为安全和可靠的集成方案。 相比之下，Amp 的本地化处理（hardness）被作者认为是相当优秀的。更重要的是，Amp 坚持不进行违规的第三方接入，从而保证了平台的完整性和安全性。

💬 文章金句

  • ACP 这种链接第三方 agent 的方式最不靠谱了
  • Amp 是自己的 hardness，相当好用。
  • 而且他们也不会做任何违规的第三方接入，比如 omp 接入 Cursor 其实就是违规的，Amp 直接去掉了。
