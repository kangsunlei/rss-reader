SaaS 做 AI，你做到哪一层了？

8/14/2026, 1:26:00 AM

📌 一句话摘要

本文将 SaaS 的 AI 产品化路径系统拆解为四层台阶（API、CLI/MCP、Agent、A2A），并为资源有限的中小 SaaS 企业提供了一套务实的落地路线图。

📝 详细摘要

文章深入探讨了 AI 时代 SaaS 厂商面临的入口迁移焦虑。作者指出，用户交互入口正从门户、搜索、应用商店向 AI Agent 迁移，SaaS 产品未来大概率将被 Agent 调用而非人直接操作。为此，作者将 SaaS 的 AI 产品化过程划分为四层台阶：第 0 层 API（能力地基）、第 1 层 CLI 与 MCP（能力交付方式）、第 2 层 Agent（虚拟员工）以及第 3 层 A2A（Agent 间协作）。文章重点澄清了两个行业误区：一是辨析了 CLI（适合本地/单用户）与 MCP（适合多租户/安全隔离）的场景差异；二是明确了 A2A 与 MCP 的主从与协作关系。最后，作者为中小 SaaS 企业给出了「补齐 API、做 MCP、接入生态、静待 A2A」的务实落地建议。

💡 主要观点

  1. AI 时代正在发生入口迁移，SaaS 的产品未来大概率是被 Agent 调用而非人直接操作。 从门户时代的推荐位、搜索时代的 SEO、移动时代的 ASO，到如今的 Agent 生态，每一次入口迁移都决定了企业的生死。SaaS 必须将自身能力以 AI 可理解的方式暴露出来，才能在新入口中被优先调用。
  2. SaaS 的 AI 产品化可分为四层台阶，API 是最容易被低估的地基。 这四层分别是：API（地基）、CLI/MCP（交付入口）、Agent（虚拟员工产品）和 A2A（跨系统协作）。如果核心功能没有对应的 API 接口，后续的 AI 接入都只是空中楼阁。
  3. CLI 与 MCP 并非替代关系，而是取决于 Agent 替谁干活。 CLI 继承执行环境凭证，适合本地/单用户的高效执行；而 MCP 天生为多租户设计，支持 OAuth 授权、隔离与审计，是 SaaS 厂商对外开放能力、保障客户数据安全的主干。
  4. 中小 SaaS 企业的 AI 落地应遵循「补 API、做 MCP、接生态、等 A2A」的务实路径。 优先补齐 90% 以上的 API，选择高频场景做 MCP 接入主流平台，利用平台解决协作问题，而无需在早期盲目自研复杂的 A2A 协作协议。

💬 文章金句

  • 你的产品未来大概率不是被「人」打开，而是被「Agent」调用。界面会贬值，但数据和能力不会。
  • CLI 是「自己人直接上手干活」，MCP 是「对外开放的标准接口」——一个讲效率 and 成本，一个讲标准化 and 多租户。
  • 停在工具层，你还会被上游 Agent 双重收割——别人调你的工具，编排流程的利润归了别人。
  • AI 产品化的终点不在协议里，在你能把一个「员工」真正卖出去的那天。
