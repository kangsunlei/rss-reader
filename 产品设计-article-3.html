📌 一句话摘要

本文提出使用 CSS 自定义属性的“关键帧 Token”来标准化和管理跨项目的动画，解决重复定义和全局作用域冲突等常见问题。

📝 详细摘要

本文旨在解决前端开发中普遍存在的动画管理问题，特别是 `@keyframes` 定义的重复和全局作用域冲突。文章强调，分散且非标准化的动画会导致开发时间浪费、维护成本增加以及行为的不可预测性，在组件化架构中尤其如此。为此，本文提出将动画视为“关键帧 Token”，类似于颜色和间距的设计 Token。通过将动态 `@keyframes` 定义集中在共享样式表中，并利用 CSS 自定义属性，开发人员可以创建灵活且可复用的动画（例如，淡入、滑入、缩放、旋转、脉冲、弹跳、弹性），以适应特定的用例。本文还深入探讨了 `animation-composition`（动画合成）等高级主题，用于在同一属性上组合动画，并阐述了变换顺序对于可预测的复合变换的重要性，文中提供了实际案例与代码示例。这种方法能够显著提高跨项目的动画一致性、可维护性和灵活性。

💡 主要观点

  1. 动画管理问题源于 `@keyframes` 的重复定义和全局作用域冲突。 未管理的 `@keyframes` 定义会导致代码冗余、难以更新，并可能由于 CSS 的全局作用域而导致意外覆盖，这在组件化开发中尤其突出。
  2. 使用 CSS 自定义属性的“关键帧 Token”实现动画标准化。 通过在共享样式表中集中管理动态 `@keyframes` 定义，并通过 CSS 变量使其可自定义，可以提高一致性，减少重复，并有效解决全局作用域问题。
  3. 诸如 `animation-composition`（动画合成）和变换顺序等高级 CSS 功能可以实现复杂的动画效果。 `animation-composition: add` 允许在同一属性上组合多个动画，而理解变换顺序对于实现可预测的复合变换至关重要。

💬 文章金句

  • 通过整合和标准化关键帧，可以将通常混乱且难以管理的内容转化为清晰且可预测的系统。
  • 这种关键帧重复定义会引发一个潜藏在表面之下的更为隐蔽的问题：**全局作用域陷阱。**
  • 解决这一问题的答案非常简单：**将预定义的动态关键帧存储在共享样式表中。**
  • 可以将其视为**关键帧 Token**。正如我们使用 Token 来表示颜色和间距一样，而且许多开发者已经使用 Token 来表示动画属性（如持续时间和缓动函数），为什么不也使用 Token 来表示关键帧呢？
  • 使用关键帧 Token 的一大优势在于它们可以无缝地彼此集成。
