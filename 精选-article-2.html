Manus 创始人手把手拆解：如何系统性打造 AI Agent 的上下文工程？

7/19/2025, 4:30:00 AM

📌 一句话摘要

Manus 创始人分享 AI Agent 上下文工程核心实践，详细阐述了围绕 KV-Cache 优化、行为约束、文件系统作为记忆、注意力操控、错误保留及 Few-Shot 陷阱的实战经验。

📝 详细摘要

文章由 Manus 联合创始人兼首席科学家 Peak 撰写，深入剖析了构建高性能 AI Agent 的上下文工程核心实践。作者首先解释了选择上下文工程而非从头训练模型的原因，强调其迭代速度快且能保持与底层模型正交性。随后，文章详细介绍了六个关键实践：首先，围绕 KV-Cache 设计以优化延迟和成本，通过保持提示前缀稳定、追加式上下文和明确标记缓存断点。其次，通过掩码而非移除的方式约束行为选择，避免动态增删工具导致的 KV-Cache 失效和模型混乱。第三，将文件系统视为终极上下文，实现无限容量、持久化和可还原的记忆，并探讨其对未来状态空间模型（SSM）的意义。第四，通过复述（如创建并更新 todo.md 文件）操控模型注意力，将核心目标推入模型近期注意力范围，减少任务偏离。第五，保留错误内容，让模型从失败中学习，提升错误恢复能力和适应性。最后，避免被 Few-Shot 反噬，通过引入上下文多样性来打破固定模式，防止模型过度泛化。文章总结强调了上下文工程对 Agent 运行速度、恢复能力和可扩展性的决定性作用，提供了宝贵的实战经验。

💡 主要观点

  1. 围绕 KV-Cache 优化是生产级 AI Agent 性能关键。 通过保持提示前缀稳定、追加式上下文等策略，可显著降低推理延迟和成本，是提升 Agent 效率的核心手段，尤其在长上下文场景下效果显著。
  2. 通过掩码而非移除方式约束 Agent 行为更稳定高效。 在解码阶段通过屏蔽 token logits 动态限制工具选择，能避免 KV-Cache 失效和模型混乱，确保 Agent 在复杂行动空间中做出准确决策。
  3. 将文件系统作为 Agent 的终极上下文和外部记忆。 利用文件系统实现无限容量、天然持久且可直接操作的外部记忆，有效解决了长上下文限制和信息丢失问题，并为未来模型发展提供思路。
  4. 通过复述策略操控模型注意力以减少任务偏离。 通过不断重写待办清单等方式，将核心目标推入模型近期注意力范围，有效防止 Agent 在多步骤复杂任务中遗忘目标或偏离主题。
  5. 保留错误内容能有效提升 Agent 的错误恢复能力。 允许模型看到失败的行动和观察结果，使其潜移默化地更新内部信念，降低重蹈覆辙的概率，是衡量 Agent 智能行为的关键指标。
  6. 避免被 Few-Shot 反噬，引入上下文多样性。 语言模型是出色的模仿者，过度单一的 Few-Shot 示例可能导致模型陷入固定模式、漂移或产生幻觉。引入结构化变化和多样性有助于打破固定模式，提升 Agent 的健壮性。

💬 文章金句

  • 如果模型进步是上涨的潮水，我们希望 Manus 是船，而不是钉在海床上的柱子。
  • 如果只能选一个指标，我会说 KV 缓存命中率是生产级 AI 智能体最重要的单一指标，它直接影响延迟和成本。
  • 在 Manus 中，我们通过一个上下文感知的状态机来管理工具可用性。它并不真正移除工具，而是在解码阶段屏蔽相应 token 的 logits，从而根据当前上下文阻止（或强制）选择某些动作。
  • 正因如此，我们在 Manus 中将文件系统视为终极上下文：容量无限、天然持久，并且代理可直接操作。模型学会按需读写文件，把文件系统不仅当作存储，更当作结构化、外化的记忆。
  • 根据我们的经验，提升智能体行为最有效的方法之一看似简单却极具欺骗性：把走错的路留在上下文中。
