我用腾讯 Kuikly，把 DeepSeek Harness 装进了口袋

9/8/2026, 9:57:00 AM

📌 一句话摘要

作者用腾讯 Kuikly 跨端框架开发了 DSH Mobile，一套 Kotlin 代码覆盖 Android、iOS 和鸿蒙，通过官方 Host 协议让手机在通勤等碎片时间处理 DeepSeek Harness 的审批、追问和进度查看。

📝 详细摘要

本文是腾讯程序员 yuki 的原创实践分享，介绍如何用腾讯开源的 Kuikly 跨端框架（基于 Kotlin Multiplatform）开发 DSH Mobile，一套代码覆盖 Android、iOS 和鸿蒙三端，让用户通过手机远程操作电脑上的 DeepSeek Harness（DSH）。文章首先阐明动机：DSH 长任务运行中常需人工审批或补充信息，作者希望手机能接住这些短而频繁的交互，而非在手机上写代码。技术方案上，App 直接使用 DSH 官方 Host 协议（HTTP RPC 方法表 + 两条下行 WebSocket 事件流），不引入中间业务层；Agent 循环与工具执行仍在电脑端。文章详细拆解了三个关键技术点：一是用 KuiklyMarkdown 和 KuiklyWebview 两个现成组件处理流式 Markdown 渲染与内嵌网页；二是通过 commonMain 定义统一 Module 接口，把 WebSocket、SSH 隧道、扫码等系统能力差异下沉到三端原生层；三是设计了断线重连状态机（补事件、对历史、覆盖快照、世代号防串写）。连接方式提供 SSH 隧道和扫码 Relay 两种，均不把 3080 端口暴露公网。作者还对比了 Cursor、ChatGPT、Claude Code 的同类移动端方案，指出「人作为决策节点」是行业共同趋势。最后给出本地与腾讯云部署的快速上手步骤，并展望图片上传、语音输入等后续方向。

💡 主要观点

  1. DSH Mobile 的定位是远程控制面板而非移动 IDE，目标是让手机接住 Agent 运行中短而频繁的人工交互。 长 Prompt、大段代码 Diff 和持续思考的修改仍适合桌面；手机适合查看流式输出、处理命令审批、回答 Agent 追问和查看后台任务进度。这与 Cursor iOS、ChatGPT 移动端、Claude Code Remote Control 等产品趋势一致——具体编码交给 Agent 后，人更多在任务节点上做判断。
  2. App 直接复用 DSH 官方 Host 协议（HTTP RPC + 两条下行 WebSocket），不在手机与电脑之间引入中间业务层。 发送消息对应 POST /api/session.prompt，会话、工作区、模型等均走同一 RPC 通道；/api/events.mux 推送会话内事件，/api/events.host 推送 Host 全局变化。这样无需理解或翻译 DSH 内部插件结构，也避免维护一套私有服务。
  3. 跨端项目的真正难点不在页面而在系统能力，Kuikly 的价值在于组件复用与原生桥接差异下沉。 KuiklyMarkdown 基于 intellij-markdown 提供流式渲染骨架，KuiklyWebview 免去三端 WebView 分别封装；WebSocket、SSH、扫码等能力在 commonMain 定义统一 Module 接口，三端各自实现。约 1.3 万行 commonMain 代码三端共享，各宿主仅三四千行。
  4. 移动网络断线恢复必须区分「补事件」与「重新执行任务」，重连是恢复观察和控制而非重发 Prompt。 重连后按序执行：重建隧道、按序号补回遗漏的 session/event、请求 session.history 对齐记录、用最新快照覆盖 queue 和 jobs；世代号用于丢弃旧连接的迟到响应。若 Agent 断线期间仍在运行，App 重新订阅任务而非再次发送用户 Prompt。
  5. 安全上坚持 DSH 默认监听 127.0.0.1:3080，通过 SSH 隧道或扫码 Relay 两种方式远程访问，均不把端口暴露公网。 SSH 模式在手机建立本地端口转发，认证发生在 SSH 层；扫码模式由电脑端插件和 App 主动连接 Relay，经 sealed-tunnel-v1 转发流量，二维码主密钥位于 URL fragment 中不会发给 Relay。Relay 只负责连接双方和传递数据，无需直接访问 3080。

💬 文章金句

  • 我想解决的不是「在手机上写代码」，而是让手机接住这些短而频繁的交互。
  • Agent 循环、工具执行和插件仍在电脑上运行，手机负责连接、交互和渲染。
  • 重连是恢复观察和控制，不是重新执行任务。
  • 这个 App 的定位是远程控制面板，不是把完整 IDE 搬到手机上。
  • 具体编码工作交给 Agent 后，人更多是在任务节点上给意图、做判断和看结果。
