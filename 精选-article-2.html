50GB 工作区秒级可访问，腾讯 EROX 破解 Agent 恢复难题

11/23/2026, 9:36:00 AM

📌 一句话摘要

文章详解了腾讯 EROX 统一数据面的设计与实现，通过懒加载、P2P 分发、读写分离和增量快照机制，实现了 50GB 工作区秒级挂载，显著缩短 Agent 冷启动时间，解决了有状态 Agent 跨会话、跨节点的状态延续问题。

📝 详细摘要

本文聚焦腾讯 EROX 统一数据面的实践，针对 AI Agent 这类有状态、长会话场景中数据恢复的瓶颈问题。文章首先分析了 Agent 需要跨会话、跨节点延续状态、支持休眠恢复以及数据形态多样等四大挑战，进一步阐述了容器镜像、VM 磁盘、工作区和运行时快照四类数据的恢复需求。随后介绍了 EROX 的统一数据面方案：将镜像、磁盘、工作区和运行时快照封装为 EROFS 制品，通过 Capsule 关联多个组件，实现读（懒加载）、写（读写分离）、存（快照）三阶段闭环。具体技术包括热点预取、块级和文件级按需读取、P2P 分发、OverlayFS 叠加存储、增量快照、版本逻辑链以及 fsmerge 拍平读取视图。最后展示了实验数据：虚拟机启动缩短 67%-90%，AI 大镜像冷启动降低 59%-95%，50GB 工作区实现跨地域节点 320ms 挂载，满足秒级访问需求。

💡 主要观点

  1. 统一数据面解决 Agent 状态跨会话、跨节点延续问题 EROX 将容器镜像、VM 磁盘、工作区和运行时快照统一封装为 EROFS 制品，通过 Capsule 关联组件，实现数据在不同节点间的快速恢复与复制，关键点在于把人的工程经验转化为系统的运行秩序。
  2. 懒加载与热点预取实现秒级启动 通过 eBPF 录制启动负载，识别热点文件进行前置预取，结合块级 NBD/ublk 和文件级 fanotify 两种按需读取方式，显著缩短冷启动时间，实验显示虚拟机启动缩短 67%-90%，AI 大镜像冷启动降低 59%-95%。
  3. 读写分离与增量快照降低存储与传输成本 采用 OverlayFS 实现只读基线与可写层分离，增量快照只保存变化的块，版本逻辑链复用未变数据，fsmerge 拍平读取视图，避免逐代查找，大幅降低高频快照的存储和传输开销。
  4. P2P 分发减少跨节点重复回源 在按需读取路径中接入 P2P 机制，节点优先从对等节点获取数据，未命中再回源，有效减轻远端存储压力，同时利用节点缓存复用数据。
  5. 50GB 工作区实现跨节点秒级挂载 通过统一数据面的按需读取和缓存机制，50GB 工作区在同地域节点仅需 320ms 完成挂载并可访问，满足 Agent 跨节点调度的快速恢复需求。

💬 文章金句

  • AI Agent 是**有状态、长会话** 的------装依赖、跑任务、等大模型，状态要跨会话、跨节点延续。
  • EROX 用一套统一数据面，把内核直挂、按需拉取、P2P、增量快照与节点侧降本串成一条链，加速镜像启动与快照分发------50GB 工作区 1 秒就绪、冷启动缩减 50%+。
  • 数据按需到达、写不污染只读、变化即固化 ------三者首尾相接，形成**只读 → 可写 → 再只读** 的闭环。
  • 增量快照：只保存本次相对父代发生变化的部分，避免每次重新保存完整状态。
  • EROX 已在公司的 Agent 平台、RL 训练等场景规模部署，仍在持续演进。
