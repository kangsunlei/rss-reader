项目拆解 | 面向 Agent 的知识库检索怎么做

11/16/2026, 8:10:00 AM

📌 一句话摘要

本文通过拆解开源项目 SAG-Wiki，系统阐述了面向 Agent 的知识库检索方案，包括多层检索、Jev 决策模型、BM25 语义化以及 Agent 友好上下文构建等关键设计。

📝 详细摘要

本文作者从 RAGFlow 1.0 面向 Agent 检索的背景切入，分析了 Agent 在知识库检索中面临的五大痛点，随后重点拆解了开源项目 SAG-Wiki 的核心设计。SAG-Wiki 采用三层检索架构：首先用 BM25 进行词项召回，其次通过 Jev 决策模型判断候选片段的可用性，最后进行扩展检索。项目不依赖向量嵌入，仅构建 SQLite 全文索引，实现了低成本、可解释的检索。文章详细介绍了文件处理、分段策略、查询构造、扩展检索算法以及返回结果的结构化设计，还提供了 Agent 使用指南。作者指出尽管 SAG-Wiki 解决了部分问题，但 RAG 的根本挑战仍需持续关注。

💡 主要观点

  1. SAG-Wiki 采用三层检索架构：BM25 召回、Jev 判断、扩展检索 第一层用 BM25 快速召回候选片段，第二层用 Jev 决策模型结构化判断片段是否为必需证据，第三层从高分片段提取新词进行二次检索，有效平衡了召回覆盖与排序精度。
  2. 项目不依赖向量嵌入，仅构建 SQLite 全文索引实现低成本检索 通过 BM25 实现可解释的关键词匹配，避免了向量化带来的计算成本和黑箱问题，同时通过标题权重和特征权重优化了检索效果。
  3. Jev 决策模型提供结构化概率输出，适合批量并发调用 Jev 以 noul 类型输出 yes 概率，输入输出结构化，可高效并发处理大量候选片段，为后续扩展检索提供可靠的可用性判断依据。
  4. 扩展检索通过句子级抽词和单词查询提升召回覆盖 从高分片段切句抽词，构造单词查询避免高频词淹没，结合逆文档频率和共现度打分，有效补足第一轮召回的漏检问题。
  5. 返回结构化片段包含路径、标题、行号等信息，便于 Agent 精准引用 每条结果附带文件路径、标题路径、正文、起止行号、字节范围和文件哈希，Agent 可据此定位原文、核对内容或进一步检索。

💬 文章金句

  • RAGFlow 刚更新的 1.0 也是这个方向。
  • SAG-Wiki 提供本机客户端，可以选择文件夹作为知识库，自动索引文件内的文档。
  • Jev 是 TypeSafe 的 System One 模型，输入一段 state 加上一组带类型的问题，输出一组带类型的答案和概率。
  • BM25 打分的三个维度：词在片段里出现多少次、这个词在整个索引里多罕见、片段多长。
  • 返回结果带路径、行号、哈希和消费说明，Agent 可以继续查，也可以核对。
