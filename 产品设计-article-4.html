一万字 Jev 工程实践长文：把 Agent 的「判断题」从大模型里拆出来

9/21/2026, 9:35:49 AM

📌 一句话摘要

作者通过阅读资料、拆解 fast-jev-compaction 并仿写 Demo，论证 Jev 的价值不在替代大模型，而在于把 Agent 中高频、封闭、可回退的判断从生成链路里拆成独立的「快判断层」。

📝 详细摘要

文章从工程视角解读 TypeSafe AI 发布的 Jev（System One Model）。Jev 刻意放弃文本生成，只返回 Choice、Score、Noul 三种类型化的概率决策，作者据此提出 Agent 的四层架构分工：慢思考层（GPT/Claude）、快判断层（Jev）、确定性层（普通代码）、兜底层（人工或更强模型）。文章指出 coding agent 上下文膨胀的主因是工具结果，而传统 summary 会改写事实、破坏可复核性、且置信度无法进入代码分支。随后逐层拆解 GitHub 项目 fast-jev-compaction：只处理工具调用与工具结果、用户与助手文本不改写，通过 tool_use_id 配对、pinned 保护、state 构造、fitState 逐级降级、两个 Noul 问题（keepCall / keepResult）拆出 keep、drop_result、drop_call 三种动作，并给出分批请求与失败回退策略。Demo 在订单导出超时样本上把上下文从 10029 字符压到 852 字符，压缩率 91.5%。文章还给出 Jev 与 structured output、tool calling、传统分类器的选型对照，并提醒「类型安全不等于语义正确」「概率可信需要 shadow mode 校准」，最后按 L1/L2/L3 划分可自动执行的动作等级。

💡 主要观点

  1. Jev 的核心变化是把模型输出从「文本」变成「可执行的概率判断」 它刻意放弃自由文本生成，只返回 Choice（选项+概率）、Score（连续分数+分布）、Noul（0~1 概率）三种封闭输出。与 GPT/Claude 的 structured output 差别不在能否返回 JSON，而在于输出空间从一开始就被封闭，因此更适合放在 Agent 内部做高频、固定输出空间的小判断。
  2. Agent 需要一个独立的「快判断层」，而不是让大模型既生成又判断 coding agent 的上下文膨胀主要来自工具结果（read_file、search_content、execute_command 日志等），而系统真正需要的往往只是一个 0~1 的保留概率。用通用大模型回答判断题会带来三层断裂：生成成本与判断需求不匹配、摘要破坏可复核性、置信度无法进入代码分支。
  3. fast-jev-compaction 用「保留决策」替代「摘要改写」，把复合压缩拆成两个窄判断 项目约束用户文本与助手文本不改写，只处理工具调用与工具结果；先按 tool_use_id 配对避免孤立调用或孤立结果，再对每组问 keepCall 与 keepResult 两个 Noul 问题，组合出 keep、drop_result、drop_call 三种动作，并保留回退到传统 summary 的路径。
  4. state 构造与 fitState 降级链路是压缩器可用的关键工程细节 发给 Jev 的不是完整工具结果，而是「ok， 4213 chars (omitted)」这类短说明；当 state 超出预算时按 full、inputs<=200、inputs<=60、texts abridged、old messages collapsed、old calls compacted、old messages left out、old calls merged 逐级降级，原则是先削弱细节再删除内容、先处理旧消息再处理最近消息。
  5. Jev 的「不会幻觉」与「概率可信」都需要被准确理解 类型安全只保证不输出 schema 之外的内容，不代表语义正确，它仍可能选错；概率校准是核心卖点，但公开资料里 RLCD 训练细节与第三方校准数据不充分，工程上应先 shadow mode 跑一段时间、用业务样本统计各概率段真实正确率，再定自动执行阈值，高风险不可逆动作不能让 Jev 单独决定。
  6. 选型上 Jev 与 structured output、tool calling、传统分类器是互补而非互斥 低频复杂判断用 LLM + JSON Schema，Agent 主流程动作用 tool calling，稳定标签与大量数据可用传统分类器，高频、输出可枚举、错误可兜底的局部判断才适合 Jev；每天调用几十万次且输出空间固定的任务，Jev 这类模型才开始有明显意义。

💬 文章金句

  • Jev 最适合的位置，不是 Agent 的大脑，而是 Agent 的反射神经。
  • 上下文压缩最怕的不是删掉废话，而是把关键事实改写成一句「差不多」。
  • 通用模型的问题不是不聪明，而是它把「判断」包装成了「生成」。
  • 这叫类型安全，不叫语义正确。
  • 概率能帮代码分流，但不能替业务背锅。
  • Jev 的价值不在于取代大模型，而在于把高频、封闭、可回退的判断从生成链路里拆出来。
