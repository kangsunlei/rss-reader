DeepSeekHarness 的新范式：让 Agent 为自己构建工具

8/18/2026, 11:45:00 PM

📌 一句话摘要

本文介绍 DeepSeek Harness 的插件化架构，解释 Agent 如何在对话中动态创建、调用和销毁工具，并阐述其对产品经理设计 AI 产品的五条实践启示。

📝 详细摘要

文章以 DeepSeek Harness（dsh）的插件机制为核心，解释 Agent 如何在会话中按需「现场造工具」而非依赖出厂配置的工具集。通过一个将 60 张截图批量转格式的实际案例，对比了「写脚本执行」与「造插件注册」的本质差异：前者是一次性动作，后者是注册为可复用、可回滚、带界面的工具资产。文章进一步提炼出五条最佳实践——能力按需、对话复杂度恒定、出错可回滚、安全设计、插件同时扩展 Agent 与界面，并强调产品经理需要研究 LLM 的基本特性与行为边界。文末附带线下课程推广内容。

💡 主要观点

  1. Agent 工具集不应是出厂固定配置，而应支持对话中动态创建和销毁。 DeepSeek Harness 将 Agent 循环、Tool、Hooks、记忆管理全部插件化，Agent 可在会话中途发现能力缺口，当场写一个插件注册为工具，任务完成后销毁，工具列表恢复原样。
  2. 脚本是消耗品，插件是资产，两者在能力形态上有本质区别。 脚本执行是一次性动作，跑完即消失；插件注册后进入模型工具箱，可反复调用、带状态、支持界面展示和版本回滚，销毁后零残留。
  3. 插件化架构解决产品设计的五个核心问题。 能力按需装配避免工具集膨胀；结果压缩保持对话复杂度恒定；版本化支持低成本试错；显式授权流程保障安全；插件同时扩展 Agent 能力和用户界面。
  4. 产品经理需要研究 LLM 的基本特性，而非仅研究用户行为。 Agent 时代的产品设计需理解模型的知识可靠性边界、任务拆分策略、上下文工程方法，以及需要提供哪些工具和权限才能让 Agent 稳定工作。

💬 文章金句

  • 脚本是消耗品，插件是资产。
  • Agent 的成长，不再依赖平台的每次升级，而是发生在每一次对话里。
  • 不要问 Agent 会不会用某个工具，要问 Agent 能不能给自己造一个工具。
