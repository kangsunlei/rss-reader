从 0 到全球 4%代码提交量：Claude Code 创造者揭秘 7 个关键决定丨 Y Combinator

2/19/2026, 2:05:00 PM

📌 一句话摘要

本文深度揭秘了 Anthropic 旗下 Claude Code 的诞生历程及其核心产品哲学：顺应模型“想使用工具”的天性，坚持为未来的模型而非当下的局限进行设计。

📝 详细摘要

文章通过对话 Claude Code 创造者 Boris Cherny，还原了这一现象级 AI 编程工具从终端原型到占据全球 4% 公开代码提交量的演进过程。核心内容涵盖了 Claude Code 的偶然起源、为何选择终端形态的务实考量、以及基于《苦涩的教训》所形成的“不与模型对赌”的设计原则。Boris 强调，产品的成功源于对用户“潜在需求”的捕捉（如 Plan Mode 的诞生），并透露 Anthropic 将编程视为通往安全 AGI 的核心路径。此外，文章还分享了 AI 工具如何将内部工程师生产力提升 150%，并预言“软件工程师”将向“Builder”转型的未来趋势。

💡 主要观点

  1. 模型的核心驱动力在于使用工具，这是实现 Agent 能力的本质。 Boris 发现模型能自发编写脚本调用外部工具解决未定义任务，意识到模型不仅是对话者，更是具备交互欲望的执行者。
  2. 坚持“为六个月后的模型而造”，避免过度开发临时的脚手架代码。 团队奉行《苦涩的教训》，认为通用方法终将胜过特定优化，因此宁愿等待模型升级也不愿构建复杂的技术债。
  3. 产品成功的关键在于捕捉“潜在需求”，而非强迫用户改变习惯。 通过观察用户自发的行为（如手动写规划）来提炼功能，将用户已经在努力做的事情变得更容易，从而实现极高的留存。
  4. 编程被视为通往 AGI 的必经之路，是模型学习使用计算机的阶梯。 Anthropic 的战略逻辑是先教模型写代码，再教其使用工具和计算机，最终通过编程能力的进化实现通用的智能交互。

💬 文章金句

  • 模型只想使用工具。这就是它全部想做的事。
  • 我们不为今天的模型而造，我们为六个月后的模型而造。
  • 人们只会做他们已经在做的事。你不能让用户做新事情，只能让旧事情更容易。
  • Claude Code 没有任何一部分存在超过六个月。
  • 我卸载了 IDE。我不再手动编辑任何一行代码。编程对我来说已经被解决了。
