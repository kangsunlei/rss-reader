终究是 Google 和 Anthropic，扛下了连接一切 Agent 的所有

4/11/2025, 4:52:52 AM

📌 一句话摘要

Google 正通过 A2A 和 ADK 争夺 AI Agent 互操作标准，旨在构建以 Google Cloud 为中心的 Agent 生态。

📝 详细摘要

文章分析了 Google 和 Anthropic 在 AI Agent 互操作性标准上的竞争。Anthropic 提出了 MCP 协议，旨在解决 AI 模型与数据孤岛的隔离问题，实现大模型数据集成的统一标准。而 Google 则推出了 A2A 协议和 ADK 工具包，试图解决 Agent 间的互操作问题，让不同框架构建的 Agent 能够安全地进行通信、交换信息并协调行动。A2A 协议基于能力发现（Agent 通过 JSON 格式的 'Agent Card' 发布自身能力）、任务管理（实现任务生命周期的同步）、协作和用户体验协商等关键原则运作，旨在为跨系统、跨领域的 Agent 协作提供一套标准化的 '握手' 和 '对话' 机制。同时，Google 联合了 Salesforce、SAP、ServiceNow、MongoDB、德勤等众多行业巨头共同参与 A2A 协议的开发和推广。Google 还推出了 Agent Development Kit (ADK) ，旨在简化 Agent 的创建过程，鼓励开发者和企业围绕 Google Cloud 构建各式各样的 Agent，从而提振 Google Cloud 的收入。文章认为，Google 的最终目标是让 AI Agents 无处不在，并且要让它们都建立在 Google 的生态里。

💡 主要观点

  1. Google 希望通过 A2A 和 ADK 构建自己的 Agent 生态。 Google 通过提供易用的 ADK 工具，鼓励开发者和企业围绕 Google Cloud 构建 Agent，从而提振 Google Cloud 的收入。
  2. Anthropic 的 MCP 协议旨在解决 AI 模型与数据孤岛的隔离问题。 MCP 通过提供统一协议替代碎片化的自定义集成，为大模型数据集成提供了统一标准，提高开发和使用效率。
  3. Google 的 A2A 协议试图解决 Agent 间的互操作问题。 A2A 旨在让任何来源、任何框架构建的 AI Agent，都能够安全地进行通信、交换信息并协调行动，实现跨系统、跨领域的 Agent 协作。
  4. Google 通过 Code Assist 的深化和 Firebase Studio 的拓宽，将 Agent 能力注入从专业开发到低代码的全流程 这显示了其完善工具与平台、配合底层 ADK 与 A2A 协议，加速 Agent 战略在 Google Cloud 生态落地的决心。

💬 文章金句

  • A2A 被定位为一个新型的、开放的互操作性协议，其野心在于让任何来源、任何框架构建的 AI Agent，都能够安全地进行通信、交换信息并协调行动。
  • Google 深知成为标准制定者的重要性，在 AI Agent 走向繁荣的关键节点，它肯定不想让所有 AI Agents 都听 Anthropic 的。
  • Google 想让 AI Agents 无处不在，并且要让它们都建立在 Google 的生态里。
