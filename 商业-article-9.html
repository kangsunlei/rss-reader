为什么我们从 Claude Code 换到 Codex？丨 Limitless

5/7/2026, 1:03:00 PM

📌 一句话摘要

本文基于 Limitless 播客内容，深入对比了 OpenAI Codex 与 Claude Code 在电脑控制、长任务自治、自动审批等维度的实际表现，并提出了 Claude 负责编排、Codex 负责执行的分工策略。

📝 详细摘要

本文是对 Limitless 播客内容的深度整理与解读，核心探讨了 AI 编程工具从 Claude Code 到 OpenAI Codex 的迁移现象。文章首先回顾了 Claude Code 曾占据工程师心智的背景，随后从电脑控制、长任务自治、浏览器能力、自动审批、Chronicle 记忆、游戏生成和仪表盘生成等多个维度，对 Codex 和 Claude 进行了详尽的对比测试。文章指出，Codex 在代码逻辑的稳定性和执行效率上表现更优，而 Claude 在对话人格、编排能力和部分远程操作上仍有优势。最终，文章提出了一个实用的分工框架：将 Claude Opus 4.7 作为编排者，负责拆解任务和制定计划，而将 Codex 作为执行者，负责将计划落实为代码。此外，文章还讨论了 Chronicle 屏幕记忆功能的潜力与隐私风险，以及“vanilla maxing”（优先使用官方原生工具）的实践原则，强调了 AI 工具栈的快速迭代特性。

💡 主要观点

  1. AI 编程工具栈的稳定期很短，选型应基于实际任务而非品牌记忆。 文章指出，Claude Code 和 Codex 的领先地位会快速轮换，工程师不应将工具选择视为长期信仰，而应通过真实任务测试来决定当前最适合的工具。
  2. Codex 在电脑控制、长任务自治和自动审批等执行层面表现更优。 通过多个维度对比，Codex 的鼠标控制速度更快，能持续执行长达 36 小时的任务，其自动审批功能能减少无意义的等待，使其更适合需要持续推进的复杂工程任务。
  3. Claude 在对话、人格和编排能力上仍有优势，适合作为规划层。 文章提出一个实用的分工框架：将 Claude Opus 4.7 作为编排者，负责拆解任务和制定计划，而将 Codex 作为执行者，负责将计划落实为代码，实现优势互补。
  4. Chronicle 屏幕记忆功能将 AI 的理解从聊天历史扩展到工作习惯。 Chronicle 通过观察用户的屏幕行为自动建立上下文和记忆，有望为知识工作者提供基于个人工作轨迹的效率建议，但也带来了显著的隐私压力。
  5. AI 编程工具的竞争已从模型参数扩展到工作流封装。 文章认为，AI model harness（预设 prompt、政策、权限、环境等）会显著改变模型表现，原生工具正在快速吞并插件功能，优先使用官方原生工具（vanilla maxing）是降低风险的有效策略。

💬 文章金句

  • 过去一周，Codex 的下载或安装超过 4600 万次。
  • 电脑控制的分水岭，已经从「能操作」走向「能不能让人放心离开」。
  • Agent 工作流的效率，不只取决于模型回答质量，也取决于权限系统能不能减少无意义等待。
  • 当记忆从聊天历史扩展到屏幕行为，AI 不再只回答问题，也开始审视工作习惯。
  • Opus 4.7 是编排者，Codex 是这份代码计划的执行者。
