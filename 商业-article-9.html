原创发布| VibeAppControl：一个全 Agent 通用的 Computer Use for Win

6/20/2026, 1:36:00 PM

📌 一句话摘要

本文正式发布 VibeAppControl (VAC)，一个独立于具体 LLM 和 Agent 的通用 Windows Computer Use 执行层，通过语义自动化与视觉识别双引擎，为所有支持 MCP 或 CLI 的 Agent 提供统一的桌面应用操控能力。

📝 详细摘要

文章由「Web3 天空之城」发布，介绍了其原创项目 VibeAppControl (VAC) 的公开 Beta 版。VAC 定位为本地 Windows 运行时，旨在解决现有 Computer Use 方案（如 Codex、Claude Code）与特定产品绑定、且对 Windows 支持不佳的问题。其核心设计是「语义自动化优先，视觉识别补充」的双引擎架构：对于标准控件应用，优先通过 UI 自动化读取元素结构（如按钮、输入框），而非依赖截图坐标；对于画布、自绘界面等，则使用截图、OCR 和坐标点击。VAC 通过 MCP 和 CLI 两种方式接入，不绑定任何特定模型，已验证可在 Codex、Claude Code 以及 DeepSeek V4、GLM 5 等国产模型（通过 OpenCode）上工作。文章还强调了 VAC 的结果核验能力，区分「动作已执行」和「结果已确认」。项目公开了一组对比测试，VAC 在 9 个 Windows 桌面任务中全部成功，而第三方 MCP 仅完成 3 个。最后介绍了当前限制（如不支持锁屏、UAC）和后续计划（加入跨 Agent 的经验系统）。

💡 主要观点

  1. VAC 将 Windows Computer Use 能力从特定产品中解耦，形成独立、可复用的执行层。 不同于 Codex 或 Claude Code 内置的 Computer Use，VAC 作为独立运行时，通过标准化的 MCP 和 CLI 接口，允许任何上层 Agent 或脚本调用，实现了执行层与模型/Agent 的彻底分离。
  2. 核心设计是「语义自动化优先，视觉识别补充」的双引擎策略。 对于有标准 UI 结构的应用，VAC 优先读取元素语义（如「保存按钮」），而非依赖截图坐标，从而避免窗口移动、分辨率变化等干扰。对于无标准结构的界面，则回退到截图、OCR 和坐标点击，确保通用性。
  3. VAC 强调结果核验，区分「动作执行」与「结果确认」。 系统会在执行点击或输入后，通过回读内容、检查文件状态、比较像素变化等方式，验证操作是否真正生效，避免将「鼠标已点击」等同于「任务已完成」。

💬 文章金句

  • 截图识别是在判断「按钮看起来在哪里」，语义自动化是在读取「哪个元素就是这个按钮」。
  • VAC 会区分：「动作已经发出」和「结果已经确认」。无法确认结果时，不直接把任务标记为成功。
