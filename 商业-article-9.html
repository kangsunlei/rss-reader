Manus 项目立项初期会议纪要，深入讨论了 Agent 的产品哲学、技术架构和用户体验，确立了“通用性平台+高频场景优化”的战略，旨在打造人类心智的延伸。

📝 详细摘要

本文是对 Manus 项目立项初期两次核心讨论的会议纪要扩展版，旨在深度还原团队在产品哲学、技术架构、用户体验及市场策略等方面的思辨与碰撞。核心议题包括 Agent 产品定位（通用性与垂直优化的战略抉择）、构建具备“代理”能力的云端环境（云端浏览器、状态持久化、用户接管），以及如何在“信任”与“控制”之间平衡的用户界面设计理念（渐进式披露、操作系统隐喻）。文章强调 Agent 应作为人类心智的延伸，克服认知局限，并最终确立了“通用性平台+高频场景优化”的双轮驱动策略，以期打造下一代智能体。

💡 主要观点

  1. 确立 Agent 产品“通用性优先，逐步沉淀和优化高频场景”的双轮驱动战略。 以“百度模式”类比，强调先构建强大的通用能力平台，再通过分析高频 Query 反向优化，沉淀预设能力，避免“Hao123 模式”的局限性。
  2. 解决当前 Agent 产品的核心痛点：实现全面的“状态持久化”。 针对 Devin 等产品一次性会话机制的不足，明确需持久化登录状态、文件系统、环境变量与密钥管理，以构建真正具备“代理”能力的云端环境。
  3. 构建“云端浏览器”作为 Agent 的 Web 复杂操作技术基石，并考虑用户接管机制。 通过“Browser in Browser”概念和流式传输技术实现 Agent 对 Web 的远程交互，同时在 Agent 遇阻时，需有流畅机制让用户接管浏览器，确保任务顺利完成。
  4. 设计 Agent 界面需平衡用户对“信任”与“控制”的需求，采用“渐进式披露”和“操作系统隐喻”。 吸取 Devin 界面信息过载的教训，提出初始界面简洁化，按任务进展逐步展示工具，并将核心功能设计为独立应用，以提供清晰、可扩展的用户体验。
  5. Agent 的根本价值在于作为人类心智的延伸，克服人类的认知局限。 Agent 可以弥补人类在经验主义、持续专注和第一性原理思维上的不足，通过全局搜索和评估，寻找任务的最短路径，尤其在管理复杂系统和长期规划方面具有巨大潜力。
