告别 AI Demo 页面：构建支持淘内货品运营、可 C 端投放的会场 Agent Harness

10/19/2026, 7:24:00 AM

📌 一句话摘要

方舟 AI 会场 Agent Harness 将一句话需求转化为可投放的淘内会场，通过策划、视觉设计、数据装配与页面构建链路，结合 Skill 体系、SubAgent 与多层质检，实现想法即生成、生成即可投放。

📝 详细摘要

文章系统介绍方舟 AI 会场 Agent Harness 如何突破传统 AI 仅生成静态 Demo 页面的局限，构建支持淘内真实货品运营且可 C 端投放的生产级会场系统。核心是把一句话需求经策划、视觉设计、数据装配、页面构建的完整链路，输出承载视觉规范、商品供给与渲染协议的 page.html。技术上构建会场域认知环境、业务 Agent 工作区与自迭代环境，借助 Skill 体系注入淘系设计规范与业务规则，利用 SubAgent 实现上下文隔离与并行提效，并配合多层质检与全链路观测保障交付质量。文章还详细讨论了 HTML 三重约束、视觉 Skill 遵循度、商品数据世界观、上下文分层与 Prompt Cache 策略、OSS 工作区设计及 SubAgent 收益成本等工程实践。

💡 主要观点

  1. 从 Demo 到生产级投放需同时满足视觉规范、真实供给与渲染协议 普通 AI 生成的 HTML 无法支撑淘内渲染体系、埋点、动态商品与个性化推荐。方舟会场要求内容实时策划、淘天设计水准、真实货品运营与 C 端线上投放，生成即需符合生产环境要求。
  2. page.html 是视觉、数据、生码三重约束的冲突中心 同一 DOM 同时承载布局、供给、字段绑定与转码要求。视觉设计是软约束，货品数据是认知约束，生码是硬约束；视觉分组不等于供给分组，加 wrapper 会改变布局前提，需通过 data-ark-slot 等协议分离表达。
  3. 会场域认知通过 Skill 渐进加载支撑设计与运营一致性 视觉认知解释设计语言，数据认知解释供给归属，生码认知理解数据协议。30+ Design Skill 将情绪、材质、排版等转化为 AI 可理解语言，并通过规则持久化、压缩恢复与编辑保护维持风格遵循度。
  4. 上下文分层、缓存与 SubAgent 拆分保障效率与一致性 按 P0-P3 分层管理上下文，重要 Skill 在压缩时显式恢复，低价值工具结果及时清理以提升 Prompt Cache 命中率。主 Agent 负责业务主循环，Skill 供给能力，Task 委派并行子任务，工作区以 OSS 虚拟文件系统持久化产物，保证多轮编辑可追溯。

💬 文章金句

  • 一句话生成可投放会场

  • html 只是底层的协议，让 AI 随便生成一张好看的 html 是比较容易的，但如果希望他可用、可运营、可投放，那还有很多事情和约束需要去做。
  • 同一棵 DOM 同时承载布局、供给、字段绑定与转码要求。
  • 视觉设计是软约束：visual-design 与风格 Skill 守住气质、视觉层级和关键特征，相框、字体、层叠、留白仍可组合------让模型把设计做好，而不是照模板填空。
