让编码 Agent 发挥作用的工程实践

3/19/2026, 12:56:45 PM

📌 一句话摘要

Simon Willison 分享与 AI 编码 Agent 高效协作的工程实践，强调测试驱动开发、手动验证和安全沙盒机制的重要性。

📝 详细摘要

在这场 Pragmatic Summit 对谈中， prolific 开源开发者、Django 联合创始人 Simon Willison 详细介绍了与 AI 编码 Agent 协作的工作流。他倡导使用红绿测试驱动开发（TDD）来防止过度工程化，并确保无需逐行人工审查即可获得高质量代码。他还涵盖了通过 curl 命令进行手动测试、包括沙盒和最小权限原则在内的安全实践，以及 AI 工具不断演进的格局。

💡 主要观点

  1. 红绿 TDD 对编码 Agent 至关重要 每次会话开始时告诉 Agent 使用红绿 TDD，能显著提高获得可用代码的概率。测试可以防止过度工程化，是获得高质量结果的第一步。
  2. 手动测试是对自动化测试的补充 Agent 应该通过启动服务器并使用 curl 验证 API 来手动测试其工作。测试套件全部通过并不能保证服务器正常运行——手动验证可以发现测试覆盖不到的漏洞。
  3. 安全需要沙盒和最小权限原则 将 AI 生成的代码视为不可信代码——在具有受限权限的沙盒环境中运行。应用「致命三要素」规则：同时获得凭证访问权、互联网访问权和不可信输入访问权会造成不可接受的风险。
  4. 「不写不读」范式正在兴起 一些团队现在完全不编写或阅读代码，完全依赖 Agent。当 Agent 通过测试和验证而非人工代码审查来证明正确性时，这种模式是可行的。

💬 文章金句

  • 红绿测试驱动开发是第一个秘诀。这是经典的测试优先理念：先写测试，看着它失败，然后再写实现。
  • 所有优秀的编码 Agent 都知道红绿 TDD 是什么意思。如果它们先写测试，你获得可用代码的概率会大幅飙升。
  • 测试不再是可选项——它们是获得高质量结果的第一步。
  • 你必须让它们进行手动测试。任何使用过自动化测试的人都知道，所有测试通过并不意味着 Web 服务器真的能启动。
  • 把 LLM 写的代码当成你不完全信任的实习生写的代码来对待。在沙盒中运行它。
  • 致命三要素是：访问凭证的权限、访问互联网的权限、访问不可信输入的权限。任意两个都没问题，但三个同时具备就是安全噩梦。
