不只是 Memory：Ontology 如何让 Coding Agent 越用越懂项目？

11/13/2026, 9:36:00 AM

📌 一句话摘要

文章阐述了腾讯在 AI Agent 研发中构建的本体（Ontology）与递归自我改进（RSI）结合方法，通过三层知识图谱（工程事实、项目语义、Bug 经验）提升 Bug 定位成功率，从 58% 提升至 65%，并探讨了持续改进的实验设计。

📝 详细摘要

文章从 AI Agent 如何逐渐熟悉项目出发，分析了本体（Ontology）在概念表达、关系语义和约束条件方面的作用，以及递归自我改进（RSI）在反馈驱动下的知识迭代机制。作者指出，个人效率提升不等于组织产出增长，关键在于知识能否从个人层面沉淀到组织层面。文章详细阐述了三层知识图谱的构建：工程事实层提供函数、类型、字段及其使用的静态关系；项目语义层结合 LLM 提取功能职责、业务概念、字段含义及跨仓映射；Bug 经验层整理历史问题及其根因、处理方式和适用范围。通过实际实验，Agent 在 Bug 定位任务中的成功率从 58% 提升至 65%，验证了三层结构带来的显著收益。文章最后提出了持续改进的实验方案，强调需区分语义缺失、映射错误、访问困难和执行遗漏等不同问题，并通过冻结版本图谱与增量学习图谱的对照实验来评估改进效果。

💡 主要观点

  1. AI Agent 熟悉项目的核心问题在于概念理解和经验复用 通用模型提供代码和推理能力，但项目特有的概念、约定和历史仍需从团队材料中获得，并能判断其适用条件，从而影响任务决策。
  2. 构建三层知识图谱实现跨仓知识关联 工程事实层提供静态代码关系，项目语义层解释业务含义和约束，Bug 经验层整理历史问题，三者相互索引，让 Agent 能从任意一层进入并导航到所需知识。
  3. 本体与 RSI 的结合提升 Bug 定位成功率 通过本体明确业务对象和约束，RSI 利用反馈迭代知识，实验显示 Bug 定位成功率从 58% 提升至 65%，验证了语义组织和经验纠正的有效性。
  4. 持续改进需区分问题类型并进行有针对性的实验 要避免统一归因为「模型不够聪明」或「Memory 不够多」，需判断是语义缺失、映射错误、访问困难还是执行遗漏，并通过冻结版本与增量学习的对照实验验证改进效果。
  5. 经验的使用应可追溯到具体的判断改变 自然语言经验转化为强制检查时，需确认契约来源、审查断言，防止同一套错误假设同时生成实现和唯一的验收标准，确保经验真正改变行为。

💬 文章金句

  • 个人效率↑ ≠ 组织产出↑，个人技能提升了，但是组织的工作流并没有得到重塑。
  • 本体帮助系统表达与使用领域知识，RSI 关注系统怎样根据反馈改进自己。
  • 我们希望形成的关系是: Loop 提供行动与真实结果， Memory 保存经验及来源， 本体组织概念和经验的适用条件， 后续任务检验这些知识是否改变了行为。
  • 三个层次分别是: 执行内迭代、跨任务自改进、改进过程的自改进。
  • Bug 定位成功率从 58% 提升到 65%，增加了 7 个百分点。
