我们用 150 个任务测试了 30 个 skill，跑出 7 个反直觉结论

5/22/2026, 7:41:00 AM

📌 一句话摘要

腾讯玄武实验室通过 150 组任务级对照实验，系统评估了 30 个 AI Skill 的真实效果，发现装上 Skill 并不一定更好，且存在虹吸、成本增加、稳定性风险等反直觉结论。

📝 详细摘要

本文是腾讯玄武实验室基于 TRACE 严选评测体系，对 30 个 AI Skill 进行系统化实验的深度报告。实验在统一 prompt、裁判和评测口径下，让每个 Skill 与裸模型（no-skill）跑完 150 组任务级对比，并评估了成本、稳定性、规范性和可迁移性。核心发现包括：Skill 组仅以 41.3%的胜率略优于裸模型（36.7%），远非压倒性；存在 Skill 虹吸现象，13.3%的轻量请求被错误路由至 Skill；装上 Skill 后 token 消耗平均增加 48%，耗时平均增加 19%；稳定性风险主要来自工具链、外部调用和长等待，而非模型本身；提高模型推理强度能改善 Skill 表现，但收益不均匀。文章最后为开发者提供了 6 条实用建议，强调在追求 Skill 数量之前，应先弄清楚其技术边界和真实价值。

💡 主要观点

  1. 装上 Skill 并不一定比裸模型更好，仅 41.3%的任务胜出。 在 150 组任务级对照中，Skill 组胜出 62 次（41.3%），no-skill 组胜出 55 次（36.7%），平局 33 次（22.0%）。真正有效的 Skill 补充了模型裸能力之外的东西，如外部工具或约束工作流；而仅用 Markdown 重写已有能力的 Skill 反而成为负担。
  2. Skill 存在虹吸现象，13.3%的轻量请求被错误路由。 系统在应该使用 Skill 时表现良好（正确触发率 99%），但在本应 no-skill 的轻量请求中，有 13.3%仍被吸入了某个 Skill。简单改写、短语生成等任务，只要出现 Skill 描述中的相关领域词，就可能被错误路由，带来额外成本和复杂度。
  3. 多数 Skill 会增加 token 消耗和耗时，平均分别增加 48%和 19%。 30 个 Skill 的全样本实验显示，装上 Skill 后 token 消耗平均多了 48%，耗时平均长了 19%。但部分流程明确、输出边界清晰的 Skill 反而能降低消耗，说明设计质量至关重要。
  4. 稳定性风险主要来自工具链和外部依赖，而非模型本身。 近一半的 Skill 在工具链、外部调用、长等待或反复修正中遇到过问题。当 Skill 从提示词演变为带工具、脚本、文件和外部服务的完整流程时，稳定性成为一个工程链路问题。
  5. 提高模型推理强度能改善 Skill 表现，但收益不均匀。 在可迁移性实验中，xhigh 推理强度下平均质量分从 3.80 提升至 4.70。对推理强度敏感的 Skill 包括需要处理隐藏约束、多步交付和强创作类的任务；而流程明确、结构性强的 Skill 收益有限。

💬 文章金句

  • 当 Skill 真正补充了模型裸能力之外的东西，比如一个清晰的输出结构、一组外部工具、一条受约束的工作流，或一份具体可交付的产物，它就是有用的；当 Skill 只是把模型本来就会的事情再'用 Markdown 重写一遍'时，它带来的更多是负担而非增益。
  • 该用 Skill 时，它很会召回；不该用 Skill 时，它有时不够克制。
  • 当 Skill 从'提示词'演变为'带工具、脚本、文件、外部服务和交付物的完整流程'，稳定性就不再是大模型的能力问题，而是一个工程链路问题。
  • 在急着追问'还能加什么'之前，更值得先弄清楚它的技术边界在哪里。
  • 克制地问一句'它真的需要吗'，或许比急着再装一个，更接近答案。
