📌 一句话摘要

OpenAI 的这场技术分享探讨了 Prompt Caching 机制、Cache Keys 和 Context Engineering 等优化策略，以及在降低延迟和成本方面的实际效率提升。

📝 详细摘要

本文总结了 OpenAI 的 “Build Hour” 专题会议，重点讨论了 Prompt Caching。该功能旨在通过重用计算资源来优化 LLM 性能。它解释了缓存自注意力层中键值（KV）张量的底层机制，从而跳过相同前缀的冗余计算。关键技术细节包括 1024 token 的激活阈值、前缀一致性的重要性，以及引入 “Prompt Cache Keys” 以确保请求被路由到同一个 GPU 引擎，从而提高命中率。会议还涵盖了高级策略，例如使用 Responses API 为推理模型（o1/o3）保留思维链（CoT）token，通过 Realtime API 中的 “retention_ratio” 管理上下文，以及 Warp 的案例研究，展示了实现高达 90% 成本降低的多层缓存架构（全局、用户和任务级别）。

💡 主要观点

  1. Prompt Caching 重用自注意力层中的中间键值（KV）张量。 系统不再为每个请求重新计算注意力，而是存储前缀的浮点 KV 对。这使得模型能够跳过对相同初始 token 的处理，显著降低延迟和计算成本。
  2. 缓存的 “第一定律” 是保持严格的前缀一致性和顺序。 只有当前缀连续且与之前的请求完全相同时，才会触发缓存。开发者应将静态系统提示词放在开头，并在末尾添加动态内容或用户消息，以最大化缓存的前缀长度。
  3. Prompt Cache Keys 对于将请求路由到正确的 GPU 引擎至关重要。 由于大规模 API 将流量分发到多台机器上，使用 Cache Key 可以确保相关请求（例如来自同一用户或对话的请求）命中存储了特定 KV 缓存的同一引擎，从而提高命中率。
  4. 推理模型（o1/o3）需要使用 Responses API 才能有效缓存思维链 token。 与无状态的 Chat Completions 接口不同，Responses API 会持久化 o1/o3 模型生成的隐藏推理 token。这使得对话中的后续轮次能够受益于缓存的推理过程，在某些情况下能使命中率翻倍。
  5. Context Engineering 需要在修剪和缓存保留之间取得战略平衡。 对上下文窗口进行频繁的微小更新会破坏缓存一致性。使用较大的 “retention_ratio” 步长（例如一次性削减 30% 的历史记录）比逐轮修剪更有效，因为它可以为后续的多个轮次保留缓存。

💬 文章金句

  • Prompt caching 是计算资源的重用……我们跳过对已处理 token 的计算，只处理新内容。
  • 缓存中实际存储的不是 token 或嵌入，而是一堆浮点数——即中间键值（KV）张量。
  • Prompt Cache Keys 就像数据库中的分片键；它们控制数据局部性，并确保相关请求命中同一引擎。
  • 缓存的 “第一定律” 是前缀一致性——尽可能保持系统提示词静态，并在末尾添加动态内容。
  • 对于推理模型，通过切换到 Responses API 并持久化思维链 token，可以将缓存命中率从 40% 提高到 80%。
