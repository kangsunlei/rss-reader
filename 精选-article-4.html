TypeSafe CEO：从 KV cache 反推 coding agent 的六个怪象与重设计

9/21/2026, 6:29:22 AM

📌 一句话摘要

TypeSafe CEO Diogo 用「如果没有 KV cache 会怎么设计 coding agent」的反事实实验，指出路由、工具调用、compaction、子 agent、重启、开箱即用等标准特性多为成本结构的补丁，并提出显式状态加按查询动态重建上下文的解法。

📝 详细摘要

这条长推系统转述 TypeSafe CEO Diogo 关于重造 coding agent 的思考。核心是一个反事实实验：如果 LLM 没有 KV cache，你会怎么设计 agent？作者据此审计出六个「怪象」——按难度路由在经济上不成立（因 cache 按模型隔离，小模型读大模型上下文要全价，回切大模型还要按输入价重付），工具调用被迫 upfront 声明且吃上下文，compaction 隐含「所有 turn 共享同一状态」的可疑假设，子 agent 卡在状态交接，重启仅在状态会腐坏时合理，以及开箱即用之争。解法是 TypeSafe-centric 设计：把「一切都在上下文里」当作显式不变量，但对每次查询重新计算上下文（meta-attention），给每个 chunk 打相关性标签，并对「复用 KV cache vs 从零重建」做成本感知决策。由此解锁成本/智能感知路由、子 agent、Skills/MCP 的第一性原理重设计、条件化 AGENTS.md 四件事，并附带后台只读任务、安全感知路由等半熟构想与一批可集成工具。

💡 主要观点

  1. KV cache 与按 token 计费塑造了 agent 的「标准特性」 作者认为今天 agent 的许多特性并非源于用户价值，而是为绕过 KV cache 与计费结构打的补丁。典型例子是按难度路由：以 Opus 输入 5/输出 25、Sonnet 3/15 计价，只要上下文 X 大或额外生成 Z 超过 Y 的约 1.67 倍，Sonnet 开路再回 Opus 反而更贵；按 Diogo 给的比例，全程 Opus 只要路由方案约 2/3 的钱。
  2. compaction、子 agent、重启等机制的前提假设值得怀疑 compaction 隐含「未来所有 turn 都想要同一份共享状态」，但压缩本身极难且不如查询感知的压缩；子 agent 的卡点在状态交接（传什么进去、合并什么回来）；重启只在「agent 有状态且状态会腐坏」时才合理，替代思路是按需即时加载相关旧状态。
  3. 显式状态 + 按查询重建上下文是让路由与子 agent 成立的前提 把「一切都在上下文里」当作显式不变量，但对每次用户查询重新计算上下文（meta-attention），并对复用 KV cache 还是从零重建做成本感知决策。上下文重建变便宜后，成本/智能感知路由、大规模子 agent、Skills/MCP 的按需加载（中间层只放一行方向性描述）、条件化 AGENTS.md 才真正划算。

💬 文章金句

  • Diogo 核心想法是一个反事实思想实验：如果 LLM 没有 KV cache，你会怎么设计 coding agent？
  • 直觉盲区在于：cache 按模型隔离，小模型读大模型的上下文要全价，回到大模型时，中途产生的每个 token 还要按输入价再付一遍。
  • 某轨迹分析中读+搜索占工具调用轮次的 56.2%、主 agent token 的 46.5%，若可泛化，“用结构化检索替代子 agent 搜索”是最大的效率杠杆。
