📝 详细摘要

本文提出了一个全面的框架，该框架由三部分组成。它的目的是将临时的人工智能实验转化为可靠且可重复的工程实践。它将“智能体原语”定义为人工智能代理的可重用、可配置的构建块，并将“上下文工程”定义为确保代理专注于最相关信息的过程。该框架从“Markdown 提示词工程”开始，利用 Markdown 的结构通过上下文加载、结构化思考和验证门禁等技术来指导人工智能推理。由此产生了“智能体原语”，它将提示词工程的见解整理为可重用的文件，例如 `.instructions.md`、`.chatmode.md` 和 `.spec.md`。这些文件定义了特定的人工智能能力和规则。最后一层“上下文工程”通过诸如会话拆分、模块化指令和记忆驱动开发等方法来战略性地管理人工智能的上下文窗口，从而优化人工智能性能，防止信息过载。然后，本文详细阐述了扩展这些“自然语言程序”所需的工具链，重点介绍了用于本地执行的 GitHub Copilot CLI 和用于统一运行时管理、软件包分发以及无缝集成到 CI/CD 管道中的 APM (Agent Package Manager)。这种强大的基础设施使智能代理组件能够演变为可共享、版本化和可用于生产的软件生态系统，从而反映了传统编程环境的演变。

💡 主要观点

  1. 一个由三部分组成的框架对于构建可靠的人工智能工作流至关重要。 通过结合 Markdown 提示词工程、智能体原语和上下文工程，可以将临时的人工智能交互转化为系统化、可重复的工程实践，从而确保人工智能输出的可预测性和一致性。
  2. 智能体原语为人工智能代理提供可重用、可配置的构建块。 这些组件以模块化文件的形式实现（例如 `.instructions.md` 和 `.chatmode.md`），使开发人员能够系统地部署结构化指导和基于角色的专业知识，从而提高人工智能的可靠性和一致性。
  3. 上下文工程通过战略性地管理信息流来优化人工智能性能。 会话拆分、模块化指令和记忆驱动开发等技术可帮助人工智能代理专注于相关数据，从而节省上下文窗口空间并提高效率和准确性。
  4. 专用工具链对于扩展和管理智能代理组件至关重要。 GitHub Copilot CLI 等工具支持本地执行，而 APM 提供软件包管理、版本控制和与 CI/CD 管道的无缝集成，从而将自然语言程序视为一流软件。
  5. 人工智能原生开发的演变反映了传统软件生态系统。 这种模式强调，用于运行时环境和软件包管理的强大基础设施（如用于 npm 的 APM）对于培育蓬勃发展、可共享且可扩展的人工智能原生生态系统至关重要。
