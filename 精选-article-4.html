金融监管领域的 Harness 实践：让知识与数据驱动 Agent 稳定运行

10/9/2026, 5:30:00 AM

📌 一句话摘要

本文介绍了中软融鑫在金融监管报送中构建的 Harness 体系，通过知识底座、数据底座、受控状态机和全链路可追溯机制，将自由发挥的 Agent 改造成一个严格遵守监管口径、确保数据准确性的受控系统。

📝 详细摘要

在金融监管领域，数据准确性要求极高，通用大模型的自由发挥往往导致口径漂移和幻觉。中软融鑫通过自研 Harness 架构，将监管发文和内部业务知识构建为知识底座，并基于数据治理成果建立数据底座。在此基础上，通过严格的 Skill 固化、动作白名单、契约化输入输出和全链路留痕，实现了对 Agent 的严格控制，确保其在报送、审核、异常处理和复核等环节中始终遵守预定义规则，从而达到'宁可不答、不能答错'的目标。

💡 主要观点

  1. 金融监管报送对数据准确性要求极高，通用大模型的自由发挥会导致口径漂移和幻觉，因此需要构建一个严格受控的 Agent 系统。 金融机构在报送过程中面临复杂口径、高频度、零容错和强追溯的要求。通用大模型在理解口径时容易产生歧义，并可能生成不符合实际的'幻觉'数据。为了解决这些问题，必须将 Agent 改造为一个严格遵守预定义规则的受控系统。
  2. Harness 体系通过知识底座和数据底座为 Agent 提供可靠的执行基础。 知识底座将监管发文和内部业务流程转化为结构化知识，而数据底座则基于数据治理成果提供标准化、分级分类的数据。这两个底座确保 Agent 在执行任务时能够准确引用正确的口径和数据，避免因信息缺失或错误而导致失败。
  3. 受控状态机制通过限制动作空间和固化 Skill 来防止 Agent 越界。 通过定义动作白名单、进行 Schema 校验和固化常用算法，系统确保 Agent 只能执行预先授权的操作。对于口径信息，Agent 只能读取而不能修改或推测，从而保证处理逻辑的稳定性和一致性。
  4. 全链路可追溯性是确保数据质量和问题诊断的关键。 系统记录了每个 Agent 调用的 Skill、引用的数据路径、执行耗时和结果校验等信息。这种详细的留痕机制不仅帮助业务人员理解数据来源，也为后续的审计和问题排查提供了坚实的基础。

💬 文章金句

  • 在这个场景里，九十七只是一个初步的概念，实际要求要比这高得多。也正因为有这样的极高标准，金融监管领域里积累了大量需要谨慎处理的生产实践。
  • 我们现在把常用算法固化到 Python、Java 程序里，大模型 Agent 只需直接调用对应的 Tool 或过程，这样计算过程和结果都相对可控。
  • 我们没精力去检查每一步里是否真的需要这么多 Token，但设置一个上限后，达到上限就认为过程异常，直接终止。
  • 治理和智能是相互为前提的。不能光说治理好再做智能化，而是一边治理一边做智能化。
