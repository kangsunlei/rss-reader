📌 一句话摘要

文章详细介绍了如何从零开始构建一个功能全面的前端 HTTP 请求库，支持请求缓存、重试、并发控制、SSE 流式数据智能解析及进度追踪等企业级特性。

📝 详细摘要

本文深入探讨了前端 HTTP 请求库的自研之路，作者首先分析了当前主流请求库（如 Axios 基于 XHR）相对于 Fetch API 的局限性，以及现有库在缓存、重试、并发、SSE 处理等方面功能不足或与框架绑定的痛点。在此基础上，作者详细阐述了其自研的 `@jl-org/http` 库所实现的核心功能，包括基于 AbortController 的请求中断、基于 Map 的请求缓存策略、利用 while 循环实现的请求重试机制、基于任务队列的并发控制方案，以及一项创新性的 SSE 流式数据智能解析方案（利用 Fetch API 和有限状态机解决数据分片、消息边界模糊和不完整消息等传输不可靠性问题）。此外，文章还介绍了如何通过监听 Content-Length 头实现请求进度追踪，并提供了一个 CLI 工具来自动生成 API 接口代码，提升开发效率。文章通过代码片段展示了关键实现细节，并提供了重试和缓存的测试截图，最后总结了该库在性能、功能、智能解析、可配置性和类型安全方面的核心优势。

💡 主要观点

  1. 自研请求库弥补了 Fetch API 在高级功能上的不足，并解决现有库的痛点。 文章通过对比 Fetch、XHR 和现有库，指出其在缓存、重试、并发、SSE 处理等方面的缺失，强调自研库通过整合这些功能提供了更全面的解决方案。
  2. 创新的 SSE 流式数据智能解析方案，有效应对网络传输不可靠性。 提出基于 Fetch API 和有限状态机处理 SSE 数据流，解决了数据分片、消息边界模糊和不完整消息等问题，尤其适用于 AI 接口等场景，提升了实时数据处理的可靠性。
  3. 库提供了请求中断、缓存、重试和并发控制等核心企业级功能。 这些功能通过 AbortController、Map 缓存、retryTask 和 concurrentTask 等机制实现，显著提升了应用性能、稳定性和用户体验，满足了企业级应用对请求管理的复杂需求。
  4. 提供了 CLI 工具以提升 API 接口代码生成效率和开发体验。 通过配置文件自动生成带有类型提示的 API 请求代码，简化了重复性工作，并解决了 ESM 与 CJS 兼容性问题，显著提升了前端开发效率和代码一致性。
