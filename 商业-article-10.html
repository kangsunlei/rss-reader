DeepSeek 的 Harness，为何是一头黑色鲸鱼？

8/17/2026, 8:30:00 AM

📌 一句话摘要

DeepSeek 开源 Harness，通过插件化的 Cordis 框架将模型与工具、状态、循环等能力解耦，让开发者可像搭积木一样组装 Agent。

📝 详细摘要

文章介绍 DeepSeek 于 2026 年 8 月 13 日向全球开发者开放的 Harness 开发者预览版，并以 MIT 协议开源。Harness 不是模型权重，而是一套 Agent 运行基础设施，包含模型适配器、工具注册表、会话日志、Agent 循环、任务调度、沙箱、存储等可插拔组件，概括为“一切皆插件”。文章解释了 Harness 的必要性：大模型仅负责生成下一步内容，真正的 Agent 需要上下文管理、权限控制、状态保存、错误恢复等运行层能力，而 Harness 正是承担这一角色。接着详细描述了基于 Cordis 插件系统的设计，阐述了时空可组合性的概念，以及对开发者的三类价值：模型与运行环境分离、企业可接入自身基础设施、Agent 能力形成独立生态。随后列出 Harness 的四种预设运行模式（标准、PTC、极简、创造），分别对应不同的开发目的和实验路径。文章还强调了仅追加会话日志的设计价值与数据治理挑战，并区分了 Harness 与 MCP 的层次关系。最后指出当前版本仍为 v0.1 候选版，部署门槛低但需配置 DeepSeek API Key，并强调开放 Harness 进一步触及“谁能决定模型如何工作”的生态竞争。

💡 主要观点

  1. Harness 将模型与工具、状态、循环等能力解耦为可插拔插件。 基于 Cordis 插件系统，模型适配器、工具注册表、会话日志乃至 Agent 循环均可作为插件加载、卸载或替换，实现“一切皆插件”的灵活架构。
  2. Harness 提供四种预设运行模式，对应不同开发与实验目的。 标准模式面向日常 Agent 任务；极简模式用于基准测试；PTC 模式采用程序化工具调用减少往返；创造模式允许 Agent 在内存中试验并组合新运行模式，支持自我探索。
  3. 开放 Harness 意味着从‘谁能运行模型’向‘谁能决定模型如何工作’的生态竞争。 开放权重解决了模型运行门槛，而开放 Harness 进一步让开发者能影响 Agent 的运行逻辑、工具选择和成本控制，形成更深层的生态价值。

💬 文章金句

  • 一切皆插件
  • 开放权重解决了“谁能运行模型”的问题，开放 Harness 进一步触及“谁能决定模型如何工作”。
  • Harness 正是负责连接模型与这些能力的运行层。
