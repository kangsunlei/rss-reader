微软按下 vibe coding 暂停键：烧 token 已经比员工贵了

5/25/2026, 12:07:00 PM

📌 一句话摘要

微软因 token 成本远超预期，取消了大部分员工的 Claude Code 许可，揭示了「副驾模式」下 AI 成本结构的结构性困境；而 YC 的 AI-native 初创公司则通过用 AI 替代人头，让高额 token 账单变得合理。

📝 详细摘要

文章以微软取消 Claude Code 内部许可为引子，深入探讨了 AI 编程工具在企业中的成本悖论。作者指出，微软的撤退并非因为 AI 不好用，而是因为太好用导致 token 账单暴涨，在「员工工资 + 新增 token 费用」的成本结构下，总成本失控。文章对比了 YC 合伙人 Tom Blomfield 的观点，他认为真正的 AI-native 公司应重新设计组织，用 AI 替代而非辅助员工，让 token 消耗直接替代人头工资。文章进一步分析了「副驾模式」与「替代模式」的本质区别，并指出未来公司的核心资产将从人脑中的知识转向可被 AI 调用的上下文文档。最终结论是，vibe coding 没有失败，但它不适合传统组织架构，所有让员工「多用 AI」的中型公司都将面临类似的成本墙。

💡 主要观点

  1. 微软取消 Claude Code 是因为 token 成本远超预期，而非工具不好用。 员工对 Claude Code 的喜爱导致 token 消耗激增，在保留原有员工薪资的基础上，新增的浮动 token 费用使总成本结构失控，最终微软选择在财年末撤换工具。
  2. 「副驾模式」存在结构性成本悖论：员工工资不变，但 token 账单上不封顶。 传统公司让 AI 辅助现有员工，意味着成本结构变为「原工资 + 新增 token 费用」，而员工产出提升并不直接转化为等比例营收增长，导致财务上难以算清账。
  3. AI-native 公司的核心是用 token 替代人头，而非给员工配副驾。 YC 合伙人提出的模式是，通过减少员工数量、让少数人配合大量 AI agent 工作，使高额的 token 账单直接替代了原本的工资支出，从而在整体上实现成本优化。
  4. 未来公司的核心资产将从人脑中的知识转向可被 AI 调用的上下文文档。 AI-native 公司通过将决策、沟通、技术细节沉淀为文档和 API，构建可继承、不随员工离职而蒸发的资产层，从而改变公司的资产负债表结构。

💬 文章金句

  • 微软撤掉 Claude Code，不是因为它不行，是因为它太行。
  • 对我的团队来说，算力的成本远远超过员工的成本。
  • 如果你的 API 账单不让你心痛，说明你烧得不够。
  • 烧 token 在 YC 的语境里不是支出，是替代。
  • 人是短暂的，上下文文档才是重要的。
