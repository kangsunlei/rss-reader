Agentic 编程：Google 的 Jules 对比 Claude Code，究竟如何？

6/18/2025, 3:40:00 AM

📌 一句话摘要

对比评测 Google Agentic 编程工具 Jules 与 Claude Code 的使用体验和工作流。

📝 详细摘要

文章对比评测了 Google 的 Agentic 编程工具 Jules 与 Claude Code。作者基于一个实际的 Ruby on Rails 项目，尝试使用这两款工具集成 Bootstrap，重点考察了使用流程和体验。Jules 被定位为异步开发代理，擅长处理 bug 和小型功能请求，其独特之处在于深度集成 GitHub，强制采用基于分支和 PR 的工作流。相比之下，作者认为 Claude 在理解意图上更灵活。文章详细描述了使用 Jules 的整个过程，包括连接 GitHub、提交请求、生成开发计划、自动创建分支和提交代码。尽管 Jules 的 GitHub 依赖和强制 Git 工作流对新手不太友好，且理解意图不如 Claude 灵巧，但作者认为其“工业级”的工作流是合理的工程实践，并成功命中了“休闲开发者”的新兴市场。

💡 主要观点

  1. Jules 是一个与 GitHub 深度集成的异步开发代理。 Jules 专为处理软件工程任务设计，尤其适合 bug 修复和小型功能请求，其核心工作流强制依赖 GitHub 进行代码版本管理和协作。
  2. Jules 的工作流基于 Git 分支和 PR，更符合工程实践但对新手有门槛。 通过自动创建分支和提交变更，Jules 实现了工业级的开发流程，但也要求用户熟悉基本的 Git 操作语义。
  3. 在理解用户意图方面，Jules 相对 Claude Code 灵活性稍逊。 尽管可以通过加强 Prompt 工程弥补，但作者实测发现 Claude 在处理非清晰、非一致的指令时表现更“灵巧”。
  4. Google Jules 成功抓住了“休闲开发者”这一新兴用户市场。 尽管存在一些 Google 产品常见的内部不一致性，但其 Agentic 编程的理念和易用性定位，契合了 Vibe Coding 等趋势下的轻量级开发需求。

💬 文章金句

  • Google 的项目 Jules 将自己定义为"一个异步开发代理：Jules 负责修复 bug、小型功能请求以及其他软件工程任务，并可直接导出至 GitHub。"
  • 我不太满意的是它哪怕在 beta 阶段也**只能** 通过 GitHub 运作
  • 它也迫使普通用户必须了解 git 的基本语义 ------ 有点"故意为难小白"的意思。
  • Jules 在理解我意图方面不如 Claude 灵巧，但只要稍微加强 prompt 工程，它也能完成任务。
  • 他们确实看到了"休闲开发者"（casual coder）这个新市场 ------ 这个市场正是最近"vibe coding"兴起的结果。
