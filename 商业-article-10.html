Manus 揭秘自己的技术：“手搓”上下文工程，推翻多个“共识”，一堆血泪教训

7/19/2025, 2:25:00 AM

📌 一句话摘要

Manus 团队深入揭秘其 AI Agent 产品背后的“上下文工程”实践与反直觉的“血泪教训”，重点阐述了 KV 缓存优化、工具管理、文件系统作为扩展上下文及错误处理等核心技术策略。

📝 详细摘要

文章详细阐述了 AI Agent 产品 Manus 在构建过程中，其联合创始人兼首席科学家季逸超关于“上下文工程”的宝贵经验和反直觉的“血泪教训”。核心观点是，相对于从头训练模型，Manus 选择押注上下文工程以实现快速迭代和产品与底层模型的正交性。文章深入探讨了提高 KV 缓存命中率的关键实践，包括保持提示前缀稳定、上下文仅追加原则以及明确标记缓存断点。针对工具数量爆炸式增长的问题，Manus 提出通过“掩码而非移除”工具来管理动作空间，避免动态增删工具导致 KV 缓存失效和模型混淆。此外，文章还创新性地将文件系统视为上下文窗口的无限扩展，以解决长上下文的痛点，并利用 Agent 自身更新待办事项列表的方式来操控模型注意力，避免“迷失在中间”的问题。最后，文章强调了保留错误痕迹的重要性，以帮助模型从失败中学习，并建议在少样本提示中引入多样性以避免 Agent 陷入重复模式。

💡 主要观点

  1. 上下文工程是 AI Agent 快速迭代和正交性的关键 相较于从头训练模型，系统性设计和操控 LLM 上下文结构与内容，能显著缩短迭代周期并使产品独立于底层模型进步。
  2. KV 缓存命中率是生产级 AI Agent 性能和成本的核心指标 通过稳定提示前缀、上下文仅追加及手动标记缓存断点等策略，可大幅提升缓存利用率，降低延迟和推理成本。
  3. 通过“掩码而非移除”工具管理动态动作空间 避免动态增删工具导致的 KV 缓存失效和模型混淆，利用上下文感知状态机和约束解码来限制动作选择。
  4. 将文件系统作为 Agent 的“无限”扩展上下文和记忆 克服固定上下文窗口限制，通过文件系统持久化存储和结构化记忆，解决长任务中信息丢失和模型性能下降问题。
  5. 保留错误痕迹并引入上下文多样性是 Agent 学习和适应的关键 允许模型从失败中学习以减少重复错误，并通过引入受控随机性避免少样本提示导致的 Agent 行为偏离和过度泛化。

💬 文章金句

  • Manus 要押注 context engineering。这样我们能在'数小时'而不是'数周'里交付改进，并保持产品与底层模型'正交'。
  • 如果我必须选择一个指标，我认为 KV 缓存命中率是生产阶段 AI Agent 最重要的单一指标。
  • 这就是为什么我们将文件系统视为 Manus 中最终极的上下文：它的大小无限，本质上是持久的，并且可以由 Agent 自己直接操作。
  • 根据我们的经验，改进 Agent 行为最有效的方法之一简单得令人意外：将走错的弯路保留在上下文中。
  • 你的上下文越统一，你的 Agent 就越脆弱。
