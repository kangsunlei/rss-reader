Claude Code：如何能构建主动式 Agent 工作流？丨 Claude

6/16/2026, 1:29:00 PM

📌 一句话摘要

本文基于 Anthropic 团队演讲，系统介绍 Claude Code routines 主动式 Agent 工作流的设计理念、核心配置与落地路径，强调从「工具等待输入」到「队友主动启动」的转变。

📝 详细摘要

文章以 Anthropic 团队成员 Maya 的演讲为蓝本，详细拆解 Claude Code 新推出的 routines 功能。核心观点是：AI 提效正从「写好 prompt」走向「设计可触发、可观察、可校验的系统」。文章将主动式 Agent 的难点拆解为三层基础设施负担（托管、触发、人工介入），并指出 routine 的最小配置只需 prompt、repo、连接器和触发器四样东西。通过文档同步、GitHub issue 触发、部署验证等具体案例，展示了如何将重复性工作（如 backlog 分拣、文档更新、发布检查）交给按时启动的 agent，同时保留人的最终判断与转向能力。文章强调，主动式 Agent 的价值不在于一次性回答更漂亮，而在于能在问题出现时先开始调查，从而释放团队注意力。

💡 主要观点

  1. 主动式 Agent 的核心是从「工具等待输入」变为「队友主动启动」。 routines 让 Claude Code 可按日程、GitHub 事件或 webhook 主动启动远程会话，无需人工按下回车，将 AI 入口从聊天框扩展到日历、GitHub、Slack 等渠道。
  2. 构建主动式 Agent 需解决三层基础设施负担：托管、触发与人工介入。 agent 跑在哪里、何时触发、人如何观察与转向，是产品团队必须与工程、运维共同确认的边界，否则自动化流程无法放心交接。
  3. Routine 的最小配置只有 prompt、repo、连接器和触发器四样。 配置极简，但每个 routine 底层仍是可打开的 Claude Code 会话，团队可在 web/CLI/desktop 上实时观察、追问、转向，避免做成黑箱后台任务。
  4. 上下文决定 Agent 成功的上限。 Claude 能访问的上下文（源码、文档、Slack、监控工具等）直接决定其判断质量，PM 在设计工作流时需像写需求一样列清输入源、权限与输出位置。
  5. PM 可先从 backlog 分拣等小流程切入，逐步建立信任。 先挑一个每周重复、输入稳定、结果需人确认的流程（如文档同步、issue 分拣），用 /schedule 命令创建第一个 routine，跑顺后再逐步放权。

💬 文章金句

  • 编码 agent 不该等你按下回车才开始工作。
  • Claude 拥有的上下文，就是它能成功的上限。
  • 我们想把 Claude Code 从今天的工具，变成明天的队友。
  • 好 workflow 的第一步，往往在于定义「哪件事发生时，AI 应该开始工作」。
  • 主动式 agent 不一定要替你做最终判断，它可以先替你把该开始的工作准时启动。
