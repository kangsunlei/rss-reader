我们对 Coding Agent 的评测，可能搞错了方向

1/16/2026, 12:20:00 PM

📌 一句话摘要

文章指出当前 Coding Agent 测评体系过度关注结果忽视过程规范，并介绍了 MiniMax 开源的 OctoCodingBench 评测集，强调 Agent 应从“能跑的代码”转向“符合规范并能协作”。

📝 详细摘要

文章指出当前主流的 Coding Agent 评估体系存在盲区，过度关注任务结果（Outcome-based Metrics），却忽视了 Agent 完成任务过程中的规范遵循问题，导致评估与实际工程场景错位。文章核心观点是，Agent 的「做得不好」主要体现在不遵循明确指令和潜在工程规范，例如不使用 emoji、先备份再修改等。为了解决这一问题，MiniMax 开源了 OctoCodingBench 评测集，旨在评估 Coding Agent 在多层指令系统（包括系统提示、用户查询、仓库规范文件、Skills、Memory/Preferences）下的过程合规性。评测结果显示，即便是最强的模型，其 Instance-level 成功率（ISR）也远低于 Check-level 准确率，大多数模型在长流程任务中指令遵循能力会下降。文章强调未来的研究方向应引入过程监督（Process Supervision），实现细粒度监督、层级化指令遵循和可验证清单，从而促使 Coding Agent 从单纯实现功能向成为“懂规矩、守纪律”的团队成员发展，最终从 Demo 走向生产环境。

💡 主要观点

  1. 现有 Coding Agent 评测体系存在缺陷，过度强调结果导向而忽略过程规范。 主流学术榜单如 SWE-bench 仅关注测试是否通过、Bug 是否修复，忽视了 Agent 在代码生成过程中是否遵守了如编码规范、安全协议等工程层面的要求。
  2. 用户对 Agent 的不满源于其过程不合规，而非能力不足。 Agent 即使能完成任务，但若不遵循指令如不使用 emoji、未经备份即修改文件等，会降低其在实际工程协作中的可用性和信任度。
  3. MiniMax 开源的 OctoCodingBench 评测集聚焦于 Coding Agent 的过程合规性评估。 该评测集通过 Check-level 准确率（CSR）和 Instance-level 成功率（ISR）衡量 Agent 遵循多层级指令系统（如 System Prompt、用户 Query、仓库规范等）的能力。
  4. 当前 Coding Agent 在过程合规方面表现不足，与生产要求有差距。 评测显示，即使顶尖模型在单项约束上表现尚可，但在同时满足所有规则时成功率断崖式下跌，且指令遵循能力随任务轮次增加而下降，表明过程合规性尚未被充分优化。
  5. 未来 Coding Agent 发展需引入过程监督（Process Supervision）。 通过细粒度监督、层级化指令遵循和可验证 Checklist，使 Agent 能够学习如何在复杂约束甚至指令冲突场景下做决策，从而成为更称职的团队成员。

💬 文章金句

  • 一个反复出现，但常常被忽略的现象是：用户对 Agent 的不满，往往不是因为它「做不到」，而是因为它「做得不好」。
  • 这种评估方式，不看模型在沙盒里的输出过程，也不看真实场景的交互体验。最后的结果是：评估和真实使用场景，完全错位。
  • 即便是最强的模型，在 2/3 的任务中，代码可能是对的，但过程是错的。
  • 所有模型的 Check-level 准确率 (CSR) 可以达到 80%+，但 Instance-level 成功率 (ISR) 只有 10%-30%。
  • Coding Agent 的能力边界，正在从「能否写出能跑的代码」，转向「能否在复杂约束下协作式地完成任务」。
