让产品经理在 Agent 时代高效产出的 skills 和 kit 分享

9/3/2026, 11:45:00 PM

📌 一句话摘要

本文介绍了七个开源的 Skill 和项目底座，帮助产品经理在 Agent 时代高效地进行需求分析、PRD 撰写、原型绘制、代码拆解和上下文构建，从而实现从模糊想法到可执行产品的快速转化。

📝 详细摘要

在 AI 时代，产品经理需要掌握新的工具和方法来应对快速变化的开发环境。本文分享了七个开源项目，涵盖了从最初的模糊想法整理、PRD 撰写、交互原型展示，到代码拆解、开源项目分析，以及个人和团队协作的上下文构建。这些工具旨在帮助产品经理更好地利用 Agent，提高工作效率，并确保产品开发的质量和可控性。

💡 主要观点

  1. PM-Make：模糊想法到清晰描述 该 Skill 帮助产品经理将初步的、模糊的产品想法通过提问和整理，转化为包含用户场景、产品边界和功能清单的详细描述，为后续开发提供清晰的起点。
  2. Make-PRD：可控的 PRD 撰写 通过分段交付和严格的控制，该 Skill 确保 Agent 在撰写 PRD 时不会因为局部反馈而引发全局改写，从而提高文档的质量和一致性。
  3. Interaction-PRD：一体化评审界面 该 Skill 将文档、可交互原型和页面标注整合到一个本地网页工作区，方便产品经理进行综合评审，并为后续的 UI 和前端开发提供清晰的参考。
  4. demo-to-product-model：从代码还原产品事实 该 Skill 拆解产品 Demo 的代码和开发对话，提取出路由、组件、API 等关键信息，帮助产品经理将 Vibe-Coding 的成果转化为可用于团队协作的产品文档。
  5. github-analysis：拆解开源项目 该 Skill 专门用于分析开源项目，帮助产品经理理解项目的架构、AI 环节和设计模式，从而为自己的产品开发提供灵感和参考。
  6. vibe-solo-kit：个人项目的可恢复上下文 这套组件为个人项目提供了一个轻量级的作业环境，通过记录关键决策和功能开发，确保在切换 Agent 或协作时，项目上下文始终保持完整和可理解。
  7. xxxdev-kit：团队资产编译 该 Kit 帮助团队将分散的资产（如设计系统、接口规范）整理并编译成一个受约束的 Agent 工作空间，确保团队成员在协作时遵循统一的规则和标准。

💬 文章金句

  • 这套 Skill 产出的 7 个定型文档信息密度非常大，特别适合直接丢给 Agent 直接 Vibe-Coding，产出的质量相当之高。
  • 这种约束针对一个常见问题：Agent 写长文时，前文的假设会在后文变成事实，局部反馈也容易引发全文改写。分段交付保留了审阅点，产品经理可以在规则扩散前纠正它。
  • 为了方便后续 UI 和前端理解页面关系，脚手架还提供一个呈现所有页面和关系的画布。
  • 我的 Hermes 有个定时任务，每天刷一遍 GitHub Trending 里的项目，随机选一个 AI 相关的使用这个 Skill 进行拆解、分析，把分析结果同步到我的飞书文档，然后推消息给我。
