本文深入探讨了 CSS 层叠上下文，解释了 z-index 经常失效的原因，并提供了调试和解决层叠问题的实用策略。

📝 详细摘要

文章探讨了 CSS 层叠上下文的复杂性，这是 Web 布局中一个基础但常被误解的方面，它决定了元素如何沿 z 轴层叠。作者引入了“文件夹”类比，解释了某些 CSS 属性（如 position、opacity 和 transform）如何将元素分组到隔离的子层叠中，从而防止子元素脱离其父层级，无论 z-index 值是多少。通过三个常见场景——被困的模态框、被淹没的下拉菜单和被裁剪的工具提示——作者演示了如何使用浏览器 DevTools 识别“被困”的层。最后，文章概述了有效的解决方案，包括 DOM 重构、父上下文调整、现代框架中 Portal 的使用，以及用于创建无副作用的纯净层叠上下文的 isolation: isolate 属性。

💡 主要观点

  1. 层叠上下文就像文件夹，将子元素与全局堆栈隔离。 一旦一个元素创建了层叠上下文，其子元素仅在彼此之间进行排序；它们无法在不同且层级更高的父文件夹元素之间或之上移动。
  2. transform 和 opacity 等属性为了 GPU 优化而创建层叠上下文。 浏览器将这些元素扁平化为独立的层，以便更高效地处理动画和效果，这无意中触发了层叠上下文作为副作用。
  3. 调试层叠问题需要系统性地向上遍历 DOM 树。 由于子元素的可见性通常受限于“祖先的过错”，开发人员必须检查父级样式中是否存在 position、overflow 或 contain 等建立低层级上下文的属性。
  4. Portal 和 DOM 重构是解决被困元素最稳健的方法。 将模态框或工具提示移动到 document body 可确保其位于根层叠上下文中，从而绕过任何限制性的父级样式或溢出裁剪。
  5. isolation: isolate 属性可以在没有视觉副作用的情况下创建层叠上下文。 与使用 opacity 或 transform 不同，isolation 显式地启动一个新上下文，允许内部 z-index 管理（如负值）而不影响元素的外部行为。

💬 文章金句

  • 一旦一张纸（即子元素）放入文件夹（即父层叠上下文）中，它就永远无法离开该文件夹，也无法放置在另一个文件夹中的纸张之间。
  • 浏览器决定谁在上面，它先堆叠文件夹，而不是文件夹里的单张纸。
  • 被遮挡的元素本身不是问题；是某个祖先元素创建了一个低层级的层叠上下文，导致子元素处于下方。
  • 我认为开发者非常信任 z-index，以至于期望它能解决任何遮挡问题，但实际上，它的工作方式并非如此。
  • Portal 就像是组件的传送装置……非常适合逃离层叠上下文陷阱。
