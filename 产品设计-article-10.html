处理带参数的 JavaScript 事件监听器 — Smashing Magazine

📌 一句话摘要

本文介绍了在 JavaScript 事件监听器中，使用箭头函数、匿名函数和闭包处理参数，并防止内存泄漏的有效方法。

📝 详细摘要

本文旨在解决 JavaScript 开发中，向事件监听器传递参数并避免内存泄漏的常见问题。文章指出了在 `addEventListener` 中直接调用函数所导致的错误，并提供了两种解决方案：一是使用箭头函数或匿名函数，虽然需要 `AbortController` 来移除监听器，但适用于管理多个监听器；二是利用 JavaScript 闭包，它允许传递参数，并可以通过存储对 handler function 的引用，使用 `removeEventListener()` 方法移除监听器。文章强调，不再需要的事件监听器应及时移除，并为每种方法提供了代码示例，帮助开发者有效管理交互元素，避免性能问题。

💡 主要观点

  1. 直接在 `addEventListener` 中调用函数会导致立即执行，而不是事件触发。 一个常见的错误是 `button.addEventListener('click'， myFunction())`，这会立即执行 `myFunction`，阻止事件在点击时被触发，并可能由于不正确的参数类型而导致 `TypeError`。
  2. 箭头函数/匿名函数允许传递参数，但需要 `AbortController` 进行移除。 这些函数提供了一种传递参数的快速方法，但由于其匿名性，`removeEventListener` 难以直接定位这些函数。`AbortController` 为批量移除提供了一个强大的解决方案。
  3. 闭包提供了一种传递参数的方式，同时保留了 `removeEventListener` 兼容性。 通过返回一个充当事件处理程序的内部函数，闭包允许访问外部作用域的变量（参数），并通过存储对外部函数的引用来启用 `removeEventListener`。
  4. 正确移除事件监听器对于防止内存泄漏和性能问题至关重要。 无论使用何种方法，在不再需要事件监听器时主动移除它们，是维护应用性能和防止资源消耗的基本最佳实践。

💬 文章金句

  • JavaScript 事件监听器在添加后通常不会被移除。
  • 浏览器通过立即调用该函数来响应此行代码，而不管是否发生了点击事件。
  • 使用箭头函数和匿名函数的唯一问题是，它们无法使用传统的 `removeEventListener()` 方法移除；您将必须使用 `AbortController`，这对于简单的情况来说可能有些过度。
  • JavaScript 中的闭包是另一种可以帮助我们处理事件处理函数的功能。
  • 始终在不再需要事件监听器时移除它们以防止内存泄漏是一个好习惯。
