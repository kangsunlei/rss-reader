为什么 Java 之父 James Gosling 认为工程师是艺术家

10/24/2026, 2:00:00 AM

📌 一句话摘要

Java 之父 James Gosling 接受采访，分享 Java 推广的自下而上社区驱动模式、对当前 AI 泡沫的警示、安全伦理在软件工程中的核心地位，以及他将编程视为一种兼具功能性与艺术性的手艺。

📝 详细摘要

本文是 THE STACK 对 Java 之父 James Gosling 的专访，涵盖多个维度：Java 的推广策略——Gosling 强调社区驱动的自下而上模式，以银行交易系统从 C 语言迁移到 Java 的真实案例说明技术说服力；AI 发展的反思——他认为自上而下强制推广 AI 效果很差，OpenAI 和 Anthropic 的商业模式在数学上不可持续，95% 的 AI 创业公司会失败；工程伦理——安全是首要考量，如同消费电器的「零号需求：不伤害客户」，而做好安全成本高昂且不产生炫目的功能效果；编程的手艺属性——Gosling 认为工程师都是艺术家，代码之美在于清晰、可理解、可维护，这决定了系统能否被后续工程师接手；LLM 编程助手——他使用但会重写所有生成代码，真正的价值在于提供 API 和编程环境的地图，而非生成高质量代码。

💡 主要观点

  1. Java 的成功源于自下而上的社区驱动推广 Gosling 讲述银行交易系统从 C 语言迁移到 Java 的案例：工程师私下重写并通过测试后说服管理层，最终以实际表现（无崩溃）赢得信任。他强调开源的本质就是自下而上的营销，让任何人先尝试，形成飞轮效应。
  2. 自上而下强制推广 AI 违背工程现实，AI 泡沫即将破裂 Gosling 批评企业 CEO/CIO 被供应商施压后强推 AI 的做法，指出 OpenAI 和 Anthropic 的商业模式在数学上不可行，建造昂贵数据中心的意义存疑，预计这轮 AI 创业公司失败率会超过 95%。他看好微软、谷歌、亚马逊等大公司，对社交媒体公司评价较低。
  3. 安全是软件工程的零号需求，如同消费电器的「不伤害客户」 Sun 从创立起就将安全作为核心，因为其产品用于银行和工业系统，一分钟故障可能造成数百万损失或危及人命。Gosling 指出管理者讨厌安全——成本高且不产生可见功能，但这是必须默认做到的底线。
  4. 编程是兼具功能性与艺术性的手艺，代码之美在于可理解与可维护 Gosling 将优秀工程师比作艺术家，以水管工和电工的美观布线为例。代码的清晰度和可理解性决定了运行数十年的系统（如伦敦地铁控制系统）能否被后续工程师顺利接手和维护。
  5. LLM 编程助手价值在于 API 地图，而非生成高质量代码 Gosling 使用 LLM 辅助编程但会重写所有生成代码。他指出编程语言容易学，难的是所有接口（网络、数据库等），LLM 真正的价值是提供编程环境和 API 的概览，而非替代人类编写高质量代码。

💬 文章金句

  • 我一直相信自下而上的营销。从某种意义上说，这就是开源的本质，就是自下而上的营销。
  • AI 仍然相当新，尤其是在大约三年前刚开始推广的时候，有很多科学实验亟待进行。但有太多资深人士却假设 AI 公司的炒作是真实的。
  • 我认为，OpenAI 和 Anthropic 尤其处于这样一种境地：他们的做法从数学上来说行不通，把巨额资金挥霍视为成功的衡量标准。
  • 对于烤面包机这样的设备，确实存在真正的风险。但他们绝不会在营销材料中写上'我们承诺不会伤害你'，而在计算机行业中，安全在很多方面也是如此——大家都默认你会这么做。
  • 我认为所有工程师都是艺术家，只是方式略有不同。
  • 大语言模型编程助手真正给我带来的价值在于，当你试图在一个从未涉足的领域编写软件时。
