📌 一句话摘要

ReSharper 采用独立进程 (OOP) 架构，显著减少 UI 线程延迟并提高打字响应速度。JetBrains 计划发布公开测试版本。

📝 详细摘要

这篇文章介绍了 ReSharper 在采用独立进程 (OOP) 架构方面取得的重大进展，旨在解决 UI 线程阻塞和垃圾回收开销等性能问题。由于用户反馈表明 ReSharper 的强大功能降低了 Visual Studio 的响应速度，因此 JetBrains 决定采用 OOP 架构。通过将 ReSharper 的核心功能移至单独的进程，显著减少了对 Visual Studio 响应速度的影响。文章详细介绍了如何通过模块化架构和 RD 协议（Remote Dev 协议）实现平滑迁移和进程间通信，并量化了 OOP 架构在减少 UI 线程暂停和提高打字响应速度方面的改进。文章还列出了当前支持的功能和已知问题，例如与某些 JetBrains 工具的不兼容，并宣布计划在不久的将来发布公开测试版本。

💡 主要观点

  1. 独立进程 (OOP) 架构显著减少了 ReSharper 对 Visual Studio 响应速度的影响 通过将 ReSharper 的核心功能移至单独的进程，减少了 UI 线程上的延迟，提高了打字响应速度。
  2. 模块化架构和 RD 协议是实现平滑迁移和进程间通信的关键 模块化架构允许逐步将 ReSharper 的各个组件迁移到 OOP 模型，而 RD 协议实现了 ReSharper 进程和 Visual Studio 进程之间的通信和数据同步。
  3. 实际测试表明，OOP 架构显著提高了打字响应速度 在实际打字场景中，中值打字延迟降低了 37%，UI 线程上的显著暂停次数减少了 6 倍。
