架构性能跃迁！iLogTail 超大规模日志采集最佳实践

3/27/2025, 11:20:13 AM

📌 一句话摘要

滴滴通过 C++ 重写和向量化优化等手段，深度优化了阿里云开源的 iLogTail，解决了性能瓶颈，实现了超大规模日志的稳定高效采集。

📝 详细摘要

文章介绍了滴滴如何基于阿里云开源的日志采集器 iLogTail，构建超大规模日志采集体系的最佳实践。针对原内部 Agent 在大流量下性能瓶颈的问题，滴滴选择了 iLogTail 并进行了深度优化。优化包括：1) 使用 C++ 重写 FlusherKafka 插件，解决 Go GC 带来的性能压力；2) 采用基于时间规则的多行解析，提升解析性能 1 倍；3) 引入支持向量化的 JSON 库 sonic-cpp，加速 JSON 序列化；4) 实现 Kafka 发送失败时的 offset 回滚和退避重试机制，保证数据可靠性。优化后的 iLogTail 版本在资源效率方面提升显著，CPU 资源消耗降低 56%，整体采集性能提升超过 2 倍，单节点可支撑 600 个采集任务并行处理，满足了滴滴内部超大规模日志采集的需求。这些优化经验对于其他使用 iLogTail 的公司具有一定的参考价值。

💡 主要观点

  1. C++ 重写 FlusherKafka 插件是解决 Go GC 性能瓶颈的关键步骤。 在日志采集场景中，大量日志对象的频繁创建和销毁对 Go GC 造成很大压力，使用 C++ 重写避免了 GC 消耗，以及 C++ 调 Go 时的协议转换开销，此优化是针对滴滴内部的特定需求进行的。
  2. 基于时间规则的多行解析大幅提升了日志解析性能。 通过时间戳判断日志是否属于异常堆栈，避免了正则表达式匹配的性能开销，处理速度提升 1 倍，并通过 AVX2 指令集向量化解析换行符，提升 CPU 性能，此优化是针对滴滴内部的特定需求进行的。
  3. 引入 sonic-cpp 高性能 JSON 库加速了序列化过程。 通过向量化加速查找转义字符，并支持构建 Json 对象时传递 std::string_view，避免了大量内存拷贝开销，进一步提升了 iLogTail 的性能，此优化是针对滴滴内部的特定需求进行的。

💬 文章金句

  • iLogTail 在面临多任务超大流量时，能保证采集不延迟，且使用不到 5core 就能采集 420+MB/s 的流量，已经能满足内部的需求。
  • 在相同 Kafka 发送链路场景下，内部版本 CPU 资源消耗较开源版本降低 56%，整体采集性能提升超过 2 倍。
  • 本次优化不仅验证了 iLogTail 的先进性，更使其成为支撑海量日志采集场景的核心基础设施，为后续千万级数据管道的构建提供了关键能力保障。
