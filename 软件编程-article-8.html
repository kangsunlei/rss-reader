Google 想为 AI Agent 打造下一个 Kubernetes

5/30/2026, 2:00:00 AM

📌 一句话摘要

Google 开源了 Agent Substrate 和 Agent eXecutor (AX) 两个项目，旨在 Kubernetes 之上构建一个专为 AI Agent 设计的轻量级控制平面和运行时，通过挂起非活跃 Agent 来大幅提升硬件效率。

📝 详细摘要

本文报道了 Google 最新开源的两个项目：Agent Substrate 和 Agent eXecutor (AX)，它们旨在解决大规模 AI Agent 在 Kubernetes 上运行时面临的效率瓶颈。文章指出，传统基础设施在处理 Agent 工作负载时，常因 Agent 等待人类交互或外部工具而处于空闲状态，导致计算和内存资源被长期占用。Agent Substrate 通过将 Agent 的逻辑生命周期与底层计算资源解耦，允许在 Agent 空闲时将其状态快照保存并释放 Worker 资源，在需要时快速恢复（毫秒级），从而避免了冷启动开销。AX 则作为运行在 Substrate 之上的分布式 Agent 运行时，负责协调 Agentic 循环、管理事件日志和 Actor 通信。Google 表示，这种架构在突发式工作负载下可将硬件效率提升 97%，并强调该项目目前处于早期阶段，但希望通过社区协作，像 Kubernetes 一样成为厂商中立的基础设施。

💡 主要观点

  1. Google 开源 Agent Substrate 和 AX，旨在解决 AI Agent 在 K8s 上的规模化运行难题。 这两个项目构建在 Kubernetes 之上，通过一个轻量级控制平面和运行时，专门优化 Agent 场景下的高频交互和突发性工作负载，弥补 K8s 在 Agent 编排上的短板。
  2. 核心创新在于将 Agent 的逻辑生命周期与计算资源解耦，实现“零空闲”架构。 当 Agent 空闲时，其状态被快照保存，Worker 资源释放回共享池；当需要恢复时，可在任意可用 Worker 上快速恢复（毫秒级），大幅提升硬件利用率，演示显示 30 个逻辑 Agent 可共享同一份物理容量。
  3. 项目处于早期阶段，但 Google 希望复制 Kubernetes 的成功路径，打造厂商中立的 AI 基础设施。 两个项目均采用 Apache-2.0 许可证，目前版本为 v0.0.0 和 v0.1.0，不保证向后兼容。Google 强调开放构建，旨在通过社区参与推动项目成熟，并最终为自家云服务创造需求。

💬 文章金句

  • 在传统模型下，每一个活跃对话通常都会将计算和内存资源绑定到一个专用进程或容器上，即使它正在等待缓慢的外部事件。
  • Agent Substrate 将 Agent 的逻辑生命周期与底层计算资源解耦。当 Agent 进入非活跃状态时，它的执行状态会被快照保存，处理它的 Worker 则返回共享池。
  • 我们选择以开放方式构建这一项目，是因为我们相信，未来的 AI 基础设施必须厂商中立、可移植，并由社区共同推动。
