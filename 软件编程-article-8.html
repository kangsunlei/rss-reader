火山引擎 AI 搜索千万级 Agent 架构演进与实践：从 ReAct 三节点到 Unified Policy

6/26/2026, 9:00:00 AM

📌 一句话摘要

本文详细解析火山引擎 AI 搜索团队如何将标准 ReAct 架构演进为 Unified Policy Agent 架构，通过 Workflow 与 Agent 分层、统一控制/行为/状态，实现 TTFT 降低 30%与推荐质量提升。

📝 详细摘要

文章深入剖析了企业级 AI 搜索场景下标准 ReAct 架构的三大工程原罪：极高延迟、上下文震荡与控制流破碎。结合业界共识，提出 Workflow 与 Agent 严格分层、万物皆 Tool、上下文独立化等原则。火山引擎 AI 搜索团队基于此设计了 Workflow + Unified Policy Agent (UP-ReAct)架构，将确定性流程交给 Workflow，动态决策交给 Unified Policy，所有行为抽象为 Tool，状态由 Context Manager 统一管理。该架构在真实电商评测中，TTFT 从 14.045s 降至 9.8s（降 30.22%），推荐准确性提升 3.76%，对话体感提升 14.78%，打破速度与质量互斥的常规认知。文章强调，系统复杂性应通过边界划分合理安置，而非塞入模型。

💡 主要观点

  1. 标准 ReAct 三节点架构在高并发工业场景存在三大原罪：高延迟、上下文震荡、控制流破碎。 三节点每次调用需三次独立决策流转，导致 TTFT 急剧恶化；状态在节点间重复搬运引发注意力稀释；新工具难以自然融入，工程师被迫硬编码 If-Else，系统退化。
  2. 行业共识转向 System Engineering：Workflow 与 Agent 分层、万物皆 Tool、上下文独立化、生产级 Eval。 预定义路径和硬规则交给 Workflow，Agent 只做动态策略决策；工具作为强契约决定系统下限；上下文管理独立为模块；用多维指标而非主观感受衡量系统。
  3. Unified Policy Agent 通过统一控制、统一行为、统一状态解决 ReAct 的痛点。 将 Thought/Action/Iteration 合并为单一 Policy 节点，单次前向传递完成规划、动作选择与终止判定；所有行为封装为 Tool（包括退出、深度思考等）；Context Manager 按预算窗口、语义压缩、分级驱逐管理上下文，减少干扰。
  4. 新架构实现了速度与质量的双重提升，TTFT 下降 30%的同时推荐与对话质量显著提高。 通过消除冗余节点和上下文降噪，模型注意力被聚焦于核心目标，决策失真率下降，打破常规认知中速度与质量互斥的定律。

💬 文章金句

  • 不要用 LLM 去做普通的 switch-case。
  • 少谈些奇技淫巧的 Prompt，多讲点扎实的 System Engineering。
  • 模型本身并没有变聪明，是我们不再用垃圾信息干扰它了。
  • 敬畏工程规律，做好复杂性治理。
  • 让大模型走下神坛，钻进流水线，变成极其坚固、稳定、疾速的工业级生产力引擎。
