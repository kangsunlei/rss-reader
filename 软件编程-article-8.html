Claude Code 80%的提示词说删就删，Anthropic 用 Fable 5 打了个样：AI 行业的“降本”才刚刚开始

7/3/2026, 8:54:00 AM

📌 一句话摘要

本文分析 AI 编程工具 Claude Code 的 token 成本失控问题，指出其以“烧 token 换体验”的设计哲学导致 prompt 债膨胀，Anthropic 已删除 80%系统提示词以降本，并对比 OpenAI 更注重 token 效率的路线。

📝 详细摘要

文章以 Anthropic 的 Claude Code 为案例，深入剖析 AI 编程工具在快速普及中暴露的 token 成本失控问题。作者指出，Claude Code 的设计初衷是展示模型“聪明”，而非帮助开发者省 token，导致大量算力浪费在无关输出和过长的系统提示词上。文章引用 Anthropic 技术团队的演讲，说明其已删除 80%的系统提示词（从 65000 token 大幅缩减），并分析“prompt 债”的隐蔽危害：旧 prompt 会限制新模型能力，且每次调用都需计费。同时，对比 OpenAI 在模型内部使用压缩语言提升 token 效率的做法，以及 Caveman 等第三方工具的出现，反映行业从“堆 token”向“省 token”的转向。最后指出，AI 公司降本的第一刀往往砍向冗余提示词，因为多说一个字就多花一份钱。

💡 主要观点

  1. Claude Code 的设计本质是营销工具，通过烧 token 营造“高产”错觉。 项目负责人承认出发点是如何展示模型聪明，而非省 token，导致大量算力用于非必要的 UI 动画、冗长推理过程等，加剧成本失控。
  2. Anthropic 已删除 Claude Code 80%的系统提示词，反映提示工程从“堆量”转向“精简”。 旧 system prompt 一度膨胀至 65000 token，每次调用都产生固定成本且限制新模型发挥。删除后既降本又释放模型潜力。
  3. Prompt 债比代码债更隐蔽，长期堆积会使模型表现“悄悄变差”。 旧提示词可能不再适配新模型，但问题不会像代码 bug 那样暴露，用户只会感觉“模型不如以前聪明”。
  4. OpenAI 与 Anthropic 在 token 效率上路线分化：前者追求压缩，后者依赖大上下文。 OpenAI 在模型内部使用类似工程速记的压缩语言减少推理 token，Anthropic 则生成完整英语、依赖百万级上下文窗口，成本更高。
  5. Caveman 等第三方工具的出现，印证了市场对“废话税”的零容忍。 Caveman 通过压缩模型输出中寒暄、过渡语等无意义内容，减少 65%-75%输出 token，甚至获得 OpenAI 工程总监贡献代码。

💬 文章金句

  • 能多烧 token 解决的问题，绝不找更省 token 的办法。
  • Prompt 债比代码债更隐蔽。代码老了，通常会在改功能、跑测试、处理 bug 时暴露出来。Prompt 老了，却可能只是让模型悄悄变差。
  • 如果 Anthropic 修复了“废话太多”这个问题，它们的收入会明显下降。
  • Caveman save you token， save you money. Star cost zero.
