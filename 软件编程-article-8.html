提高 Web 上 JavaScript 的可信赖性

10/16/2025, 2:00:00 PM

📌 一句话摘要

本文介绍了 Web 应用程序完整性、一致性和透明性 (WAICT)，这是一项由 W3C 支持的倡议，旨在提高 Web 应用程序的可信赖性，特别是对于浏览器内密码学，通过增强其安全性来实现。

📝 详细摘要

本文探讨了基于 JavaScript 的 Web 应用程序中可信赖性这一关键且长期存在的问题，特别是关于浏览器内密码学，它在分发过程中仍然容易受到代码篡改的影响。文章将此问题与智能手机应用商店进行类比，后者提供了重要的安全属性，如完整性（确保代码不被篡改）、一致性（所有用户获得相同的应用程序）和透明性（应用程序版本的公共记录）。文章的核心是介绍 Web 应用程序完整性、一致性和透明性 (WAICT)，这是一项由 W3C 支持的倡议，旨在为 Web 带来这些强大的安全保障，而无需依赖单一的中心机构。WAICT 通过对单个资源使用子资源完整性 (SRI)，以及使用“完整性声明文件”以密码学方式提交整个 Web 应用程序的所有资产来实现完整性。对于透明性，该系统采用基于站点的哈希链来维护清单更改的仅附加日志，并采用全局前缀树（字典树）来跟踪所有已注册的站点及其各自的日志状态。这种结构允许受信任的第三方“见证者”签署树更新，从而实现 Web 应用程序版本的公共可审计性。文章还详细介绍了 WAICT 的关键设计要求，例如选择性参与、不增加额外的网络往返、用户隐私和非中心化。此外，它还讨论了通过限制透明性服务的数量，并要求见证者签名具有合理较短的有效期来缓解树和时间不一致的问题，从而提高 Web 应用程序的整体安全态势。

💡 主要观点

  1. 由于 Web 代码分发中缺乏完整性保证，浏览器内 JavaScript 密码学面临着严重的可信赖性问题。 与原生应用程序不同，Web 应用程序缺乏一个中心机构（如应用商店）来确保交付的 JavaScript 代码没有被篡改，这对诸如密码密钥生成等敏感操作构成了严重风险。
  2. WAICT 提出了子资源完整性 (SRI) 和一个“完整性声明文件”，以精确定义 Web 应用程序的整个资产集，并以密码学方式提交。 SRI 保护单个外部资源，而完整性声明文件将此概念扩展到覆盖域下的所有资产，从而确保整个站点的代码库都经过哈希处理，并且可以被浏览器验证。
  3. 透明性是通过每个站点的清单日志的哈希链和所有已注册站点的全局前缀树（字典树）来实现的，从而可以公开审计 Web 应用程序版本。 哈希链为站点清单提供仅附加日志，而前缀树（字典树）在全球范围内跟踪这些日志，从而使见证者和浏览器无需单一信任点即可验证站点完整性和历史记录。

💬 文章金句

  • 正如 2011 年一样，今天 JavaScript 密码学仍然被认为是有害的。
  • WAICT 是由浏览器供应商、云提供商和加密通信开发者共同支持的 W3C 项目，旨在为整个 Web 带来更强大的安全保障。
  • 如果页面上的每个外部脚本、样式表等都带有 SRI 完整性属性，那么整个页面就仅由其 HTML 定义。
  • 回想一下，透明的 Web 应用程序是指其代码存储在可公开访问的仅附加日志中的应用程序。
  • 我们不会实现最强版本的一致性，但事实证明，较弱的概念对我们来说已经足够了。
