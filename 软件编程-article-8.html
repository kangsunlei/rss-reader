Google 增强 LiteRT，加速设备端推理

5/24/2025, 12:00:00 AM

📌 一句话摘要

Google 全新 LiteRT (原 TensorFlow Lite) 通过精简的 API、优化的 GPU 加速和扩展的 NPU 支持，增强设备端 ML 推理能力，实现更快速高效的性能。

📝 详细摘要

Google 发布了设备端机器学习推理引擎的重大更新，现已更名为 LiteRT (原 TensorFlow Lite)。主要改进包括精简的 API，旨在简化硬件加速的集成。一种新的 GPU 加速方案 MLDrift，承诺相比早期版本和其他框架，尤其是在 CNN 和 Transformer 模型上，带来更卓越的性能。更重要的是，LiteRT 增加了对高通和联发科 NPU 的原生支持，为开发者提供了一种统一的方式来充分利用这些节能加速器，它们的性能比 CPU 快 25 倍，功耗却降低 5 倍。通过 TensorBuffer API 实现的零拷贝缓冲区互操作性，以及对异步并发执行等高级功能的支持，进一步优化了性能，有望将延迟减半。文章重点介绍了 LiteRT 在 GitHub 上的可用性，并提供了示例应用，将其定位为在移动和边缘设备上部署 AI 模型的强大工具。

💡 主要观点

  1. LiteRT 引入了精简的 API，以便更轻松地集成硬件加速。 新的 API 简化了指定目标后端（CPU、 GPU、 NPU）的过程，不再需要为每种后端使用不同的方法，从而简化了设备端机器学习的开发。
  2. 增强的 GPU (MLDrift) 和新的 NPU 支持提供了显著的性能和效率提升。 MLDrift 提供了更快的 GPU 推理速度，而通过 NNAPI 集成 NPU，相比 CPU，速度提升高达 25 倍，功耗降低 5 倍，从而使设备端 AI 更加可行。
  3. 零拷贝和并发执行等高级功能进一步优化了推理性能。 缓冲区互操作性消除了内存类型之间的数据复制，并且跨不同处理器进行异步执行可以显著降低整体推理延迟。

💬 文章金句

  • 通过在移动 GPU 和 NPU 上加速 AI 模型，与 CPU 相比，您可以将模型速度提升高达 25 倍，同时将功耗降低高达 5 倍。
  • 这意味着相比 CPU，以及旧版本的 TFLite GPU 委托，甚至其他支持 GPU 的框架，在 CNN 和 Transformer 模型上的性能都有显著提升。
  • 此外，为了让处理 GPU 和 NPU 加速更加容易，Google 简化了 LiteRT 的 API，让开发者可以指定创建编译模型时要使用的目标后端。
  • 这些包括通过新的 TensorBuffer API 实现的缓冲区互操作性，该 API 消除了 GPU 内存和 CPU 内存之间的数据复制；以及支持跨 CPU、 GPU 和 NPU 异步并发执行模型的不同部分，根据 Google 的说法，这可以将延迟降低高达 2 倍。
