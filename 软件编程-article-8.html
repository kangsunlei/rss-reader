弱模型反向解码强模型，OpenAI 等 API 漏洞泄露数百条机密

8/13/2026, 10:00:00 AM

📌 一句话摘要

研究发现 OpenAI、Anthropic、谷歌 API 的加密推理对象存在设计漏洞，允许较弱模型解码较强模型的推理轨迹，导致机密信息（如 API 密钥、密码）泄露，涉及 704 个隐私产物。

📝 详细摘要

近日披露的漏洞涉及 OpenAI、Anthropic 和谷歌 API 在跨会话传递加密推理对象时的设计缺陷。研究团队通过重放推理块，利用同一提供商的较弱模型（如 Claude Haiku 4.5 解码 Claude 轨迹）提取隐藏推理内容，包括 API 密钥、密码等机密信息。在 6708 条公开 Agent 轨迹中，解码了 315320 个思考块，并从真实用户会话中统计出 704 个隐私产物（62 个 API 密钥、33 个密码、24 个访问令牌、7 个私钥）。攻击需获取加密推理块及同一提供商的 API 权限，且已向厂商披露并修复。文章还探讨了隐形提示注入风险及厂商回应，并建议开发者共享轨迹时剥离推理块。

💡 主要观点

  1. 加密推理对象的跨会话可移植性导致推理轨迹泄露 OpenAI、Anthropic、谷歌的 API 设计允许推理块在会话间重放，较弱模型可解码较强模型的推理内容，无需破解加密密钥，仅依赖提供商接受不透明块。
  2. 大规模隐私数据泄露风险 研究团队从 6708 条公开轨迹中解码 315320 个思考块，提取 704 个隐私产物（含 API 密钥、密码等），且 64 个仅出现在隐藏推理中，清理可见文本仍可能残留机密。
  3. 隐形提示注入的 PoC 示例 攻击者可构造携带恶意指令的不透明推理块，重放后导致接收模型执行隐藏操作（如上传文件），而指令不出现在可见文本中。
  4. 厂商已修复但文档未同步更新 OpenAI、Anthropic、谷歌已采取缓解措施，但未公开承认漏洞或更新文档，研究团队称攻击已无法复现。

💬 文章金句

  • 加密本身并未被破解，攻击也无需获取加密密钥。它依赖于提供商接受并处理完整的不透明块。
  • 在该团队恢复的 704 个非基准测试产物中，有 64 个仅出现在隐藏推理中，在可见轨迹中没有任何踪迹。
  • 同样的可移植性还催生了一个隐形提示注入的 PoC。
