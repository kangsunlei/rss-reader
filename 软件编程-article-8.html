LiteLLM 漏洞链可致 AI 网关遭接管，泄露所有密钥与数据

6/16/2026, 10:00:00 AM

📌 一句话摘要

本文披露了开源 AI 网关 LiteLLM 中三个漏洞组成的攻击链，低权限用户可借此完全接管服务器、窃取所有 API 密钥与数据，并篡改模型响应。

📝 详细摘要

文章基于 Obsidian 安全研究团队的披露，详细分析了 LiteLLM 中三个漏洞（CVE-2026-47101、CVE-2026-47102、CVE-2026-40217）如何串联形成一条完整的攻击链。首个漏洞是授权绕过，允许普通用户创建包含通配符的虚拟 API 密钥，从而访问管理员专属路由。利用此权限后，攻击者可触发第二个漏洞，通过 /user/update 端点修改自身用户角色为 proxy_admin，实现权限提升。最后，利用 Custom Code Guardrail 功能中的沙箱逃逸漏洞（CVE-2026-40217），通过 exec() 执行恶意 Python 代码，获得服务器端的代码执行能力。文章还详细说明了被攻陷网关会泄露哪些敏感信息（提供商密钥、提示词、响应等），并指出攻击者不仅能窃取数据，还能篡改 AI 模型返回的响应，例如在 Claude Code 中注入反向 Shell。最后，文章给出了具体的修复建议和后续审计要点。

💡 主要观点

  1. LiteLLM 存在由三个漏洞组成的攻击链，可致服务器完全被接管。 漏洞链包括授权绕过（CVE-2026-47101）、权限提升（CVE-2026-47102）和沙箱逃逸（CVE-2026-40217），低权限用户可借此获得管理员权限并执行任意代码。
  2. 被攻陷的网关会暴露所有提供商密钥、用户数据及模型交互内容。 作为 AI 调用的枢纽，网关存储了 OpenAI、Anthropic 等所有提供商的 API 密钥，以及所有流经的提示词和响应，这些数据通常包含 PII 和敏感信息。
  3. 攻击者不仅能窃取数据，还能篡改 AI 模型返回的响应。 通过利用内置回调机制，攻击者可在用户无感知的情况下替换模型输出，例如注入恶意工具调用，实现对下游 Agent 或开发环境的控制。
  4. 漏洞根源在于各层级信任机制的失效。 路由网关信任了调用者提供的字段，处理程序信任了路由网关的校验，而实际上没有任何环节实施有效验证，导致权限校验形同虚设。

💬 文章金句

  • 该漏洞链的根源在于各层级信任机制的失效——路由网关信任了调用者提供的字段、处理程序信任了路由网关的校验，而实际上没有任何环节实施有效验证。
  • 被入侵的代理不仅是数据泄露源，更可篡改 Agent 与模型间的通信数据。
