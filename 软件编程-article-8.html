数据库监控的进化之路：去哪儿网的指标采集与智能告警实践

9/1/2025, 10:01:00 AM

📌 一句话摘要

去哪儿网分享了其数据库监控系统从旧模式到基于 Prometheus 的新模式的进化实践，着重介绍了全面的指标采集和智能告警策略。

📝 详细摘要

文章详细阐述了去哪儿网数据库监控系统的演进过程。针对旧系统中 Push 模式（collectd/nagios）存在的采集不全、数据断点难排查、告警漏报/误报、粒度粗等痛点，团队决定转向 Pull 模式（Prometheus）。新系统旨在实现全面的数据库（MySQL/Redis）和操作系统指标采集，并引入了分组分级采集、动态告警阈值、动态检测频率、探测结果聚合法、告警自愈等智能告警策略，以满足公司“1-5-10”的故障响应要求，显著减少误报和漏报。文章通过多个实际案例展示了新系统在定位问题 SQL、评估集群负载、资源容量规划、排查网络抖动和高维度数据汇总方面的显著成效。

💡 主要观点

  1. 从 Push 模式转向 Pull 模式解决了旧系统数据采集和告警的诸多痛点 通过对比 Push 与 Pull 模式优劣，选择 Prometheus 的 Pull 模式，有效解决了旧系统数据断点、指标不全、元数据缺失及告警粒度粗等问题，提升了数据采集的可靠性和灵活性。
  2. 智能告警策略显著提升了告警的及时性、真实性和有效性 引入动态阈值、动态检测频率、探测结果聚合并结合业务场景，有效减少了误报和漏报，同时通过告警自愈机制提升了问题处理效率，满足了高标准的故障响应要求。
  3. 全面的指标采集和高层次标签为深度分析和决策提供了数据支撑 新系统实现了数据库内外指标的全面采集，并附加了丰富的元数据标签，使得数据可以按实例、库、表、集群、部门等多维度聚合分析，支持容量评估和资源规划。

💬 文章金句

  • 告警系统是保障线上服务稳定运行的最后一道防线，但它不应该是终点，自愈才是目标，业务无问题是终极目标。
  • Qunar 业务线对故障要求'1-5-10'，即一分钟发现问题，五分钟定位问题，十分钟解决问题，这也对告警系统提出更高的要求。
  • 通过在不同的时间段设置不同的阈值，避免统一阈值，这样既避免业务在非特殊时间因为高阈值导致告警漏报，也可以避免业务因为特殊时期的阈值较低导致频繁误报。
  • 采用动态检测频率，相比固定的检测区间使告警具备很好的及时性。
  • 通过个性化标签可以定制高纬度的汇总信息，可以根据使用情况和变化趋势提前规划资源的使用。
