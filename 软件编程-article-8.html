.NET MAUI RC1 带来了诊断和 Android CoreCLR 实验支持

9/29/2025, 12:00:00 PM

📌 一句话摘要

.NET MAUI RC1：诊断、控件、Android CoreCLR 实验支持。

📝 详细摘要

本文宣布发布适用于 .NET 10 的 .NET MAUI RC1，它现在包括上线支持，表明微软对其生产环境的就绪性充满信心。此版本侧重于稳定性、质量和诊断工具，而不是主要的新功能。主要增强功能包括一个全面的、可扩展的诊断系统，具有新的 `ActivitySource` (活动源) 和 `Meter` (测量器) 原语，用于跟踪布局操作。这些工具发出跟踪事件和性能计数器，与 .NET Aspire 和 OpenTelemetry 仪表板无缝集成，以极低的性能损耗实现布局测量和排列成本的实时监控。此外，`HybridWebView` 控件已使用 `WebViewInitializing` 和 `WebViewInitialized` 事件进行了更新，镜像了 `BlazorWebView` 的功能。这简化了混合应用程序在 iOS、Android、Windows 和 macOS 上的平台特定定制。一个受欢迎的可用性改进是在 `RefreshView` 中添加了 `IsRefreshEnabled` 属性，允许开发人员在保持内容活动的同时禁用下拉刷新。重要的是，RC1 引入了对 Android 应用程序的实验性 CoreCLR 运行时（.NET 的一个运行时实现）支持，提供了 Mono 运行时（另一种 .NET 运行时实现）的替代方案。此举表明了微软在所有移动和桌面平台上统一 .NET 运行时体验的战略意图，尽管它在应用程序大小和调试方面存在一些注意事项。包括“压缩”布局类型和旧的性能工具在内的几个旧版 API 已被弃用，与新的诊断基础结构保持一致。开发人员可以通过 .NET 10 SDK 访问 RC1，并通过 GitHub 提供反馈。

💡 主要观点

  1. .NET MAUI RC1 引入了全面的、低开销的诊断功能，用于跟踪应用程序布局性能。 新的 `ActivitySource` (活动源) 和 `Meter` (测量器) 提供对布局操作的实时可见性，与 .NET Aspire 和 OpenTelemetry 等工具集成，这对于以极低的性能损耗优化应用程序性能至关重要。
  2. 对 Android 的实验性 CoreCLR 支持旨在统一跨平台的 .NET 运行时体验。 开发人员现在可以选择在 CoreCLR 运行时（.NET 的一个运行时实现）而不是 Mono 运行时（另一种 .NET 运行时实现）上运行 Android 应用程序，这表明了微软在跨平台实现一致运行时的长期目标，尽管目前存在实验性限制，例如应用程序大小增加。
  3. 增强的 `HybridWebView` 和 `RefreshView` 控件简化了跨平台 UI 开发。 用于 `HybridWebView` 的新初始化事件允许更轻松的平台特定自定义，而 `RefreshView` 中的 `IsRefreshEnabled` 提高了控件可用性并使跨平台行为保持一致。

💬 文章金句

  • RC1 版本通过稳定 API 表面并添加 10 月 14 日之前的上线许可来延续这一趋势，以便开发人员可以在 Microsoft 的支持下在生产环境中部署 RC1 版本。
  • 其中一个最重要的补充是针对 .NET MAUI 应用程序的全面且可扩展的诊断和布局性能指标跟踪。
  • 开发人员现在可以通过在项目文件中设置 `false` 来选择在 CoreCLR 运行时而不是长期存在的 Mono 运行时上运行 Android 应用程序。
  • 尽管如此，此举表明了微软在移动和桌面平台上统一 .NET 运行时体验的意图。
