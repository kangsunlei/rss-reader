📝 详细摘要

本期早报围绕企业级 AI 工程与前沿模型展开。重点包括：小红书 Muse 把焦点从代码生成速度转向交付连续性，拆解 Agent Team、Harness、One Workspace 与结构化状态的协同；OpenAI 推理团队介绍 IRB 路由如何把全局优化与本地决策分离，兼顾容量、健康度与 KV 缓存；LinkedIn 用 MCP 构建组织级上下文层，以 playbook 和治理机制控制上下文负担。此外还涉及 Positron AI 对内存瓶颈的判断、扩散模型替代自回归的论证、IMO 2025 压轴题的动机化证明、达摩院 DAMO RADAR 登上 Science、Databricks CEO 对 AI 风险的看法、Claude Code 的 Thread 多智能体架构，以及 AI 音乐产业的丰饶与失衡。

💡 主要观点

  1. 企业 AI Coding 的瓶颈已从代码生成速度转向交付连续性 小红书 Muse 实践拆解了 Agent Team、Harness、One Workspace 与结构化状态的协同方式，并强调权限、验证和副作用日志必须进入运行时控制，为复杂工程团队提供从原型共创到生产落地的设计线索。
  2. 生产环境 LLM 路由需要在全局优化与本地快速决策之间分层 OpenAI 推理团队的 IRB 把全局权重计算与本地决策分开，结合容量、健康度、网络开销和 KV 缓存，再用惩罚、受限重试与负载削减应对故障和过载，说明距离最近的 GPU 未必带来最低端到端延迟。
  3. 组织级上下文层是编码 Agent 处理大型内部系统的前提 LinkedIn 用 MCP 交付可组合的 playbook 并按需检索工具与说明以控制上下文负担，同时以代码审查、鉴权和弃用机制维护目录，提示企业需把组织知识、质量与治理一起做成 Agent 的运行基础。
