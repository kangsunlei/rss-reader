NVIDIA Dynamo Planner 为多节点 LLM 推理带来 SLO 驱动的自动化

1/31/2026, 9:00:00 AM

📌 一句话摘要

NVIDIA 和微软推出了 Dynamo Planner，这是一套基于严格服务水平目标 SLO 在 Kubernetes 上优化和扩展多节点 LLM 推理的自动化工具集。

📝 详细摘要

本文详细介绍了 NVIDIA 与微软在 Azure Kubernetes Service AKS 上针对 LLM 推理开展的 NVIDIA Dynamo 合作的第二阶段。文中引入了两个核心组件：Dynamo Planner Profiler 和基于 SLO 的 Dynamo Planner。这些工具解决了“解耦服务”的复杂性——这是一种将预填充和解码操作拆分到不同 GPU 池以优化性能的技术。Profiler 通过模拟自动搜索最佳配置，而 Runtime Planner 则根据 KV 缓存负载和队列深度等实时指标动态扩展资源，以维持首字延迟 TTFT 和 Token 间延迟 ITL 等延迟目标。这种自动化显著减轻了管理高吞吐量、多节点 GPU 环境的运维负担。

💡 主要观点

  1. 解耦服务提高了效率，但引入了复杂的“速率匹配”挑战。 将预填充和解码阶段拆分到不同的 GPU 池中，可以分别优化计算密集型和内存受限型任务，但确定每个阶段的最佳 GPU 分配需要大量人工操作且难以平衡。
  2. Dynamo Planner Profiler 通过快速性能模拟实现配置发现的自动化。 通过使用 AI 配置器模式，Profiler 可以在 20-30 秒内模拟性能，使开发人员能够找到最佳的张量并行大小和 GPU 数量，而无需在手动测试上浪费昂贵的物理 GPU 运行时间。
  3. 基于 SLO 的 Dynamo Planner 提供“感知 LLM”的运行时编排和动态扩展。 与传统的负载均衡器不同，该组件监控集群内部状态（如 KV 缓存负载和预填充队列深度），自动扩展工作节点，以确保系统在不可预测的流量激增期间仍能达到延迟目标。
  4. 该系统通过平衡吞吐量与延迟约束，专注于最大化有效吞吐量 Goodput。 其目标是在严格遵守首字延迟 TTFT 和 Token 间延迟 ITL 的服务水平协议的前提下，实现尽可能高的 Token 吞吐量，从而确保一致的用户体验。

💬 文章金句

  • 这些工具协同工作，解决了解耦服务中的“速率匹配”挑战。
  • Profiler 包含一个 AI 配置器模式，可以根据预先测量的性能数据，在约 20 到 30 秒内模拟性能。
  • Planner 利用 Profiler 的性能边界来扩展预填充和解码工作节点……以便在流量模式变化时满足服务水平目标。
  • 从手动设置转向自动化的、SLO 驱动的资源管理，展示了团队如何更好地处理 Kubernetes 上的大语言模型部署。
  • 自动化工具可以帮助处理重推理或长上下文 LLM 的组织……使管理复杂的多节点 GPU 设置变得更加容易。
