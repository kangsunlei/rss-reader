Android AI Agent 现漏洞，隐形文本可执行主机代码

7/22/2026, 10:36:00 AM

📌 一句话摘要

安全研究发现多个开源 Android AI Agent 框架存在漏洞，利用不可见屏幕文本和截图竞争条件可在主机上执行任意代码。

📝 详细摘要

文章报道了西蒙菲莎大学等机构的研究论文，揭示了五个开源移动 Agent 框架（AppAgent、AppAgentX、Mobile-Agent-v3、Open-AutoGLM、MobA）中存在的安全漏洞。攻击者可通过在屏幕上植入人眼不可见的 2% 透明度文本，利用截图保存与拉取之间的竞争窗口（50‑500 ms）将恶意指令注入 Agent 输入；由于这些框架在构建 adb shell 命令时未充分清理 shell 元字符，模型输出直接导致主机代码执行。研究人员在实验中成功载荷如 calc.exe 启动及任意命令注入，且未看到 CVE 编号或维护者回复。文中还给出了具体的防御建议，如避免使用 shell=True、流式传输截图、添加签名级权限等。

💡 主要观点

  1. 隐形文本（2%透明度）可被视觉模型读取而人眼不可见，作为攻击载荷。 研究表明所有测试的六个视觉模型在 18/20 次实验中能读取如此低透明度的文本，为攻击提供隐蔽通道。
  2. 通过截图竞争条件（TOCTOU）将恶意文本注入 Agent 的输入。 框架在截图保存与拉取之间存在 50-500ms 窗口，后台服务可在此窗口修改 PNG，成功率达 19/20。
  3. 主机命令注入源于未清理的 shell 拼接（subprocess.run(...， shell=True)），导致模型输出直接作为 shell 参数执行命令。 仅去除空格和单引号，保留分号、&、>等元字符，使载荷如 test;pwd>rce_success 在主机上执行。
  4. 五个开源移动 Agent 框架均存在至少六种攻击向量，且目前未分配 CVE，维护者未响应漏洞报告。 论文在 AppAgent、AppAgentX、Mobile-Agent-v3、Open-AutoGLM 和 MobA 上演示了攻击链，所有框架至少被六种攻击破解。
  5. 建议的修复包括避免 shell=True、流式传输截图、添加签名级权限、Activity 白名单等，但未有一个框架同时实现所有措施。 作者提供了具体防御措施，指出只有 Open-AutoGLM 对主机命令注入免疫，MobA 通过 exec-out 避免文件竞态。

💬 文章金句

  • 你的 LLM 不是安全边界。
  • 没有直接有效的基于软件的解决方案。
  • Android AI Agent 漏洞，不可见屏幕文本即可在主机上执行代码。
  • 模型相信了该提示。
  • 团队在发布预印本之前已私下联系了受影响的维护者，但'至今未收到回复'。
