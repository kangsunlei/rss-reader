📝 详细摘要

这篇文章是 Sophie Beaumont 演讲的文字稿，概述了 BBC 扩展其 Web 设计系统的策略，以服务于跨多个品牌和数百个贡献者的数十亿次的访问请求。文章首先用一个维护不善的花园围栏作类比，强调了文档、沟通、所有权和维护在设计系统中的关键重要性。BBC 的系统在内部被称为 WebCore，支持 10 个品牌和 25 个能力团队，其 Monorepo 拥有超过 450 名贡献者，每月部署 285 次。WebCore 的一个关键和独特的方面是其非版本化的组件，这些组件在合并后立即生效，并严重依赖 Chromatic 进行视觉回归测试。该系统主要使用带有自定义 Web 框架的 React 前端，Storybook 作为其中心的“前门”。 其可扩展性的核心是联邦贡献模型，产品团队积极贡献组件，而专门的中央“维护”团队则确保一致性、易用性和符合标准。新团队的入职培训被设计为高度灵活，提供 Storybook 中的自助服务文档，用于指导决策的 Figma 流程图，以及每季度一次的人工指导培训课程。该系统采用了一种创新的分层令牌架构，其中令牌定义了它们的用途（例如，`accent`、`accentContrast`），而不仅仅是原始的十六进制颜色代码，从而确保了内置的易用性和跨不同品牌的无缝可移植性。此外，文档在很大程度上是自动化的，TypeScript 定义文件生成属性表，命令行界面（CLI）工具预先填充必要的可访问性健康检查和元数据。 强制性的所有权，在 GitHub CODEOWNERS 中严格定义，确保每个组件都有明确的所有者，防止孤立的资产，并促进强大的开放协作。BBC 的方法还通过专门的 Slack 频道和定期会议来培养强大的社区，使团队能够分享解决方案并共同应对常见的挑战。这种全面的、社区驱动的“维护”方法，在强大的工具和严格的治理的支持下，使 BBC 能够在面对涉及数百个子品牌的复杂品牌需求时，保持其大型数字平台的一致性、易用性和效率。

💡 主要观点

  1. BBC 采用具有中央“维护”团队的联邦贡献模型来扩展其设计系统。 分布式团队贡献组件，而专门的中央团队确保系统的一致性、符合标准和整体健康状况，从而在自主性和治理之间取得平衡。
  2. 一种创新的分层令牌系统定义了颜色用途，以实现一致的品牌推广和内置的易用性。 令牌旨在表示意图（例如，“accent”，“accentContrast”），而不是特定值，从而确保内置易用性，并在各种品牌和上下文中保持可维护性。
  3. 强大的工具和自动化对于效率、可扩展性和治理至关重要。 像 Storybook 作为“前门”，Chromatic 用于视觉回归测试，以及 CLI 驱动的文档生成（包括易用性检查和元数据）等关键工具可自动执行流程，执行标准并支持系统的大规模应用。
  4. 强制性组件所有权在存储库中定义，有助于培养责任感和协作。 每个组件都通过 GitHub CODEOWNERS 分配了明确的所有者，从而可以防止孤立的资产，明确责任，并促进有针对性的开放协作以进行维护和发展。
  5. 强大的社区和灵活的新手引导对于系统采用和协作发展至关重要。 广泛的新手引导资源（文档，Figma 流程图，季度会议）和活跃的社区渠道（Slack，会议）可以促进参与，从而使团队能够有效地使用和协作地发展大规模的设计系统。
