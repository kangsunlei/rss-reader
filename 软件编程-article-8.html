LLM 系统的数据基础

9/10/2025, 1:40:00 PM

📌 一句话摘要

本文概述了一个以特征训练推理模式为中心的稳健 LLM 系统架构，强调数据流、RAG 和可观测性，用于构建生产级 AI 应用。

📝 详细摘要

这篇文章是 Paul Iusztin 的演讲稿，深入探讨了构建生产级大型语言模型（LLM）系统的架构考量。它强调了从传统 ML 工程向 AI 工程的转变，其中检索增强生成（RAG）成为核心，强调软件和数据工程原则。Iusztin 介绍了一种 LLM 系统设计的基础模式：特征训练推理（FTI）架构，并辅以可观测性管道（用于监控和调试系统）。他细致地解释了 RAG，详细介绍了其摄取和推理管道，以及跨预检索、检索和后检索阶段的高级优化技术，解决了诸如有效分块、查询优化、嵌入模型选择和重新排序等关键方面，以应对“稻草堆问题” (haystack problem)。讨论还涵盖了向量数据库的格局。然后，文章将这些概念整合到一个全面的 LLM 系统架构中，说明了模型层（数据工程、特征工程、微调）和应用层（RAG 摄取、Agentic 推理）中的数据流。它强调了高吞吐量、可重复性和实验的重要性，最后介绍了为 LLM 环境量身定制的“逻辑特征存储”的实际应用。

💡 主要观点

  1. FTI 架构为设计和扩展 LLM 系统提供了一个稳健的框架。 特征训练推理（FTI）模式，加上可观测性管道，提供了清晰的接口和模块化，简化了复杂、可用于生产环境的 LLM 应用的设计、开发和调试。
  2. RAG 是大多数 LLM 应用的核心组件，需要在多个阶段进行系统优化。 有效的 RAG 实施涉及仔细的摄取（清理、分块、嵌入）和推理（查询嵌入、检索、提示构建），以及在预检索、检索和后检索阶段的高级优化，这对于性能和准确性至关重要，尤其是在解决“稻草堆问题”时。
  3. 良好定义的数据流和基础设施对于可重复和可扩展的 LLM 系统至关重要。 一个强大的数据层，包括数据仓库、数据注册表和向量数据库，对于管理数据、生成数据集、微调模型以及确保训练和推理中的可重复性、高吞吐量和高效实验至关重要。

💬 文章金句

  • RAG 至关重要，实际上在 AI 工程中，几乎每个问题都是一个 RAG 问题，最终归结为软件工程、数据工程和信息检索。在大多数应用中没有 ML 工程。
  • 大道至简。
  • 这种设计的关键在于，RAG 摄取管道作为离线流程卸载，而 RAG 推理管道通常位于与用户交互的实际应用程序中。
  • LLM 存在一个众所周知的问题，即所谓的稻草堆问题，其中 LLM 总是倾向于根据提示的第一部分和最后一部分来回答问题。通常，中间的内容会丢失，因此我们在构建提示时需要考虑到这一点。
  • 在 LLM 领域中，特征存储最重要的部分是在线存储和离线存储，其中在线存储针对低延迟进行了优化，实际上这只是您已经针对低延迟进行了优化的普通数据库。离线存储即数据注册表，它提供高吞吐量、数据版本控制、血缘关系以及跨多个训练管道的数据集共享等功能。
