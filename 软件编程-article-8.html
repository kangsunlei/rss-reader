通过 ecdysis 蜕去旧代码：Cloudflare Rust 服务的平滑重启

2/13/2026, 2:00:08 PM

📌 一句话摘要

Cloudflare 开源了 ecdysis，这是一个 Rust 库，通过使用 fork-and-inherit 模型在进程代际之间传递监听套接字，实现网络服务的零停机平滑重启。

📝 详细摘要

本文介绍了 ecdysis，这是一个经过生产环境验证的 Rust 库，旨在解决高流量网络服务在升级时不丢失连接的难题。文章解释了朴素重启方法的陷阱以及 SO_REUSEPORT 的局限性，例如内核 accept 队列中的孤儿连接。ecdysis 实现了由 NGINX 首创的健壮的 fork-exec-inherit 模型，新进程通过命名管道从父进程继承监听套接字文件描述符。这确保了套接字在过渡期间始终保持打开状态。该库具有原生 Tokio 集成、systemd-notify 支持和崩溃安全初始化功能，确保如果新版本启动失败，旧版本仍能继续处理流量。ecdysis 自 2021 年起就在 Cloudflare 内部使用，现在作为开源工具提供给更广泛的 Rust 生态系统。

💡 主要观点

  1. 朴素的进程重启会产生停机窗口，导致连接丢失。 在启动新进程之前停止旧进程会导致操作系统拒绝连接 (ECONNREFUSED)。在 Cloudflare 的规模下，即使是 100 ms 的间隙也可能导致全球范围内数百万次请求失败。
  2. SO_REUSEPORT 套接字选项不足以实现高负载场景下的真正平滑重启。 虽然它允许多个进程绑定到同一个端口，但如果进程在接受连接之前退出，位于该进程 accept 队列中的连接将被终止，从而导致孤儿请求。
  3. ecdysis 利用 fork-exec-inherit 模型来保持套接字的持续可用性。 通过 fork 子进程并通过命名管道传递文件描述符，监听套接字在内核中保持打开状态。两个进程可以短暂共存，直到新进程发出就绪信号。
  4. 该库在服务初始化阶段提供了内置的崩溃安全性。 如果新进程由于配置错误在启动期间崩溃，父进程将保持活跃并继续处理流量，从而允许在不影响服务可用性的情况下进行重试。
  5. 现代基础设施集成是其核心特性，支持 Tokio 和 systemd。 它为 Tokio 提供了原生的异步流包装器，并集成了 systemd-notify (Type=notify-reload)，允许标准的 Linux 服务管理器正确跟踪和管理平滑升级。

💬 文章金句

  • 朴素的方法涉及在启动新进程之前等待旧进程停止，但这会产生一个连接被拒绝、请求被丢弃的时间窗口。
  • 当使用 SO_REUSEPORT 时……如果进程在接受此连接之前退出，它就会变成孤儿连接并被内核终止。
  • 至关重要的一点是，套接字在整个过渡期间保持打开状态。子进程通过命名管道共享的文件描述符从父进程继承监听套接字。
  • 如果子进程在初始化期间失败（例如由于配置错误），它会直接退出。由于父进程从未停止监听，因此不会丢失任何连接。
  • 使用 ecdysis 的每次重启都能挽救数十万个请求，否则这些请求在朴素的停止/启动周期中会被丢弃。
