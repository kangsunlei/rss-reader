从基础到规模化：Vanguard 的 SRE 转型之路

10/6/2025, 1:06:00 PM

📌 一句话摘要

Vanguard 的 SRE 转型，从最初的混沌工程实践到成熟的解决方案。文章详细介绍了工具开发、团队指导，以及在弹性与扩展性方面的创新技术。

📝 详细摘要

本文详细介绍了 Vanguard 全面的 SRE 转型，从传统的单体发布和孤立的开发/运维 (Dev/Ops) 转变为具有持续交付的现代微服务架构。这一旅程始于由个人贡献者驱动 (IC-driven) 的混沌工程计划，从而开发了用于混沌和性能测试的自助式内部工具。在认识到最初的“本末倒置”方法后，该计划随后优先考虑强大的可观测性 (Observability)，标准化 OpenTelemetry，并采用服务级别指标 (SLI)、服务级别目标 (SLO) 和错误预算 (Error Budgets) 来进行细致的可用性评估，并采用 CASE 方法 (Context-heavy， Actionable， Symptom-based， and Evaluated) 实现可操作的警报。面对工具采用率低和团队混乱的问题，Vanguard 建立了一个 SRE 指导团队，开发了一个结构化的课程来提升工程师的技能，并定义了一个具有 SRE 负责人 (SRE Leads) 和 SRE 倡导者 (SRE Champions) 的 SRE 运营模式。文章还重点介绍了最近的技术成就，包括创新地使用 AWS DNS 防火墙 (AWS DNS Firewall) 进行区域故障游戏日，以及开发具有“智能调度器”的“请求速率缩放 (request rate scaling)”以主动管理流量高峰，从而显著提高自动伸缩 (Autoscaling) 效率并降低云成本。还讨论了诸如在成本中心 IT 环境中展示 SRE 影响以及有效的 SRE 人员配置等挑战。

💡 主要观点

  1. Vanguard 的 SRE 之旅是迭代发展的，从基层混沌工程计划开始。 转型始于由个人贡献者驱动 (IC-driven) 的混沌工程实施，从而开发了用于混沌和性能测试的自助工具，这为更广泛的 SRE 采用提供了基础层。
  2. 有效的 SRE 采用需要强大的可观测性和专门的指导计划。 标准化 OpenTelemetry 和服务级别指标 (SLI) / 服务级别目标 (SLO)，并结合 SRE 指导团队和结构化课程，对于克服采用障碍以及在整个工程团队中嵌入可靠性实践至关重要。
  3. 创新的技术解决方案解决了企业环境中现代 SRE 的挑战。 Vanguard 实施了独特的方法，例如使用 AWS DNS 防火墙进行区域故障模拟，以及开发具有智能调度器的预测性请求速率缩放，以提高弹性和成本效益。

💬 文章金句

  • SRE 是 DevOps 转型的赋能者。这有点违反直觉，我们学到的教训之一是也许我们一开始并没有完全找对地方，但是我们听到了很多关于这种混沌工程的事情。
  • 如果我可以回去重做，我会反过来做。当我们谈论弹性测试时，它是性能测试与混沌工程的结合，目的是验证系统在负载下处理故障场景的能力。
  • 现在我们更多地谈论服务级别指标和目标以及错误预算。这使我们能够对事物进行细微的调整，并在我们的可观测性指标中更好地了解情况的紧迫性。
  • 出于必要，我们实际上成立了一个 SRE 指导团队，除了工具的评估和推广之外，还建立了一个自学课程，其中包含了所有不同风格的汇总内部文档。
  • 这是第一次，自动伸缩首次具备了快速响应能力，能够满足峰值负载需求，并显著降低了我们的总体 AWS 账单。
