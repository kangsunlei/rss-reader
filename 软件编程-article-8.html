分享一些在 AI 解析中常见的问题，以及工具区别

6/20/2026, 9:51:17 AM

📌 一句话摘要

本文对比 MinerU 与 Knowhere 在文档解析上的差异，指出解析成 Markdown 不等于 Agent 能理解，并介绍 Knowhere 如何通过结构重建、多模态处理与记忆图谱补齐 RAG/Agent 链路。

📝 详细摘要

文章作者分享了自己在 AI 文档解析领域的实践与思考。文章首先承认 MinerU 是优秀的文档解析工具，能将 PDF 转为 Markdown。但核心观点是：解析成 Markdown 不等于文档能被 Agent 理解。传统流程中，Markdown 经过切片后丢失了章节层级、表格与正文的关联等结构信息，导致 RAG 检索效果不佳。为此，作者介绍了自己的开源项目 Knowhere，它在解析与向量化之间插入了结构重建流水线，包括重建文档层级、处理多模态内容（OCR、表格摘要）、构建轻量记忆图谱以及提供 Agentic Retrieval。文章引用了内部评测数据，显示使用 Knowhere 后首次准确率提升 36%，召回率提升 11%。最后列举了 Knowhere 的适用场景，如企业内部知识库、技术文档助手、合同分析等。

💡 主要观点

  1. 解析成 Markdown 不等于文档能被 Agent 理解。 传统流程中，Markdown 切片后丢失了章节层级、表格与正文的关联等结构信息，导致 Agent 检索时只能拿到孤立片段，无法理解上下文。
  2. Knowhere 通过结构重建补齐了从解析到 Agent 使用的链路。 在解析与向量化之间，Knowhere 插入重建文档层级、处理多模态内容、构建轻量记忆图谱等步骤，使文档成为 Agent 可导航的知识结构。
  3. 结构化的文档能显著提升 Agentic RAG 的效果与效率。 内部评测显示，使用 Knowhere 后首次准确率提升 36%，召回率提升 11%，同时 Agent 循环次数更少，Token 消耗更低。

💬 文章金句

  • 解析成 Markdown ，并不等于文档已经能被 Agent 理解。
  • 如果 Agent 面对的是一整坨文本，那它只能盲找。但如果 Agent 面对的是一棵树、一张图、一组带来源路径的 Chunk ，它就可以像人读文档一样：先看目录，再定位章节，再进入细节。
