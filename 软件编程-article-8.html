蓝牙耳机总断连？开发者顺藤摸瓜，竟发现阿里全球速卖通在“播放静音”

9/8/2026, 4:04:00 AM

📌 一句话摘要

开发者在调试蓝牙多点连接断连时，发现阿里速卖通通过播放静音音频进行设备指纹识别，导致系统空闲状态被阻断并引发蓝牙音频路由问题。

📝 详细摘要

在调试 BLE 多点连接频繁断连的过程中，开发者 Matt Callaghan 追踪到阿里巴巴的速卖通首页使用 Web Audio API 播放一段零增益的音频流，以实现设备指纹识别。该音频虽不可闻，却会占用硬件音频路径，使操作系统无法进入空闲状态，从而锁定蓝牙音频路由，导致耳机断连。文章详细解释了指纹技术的实现原理、涉及的脚本文件以及不同浏览器的缓解措施，如 Brave 的 farbling 噪声注入和 Firefox 的数学分桶标准化。作者指出，这一做法暴露了 W3C 规范中对 AudioContext 的权限缺口，并对企业安全防护提出了更复杂的风险考量。

💡 主要观点

  1. AliExpress 通过播放零增益的音频流实现设备指纹识别 利用 Web Audio API 合成音频图并将 GainNode 设置为 0，捕获硬件层面的浮点运算差异，以唯一标识用户设备。
  2. 隐藏的音频流阻止系统进入空闲状态，导致蓝牙多点连接音频路由被锁定 零增益音频仍占用音频输出通道，使操作系统保持活跃，进而影响蓝牙耳机的音频焦点切换，出现断连。
  3. 主流浏览器提供不同的防指纹缓解方案 Brave 通过在音频缓冲区注入伪随机噪声（farbling）扰乱指纹特征，Firefox 在 privacy.resistFingerprinting 模式下进行数学分桶和规范化处理，降低指纹可辨识度。
  4. AudioContext 的使用缺乏用户授权提示，构成结构性权限缺口 与 getUserMedia、地理位置等敏感 API 不同，初始化 AudioContext 不触发任何权限弹窗，导致隐蔽的指纹采集成为可能。
  5. 该技术对企业安全防护带来新挑战 反机器人脚本若未对音频指纹进行隔离，可能干扰物理设备状态，增加账户接管和自动化攻击的风险评估难度。

💬 文章金句

  • AliExpress 并没有录制用户的声音，而是播放一段静音音频，再测量用户的特定设备如何处理这段音频，从而识别用户的设备指纹。
  • 通过将零增益的 GainNode 连接到 ctx.destination，脚本在平台层启动了一条未静音的音频流，使主机操作系统无法进入空闲状态，并锁定了蓝牙多点连接的音频路由。
  • 不同于 getUserMedia 或 地理位置 API 等敏感的浏览器接口，初始化 AudioContext 并渲染音频合成图，无需经过任何明确的权限提示。
  • Brave 通过'扰动（farbling）'缓解这种风险。这种方法会在音频渲染缓冲区中动态注入确定性的伪随机噪声。
  • Firefox 会在其高级 反指纹识别配置（privacy.resistFingerprinting）下采用数学分桶和规范化处理，将音频处理结果限制在标准化的精度区间内。
