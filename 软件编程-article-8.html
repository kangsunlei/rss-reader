如何自建邮件服务器

3/6/2026, 4:10:41 PM

📌 一句话摘要

一份关于如何使用 Postfix 和 Docker 自建简化版 SMTP 服务器的全面实用指南，重点在于通过 DNS、SPF、DKIM 和 DMARC 掌握现代邮件送达率。

📝 详细摘要

本文为开发者提供了一份详细路线图，旨在通过自建邮件基础设施摆脱“大厂”邮件服务商。作者提出了一种“非对称”设计：使用自建的 Postfix 服务器发送事务性邮件，同时利用域名注册商的转发功能接收邮件，从而避免了 IMAP 和邮箱管理的复杂性。指南涵盖了固定 IP 和 25 端口访问等关键基础设施要求，提供了使用 Docker 的容器化部署策略，并详细解释了反向 DNS、SPF、DKIM 和 DMARC 等核心认证协议的配置，以确保高送达率和发件人信誉。

💡 主要观点

  1. 采用非对称 SMTP 架构以简化自建需求。 通过仅使用自建服务器发送邮件并依靠注册商转发接收邮件，可以省去对 IMAP 和复杂邮箱管理的需求，从而显著减少攻击面。
  2. 获取拥有固定 IP 的 VPS，并确保服务商未封禁 25 端口。 住宅 IP 通常会被列入黑名单或是动态 IP，不适合用于邮件服务。从 VPS 提供商处获取干净、静态的 IP 对于长期建立可靠的发件人信誉至关重要。
  3. 实现 DNS 和反向 DNS 的“完美闭环”以确保服务器合法性。 域名的 A 记录必须指向服务器 IP，且该 IP 的 PTR 记录必须指向该域名，这满足了主流邮件服务商过滤垃圾邮件的主要检查项。
  4. 配置 SPF、DKIM 和 DMARC 以验证外发邮件并防止欺骗。 这些协议使用基于 DNS 的授权和加密签名来证明发件人身份，并确保 From 标头与经过身份验证的域名一致，这对于绕过现代垃圾邮件过滤器至关重要。
  5. 需理解由于信誉机制的存在，技术上的完美配置并不意味着能立即获得高送达率。 即使配置完美，新服务器也经常面临“灰名单”或退信。与 Google 等主流服务商建立信任需要耐心，并在数天或数周内保持持续、合法的发送行为。

💬 文章金句

  • 由于想到又要增加一个对大厂的依赖就令人沮丧，我决定违背常规建议，自己动手搭建邮件服务器。
  • 发送邮件真正需要的其实只有 SMTP。IMAP 是用来访问邮件的，而不是发送邮件。所以从一开始我就决定跳过 IMAP。
  • 在任何情况下，都不要让 Postfix 容器的 587 端口监听连接到公网的网络接口，因为那将是一个巨大的安全风险。
  • DMARC 通过确保 From 地址来自经过 DKIM 和 SPF 验证的同一域名来解决这个问题。
