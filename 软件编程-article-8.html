如何利用 Zizmor 大规模检测存在漏洞的 GitHub Actions

6/30/2025, 3:06:01 PM

📌 一句话摘要

Grafana Labs 在 2000 多个代码库中部署 Zizmor 工具，通过检测和预防 GitHub Actions 漏洞来增强 CI/CD 流水线安全性，该措施是在一起安全事件后实施的。

📝 详细摘要

在发生一起由存在漏洞的 GitHub Action 引发的安全事件（该漏洞允许未经授权的代码执行）后，Grafana Labs 推出了开源静态分析工具 Zizmor，用于检测和预防其 CI/CD 流水线中的类似漏洞。该工具会检查不安全实践（如使用 pull_request_target 而非更安全的 pull_request），并执行版本固定等最佳实践。Grafana 的主动安全防护措施（包括金丝雀令牌技术）成功检测到了攻击尝试。该公司通过可复用工作流和 GitHub 组织规则集，在 2000 多个代码库中规模化部署了 Zizmor，并针对在线/离线操作模式进行特定配置以应对 GitHub API 速率限制问题。通过回退机制解决了集中式配置管理等挑战，同时定时任务为关键代码库提供了额外的安全检查。

💡 主要观点

  1. Zizmor 通过检测存在漏洞的 GitHub Actions 来预防安全事件 该工具能够识别不安全实践（如使用 pull_request_target）并强制实施版本固定，同时通过其全面的审计规则检查禁用操作和冒名提交。
  2. 主动安全措施与可扩展实施方案 Grafana 的金丝雀令牌系统检测到了初始攻击，而可复用工作流和 GitHub 规则集使得 Zizmor 能够在 2000 多个代码库中实现集中管理的部署。
  3. 架构设计有效解决速率限制和配置挑战 离线模式避免了 GitHub API 速率限制问题，而回退配置和定时任务确保了在分叉限制和规模需求下仍能实现全面覆盖。
  4. 可复用工作流设计支持全组织范围采用 安全团队创建了一个公共工作流模板，该模板可生成 SARIF（静态分析结果交换格式）报告和人工可读注释，并与 GitHub 代码扫描功能集成以实现持续监控。

💬 文章金句

  • 一个存在漏洞的 GitHub Action（使用 pull-request-target 而非更安全的 pull-request）导致了 4 月份的安全事件。
  • 安全机制按设计生效：当有人尝试使用金丝雀令牌时，系统实时触发了告警。
  • Zizmor 不仅能检测 pull_request_target 的使用情况，还包括一整套审计规则，如禁用操作和未固定版本的使用。
  • 由于在线模式会消耗我们的 API 调用配额，我们选择在代码审查时使用离线模式运行。
  • 当下次出现 GitHub Actions 漏洞时，我们将通过 Zizmor 检查工作流规范性来做好更充分的准备。
