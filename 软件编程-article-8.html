TLS 全链路可观测体系：破解 LLM 应用黑盒，实现会话透明复盘

9/9/2026, 10:05:00 AM

📌 一句话摘要

TLS 的 AgentLoop 为 LLM 应用提供全链路可观测，实现会话追踪、成本分析和故障复盘。

📝 详细摘要

本文介绍了火山引擎日志服务 TLS 的 AgentLoop 如何为 LLM 应用破解黑盒问题。通过在应用侧接入 LLM Observer SDK，采集用户请求、模型调用、工具执行等数据，并遵循 OpenTelemetry GenAI 语义将其标准化为 Trace，随后上报至 TLS 实现统一存储。AgentLoop 前端提供 Session、Trace、Span 的可视化仪表盘，支持单轮、多轮、流式和工具调用等场景的监控与分析。文章详细说明了 SDK 的接入步骤、采集内容的可配置性以及如何利用 Trace 进行精准排障、成本优化和完整复盘，并展望了生态扩展、指标完善和观测评测闭环等演进方向。

💡 主要观点

  1. TLS AgentLoop 将 LLM 应用运行过程结构化为 Session、Trace、Span，实现全链路可观测。 通过统一的 Trace 模型，将用户请求、模型调用、工具执行等阶段记录下来，支持黑盒问题的追溯与分析。
  2. LLM Observer SDK 在应用侧采集关键数据并上报至 TLS。 SDK 捕获请求、模型交互、Token 消耗、错误状态等信息，遵循 OpenTelemetry 约定，实现标准化上报。
  3. 可视化仪表盘提供 Session、Trace、调用链三层视图，支撑排障、成本优化和复盘。 Session 汇总会话信息，Trace 展示单轮请求细节，Span 还原模型与工具的调用链，帮助定位异常环节和高消耗请求。
  4. 支持多种场景并可配置采集范围以保护敏感信息。 包括单轮、多轮、流式响应、工具调用和异常链路，且通过 TLS_TRACE_CAPTURE_CONTENT 控制是否采集 Input/Output 等内容。
  5. 未来将扩展模型生态、完善观测指标并实现观测‑评测闭环。 计划接入更多模型服务商、补充首 Token 延迟等指标，并将线上 Trace 与模型评测、Prompt 优化打通，实现持续迭代。

💬 文章金句

  • LLM Observer SDK 不负责调用模型。应用仍通过模型客户端调用火山方舟等 OpenAI 兼容服务；SDK 采集模型、Token、耗时和错误状态，并上报到 TLS。
  • Session 表示一段用户会话，可包含多个 Trace；Trace 表示一次请求或一轮对话；Span 表示具体执行阶段。
  • 通过 Trace 调用链定位模型、工具或业务逻辑中的异常环节。
  • 通过 Trace 和 Session 级 Token 汇总识别高消耗请求与会话。
  • TLS LLM 应用可观测方案包括：应用侧数据采集、标准化数据处理、数据存储与消费、可视化观测仪表盘。
