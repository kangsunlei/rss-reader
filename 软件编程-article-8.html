自动化你的安全“打地鼠”游戏：对话 Exaforce

1/22/2026, 3:00:00 PM

📌 一句话摘要

本访谈探讨了 Exaforce 如何利用 AI 智能体和统计建模来实现 SOC 运营自动化，重点关注云和 SaaS 环境的检测、分诊与响应。

📝 详细摘要

本文是对安全初创公司 Exaforce 创始人的采访，该公司致力于实现安全运营中心（SOC）的自动化。文章探讨了安全人才严重短缺以及保护 GitHub 和 Snowflake 等 SaaS 服务日益复杂的问题。Exaforce 的平台采用“数据优先”的方法，将传统的统计基准与基于 LLM 的推理相结合，以减少异常检测中的噪音。通过为 AI 智能体提供特定的业务上下文和缩小的核心数据范围，他们实现了自动分诊和动态事件响应，例如通过 Slack 进行自动用户验证以及定制化的威胁狩猎智能体。该系统旨在通过 API 和单租户云架构进行快速部署。

💡 主要观点

  1. AI 智能体通过自动化安全信号的分诊和调查，增强了 SOC 的能力。 Exaforce 不再仅仅依靠人工分析师来筛选嘈杂的警报，而是利用 LLM 通过提供特定的业务上下文和过滤后的数据来对检测结果进行推理，有效地将一个小团队转变为一个规模大得多的团队。
  2. 在安全领域，具有前期工程设计的“数据优先”方法优于简单的 LLM 叠加。 通过在引入 LLM 之前摄取原始数据并构建语义/富化信息，系统减少了幻觉和对大规模微调的需求，利用 API 的通用智能与特定领域上下文相结合。
  3. 现代安全漏洞越来越多地出现在关键 SaaS 服务中，而非传统基础设施。 许多大型组织对 Snowflake、OpenAI 和 GitHub 等平台缺乏检测覆盖，而敏感数据现在正存储于此，这使得基于 API 的日志摄取和行为建模变得至关重要。
  4. 自动化响应正从静态剧本演变为动态的、自然语言驱动的智能体。 除了密码重置等简单操作外，用户现在可以使用自然语言构建定制的自动化智能体，以执行复杂的任务，如交叉引用 IP 活动并报告来自可疑来源的成功身份验证。

💬 文章金句

  • 如果你确实拥有一个配有分析师的安全运营中心，我们的目标是增强这些分析师的能力。想想一个由两三名分析师组成的团队——你如何让他们发挥出十人团队的作用？
  • 在过去，你无法创造更高的保真度，因为你没有足够的人手来查看这些检测结果。现在我们实际上有了机器在查看它们，所以我们甚至可以获取最低限度的信号，并将它们整合在一起。
  • 我们主要通过 API 利用大量 LLM 的推理能力。我们发现它们在通用智能方面表现出色……我们为它们提供所有特定领域的上下文。
  • 智能体本身会响应请求以获取更多信息，从而确定某件事是误报、需要进一步调查，还是被判定为确定的阳性案例。
  • 在开始构建这个 AI SOC 平台的旅程中，我们发现市场上大多数人将其视为一个 AI 分析师问题。但我们认为这包含四个主要任务：检测、分诊、调查和响应。
