Rust 给 AI 编程立新规：能帮你看，不能替你写，用多了还会“熔断”

8/9/2026, 2:15:00 AM

📌 一句话摘要

本文报道 Rust 五个核心团队正式采纳 LLM 使用准则，核心原则是可分析、可审查、不可创造，并介绍了三层规则、熔断机制与 Zig 禁令路线的对比。

📝 详细摘要

文章报道 Rust 项目中编译器、标准库、类型系统、rustdoc 与 bootstrap 五个团队正式采纳 LLM 使用准则，规范贡献者向 rust-lang/rust 提交代码时如何使用大语言模型。准则核心是：LLM 可用于回答问题、分析、提炼、完善、检查和审查，但不能用来创造。文章梳理了三层规则：仅本人可见的私人用途完全允许；机器翻译、微小修改、发现 Bug 与代码审查机器人必须披露 LLM 参与；LLM 直接生成评论、文档和编译器诊断，或仅凭 LLM 审查结论决定合并、拒绝改动则被明确禁止。违反披露义务将被视为违反行为准则，与骚扰同级。项目同时为 LLM 创建的 PR 设立实验机制：需前置沟通审阅者、避开编译器健全性等关键部分、补足测试，并设置六周窗口熔断机制。文章还对比了 Zig 全面禁止 LLM 的严格路线，分析了促使 Rust 立规的三重压力——PR 信号失效、审查资源稀缺、LLM 往返浪费审阅时间，并指出 Rust 内部对 AI 并无共识，未来可能被项目级 LLM 委员会规则覆盖。

💡 主要观点

  1. Rust 新准则的核心原则是「可以思考、审查，唯独不能创造」。 LLM 可用于回答问题、分析、提炼、检查、提出建议和审查代码，但不能直接生成代码或文档内容。
  2. 规则按用途分三层管理：私人使用、披露使用、明确禁止。 私人用途完全允许；机器翻译、微小修改、发现 Bug 和审查机器人必须披露；LLM 直接生成评论文档或仅凭其审查结论合并改动则被禁止。
  3. 违反披露义务按行为准则处理，与骚扰同级。 首次违规可能警告，反复违规可封禁；规则同时承认难以技术强制，目标是消除推脱空间而非抓每一次违规。
  4. LLM 创建的 PR 进入实验通道并设熔断机制。 需提前沟通指定审阅者、避开关键部分、补足测试；若六周窗口内 LLM 创建 PR 超过合并量一半，将暂停合并至少 10 天。
  5. 促使立规的三大压力是信号失效、审查资源稀缺与 LLM 往返浪费。 漂亮 PR 不再代表真实投入；代码生成成本下降加剧审查瓶颈；把审阅意见复制进 LLM 再把回答贴回 GitHub 是在浪费所有人的时间。

💬 文章金句

  • 可以用 LLM 回答问题、分析、提炼、完善、检查、提出建议和审查，但不能用它来创造。
  • 我们的目标并不是抓住每一次违规行为......我们的目标，是消除任何可以推脱的空间：让人们必须在遵守准则和故意违反准则之间作出选择。
  • LLM 可以让一个人非常快地生成更多代码，但并不会同步增加能够判断这些代码是否应该进入项目的人。
