如何使用 n8n 和 Decapod 构建自主 AI 智能体

3/11/2026, 8:18:39 PM

📌 一句话摘要

本手册提供了构建 Decapod 的全面指南，这是一个 DIY 智能体 AI 框架，通过编排 n8n、Docker 和 Open WebUI 来创建一个安全、可定制且低代码的自主智能体。

📝 详细摘要

本文介绍了 Decapod，这是一个针对追求透明度和控制权的“全民开发者”设计的开源 AI 智能体平台替代方案。与黑盒 SaaS 产品不同，Decapod 是一个模块化系统，使用 n8n 进行工作流自动化，Open WebUI 作为聊天界面，并使用 Docker 进行沙箱部署。作者详细介绍了一种稳健的架构，其中 n8n 充当兼容 OpenAI 的中间件，拦截 API 调用以管理状态、任务队列和“技能”（以子工作流形式实现）。指南涵盖了整个设置过程，包括 VPS 选择、DNS 配置、使用 Docker Compose 部署 Postgres 和 MinIO，以及凭据的配置。强调的核心优势包括增强的安全性（API 密钥对 LLM 隐藏）、通过自托管实现的成本效益，以及在智能体工作流中实施人工干预（HITL）检查点的能力。

💡 主要观点

  1. Decapod 充当兼容 OpenAI 的中间件，用于智能体编排。 它拦截来自 Open WebUI 等工具的标准 API 调用，并使用 n8n 工作流来管理复杂的智能体逻辑、工具调用和状态，最后返回最终响应。
  2. 该架构通过在 n8n 内部对凭据进行沙箱化处理，将安全性放在首位。 通过在 n8n 节点内部处理所有 API 密钥和服务器连接，LLM 永远无法直接访问敏感凭据，从而降低了提示词注入攻击的风险。
  3. 技能被实现为模块化的 n8n 子工作流，具有极高的可扩展性。 系统遵循“一个技能 = 一个子工作流”的模式，开发者只需创建一个符合特定 JSON 模式的新工作流，即可添加新功能。
  4. 在 VPS 上自托管该技术栈，为 AI SaaS 提供了一个极具成本效益的替代方案。 在单个 VPS 上使用 MinIO 和 Postgres 等工具，可以构建一个强大且全天候运行的智能体环境，而无需支付多个专业 SaaS 订阅的高昂经常性费用。

💬 文章金句

  • Decapod 不是一个封闭的 SaaS 产品。它的任何部分都不是黑盒，完全可以进行二次开发。
  • 智能体永远看不到任何一个 API 密钥，甚至不需要确切知道你是如何连接服务的。凭据由 n8n 处理。
  • Decapod 在最适合由代码/逻辑处理的部分与最适合由 AI 处理的部分之间保持了清晰的界限。
  • 当绝对最佳的解决方案已经存在时，为什么要重新发明轮子？
  • Decapod 是一个表现得像 OpenAI API 的中间件。但它会拦截 API 调用，并利用真实的 API 执行智能体任务。
