使用 Clawdbot + DMR 运行私有个人 AI

1/26/2026, 12:53:33 PM

📌 一句话摘要

本指南演示了如何通过集成 Clawdbot 与 Docker Model Runner (DMR) 进行本地 LLM 执行，构建一个隐私优先、自托管的个人 AI 助手。

📝 详细摘要

本文介绍了一种使用 Clawdbot 和 Docker Model Runner (DMR) 创建私有 AI 助手的技术方案。Clawdbot 作为智能体接口，可与 Telegram 和 Signal 等消息平台集成，而 DMR 则作为本地推理引擎，将 LLM 作为 OCI 制品运行。该方案解决了日益增长的数据隐私、数据驻留以及云端 AI 高昂 Token 成本的问题。作者提供了详细的技术步骤，包括配置 Clawdbot 将请求路由到本地 DMR 服务器、管理模型上下文窗口，以及部署 gpt-oss 或 glm-4.7-flash 等特定模型。该工作流支持在本地硬件上完成自动化邮件摘要等复杂任务，确保敏感数据永远不会离开用户的基础设施。

💡 主要观点

  1. 结合 Clawdbot 和 Docker Model Runner 构建以隐私为中心的 AI 技术栈。 Clawdbot 提供消息集成和智能体能力，而 DMR 处理本地模型推理，确保个人数据保留在本地硬件上。
  2. 通过在本地 GPU/CPU 资源上运行推理来消除 Token 计费。 通过 DMR 在本地托管模型，用户可以执行长期记忆处理和主动搜索等高 Token 消耗任务，而无需支付云端 API 费用。
  3. 配置 Clawdbot 以使用兼容 OpenAI 的本地端点。 用户可以手动更新 Clawdbot 的 JSON 配置以指向 DMR 服务器，从而允许助手在“思考”过程中绕过外部供应商。
  4. 通过上下文窗口管理和“灵魂”文件优化助手性能。 为了实现有效的个人辅助，模型需要较大的上下文窗口和特定的性格定义 (SOUL.md) 以维持长期记忆和指令遵循。

💬 文章金句

  • 在“隐私优先”的设置中，助手的记忆、消息历史和文件都保留在您的硬件上。
  • 使用 Docker Model Runner，推理运行在您自己的 GPU/CPU 上。一旦拉取模型，就不再产生 Token 费用。
  • 此配置告知 Clawdbot 绕过外部 API，并将所有“思考”过程路由到您的私有模型。
  • 如果模型的默认上下文太小，它会在对话中途“忘记”您的指令。
  • 没有任何数据离开您的机器；您只需通过选定的消息应用在手机上接收有用的通知。
