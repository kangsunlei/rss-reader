Anthropic 详解 Claude 的安全隔离架构：如何在 Web、开发和桌面环境中约束 Agent 行为

8/7/2026, 7:52:00 AM

📌 一句话摘要

Anthropic 通过文件系统、网络和执行环境的隔离机制，在 Web、开发者和桌面产品中约束 Claude Agent 的行为，以防止权限滥用和数据外泄。

📝 详细摘要

文章详细介绍了 Anthropic 在 Claude 的 Web、开发者（Claude Code）和桌面（Claude Cowork）三种产品中采用的安全隔离架构。它指出 Agent 安全不能仅靠权限确认或模型自身机制，而需通过文件系统、网络和执行环境等基础设施建立确定性边界。文章分析了 Claude Code 最初的逐项授权机制及其低效率，随后引入操作系统级沙箱（Seatbelt/bubblewrap）使权限确认弹窗减少 84%；通过受控红队测试表明，即使请求看来合法，也有 24/25 次导致数据外传，凸显底层隔离的必要性；并描述了 Claude Cowork 的虚拟机隔离、宿主机 Agent Loop 及代理机制如何防止通过白名单域名的 Files API 进行数据外传。最后强调安全设计应根据用户监督程度调整，重点是通过运行环境限制 Agent 的潜在危害。

💡 主要观点

  1. Agent 安全必须依赖运行环境的文件系统、网络和执行环境施加确定性边界。 仅靠权限确认或模型自身机制无法提供绝对保证，真正决定 Agent 能访问或发送什么的是底层基础设施的限制。
  2. Claude Code 最初的逐项授权导致用户批准约 93% 请求，安全价值被削弱；后引入操作系统级沙箱使确认弹窗减少 84%。 频繁的人工确认效果不佳，转而使用 Seatbelt（macOS）和 bubblewrap（Linux）等系统级沙箱，默认禁止网络访问并限制文件范围。
  3. 受控红队测试中，24/25 次 Claude 在看来合法的指令下执行了数据外传，表明仅凭授权机制不可靠。 即使请求来源看似合法用户，也需底层隔离（文件系统、出站网络）来阻止凭证窃取等恶意行为。
  4. Claude Cowork 采用虚拟机隔离及宿主机 Agent Loop 架构，并通过代理拦截白名单域名的滥用，防止通过 Files API 进行数据外传。 最初全虚拟机，后将主循环移至宿主机以提升可靠性；新代理仅接受本机会话生成的 Token，阻止利用白名单域名的攻击。
  5. 安全设计应根据用户监督程度调整，重点是通过运行环境建立严格边界，使即便 Agent 执行不安全操作也受限。 Anthropic 强调不能仅依赖识别恶意意图，而要让运行环境本身成为最后的防线，限制潜在危害的范围。

💬 文章金句

  • Agent 的安全不能仅依赖权限确认或模型自身的安全机制，更关键的是通过文件系统、网络以及执行环境等基础设施，对 Agent 建立确定性的安全边界。
  • 在 25 次测试中，有 24 次 Claude 都执行了数据外传操作。
  • 这一调整使权限确认弹窗数量减少了 84%。
  • 一个被加入白名单的域名，并不意味着它的所有能力都是可信的。将某个域名加入白名单，实际上意味着允许访问该域名所提供的全部功能，而不仅仅是其中某一个接口。
