Python 新版本去 GIL 刷屏，Karpathy 点赞敢死队，Python 之父：冷静，别神话并发

10/12/2025, 4:16:00 AM

📌 一句话摘要

Python 3.14 引入可选的去 GIL 特性，引发开发者热议，但 Python 之父 Guido van Rossum 呼吁冷静看待并发和 AI 炒作。

📝 详细摘要

文章报道了 Python 3.14 版本正式引入可选的“去 GIL”（全局解释器锁）功能，实现了自由线程支持和并发解释器，预计能显著提升 CPU 密集型多线程程序的并行性能。许多开发者对此表示兴奋，认为这是一个“革命性”的更新，Andrej Karpathy 也表示赞同。然而，Python 之父 Guido van Rossum 在访谈中对此泼了“冷静水”，他认为 GIL 移除的影响被高估，主要服务于超大规模并发场景，并增加了 CPython 的维护复杂性。他强调代码可读性和人类审查的重要性，对 AI 炒作持谨慎态度，并指出类型提示对于大规模非 AI 应用的质量至关重要。文章呈现了对 Python 核心技术演进的两种不同观点，并探讨了其在 AI 时代的发展方向。

💡 主要观点

  1. Python 3.14 引入可选的去 GIL 特性，显著提升多线程并行计算性能 新版本通过自由线程支持移除 GIL，使得 CPU 密集型多线程程序能真正并行利用多核，解决长期以来的性能瓶颈，为开发者提供更多选择。
  2. Python 之父 Guido van Rossum 认为 GIL 移除影响被高估，警示并发编程复杂性与 AI 炒作 Guido 强调并发模型不易掌握，过度并行化可能适得其反，并对当前 AI 领域的过度宣传保持清醒，认为其本质仍是软件工程问题。
  3. 类型提示对大规模代码库质量至关重要，且 Python 需持续关注生态兼容性与可维护性 Guido 指出类型提示是保证万行以上代码质量的关键，同时强调 Python 未来发展应优先考虑向后兼容性、库的维护性及长期演进。

💬 文章金句

  • Python 3.14 终于真的发布了。终于移除了 GIL，这意味着多线程代码会快得多，不用再忍受多进程的脑损伤和各种临时变通。
  • 老实说，我觉得移除 GIL 这事的影响被过度夸大了。这既满足了我们最大用户（例如 Meta）的需求，同时也给 CPython 代码库的潜在贡献者招了点麻烦（新代码更容易引入并发性 bug）。
  • 代码仍然离不开人类的阅读和审查，否则我们可能会完全失去对自身生存的控制力。
  • 我什么都想不出来。我还是觉得现在 AI 炒作太甚了，它的本质仍然是种软件。
  • 我希望 Python 的传承能够始终体现其草根精神和全球协作精神，始终依托于平等和尊重，而非权力和金钱。
