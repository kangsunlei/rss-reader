Pega Launchpad：基于 AWS Lambda 的安全 SaaS 扩展方案

5/30/2025, 11:30:49 AM

📌 一句话摘要

Pega Launchpad 利用 AWS Lambda 构建安全、可扩展的多租户 SaaS 平台，用于执行客户自定义代码。

📝 详细摘要

本文详细介绍了 Pegasystems 如何开发 Launchpad，一个 SaaS 平台，允许租户运行自定义代码来实现安全扩展。核心挑战在于如何在多租户环境下，安全地执行不受信任的代码，并保持隔离性。Launchpad 利用 AWS Lambda 固有的隔离（Firecracker microVM）和可扩展性，在与核心平台分离的专用 AWS 账户中运行租户函数。该架构提供诸多优势，如托管运行时、细粒度权限控制、自动伸缩和内置监控。本文概述了创作和运行时架构，包括使用 EKS 作为控制平面，使用 IAM 角色进行跨账户调用，以及使用 CloudWatch 和 X-Ray 的集中式可观测性策略。文章还探讨了构建此类可扩展 SaaS 解决方案的最佳实践，重点包括扩展点、账户隔离、最小权限和函数/租户隔离。

💡 主要观点

  1. AWS Lambda 提供强大的租户代码隔离 利用 Lambda 基于 Firecracker 的 microVM 确保每个租户的自定义函数都具有专用且隔离的执行环境，这对于多租户安全性至关重要。
  2. 在单独的 AWS 账户中运行租户代码可增强安全边界。 将不受信任的代码执行环境与核心 SaaS 平台账户分离，增加了针对潜在安全漏洞的关键隔离层。
  3. 全面的可观测性策略对于分布式租户代码至关重要。 聚合跨不同账户的日志和指标，并通过关联 ID 将它们链接起来，可以对每个租户函数进行有效的监控、故障排除和成本分析。
  4. SaaS 平台应设计显式扩展点 通过为租户提供明确的接口来注入自定义逻辑，避免修改核心平台，从而保持代码库的整洁并减少技术债。

💬 文章金句

  • 一种新兴模式是租户提供的自定义代码执行，允许租户将代码注入到特定的工作流节点…
  • 每个租户提供的不可信代码片段都以独立 Lambda 函数的形式启动，不同函数之间通过 Firecracker 提供强隔离…
  • 为进一步降低风险，Launchpad 在专用 AWS 账户中运行这些包含不可信代码的 Lambda 函数。该账户与核心 SaaS 平台账户隔离。
  • 运维一个在多个 AWS 账户中运行不可信代码的分布式架构，需要全面的可观测性策略。
  • 在核心平台代码中为每个租户实现变体，可能导致维护复杂性和技术债。因此，SaaS 解决方案应设计为具有扩展点…
