Node.js Plus 来了！

6/19/2026, 7:17:00 AM

📌 一句话摘要

Nub 是一个由 Zod 和 tRPC 作者开发的开源工具包，旨在通过整合 TypeScript 运行、包管理、环境变量加载等能力，在不脱离 Node.js 生态的前提下，提供接近 Bun 的现代开发体验。

📝 详细摘要

本文介绍了开源工具 Nub，它定位为 Node.js 的增强层，而非一个新的 JavaScript 运行时。Nub 由知名开源项目 Zod 和 tRPC 的作者开发，其核心思路是利用 Node.js 自身的扩展能力（如 preload、loader hook、N-API），将 TypeScript 运行、JSX/Decorators 支持、包管理、环境变量加载、文件监听、tsconfig paths 解析等原本需要多个独立工具（如 tsx、dotenv、nodemon、npx、nvm）完成的功能，整合到一个统一的命令行入口中。文章详细解释了 Nub 的工作原理：通过 Rust CLI 启动前预处理，然后注入 preload 脚本，利用 Node 的模块钩子处理非标准文件格式。在性能方面，Nub 通过 Rust 工具链替代了部分 Node.js 工具（如 pnpm run、npx），实现了显著的启动速度提升。此外，Nub 还内置了安全策略，如默认阻止 postinstall 脚本。文章认为，Nub 为那些无法迁移到 Bun 或 Deno 的现有 Node.js 项目提供了一条更现实的升级路径。

💡 主要观点

  1. Nub 定位为 Node.js 的增强层，而非替代运行时。 它不修改 Node 源码或替换 JS 引擎，而是通过 Rust CLI 和 Node 的扩展钩子，在启动前整合并优化开发工具链，让现有 Node 项目获得更现代的体验。
  2. Nub 通过整合多个工具，简化了 Node.js 开发配置。 它将 tsx、dotenv、nodemon、npx、nvm 等工具的功能统一到一个命令中，降低了项目对多个外部依赖的管理成本，尤其对老项目友好。
  3. Nub 的性能提升主要体现在工具链层，而非业务代码执行。 由于使用 Rust 编写的 CLI 替代了部分 Node.js 工具（如 pnpm run、npx），减少了 JS 工具链的启动开销，官方数据显示替代品可提速数倍至数十倍。
  4. Nub 内置了安全策略，并兼容现有生态。 它默认阻止 postinstall 脚本并检查依赖漏洞，同时不强制迁移项目格式，可与现有包管理器和 lockfile 共存，降低了采用风险。

💬 文章金句

  • Nub 真正有意思的地方就在这里。它不是喊一句我比 Node 更快，也不是要求你离开 Node 生态。
  • 对已经离不开 Node 的项目来说，这可能是一条更现实的升级路线：不用切到 Bun / Deno，也能在 Node.js 生态里获得接近 Bun 的开发速度和现代体验。
