用代码染色实现精准无效代码清理

12/23/2025, 12:31:00 AM

📌 一句话摘要

文章利用代码染色和覆盖率分析技术，结合 JaCoCo 和 IDEA 插件，实现对 Java 服务端应用中无效代码的精准识别并高效清理。

📝 详细摘要

本文介绍了淘天集团首页与信息流工程团队在解决应用 D（一个历史悠久的 Java 服务端应用）中大量无效代码问题时所采用的技术方案。该方案核心是基于代码执行染色和覆盖率分析，通过 JVM Agent 实现代码插桩和在线染色，并利用 JaCoCo 工具高效采集代码执行数据。为提高清理效率，团队开发了 IDEA 插件，将数据采集和覆盖率可视化集成，让开发者能直观地看到代码执行情况。文章详细对比了 Agent 与 Attach、自研插桩与 JaCoCo、在线与离线插桩等不同方案的优劣，并最终选择了 Agent 方式集成了 JaCoCo。此外，还介绍了数据合并、报告生成以及插件设计与实现过程。通过此方案，团队成功清理了数十万行无效代码，显著降低了老旧代码库的维护成本和学习门槛，并对未来的代码治理工作提出了反思和展望。

💡 主要观点

  1. 利用 JVM Agent 和 JaCoCo 实现代码执行染色，为无效代码清理提供数据支撑。 通过 Java Agent 机制在运行时动态修改字节码进行代码插桩，结合 JaCoCo 实现高效、稳定的代码执行情况采集，为识别“僵尸代码”提供了客观依据，避免误删。
  2. 开发 IDEA 插件实现代码覆盖率的可视化，极大提升了代码清理效率和准确性。 将采集到的代码覆盖率数据通过 IDEA 插件直观展示，开发者可以直接在 IDE 中看到代码行执行情况，快速定位、分析并清理无效代码，实现“又准又快”的治理。
  3. 采取 Agent 方式结合 JaCoCo 进行长期、周期性在线代码执行数据采集，适应了生产环境需求。 综合考虑稳定性、效率和对生产环境的影响，选择 Agent 方式在应用启动时加载 JaCoCo，并周期性 dump 数据，确保了大规模服务代码治理的持续性和可靠性。
  4. 详细的数据合并与报告生成机制，确保覆盖率数据的完整性和可读性。 通过 jGit 获取最新代码、Maven 编译生成.class 文件，再与 JaCoCo 采集的.exec 数据合并生成详细 XML 报告，为开发者提供了全面、准确的代码执行视图。
  5. 技术方案考虑热部署及复杂架构影响，确保了方案的普适性和鲁棒性。 在面对 D 应用的热部署架构时，文章分析了自定义类加载器对 Agent 插桩的影响，并验证了方案的有效性，体现了对复杂生产环境的适应性。

💬 文章金句

  • D 是我们团队的服务端应用，其代码库历史悠久，最早可以追溯到淘宝 APP 无线端迁移，应用中许多代码已无线上流量，但代码并未随业务的下线被清理。
  • 清理代码就"有理有据"；仅靠原始分析出的数据清理依然低效，为此我们将数据采集、覆盖率可视化通过 IDEA 插件集成，实现清理无效代码过程又准又快。
  • 针对腐朽代码染色我们主要讨论行覆盖率，知道指定 package 和类的行覆盖率就大概可以知道治理的方向。
  • 高效将探针插入到代码中，不对正常业务代码造成太大影响，是保障线上代码正常采集结果的前提，如前所述，自己实现插桩自定义空间大，方案设计灵活，缺点是效率和开发成本高；使用 JaCoCo 工具可以快速集成、性能高效。
  • 通过代码插桩染色和执行情况的采集，较好对 D 应用代码做了治理，中间过程有收获也走了弯路。
