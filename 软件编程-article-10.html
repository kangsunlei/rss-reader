Agent、MCP、Skill、Cli 一次讲透：老系统接入 AI 的地图与三条路径

10/12/2026, 9:36:00 AM

📌 一句话摘要

本文介绍了 Agent、MCP、Skill、CLI 和 Model 的概念关系，并为企业老系统接入 AI 提供了 API 封装、CLI 包装及 RPA 三种落地路径。

📝 详细摘要

针对企业希望让 AI 深入老业务系统的工程挑战，作者通过“数字化团队”类比清晰梳理了 Model（大脑）、Agent（数字员工）、Skill（岗位手册）、MCP（万能转接头）和 CLI（命令行）的功能与协作关系。文章详细分析了根据系统开放程度、文档完整、鉴权体系及变更风险，提出了 API 封装首选、CLI 包装次选、RPA 兜底的落地策略，并对 MCP 的实现形式（stdio， Streamable HTTP 等）提供了标准化建议。

💡 主要观点

  1. AI 系统的核心架构应被视为一个协同运作的数字化团队 Model 负责推理，Agent 负责目标驱动的执行，Skill 封装 SOP 经验，MCP 提供统一标准接口，CLI 则提供交互通道。
  2. MCP (Model Context Protocol) 是连接 AI 与外部系统的关键标准 MCP 通过标准化的外壳让 Agent 无需感知底层是 API、脚本还是 CLI，极大地提升了老系统接入的兼容性。
  3. 老系统接入 AI 有三种主流路径，按优先级排序 API 封装最稳定且改动最小；CLI 包装适用于无 API 但有命令的系统；RPA/浏览器自动化作为无界面的兜底方案，但脆弱性最高。
  4. MCP 的实现形式应根据场景选择传输协议 本地开发和桌面 Agent 推荐 stdio；企业级共享推荐使用 Streamable HTTP 加 OAuth；SSE 仅用于存量迁移，WebSocket 留给实时或浏览器场景。
  5. 企业级 AI 落地必须重视安全与鉴权问题 敏感操作应引入人工确认，身份信息需要从用户传递到 Agent 再到系统，且需单独评审。

💬 文章金句

  • 上新系统是采购问题，深入老系统是工程问题。
  • 把整套 AI 系统想象成公司新职的一支数字化团队。
  • MCP 是传输无关的，协议逻辑不变，变的只是消息跑腿。
  • 第一场仗必须赢，要赢得便宜。
