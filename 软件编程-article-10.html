Kubernetes 统治了容器时代，谷歌 Agent Substrate 意在拿下下一个十年

7/30/2026, 7:30:00 AM

📌 一句话摘要

本文分析谷歌 GKE Agent Sandbox 与 Agent Substrate，指出 Kubernetes 的控制平面架构不适合 AI 智能体负载，智能体需要一种新的运行时形态。

📝 详细摘要

文章从谷歌 2026 年 5 月推出的 GKE Agent Sandbox 与 Agent Substrate 两个项目出发，系统论证了 Kubernetes 作为智能体控制平面的不匹配性。作者将智能体类比为操作系统中的进程——大部分时间休眠、被事件唤醒后短暂运行——指出 Kubernetes 最初为长期运行的复制服务设计，其中心化 API 服务器与调度器在面对数百万细粒度调度事件时成为瓶颈。Agent Sandbox 提供基于 gVisor 的安全沙箱与预热池机制（90% 分配在 200ms 内完成），解决不可信代码隔离与冷启动问题；Agent Substrate 则在 Kubernetes 旁叠加专用调度层，通过虚拟内存超分配思路实现 30 倍以上超额订阅与亚秒级激活。文章最后提出开放问题：智能体控制平面是否会像容器编排一样收敛为单一开源项目，还是各云厂商各自为政。

💡 主要观点

  1. 智能体的负载特性与 Kubernetes 的设计假设根本性不匹配。 智能体大部分时间休眠、被事件唤醒后短暂运行，而 Kubernetes 为长期运行的复制服务设计，其 API 服务器与调度器在数百万细粒度调度事件下成为瓶颈。
  2. Agent Sandbox 用 gVisor 内核隔离与预热池解决不可信代码与冷启动问题。 默认通过 gVisor 实现内核级隔离而非容器级信任，配合预配置副本池实现 90% 分配在 200ms 内完成，LangChain、Lovable 等客户已运行数百万智能体。
  3. Agent Substrate 借鉴虚拟内存超分配思路实现智能体调度。 将大量有状态会话复用到少量预热工作 Pod 上，空闲会话快照持久化，实现 30 倍以上超额订阅与亚秒级激活，绕过 Kubernetes 控制平面。
  4. 智能体运行时可能成为继 VM、容器、无服务器之后的第四种计算形态。 会话感知、隔离的智能体运行时具备独立的资源调度与生命周期管理逻辑，超大规模云厂商已朝此方向布局。

💬 文章金句

  • Kubernetes 是一个优秀的数据中心调度器，在配置底层机器资源方面仍然很有用。但对于一大群休眠进程形态的负载而言，它并不是合适的调度器。
  • 智能体是进程，资源预热池对应一组 CPU 核心，空闲会话快照等同于内存页置换至磁盘，而资源超配背后的思路和虚拟内存机制一贯的设计逻辑如出一辙。
