Vitest 推出浏览器模式，作为 JSDOM 的替代方案

6/5/2025, 12:00:00 AM

📌 一句话摘要

Vitest 推出实验性浏览器模式用于前端测试，提供了 JSDOM 的真实替代方案。

📝 详细摘要

Vitest，这个现代的 Vite 原生测试运行器，最近发布了一个实验性的浏览器模式。该模式允许前端测试直接在真实的浏览器环境（通过 Playwright 或 WebDriverIO）中运行，而不再依赖于 JSDOM 这样的模拟 DOM 环境。此举旨在为使用 React、Vue 和 Svelte 等框架构建的 UI 应用提供更准确、更可靠的测试结果，解决 JSDOM 在处理复杂浏览器行为（例如布局计算、CSS 行为或 JSDOM 尚未支持的 API）方面的局限性。尽管这种模式为实现更真实的测试体验以及潜在地摆脱对 React Testing Library 等库中 JSDOM 的依赖提供了前景，但它目前仍处于早期开发阶段，与模拟环境相比可能需要更长的初始化时间，因此在决定采用时需要仔细权衡。

💡 主要观点

  1. Vitest 浏览器模式在真实浏览器中运行测试，以提高准确性。 通过利用 Playwright 或 WebDriverIO 等工具，测试在真实的浏览器环境中执行，为 UI 组件提供比 JSDOM 更真实的行为。
  2. 它解决了 JSDOM 在高级浏览器功能方面的局限性。 JSDOM 模拟在 CSS、布局计算和不支持的 API 方面可能存在不足，而真实浏览器测试可以准确处理这些问题。
  3. 支持流行的前端框架，如 React、Vue 和 Svelte。 新模式与主要框架兼容，为广泛的项目提供了可行的测试替代方案。
  4. 浏览器模式是实验性的，并存在潜在的缺点。 目前处于早期开发阶段，可能会有变动，并且与 JSDOM 等模拟环境相比，可能具有更长的初始化时间，因此需要仔细考虑是否采用。

💬 文章金句

  • Vitest，现代的 Vite 原生测试运行器，引入了 Vitest 浏览器模式，为开发人员提供了 JSDOM 等传统 DOM 模拟库的替代方案。
  • 此模式允许真实的浏览器渲染和交互。
  • 然而，由于 JSDOM 不是一个真实的浏览器，其实现有时可能无法满足高级用例的需求...
  • React Testing Library 的作者 Kent C. Dodds 表示，看到人们卸载 React Testing Library 转而使用原生实现，他从未如此高兴。
