深度实践：得物算法域全景可观测性从 0 到 1 的演进之路

1/7/2026, 10:30:00 AM

📌 一句话摘要

得物技术分享了其如何自研 APM SDK、标准化 Trace/Log、构建算法知识图谱、并应用智能异常检测和事件联动的全景可观测性平台，以提升算法域系统稳定性。

📝 详细摘要

得物技术团队详细介绍了其从 0 到 1 构建算法域全景可观测性的实践经验。文章围绕“四大支柱”——Trace、Metric、Log、Event，阐述了如何通过标准化手段，特别是针对 C++服务 Trace 缺失的问题，自研 APM Cpp SDK，并优化报文压缩、异步上报等方案来解决性能挑战。Log 标准化方面，提出跨语言语义对齐和场景化建模。文章最核心的创新在于以“场景”为魂，通过 Baggage 机制和 InnerBaggage 在全链路传递场景信息，并结合动态元数据和流式计算引擎构建算法知识图谱。最后，通过改进型 IQR 算法实现智能异常检测，并统一事件协议，完成变更事件与链路抖动的因果关联，大幅提升了算法系统的稳定性和故障排查效率。

💡 主要观点

  1. 得物算法域全景可观测性以“场景”为核心，通过四大支柱（Trace、Metric、Log、Event）实现数据联动。 区别于传统物理链路视角，得物强调将业务场景语义融入可观测性数据，通过 Baggage 机制透传场景信息，将 Trace、Metric、Log、Event 四者紧密结合，从而打破数据孤岛。
  2. 针对 C++核心服务性能敏感，得物自研了高性能 APM Cpp SDK，并优化 Trace 报文压缩与异步上报机制。 考虑到 OpenTelemetry C++ SDK 的通用性和性能不确定性，得物团队根据 C++服务的极致性能需求，自研了定制化的 SDK，并通过长度过滤、字段压缩、批量聚合等手段高效上报 Trace 数据，确保对业务无侵入和低延迟。
  3. 通过构建场景化建模（AlgoScene）和算法知识图谱，将离散链路信息转化为标准化的业务计算流。 利用 OpenTelemetry 的 Baggage 机制在全链路传递算法场景名称，并结合 InnerBaggage 在进程内传递算子信息，通过流式计算引擎实时处理 Trace 数据，并存储到 Neo4j 图数据库中，形成场景调用拓扑图。
  4. 引入改进型 IQR 算法进行异常检测，有效应对非正态分布的数据特征，降低误报率。 针对算法指标数据（如错误数）常呈现正偏态、高峰度、零基线等特点，放弃了传统的 3-Sigma 算法，改进了 IQR 算法，使其在保持灵敏度的同时，显著降低了虚假告警，提升了异常检测的准确性。
  5. 实现统一的事件标准化协议，将各类变更事件与链路异常进行因果关联。 标准化了配置中心、发布平台、AB 实验平台等 10+个源头的变更事件协议，将每日上万+的变更事件与实时链路数据进行关联，从而快速定位故障根因，提升故障止血效率。

💬 文章金句

  • 监控建设不能不结合业务场景，否则产生的数据很难在实际排查中发挥价值。
  • C++侧服务位于请求链路关键路径，对 RT 与尾延迟极其敏感，需要对 Span 创建、上下文传播、属性写入等操作进行严格的 CPU 与内存开销控制。
  • 在全链路可观测体系中，日志是还原业务现场的最终证据。
  • 我们决定打破传统的物理链路视角，转而以“场景”为核心单元构建知识图谱。
  • 事件标准化的核心目标是：让每一次变更都有迹可循，并能自动与链路抖动建立因果关联。
