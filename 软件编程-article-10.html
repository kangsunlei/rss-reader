AI 智能体未来之争：是迷你应用（GPTs）？还是模块化代码（Skills）？开发者，你站哪边？

11/7/2025, 3:43:00 AM

📌 一句话摘要

Anthropic 推出 Skills 功能，通过模块化、可复用的组件扩展 Claude 能力，与 OpenAI GPTs 和微软 Copilot Studio 形成差异化竞争，更侧重开发者中心和治理。

📝 详细摘要

文章详细介绍了 Anthropic 为 Claude 推出名为 Skills 的全新功能。Skills 允许开发者通过模块化、可复用的任务组件来扩展 Claude 的能力，例如文档总结、API 数据检索或特定计算。它全面覆盖 Claude 的网页应用、Code 环境及 API 接口，通过 schema 定义输入、输出和权限，并依赖 Code Execution Tool 安全运行。文章强调 Skills 与 OpenAI 的 GPTs（迷你智能体）和微软 Copilot Studio（可视化界面）不同，Anthropic 更注重透明化、可审计性，采用以开发者为中心的方法，优先强调模块化、可维护性和治理。早期采用者对此表示兴奋，认为这是迈向智能体未来的重要一步。Anthropic 计划提供更多文档、SDK 示例和社区展示，并开放抢先体验权限。

💡 主要观点

  1. Anthropic Skills 提供模块化、可复用的任务组件，显著扩展 Claude 的能力。 开发者可创建独立、自洽的功能，如数据检索、邮件撰写，通过 API 动态调用，提高 Claude 在特定业务场景下的实用性。
  2. Skills 设计强调开发者中心、透明化和细粒度控制，满足企业合规性需求。 通过 schema 定义和 Code Execution Tool 保障数据访问和操作权限，与 Anthropic 对模型安全性和可解释性的理念高度一致，对企业用户吸引力强。
  3. Anthropic Skills 在方法论上与 OpenAI GPTs 和微软 Copilot Studio 形成差异。 Skills 侧重于代码和 schema 定义，强调模块化、可维护性和治理，而非用户创建的迷你应用或可视化连接，为开发者提供了更严谨的扩展范式。

💬 文章金句

  • 每一个 Skill 都是一项独立、自洽的功能，Claude 可以在对话过程中调用，例如总结长篇文档、从 API 检索数据，或执行特定领域的计算等。
  • 这种架构与 OpenAI 的 GPT 模型和微软 Copilot 生态系统中已采用的 function calling（函数调用）范式相似，但 Anthropic 更强调透明化和可审计性，这与其专注于模型安全性和可解释性的理念相一致。
  • Anthropic 的 Skills 采取了更以开发者为中心的方法，优先强调模块化、可维护性和治理。这与 OpenAI 的 GPTs 不同，后者允许用户创建并分享带有自定义指令和工具的迷你智能体。
  • Claude 实现了从智能到专业的飞跃。自动化领域的未来，在于个性化、持续演进和高度自由。
