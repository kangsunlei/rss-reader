Agent 的能力还不足维护代码库！HumanLayer 创始人质疑“无人值守”的软件工厂

11/2/2026, 9:30:00 AM

📌 一句话摘要

HumanLayer 创始人德克斯·霍西指出，AI Agent 虽能快速生成代码，但在长期维护代码库时缺乏持续质量控制能力，警示「关灯运行的软件工厂」不可取，主张通过规划、会话记录和人机协作维持代码质量。

📝 详细摘要

本文基于 HumanLayer 创始人德克斯·霍西的演讲，探讨了 AI Agent 在软件开发全流程中的局限性。演讲指出，AI Agent 能将代码编写从数天缩短至数小时，但审查环节仍需人工介入。作者提出「关灯运行的软件工厂」概念，警示完全依赖 AI 自动化会导致代码质量难以持续维护。通过引用 SlopCodeBench 分阶段评测，展示 Agent 在连续修改中难以保持架构一致性。作者建议：针对影响面大的任务，先与 Agent 讨论方案再实现；让 Agent 能直接运行软件验证功能；将用户反馈和告警纳入开发流程；保留 Agent 会话记录以积累团队经验。

💡 主要观点

  1. AI Agent 加速代码编写，但审查环节仍是瓶颈，「关灯运行的软件工厂」不可取 演讲指出，AI Agent 能将编写和测试环节从数天缩短至数小时，但人工审查仍需数小时甚至数天。完全依赖 AI 自动化会导致代码在后续维护中难以维持质量。
  2. 测试通过不等于代码可维护，架构问题代价在后期才显现 现有测试只能验证当前功能是否符合预期，无法预判后续需求变更是否会带来维护成本。糟糕架构的代价往往在数月后才显现，此时问题的处理者可能不是最初合并 PR 的人。
  3. SlopCodeBench 评测显示，Agent 在连续修改中难以保持代码可维护性 基准测试包含 36 道任务、196 个阶段检查点，结果显示没有 Agent 能完整完成所有任务，最佳 Agent 仅通过 14.8%的严格检查点，说明 AI 在长期迭代中难以保持架构一致性。
  4. 提出「先规划后实现」的协作模式，减少审查和返工成本 对于影响面大的任务，建议先花 20-30 分钟与 Agent 讨论改法，明确模块划分和修改顺序，从而在审查阶段减少争议，避免后期返工。
  5. Agent 应看到软件实际运行效果，纳入用户反馈和告警 除了代码审查，作者主张让 Agent 能直接运行软件、调用接口、观察用户操作效果；同时将用户提交的问题、线上报警和功能开关纳入开发流程，帮助 Agent 快速形成候选修复方案。

💬 文章金句

  • 如果完全放手不管，模型不会在一次次改动中自动维持代码库的质量。
  • 你可以让它改进架构，但首先得有人知道代码库哪里出了问题，再把问题讲给它听。这已经不是'无人值守'了。
  • 糟糕架构的成本，是按月、按年计算的。今天没有一个测试，能立刻告询你这份代码将来是否容易维护。
  • 先花 20 到 30 分钟规划，可能省掉审查时的几小时。
  • 给 Agent 浏览器和运行中的应用，让它自己操作、截图、调用接口。不要只让它在终端里看见'测试通过'。
