如何优化 React 图形界面代码库：优化 d3-zoom 和 dnd-kit 代码

10/16/2025, 12:40:20 PM

📌 一句话摘要

本文深入探讨了如何通过高级 React 性能优化，提升使用 d3-zoom 和 dnd-kit 构建的图形化应用性能。这些优化措施能够显著改善大量交互元素的处理效率。

📝 详细摘要

本文旨在解决 React 图形应用（如 Miro 或 Figma）中存在的性能瓶颈，这些应用通常依赖 D3 Zoom 实现平移/缩放，以及 dnd-kit 实现拖拽功能。文章指出，诸如 `useCallback` 和 `memo` 等常见的 React 优化手段往往效果不佳，因为浏览器布局和渲染时间占据了主导。作者建议使用 JavaScript 性能 API 进行精确测量。关键优化包括调整用于画布缩放的 CSS 转换，以避免在平移/缩放过程中子元素的重复渲染。在拖拽方面，文章介绍了一种精妙的组件重构方案：使用经过 memo 优化的 `AllCards` 组件，其中包含 `NonDraggable` 元素，并动态地在顶部渲染一个激活状态的 `Draggable` 组件和一个 `Cover` 组件。此方法能够显著减少重复渲染和 `memo` 的开销，使得拖拽启动速度提升高达 20 倍，即使处理 100，000 张卡片，也能在拖拽完成时获得显著的性能提升。但与此同时，代码复杂度也会相应增加。文章末尾提供了一个详细的性能对比表格。

💡 主要观点

  1. JavaScript 性能 API 对于图形化 React 应用的性能测量至关重要。 传统的 React 性能分析工具通常会忽略重要的浏览器布局和渲染时间，而这在高度可视化的应用中至关重要。因此，JavaScript 性能 API 对于以用户为中心的性能指标测量更为准确。
  2. 使用 CSS 转换优化画布的平移/缩放，可以减少子组件的重复渲染。 通过将 `translateX/Y/scale` 应用于画布，子元素能够自动跟随画布进行缩放，从而避免了单独的重新渲染，提升了性能，尤其是在元素数量庞大的情况下。
  3. 通过巧妙的组件重构，可以显著提升大量元素的拖拽性能。 使用经过 memo 优化的 `AllCards` 组件（包含 `NonDraggable` 元素），并在顶部动态渲染一个激活状态的 `Draggable` 组件，能够最大限度地减少 `memo` 开销和重复渲染，从而显著提升拖拽速度。

💬 文章金句

  • 类似 `useCallback` 和 `memo` 的标准优化，在拖动操作中使速度提升约两倍，但对平移和缩放没有明显效果。
  • 在这种情况下，浏览器布局和渲染所消耗的时间非常显著，而 React 性能分析工具未能将其纳入考量。
  • 我将其修改为使用 `translateX(x) translateY(y) scale(k)`，效果相同，但会缩放子元素。
  • 在少量卡片的情况下，速度大致相同；但在大量卡片的情况下，速度大约快了二十倍。
  • 但这样做的代价是代码复杂度显著增加，使得代码更难理解和修改，特别是对于新手而言。
