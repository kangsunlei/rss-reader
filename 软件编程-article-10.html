黑客利用 LiteLLM 管理 API 漏洞，窃取机密并攻击 AI 网关服务器

9/3/2026, 10:00:00 AM

📌 一句话摘要

攻击者利用 LiteLLM 管理 API 未授权漏洞（CVE-2026-35029）提权，通过篡改配置实现任意文件读取，窃取 API 密钥和云凭证，Zenity 蜜罐数据显示 2026 年 4 月起攻击活动持续活跃。

📝 详细摘要

文章报道了攻击者积极利用 LiteLLM AI 网关中的一个已授权漏洞 CVE-2026-35029 进行攻击。该漏洞存在于 1.83.0 版本之前，允许已认证的低权限用户访问敏感的/config/update 端点，从而修改环境变量和配置值。攻击手法包括将 UI_LOGO_PATH 替换为敏感文件路径（如/app/.env），通过/get_image 端点读取文件内容，暴露模型提供商 API 密钥、数据库 URL、AWS 凭证等机密信息；还可覆盖 UI_USERNAME 和 UI_PASSWORD 接管管理界面，或通过注册恶意透传端点处理器实现远程代码执行。Zenity 蜜罐数据显示 2026 年 2 月至 6 月期间约 3，900 次针对管理 API 的请求中约 1，000 次针对/config/update，首次探测出现在漏洞披露次日。文章提供了详细的防护建议，包括升级至 1.83.0、移除公网暴露、轮换所有可能泄露的机密信息等。

💡 主要观点

  1. 漏洞机制：低权限账户可篡改 AI 网关核心配置 CVE-2026-35029 源于/config/update API 路由缺少授权检查，受影响的 proxy_admin_viewer 等只读角色即可修改仅限管理员的设置，包括环境变量和 UI 凭证。
  2. 攻击手法：通过配置篡改实现任意文件读取和凭证接管 攻击者将 UI_LOGO_PATH 替换为敏感文件路径（如/app/.env、/proc/self/environ），利用无需认证的/get_image 端点读取文件内容；同时可通过覆盖 UI_USERNAME/UI_PASSWORD 接管仪表盘，或注册恶意透传端点处理器创造 RCE 通道。
  3. 实际攻击活动：漏洞披露次日即出现系统性探测 Zenity 蜜罐数据显示 2026 年 2 月至 6 月约 3，900 次管理 API 请求中约 1，000 次针对/config/update，首次配置更新探测出现在 4 月 7 日（CVE 公开次日）。攻击行为包括猜测主密钥、生成 API 密钥、创建管理员账户、枚举用户和密钥、探测 SCIM 路由及删除模型，表明威胁行为者在系统测绘并试图取得控制权。
  4. 防护建议：升级、网络隔离与密钥轮换 组织应立即升级至 1.83.0 或更高版本（添加了缺失的授权校验），将管理界面置于反向代理或内部网络之后，使用高强度唯一主密钥，审查可疑请求日志，并对曾暴露的组织轮换所有可能泄露的机密信息。

💬 文章金句

  • 攻击者正在积极探测 LiteLLM AI 网关部署中一个已知的授权漏洞，该漏洞可将低权限账户提升为完全管理控制权。
  • 攻击者将正常图片路径替换为敏感的服务器端文件路径（如/app/.env 或/proc/self/environ），即可诱使 LiteLLM 读取该文件。
  • 该漏洞还可用于覆盖 UI_USERNAME 和 UI_PASSWORD 环境变量，使攻击者能够替换仪表盘凭证并接管管理界面。
  • 首次配置更新探测出现在 4 月 7 日，即 CVE-2026-35029 公开披露的次日。
