又一次 Rust 重写：OpenAI 的 Codex CLI 转向原生，放弃 Node 和 TypeScript，转投 Rust

6/4/2025, 12:00:00 AM

📌 一句话摘要

OpenAI 正在用 Rust 重写其 Codex CLI，以获得更好的性能、安全性以及依赖管理。

📝 详细摘要

OpenAI 正在将其 Codex CLI 从最初的 Node.js/TypeScript 实现转向 Rust。Codex CLI 是一个基于云的软件工程代理，能够执行编写功能、回答代码问题和修复 bug 等任务。此次重写的动机是希望实现零依赖安装、改进原生安全绑定、Rust 无运行时垃圾回收，性能得到优化，以及开发一个支持多语言的可扩展通信协议。Rust 在性能、内存安全和可靠性方面的优势被认为是关键优势，尽管学习曲线也得到了承认。Rust 版本正在与现有的 TypeScript 版本并行积极开发。此举反映了采用 Rust 来开发需要高性能和可靠性的开发工具的更广泛行业趋势。开发者可以通过 npm 访问原生版本。

💡 主要观点

  1. Codex CLI 正在用 Rust 重写。 OpenAI 正在将其用于 Codex 代理的命令行界面工具从 Node.js 和 TypeScript 移植到 Rust 编程语言。
  2. 重写目标是零依赖安装和更好的性能。 主要目标包括移除 Node.js 的依赖，并通过 Rust 的内存效率和原生执行实现性能提升。
  3. 原生安全绑定增强了工具的可靠性。 利用 Rust 可以实现原生的系统安全特性和内存安全，从而在编译时减少漏洞类型。
  4. 新版本将具有一个可扩展的协议。 正在开发一个接口协议，以便使用 Rust 以外的语言（如 Python 和 JavaScript）来扩展 Codex CLI 的功能。

💬 文章金句

  • 我们的目标是让软件组件尽可能高效，并且有一些我们希望改进的领域
  • 零依赖安装 --- 目前需要 Node v22+，这对一些用户来说令人沮丧或是一个障碍
  • 原生安全绑定 --- 惊喜！由于绑定是可用的，我们已经为 Linux 发布了一个 Rust 沙盒实现
  • 优化性能 --- 没有运行时垃圾回收，从而实现更低的内存消耗
  • 可扩展的通信协议 --- 我们一直在为 Codex CLI 开发一个“通信协议”，以便开发者能够使用不同的语言（包括 TypeScript/JavaScript、Python 等）扩展该代理
