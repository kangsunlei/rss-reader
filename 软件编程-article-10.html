全世界只有 5000 人见过的 AI 群控，会把软件公司的差距拉到一百倍

10/22/2026, 8:57:00 AM

📌 一句话摘要

本文通过将 AI 写代码的演进与汽车工业百年历史类比，提出「AI 群控」概念——成千上万个 agent 共用一条代码主线、即时提交即时检验，并用自建实验证明群控相比传统组织方式可提速数倍，指出软件公司未来的竞争壁垒在于模型之外的工业化产能体系。

📝 详细摘要

本文从 Karpathy 提出的 AI 认知分层切入，指出全球仅有约 5000 人能接触到前沿实验室内部成千上万个 agent 连续数周协作的「群控」系统。作者将 AI 写代码的历史划分为四个时代——人工、人工加 AI 助手、AI 自动化、AI 群控——并与汽车工业从手工打造到黑灯工厂的四步演进平行类比，揭示每个阶段瓶颈从人身上转移到协同机制上的规律。文章剖析了当前三种主流多 agent 组织方式的致命缺陷：单 agent 全包随上下文膨胀而减速；共享文件加锁时 agent 拿锁思考需数秒至数十秒，导致严重排队；分支后合并则使接口变更直到合并时才暴露，修复成本高昂。作者提出群控的核心是所有 agent 共用一条主线、做完立刻提交、提交立刻检验、出错后相关 agent 当场修复。为验证这一判断，作者自建实验用 60 个真实编程任务对比四种组织方式，结果显示 5 个 agent 群控仅需 3 分 23 秒，加锁方式需 6 分 24 秒，单 agent 需 8 分 52 秒，且群控在接口变更场景下能实现测试当场报错、相关 agent 半分钟内自修。基于实验与行业观察，作者提出五项前瞻判断：软件产品将趋同、软件从手艺生意变成重资产产能生意、工厂与作坊的速度差可达十几倍至上百倍、未来最值钱的工程师是能指挥大量 agent 的人、时间是唯一护城河。文末开源了用 Rust 编写的 agent 群控协同层 Trellis 及完整实验记录。

💡 主要观点

  1. AI 写代码的四个时代与汽车工业的四步演进高度平行，瓶颈随阶段转移 从人工手敲到 AI 助手，再到单 agent 自动化，最终走向成千上万个 agent 的群控——每个阶段的瓶颈从人的手速和精力，转移到单个 agent 的上下文长度，最终变成几千个 agent 之间的协同分工。这与汽车工业从手工打造、移动装配线、单台机器人到黑灯工厂的演进路径完全一致，软件行业正在三年内重走汽车工业一百年的路。
  2. 当前三种主流多 agent 组织方式各有致命缺陷，无法支撑规模化群控 单 agent 全包在任务增多时上下文膨胀导致速度越来越慢；共享文件加锁时 agent 拿锁后需数轮模型调用（数秒至数十秒），远慢于程序锁的微秒级占用，导致严重排队；各开分支最后合并则使中途接口变更对其他 agent 不可见，直到合并时才暴露冲突，如同手工时代总装时才发现零件对不上。
  3. agent 群控的核心机制是共用主线、即时提交、即时检验、问题当场修复 所有 agent 工作在同一条主线上，做完一块立刻推上去并自动合并（仅毫秒级原子操作），提交后立刻跑测试，失败时自动生成修复任务由空闲 agent 领走，相关 agent 当场收到通知自行修复而其他人不停工。Anthropic 新控制系统的设计原则「提交必须便宜、增量、无锁」正朝此方向演进。
  4. 自建对照实验证实群控在规模化场景下优势显著，锁的代价几乎使时间翻倍 在 60 个真实编程任务的实验中，5 个 agent 群控用时 3 分 23 秒，各开分支最后合并用时 3 分 52 秒（其中 47 秒花在解决冲突），加锁方式用时 6 分 24 秒，单 agent 用时 8 分 52 秒。锁的代价在于相邻提交最短间隔达 6 秒以上（即一个 agent 拿着锁在思考）；分支的盲区在于接口变更后各分支测试全绿但合并后三轮全部测出问题。
  5. 下半场竞争比的是模型之外的工业化产能，且注定是重资产 模型会越来越强且普及，算力和 token 花钱就能买，真正拉开差距的是三样东西：每个 agent 干活用的机器（编译、测试、CI 沙箱）、让大量 agent 协同的调度系统、以及一套共享工作记录与可调用接口的生产体系。Anthropic 七人团队五个月内重写了版本控制、代码评审、权限系统等整套基础设施，正是在为自己的 agent 建工厂。

💬 文章金句

  • 成千上万个 agent 组成一个群体，连续几周协作，完成超大型的软件项目。
  • 第四个时代需要的组织方式，更像工厂的调度系统。我管它叫 agent 群控。
  • 瓶颈在'为人类规模设计的整套开发基础设施：版本控制、构建和 CI'。
  • 真正拉开差距的，是模型之外的那套生产体系------而且注定是重资产。
  • 时间是唯一的护城河。
