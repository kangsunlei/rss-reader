Cloudflare 正式发布 Python Workers，但关于冷启动和上游维护的问题仍待解答

10/24/2026, 2:00:00 AM

📌 一句话摘要

Cloudflare 推出 Python Workers，基于 Pyodide 和 PEP 783，实现了与 Workers AI 等服务的绑定，但因冷启动时间长和对上游维护的依赖，社区反应两极分化。

📝 详细摘要

Cloudflare 的 Python Workers 现已正式发布，支持 FastAPI、Django 和 Flask，并与 Workers AI、R2、D1 等服务绑定。该功能基于 Pyodide，并依赖于 PEP 783 标准化 WebAssembly 编译。尽管实现了套接字桥接和 HTTP 客户端优化，但冷启动时间（约 900ms）和对上游维护的依赖（如 urllib3 的 CVE-2025-50182）引发了社区争议。Cloudflare 承诺通过内存快照和分片技术改善性能，并积极参与 Pyodide 的开发。

💡 主要观点

  1. 正式发布与工程成果 Python Workers 现已正式发布，支持多种 Web 框架和 Cloudflare 服务。其实现基于 Pyodide，并依赖于 PEP 783 标准化交叉编译，以及对套接字和 HTTP 客户端的底层优化。
  2. 社区争议与技术挑战 尽管功能丰富，但社区对冷启动时间（约 900ms）和对上游维护的依赖表示担忧。例如，urllib3 的 CVE-2025-50182 凸显了在 WebAssembly 环境中重定向控制的差异，而 Wasmer 的基准测试也揭示了启动性能的差距。
  3. 未来展望与改进计划 Cloudflare 计划通过内存快照和分片技术来减少冷启动时间，并继续参与 Pyodide 的开发以提升兼容性。然而，关于如何平衡对上游的依赖与自身性能优化的策略，仍是未来发展的关键问题。

💬 文章金句

  • 资助项目的上游贡献与资助上游维护者之间存在着本质性的区别。
  • 以他们目前的架构，要实现 <100ms 的启动时间将相当困难。
  • 我们的内存快照实现已经显著改善了冷启动性能。
