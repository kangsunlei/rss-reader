Cloud Use：当 Agent 开始真正使用云

7/9/2026, 10:08:00 AM

📌 一句话摘要

本文提出 Cloud Use 概阐述 Agent 如何以受治理的身份、凭证、环境和生命周期真正成为云上的可托管工作负载，区别于普通 Tool Use。

📝 详细摘要

文章深入探讨了 Cloud Use 与传统 Tool Use 的区别，指出 Agent 若要成为云上的真实工作负载，必须具备身份识别、受控凭证、治理工具调用和云端运行时四层能力。通过 Vault、Skill、任务合约、云端 Session、结果回传等机制，实现凭证不可见、路径可复用、边界明确、任务可托管。接着从周期性任务、诊断任务和执行任务三类场景说明 Cloud Use 的价值，强调任务脱离人在线状态并具备审计与故障恢复能力。随后分析失败可控的关键点：错误路径、基础设施异常、结果回传异常和验收过松都需在治理边界内处理，避免越权。最后提出从低风险高频任务起步，逐步引入确认机制，是 Agent 进入生产的可行路径。全文结构清晰、案例丰富、兼具理论深度与工程实践，为设计可托管的 AI Agent 提供了完整框架。

💡 主要观点

  1. Cloud Use 的核心是让 Agent 成为受治理的云上执行体，需要身份、凭证、工具和运行时四层能力。 文章通过 Identity Use、Credential Use、Tool/API Use 和 Runtime Use 四层依赖链，说明 Agent 只有在这四方面都具备治理特性时，才能被云平台识别、授权、托管和审计。
  2. 通过 Vault、Skill、任务合约、云端 Session 和结果回传等机制，实现凭证不可见、路径可复用、边界明确、任务可托管。 凭证进入 Vault 后仅以引用形式使用；Skill 沉淀验证过的执行路径；任务合约明确工具使用、输出格式和异常处理；云端 Session 使任务脱离人在线状态；结果回传依赖事件触发和签名验证，确保业务系统获得完整可靠的产出。
  3. Cloud Use 的价值体现在周期性任务、诊断任务和执行任务三类场景中，使任务脱离人在线状态并具备审计与故障恢复能力。 周期性任务可自行触发并完成全链路分析；诊断任务让 Agent 主动进入云上现场取证；执行任务则在低风险自动化、高风险人工确认之间划清边界，全程可审计且失败可恢复。
  4. 失败可控是 Cloud Use 的关键：错误路径、基础设施异常、结果回传异常和验收过松都需在治理边界内处理，避免越权。 文章指出 Agent 会因推理走向看似合理但实际不可用的 API，需在 Skill 中沉淀正确与错误路径；资源组冻结等异常应在预授权边界内自救或停止；结果回传须在线程 idle 后拉取并验证；验收标准必须可执行可检查，防止 Agent 只生成形式报告而未回答实际业务问题。
  5. 从低风险高频任务起步，逐步引入确认机制，是 Agent 进入生产的可行路径。 建议先从周期性巡检、成本异常分析、CI 失败诊断等低风险、结果易验证的任务开始，待这些任务稳定后再逐步引入带确认的执行动作（如人工审批后触发流水线），最终在高风险节点保持人工介入，实现可托付的云上执行。

💬 文章金句

  • Cloud Use 解决的是‘云如何接纳 Agent 成为受治理的使用主体’。
  • 仅有 Tool Use 的 Agent 解决的是‘模型如何调用工具’；Cloud Use 解决的是‘云如何接纳 Agent 成为受治理的使用主体’。
  • 真正可托付的 Agent，不是自己宣布任务完成，而是它的完成状态可以被事件、日志、产物和验收标准共同证明。
  • Cloud Use 的价值不是让 Agent 多调用几个云 API，而是让 Agent 成为云平台可以识别、授权、托管和审计的执行主体。
