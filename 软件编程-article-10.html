一个任务 50 次调用，成本狂砍 90%？Manus 首次公开上下文工程秘诀，一堆反复重写换来的教训

📌 一句话摘要

Manus 团队首次公开其 AI Agent 上下文工程秘诀，通过优化 KV 缓存、工具管理、外部记忆等策略，将任务调用成本狂砍 90%，并分享了大量实践教训。

📝 详细摘要

文章深入剖析了 Manus 项目在构建 AI Agent 时，如何通过“上下文工程”解决实际挑战并显著提升效率和降低成本。作者从早期创业的经验教训出发，强调了上下文工程在快速迭代产品中的重要性。文章详细介绍了六个核心实践：围绕 KV 缓存设计以降低延迟和成本；通过“掩码而非移除”来管理工具集以保持缓存稳定和模型行为一致；将文件系统作为 Agent 的外部化、持久化记忆以克服上下文窗口限制；通过“背诵”关键信息来操纵模型注意力以避免任务跑偏；保留错误的回合让 Agent 从失败中学习；以及通过引入多样性来避免少样本提示导致的过度模仿。这些实践都基于 Manus 团队在数百万用户真实世界测试中获得的宝贵经验，为 AI Agent 开发者提供了实用且可操作的指导。

💡 主要观点

  1. KV 缓存命中率是生产阶段 AI Agent 最重要的指标，直接影响延迟和成本。 通过保持提示前缀稳定、上下文只追加内容、序列化确定性以及明确标记缓存断点等方式，可大幅提升 KV 缓存命中率，显著降低推理成本和 TTFT。
  2. 通过“掩码”而非“移除”工具来管理 Agent 动作空间，保持上下文稳定。 避免动态增减工具，而是利用响应预填充和 token 对数屏蔽来限制动作选择，防止 KV 缓存失效和模型困惑，确保 Agent 行为稳定。
  3. 将文件系统作为 Agent 的“最终上下文”，实现无限大小的外部化记忆。 Agent 学习按需读写文件，将长期状态外部化，有效解决了上下文长度限制和高成本问题，并支持可恢复的压缩策略。
  4. 通过“背诵”关键目标来操纵模型注意力，避免 Agent 偏离主题。 Agent 通过不断重写待办事项列表等方式，将全局计划推入近期注意力范围，减少“迷失在半道”和目标错位的问题。
  5. 在上下文中保留错误的回合，让 Agent 从失败中学习并改进行为。 模型通过观察失败的动作及其产生的错误信息，能够隐式更新内部信念，避免重复相同错误，提高错误恢复能力。
  6. 引入多样性，避免少样本提示导致的 Agent 过度模仿和脆弱性。 通过在动作和观察中引入少量结构化变化，打破模型模仿上下文行为模式的倾向，增强 Agent 的鲁棒性。

💬 文章金句

  • Manus 将押注于上下文工程。这使我们能够在几小时内而不是几周内发布改进，并且使我们的产品与底层模型保持正交：如果模型进步是潮水上涨，我们希望 Manus 是船，而不是粘在海底的柱子。
  • 如果我只能选择一个指标，我会争辩说 KV 缓存命中率是生产阶段 AI Agent 最重要的单一指标。它直接影响延迟和成本。
  • 这就是为什么我们在 Manus 中将文件系统视为最终的上下文：大小无限，本质上持久，并且可以直接由 Agent 本身操作。模型学会按需写入和读取文件------不仅将文件系统用作存储，而且作为结构化的、外部化的记忆。
  • 通过不断地重写待办事项列表，Manus 将其目标背诵到上下文的末尾。这会将全局计划推入模型的近期注意力范围，避免了“迷失在半道”的问题，并减少了目标错位。
  • 在我们的经验中，改进 Agent 行为最有效的一种方法出奇地简单：在上下文中保留错误的回合。当模型看到一个失败的动作------以及由此产生的观察或堆栈跟踪------它隐式地更新其内部信念。
