Agent Bucket：万亿级 Agent 原生存储桶

2/14/2026, 3:04:00 AM

📌 一句话摘要

字节跳动提出 Agent Bucket 存储范式，通过引入原生 ObjectSet 层级，解决 AI Agent 在海量多租户场景下的隔离、计费与扩展性难题。

📝 详细摘要

文章深入探讨了 AI Agent 在从原型向生产级应用迈进过程中面临的存储挑战。传统对象存储（如 S3/TOS）在处理海量多租户时，面临桶配额限制、前缀隔离导致的性能“扰邻”及计费复杂等问题。为此，字节跳动技术团队提出了 Agent Bucket 方案，核心创新是在桶与对象间引入“ObjectSet”原生层级。该设计支持亿级租户，提供原生的性能隔离、细粒度权限、精准计量计费及容量上限管理。同时，通过 Set Tagging、Set Slice 和 Set AccessPoint 等技术，解决了海量用户分级、万亿级数据物理扩展及接入点安全隔离等底层架构难题，为 Agent 开发者提供了一套 Serverless 化的 AI 原生存储基础设施。

💡 主要观点

  1. 传统对象存储的“单桶多前缀”方案难以支撑海量 Agent 租户需求。 在扁平的对象存储上通过硬编码前缀模拟多租户，会导致权限管控复杂、计费困难及严重的“扰邻效应”，无法满足生产级 Agent 应用对性能隔离和精细化管理的要求。
  2. 引入 ObjectSet 原生层级，为每个终端用户提供专属的逻辑存储空间。 ObjectSet 在桶和对象间建立新层级，使存储系统能原生感知租户，从而实现针对单个用户的 QPS 限制、带宽配额、独立域名及自动化计量计费，极大降低了开发者的系统复杂度。
  3. Set Slice 技术通过“逻辑不拆、物理拆分”解决万亿级数据扩展瓶颈。 将元数据根据范围划分为多个物理切片（Slice）并分布于不同集群，在保持逻辑统一的前提下，实现了单 Set 的线性扩展和跨 Set 的物理资源隔离，支撑起千亿甚至万亿级的对象规模。
  4. Set AccessPoint 结合“两把锁”模式，构建了极高熵的安全防护体系。 通过为每个 ObjectSet 分配独立的高熵散列域名，结合 STS 临时访问凭证，从网络隐匿性和权限收敛性两个维度确保了海量用户数据的访问安全，防止了凭证泄露后的风险扩散。

💬 文章金句

  • Agent Bucket 旨在通过 AI 原生的存储设计，彻底简化多租户系统的构建流程，提供更友好的 Agent 能力。
  • 我们实际上是在用一种“静态的 KV 存储”，去承载一个“目录语义、强隔离的” Agent 应用的文件访问方式。
  • 这个设计的核心思想极其简洁：为你的每一个终端用户，都匹配一个专属的 ObjectSet。
  • Set Slice 提供了一种“逻辑不拆、物理拆分”的思路：从逻辑上看，你仍然只管理一个 Agent Bucket；在物理上，将元数据划分成多个 Slice。
