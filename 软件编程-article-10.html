如何高效的长时间运行智能体

2/3/2026, 8:14:00 AM

📌 一句话摘要

本文介绍了 Anthropic 针对长时间运行智能体提出的双层架构方案，通过模拟人类工程师的协作模式解决跨上下文窗口的衔接难题。

📝 详细摘要

文章深入探讨了 AI 智能体在处理需持续数小时或数天的复杂任务时，因上下文窗口限制而导致的“遗忘”和失控问题。作者借鉴软件工程师的轮班协作经验，提出了由“初始化智能体”和“编码智能体”构成的双层方案。初始化智能体负责搭建环境、制定细粒度 JSON 功能清单；编码智能体则在后续会话中进行增量开发，并通过 Git 提交历史和进度文件实现状态同步。该方法强调了结构化数据、小步快跑的增量交付以及端到端测试在提升智能体长周期任务稳定性中的核心作用。

💡 主要观点

  1. 智能体在长周期任务中常因上下文耗尽导致“一次性做太多”或“过早宣布完成”的失败模式。 由于模型在离散会话中缺乏持久化记忆，容易在复杂项目中迷失方向。通过限制单次会话的交付范围，并要求智能体在结束前整理出“干净状态”，可以有效避免半成品堆积。
  2. 采用“初始化+编码”的双层智能体架构，通过明确的分工实现跨会话的稳定衔接。 初始化智能体仅运行一次，负责建立 init.sh 和功能清单等基础设施；编码智能体则在后续每一轮会话中读取这些状态，确保新会话能像接力赛一样无缝继续工作。
  3. 利用结构化的 JSON 功能列表和 Git 提交历史作为智能体协作的“交接棒”。 相比 Markdown，JSON 格式更能约束模型不随意篡改任务结构。结合 Git 的版本回溯能力，智能体可以清晰地了解前序工作的进展，并在发现环境异常时优先进行修复而非盲目堆砌代码。
  4. 引入浏览器自动化工具（如 Puppeteer）进行端到端测试，以验证智能体工作的真实有效性。 智能体往往会高估代码的正确性，仅靠单元测试不足以发现 UI 层的逻辑漏洞。强制要求智能体使用自动化工具模拟真实用户操作，能显著提升其在 Web 全栈开发中的交付质量。

💬 文章金句

  • 长时间运行智能体的核心问题在于：它们只能在离散的会话中工作，而每一次新会话开始时，几乎'忘记'了之前发生的一切。
  • 让每一次会话都只做'可交付的增量开发'，并在结束时把环境整理到一个'干净状态'。
  • 我们发现 JSON 比 Markdown 更安全：模型更不容易'修改'结构化数据。
  • 如果项目运行有问题，智能体会优先修复问题，而不是继续堆新功能，以避免问题更加严重。
  • 智能体在没有真正验证的情况下，就把功能标记为完成。使用 Puppeteer MCP 后，Claude 能发现很多'代码看不出来'的问题。
