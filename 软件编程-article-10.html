容器部署虽易，遗留系统迁离虚拟机则难

12/26/2025, 8:40:00 AM

📌 一句话摘要

本播客探讨了遗留虚拟机与现代 Kubernetes 环境的集成，强调了共存策略、在虚拟机上运行 Kubernetes 的优势，以及人工智能在遗留系统现代化中的未来作用。

📝 详细摘要

这篇来自 Stack Overflow 播客的文章，邀请到 Nutanix 云原生副总裁兼总经理 Dan Ciruli，他讨论了将基于遗留虚拟机的系统与现代容器化（Kubernetes）环境集成的挑战和策略。Ciruli 强调，尽管容器能加快软件交付和创新，但现有虚拟机并不会很快消失，因此需要可靠的共存策略。他解释了为什么在虚拟机内运行 Kubernetes 通常能解决网络和孤岛问题，从而实现一个通用的基础设施基础。讨论深入探讨了虚拟机与 Kubernetes 集群之间互通的复杂性，特别是 Kubernetes 中 IP 地址的瞬时性问题。他还提到了部分云原生公司出于经济原因将工作负载迁回本地部署的趋势，并指出了云平台擅长的用例（例如，高度可变的工作负载、BigQuery 等独特服务）。对话最后讨论了使用大型语言模型（LLM）来现代化诸如 COBOL 或 Pascal 等遗留代码库，以此作为大型机退役的潜在解决方案。

💡 主要观点

  1. 容器通过允许更频繁地推动代码，实现了更快的软件交付和创新。 采用容器的核心好处在于提高了软件部署的频率和速度，从而带来更快的创新周期，Google 等早期采用者便是例证。
  2. 由于重新架构现有应用程序的高成本和低商业价值，遗留虚拟机将继续存在。 仅仅为了容器化而重写有数十年历史的应用程序，不仅商业价值甚微，还需耗费巨大精力。因此，在可预见的未来，虚拟机仍将与新的容器化工作负载共同存在于企业数据中心。
  3. 在虚拟机中运行 Kubernetes 可以有效解决常见的网络和基础设施孤岛问题。 利用现有的虚拟机基础设施和网络策略进行 Kubernetes 部署，简化了遗留虚拟机应用程序与新的容器化应用程序之间的通信，克服了如 Kubernetes IP 地址瞬时性和不同网络堆栈等复杂性。
  4. 由于经济和性能方面的考量，越来越多的组织正将云工作负载迁回本地部署。 在云端多年后，一些公司，包括云原生公司，发现对于稳定、高容量的工作负载，拥有本地部署的基础设施可能比持续租赁更具成本效益，特别是对于可预测的基线流量。
  5. 大型语言模型（LLM）在现代化诸如 COBOL 或 Pascal 等遗留代码库方面显示出潜力，可能自动化大量的重构工作。 利用 AI 翻译和生成现代化遗留代码，特别是首先从原始代码创建全面的测试套件，被认为是大型语言模型（LLM）在帮助大型机退役方面一个有价值的潜在应用。

💬 文章金句

  • 从根本上讲，你想采用容器的原因是，将代码推送到容器的开发者最终能更频繁地推送代码。
  • 事实是，迁移到容器——为容器编写代码本身并不十分困难，但当你有一个已经在运行的应用程序时，要对其进行修改以适应在容器中运行，那可能会相当困难。
  • 对于大多数公司来说，在虚拟机中运行 Kubernetes 确实解决了许多问题。因为，当实体（如 Kubernetes）置于虚拟机内时，即使其中有内容在运行，该 Kubernetes 实例本身也是运行在虚拟机中的，因此可以利用现有的虚拟机网络策略。
  • 我确实看到有组织将内容从云端移回本地部署。这是一个有争议的问题，因为我也听过分析师说，“不，没有这样的趋势”。但这绝对是真的。
  • 我认为这方面我们可能会取得一些成功……使用原始代码生成一套测试用例，对吗？这样，你就能有效地验证结果，然后付诸实施。
