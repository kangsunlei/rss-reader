每个工程师都要知道的 29 个 LLM 核心评估概念

8/1/2026, 12:00:00 AM

📌 一句话摘要

本文系统梳理了 LLM 评估的核心概念、方法论与分层体系，为应用开发工程师提供了一套从零搭建评估框架的完整指南。

📝 详细摘要

文章指出，传统软件测试方法因 LLM 的非确定性、模糊正确性和静默回归问题而失效，因此需要一套全新的评估体系。文章首先定义了评估标准、质量维度、评分细则、测试用例、黄金测试集、合格阈值和评估覆盖率等核心原语。接着，详细介绍了五种打分方式：人工评估、启发式评估、语义相似度评估、任务特定指标（BLEU/ROUGE）和 LLM 评审，并强调了评审模型校准的重要性。针对 RAG 系统，文章解析了忠实度、答案相关性、上下文精准度这三元组及其特有的失效模式。最后，文章提出了离线与在线评估结合、提示词版本管理，以及从启发式规则到人工校验的五层评估分层体系，并给出了一个极简的 MVP 搭建方案，强调评估是快速迭代的基础而非收尾工作。

💡 主要观点

  1. LLM 的非确定性、模糊正确性和静默回归问题，使得传统软件测试方法失效，必须建立独立的评估体系。 温度参数导致输出随机，质量评判标准主观多维，且缺乏 CI 机制来发现提示词调整引入的回归问题，这三大挑战是评估体系建立的必要性前提。
  2. 黄金测试集是评估的基准真值，必须基于真实用户查询构建，并持续迭代以覆盖长尾场景。 自行编写的用例只能反映预设认知，无法覆盖用户真实、多样甚至误用的场景。评估覆盖率偏低会导致测试结果过于乐观，无法反映真实生产环境的表现。
  3. LLM 评审是实现评估规模化的关键，但必须通过校准来确保其与人工判断的一致性。 使用 GPT-5、Claude Opus 等强模型依据评分细则进行自动化评审，可以处理数千条输出。但评审模型存在偏见，必须通过人工与模型打分的一致性校验（校准）才能可靠使用。
  4. RAG 系统的评估需关注忠实度、答案相关性和上下文精准度三个维度，以定位检索、增强或生成阶段的具体问题。 RAG 引入了新的失效模式，如检索到无关文档、模型忽略检索结果或答案无法解决用户问题。三元组框架帮助开发者精准定位问题环节，从而明确优化方向。
  5. 有效的评估体系是分层构建的，从启发式规则到人工抽检，各层拦截不同类型的问题，并应协同离线与在线评估。 离线评估（如 CI）在部署前拦截已知问题，使用高成本模型；在线评估在生产环境中监控突发问题，使用低成本轻量模型。分层体系兼顾了成本、速度与准确率。

💬 文章金句

  • 对于 LLM 而言，单次测试通过只能算作一个数据样本，不能作为最终结论。我们并非在测试常规函数，而是从概率分布中抽样，单一样本几乎不具备参考价值。
  • 没有评分细则，所有评估都只是个人的主观判断。
  • 当一项指标成为目标，它就不再是一项好的衡量标准。
  • 评估不是项目收尾才进行的工作。恰恰相反，评估是快速迭代的核心基础。
