大促数据库压力激增，如何一眼定位 SQL 执行来源？

6/18/2025, 10:18:00 AM

📌 一句话摘要

通过 SQL 染色技术，利用 Mybatis 拦截器或 AspectJ 快速定位大促期间数据库高压下的 SQL 代码来源。

📝 详细摘要

本文针对大促等高并发场景下数据库压力激增、难以快速定位问题 SQL 的痛点，提出 SQL 染色解决方案。该方案的核心是在 SQL 执行前，通过注释标记 SQL 对应的 Mapper 方法和方法调用栈，从而在监控系统中直观查看 SQL 的来源。文章详细介绍了两种实现方式：基于 Mybatis 拦截器和基于 AspectJ 织入。重点阐述了 Mybatis 拦截器的原理、作用范围以及如何选择合适的切入点（StatementHandler#prepare 方法），并通过对 Mybatis 内部执行流程（MapperProxy、Executor、StatementHandler 等）的源码分析，论证了选择该切入点的合理性。文中还提及了染色操作对性能影响微微（0-1ms）。文章提供了快速接入指南和 Mybatis 拦截器实现的部分源码，并预告了 AspectJ 实现。

💡 主要观点

  1. SQL 染色技术可高效定位高压下问题 SQL 的执行来源 通过在 SQL 中加入标记代码来源（Mapper 方法、调用栈）的注释，使开发者能在监控系统中快速追溯到是哪个业务逻辑执行了该 SQL。
  2. Mybatis 拦截器是实现 SQL 染色的有效方式之一 文章通过分析 Mybatis 四大处理器和 SQL 执行流程，确定 StatementHandler#prepare 方法是进行 SQL 染色的合适切入点，方便获取和修改 BoundSql 对象。
  3. SQL 染色操作对系统性能影响极小 经过实际生产环境验证，在 SQL 执行前进行染色标记的耗时仅在 0-1ms 左右，对整体性能无显著影响。

💬 文章金句

  • 在大促活动期间，用户访问量骤增，数据库的压力陡然加大，导致响应变慢甚至服务中断。
  • 染色的含义是在 SQL 执行前，在 SQL 上进行注释打标，标记内容为这条 SQL 对应的是 Mapper 文件中的哪条 SQL 以及相关的方法执行堆栈。
  • 由此可知，拦截器的作用范围是 ParameterHandler， ResultSetHandler， StatementHandler 和 Executor 处理器（Handler）。
  • 由于该方法（BaseExecutor#query 内部调用）是在方法内部被调用的，所以无法使拦截器生效（动态代理），这也是说它"有时不是很合适"的原因所在。
  • 如果选择切入 StatementHandler#prepare 方法，那么在该方法执行前在 StatementHandler 中拿到 BoundSql 对象进行修改便能实现我们的需求。
