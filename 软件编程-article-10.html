你写的 Skill，及格了吗？

4/22/2026, 10:00:00 AM

📌 一句话摘要

本文提出了一套包含 8 个维度的 Skill 量化评估框架，通过元数据质量、执行引导、领域知识密度等指标对 AI Agent 的 Skill 进行打分评级，并设计了多模型交叉验证流程和四种执行策略来提升评估的可靠性与兼容性。

📝 详细摘要

文章针对 AI Agent 生态中 Skill 质量参差不齐、难以客观衡量的问题，提出了一套原创的 8 维度量化评估框架。该框架将 Skill 的生命周期分为「发现」、「执行」、「价值」三个阶段，分别评估元数据质量、执行引导清晰度、工作流完整性、输入输出清晰度、资源利用、领域知识密度、写作质量、范围与聚焦八个方面，并赋予不同权重，最终给出 S/A/B/C/D 的等级评定。为解决单模型评估的主观性，作者设计了多模型交叉验证机制，通过独立评估、交叉互审、仲裁综合三个步骤，结合三级共识机制，提升评估结果的可靠性。此外，文章还提供了四种适配不同 AI 工具环境的执行策略，并通过实际案例展示了框架在自我评估、横向对比和优化改进中的应用。

💡 主要观点

  1. Skill 质量评估需要可量化的标准，而非依赖主观感觉。 作者提出了一套 8 维度的评估框架，覆盖 Skill 从触发到执行的全生命周期，将模糊的「好用」概念转化为具体的分数和等级，为开发者提供了明确的改进方向和用户提供了选型依据。
  2. 多模型交叉验证能有效提升评估的客观性和可靠性。 通过让多个模型独立打分、互相质疑、最终仲裁的流程，可以避免单一模型的偏见，不同模型间的共识与分歧本身也具有诊断价值，能更准确地定位 Skill 的优缺点。
  3. 评估框架需具备良好的工程化适配能力。 为应对不同 AI 工具（如 Claude Code、百度 dodo）的能力差异，作者设计了四种执行策略（原生多模型、第三方 API、单模型多视角、纯文本分析），并实现自动路由，确保了评估工具的广泛适用性。
  4. 评估是手段，优化才是目的，评估结果可直接驱动 AI 辅助改进。 框架不仅用于打分和对比，其产出的具体问题与建议可以直接作为输入，让 AI 助手自动生成优化方案，实现了「评估-优化」的闭环，提升了开发效率。

💬 文章金句

  • 能跑和好用之间隔着十万八千里。
  • D1（元数据质量）是唯一一个决定 Skill 生死的维度。其他维度影响的是‘好不好用’，D1 决定的是‘有没有机会被用到’。
  • 好的 Skill 内嵌了难以获取的专业知识：私有 API 的调用方式、内部系统的数据模型、行业特定的最佳实践。
  • 这套评估框架只是一把尺子，也有一定的局限性，它度量的是 Skill 的文档工程质量，而非运行时的全部真相。
  • 单模型评分的绝对值不够可靠，但不同模型之间的共识是有价值的。
