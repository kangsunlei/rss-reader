谁写的代码谁负责！Cursor 发布 Agent Trace：从此 Bug 别想再推给 AI

2/6/2026, 8:46:00 AM

📌 一句话摘要

Cursor 发布 Agent Trace 开放规范，旨在通过标准化的 JSON 追踪记录解决 AI 协作编程中的代码归属与可追溯性难题。

📝 详细摘要

本文详细介绍了 Cursor 发布的 Agent Trace 开放规范草案（RFC）。该规范旨在解决当前 AI 辅助编程中一个核心痛点：传统版本控制工具（如 git blame）无法区分代码是由人类还是 AI 生成。Agent Trace 定义了一种厂商中立、存储中立的 JSON 格式，用于记录代码变更的上下文、参与者（人类/AI/混合）及对话过程。该规范支持 Git、Jujutsu 等多种版本控制系统，并允许通过命名空间扩展元数据。尽管在合并和变基等复杂场景下仍有待完善，但它为 AI 时代的代码审查和调试提供了关键的可追溯性标准。

💡 主要观点

  1. 填补 AI 协作编程中的归属追踪空白 传统 Git 工具仅记录修改时间，Agent Trace 通过结构化数据明确代码是由 AI、人类还是两者协作完成，解决了责任判定难题。
  2. 采用厂商中立与存储灵活的技术设计 规范不强制存储位置，支持多种版本控制系统，并允许厂商通过命名空间添加自定义元数据，确保了跨工具的互操作性。
  3. 聚焦于可追溯性而非代码质量评估 设计目标明确，仅关注“代码归属”和“上下文关联”，刻意回避了所有权语义和训练数据溯源等复杂争议问题。

💬 文章金句

  • git blame 等工具只能显示某一行代码“何时被修改”，却无法说明这次修改是由人类完成、由 AI 完成，还是二者协作的结果。
  • Agent Trace 正是为了解决这一缺口，试图以结构化、可互操作的方式捕获这些关键信息。
  • 该规范刻意回避了对 UI 形式、代码所有权语义的定义……而是将关注点严格限定在“代码归属”和“可追溯性”本身。
  • 团队一旦搞不清 Agent 为啥跑偏，就会直接停工。Trace 解决了这个痛点，开放得正好。
