OpenViking：面向 Agent 的上下文数据库

2/2/2026, 10:04:00 AM

📌 一句话摘要

字节跳动开源 OpenViking，通过文件系统范式和分层加载机制，为 AI Agent 提供结构化、可观测且低成本的上下文数据库解决方案。

📝 详细摘要

文章详细介绍了字节跳动团队开源的 OpenViking 数据库。针对 AI Agent 在处理长周期任务时面临的上下文管理混乱、Token 成本高昂、RAG 检索局限及黑箱化等痛点，OpenViking 创新性地提出了“文件系统范式”。它将 Agent 的记忆、资源和技能统一组织为虚拟文件目录，通过 L0-L2 三层分层加载机制实现按需读取，并结合目录递归检索策略提升信息获取的精准度。此外，系统支持检索轨迹可视化与记忆自迭代，旨在帮助开发者构建具备“知识复利”能力的智能体。

💡 主要观点

  1. 采用文件系统管理范式解决上下文碎片化问题 将记忆、资源和技能统一抽象为虚拟文件系统中的文件，通过 URI 定位，使 Agent 能像操作本地文件一样精确地浏览和管理信息。
  2. 通过分层上下文按需加载机制大幅降低 Token 成本 将数据自动处理为摘要(L0)、概述(L1)和详情(L2)三个层级，Agent 在规划阶段仅读取高层信息，确有必要时才调取详情。
  3. 目录递归检索策略提升了复杂查询下的检索效果 融合意图分析与层级探索，先锁定高分目录再进行精细化递归搜索，解决了传统平铺式 RAG 缺乏全局视野和语境理解的问题。
  4. 内置记忆自迭代闭环让 Agent 具备自我进化能力 通过会话提交机制异步分析任务结果与用户反馈，自动更新用户偏好和操作经验，使 Agent 随使用时间增加而变得更加聪明。

💬 文章金句

  • 记忆、资源、技能，皆为文件。
  • OpenViking 摒弃了传统 RAG 的碎片化向量存储模式，创新性地采用'文件系统范式'。
  • 让上下文的管理从模糊的语义匹配演变为直观、可追溯的'文件操作'。
  • 沉淀的记忆才是 Agent 的核心资产......记忆需要在开发初期就建设起来，这样才能形成使用时间越长，体验越好的复利效果。
  • 我们旨在为 Agent 定义一套极简的上下文交互范式，让开发者彻底告别上下文管理的烦恼。
