📌 一句话摘要

本文介绍了如何通过自定义 MybatisPlus 的 InsertBatchSomeColumn 方法，实现 MySQL 和 Oracle 数据库的真正批量插入，并解决 jdbcType 相关问题，提升插入效率。

📝 详细摘要

本文深入探讨了 MybatisPlus 框架下实现批量数据插入的多种方法，包括使用 IService 接口的 saveBatch 方法（实际为单条插入）、手动编写 XML SQL 以及自定义 InsertBatchSomeColumn 方法。重点介绍了自定义 InsertBatchSomeColumn 的实现步骤，包括自定义 SQL 注入器、配置类、自定义 BaseMapper 以及针对 Oracle 数据库的适配。相比默认 saveBatch 方法，该方法在处理大量数据时能显著提升插入效率。同时，针对批量插入过程中可能出现的 jdbcType 问题，提供了两种解决方案：指定实体属性的 jdbcType 类型或设置 mybatis-plus 的 `jdbc-type-for-null` 属性。最后，对 InsertBatchSomeColumn 方法进行了 Service 层的封装，方便后续调用，尤其强调了 Oracle 适配的重要性。

💡 主要观点

  1. MybatisPlus 的 saveBatch 方法底层是单条插入，效率较低。 默认的 saveBatch 方法虽然可以实现批量插入，但实际上是对集合中的每个实体进行单条插入操作，性能较差。
  2. 通过自定义 InsertBatchSomeColumn 方法，可以实现通用的、高效的批量插入。 通过自定义 SQL 注入器并重写插入逻辑，可以拼接出高效的批量插入 SQL，避免了为每个表编写 XML 的繁琐。
  3. 字段值为 NULL 时，需要指定 jdbcType 或设置全局的 jdbc-type-for-null 属性。 Oracle 数据库对 NULL 值的 jdbcType 有严格要求，需要显式指定类型或设置全局属性，否则会导致插入失败。
