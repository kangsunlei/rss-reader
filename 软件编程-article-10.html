MongoBleed 漏洞允许攻击者从 MongoDB 堆内存中读取数据

1/10/2026, 7:36:00 AM

📌 一句话摘要

MongoDB Server 中的 "MongoBleed" 漏洞（CVE-2025-14847）由不当的 zlib 解压缩引起，允许未经身份验证的攻击者远程从堆内存中窃取敏感数据，已有活跃利用报告且已发布补丁。

📝 详细摘要

MongoDB 最近修补了 CVE-2025-14847，该漏洞被命名为 "MongoBleed"，是一个 CVSS 评分为 8.7 的关键漏洞，允许未经身份验证的远程攻击者读取未初始化的堆内存。该缺陷源于基于 zlib 的网络消息解压缩中的长度处理错误，发生在身份验证之前。这可能导致凭据或令牌等敏感数据被窃取。Wiz 的安全研究人员确认了野外活跃利用，根据 Censys 的数据，42% 的云环境中至少存在一个易受攻击的 MongoDB 实例，全球约有 87，000 台服务器可能暴露。虽然 MongoDB Atlas 实例已自动修补，但自托管部署必须立即应用更新或实施缓解措施，如禁用压缩和限制网络暴露。该漏洞影响自 2017 年以来的所有 MongoDB 版本，甚至生命周期结束版本（3.6、4.0、4.2）也不会收到修复。此事件凸显了数据库安全和及时修补的极端重要性，即使对于成熟的开源项目也是如此。

💡 主要观点

  1. MongoBleed（CVE-2025-14847）是 MongoDB 中一个关键的、被主动利用的身份验证前漏洞。 此漏洞允许未经身份验证的远程攻击者通过发送格式错误的 zlib 压缩网络数据包来触发堆内存泄漏，可能导致数据和凭据被盗。
  2. 该漏洞影响自 2017 年以来的 MongoDB 版本，原因是解压缩逻辑中的长度处理不正确。 `message_compressor_zlib.cpp` 中的一个错误返回了分配的缓冲区大小而不是实际的解压缩数据长度，从而暴露了相邻的堆内存。
  3. 全球存在重大暴露风险，特别是面向互联网的、未修补的自托管实例。 Wiz 报告称 42% 的云环境易受攻击，Censys 识别出约 87，000 台暴露的服务器，突显了由于未经身份验证的可利用性而带来的高风险。
  4. 对于自托管部署而言，立即打补丁至关重要，因为托管的 Atlas 实例已更新。 敦促组织应用可用的安全补丁或实施缓解措施，如禁用压缩和网络限制，以防范主动利用。
  5. 该事件凸显了严格的安全实践和及时更新的持续重要性，即使对于成熟软件也是如此。 它提醒我们数据库安全就是基础设施安全，挑战了关于开源安全模型的常见假设。

💬 文章金句

  • MongoBleed 突显了即使成熟的数据库在暴露或未修补时也可能成为关键的攻击面。
  • 通过发送格式错误的压缩网络数据包，未经身份验证的攻击者可以触发服务器错误处理解压缩消息长度，导致未初始化的堆内存返回给客户端。
  • 在代码层面，该漏洞是由 `message_compressor_zlib.cpp` 中的长度处理不正确引起的。受影响的逻辑返回了分配的缓冲区大小（output.length()）而不是实际的解压缩数据长度。
  • 许多人认为开源代码比闭源代码更安全，或者安全问题在开源代码中会被更快发现。存在如此级别的漏洞是对前者的反驳。
  • 它极易被利用 - 只需要连接到数据库（无需身份验证）。截至撰写本文时已修复，但一些 EOL 版本（3.6、4.0、4.2）将不会获得修复。
