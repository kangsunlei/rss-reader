如何利用 Harness “一句话交付产品功能”？

6/10/2026, 10:00:00 AM

📌 一句话摘要

本文详细介绍了团队如何通过构建单仓代码库、设计 6 个 Sub-Agent 协作流水线并定义 Agent Handoff 协议，将 AI 驱动开发从 Vibe Coding 升级为 Harness 模式，实现功能开发效率提升约 4 倍。

📝 详细摘要

文章分享了团队将 AI 驱动开发模式从 Vibe Coding 升级为 Harness 模式的完整实践。作者首先指出 Vibe Coding 模式下与 AI 反复沟通的低效痛点，随后借鉴 OpenAI 与 Anthropic 的思路，通过 Git Submodule 将前后端分离仓库重构为单仓，并设计了一套由 6 个专业 Sub-Agent（需求设计、后端实现、前端开发、测试用例设计、集成测试、E2E 测试）组成的自动化协作流水线。核心创新在于定义了清晰的 Agent Handoff 协议，实现任务状态在不同 Agent 间的安全、结构化流转。实践表明，该模式将原本需要 1 天完成的功能开发缩短至约 2 小时，效率提升约 4 倍。文章也坦诚讨论了 E2E 测试检测能力较弱、需求改动存在遗漏等局限性。

💡 主要观点

  1. 从 Vibe Coding 到 Harness 模式的升级，核心是将代码库作为唯一事实源，实现 Agent 自治流转。 Vibe Coding 模式下，AI 写代码但人仍需统筹状态和联调；Harness 模式通过单仓代码库和 Agent Handoff 协议，让 Agent 自动完成从需求到测试的全流程，减少人工介入。
  2. 通过 Git Submodule 实现 AI-First 的单仓代码库重构，是 Harness 模式成功的基础。 将前后端分离仓库整合为单仓，使 Agent 能访问所有代码和文档知识，解决了跨仓库知识无法被 Agent 感知的问题，符合 AI-first 原则。
  3. 6 个 Sub-Agent 协作流水线配合 Agent Handoff 协议，解决了单 Agent 的上下文焦虑和自视甚高问题。 将端到端流程拆分为需求、后端、前端、测试用例、集成测试、E2E 测试 6 个专业 Agent，通过标准化的 Handoff 块传递状态和上下文，实现安全、自动化的任务流转与缺陷修复闭环。
  4. Harness 模式显著提升效率，但 E2E 测试和需求完整性仍是当前局限。 实践数据显示功能发布效率提升 4 倍，但 E2E 测试对样式和布局缺陷的检测能力弱于人工，且 Agent 生成的 PRD 可能存在遗漏，需要人工审核兜底。

💬 文章金句

  • AI-first 意味着我们必须以 AI 为核心重塑我们的流程、架构、组织模式，而不是让 AI 来适配当下的架构。
  • 代码库作为 Agent 的唯一知识来源，代码库之外，别无他物。
  • 当前的 Harness 已经让我们的功能发布效率提升了 4 倍，虽然与 OpenAI 博客中的 10 倍相比还有不少差距，但是已经让我们成功从'人工调优代码'跨越到'治理 Agent 流水线'。
