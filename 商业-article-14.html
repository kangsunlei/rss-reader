Clawdbot 如何搭建永久记忆管理系统：全靠 MD 文档

2/2/2026, 11:56:00 AM

📌 一句话摘要

本文深入解析了 Clawdbot 如何利用纯 Markdown 文件构建透明、持久且可搜索的 AI 智能体双层记忆管理系统。

📝 详细摘要

文章详细介绍了 Clawdbot（现 OpenClaw）的记忆管理机制。该系统将“记忆”视为独立的子系统，核心原则是使用本地 Markdown 文件存储，确保用户对上下文的完全掌控。系统采用双层架构：第一层是每日日志，记录即时信息；第二层是长期记忆，存储精选知识。通过集成 sqlite-vec 和 FTS5，系统实现了语义与关键字的混合搜索。此外，文章还探讨了应对 LLM 上下文限制的压缩、剪枝及记忆刷新等高级优化策略，为构建长效运行的 AI Agent 提供了系统化的工程方案。

💡 主要观点

  1. 明确区分瞬时上下文与持久记忆，将记忆作为独立于模型窗口的存储系统。 上下文受限于模型 Token 窗口且成本高昂，而记忆存储在本地硬盘，具有持久、无边界、低成本且可搜索的特性，是智能体长期进化的基础。
  2. 采用双层 Markdown 存储结构，兼顾信息的即时记录与长期知识的精选沉淀。 系统由每日日志（YYYY-MM-DD.md）和长期记忆（MEMORY.md）组成。前者记录全天候的原始互动，后者则由智能体或用户提炼重要的决定、偏好和经验。
  3. 结合向量相似度与 FTS5 全文检索，通过混合搜索策略提升记忆召回的准确性。 系统按 7:3 的权重合并语义搜索与关键字匹配结果。语义搜索负责捕捉概念关联，而关键字匹配则确保名称、日期等精确术语不被遗漏。
  4. 引入“压缩前记忆刷新”机制，防止在上下文窗口溢出处理中丢失关键信息。 在触发对话压缩前，系统会静默引导智能体审查当前上下文，将重要事实写入硬盘。这种“先存盘后压缩”的策略确保了知识在有损总结过程中的完整性。

💬 文章金句

  • 记忆就是 AI 智能体工作区里的纯 Markdown 文件。你能读、能改，还能用版本控制管它。
  • 搜索 > 注入：AI 智能体不是把所有东西一股脑塞进上下文，而是去搜相关的。这样既保持了上下文的专注，又省钱。
  • 透明度 > 黑盒：没有什么不透明的数据库或者专有格式，所有记忆对用户完全透明。
  • 语义相似度是记忆召回的主力，但 BM25 关键字匹配能抓住向量可能会漏掉的精确术语。
