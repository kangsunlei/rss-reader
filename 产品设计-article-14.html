SaaS 做 AI，你做到第几层了？

8/16/2026, 11:45:00 PM

📌 一句话摘要

本文为 SaaS 厂商拆解了 AI 产品化的四个递进层级（API $ ightarrow$ CLI/MCP $ ightarrow$ Agent $ ightarrow$ A2A），并为中小 SaaS 提供了务实的落地路径建议。

📝 详细摘要

文章探讨了在 AI Agent 成为新流量入口的背景下，SaaS 厂商如何避免被生态淘汰。作者将 AI 产品化分为四层台阶：第 0 层 API（能力地基）、第 1 层 CLI/MCP（交付方式）、第 2 层 Agent（虚拟员工产品）以及第 3 层 A2A（Agent 间协作）。文章重点分析了 MCP 与 CLI 的场景差异，指出 MCP 在多租户隔离与生态接入上的核心价值，并建议中小 SaaS 厂商应优先补齐 API，主攻 MCP 并接入大厂生态，而非盲目追求 A2A 协议，强调 AI 产品化的终点是交付能卖钱的「虚拟员工」。

💡 主要观点

  1. AI Agent 正在引发新一轮的入口迁移。 用户交互从界面转向自然语言指令，SaaS 的能力需要以 AI 能理解的方式交付，否则将被上游 Agent 绕过，失去被用户发现的机会。
  2. AI 产品化分为四个递进层级：API $ ightarrow$ CLI/MCP $ ightarrow$ Agent $ ightarrow$ A2A。 从最基础的能力接口化（API），到标准化交付（MCP），再到封装为可销售的虚拟员工（Agent），最后实现跨厂商协作（A2A）。
  3. MCP 是 SaaS 对外开放生态的主干，而 CLI 适用于本地高效执行。 CLI 虽然省 token，但缺乏多租户隔离和审计能力；MCP 通过标准化协议支持 OAuth 授权和多租户隔离，是 SaaS 服务成千上万客户的必然选择。
  4. 中小 SaaS 应采取「地基 $ ightarrow$ 主干 $ ightarrow$ 借力」的务实路径。 建议顺序为：补齐 API $ ightarrow$ 实现 MCP $ ightarrow$ 入驻大厂 Agent 生态 $ ightarrow$ 等待 A2A 需求出现，避免被新技术焦虑绑架。

💬 文章金句

  • 你的产品未来大概率不是被「人」打开，而是被「Agent」调用。界面会贬值，但数据和能力不会。
  • CLI 是「自己人直接上手干活」，MCP 是「对外开放的标准接口」。
  • AI 产品化的终点不在协议里，在你能把一个「员工」真正卖出去的那天。
