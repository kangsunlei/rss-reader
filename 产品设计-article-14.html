测评：用 Kimi 新模型 K2 做数据分析，国内 Agent 有救了

7/13/2025, 11:45:00 PM

📌 一句话摘要

文章通过实际测评，对比了 Kimi K2、DeepSeek 和豆包模型在数据分析任务中的 Agent 能力，指出 K2 在迭代优化和工具调用上表现更优，并探讨了 AI 胜任数据分析的关键。

📝 详细摘要

文章深入测评了 Kimi 新模型 K2、DeepSeek V3 和豆包 Seed 1.6 在全流程数据分析任务中的表现。作者通过使用第三方客户端 Cline-VS Code，让这些模型分析客户服务满意度数据，并重点考察它们在任务理解、规划、工具调用和反馈纠偏等方面的 Agent 能力。测评发现，K2 能够分步执行、迭代优化分析报告，其 Agent 能力显著优于 DeepSeek 和豆包的“一口吃个胖子”式一次性生成，后者往往将分析结论写死在代码中。文章还盘点了扣子空间、豆包、智谱、元宝等内置工具的 AI 数据分析平台，并指出这些工具通过代码执行弥补了 LLM“心算”的短板，是 AI 胜任数据分析任务的关键基建。文章最后强调了数据分析作为衡量大模型 Agent 水平的综合任务的价值，并预示 AI 将极大降低数据分析的门槛。然而，文章末尾包含明显的付费课程推广内容。

💡 主要观点

  1. Kimi K2 在数据分析任务中展现出更强的 Agent 能力 K2 能够分步执行、迭代优化分析报告，通过打印中间结果辅助最终报告生成，区别于其他模型的一次性输出，显示出更成熟的 Agent 思维。
  2. 大模型胜任数据分析需依赖工具而非“心算” 文章指出，直接通过上下文“硬分析”Excel 数据效率低下且不准确，内置代码执行工具是实现全流程、准确数据分析的关键。
  3. 数据分析是衡量大模型 Agent 水平的综合任务 数据分析任务涵盖任务理解、意图识别、规划、工具调用、代码编写、反馈纠偏等环节，是评估 AI Agent 能力的理想场景和重要指标。

💬 文章金句

  • 考虑到当前官网还没上线 MCP 功能，直接让它分析 Excel 中的数据会以上下文的形式「硬分析」，一是准确度不高(具体原因在 Part3)，二是无法体现它的 Agent 能力。
  • 它会以解决问题为第一目标，而不是节省 Token 糊弄事儿。
  • 一旦解决了'一口吃个胖子'的毛病，胜任 Agent 场景就指日可待了。
  • 数据分析是一个综合了任务理解、意图识别、任务规划、工具调用、代码编写、反馈纠偏、异常处理等可以衡量大模型 Agent 水平的各种环节的任务。
