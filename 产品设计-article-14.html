当 Agent 被强行变成入口，会带来哪些改变

8/1/2026, 2:00:00 AM

📌 一句话摘要

本文以办公 Agent 三国杀为背景，论述 Agent 成为入口后产品经理角色、PRD 设计、KPI、权限风控、用研方法等 10 个维度的系统性转变。

📝 详细摘要

文章以 WorkBuddy 月活突破 2097 万、阿里整合千问办公、字节将飞书并入豆包三件事为切入点，指出大厂正把 Agent 做成新的办公入口。作者区分了「AI 赋能」与「Agent 赋能」的本质差异：前者是产品拥有 AI 工具，后者是用户通过 Agent 调度产品，产品沦为可被调用的工具。基于这一判断，文章梳理了 10 个即将到来的变化，包括产品经理要同时服务人类用户与 Agent 用户、产品界面从操作主体变为状态查看与异常处理终端、PRD 需补充 Agent 故事、功能需原子化拆解、出现类似 SEO 的 AEO 概念、KPI 从 DAU 转向调用成功率与任务完成率、权限风控升级、隐形业务规则显化、用研需观察 Agent 执行过程、产研协作边界向 Tool Use/MCP/Skills 等技术概念延伸。文末附有作者线下课程推广。

💡 主要观点

  1. 「AI 赋能」与「Agent 赋能」是主体反转的两种范式。 AI 赋能中产品是主体、AI 是工具；Agent 赋能中用户是主体、Agent 是代理、产品变成可被调用的工具，产品经理的主导权被削弱。
  2. Agent 成为入口后，产品需同时服务人类用户与 Agent 用户。 产品经理要回答 Agent 能否理解产品、何时调用、为何选你、失败如何恢复等问题，UX 需拆分为给人看的交互体验和给 Agent 用的调用体验。
  3. 产品界面从操作主体退化为状态查看与异常处理终端。 高频标准化操作交给 Agent，页面更多用于查看状态、处理异常和确认高风险操作，部分功能只需暴露为 API、MCP Tool 或 Skill。
  4. KPI 体系需从 DAU/点击率转向调用成功率与任务完成率。 Agent 调用次数、首次执行成功率、人工接管率、单次任务成本等成为新指标，且需区分工具执行成功、任务完成与业务结果达成三个层次。
  5. 权限风控与隐形规则显化成为产品设计的硬约束。 Agent 可执行真实业务操作，误操作危害大，需设计二次确认、操作范围限定、日志追溯；同时把散落在老员工脑子里的业务经验整理为规则、SOP 与 Tool 描述。

💬 文章金句

  • 过去 PM 设计的是用户完成任务的路径；以后还要设计 Agent 代替用户完成任务的条件、工具和边界。
  • 不怕流氓有文化，就怕文化人耍流氓。
  • AI 拥有大量知识，但反倒更不可靠。
