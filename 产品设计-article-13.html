WorkBuddy 执行任务重复循环浪费 token，教你一招止损

11/15/2026, 3:11:06 PM

📌 一句话摘要

WorkBuddy 执行任务易出现失败/成功循环导致 token 浪费，作者介绍了一个 12KB 外部脚本，可在连续失败 3 次或重复命令时自动止损，平均节省 40-60% token。

📝 详细摘要

本文分析了 WorkBuddy 执行任务时发生的两种循环问题：失败重复（如反复查询不存在的文件）和成功重复（查到后仍重复查询）。自带的 Harness 仅在重试上限、 token 耗尽或上下文溢出时才停止，导致 token 浪费。作者基于微软的开源 TokenEconomizer 开发了一个 12KB 本地脚本，通过 Hook 机制监控工具调用，在连续失败 3 次或同一命令重复多次时自动介入，强制模型停止，节省 token。实测结果显示卡点任务 token 消耗可减少 40%～60%，日常任务也可降低 5%～15%，为 AI 产品经理提供了实用的 token 管理方案。

💡 主要观点

  1. WorkBuddy 执行任务易出现失败重复和成功重复循环，导致 token 浪费。 失败重复是指模型反复查询不存在资源；成功重复是指查到结果后仍重复查询。两者均造成 token 消耗，尤其当 Harness 仅在重试上限触发时才停止。
  2. 自带 Harness 缺乏实时止损机制，只在轮次上限、 token 耗尽或上下文溢出时才喊停。 Harness 为模型提供无限重试机会，但不会及时检测空转，导致 token 浪费严重。
  3. 外部 12KB 止损脚本可监控工具调用并自动介入。 该脚本通过 Hook 挂载到 WorkBuddy 底层，在连续失败 3 次或同一命令重复多次时强制模型停止，响应速度约 33ms，不消耗 token。
  4. 脚本实测可显著降低 token 消耗，提高任务效率。 实测结果显示卡点任务 token 消耗可减少 40%～60%，日常任务也可降低 5%～15%，为 AI 产品经理提供了实用解决方案。

💬 文章金句

  • WorkBuddy 有时兜圈子、卡在思考里空转，根源是失败重复和成功重复两种 loop，Harness 只在轮次上限才喊停。
  • 作者写了一个 12KB 的外聘教练脚本，专门算 token 账，撞墙三四次就掐断止损。
  • Harness 只是给模型无限重试的机会，并没有对应的及时喊停止损机制。
  • 这是一个装在 WorkBuddy 底层的本地小程序，通过 Hook 钩子的挂载机制，挂上去的一个叫 Python 写的小脚本。
  • 发现连续失败 3 次，或者同一条命令原样重复好几遍没有进展
