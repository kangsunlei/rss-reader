不能只算 token 账：从龙虾爆火看 AI 行业范式转移

4/8/2026, 11:46:00 PM

📌 一句话摘要

本文深入探讨了 AI 行业从「API 套壳」向「模型产品深度整合」的范式转移，分析了龙虾（Lovable）等工具对二线模型厂商的叙事支撑及其背后的工程效率与商业模式困境。

📝 详细摘要

文章以 Anthropic 禁止第三方工具接入为切入点，探讨了当前 AI 行业的竞争格局。作者指出，以龙虾（Lovable）为代表的 AI 编程工具虽然存在工程纪律缺失、浪费 token 等问题，但却为国内二线模型厂商提供了关键的流量入口和估值叙事。然而，随着行业进入第二代范式——即模型与产品深度整合（如 Claude Code），纯粹卖 API 的模型厂商将面临巨大压力。文章强调，模型厂商的第一性原理是「有人用」，但在价格战和 token 倾销的掩盖下，如何通过工程优化提升效率并跑通盈利模式，才是长期的核心挑战。

💡 主要观点

  1. AI 行业正经历从「API 套壳」向「模型产品深度整合」的范式转移。 第一代范式是模型作为通用 API 被外部产品调用，导致效率浪费；第二代范式如 Claude Code，模型与产品从架构层共同设计，实现精细的上下文管理和性能优化。
  2. 龙虾（Lovable）等工具是二线模型厂商的「叙事救星」，但窗口期有限。 龙虾虽然制造了大量「屎山代码」和 token 消耗，但它成功让阿里、小米、阶跃星辰等模型在 OpenRouter 排行榜登顶，支撑了厂商的估值叙事。
  3. 模型厂商的第一性原理是「模型得有人用」，但不能仅靠价格战。 低价倾销虽能加速技术采纳，但不可持续。长期竞争力来自于模型能力与应用层的深度耦合，而非单纯的 API 售卖。

💬 文章金句

  • 模型厂商的第一性原理就是模型得有人用。没人用，叙事就崩塌了。
  • 龙虾架构上的天然缺陷，意味着每次工具调用都携带完整的长上下文发起独立请求……这不仅烧 token，也制造延迟，制造不稳定。
  • 模型不再是被调用的服务，而是产品本身的一部分。
  • 除非你的商业模式是只卖 API，否则模型始终是产品的组成部分，而不是产品的全部。
