基于浏览器扩展 API Mock 工具开发探索｜得物技术

9/22/2025, 10:31:00 AM

📌 一句话摘要

得物技术团队详细介绍了如何基于 Manifest V3 开发浏览器扩展 API Mock 工具，解决前端开发中的接口依赖问题，并深入探讨了其实现原理和架构。

📝 详细摘要

文章深入探讨了得物前端团队开发一款基于浏览器扩展的 API Mock 工具的实践。首先，阐述了开发该工具的背景与痛点，即后端接口未完成或环境问题导致的接口依赖。接着，详细介绍了浏览器插件的基础知识，特别是 Manifest V3 架构的核心变化，如 Service Worker 和 declarativeNetRequest API。文章的核心在于阐述了 Manifest V3 下请求拦截的实现原理，通过在页面上下文中重写原生`fetch`和`XMLHttpRequest`，并结合多重脚本注入策略来规避 Content Security Policy 和`webRequest`阻塞能力的移除。随后，展示了工具的项目结构、Mock 规则创建（支持从得物 API 管理平台导入）、页面白名单管理和请求日志等功能。最后，总结了开发过程中的收获，并展望了未来功能升级及结合 AI 能力的应用，旨在进一步提升开发效率。

💡 主要观点

  1. 基于 Manifest V3 的浏览器插件是解决 API Mock 的有效途径。 通过开发浏览器扩展工具，可以在前端开发中有效模拟后端接口数据，解决接口依赖和环境问题，显著提升开发效率。
  2. Manifest V3 架构下需巧妙规避`webRequest`阻塞能力限制。 由于 V3 移除了`webRequest`的阻塞能力且`declarativeNetRequest`无法重定向到自定义数据，文章采用在页面上下文中重写原生`fetch`和`XMLHttpRequest`的方式实现请求拦截。
  3. 多重脚本注入策略是绕过 Content Security Policy 的关键。 为确保`injected.js`脚本能在页面环境中顺利执行，文章设计了内联、外部及简单注入相结合的多重策略，以应对浏览器的 Content Security Policy 限制。
  4. 工具具备完善的 Mock 规则管理与调试能力。 支持从公司 API 平台导入、手动新建 Mock 规则，提供页面白名单控制性能，以及请求日志方便调试，提升了工具的实用性和易用性。

💬 文章金句

  • 该工具专注于 API 请求拦截和数据模拟，旨在帮助开发者提升开发效率，能够解决一些问题。
  • Manifest V3 采用'静态声明+内核级处理'模式替代 V2 的'动态脚本+插件自主控制'模式，通过浏览器内核直接介入关键流程（如网络拦截），在性能与安全性之间取得平衡。
  • 由于 Manifest V3 移除了 webRequest API 的阻塞能力，declarativeNetRequest 又无法重定向到自定义数据，于是方案上选择的是在页面上下文中重写原生 API，目前重写了 fetch 跟 XMLHttpRequest。
  • 本次插件开发过程中，探索了浏览器扩展插件的能力，学习了 Manifest V3 的新知识，掌握了浏览器插件开发相关技术点。
  • 如何在后续需要对功能点进行改造时，使用效率并不是高，如何建立规则和组织话术，让 AI 更加规范、高效地辅助开发是一个值得深思的问题。
