Microsoft Azure 通过为 Logic Apps 和 Functions 添加 OpenTelemetry 支持增强可观测性

6/23/2025, 12:00:00 AM

📌 一句话摘要

Microsoft Azure 通过添加 OpenTelemetry 支持，增强了 Logic Apps 和 Functions 的可观测性，实现了标准化的日志、跟踪和指标导出。

📝 详细摘要

微软宣布扩展对 Azure Logic Apps （标准版和混合版）和 Azure Functions （公开预览版）的 OpenTelemetry ( OTel ) 支持。OpenTelemetry 是一个 CNCF 项目，提供了一个厂商无关的框架，用于生成、收集和导出遥测数据，包括日志、指标（尽管 Logic Apps 尚不支持）和跟踪。这项集成显著提升了诊断能力，尤其有利于混合和本地部署，通过提升主机与应用程序代码之间的关联性，并确保基于标准的数据生成。 文章详细介绍了在这些服务中启用 OpenTelemetry 的配置过程。这包括更新 `host.json` 文件，设置 `"telemetryMode": "OpenTelemetry"`，以及配置应用程序设置以指定 OTLP 导出器端点 ( `OTEL_EXPORTER_OTLP_ENDPOINT` ) 和可选的请求头。配置适应不同的托管环境，如工作流标准计划、 App Service 环境 v3 或混合容器，并且可以通过 Visual Studio Code 或 Azure 门户进行管理。 通过支持 OTel， Azure 服务获得了与各种可观测性后端（包括 Azure Monitor 、 Grafana Tempo 和 Jaeger ）增强的互操作性，为开发者提供了在监控和调试策略上更大的灵活性。

💡 主要观点

  1. 微软为 Azure Logic Apps 和 Azure Functions 添加 OpenTelemetry 支持。 这项集成使这些流行的 Azure 无服务器和集成服务能够实现标准化的可观测性，超越了默认的 Application Insights 能力。
  2. OpenTelemetry 标准化了遥测数据（日志、跟踪、指标）的生成和导出。 作为一个厂商中立的框架， OTel 简化了遥测数据的收集，并允许导出到各种可观测性后端，为监控工具选择提供了灵活性。
  3. OTel 支持改进了诊断能力，特别是在混合和本地场景中。 跨应用程序和基础设施不同部分的标准数据生成和关联性增强了调试和性能分析。
  4. 配置只需要简单修改 `host.json` 和应用程序设置。 启用 OTel 需要对服务配置文件进行简单更改，并设置导出器端点的环境变量，使得实现过程直接明了。
