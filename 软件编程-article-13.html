[视频播客] 与 Madelyn Olson 探讨 Valkey 的改进

2/9/2026, 11:00:00 AM

📌 一句话摘要

Valkey 是一个由社区驱动、高性能的 Redis 开源分支，通过对内部哈希表结构的精巧重新设计，实现了显著的内存效率和吞吐量提升。

📝 详细摘要

本文基于一场技术播客，详细介绍了 Valkey 的演进过程。Valkey 是因 2024 年 Redis 许可变更而诞生的开源替代方案。维护者 Madelyn Olson 解释了 Valkey 如何在保持严格向后兼容性的同时，实施深层的架构优化。关键技术亮点包括从传统的链表哈希表转向更现代、受 SwissTable 启发的缓存感知设计。通过利用 SIMD 指令、减少内存分配以及实现用于跨集群高效数据采样的二叉索引树，Valkey 显著降低了内存开销。讨论强调，在这种语境下，性能重点在于吞吐量和硬件效率，确保开发者能从 Redis 无缝迁移，同时为现代硬件提供更优化的引擎。

💡 主要观点

  1. Valkey 作为社区驱动、厂商中立的 Redis 分支，旨在应对 2024 年的许可变更。 该项目由来自亚马逊和阿里巴巴等大型科技公司的工程师在短短八天内创建，确保了在 Linux 基金会治理下，高性能、BSD 许可的键值存储能够持续可用。
  2. 由于网络占据了主要的响应时间，该项目优先考虑吞吐量和硬件效率，而非单纯的原始延迟。 由于内部命令执行仅需约 1 微秒，维护者专注于减少 CPU 后端停顿和内存争用，以便在现代多核系统上更有效地处理大规模并发工作负载。
  3. 8 和 9 版本的架构转变引入了受 SwissTable 启发的缓存感知哈希表设计。 通过将传统的链表冲突处理替换为 64 字节缓存行内的 SIMD 加速探测，Valkey 在保持高性能的同时，将每个条目的内存开销显著降低了约 23 字节。
  4. 实现二叉索引树以解决跨分布式槽字典进行随机采样的挑战。 该数据结构允许在过期和淘汰过程中进行高效的 O(log N) 采样，即使在集群环境下数据被水平分区到数千个内部字典中也是如此。
  5. Valkey 保持严格的向后兼容性，可作为 Redis 7.2 用户的无缝替代方案。 该项目确保现有的 Redis 客户端和基础设施无需更改代码即可迁移，通常只需简单的配置更新或托管服务开关即可完成过渡。

💬 文章金句

  • Valkey 是 Redis 开源 7.2 的无缝替代品……大多数适用于 Redis 的客户端也同样适用于 Valkey。
  • 当我们谈论性能时，几乎总是在谈论吞吐量，因为一旦达到吞吐量极限，就会开始看到巨大的延迟峰值。
  • 我们花了很多时间观察 CPU 计数器……我们等待内存可供处理的时间有多长？
  • Valkey 真正的强大之处在于它拥有复杂的数据类型或值……它周围的所有东西才是真正复杂的。
  • 我们从其他一些哈希表中汲取了灵感……处理这些冲突的更现代的方法是进行探测。
