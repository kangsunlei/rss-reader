OpenAI 曝出沙箱逃逸漏洞，无需 API 密钥就能免费调用付费模型

10/8/2026, 10:00:00 AM

📌 一句话摘要

安全研究员 Oliver Fish 披露 OpenAI 存在一处未认证沙箱逃逸漏洞，可绕过 API 密钥免费调用付费模型，但仅获 300 美元奖励引发争议，且技术细节与大规模利用证据尚未公开。

📝 详细摘要

文章报道了安全研究员 Oliver Fish 发现的 OpenAI 沙箱逃逸漏洞。该漏洞允许攻击者在不提供 API 密钥甚至账号的情况下，通过内部路径直接调用 OpenAI 的 Responses API 及付费模型，同时突破了沙箱隔离与身份认证两道防线。然而，目前漏洞的技术细节（如 PoC、受影响接口、CVE 编号）均未公开，也没有证据表明发生了大规模数据泄露或在野利用。Fish 因仅获得 300 美元的 Bugcrowd 平台奖励而公开表达不满，认为其价值被低估。文章最后引用 Cyber Security News 的观点，强调企业需将共享内部服务视为安全边界进行全面测试，并建议 API 服务商在转发节点强制身份校验，用户则应关注账单异常而非依赖密钥轮换。

💡 主要观点

  1. 漏洞核心在于同时突破沙箱隔离与 API 身份认证机制 正常流程要求开发者创建 API 密钥才能调用 Responses API，但该漏洞允许远程攻击者通过内部路径发送请求，绕过常规的身份校验与计费流程，实现无密钥访问付费模型。
  2. 当前信息透明度低，缺乏大规模利用的直接证据 OpenAI 未公开漏洞的技术细节（如 PoC 代码、具体接口地址、受影响模型列表、CVE 编号等），且暂无证据显示客户数据泄露或除研究员测试外的在野利用，因此尚不能认定为已确认的大规模安全事件。
  3. 漏洞评级与奖励金额的巨大落差引发社区争议 尽管标题描述为“未认证沙箱逃逸”，但 OpenAI 仅发放 300 美元奖励（处于低危区间）。这可能意味着官方评定的实际影响远低于报告描述，或者存在其他缓解措施未被公开，导致研究员对赏金计划产生信任危机。
  4. 防御侧需从架构层面加强内部服务的边界管控 历史案例表明沙箱并非绝对安全。建议 API 服务商在所有内部请求转发节点强制身份校验，拦截匿名调用，并设置严格的速率与额度限制；用户需注意服务端认证绕过无法通过客户端密钥轮换解决。

💬 文章金句

  • 如果 Fish 披露的情况属实，远程攻击者可以通过内部路径发送模型调用请求，绕过常规的身份校验与计费流程。
  • 一个无需 API 密钥或账号就能免费访问 OpenAI 付费模型的漏洞，只值 300 美元。我以后再发现任何问题，都绝对不会报给他们了。
  • 企业必须将共享内部服务、薄弱的访问规则、开放的网络路径视为安全边界，全面开展测试。
