📌 一句话摘要

得物 iOS 团队通过修改函数名解决 dyld BuildingClosure 阶段的字符串 Hash 碰撞，从而优化了启动速度。

📝 详细摘要

本文深入探讨了得物 iOS 团队在启动优化过程中遇到的 BuildingClosure 耗时问题。文章首先介绍了 BuildingClosure 的概念和在 dyld 中的作用，指出 BuildingClosure 优化对于应用启动优化至关重要。然后详细描述了启动耗时暴增 200ms 的问题定位过程，最终发现是由于 BuildingClosure 阶段的 Perfect Hash 算法中，函数字符串 Hash 碰撞导致循环次数增加，耗时增加。最后，通过修改冲突的函数名称，成功避免了 Hash 碰撞，显著降低了启动耗时。文章还提出，彻底解决 Hash 碰撞问题可以进一步优化启动速度。

💡 主要观点

  1. 修改冲突的函数名称可以有效避免 Hash 碰撞，优化启动速度。 通过修改发生 Hash 碰撞的函数名称，可以减少循环次数，从而降低 BuildingClosure 阶段的耗时，是解决启动耗时问题的有效方法。
  2. BuildingClosure 是 iOS 启动过程中一个重要的耗时阶段。 BuildingClosure 在首次启动、版本更新或重启后首次启动时生成，会显著影响用户体验，需要重点关注。
  3. 字符串 Hash 碰撞是 BuildingClosure 耗时增加的潜在原因。 在 BuildingClosure 阶段的 Perfect Hash 算法中，Hash 碰撞会导致查找唯一整数的循环次数增加，从而增加耗时。

💬 文章金句

  • Building Closure 并非工程的编译阶段，Building Closure 是应用初次启动时会经历的阶段，因此它会影响应用的启动时长。
  • BuildingClosure 是在 System Interface Initialization 阶段 dyld 生成的，并且我们也无法做任何的干预，另外相关的剖析文章相对较少，所以说 BuildingClosure 较为神秘，也是实至名归。
  • 在 Building Closure 阶段中，可能存在字符串的 Hash 碰撞 引发循环次数大幅增加，进而引发了启动耗时暴增。
