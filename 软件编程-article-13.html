从亚百毫秒级启动到生产级部署，腾讯云为何重构 Agent 沙箱？

8/12/2026, 6:52:00 AM

📌 一句话摘要

本文通过采访腾讯云 IaaS 前沿技术团队负责人，解析开源 Agent 沙箱 Cube Sandbox 如何从 Serverless 底座演进到 Agent Runtime，并讨论生产级部署门槛与 Agent Infra 未来方向。

📝 详细摘要

文章以对腾讯云 IaaS 前沿技术团队负责人金峰的访谈为主线，讨论 Agent 基础设施为何不能沿用传统方案。作者先以 OpenClaw 引发的安全事件为背景，归纳 Agent 对运行环境的三类需求：工具执行的隔离环境、承载 Agent Harness 的长时运行、面向 Agent 的服务底座。随后介绍 Cube Sandbox 的演进路径：2023 年前后为 Serverless 场景构建基于 RustVMM+KVM 的轻量虚拟机底座，具备百毫秒级冷启动、高并发与高密度能力；Agent 兴起后依次进入代码执行/数据分析、Agent RL 与 Agent Runtime 场景。文章重点梳理 v0.3 至 v0.6 版本如何补齐快照、克隆、回滚、出站治理、凭证托管、自动暂停唤醒、Arm 支持、Kubernetes 部署与 E2B 兼容 Volume 等能力，并展望跨节点迁移、系统层可观测性、Agent Teams 协作与风险边界扩展等下一代方向。

💡 主要观点

  1. Agent 需要专用运行环境，VM、容器、Serverless 都只解决部分问题。 沙箱在隔离边界、启动速度、资源密度与有状态能力之间取得平衡，更匹配 Agent 自主执行与长时任务的行为方式。
  2. Cube 的竞争力来自先有一套 Serverless 生产底座，再向 Agent 场景演进。 它不是 Agent 爆火后的新原型，而是 2023 年起为百毫秒冷启动、高并发、高密度设计的基础设施，经历过腾讯内部生产环境磨合。
  3. 生产级沙箱的关键是状态可恢复与行为可控。 v0.3 快照/克隆/回滚解决状态复制，v0.4 出站治理、凭证托管与网络审计为不可预测行为加边界，v0.5/v0.6 补自动休眠、Arm、Kubernetes 与 Volume 部署能力。
  4. Agent Infra 下一步将跨出单机沙箱，覆盖集群、系统层观测与多 Agent 协作。 跨节点迁移恢复、操作系统级审计、以 Agent 为主要使用者的服务设计，以及把安全边界扩展到整个生产系统，是团队给出的演进方向。

💬 文章金句

  • Agent 确实需要一种更好的、更先进的 Infra，而不是继续复用老式的 Infra。
  • 我们不希望干扰 Agent 的灵活性，因为泛化能力正是 AI 的价值；但它不可控的部分，还是要把边界管好。
  • 今天我们叫它 Sandbox，但它已经远远超出了一个沙盒。它代表的是一套 Infra 系统。
