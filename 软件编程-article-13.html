当 Agent 成为新的核心云用户：阿里云重新定义“用云范式”

6/26/2026, 6:06:00 AM

📌 一句话摘要

阿里云围绕 AI Agent 特性，通过 Gateway、3A 身份体系、Spec-driven Development 和 Skills 门户，系统性重塑云平台以支持 Agent 自主调用，定义 Agent 时代的用云范式。

📝 详细摘要

文章分析阿里云针对 AI Agent 自主规划、高批量、长任务特性推出的 Agentic Cloud 架构：Agent Gateway 处理行为不确定性，Agent 3A（可认证、可授权、可审计）解决身份信任问题，Agentic Skills 将 300+云产品、20000+API 封装为 Agent 可理解的标准化能力单元，并通过 Spec-Driven Development（SDD）在意图与执行间插入可确认、可校验的规格层。文章还讨论了开放标准（MCP、A2A）的重要性以及企业级 Agent 调云的可信、可控路径。

💡 主要观点

  1. Agent 成为新的云调用主体，传统 API 无法直接服务 Agent。 Agent 会理解意图、拆解任务、选择工具，但缺乏人类工程师的经验容错，需要接口附带场景、风险、前置条件和失败处置规则。
  2. 阿里云通过三层架构解决 Agent 调云的不确定性：Gateway、3A、Skills。 Gateway 管入口与行为；3A 管身份与权限；Skills 管能力表达与安全调用，使企业敢把部分云操作交给 Agent。
  3. Spec-Driven Development 是意图与执行间的稳定器。 Agent 不能从自然语言直接跳到执行，需先生成可确认的规格（Spec），转为 IaC 配置，经过校验预检后再受控执行，形成 Plan-Code-Validate-Execute 链路。
  4. 下一代云入口之争本质是开放标准之争。 阿里云接入 MCP、A2A 等开放协议，通过 Skills 门户和 Skill Forge 计划共建标准，避免 Agent 时代碎片化。

💬 文章金句

  • Agent 可以自动化，但不能无边界地自动化；Agent 可以自主执行，但必须被身份、权限、工具、风险和审计约束住。
  • 所有工具和能力，无论是 CLI、SDK、Terraform、MCP Server，还是网关、身份、权限和可观测，最终都是为了让云真正可靠地运转起来。
  • 这不是给智能套上枷锁，而是给智能划定一条能够被信任的边界——唯有可控，自动化才谈得上真正可用。
