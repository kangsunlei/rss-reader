repowise：为仓库建本地索引，减少 Agent 重复翻代码

9/22/2026, 10:00:06 AM

📌 一句话摘要

repowise 通过为代码仓库建立本地索引，把依赖关系、git 历史、测试与架构决策提前整理好，供 Agent 和开发者直接查询，作者在 django 仓库实测 Agent 工具调用从 7.2 次降到 3.8 次、输出减少 31.6%。

📝 详细摘要

针对 Claude Code 等 Agent 每次新任务都要重新翻文件、重复理解代码结构、浪费 token 的痛点，repowise 的思路是把这些工作提前做一次：为仓库建立本地索引，纳入代码依赖关系、git 历史、测试、文档和架构决策。它向 Claude Code、Codex、Cursor 提供 10 个按任务设计的 MCP 工具，例如「改了这个文件会影响谁」可直接给出带引用的答案。作者在 django 仓库上用 43 个问题做对比，Agent 工具调用从 7.2 次降到 3.8 次，输出减少 31.6%，样本、方法与失败案例均公开。此外还提供改动前 0 到 10 的风险分、51 个代码健康检测器与可执行的重构方案，支持 26 种语言，建图与风险计算不调用大模型、无需 API Key，索引留在本地。

💡 主要观点

  1. 用本地索引替代 Agent 的重复探索，直接降低 token 与调用成本 把依赖关系、git 历史、测试、文档和架构决策预先索引，Agent 无需每次重新翻文件；作者在 django 仓库 43 个问题上的对比显示工具调用从 7.2 次降至 3.8 次、输出减少 31.6%，且样本与方法公开可核对。
  2. 以 MCP 工具形式接入主流编程 Agent，降低使用门槛 为 Claude Code、Codex、Cursor 提供 10 个按任务设计的工具，把「改了这个文件会影响谁」这类问题变成带引用的直接答案，而不是让模型自行推断。
  3. 把改动前的风险与代码健康评估做成可量化、可执行的输出 按仓库自身近期提交分布给出 0 到 10 的风险分，列出受影响的调用方、应跑的测试和历史上常一起改的文件；51 个检测器分别评估缺陷风险、可维护性与性能，并给出可直接交给 Agent 的重构方案。
  4. 本地化与免模型调用是其主要工程取舍 支持 26 种语言，建图、算风险、查健康度、找死代码均不调用大模型、不需要 API Key，索引留在本机，一条命令安装并提供免费 PR 机器人。

💬 文章金句
