Cloudflare 推出面向智能体的 Markdown 和内容信号，旨在引导 AI 爬虫

3/5/2026, 7:19:00 AM

📌 一句话摘要

Cloudflare 推出了“面向智能体的 Markdown”以降低 AI Token 成本，并发布了“内容信号”让发布者能够精细化控制 AI 爬虫对其数据的使用。

📝 详细摘要

Cloudflare 的新举措旨在弥合传统网页内容与 AI 消费之间的鸿沟。“面向智能体的 Markdown”允许 AI 机器人通过“Accept: text/markdown”标头请求网页的简化 Markdown 版本，从而显著降低 Token 使用量——例如，将一篇 HTML 格式的博客文章从 16，180 个 Token 缩减至 Markdown 格式的 3，150 个。与之配套的是“内容信号”，这是一项针对 robots.txt 的提案，允许发布者指定内容是否可用于搜索、实时 AI 输入或模型训练。尽管 Cloudflare 宣传此举能提升 RAG 流水的效率，但 Google 的 John Mueller 等批评者认为，剥离 HTML 会移除关键的上下文，且 LLM 已经具备解析复杂结构的能力。此举正值整个行业在 AI 抓取、许可和变现问题上展开激烈博弈之际。

💡 主要观点

  1. 面向智能体的 Markdown 通过剥离非语义化的 HTML，显著降低了 LLM 的 Token 开销。 通过在边缘侧将复杂的 HTML 转换为简洁的 Markdown，Cloudflare 将网页的 Token 数量减少了高达 80%，使 RAG 流水线更具成本效益且更高效。
  2. 内容信号为发布者提供了一种标准化（尽管非强制性）的方式来表达 AI 数据使用偏好。 该提案在 robots.txt 中引入了如“ai-train”和“ai-input”等特定标签，允许网站所有者针对不同类型的 AI 处理和索引表达其许可意愿。
  3. 行业专家对于是否应专门为 AI 智能体重新设计网页存在分歧。 批评者认为 LLM 已经能够解析 HTML，而将页面扁平化为 Markdown 会移除对理解网页内容至关重要的结构化上下文和导航线索。
  4. 该举措反映了 AI 公司与内容创作者之间在数据价值和补偿问题上日益加剧的紧张关系。 随着发布者越来越多地屏蔽 AI 爬虫或寻求变现，Cloudflare 的工具代表了一种尝试，旨在为受控的、机器友好的访问建立技术上的中间地带。

💬 文章金句

  • 一个简单的 Markdown 标题大约消耗 3 个 Token，但等效的 HTML 标记则需要 12–15 个 Token。
  • 该公司表示，一篇在 HTML 格式下需要 16，180 个 Token 的博客文章，转换为 Markdown 后会缩减至约 3，150 个 Token。
  • John Mueller 质疑 LLM 爬虫是否会将 Markdown 仅仅视为纯文本文件，以及它们是否能正确追踪链接。
  • 面向智能体的 Markdown 是否能成为广泛采用的标准……将取决于 AI 平台如何回应这些信号，以及发布者是否能从中看到价值。
