黄仁勋给 AI 热潮泼冷水：接入 AGI，公司也不会一夜之间提高效率，大模型只是“大脑”，Agent 还要先装上“外骨骼”

9/3/2026, 9:30:00 AM

📌 一句话摘要

黄仁勋在 G20 会议提出：AGI 接入企业不会自动解决问题，大模型只是「大脑」，还需 Agent Harness「外骨骼」工程体系；任务会被自动化，但工作职责和判断不能外包。

📝 详细摘要

黄仁勋在 2026 年 9 月 2 日 G20 创新部长级会议上将 Agent 比作刚从 MIT 毕业的博士新人——聪明但需要入职培训。他提出企业接入 AGI 后仍需投入大量精力完成「入职」：提供上下文、目标、相关知识和访问权限。真正让 AI 有用的不是模型本身，而是套在大模型外面的 Agent Harness——负责检索知识、工作记忆、工具调用和协作。当 Agent 从数字工具延伸到物理系统时，幂等、超时、重试等传统工程概念变为安全要求。黄仁勋强调企业使用 Anthropic、OpenAI、Cursor 等现成产品没问题，但不能把所有智能外包；需要留在自己手里的是一切知识入口、工具接口、权限规则和评测集。最终判断：具体任务会被 AI 自动化，但工作的目的和责任不会消失。

💡 主要观点

  1. AGI 不会让企业效率一夜提升，需要像培养新人一样给 Agent「入职」 黄仁勋用 MIT 博士新人比喻：即使模型能力很强，进入企业仍需要上下文、目标、相关信息和访问权限。公司内部未文档化的约定、业务规则、依赖关系都需要团队主动交付给 Agent。
  2. 大模型只是「大脑」，必须加上 Agent Harness「外骨骼」才能干活 Agent Harness 负责检索知识、保存工作记忆、调用工具、支持多 Agent 协作。以开发场景为例，模型能理解「修复登录超时」，但找到入口、读日志、搜提交、跑测试、改文件、看失败信息再继续调整——每一步都依赖模型之外的工程系统。
  3. Agent 进入物理系统后，错误后果从可撤回升级为安全风险 浏览器 Agent 点错按钮通常能撤回，但机械臂重复执行可能损坏物料，实验室设备读到过期状态可能在错误条件下启动。传统的幂等、超时、重试在物理系统里变成安全要求，状态校验和执行控制必须由工程系统负责。
  4. 企业不能把所有智能外包，需保留知识入口、权限规则和评测集 黄仁勋承认 NVIDIA 使用 Anthropic、OpenAI、Cursor 等现成产品，但强调通用模型可以更换，内部系统的含义不能随供应商一起换掉。如果业务规则散落在提示词里，迁移成本极高。
  5. 任务会被自动化，但工作的目的和责任不会消失 软件工程师的任务（写代码、查日志、修 Bug）会被 AI 接走，但岗位存在的目的是让系统解决问题并稳定运行，这个目的不变。需求选错、测试遗漏、部署影响旧数据，责任仍在团队。
