用于密码管理和 TOTP 验证的 Python 库

6/20/2026, 8:27:33 AM

📌 一句话摘要

本文介绍了一个纯 Python 开发的本地密码管理与 TOTP 两步验证工具 jkey，强调轻量、零外部依赖（除二维码扫描外）和本地加密存储。

📝 详细摘要

作者因不满谷歌验证器和 1Password 的「重量级」与对第三方服务的依赖，使用 Python 开发了 jkey 工具。文章详细介绍了其四大模块：2FA 模块（管理 TOTP 两步验证账号，兼容 RFC 6238，支持从二维码图片导入）、RC 模块（管理恢复码）、PM 模块（密码生成与存储）和 PV 模块（保险库管理，含加解锁、加密/解密文件、数据导出）。工具使用 AES-256-CBC + HMAC-SHA256 加密，所有数据存储在本地 `~/.config/jkey/` 目录。作者还坦诚讨论了实现中的技术细节（如模块名以数字开头的导入问题）、设计取舍（密码明文输出）和当前不足（纯 Python AES 速度慢、opencv 依赖体积大、仅测试于 ArchLinux）。

💡 主要观点

  1. jkey 是一个纯 Python、本地优先的密码与 2FA 管理工具。 使用 AES-256-CBC 加密，所有数据存储在本地 `~/.config/jkey/`，不依赖任何第三方云服务，强调轻量与隐私。
  2. 工具包含 2FA、恢复码、密码管理和保险库四大模块。 2FA 模块兼容 RFC 6238，支持从二维码图片导入；RC 模块管理恢复码；PM 模块生成和存储密码；PV 模块负责保险库的加解锁、文件加密与数据导出。
  3. 作者坦诚讨论了设计取舍与技术局限。 如密码明文输出（简化使用流程）、纯 Python AES 实现速度慢（仅适合小文件）、opencv 依赖体积大、当前仅支持 Linux。

💬 文章金句

  • 之前一直用谷歌验证器和 1Password ，但总感觉太重了，而且总会依赖别人的服务，后来想了想，我的需求其实很简单，最主要就是两步验证 2FA ，没必要搞那么复杂。
  • 密码以明文形式打印到终端，设计上倾向于简单直接，既然你问密码就是要用，那就不搞掩码这种多余的操作了。
  • 纯 Python AES 速度慢是硬伤。加解密大文件的时候能感觉到明显延迟，所以只适合小文件。
