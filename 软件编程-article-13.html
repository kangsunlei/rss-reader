精打细算虾养成指南：省 Token 和把 AI 用好，从来就是一件事

7/8/2026, 9:36:00 AM

📌 一句话摘要

本文提出通过上下文管理、提示工程与子智能体架构，在保证 AI 效能的前提下降低 Token 消耗，实现工程化用 AI。

📝 详细摘要

文章深入探讨了在 AI Agent 使用中如何通过结构化方式替代蛮力输入，从而节省 Token 并提升效果。作者从上下文膨胀与 Context Rot 的成因出发，提出了最小上下文、JIT 检索、Prompt Caching、约束式提示词以及会话三阶段生命周期管理等策略。针对复杂任务，文章详细介绍了主虾+子虾的架构设计，强调通过任务拆分粒度与模型选型来降低成本，核心观点是省 Token 与用好 AI 本质上是同一件事。

💡 主要观点

  1. 上下文膨胀与 Context Rot 是导致 AI 变笨和成本增加的主因。 Transformer 架构中注意力机制随上下文长度呈平方级增长，导致信息稀释，必须通过工程化管理上下文来维持效果。
  2. 采用 JIT 检索与分层存储替代全量输入。 参考代码库索引方案，只维护轻量索引，按需读取；将上下文视为计算机存储系统，区分缓存、内存与硬盘，实现上下文卸载。
  3. 通过约束式提示词减少反复拉扯。 花时间定义清晰的目标和约束（而非堆砌规则），使用 One-Shot 示例，能让 AI 一次到位，大幅降低返工和无效 Token 消耗。
  4. 使用主 Agent + 子 Agent 架构处理复杂任务。 主 Agent 负责决策与调度，子 Agent 执行原子任务，利用便宜模型并行处理，避免强模型上下文积压，成本可降至 20%-30%。

💬 文章金句

  • 真正的省 token 不是削减投入、不是降低预算，而是在保证效率和产能的前提下，用结构化的方式替代蛮力输入。
  • 省 token 和把 AI 用好，就是同一件事。
