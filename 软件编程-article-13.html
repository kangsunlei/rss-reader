OpenJDK 进展报告：密钥派生、作用域值、紧凑标头、JFR 方法计时与追踪

5/19/2025, 12:00:00 AM

📌 一句话摘要

本文总结了 OpenJDK 在 2025 年 5 月 12 日当周的更新，重点关注与 JDK 25 发布准备相关的 JEP 状态变化。

📝 详细摘要

本文综述了 OpenJDK 生态系统在 2025 年 5 月 12 日当周的重要活动，重点关注即将发布的 JDK 25 的 Java 增强提案 (JEP) 的进展。文章详细介绍了密钥派生函数 API (JEP 510) 和作用域值 (JEP 506) 这两项 JEP，它们已被提升到“已定目标”状态，并提议最终确定。此外，紧凑对象头 (JEP 519)、提前编译方法分析 (AOT Method Profiling， JEP 515)、提前编译命令行优化 (AOT Command-Line Ergonomics， JEP 514)、模式中的原始类型、instanceof 和 switch 这四项 JEP 已进入“提议定为目标”阶段。同时，JFR 方法计时与追踪这项新的 JEP 已达到“候选”状态。随着发布流程进入降速第一阶段，文章还列出了当前包含在 JDK 25 功能集中的 13 项 JEP，并确认 JDK 25 将是继 JDK 21、JDK 17、JDK 11 和 JDK 8 之后的下一个长期支持 (LTS) 版本。

💡 主要观点

  1. 作用域值和 KDF API 等关键 JEP 已被确定为 JDK 25 的最终目标。 作用域值 (JEP 506) 解决了虚拟线程的线程局部数据共享问题，密钥派生函数 API (JEP 510) 标准化了密码密钥派生，体现了平台关键功能的成熟度。
  2. 多个以性能为中心的 JEP 正在朝着纳入 JDK 25 迈进。 紧凑对象头 (JEP 519) 减少了内存开销，而提前编译方法分析 (AOT Method Profiling， JEP 515) 和提前编译命令行优化 (AOT Command-Line Ergonomics， JEP 514) 旨在缩短应用程序启动时间，表明了对 JVM 效率的关注。
  3. 模式中的原始类型等语言增强功能将继续进行预览周期。 JEP 507 正在经历第三次预览，展示了 Java 在模式匹配功能方面的迭代改进，旨在提高代码的表达能力。
  4. JDK 25 已被确认为下一个长期支持 (LTS) 版本。 将 JDK 25 指定为 LTS 版本，为计划使用相应 Java 版本的企业和项目提供了稳定性和长期支持，突显了其在发布周期中的重要性。

💬 文章金句

  • 两项 JEP 已从“提议定为目标”提升为 JDK 25 的“已定目标”。
  • 此功能引入了密钥派生函数 (KDF) 的 API，这是一种使用密码算法从密钥和其他数据派生密钥的技术。
  • 该特性之前被称为“范围局部变量(孵化器)”，它支持在线程内部和跨线程共享不可变数据。
  • 该 JEP 提议通过“使 HotSpot JVM 启动时能够立即使用应用程序先前运行的方法执行分析数据”来改善应用程序的预热时间。
  • JDK 25 被指定为继 JDK 21、JDK 17、JDK 11 和 JDK 8 之后的下一个长期支持 (LTS) 版本。
