Spring Modulith 1.4 正式版，1.3.6 和 1.2.13 已发布

5/28/2025, 12:00:00 AM

📌 一句话摘要

Spring Modulith 1.4 正式版发布，在核心功能、测试、事件处理、运行时环境和可观测性等方面均有更新和改进。

📝 详细摘要

Spring 团队宣布 Spring Modulith 1.4 正式发布，经过六个月的开发，同时发布了 Bug 修复版本 1.3.6 和 1.2.13。1.4 版本引入了重大增强，包括对核心应用模块抽象的改进，用于以编程方式检测命名接口的 SPI（服务提供者接口），以及性能修复。测试能力得到改进，通过 `@ApplicationModuleTest` 进行集成测试时，现在可以使用来自测试源的 Bean，并且当 AssertJ 库存在时，支持使用 `AssertablePublishedEvents` 实例进行断言。事件发布基础设施已更新，可以处理结构上相同的事件，并且具有性能改进。运行时支持已重构，以移除拓扑排序的外部依赖，从而实现稳定的模块顺序，并避免在运行时完全初始化 `ApplicationModules`。迁移到 Micrometer 观测 API 后，并通过 `ModulithEventMetrics` API 引入了应用程序事件的自动计数器，从而增强了系统的可观测性。此版本还包括 Spring Boot 3.5、Spring Framework 6.2 和 ArchUnit 1.4 的依赖项升级。接下来是即将发布的 2.0 主要版本的准备工作。

💡 主要观点

  1. 改进的运行时支持移除了模块排序对外部依赖的需要。 通过内部化拓扑排序逻辑，消除了对外部库的运行时依赖，从而可能简化项目的依赖关系图并改善启动。
  2. 现在，通过 `@ApplicationModuleTest` 进行集成测试时，可以使用来自测试源的 Bean。 此增强功能使开发人员在设置使用特定于测试的配置和组件的应用程序模块集成测试时，具有更大的灵活性和控制权。
  3. 事件发布基础结构已更新，可以处理结构上相同的事件。 此功能解决了一个潜在问题，即具有相同结构但可能具有不同语义含义的事件可能会被事件系统混淆或错误处理。
  4. 引入 Micrometer 观测 API 及自动事件指标。 迁移到现代 Observations API 提供了更精细的监控功能。已发布事件的自动计数器提供了对模块交互的开箱即用可见性。
