OpenCode 2.0 正式发布：一次“重大改造”

10/17/2026, 6:00:00 AM

📌 一句话摘要

OpenCode 2.0 彻底重写，运行时从 Bun 切回 Node.js、桌面端从 Tauri 换回 Electron，插件与服务器 API 全面重构，旧插件全部报废。

📝 详细摘要

开源编程 Agent OpenCode 在经历三个月 Beta 后发布 2.0 稳定版，官方称之为“一次重大改造”。核心变化是技术栈推倒重来：运行时从 Bun 切换回 Node.js，桌面端从 Tauri 换回 Electron，理由是 Node.js 在 Windows 上更稳定、Electron 可内嵌服务、Bun 的性能优势未带来实际收益。架构上，服务器作为统一后台进程常驻，终端、浏览器和桌面界面共享同一底层服务，API 从头重新设计，Agent 可创建 Git 工作树、转移或中断会话。Code Mode 成为所有 MCP 服务器的默认模式，Agent 通过编写 JavaScript 脚本一次调用多个工具，官方称可接入上千个 MCP 服务器而只增加极少上下文开销。插件系统被提升为核心，内部已有 80 多个插件并支持热重载，但 1.x 第三方插件、旧服务器 API 集成全部失效，LSP 诊断和 CLAUDE.md 支持也被移除。文章最后讨论了 OpenCode 与闭源 Claude Code 的路线差异，以及国内分叉项目面临的同步重构难题。

💡 主要观点

  1. OpenCode 2.0 以工程稳定性为由放弃 Bun 和 Tauri，回归 Node.js/Electron 官方称 Node.js 在 Windows 上稳定得多，Electron 可直接嵌入桌面应用而无需独立进程，且基准测试显示 Bun 的微弱性能领先并未带来明显收益，因此用体积换取跨平台稳定性。
  2. 服务器成为常驻后台进程，统一支撑终端、浏览器和桌面多界面 开发者可在终端启动会话后用桌面或网页应用继续处理，脚本能自动发现本地服务执行定时任务，也可将服务开放给其他设备，Agent 从被动插件变为可编程控制的常驻进程。
  3. Code Mode 将工具调用转为脚本执行，缓解 MCP 工具膨胀带来的上下文压力 传统模式下每个工具的名称、描述和参数 Schema 都会预先进入上下文，接入几十台服务器就会淹没模型注意力；Code Mode 让 Agent 按需发现工具并组合进 JavaScript 脚本，官方称可同时接入 1000 个 MCP 服务器。
  4. 插件系统重做带来三项破坏性变更，1.x 生态被强制迁移 插件底层 API 全面革新、服务器 API 及客户端采用全新约定、终端配置从 tui.json 迁移到 cli.json；旧逻辑插件必须对照新接口重写，外部脚本调用旧版服务器的工作流也需重写。
  5. 2.0 移除 LSP 诊断和 CLAUDE.md 支持，升级需按工作流谨慎决策 运行时不再启动语言服务器，官方建议改用项目本地的代码检查工具；同时只读取 AGENTS.md。依赖 LSP 诊断的团队应暂留 1.x，维护逻辑插件或深度调用服务器 API 的团队需先在沙箱完成迁移。

💬 文章金句

  • 我们不得不推倒重来。这个决定和过程都很痛苦，也让我们落后了不少。但现在，我们打好了基础，可以试着做出点好东西。
  • 旧 API 是在我们和整个行业逐渐理解 Agent 是什么的过程中，杂乱无章地发展起来的。它做得很糟糕。
  • 2.0 中，所有 MCP 服务器默认都会启用 Code Mode。这意味着你可以接入上千个 MCP 服务器，同时只增加极少的上下文开销；Agent 会自行发现并组合这些服务器提供的工具来完成任务。
  • 当竞争的壁垒从“谁的模型更聪明”转移到“谁的运行时更硬核”时，OpenCode 2.0 无疑砸下了最重的一颗筹码。
