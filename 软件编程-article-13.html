HCP Terraform 现在为工件加密提供自有密钥 (HYOK) 选项

8/18/2025, 12:00:00 PM

📌 一句话摘要

HCP Terraform 现在为工件加密提供自有密钥 (HYOK) 选项，使客户能够完全控制其加密密钥，从而增强安全性和合规性。

📝 详细摘要

本文宣布 HashiCorp 的 HCP Terraform 正式提供自有密钥 (HYOK) 支持。这是一项关键功能，旨在让客户完全控制加密密钥，从而保护敏感的 Terraform 工件，例如状态文件和计划文件。现在，加密过程发生在客户网络中，使用客户控制的密钥（通过 Vault、AWS KMS、Azure Key Vault 或 Google Cloud KMS）。这确保了明文密钥不会离开客户环境，从而避免通过 HashiCorp 的基础设施。这显著提高了安全性，并帮助组织遵守严格的数据主权法规。该工作流程涉及一个轻量级代理，在传输之前在本地加密工件，生成完全加密和脱敏的版本以供平台操作。本文还强调了 HashiCorp 的 HYOK 在基础设施即代码 (IaC) 领域的独特性，专门针对 Terraform 状态文件和计划文件，并提供无缝的多云 KMS 集成，使其与来自其他主要云提供商和 Salesforce 的类似 CMEK/HYOK 产品区分开来。此功能适用于高级层 HCP Terraform 客户，提供增强的灵活性、可观察性和符合企业级标准的能力。

💡 主要观点

  1. HYOK 授予客户对其敏感 Terraform 工件的加密密钥的完全控制权。 通过使用客户控制的密钥，而非平台管理的密钥，HYOK 增强了数据安全性。它确保密钥不会以明文形式离开客户网络，从而满足严格的合规性和数据主权要求。
  2. HYOK 工作流程在传输之前在客户网络中加密工件。 轻量级代理使用 OIDC 进行令牌交换，并使用客户管理的密钥实现本地加密。这会生成状态文件和计划文件的加密版本和脱敏版本，从而允许平台执行相关功能，同时保护密钥安全。
  3. HashiCorp 的 HYOK 独特地专注于具有多云 KMS 支持的基础设施即代码工件。 与其他供应商的 HYOK/CMEK 通常适用于通用平台数据不同，HashiCorp 的实施专门针对 Terraform 状态文件和计划文件，从而在各种云环境中的 IaC 安全领域提供了独特的优势。

💬 文章金句

  • 此功能使客户可以完全控制用于保护敏感 Terraform 工件（如状态文件和计划文件）的加密密钥。
  • 借助 HYOK，现在可以在工件离开客户网络之前进行加密，并使用存储在客户控制的 Vault、AWS KMS、Azure Key Vault 或 Google Cloud KMS 中的密钥。
  • HYOK “使客户可以更好地控制对 Terraform 工件中密钥的访问”，并显著增强了安全性和合规性。
  • HashiCorp 的 HCP Terraform HYOK 的不同之处在于，它专注于 Terraform 状态文件和计划文件，在工件离开客户网络之前对其进行加密，并无缝支持多云 KMS 系统（Vault、AWS、Azure、GCP）。
