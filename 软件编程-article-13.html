📌 一句话摘要

ReSharper 2025.2 通过独立进程执行、优化的重构、更快的加载速度和即时导航，显著提升性能与响应性。

📝 详细摘要

ReSharper 2025.2 提供了多项性能增强，旨在直接解决开发者面临的常见问题，并提高其生产力。 新的独立进程 (Out-of-Process， OOP) 模式将 ReSharper 与 Visual Studio 隔离，有效减少了令人沮丧的输入延迟，并提高了整体稳定性。 针对 Razor/Blazor 支持的重大优化，最大限度地减少了内存流量，并加速了“查找引用”等操作，使 Web 项目的开发更加顺畅。 核心重构，特别是“重命名”，现在速度更快，并提供更清晰的反馈，受益于并行处理和更小的内存占用，从而消除了延迟。 就地重构现在是非阻塞和异步的，允许开发人员在复杂操作期间立即输入，而不会中断。 此外，通过优化现代 SSD 的文件 I/O 和简化后台进程，解决方案加载和初始索引得到了显著加速，从而减少了等待时间。 一种新的“提前跳转”模式通过在完整解决方案索引完成之前实现即时文件导航来彻底改变启动过程，从而大大缩短了感知的启动时间，并让开发人员能够立即在大型项目上提高工作效率。

💡 主要观点

  1. 独立进程执行显著提升了 ReSharper 的性能和稳定性。 通过在与 Visual Studio 不同的进程中运行 ReSharper，新的 OOP 模式直接解决了输入延迟问题，提供了更流畅、更快速的编码体验，同时还增强了整体 IDE 的稳健性。
  2. 异步并行处理大大提高了开发人员的工作流程效率。 非阻塞就地重构（允许立即输入而不会中断）和并行“重命名”操作等功能，结合针对 SSD 优化的文件读取以加快解决方案索引速度，共同减少了等待时间，并提高了关键开发任务期间的响应速度。
  3. “提前跳转”模式使开发人员能够立即在大型解决方案上提高工作效率。 这种创新的启动模式允许开发人员即使在完成完整解决方案索引之前也能立即导航和搜索文件，从而有效地消除了等待时间，并显著缩短了感知的启动时间，从而使用户能够更快地提高工作效率。

💬 文章金句

  • ReSharper 2025.2 是第一个支持在独立进程 (OOP) 中运行 ReSharper 的稳定版本，与 Microsoft Visual Studio 配合使用。
  • 最大的性能提升来自并行化验证可疑引用的阶段。
  • 现在，ReSharper 允许用户立即开始输入，并在后台完成编辑后的所有分析工作。
  • 我们取消了对 ReSharper 的旧限制，因此它现在可以充分利用您的 SSD 的功能，一次读取多个文件以加快启动速度。
  • 在大型解决方案上，此改进可以将您的有效启动时间最多减少一整分钟。
