理解 Tree Shaking：原理与那些“甩不掉”的代码陷阱

📌 一句话摘要

文章深入解析了前端构建中 Tree Shaking 的原理、必要条件，并结合代码示例详细阐述了导致其失效的常见陷阱及解决方案。

📝 详细摘要

本文详细介绍了前端优化技术 Tree Shaking。首先阐述了其作为静态分析技术的工作原理、必须使用 ES Module 以及生产模式构建的前提条件。随后，通过多个代码示例，深入剖析了 Tree Shaking 常见的失效场景，包括使用 CommonJS 模块、聚合导出对象、通过间接引用（如`export default *`）转发模块、以及含有副作用的模块。针对每个失效场景，文章均给出了清晰的建议修复方式。最后，提供了通过查看构建产物体积和代码来验证 Tree Shaking 是否生效的方法，并总结了常见错误用法及其修复方案。文章内容全面且实用，对前端开发者优化项目构建体积具有很高的指导价值。

💡 主要观点

  1. Tree Shaking 依赖 ES Module 的静态分析特性来移除死代码 Tree Shaking 是一种静态分析技术，它通过分析 ES Module 的导入导出关系，识别并移除未被实际引用的代码，从而减小最终打包体积。
  2. 多种动态语法和模块导出方式会阻碍 Tree Shaking 生效 CommonJS、导出聚合对象、间接引用、动态属性访问以及模块副作用等，都会因无法进行静态分析而导致 Tree Shaking 失效，增加不必要的代码体积。
  3. 理解并正确配置副作用模块是确保 Tree Shaking 彻底的关键 对于有副作用的模块，构建工具默认会保留，需要通过`package.json`中的`sideEffects`字段明确告知构建工具其行为，以实现更精细的优化。

💬 文章金句

  • Tree Shaking 是一种 **「静态分析（Static Analysis）」** 技术，用于在构建过程中移除未被引用的 ES 模块导出内容。
  • 你可能只用了 add，但由于 math 是整个对象，打包工具无法静态分析 math.sub 是否会在运行时被用到。因此它会**「保留整个模块」** 的内容（包括 sub）。
  • Tree Shaking 并不是魔法，而是一种依赖静态语法分析的工具优化手段。
