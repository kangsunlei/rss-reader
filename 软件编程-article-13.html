【早阅】这是前端的失落十年。开发者现在能做什么？

7/18/2025, 12:01:00 AM

📌 一句话摘要

文章指出前端开发过度依赖流行框架导致性能下降和用户体验欠佳，呼吁开发者回归工程本质，关注真实用户设备限制和平台原生能力。

📝 详细摘要

文章深入探讨了前端开发领域面临的严峻挑战，指出过去十年因过度依赖流行 JavaScript 框架而导致 Web 应用在真实用户体验和性能指标（如 Core Web Vitals）上表现不佳，称之为“失落的十年”。作者 Alex Russell 强调，工程师的职责是理解并适应硬件限制、网络条件和设备多样性，特别是市场边缘用户的旧款廉价设备。他认为 JavaScript 是 Web 上最慢的做事方式，呼吁开发者回归工程本质，关注用户体验，利用平台原生能力而非盲目追随流行工具，并通过测试验证成果，以提升 Web 生态系统的竞争力。

💡 主要观点

  1. 工程成功的衡量标准是最终产品对终端用户的表现，而非所用工具的流行度。 开发者不应盲目追随流行技术，而应以实际的用户体验和产品性能作为衡量开发质量的核心指标，确保技术选择服务于用户价值。
  2. 前端开发需充分理解并适应设备硬件、网络条件及设备多样性的真实限制。 忽视中低端设备和不稳定网络的用户体验，是导致 Web 应用性能欠佳的关键原因，开发者应针对这些普遍存在的限制进行优化。
  3. JavaScript 本质上是 Web 上最慢的编程方式，应作为连接底层库的管道而非计算核心。 随着摩尔定律的终结，依赖 JavaScript 的单线程性能提升已不再自动发生，开发者应尽可能利用浏览器原生能力和底层优化来提升性能。
  4. Web 核心生命指标的糟糕通过率表明当前流行工具未能有效提升用户体验。 许多被广泛宣传和采用的工具，实际上对网站性能产生了负面影响，开发者需要重新思考工具选择对用户体验的实际影响。
  5. 应对挑战需关注边缘用户质量，并以测试结果为导向。 开发者不应盲目接受工具建议，而应通过严格的测试来验证其对用户体验的实际影响，从而做出明智的技术决策。

💬 文章金句

  • 工程的适应性功能不是您的工具是否流行。工程的适应性功能是结果是否对最终用户，即您实际构建和设计的人员有效。
  • 这些工具在指标中玩弄用户体验。当指标变得更诚实，并试图更准确地反映用户整天所看到的一切时，那些投资于这些工具的人发现自己的麻烦比那些投资于更简单技术栈的人更多。
  • JavaScript 一直并将永远是 Web 上最慢的做事方式。
  • 不要接受任何关于您的工具和技术栈应该是什么样子的想法。进行测试。结果好吗？这才是唯一重要的事情。
