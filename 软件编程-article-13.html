开放式湖仓的新纪元：Apache Iceberg™ v3 在 Databricks 上开启公开预览

4/9/2026, 5:10:42 PM

📌 一句话摘要

Databricks 宣布公开预览支持 Apache Iceberg v3，集成了行血缘（Row Lineage）、删除向量（Deletion Vectors）和 VARIANT 数据类型等关键特性，旨在提升开放式湖仓架构的性能与互操作性。

📝 详细摘要

本文详细介绍了 Apache Iceberg v3 在 Databricks 平台上的集成，这标志着开放表格式的重大进步。通过支持行血缘和删除向量等原生特性，Databricks 实现了更高效的增量数据处理，减少了昂贵的全表重写需求。此外，VARIANT 数据类型的引入使得无需复杂的 ETL 流程即可直接摄取和查询半结构化数据。此次更新强调了 Databricks 对统一且受治理的湖仓架构的承诺，利用 Unity Catalog 提供跨引擎的互操作性和自动化性能优化，最终帮助企业消除数据孤岛并降低运营成本。

💡 主要观点

  1. 原生支持行血缘和删除向量。 这些特性通过追踪行级变更并逻辑标记删除，实现了高效的增量处理（CDC），与传统的写时复制（copy-on-write）方法相比，数据操作速度提升高达 10 倍。
  2. 引入用于半结构化数据的 VARIANT 数据类型。 VARIANT 允许直接在关系表中存储和查询不断演变的半结构化数据（如日志或 JSON 载荷），无需严格的模式强制或复杂的规范化流水线。
  3. 通过 Unity Catalog 实现统一治理与互操作性。 Databricks 利用 Unity Catalog 提供跨多个引擎和目录的统一治理层，实现了细粒度的访问控制以及 Delta Lake 和 Iceberg 生态系统之间的无缝数据共享。

💬 文章金句

  • 行血缘和删除向量共同使 CDC 成为表本身的一种原生属性。
  • Iceberg v3 的 VARIANT 类型解决了这一权衡问题。VARIANT 是一种原生列类型，可以在同一个 Iceberg 表中将半结构化载荷与关系列存储在一起。
  • Databricks 将智能维护、物理布局优化和跨引擎治理结合在一个层级中，无需任何手动配置。
