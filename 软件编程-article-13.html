MicroProfile 7.1 发布 Telemetry 和 OpenAPI 规范更新

6/27/2025, 12:00:00 AM

📌 一句话摘要

MicroProfile 7.1 推出社区主导的 Telemetry 和 OpenAPI 规范更新，在保持与 Jakarta EE 10 兼容的同时，增强了可观测性和 API 文档功能。

📝 详细摘要

MicroProfile 工作组发布了 MicroProfile 7.1，更新了两个社区开发的核心 API：Telemetry 2.1 和 OpenAPI 4.1。Telemetry 规范现在包含对 Awaitility 4.2.2 的依赖升级，并改进了 ThreadCountHandler 的指标收集功能；而 OpenAPI 则新增了 jsonSchemaDialect() 方法并优化了 Extensible 接口。该版本继续保持与 Jakarta EE 10 核心规范集的七个标准的兼容性，支持微服务开发。本文详细介绍了这些技术更新，以及自 2016 年以来由各大科技公司和 Java 用户组共同推动的这一倡议的发展历程。

💡 主要观点

  1. 社区主导开发的 Telemetry 2.1 和 OpenAPI 4.1 规范更新 体现了 MicroProfile 开发的协作特性，同时提供了实质性的技术改进
  2. Telemetry 2.1 通过新增指标和 JDK 23 支持强化了 OpenTelemetry 集成 ThreadCountHandler 的改进和 Awaitility 升级为现代 Java 环境提供了更强大的可观测性能力
  3. OpenAPI 4.1 新增 jsonSchemaDialect() 方法并优化接口文档 通过标准化模式支持提升 API 文档渲染精度和开发者体验
  4. 保持与 Jakarta EE 10 核心规范集的七个标准的一致性 确保与 CDI、JAX-RS、JSON-P 等企业 Java 基础标准的兼容性
  5. Jakarta EE 10 核心规范集专为微服务和 AOT 编译优化 展现了 MicroProfile 对现代部署场景和性能优化的重视

💬 文章金句

  • MicroProfile Telemetry 采用了云原生计算基金会(CNCF)的 OpenTelemetry 规范，使 MicroProfile 应用程序能够利用追踪、日志、指标和上下文传递数据等可观测性功能。
  • MicroProfile Telemetry 2.1 的新特性包括：升级至 Awaitility 4.2.2 依赖，支持在 JDK 23 上运行 TCK；以及改进 ThreadCountHandler 类的指标收集，确保文本描述的一致性。
  • MicroProfile OpenAPI 4.1 包含：在 OpenAPI 接口中定义的 jsonSchemaDialect() 方法，用于渲染 jsonSchemaDialect 字段；以及对 Extensible 接口的小幅优化，在 Javadoc 中添加了 @since 标签。
  • Jakarta EE 10 核心规范集包含七个专门为适合微服务和 AOT 编译的轻量级运行时设计的规范。
