Scala 插件中的 Scala 3.8 支持 | IntelliJ Scala 插件博客

1/15/2026, 12:08:14 PM

📌 一句话摘要

JetBrains 的 Scala 插件现已支持即将到来的 Scala 3.8 特性，包括 `into` 修饰符、JDK 17 要求、"更好的 for 推导" 和基础捕获检查，支持早期测试和反馈。

📝 详细摘要

这篇来自 JetBrains IntelliJ Scala 插件博客的文章宣布了其 Scala 插件对 Scala 3.8 的支持。文章重点介绍了 Scala 3.8 引入的几个关键特性，例如用于类型包装和隐式转换的新 `into` 修饰符、最低 JDK 要求更新至版本 17，以及对 for 推导语法的重大放宽（称为 "更好的 for 推导"）。此外，文章还提到了对捕获检查的基础实验性支持，以及用于豁免表达式某些静态编译器检查的 `runtimeChecked` 方法。文章强调这些更新允许开发者立即测试新特性，为插件和 Scala 编译器团队提供宝贵反馈，并暗示未来更新中将进一步改进对 Scala 3 的支持。

💡 主要观点

  1. Scala 插件引入对 Scala 3.8 新 `into` 修饰符的支持，促进灵活的隐式转换。 `into` 修饰符允许类型包装（`into[T]`）接受可隐式转换的类型而无需显式导入，或者可以应用于类型以全局允许隐式转换，插件会推断类型并高亮错误。
  2. Scala 3.8 要求 JDK 17 或更高版本，这一要求现已集成到 Scala 插件的项目设置和错误检测中。 插件的 New Project Wizard 会警告选择 Scala 3.8 但使用旧版 JDK 的用户，并且在 JDK <17 上编译 Scala 3.8 的现有项目将收到错误通知，确保兼容性。
  3. Scala 3.8 放宽了 for 推导的语法，允许生成器之前的别名，提高了代码可读性。 这个被称为 "更好的 for 推导" 的特性自动将 for 推导中的前置别名转换为值，简化了先前受限的语法（别名必须跟在生成器之后或在外部定义）。
  4. 插件提供对捕获检查的基础实验性支持，改进了标准库的导航。 随着 Scala 标准库现在使用 Scala 3.8 的捕获检查进行编译，插件确保对捕获相关代码的无错误导航、类型信息显示和跳转到声明功能。
  5. 新的 `runtimeChecked` 方法允许开发者绕过某些编译时静态检查。 在表达式后附加 `.runtimeChecked` 会禁用静态检查（如模式匹配穷尽性警告），让开发者对编译器行为有更多控制，插件完全支持此功能。

💬 文章金句

  • 这是特性冻结前的最后一个主要版本。下一个版本 3.9 将是新的长期支持版本。
  • Scala 语法中有一个新的修饰符 `into`，可以以两种方式使用：作为类型的包装器，或作为类、特质、不透明类型别名和枚举类型前的软关键字。
  • 在新的 Scala 版本中，最低要求的 JDK 版本已更新至 17。
  • "更好的 for 推导" 作为特性名称可能听起来有点别扭，但它为 Scala 的 for 推导引入了重要且期待已久的语法放宽。
  • `runtimeChecked` 方法是在 `scala.Predef` 中定义的扩展方法，可以在任何表达式上调用。当表达式以 `.runtimeChecked` 结尾时，它会豁免编译器中的某些静态检查，例如模式匹配穷尽性检查。
