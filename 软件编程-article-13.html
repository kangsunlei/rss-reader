Kimi 坐上全球程序员的工位！GitHub Copilot 模型菜单中第一次出现开放权重模型

7/3/2026, 7:35:00 AM

📌 一句话摘要

Kimi K2.7 Code 成为 GitHub Copilot 中首个开放权重模型，标志 Copilot 从单一助手向多模型调度入口转变。

📝 详细摘要

文章报道了 Kimi K2.7 Code 正式集成到 GitHub Copilot 的消息，成为 Copilot 模型菜单中首个开放权重模型。文章详细介绍了模型部署方式（Azure 托管、用量计费）、推送计划（个人版优先、企业版需管理员启用），以及 Kimi 的定位（侧重长链路编码任务，256K 上下文，高速度）。作者分析认为，Copilot 正从默认助手变为多模型入口，旗舰模型处理复杂判断，小型模型承担日常编码，两者分工协作。文章还引用了 Hacker News 上的社区讨论，反映出开发者对成本、稳定性、长期可用性的关注。最后指出，AI 编程进入多模型时代，开发者的工程判断将拓展到模型选择。

💡 主要观点

  1. Kimi 成为 Copilot 首个开放权重模型，Copilot 走向多模型调度。 此前 Copilot 仅提供闭源旗舰模型，Kimi 的加入意味着平台开始支持不同定位的模型，开发者可根据任务选择合适模型。
  2. Kimi 定位为高频、低成本的长代码任务执行模型。 侧重工程脏活（读仓库、改代码、补测试），而非追求榜单第一，适合日常编码，降低旗舰模型调用成本。
  3. 企业需额外管理模型权限与成本，模型进入 Copilot 即纳入治理流程。 企业默认不开启，管理员需手动启用，关注账单、合规和团队使用策略。
  4. AI 编程进入多模型时代，选模型成为新的工程判断。 开发者需要根据任务复杂度、上下文长度、成本等因素决定使用哪个模型，而非只依赖一个最强助手。

💬 文章金句

  • Copilot 不再只卖一个最强助手，而是在变成一个多模型调度入口。
  • AI 编程进入多模型时代以后，选模型会变成新的工程判断。
  • Model serving is becoming a model menuing system.
