Grab 通过 Temporal 提升订阅平台性能，告别 SQS 和 Redis

7/21/2025, 12:00:00 AM

📌 一句话摘要

Grab 成功地将其 GrabUnlimited 订阅平台从 SQS/Redis 迁移到 Temporal，大幅提高了系统稳定性和可扩展性，并将生产事故减少了 80%。

📝 详细摘要

Grab 的 GrabUnlimited 订阅平台在其原始架构中面临着严重的可扩展性和可靠性挑战，该架构依赖于 Amazon RDS、SQS 和 Redis。问题包括会员状态损坏、自动续订失败和系统中断，主要原因是效率较低的每日定时任务、Redis 锁限制以及缺乏强大的重试机制。为了解决这些问题，Grab 选择用基于 Temporal（一个开源工作流编排引擎）的新架构替换现有系统。此次迁移利用了 Temporal 的内置功能，例如用于分布式续订的定时器、用于并发的工作流 ID 重用以及弹性机制（如无限重试和指数退避）以确保幂等性并保护外部服务。这一战略转变使生产事故减少了 80%，并使工程团队能够更加专注于产品创新，而不是底层基础设施。

💡 主要观点

  1. 原始架构面临着快速增长的订阅服务的严重可扩展性和可靠性问题。 依赖每日定时任务进行续订、有限的 Redis 锁以及不足的 SQS 重试机制导致了性能瓶颈、数据损坏和频繁的系统中断，严重影响了用户体验。
  2. 迁移到 Temporal 显着增强了 GrabUnlimited 的系统稳健性和可扩展性。 Temporal 的工作流编排能力，包括用于分布式处理的定时器、用于并发的工作流 ID 重用以及内置的弹性功能，有效地解决了核心架构缺陷并提高了系统稳定性。
  3. 架构转变使生产事故减少了 80%，并允许专注于产品创新。 通过将复杂的状态管理、错误处理和重试逻辑迁移到 Temporal，工程师可以专注于核心业务逻辑，从而实现更可靠的系统并加速功能开发。

  • 罪魁祸首？一个后端服务，虽然功能齐全，但并非旨在有效地管理快速扩展的会员模式的复杂性。
  • 新架构受益于 Temporal 的许多内置功能，如无限重试、指数退避、速率限制和可观测性。
  • 这种切换使他们能够专注于产品平台的重要方面，而不是花费时间来实现底层基础设施。
