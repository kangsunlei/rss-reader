WebMCP 技术专栏｜平衡智能体可用性与安全性

11/10/2026, 10:30:00 AM

📌 一句话摘要

本文介绍了 WebMCP 技术专栏，重点阐述了如何通过 Web Model Context Protocol 构建结构化工具，为浏览器中的 AI 智能体提供安全可控的能力支持。

📝 详细摘要

随着智能体深度融入浏览器生态，工具安全成为核心基石。文章通过 Web Model Context Protocol (WebMCP)，帮助开发者构建结构化工具并向浏览器中运行的 AI 智能体公开能力。由于大模型将文本、指令和用户数据视为单一 token 序列，容易受到间接提示注入攻击。为解决此问题，作者提供了工具安全性指南，包括使用注解提示（untrustedContentHint、consequentialHint、readOnlyHint）、谨慎开放工具（exposedTo 选项）、设置字符数上限等建议。同时，文章提到正在持续研究跨主体授权同意管理，并包含 requestUserInteraction() 以便在工具执行过程中异步请求用户输入。

💡 主要观点

  1. WebMCP 允许开发者构建结构化工具并向浏览器 AI 智能体公开能力 通过 Web Model Context Protocol，开发者可以将工具暴露给运行在浏览器中的 AI 智能体，智能体可依托大模型、规则、记忆和工具代表用户执行操作。
  2. 大模型易受间接提示注入攻击，需采取安全措施 大模型将所有文本、指令和用户数据视为单一 token 序列，容易受到攻击者植入恶意指令的攻击，已出现可重复实施的提示注入攻击。
  3. 提供工具安全性指南，包括注解提示和谨慎开放工具 建议使用 untrustedContentHint 标记不可信数据、consequentialHint 标识高风险操作、readOnlyHint 标注只读工具，并通过 exposedTo 选项限制工具访问来源。
  4. 设置字符数上限可避免触发智能体防护机制 建议工具描述不超过 500 字符，参数描述不超过 150 字符，名称不超过 30 字符，输出字符数上限为 1500，以获得更好效果。
  5. 持续研究跨主体授权同意管理及 requestUserInteraction() 正在探讨授权同意管理，标准规范草案中包含 requestUserInteraction()，以便在工具执行过程中异步请求用户输入。

💬 文章金句

  • 随着智能体深度融入浏览器生态，工具安全已成为核心基石。
  • 由于大模型将所有文本、指令和用户数据视为单一 token 序列，因此它们容易受到间接提示注入攻击 (即攻击者在其中植入恶意指令) 的攻击。
  • 构建工具时，建议您添加一些关键提示：在适当的情况下使用 untrustedContentHint、对于高风险或不可逆的操作，请使用 consequentialHint、在不更改状态的工具上使用 readOnlyHint。
  • WebMCP 的 document.modelContext.registerTool API 仅向智能体开放工具的能力。默认情况下，其他网站或跨源 iframe 无法观察或与工具交互。
