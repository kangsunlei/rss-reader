消耗了上百亿 Token 后，对于 Agent 时代软件构建、软件形态及未来发展的思考

4/19/2026, 2:16:00 AM

📌 一句话摘要

本文基于 TiDB CTO 黄东旭在 QCon 的演讲，分享了其消耗上百亿 Token 后对 Agent 时代软件生产、形态及未来趋势的深度思考，核心观点包括代码成为执行载体、软件生产民主化、软件形态向意图接口演进以及未来将出现超越 Skill 的复杂抽象。

📝 详细摘要

文章是 TiDB 联合创始人兼 CTO 黄东旭在 QCon 2026 大会上的演讲实录。他基于过去几个月消耗上百亿 Token、与 Agent 协同开发并成功交付数百万行代码基础软件项目的实践经验，系统阐述了对 Agent 时代软件行业的深刻洞察。核心观点包括：1）软件生产发生根本性变革，代码已从思考载体退化为执行载体，软件生产走向民主化，新的思考媒介由 Goal（目标）、Context（上下文）、Constraints（约束）构成；2）人机协同需要人类通过 SPEC 定义规范并组织 Agent 团队，通过大量 Token 消耗激发模型的“灵光一闪”；3）软件形态从静态固定转向以“意图”为接口，Unix 哲学复兴，软件生态将向“贴近人”和“贴近机器”两端集中；4）Skill 并非最终形态，未来将出现能蒸馏人类专家知识、更复杂、可 Debug 的抽象，真正击穿软件开发门槛。

💡 主要观点

  1. 代码已从思考载体退化为执行载体，软件生产迎来编程语言发明级别的根本性变革。 作者认为，在 Coding Agent 能力跨越阈值后，程序员已不再需要用代码思考，代码的作用类似于硬件，仅负责执行。这标志着自编程语言发明以来最重大的变革，软件生产将因此变得极度民主化。
  2. Agent 时代软件构建的思考媒介是 Goal、Context、Constraints 三者的组合。 人类应聚焦于定义清晰的 Goal（目标），而 Context（上下文工程如 RAG、Memory）和 Constraints（约束工程如 Sandbox、测试）则由相应的基础设施解决。当前 Agent 生态的所有技术都可纳入此框架。
  3. 高效的人机协同需要人类定义工程规范（SPEC）并组织 Agent 团队，通过大量 Token 消耗激发创新。 纯黑盒模式不可行，人类需扮演“HR”和资深工程师角色，提供清晰的需求规格说明书（SPEC）并管理 Agent 团队。通过让多个 Agent 反复重写和讨论，消耗大量 Token 以追求那 1% 的“灵光一闪”，从而实现代码质量的跃迁。
  4. 软件形态正从静态固定转向以“意图”为接口，生态将向“面向人”和“面向机器”两端极化。 未来的软件没有固定 UI，“意图”才是真正的操作接口，这导致 Unix 哲学复兴。软件产业将从纺锤形向哑铃形转变，创新和资本会涌向提供极致情绪价值的用户端和作为纯粹基础设施的机器端，中间层的 SaaS 市场将被压缩。
  5. Skill 不是终点，未来需要能蒸馏人类专家知识的、更复杂的抽象。 当前的 Skill 过于简单粗糙，无法表达复杂软件的协同逻辑。未来将出现通过自然语言人机协同生成、结构清晰、可 Debug、可分发的更高级抽象，其核心是封装和蒸馏领域专家的知识，从而真正击穿各行业的软件开发门槛。

💬 文章金句

  • 当代码已经变成执行载体后，我们今天去生产和构建软件的‘思考媒介’是什么？我认为大概是由三个维度的组合：Goal（目标）、Context（上下文）和 Constraints（约束）。
  • 所以今天大家想做个好软件还要省 Token，是不行的，必须要大力出奇迹。其次，模型的智商是决定性要素。
  • 软件不会变革，但软件生产会变得非常民主化。想象一下，上一次这种级别的载体变革（编程语言的发明），诞生了整个软件行业；那这一次它会产生什么？
  • 今天，软件已经没有固定形态了。Open Claw（小龙虾）最大的意义，在于它定义了 Agent 时代软件的‘60 分及格线’。如果未来的新软件，体验和灵活性不如 Open Claw，那就是旧时代的东西。
  • Skill 核心问题在于太简单、太粗糙了。今天我们交换 Skill 的方式，就跟当年这些交换奇奇怪怪的 recipe 的方式是一样的。但是未来像 AWS 或者 Photoshop 等庞杂的软件，是不可能通过‘一张纸’去交付的。
