📝 详细摘要

本文全面概述了联合凭证管理 (FedCM)，这是一个由 W3C 提出的新型浏览器 API，旨在彻底改变 Web 上的联合登录。它强调了 FedCM 的主要目标：通过为委托身份验证提供浏览器原生解决方案，从而增强用户隐私和安全性，摆脱了存在问题的通用 Web 技术，如常被用于跨站追踪的重定向和第三方 Cookie。文章详细介绍了 Web 身份验证的历史演变，从单服务器到 SAML、OAuth 和 OIDC，解释了它们的局限性，例如“NASCAR 旗帜问题（指网站必须枚举支持的身份提供商，导致页面空间有限，偏向少数大型提供商的问题）”和对第三方 Cookie 的依赖。然后，它概述了 FedCM 的时间表、功能和用户流程，并附有说明性图表，区分了首次登录和后续登录，以实现无缝体验。文章还介绍了当前浏览器、身份提供商 (IDP) 和依赖方 (RP) 的支持，以及 RP 的实际实施细节，包括用于登录和断开连接的 JavaScript 代码片段。它强调 FedCM 正在积极开发中，并鼓励开发人员随时了解这一不断发展的标准。

💡 主要观点

  1. FedCM 提供了一种注重隐私保护的浏览器原生联合登录方案。 通过利用浏览器功能，FedCM 旨在取代依赖通用 Web 原语的传统方法，从而增强用户隐私并提供更安全、更一致的登录体验。
  2. 它解决了传统身份验证方法的局限性，例如依赖第三方 Cookie 导致的用户追踪问题。 FedCM 解决了诸如“NASCAR 旗帜问题”以及浏览器阻止第三方 Cookie 所带来的挑战，这些 Cookie 对于许多现有的联合登录流程至关重要。
  3. 该 API 已在 Chromium 浏览器中实现，并获得多家 IDP 和 RP 的支持。作为 W3C 的积极开发标准，值得开发者关注。 该 API 在 Chromium 浏览器中实现，获得了各个 IDP 和 RP 的支持，并且正在通过 W3C 标准化流程，需要开发人员的关注。

💬 文章金句

  • FedCM 是一种新提出的浏览器 API，提供顺畅的联合登录体验。
  • FedCM 的最初目的是为联合登录提供更好的浏览器原生支持。相比于重定向、iframe 和第三方 Cookie 等通用 Web 技术（它们常被广告商用于追踪用户），开发者可以直接使用原生 API。
  • FedCM 专注于用户隐私，并充分利用浏览器原生 UI 元素，旨在构建更一致、更安全的登录体验，并解决传统方式难以解决的问题。
  • 浏览器、IDP 和 RP 都有实施责任。
  • FedCM 规范尚未最终确定。虽然本实施指南在发布时是正确的，但可能存在不准确之处。
