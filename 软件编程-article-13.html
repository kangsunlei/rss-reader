企业和个人基于业务知识和代码库增强的大模型生成代码实践

7/18/2025, 2:01:00 AM

📌 一句话摘要

文章详细阐述了京东零售如何通过分阶段应用大模型，结合企业内部业务知识和代码库，构建智能知识管理系统，以提升研发效能和解决新人上手难题。

📝 详细摘要

本文以研发新人面临的知识断层、代码理解困难等痛点为切入点，提出了基于大模型增强企业知识库和代码库的解决方案。文章将大模型应用分为三个阶段：基础应用（Prompt 工程）、知识整合（构建系统级知识库和智能检索）和深度应用（需求与代码关联，实现代码生成与变更追溯）。作者详细介绍了 STAGE-2 和 STAGE-3 的架构图、技术路线及 Dify 平台实践示例，包括如何通过 GitHub API 获取需求与代码关联，清洗数据并上传知识库，以及配置工作流。最终，该方案有效解决了新人上手难、知识传承难的问题，并建立了可持续优化的知识沉淀机制。文章也指出了未来在代码生成质量、知识关联准确性和 RAG 召回精度方面的优化方向。

💡 主要观点

  1. 分阶段应用大模型策略有效解决企业知识管理痛点。 通过从基础 Prompt 应用到深度集成内部知识库的三阶段方法，系统性地解决了新人上手难、知识资产流失和运维耗时等企业普遍问题，逐步提升研发效率。
  2. 结合业务知识和代码库增强大模型能力是关键。 文章详细阐述了如何通过整合需求文档、ERD、TRD、FAQ 及代码变更记录等内部知识，构建 RAG（检索增强生成）系统，使大模型能提供更精准、专业的回答和代码建议。
  3. 明确的需求与代码关联是实现深度应用的核心。 通过 GitHub API 等方式实现需求与代码的自动关联，是实现历史变更追溯、代码生成及经验传承的基础，但其准确性仍是未来优化重点。

💬 文章金句

  • 或许，打破这座'代码迷宫'的钥匙，就藏在 AI 与知识库的结合中？
  • 通过知识库建设，反向推动了各部门完善文档沉淀。
  • 代码生成质量依赖需求变动频率，李明注意到，对于那些需求变动较少的模块，系统生成的代码往往比较基础，缺乏深度。
  • 如果能严格要求每次代码提交都必须关联明确的需求文档，系统的准确率会有显著提升。
  • 他发现，由于采用了 RAG 技术，生成代码后比较依赖于对于 query 识别到需求的准确度，比较依赖召回的准确度。
