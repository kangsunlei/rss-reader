模型上下文协议 (MCP)：三大误解与修正

9/3/2025, 9:59:48 AM

📌 一句话摘要

本文通过纠正三个常见的误解来阐明模型上下文协议 (MCP)，强调其作为面向模型的协议，用于可靠的 AI 代理与工具交互，区别于传统的 API 调用方式。

📝 详细摘要

本文旨在纠正开发者对模型上下文协议 (MCP) 的常见误解，他们常将其误认为传统的 API。文章强调，MCP 专为 LLM 工具使用、意图调解和上下文交换而设计，是连接非确定性 AI 规划与确定性执行的关键接口。作者纠正了三个误解：1) MCP 并非仅仅是另一种 API，而是专门面向模型的协议；2) 工具并非代理，因为代理负责规划和评估，而工具仅执行；3) MCP 不仅包含工具，还包括资源、提示和引导，从而提供更丰富的上下文。本文提供了具体的设计模式、反模式和核对清单，旨在指导开发人员利用 MCP 的全部功能，构建强大而可靠的 AI 代理系统。

💡 主要观点

  1. MCP 是一种面向模型的协议，专注于 LLM 工具的使用以及上下文管理，并非传统 RPC API 的替代品。 它提供的工具接口不仅包含意图和可供性，还提供超越传统请求/响应模式的上下文，以及非确定性规划与确定性执行之间的桥梁，这些都是传统 API 无法实现的。
  2. 工具执行特定操作，而代理负责规划、重新规划和评估目标。 代理拥有能动性，能够进行目标跟踪、错误恢复和评估。同时，代理还具备记忆和上下文演变的能力。这与工具的无状态和仅执行的特性截然不同。
  3. MCP 的范围不仅限于工具定义，还包括资源、提示和引导，以实现丰富的上下文和人机交互。 资源管理结构化的人工制品，提示提供可重用的指令，引导则支持结构化的人工参与请求。所有这些对于构建强大且可靠的 AI 系统至关重要。

💬 文章金句

  • 大多数开发人员误解了模型上下文协议，因为他们习惯于将其映射到熟悉的 API 心理模型上。这种错误会破坏代理设计、可观察性，以及非确定性推理必须与确定性执行相遇的“最后一英里”（指从模型规划到实际执行的最终阶段）。
  • MCP 是一种面向模型的协议，专为 LLM 工具使用、意图调解和上下文交换而设计。它不会取代 RPC。
  • 工具执行。代理进行规划、重新规划和评估。代理循环往复，直至目标达成。而工具不会。
  • 除了工具之外，MCP 还包括**资源**、**提示**和**引导**。这些对于构建上下文丰富的工作流至关重要。
  • 如果仍然以 'API' 的思维模式思考，那么最终交付的将是脆弱且一次性的演示。将工具视为确定性执行器，将代理视为规划者和评估者，并充分利用 MCP 的所有组成部分——工具、资源、提示和引导——作为智能行为与可靠系统之间的桥梁。
