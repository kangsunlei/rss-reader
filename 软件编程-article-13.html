Tracy 简介：面向 Kotlin 的 AI 可观测性库 | Kotlin 官方博客

3/11/2026, 5:41:09 PM

📌 一句话摘要

JetBrains 推出了 Tracy，这是一个基于 OpenTelemetry 的开源 Kotlin 库，旨在为 AI 应用提供生产级的可观测性，包括 LLM 调用、工具执行和自定义逻辑。

📝 详细摘要

Tracy 是一个专门为 Kotlin AI 生态系统设计的全新可观测性库。它通过提供一种与框架无关的方式来追踪 LLM 交互、工具调用和内部应用逻辑，解决了监控复杂 AI 驱动应用的难题。与要求使用专有 API 进行追踪的成熟 AI 框架不同，Tracy 对标准 HTTP 客户端（OkHttp、Ktor）和 AI SDK（OpenAI、Anthropic、Gemini）进行插桩。它底层利用 OpenTelemetry，允许开发者将数据导出到 Jaeger 等传统后端，或 Langfuse 和 W&B Weave 等专门的 AI 工程平台。其核心特性包括用于逻辑流的作用域 Span、自动化的客户端插桩，以及类似于 Python 的基于注解的工具调用追踪，这显著减少了样板代码并确保了对智能体工作流的全面覆盖。

💡 主要观点

  1. Tracy 通过对标准 AI 和 HTTP 客户端进行插桩，提供非侵入式的可观测性。 Tracy 不强迫开发者使用特定的 AI 框架，而是与 Ktor 和 OkHttp 等现有工具协同工作，从而能够更轻松地集成到现有的 Kotlin 代码库中，无需进行重大重构。
  2. 该库利用 OpenTelemetry 确保数据导出和分析的最大灵活性。 通过遵循 OpenTelemetry 标准，Tracy 允许开发者将遥测数据路由到各种后端，从 Jaeger 等通用工具到 Langfuse 等 AI 专用平台。
  3. 基于注解的追踪为 Kotlin AI 工具监控带来了类似于 Python 的易用性。 “@Trace” 注解允许开发者自动监控所有实现中的接口方法和工具执行，减少了手动插桩的工作量，并防止了智能体逻辑中出现未追踪的“盲点”。
  4. 对敏感数据的细粒度控制确保了生产安全和隐私合规。 Tracy 默认仅追踪元数据，需要通过编程或基于环境的显式激活才能捕获通常包含敏感用户信息的 LLM 输入和输出。

💬 文章金句

  • Tracy 是一个开源 Kotlin 库，能在几分钟内为 AI 驱动的应用添加生产级的可观测性。
  • 虽然像 Spring AI 或 Koog 这样成熟的 AI 框架提供了内置的可观测性，但必须完全通过它们的框架 API 进行 LLM 调用才能被追踪。
  • 虽然装饰器在 Python 框架的此类场景中大放异彩，但 Kotlin 开发者以前只能羡慕不已。Tracy 的出现改善了这一现状。
  • 无论底层 LLM 变得多么强大，使用它们的应用仍然必须经过调试和评估——无论是在开发阶段还是在实际应用中。
