MybatisPlus Sql Inject 魔法

10/4/2025, 1:02:00 AM

📌 一句话摘要

针对 MySQL 唯一索引冲突场景，文章创新性地利用 MybatisPlus 的 SQL 注入机制，实现了高效且无侵入的`ON DUPLICATE KEY UPDATE`操作，大幅简化了代码。

📝 详细摘要

文章首先介绍了在处理 MySQL 唯一索引约束时，当唯一键存在时更新，否则插入的常见业务需求。对比了传统上使用分布式锁实现此功能所带来的复杂性和冗余代码。接着，作者深入剖析 MybatisPlus 的源码，揭示了其通过`AbstractMethod`定制 SQL 生成逻辑的机制。在此基础上，提出了一种创新的解决方案：通过自定义`AbstractMethod`实现`DuplicateInserter`，并将其注册到 MybatisPlus 的`SqlInjector`中，从而实现对`ON DUPLICATE KEY UPDATE`语法的自动化支持。最终，开发者只需在 Mapper 接口中声明一个方法，即可调用此功能，极大提高了开发效率并减少了样板代码。文章代码实践性强，为解决特定场景下的数据写入冲突提供了优雅的方案。

💡 主要观点

  1. MybatisPlus 的 SQL 注入机制提供强大的扩展能力 通过继承`AbstractMethod`并注册到`SqlInjector`，可以自定义 MybatisPlus 生成 SQL 的逻辑，实现框架功能的深度定制。
  2. 利用 MySQL 的`ON DUPLICATE KEY UPDATE`可高效处理唯一键冲突 相比传统分布式锁方案，直接利用数据库特性能更简洁、高效地实现“存在则更新，不存在则插入”的业务逻辑，减少并发处理的复杂性。
  3. 定制化`DuplicateInserter`能大幅简化业务代码 将复杂的`ON DUPLICATE KEY UPDATE`逻辑封装进 MybatisPlus 的扩展中，业务层只需声明接口方法即可调用，有效减少样板代码，提升开发效率。

💬 文章金句

  • 业务功能相似，要求当唯一键存在时根据唯一键更新，否则直接插入
  • Mysql DUPLICATE KEY UPDATE 天然支持上述功能
  • 我直接按照官方的规范定制一个 AbstractMethod 的实现不就可以一劳永逸嘛。
  • 仅仅只需要在业务 Mapper 中声明一下 duplicateUpdate 即可，框架会自动帮你生成支持「DUPLICATE KEY UPDATE」语法的 SQL。
  • 因为我们是替换 MybatisPlus 自带的 DefaultSqlInjector，注意这里是替换逻辑，因此假设你的系统中有多个 MybatisPlusPropertiesCustomizer 的 Bean 那么只会有最后一个生效
