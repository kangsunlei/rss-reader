Cumora：把多个 Agent 和人放进同一个通讯录的团队协作工具

9/19/2026, 1:30:07 PM

📌 一句话摘要

yetone 做的 Cumora 让 Agent 与人共处同一通讯录，可私聊拉群、共享看板和日历，Agent 有独立人设与记忆并主动认领任务，支持本地引擎接入且代码全开源。

📝 详细摘要

Cumora 是 yetone 开发的团队聊天 AI 工具，解决同时跑多个 Agent 时需反复切换终端窗口的问题。Agent 与人处于同一通讯录，支持私聊、拉群，看板和日历共用。每个 Agent 有自己的人设与记忆，会主动认领看板任务，还能收发真实邮件。并发控制上，若一条回复基于过时消息，服务器会先扣住，等它看完新消息再决定是否发出；任务认领是原子的，一件事只归一个 Agent。大脑有两种接法：官方云端，或在本地 Mac/服务器上配置命令，用本地 Claude Code、Codex、Gemini CLI 当脑子，本地引擎支持 10 种，密钥留在自己机器上不经过服务器。有桌面版、网页版，iOS 在 TestFlight 测试，代码全开源，自部署需准备 Postgres 和 Redis。

💡 主要观点

  1. 把 Agent 当作通讯录成员而非独立终端会话 Agent 与人处于同一通讯录，可私聊、拉群，看板与日历共用，作者认为这种形态让多 Agent 协作只需盯着群聊即可，省去逐个切换窗口查看进度。
  2. 并发一致性靠服务端扣留与原子认领解决 基于过时消息的回复会被服务器先扣住，等 Agent 看完新消息再决定是否发出；任务认领是原子的，一件事只归一个 Agent，避免两个 Agent 同时改同一处。
  3. 推理引擎可本地化，密钥不出本机 除官方云端外，可在自己的 Mac 或服务器上配一条命令，用本地 Claude Code、Codex、Gemini CLI 当脑子，本地引擎认 10 种，密钥留在自己机器上不经过服务器。

💬 文章金句

  • Agent 在里面不是问一句答一句，每个有自己的人设和记忆，会主动认领看板上的任务，还能收发真实的邮件。
  • 一条回复如果基于的是过时消息，服务器会先扣住，让它看完新消息再决定发不发。
