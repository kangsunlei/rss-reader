如何把 Skills 变成 Agent 的训练场？小红书 AllSpark 提出 Skill2Env

10/16/2026, 9:59:00 AM

📌 一句话摘要

小红书 AllSpark 提出 Skill2Env 框架，从已有 Skills 出发自动合成可执行训练环境，用 1.5K 条高分轨迹微调 Qwen3.6-35B-A3B，在七项 Agent 基准上均获提升。

📝 详细摘要

针对 Agent 后训练中训练环境难以规模化构建的问题，小红书 AllSpark 团队提出 Skill2Env：从 ClawHub 下载超 47K 个 Skill 文件夹，筛选保留约 3K 个，将能力需求归纳为环境理解、规划、技能使用、长程一致性、错误恢复五个维度，并设计可复用难度模式池与任务蓝图，协同构建任务指令、运行依赖、初始工作区和评估器。系统通过迭代任务强化，依据执行轨迹和评分结果诊断被绕过的挑战，针对性加难，使任务难度由 Agent 实际表现驱动。论文以 Docling 文档处理 Skill 为例，展示对账任务经两轮加难后文件数从 10 增至 21、异常项从 3 增至 12。最终构建 2，963 个可执行任务、覆盖 25 个领域、初始工作空间含 46，295 个文件，用 1.5K 条高分轨迹监督微调 Qwen3.6-35B-A3B，在七项基准上均提升，并在四种执行框架和 SkillsBench 八个领域中验证了泛化性。

💡 主要观点

  1. Skill2Env 以能力需求为导向，把已有 Skills 转化为可执行训练环境 团队从 ClawHub 下载超 47K 个 Skill 文件夹，按真实场景适用性、沙箱兼容性和依赖配置可行性筛选保留约 3K 个，再将环境理解、规划、技能使用、长程一致性、错误恢复五类能力需求落实为具体任务挑战。
  2. 可复用难度模式池与任务蓝图是任务与环境协同构建的核心机制 难度模式如「分散证据」「状态依赖」可自然组合进同一目标；任务蓝图统一说明任务目标、预期挑战、环境事实、验收标准和信息边界，使任务指令、运行依赖、初始工作区与评估器有共同依据。
  3. 迭代任务强化让难度由 Agent 实际执行表现驱动，而非预先设定 系统检查执行轨迹和评分结果，诊断哪些挑战已被解决、哪些要求被绕过，再针对性强化已有难度模式或引入新模式，调整先体现在任务蓝图中，再同步更新任务指令、工作空间、执行环境和评估器。
  4. Docling 对账案例展示了从单轮任务到多轮加难的完整过程 初始任务要求核对 10 个文件、6 种格式的材料，Agent 首次执行即满分；两轮加难后工作区文件从 10 增至 21，对账异常项从 3 增至 12，且异常项开始相互影响，需要提取、范围判断、费率计算与结算核对连成完整流程。
  5. 基于合成环境生成的训练数据在多项基准和框架上均带来提升 Skill2Env 构建 2，963 个可执行任务、覆盖 25 个领域、初始工作空间含 46，295 个文件；用 1.5K 条高分轨迹微调 Qwen3.6-35B-A3B 后，在七项基准上均提升，并在 pi、Terminus-2、OpenCode、Claude Code 四种框架下分别提升 11.2、13.5、16.9 和 12.3 个百分点。

💬 文章金句

  • 任务难度的提升不再依赖预先设定的复杂度，而是由 Agent 的实际执行表现驱动。
  • Skill2Env 并未针对任何下游基准专门设计训练环境，却在七项基准上均取得了性能提升。
  • 信息边界明确了哪些内容需要直接写在任务说明中，哪些需要到工作区查找，哪些需要由已有证据推断。
  • 随着 Agent 逐渐掌握已有挑战，系统可以有针对性地提高任务要求，持续生成更具挑战性的训练环境。
