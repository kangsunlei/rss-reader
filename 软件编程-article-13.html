OpenAI“Agent 圣经”翻车？LangChain 创始人怒怼“全是坑”！

4/22/2025, 8:48:22 AM

📌 一句话摘要

LangChain 创始人批评 OpenAI 的 Agent 指南，引发 Agent 与 Workflow 的优劣之争。

📝 详细摘要

文章报道了 LangChain 创始人 Harrison Chase 对 OpenAI 发布的《A Practical guide to building AI agents》指南的批评。Chase 认为 OpenAI 对 Agent 的定义过于僵化，并强调在生产环境中，Agentic 系统应是 Workflows 和 Agents 的有机结合，并支持二者之间的灵活切换。文章探讨了在构建大模型应用时，工程师手动调优的流程容易被大型模型更新所取代的痛点。同时，文章对比了传统的软件系统设计和引入模糊计算的系统，认为后者由不断进化的模型能力动态驱动。文章还引用 Anthropic 对 Workflows 和 Agents 的定义，并指出构建可靠 Agent 的关键在于确保大模型接收到正确的上下文信息，而 Workflows 在传递上下文方面具有优势。文章最后还提到了 Harrison Chase 制作的 Agent 框架对比表格，为开发者选择合适的框架提供了参考。

💡 主要观点

  1. 生产环境中的 Agentic 系统应是 Workflows 和 Agents 的结合。 对于绝大多数应用而言，Workflows 仍然不可或缺，只有在确实需要时才引入更复杂的 Agent，不应过度依赖 Agent。
  2. Agentic 系统应是 Workflows 和 Agents 的有机结合。 理想的 Agent 框架应支持从结构化工作流向大模型驱动的模式逐步过渡，并在两者之间灵活切换，以应对不同场景的需求。
  3. 构建可靠 Agent 的关键在于确保大模型接收到正确的上下文信息。 Workflows 的优势在于能够将正确的上下文传递给 LLM，可以精确地决定数据如何流动，从而提高系统的可预测性和可靠性。

💬 文章金句

  • 在实际应用中，我们发现大多数 'Agentic 系统' 其实是 Workflows 和 Agents 的结合。这也是为什么我更倾向于讨论一个系统 '有多 Agentic' 。
  • 在开始构建 Agent 之前，确保你的用例确实需要它。
  • 能够控制输入给 LLM 的内容依然会非常重要（垃圾进，垃圾出）
  • 构建可靠 Agents 的核心，依然是确保 LLM 能接收到正确、充分的上下文信息
