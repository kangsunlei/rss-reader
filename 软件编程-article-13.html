Cloudflare 容器服务进入公开测试阶段

6/28/2025, 12:00:00 AM

📌 一句话摘要

Cloudflare 推出容器服务公开测试版，支持在其全球边缘网络上部署 Docker 容器，并与 Workers 平台深度集成。

📝 详细摘要

Cloudflare 正式推出容器服务的公开测试版，开发者现可在其遍布全球的 300 多个边缘节点部署 Docker 容器。该服务突破了 Cloudflare Workers 的局限性，能够支持需要并行 CPU 核心、完整文件系统访问或特定运行时环境的资源密集型应用。通过与 Workers 及持久性对象（Cloudflare 有状态应用的构建模块）的深度集成，该服务提供了可编程的入站逻辑和生命周期管理能力。主要应用场景包括 API 网关、服务网格和容器编排，有效解决了 Workers 在语言支持、CLI 工具和应用可移植性方面的限制。测试版目前限制为 40 GB 内存和 40 vCPU，未来计划加入全局自动扩展、基于延迟的路由等新特性。计费模式采用创新的按 10 毫秒为单位的运行时间计费，费用根据内存、磁盘和 CPU 使用情况动态调整。

💡 主要观点

  1. Cloudflare 容器服务支持在 300 多个边缘节点运行资源密集型应用 支持媒体处理等边缘工作负载的 Docker 容器，有效解决了 Workers 在语言支持、CLI 工具和应用可移植性方面的限制。
  2. 与 Workers 和持久性对象的深度集成提供可编程控制 持久性对象作为可编程的 sidecar 代理管理容器生命周期，而 Workers 提供从边缘节点的全局路由能力，实现类似 API 网关的功能。
  3. 创新的按 10 毫秒运行时间计费模式 费用根据内存、磁盘和 CPU 使用情况动态变化，容器在收到请求或被手动启动时开始计费。
  4. 公开测试版的限制及发展路线图 当前限制为 40 GB 内存和 40 vCPU，未来将增加全局自动扩展、基于延迟的路由和增强的 Worker-容器通信功能。

💬 文章金句

  • 持久性对象不仅能对容器生命周期进行精细控制，整个 Workers 平台还允许您根据需要自定义路由和调度行为。
  • 每个持久性对象都充当可编程的 sidecar 代理，既可以将请求转发至容器，又能管理其生命周期。这种控制方式在其他平台上很难实现。
  • 将广为人知的 Docker 容器与 Cloudflare '简单、全局、可编程'的计算愿景相结合，创造了诸多新的可能性。
  • Workers 从全球 300 多个边缘节点提供可编程的入站逻辑，其功能类似于 API 网关。
