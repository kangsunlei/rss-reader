Kimi 向左，Claude、GPT 向右

9/19/2026, 3:59:35 AM

📌 一句话摘要

Kimi 推出独立 Kimi Code 桌面客户端做加法，而 Claude 将 Chat 与 Cowork 合并、ChatGPT 把 Codex 并入桌面端做减法，文章分析两种路线差异并判断 Kimi 未来可能走「客户端统一、专业功能保留」的整合路径。

📝 详细摘要

文章以两条相邻的新闻切入：9 月 17 日 Kimi Code 推出支持 macOS 和 Windows 的桌面客户端，把终端里的编程 Agent 搬到图形界面，支持打开本地项目、修改代码、执行命令、查看文件改动、调用浏览器和权限模式控制；而前一天 Claude 宣布把原本独立的 Chat 和 Cowork 合并成一个 Claude，用户不必再判断任务该交给聊天助手还是办公 Agent。OpenAI 此前也把 Codex App 并入新版 ChatGPT 桌面应用。作者由此提出「Claude、ChatGPT 做减法，Kimi 做加法」的对比。文章先区分 Kimi Code 与 Kimi Work 的工作环境差异：前者围绕软件开发，需要理解代码仓库、修改多文件、运行命令、展示 diff 并让开发者审查每一步；后者面向办公与知识工作。作者还指出 Kimi Code 支持接入 Anthropic、OpenAI、Google 等第三方模型，可能成为面向开发者的多模型工作台，从而争取原本不会使用 Kimi Work 的开发者。随后解释 Claude 做减法的原因：用户反馈每次开始任务前要先决定入口，不同工作区域的上下文无法自然延续。文章判断 Kimi 未来存在整合可能，但未必合并成一个聊天窗口，更可能参考 ChatGPT「客户端统一、专业功能保留」的思路，先共享账号、会员权益、模型配置和项目资料，再逐步打通任务与对话；并认为 Kimi 现在不必急着合并，先观察开发者需求更有意义。

💡 主要观点

  1. Kimi 与 Claude、ChatGPT 在桌面端走出了相反的产品路线：前者做加法，后者做减法 Kimi 在已有 Kimi Work 的情况下又推出独立的 Kimi Code 客户端；Claude 则把 Chat 和 Cowork 合并成同一个 Claude，OpenAI 也把 Codex App 并入新版 ChatGPT 桌面应用，减少用户需要面对的入口。
  2. Kimi Code 与 Kimi Work 面向的工作环境不同，是拆分客户端的直接理由 Kimi Work 面向办公和知识工作，用户关心最终文档质量；Kimi Code 围绕软件开发，需要理解代码仓库、修改多个文件、运行命令、展示代码差异，并让开发者审查和控制每一步操作，因此需要更专业的交互界面。
  3. Kimi Code 支持接入第三方模型，可能成为面向开发者的多模型工作台 官方文档显示 Kimi Code 可配置 Anthropic、OpenAI、Google 等模型服务，也能对接 DeepSeek、千问等兼容接口。即使不使用 Kimi 自家模型，开发者也可能因为喜欢其编程工具而安装，从而为 Kimi 争取原本不会主动使用 Kimi Work 的用户。
  4. Claude 做减法的动因是用户不想在任务开始前先选择入口，且上下文难以延续 Anthropic 在 9 月 16 日的官方公告中解释，用户反馈每次开始任务前还得决定去哪个入口，不同工作区域里的上下文也不能自然延续，因此把能力整合到同一段对话中，由系统选择合适的工具。
  5. Kimi 未来可能整合 Code 与 Work，但更可能是「客户端统一、专业功能保留」而非合并成一个聊天窗口 作者参考 ChatGPT 把 Chat、Work、Codex 收进同一桌面应用但保留专门 Codex 工作界面的做法，建议先共享账号、会员权益、模型配置和项目资料，再逐步打通任务与对话，并认为 Kimi 现在不必急着合并，先观察开发者需求更有意义。

💬 文章金句

  • Claude、ChatGPT 正在做减法，Kimi 却还在做加法。
  • Kimi Code 还在尝试成为一个面向开发者的多模型工作台。
  • 如果每一步都需要重新打开一个产品、复制上下文、重新交代需求，所谓 AI 提升效率，可能有不少时间都浪费在切换工具上了。
  • 客户端统一，专业功能保留。
  • 当同一个模型能够写代码、做 PPT、操作浏览器、处理文件，甚至完成越来越多复杂任务时，我们还需要为每一项能力开发独立的 App 吗？
