Coding Agent 技术全景图：Context Engineering、Subagents 与 Harness，一年范式转移全解析

6/7/2026, 2:15:00 AM

📌 一句话摘要

本文基于 Thoughtworks 专家在 QCon 的演讲，系统梳理了 Coding Agent 领域过去一年的范式转移，核心围绕 Context Engineering、Subagents、Harness Engineering 三大主题，并深入探讨了减少人工监督带来的安全、成本与可维护性挑战。

📝 详细摘要

文章是 InfoQ 对 Thoughtworks 全球 AI 辅助软件交付负责人 Birgitta Böckeler 在 QCon 纽约站演讲的编译整理。内容全面回顾了过去一年 Coding Agent 领域的关键演进：从 Context Engineering 的兴起（Skills、Subagents、渐进式上下文加载），到云端低监督/无监督自主开发模式的普及，再到核心问题——如何通过 Harness Engineering（确定性工具、结构性测试、自定义 Lint 规则）构建安全网来约束非确定性模型产出。演讲还深入分析了减少人工监督带来的风险评估框架（概率、影响、可检测性）、安全风险（Prompt Injection、Secrets Extraction、Lethal Trifecta）、成本爆炸（从 12 美分到年化 9 万美元+）以及长期代码可维护性挑战（熵增、漂移）。最后提出了 Harness 可能成为未来新的抽象层的展望。

💡 主要观点

  1. Context Engineering 是过去一年 Coding Agent 领域最关键的演进，成为放大工程实践的强力杠杆。 从简单的 rules files 发展到 Skills、Subagents、MCP Servers 等模块化、可按需加载的上下文管理手段，但这也意味着它会同时放大好的和坏的工程实践，需要谨慎设计。
  2. 减少人工监督的趋势不可逆，但需要建立基于风险评估的决策框架。 评估任务是否适合交给 Agent 需从三个维度考量：AI 出错的概率、出错的影响、以及能否检测到错误。开发者需要积累对 AI 能力边界的直觉，才能安全地减少监督。
  3. Harness Engineering 是建立对 Agent 信任的核心，通过确定性工具约束非确定性模型。 通过结构性测试、自定义 Lint 规则、Codemod 等确定性工具构建反馈系统，将原本为人类设计的工程约束改造成 Agent 可学习、可反馈、可优化的系统，是 Context Engineering 真正工程化的关键。
  4. 安全与成本问题随着 Agent 自主性提升而急剧放大。 Prompt Injection、Secrets Extraction 等安全风险在低监督模式下更为致命；同时，Agent 工作流的复杂化导致 Token 消耗激增，年化成本已可媲美一名资深开发者的薪资。

💬 文章金句

  • Context Engineering 正在变成一个非常强的「放大器杠杆」，而且这种放大是双向的：既能放大好的工程实践，也同样会放大坏的结构问题。
  • 风险评估永远都离不开三个维度：概率、影响、可检测性。也就是：它出错的概率有多大？如果出错，后果有多严重？以及你能不能发现它出了错？
  • 把原本为人类设计的工程约束系统，改造成 agent 可学习、可反馈、可优化的系统，这可能才是 Context Engineering 真正开始变得「工程化」的地方。
  • 也许未来我们不再靠传统服务模板起步，而是一个 Harness 模版，实例化之后就能支撑我们的代码库。
