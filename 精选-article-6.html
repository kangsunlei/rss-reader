折腾了整整 1 年，毫无保留地分享一下我这套 Agent 自动化系统。

11/2/2026, 12:19:00 AM

📌 一句话摘要

作者分享了一套基于 Agent 自动化的系统架构，通过事件中台统一调度、模型按需调用和 CI 流水线，最大化释放人类注意力，实现「批奏折」决策模式，显著提升生产力。

📝 详细摘要

本文作者从设计师出发，经过一年探索，构建了一套完整的 Agent 自动化系统。核心在于将「人类注意力」作为瓶颈，通过事件中台统一接收并分发各类触发信号（定时任务、Webhook、消息等），按规则分配给不同模型（Claude、GPT 等）处理。系统包含事件中台、Agent 执行层、CI 中台和「批奏折」决策环节。CI 中台自建在本地 M4 Mac Mini 上，完成代码审查、测试、合并、发布、核实五步，极大提升上线质量与速度。最终通过飞书卡片实现「批奏折」决策，只有少数需要人类判断的事才推送至用户，最大化释放注意力。

💡 主要观点

  1. 将注意力视为稀缺资源，通过 Agent 自动化解放人类决策 作者引用朱元璋报奏折的历史典故，指出人类注意力是 Agent 系统的最大瓶颈。通过事件中台和规则引擎，实现「批奏折」模式，只有需要人类判断的少数事务推送至用户，最大化释放注意力。
  2. 事件中台统一调度，实现多模型按需调用 所有事件（定时任务、Webhook、消息等）统一发至中台，根据 rules.json 配置分配给不同 Agent（Claude Code、Codex 等），支持去重、规则动态配置和模型灵活替换，大幅提升性价比。
  3. 本地 CI 中台自建，解决云端 CI 配额与速度问题 因 GitHub CI 配额不足且海外云端访问国内资源慢，作者在本地 M4 Mac Mini 上自建 CI 中台，完成审查、检查、合并、发布、核实五步流程，中位数两三分钟即可上线，质量大幅提升。
  4. Skill 化管理确保任务可控可复用 每个自动化任务配备专属 Skill（SOP+脚本），实现清晰、可控、可管理。修改任务细节只需改 Skill，不影响 Agent 逻辑，解耦后可复用。
  5. 飞书「批奏折」实现决策可视化 通过飞书 AI 助理推送决策卡片，用户只需点击确认即可完成决策。卡片显示 Agent 已写好的「票拟」，用户批准后自动继续执行，形成可视化的决策流。

💬 文章金句

  • 一个人通常只能同时跟进 3 到 5 个活跃的会话，在这种设计下，单任务的上限取决于模型能力，多任务的上限取决于人的注意力。
  • 在整个 Agent 系统里，人的注意力是最宝贵的资产，同时也是最大的瓶颈。
  • 我唯一要做的事，就是最后一步，我称为批奏折。
  • 全程不需要我管，并且上线的质量大大提高，几乎很难会有 BUG 或者返工的情况。
