智能体 Skill 调优“焚诀”——业务逻辑之外的胜负手

11/13/2026, 7:47:00 AM

📌 一句话摘要

本文系统阐述了 AI Agent 技能调优的工程化方法，通过意图树重构、三层架构设计和 bad case 闭环调优，显著提升了路由准确率和输出可信度，最终将 37 个平铺技能压缩整合为 1+6+19 的层级结构。

📝 详细摘要

本文聚焦于 AI Agent 技能调优的工程化实践，针对投研场景中出现的路由不准、上下文爆炸、输出不可信等问题，提出了系统化的解决方案。文章首先从运行时视角阐明 skill 的本质是参与路由与注意力分配的组件，进而给出五条生产级技能判定标准。通过意图树按分析范式重新切分，将准确率从 92.5%提升至 98.5%；构建 1+6+19 的三层架构，将 token 消耗降低 80%；设计四阶段改写管道提升问题治理效果；并通过六个典型 bad case 案例，提炼出五步法的规则写作范式。最后构建三层评测体系，确保每次改动都可量化验证。

💡 主要观点

  1. 意图树按分析范式重构显著提升路由准确率 将原 9 个话题式意图收敛为 6 个范式式意图，消除'公司基本面'等黑洞意图的结构性混淆，回归评测准确率从 73%提升至 92.5%，兜底率从 4.59%降至 1.08%。
  2. 三层架构（基座+聚合索引+模板）解决规则重复与 token 浪费 将 37 个平铺技能整合为 1+6+19 结构，基座统一定义合规规则，聚合索引负责业务路由，模板按需加载，单技能上下文从 6000 token 降至 1200 token，节省约 80%成本。
  3. bad case 驱动的五步调优方法论 通过归因分层、落点选择、落点唯一、配正误例、登记自检五步法，将纠错型规则写作从抽象约束转化为可执行的正例样本，显著提升规则遵循度。
  4. description 只写 when to/not to use 是路由的关键 生产级技能的 description 必须明确使用边界和反例，短而准的描述比冗长的功能简介更有效，补上反例后路由准确率从 53%提升至 85%。
  5. 评测闭环是技能调优不可或缺的保障 构建三层评测体系（意图离线评测+技能 L0 用例+整体回归），每次改动都可量化验证，防止修 A 坏 B，确保技能调优从玄学走向科学。

💬 文章金句

  • AI 一天能帮你生成 37 个 skill，但'能生成'距离'能生产'，隔着一整套工程体系------路由分得准、结构拆得省、规则写得狠、案例配得真、评测兜得住。
  • 意图树结构决定分类准确率的天花板，例句和规则只能帮你逼近天花板。
  • 短和准是两个独立要求，缺一不可。
  • 反例不是可选项，是描述能不能起路由作用的关键。
  • 改完之后，你得知道有没有变好、有没有把别的改坏。没有评测集，skill 调优就是玄学。
