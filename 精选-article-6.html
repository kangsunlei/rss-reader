📌 一句话摘要

作者分享基于 AI 的编程工作流方法论，强调模型仅占三成，核心在于如何搭建六个工位的闭环交付流程，从蓝图到验收，实现高效 AI 代码生成与质量控制。

📝 详细摘要

本文作者从个人实践出发，系统阐述了 AI 编程工作流的完整方法论。文章指出，AI 模型只占任务产出的三成，剩余七成在于工位布局与流程设计。作者详细描述了六个核心工位：蓝图（结构设计）、施工图（方案固化）、拆工单（任务切分）、实施（多 worktree 并行）、评审（对抗式 code review）和兜底（静态扫描）。同时，文章探讨了 Agent 在不同环境中的「住址」（云端、虚拟机、本地 PC、手机常驻），以及如何通过「盲盒理论」避免对话式任务导致的质量问题。作者还分享了工具使用的三层账单结构（订阅打底、按量兜底、免费捡漏），并强调流程清晰度是 AI 落地的关键，而非模型选型。最后，作者提出三个边界观：验收比生成更贵，契约先于代码，落盘才算发生。

💡 主要观点

  1. AI 模型只占三成，工位布局决定产出规模 同一批任务、同一套工具，换个人来摆工位，产出能差出一个数量级；同一人换模型，可能毫无感觉。这说明模型提效有限，核心在于流程设计与工位布局。
  2. 六个工位构成 AI 编程的闭环交付流程 从蓝图（结构设计）、施工图（方案固化）、拆工单（任务切分）、实施（多 worktree 并行）、评审（对抗式 code review）到兜底（静态扫描），每个环节都有明确的输入输出和验收标准，确保质量可控。
  3. 盲盒理论揭示对话式任务的本质问题 对话式任务本质是开盲盒，需求越补越偏差，最终交付的是「它以为你要的」和「它记得你说过的」的混合物。正确做法是先锁唯一方案，再让模型动手。
  4. 工具使用遵循三层账单结构 订阅打底用于日常高频任务，按量兜底用于硬骨头问题，免费捡漏用于简单格式转换。这种结构有效缓解 token 焦虑，避免因额度担忧而影响使用决策。
  5. Agent 的「住址」决定其应用场景 云端 Agent 适合定时任务，虚拟机 Agent 适合终端自动化，本地 PC Agent 适合文件系统和内网服务操作。作者主力使用本地 PC Agent，因为其工作长在本地，安全可控。

💬 文章金句

  • AI 编程这件事，模型只占三成，剩下七成在你怎么摆工位。
  • 同一批任务、同一套工具，换个人来摆，产出能差出一个数量级------反过来也一样，同一个人换个模型，可能毫无感觉。
  • 跟大模型对话式地做任务，本质上是在开盲盒。
  • 生成不值钱，验收值钱。
  • 契约先写，代码后写。
  • 落盘才算发生。
