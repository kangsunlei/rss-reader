Gemini 2.5 Pro 负责人：最强百万上下文，做好了能解锁很多应用场景

6/30/2025, 12:03:11 PM

📌 一句话摘要

Gemini 2.5 Pro 负责人分享百万级长上下文技术的核心、应用场景及未来发展方向，强调千万级 token 上下文将成标准配置

📝 详细摘要

文章详细介绍了谷歌 DeepMind 长上下文预训练联合负责人 Nikolay Savinov 对 Gemini 2.5 Pro 百万级长上下文技术的见解。核心观点包括：在当前百万 token 上下文质量未达完美前，盲目追求更大规模意义不大；长上下文与 RAG 是协同关系，而非替代；未来千万级 token 上下文将成为标准配置，对编码等场景带来革命性突破。文章还探讨了长上下文在推理、Agent 应用中的重要性，开发者如何有效利用上下文缓存等技术优化应用，以及模型质量与成本平衡的关键权衡点。

💡 主要观点

  1. 百万级长上下文质量未达完美前，盲目扩大规模意义不大 Nikolay Savinov 认为当前应优先提升百万 token 上下文的质量，而非盲目追求更大规模，这能更好地解锁应用场景
  2. 长上下文与 RAG 是协同关系，而非替代 RAG 负责从海量信息中粗筛，长上下文负责精细处理，两者结合能实现更高召回率；真正的限制因素在于应用程序的延迟要求
  3. 千万级 token 上下文将成标准配置，革命性改变编码场景 随着成本下降，千万级 token 上下文将能完整容纳大型代码库，极大提升编码效率，成为程序员的新标配
  4. 长上下文对推理和 Agent 应用至关重要 长上下文能力强的模型在推理方面表现更佳；Agent 既能作为长上下文的使用者追踪状态，又能作为提供者自动整理上下文
  5. 注意力机制中 token 存在竞争关系 上下文中的 token 越多，注意力竞争越激烈，强干扰信息会分散模型对目标信息的注意力
  6. 开发者应善用上下文缓存技术优化应用 合理利用上下文缓存可显著降低处理成本和提高响应速度，问题应放在上下文末尾以最大化缓存效果

💬 文章金句

  • 在当前百万 token 上下文远还没有达到完美之前，盲目追求更大规模的长上下文意义不大
  • RAG 不会过时。在实际应用中，RAG 不会迅速被淘汰，而是会与长上下文来协同工作
  • 具备强大长上下文能力的模型，也应该在推理方面表现出色
  • 未来，千万级别的 token 上下文很快会成为标准配置，对于编码等应用场景将是革命性的突破
  • 不要将长上下文当成「数据垃圾桶」，不相关的信息会降低模型表现
  • 注意力机制存在一个固有的特点，即 token 之间存在竞争关系
