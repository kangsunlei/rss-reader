Open SWE：一个用于内部编码智能体的开源框架

3/17/2026, 6:37:23 PM

📌 一句话摘要

Open SWE 是 LangChain 推出的一个开源框架，它使组织能够基于生产验证的模式（如隔离沙盒和无缝工作流集成）构建可定制的内部编码智能体。

📝 详细摘要

本文介绍了 Open SWE，这是一个专为工程团队部署内部 AI 编码智能体而设计的框架。它借鉴了 Stripe、Ramp 和 Coinbase 的生产系统经验，将隔离云沙盒（用于安全代码执行）、精选工具集以及与 Slack、Linear 和 GitHub 的深度集成等架构模式进行了规范化。Open SWE 基于 LangChain 的 Deep Agents 和 LangGraph 构建，强调“可组合”的方法，允许团队在不分叉核心逻辑的情况下定制模型、工具和沙盒。它通过 AGENTS.md 文件实现独特的上下文管理，并使用确定性中间件来确保 PR 创建和消息处理等任务的可靠性，为企业级 SWE 智能体提供了一个结构化的起点。

💡 主要观点

  1. 生产级编码智能体共享沙盒和精选工具的融合架构。 对 Stripe、Ramp 和 Coinbase 系统的分析表明，工具集成正从“越多越好”转向隔离执行环境和专注的工具集。
  2. Open SWE 采用组合而非分叉的方式，以确保可持续的升级路径。 通过基于 Deep Agents 框架构建，Open SWE 允许组织将自定义工具和提示作为配置进行维护，从而在无需手动合并代码的情况下受益于核心库的改进。
  3. 隔离云沙盒对于安全和自主的智能体执行至关重要。 在专用的远程 Linux 环境（通过 Modal、Daytona 等）中运行任务，可以限制错误的“爆炸半径”，并允许智能体在无需持续人工批准的情况下执行 shell 命令。
  4. 有效的上下文工程需要平衡仓库级知识与任务特定数据。 该框架使用 AGENTS.md 来定义架构约定和团队特定模式，同时从 Slack 话题或 Linear 问题中提取实时上下文，以减少工具调用的开销。
  5. 确定性中间件是智能体编排的必要安全网。 虽然 LLM 驱动逻辑，但中间件钩子负责处理可靠的任务，例如注入运行中消息或确保 PR 被打开，从而平衡了 AI 的灵活性与工程可靠性。

💬 文章金句

  • 工具的精选似乎比工具的数量更重要。
  • 先隔离，然后在边界内授予完全权限。
  • 这种智能体（模型驱动）和确定性（中间件驱动）编排的分离有助于平衡可靠性与灵活性。
  • Open SWE 旨在成为一个可定制的基础，而非一个成品。
  • 组合提供了两个优势：升级路径和无需分叉的定制。
