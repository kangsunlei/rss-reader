万字综述 Harness 革命！

4/13/2026, 3:10:00 PM

📌 一句话摘要

本文基于 2026 年 AI 发展背景，系统阐述了 Agent Harness 作为驾驭智能体复杂性的战略基础设施，从软件工程演进史切入，分析了其核心组件、生态格局，并探讨了工程师在 Agent 时代的能力转型方向。

📝 详细摘要

文章是新加坡 AI 研究员黄佳在 Datawhale 的深度分享，核心观点是：当大模型能力进入高原期，决定 Agent 系统成败的关键已从模型本身转向其外围工程——Harness。作者通过回顾 30 年软件工程演进史（从 GOF 设计模式到微服务、DDIA），论证了 Harness 是驾驭 Agent 这一“不确定性系统”复杂性的历史必然。文章详细定义了 Agent = Model + Harness，并解析了其六大核心组件（Agentic Loop、Tool System 等）以及解决的五大落地难题（如无限循环、权限失控）。同时，梳理了当前 Harness 生态格局，指出 Claude Code 是纵深型代表，OpenClaw 等是横向扩展代表。最后，文章强调工程师需从“码农”升级为“系统工程师”，掌握抽象、结构化思维和驾驭不确定性的能力，以设计可控的 Agent 系统，实现从写代码到设计系统的转型。

💡 主要观点

  1. Harness 是 Agent 时代的战略级基础设施，核心价值在于驾驭智能体的不确定性。 当模型智力达到高原期，比拼的重点从模型能力转向其外围工程（Harness）。Harness 作为包裹模型的运行时和基础设施，负责工具调用、上下文管理、权限控制等，是将大模型“大脑”变为 Agent “身体”的关键，旨在构建可控的系统。
  2. Harness 的出现是软件工程演进历史的必然，其本质是工程师与系统复杂性斗争的延续。 从 GOF 设计模式（驾驭对象）、企业架构模式（驾驭业务）、微服务（驾驭分布式通信）到 DDIA（驾驭数据系统），复杂性的中心不断转移。Agent 引入了概率和不确定性，Harness 正是应对这一新复杂性中心的“缰绳”，其核心方法论仍是抽象与结构化。
  3. 工程师在 Agent 时代需从“码农”转型为“系统工程师”，核心能力是设计并驾驭复杂系统。 单纯写代码的“码农”价值可能被 AI 替代，而能理解业务、具备抽象思维、能设计循环策略和质量审核机制的“系统工程师”将不可或缺。这要求工程师深度理解现代 IT 系统，掌握 Harness 设计能力，并以“懂业务”和“深度交互能力”构建个人护城河。

💬 文章金句

  • 模型智力已经在线，我们现在比拼的就是 Harness。
  • Harness 做的就是把大模型的大脑变成了 Agent 的身体。
  • 工程师永远不会失业，但码农可能会失业。
  • 技术架构演进二十几年不变的是什么？不变的就是如何驾驭复杂性。
  • Harness 就是我们驾驭 Agent 这个‘不确定性系统’的缰绳。
