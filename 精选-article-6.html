Agent 大评测指南：一门纯粹的实践学科

11/23/2026, 2:00:00 AM

📌 一句话摘要

本文系统性阐述了 Agent 评测的定义、方法论及实践要领，强调可观测性和主观判断的重要性，并提出四条核心经验指导 Agent System 评测设计。

📝 详细摘要

本文从 Agent 评测的本质出发，阐明了其与传统软件测试的区别，指出 Agent 评测的复杂性源于模型输出的不可预期性和 Agent 内部高度耦合的特性。作者通过四个核心经验：先确定产品评分指标再设计题目、可观测性是实践学科的关键、敢下主观判断并为之负责、紧贴真实世界关联性的 Task，系统化地指导了 Agent System 评测的设计方法。文章进一步探讨了 Harness 迭代的挑战，强调工程与模型能力的协同演进，以及用户视角评测的必要性，最后呼吁建立更具可解释性和可迁移性的评测体系。

💡 主要观点

  1. Agent 评测是独立于模型测试的实践性科学，核心挑战在于模型输出的不可预期性与 Agent 内部高度耦合 相比传统软件测试，Agent 评测必须应对模型随机性和 Prompt 间的相互影响，导致系统行为难以完全预测和控制
  2. 评测设计应以产品评分指标为先行，先确定如何判断好坏，再设计具体题目 通过分析用户反馈和理论模型（如语言学隐喻率），先构建可靠的评分维度，再匹配相应的测试任务，避免题目与产品目标之间的 Gap
  3. 可观测性是 Agent 评测工作的核心原则，需通过轨迹、Token 消耗、Effort 等指标实现结果可视化展示 通过前端展示、视频录屏、行动摘要和资源消耗统计等方式，让评测结果直观可达，支持主观判断的科学化
  4. 针对真实世界时效性任务，需构建双轨评测机制：快照回归测试与动态运行提取迭代灵感 对不稳定的真实任务（如新闻检索），既要通过存档+搜索基建做回归测试，又要在题目设计中考虑动态性，以暴露问题为目的进行日常运行

💬 文章金句

  • 评测也是测，评测就是一个测试工作。
  • 把它的逻辑完全梳理清楚是一件太困难的事情，对人的要求非常高。
  • 所以评测就从正常软件开发里的测试分化了出来。并且相比传统软件测试，工作的重要性也被提了上来。
  • 可观测性是实践学科中最重要的实验设计原则之一。
  • 任何道理、任何规律刚刚诞生后都是「主观定义」，「客观标准」是经历了长久时间形成的「主观定义」。
