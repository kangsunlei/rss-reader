Anthropic 新增合规性 API 端点，直面 Claude Code 安全治理盲区

9/2/2026, 10:00:00 AM

📌 一句话摘要

Anthropic 新增合规性 API 本地会话记录端点，弥补 Claude Code 安全治理盲区，但仅凭日志仍不足以判断 Agent 访问合法性，需结合托管设置、端点采集与身份治理三层方案。

📝 详细摘要

文章分析了 Anthropic 为 Claude Code 新增的合规性 API 端点及其在本地 Agent 安全治理中的作用。Claude Code 等执行框架运行在开发者本地，可读取文件、执行命令、调用 MCP 工具，但 Anthropic 此前缺乏可见性。2026 年 8 月新增的本地会话记录端点可捕获 Agent 与模型的交互内容，包括 bash 命令、工具调用和 MCP 请求。然而文章指出，仅靠 API 日志无法判断访问是否合法，还需要 OpenTelemetry 记录端点级原子操作，以及端点采集获取配置文件和插件信息。文章最后强调，真正的治理需要将遥测数据与组织上下文、身份权限关联，实现最小权限和及时撤销。

💡 主要观点

  1. Claude Code 等本地执行框架带来新型安全风险 Agent 运行在开发者机器上，继承员工凭据和权限，Token Security 调查显示 68.6%的 AI Agent 是本地 Agent，但 82%的安全团队发现过未知 Agent。
  2. Anthropic 合规性 API 新增本地会话记录端点 可捕获 Agent 与模型交互的 text、tool_use、tool_result 三类数据，覆盖 bash 命令、MCP 调用、文件读写，但仅记录到达模型的内容。
  3. 单一数据源不足，需三层治理方案 第一层托管设置提供策略基线但缺乏上下文；第二层 Compliance API 提供会话可见性；第三层端点采集获取配置文件、skill 和插件信息。
  4. OpenTelemetry 补充原子级操作日志 记录钩子决策、权限模式切换等合规性 API 看不到的操作，但不覆盖非 Anthropic 模型的会话。
  5. 最终治理需要身份与意图关联 遥测数据必须与企业代码仓库、权限清单关联，才能判断访问是否合理，实现最小权限和及时撤销。
