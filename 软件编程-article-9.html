可选择禁用 GitHub Actions 的 `deployment_status` Webhook 事件 - Vercel

5/1/2025, 1:00:00 PM

📌 一句话摘要

Vercel 允许禁用 `deployment_status` Webhook 事件，并建议使用 `repository_dispatch` 事件显著优化 GitHub Actions 工作流程。

📝 详细摘要

Vercel 现在允许用户禁用 `deployment_status` Webhook 事件。启用 `deployment_status` 事件会为 GitHub Pull Request 中的每个部署创建一个状态事件日志，可能会导致嘈杂的事件日志，尤其是在单体仓库中。禁用这些事件可以防止重复的消息污染 GitHub PR 历史记录，从而节省 CI 资源并提高开发效率。Vercel 建议迁移到 `repository_dispatch` 事件，该事件提供更丰富的 Vercel 部署信息，以简化工作流程。

💡 主要观点

  1. 禁用 `deployment_status` 事件可减少 PR 历史记录中的干扰信息。 禁用 Vercel 的 `deployment_status` Webhook 事件可防止 Pull Request 中出现过多的状态事件日志，从而保持更清晰的事件历史记录。
  2. 迁移到 `repository_dispatch` 事件可简化工作流程并提供更丰富的 Vercel 部署信息 Vercel 建议使用 `repository_dispatch` 事件而不是 `deployment_status` 事件，以获得更丰富的 Vercel 部署信息并简化 GitHub Actions 工作流程。

💬 文章金句

  • 您现在可以禁用 Vercel 在连接到您的 GitHub 仓库时发送到 GitHub 的 [`deployment_status` Webhook 事件](https://docs.github.com/en/webhooks/webhook-events-and-payloads#deployment_status)。
  • 禁用这些事件可以防止重复的消息污染您的 GitHub PR 的事件历史记录，从而为您提供更清晰、更集中的 Pull Request 活动视图。
  • 我们建议[迁移到 `repository_dispatch` 事件](https://vercel.com/docs/git/vercel-for-github#migrating-from-deployment_status)以简化工作流程，并提供更丰富的 Vercel 部署信息。
