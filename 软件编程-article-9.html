CopyEscape Docker 漏洞允许恶意容器覆盖宿主机文件并获得 Root 权限

8/13/2026, 10:00:00 AM

📌 一句话摘要

Docker 曝光 CopyEscape 漏洞（CVE-2026-17106），恶意容器可通过符号链接竞态条件覆盖宿主机文件，并在 Linux 特定条件下获取 Root 权限，影响 docker cp 及 AI 沙箱 sbx cp 命令。

📝 详细摘要

Imperva 红队发现的 Docker CopyEscape 漏洞（CVE-2026-17106）利用文件系统竞态条件与符号链接检查缺陷，允许恶意容器在 docker cp 操作中覆盖宿主机任意文件，并在 Linux 提升权限运行时实现 Root 代码执行。漏洞根因是 Docker 归档传输管道中路径验证与实际解压路径不匹配，攻击者可通过精心时序的目录交换操作绕过沙箱隔离。该漏洞威胁 CI/CD 流水线、开发环境及 AI Agent 沙箱，Docker 已在 29.7.2 等版本修复，建议升级或采用临时缓解措施。

💡 主要观点

  1. 漏洞核心是归档传输管道的路径验证缺陷。 Docker 在解压归档时，验证的是构造路径，但实际使用未验证的归档路径创建符号链接，导致恶意容器可通过竞态条件将文件写入宿主机任意位置。
  2. Linux 下可实现 Root 权限获取。 若 docker cp 以提升权限运行（如 sudo），攻击者可覆盖系统二进制文件（如 runc），直接获得 Root 访问权限。
  3. 漏洞影响范围广泛。 除 docker cp 外，Docker 沙箱的 sbx cp 命令同样受影响，AI 编码 Agent 环境从不受信任沙箱检索文件时面临逃逸风险。
  4. 修复与缓解措施已明确。 Docker 已发布修复版本（Engine/CLI 29.7.2、Desktop 4.86.0、Sandboxes 0.38.0），临时措施包括避免对不受信任容器执行 docker cp、停止容器后复制文件等。

💬 文章金句

  • 归档解压本身就是一个安全边界，一旦符号链接和并发文件更改进入场景，仅靠路径字符串检查是无法保证安全的。
  • 安全分析师为了调查而从受感染容器中提取证据时，可能会在不知不觉中触发该漏洞。
