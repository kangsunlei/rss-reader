从研发经验到团队知识：Akashic 知识工程实践｜得物技术

11/18/2026, 10:30:00 AM

📌 一句话摘要

本文介绍了得物团队通过 Akashic 知识工程实践，将研发过程中的代码变更、对话结论和团队经验系统化沉淀到 Git 维护的知识库中，形成闭环知识积累的方案。

📝 详细摘要

随着 AI 深度参与日常研发，团队知识分散在代码、文档和研发对话中。为解决人工难以及时沉淀知识的问题，得物团队构建了 Akashic 知识工程体系。该体系通过 Git 仓库统一维护 L1（AGENTS.md 入口）、L2（模块文档和 Skill）、L3（源码注释）三层知识库结构，结合代码变更同步检查和对话知识回写机制，实现知识与代码的持续同步。全流程由 Akashic CLI 统一管理，Agent 负责提炼与复核，Owner 审核后合入仓库，最终形成一条知识库支撑研发、研发产出推动知识库更新的闭环。

💡 主要观点

  1. 知识三层结构设计 L1 层提供全局入口路由，L2 层承载模块文档和操作 Skill，L3 层贴近代码实现细节，按读取时机和适用范围分层，避免 Agent 加载无关上下文。
  2. 代码变更同步机制 通过 Akashic-Knowledge Skill 在提交代码时自动检查变更文件与知识库映射关系，判断文档是否需同步更新，确保知识随代码走，无需人工主动维护。
  3. 对话知识回写流程 从 OSS 归档会话中提取候选知识，Session Agent 提炼结论，Audit Agent 复核证据，最终以 MR 形式提交，Owner 审核后入库，实现对话经验的系统化沉淀。
  4. 本地 CLI 统一能力基座 Akashic CLI 统一管理工具安装、配置同步和会话采集，自动触发安装、版本更新和 Git Hook 上传，会话，降低团队成员操作门槛和工具不一致风险。
  5. 对话洞察反馈闭环 通过统计轮次、Token 等指标，归纳主题和补充信号，帮助团队发现知识缺口和 AI 应用问题，指导后续优化 AI 协作能力。

💬 文章金句

  • 团队知识逐渐分散在代码、文档和研发对话中：代码承载实现方式，文档沉淀架构和规则，对话则保留问题背后的取舍、边界和经验。
  • 由此形成一条持续累积的闭环：知识库支撑研发任务，任务产生代码和对话，代码与对话再推动知识库更新，让一个人走通的路径或踩过的坑成为团队成员在后续任务里复用的经验。
  • Akashic 把知识库初始化、代码变更检查、会话采集和候选知识提炼接入研发流程，让需要维护的内容随研发流程被发现并更新，不再依赖事后补充。
