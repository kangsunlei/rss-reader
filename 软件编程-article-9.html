一个跑在 Claude Code 之上的元调度层，这个 GitHub 项目有趣。

6/19/2026, 5:52:00 AM

📌 一句话摘要

本文介绍开源项目 Omnigent，一个跑在 Claude Code、Codex 等 AI 编程 Agent 之上的元调度层，支持多 Agent 协同、交叉审查、跨设备接力与策略治理。

📝 详细摘要

文章以一个有趣的视角切入：当开发者深度绑定某个 AI 编程 Agent（如 Claude Code、Codex）时，迁移成本高，且单一模型存在盲区。Omnigent 正是为解决此问题而生——它将自己定位为 meta-harness（元调度层），跑在所有 Agent 之上。核心能力包括：同一 session 内调度多个 Agent 并实现交叉审查（如让 Codex 审查 Claude Code 的代码）、跨设备无缝接力（终端→浏览器→手机）、以及内置三层策略系统（server/agent/session 级）实现可控治理。文章重点介绍了内置的「技术总监」Agent Polly，它不写代码，而是负责拆解任务、并行分派给多个子 Agent、组织交叉审查，最终由人类拍板合并。此外还介绍了上手方式（一行命令安装、YAML 文件定义 Agent）、实时协作模式（Share session / Co-drive / Fork），并提示项目仍处 alpha 阶段，依赖较重（Python 3.12+、Node 22、tmux）。

💡 主要观点

  1. Omnigent 定位为 meta-harness，跑在所有 AI 编程 Agent 之上。 它不是又一个 Agent，而是一层调度系统，让开发者可以在同一 session 中切换或同时使用 Claude Code、Codex、Cursor 等，并让它们互相审查代码。
  2. 交叉审查机制是核心亮点，利用不同模型的盲区互补。 Claude 和 GPT 系列各有优劣势，让一个 Agent 写代码、另一个来自不同厂商的 Agent 做 review，比单押一家更稳健，类似工程团队中的 cross-review 实践。
  3. 内置的 Polly Agent 模拟技术总监角色，实现任务分解与并行调度。 Polly 不写代码，负责理解需求、拆解任务、并行分派给多个子 Agent（在独立 git worktree 中工作），然后组织交叉审查，最终由人类决定是否合并。
  4. 上手门槛不高，但依赖较重且仍处 alpha 阶段。 安装一行命令，Agent 定义只需一个 YAML 文件，支持一行切换底层引擎。但需要 Python 3.12+、Node 22、tmux，Linux 还需 bubblewrap 沙箱，不适合生产环境。

💬 文章金句

  • 如果有一层上层建筑，能让你随时切换、甚至让 Claude Code 和 CodeX 互相审查对方的代码呢？
  • 每个模型都有自己的盲区。Claude 可能在某些模式上稳定但缺想象力，GPT 可能更激进但容易出 corner case。让它们互相挑刺，比单押一家要稳得多。
  • harness 是发动机，meta-harness 是底盘和方向盘。你可以在同一辆车上换发动机，也可以同时装好几台发动机一起跑。
