国产编程神器，ZCode 再次升级！

8/12/2026, 9:05:00 AM

📌 一句话摘要

ZCode 升级后重点优化 GLM 深度适配与缓存命中率，作者实测用它 5 分钟基于 anydoc 构建文档转 Markdown 工具，配合闲时任务几乎不耗套餐积分。

📝 详细摘要

文章介绍智谱 ZCode 的新一轮升级：用户数突破百万，GLM Coding Plan 限额重置，产品主打深度适配 GLM 模型与提升缓存命中率。作者以实际任务验证效果，用 ZCode + GLM 基于开源 Rust 库 anydoc 从零构建本地文档转 Markdown Web 工具，通过 /goal 设定可验收目标，ZCode 自动拆解任务、派出子智能体调研代码并迭代完成，耗时约 5 分钟、Token 消耗 184.3 万。随后作者尝试闲时任务队列，为工具新增批量转换、自动化测试与打磨收尾三个任务，三个任务合计消耗 680 万 Token 但完全不计入套餐积分；叠加 1.5 倍额度活动后，整个项目仅消耗约 140 积分，缓存命中率高达 94%。文章也列出了闲时任务的限制：需要电脑保持唤醒、每日限 3 个、仅支持桌面端本地项目且需有效 Coding Plan 订阅。最后强调工具层把模型用满用省才是竞争下半场的关键，并引导读者下载体验。

💡 主要观点

  1. ZCode 升级聚焦 GLM 深度适配与缓存命中率提升，能显著降低使用成本。 作者实测缓存命中率达 94%，七成多消耗走缓存计费，整个项目仅消耗约 140 积分，说明高命中率是省钱的关键设计。
  2. 通过 /goal 设定可验收目标，ZCode 能自主拆解任务并迭代完成。 任务目标写清楚后，ZCode 先派子智能体调研 anydoc 源码，再开发本地 Web 工具，并在每轮自行跑构建验证，直到无报错和样例全部转换成功。
  3. 闲时任务利用平台空闲算力执行，不消耗套餐积分。 三个闲时任务共消耗 680 万 Token，但套餐内消耗量保持不变，适合处理批量转换、自动化测试等非紧急开发任务。
  4. 模型能力差距收窄后，工具层如何用满用省模型成为竞争重点。 作者认为国产模型写代码能力已跟上，未来体验差异更多来自工具层对模型调度、缓存和成本的控制。

💬 文章金句

  • 模型之间的差距在收窄，工具层怎么把模型用满、用省，才是下半场真正拉开体验的地方。
