消除冷启动 2：分片与征服

9/26/2025, 2:00:01 PM

📌 一句话摘要

Cloudflare 引入了使用一致性哈希的 Worker 分片技术，以显著减少冷启动，并提高其无服务器 Workers 平台的热请求率。

📝 详细摘要

Cloudflare 详细介绍了一种新技术——Worker 分片，旨在进一步减少其无服务器 Workers 的冷启动。文章解释说，随着 Workers 在复杂性和规模上的增长，之前在 TLS 握手期间进行预热的方法效果变差，导致冷启动时间超过握手持续时间。新方法利用类似于其 CDN 缓存的一致性哈希环，智能地将请求路由到数据中心内现有的热 Worker 实例。这种策略将低流量 Workers 合并到更少的服务器上，从而大幅降低淘汰率，并将热请求率从 99.9% 提高到 99.99%。文章还解决了服务器过载和复杂的嵌套 Worker 调用等挑战。为了应对这些挑战，文章采用了基于 Cap'n Proto RPC 的乐观分片技术，并通过序列化执行上下文来管理嵌套调用。这些措施显著提升了效率，并改善了用户体验。

💡 主要观点

  1. Worker 复杂性超过了 TLS 握手预热，因此需要一种新的冷启动策略。 为了支持复杂的应用程序，Cloudflare Workers 在脚本大小和 CPU 限制方面有所增长。然而，这也导致冷启动时间开始超过 TLS 握手持续时间，从而降低了初始预热技术的有效性。
  2. Cloudflare 实施了 Worker 分片技术，使用一致性哈希环将请求路由到热实例。 该方案利用一致性哈希环，将特定 Workers 的请求路由到数据中心内的指定 '分片服务器'。这显著降低了冷启动的频率，并提高了资源利用率。
  3. 分片机制大大降低了 Worker 淘汰率，并提高了热请求率。 尽管仅对总流量的 4% 进行了分片，但该系统实现了全球 Worker 淘汰率降低 10 倍，并将企业流量的热请求率从 99.9% 提高到 99.99%。
  4. 乐观分片和 Cap'n Proto RPC 解决了过载和复杂的嵌套 Worker 调用。 为了处理潜在的过载，请求会被乐观地分片。如果分片服务器拒绝请求，则可以选择在本地进行冷启动。Cap'n Proto RPC 能够序列化复杂的调用上下文，从而在多个分片服务器上实现无缝执行。

💬 文章金句

  • 通过在 TLS 握手期间预热 Workers 来消除冷启动对我们来说是向前迈出的一大步，但“完全避免”是一个强烈的词。
  • 一毫秒远小于典型的冷启动，这意味着在每个可衡量的方面，将请求代理到热的 Worker 都比冷启动一个新的 Worker 更好。
  • Worker 冷启动类似于 HTTP 缓存未命中，因为对热 Worker 的请求就像 HTTP 缓存命中。
  • 尽管分片总速率较低，但我们将全球 Worker 淘汰率降低了 10 倍。
  • 对于企业流量，我们的热请求率从 99.9% 提高到 99.99% —— 这是从 99.9% 提升至 99.99%。
