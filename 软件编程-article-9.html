Sudo 高危漏洞曝光，本地用户可绕过提权时间限制

9/27/2026, 10:00:00 AM

📌 一句话摘要

Sudo 曝出高危漏洞 CVE-2026-96512，本地攻击者可通过构造恶意 TZ 环境变量绕过基于时间的提权限制（NOTBEFORE/NOTAFTER），影响 1.8.20 至 1.9.17p2 版本，建议立即升级或显式配置 UTC 时间戳。

📝 详细摘要

文章报道了 Linux 权限管理工具 Sudo 中的高危安全漏洞 CVE-2026-96512。该漏洞源于 Sudo 在处理未显式指定时区的时间戳时，直接继承并信任用户可控的 TZ 环境变量，导致攻击者可通过设置极端 POSIX 时区偏移值（如 TZ=XXX24）使时间判断前后偏移约 25 小时。这使得已过期的 NOTAFTER 规则被判定为有效，或未生效的 NOTBEFORE 规则被提前放行，从而突破临时授权限制进行提权。虽然该漏洞无法绕过密码认证且需具备本地合法账号及特定 sudoers 配置，但 Red Hat 仍将其评级为高危。上游维护者已提交修复补丁，移除运行环境中的用户可控 TZ 变量，但截至发稿尚未发布正式更新版本。管理员应排查受影响版本系统，并在配置中优先使用显式 UTC 时间戳以降低风险。

💡 主要观点

  1. TZ 环境变量处理缺陷导致时间访问控制失效 Sudo 作为 setuid-root 程序启动时会继承调用者的环境变量。其 parse_gentime() 函数在处理未指定时区的时间戳时依赖 mktime() 和 TZ 变量，攻击者可构造特殊 TZ 值（如 XXX24）使时间计算偏移约 25 小时，从而绕过 NOTBEFORE 和 NOTAFTER 规则。
  2. 漏洞利用存在特定前提条件 攻击者必须拥有本地系统的合法认证账号，且该账号在 sudoers 中配置了带时间限制的权限规则。该漏洞不能绕过密码认证或 PAM 机制，主要破坏的是基于时间窗口的临时授权控制。
  3. 修复方案与缓解措施明确 上游维护者 Todd Miller 已提交补丁，通过在设置时区时从环境中移除用户可控的 TZ 变量来修复问题。在官方更新发布前，管理员应在 sudoers 配置中尽可能使用显式的 UTC 时间戳或时区偏移值，以减少歧义和风险。

💬 文章金句

  • Sudo 是 setuid-root 程序，启动时会直接继承调用用户的环境变量，本地用户可在执行 Sudo 命令前，预先设置经过特殊构造的时区值。
  • 如果用户设置极端的 POSIX 时区偏移值（例如 TZ=XXX24），可让 Sudo 对授权时间的判断前后偏移约 25 小时。
  • 补丁会在 Sudo 设置时区时，从运行环境中移除用户可控的 TZ 变量，避免 mktime()函数重复调用时读取攻击者构造的时区值。
