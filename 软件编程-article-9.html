通过封装 Axios 和安全请求函数，实现业务层无 try-catch 的优雅异步错误处理，提升代码可读性和健壮性。

📝 详细摘要

文章详细介绍了一种在前端项目中消除业务层 try-catch 的异步请求错误处理方案。首先，作者指出传统 try-catch 方式导致代码冗余、错误处理逻辑分散的问题。为解决此痛点，文章提出核心目标是实现“不抛异常的安全请求封装”。具体实现步骤包括：1. 封装 Axios 实例，统一处理请求头（如 token）、响应数据格式以及通用错误提示。2. 引入一个名为`safeRequest`的关键函数，该函数接收一个 Promise，并将其可能抛出的异常捕获，以`[err， data]`的元组形式返回，从而避免异常在业务层扩散。3. 结合 API 模块，在业务组件中通过`safeRequest`调用接口，并通过解构赋值获取错误或数据，实现清晰的错误判断。文章还进一步优化了`safeRequest`，增加了自动错误提示的开关选项，并提供了 TypeScript 类型支持，以提升开发体验和代码健壮性。此方案有效简化了业务代码，使错误处理更加集中和可控。

💡 主要观点

  1. 传统 API 请求中的 try-catch 模式存在代码冗余和错误处理分散的问题 在每个异步请求中重复编写 try-catch 块导致代码量大、逻辑分散，降低了代码的可读性和可维护性，且不易统一管理错误提示。
  2. 通过封装 safeRequest 函数实现非侵入式的异步错误处理 safeRequest 函数将 Promise 的成功和失败结果统一包装为`[err， data]`元组返回，使得业务层无需直接使用 try-catch，从而简化了错误判断逻辑，提高了代码的整洁度。
  3. Axios 拦截器与 safeRequest 结合，提供统一的请求和错误处理机制 Axios 请求和响应拦截器负责处理 token、数据格式转换及全局错误提示，与 safeRequest 配合，共同构建了一套集中、高效且对业务层透明的请求与错误管理体系。

💬 文章金句

  • 💡 目标：**「不抛异常的安全请求封装」**
  • 这就是关键！它让所有 Promise 都变得「温柔」------不再抛出异常，而是返回结构化结果。
  • 拦截器的作用：✅ 统一处理 token；✅ 统一处理错误提示；✅ 保证业务层拿到的永远是"干净的数据"。
  • 是不是很优雅、数据逻辑清晰、不需要 try-catch、 错误不崩溃。
  • 如果你用的是 TypeScript，可以让返回类型更智能
