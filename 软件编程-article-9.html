微软发布 Azure Functions 对模型上下文协议服务器的支持

1/19/2026, 10:25:00 AM

📌 一句话摘要

微软已将其对 Azure Functions 的模型上下文协议（MCP）支持正式发布，通过标准化身份验证和可流式传输的 HTTP 传输增强 AI 智能体对企业数据的安全访问。

📝 详细摘要

支持，这标志着向标准化、身份安全的智能体工作流程迈出了重要一步。此次更新通过集成原生 On-Behalf-Of（OBO）身份验证和可流式传输的 HTTP 传输，解决了历史上阻碍 AI 智能体访问敏感企业数据的 '安全痛点'。MCP 扩展现在支持 .NET、Java、JavaScript、Python 和 TypeScript。新的自托管选项允许部署现有的基于 MCP SDK 的服务器而无需代码更改。由 Anthropic 开发并被主要 AI 平台采用的模型上下文协议，为 AI 智能体访问外部工具和数据提供了标准化接口，服务器下载量呈指数级增长。文章强调这些新功能（包括内置身份验证和授权）如何促进在企业环境中安全部署 AI 智能体，简化了之前 AI 集成中复杂且存在风险的方面。

💡 主要观点

  1. 微软的 Azure Functions 现在提供对模型上下文协议（MCP）的正式支持 这一发展使得能够创建标准化、身份安全的智能体工作流程，对于 AI 智能体安全地与敏感企业数据系统交互至关重要。
  2. 更新集成了原生 On-Behalf-Of（OBO）身份验证和可流式传输的 HTTP 传输 这些功能直接解决了之前限制 AI 智能体访问关键下游企业数据的 '安全痛点'，确保强大的身份验证和高效的数据交换。
  3. MCP 支持扩展到多种编程语言，并包括自托管部署选项 开发人员现在可以使用 .NET、Java、JavaScript、Python 和 TypeScript 构建支持 MCP 的工具，并具有将现有的基于 SDK 的服务器部署到 Azure Functions 而无需代码修改的灵活性。
  4. 模型上下文协议（MCP）为 AI 智能体与外部系统交互提供了标准化接口 最初由 Anthropic 开发并被 OpenAI、Google DeepMind 和 Microsoft 等主要 AI 平台采用，MCP 简化了 AI 智能体访问工具和数据源的方式，促进了更广泛的采用和互操作性。
  5. 具有内置治理功能的托管平台对于企业采用 AI 智能体至关重要 对安全、合规环境的需求源于企业对 '影子智能体' 访问敏感数据的担忧，突显了 Azure Functions 在为 MCP 服务器提供治理解决方案方面的作用。

💬 文章金句

  • 微软已将其对 Azure Functions 的模型上下文协议（MCP）支持正式发布，标志着向标准化、身份安全的智能体工作流程的转变。
  • 通过集成原生 OBO 身份验证和可流式传输的 HTTP 传输，此次更新旨在解决历史上阻止 AI 智能体访问敏感下游企业数据的 '安全痛点'。
  • 由 Anthropic 开发的模型上下文协议提供了一个标准化接口，使 AI 智能体能够访问外部工具、数据源和系统。
  • 安全和合规团队不能允许在开发人员笔记本电脑上运行的任意、未经审查的 '影子智能体' 访问关键数据系统，如电子健康记录或客户个人身份信息。
  • 你的 Python 或 Node 脚本永远不会看到身份验证逻辑。平台处理繁重的工作。
