📌 一句话摘要

本文基于 Anthropic 官方博客和 Claude Code 创始人 Boris Cherny 的分享，系统总结了在百万行级别大代码库中使用 Claude Code 的 7 个核心实践，核心观点是 harness（外围基建）比模型本身更重要。

📝 详细摘要

文章围绕「大代码库下如何用好 Claude Code」这一核心问题，提炼了 7 个高频踩坑点并给出官方答案。核心概念是「harness」—— 围绕模型搭建的工具链（CLAUDE.md、Hooks、Skills、Plugins、MCP、LSP、子 agent）对最终效果的影响比模型本身更大。具体实践包括：CLAUDE.md 单文件控制在 200 行以内并分层加载、在子目录启动 Claude 而非根目录、安装 LSP 实现符号级代码搜索、用 subagent 和会话拆分处理跨文件改动、将高频操作封装为 skill 并用 plugin 分发、最后用 MCP 连接外部系统。文章还分享了创始人 Boris 的日常用法，并坦诚指出 Claude Code 最擅长的是「Git + 工程师 + 标准目录」场景，游戏引擎等非常规项目需要额外配置。

💡 主要观点

  1. Harness 比模型本身更重要，Claude Code 的效果取决于外围基建的搭建。 Anthropic 官方提出「The harness matters as much as the model」，强调 CLAUDE.md、Hooks、Skills、Plugins、MCP、LSP 和子 agent 这七层工具链对最终效果的影响远超模型选型。
  2. CLAUDE.md 单文件应控制在 200 行以内，采用分层加载策略。 根目录只放跨包通用约定，子目录放模块细节，Claude 会自动从当前目录往上加载。超过 200 行后指令被忽略的概率会明显上升，需每 3-6 个月审查一次。
  3. 大代码库下应使用 agentic search 而非 RAG，配合 LSP 和子目录启动。 Claude Code 不依赖 embedding 和向量数据库，而是让模型像真人工程师一样逐层探索代码。安装 LSP 后可按符号精确搜索，在子目录启动可避免加载无关 context。
  4. 跨大量文件的改动应拆分为多个会话，使用 subagent 探索、主 agent 执行。 先派 subagent 独立探索并生成 findings 报告，主 agent 基于报告在干净 context 中实现。大规模迁移可用 /batch 命令并行处理。
  5. 团队推广需将好实践封装为 skill 和 plugin，并指定专人维护。 Skill 按需加载不占 context，plugin 打包分发让全团队共享配置。推广最顺的组织会先安排一小队人搭好基础设施，并设置 Agent Manager 或 DRI 负责维护。

💬 文章金句

  • Ruthlessly edit your CLAUDE.md over time.
  • Pour your effort into the plan so Claude can one-shot the implementation.
  • 如果一件事你一天做超过一次，就把它做成 skill。
