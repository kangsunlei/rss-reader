Superpowers：给 Claude Code 装上“工程大脑”

6/15/2026, 10:00:00 AM

📌 一句话摘要

本文深度解析 Superpowers 项目，阐述其如何通过 14 个内置技能为 Claude Code 施加工程纪律，将 AI 编码从概率性的自由输出转变为确定性、可复现的工程流程。

📝 详细摘要

文章以作者在 querit.ai 项目中遇到的 AI 编码痛点开篇，指出裸跑 Claude Code 存在回答随机性、直觉快思考和注意力稀释三大原罪。随后引入 Superpowers 项目，详细介绍其作者 Jesse Vincent 的背景、项目诞生动机、现象级增长数据及 Anthropic 官方认可。文章核心部分深度解剖了 Superpowers 的 14 个核心技能、整体工作流程和 Skill 文件结构，并以 brainstorming 技能为例，通过源码解析和对比实验，展示了其如何通过强制指令、结构模板、状态锁定和链式调用等技巧改变 LLM 的概率分布，将 AI 从自由艺术家转变为守纪律的工程师。文章还探讨了 Superpowers 与《The Bitter Lesson》的关系，认为两者不在同一层面竞争，并预测当模型内生能力补足纪律缺口后，此类外挂将被淘汰。最后，文章通过复盘 querit.ai 订阅支付前端案例，对比了使用 Superpowers 前后的开发流程差异。

💡 主要观点

  1. AI 编码代理缺少的不是能力，而是纪律。 原生 Claude Code 倾向于直接输出代码，容易遗漏需求澄清、边界处理和测试等关键步骤，导致结果不稳定、漏洞百出。Superpowers 通过强制流程约束来解决此问题。
  2. Superpowers 通过改变 LLM 的概率分布来约束其行为。 通过系统提示词注入，将“先澄清需求、设计方案”等正确行为的概率大幅提升，将 AI 从概率性的自由采样转变为遵循确定性流程的工程执行。
  3. Superpowers 的设计哲学是“管理 AI 代理如同管理初级程序员”。 作者 Jesse Vincent 将 30 年管理开发团队的经验应用于 AI 代理，通过定义清晰的流程、强制验证和状态锁定，确保 AI 输出的一致性和可靠性。
  4. Superpowers 与《The Bitter Lesson》不矛盾，两者处于不同层面。 《The Bitter Lesson》讨论如何让模型更聪明，而 Superpowers 讨论如何让一个已经聪明的模型在当前任务中稳定地表现出所需行为，属于人机协作中的流程管理艺术。

💬 文章金句

  • AI 编码代理缺少的不是能力，而是纪律。
  • Superpowers 不让 AI 变聪明，而是让 AI 守纪律。
  • 施加一位资深工程主管会对初级开发者执行的同样纪律：停下来、思考、规划、再构建。
  • Superpowers 不是“教 Claude 如何设计”，而是“强制 Claude 按设计流程走”。
