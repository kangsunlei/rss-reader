程序员别急着复制“全自动开发”！Gas Town 作者：软件工厂先惊艳、后变“垃圾山”，最终还是要推倒重来

11/25/2026, 10:06:00 AM

📌 一句话摘要

Gas Town 作者 Steve Yegge 分享 AI Agent 管理 Agent 的软件工厂实践，揭示模型先惊艳后变“垃圾山”的困境，强调需关注规则堆积、运行成本及人工介入，最终建议聚焦实际产品而非单纯堆砌 Agent。

📝 详细摘要

本文基于 Gas Town 和 Beads 项目创建者 Steve Yegge 的实践经验，探讨了 AI Agent 在软件开发中的应用边界。Yegge 首次尝试让 Claude 管理 Claude 的编排系统失败，后为长期维护的 RPG 游戏 Wyvern 搭建 Wheelhouse 工厂，让 Agent 参与持续开发。文章揭示软件工厂面临的核心问题：①玩家反感高速迭代，工厂每天产出 50-100 个功能但用户无法跟上；②Agent 将日常表态记录为决策，形成“垃圾山”，旧规则与新要求冲突；③过度的限制导致系统停滞，2000 项待办却无事可做；④运行成本高昂（月均约 1 万美元），单纯加 Agent 无法解决。Yegge 提出需主动清理记录、明确会话角色衔接，并最终建议开发者应聚焦实际产品体验，而非追逐“全自动开发”。

💡 主要观点

  1. AI Agent 管理 Agent 的编排系统容易演变为难以维护的‘垃圾山’ 模型先生成优质内容，后续历史决定和规则不断堆积，导致系统僵化，Agent 面对旧限制与新需求时产生冲突，最终停滞不前。
  2. 高速自动化产出反噬用户体验，玩家要求放慢更新速度 工厂每天产出 50-100 个功能，用户无法消化和反馈，导致玩家拒绝 AI 生成的美术并要求提供路线图，说明自动化必须遵循用户可接受的节奏。
  3. 规则堆积问题需主动清理，而非简单加算 Agent Agent 将每次对话记录为决策，形成冗长的历史积累。Yegge 发现即使窗口更长也无法解决该问题，需定期审查、删除过期规则，否则会阻碍任务推进。
  4. 运行成本高昂，需关注效率而非盲目扩容 每月约 5000 美元的推理费用和 5000 美元的云计算成本（游戏月收入不足 1 万美元），导致 Yegge 要求系统主动优化运行效率，避免因加 Agent 而进一步消耗预算。
  5. 软件工厂的最终价值在于实际产品体验，而非技术堆砌 Yegge 强调，开发者在决定搭建 AI 工厂时，应先明确它替谁做事、如何验证成果，若目标不清晰，仅靠多加 Agent 只会增加被照看的工作负担。

  • 你说的每句话都会被记录下来，但这些记录只往里加，没有人清理
  • 工厂一夜没干出什么，系统里明明还有约 2000 项待办，却找不到一件被允许去做的事
  • 别只盯着 SaaS 和工具。去做游戏，做电影，做那些人们可以体验、觉得有意思的东西
