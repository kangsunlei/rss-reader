首 token 延迟降 3.25 倍！小红书联合北大、上交提出 HYPIC，让混合注意力大模型用上「位置无关缓存」

7/16/2026, 10:00:00 AM

📌 一句话摘要

小红书联合北大、上交提出 HYPIC 系统，通过缓存段累积转移算子、缝合窗口与段并行三项机制，首次在混合注意力大模型上实现位置无关缓存，将首 token 延迟平均降低 3.25 倍。

📝 详细摘要

随着 RAG 与 Agent 成为大模型服务主流形态，超长 prompt 的 prefill 阶段算力开销成为核心瓶颈。现有「位置无关缓存」（PIC）技术依赖逐 token 的 KV 缓存原语，无法应用于只暴露循环状态的线性注意力层，导致混合注意力模型（线性层占比 75% 以上）无法享受 PIC 红利。HYPIC 针对这一冲突提出三项机制：线性层缓存「段累积转移算子」T_C 与零初值末状态，实现常数时间状态组合；全注意力层用缝合窗口（默认 8 token）修复跨段注意力；段并行将长冷请求分发多 worker 并行处理。在 SGLang 上实现后，4 个生产级模型、5 个工作负载下 TTFT 平均降低 3.25 倍，同 SLO 下可持续 QPS 提升 1.66 倍，任务质量与完全重算仅差 1.71 分。

💡 主要观点

  1. 混合注意力模型中 PIC 与线性注意力层存在根本性冲突，现有 PIC 无法复用。 PIC 依赖逐 token 的 KV 缓存原语（splice/correction），而线性注意力层只暴露一个 per-request 的循环状态，无逐 token 可供操作，导致 75% 以上的层落在现有 PIC 能力之外。
  2. 段累积转移算子 T_C 是线性层 PIC 的关键，可实现常数时间状态组合。 真实末状态应为 S(C1·C2) = T(C2)·S(C1) + S(C2)，朴素相加丢失了 T(C2) 项。T_C 与 S(C|0) 只由片段内部 token 决定、与前缀无关，可缓存后按组合律复用，在 Qwen3.5-35B-A3B 第 0 层误差仅 6×10⁻⁵。
  3. 缝合窗口以极小重算开销修复全注意力层的跨段注意力偏差。 跨段注意力偏差高度集中在每个复用片段开头，HYPIC 对内部片段开头 w 个 token（默认 8）构造缝合窗口，缓存时跳过、重算时补齐；由于实际片段通常 >512 token，开销占比极小。
  4. 段并行将冷 prefill 从 O(n·|C|) 降至 O(⌈n/m⌉·|C|+c)，实现近线性扩展。 Router 探测每段命中状态，冷片段并行分发给 scatter worker，combine worker 组装结果；LPT 贪心均衡负载、流水线重叠计算与传输，与 TP/SP 等实例内并行正交可叠加。

💬 文章金句

  • 在此之前，没有任何系统能为混合注意力大模型提供 PIC。
  • T_C 和零初值末状态 S(C|0) 都只由片段内部的 token 决定，与前缀无关。
  • 它让 RAG / Agent 这类长上下文服务，在拥抱高效混合架构的同时，也能享受到片段级缓存复用的红利。
