AWS 为 S3 Tables 增加智能分层和复制功能

1/5/2026, 10:18:00 AM

📌 一句话摘要

AWS 增强了 S3 Tables 功能，引入用于自动成本优化的智能分层，以及支持跨区域和跨账号维护一致的 Apache Iceberg 表副本的复制功能。

📝 详细摘要

AWS 为 S3 Tables 推出了两项重大增强功能：智能分层和复制支持。智能分层可根据访问模式自动在频繁访问、非频繁访问和归档即时访问层之间移动数据，从而优化存储成本，且无需更改应用程序或影响性能。对于非频繁访问的数据，该功能可降低高达 68% 的成本。用户可以通过 AWS CLI 或控制台进行配置，使其成为管理高性价比数据湖的强大工具。此外，S3 Tables 现在支持复制功能，使用户能够在不同的 AWS 区域和账号之间维护其 Apache Iceberg 表的一致只读副本。这些副本在几分钟内即可完成更新，保留快照关系，并支持独立的加密和保留策略。用户可以使用各种兼容 Iceberg 的引擎（如 SageMaker Unified Studio、DuckDB 和 Apache Spark）对这些副本进行查询，从而简化了灾难恢复和地理分布式数据访问。这两项功能旨在减少管理 S3 大规模数据的手动配置和运营开销。

💡 主要观点

  1. S3 Tables 现具备智能分层功能，可自动优化存储成本。 这种新的存储类根据访问模式自动在频繁访问、非频繁访问和归档即时访问层之间移动数据，在无需手动调整策略或更改代码的情况下，为访问频率较低的数据降低高达 68% 的成本。
  2. S3 Tables 的复制支持实现了跨区域和跨账号的一致副本。 用户可以为其 Apache Iceberg 表创建只读副本，这些副本可在几分钟内保持同步，保留快照关系并允许独立加密，这对于灾难恢复和分布式分析至关重要。
  3. 这两项新功能旨在简化数据管理并减少大规模数据湖的运营开销。 智能分层消除了对 Iceberg 数据进行手动生命周期策略管理的需要，而复制功能则为维护不同环境间的数据一致性提供了原生解决方案，从而节省了工程时间。

💬 文章金句

  • 在 30 天没有访问后，数据会移动到非频繁访问层；90 天后，它会移动到归档即时访问层。这一切的发生无需更改您的应用程序，也不会影响性能。
  • 大多数分析数据集在一段时间内是“热”的，然后慢慢变冷。通过 S3 Tables 上的智能分层，您不再需要不断调整 Iceberg 数据的生命周期策略。
  • 副本表可以使用 Amazon SageMaker Unified Studio 或任何兼容 Iceberg 的引擎进行查询，包括 DuckDB、PyIceberg、Apache Spark 和 Trino。
  • 原生复制支持让您可以创建在几分钟内保持同步的只读副本，并且这些副本仍然可以作为 Iceberg 表进行查询。更少的自定义管道，更多的时间用于实际使用数据。
