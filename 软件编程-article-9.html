R2 SQL：一种新型分布式查询引擎深度解析

9/25/2025, 2:00:00 PM

📌 一句话摘要

Cloudflare R2 SQL 是一款无服务器分布式查询引擎，专为 R2 上的 PB 级数据设计，它利用 Iceberg 元数据和并行执行，实现高效且快速的分析。

📝 详细摘要

本文深入探讨 Cloudflare 的 R2 SQL，这是一种新型的无服务器分布式查询引擎，旨在高效查询存储在 R2 中的 PB 级数据。它通过引入两阶段架构，解决了在对象存储中查询海量数据集时 I/O 和计算所面临的根本挑战：查询规划器和查询执行系统。查询规划器智能地利用 R2 数据目录（Apache Iceberg）的元数据，包括分区和列级别统计信息，以缩小搜索范围并最大限度地减少读取的数据量。它采用预先排序的流式处理管道，以尽早开始执行，并支持 LIMIT 查询的提前终止。然后，查询执行系统将工作单元（行组）分发到 Cloudflare 全球网络中的查询工作器，这些工作器利用 Apache DataFusion 进行并行、向量化和列选择处理。查询结果通过 Apache Arrow 和 gRPC 进行高效聚合和返回。R2 SQL 旨在为大规模数据集上的高级分析提供可扩展、经济高效且易于操作的解决方案，从而消除管理传统查询引擎集群的开销。

💡 主要观点

  1. R2 SQL 通过智能数据修剪和大规模并行处理，解决了对象存储上 PB 级数据的 I/O 和计算挑战。 它采用查询规划器进行智能数据修剪以最大限度地减少读取，并采用分布式查询执行系统进行大规模并行处理，从而动态扩展计算。
  2. 查询规划器利用 Apache Iceberg 元数据进行多层数据修剪。 通过利用分区级别和列级别统计信息，查询规划器可以有效地缩小搜索范围，避免读取不相关的数据，并显著提高查询效率。
  3. 预先排序的并发管道能够及早进行查询执行和停止，从而降低整体延迟。 工作单元在可用后立即流式传输到执行器，并且基于 ORDER BY 子句的优先级处理允许提前终止 LIMIT 查询，从而减少整体延迟。
  4. 查询执行通过使用 Apache DataFusion 分布在 Cloudflare 的网络中。 查询工作器使用 DataFusion 并行处理行组，从而受益于向量化执行、列选择读取和过滤器下推，从而优化了性能和资源利用率。

💬 文章金句

  • 如何在无服务器环境下对 PB 级数据执行 SQL 查询？
  • R2 SQL 彻底消除了传统模式的限制，它是一个无服务器查询引擎，可以直接在数据所在的 Iceberg 表上执行 SQL 查询。
  • 处理数据最有效的方法是首先避免读取它。这是 R2 SQL 查询规划器的核心策略。
