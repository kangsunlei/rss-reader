Elena Samuylova 谈基于大型语言模型 (LLM) 的应用评估和 LLM 作为评判者

10/6/2025, 11:00:00 AM

📌 一句话摘要

本文讨论了评估基于大型语言模型 (LLM) 应用的最佳实践，包括 “LLM 作为评判者” 方法和 RAG 系统评估。

📝 详细摘要

InfoQ 播客采访了来自 Evidently AI 的 Elena Samuylova，她概述了评估基于 LLM 的应用的最佳实践。她强调了评估 LLM *模型*（抽象基准）和 LLM *系统*（具有提示词、RAG、数据库的特定应用）之间的区别。评估过程从迭代的 “快速测试” 开始，然后是用于实验的自动评分、预生产测试（压力测试、红队测试（一种模拟攻击的测试方法））以及生产中的持续在线监控和回归测试。讨论的关键技术是 “LLM 作为评判者”，其中 LLM 充当分类器来评估特定的输出质量，如安全性或语气。要设计自定义的 LLM 评判者，需要首先明确评估标准，并通过人工标注的数据来验证其性能。对于检索增强生成 (RAG) 系统，分别评估信息检索（搜索）和生成组件对于有效的调试至关重要。本文还涉及合成数据在数据稀缺领域中进行测试的作用，以及必要的技能组合，强调需要领域专业知识和 “分析翻译者” 角色来连接业务和技术团队。

💡 主要观点

  1. 评估 LLM *系统* 与评估 LLM *模型* 不同，前者更侧重于特定应用场景下的实际效果。 虽然模型通过抽象基准进行评估，但系统需要在其特定的应用环境中进行测试，包括提示词和 RAG 等集成，以确保实际性能。
  2. “LLM 作为评判者” 使用 LLM 来分类特定的输出质量，从而自动化评估并扩展流程。 这种方法允许 LLM 充当安全性、礼貌性或全面性等属性的评估者，从而减少手动标记工作，但明确的标准定义至关重要。
  3. 基于 RAG 的应用必须分别评估其搜索（检索）和生成组件，以实现有效的调试。 RAG 系统中的问题可能源于不良的信息检索或错误的生成；隔离这些组件有助于查明并解决问题的根本原因。
  4. 一个全面的 LLM 应用评估过程涵盖从最初的 “快速测试” 到持续的生产监控。 该过程包括迭代开发评估、用于实验的自动评分、扩展的预生产测试（压力、红队）以及部署后的持续监控和回归测试。

💬 文章金句

  • 与评估模型不同，系统评估更像是初步选型。理解不同模型的优劣固然重要，但更关键的是在实际应用中持续评估和测试系统，并在每次发布时进行验证。
  • LLM 作为评判者的理念是使用 LLM 来评估你的 LLM 系统的输出。
  • 如果你评估 RAG，实际上你需要分别评估这两件事，因为问题可能来自搜索或生成。
  • 我认为第一个问题甚至不在医学领域或其他地方，而总是在于数据。无论我们谈论什么，总是在于数据。
  • 我认为在 LLM 应用中，我们需要有专门负责评估的人员。关键在于，初期需要有人承担起评估的职责，主动理解业务领域，并在必要时寻求专业人士的帮助。
