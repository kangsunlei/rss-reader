百度网盘基于 Flink 的实时计算实践

9/1/2025, 10:01:00 AM

📌 一句话摘要

百度网盘基于 Flink 构建了名为 Tiangong 的实时计算引擎，解决了 Spark Streaming 问题，实现了高性能、低延迟、高稳定性的数据处理能力，并提供了配置化接入和精细化优化方案。

📝 详细摘要

文章详细阐述了百度网盘如何从 Spark Streaming 转向 Flink，并在此基础上自研实时计算引擎 Tiangong 的实践经验。面对 Spark Streaming 在监控告警薄弱、接入成本高、时效性低等方面的不足，网盘团队选择 Flink 作为核心，构建了支持多源异构数据、流批一体、配置化清洗、精准一次处理的 Tiangong 引擎。文章深入介绍了 Tiangong 的架构、在商业 BI 和用户策略特征计算等业务场景的应用，并重点分享了解决大状态问题、TableStorage 写入性能差等技术挑战的方案，包括状态后端优化、快照存储优化和自定义作业执行计划等。未来，该平台计划进一步实现平台化和低代码接入，以赋能更多业务线。

💡 主要观点

  1. Tiangong 引擎实现高性能低延迟实时计算 基于 Flink 构建的 Tiangong 引擎解决了 Spark Streaming 的痛点，提供高性能、低延迟、稳定的实时数据处理能力，已支持千万/s 吞吐量和数百万亿大流量场景。
  2. 配置化、低代码接入大幅降低开发门槛 Tiangong 引擎通过配置化的 Source/Sink、SQL 清洗逻辑和 UDF，实现了低代码快速接入，有效降低了实时任务的开发和维护成本，提升了业务方效率。
  3. 针对 Flink 大状态和写入性能进行深度优化 通过选择 RocksDB 增量 Checkpoint、Changelog 状态机制、状态 TTL 以及细粒度任务拆分等方案，有效解决了 Flink 在大规模应用中的性能瓶颈。
  4. 自定义作业执行计划提升资源利用率和稳定性 提供了细粒度算子并行度、分区关系、资源共享策略和算子名称优化能力，显著提升了作业运行效率，降低了资源消耗，增强了系统稳定性。

💬 文章金句

  • 为了解决 Spark Streaming 存在的监控告警薄弱、接入成本高、时效性低等问题，网盘于 2023 年初首次引入 Flink 实时计算引擎。
  • 从百度内部实时计算 RoadMap 和状态管理、流批一体、监控告警、任务管理、生态体系 等各方面我们选择基于 Flink 建设网盘内部的实时计算平台。
  • Tiangong 计算引擎目前已在数据团队、反作弊团队、用户增长等场景广泛应用，并支持数百万亿的大流量场景。
  • 基于商业策略实时核心行为相关特征依赖场景，结合核心行为以及用户付费埋点行为数据建设从 0 点实时累计特征与基于滚动窗口的近 X 分钟实时特征有助力策略侧对用户刚需需求的感知，并结合用户刚需行为个性化出价以此促进整体商业收入。
  • Tiangong 计算引擎本质基于 Flink SQL+Table API+DataStream API 做的混合计算引擎，其本质相当于 Flink SQL，因此一旦定义好 Source 和 Sink 并行度后，其任务所涉及的计算、清洗、聚合等算子都与 Source 端并行度一致，从而导致如果想要增加清洗等算子的并行度需要把 Source 的并行度也增加，从而造成资源浪费、性能降低等问题。
