Messenger 中的高级浏览保护机制是如何运作的

3/9/2026, 4:00:14 PM

📌 一句话摘要

Meta 详细介绍了结合 PIR、OPRF、TEE 和 ORAM 的多层加密与基础设施方案，旨在不损害隐私的前提下，保护 Messenger 用户免受端到端加密（E2EE）聊天中恶意链接的侵害。

📝 详细摘要

本文深入探讨了 Messenger 中的高级浏览保护（ABP）系统，该系统旨在端到端加密（E2EE）环境下，在维护用户隐私的同时，针对海量恶意 URL 数据库进行链接检测。由于服务器无法查看消息内容，ABP 利用私有信息检索（PIR）原理，允许客户端在不泄露具体链接的情况下查询数据库。文章概述了 Meta 如何通过迭代“规则集”来平衡数据库桶，从而解决非精确 URL 前缀匹配等技术难题。该架构集成了多种先进原语：用于匹配的不经意伪随机函数（OPRF）、用于安全处理的 AMD SEV-SNP 机密虚拟机、用于掩盖 TEE 内内存访问模式的 Path ORAM，以及用于去标识化网络请求的不经意 HTTP（OHTTP）。这种纵深防御方法确保了 Meta 和中间观察者都无法确定用户正在访问的具体链接。

💡 主要观点

  1. 利用私有信息检索（PIR）实现隐私保护的数据库查询。 ABP 利用 PIR 原理，允许客户端检查 URL 是否存在于恶意数据库中，而服务器无法获知具体查询了哪个 URL，解决了安全性与 E2EE 隐私之间的根本冲突。
  2. 实施迭代规则集以平衡 URL 桶并高效处理前缀匹配。 由于 URL 并非完全匹配，Meta 使用服务器生成的规则集来指导客户端如何按域名和路径段对 URL 进行哈希处理，确保即使在处理短链接服务等高流量域名时也能保持桶的平衡。
  3. 利用可信执行环境（TEE）和 ORAM 防止侧信道数据泄露。 通过在 AMD SEV-SNP 机密虚拟机中运行匹配逻辑，并使用 Path ORAM 隐藏内存访问模式，该系统确保即使是拥有宿主机管理权限的攻击者也无法推断出客户端的查询内容。
  4. 集成不经意 HTTP（OHTTP）以实现用户身份与技术链接查询的解耦。 该系统采用第三方代理和 OHTTP 协议从请求中剥离 IP 地址等标识信息，确保服务器只能看到“内容”（加密的桶 ID），而永远无法得知“发送者”。

💬 文章金句

  • 该协议旨在让服务器尽可能少地（理想情况下是完全不）获取有关客户端查询的信息。
  • 为了解决这个问题，我们让服务器执行预处理步骤，通过生成“规则集”来尝试平衡桶。
  • 尽管内存页通过 AMD 的安全嵌套分页（SNP）技术进行了加密，但访问模式本身也必须保持私密。
  • 第三方代理位于客户端和服务器之间，通过剥离标识信息来处理加密的客户端请求。
