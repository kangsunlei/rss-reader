在本文中，作者分享了他在库存推荐系统中处理 AI 智能体幻觉问题的实践经验，并介绍了解决方案。作者主张搭建一个共享大模型平台，内置提示词注册表与版本管理、Schema 强制校验、按请求进行 Token 成本归因等通用服务。

💡 主要观点

  1. FlashQLA 的定位与 GDN 线性注意力的必要性 Qwen 系列采用三层 GDN 加一层 softmax attention 的混合架构。线性注意力通过递推形式将计算复杂度从 O(N²d) 降至 O(Nd²)，但数据依赖强、GPU 利用率低。GDN 引入门控机制，是当前表达力与效率兼顾最好的线性注意力方案。
  2. 序列并行与滑动窗口的协同优化 利用矫正矩阵的结合性质，将 dK×dK 矩阵的递推结合在一起，实现卡内序列并行。统计发现约 60%~80% 的注意力头 alpha 不恒为 1，具备滑动窗口性质，可跳过完整递推直接从窗口起点开始，与序列并行方案复用算子。
  3. 硬件友好的代数改写降低 SFU 负载 通过将大 Gamma 矩阵从求逆过程中提取出来，避免在多个算子中重复计算 O(C²) 次 EXP 运算，显著降低 SFU 压力。同时优化矩阵连乘顺序，将 M 矩阵递推的数值范围控制在合理区间，从另一路径验证了滑动窗口性质。
  4. Warp specialization 流水线设计 基于 Hopper 架构将四个 warp group 分别赋予数据搬运、V' 计算、O 计算和 S 计算职责，S 矩阵常驻寄存器。通过乒乓式 two-stage 流水线与极致的 shared memory 复用，将访存、tensor core、CUDA core 和 SFU 计算全面重叠，访存负载超过 70%。
  5. 性能表现与开源生态 前向获得 2~3 倍加速，反向约 2 倍加速。项目于 2026 年 4 月开源，7 月成为 FLA 官方后端，覆盖 Hopper 与 Blackwell 全系 GPU。千问内部训练和推理链路均已接入，社区完成了部分 vLLM 集成。

💬 文章金句

  • 只要能够绕开中间那个逐行 softmax，注意力计算的时间复杂度就存在从 O(N²d) 降到 O(Nd²) 的空间。
  • 这个观察到 dK×dK 矩阵的递推可以被'结合'到一起，是序列并行的理论前提。
  • 只要一个 head 上的 alpha 不恒为 1，就一定会存在一个滑动窗口，窗口大小由 alpha 分布和 gate 数据分布共同决定。
  • 通过这种 warp specialization 设计，我们把数据搬运、tensor core 计算、CUDA core 计算以及 SFU 计算全部重叠起来。
  • 总体而言这仍然是一个 memory bound 算子。
