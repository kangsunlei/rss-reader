AI 写代码越来越快，质量谁来守？网盘主端 FE 的 AICR 准入实践

7/6/2026, 10:00:00 AM

📌 一句话摘要

百度网盘主端 FE 团队分享了如何在 CI/CD 流水线中嵌入多 Agent AI 代码审查准入系统，以应对 AI 生成代码占比超 55%后的质量保障挑战，并给出模型选型、误报治理与耗时控制的实战经验。

📝 详细摘要

文章详细阐述了网盘主端 FE 团队建设 AICR（AI Code Review）准入系统的完整实践。背景是 AI 生成代码已达月 CR 量 2000 次中的 55.87%，人工 Reviewer 压力剧增。团队选择 CI/CD 流水线作为主方案，而非 Pre-commit，核心在于统一规则管理、深度接入工作流和数据闭环。系统采用多 Agent 协作：审查 Agent（三路并行）、核实 Agent（反向验证）、复核 Agent（防止误删），在发现缺陷与控制误报之间取得平衡。文章还对比了 GLM5 与 GPT5.5 的检测效果，发现 GPT5.5 检出率提升 3.2 倍，并总结出“越高阶的模型，规则应越轻”的选型经验。此外，讨论了误报治理的常态化纠错机制、Spec 模式下 AICR 的适用性，以及从需求到合入后复盘的完整代码质量体系展望。全文基于真实数据和工程实践，具备高度可参考性。

💡 主要观点

  1. 在 AI 生成代码占比超过一半的背景下，传统人工 Code Review 压力剧增，需要 AI 辅助的代码准入机制。 团队每月 2000 次 CR 中 AI 生成代码占 55.87%，人工 Reviewer 精度与专注度下降，亟需强制性的 AI 检测链路来减负和兜底。
  2. 选择 CI/CD 流水线而非 Pre-commit 作为团队级 AICR 接入方案，核心在于统一治理、流程闭环和数据沉淀。 CI/CD 可统一管理规则、深度接入工作流、自动回写结果并沉淀数据，适合团队级准入；Pre-commit 适合个人前置自检，两者互补而非互斥。
  3. 通过多 Agent 协作（审查 Agent、核实 Agent、复核 Agent）在缺陷发现与误报控制之间取得平衡。 审查 Agent 倾向于过度发现问题，核实 Agent 倾向删除问题，复核 Agent 二次校验防止真实缺陷被误删，形成相互制衡的检测闭环。
  4. 模型选型需根据能力动态调整规则：越高阶的模型，规则应越轻。 GLM5 弱模型需强规则提升检出率；GPT5.5 高阶模型在强规则下反而过度推理，软化规则后检测时间下降、质量提升。
  5. 误报治理需要持续闭环：接受其客观存在，通过反馈收集、知识本补充、纠错本沉淀和周期复盘降低误报率。 建立用户反馈入口、每周复盘高频误报，通过纠错本固定“表面错误但业务安全”的模式，持续优化模型判断，减少噪音干扰。

💬 文章金句

  • 没有闭环的检测结果，本质上是一种噪音
  • 大模型的主观思维不是局限，而是一种可以被设计和利用的能力
  • 越高阶的模型，规则可以越轻。
  • 适合团队的，才是最好的。
