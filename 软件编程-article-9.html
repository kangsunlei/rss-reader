浏览器自动化：从 GUI 到 OpenCLI

4/14/2026, 10:01:00 AM

📌 一句话摘要

本文介绍了 OpenCLI 这一开源工具，它通过解析和复现网页底层 API 请求，而非模拟前端 UI 交互，来解决浏览器自动化的效率与稳定性难题，并阐述了其核心原理、工作流及对未来软件“可调用性”的思考。

📝 详细摘要

文章深入探讨了传统基于 GUI 的浏览器自动化（如 Puppeteer、Playwright）在效率和稳定性上的困境，并提出了一种名为 OpenCLI 的创新解决方案。OpenCLI 的核心思路是绕过不稳定的前端界面，直接抓取和复现网页背后的 API 请求。文章详细介绍了其工作原理，包括一个为 AI Agent 设计的探索工作流、针对不同鉴权方式的五级认证策略（从公开 API 到 UI 自动化）、适配器生成机制（YAML/TypeScript），以及通过 `record` 和 `explore` 命令实现 CLI 自动生成的流程。作者还分享了内部会画平台和 BOSS 直聘招聘自动化的实际用例，并最终升华观点，指出未来软件的竞争维度将从“界面”转向“可调用性”，强调为 Agent 提供清晰、稳定的调用接口的重要性。

💡 主要观点

  1. 放弃不稳定的 GUI 自动化，转向解析底层 API 是浏览器自动化的更优路径。 传统模拟点击的自动化方式易受前端 UI 变化影响，而直接调用生成数据的后端 API 接口则更加稳定和高效，OpenCLI 正是基于此理念构建。
  2. OpenCLI 为 AI Agent 设计了一套完整的 API 探索、验证与适配器生成工作流。 通过 `browser_navigate`、`browser_network_requests` 等工具，引导 Agent 主动交互页面以发现懒加载 API，并利用五级认证策略自动匹配鉴权方式，最终生成 YAML 或 TypeScript 适配器。
  3. 未来软件的竞争力将体现在“可调用性”上，而不仅仅是用户界面。 随着 AI Agent 的普及，软件需要提供稳定、清晰、易于被程序理解和调用的接口（命令、参数、返回值），才能更好地融入下一代自动化工作流。

💬 文章金句

  • 浏览器里看到的数据，本质上都是前端从某个接口拿回来的。把这个接口找出来、把请求复现出来，比点按钮靠谱得多。
  • OpenCLI 提供 5 级认证策略。使用 cascade 命令自动探测。
  • 你（AI Agent）必须通过浏览器打开目标网站去探索！不要只靠 `opencli explore` 命令或静态分析来发现 API。
  • GUI 是给人用的。API 是能力底座。而 Agent 最喜欢的，其实是更清晰的执行面：命令、参数、返回值、失败原因。
  • 未来软件可能会多一个新竞争维度：不是谁页面更好看。而是谁更容易被 Agent 理解、调用、验证，再接进工作流。
