Plan Mode 已死：大模型时代的工作流重构

9/26/2026, 1:28:50 PM

📌 一句话摘要

作者分享 HN 文章观点，认为大模型能力提升使得冗长的计划模式过时，提倡“理解-行动-检查”的敏捷流程，并指出过度依赖技能会限制模型发挥。

📝 详细摘要

推文引用了 HackerNews 上的《Plan Mode 已死》一文，核心观点是大模型能力的飞跃降低了编写详尽计划的需求。作者主张采用“understand → act → inspect → clarify → adjust → act again”的迭代流程，取代传统的先写 Spec 再执行的线性模式。同时，作者反思了许多传统开发技能在强大模型面前反而成为束缚，建议让模型自由发挥，并透露自己已卸载大量 Skills 且久未使用 Plan 模式。

💡 主要观点

  1. 大模型能力跃升导致传统 Plan Mode 失效 随着模型理解与执行能力的增强，预先编写冗长、严格的 Spec（规格说明）不仅效率低下，且不再必要。
  2. 推荐“理解-行动-检查”的敏捷交互范式 新的工作流强调边做边改（act again），通过快速迭代和即时反馈来修正方向，而非一次性交付完美计划。
  3. 警惕“技能过载”对模型潜力的限制 过多的预设 Skills 或 Prompt 约束可能框定模型的思维边界，作者主张在适当场景下减少干预，释放模型的自由创造力。

💬 文章金句

  • 大模型现在能力在飞跃 写一份给人看的冗长的 plan 的需求已经大幅的降低了
  • 它提倡一个流程是：understand → act → inspect → clarify → adjust → act again
  • 很多 skills 只会限制强大的大模型的行为方式 不如让它自由发挥
