深度访谈｜第二次权力转移：当 Agent 拿走数据库的行动权

7/30/2026, 7:30:00 AM

📌 一句话摘要

本文以阿里云数据库团队深度访谈为载体，论述 Agent 正在引发数据库领域的「第二次权力转移」，并从交互、能力、内核、安全四个层面重构数据库的产品形态与竞争壁垒。

📝 详细摘要

文章以阿里云智能集团数据库产品事业部负责人杨辛军与王远的访谈为骨架，论述 Agent 时代数据库正在经历的「第二次权力转移」。作者先以 1974 年关系模型取代导航式数据库的「第一次权力转移」作类比，指出本次转移的本质是数据库的直接使用者从人变为 Agent：Databricks 收购 Neon 后约 80% 实例由 Agent 创建，阿里云 PostgreSQL 近几个月 Agent 创建实例数已达过去 5 年累计的 3 倍。文章从四个层面展开重构：交互层从「SQL in、Table out」走向「Token in、Token out」；能力层把治理、运维、分析收拢为 DAS Agent、Meta Agent 等；内核层为 Agent 的高频试错补充分支、备份恢复、负载隔离等能力；安全层保留事务与一致性的确定性底座。文中还讨论了 DBA 角色从「执行者」转向「组织者」的分化，以及竞争壁垒从「能被调用」升级到「能被托付」的判断。

💡 主要观点

  1. Agent 正在引发数据库的「第二次权力转移」，使用者从人变为 Agent。 文章以 1974 年关系模型取代导航式模型为类比，指出本次转移的本质是 Agent 直接创建、操作数据库，Neon 约 80% 实例、阿里云 PostgreSQL 近几个月新增实例均由 Agent 创建。
  2. 数据库需要在交互、能力、内核、安全四个层面被重新设计。 交互从 SQL 走向自然语言 Token；能力被收拢为 DAS、Meta、Analytics 等 Agent；内核补充分支、备份恢复、负载隔离以适应高频试错；底层保留事务与一致性的确定性底座。
  3. DBA 角色从「执行操作」转向「组织与驾驭多 Agent 系统」。 规则清晰的工作被 Agent 接管，DBA 价值转向业务语义判断、流程重构与多 Agent 边界定义，评价标准也从救火次数变为自动化覆盖率与高风险操作限制能力。
  4. 竞争壁垒从「能被调用」升级到「能被托付」。 向量检索、MCP、分支等能力会变成入场券，真正的分水岭是企业敢不敢让 Agent 动手，这要求权限隔离、审计追溯、成本可预算等企业级能力。

💬 文章金句

  • 能被调用，决定数据库能否进入 Agent 生态；能被托付，决定它能否进入企业生产核心。
  • Agent 可以探索，但企业数据库不能把所有判断交给概率模型。
  • 原来相对固定的系统逻辑，正在变成秒级甚至亚秒级变化的执行方式。
  • 自动驾驶不等于拆掉方向盘和刹车，人仍然保留设定目标、限定范围和随时接管的权力。
