意识 × Loop：让 Loop 跨 Session 自进化的最佳实践

7/10/2026, 10:18:00 AM

📌 一句话摘要

本文以 FDE 公司调研实践为例，提出通过「意识层」（AGENTS.md / MEMORY.md / USER.md）实现 Agent Loop 跨会话自进化的方法论，并详细阐述三层对齐、手动阀门保留及搭建步骤。

📝 详细摘要

文章从 Loop Engineering 的致命问题切入——一次会话结束 Loop 即失忆，实践经验无法跨 Session 复用。作者以单人一天完成 61 家 FDE 公司 3C 深度调研（12 万字）为案例，展示了如何通过「意识层」让 Loop 自进化。意识层由三个文件构成：AGENTS.md（主动规则与 evals）、MEMORY.md（被动教训与状态）、USER.md（判断偏好）。每次会话自动加载、自动沉淀更新。文章重新定义了 Addy Osmani 六大框架中的 Worktrees 为上下文隔离以防止偏见污染，Sub-agents 用于正反对抗查找证据，State 扩展为行为塑造而非仅进度追踪。对齐方面提出三层解法：evals 对齐（AGENTS.md 承载）、场景对齐（三要素确定受众与决策）、judge 偏好对齐（USER.md 承载），三者分层不混用。特别强调两个必须保留的手动阀门：MEMORY 升格 AGENTS 需人工判断（避免偶发规律污染），硬结论下判必须亲自过稿。最后给出零基础搭建步骤、成本估算与维护建议，并指出 Loop 只放大已有 taste，不生产 taste。

💡 主要观点

  1. Loop 不自进化就只是更花哨的 prompt，意识层是其跨会话自进化的关键。 AGENTS.md（主动规则）、MEMORY.md（被动教训）、USER.md（判断偏好）三个文件在每次会话自动加载并更新，使上一次的教训和偏好跨 Session 延续，避免重复教学。
  2. Worktrees 用于上下文隔离，收益不仅是并行加速，更是防止偏见在公司之间传染。 并行调研时隔离各公司的上下文，强制每份分析从原点起步，避免因前一个分析的心智框架污染后续判断，如避免将 A 公司的商业模式套用在 B 公司。
  3. 三层对齐（evals、场景、judge 偏好）必须分层承载，不能混在一个 prompt 里。 evals 对齐由 AGENTS.md 承载客观正确性，场景对齐由启动时三要素定义，judge 偏好由 USER.md 承载个人口味，分层确保 Agent 抓重点且不冲突。
  4. MEMORY 升格 AGENTS 和硬结论下判这两个阀门必须人工保留。 自动升格可能将偶发规律污染为硬约束，需人工判断样本量足够；硬结论涉及个人信用，必须亲自过稿。

💬 文章金句

  • Loop 不自进化，就只是一个更花哨的 prompt。
  • Loop 只放大你已有的 taste，不生产 taste。
  • 调研最大的时间黑洞从来不是‘写’，是‘返工’，是写完一版被打回来补数据、补视角、补结论。
  • MEMORY 升格 AGENTS 是一个‘松变紧’的动作。MEMORY 允许试探性表达（‘这次学到’），AGENTS 是硬约束（‘以后都要’）。
