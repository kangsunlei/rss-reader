快手二面：大模型的 Function Call 能力是怎么训练出来的？

6/12/2026, 6:12:00 AM

📌 一句话摘要

本文以面试问答形式，系统讲解大模型 Function Call 能力的训练方法，核心在于 SFT 教会模型「怎么调」，RLHF 教会模型「什么时候调」。

📝 详细摘要

文章以快手二面面试题为引，纠正了「预训练就能学会 Function Call」和「SFT 只需单工具调用样本」两个常见误区。作者将训练过程拆解为两个阶段：SFT 阶段通过构造包含工具定义、用户问题、结构化 JSON 调用、工具执行结果和最终答案的完整对话样本，让模型通过模仿学习掌握调用流程；RLHF 阶段则通过人类偏好排序训练奖励模型，再用 PPO 强化学习算法调整主模型，建立「该不该调工具」的边界感。文章还详细介绍了训练数据的场景覆盖（单工具、多工具并行、失败重试、无需工具直接回答、多轮对话）和数据来源（人工标注与模型自动生成），并对比了 RLAIF 与 RLHF 的优劣。最后给出面试回答的结构化建议。

💡 主要观点

  1. 预训练无法学会 Function Call，必须靠 SFT 专项微调。 预训练基于「预测下一个 token」，语料中缺乏标准工具调用 JSON 模式，模型最多能描述意图，无法输出可被程序解析的结构化调用请求。
  2. SFT 通过完整对话样本让模型学会调用流程。 训练样本需包含 system 工具定义、user 问题、assistant 的 JSON 调用、tool 执行结果和最终答案，模型通过反向传播学习整套流程。
  3. 训练数据需覆盖多种场景，缺一不可。 除单工具调用外，还需覆盖多工具并行、调用失败重试、无需工具直接回答、多轮对话等场景，否则模型会在对应场景翻车。
  4. RLHF 解决「该不该调」的边界感问题。 通过人类对多种回答的偏好排序训练奖励模型，再用 PPO 强化学习算法调整主模型，让模型学会「能直接回答就直接回答，需要实时数据才调工具」。
  5. RLAIF 用 AI 替代人工打分，但存在偏见传递风险。 RLAIF 成本低、速度快，但打分 AI 的偏差会被学进去，业界通常混用 RLHF（关键数据保质量）和 RLAIF（大量数据提效率）。

💬 文章金句

  • SFT 教会怎么调，RLHF 教会什么时候调。
  • 预训练学到的是「预测下一个 token」，模型最多能描述「我要调 API」，但不会输出结构化 JSON 调用请求。
  • RLHF 本质上要让模型在「追求高奖励」和「保持语言能力」之间走钢丝，PPO 在这个平衡上是目前公认好用的工具。
