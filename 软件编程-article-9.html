Datadog 发布 Monocle，一款统一的 Rust 实现的实时指标引擎

9/22/2025, 2:00:00 PM

📌 一句话摘要

Datadog 发布 Monocle，一款基于 Rust 的新型实时时序引擎，统一指标存储，显著提高数据接入吞吐量、降低查询延迟并减少运维负担。

📝 详细摘要

Datadog 推出了 Monocle，一个用 Rust 构建的实时时序存储引擎，旨在整合并优化其指标存储基础设施。文章详细介绍了 Datadog 之前存储后端的演变，其中包括基于 Cassandra、Redis、MDBM、基于 Go 的 B+ 树和 RocksDB 的解决方案，每种方案在可扩展性、并发性和运维负担方面都提出了独特的挑战。Monocle 通过采用统一的每核分片、每分片工作器模型 (shard-per-core， worker-per-shard model) 来解决这些问题，其中每个工作器管理自己的日志结构合并树（LSM 树）实例。这种设计利用 Rust 的内存安全性和效率，消除了写入路径上的锁，显著减少了争用。该引擎集成了数据接入、存储和查询处理，利用内存表进行数据存储，基数树缓冲区用于数据聚合，统一缓存用于降低延迟。性能基准测试显示，与之前的系统相比，数据接入吞吐量提高了 60 倍，查询延迟降低了 5 倍，成本降低了一半。Monocle 的模块化 Rust 组件也被重新用于其他 Datadog 系统，从而增强了可维护性和一致性。

💡 主要观点

  1. Monocle 使用 Rust 统一了 Datadog 分散的指标存储基础设施。 通过替换多代不同的存储后端，Monocle 将数据接入、存储和查询处理整合到一个高效的基于 Rust 的引擎中，从而简化了运维流程，提高了资源利用率。
  2. 每核分片、每分片工作器模型显著提高了性能和效率。 这种并发模型与 Rust 的能力和 LSM 树实例相结合，实现了 60 倍的数据接入吞吐量增加和 5 倍的查询延迟降低，同时成本降低了一半。
  3. Monocle 的设计解决了关键的可扩展性和并发性挑战。 消除写入路径上的锁和原子操作，以及 Rust 的内存安全性，解决了长期存在的问题，这些问题限制了以前的架构，确保了在极端负载下的高性能。

💬 文章金句

  • Monocle 取代了几代存储后端，解决了随着时间积累的并发挑战和扩展限制。
  • 这种每核分片、异步工作器模型是实时数据库 (RTDB) 的基础。
  • 该设计消除了写入路径上的锁和原子操作，减少了争用，而 Rust 的内存保证了安全性和并发性。
  • 与早期系统相比，Monocle 的数据接入吞吐量提高了 60 倍，峰值规模下的查询延迟降低了 5 倍，成本降低了一半。
