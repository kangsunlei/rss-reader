大规模主题系统：如何构建高度可定制的软件

1/26/2026, 11:40:00 AM

📌 一句话摘要

本文深入探讨了 Shopify 基于 Liquid 的主题系统，详细介绍了自定义 DSL、结构化 JSON Schema 以及原生代码扩展如何为数百万用户实现高度可定制、可扩展且安全的软件。

📝 详细摘要

本文深入剖析了 Shopify 主题系统的架构设计，该系统旨在处理海量规模（每分钟 6000 万次请求），同时保持非技术商家的高度可定制性。其核心支柱包括：Liquid（一种安全且受限的 DSL）、Schemas（连接开发者与编辑器的 JSON 桥梁）以及高性能运行时。作者解释了 Shopify 为何放弃标准的 Ruby 模板而转向自定义 DSL，以防止安全风险和 N+1 查询等性能瓶颈。通过实施严格的资源限制和严谨的解析模式来确保向后兼容性，Shopify 保证了平台的稳定性。此外，系统使用 “Liquid Drops” 进行安全的数据暴露，并利用 C/Rust 原生扩展来优化渲染速度和内存管理，从而绕过高层语言在流量高峰期的垃圾回收停顿等限制。

💡 主要观点

  1. 自定义 DSL 为多租户平台提供了安全边界。 通过使用 Liquid 而非原始的 Ruby 模板，Shopify 阻止了第三方代码执行数据库查询或消耗过多的系统资源，从而确保了平台的稳定性。
  2. JSON Schema 充当了技术人员与非技术用户之间的通用语言。 在 Schema 中定义 UI 属性，允许开发者编写代码的同时，自动为商家生成可视化编辑器，使其无需触碰代码即可定制商店。
  3. 严格解析和向后兼容性对于生态系统信任至关重要。 在 DSL 解析中采用严格的错误模式，可以防止意外与用户建立“隐式契约”，从而允许语言在不破坏现有实现的情况下进行演进。
  4. 原生扩展针对关键性能路径优化了高层语言。 在 Ruby 中使用 C 或 Rust 扩展可以实现手动内存管理和更快的执行速度，这对于处理黑五等活动期间的海量流量峰值至关重要。

💬 文章金句

  • Liquid 的工作方式略有不同，因为它几乎是你可以在视图中执行的操作的白名单。
  • 存在于 Schema 标签内的 JSON 结构是开发者与非技术人员之间的桥梁。
  • 对渲染内容和 DSL 保持严格要求会更好……这样你才能不断演进你的 DSL。
  • 原生扩展是高层语言优化执行并让代码运行飞快的常用技术。
  • 主题系统是一套原语，它允许所有人协作共同构建一家商店。
