GPU，CPU，谁是谁的“伴侣”？—— 阿里 RTP 平台的异构资源解耦大冒险

4/4/2025, 2:23:33 AM

📌 一句话摘要

阿里 RTP 平台通过 GPU - CPU 异构资源解耦，优化 DLRM 模型部署的资源利用率，并在生产实践中进行了深入思考。

📝 详细摘要

本文深入探讨了阿里巴巴 RTP 平台为解决深度学习推荐模型 (DLRM) 部署时面临的资源分配和利用率问题，探索并实践了 GPU - CPU 异构资源解耦方案。该方案被 NSDI25 收录，具有一定的技术价值。文章分析了 DLRM 模型与 LLM 在在线部署方面的差异，以及由此带来的资源调度挑战。针对 GPU 集群资源分配效率低和高峰期资源供给不足两大问题，提出了通过资源比例归一化和灵活化来提升资源利用率的策略。重点介绍了通过将 DLRM 模型拆分为 CPU 和 GPU 子图，实现算算分离的方案。文章还讨论了在实际部署中面临的网络通信开销、训练资源释放等问题，以及相应的解决方案。最后，总结了该方案在生产环境中的收益，并对 Disaggregation 的通用性、LLM 时代的 Disaggregation 思路以及未来发展方向进行了深入思考。

💡 主要观点

  1. 资源比例归一化和灵活化是提升资源利用率的关键 通过统一 CPU / MEM 比例和灵活配置 CPU / GPU 比例，解决资源分配不均和利用率低的问题，充分利用硬件资源。
  2. 算算分离通过解耦 CPU 和 GPU 子图实现资源灵活调度 将 DLRM 模型拆分为 CPU 和 GPU 子图，分别在不同容器实例上运行，通过网络通信协同工作，实现计算资源的解耦和优化。
  3. 异构资源解耦需要在网络通信和系统复杂度之间寻求平衡 在实现 GPU - CPU 分离的同时，需要在引入的网络通信延迟和系统复杂度之间找到平衡点，并采取相应优化措施。

💬 文章金句

  • Disaggregation 是一个理想，但不是一个必然选择。
  • 训推一体的设计不适合大规模预训练任务，除非可以接受只在某些 "大促节点" 短暂地停掉任务。
  • 其实 Disaggregation 还有一个好处，它自然地划分出不同 workload ，帮助你有针对性地观测、分析、优化。
