Harness 之后，硅谷 AI 圈又来新词了：Loop Engineering

6/12/2026, 11:09:00 AM

📌 一句话摘要

本文系统介绍 Loop Engineering 概念，阐述如何构建让 AI Agent 自主循环工作的系统，并拆解其五大核心模块与在 Claude Code、Codex 中的实现。

📝 详细摘要

文章由 Founder Park 编译自 Google Cloud AI 总监 Addy Osmani 的博文，系统介绍了硅谷 AI 圈新兴概念「Loop Engineering」。核心思想是：不再由人手动提示编码 Agent，而是设计一套系统让 Agent 自动循环工作。文章详细拆解了一个完整 Loop 所需的五大核心模块——Automations（自动触发）、Worktrees（并行隔离）、Skills（项目知识固化）、Plugins & Connectors（工具接入）、Sub-agents（生成与检查分离），以及作为持久化记忆的 state file。文章以 Claude Code 和 Codex 为例，展示了这些模块在两个产品中的对应实现，并给出了一个完整的日常 Loop 示例。最后，作者强调了 Loop 工程中人的不可替代性：验证责任、代码理解债、认知投降风险，并指出设计 Loop 比提示词工程更难，工程师应带着判断去构建。

💡 主要观点

  1. Loop Engineering 的核心是用系统替代人手动提示 Agent。 不再一轮轮手动输入提示词，而是构建一个能自动发现任务、分配、检查、记录状态并决定下一步的系统，让 Agent 自主循环工作。
  2. 一个完整的 Loop 需要五大核心模块加持久化记忆。 Automations（自动触发与分类）、Worktrees（并行隔离）、Skills（固化项目知识）、Plugins & Connectors（接入外部工具）、Sub-agents（生成与检查分离），外加一个存储在磁盘上的 state file 作为跨会话记忆。
  3. 生成者与检查者分离是 Loop 中最关键的结构设计。 让写代码的模型和检查代码的模型分开，避免自我审查的盲区。这一原则也被用于判断 Loop 是否完成——应由独立模型决定，而非执行工作的模型。
  4. Loop 工程并未让工程师变得多余，反而放大了人的责任。 验证责任、代码理解债、认知投降风险是 Loop 带来的三大挑战。设计 Loop 比提示词工程更难，工程师需带着判断去构建，而非成为「按下启动键的人」。

💬 文章金句

  • 你不应该再去手动提示编码智能体了。你应该设计让智能体自动运行的 loop。
  • 智能体会忘，但代码仓库不会。
  • Build the loop. Stay the engineer.
  • 一个人用它在自己深刻理解的工作上跑得更快；另一个人用它来逃避理解工作本身。Loop 不知道这两者的区别，但你知道。
