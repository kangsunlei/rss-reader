一个回车符搞崩 Git，甚至能触发远程代码执行？

7/10/2025, 9:27:00 AM

📌 一句话摘要

一个回车符导致的 Git 子模块高危漏洞（CVE-2025-48384）被披露，攻击者可借此实现远程代码执行，需尽快更新。

📝 详细摘要

文章详细解析了 Git 子模块克隆逻辑中发现的严重漏洞（CVE-2025-48384），该漏洞源于 Git 配置解析器对回车符（\r）处理的不一致性。文章首先追溯了回车符的历史背景，阐明了不同操作系统对回车符处理的差异，以此铺垫了 Git 内部对\r 字符解析和写入逻辑的缺陷。攻击者可通过精心构造的.gitmodules 文件，在类 Unix 系统上利用此漏洞实现任意文件写入，进而触发远程代码执行。文章深入剖析了 Git 读写配置文件的代码逻辑缺陷，并与此前类似的漏洞进行对比。同时，文章提供了手动缓解措施，并强调了 GitHub Desktop 等默认开启递归克隆的工具可能面临的风险，最后给出了简洁的修复方案，并从更宏观的软件安全角度探讨了“在接收时要宽容”原则的局限性。此漏洞对开发者和运维人员具有重要的安全警示。

💡 主要观点

  1. Git 配置解析器对回车符（\r）处理不一致导致严重漏洞 Git 在读取配置文件时会忽略行尾的\r，但在写入时若无特定字符则不加引号，导致攻击者可构造含\r 的路径，使其在校验与实际使用时产生差异，形成路径混淆。
  2. 子模块克隆操作中的路径混淆可被利用实现远程代码执行 攻击者通过在.gitmodules 文件中注入带有\r 的路径，诱导 Git 将恶意文件写入任意位置，例如.git 目录下的 hook 脚本，从而在用户执行 Git 操作时触发 RCE。
  3. 用户应避免对不可信仓库使用 --recursive 参数并及时更新 Git 手动缓解措施是先普通克隆再检查.gitmodules 文件，最后手动初始化子模块。更根本的解决办法是尽快更新 Git 及相关软件到修复版本，以防范风险。

💬 文章金句

  • 一个看似无害的回车符（Carriage Return），竟然能让 Git 的子模块克隆逻辑彻底"失控"，甚至引发远程代码执行（RCE）！
  • 在类 Unix 平台上，如果你对不可信的仓库执行了 git clone --recursive 操作，极有可能会导致远程代码执行（RCE）。
  • 真正的 bug 就出在 get_next_char 与上面写入逻辑的配合问题上。
  • 目前一个手动的缓解办法是：在命令行使用 Git 时，不要直接加上 --recursive 参数执行 git clone。
  • 这个漏洞的修复其实出奇地简单：只需要确保在 write_pair 函数中，如果写入的字符串中包含回车字符（Carriage Return， \r），就要对它加上引号。
