脸萌、剪映后郭列再创业，做视频 Agent、但学的是 Claude Code｜对话一线

7/21/2026, 1:30:00 PM

📌 一句话摘要

文章通过对 Flova 创始人郭列及团队的访谈，阐述视频 Agent 的产品理念、技术架构及其在多模型协作中的核心壁垒。

📝 详细摘要

Flova 创始人郭列回顾了从脸萌、剪映到视频 Agent 的创业历程，强调产品不是要比拼单一视频模型，而是通过 Agent 组织多模型协作，降低创作者的执行负担，让人专注于创意判断。团队认为视频 Agent 的核心是资产管理与用户 Taste，Skill 生态不是壁垒，真正的竞争力在于持续观测用户与 Agent 的协作过程并据此迭代产品。文章还探讨了视频 Agent 与 Coding Agent 在上下文管理、版本控制及 Human‑on‑the‑loop 的差异，以及 AI‑Native 组织中上下文共享带来的协作效率提升。最后，团队谈及商业化路径，认为短期内视频 Agent 的大众普及仍受制约，专业场景具备更高溢价，长期看好模型成本下降带来的应用百花齐放。

💡 主要观点

  1. 视频 Agent 的核心是组织多模型协作，而非单模型竞争。 Flova 团队认为产品价值在于让 Agent 理解用户创作目标，调度图片、视频、音乐等不同模型，从而解放创作者在提示词调试上的注意力，让人专注于内容与审美判断。
  2. 真正的壁垒在于持续观测用户与 Agent 的协作过程。 团队强调需要同时追踪用户意图和 Agent 的工具调用、推理路径，通过这种双层观测不断迭代产品，而不是依赖静态的 Skill 生态或模型优势。
  3. 视频 Agent 与 Coding Agent 在上下文管理和版本控制上有根本区别。 视频数据是多模态的，同一素材可能被多个镜头引用；创作过程需要非线时的版本管理，用户会保留中间某次灵感版本，这与代码的文件‑Git 管理模型完全不同。
  4. AI‑Native 组织的关键是上下文共享，带来协作效率的指数级提升。 通过在 GitHub 仓库中共享产品需求、代码与用户 trace，所有成员可快速理解功能来龙去脉，市场同学也能基于专业视角获得建议，淡化传统分工边界。
  5. 短期内视频 Agent 的大众普及仍受成本限制，专业场景更具溢价。 团队认为普通用户愿意为日常表达视频付费仅几块到十几块，而当前生成成本仍在几十到上百元，因此先聚焦短剧、漫剧等专业创作场景，待模型成本下降后再面向大众。

💬 文章金句

  • 重点不是和单一视频模型竞争，是如何组织多模型协作的系统。
  • 做 Agent 产品，不是直接满足用户需求，是通过 Agent 去更好地满足。
  • 真正的壁垒还是能够持续地去观测用户、观测 Agent。
  • Agent 越往后做，它应该越去跟人讨论创意本身，花很多时间帮你讨论剧本，这个故事怎么更有趣，这个画面还有哪些表达方式更好，然后把执行的事情全都交给 Agent。
  • 我们真正学习的不是某个具体功能，而是让 Agent 成为人创作过程中的协作者。
