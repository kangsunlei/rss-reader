产品经理如何重构面向 AI Agent 的软件设计逻辑

2/20/2026, 2:04:00 AM

📌 一句话摘要

本文探讨了在 AI Agent 成为软件核心用户的背景下，产品经理应如何通过回归经典心智模型、利用符号逻辑消除歧义、以及构建低成本并行基础设施来重构软件设计逻辑。

📝 详细摘要

随着 TiDB Cloud 等平台 90% 的资源由 AI Agent 自主创建，软件设计范式正从“以人为中心”转向“以 Agent 为中心”。作者指出，UI 正在消亡，产品经理应停止发明新概念，转而贴合文件系统、SQL 等被 LLM 广泛内化的经典心智模型。在接口设计上，应结合自然语言的意图表达与代码的符号逻辑执行，以消除歧义。此外，Agent 的“日抛型”工作负载要求基础设施具备极致的低成本、多租户隔离和高并行调度能力。商业模式上，应将高成本的 Token 推理转化为可重复使用的“无聊”在线服务，以实现规模化增长。

💡 主要观点

  1. UI 已死，心智模型永生，产品设计应回归经典抽象。 AI 通过海量代码训练内化了经典系统模型，PM 应贴合文件系统、SQL 等成熟抽象，而非发明新接口，因为 Agent 更擅长在已知模型上写胶水代码。
  2. 接口设计需结合自然语言的意图表达与符号逻辑的执行。 自然语言适合表达模糊意图，但执行需通过代码等符号逻辑来固化。系统应在代码生成的瞬间消除歧义，利用代码的高认知密度实现高效自动化。
  3. 基础设施需适应 Agent 的“日抛型”与大规模并行特征。 Agent 倾向于快速试错和瞬时大规模并行，要求系统具备极致的虚拟化隔离、极低的运行成本以及类似 K8s 的高效任务调度与执行环境。
  4. 商业模式应从单纯卖 Token 转向提供确定的在线服务。 纯 Token 模式边际成本高且脆弱，应将 Agent 的推理能力沉淀为确定的云服务（Boring Service），从而将高频推理成本转化为规模化业务收入。

💬 文章金句

  • 如果你希望设计的是‘给 AI Agent 使用的软件’，请停止发明新概念，尽可能去贴合那些古老、却被一再验证的心智模型。
  • 代码是目前最好的逻辑符号描述。这不是为了省钱，而是为了提高‘认知密度’。
  • Agent 的工作负载本质上是‘日抛型’的。它们会快速创建资源、试错，不行就扔掉。
  • 一个真正成功的 Agent 公司，绝不应该是一家‘卖 Token 的公司’。
  • 放下对‘我是不是在控制一切’的执念，回归到那些古老而稳固的心智模型上，去为这个即将到来的机器洪流，修筑最坚实的河床。
