一份全面的技术指南，介绍如何从遗留的 Moment.js 库迁移到现代、不可变且内置的 JavaScript Temporal API。

📝 详细摘要

本文深入探讨了从 Moment.js 到新的 ECMAScript Temporal API 的过渡。它概述了 JavaScript 日期处理的历史背景，强调了 Moment.js 的弊端，例如其庞大的包体积、缺乏 tree-shaking 以及存在问题的可变性。作者针对创建、解析、格式化和算术运算等常见操作，提供了实用的“秘诀”，并对两种方法进行了并排比较。文章强调了 Temporal 的主要优势，包括其不可变架构、基于 1 的月份索引、内置时区支持以及对原生 Intl API 的依赖以实现本地化格式化。本指南最后提供了一个真实的重构示例，并对当前 polyfill 进行了性能分析。

💡 主要观点

  1. Temporal 消除了对象可变性导致的 bug。 与 Moment.js 中 .add() 等操作会修改原始实例不同，Temporal 对象是不可变的。任何计算都会返回一个新对象，从而确保数据完整性。
  2. 严格解析强制数据可靠性并防止猜测。 Temporal 要求符合 ISO 8601 或 RFC 9557 标准的字符串，并对无效格式抛出错误。这避免了在遗留库中发现的不可预测的“最佳猜测”解析行为。
  3. 通过 Intl API 实现原生本地化格式化。 Temporal 利用浏览器内置的 Intl.DateTimeFormat，允许开发者创建本地化日期字符串，而无需手动定义格式标记或附带额外的本地化数据。
  4. 针对特定用例的粒度化时间表示。 该 API 提供了 PlainDate、PlainTime 和 ZonedDateTime 等不同的类，允许开发者根据其应用程序的需求选择精确度和上下文级别。
  5. 显著减少应用程序包体积。 作为原生浏览器 API，Temporal 一旦得到支持，将无需额外字节；而 Moment.js 及其时区数据可能会给项目增加数百 KB。

💬 文章金句

  • Temporal 是一个新标准，它填补了原始 Date API 的空白，并解决了 Moment 中发现的一些限制。
  • 一旦创建了 Temporal 对象，它就不能被改变。时间算术或时区转换不会修改底层对象。
  • Temporal 通过使用基于 1 的索引来解决这个问题——一月是月份 1。
  • 更明确意味着更少的意外和意外的 bug。如果你给 Temporal 提供了无效内容，它会抛出错误。
  • Temporal 不会增加任何东西（一旦它在你的目标浏览器中发布）。
