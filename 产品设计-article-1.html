两个 skills 把产品经理从 PRD 中解脱出来

7/7/2026, 11:45:00 PM

📌 一句话摘要

本文介绍两个 AI Skill：PM-Make 通过多轮澄清将模糊需求定型为结构化文档，PRD-Make 通过分模块、分轮次写作提升 PRD 质量，核心思路是约束 LLM 注意力而非一次性生成全文。

📝 详细摘要

作者分享了两个自研的 AI Skill，旨在解决产品经理在需求澄清与 PRD 写作中的痛点。第一个 Skill「PM-Make」通过强制初始化 6 个文档、保留 [待确认] 标记、分轮抛出少量关键问题的方式，将模糊的产品想法逐步澄清为包含产品定位、目标用户、MVP 范围等要素的定型文档，避免 LLM 编造未经确认的假设。第二个 Skill「PRD-Make」则通过制定模块计划、逐个模块写作并逐轮确认的流程，确保 LLM 注意力聚焦，提升 PRD 细节质量。文中还分享了产品经理使用 AI 应重在「约束添加」而非单纯「生成」的理念，以及将定型文档用作 Coding Agent 提示词的成功实践。文末附有线下课程推广与 Skill 获取方式。

💡 主要观点

  1. AI 辅助需求澄清的核心是强制分步、避免 LLM 编造假设。 PM-Make 通过初始化文档并保留 [待确认] 标记，防止 LLM 将不确定信息写得像真的一样，从而避免后续 PRD 中积累大量不可用的假设。
  2. 分模块、分轮次写作是提升 PRD 质量的关键策略。 PRD-Make 不让 LLM 一次性生成完整 PRD，而是按模块逐个写作并逐轮确认，确保 LLM 注意力聚焦，提升每个模块的交付质量。
  3. 产品经理使用 AI 应转向「约束添加」而非单纯「生成」。 作者认为，理解 AI 原理后，产品经理的价值在于为 AI 添加约束、提供详尽上下文，以服务者姿态释放 AI 价值，而非仅依赖其生成能力。
  4. 结构化的产品定型文档可直接作为高质量的 Coding Agent 提示词。 作者验证了使用定型文档而非完整 PRD 作为开发需求，能避免 Agent 注意力崩溃，实现产品「一稿过」，无需修正补充。

💬 文章金句

  • LLM 最大的臭毛病就是太会写了。它会把不确定的信息写得很像真的，导致我们看着很顺，但其实里面已经混进了很多未经确认的假设。
  • 产品经理使用 AI，不应该再只聚焦在「生成」这两个字上，更多应该是在理解了原理后的「约束添加」。
  • Agent 的底层虽然是非常简单的「Loop + Tools」，但它是「带脑子的循环」。
