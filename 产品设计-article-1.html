📌 一句话摘要

本文旨在强调 XPath 在现代 Web 开发中的价值，尤其是在提升 Web 测试的健壮性方面。

📝 详细摘要

本文着重指出，越来越多的年轻 Web 开发者过度依赖现代框架，却往往忽略了这些框架所抽象的底层 Web 技术。作者通过动态加载样式表、处理标签导航等个人经历，阐述了这种知识鸿沟的现象。文章重点介绍了 XPath，一种 XML 查询语言，并论证了其在浏览器技术栈中的持续实用性，即使像 XSLT 1.0 这样的相关技术已逐渐被弃用。文章展示了 XPath 如何作为 CSS 选择器的补充，提供 CSS 所不具备的功能，例如按元素位置查询或遍历祖先元素。文中提供了大量 XPath 函数在文本处理和数值运算中的实际应用示例。此外，作者还强调了 XPath 在 Web 测试中的重要价值，相较于在动态 DOM 环境下可能较为脆弱的 CSS 选择器，XPath 能够实现更稳定、更精准的元素选择。最后，文章鼓励开发者们积极拥抱这些经典而强大的工具，使其成为开发工具箱中另一项宝贵的资产。

💡 主要观点

  1. 现代框架对核心 Web 技术进行了抽象，导致开发者在基础概念上存在知识短板。 由于框架的抽象，许多开发者，特别是新入门的开发者，可能没有机会接触或理解底层的浏览器 API 和早期技术，这可能会限制他们解决问题的思路。
  2. XPath 提供了超越 CSS 选择器的独特且强大的 DOM 查询能力。 XPath 能够根据元素的位置进行查询，遍历祖先元素，并执行复杂的字符串和数值运算，这使其成为一个多功能的工具，尤其是在与 CSS 选择器结合使用时。
  3. XPath 在创建健壮且具有弹性的 Web 测试方面具有重要价值。 XPath 能够精确定位元素，不受类名或 DOM 结构变化的影响，因此非常适合编写稳定且不易出错的自动化测试。

💬 文章金句

  • 事实上，现代前端框架是站在前辈技术巨人的肩膀上发展起来的。
  • 关键在于，XPath 能够实现 CSS 无法实现的功能，并且仍然非常有用。即使它在浏览器技术栈中是一项相对较旧的技术，这一点也可能最初并不明显。
  • XPath 在测试中确实能大放异彩。原因不难理解，因为 XPath 可以从 DOM 中的任何位置获取任何元素，而 CSS 则无法做到这一点。
  • 没有什么比仅仅因为 CSS 选择器失效（由于某些元素被重命名或删除）而导致测试失败更糟糕的事情了。
  • 这是一个完美的例子，说明浏览器技术栈中的经典技术在今天仍然具有很大的实用价值，即使您从未了解过它的存在，或者从未考虑过使用它。
