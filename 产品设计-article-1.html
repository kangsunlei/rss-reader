硬核拆解：Manus 控制 AI 选择工具的“遮蔽”究竟是什么，真的靠谱么？

7/22/2025, 11:46:00 PM

📌 一句话摘要

深入解析并验证了 Manus 团队用于控制 AI 工具选择的“预填充”和“遮蔽”策略，揭示了其在 LLM 应用开发中的可行性与挑战。

📝 详细摘要

本文以“硬核拆解”的方式，深入分析并实测验证了 Manus 团队在 LLM 上下文工程中，通过“提供完整工具列表但有效干预模型选择”来优化 Function Call 模式下工具使用的策略。作者首先阐述了动态工具列表在多轮对话中可能导致模型幻觉和缓存失效的问题，随后详细介绍了 Manus 的两种核心干预方法：响应预填充（强制模型选择特定工具）和修改 Logits 进行“遮蔽”（阻止模型选择某些工具）。通过对 Kimi、豆包和 OpenAI API 的实测，文章验证了预填充策略的可靠性，但对“遮蔽”策略的实践效果表示初步探索结果不佳，作者也指出这可能是其用法有误，揭示了该方法在当前闭源模型中实现的挑战。文章提供了详尽的代码示例，具有较高的实践指导价值，但需注意文末包含的推广内容。

💡 主要观点

  1. 动态工具列表在 LLM 多轮对话中导致幻觉和缓存失效 模型对前序轮次工具选择的记忆依赖于工具列表一致性，动态移除工具会使模型混淆；同时，工具列表变化会使缓存无法命中，增加成本和响应时间。
  2. 响应预填充是强制 LLM 选择特定工具的有效方法 通过在 API 请求中预先填充模型的响应起始部分（如特定工具名），可强行引导模型按预期选择工具，经测试证明其稳定可靠。
  3. 通过修改 Logits“遮蔽”工具在闭源模型中实现面临挑战 理论上可通过降低特定 token 权重阻止模型生成，但作者实测发现，目前豆包和 OpenAI 的 logit_bias 参数在工具选择场景下效果不佳，尚需深入探索。

💬 文章金句

  • 但是，大模型判断当前任务该选用哪个工具，几乎完全取决于工具的名字和描述。
  • 多轮对话中，如果每轮工具列表不一致，模型会因为不理解前序轮次任务的工具选择而产生幻觉。
  • Manus 选择的这个“遮蔽”的方法，就是强行给某些 token 降权（比如降为负数），以至于模型在选择生成下一个 token 时“看不见”这些 token。
  • 通过预填充强行要求大模型选择某个工具，结论：完全可行，很稳。
  • 通过遮蔽让模型无法选择某工具，结论：豆包和 OpenAI 都不太行，可能是我的用法不对。
