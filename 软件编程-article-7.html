分享一些在 AI 解析中常见的问题，以及工具区别

6/20/2026, 9:51:17 AM

📌 一句话摘要

本文对比了 MinerU 与 Knowhere 在文档解析上的差异，指出仅解析为 Markdown 不足以支撑 RAG/Agent 系统，Knowhere 通过结构重建、多模态处理和记忆图谱补齐了从解析到检索的完整链路。

📝 详细摘要

文章以作者自研项目 Knowhere 为切入点，对比了主流文档解析工具 MinerU 与 Knowhere 在面向 AI Agent 场景下的差异。作者指出，MinerU 擅长将 PDF 解析为 Markdown，但 Markdown 在切片后丢失了章节层级、表格与图片的上下文关联，导致 RAG 系统检索到的只是孤立文本片段，效果不佳。Knowhere 则在解析与向量化之间插入了结构重建流水线，包括重建文档层级、处理多模态内容（OCR、表格摘要）、构建轻量记忆图谱，并提供融合关键词、路径与语义的 Agentic Retrieval。文章引用内部评测数据，显示使用 Knowhere 后首次准确率提升 36%，召回率提升 11%，Token 消耗更低。最后列举了企业知识库、技术文档助手、合同分析、Agentic RAG 等适用场景。

💡 主要观点

  1. 仅将 PDF 解析为 Markdown 不足以支撑 RAG/Agent 系统。 Markdown 切片后丢失章节层级、表格与图片的上下文关联，Agent 检索到的只是孤立文本片段，无法理解文档结构。
  2. Knowhere 在解析与向量化之间插入结构重建流水线。 包括重建文档层级、处理多模态内容（OCR、表格摘要）、构建轻量记忆图谱，使文档成为 Agent 可导航的知识结构。
  3. 结构化的文档能显著提升 Agent 检索的准确率与效率。 内部评测显示，使用 Knowhere 后首次准确率提升 36%，召回率提升 11%，Agent 循环次数更少，Token 消耗更低。

💬 文章金句

  • 解析成 Markdown ，并不等于文档已经能被 Agent 理解。
  • 如果 Agent 面对的是一整坨文本，那它只能盲找。但如果 Agent 面对的是一棵树、一张图、一组带来源路径的 Chunk ，它就可以像人读文档一样：先看目录，再定位章节，再进入细节。
