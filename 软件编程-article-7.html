微软为 MCP 服务器发布了 Azure 函数支持

1/24/2026, 2:16:00 AM

📌 一句话摘要

微软宣布 Azure Functions 对模型上下文协议 (MCP) 的支持进入一般可用性阶段，通过集成原生认证和流式传输，为企业级 AI 智能体提供安全的托管环境。

📝 详细摘要

本文详细介绍了微软 Azure Functions 对 Anthropic 发起的模型上下文协议 (MCP) 的原生支持更新。核心亮点包括：支持 .NET、Java、Python 等多语言扩展；引入流式 HTTP 传输以取代旧的 SSE 模式；集成 Microsoft Entra ID 和代表用户 (OBO) 认证，解决了 AI 智能体访问企业敏感数据时的安全合规痛点。此外，文章还探讨了自托管 MCP 服务器的“提升和转移”部署模式，以及针对不同业务场景的 Flex、Premium 等托管计划选择建议。

💡 主要观点

  1. Azure Functions 通过原生 OBO 认证解决 AI 智能体的安全痛点。 集成 Microsoft Entra ID 认证，支持代表用户（OBO）模式，确保 AI 工具使用用户身份而非服务账户访问数据，满足企业合规要求。
  2. 引入流式 HTTP 传输协议提升 MCP 通信效率。 新版本建议使用流式 HTTP 取代传统的服务器发送事件（SSE），并提供专门的 Webhook 端点，以获得更稳定的连接体验。
  3. 提供“提升和转移”的自托管模式，简化现有 MCP 服务器迁移。 开发者无需修改代码，仅通过 host.json 配置即可将基于官方 SDK 构建的 MCP 服务器部署到 Azure 无服务器环境。
  4. 针对 Java 开发者优化了构建时分析，减少冷启动延迟。 通过 Maven 构建插件在编译阶段解析 MCP 工具注释，避免了运行时反射带来的性能损耗，提升了无服务器函数的响应速度。

💬 文章金句

  • 安全和合规团队不能允许运行在开发人员笔记本电脑上的未经审查的'影子代理'访问电子医疗记录或客户个人身份信息等关键数据系统。
  • 如果你没有安全专业知识，这本质上是痛苦且有风险的。你可能会错误地配置一些东西，最终将所有数据暴露给不能看到它们的人。
  • 你的 Python 或 Node 脚本永远不会看到认证逻辑，平台负责处理繁重的工作。
  • 在 Azure Functions 上托管 MCP 服务器，可以让你兼得两者的优点：无服务器基础设施的简单性和官方 Anthropic SDK 的强大功能。
