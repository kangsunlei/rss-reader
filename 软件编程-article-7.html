📌 一句话摘要

本技术指南探讨了在 RubyMine 生态系统中构建 LLM 友好型 MCP 工具的工程挑战与设计模式，重点关注分页、过滤和错误恢复。

📝 详细摘要

本文深入探讨了 RubyMine 的模型上下文协议 (MCP) 服务端中 Rails 工具集的实现。文章针对与大语言模型 (LLM) 交互时的固有局限性，特别是上下文窗口限制、工具调用限制和工具发现上限，提出了解决方案。为了克服这些问题，作者详细介绍了如何使用带有缓存键的偏移分页来确保数据一致性，强调了通过强大的服务端过滤来减少 Token 消耗的必要性，并设计了“面向恢复”的错误消息。此外，文章强调工具描述和 JSON Schema 应被视为功能性提示词，引导 LLM 高效准确地使用工具，确保 AI 助手能够有效处理复杂的 Rails 项目。

💡 主要观点

  1. 实现分页以管理 LLM 严格的上下文窗口限制。 像 GitLab 这样的大型代码库会超出上下文限制；分页允许 LLM 分块处理数据，防止数据丢失并降低模型遗漏关键信息的风险。
  2. 使用带有缓存键的偏移分页来获取稳定的 IDE 状态快照。 由于 IDE 数据通常在请求之间被缓存且保持静态，结合缓存键的偏移分页可确保一致性，并允许 LLM 检测底层数据是否发生了变化。
  3. 设计强大的服务端过滤以保持在工具调用限制内。 AI 助手通常在一定次数的工具调用后停止执行；服务端过滤缩小了搜索空间，使 LLM 能够以更少的迭代和更小的上下文找到答案。
  4. 编写面向恢复的错误消息，引导 LLM 的后续步骤。 错误消息不应仅仅报告失败，而应明确指示 LLM 如何修复参数，从而防止不必要的重试和资源耗尽。
  5. 优化工具描述和 Schema，使其发挥有效提示词的作用。 详细的描述、使用示例和清晰的输出 Schema 能引导 LLM 遵循预期模式，帮助其理解每个工具的“为什么”和“怎么做”，避免盲目尝试。

💬 文章金句

  • 当工具调用发生错误时，除了告知模型出了什么问题，明确说明如何从中恢复也至关重要。
  • 目标是使它们尽可能对 LLM 友好。这意味着提供清晰的工具描述和示例，并在发生错误时明确告知模型如何恢复。
  • 分页使模型能够逐步处理数据，并在获取到必要信息后及早停止，而无需遍历整个数据集。
  • 模型利用这些信息来理解如何使用工具，因此提供简洁的描述和示例以引导模型走向预期的使用模式至关重要。
  • 处理大量数据的工具应致力于在尽可能少的调用中最大限度地缩小搜索空间。
