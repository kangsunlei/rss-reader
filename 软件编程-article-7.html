Oxlint 1.0 稳定版发布：基于 Rust 的 JavaScript 静态检查器

8/24/2025, 2:15:00 AM

📌 一句话摘要

Oxlint 1.0 稳定版发布，作为基于 Rust 的 JavaScript/TypeScript 静态检查器，以其卓越的性能、广泛的规则覆盖和便捷的迁移工具，旨在简化前端项目的代码质量管理。

📝 详细摘要

文章宣布了基于 Rust 的 JavaScript 和 TypeScript 静态检查器 Oxlint 1.0 稳定版的发布。作为 Oxc 工具链的一部分，Oxlint 带来了显著的性能提升，声称比 ESLint 快 50-100 倍，甚至比 Biome 快 2 倍，能够在数秒内处理包含大量文件的代码库。它支持超过 520 个 ESLint 规则，并具备多文件分析能力。Oxlint 提供零配置默认模式以简化上手，同时也支持 `.oxlintrc.json` 进行自定义配置。为了方便迁移，项目提供了 `oxlint-migrate` 和 `eslint-plugin-oxlint` 等工具，支持逐步过渡。文章还提到 Oxlint 已集成到 VSCode、IntelliJ 等主流 IDE，并指出当前版本暂不支持类型感知规则，但已列入未来规划。整体而言，Oxlint 旨在成为前端开发中高效、易用的静态代码分析解决方案。

💡 主要观点

  1. Oxlint 1.0 凭借 Rust 架构实现惊人性能提升 基于 Rust 开发的 Oxlint 在实际场景中比 ESLint 快 50-100 倍，甚至比 Biome 快 2 倍，大幅缩短了代码检测时间，尤其在大型项目中优势明显。
  2. 提供广泛的 ESLint 规则覆盖和多文件分析能力 Oxlint 支持超过 520 个 ESLint 规则，并能高效处理 `import/no-cycle` 等需要跨文件依赖分析的复杂规则，确保代码质量和一致性。
  3. 简化了开发者采用和迁移的流程 Oxlint 提供零配置模式快速上手，支持 `.oxlintrc.json` 自定义，并提供 `oxlint-migrate` 和 `eslint-plugin-oxlint` 等工具，帮助项目平滑过渡。

💬 文章金句

  • 1.0 里程碑带来了快速检测、广泛的规则覆盖和迁移工具的组合，旨在使开源项目和大型企业的采用都能变得简单直接。
  • 在实际场景中，性能比 ESLint 提高了 50-100 倍，基准测试显示，以前需要几分钟才能检测的代码库现在在不到一秒钟内就完成了。
  • Oxlint 的开箱即用体验被设计得很简单，目前只能在中小型项目中完全取代 ESLint。
  • 用户反馈：'我刚刚从 ESLint 迁移到我的一个项目中，体验非常好。它非常快，我可以用一个依赖库替换大约 5 或 6 个依赖项，配置格式也容易得多。'
  • 维护者指出，Oxlint 目前不支持类型感知规则，尽管未来的版本正在考虑这一点。
