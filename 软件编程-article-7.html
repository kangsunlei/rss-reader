📌 一句话摘要

JetBrains Amper 0.7.0 更新专注于独立构建，增加了对 Ktor 和 Spring 服务器开发的支持，以及 Kotlin 多平台项目对 iOS 的支持。

📝 详细摘要

本文详细介绍了 Amper 0.7.0 更新。重点介绍了该项目向优先考虑独立构建工具的转变，弃用了基于 Gradle 的版本。主要新增功能包括对 Ktor 和 Spring 框架的服务器端开发提供即时可用的支持，通过简单的 YAML 配置实现可执行 JAR 打包和 BOM 依赖管理。此外，Amper 现在支持 iOS 作为 Kotlin Multiplatform 项目的目标平台，无缝处理原生工具链集成。此更新还带来了重要的 IDE 改进，例如更好的诊断，包括针对依赖版本冲突和缺少多平台目标的快速修复，以及从代码添加模块依赖的快速修复。这些增强旨在简化构建配置并改善各种项目类型的开发人员体验。

💡 主要观点

  1. 独立的 Amper 现在是主要重点，弃用基于 Gradle 的版本。 这种战略转变通过消除对 Gradle 的依赖，简化了构建设置过程。从而实现了更深入的 IDE 集成，并优化了 Amper 项目的开发流程。
  2. Amper 0.7.0 增加了对 Ktor 和 Spring 服务器项目的直接支持。 开发人员现在可以使用 Amper 基于 YAML 的系统配置 Ktor 和 Spring 应用程序，包括打包可执行 JAR 并利用 BOM，从而简化服务器端设置。
  3. 现在，Kotlin Multiplatform 可以使用 Amper 以 iOS 为目标平台。 Amper 简化了与原生 iOS 工具链的集成，从而更轻松地构建和运行以 Apple 移动平台以及 Android 和桌面为目标的 KMP 应用程序。
  4. 改进的 IDE 诊断和快速修复增强了可用性。 Amper 与 IntelliJ IDEA 的集成提供了更清晰的错误消息、针对依赖项问题的可操作快速修复以及简化的依赖项添加，从而减少了配置错误。

💬 文章金句

  • Amper 的独立版本现在是该项目的主要重点，并且基于 Gradle 的变体正在逐步淘汰。
  • Amper 现在提供对 Ktor 和 Spring 项目的开箱即用支持，包括打包可执行 JAR 和使用 BOM 依赖项以及 IDE 集成的能力。
  • 在 0.7.0 中，Amper 的独立版本现在支持 iOS 的 Kotlin Multiplatform 开发，以及 Android 和桌面。
  • 为配置错误的构建提供清晰的诊断和可操作的指导是我们的首要任务之一。
