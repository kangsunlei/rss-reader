如何构建企业级数据智能体：Data Agent 开发实践

10/31/2025, 12:31:00 AM

📌 一句话摘要

本文详细介绍了阿里巴巴 DMS 团队如何构建企业级数据智能体（Data Agent），通过融合传统 BI 与高级分析能力，降低数据分析门槛，实现端到端智能洞察。

📝 详细摘要

本文深入探讨了阿里 DMS 团队构建企业级数据智能体（Data Agent）的技术思考与实践。文章首先明确了 Data Agent 与传统 ChatBI/NL2SQL 产品的本质区别，指出 Data Agent 旨在同时覆盖描述性、诊断性、预测性和规范性分析，打破传统 BI 的预定义限制，并降低高级分析的技术门槛。其核心价值主张包括打破分析能力边界、降低高级分析门槛、摆脱预定义限制、实现端到端分析闭环以及支持更大规模数据的企业级分析。接着，文章详细阐述了 Data Agent 的技术内核，如何通过深度语义理解（知识与记忆管理、意图澄清）、上下文管理（Agent Core Loop，特别是通过多 Agent 协作来优化上下文管理）和幻觉抑制（Code-based Reasoning 策略、工具调用）来优化 LLM 的局限性。特别强调了 Code-based Reasoning 将 LLM 的幻觉风险转移至可验证的代码执行，并借助云原生沙箱环境实现安全、可复现的分析。最后，文章总结了 Data Agent 的企业级能力，包括可靠性、可控性和可复用性，并指出其通过多 Agent 协作赋能不同层级的企业用户，实现更深层次的数据洞察。

💡 主要观点

  1. Data Agent 融合传统 BI 与高级分析能力，提供端到端智能洞察。 Data Agent 超越了传统 ChatBI/NL2SQL 的局限，能处理描述性、诊断性、预测性及规范性分析，通过自然语言调用复杂分析，实现从查询到行动建议的闭环。
  2. Code-based Reasoning 是抑制 LLM 幻觉并确保分析结果可靠的核心策略。 Data Agent 让 LLM 生成可执行代码（SQL， Python），将幻觉风险从自然语言层面转移到代码层面，并通过沙箱环境执行与验证，确保分析结果的可解释、可复现和准确性。
  3. 构建企业级 Data Agent 需关注深度语义理解、上下文管理和安全的工具使用。 构建企业级 Data Agent，需通过精细化的知识与记忆管理、多轮意图澄清实现深度语义理解；利用动态上下文工程和多 Agent 协作优化上下文管理；并通过受控的云原生沙箱环境确保工具调用的安全与分析结果的可靠性。

💬 文章金句

  • Data Agent for Analytics 定位为一款企业级数据分析智能体，基于 Agentic AI 技术，帮助用户查数据、做分析、生成报告、深入洞察。
  • Data Agent 能根据用户模糊或复杂的自然语言提问，自动判断所需的分析技术组合，无缝衔接查询、诊断、预测和规划。
  • Data Agent 综合了以上的优化思路，尤其是以 Code-based Reasoning 为核心策略，LLM 负责理解问题并生成可执行代码，作为中间的逻辑表示，将最终答案生成的责任转移给代码执行引擎，使输出可执行、可解释、可复现。
  • Data Agent 对于工具的选择始终保持克制，前文提到 Data Agent 使用 'Code-based Reasoning' 的策略，专注于数据分析， 除了给到 LLM 的上下文是连贯的， 我们希望代码逻辑也是连贯的。
  • 我理解核心有三点：首先是可靠性，系统持续在线；其次是可控性，数据，安全，责任边界等可控；最后是可复用性， 知识，流程，洞察能被沉淀和扩展。
