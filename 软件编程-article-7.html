📌 一句话摘要

本文通过实例解析 Python 中 async/await 和线程的并发机制及差异。

📝 详细摘要

本文旨在区分 Python 中的 asyncio (async/await) 和线程，并解释：尽管全局解释器锁 (GIL) 限制了线程的真正并行性，但 asyncio 和线程如何实现伪并发。文章通过快餐店类比和实际代码示例（包括模拟）阐释协作式并发（ asyncio ）与操作系统管理的抢占式并发（线程）的差异。作者演示了 asyncio 和线程的基本实现，并探讨了任务队列以及如何使用 `asyncio.to_thread` 处理阻塞 I/O 等复杂场景。此外，文章还介绍了线程中常见的竞争条件，以及如何利用锁来解决这些问题，为本系列第二部分的探讨埋下伏笔。

💡 主要观点

  1. asyncio 和线程均可实现 Python 中的并发。 并发指的是多个任务彼此独立执行，并在时间上可能重叠，从而产生同时执行多个任务的假象，即便是在单核 CPU 上（受限于标准 Python 线程中的 GIL ）。
  2. 主要区别在于谁控制任务调度。 asyncio 采用协作式并发（任务主动让出控制权），而线程则使用操作系统调度器管理的抢占式并发。
  3. asyncio 尤其适用于 I/O 密集型任务。 当任务等待 I/O 操作（如网络请求或用户输入）时， asyncio 允许其他任务继续执行，从而避免程序阻塞。
  4. 线程可能引发竞争条件。 当多个线程在缺乏适当同步机制的情况下并发访问共享资源时，可能出现不可预测的错误，因此需要诸如锁之类的机制来管理资源访问。

💬 文章金句

  • 编程中的并发意味着计算机同时执行多项操作，或者*看起来*同时执行多项操作，即使不同的任务在同一个处理器上执行。
  • 对于 `async/await`，这种方法有时被称为协作式并发。协程或未来对象会主动将控制权交给其他协程或未来对象，以便它们有机会运行。
  • 相反，在 `threading` 中，由操作系统管理器来决定哪个进程正在运行。
  • 通过使用 `asyncio.to_thread`，我们已将 `input` 函数放入一个单独的线程中。
  • 当多个线程尝试同时访问同一资源或数据，并导致系统出现问题时，就可能发生竞争条件。
