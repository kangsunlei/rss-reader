将平台开发从项目转向产品

7/12/2026, 2:15:00 AM

📌 一句话摘要

本文总结了一家游戏流媒体公司如何将其平台开发从项目模式转向产品模式，以应对多租户需求，包括转型信号、架构演变和实践经验。

📝 详细摘要

文章基于 KubeCon 欧洲大会上的分享，介绍了平台从项目转向产品的实践。最初平台按年度项目规划交付，为单一服务团队工作良好。但随着服务多个内部团队，项目模式的局限性暴露：每次改进视为一次性交付、功能累积冲突、产品定义缺失、反馈循环薄弱。团队受外部开源生态（Prometheus、Grafana）和内部读书（《从项目到产品》《凤凰计划》）启发，转向产品思维。现在的平台采用 API 驱动的自助式多租户架构，具有清晰的租户边界、更完善的抽象层，并持续投资于环境和项目等高层抽象。转型的关键信号包括待办积压、团队绕过平台、无法确认产品是否被使用。团队从交付功能转向解决用户问题，从固定范围转向假设驱动路线图，从输出指标转向采用率信号。

💡 主要观点

  1. 平台开发需要从项目思维转向产品思维，以用户问题为导向。 当平台从服务单一团队扩展到多团队后，项目模式（一次性交付、固定范围、输出指标）不再适用，需要转向产品模式（持续解决用户问题、假设驱动路线图、以采用率衡量成功）。
  2. 转型信号包括待办积压、团队绕过平台、无法确认产品是否被使用。 这些信号表明平台团队不再是单纯交付基础设施，而是向内部客户提供能力，需要改变方法和衡量标准。
  3. 产品化后的平台架构采用 API 驱动、自助式、多租户设计。 通过服务层、控制层、管理层分离，抽象底层基础设施，提供稳定的接口，类似内部云服务提供商，支持更广泛的租户需求。

💬 文章金句

  • 我们不再仅仅是交付基础设施，而是向内部客户提供能力。
  • 从交付功能 → 到解决用户问题；从固定范围 → 到假设驱动的路线图；从输出指标 → 到采用率和可用性信号。
