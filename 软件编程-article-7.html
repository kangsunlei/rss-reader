JSON 模块现在可以在所有现代浏览器中导入 JavaScript，CSS 模块紧随其后

6/26/2025, 12:00:00 AM

📌 一句话摘要

现代浏览器现在通过 `with { type: "json" }` 语法，支持在 JavaScript 中直接导入 JSON 模块。

📝 详细摘要

文章宣布了在所有现代浏览器中原生 JSON 模块导入功能的可用性，这是一项由导入属性提案启用并通过 Interop 2025 标准化的特性。这消除了将 JSON 文件直接导入到 JavaScript 代码时对打包工具、转译或 Polyfills 的需求。该语法使用 `import ... from "./file.json" with { type: "json" }`。该特性利用浏览器的原生解析能力。文章还指出，使用类似语法 (`with { type: "css" }`) 的原生 CSS 模块导入尚未完全标准化，但已在 Chrome 中得到支持，并可能包含在未来的 Interop 工作中。像 Deno 这样的运行时已经符合这种浏览器行为。文章阐明，JSON 模块不支持命名导出，而是将 JSON 文档视为一个单一实体。

💡 主要观点

  1. 原生 JSON 模块导入现在已在所有现代浏览器中可用。 开发者可以将 JSON 文件直接导入到 JS 中，无需额外的构建步骤或手动解析，从而简化工作流程并可能提高性能。
  2. 导入 JSON 的标准语法使用 `import ... with { type: "json" }`。 这个特定的导入属性告诉运行时如何加载和处理非 JS 文件，以实现浏览器原生处理。
  3. 此特性是 Interop 2025 努力的一部分，旨在提高 Web 平台一致性。 跨浏览器的标准化确保开发者可以依赖此特性构建可互操作的 Web 应用程序。
  4. CSS 模块导入是使用类似语法的潜在未来特性。 尽管尚未完全在 Interop 2025 中标准化，但 `with { type: "css" }` 属性正在被考虑，并且已在某些浏览器中得到支持，有望实现原生 CSS 加载。

💬 文章金句

  • JSON 模块脚本现在已在所有现代浏览器中可用。
  • 导入属性告诉运行时，特定的模块应该如何加载。
  • 此前，Web 开发者的选择包括使用打包工具、额外的转译步骤，或使用 Polyfills 来支持那些尚未实现此特性的浏览器。
  • 在 Web 上，每个 `import` 语句都会产生一个 HTTP 请求。然后，响应会处理成一个 JavaScript 值，再由运行时提供给程序使用。
  • 然而，JSON 模块不支持命名导出……将 JSON 文档概念上视为‘一个单一事物’更有意义。
