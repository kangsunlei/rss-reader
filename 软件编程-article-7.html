📌 一句话摘要

Python 之父 Guido 回顾 Python 早期开发并探讨“差即是好”哲学是否仍适用。

📝 详细摘要

文章编译了 Python 之父 Guido van Rossum 在近期峰会上的分享。他回顾了 Python 诞生初期的业余项目性质，以及如何在 Unix 哲学“Worse is Better”的影响下，通过牺牲早期完美性（例如没有长整型、依赖 C stdio 实现等）换取快速成型和迭代。正是这种“够用就好”的策略，使得 Python 在三个月内有了雏形并在一年内发布，迅速获得社区参与并普及。然而，Guido 反思，在 Python 生态日益庞大复杂、新功能开发需要大厂资助团队数年投入的当下，早期那种快速迭代和社区广泛参与的模式已不复存在，这使他质疑“差即是好”理念是否仍然适用，并表达了希望更多社区成员能参与到语言发展中的愿望。

💡 主要观点

  1. Python 早期成功得益于“Worse is Better”哲学 优先实现简洁性和快速构建，而非追求完美设计，使得 Python 在早期资源有限时迅速面世并迭代，吸引了大量用户和贡献者。
  2. 早期妥协的设计在后期被社区逐步完善 虽然早期存在许多“糟糕设计”，但随着社区壮大，这些问题被不断修复和优化，证明了演进的力量。
  3. 现代 Python 开发模式变化，使“差即是好”实践空间受限 如今新功能开发依赖大型团队多年投入，与早期快速迭代形成鲜明对比。这种模式使早期那种“先做出来再完善”的“Worse is Better”实践难以延续，也影响了社区贡献者的参与方式和积极性。
