在攻击者利用前检测 GitHub Actions 工作流注入

7/16/2025, 4:00:00 PM

📌 一句话摘要

本文详细介绍了一种常见的 GitHub Actions 工作流注入漏洞，并解释其根本原因。同时，本文还提供了利用环境变量、最小权限原则和 CodeQL 来主动缓解此漏洞的策略。

📝 详细摘要

本文重点介绍了 GitHub Actions 工作流注入作为一种常见的安全漏洞，攻击者利用问题标题或分支名称等不受信任的输入，在工作流中注入并执行恶意命令。文章解释了 `${{}}` 语法如何导致此类注入，并提供了一个实际示例。为了防止这些攻击，文章建议使用环境变量来处理不受信任的数据，遵循工作流权限的最小权限原则，并谨慎使用 `pull_request_target` 触发器。此外，文章还介绍了 GitHub 的代码分析工具 CodeQL，利用污点追踪技术有效检测这些漏洞，并鼓励采用该工具。核心信息强调持续的安全意识和主动措施。

💡 主要观点

  1. 当不受信任的输入在工作流中直接执行时，就会发生 GitHub Actions 工作流注入。 恶意命令通过用户可控数据（如问题标题）嵌入，并被工作流扩展和执行，这通常是由于直接使用 `${{}}` 语法，从而导致未经授权的代码执行。
  2. 像环境变量和最小权限原则这样的主动措施对于缓解至关重要。 通过将不受信任的输入转换为环境变量，并将工作流权限限制在最低必要范围内，开发人员可以显著降低成功注入攻击的影响和可能性。
  3. CodeQL 的污点追踪是一种有效的自动化工具，用于检测工作流注入。 GitHub CodeQL 能够追踪不受信任数据在代码中的流动，从而自动识别 GitHub Actions 工作流中潜在的注入漏洞，帮助及早发现和修复。

💬 文章金句

  • GitHub Actions 注入是存储在 GitHub 仓库中的项目中最常见的漏洞之一。
  • 当恶意攻击者能够提交命令，并由仓库中的工作流执行时，就会发生这种情况。
  • 一种解决方案是避免在诸如 `run` 的工作流配置中使用 `${{}}` 语法。
  • 当 actions 工作流注入触发时，它会以授予工作流的权限运行。
  • CodeQL 是 GitHub 的代码分析工具，可针对您的代码提供自动化安全检查。
