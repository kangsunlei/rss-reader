深度解析 Codex Harness 架构及其全新上下文压缩记忆体系的设计思路

10/27/2026, 5:21:00 AM

📌 一句话摘要

深度解析 Codex Harness 模块化架构、事件驱动机制、三层循环设计，并重点剖析其创新的 Token Budget 跨窗口短期记忆体系与两阶段长期记忆机制。

📝 详细摘要

文章基于 Codex CLI 开源代码，系统拆解其 Harness 核心架构：采用 118 个 Rust Crate 模块化解耦，通过 Op/Event 双向事件驱动、Task/Turn/Sampling 三层嵌套循环、FuturesOrdered 并发工具执行、World State Diff 优化上下文、SubAgent 与 Mailbox 协同机制，以及 arg0 身份识别设计。重点分析了上下文压缩从「交接文档」策略演进到 Token Budget 方案：引入 Thread Hint、Notes、History 三件套实现跨 Context Window 的状态衔接，配合 Rollout Extraction 与 Global Consolidation 两阶段长期记忆，形成短长期记忆正交体系。文中对比了 Claude Code、DeepSeek Harness 等同类设计，提供工程落地参考。

💡 主要观点

  1. Codex Harness 采用极致模块化架构，118 个 Crate 实现高内聚低耦合 核心 codex-core 禁止直接添加代码，强制新功能拆分至独立 Crate；codex-protocol 定义 Op/Event 协议，codex-api 封装模型接口，codex-app-server 统一暴露 JSON-RPC，支撑 TUI、Desktop、Headless 多前端复用；codex-rollout 持久化 Agent Trace，codex-arg0 通过入口参数实现身份识别。
  2. 三层循环与事件驱动构建清晰的运行时模型，工具并发执行但有序返回保证上下文确定性 Task Loop 处理用户需求，Turn Loop 对应单轮对话及压缩，Sampling Loop 为最小执行单元；Op 从客户端发起，Event 从 Agent 返回，形成双向通信；工具调用用 FuturesOrdered 并发执行，结果按调用顺序拼装，避免模型困惑。
  3. World State 以 Diff 机制优化上下文注入，兼顾 KV Cache 友好与 Token 节省 将环境信息拆为带类型 Section，首次全量注入，后续仅注入变更 Diff，不破坏 Prefix KV Cache 前缀，降低 Context Window 消耗并保持推理速度。
  4. Token Budget 以跨窗口短期记忆替代传统压缩，通过 Thread Hint、Notes、History 实现按需回溯 触发阈值时新建干净 Context Window，Thread Hint 注入任务进度摘要，Notes 作为模型私有笔记本记录关键步骤，History 保存完整 Trace 供渐进式检索；模型自主决定读取何种信息，避免压缩丢失关键细节。
  5. 长期记忆采用两阶段「提取-巩固」与可遗忘衰减机制，按引用频次动态排序 Rollout Extraction 从旧会话提取关键信息脱敏入库；Global Consolidation 基于 Citation 次数选 Top-N 入磁盘，高频信息高频召回，低频自然遗忘，实现自进化记忆管理。

💬 文章金句

  • Resist adding code to codex-core
  • 你现在要产出一份"交接文档"。也就是说，你当前的工作要交给另外一个模型了
  • Token Budget 的核心思想是什么呢？就是让模型自己去管理这个记忆，不让 Summary 或 Compaction 的模型去猜了，而是让主 Agent 模型自己来决定
  • Notes 是模型的私人笔记本，是一个服务端托管的虚拟文件系统
  • Memory 管的是长期不能遗忘的记忆，Token Budget 管的是当前窗口内的任务状态衔接。所以这两者其实是正交的
