如何在 Flutter 中使用 Monorepo

2/4/2026, 8:07:39 PM

📌 一句话摘要

一份关于使用 Monorepo 架构构建可扩展 Flutter 应用的全面指南，利用 Melos 进行任务编排，并结合 Dart 3.6+ Workspaces 进行原生依赖管理。

📝 详细摘要

本文探讨了扩展 Flutter 项目时面临的挑战，例如多个应用（如乘客端、司机端和管理端应用）之间的代码重复和同步问题。文章提出将 Monorepo 策略作为解决方案，并以一个网约车平台为例进行了详细演示。指南解释了 Melos（用于任务编排、过滤和版本管理的工具）与全新的原生 Dart 3.6 Workspaces（处理底层依赖解析）之间的协同作用。内容包括设置仓库、配置共享逻辑和 UI 包以及在应用中调用它们的逐步实现指南。最后，文章概述了避免循环依赖和“上帝包”等常见陷阱的最佳实践。

💡 主要观点

  1. Monorepo 解决了多应用项目中代码重复和版本管理的摩擦。 通过集中管理代码，团队可以跨多个应用和共享库进行原子级更改，防止“依赖地狱”，并确保业务逻辑的单一事实来源。
  2. Melos 是管理复杂 Dart/Flutter Monorepo 必不可少的编排层。 它能自动执行重复性任务，如跨包运行测试、管理语义化版本，并在开发过程中使用强大的过滤功能定位特定模块。
  3. Dart 3.6 Workspaces 为多包项目提供原生且高效的依赖解析。 该特性允许多个包共享单个 lock 文件和分析上下文，显著减少内存占用，并使跨包的 IDE 导航变得即时。
  4. 结构化的目录布局（应用与包分离）强制执行清晰的架构边界。 将可执行应用与共享逻辑和 UI 包分离，可确保依赖关系向下流动，使系统更易于测试、维护和扩展。
  5. 避免“上帝包”对于维持健康且高性能的 Monorepo 至关重要。 开发者不应使用单一的“shared”文件夹，而应创建细粒度的包（例如 auth、theme、networking），以确保应用仅导入所需的模块并保持较快的构建速度。

💬 文章金句

  • Monorepo 是一种软件开发策略，将多个项目的代码存储在单个版本控制仓库中。
  • Workspaces 让代码得以编译，而 Melos 让开发生命周期变得高效。
  • 将用于依赖解析的 Dart Workspaces 与用于工作流编排的 Melos 相结合，为任何 Flutter 团队提供了坚实的基础。
  • 应用仅仅是将共享包绑定在一起的粘合剂。
  • 如果你更新了 API 客户端，你就同时为所有人完成了更新。
