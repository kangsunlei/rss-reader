MCP 服务器五大最佳实践

7/3/2025, 8:30:11 AM

📌 一句话摘要

Docker 的 MCP（模型上下文协议）服务器最佳实践指南聚焦于同时为人类用户和 AI 代理设计，重点包括工具预算管理、Docker 打包及提交至 MCP 目录。

📝 详细摘要

这篇 Docker 文章提出了开发 MCP（模型上下文协议）服务器的五项关键实践建议。强调通过管理工具预算避免系统过度复杂、专门为 AI 代理（而非仅终端用户）需求设计、创建同时服务人类和代理的文档、使用 MCP 检查工具进行全面测试，以及采用 Docker 打包确保可移植性。指南重点介绍了实用方法，如使用 Docker AI 命令进行优化，并解释了提交至 Docker MCP 目录的流程（包括标准输入输出传输要求）。这些实践旨在创建可靠、用户友好的 MCP 服务器，以应对自主代理工作负载。

💡 主要观点

  1. 主动管理工具预算以平衡功能性与可用性。 围绕明确用例设计工具，而非暴露所有 API 端点，使用指令序列串联操作（如宏指令）以提升用户体验。
  2. 主要面向实际使用者——AI 代理进行设计。 创建能指导代理后续行动的错误信息（而非仅通知人类），重点关注可修正的配置问题。
  3. 创建人类与代理双用途文档。 向人类用户阐明价值主张，同时为代理提供清晰的工具名称/描述以便发现和选择。
  4. 使用 MCP 检查工具进行全面测试。 从用户和代理双视角验证服务器生命周期阶段（连接、工具列表、调用）。
  5. 采用 Docker 打包确保可移植性和简化部署。 利用 Docker 的跨环境一致性保证，使用 Docker AI/Gordon（Docker AI 代理）进行优化，为提交至 MCP 目录做好准备。

💬 文章金句

  • "工具预算'是我们内部术语，指代代理能有效处理的工具数量。如同任何预算，良好管理是优质用户体验的关键。"
  • "构建 MCP 服务器时，你不是直接与用户交互，而是在作为用户代理构建系统。"
  • "要访问此系统，MCP 服务器需配置有效的 API_TOKEN，当前 API_TOKEN 未通过验证"（面向代理的错误消息示例）
  • "打包 MCP 服务器不仅关乎制品创建，更需考虑制品的使用方式。"
  • "只需输入 `docker ai improve my Dockerfile`，Docker AI 代理 Gordon 就会帮你优化 MCP 服务器的 Dockerfile。"
