新型 Agent 数据注入攻击可诱导 AI Agent 误点或执行攻击者指令

7/17/2026, 10:00:00 AM

📌 一句话摘要

新型 Agent 数据注入攻击通过伪造可信数据（如虚假标点、按钮 ID）诱导 AI Agent 误点或执行攻击者指令。

📝 详细摘要

本文详细介绍了首尔大学等研究团队提出的新型攻击手法——Agent 数据注入（ADI），说明攻击者无需直接注入指令，只需在 AI Agent 所信赖的数据中植入虚假信息（如伪造的发件人名称、按钮 ID 或虚假标点），即可诱导 Agent 误点“立即购买”按钮或在开发者机器上执行恶意命令。文章分析了攻击原理、针对 Web Agent、编码助手和恶意 Pull Request 的三种实现方式，评估了现有防御的失效原因，并提出了随机 ID、数据来源追踪等缓解措施，同时指出目前尚未发现野外利用案例。

💡 主要观点

  1. 攻击原理：利用 Agent 对数据的信任，通过概率性定界符注入伪造可信字段。 Agent 将标点视为数据结构边界，攻击者在可控字段中插入类似标点的字符（如转义引号、美元符号），使模型误认为存在额外的可信数据，从而绕过传统提示注入防御。
  2. 三种实现方式：Web Agent 误点购买按钮、编码助手执行攻击者命令、恶意 Pull Request 绕过代码审查。 Web Agent 中植入产品评论复用真实按钮 ID 导致误点；编码助手中伪造 GitHub 评论作者行使其执行攻击者命令；恶意 PR 通过伪造检查记录使 Agent 误判代码安全并合并恶意代码。
  3. 防御措施及其 trade-off：随机不可猜测的元素 ID、数据来源追踪、去除标点符号。 Atlas 浏览器为每个页面元素分配随机 ID 阻断点击攻击；追踪数据来源可零成功率但牺牲约三分之一功能；去除标点虽能降低攻击效果但同时破坏链接、文件路径等正常解析。
  4. 研究现状与影响：概念验证攻击成功率高，尚未见野外利用，厂商已获通报但尚无公开修复。 测试中结构化数据攻击成功率 31%-43%，网页数据最高可达 100%；OpenAI、Google、Anthropic 确认攻击有效，但截至论文发表时未公布具体修复方案。

💬 文章金句

  • 攻击者的输入会被伪装成 Agent 已经信赖的数据，例如发件人名称或按钮 ID，从而绕过大多数为阻止提示注入而构建的防御机制。
  • 让防御变得困难之处在于：虚假标点甚至不需要完全正确。
  • 研究人员仅描述了概念验证攻击，目前尚无 ADI 在野外被利用的公开报告。
