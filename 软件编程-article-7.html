KotlinX RPC 0.9.1 发布 | Kotlin 官方博客

8/8/2025, 1:40:42 PM

📌 一句话摘要

KotlinX RPC 0.9.1 通过解除依赖关系、简化资源生命周期管理和默认启用严格模式，显著提升了稳定性和可维护性。

📝 详细摘要

KotlinX RPC 0.9.1 版本的发布重点在于增强库的长期稳定性和易维护性。主要更新包括将 `kotlinx-rpc-core` 模块与 `kotlinx.serialization` 解除依赖关系，为开发者在选择序列化方法时提供更大的灵活性，尤其是在 gRPC 设置中。通过从核心接口中移除 `CoroutineScope`，简化了资源管理，有助于减少与资源生命周期管理相关的常见错误。此外，旨在简化 API 并确保正确性的*严格*模式现已默认启用，且在 0.8.0 之后的版本中无法禁用，因此用户需要相应调整项目。此版本还将 Kotlin 更新至 2.2.0 版本，并包含多项错误修复和小的改进，旨在为使用 Kotlin 构建 RPC 服务的开发者提供更强大且用户友好的体验。

💡 主要观点

  1. 解除与 `kotlinx.serialization` 的依赖，数据序列化更灵活。 这允许开发者将 KotlinX RPC 与替代序列化方法集成，从而更好地适应不同的使用场景和特定的 gRPC 需求。
  2. 简化资源生命周期管理，减少常见资源处理错误。 通过简化 `CoroutineScope` 集成，API 变得更清晰，不易被误用，从而为 RPC 服务带来更强大和可维护的代码库。
  3. *严格*模式现为默认设置，确保 API 正确性并简化使用。 此更改强制执行最佳实践并保证可预测的行为，但也要求现有项目适应新的默认设置，以提高可靠性。

💬 文章金句

  • 此版本的 kotlinx.rpc 引入了重大改进，旨在提升库的长期稳定性、可维护性和发展。
  • `kotlinx-rpc-core` 模块不再与 kotlinx.serialization 耦合。
  • 我们简化了资源管理，并降低了常见错误的发生概率。
  • 于 0.5.0 版本引入的*严格*模式旨在简化 API 并保证正确性，现在已默认启用。
