在 Go 语言中使用 QJS 和 WebAssembly 运行现代 ES2023 JavaScript

12/28/2025, 7:07:00 AM

📌 一句话摘要

QJS 通过在 WebAssembly 中嵌入 QuickJS 并使用 Wazero 运行，为 Go 应用程序提供了一个不依赖 CGO 的沙盒化 ES2023 JavaScript 运行时，实现了 Go-JS 的紧密互操作性和强大的性能。

📝 详细摘要

本文介绍了 QJS，一个为 Go 语言设计的现代 JavaScript 运行时。它将 QuickJS 引擎嵌入到 WebAssembly 模块中，并通过 Wazero 执行。QJS 为 Go 应用程序提供了一个不依赖 CGO 的沙盒化 ES2023 环境，支持 async/await 和 BigInt 等特性，并实现了 Go-JS 的紧密互操作性。QJS 专为需要运行 JavaScript 且不依赖 C 库的 Go 开发者设计，利用 WebAssembly 实现内存安全和隔离。文章演示了 QJS 的 API，用于评估 JavaScript 代码、将 Go 函数绑定到 JS、以及交换复杂数据结构。它还强调了性能基准测试结果，表明 QJS 在执行速度和内存使用方面，与 Goja 和 ModerncQuickJS 等其他 Go JavaScript 运行时相比，具有竞争力。该工具适用于安全插件系统、用户提供的脚本以及 Go 应用程序中嵌入业务逻辑等用例。

💡 主要观点

  1. QJS 是一个不依赖 CGO 的 Go JavaScript 运行时，利用 WebAssembly 和 Wazero。 它将 QuickJS 引擎作为 WebAssembly 模块嵌入，消除了 CGO 依赖，并在 Go 应用程序中提供了一个沙盒化、内存安全的 ES2023 环境。
  2. 它提供全面的 Go-JS 互操作性，并完全支持 ES2023。 开发者可以评估 JavaScript，将 Go 函数绑定到 JS，将 JS 函数转换为 Go 可调用对象，并交换复杂数据结构，包括 async/await 功能。
  3. QJS 为嵌入式 JavaScript 提供强大的隔离和可配置性。 通过在 Wazero 中运行 QuickJS，它默认提供文件系统和网络隔离，并提供一个 `Option` 结构，允许配置内存限制、堆栈大小、执行超时和 GC 阈值，以实现安全可控的执行。
  4. 基准测试表明 QJS 与其他 Go JavaScript 运行时具有竞争力，并且通常表现更优。 与 Goja 和 ModerncQuickJS 的对比基准测试显示，在几种常见场景中，QJS 实现了更低的内存使用和更快的执行时间，这使其成为一个高性能的选择。
  5. QJS 是构建安全插件系统和在 Go 中嵌入动态业务逻辑的理想选择。 其设计使其适用于需要用户提供的脚本或用 JavaScript 编写的外部逻辑的用例，而无需 CGO 相关的复杂性和安全问题。

💬 文章金句

  • QJS 是一个不依赖 CGO 的现代 Go JavaScript 运行时，它将 QuickJS 引擎嵌入到 WebAssembly 模块中，并使用 Wazero 运行，为 Go 应用程序提供了一个沙盒化的 ES2023 环境，支持 async/await 和 Go-JS 的紧密互操作性。
  • QJS 旨在帮助 Go 开发者在不链接原生 C 库的情况下，在 Go 进程内部运行现代 JavaScript。
  • Go 函数可以暴露给 JavaScript，JS 函数也可以转换回类型化的 Go 可调用对象。
  • 通过这种设计，QJS 针对 Go 开发者，他们需要安全的插件系统、用户提供的脚本或用 JavaScript 编写的嵌入式业务逻辑，而无需在其构建和部署管道中引入 C 工具链或 CGO。
