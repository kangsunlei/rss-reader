面向量子未来的安全：WARP 客户端现已支持后量子密码学 (PQC)

9/24/2025, 2:00:01 PM

📌 一句话摘要

Cloudflare 的 WARP 客户端现在支持后量子密钥协商，为互联网流量提供即时保护，防止“先收集后解密”的攻击。

📝 详细摘要

Cloudflare 宣布其 WARP 客户端，包括免费的消费者版本 1.1.1.1 和企业版 Cloudflare One Agent，现在都支持后量子密钥协商。这项积极的措施远早于 NIST 针对传统密码学的 2030/2035 年弃用时间表，旨在保护互联网流量免受“先收集后解密”的攻击，即今天收集加密数据，供未来强大的量子计算机解密。文章详细介绍了 WARP 客户端如何使用后量子加密的 MASQUE 隧道传输流量，确保企业资源端到端的保护，并为消费者流量提供初步保护。值得注意的是，实验表明，在混合模式下使用 ML-KEM 的后量子密码与 TLS 1.3 相比，比传统的 TLS 1.2 性能更好。文章阐明了成熟的后量子密钥协商 (ML-KEM) 和仍在标准化的后量子数字签名之间的区别。Cloudflare 实施了一种独特的分阶段推出策略 (phased rollout strategy)，包括临时的 PQC 降级、逐步部署和 MDM 覆盖，以有效地管理数百万不受控制的设备和各种操作系统上的复杂更新过程，同时确保稳健性和安全性。文章还简要提到了政府相关服务的 FIPS 合规性要求。

💡 主要观点

  1. Cloudflare 的 WARP 客户端现在支持 PQC 密钥协商，为互联网流量提供即时保护，防止“先收集后解密”的攻击。 此升级通过将最终用户的互联网流量包装在后量子加密的 MASQUE 隧道中来保护它，从而为未来的量子解密提供关键防御，即使单个连接尚未启用 PQC。MASQUE 隧道利用 ML-KEM 算法进行密钥协商，确保即使在量子计算机出现后，数据也无法被解密。
  2. Cloudflare 正在 NIST 官方弃用时间表之前，在其网络和产品中积极实施 PQC。 该公司致力于让所有用户都能免费使用 PQC，无需专门的硬件即可部署它，并且远在联邦政府强制弃用传统密码学之前。Cloudflare 旨在通过软件升级实现 PQC，无需用户更换硬件或进行复杂的配置。
  3. 独特的分阶段推出策略 (phased rollout strategy) 解决了在数百万不受控制的设备上更新客户端软件的挑战。 为了确保稳健性和安全性，Cloudflare 开发了一种细致的方法，包括临时的 PQC 降级、在客户端群体中的逐步部署以及企业用户的 MDM 覆盖，从而管理了各种操作系统上的过渡。这种分阶段推出策略 (phased rollout strategy) 允许 Cloudflare 在大规模部署前识别和解决潜在问题。
  4. 使用 ML-KEM 在混合模式下与 TLS 1.3 结合使用的后量子密钥协商被证明是成熟的、高性能的，甚至比传统的 TLS 1.2 更快。 Cloudflare 的实验证明了 ML-KEM 部署的效率，表明可以在不影响网络性能的情况下采用 PQC，在某些情况下，还可以提供改进。实验结果表明，ML-KEM 与 TLS 1.3 结合使用时，握手延迟甚至低于传统的 TLS 1.2。
  5. 在 WARP 中使用 MASQUE 隧道提供了内置的密码敏捷性，从而可以批量保护流量和未来的适应性。 这种隧道方法提供了固有的灵活性，使用户和组织可以轻松适应不断发展的密码学标准和新的量子威胁，而无需进行重大的架构改革。MASQUE 隧道允许 Cloudflare 灵活地切换和更新加密算法，以应对新的安全挑战。

💬 文章金句

  • 如今，发送到 Cloudflare 网络的由人类产生的互联网流量中，超过 45% 已经经过后量子加密。
  • WARP 客户端升级到后量子密钥协商，为最终用户提供即时保护，防止他们的互联网流量受到“先收集后解密”的攻击。
  • 我们今天需要后量子密钥协商来阻止“先收集后解密”的攻击，即攻击者今天收集加密数据，然后在未来强大的量子计算机可用时对其进行解密。
  • 我们的实验表明，在 TLS 1.3 上以混合模式（与传统 ECDH 并行）部署后量子 Module-Lattice-Based Key-Encapsulation Mechanism (ML-KEM) 算法实际上比使用带有传统密码学的 TLS 1.2 性能更好。
  • 一种强大的策略是使用受后量子密钥协商保护的隧道来批量保护互联网流量，免受“先收集后解密”的攻击——即使通过隧道发送的单个连接尚未升级到 PQC。
