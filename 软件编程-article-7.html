Amazon S3 Vectors 正式发布，为 RAG 引入“存储优先”架构

1/2/2026, 10:17:00 AM

📌 一句话摘要

AWS S3 Vectors 正式商用，支持高达 20 亿个向量且延迟低于 100ms，通过“存储优先”架构为 RAG 应用显著降低成本并简化管理。

📝 详细摘要

AWS 宣布 S3 Vectors 正式商用（GA），这是一种原生支持存储和查询向量数据的云对象存储服务。此次 GA 版本将单个索引的容量显著提升至 20 亿个向量，并针对频繁查询实现了低于 100ms 的查询延迟。相关增强功能包括单次查询可检索多达 100 个搜索结果（为 RAG 应用提供更丰富的上下文），以及支持每秒高达 1，000 次的单向量更新 PUT 事务。与 Amazon Bedrock Knowledge Base 和 Amazon OpenSearch 的关键集成也已正式上线。开发者 Jalaj Nautiyal 提出了一个值得关注的观点，他强调 S3 Vectors 实现了从“计算优先”到“存储优先”架构的转变，通过利用 S3 的低成本存储，推动了无服务器化、大规模可扩展性以及高达 90% 的成本削减。他将 S3 Vectors 定位为适用于大多数内部 RAG 应用的“无限后备箱”，从而消除了对更复杂、昂贵的向量数据库的需求。该服务目前已在 14 个 AWS 区域可用，定价基于向量上传、存储和查询量。

💡 主要观点

  1. AWS S3 Vectors 正式商用，显著提升了向量数据的容量和性能。 该服务现在支持每个索引高达 20 亿个向量，为频繁查询提供低于 100ms 的延迟，并与 Bedrock Knowledge Base 和 OpenSearch 集成，简化了 AI 应用的大规模向量数据管理。
  2. 它引入了“存储优先”架构，重新定义了 RAG 中向量搜索的处理方式。 通过像处理其他 S3 对象一样处理向量，它实现了一种无服务器模式，用户无需管理复杂的基础设施，将重心从计算转向了具有成本效益、可扩展的存储。
  3. S3 Vectors 为 RAG 应用提供了大幅的成本削减并简化了扩展性。 由于利用了 S3 廉价的存储并消除了闲置计算成本，成本可降低高达 90%，使其成为许多不需要高端向量数据库的内部 RAG 场景的理想且可靠的解决方案。

💬 文章金句

  • 你现在可以在单个索引中存储和搜索多达 20 亿个向量……这意味着你可以将整个向量数据集整合到单个索引中，无需在多个小索引之间进行分片，也不需要实现复杂的查询联邦逻辑。
  • S3 Vectors 将向量搜索从一个“计算优先”的问题转变为一个“存储优先”的解决方案。
  • “无服务器”转型：你不再需要管理集群、Pod 或分片。你像对待 S3 中的任何其他对象一样对待向量。规模：存储数十亿个向量。
  • 成本：将总拥有成本降低高达 90%。你只需支付 S3 存储费（便宜）+ 查询费。没有闲置计算成本。
  • 对于 80% 的内部 RAG 应用和自主智能体来说，你可能不需要向量数据库中的法拉利。你只需要一个可靠的、无限大的后备箱。S3 刚刚成为了那个后备箱。
