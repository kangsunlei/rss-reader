Agent 研发工作系统：面向多需求并行端到端开发的设计与实践

11/10/2026, 1:45:00 PM

📌 一句话摘要

本文介绍了京东技术团队构建的 Agent 研发工作系统，通过八个模块（主 Agent、规则与技能、上下文检索、任务状态、工具适配、动作策略、证据质量、方法治理）协同工作，解决 Agent 完成任务的续接、验收、复用等关键问题，实现端到端的多需求并行开发。

📝 详细摘要

本文聚焦京东技术团队研发的 Agent 工作系统，旨在解决「Agent 改一行代码不难，难的是让它能续接、能验收、能复用经验」的核心问题。文章构建了八个逻辑模块：M1 主 Agent 负责理解目标、组织工具调用；M2 规则与技能分离项目知识与操作流程；M3 提供历史检索、精确源码定位、意图检索三条路径；M4 任务状态保存进度并防旧进度覆盖；M5 工具适配连接本地仓库、测试和企业平台；M6 动作策略检查具体动作是否获授权；M7 证据质量用 E0-E5 等级界定结论；M8 方法治理记录可复用的经验。系统围绕「续接、验收、复用」三大需求设计，结合乐观并发、内容哈希、显式合同等工程思想，实现了从目标澄清到业务验收的完整闭环，为 Agent 研发工作提供了可复制的实践范式。

💡 主要观点

  1. Agent 工作系统通过八个模块协同解决续接、验收、复用问题 系统从目标理解、规则执行、上下文检索、状态保存、工具适配、动作策略、证据质量到方法治理八个维度构建闭环，确保 Agent 完成任务时能说明做到哪了、运行的是什么、凭什么验收，及经验能否复用。
  2. 任务状态与方法治理实现经验的版本化复用 通过 workctl.py 保存任务文件、reqctl.py 管理需求卡，结合 methodctl.py 记录方法适用性、执行步骤、验收标准和反馈，确保方法改版后旧成功不能继续计数，经验复用更加可靠。
  3. 动作策略与证据等级确保执行安全与验收严谨 M6 通过 authzctl 检查具体动作是否获授权，M7 用 E0-E5 证据等级界定结论能说到哪一步，防止误操作并保证交付结果可追溯。

💬 文章金句

  • 让 Agent 改一行代码不难，难的是让它能续接、能验收、能复用经验。
  • AI 加速了局部工作，也让原有组织中的摩擦，更加集中地暴露了出来。
  • 规约栅栏（持续优化）。AI 犯错后，正确的动作不是简单地对话纠正，而是沉淀出一条规约去约束它不再犯同样的错。
