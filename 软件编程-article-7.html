研究人员发现 GitHub “错误提交” 中泄露的数千个敏感信息

9/4/2025, 12:00:00 PM

📌 一句话摘要

一位研究人员在 GitHub 存档的“错误提交”中发现了数千个泄露的高价值敏感信息，并发布了一个开源工具来检测它们，强调了强大的敏感信息管理的关键需求...

📝 详细摘要

安全研究员 Sharon Brizinov 与 Truffle Security 合作，对 GitHub 的“错误提交”（即，即使开发者尝试通过强制推送删除提交，GitHub 仍然会将其作为零提交推送事件保存在其存档中）进行了全面调查。通过使用 GitHub Archive 数据系统地扫描自 2020 年以来所有此类公共提交，Brizinov 发现了数千个泄露的敏感信息，包括高价值令牌和管理员级别的凭据，如 GitHub 个人访问令牌 (PAT) 和 AWS 凭据，这些凭据可能导致广泛的供应链攻击。这项研究获得了约 25，000 美元的漏洞赏金奖励。为了增强社区的能力，Truffle Security 和 Brizinov 共同开发了开源 “Force Push Scanner” 工具，该工具利用 GH Archive 和 TruffleHog 来识别和扫描 GitHub 组织内隐藏漏洞的孤立提交。调查结果强调，一旦提交了敏感信息，即使试图删除它，也应被视为永久暴露并立即撤销。文章强烈主张采取预防措施，包括使用专门的密钥管理工具（例如，HashiCorp Vault，AWS Secrets Manager）、环境变量，并在多个阶段（提交前、CI/CD、历史扫描）强制执行敏感信息扫描。它还强调了立即撤销、最小权限访问以及培养强大的安全文化以减轻敏感信息暴露风险的重要性。

💡 主要观点

  1. GitHub 的 “错误提交”（强制推送/删除）保留敏感数据，使其成为泄露敏感信息的重要来源。 GitHub 存档所有公共提交，即使是那些打算删除的提交，也会产生暴露高价值凭据（如 API 密钥和管理员令牌）的持久风险，最近的一项调查中发现的数千个此类敏感信息就证明了这一点。
  2. Git 历史记录中泄露的敏感信息会带来严重的供应链风险，因此需要立即撤销和采取强有力的预防措施。 暴露的凭据，即使在历史提交中，也可以授予对关键系统的未经授权的访问权限。这需要一个“视为已受损”的策略、快速撤销以及采用安全的密钥管理实践和持续扫描工具。
  3. 有效的密钥管理包括安全存储、持续扫描和强大的安全文化，以防止和补救泄漏。 开发人员必须优先使用专门的密钥管理工具，将敏感信息扫描集成到他们的开发工作流程中（提交前、CI/CD），并培养一种安全至上的心态，以显著降低敏感信息暴露的风险。

💬 文章金句

  • 一旦提交离开本地机器，便无法彻底删除，必须假定其已永久暴露
  • 任何提交的敏感信息，即使是不知情的，也应被视为已受损并立即撤销。
  • 为了防止敏感信息泄漏，开发人员应该优先使用密钥管理工具和环境变量，而不是硬编码凭据。
  • 通过将技术保障与文化变革相结合，团队可以显著降低敏感信息暴露的风险，并使安全编码实践成为其工作流程的默认部分。
