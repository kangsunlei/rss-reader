Kubernetes 环境中作业帮大模型服务流量调度优化实践

8/2/2025, 2:12:00 AM

📌 一句话摘要

作业帮在大模型服务部署于 Kubernetes 环境时，通过自研模型网关解决了传统 Ingress 在流量调度、并发控制、KV Cache 利用和异构硬件优化等方面的局限，显著提升了服务性能和稳定性。

📝 详细摘要

文章深入探讨了在大模型服务广泛应用背景下，Kubernetes 环境中传统 Ingress 在流量调度方面面临的挑战，包括基于路径的路由限制、缺乏并发控制、KV Cache 利用不足、不支持异构硬件优化以及成本跟踪缺失。为解决这些问题，作业帮提出并实践了一种创新的“模型网关（Model API Gateway）”方案。该方案集成了模型路由、基于最小堆的并发控制、KV Cache 亲和路由、异构设备感知调度以及基于 token 的成本分配五大核心功能。文章详细阐述了每项功能的实现原理、优势及其如何克服传统方案的痛点，最终实现大模型服务的易用性、稳定性、性能和成本管理的全面提升。该方案对企业级 AI 服务平台、云服务提供商和研究实验室具有重要的实践参考价值。

💡 主要观点

  1. 传统 Ingress 无法满足大模型服务在动态路由、并发控制和资源利用上的特殊需求。 大模型推理对 GPU 显存敏感，现有负载均衡策略易导致 OOM；静态路由和缺乏 KV Cache 亲和性也限制了性能和运维效率，急需针对性解决方案。
  2. 作业帮构建的模型网关通过多项创新功能全面优化大模型流量调度。 模型路由、基于最小堆的并发控制、KV Cache 亲和、异构设备感知和 token 成本分配，共同解决了大模型部署的关键痛点，提升了系统整体效能。
  3. 该方案显著提升了服务的稳定性、性能、易用性并实现了精细化成本管理。 通过避免 OOM、提高缓存命中率、优化异构资源利用和实现多租户计费，模型网关为企业级大模型服务提供了高价值的实践经验。

💬 文章金句

  • 在大模型服务场景中，Ingress 存在以下局限：缺乏并发控制、KV Cache 利用不足、不支持异构硬件优化、成本跟踪缺失。
  • 作业帮提出了一种综合的大模型服务流量调度方案，专为 Kubernetes 中的大模型服务设计，整合成模型网关 (Model API Gateway)。
  • 作业帮提出了一种基于最小堆的最小连接调度算法，优先选择活跃连接数最少的实例分配流量，并设置每个实例的并发上限，确保服务稳定性。
  • KV Cache 亲和路由通过请求方指定会话标识或 prefix caching 自动计算将请求路由到已有相应 KV Cache 的后端实例，增加缓存命中率，提升推理效率。
  • 通过模型网关 (Model API Gateway) 实现针对 Kubernetes 中大模型服务独特需求的流量调度方案，克服了传统 Ingress 的局限性。
