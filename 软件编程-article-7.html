Loop Engineering 实践指南：在 Code Buddy 中构建自主循环系统

6/22/2026, 9:22:00 AM

📌 一句话摘要

本文深入介绍 Loop Engineering 这一 AI 编程新范式，阐述其与 ReAct 的区别、核心架构，并通过 CodeBuddy 工具展示如何运用/goal、/loop 等机制实现自主循环系统。

📝 详细摘要

文章由腾讯技术工程团队撰写，系统性地介绍了由 Google 工程师 Addy Osmani 提出的 Loop Engineering 概念。文章首先阐明 Loop Engineering 的本质——围绕大模型构建自主循环系统，使 AI 从单次响应工具升级为长期自治代理，并定位其为继 Prompt Engineering 和 ReAct 之后的“AI 编程第三次革命”。接着详细对比了 Loop Engineering 与 ReAct 的差异，指出 ReAct 是 Inner Loop（单任务执行），而 Loop Engineering 是 Outer Loop（跨任务编排），两者是演进而非替代关系。文章核心部分提出了五阶段循环机制（Discover→Plan→Execute→Verify→Iterate）、双层循环模型和六要素构建体系，强调状态外置哲学。随后聚焦 CodeBuddy 工具，具体介绍了/goal（条件驱动）、/loop（时间驱动）、Automations（跨会话定时任务）三种循环模式及其适用场景，并给出了多个实践案例，包括模块迁移、CI 监控、Team 模式对抗验证、Skills 固化知识、MCP 连接器、Rules 和 Memory 状态外置。最后总结了最佳实践、常见陷阱和模式选择指南。文章理论结合实践，具有很强可操作性。

💡 主要观点

  1. Loop Engineering 的核心是让人从循环内的操作者变为循环上的监督者。 传统 AI 交互是“一问一答”，人成为循环瓶颈；Loop Engineering 为人设定目标和完成条件，AI 自主决策执行步骤并持续迭代，直至目标达成或不可达。
  2. Loop Engineering 与 ReAct 是 Outer Loop 与 Inner Loop 的关系。 ReAct 解决单次任务内“怎么做”，Loop Engineering 解决跨任务“做什么、谁来做、何时停、怎么续”。两者协作：ReAct 作为执行层，Loop Engineering 作为编排层。
  3. CodeBuddy 通过/goal、/loop、Automations 三种机制实现不同驱动模式的循环。 /goal 适用于有明确终态的实质性工作，条件驱动；/loop 适用于时间驱动的监控巡检；Automations 适用于跨会话的长期定时任务。三者覆盖不同场景。
  4. 状态外置是 Loop Engineering 的关键设计原则。 所有状态存储于外部文件（如 Memory、CODEBUDDY.md、Rules），每次循环从全新上下文开始，彻底解决模型遗忘和信息漂移问题，并支持断点续跑。

💬 文章金句

  • 这种模式的瓶颈在于：人成了循环的瓶颈。
  • 让人从循环内部的操作者，转变为循环之上的监督者和目标设定者。
  • Loop Engineering 不是要替代 ReAct，而是在 ReAct 之上增加编排层。
  • 关键变更仍需人工审查，Loop 不代替 Code Review
