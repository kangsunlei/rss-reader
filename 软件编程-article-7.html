Jakarta EE 12 里程碑 2：数据时代的到来以及一致性与配置

2/10/2026, 9:00:00 AM

📌 一句话摘要

Jakarta EE 12 里程碑 2 引入了统一的 Jakarta Query 规范，更新了用于多语言持久化的 Data 和 NoSQL，并新增了 Agentic AI 规范，同时将基准版本提升至 Java 21。

📝 详细摘要

本文详细介绍了计划于 2026 年初发布的 Jakarta EE 12 第二个里程碑的技术概览。该版本的发布主题为“稳健且灵活”，标志着作者所称的企业级 Java “数据时代”的到来。关键进展包括全新的 Jakarta Query 规范，它将 JPQL 和 JDQL 统一为单一语言，以在关系型和 NoSQL 数据库之间提供一致性。Jakarta Data 1.1 和 Jakarta NoSQL 1.1 进行了更新以集成这一新的查询基础，引入了动态存储库查询和有状态存储库等特性。此外，文章强调了 Jakarta Agentic AI 规范的创建，旨在为构建和运行 AI 智能体提供厂商中立的 API。平台基准正式转向 Java 21，在清除旧版 API 的同时，支持 SequencedCollections 和虚拟线程等现代特性。

💡 主要观点

  1. Jakarta Query 的引入为整个持久层建立了统一的面向对象语言。 它将 JPQL 和 JDQL 集中到包含 Core 和 Persistence 配置文件的单一规范中，在生态系统内的关系型和 NoSQL 数据库中提供一致的查询体验。
  2. Jakarta Data 1.1 引入了重大增强，包括动态存储库查询和对有状态存储库的支持。 这些更新允许开发人员使用流式 API 进行复杂搜索，并更有效地管理实体生命周期，结合了无状态的简洁性与稳健的持久化上下文优势。
  3. 平台正式将 Java 21 作为所有 Jakarta EE 12 规范的最低基准。 这一举措支持使用 SequencedCollections 和将 Record 作为 ID 等现代 Java 特性，同时便于移除 SecurityManager 等旧组件以获得更好的性能。
  4. 正在开发新的 Jakarta Agentic AI 规范，以标准化企业运行时中的 AI 智能体集成。 它为 LLM 访问和智能体工作流提供厂商中立的 API，确保智能解决方案可以在不同的符合 Jakarta EE 标准的环境中一致地构建和部署。

💬 文章金句

  • Jakarta EE 12 通过将查询、数据访问、配置和一致性视为平台的一等公民，带来了关于数据的新视角。
  • Jakarta EE 12 的主题是稳健且灵活……我们可以将 Jakarta EE 12 称为数据时代。
  • Jakarta Query 将作为持久层的统一语言……在一个核心规范中整合了 JPQL 和 JDQL。
  • Jakarta Agentic AI……最终将提供一套厂商中立的 API，旨在简化、标准化和优化构建 AI 智能体的过程。
  • 以 Java 21 作为新基准，Jakarta EE 延续了拥抱现代 Java 语言特性的传统，提供了更高的性能和更简洁的语法。
