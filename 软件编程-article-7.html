这类前端应用会导致 macOS 26 系统卡死，赶紧自查！

10/1/2025, 8:02:00 AM

📌 一句话摘要

文章揭示了 macOS 26 系统因 Electron 应用使用私有 API 与新渲染机制冲突，导致卡顿甚至死机的问题，并提供了升级 Electron 版本作为解决方案。

📝 详细摘要

文章指出，随着 macOS 26 的上线，许多用户发现部分 Electron 应用（如 VS Code）会导致系统性能显著下降，甚至出现卡顿和整机死机的情况。具体现象包括拖动窗口时桌面 UI 掉帧、多开 Electron 应用时问题加剧，以及在滚动、切换标签页、编辑代码等特定操作下 WindowServer 进程 GPU 占用异常飙升。文章深入分析了问题根源：macOS 26 引入了“Liquid Glass”等新的界面渲染效果和底层窗口处理机制，而 Electron 为了实现无边框、圆角等自定义窗口效果，使用了 macOS 的私有 API。这种新旧机制的冲突导致 WindowServer 进程负担过重，进而拖慢整个 macOS UI。文章强调，Electron 团队已确认并修复此 Bug，解决方案是开发者需将项目中使用的 Electron 版本升级到 v38.2.0+、v37.6.0+或 v36.9.2+等最低修复版本。文章最后警示开发者应避免使用私有 API，并及时更新依赖库版本以应对系统兼容性变化。

💡 主要观点

  1. macOS 26 与 Electron 应用因底层渲染机制冲突导致系统卡顿 macOS 26 引入的新界面渲染方式与 Electron 应用通过私有 API 实现自定义窗口效果的方式发生冲突，导致 WindowServer 进程 GPU 占用异常，进而拖慢整个系统 UI。
  2. 问题根源在于 Electron 对 macOS 私有 API 的依赖 Electron 为实现特殊窗口效果而依赖系统内部接口，当 macOS 底层更新这些接口后，便产生了兼容性问题，导致应用性能受损。
  3. 升级 Electron 版本是解决该兼容性问题的直接有效方案 Electron 团队已针对此兼容性 Bug 发布了修复版本，开发者通过升级项目中 Electron 依赖到指定版本即可解决 macOS 26 上的性能问题。

💬 文章金句

  • 只要开着一些 Electron 应用（比如 VS Code），系统就会变得很慢，甚至整机卡死。
  • 问题出在 macOS 26 带来了新的界面效果，比如 "Liquid Glass"，Apple 在系统底层调整了窗口圆角和阴影的渲染方式。
  • 别去动私有 API：为了窗口阴影、透明度这些效果，Electron 之前靠过一些系统内部接口。问题是，Apple 一改底层，这些"小捷径"马上就出问题。
  • Electron 官方会尽快适配新系统。我们最省事的做法，就是及时升级，不要拖着不动。
