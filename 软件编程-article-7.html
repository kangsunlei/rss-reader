jev-visual：用打分替代生成，让 0.8B 小模型一次答 64 道视觉选择题

9/23/2026, 1:30:04 PM

📌 一句话摘要

jev-visual 参考 TypeSafe 的 Jev 思路，让视觉模型对候选答案直接打分而非生成 JSON，配合图片与上下文只算一遍的共享机制，在 M4 上把 64 个问题的耗时从 37.30 秒降到 2.40 秒。

📝 详细摘要

针对小模型输出 JSON 做视觉选择题时格式易错、解析失败的问题，jev-visual 改为给每个候选答案直接打分、取最高分，绕开文本生成。项目在 Apple 芯片 Mac 上本地运行，模型为 0.8B 的 Qwen3.5，同一张图一次可问 1 到 64 个问题，支持选项题、是非题和分等级打分。图片与上下文只计算一遍供所有问题共用，作者在 M4 上实测 64 个问题从每题单独算的 37.30 秒降到 2.40 秒。仓库附带传送带分拣、打砖块、摄像头手势控制粒子三个小游戏演示，其中打砖块把画面分成五块只问球在哪一块。首次运行需下载约 600 MB 模型，之后全本地运行，提供网页界面、命令行和接口三种用法，并配中文说明。

💡 主要观点

  1. 用「候选答案打分」替代「生成 JSON」，规避小模型的格式错误 小模型在问题数量增多时输出 JSON 容易格式出错导致解析失败，改为对每个候选答案直接打分并取最高分，把结构化输出问题转化为分类打分问题。
  2. 图片与上下文只计算一遍、多问题共用，是提速的主要来源 作者在 M4 上实测 64 个问题：每题单独计算需 37.30 秒，共用视觉编码后降到 2.40 秒，说明瓶颈在重复的视觉前向计算。
  3. 面向学习与理解推理过程，附带可上手的演示与中文文档 项目在 Apple 芯片 Mac 上本地运行 0.8B 的 Qwen3.5，提供网页界面、命令行和接口三种用法，并给出 README 阅读顺序，适合想弄清视觉模型推理每一步在做什么的读者。

💬 文章金句

  • 不让模型生成文字，而是给每个候选答案直接打分，挑分最高的那个。
  • 作者在 M4 上测了 64 个问题，每个问题单独算要 37.30 秒，共用之后 2.40 秒。
