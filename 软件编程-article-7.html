📌 一句话摘要

本文列出了一套强制性的 Agent 行为规范，覆盖语言用词、编码行为、行为模式等，旨在确保模型输出可预测、无副作用。

📝 详细摘要

本文是腾讯程序员 daisy 为自身使用的 Agent 行为手册，以 Markdown 形式列出了一系列强制性规则。语言部分禁止使用比较句式、单字缩写和冗余黑话，要求完整两字词汇；行为部分规定直接 import 库、禁止 try‑except、plan mode、Git 回滚、/tmp 读写、主动视觉功能，要求验证链接内容、fast‑fail、避免 mock、禁止程序化代码修改和手写 parser；行为模式警告通过番茄炒蛋加东坡肉的例子说明输出必须是纯净的最终状态，不得保留任何中间痕迹；文末提供获取完整 md 文件的方式。整体旨在通过严格约束降低模型不确定性，提升代码可靠性和可维护性。

💡 主要观点

  1. 语言规范：禁止比较句式、单字缩写和冗余黑话，要求使用完整两字词汇。 文章指出，不允许出现“不是...而是...”等比较结构，也不准使用单字缩写如‘崩’、‘判’，以及‘落地’、‘钉死’等互联网黑话，以避免歧义和低质量表达，确保沟通精准。
  2. 编码行为约束：直接 import 库、禁止 try‑except、plan mode、Git 回滚、/tmp 读写、主动视觉功能，要求验证链接并 fast‑fail。 为了减少隐藏依赖和副作用，规则强制可见的依赖引入、禁止捕获错误回滚、禁止使用临时目录和视觉功能，并在获取外部资源前先确认内容，出错时就地崩溃而不尝试恢复。
  3. 测试与依赖限制：禁止使用 mock、假数据或仅为通过测试的 workaround，也不允许程序化修改代码或手写 parser。 文章认为 mock 会掩盖真实行为，程序化代码修改和自行解析成熟格式会引入不可预见的错误，因此要求在实现和测试阶段使用真实依赖和第三方库，保证行为的一致性。
  4. 行为模式警告：输出必须是纯净的最终状态，不得保留任何中间修正痕迹，如番茄炒蛋加东坡肉的例子所示。 通过举例说明，任何对需求的改动都应直接体现在最终设计中，不能留下注释或代码残迹，以确保 Agent 的行为是可预测、可审计的。

💬 文章金句

  • 本文件中的每一条规则都是强制性的
  • 违反任何一条规则都会遭受毁灭性打击。不存在任何例外与豁免
  • 不允许使用"不是...而是..."句式
  • 禁止使用 try-except 进行 import
  • 禁止擅自进入 plan mode
