关于 JDK 27 和 JDK 28，我们目前都知道些什么

9/3/2026, 10:08:00 AM

📌 一句话摘要

JDK 27 进入首个发布候选阶段，确定九项新特性；JDK 28 已锁定六项 JEP，涵盖 GC 默认化、简单 JSON API、严格字段初始化等方向。

📝 详细摘要

本文系统梳理 JDK 27 和 JDK 28 的进展与特性规划。JDK 27 为 JDK 25 后的第二个非 LTS 版本，已进入首个发布候选阶段，计划 2026 年 9 月 15 日发布，共九项 JEP，涵盖核心库（惰性常量、结构化并发、向量 API）、HotSpot（G1 默认回收器、紧凑对象头、JFR 数据屏蔽）、安全库（TLS 1.3 后量子密钥交换、PEM 编码）和 Java 语言规范（基本类型模式匹配）。JDK 28 计划于 2027 年 3 月发布 GA，已确认六项目标 JEP：废弃 macOS/x64、简单 JSON API、严格字段初始化、Shenandoah 分代默认启用、值对象，以及 PEM 编码定稿。文章同时提及两个潜在候选提案：惰性常量继续预览和 ZGC 启动优化。

💡 主要观点

  1. JDK 27 已进入首个 RC 阶段，九项新特性按四大类分布，整体偏向稳定性提升而非语言大变革。 JDK 27 功能集已于 2026 年 6 月分叉至 Rampdown 阶段，严重缺陷可通过 Fix-Request 修复。九项 JEP 中，结构化并发（第七预览）、向量 API（第十二孵化）和惰性常量（第三预览）延续早期项目，G1 设为所有环境默认 GC、紧凑对象头默认化、JFR 进程内屏蔽敏感信息等属于 HotSpot 内部优化，PEM 编码和安全 TLS 特性服务于工程实践。
  2. JDK 28 已锁定六项目标 JEP，重点方向是 GC 演进、语言特性完善和标准库简化。 已确认的目标包括：Shenandoah 默认分代模式（废弃非分代）、值对象预览（JEP 401）、严格字段初始化（JVM 层面保证字段在使用前被赋值）、简单 JSON API（取代已撤回的轻量级 JSON API）、PEM 编码定稿，以及废弃 macOS/x64 移植版。此外还有两个潜在候选：惰性常量第四轮预览和 ZGC 启动加速增强。
  3. Java 长期孵化项目（Amber/Loom/Panama/Valhalla）持续迭代，但节奏平稳，暂无突破性版本。 结构化并发自 JDK 19 起已进行六轮预览+七轮预览；向量 API 经历十一轮孵化后仍处孵化；惰性常量从 JDK 23 起历经多轮名称与状态调整；值对象（JEP 401）作为 Valhalla 的一部分在 JDK 28 中首次进入预览。这些项目仍在稳步推进，但尚未有特性在本轮完成从预览到正式发布的跃迁。
  4. JDK 27 和 JDK 28 均非 LTS 版本，企业用户应关注 JDK 21/25 的 LTS 路径。 JDK 25 是当前 LTS，JDK 27 和 28 为非 LTS 迭代版本，主要面向早期采用者验证新特性。Loom 的结构化并发、Valhalla 的值对象等重大项目尚未在任何非 LTS 版本中完成最终定稿，预计将在后续 LTS（JDK 29 或更晚）中迎来正式支持。

💬 文章金句

  • JDK 27 现在已经进入了首个发布候选版本阶段。
  • 最终确定的九项新特性（以 JEP 形式呈现）可以分为四大类：核心 Java 库、HotSpot、安全库和 Java 语言规范。
  • JDK 28 计划于 2027 年 3 月发布 GA 版本，届时将包含六项 JEP。
  • JEP 523（在所有环境中将 G1 设为默认垃圾回收器）提议将 G1 GC 设为所有环境中的默认选项。
  • JEP 540（简单 JSON API 第一个孵化版）定义了无需依赖外部库即可解析和生成 JSON 文档的标准 API。
