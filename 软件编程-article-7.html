HashiCorp 如何通过 Amazon Application Recovery Controller 实现无缝跨区域切换 | Amazon Web Services

7/25/2025, 6:27:45 AM

📌 一句话摘要

HashiCorp 使用 Amazon Application Recovery Controller (ARC) 和自定义编排服务优化了其跨区域灾难恢复 (DR)，实现了无缝、自动的故障转移并提高了弹性。

📝 详细摘要

本文详细介绍了 HashiCorp 如何通过实施 Amazon Application Recovery Controller (ARC) 来解决其 HashiCorp Cloud Platform (HCP) 复杂的、且易出错的跨区域故障转移挑战。SRE 团队寻求一种高度弹性的解决方案，该解决方案允许人工判断启动，并自动执行，同时显著改善恢复点目标 (RPO) 和恢复时间目标 (RTO) 指标。ARC 的分布式架构可通过多个区域端点访问，即使在重要的区域中断期间，也能保持恢复机制的可用性。这使其成为理想选择。HashiCorp 设计了一种自定义编排服务来与 ARC 交互，从而自动执行主区域和备区域的两步路由控制更改。他们还创新地使用了与 ARC 路由控制相关联的 TXT DNS 记录，从而为服务提供可发现的全局状态指示，以动态确定活动区域。该解决方案将人工监督与自动执行相结合，并由严格的每月灾难恢复 (DR) 测试计划提供支持，从而大大缩短了故障转移时间，并将 DR 转变为 HashiCorp 的标准化、可预测流程。

💡 主要观点

  1. ARC 提供了一个高度弹性的分布式控制平面，用于管理跨区域故障转移。 其在五个不同区域中具有端点的架构，确保了即使在重要的区域中断期间，恢复机制也能保持运行，从而解决了传统 DNS 故障转移方案的关键漏洞。
  2. HashiCorp 将 ARC 与自定义编排服务和 DNS 记录集成在一起，以实现自动化的、人工启动的故障转移。 这种组合实现了区域之间精确的两步流量转换，并通过 TXT 记录实现了活动区域的动态服务感知，从而简化了复杂的灾难恢复 (DR) 过程。
  3. 严格的双向灾难恢复 (DR) 测试对于持续改进和运营准备至关重要。 HashiCorp 的每月测试计划（包括故障转移和故障恢复）确定了程序和 ARC 实施中的改进，从而将 DR 从一种专门的功能转变为一种实践的、可预测的过程。

💬 文章金句

  • 通过使用 AWS SDK 与 ARC 交互，HashiCorp 获得了几个关键优势。他们可以将基础设施即代码 (IaC) 实践应用于灾难恢复 (DR) 工作流程，自动执行故障转移程序测试，并将弹性与他们现有的运营工具无缝集成。
  • ARC 通过其分布式架构解决了这个问题，该架构将 Amazon Route 53 连接到弹性的控制机制，并通过 Route 53 健康检查实现，可通过多个区域端点访问。
  • 为了使分布式系统能够无缝感知区域状态，该团队使用专门设计的 TXT DNS 记录，实现了一种信令机制。
  • 曾经需要专业操作员小心操作 DNS 记录的区域转换现在可以通过单个 API 调用来执行，流量在几秒钟内转移，并在大约 2 分钟内完成完全传播。
  • 最重要的是，此实施已在 HashiCorp 内部普及了灾难恢复 (DR)，将其从一种专门的功能转变为由其常规值班轮换人员执行的标准化程序。
