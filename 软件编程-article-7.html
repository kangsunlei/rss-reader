百度百舸开源全模态训练框架 LoongForge：一套代码跑通 GPU 与昆仑芯，多模态训练提速 45%

5/13/2026, 10:01:00 AM

📌 一句话摘要

百度百舸开源全模态训练框架 LoongForge，通过统一模型抽象、系统层端到端优化和跨硬件平台支持，解决多模态训练中工程复杂、效率低下和平台割裂的核心挑战，在主流模型上实现 45% 的端到端训练加速。

📝 详细摘要

本文详细介绍了百度百舸开源的 LoongForge 全模态训练框架。文章首先指出当前多模态大模型训练面临的核心挑战：模型架构从单一文本向多模态演进，算力从单一 GPU 走向多元异构，但现有训练框架仍基于「数据同质、结构单一、平台固定」的设计前提，导致迭代速度被工程复杂度拖累、异构结构带来隐性性能损耗、跨平台迁移产生沉没成本。LoongForge 的解决方案分为三层：模型层通过统一的抽象将多模态模型拆解为感知编码层、生成主干层和组合调度层，新模型接入只需通过 YAML 配置即可完成，适配周期从数周压缩至天级；系统层从 LLM 基座优化（CCT 算通传并行、ChunkPipe 流水线并行、DSA 算子融合）到多模态专项优化（DP 负载均衡、模型异构并行、自适应 FP8），实现端到端性能提升；硬件层通过插件化接入层实现一套代码在 NVIDIA GPU 与昆仑芯 XPU 上无缝切换。实测数据显示，LoongForge 在 Qwen3-VL-30B 上实现 45% 加速，在 DeepSeek V3.2 上实现 4.8 倍性能提升，并在 5000+ 卡昆仑 P800 集群上达到 90%+ 的线性扩展效率。文章还通过 LLaVA-OneVision、千帆 VL 等真实案例验证了框架的生产级稳定性。

💡 主要观点

  1. 多模态训练面临工程复杂、效率低下和平台割裂三大核心挑战。 现有框架如 Megatron 模型定义与分布式策略深度耦合，适配周期长；FSDP 虽快速但大规模训练效率不足。多模态数据的异构性导致负载不均，跨平台迁移需维护多套代码分支。
  2. LoongForge 通过三层架构系统性解决多模态训练的结构性问题。 模型层提供统一抽象，将模型拆解为 Encoder、Foundation、组合调度三层，YAML 配置即可完成组网；系统层从 LLM 基座到多模态专项逐层优化；硬件层通过插件化实现跨平台无缝切换。
  3. LoongForge 在主流模型上实现 45% 端到端加速，在 DeepSeek V3.2 上实现 4.8 倍性能提升。 CCT 通算传并行打破 MoE 长序列训练的显存-通信二选一困局；ChunkPipe 让超长序列训练在中小集群可落地；模型异构并行允许 ViT 与 LLM 各自独立配置最优策略，消除流水线负载不均。
  4. LoongForge 已在 5000+ 卡昆仑 P800 集群上实现 90%+ 线性扩展效率。 通过 DP 负载均衡机制动态重排样本分配，消除多模态数据异构带来的隐性算力损耗，在国产算力大规模集群上验证了框架的稳定性和性能表现。

💬 文章金句

  • 当前大模型的竞争，拼的不是谁的 Idea 更精妙，而是 AI Infra 的正确性与单位时间内的迭代次数。
  • Idea 是廉价的，能被快速验证的 Idea 才值钱。
  • 多模态训练的上限，首先取决于语言基座的效率地基；地基不稳，上层优化再精细也是空中楼阁。
  • 当训练不再成为瓶颈，多模态时代的加速，才会真正开始。
