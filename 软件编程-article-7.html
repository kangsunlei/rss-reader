Agent skill 迭代式编写实战

6/12/2026, 7:02:00 AM

📌 一句话摘要

本文系统梳理 Agent Skill 的概念、三层渐进式加载架构与迭代式编写实战经验，强调用决策树替代模糊判断、建立双重验证机制，将隐性专家经验转化为可复用的知识资产。

📝 详细摘要

文章来自淘天集团物流技术团队，是一篇关于 Agent Skill 的深度实践总结。作者首先定义 Agent Skill 为模块化的领域知识资产 bundle，类比为给 AI 的「操作手册」，并介绍了其基于文件系统的标准目录结构（SKILL.md、references/、scripts/）。核心部分详细阐述了迭代式编写经验：采用三层渐进式加载架构（目录/概要 → 详细指令 → 完整资源）；用决策树替代模糊判断，让 agent 行为可控；负向约束必须配替代方案；建立内部自查与外部 eval 的双重验证机制。文章还对比了 Skill 与 LangGraph 等专用 Agent 框架的差异，指出 Skill 本质是用文件系统结构 + 文本决策树替代运行时服务，以零基础设施依赖换取极简部署，但确定性不如专用框架。最后总结了适用场景与边界，强调 Skill 的价值在于将隐性专家经验转化为显性、可执行、可验证的知识资产。

💡 主要观点

  1. Agent Skill 是模块化的领域知识资产，本质是给 AI 的「操作手册」。 Skill 以文件系统结构（SKILL.md + references/ + scripts/）封装执行流程、背景知识与工具使用说明，让 Agent 在需要时自动加载，实现零依赖部署。
  2. 核心设计原则是三层渐进式加载架构。 将技能信息拆为目录/概要、详细指令、完整资源三层，Agent 平时只需知道手册目录，需要时才按需加载具体章节，避免上下文窗口被无关知识占满。
  3. 用决策树替代模糊判断是高质量 Skill 的关键标志。 决策树将专家判断知识显性化为可执行的分支逻辑，Agent 无需推理、顺着树走即可，比模糊描述的可执行性高很多，是 skill-judge 工具明确列出的加分项。
  4. 建立内部自查与外部 eval 的双重验证机制。 内部自查是执行后的规范符合性与覆盖完整性检查；外部 eval 通过有无 Skill 的输出对比进行迭代优化，两者定位不同但都不可或缺。
  5. Skill 是简化版的专用 Agent，以确定性换极简部署。 相比 LangGraph 等框架，Skill 用文件系统 + 文本决策树替代运行时服务，部署成本极低；但当流程确定性要求 100% 或逻辑复杂时，仍需回归专用 Agent 框架。

💬 文章金句

  • Skill 本质是以文件系统结构替代复杂运行时服务，实现零依赖部署。
  • 决策树把「应该怎么判断」写清楚，而不是用模糊语言把判断压力甩给 agent。
  • 能写成脚本的就不要靠 agent 推理——脚本的稳定性和可复现性远高于让 agent 猜。
  • Skill 的价值不在于技术本身，而在于能否将隐性专家经验转化为显性、可执行、可验证的知识资产。
