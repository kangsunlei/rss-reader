Token 节俭之道：如何减少 Token 使用量

5/17/2026, 6:00:52 PM

📌 One-Sentence Summary

本文介绍了面向 AI 编程助手的“Token 节俭”概念，详细阐述了输入压缩、上下文优化以及运行本地 MoE 模型等实用策略，以降低 Token 消耗和成本。

📝 Summary

文章认为，在 AI 编程助手时代，Token 已成为一种关键且昂贵的资源，其重要性堪比过去的 CPU 或 RAM。作者作为一名 Java 开发者，提出了“Token 节俭”这一指导原则。文章详细介绍了三种减少 Token 使用的主要策略。首先，推荐使用 `rtk` 这类代理工具，在输入到达 LLM 之前压缩输入，例如去除不必要的冠词等词汇。其次，强调上下文优化，建议用户谨慎选择包含的工具、MCP 服务器和对话历史，并使用 `/compact` 命令来减小上下文体积。第三，提供了详细的实践指南，介绍如何使用 `llama.cpp` 和 `Claude Code` 运行本地模型（特别是 Qwen3.5-35B-A3B 这类 MoE 模型），从而完全消除按 Token 计费的云端成本。作者分享了自己的排错经历，包括 Docker 问题、上下文窗口限制，以及混合专家模型在本地硬件上相对于密集模型的优势。文章最后主张，这种本地优先的方法相比不透明的、基于订阅的云服务，是一种更具成本效益和透明度的替代方案。

💡 Main Points

  1. 对于使用 AI 编程助手的开发者来说，Token 节俭是一项关键的新技能。 随着 Token 成为一种有限且昂贵的资源，能够用更少 Token 达到相同效果的开发者将对组织更有价值，这类似于过去使用更少 CPU 或内存的工程师。
  2. 输入压缩和上下文优化是减少 Token 使用的有效第一步。 使用 `rtk` 等工具去除命令中不必要的词汇，并谨慎选择包含在上下文中的工具、MCP 服务器和对话历史，可以显著降低每次请求的 Token 数量。
  3. 运行本地混合专家模型是消除按 Token 计费的云端成本的一种可行替代方案。 通过使用 `llama.cpp` 运行本地 MoE 模型（例如 Qwen3.5-35B-A3B），并配置 `Claude Code` 指向该模型，开发者可以避免重复的订阅费用，用一次性硬件成本换取每次查询的零边际成本。

💬 Key Quotes

  • 如今，关键资源不再是 CPU、RAM 或存储，而是 Token。Token 是一种有限且昂贵的资源。
  • 我的观点是，很快开发者将根据其 Token 使用量来衡量：更好的开发者将是那些用最少 Token 实现类似结果的人。
  • 保留 Claude Code 的同时在本地托管模型，是一种非常划算的替代方案。你只需要为硬件支付一次费用。
