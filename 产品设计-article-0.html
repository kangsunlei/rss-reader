📌 一句话摘要

比较 BEM、实用类和 CSS 层叠层在 CSS 特异性控制上的应用。

📝 详细摘要

本文分析了不同的 CSS 方法如何解决特异性挑战。它解释了为什么在复杂的项目中会出现特异性问题，以及依赖 `!important` 的问题所在。作者回顾了 BEM 的显式命名约定以实现低特异性，实用类的原子类方法以避免特异性冲突，以及较新的 CSS 层叠层，后者允许显式控制层叠顺序本身，独立于特异性权重。本文讨论了每种方法的优点、缺点和最佳用例，提供了代码示例和比较表。结论是，虽然 BEM 和实用类提供了有效的策略，但 CSS 层叠层为细粒度控制提供了一个强大的新工具，尤其是在遗留代码或集成第三方样式等具有挑战性的场景中，并建议它们甚至可以结合使用。

💡 主要观点

  1. CSS 特异性决定了应用哪些样式，经常导致意外行为。 当多个 CSS 规则匹配一个元素时，浏览器使用特异性算法来决定最终应用的样式声明，如果不理解这一点，可能会导致困惑。
  2. BEM 和实用类通过结构化命名或原子类规则来管理特异性。 BEM 旨在通过显式类名实现扁平的、低特异性。实用类通过使用统一的、单一用途的类来避免特异性冲突。
  3. CSS 层叠层提供对层叠顺序的显式控制。 层叠层允许开发人员定义样式组的优先级，覆盖特异性规则，并为遗留代码等复杂场景提供细粒度控制。

💬 文章金句

  • 特异性的核心在于，当两个或多个 CSS 规则应用于同一元素时，浏览器通过 CSS 层叠算法来决定最终生效的样式声明。
  • 为了避免很多这些问题，我始终遵守一个原则：尽可能保持较低的特异性。
  • 实用类并没有直接解决特异性问题，而是将 BEM 的低特异性思想发挥到了极致。
  • BEM 提供结构，实用类提高开发速度，CSS 层叠层为我们提供了至关重要的东西：控制。
  • 由于 `@layer` 的工作方式，`.button` 将会胜出，因为 `components` 层具有最高的优先级，即使 `#button` 具有更高的特异性。
