📝 详细摘要

本文档作为学习无障碍富互联网应用（ARIA）的入门指南。它解释了 ARIA 的根本目的：当原生 HTML 元素不足时，向辅助技术提供补充信息。作者深入研究了 ARIA 的历史，将其核心理念与旧的操作系统的交互模式和键盘期望（如 Windows XP 中的）联系起来。关键章节涵盖了正确使用 ARIA 的五个基本规则，并详细介绍了其角色、状态和属性的分类体系。文章强调在可能的情况下，优先使用语义 HTML 和隐式角色，而不是显式 ARIA，并提供关于如何在 HTML 元素上声明 ARIA 属性的指导。它的目标是构建一个坚实的理论基础，而不是提供具体的实现方案。

💡 主要观点

  1. 当原生元素不足时，ARIA 补充了 HTML 语义以用于辅助技术。 仅当标准 HTML 无法有效地向屏幕阅读器和语音控制软件传达这些细节时，才使用 ARIA 添加有关交互性、目的和状态的信息。
  2. 理解 ARIA 植根于旧操作系统交互模式的历史背景至关重要。 ARIA 反映了 Windows XP 等系统的设计模式，这影响了 Web 应用程序的键盘行为和交互模型。
  3. 严格遵守 ARIA 使用的五个规则，以确保可访问性。 这些规则强调首先使用语义 HTML，保留原生元素语义，确保键盘可操作性，避免滥用 `role="presentation"` 或 `aria-hidden="true"`，以及命名交互元素。
  4. ARIA 采用角色、状态和属性的分类来定义元素及其特征。 角色定义了一个元素是什么（语义），而状态和属性描述了它当前的特征；通常优先于显式 ARIA 角色使用来自原生 HTML 的隐式角色。

💬 文章金句

  • 如果没有更适合用于传达交互性、目的和状态的原生 HTML 元素或属性，ARIA 就是你的选择。
  • ARIA 的创建是为了在 HTML 的局限性与使辅助技术能够理解交互式体验的需求之间架起一座桥梁。
  • ARIA 是此时期操作系统交互模式的快照。
  • 尽可能使用原生元素。
  • 如果用例需要，几乎总是最好使用隐式角色。
