徒步佬怒改两步路 UI 设计 | 优化思路分享

5/25/2026, 2:35:00 PM

📌 一句话摘要

本文以两步路 APP 路线详情页为例，系统分析了其 UI 设计中的信息层级混乱、交互逻辑不合理等问题，并提出了具体的优化方案和设计思路。

📝 详细摘要

文章作者以产品设计专家的视角，对户外徒步应用「两步路」的路线详情页进行了深度体验分析。文章首先指出了原页面存在的五大核心问题：首屏信息展示混乱、线路轨迹与途经景点脱节、文本信息顺序不符合阅读习惯、底部推荐样式重复且交互困难、底部操作栏布局与表述混乱。针对这些问题，作者提出了对应的优化方案，包括优化顶部图片为可滑动卡片、重构信息层级以突出关键数据、强化地图与途经点的联动、优化推荐模块的视觉与交互形式，以及调整底部操作按钮的逻辑顺序。文章通过原型对比展示了优化后的页面结构，强调了 UI 设计应紧密贴合用户的实际使用场景和认知习惯。

💡 主要观点

  1. 原页面首屏信息层级混乱，关键数据展示不足。 封面图作用有限，里程、爬坡等核心数据被弱化，用户信息与路线属性穿插，破坏了阅读节奏，增加了用户的理解成本。
  2. 线路轨迹与途经景点信息脱节，缺乏交互联动。 地图上的路线不够清晰，途经景点仅以标签罗列，缺乏位置关联和引导性，用户无法直观了解景点在路线中的具体位置。
  3. 底部推荐模块样式重复，交互效率低下。 约伴、路线、视频三种推荐内容使用同一种横向滚动样式，视觉疲劳且操作效率低，降低了用户继续探索的意愿。
  4. 优化方案强调信息重组与场景化交互。 通过优化图片展示、强化关键数据、重构信息顺序、加强地图与景点联动、优化推荐样式和操作栏布局，使页面更符合用户认知和徒步场景的实际需求。

💬 文章金句

  • 在首屏中，内容是很分散且混乱的。
  • 地图和途径点做更深度的结合，途径点做成左右连线，可以通过滚动来查看途经点，且选中途经点可以在地图中标识出来。
  • 详情页的优化和真实的使用场景关联度很大。
  • 先有交通抵达，才开始线路行程的逻辑更符合出行的顺序。
