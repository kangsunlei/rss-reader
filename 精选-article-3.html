保护 VS Code 免受提示注入攻击

8/25/2025, 4:01:12 PM

📌 一句话摘要

本文详细介绍了 VS Code 的 Copilot Chat 代理模式中存在的提示注入漏洞，该漏洞源于不当的工具处理和 LLM 对外部输入的错误解析，可能导致数据泄露和任意代码执行。

📝 详细摘要

本文探讨了 VS Code 的 Copilot Chat 代理模式中发现的关键提示注入漏洞。该模式集成了大型语言模型 (LLM) 与本地开发环境和各种工具。代理的内部机制将工具输出和用户提示混合，形成单一的输入供 LLM 处理，但这种混合可能被恶意利用。LLM 可能将外部数据（如 GitHub 问题中的恶意指令）错误地解释为命令，而非单纯的信息。文中详细描述了三个主要漏洞：`fetch_webpage` 工具因 URL 解析缺陷绕过信任检查导致的数据泄露；`simpleBrowser` 工具的类似漏洞，导致本地 GitHub 令牌在未经用户确认的情况下泄露；以及 `editFile` 工具利用立即保存文件行为，修改敏感配置文件实现任意代码执行。作者还讨论了增强攻击可靠性的间接提示注入技术，并概述了 VS Code 的缓解措施，包括对敏感操作更严格的用户确认和限制工作区外的文件修改。

💡 主要观点

  1. LLM 可能将工具输出误解为指令，从而导致提示注入。 当 VS Code 将用户查询、系统消息和工具输出混合成一个提示时，LLM 可能无法区分预期指令和外部数据，从而允许执行工具输出中的恶意指令。
  2. 有缺陷的 URL 解析和自动工具执行导致数据泄露。 `fetch_webpage` 和 `simpleBrowser` 工具存在漏洞（例如，基于正则表达式的 URL 信任验证），这些漏洞允许它们在未经用户确认的情况下将敏感本地数据（如 GitHub 令牌）发送到外部恶意服务器。
  3. `editFile` 工具的立即文件更改可能导致任意代码执行。 `editFile` 工具在保存更改到磁盘时的立即执行行为，即使在用户确认之前，也可能被利用来修改敏感配置文件（如 `settings.json`），从而触发恶意命令。
  4. 间接提示注入技术提高了针对 LLM 的攻击可靠性。 攻击者可以使用微妙的方法，如条件语句、引用其他提示部分或模仿系统提示，来可靠地欺骗 LLM 执行非预期操作，尤其是在 `temperature: 0` 的情况下。

💬 文章金句

  • 在这种情况下，模型不仅可能被诱骗给出不正确的答案，还可能通过工具调用秘密地执行敏感操作。
  • 在我的测试中，我发现即使是最先进的模型，如 GPT-4.1、Gemini 2.5 Pro 和 Claude Sonnet 4，也可能被工具输出误导，从而做出与用户最初请求完全不同的事情。
  • 微妙之处在于，当提示用户审查这些更改时，文件已经被编辑到磁盘上，因此“保留”选项不起作用。
  • 从我观察到的情况来看，Claude Sonnet 4 似乎是经过最彻底训练以抵抗这些类型攻击的模型，但即使是它也可以被可靠地欺骗。
  • VS Code 不再允许代理编辑工作区之外的文件。即将推出更多保护措施（已在 Insiders 版本中提供），这些措施强制用户在编辑敏感文件（例如配置文件）时进行确认。
