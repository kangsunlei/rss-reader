构建面向 Agentic 推理的下一代 LLM 推理引擎

11/12/2026, 5:55:00 AM

📌 一句话摘要

文章系统阐述了 TokenSpeed 项目从立项到迭代构建面向 Agentic 推理的下一代 LLM 推理引擎的完整技术路径，聚焦 Agent 场景下的延迟约束吞吐优化、KV Cache 复用、跨平台 Kernel 设计及自动并行编译等核心挑战与创新方案。

📝 详细摘要

在 Agent 推理负载快速增长的背景下，传统面向聊天场景的推理引擎面临吞吐优化目标失效、缓存利用率不足、硬件适配滞后等结构性挑战。文章基于 TokenSpeed 项目，系统介绍了从立项到版本迭代的完整技术路径。核心在于将优化目标从单纯追求吞吐转向延迟约束下的吞吐最大化，定义每用户 TPS 不低于 70 的性能指标。通过分层解耦的系统架构（控制层 C++、Runtime 层 Python、Kernel 层独立子包），实现调度决策、执行计划、算子计算的清晰分离。自动并行编译系统将并行切分逻辑从模型适配代码中抽离，降低维护成本。KV Cache 管理方面，从 Radix Tree 迁移到 Flat KV 设计，引入双层 block 机制提升前缀复用效率。Kernel 层针对 MLA 注意力机制在 Blackwell 平台进行深度优化，充分利用 Tensor Memory 和折叠因子技术。跨平台设计参考 Linux 内核抽象思路，建立 register 和 selector 机制，实现对 NVIDIA、AMD 等多硬件的统一支持。实验数据表明，TokenSpeed 在 Blackwell 平台相较 TensorRT-LLM，最小延迟场景下快 9%，每用户 100TPS 工作点下每 GPU 吞吐提升 11%。

💡 主要观点

  1. Agent 场景推理引擎的优化目标从吞吐转向延迟约束下的吞吐最大化 文章指出 Agent 场景下模型持续思考、调用工具、获取结果的多轮短请求循环，对延迟敏感度显著提升，必须定义每用户 TPS 不低于 70 的性能指标，以 Pareto 前沿评价推理引擎性能。
  2. 分层解耦的系统架构实现调度、执行、算子计算的清晰分离 控制层使用 C++负责调度决策，Runtime 层使用 Python 执行控制面下发的计划，Kernel 层独立子包专注算子实现，避免了过去推理引擎中逻辑渗透导致的维护困境。
  3. 自动并行编译系统降低模型适配的维护成本 将并行切分逻辑从模型适配代码中抽离为独立的 Placement 系统，开发者只需声明模块边界和并行策略属性，系统自动处理切分和通信，同时通过类型系统实现算子 fusion。
  4. Flat KV 设计和双层 block 机制提升前缀复用效率 针对 Agent 场景下几十 K 甚至几百 K 的前缀长度，文章从 Radix Tree 迁移到 Flat KV 设计，引入逻辑块 128 和物理块 1536 的双层结构，显著改善前缀复用效率和页内碎片问题。
  5. Kernel 层针对 MLA 注意力机制在 Blackwell 平台进行深度优化 针对 MLA 在 decode 阶段的 Tensor Core 利用率低、带宽瓶颈和矩阵形状不匹配问题，设计 Tensor Memory 分配器、折叠因子优化、Split KV 机制等技术，使 Kernel 在 Blackwell 上达到 state-of-the-art 水平。
  6. 跨平台 Kernel 设计通过抽象层实现多硬件统一支持 参考 Linux 内核抽象思路建立 register 和 selector 机制，模型适配代码不感知底层硬件，通过 API 定义操作类型和 capability，不同厂商团队可独立适配，提供 reference、performance 和 specialized plugin 三层优先级。

💬 文章金句

  • Agent 场景下真正需要优化的是延迟约束下的吞吐
  • 我们内部定义了一个性能指标：每用户 TPS 不低于 70
  • KV Cache 复用率是决定推理成本的关键变量
  • TokenSpeed 在 Blackwell 平台上取得了一系列可量化的性能成果
  • 系统分层必须清晰，控制面只负责调度决策，不触碰数据面
