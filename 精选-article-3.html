让 Hy4 flash 吐字提速 4.2 倍，混元 DFly2 开源

11/26/2026, 6:33:00 AM

📌 一句话摘要

腾讯混元开源 DFly2 草稿模型，通过极致复用目标模型的 KV cache 和稀疏索引，在保持 Hy4 flash 权重不变的前提下，将长上下文场景下的吐字速度提升最高 4.2 倍。

📝 详细摘要

本文介绍腾讯混元团队开源的 DFly2 草稿模型，这是一种为 DSA 类稀疏注意力大模型和长上下文场景设计的加速组件。DFly2 通过 KV Share 与 Index Share 机制，直接复用目标模型 Hy4 flash 已计算好的 KV cache 和稀疏索引，实现计算与显存的双重节省。实测表明，在同等训练条件下，DFly2 的接收长度相较于 DFlash 与 DSpark 整体优势更大，长文与 Agent 场景优势更明显，平均加速分别高约 12% 与 30%，单项最高提升 4.2 倍。该模型的权重已随 Hy4、Hy4 flash 开源，训练代码集成至 AngelSpec 平台。

💡 主要观点

  1. DFly2 通过极致复用目标模型的 KV cache 和稀疏索引实现加速 DFly2 的每个草稿层直接共享目标模型对应的稀疏注意力层的 KV cache 和 indexer 选出的至多 2，048 个位置，计算开销固定、零额外 KV 显存，显著提升了长上下文推理效率。
  2. 实测显示 DFly2 在长文与 Agent 场景下加速显著 在同等训练条件下，DFly2 相较于 DSpark 在长文场景下接收长度提升约 18%，Agentic 场景下最高提升 68.5%，平均加速约 3.2 倍，最高可达 4.2 倍。
  3. DFly2 采用免 rollout 的 DFly-OPD 在线蒸馏训练方式 训练时，drafter 在自己起草的候选上接收目标模型打分，使训练与推理保持一致，省去了整段 rollout 的计算，提高了训练效率。
  4. PD 分离部署实现 KV 零冗余 DFly2 在 Decode 端直接复用主模型的历史 KV 和稀疏索引，Prefill 端只运行主模型，P→D 传输数据减少 98.5 MiB，端到端输出吞吐比 MTP 高 26%。

💬 文章金句

  • 我们把让 Hy4 flash 模型变得更快的秘密武器开源了。
  • DFly2 最大的亮点是极致复用目标模型：每个 draft 层直接共享目标模型对应稀疏注意力层的 KV cache（KV Share）和 indexer 选出的至多 2，048 个位置（Index Share）。
  • 长文：上下文越长，DFly2 领先越多。相对 DSpark 的接收长度提升从短文约 4% 扩大到 128K 约 18%，长上下文上仍有约 3.2× 加速。
  • Agentic：接收长度最高提升 68.5%。agentlongbench 上 A12B 达 4.20×；4 项平均加速约 3.2×，比 DSpark 高约 25%。
  • DFly2 比 MTP 少传 98.5 MiB，约占原历史缓存总载荷的 1.44%，两端也各少存 98.5 MiB。
