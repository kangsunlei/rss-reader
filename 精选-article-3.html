构建更有效的 AI 智能体

10/17/2025, 4:01:56 PM

📌 一句话摘要

Anthropic 专家讨论了构建更有效的 AI 智能体的策略，涵盖多智能体系统、技能与工具的最佳实践，以及未来发展方向。

📝 详细摘要

本次讨论由 Anthropic 的 Alex Albert 和 Erik Schluntz 主讲，他们深入探讨了构建有效 AI 智能体的演变和最佳实践。他们解释了如何训练 Claude 用于智能体任务，强调编码在使智能体更具自主性方面的作用。对话重点介绍了 Claude Agent SDK 对开发者的实用性，这使得开发者无需重建核心智能体循环，即可集成自定义业务逻辑和工具。讨论的一个关键创新是“智能体技能 (Agent Skills)”，它扩展了 `claude.md` 文件，以包含可重用的资源（如模板、代码和资产），从而显著增强了智能体的能力。专家区分了“代理工作流 (Agent workflows)”（顺序智能体）和“多智能体系统 (Multi-agent systems)”（并行或协调智能体），详细介绍了并行化和 MapReduce 等模式。他们还讨论了常见的失败模式，例如多智能体设置中的过度工程和通信开销。最佳实践包括从简单开始、理解智能体的视角，以及设计面向模型的工具，这些工具映射到 UI 概念而不是原始 API。智能体的未来设想是具有更强的“计算机应用 (Computer Use)”能力，从而实现自我验证以及与 Google Docs 等应用程序的自主交互，最终减少对人工 QA 的需求。

💡 主要观点

  1. 通过开放式多步骤任务及编码训练，Claude 的智能体能力显著增强。 使用复杂的、多步骤的问题（尤其是在编码方面）训练 Claude，使其成为一个高效的智能体，能够通过代码驱动的操作和 API 交互来执行各种任务，从而实现更广泛的应用。
  2. 多智能体系统使用协调器和子智能体，具有并行化、上下文保持和改进问题解决等优点。 通过分解任务并委派给专门的子智能体，可以更有效地解决复杂问题，从而利用并行处理并防止主上下文因不必要的令牌 (tokens) 而过载。
  3. 构建智能体的最佳实践包括从简单开始、从智能体的角度思考，以及设计用于以模型为中心的交互的工具。 应避免过度工程。开发者必须考虑模型接收哪些信息，并设计将复杂 API 抽象为用户友好的、类似 UI 的交互的工具，而不是直接的 API 映射。
  4. 智能体技能 (Agent Skills) 提供的可重用资源不仅仅是指令，从而显著增强了智能体的能力。 技能允许智能体不仅访问指令，还可以访问模板、代码、图像和其他资产，使他们能够以所有必要的资源随时可用的状态开始任务，就像尼奥在《黑客帝国》中学习功夫一样。
  5. AI 智能体的未来涉及通过“计算机应用 (Computer Use)”能力改进自我验证，使智能体能够测试和调试自己的工作。 智能体将不仅仅是生成输出，还会积极地与计算机环境（例如，Web 应用程序、Google Docs）交互，以测试、改进和自主完成任务，从而减少对人工 QA 的需求。

💬 文章金句

  • 编码是我们关注的第一个任务。但是，一旦拥有强大的编码智能体，它几乎能胜任任何其他类型的工作。
  • 我想说的是，它与代理工作流 (Agent workflows) 非常不同。代理工作流是指一个智能体完成任务后，将结果传递给下一个智能体。
  • 我认为面向模型的工具或 MCP 应该与你的 UI 一对一，而不是你的 API。因为归根结底，模型是这些东西的用户。
  • 最令人兴奋的是，智能体若能通过“计算机使用 (Computer Use)”等能力更好地验证自身工作，例如，编写 Web 应用程序后能自行打开测试并找出错误，而无需人工介入。
