智能工具选择：利用 Spring AI 动态工具发现实现 34-64% Token 节省

12/11/2025, 12:00:00 AM

📌 一句话摘要

本文介绍了 Spring AI 的工具搜索工具，它能动态发现并注入相关工具到 LLM 提示中，从而实现 34-64% 的 Token 节省，并提高大型工具库的准确性。

📝 详细摘要

本文旨在解决 LLM 驱动的 AI 代理在拥有大型工具库时面临的上下文膨胀和工具选择混乱问题。文章引入了“工具搜索工具”模式，该模式受 Anthropic 启发，但通过 Spring AI 的递归增强器 (Recursive Advisors) 为任何 LLM 提供了可移植的实现。此方法在初期会对所有工具进行索引，但只向 LLM 发送一个“工具搜索工具”的定义。随后，LLM 会查询此搜索工具以了解其功能，并仅将相关的工具定义动态注入到后续的提示中。初步的基准测试表明，在 Gemini、OpenAI 和 Anthropic 模型中，该方法实现了显著的 Token 节省（34-64%），并提高了工具选择的准确性，尤其是在处理 30 多个工具时。文章详细阐述了实现过程，展示了可插拔的搜索策略（语义、关键词、正则表达式），提供了代码示例，并讨论了该方法最有利的使用场景，建议将其应用于拥有 20 多个工具或工具消耗超过 5K Token 的系统。

💡 主要观点

  1. 动态工具发现显著降低了 AI 代理的 Token 消耗和成本。 “工具搜索工具”模式并非预先加载所有工具定义，而是仅动态注入所需的工具。初步基准测试证实，这使得各种 LLM 的 Token 节省达到 34-64%。
  2. Spring AI 提供了动态工具发现的可移植且与 LLM 无关的实现。 借助 Spring AI 的“递归增强器”架构，“工具搜索工具”能够无缝兼容不同的 LLM 提供商（OpenAI、Anthropic、Gemini、Ollama、Azure OpenAI），屏蔽了特定于提供商的实现细节。
  3. 该方法提高了大型工具库的工具选择准确性和可管理性。 通过减少上下文膨胀，避免用过多工具定义使 LLM 过载，模型能够做出更准确、更高效的工具选择，尤其适用于拥有 20 多个工具的系统。

💬 文章金句

  • 我们的初步基准测试显示，Spring AI 的工具搜索工具实现在保持对数百个工具的完全访问的同时，使 OpenAI、Anthropic 和 Gemini 模型的 Token 消耗减少了 34-64%。
  • Spring AI 递归增强器架构的强大之处在于，它使我们能够实现复杂的工具发现工作流，这些工作流具有普适性——无论您使用的是 OpenAI 的 GPT 模型、Anthropic 的 Claude、本地 Ollama 模型，还是 Spring AI 支持的任何其他 LLM。
  • 工具搜索工具模式是迈向可扩展 AI 代理的关键一步。通过将 Anthropic 的创新方法与 Spring AI 的可移植抽象相结合，我们能够构建高效管理数千个工具，并在任何 LLM 提供商上保持高准确性的系统。
