你的 AI Agent 真的在受控运行吗？

3/13/2026, 12:31:00 AM

📌 一句话摘要

本文以 OpenClaw 为例，系统阐述了如何通过 Session 审计日志、应用日志和 OTEL 遥测构建 AI Agent 的可观测体系，解决其行为非确定性带来的安全与受控运行难题。

📝 详细摘要

文章深入探讨了 AI Agent 在运行时面临的安全挑战，如指令遗忘、高危工具滥用和攻击面宽广等问题。作者指出，由于 Agent 行为具有非确定性，传统的预防性控制（如策略管道、命令过滤）不足以保证其完全受控。文章提出了一套基于 Logs、Metrics 和 Traces 的可观测性架构，详细介绍了三条数据管道：Session 审计日志用于还原行为链和威胁检测；应用日志用于监控系统运行状态；OTEL 遥测用于实时性能与成本监控。通过多源联动的排查路径，为 AI Agent 从“能用”转向“可信”提供了完整的方法论和技术实践。

💡 主要观点

  1. AI Agent 的非确定性行为使得传统 API 审计模式失效。 同样的用户输入可能产生不同的工具调用序列，无法通过静态代码审查预判所有路径，必须依赖运行时的可观测性来追溯行为。
  2. 运行时防护存在局限，必须依靠持续可观测性作为补位哨兵。 预防性控制无法覆盖配置错误、规则遗漏或模型上下文压缩导致的指令遗忘，需通过日志和指标在策略失效时及早发现风险。
  3. Session 审计日志是还原 Agent 行为链及检测威胁的核心数据源。 通过记录每轮对话的结构化数据，可以实现敏感数据外泄检测、高危工具调用监控及精准的成本归因，完整还原 Agent 到底做了什么。
  4. OTEL 遥测能够实时监控 Token 消耗增速和会话健康度。 利用 Metrics 指标可以快速识别 Token 激增、会话卡死或 Webhook 错误率异常，为系统运维提供实时的告警能力。
  5. 建立“指标发现-日志定位-审计还原”的多源联动排查模式。 通过 OTEL 告警发现异常，利用应用日志缩小范围，最后下钻到 Session 审计日志确认根因，形成完整的审计与运维闭环。

💬 文章金句

  • Agent 的行为是非确定的。这意味着你无法像审计 REST API 那样通过代码审查预判所有行为路径。
  • 运行时防护相当于“城墙”——能挡住绝大多数已知攻击路径，但无法保证配置永不出错，也无法覆盖未知绕过。
  • 回答“你的 AI Agent 真的在受控运行吗？”需要同时回答：谁在触发调用、花了多少钱、做了哪些操作、行为是否可追溯。
  • Token 激增往往不只是成本问题——Prompt 注入导致上下文被恶意填充、工具调用陷入死循环都会表现为曲线陡升。
  • 只有三源联动，才能从“有异常”到“哪里出了问题”再到“Agent 具体做了什么”形成可查证的审计与运维闭环。
