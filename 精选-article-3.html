📌 一句话摘要

文章深入分析了 JavaScript 中 await fetch()可能导致的性能问题，并提供了包括连接复用、流式解析、并发控制及协议优化在内的全面解决方案。

📝 详细摘要

本文对 JavaScript 应用中 await fetch()的常见性能瓶颈进行了系统性剖析。作者首先揭示了冷启动 TCP 连接（DNS 解析、TCP/TLS 握手）带来的延迟，并提出了使用 undici 的 Agent 进行连接复用、DNS 缓存的解决方案。其次，文章深入探讨了 response.json()在处理大量数据时阻塞事件循环的问题，倡导采用流式解析以提升效率。针对循环中 await 导致的串行执行低效，文章给出了限制并发数量的有效策略。此外，文中还涵盖了优化响应体大小（如 Brotli 压缩）、简化 CORS 预检请求、解决 HTTP/2 HOL 阻塞以及 JSON.stringify()序列化性能问题等多个方面。文章特别区分了 Node.js 和浏览器端的 fetch 优化策略，为不同开发环境提供了针对性的实践建议，旨在帮助开发者显著提升应用的网络请求性能和用户体验。

💡 主要观点

  1. 揭示 await fetch()在冷启动连接和大数据解析中的性能瓶颈 首次请求涉及 DNS、TCP 和 TLS 握手带来的数百毫秒延迟，以及 response.json()处理大文件时阻塞事件循环、占用 CPU 资源，是常见的性能痛点。
  2. 通过连接复用和流式处理显著提升网络请求效率 利用 undici 的 Agent 管理 Keep-Alive 连接，避免重复握手；采用流式 JSON 解析，避免一次性加载大文件，有效降低延迟和内存占用。
  3. 优化并发控制和网络协议以提升系统吞吐量 避免在循环中串行 await，通过限制并发数量来平衡资源；同时，利用 HTTP/2 多路复用或 HTTP/3 的 0-RTT 特性，可进一步减少请求延迟。
  4. 区分 Node.js 与浏览器端 fetch 优化策略，提供针对性指导 Node.js 环境可使用 undici、自定义 Agent 等；浏览器端则侧重缓存、请求合并、懒加载和后端压缩，指导开发者根据场景选择最佳实践。

💬 文章金句

  • 即使是像 await fetch() 这样简单的代码，也可能会无意中拖慢应用的速度，导致网络请求延迟，让用户体验变差。
  • 每次调用 fetch() 都会创建一个新的套接字连接，这包括以下几个步骤：DNS 解析、TCP 握手、TLS 握手。
  • 当服务器返回大量 JSON 数据（例如 5-10MB 或更多）时，response.json() 会阻塞事件循环，占满 100% 的 CPU 资源。
  • 在循环中执行多个异步任务时，如果使用 await，它们会按顺序一个一个执行，即使它们本可以并行完成。
  • 为了获得更好的性能，建议使用 undici 的 request 方法来替代内建的 fetch，因为它更快、开销更小。
