从 HITL(Human In The Loop) 实践出发看 Agent 与设计模式的对跖点

1/8/2026, 12:30:00 AM

📌 一句话摘要

文章详细阐述了如何在 Agent 中实现 Human In The Loop (HITL) 机制，并深入探讨了 Agent 演进与传统工程设计模式之间的深层对跖关系及未来可能。

📝 详细摘要

本文围绕如何在 ReactAgent 中实现 Human In The Loop (HITL) 机制展开，详细介绍了通过设计 XML 协议、将 HITL 交互定义为工具、以及规划系统提示词和对话挂起重连等技术实现细节，以解决传统 Agent 伪人机协同中的问题。文章通过具体案例展示了 HITL 在参数不明确和任务走向控制方面的应用效果。更进一步，作者深入探讨了 Agent 演进过程与传统工程设计模式之间的联系，将 HITL 类比为 Hook 和拦截，将 Dify 和 LangGraph 类比为图数据结构，ReactAgent 类比为循环+责任链，MCP 类比为防腐层与适配器模式，按需加载工具类比为懒加载，记忆类比为多级缓存，Skills 类比为简单工厂模式。最后，作者设想了利用复杂工厂模式自适应生成专业 Agent 的未来可能性，强调了设计模式在 Agent 发展中的关键作用。

💡 主要观点

  1. 实现 Agent 中的 Human In The Loop (HITL) 机制以解决伪人机协同问题 通过引入 HITL，使得用户能在对话过程中实时参与参数补充和任务走向控制，避免传统多轮对话中上下文失真、成本高和性能不可控等弊端，提升人机交互效率和体验。
  2. HITL 的技术实现涉及交互设计和工具化 通过设计支持 HTML 渲染的 XML 协议实现复杂 UI 交互，将 HITL 定义为 Agent 的专用工具，通过 functionCall 语法唤起，并利用 Redis 实现对话挂起、重连、超时处理，确保用户输入的实时反馈和任务的连续性。
  3. Agent 的演进可与传统工程设计模式建立对跖关系 文章将 HITL 类比于编程中的 Hook/拦截，将 Dify/LangGraph 类比于图数据结构，ReactAgent 类比于循环+责任链，MCP 类比于防腐层/适配器模式等。这种映射揭示了 Agent 背后相通的工程设计思想。
  4. 设计模式为 Agent 创新提供方向 通过将懒加载、多级缓存、简单工厂等设计模式映射到 Agent 的工具按需加载、记忆管理和技能设计中，作者展望了利用复杂工厂模式自适应生成专业 Agent 的未来潜力，强调了从工程角度审视 Agent 发展的重要性。

💬 文章金句

  • 冗余的架构设计倒推我们去思考合理的代码设计，也正是这种合理的设计——Hook、钩子、拦截。。。 这些手段的优化，催生出了 Human In The Loop 这种人机协同的用户体验出来。
  • 将数据结构中的图结构与 LLM 做结合，无疑是初代 Agent 最成功的范式。
  • 从设计模式看，就是将循环和责任链进行了组合使用，循环结束的条件交给了 LLM 自行判断。
  • 同样如果从结果来看，防腐层、适配器模式无疑是为 LLM 的调用提供了一种新的玩法——MCP。
  • 利用工厂模式，一次对话中自适应生成解决本次任务所需要的专业 Agent，有点天马行空，但从目前 Agent 的玩法中，其实很容易实现，只不过用来解决的场景还没有出现。
