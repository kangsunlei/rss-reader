与 Boris Cherny 共同构建 Claude Code

3/4/2026, 5:57:56 PM

📌 一句话摘要

Claude Code 的创建者 Boris Cherny 探讨了他 100% 由 AI 驱动的工作流、Anthropic 独特的工程文化，以及为什么在 AI 时代软件工程师正从“抄写员”转变为“作者”。

📝 详细摘要

在这次访谈中，Anthropic 工程负责人 Boris Cherny 详细介绍了 Claude Code 的演进以及他向“零手动代码”工作流的激进转变。他分享了如何利用并行 AI 智能体每天管理 20-30 个 PR（拉取请求），并强调通过“计划模式”（Plan Mode）和 Git Worktrees 来保持高速产出。讨论涵盖了 Anthropic 的“技术参谋”（Member of Technical Staff）文化——通过取消职级头衔来鼓励通才式的问题解决，并用快速原型设计取代 PRD。Boris 提供了构建智能体工具的深度架构见解，倡导“瑞士奶酪”安全模型，并阐述了智能体搜索优于传统 RAG 的观点。最后，他引用了一个强有力的历史比喻，将当前的 AI 革命比作印刷机的发明，后者将抄写员转变为作者，并极大地扩张了文学市场。

💡 主要观点

  1. 从手动编码转向管理并行 AI 智能体可显著提升工程吞吐量。 Boris 倡导一种使用多个终端标签页和 Git Worktrees 的工作流，工程师在其中扮演导演的角色。通过在执行前使用“计划模式”来对齐意图，他每天提交数十个高质量的 PR，而无需手动编写任何一行代码。
  2. 现代 AI 工具应被视为自主主体，而非僵化的软件组件。 Claude Code 背后的架构哲学不再将模型“框定”在特定的接口中。相反，它为模型提供 Bash 和文件访问等原始工具，让 LLM 固有的“工具使用”本能通过迭代的智能体推理来解决复杂问题。
  3. “瑞士奶酪”安全模型对于在生产环境中部署自主编码智能体至关重要。 Anthropic 通过多个重叠层确保安全：模型层面的对齐、用于检测提示词注入的运行时分类器，以及强制性的人机回环审核。这种多层方法在允许高度自主性的同时，降低了非确定性 AI 行为和恶意指令的风险。
  4. 软件工程师的角色正从技术“抄写员”演变为高层级的“作者”。 Boris 借鉴了 15 世纪印刷机的类比，认为虽然编码的“体力劳动”正在被自动化，但随着软件创建成本的骤降，对“作者”（即定义意图、架构和跨学科解决方案的人）的需求将会爆发。
  5. 快速原型设计和“吃自家狗粮”取代了传统的文档和 PRD 在高速发展的 AI 团队中的地位。 在 Anthropic，工程师、设计师甚至财务人员都使用 Claude Code 来构建功能原型。这种文化优先考虑“演示而非说教”，允许团队在几天内迭代数十个版本，这对于不可预测的 AI 产品来说比静态设计规范有效得多。

💬 文章金句

  • 我没有手动修改过任何一行代码。我每天提交 10 到 20 个 PR，全部 100% 由 Opus 4.5 和 Claude Code 编写。
  • 模型本身是一个独立的主体。你给它工具……让它运行并编写程序，而不是强行将其作为组件塞进一个大型系统中。
  • 我们是 15 世纪的抄写员……印刷机并没有摧毁这个职业，它孕育了作家和作者。
  • 最佳实践始终是保持代码库整洁……这不仅对工程师有好处，现在对 AI 模型也同样重要。
  • 我没有任何历史经验可以借鉴……我必须完全放下自我，每天以“初学者心态”投入工作。
