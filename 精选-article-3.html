基于 LLM Wiki、OKF 与 Git 的 Agent 知识库：淘宝直播互动团队的 AI Coding 实践

11/20/2026, 8:39:00 AM

📌 一句话摘要

本文介绍了淘宝直播互动团队构建的 LiveX Wiki——一种面向 AI Coding Agent 的知识库方案，通过 LLM Wiki 编纂业务理解、OKF 表达知识结构、Git 管理版本，按域-场景-知识三层组织跨端跨仓业务经验，显著提升代码产出质量。

📝 详细摘要

文章聚焦淘宝直播互动团队在 AI Coding 实践中构建的 LiveX Wiki 知识库方案。针对传统 RAG 向量知识库在复杂业务编码中存在的知识碎片化、相关性低等瓶颈，团队融合 LLM Wiki 编纂业务理解、OKF 思想组织知识表达、Git 管理版本迭代，按'域-场景-知识'三层结构将跨端跨仓的业务经验显式沉淀为机器可解析的上下文。方案通过层次索引与 Agentic Search 结合实现按需消费与回源核验，评测表明 LiveX Wiki 端到端生码平均得分较无知识库提升 39.15%，较 RAG 方案提升 30.1%，线上仓库定位准确率从 60%升至 90%。

💡 主要观点

  1. LiveX Wiki 采用域-场景-知识三层结构组织业务知识 以业务域承载能力职责，以业务场景聚合入口、规则、依赖和维护责任，以共享知识维护通用约束，形成层次化的知识网络结构，帮助 Agent 判断修改范围。
  2. 知识生产通过 LLM Wiki 编纂+人工定边界实现跨源调查沉淀 负责人明确场景边界和权威来源，Agent 在固定版本下跨仓调查、核对证据，将已核实的关系编纂为场景知识，未闭合证据单独记录，确保知识可溯源。
  3. 消费采用层次索引+Agentic Search 实现按需检索与核验 先由程序提供域和场景紧凑入口，Agent 按需选择场景、核心接口链和必要依赖，最后回到代码与运行平台核验当前事实，避免重复调查。
  4. 知识迭代通过 LLM 增量更新+Git 治理实现持续演进 从代码变化定位受影响场景，调查差异后形成候选修订，经过结构检查、质量门禁和评审流程后发布，确保每次变更都有依据、有版本可追溯。
  5. 评测验证 LiveX Wiki 对业务代码产出质量的显著提升 端到端生码测评显示，LiveX Wiki 综合得分较无知识库基线提升约 39.15%，较 RAG 方案提升 30.1%，需求路由测评中链路 F1 达到 1.38，证明场景覆盖建设的价值。

💬 文章金句

  • 动线 Agent 是一套面向电商用户全动线、由 LLM 驱动并受确定性规则约束的智能经营系统
  • LiveX Wiki 的价值，在于尝试建立一种新的用户经营方式：平台能够沿着用户完整旅程持续感知状态，在不同时间尺度上做出合适决策
  • 把业务理解留下来，是为了让下一次变更有可复
  • LiveX Wiki 的核心价值在于把业务知识以机器可解析的形态持续沉淀、按需消费与核验，显著提升 AI Coding Agent 对业务代码的产出质量
