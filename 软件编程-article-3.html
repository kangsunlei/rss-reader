Ruby on Rails 之父彻底倒向 AI！两个月没亲手写一行代码，却亲眼看着 Vibe Coding 毁掉系统架构

8/28/2026, 9:50:00 AM

📌 一句话摘要

Ruby on Rails 之父 DHH 分享了其全面拥抱 AI 编程的转变，指出 Agent 虽能接管 100% 的实现代码，但 Vibe Coding 也带来了架构失控与并行管理的新挑战，迫使开发者从“手写代码”转向架构审查与任务调度。

📝 详细摘要

Ruby on Rails 创始人 David Heinemeier Hansson（DHH）在最近的 Lex Fridman 访谈中分享了其对待 AI 编程的巨大转变。在短短 13 个月内，他从排斥代码补全发展到 Omarchy Quattro 项目的所有新增代码全部交由 Agent 完成。他探讨了全面使用 Vibe Coding 带来的深刻教训：虽然每个单独的 PR 都合情合理，但缺乏统一架构约束的局部修改合起来会毁掉系统架构。DHH 目前通过多台机器同时运行约 16 条 Agent 线程，并开发工具进行管理。他认为代码行数指标已经失效，机械式编码正在受到威胁，开发者的核心价值正在向定义问题、约束边界、架构审查和结果验收等上下游环节转移。

💡 主要观点

  1. AI 编程从辅助走向全面接管 DHH 从排斥小工具发展到让 Agent 承接 Omarchy Quattro 项目 100% 的新增代码，标志着编程工具正从提供代码片段演变为接管完整任务。
  2. Vibe Coding 带来架构失控风险 在 Basecamp 5 的实践中发现，设计团队通过 AI 快速生成的 PR 各自合理，但缺乏全局架构约束的改动累积在一起反而会破坏系统整体架构。
  3. 开发者角色向总调度与审查者转变 当一个人同时运行多条 Agent 线程时，实现权虽已下放，但判断权、架构边界和架构审查仍然牢牢掌握在人类手中，行数指标也彻底失效。
