快速最终一致性：深入 Corrosion，Fly.io 的分布式系统引擎

1/9/2026, 2:10:00 PM

📌 一句话摘要

Corrosion 是 Fly.io 自主研发的最终一致性分布式系统，能够在大型集群中快速复制 SQLite 数据，利用 CRDT 解决冲突，并采用基于 gossip 的传播模型为其全球应用部署平台提供支持。

📝 详细摘要

本次演讲介绍了 Corrosion，这是 Fly.io 专为快速最终一致性设计的专有分布式系统，可在众多节点间复制 SQLite 数据。该系统旨在解决之前基于 Consul 架构的可扩展性和延迟问题，优先考虑路由决策中数据传播的速度。它利用 CR-SQLite 通过 CRDT 进行冲突解决，确保即使在副本间存在独立并发更新的情况下数据也能收敛。集群成员资格由采用 SWIM 协议的 Foca 管理。Corrosion 提供用于 SQL 操作的 HTTP/PG API，支持动态模式更新，并具有基于订阅的 SQL 查询功能以实现实时客户端更新。数据传播使用 QUIC 和基于 gossip 的机制，辅以定期节点同步。该系统已在 Fly.io 的 800 台物理服务器上经过实战测试，被其代理用于机器更新和健康检查，但存在需要主键和缺乏内置身份验证等特定注意事项。

💡 主要观点

  1. Corrosion 是一个自主研发的最终一致性分布式系统，用于快速 SQLite 数据复制 由 Fly.io 开发以替代 Consul，提供更好的可扩展性和更低延迟，通过在 800+ 台物理服务器上高效分发应用状态来实现边缘路由决策
  2. 它利用 CR-SQLite（SQLite 扩展）和 CRDT 实现无冲突数据合并 CR-SQLite 在细粒度列级别跟踪变更，使用列版本和因果长度在副本同步时自动解决冲突，确保收敛而不依赖于严格的更新顺序
  3. 数据传播主要基于 gossip 机制，辅以定期同步 变更使用'感染式'模型（log n 次）广播到附近节点，然后由这些节点重新广播。定期同步确保最终一致性并捕获任何遗漏的更新，即使对于临时离线的节点也是如此
  4. Corrosion 提供用于 SQL 操作的 API 并支持基于订阅的查询 这允许客户端（如 Fly Proxy）订阅特定的 SQL 查询结果，并在底层数据变更时接收实时更新，减少了对持续数据库轮询的需求
  5. 系统架构强调本地优先操作和清晰的数据所有权以最小化冲突 尽管 CRDT 处理冲突，但 Fly.io 的实现通过让不同组件拥有不同数据段（例如，每个节点维护自己的机器数据）来最小化冲突，防止对同一行的并发写入

💬 文章金句

  • Corrosion 是一个将 SQLite 数据复制到不同节点的分布式系统
  • CRDT 是分布式系统中的一种数据类型，您可以独立地对副本进行更新并同步它们。当它们同步时，数据类型本身可以解决冲突
  • Corrosion 建立在一个名为 CR-SQLite 的库之上。CR-SQLite 是一个扩展，它允许您合并 CR-SQL 数据库
  • 我们倾向于优先传播那些广播次数较少的数据，因为它们尚未像其他数据那样广泛传播
  • 如果您将错误数据插入 Corrosion，它会迅速传播这些数据
