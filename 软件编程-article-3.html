CVE-2025-49005 - Vercel 缓存污染漏洞

7/3/2025, 1:00:00 PM

📌 一句话摘要

Next.js 应用路由与 Vercel CLI 漏洞（CVE-2025-49005）在自主托管环境中，由于 CDN 缓存键未正确区分内容类型，可能导致 HTML 请求返回 RSC 响应数据而引发缓存污染，该问题已在 Next.js v15.3.3 中修复。

📝 详细摘要

本文详细分析了 Next.js 应用路由（版本 ≥15.3.0 <15.3.3）和 Vercel CLI（版本 41.4.1-42.2.0）中的缓存污染漏洞。当中间件重定向移除了缓存失效参数时，在特定条件下会导致页面请求 HTML 内容却返回 React 服务端组件（RSC）响应数据。在 Vercel 平台上仅影响浏览器缓存，而自主托管部署可能造成 CDN 缓存污染。该漏洞已在 Next.js v15.3.3 中通过正确设置 `Vary` 标头来区分内容类型得到修复。文章提供了临时解决方案，包括为 RSC 响应设置必要的 `Vary` 标头值，并对相关团队致谢。

💡 主要观点

  1. Next.js 应用路由与 Vercel CLI 中的缓存污染漏洞 当中间件重定向移除了缓存失效参数时，该漏洞会导致 HTML 请求返回 RSC 响应数据，可能引发内容渲染错误及注水过程失败。
  2. 临时解决方案包括为 RSC 响应设置特定 `Vary` 标头值和缓存失效参数 针对无法立即升级的用户，临时解决方案需要手动设置标头：`Vary: RSC， Next-Router-State-Tree， Next-Router-Prefetch`。
  3. Next.js v15.3.3 通过正确设置 `Vary` 标头解决了该问题 修复方案通过正确配置 `Vary` 标头确保缓存键正确分离，Vercel 托管的应用需要重新部署才能生效。

💬 文章金句

  • 该漏洞允许在涉及中间件重定向和缺失 `Vary` 标头的特定条件下，页面请求 HTML 内容时返回 React 服务端组件（RSC）响应数据。
  • 在自主托管并外部部署的环境中，如果 CDN 未能正确区分缓存键中的 RSC 和 HTML 内容，可能导致缓存污染。
  • 触发漏洞时，由于 RSC 与 HTML 内容不匹配，应用程序可能显示错误或异常的客户端内容。
