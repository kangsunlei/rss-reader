重磅！Anthropic 首次公开 Claude 记忆架构！

11/22/2026, 7:16:00 AM

📌 一句话摘要

本文解析了 Anthropic 公开的 Claude 记忆架构，阐释了「在线记笔记」和「离线做梦」两种机制如何帮助无状态的 Agent 实现跨会话的「长记性」，并通过宝可梦测试和 Stainless 文档库实测展示了记忆系统的设计原则与实际效果。

📝 详细摘要

本文系统性分析了 Anthropic 最新发布的 Claude 记忆架构，旨在解决无状态 Agent 跨会话「短记性」的核心问题。文章首先澄清了 Agent 记忆的定义，明确区分其与模型微调、上下文学习、对话压缩的区别，强调记忆必须基于真实经验并以可读文本形式存储于外部。随后揭示了四层记忆架构：Transcripts（原始日志）、Memory Notes（零碎笔记）、Memory Representations（结构化知识库）和 Injected Context（预加载上下文）。核心创新在于「Dreaming」机制，即利用会话间空闲时间进行离线复盘，完成纠错、知识库构建和核心规则置顶。通过宝可梦红游戏测试，比较了 Claude Sonnet 3.7（413 个文件、100 万字符）与 Fable 5（9 个文件）的记忆管理差异，凸显「少即是多」的原则。CL-Bench 测试进一步表明，强模型倾向自主判断记忆策略，而弱模型需要引导；强加僵化规则反而导致性能下降。Stainless 35 万文件实验显示，Dreaming 整理后的 Wiki 使问答准确率从 13% 提升至 48%，配合搜索可达 61%，且显著降低 token 消耗。文章最后提炼出三条实践建议：记忆冷热分层、提示词只交代目标、定期离线复盘。

💡 主要观点

  1. Agent 记忆需以模型可读的文本形式存储于外部，跨会话保留经验 文章明确区分了记忆与微调、上下文学习、压缩的区别，强调记忆必须从真实经验中提炼，并以结构化文本形式保存，供后续会话直接读取。
  2. 四层记忆架构从底到顶分别对应原始日志、零碎笔记、结构化知识库和预加载上下文 通过课堂类比，阐释了 Transcripts、Memory Notes、Memory Representations 和 Injected Context 四层设计，实现记忆信息的层级化管理与高效检索。
  3. 「Dreaming」离线复盘机制通过纠错、知识库构建和核心规则置顶提升记忆质量 利用会话间空闲时间进行离线整理，结合原始日志校对记忆笔记，构建结构化 Wiki，并将高频核心规则提升至顶层预加载，显著提升问答准确率和效率。
  4. 记忆策略需随模型能力差异调整，强模型自主判断优于强加僵化规则 宝可梦测试显示 Claude Sonnet 3.7 记忆文件过多导致停滞，而 Fable 5 仅 9 个文件轻松获胜；CL-Bench 实验进一步证明，强加「只记失败」等限制会降低得分，弱模型则需要引导性提示。
  5. 记忆系统的实践价值在于冷热分层、目标导向提示和定期复盘 文章总结出三条开发经验：顶层仅保留核心红线与目录索引，具体细节下沉至子文件；提示词只说明记忆目标，少微操具体写法；干活后定期进行离线复盘，确保知识库干净高效。

💬 文章金句

  • 怎么让无状态的 Agent 跨会话真正「长记性」？
  • 记多了全是噪音，记错了还会把后面的会话一起带沟里。
  • Agent 记忆到底是什么？简单来说就看两点。第一是从真实经验里学出来的……第二是能跨会话保留下来，以模型直接能读懂的文本形态存在外部存储里。
  • 写一条记忆，本质上是在对未来做一次预测。
  • 记错了，或者记下了一条很快就过时的信息……一条错笔记，就能把后面一连串会话全带进沟里。
  • 少即是多。
  • 强加「只记失败」的规则反而把模型的得分掉了一大截。
  • 把「干活」和「整理」拆开，定期做离线复盘。
