使用 Knock 和 Cloudflare 的 Agents SDK 构建具有人工干预的 AI 代理

6/3/2025, 2:00:01 PM

📌 一句话摘要

使用 Cloudflare Agents SDK 和 Knock 的消息传递，构建用于处理需要人工审批的工作流程的“人在回路” AI 代理。

📝 详细摘要

本文探讨了如何通过集成 Cloudflare 的 Agents SDK 与 Knock 的消息平台来构建实用的、“人在回路” AI 代理。文章强调了在自主代理工作流程中进行人工干预的必要性，并提出了一种解决方案：Agents SDK 在 Durable Objects 上提供了有状态的、无服务器的基础，而 Knock 则处理多渠道通知和异步审批工作流程。一个虚拟卡发行的例子展示了如何通过 Knock 延迟工具调用以进行人工审批，通过 webhook 管理响应，以及使用 Agents SDK 的能力恢复代理的状态。这种组合方法简化了构建有状态、异步且有效纳入人类决策点的代理的复杂性。

💡 主要观点

  1. 将人类集成到 AI 代理循环中对于构建实用、有用的代理至关重要。 完全自主的代理通常不切实际。对于许多现实世界的任务，人工审批或指导是必需的，这使得“人在回路”的交互模式对于部署至关重要。
  2. Cloudflare Agents SDK 为代理提供了有状态的、无服务器的基础。 利用 Durable Objects，SDK 处理状态持久化、实时通信 (WebSockets) 和扩展，简化了构建代理的基础设施层。
  3. Knock 简化了跨渠道人工审批工作流程的编排。 Knock 的平台管理跨渠道的消息传递，并提供 webhook 来处理诸如审批等异步交互，将其路由回代理进程。
  4. 延迟工具调用使代理能够暂停等待人工输入并恢复。 Knock 和 Agents SDK 的结合使得代理能够触发外部审批流程并等待，一旦异步接收到必要的人工输入，即可恢复原始任务。
  5. 通过 Knock webhook 接收的异步审批响应可以恢复特定的代理状态。 当通过 Knock 收到人工输入时（例如，点击审批链接），webhook 会将此交互路由回正确的代理实例（由 Durable Object 支持），使代理能够恢复其延迟的工具调用并更新其状态。

💬 文章金句

  • 无论您的代理在决策方面有多优秀，您都需要一个人在其实现目标的路径上提供指导或输入。
  • 这就是“人在回路”的交互模式的作用所在。
  • 由于 Agents SDK 由 Durable Object 提供支持，我们可以免费获得这些好处，同时拥有一个具有内置存储的全球可寻址计算单元，它完全是无服务器的并且可以缩容到零。
  • Knock 的工作流程构建器和通知引擎为您提供了构建块，用于为您的代理创建复杂的跨渠道消息传递。
  • 使用 Agents SDK 和 Knock，可以轻松构建先进的、具有延迟工具调用能力的人在回路体验。
