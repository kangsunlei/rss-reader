GitHub 2025 年 7 月的可用性报告详细说明了一起由基础设施配置错误导致的 5.5 小时 GEI 中断事件，该事件需要用户使用新的范围更新 IP 白名单。

📝 详细摘要

本文是 GitHub 2025 年 7 月的可用性报告，详细说明了一起影响 GitHub 企业导入器 (GEI) 的重大事件。该事件发生在 2025 年 7 月 28 日，持续约五个半小时，在此期间 GEI 迁移处于降级状态。根本原因是 GEI 基础设施组件在例行内部改进期间被错误地停止服务，导致无法恢复到之前的配置，因此需要配置新的资源。问题解决后，GitHub 在基础设施恢复、单元测试和使用测试数据进行验证方面实施了改进。对用户来说，一个关键的结果是需要更新其 IP 白名单，以包括新的 GEI IP 范围 (20.99.172.64/28，135.234.59.224/28) 并删除旧的范围 (40.71.233.224/28，20.125.12.8/29)，这需要在 github.com 上的组织、Azure Blob 存储、亚马逊 S3 或 Azure DevOps 等各种平台上进行。受影响的用户已收到电子邮件通知，客户支持可用于解决与迁移相关的问题。

💡 主要观点

  1. 由于基础设施配置错误，GitHub 企业导入器经历了重大中断。 在例行维护期间，由于操作失误，一个 GEI 基础设施组件被意外停用，导致 5.5 小时的服务降级并阻止了迁移处理。
  2. GitHub 已经实施了内部改进，以防止类似事件发生。 事件发生后，GitHub 增强了基础设施恢复机制、单元测试和验证流程，以提高系统弹性和防止再次发生。
  3. 用户必须更新 IP 白名单才能继续使用 GEI 迁移功能。 该事件需要新的 GEI IP 范围；用户需要将这些范围添加到他们的白名单中，并删除已弃用的范围，以确保不间断的迁移服务。
