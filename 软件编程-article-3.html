在 Cloudflare 平台上构建垂直微前端

1/30/2026, 2:00:00 PM

📌 一句话摘要

Cloudflare 推出了一种利用 Workers、Service Bindings 和现代浏览器 API 的垂直微前端 (VMFE) 架构，在保持无缝的类 SPA 用户体验的同时，实现了团队自主性。

📝 详细摘要

文章详细介绍了 Cloudflare 新的垂直微前端架构模板，该模板允许组织按 URL 路径而非水平组件拆分大型应用。这种模式使独立团队能够拥有特定路由（如 /blog 或 /dash）的整个技术栈，包括框架选择和 CI/CD 流水线。实现方案利用了一个核心的 “Router” Worker，通过 Service Bindings 进行低延迟内部路由，并使用 HTMLRewriter 进行动态资源路径修正。为了确保高质量的用户体验，该系统集成了 CSS View Transitions 以消除导航闪烁，并利用 Speculation Rules API 实现近乎即时的文档预加载，从而有效地让多页面架构拥有单页面应用的感觉。

💡 主要观点

  1. 垂直微前端通过基于 URL 路径拆分应用，实现了全栈所有权。 与在单个页面上混合组件的水平微前端不同，垂直切片允许团队拥有特定路由从 UI 到 CI/CD 的一切，减少了跨团队的回归风险，并允许选择 Astro 或 React 等不同的框架。
  2. Cloudflare Service Bindings 是缝合独立 Workers 的高性能骨干。 核心 Router Worker 使用 Service Bindings 在内部调用子 Worker，而无需经过公共互联网。这种架构在保持每个微前端隔离性和独立部署能力的同时，实现了请求处理的集中化。
  3. HTMLRewriter 动态解决了资源代理和视觉连续性的技术挑战。 Router 使用 HTMLRewriter 为绝对资源 URL 添加路径前缀，并自动注入 CSS View Transitions 和 Speculation Rules，确保独立开发的服务在单一域名下运行时能够正常工作且感觉统一。
  4. 利用现代浏览器 API 弥合 MPA 和 SPA 之间的用户体验差距。 通过利用 CSS View Transitions 实现元素持久化的动画效果，以及利用 Speculation Rules 进行后台预取，该架构在保持多页面应用简单性的同时，提供了单页面应用的高性能和流畅度。

💬 文章金句

  • 垂直微前端采取了不同的方法，通过 URL 路径拆分应用……它们拥有该路由的整个垂直技术栈——框架、库选择、CI/CD 等。
  • 我们绝对不希望发生的是将我们的实现细节和内部决策泄露给用户。
  • 通过 View Transitions 和 Speculation Rules，我们能够将完全不同的代码库联系在一起，让它们感觉就像是从一个单页面应用中提供服务一样。
  • Router Worker 可以调用已定义的每个垂直微前端 Worker……这正是将这些垂直切片“缝合”在一起的机制。
  • 如果我们不能让这种用户体验感觉像是一个统一的前端，那么我们就对用户犯下了严重的失职。
