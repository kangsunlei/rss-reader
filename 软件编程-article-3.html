得物知识问答：复合检索 Agent 的系统设计实践

8/12/2026, 10:30:00 AM

📌 一句话摘要

得物技术复盘知识问答复合检索 Agent 的系统设计：基于 AgentScope 2.0 构建「搜索→评估→决策」自主闭环、三阶段检索质量 Pipeline 与生产级 SSE 断点续传，实现知识库与个人飞书数据融合的知识问答。

📝 详细摘要

本文是得物技术团队对知识问答系统「复合检索 Agent」的完整工程复盘。文章以 AgentScope 2.0 的 HarnessAgent 架构为底座，重点使用 ReAct 循环、Middleware 与并行工具调用三个能力，构建了「知识库 + 个人飞书数据」双通道的检索产品。核心设计是让 Agent 在「搜索→评估→决策」循环中拥有自主决策权：多源并行检索、自主判断信息充分性、通过精读全文/补充检索/交叉验证三种策略深挖，并按来源权威性分层整合。针对检索质量，团队在向量检索之上构建三阶段 Pipeline（FastPass → Reranker → LLM Grading），用自然语言句子做查询扩展并生成多角度变体，以 Middleware 方式在 onActing 钩子中拦截工具结果，做到与 Agent 核心逻辑解耦。文章还涵盖多模态图片提问、自动模型切换，以及生产级多实例 SSE 断点续传的三路径设计（同实例恢复、跨实例转发、快照重建），并对快照 vs 逐条重放、路由表 vs Redis Pub/Sub 等关键决策做了权衡说明。最后给出评测结果与框架选型对比，并展望了从知识问答向长期记忆个人知识助手的演进路径。

💡 主要观点

  1. 让 Agent 拥有自主决策权，而非固定检索路径。 传统 RAG 单向检索、Agent 被动接受；本方案基于 ReAct 循环实现「搜索→评估→决策」闭环，由 Agent 自行决定工具、次数与停止时机。
  2. 检索质量靠三阶段 Pipeline 层层过滤，而非单一 Reranker。 检索结果先经 FastPass 免检，再 Reranker 粗筛「词像但意思不对」的内容，最后由 LLM 精评相关性；每阶段独立可开关，过滤对 Agent 透明。
  3. 查询扩展用自然语言句子而非关键词，提升语义匹配。 Embedding 模型对完整句子的语义编码优于关键词；生成多个角度变体并行检索，可覆盖用户意图的不同侧面，提升召回率。
  4. SSE 断点续传采用快照加路由表方案，而非事件重放或 Pub/Sub。 Pub/Sub 订阅延迟会造成消息丢失；Redis 只存路由、跨实例内部转发，快照一帧恢复避免事件逐条重放带来的前端渲染抖动。
  5. 知识库与个人数据双通道融合，按来源权威性交叉验证。 知识库提供权威结构化知识基座，飞书个人数据补充实时上下文；冲突时按官方文档 > 飞书文档 > 消息/妙记排序，回答可追溯到 sourceId。

💬 文章金句

  • 从"搜到什么用什么"到"搜→筛→挖→验"自主决策闭环------我们造了一个有判断力的 RAG Agent，不是套壳。
  • RAG 系统的质量由两个指标决定：召回率------有没有把相关文档找出来；精准度------找出来的文档是不是真的相关。
  • 向量相似 ≠ 语义相关
  • 快照方案把所有这些事件折叠成一个完整的"当前状态"------就像游戏存档，一帧恢复。
  • 知识库提供权威性和结构化的知识基座，个人数据提供实时性和上下文关联的补全。
