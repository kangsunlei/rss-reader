大规模保护供应链安全：从 71 个重要的开源项目开始

8/11/2025, 4:00:00 PM

📌 一句话摘要

GitHub 的安全开源基金通过为关键开源项目的维护者提供资金、教育和安全工具，积极加强软件供应链安全。

📝 详细摘要

本文详细介绍了 GitHub 安全开源基金的影响性工作。该基金于 2024 年 11 月启动，旨在解决软件供应链中普遍存在的漏洞，例如 Log4j 事件。该基金为重要开源项目的维护者提供资金支持和一个为期三周的项目，内容涵盖安全教育、指导和工具。前两次会议初步结果显著，涉及 71 个项目的 125 名维护者参与，共修复了 1，100 多个 CodeQL 漏洞，发布了 50 多个新的 CVE，并防止了 92 起密钥泄露事件。该计划还加速了安全最佳实践的应用，80% 的项目启用了 GitHub 安全功能，63% 的项目对 AI 安全有了更好的理解。本文重点介绍了各种项目类别（包括 AI/ML 框架、前端库、Web 服务器、DevOps 工具、安全框架和开发者工具）的特定改进，展示了 Ollama、shadcn/ui 和 Log4j 等项目如何增强其安全状况。该倡议旨在培养维护者之间的安全文化，最终降低整个软件生态系统中的风险。

💡 主要观点

  1. GitHub 的安全开源基金显著增强了关键开源项目的安全态势。 该基金为维护者提供重要的资金支持、安全教育和工具，使他们能够主动识别和修复漏洞，从而保护软件供应链中的关键组件。
  2. 积极的安全措施和工具可显著降低整个软件生态系统中的风险。 早期成果表明了巨大的影响，包括修复数千个漏洞、发布新的 CVE 和防止密钥泄露，展示了结构化安全计划和 CodeQL 和 GitHub Copilot 等工具的有效性。
  3. 投资于基础开源项目的维护者可以加强整个软件生态系统。 通过支持 Node.js、Log4j、scikit-learn 等广泛使用的项目的维护者，该计划产生了连锁反应，从而提高了无数下游应用程序的安全性，并培养了更安全的发展文化。

💬 文章金句

  • 一个资金不足的库可能会给整个软件供应链带来冲击。
  • 由于安全开源基金，AI 智能体生态系统更加安全，并且将继续变得更加安全。
  • 安全已从被动要求转变为主动实践。
  • 无知是最大的安全漏洞。如果五年前存在这种培训，那么 Log4Shell 可能就不会出现在今天。
