“AI 即文本”的时代已经结束。执行是新的界面。

3/10/2026, 8:16:04 PM

📌 一句话摘要

GitHub 推出 Copilot SDK，将 AI 从基于文本的聊天界面转变为可编程的执行层，使开发者能够将智能体工作流直接嵌入到应用程序中。

📝 详细摘要

本文宣布推出 GitHub Copilot SDK，标志着从“AI 即文本”向“AI 即执行”的转变。文章认为，生产环境的软件需要的不仅仅是孤立的文本交互，更需要能够规划、调用工具并从错误中恢复的系统。通过提供可编程 SDK，GitHub 允许开发者将 Copilot CLI 中使用的经过生产验证的编排引擎嵌入到自己的应用中。文中概述了三种架构模式：通过意图而非固定脚本委托多步任务；使用模型上下文协议 (MCP) 将智能体置于结构化的运行时上下文中；以及将 AI 能力从 IDE 扩展到后台服务和 SaaS 平台。这一转变将 AI 定位为核心基础设施，而不仅仅是侧边栏助手。

💡 主要观点

  1. AI 正在从基于文本的界面演变为可编程的执行层。 新范式不再依赖手动的提示词-响应循环，而是专注于智能体执行，即 AI 在定义的约束范围内自主进行规划、使用工具并修改系统。
  2. 委托意图比硬编码固定自动化脚本更具韧性。 通过向智能体传递高层目标和约束，软件可以适应上下文变化并在运行中从错误中恢复，而无需开发者手动编写每一个边缘情况的代码。
  3. 通过 MCP 提供的结构化上下文优于将系统逻辑塞进提示词中。 使用模型上下文协议允许智能体在运行时直接查询服务归属和 API，确保执行的可靠性，并减少与冗长复杂的提示词相关的脆弱性。
  4. 智能体能力正在超越 IDE，进入通用的应用层。 Copilot SDK 实现了 AI 在后台服务、内部工具和 SaaS 平台中的执行，将 AI 从开发者的辅助工具转变为集成的应用基础设施。

💬 文章金句

  • “AI 即文本”的时代已经结束。执行是新的界面。
  • 与其维护自己的编排栈，不如将驱动 GitHub Copilot CLI 的、经过生产验证的规划和执行引擎直接嵌入到你的系统中。
  • 借助 Copilot SDK，你的应用程序可以委托意图，而不是编码固定的步骤。
  • 当执行被嵌入到你的应用程序中时，AI 不再是侧边窗口中的助手，而是成为了基础设施。
  • 如果你的应用程序可以触发逻辑，那么它现在就可以触发智能体执行。
