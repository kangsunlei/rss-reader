Uber Eats 如何去重数亿商品图片，优化存储与效率

8/5/2025, 3:30:44 PM

📌 一句话摘要

Uber Eats 通过内容寻址图像管道去重数亿商品图片，显著降低成本并提高效率。

📝 详细摘要

本文解释了 Uber Eats 如何在面对数亿张商品图片和每小时数百万次更新的挑战时，重新设计其图像管道，以解决冗余和低效问题。旧系统仅依赖 URL，重复处理相同的图像，且无法检测到稳定 URL 上的内容更改。新的内容寻址管道通过字节的加密哈希值识别图像，实现了基于内容的去重和智能缓存。它支持三个主要流程：服务缓存的已处理图像、处理新图像，以及按新规范重新处理已知图像，从而利用逻辑映射以及 Uber 的 Terrablob 和 Docstore。通过检查 HTTP Last-Modified 标头，该系统现在可以优雅地处理没有 URL 更改的图像更新。这种转变使得超过 99% 的请求无需重新处理即可完成，从而显著降低了基础设施成本和延迟，并增强了可靠性，所有这些都在两个月内部署完成。

💡 主要观点

  1. 依赖 URL 的传统图像管道导致大量重复操作和高运营成本。 旧系统无法识别不同 URL 上的相同图像，导致重复下载、处理和存储，显著增加基础设施费用。
  2. Uber Eats 实施内容寻址图像管道，使用加密哈希高效去重。 新系统通过哈希值识别图像字节内容，确保相同图像仅处理和存储一次，与源 URL 无关，从而显著提高效率。
  3. 新系统使用 HTTP Last-Modified 标头，优雅地处理稳定 URL 上的图像更新。 此机制允许商家在不更改 URL 的情况下更新图像内容，确保数据新鲜度并避免不必要的重新处理，是对旧系统的重要改进。

💬 文章金句

  • 每张图片都有成本：网络带宽、处理时间、存储空间和 CDN 占用空间。
  • 该系统现在不依赖于外部信号（如 URL 更改），而是使用内容寻址缓存。每个图像都通过其字节的加密哈希值来识别。
  • 现在超过 99% 的请求无需重新处理图像即可完成。这对于性能和效率来说是一个明显的胜利。
  • 新的架构在不到两个月的时间内部署完成，但支持 Uber Eats 的最高流量数据路径之一。
