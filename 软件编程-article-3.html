Kraken 的 Serverless 架构：守护绿色电网

1/23/2026, 3:15:00 PM

📌 一句话摘要

Kraken Technology 利用 AWS 上的云原生 Serverless 架构来管理大规模电池储能，从而平衡英国电网中可再生能源固有的不可预测性。

📝 详细摘要

这份技术演讲详细介绍了 Octopus Energy 旗下的 Kraken Technology 如何利用 Serverless 架构将可再生能源整合到英国电网中。其核心挑战在于应对风能和太阳能的波动性，这需要复杂的电池储能管理来将电网频率维持在 50Hz。作者描述了一个基于 AWS Lambda、EventBridge 和 DynamoDB 构建的微服务系统。关键组件包括一个通过 MQTT 处理数千个数据点的遥测系统、一个使用线性规划进行 24 小时预先规划的优化器，以及一个与国家能源系统运营商（NESO）对接的市场连接器。该架构强调异步解耦、事件驱动处理和“触发器-动作”Lambda 模式，以确保在没有传统基础设施管理开销的情况下实现可扩展性和可靠性。

💡 主要观点

  1. 利用 Serverless 托管服务，将重心从基础设施转向业务价值。 通过采用 AWS Lambda 和 DynamoDB，团队避免了“重新发明轮子”，从而专注于能源优化的“核心魔力”，而不是管理虚拟机或数据库维护。
  2. 为异步 Lambda 处理实现“触发器-动作”模式。 通过队列将刺激（触发器）与逻辑（动作）解耦，实现了独立扩展、通过死信队列实现更好的错误处理，并提升了系统韧性。
  3. 通过高速自动化交易和电池控制管理电网稳定性。 系统实时监控电网频率，并控制电池逆变器进行充电或放电，从而在可再生能源供应波动或电网跳闸时防止停电。
  4. 针对遥测数据采用多模型存储策略。 遥测数据存储在 Redis 中用于低延迟的“最新值”查询，存储在 InfluxDB 中用于时序分析，存储在 S3 中用于长期存档，从而针对不同的消费者需求进行优化。

💬 文章金句

  • 我们需要站在巨人的肩膀上，避免为了重新发明而重新发明。
  • 当时电网频率降至危险的低位……一大批电池突然间几乎是瞬间跃升至全功率运行。
  • 我们在云端使用 Serverless 托管服务，并将精力集中在这些服务之上我们所能创造的价值上。
  • 人类仍然对最终的软件负责……LLM 是为了加速我的工作，而不是取代我的判断。
  • 我们没有直接暴露 Redis，而是通过一个由 Lambda 驱动的 API 来提供服务……这样我们可以在必要时更换后端数据存储，而无需协调变更。
