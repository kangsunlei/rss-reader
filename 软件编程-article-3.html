Slack：基于 AI 的 Enzyme 到 React Testing Library 大规模迁移混合方案

9/2/2025, 4:03:00 PM

📌 一句话摘要

Slack 通过结合 AI、AST 和 LLM 的创新混合方法，成功将 15，500 个 Enzyme 测试迁移到 React Testing Library，从而节省了大量的工程时间。

📝 详细摘要

本文详细介绍了 Slack 成功地将 15，500 个基于 Enzyme 的 React 测试大规模迁移到 React Testing Library (RTL)，这是升级到 React 18 的关键一步。面对手动转换估计需要 10，000 多个工程小时，该团队探索了各种自动化策略。由于 JavaScript/TypeScript 的复杂性、Enzyme 庞大的 API 以及 Enzyme（实现细节）和 RTL（用户行为）之间根本的理念差异，使用传统抽象语法树 (AST) 代码修改器 (AST codemod) 的初步尝试仅产生了 45% 的成功率。纯 LLM (Claude 2.1) 方法也显示出不一致的结果（40-60% 的成功率）。突破来自于一种模仿人类理解的 AI 驱动混合管道。这包括收集全面的上下文，包括每个测试用例的 DOM 树（RTL 必不可少），使用可靠的 AST 规则部分转换代码，然后利用 LLM 进行剩余的复杂转换，并基于测试失败进行动态反馈循环和提示词工程。这种创新方法显著加速了迁移，最终在一个季度内转换了所有剩余的 8，000 个测试，展示了 LLM 在复杂代码转换中的强大实际应用。文章还涉及一种独特的工作负载分配策略，以调动 150 多名开发人员的积极性。

💡 主要观点

  1. 大规模代码迁移带来了重大挑战，需要超越传统自动化的创新解决方案。 Slack 的 15，500 个测试迁移突显了手动和仅 AST 方法在复杂转换中的局限性，强调需要先进的方法来克服测试框架在设计理念上的差异。
  2. 结合 AST 和 LLM 的混合方法，以人类理解为基础，对于复杂的代码转换非常有效。 通过集成 AST 进行可靠的转换，并集成具备丰富上下文（如 DOM 树和测试反馈）的 LLM 来处理复杂的逻辑，Slack 实现了接近 100% 的成功率，展示了卓越的自动化。
  3. 利用 LLM 进行代码生成需要全面的上下文和动态反馈循环才能实现高精度。 Slack 的 AI 管道的成功取决于为 LLM 提供 DOM 树，并使用测试结果来动态优化提示，从而显著提高了转换质量，超越了基本的 LLM 或 AST 能力。
  4. 绕过传统层级的战略性工作负载分配可以激励开发人员并加速大规模的组织变革。 将小型、可管理的测试转换配额直接分配给活跃的开发人员，培养了集体责任感和参与度，有效地克服了对这项被认为“枯燥”但至关重要的任务的抵触情绪。
