📌 一句话摘要

本文详细记录了从零构建 Coding Agent「Violin」的全过程，涵盖三层架构设计、Zig+Python 技术选型、Agent Loop 核心循环、模型适配、工具系统、会话与压缩管理、Lua 插件机制及 C/S 网络协议，是一份极具工程参考价值的 AI Agent 全栈实战教程。

📝 详细摘要

文章由得物技术团队发布，作者酒米分享了自研 Coding Agent Violin 的完整构建过程。Violin 架构借鉴了开源项目 Pi 的三层分离设计（模型适配层、内核层、产品层），核心引擎用 Zig 实现追求性能与内存安全，客户端用 Python 快速构建 TUI，两者通过 TCP + JSON Lines 通信。 文章深度拆解了七大核心模块： 1. **Agent Loop**：核心 while 循环，处理「问模型→执行工具→回写结果」流程，含 max_turns 保护与错误重试分类。 2. **模型适配层**：统一 OpenAI 与 Anthropic 协议差异，封装为统一 `Model.complete()` 接口，支持 SSE 流式输出。 3. **工具系统**：内置 6 种基础工具，通过注册表管理，向模型暴露 JSON Schema。 4. **产品层**：`agent.zig` 作为胶水层协调会话加载、循环执行、上下文溢出压缩重试与持久化；`session.zig` 采用 JSONL 树形存储支持分支回滚；`compaction.zig` 实现基于字符数估算的上下文压缩策略。 5. **资源加载**：解析 AGENTS.md/CLAUDE.md 与 SKILL.md 注入 System Prompt，赋予 Agent 项目规则与技能。 6. **事件系统与 Lua 插件**：EventBus 驱动插件，支持拦截工具调用、修改上下文、阻止启动等 Hook，选型 Lua 因其极小运行时与成熟嵌入生态。 7. **网络层**：C/S 架构设计，定义握手、聊天、工具调用等核心协议，便于多语言客户端接入。 全文贯穿大量伪代码与实现细节，诚实记录工程权衡（如 Token 估算近似、Zig 多态实现、为何不选 WASM/ACP），是难得的 AI Agent 工程化原创实践分享。

💡 主要观点

  1. 三层分离架构是现代 Coding Agent 的核心设计模式。 借鉴 Pi 设计，将模型适配、Agent 核心循环、产品能力（会话、压缩、资源）解耦，各层单一职责、松耦合，便于替换模型、扩展工具、多语言协作。
  2. Zig + Python 组合在「引擎+界面」分工上极具性价比。 Zig 提供内存安全、无运行时、C 互操作优势，适合写高性能 Agent 后端；Python 生态丰富，适合快速构建 TUI 客户端。TCP + JSON Lines 协议使两端完全解耦。
  3. Agent Loop 只是起点，产品层才是落地的关键。 循环之外的会话持久化（JSONL 树形结构）、上下文压缩（摘要+保留最近 N 条）、资源加载（规则与技能注入）、错误重试分类，构成了可用工程产品的骨架。
  4. Lua 是嵌入式插件系统的最优解之一。 500KB 运行时、C API 简洁、20 年嵌入验证（WoW/Redis/Nginx），配合 EventBus 实现工具拦截、上下文注入、启动阻断等动态能力，避免了 WASM 等方案的重量级依赖。
  5. 工程权衡比技术选型更值得学习。 文中大量展示取舍理由：Token 估算用字符数/4 而非引入 Tokenizer；Zig 用函数指针表实现多态；协议选简易 TCP 而非 ACP；压缩摘要由 LLM 生成而非本地算法。这些决策体现了工程落地的务实视角。

💬 文章金句

  • 理解了 coding agent 的构建原理，也就掌握了理解其他 agent 的一把钥匙。

  • 写一个 Agent Loop 不难，难的是把它变成每天能用的开发工具。
  • 最终我选了 Lua。不是因为 Lua 是最好的语言，而是因为它是最小的对的那一个。
