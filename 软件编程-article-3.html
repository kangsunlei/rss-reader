Git 2.51 的亮点

8/18/2025, 5:04:36 PM

📌 一句话摘要

本文重点介绍了 Git 2.51 的主要特性，包括通过无冗余多包索引和路径遍历实现的性能优化、增强的暂存管理以及其他重大更新。

📝 详细摘要

本文深入探讨了 Git 2.51 中引入的最具影响力的特性和更改。首先详细介绍了新的“无冗余多包索引 (MIDXs)”，解释了 Git 现在如何智能地存储对象副本以确保非冗余包是自包含的，从而减少 MIDXs 的大小、加快写入操作并提高存储库读取性能，并引用了 GitHub 自身 38% 的 MIDX 大小减少。接下来，它介绍了“基于路径遍历的更小包”，这是一种新颖的重新打包方法，通过根据文件路径对对象进行分组来优化增量压缩，从而显著减少包文件的大小。一个主要的工作流改进是新的“暂存交换格式”，它将暂存条目转换为一系列提交，从而可以跨不同的机器无缝导出和导入暂存。除了这些核心特性之外，Git 2.51 还增强了 `git cat-file` 以获得更好的子模块信息，扩展了对具有多个路径规格的 `git log` 的 Bloom 过滤器支持，`git switch` 和 `git restore` 不再处于实验状态，并且弃用了 `git whatchanged`。文章最后预览了 Git 3.0 未来的默认设置（引用表和 SHA-256），并更新了 Git 的内部开发流程，例如 C99 特性采用和修订后的补丁提交指南。

💡 主要观点

  1. 无冗余多包索引显着优化了 Git 存储库的性能和大小。 通过确保非冗余包在可达性下关闭，Git 2.51 减少了 MIDX 大小、写入时间，并提高了整体存储库读取性能，正如 GitHub 自己的单体仓库指标所证明的那样。
  2. “路径遍历”方法通过改进的增量压缩提高了 Git 的包文件效率。 这种新的对象收集策略在重新打包期间按文件路径对对象进行分组，从而实现更有效的增量压缩，并显着减少包文件的大小。
  3. Git 的新暂存交换格式简化了机器之间暂存的迁移。 暂存条目现在可以表示为提交日志，允许将它们轻松导出到引用，然后像普通分支一样推送或拉取，从而简化了跨机器工作流。

💬 文章金句

  • Git 2.51 变更了存储库中非冗余部分的打包方式。
  • 在 GitHub 上使用它使我们能够编写更小的 MIDX，花费的时间更少，并最终提高了整体存储库读取性能。
  • Git 2.51 延续了这一改进思路，通过引入一种新的对象收集方式，即“路径遍历”，实现了进一步优化。
  • 因此，您现在可以将暂存导出到单个引用，然后像对待普通分支或标记一样推送或拉取它。
  • 六年之后，这些命令已不再处于实验阶段，其命令行界面在未来的版本中将保持稳定并提供向后兼容性。
