更智能地测试：在复杂分布式系统中构建信心

📝 详细摘要

本文整理自 Elias Nogueira 的演讲，深入探讨了构建在微服务架构上的复杂分布式银行系统中的关键测试挑战。它指出了关键障碍，例如使用真实依赖项进行测试、支持各种数据库、有效模拟外部服务以及处理异步请求。Nogueira 主要关注两个领域：实现多数据库支持和管理脆弱的第三方依赖项。对于前者，他提出了一种并行测试策略，该策略利用 Testcontainers 来配置真实数据库实例（例如，MySQL 、MSSQL ）以进行集成测试，并通过 Spring Profiles 进行配置。这种方法确保测试在类似生产的环境中运行，有效避免内存数据库的局限性。他演示了如何使用 GitHub Actions 的矩阵功能实现并行执行，从而显著减少 CI 反馈时间。本文还介绍了脆弱的第三方依赖项的问题，其中内部模拟通常在团队之间重复，从而导致维护开销、不稳定性和缓慢的测试。讨论强调了强大的集成测试、并行执行和容器化的重要性，以提升分布式系统的可靠性，尽管提供的文本中第三方依赖项的解决方案并不完整。

💡 主要观点

  1. 使用真实数据库的并行集成测试对于复杂的分布式系统至关重要。 内存数据库通常无法复制生产问题，并且对多个配置进行顺序测试的速度非常慢。通过真实数据库进行并行测试，可获得更快、更可靠的反馈。
  2. Testcontainers 简化了在隔离环境中针对实际依赖项运行集成测试的过程。 Testcontainers 允许开发人员以编程方式管理 Docker 容器，以用于真实数据库实例或其他服务，从而直接在测试中模拟生产设置，而无需复杂的本地安装。
  3. CI / CD 平台，尤其是 GitHub Actions ，有助于高效的并行测试执行。 利用 GitHub Actions 中的矩阵构建等功能可以跨各种配置（例如，多个数据库）并发执行测试，从而大大缩短了整体测试反馈周期。
  4. 管理脆弱的第三方依赖项需要一种超越基本内部模拟的强大策略。 依赖共享的外部服务进行测试可能会导致不稳定和缓慢，而各团队维护的模拟通常会导致大型组织中的重复和维护难题。

💬 文章金句

  • Testcontainers 是一个容器，它为不同的应用程序提供容器，并且它们实际上可以模拟真实的依赖关系。
  • 并行执行是当今的必须，因为我们想了解我们的测试是否失败，我们的应用程序是否足够可靠以进行下一步，或者部署到生产环境，或者只是等待单击以部署到生产环境。
  • 使用容器，特别是使用 Testcontainers ，你们可以使用 Podman ，无论如何，它都会使您更接近使用该数据库或那里的那些依赖项进行生产。
  • 通常，内部集成测试中的模拟方法存在问题……根据我的经验，效果并不理想。
