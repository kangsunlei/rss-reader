OAuth 2.0 Git 凭证支持服务主体身份已正式发布

6/18/2025, 5:55:55 PM

📌 一句话摘要

Databricks 增加 OAuth 2.0 Git 凭证对 GitHub 和 Azure DevOps 服务主体身份的支持，显著提升自动化工作流程的安全性。

📝 详细摘要

Databricks 宣布正式发布 OAuth Git 凭证对服务主体身份的支持，建议使用 OAuth 凭证替代个人访问令牌 (PAT)，以提升 GitHub 和 Azure DevOps 自动化工作流程的安全性。本文重点阐述了 PAT 的局限性，包括生命周期长、存储不安全、范围广泛以及某些提供商中缺乏服务主体支持。相反，OAuth 提供自动刷新的短期令牌、精细的范围控制以及改进的管理控制。该实现利用 OIDC (OpenID Connect) 用于 Azure DevOps，从而显著简化了连接过程。与传统的 PAT 相比，此功能为 CI/CD 管道和其他自动化任务中的 Git 身份验证提供了一种更安全、更可靠的方法。

💡 主要观点

  1. 用于服务主体的 OAuth Git 凭证现已在 Databricks 上正式发布，支持 GitHub/Azure DevOps。 此功能为服务主体通过 Databricks 与 Git 仓库交互提供了一种更安全、更可自动化的方式。
  2. 对于自动化，传统的 PAT 具有重大的安全性和运维缺点。 诸如生命周期长、处理不安全、范围广泛以及缺少服务主体兼容性等问题使得 PAT 不太适合强大的自动化工作流程。
  3. OAuth 提供了比 PAT 更强的安全性、可靠性和管理控制。 优势包括自动刷新短期令牌、仓库特定的访问控制以及更好的管理员可见性，从而降低了风险和手动工作量。
  4. Databricks 通过 OIDC 简化了 Azure DevOps 服务主体的连接流程。 集成 OIDC 简化了身份验证过程，从而可以更快、更安全地使用 Azure DevOps 服务主体设置 CI/CD 管道。

💬 文章金句

  • 我们现在将此建议扩展到 Databricks Git 凭证，并鼓励在使用 Git 提供商进行身份验证时，使用 OAuth 代替 Git 提供商的 PAT。
  • OAuth Git 凭证支持 GitHub 和 Azure DevOps 的服务主体，从而提高了自动化工作负载的 Git 连接安全性。
  • PAT 的访问时长（几周 / 几个月）远长于短期令牌（几小时 / 几天）。
  • OAuth 令牌默认情况下会自动刷新。当用户的 PAT 令牌过期时，用户不再遇到错误。
  • OAuth 允许您配置对特定 GitHub 仓库的访问。
