📌 一句话摘要

Scale to Win 阐述了其利用 AWS WAF、CloudFront 和 Shield Advanced 构建的综合 DDoS 防护体系，着重介绍了架构优化与高级规则配置。

📝 详细摘要

本文由 Scale to Win 联合撰写，概述了他们在 2024 年美国总统竞选期间经历的大规模 DDoS 攻击的强大防御措施。面对每秒超过 200 万次请求的峰值，他们与 AWS 合作实施了 AWS Web 应用程序防火墙 (AWS WAF)、AWS Shield Advanced 和 Amazon CloudFront。核心策略在于通过 CloudFront 重新路由流量，以提升容量和边缘防护能力，并通过安全组和共享密钥机制，阻止直接访问应用负载均衡器 (ALB)，确保安全性。本文详细阐述了如何使用启发式和硬限制方法配置 AWS WAF 规则，强调了人工和机器流量的关键分段。它提供了关于为基于浏览器的用户应用不同速率限制和全自动区分计算机和人类的图灵测试 (CAPTCHA) 挑战，以及应用程序编程接口 (API) 和 webhook 流量的特定验证方法的详细指导。最后，它讨论了高级安全措施，例如用于单页应用程序 (SPA) 的客户端 CAPTCHA 处理以及使用 AWS WAF 机器人控制防止 CAPTCHA 令牌重用。

💡 主要观点

  1. 利用 CloudFront 作为主要防御层可显著增强 DDoS 防护能力和基于边缘的 WAF 部署。 通过 CloudFront 在应用负载均衡器 (ALB) 前端路由流量，能够提供更大的网络层容量，并使 AWS WAF 在边缘节点以更高配额运行，从而提升整体 DDoS 防护能力。
  2. 对人工和机器流量进行分段可以实现定制的 AWS WAF 规则，从而优化保护，而不会中断合法的大容量 API 调用。 通过根据请求路径区分流量类型，组织可以应用特定的速率限制、互联网协议 (IP) 集验证或 CAPTCHA 挑战，从而确保各种应用程序交互的有效安全性。
  3. 高级 CAPTCHA 处理和令牌重用防范机制，是有效防御复杂僵尸网络攻击的关键。 为单页应用程序 (SPA) 实施客户端 CAPTCHA 逻辑并利用 AWS WAF 机器人控制来阻止分布式 CAPTCHA 令牌重用，从而增加了针对自适应威胁参与者的关键防御层。
  4. DDoS 防御需要持续的自适应策略，需要不断监控和改进规则以应对不断变化的威胁参与者策略。 启发式方法以及不断调整规则以应对不断演变的攻击模式的需求突出表明，DDoS 缓解不是一次性设置，而是适应和响应的持续过程。

💬 文章金句

  • 在 2024 年美国总统竞选季期间，我们成为了分布式拒绝服务 (DDoS) 事件的目标。这些事件达到了每秒超过 200 万次请求的峰值，来自近一万个唯一的 IP。
  • 使用 AWS WAF 防御 DDoS 事件的推荐模式是改为通过 CloudFront 分配路由流量。
  • 为了防止威胁参与者绕过我们的 CloudFront 分配和 AWS WAF，我们实施了一个安全组，该安全组仅允许来自 CloudFront 边缘 IP 地址的流量，并使用托管前缀列表来防止直接连接到应用负载均衡器 (ALB)。
  • 我们构建 AWS WAF 规则以对人工和机器流量进行分段。我们通过请求路径来做到这一点。
  • 虽然 AWS WAF 提供了内置的 CAPTCHA 功能，但需要额外的安全措施来防止令牌重用事件。
