或许你也有多 Gradle 项目多 JDK 要求混用的痛点？不妨试试我这个 patch project， gradlew-jdk-local

6/16/2026, 4:57:01 PM

📌 一句话摘要

本文介绍了一个名为 gradlew-jdk-local 的 Gradle 补丁项目，用于解决在命令行或 AI Agent 编程环境下，不同 Android 项目因维护周期不同而需要混用多个 JDK 版本的痛点。

📝 详细摘要

作者分享了在工作和兴趣中维护多个 Android 项目时遇到的 JDK 版本管理痛点。这些项目因迭代维护时间不同，依赖的 JDK 版本各异。在 Android Studio 中，可以通过私有配置指定 JDK 路径，不影响团队。但在纯命令行环境，尤其是使用 AI Agent 编程时，手动注入 JDK 环境变量或让 Agent 自行尝试都效率低下。为此，作者研究并开发了 gradlew-jdk-local 这个补丁项目，旨在填补 Android Studio 私有配置与 Gradle 官方方案之间的空白，简化多项目多 JDK 混用的流程，并节省 AI Agent 的 token 消耗。

💡 主要观点

  1. 多 Android 项目因迭代周期不同，常需混用多个 JDK 版本。 不同项目基于不同时期的 Gradle 或 Android SDK 构建，对 JDK 版本有特定要求，手动管理环境变量在命令行下非常繁琐。
  2. 现有方案在命令行和 AI Agent 场景下存在空白。 Android Studio 有私有 JDK 配置，Gradle 官方方案不完善，导致纯命令行或 AI Agent 编程时，JDK 版本管理成为痛点。
  3. gradlew-jdk-local 补丁项目旨在简化多 JDK 混用流程。 该项目通过补丁方式，让 Gradle 能根据项目自动选择正确的本地 JDK，无需手动干预，尤其适合 AI Agent 自动化构建场景。

💬 文章金句

  • 之前手工编程都用 AS 打开还好，AS 会提示让指定一个 JDK ，并且这个 JDK Path 也不会影响到团队其他同事的使用。
  • 但现在大部分情形下 Agent 编程了，纯命令行跑的时候就麻烦了，要么就给 Agent 强调编译时要注入什么版本的 JDK 环境变量，要么就得让 Agent 自己试，多不环保啊
