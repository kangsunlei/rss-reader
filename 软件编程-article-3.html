QCon London 2026：引入 Tansu.io — 重新思考 Kafka 的精简运营

3/21/2026, 10:01:00 AM

📌 一句话摘要

Tansu.io 是一个开源的、无状态的 Kafka 兼容消息代理，将持久化委托给 S3 或 Postgres 等外部存储，支持 scale-to-zero 操作，简化事件驱动架构。

📝 详细摘要

本文介绍了 Tansu，这是一款革命性的 Kafka 兼容消息代理，专为精简运营而设计。与传统 Kafka 依赖复杂的代理端复制和状态管理不同，Tansu 将代理视为无状态的「 cattle 」。通过将数据持久化委托给 S3、SQLite 或 Postgres 等弹性外部后端，Tansu 实现了仅 20MB 的极小内存占用，并且可以在 10 毫秒内从零扩展到活跃状态。主要特性包括：通过 COPY 协议实现高吞吐量 Postgres 集成、强制在代理端进行模式验证（Avro/JSON/Protobuf），以及直接将数据流式传输到 Apache Iceberg 或 Delta Lake 等开放表格式，有效消除了复杂 ETL 管道和事务发件箱模式的需求。

💡 主要观点

  1. Tansu 通过将持久化委托给外部存储，重新定义了代理为无状态实体。 通过移除内部复制和领导者选举，Tansu 将代理视为「 cattle 」而非「 pets 」，实现了极致的运营简化，并能够在 Fly.io 等平台上实现零扩展。
  2. 深度 Postgres 集成消除了对传统事务发件箱模式的需求。 使用 Postgres 作为后端允许开发者在单个事务中原子性地更新业务数据和队列消息，而 COPY FROM 协议确保高吞吐量摄入，无需逐个确认。
  3. 强制代理端模式验证确保所有生产客户端的数据一致性。 与 Kafka 可选的客户端注册表不同，Tansu 在代理级别对每条记录进行 Avro、JSON 或 Protobuf 模式验证，在数据写入存储之前就拒绝无效数据。
  4. 与开放表格式的直接集成简化了从消息传递到分析的数据路径。 Tansu 可以自动将验证后的 Protobuf 或 Avro 记录转换为 Apache Iceberg 或 Delta Lake 的 Parquet 文件，为分析就绪数据创建直接管道，无需中间 ETL 步骤。

💬 文章金句

  • 如果你保留 Kafka 的协议，但抛弃其他一切呢？抛弃复制、领导者选举、代理的永久状态，用无状态代理取而代之？
  • Kafka 代理是 Morgan 所说的『 pets 』…… Tansu 代理是『 cattle 』。它们不携带状态，没有领导者，只占用约 20MB 的常驻内存。
  • 事务发件箱模式完全消失了：你可以在同一个数据库事务中使用存储过程原子性地更新业务数据和队列消息。
  • 无效数据在代理端被拒绝，而不是客户端。这是一个刻意权衡……但它保证了无论哪个客户端生产数据，都能实现数据一致性。
  • 『 sink topic 』配置完全跳过普通存储，仅写入开放表格式，使 Tansu 成为分析就绪数据的直接管道。
