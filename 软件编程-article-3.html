Robert Nishihara：基于 Kubernetes、Ray、PyTorch 和 vLLM 的开源 AI 计算方案

11/28/2025, 6:15:00 PM

📌 一句话摘要

本文介绍了利用 Kubernetes、Ray、PyTorch 和 vLLM 构建的开源 AI 计算堆栈，旨在有效管理复杂且不断发展的人工智能工作负载，覆盖从数据处理到模型服务的各个环节。

📝 详细摘要

本文总结了 Robert Nishihara 在 KubeCon 上的演讲，详细介绍了一个使用 Kubernetes、PyTorch、vLLM 和 Ray 构建的开源人工智能（AI）计算堆栈，以应对日益复杂的人工智能工作负载。文章强调 Ray 是一个用于扩展机器学习（ML）和 Python 应用程序的关键框架，并强调了它最近集成到 PyTorch 基金会（PyTorch Foundation）中。Nishihara 确定了推动人工智能工作负载发展的三个关键领域：数据处理（Data processing，转向多模态数据和 GPU 推理）、模型训练（Model training，利用强化学习和 Ray 的 Actor API）和模型服务（Model serving）。他解释了 Ray 如何编排分布式工作负载，包括其用于 GPU 对象传输的原生 RDMA (Remote Direct Memory Access) 支持。本文还描述了 Kubernetes 和 Ray 之间的互补关系，从而实现了强大的隔离、自动缩放以及训练和推理之间高效的 GPU 资源分配。最后，它概述了现代人工智能平台的基本要求，例如多云（Multi-cloud）支持、工作负载优先级排序、可观察性（Observability）和数据血缘追踪（Data Lineage Tracking）。

💡 主要观点

  1. 人工智能工作负载正在发展，需要在数据处理、模型训练和服务方面进行调整。 数据处理现在需要多模态数据集和 GPU 加速的推理，这是从传统的基于 CPU 的 SQL 操作的重大转变，影响了人工智能应用程序的构建和部署方式。
  2. Ray 是用于编排和扩展分布式人工智能工作负载的关键开源框架。 Ray 促进了 ML/Python 应用程序的构建和扩展，提供了诸如用于训练组件的 Actor API 以及用于高性能 GPU 对象传输的原生 RDMA (Remote Direct Memory Access) 支持等功能，从而将应用程序连接到硬件。
  3. Kubernetes 和 Ray 为强大的人工智能应用程序托管和资源管理提供了协同解决方案。 它们共同扩展了隔离，提供了垂直和水平自动缩放，并实现了在计算密集型的推理和训练阶段之间高效的 GPU 资源转移，从而优化了基础设施利用率。
  4. 现代人工智能平台需要多云、优先级排序和治理的综合能力。 核心要求包括原生多云体验、基于 GPU 预留的工作负载优先级排序、强大的可观察性（Observability）、模型和数据血缘追踪（Data Lineage Tracking）以及生产环境部署的整体治理方案。

💬 文章金句

  • 人工智能工作负载在计算和数据方面变得越来越复杂，而像 Kubernetes 和 PyTorch 这样的技术可以帮助构建生产就绪的人工智能系统来支持它们。
  • 数据处理已从 ‘CPU 上的 SQL 操作’ 转变为 ‘GPU 上的推理’ 。
  • Kubernetes 和 Ray 相互补充，用于托管人工智能应用程序，通过进程级隔离扩展容器级隔离，并提供垂直和水平自动缩放。
  • Nishihara 强调了人工智能平台的核心要求，这些平台必须支持原生多云体验、跨 GPU 预留的工作负载优先级排序、可观察性（Observability）和相关工具、模型和数据血缘追踪（Data Lineage Tracking）以及整体治理。
