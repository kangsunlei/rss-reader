通过主机名连接并保护任何私有或公共应用——Cloudflare One 全员免费

9/18/2025, 2:00:00 PM

📌 一句话摘要

Cloudflare Tunnel 现已支持基于主机名的路由，无需依赖不稳定的 IP 地址，即可在 Cloudflare One 中实现零信任和出站流量策略。

📝 详细摘要

本文介绍 Cloudflare Tunnel 在 Cloudflare One SASE 平台中新增的基于主机名的路由功能，旨在解决现代动态云环境中基于 IP 的安全策略所固有的脆弱性和管理开销。文章提倡采用基于资源授权的零信任模型，根据稳定的主机名（而非临时的 IP 地址或宽泛的网络分段）授予访问权限。本文详细阐述了两个主要用例：利用精细的访问策略保护内部私有应用，以及控制需要专用源 IP 的第三方服务的出站流量。文章深入探讨了“合成 IP”机制，即 Cloudflare Gateway 拦截 DNS 查询以标记流量，从而实现基于第七层主机名的第四层路由决策。此外，文章还介绍了使用网关解析器策略实现复杂网络拓扑的高级场景。此功能显著简化了网络安全管理，并提高了零信任部署的精确性。

💡 主要观点

  1. 基于主机名的路由通过消除对不稳定 IP 的依赖，简化了零信任策略的应用。 动态云 IP 使传统的基于 IP 的安全性变得脆弱；主机名路由支持稳定、细粒度的基于每个资源的授权，并符合零信任原则。
  2. Cloudflare 的“合成 IP”机制支持基于第七层主机名的第四层路由决策。 通过拦截 DNS 查询并分配临时合成 IP，网关可以在第七层数据（主机名）可用之前，将流量路由到正确的通道。
  3. 该功能显著简化了对私有应用的访问管理，并保障出站流量的安全。 该功能无需使用复杂且容易出错的 IP 列表，管理员可以使用稳定的主机名为内部和第三方服务定义精确的访问和出站策略。

💬 文章金句

  • 连接到应用应该像知道它的名称一样简单。然而，许多安全模型仍然迫使我们依赖脆弱、不断变化的 IP 地址。
  • 基于每个资源的授权要求在每个资源的基础上配置访问策略。通过应用最小权限原则，您只允许用户访问他们绝对需要完成工作的资源。
  • 幸运的是，基于主机名的路由使这种 IP 列表变通方法变得过时。
  • Cloudflare Gateway 必须在收到连接中的第一个 IP 数据包时，就决定将流量发送到哪个 Cloudflare Tunnel，因为这意味着必须在第四层做出决定，而在第四层，网关只能看到数据包的 IP 和 TCP/UDP 标头。
  • 解决方案在于 Cloudflare Gateway 也充当 DNS 解析器。这意味着我们在看到实际的应用流量*之前*，就看到了用户的*意图*——对主机名的 DNS 查询。
