使用 R2 Local Uploads 提升全球上传性能

2/3/2026, 2:00:00 PM

📌 一句话摘要

Cloudflare R2 推出 “Local Uploads” 功能，通过先将数据存储在客户端附近并进行异步复制来优化全球写入性能，将延迟降低高达 75%。

📝 详细摘要

本文详细介绍了 Cloudflare R2 Local Uploads 的公开测试版发布，该功能旨在解决全球对象存储中固有的延迟问题。传统上，上传必须传输到存储桶的主区域，这会导致远程用户出现显著延迟。Local Uploads 允许将数据写入靠近客户端的存储位置并立即确认，从而确保强一致性和即时可访问性。文章解释了其底层架构，包括 Gateway Workers、用于元数据的 Durable Objects，以及使用 Cloudflare Queues 的基于拉取的复制模型。基准测试显示，跨区域上传的最后一字节时间 (TTLB) 减少了 75%，使其成为全球分布式应用的理想选择。

💡 主要观点

  1. Local Uploads 将初始写入与最终存储位置解耦，以最大限度地减少全球延迟。 通过先写入本地存储节点并异步复制到存储桶的主区域，R2 在保持数据即时可访问性的同时，减少了全球用户的往返时间。
  2. 综合基准测试表明，跨区域任务的上传请求时长显著减少了 75%。 涉及从北美上传到亚太地区存储桶的测试显示，TTLB 中位数从 2 秒降至 500 毫秒，突显了对全球用户体验的影响。
  3. 系统利用原子元数据更新过程来可靠且一致地管理复制任务。 当对象上传时，R2 会同时存储元数据、创建待处理副本密钥并设置任务标记，确保后台复制得到跟踪并最终完成，且不会丢失数据。
  4. 使用 Cloudflare Queues 的基于拉取的复制模型确保了系统的稳定性和高效的数据移动。 集中式轮询服务从区域队列中消费任务并将其分发给 Gateway Workers，允许系统根据实时系统健康状况和网络成本调整复制速度。

💬 文章金句

  • 启用 Local Uploads 后，对象数据会自动先写入靠近客户端的存储位置，然后异步复制到存储桶所在的区域。
  • 在我们的综合基准测试中，当上传请求发生在与存储桶不同的区域时，我们观察到最后一字节时间 (TTLB) 减少了高达 75%。
  • 重要的是，对象在初始写入完成后即可立即访问……在读取对象之前，无需等待后台复制完成。
  • 我们通过先在目标存储桶区域创建一个副本，然后使用此本地副本创建其他副本，从而最大限度地减少跨区域数据移动的次数。
