Amper 2025 年 10 月更新：Compose 热重载与用户体验提升 | Amper 博客

10/3/2025, 4:55:44 PM

📌 一句话摘要

Amper 0.8.0 引入了 Compose 热重载、自定义 Kotlin 编译器版本、JavaScript/WebAssembly 目标平台、增强的依赖解析以及各种 IDE/CLI 改进，标志着其构建系统向更注重开发者体验和多平台支持的战略转变。

📝 详细摘要

JetBrains 的 Amper 0.8.0 更新对其构建系统进行了重大改进，重点关注开发人员体验和多平台支持。主要功能包括备受期待的 Compose 热重载，它可以在 JVM 桌面目标平台上无需重启应用程序即可立即进行代码更改。同时，它还提供了自定义 Kotlin 编译器版本（2.0.0 及更高版本）的灵活性。此更新通过简化 `src` 目录的使用，简化了 JVM 和安卓应用程序的单平台体验，并为仅 JVM 的库引入了专用的 `jvm/lib`。此外，Amper 现在支持 JavaScript 和 WebAssembly (WasmJs， WasmWasi) 目标平台，扩展了其多平台功能，尽管这些目标平台的执行工具仍然很基础。依赖管理方面，通过完整的 Maven-local 仓库解析得到了改进，允许依赖本地构建的制品。IDE 和 CLI 的可用性得到了提升，这体现在多个方面：用于添加依赖项（包括第三方 Maven）的快速修复、Spring Boot 启动器内嵌提示、更新的“新建目录”弹出窗口、新的 `show dependencies` 命令，以及用于 `amper run` 的自定义工作目录选项。值得注意的是，JetBrains 确认弃用基于 Gradle 的 Amper，强调未来专注于独立的 Amper，并承诺在即将发布的版本中提供可扩展性原型和官方 Maven 发布库支持。默认工具链和框架版本也已更新，反映了最新的稳定版本。此版本加强了 Amper 对为 Kotlin 开发者提供精简、高效的构建体验的承诺。

💡 主要观点

  1. Amper 0.8.0 通过 Compose 热重载和灵活的 Kotlin 编译器版本控制，显著提高了开发效率。 Compose 热重载允许 JVM 桌面应用程序即时进行代码更改，无需重启。自定义 Kotlin 编译器版本支持使开发者能够快速测试新的语言功能，从而简化开发工作流程。
  2. 此更新通过添加 JavaScript 和 WebAssembly 目标平台并改进依赖解析，扩展了 Amper 的多平台功能。 新的 `js`、`wasmJs` 和 `wasmWasi` 目标平台扩展了 Amper 的覆盖范围。完整的 Maven-local 仓库解析简化了对本地构建和第三方依赖的管理，这对于复杂项目至关重要。
  3. JetBrains 正在逐步淘汰基于 Gradle 的 Amper，未来将专注于独立的 Amper，并计划提供可扩展性和官方 Maven 发布支持。 这种战略转变表明了对更简单、更集成的构建体验的承诺。即将到来的可扩展性和官方库发布将解决当前的局限性，并扩展 Amper 对库作者的实用性。

💬 文章金句

  • Amper 0.8.0 已发布，具有 Compose 热重载、可自定义的 Kotlin 编译器版本、新的 JavaScript 和 WebAssembly 平台，以及对 IDE 和 CLI 体验的许多其他改进。
  • 您现在可以使用 Compose 热重载来自动加载代码更改，而无需重新启动应用程序。
  • 如果您渴望在下一个 Amper 版本之前尝试新的 Kotlin 编译器版本，您现在可以使用简单的设置自定义 Kotlin 编译器版本。
  • Amper 现在支持 `js`、`wasmJs` 和 `wasmWasi` 目标平台。
  • 正如之前宣布的那样，我们正在逐步淘汰基于 Gradle 的 Amper。作为 Gradle 插件的 Amper 的最后一个版本是 0.7.0，并且此插件将不再以这种形式发布。
