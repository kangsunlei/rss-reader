📝 详细摘要

文章详细剖析了 Fastjson 1.2.83 版本的内部工作原理。首先介绍了 Fastjson 的概述及其在数据“跨边界搬家”中的作用，强调了学习其架构对技术人员的价值。接着，从核心模块架构、项目结构和关键类入手，系统阐述了序列化和反序列化的详细流程。特别深入讲解了序列化器查找、JavaBean 序列化、循环引用检测、上下文管理以及高效的 JSON 字符串构建（SerializeWriter）。反序列化部分则涵盖了反序列化器选择、词法分析、AutoType 安全检查和对象实例化过程。文章还重点介绍了 ASM 性能优化和 AutoType 机制等核心特性，为读者全面理解 Fastjson 内部机制提供了宝贵资料，对技术人员提升软件设计工程实践能力具有重要价值。

💡 主要观点

  1. Fastjson 1.x 版本在国内广泛使用，深入学习其架构设计对技术人员提升软件设计工程实践能力具有重要价值。 尽管 Fastjson 1.x 已停止维护，但其在国内的广泛应用使得理解其内部机制成为提升软件设计与工程实践能力的宝贵资源。
  2. Fastjson 通过 ASM 字节码生成技术实现高性能序列化与反序列化。 ASM 技术在运行时动态生成定制化序列化/反序列化器，避免了 Java 反射带来的性能开销，是 Fastjson 处理小数据时速度快的重要原因。
  3. Fastjson 的架构设计体现了高度的模块化和可扩展性。 框架清晰划分为用户接口、配置管理、序列化/反序列化引擎和安全防护层，支持 SPI 扩展和自定义序列化器，满足复杂定制需求。
  4. 反序列化过程比序列化更为复杂，涉及精密的词法分析、安全检查和类型匹配。 反序列化不仅需要将 JSON 字符串解析为 Java 对象，还需应对多种数据结构、潜在的安全漏洞（如 AutoType）和复杂的类型推断，其实现难度和细节处理显著高于序列化。
  5. 循环引用检测和 AutoType 安全机制是 Fastjson 核心特性。 循环引用检测通过'$ref'占位符防止对象循环引用导致的栈溢出；AutoType 机制则通过黑白名单检查增强反序列化安全性，避免潜在漏洞。
  6. SerializeWriter 采用线程本地缓冲机制高效构建 JSON 字符串。 内部使用 char[]数组拼接字符串并配合动态扩容和线程本地缓存，减少内存分配和 GC 压力，显著提升了 JSON 字符串的写入性能。

💬 文章金句

  • Fastjson1.X 版本目前已停止维护，被 Fastjson2.X 代替，但 1.X 版本国内被广泛使用，通过学习其技术架构，剖析架构上优缺点，对技术人员提升软件设计工程实践能力很有价值。
  • 整体上 Fastjson 通过统一的门面 API（JSON.toJSONString/parseObject）调用核心控制器（JSONSerializer/DefaultJSONParser），利用 ASM 字节码生成或反射机制，配合 SerializeWriter/JSONLexer 进行高效的 Java 对象与 JSON 字符串间双向转换，同时提供配置缓存、循环引用检测和 AutoType 安全防护等优化机制。
  • SerializeWriter.java 采用线程本地缓冲机制，提供高效的字符串构建。
  • 虽然"序列化"与"反序列化"在概念上是对偶的(Serialize ↔ Deserialize)，但在实现层面并不严格对偶，反序列化实现明显比序列化复杂。
  • Fastjson 使用$ref 占位符处理循环引用问题，防止对象循环引用造成解析查询栈溢出。
