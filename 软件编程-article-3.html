我们如何利用 Copilot 加速机密信息保护工程

8/28/2025, 5:08:51 PM

📌 一句话摘要

GitHub 成功利用 Copilot 智能编码代理，显著加速了机密信息验证检查的开发，展示了人工智能在可重复工程流程中的价值。

📝 详细摘要

本文详细介绍了 GitHub 如何成功利用其 Copilot 智能编码代理，以显著加速机密信息验证检查的开发，这是其机密信息保护功能的核心组成部分。从历史上看，为新的令牌类型添加验证支持的过程一直是一个缓慢、手动且框架驱动的工作流程，包括研究、代码实现、暗部署（即在不影响最终用户的情况下进行内部测试）以进行观察以及最终发布。GitHub 将 Copilot 战略性地集成到编码和发布阶段，并将这些阶段确定为适合自动化的可重复任务。虽然 Copilot 在复杂、细致的研究（如识别最佳应用程序编程接口端点）方面表现欠佳，但它在从全面的、示例丰富的提示中生成代码（验证器）方面表现出了卓越的能力。人工智能生成的代码像任何人为贡献一样对待，要经过自动化测试和人工审查。这种创新方法使 GitHub 能够在短短几周内通过实习生监督完成近 90 种新令牌类型的上线，与之前花费数月添加 32 种类型相比，有了显著改进。这一经验强调了人工智能编码助手作为框架驱动、可重复工程任务的效率倍增器的巨大潜力。同时，也 критически 强调了人工工程判断、彻底审查、高质量提示和持续过程迭代的必要性。

💡 主要观点

  1. GitHub 通过将 Copilot 集成到可重复的编码任务中，显著加速了机密信息验证开发。 通过自动化新令牌验证器的代码生成和发布配置步骤，GitHub 在很短的时间内大幅增加了支持的机密信息类型数量，展示了人工智能对开发速度的倍增效应。
  2. 人工智能编码助手对于框架驱动、可重复的工程流程非常有效。 本文说明，具有明确、一致步骤的任务（例如基于特定框架创建新的验证器）是人工智能自动化的理想选择，从而可以显著提高规模和效率。
  3. 使用人工智能编码助手时，人工工程判断、详细的提示和严格的审查仍然至关重要。 Copilot 在复杂的研究中表现欠佳，有时会犯错误，这表明人工智能增强了人类工程师，而不是取代了人类工程师，因此需要仔细监督、彻底测试和改进提示才能获得最佳结果。

💬 文章金句

  • 不小心将密钥提交到源代码是每个开发人员都害怕犯的错误，而且这个错误非常容易犯。
  • 编码助手是利用自动化加速框架驱动的可重复工作流程的可行选择。在我们的例子中，Copilot 实际上是一个效率倍增器。
  • Copilot 提供了速度和规模，但它不能取代人工工程判断。始终审查、测试和验证它生成的代码。
  • 自动化放大了可重复性：如果您的流程具有明确定义的步骤，则编码助手可以帮助您扩展工作并扩大您的影响。
  • 像对待团队成员一样对待 Copilot：它的贡献需要像任何人的代码一样进行仔细的审查、测试和反馈。
