本文分享将 Oracle Cloud 抢机脚本部署为本地 launchd 守护进程的实战经验，包括 API 密钥选择、错误处理、重试策略与 PAYG 升级等关键技巧，最终约 1 小时抢到 4 核 24G 实例。

📝 详细摘要

作者分享了将 Oracle Cloud 永久免费资源抢机脚本从 Cloud Shell 迁移到本地 macOS launchd 守护进程的完整思路与踩坑记录。文章覆盖了 API 签名密钥（避免 session token 过期）、错误分类处理（区分 500 InternalError 与 429 退避）、OCI CLI 重试策略（使用 --no-retry 避免默认重试打乱轮询节奏）、抢到即停与防重复抢购（通过查询存量与 KeepAlive 配置实现）等关键细节。作者特别指出，升级 PAYG 账户（仍使用免费额度，不产生费用）是提升抢中率的最大杠杆，升级后约 1 小时即成功抢到 4 核 24G 实例。文章最后提及了 Oracle Ubuntu 镜像的默认防火墙与 MTU 配置注意事项。

💡 主要观点

  1. 使用 API 签名密钥而非 session token 可避免过期问题。 Cloud Shell 中的 session token 会随连接断开而失效，改用 API 签名密钥后守护进程可长期稳定运行。
  2. 错误处理需按消息文本分类，而非仅看状态码。 Out of host capacity 实际返回 500 InternalError，仅靠状态码无法准确判断；429 限流则需退避重试。
  3. OCI CLI 默认对 5xx 内部重试退避约 110 秒，会打乱轮询节奏。 在 launch 命令中加入 --no-retry 参数可让请求秒级返回，保持稳定的轮询频率。
  4. 升级 PAYG 账户是提升抢中率的最大杠杆。 即使只使用免费额度（不产生费用），PAYG 账户在资源分配优先级上远高于免费账户，作者升级后约 1 小时即抢到 4 核 24G 实例。

💬 文章金句

  • 升级 PAYG（只用免费额度仍 $0，但拿容量优先级高得多）。
  • 错误按消息文本分类：Out of host capacity 其实是 500 InternalError，不能只看状态码；429 要退避。
