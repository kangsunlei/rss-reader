Agent 改了 40 个文件你才发现？用 Harness Hook 把止损写进架构

11/17/2026, 12:45:00 AM

📌 一句话摘要

本文提出了 stop-line 框架，通过 Harness Hook 将止损机制从 Prompt 层面提升到控制面，实现对 Agent 长任务执行的精准控制，防止范围失控和不可逆操作。

📝 详细摘要

文章聚焦于 Agent 长任务执行中常见的三类失败场景：换汤不换药的重试、错误指纹漂移以及范围失控和不可逆操作。作者指出纯 Prompt 方案难以有效止损，于是构建了基于 Harness 生命周期钩子的 stop-line 框架。该框架采用双层架构：Hook 层负责确定性的计数和拦截，Skill 层负责判断和交接。文章详细阐述了四个核心抽象（HANDOFF 文档结构、停止状态机、四条设计原则）以及关键实现（签名归一化、只读判定、失败识别、状态持久化等），并通过线上实测记录验证了框架的有效性。同时指出了两个实际 Bug（预算停止被误解除、临时文件被计入预算）并给出修复方案。

💡 主要观点

  1. 纯 Prompt 方案难以有效防范止损 因为止损场景下的四个失效点（模型自我约束失效、错误指纹漂移、范围失控、不可逆操作）会导致模型在需要止损时不够可靠，需将控制逻辑从数据面挪到控制面。
  2. stop-line 框架采用双层架构分工明确 Hook 层负责确定性的计数和拦截，Skill 层负责判断和交接，形成清晰的职责边界，确保在 Agent 继续之前先判断该任务是否值得继续。
  3. 通过 HANDOFF 文档实现有效的交接与复用 交接文档包含「已验证的事实」「已完成的改动」「已排除的假设」等六个章节，其中「已排除的假设」是最有价值的一节，避免后续会话重复验证失败方向。
  4. 签名归一化技术识别换汤不换药的重试 通过正则表达式统一处理十六进制、IP 地址、字符串、路径、数字等，使不同表面形式的相同操作被识别为同一签名，从而有效检测循环重试。
  5. 线上实测验证框架有效性并暴露实际问题 实测中框架成功拦截了范围失控和不可逆操作，同时发现了预算停止被误解除和临时文件计入预算两个 Bug，进一步完善了框架的健壮性。

💬 文章金句

  • 用 Agent 跑长任务，做错一步其实不算什么，麻烦的是它错了还接着干：同一个补丁换着写法打四遍，原本 3 个文件的改动蔓延到 40 个，rm -rf 不问一声就执行了。
  • 我的思路是不指望模型自觉，把计数和拦截从模型推理（数据面）挪到 harness 的生命周期钩子（控制面）上。
  • 计数和拦截交给代码，判断和交接交给模型。
  • 交接之所以比从头再来省钱，靠的就是这一节：下一个会话不用再花预算去验证已经失败过的方向。
  • 守卫类插件默认应该项目级启用，全局启用要用户显式选择。
