Git 2.50 新特性亮点

6/16/2025, 5:12:27 PM

📌 一句话摘要

重点介绍 Git 2.50 版本中的功能和改进，涵盖存储、合并和命令行工具等方面。

📝 详细摘要

这篇来自 GitHub 博客的文章详细介绍了 Git 2.50 版本中的关键更新。重要变更包括通过新的 `--combine-cruft-below-size` 选项改进了多个 cruft 包的处理方式，从而提升了不可达对象的垃圾回收效率。该版本还引入了对增量式多包可达性位图的实验性支持，这提高了使用多包索引（MIDX）的大型仓库的性能。一项主要更新是完全用更快、更易维护的 'ORT' 引擎替换了旧的 'recursive' 合并引擎，ORT 引擎还支持通过 `git merge-tree --quiet` 在不持久化对象的情况下检查可合并性。其他较小的增强功能包括使用 `git cat-file` 过滤对象、`git maintenance` 的新任务、简化的 reflog 删除、优化的引用处理以及新的 curl TCP keepalive 配置选项。该版本包含了来自 98 位开发者的贡献。

💡 主要观点

  1. 改进了对不可达对象的多个 cruft 包的管理。 引入 `--combine-cruft-below-size` 并重新定义 `--max-cruft-size` 的用途，以便更好地控制 cruft 包的合并和大小，从而提高垃圾回收效率。
  2. 增加了对增量式多包可达性位图的支持。 将增量式 MIDX 扩展到位图，使得大型仓库能够高效地添加新的可达性数据，从而加快 `git log` 等操作的速度。
  3. ORT 合并引擎完全取代了旧的 'recursive' 策略。 更快、更易维护的 ORT 现在是唯一的默认合并引擎，提供了性能提升以及静默可合并性检查等新功能。
  4. 增强了 `git cat-file` 的对象过滤能力。 利用部分克隆过滤机制，更轻松地按类型枚举对象，简化了围绕 Git 对象的脚本操作。
  5. 为 `git maintenance` 增加了新任务和配置选项。 将 `worktree-prune`、`rerere-gc` 和 `reflog-expire` 等常见维护任务整合到一个命令下，并允许配置松散对象打包。
