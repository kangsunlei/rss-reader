你的工作正在被蒸馏成 Skill！硅谷 YC 掌门人：个人 AGI 不在云端，就藏在自己的文件夹里，下一代开发者，要拥有自己的“经验代码库”

8/7/2026, 9:30:00 AM

📌 一句话摘要

文章介绍如何通过个人 Markdown 知识库和 Skill 文件，让 AI 助手掌握开发者的经验，实现个人 AGI，提升工作效率。

📝 详细摘要

文章以 YC 总裁 Garry Tan 的演讲为基础，阐述了个人 AGI 的概念：开发者应将经验、判断和工作流程沉淀为可被 Agent 理解和执行的 Skill 文件（以 Markdown 形式保存），而不仅仅依赖云端模型。Garry 分享了他个人约 22 万页的 Markdown 知识库（GBrain），说明 Agent 如何在此基础上检索上下文、调用工具并完成任务。他强调模型负责判断与偏好，而确定性计算（如金额、数据查询）必须交给代码和数据库，以避免 hallucination。文章进一步给出构建个人 AGI 的实践路径：选择 Agent 框架、建立 Markdown 资料夹、编写第一份 Skill（从最讨厌的重复任务开始）、将其接入定时任务、任务后将成功过程整理为新 Skill，并强调知识库需要维护——记录信息来源与时间、冲突提示、定期删除失效内容、设置权限边界。最后鼓励开发者从“一页文件”起步，长期积累可复用的工作系统，以在模型能力提升时仍保持个人经验的竞争优势。

💡 主要观点

  1. 个人 AGI 的核心是将经验沉淀为可被 Agent 理解和执行的 Skill 文件。 通过 Markdown 记录判断、流程和边界，Agent 在遇到类似任务时可以直接调用，避免重复解释并提升效率。
  2. 模型负责判断和偏好，确定性计算必须交给代码和数据库。 Garry 将 Agent 分为潜在空间处理偏好与确定性系统处理金额、查询等，防止模型 hallucination，确保关键操作的可靠性。
  3. 构建个人知识库需要持续维护，以避免信息过期和冲突。 记录信息来源与更新时间、新旧事实冲突时先提示而不直接覆盖、定期删除失效内容、设置权限边界，确保 Agent 基于可信信息行事。
  4. 从最讨厌的重复任务开始编写第一份 Skill，逐步积累可复用的工作系统。 先像教新同事一样写清输入、步骤、输出和禁区，让 Agent 运行后根据纠正更新文件，长期形成经验代码库。

💬 文章金句

  • 把技能掌握在自己手里。否则有一天，你的岗位只会剩下一份 Skill 文件。
  • 同样使用 Claude，有人只是写代码快了一点，有人却能把工作效率提高几十倍。
  • Markdown is code.
  • Never do one-off work.
  • 不要让 Agent 每天醒来都失忆
