Anthropic 工程师：我们日常如何使​​用 Claude Code 丨 Claude

6/11/2026, 1:36:00 PM

📌 一句话摘要

本文总结 Anthropic 工程师 Arno 的 workshop，展示如何将 Claude Code 配置为工程系统的一部分，通过需求采访、HTML 规格稿和内置验证框架，让 Agent 在长任务中减少偏差、产出可验证结果。

📝 详细摘要

文章基于 Anthropic Applied AI 团队架构师 Arno 的公开 workshop，详细拆解了 Claude Code 在真实项目中的进阶工作流。核心思路是：随着模型能力增强，Agent 可以执行更长的任务，但跑偏的代价也更大，因此需要改变工作习惯，将方向确认、验证和反馈机制前置。文章通过一个分账应用和一个 to-do app 的演示，分三个阶段展开：第一阶段让 Claude 通过提问式采访提取需求，避免一次性硬编码；第二阶段用 HTML 文件替代冗长的 Markdown 规格稿，生成多个可交互的设计方向，方便人类通过截图和点击给出反馈；第三阶段是核心亮点，提出了一个「verification framework」，将验证嵌入产物本身，通过 DOM contract、fixtures、invariants 和 probes 让 Agent 能自主检查结果，并生成可追溯的验证记录。文章还讨论了如何让同一套验证同时服务于人类 dashboard、Agent 浏览器驱动和 CI 流程，以及证据录制对团队信任 Agent 的重要性。

💡 主要观点

  1. 模型越强，越应减少对 Agent 的硬编码约束，转而通过前置采访明确需求。 Arno 认为 Claude 可能比人更擅长从对话中提取需求，因此应让 Agent 使用提问工具进行多轮采访，而不是一次性给出模糊指令，从而减少长任务跑偏的风险。
  2. HTML 规格稿比 Markdown 更适合作为人与 Agent 对齐的中间产物。 Markdown 超过 200 行后难以阅读和反馈，而 HTML 可生成可点击、可截图的可视化设计方向，让人能直观比较并给出具体反馈，从而减少迭代次数。
  3. 验证应嵌入产物本身，而非事后检查，让 Agent 能自主证明改动有效。 Arno 区分了 test 和 verify：普通测试关注代码是否通过，而 verification framework 通过 DOM contract、fixtures 和 invariants 让 Agent 能原生检查产物状态，实现「测试通过但验证失败」的精细检测。
  4. 同一套验证框架应同时服务于人、Agent 和 CI，形成统一的观察面。 通过 manifest、probes 和 invariants，人类 dashboard、Agent 浏览器驱动和 CI 命令行共享同一套验证逻辑，减少「人看到一套、机器看到另一套」的错位，便于排查问题。
  5. Agent 的验证过程应自动录制证据包，作为团队信任的基础设施。 Claude Code 团队会记录代码变更和验证步骤的 clips，可打包下载或分享，让 code review 从看 diff 和口头说明升级为可复现的验收材料。

💬 文章金句

  • 模型越强，你越应该少约束它。
  • Agent 跑得越久，走错时烧掉的 token 越多。
  • 目标是把验证嵌进产物本身。
  • 让验证原生存在于事物本身，这样 Agent 可以和人一起驱动它。
  • 长期来看，如果 HTML spec 足够好、足够丰富，你会少迭代。
