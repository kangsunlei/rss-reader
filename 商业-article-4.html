Anthropic 负责人：AI Agent 正在重写企业工作流丨 Every

5/9/2026, 12:45:00 PM

📌 一句话摘要

Anthropic 平台负责人深度解析 Claude Agent 平台的设计哲学：从补全 API 演进为带文件系统、记忆和工具的云端电脑，强调平台应提供可组合的原语，让开发者聚焦业务逻辑而非重复搭建基础设施。

📝 详细摘要

本文编译自 Every 对 Anthropic Claude 平台负责人 Angela 和工程负责人 Caitlin 的深度访谈。文章系统阐述了 Claude 平台从早期补全 API 向 managed agents 平台的演进逻辑，核心观点是平台的任务已从「吐 token」变为「让结果稳定发生」。Angela 详细介绍了文件系统、skills、vaults 等原语的设计考量，强调平台在关键路径上保持 opinionated 以最大化模型能力。文章还讨论了团队级 Agent 的协作挑战：权限、审计、升级和退场机制，以及法律审稿 Agent 等内部实践案例。Caitlin 指出，当 Agent 进入产品并规模化后，基础设施复杂度会指数级上升，平台化的核心目标是摊薄重复的云端运行成本。

💡 主要观点

  1. Agent 平台正从补全 API 演进为带状态、工具和运行环境的云端电脑。 Angela 指出平台演进的核心线索是 stateful：从简单补全到 chat session、tool calling，再到 managed agents，平台的任务从生成 token 变为确保结果稳定发生。
  2. 平台应在关键路径上保持 opinionated，以最大化模型能力。 Anthropic 选择让 Claude 原生使用文件系统和 skills，这些看似简单的原语会影响模型如何读项目、修改文件和复用组织经验，最终形成模型行为的训练场。
  3. 未来竞争发生在 Agent 配方层，而非底层模型切换。 Angela 观察到 harness 和模型正变成一组交付单元，团队的技术决策应从「选哪个底层模型」转向「哪套 Agent 能更稳定交付」，切换层级上移到整套 Agent。
  4. 团队级 Agent 的难点在于协作、权限、审计和升级退场。 个人工具只需提高单点效率，团队 Agent 要处理共享上下文、统一规则、审计轨迹和权限层级，还需要可看见的会话和多人协作界面。
  5. 平台化的核心是摊薄重复的云端运行成本。 Anthropic 内部多次重复搭建 Agent 基础设施后，决定将其平台化，让开发者不必每次重新实现 memory、运行 loop、权限和部署，聚焦业务逻辑。

💬 文章金句

  • 平台最终会是一组原语和基础设施，让你用最少的工作最快拿到结果。
  • 如果你把 Agent 做进产品，并且真的跑到规模上，基础设施会越来越难。
  • 使用文件系统，使用 skills。它们很基础，但我们希望 Claude 从这些原语出发。
  • 你仍然需要冗余，也可能在某些事情上用别的模型，但更可能是在 Agent 这一层切换。
  • 最后的状态也许会把一切压缩成一个结果和一个预算。
