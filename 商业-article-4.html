提示工程已死？

7/12/2026, 12:26:00 PM

📌 一句话摘要

本文驳斥了“提示工程已死”的论调，指出在 Agent 时代，Prompt 已从一次性指令升级为驱动智能体推理、决策与工具调用的系统基础设施，其工程化理解反而更加重要。

📝 详细摘要

文章针对 2026 年 AI 圈流行的“Prompt 已死”观点展开反驳。作者引用黄仁勋与 Boris Cherny 的言论引出话题，随即提出核心论点：Agent 时代非但没有淘汰 Prompt，反而将其从“魔法咒语”升级为“系统的基础设施”。文章结合其翻译的《大模型提示工程》一书内容，从大模型自回归生成机制讲起，论证了理解 Token 生成、温度等底层原理的必要性。进而阐述了提示词内容设计（少样本提示、RAG）与工程化组装（Token 独立性、元素顺序）等“内功心法”，并明确指出 Agent 的推理、决策与工具调用底层均由 Prompt 驱动，其本质已变为“可组合、可复用、可迭代的系统组件”。最终结论是，Prompt 只是退居幕后，成为更关键的工程基石。

💡 主要观点

  1. “Prompt 已死”的论调源于对 Prompt 理解的浅层化，将其等同于“聊天话术”。 作者指出，随着 Agent 架构兴起，简单的自然语言指令写法失效，但这并不意味着 Prompt 不重要，而是需要更系统、更底层的工程化理解。
  2. 理解大模型的 Token 生成机制是做好 Prompt 工程的前提。 文章强调，大模型本质是文本补全系统，不理解 Token、温度、概率分布等机制，就无法真正控制模型的“思考”过程，Prompt 不是玄学而是工程。
  3. Agent 的推理、决策与工具调用底层均由 Prompt 驱动。 无论是思维链推理、ReAct 模式的迭代式行动，还是对话管理，Agent 的每一次行为都依赖 Prompt 作为指令，Prompt 已升级为可组合、可复用的系统组件。
  4. 提示工程正从“一次性指令”进化为“剧本创作式”的系统设计。 在 Agent 系统中，提示工程需要关注内容设计、工程化组装、元素位置与顺序等细节，这些决定了 Agent 在复杂任务中的表现上限。

💬 文章金句

  • Agent 不是替代了 Prompt，而是把 Prompt 从“一次性指令”升级为了“可组合、可复用、可迭代的系统组件”。
  • 如果你只把 Prompt 当作“跟 AI 聊天的话术”，那它确实过时了。但如果你把它理解为与智能体对话的协议、控制系统行为的语言、设计认知框架的蓝图——那么这门传统手艺，将在 Agent 时代焕发全新的生命力。
