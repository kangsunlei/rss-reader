协同文档下的 Agent 协作闭环：可回滚、可对比的透明化编辑实现

8/19/2026, 12:00:00 PM

📌 一句话摘要

本文详细阐述在协同文档中引入 AI Agent 的透明化编辑方案，通过身份归属、事实链记录、side-by-side 差异展示及精准撤回机制，实现 AI 改动的可见、可控与可回滚。

📝 详细摘要

文章围绕 vivo 互联网项目团队在 AI 编辑器二期的调研与实践，系统拆解了 Agent 在协同文档中的角色定位、透明化编辑的实现路径以及可回滚、可对比的机制。首先讨论了 Agent 作为独立 Peer、附属 Cursor 或模拟用户三种身份模式的利弊，最终选择附属用户但保持独立身份证明的方案。接着介绍了如何通过 editor.chain().changedByAI(...) 将 AI 编辑纳入统一身份边界，采用块级感知与文本级细化的两层差异对比策略，并构建基于 baseJson + 有序 stepsJson 的事实链，以实现可还原、可审计的记录层。在展示层，系统将事实回放为 beforeDoc/afterDoc，再通过 side-by-side 块级对齐与文本级细化生成可读的差异视图。撤回层则通过在事务中加入 sessionId、runId 等元数据，实现用户手动撤销（Ctrl+Z）与 AI 编辑撤回的精准区分，避免误伤他人编辑。最后强调，这三层（记录、展示、决策）缺一不可，共同构建了让用户在 AI 参与编辑后仍能牢牢掌握文档掌控权的闭环。

💡 主要观点

  1. Agent 附属于用户但保持独立身份证明，避免占用协同席位且可精准区分人与 AI 的编辑。 文章比较了独立 Peer、附属 Cursor、模拟用户三种模式，认为附属用户并加入会话 ID、运行轮次、消息批次等身份信息，能在保持权限简单、体验顺滑的同时，使系统能够分辨哪些改动来自用户、哪些来自本轮 AI 编辑。
  2. 采用 baseJson + 有序 stepsJson 的事实链记录方式，实现 AI 编辑的可还原、可审计与可定位。 每轮 AI 编辑保存编辑开始前的文档状态为 baseJson，并将每一步操作序列化为 stepsJson；记录层仅保存机器可还原的事实，展示层再将其回放为可读的差异，决策层基于同一事实链执行接受、拒绝或撤回操作。
  3. 使用 side-by-side 块级对齐加文本级细化的差异展示，提升用户对 AI 修改的观测效率。 首先按内容块（段落、标题、列表等）判断变化类型，再在内容未变块内部进行文本级细化。这种双层策略既保留结构语义，又避免字符级 diff 带来的噪音，使用户能够快速定位哪些块被修改以及具体修改了哪些文本。
  4. 撤回机制通过会话/运行元数据实现用户手动撤销与 AI 编辑撤回的精准区分，防止误伤他人编辑。 在事务中加入 sessionId、runId 等元数据，并设置 addToHistory=false；撤回时仅过滤具有相同元数据的事务。这样 Ctrl+Z 撤销仅影响用户自身编辑，而 Agent 对话框中的撤回仅回退本轮 AI 编辑，确保协同环境下的操作安全可靠。

💬 文章金句

  • Agent 附属于用户，但其改动拥有独立的归属
  • 底层记录采用 baseJson + ordered stepsJson 的方式，而非仅仅保存前后快照
  • 展示层则运用 side-by-side 的块级行展示加上文本级细化
  • 撤回层则将 Ctrl+Z 的用户手动撤销与 Agent 运行级别的撤回明确区分开来
