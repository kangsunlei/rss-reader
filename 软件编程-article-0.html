SSL for SaaS v1 漏洞披露

8/1/2025, 2:00:01 PM

📌 一句话摘要

Cloudflare 披露了已弃用的 SaaS v1 (Managed CNAME) 的 SSL 架构漏洞，强调了 IP 路由的安全风险，并介绍了安全增强的替代方案。

📝 详细摘要

这篇来自 Cloudflare 博客的文章详细介绍了外部研究人员在其已弃用的 SaaS v1 的 SSL（托管 CNAME）产品中发现的安全漏洞。v1 于 2017 年推出，其架构依赖于基于 IP 的路由，而没有验证域名所有权，这使得未经验证的域名可以通过 Cloudflare 提供服务。这造成了一种微妙但重大的风险，如果与 DNS 投毒或跨站脚本结合使用，可能会导致中间人攻击 (MITM) 或主机头重定向。Cloudflare 于 2021 年弃用 v1，并推出了 SSL for SaaS v2 (Cloudflare for SaaS) 以缓解此问题。新版本强制执行经过验证的自定义域名模型，需要同时进行域名和 SSL 证书验证。该公司表示，大多数客户已成功迁移。对于少数剩余的 v1 用户，Cloudflare 实施了补偿性控制措施，包括限制新的 v1 配置、维护允许列表以及部署 WAF 自定义规则。Cloudflare 正在积极努力完成这些最后几个客户的迁移，并重申其对安全性和透明漏洞披露的承诺。对于绝大多数 Cloudflare 客户，当前无需采取任何行动。

💡 主要观点

  1. SaaS v1 的 SSL 基于 IP 的路由存在架构安全缺陷，未在代理流量前验证域名所有权。 这种架构设计允许未经证实的自定义域名通过 Cloudflare 提供服务，当与其他漏洞（如 DNS 投毒或 XSS）结合使用时，会产生恶意主机头重定向和中间人攻击 (MITM) 的潜在风险。
  2. Cloudflare for SaaS (v2) 采用经验证的自定义域名模型，有效解决了 v1 存在的漏洞。 V2 强制执行域名验证步骤以及 SSL 证书验证，确保只有经过授权和验证的域名才能路由到其各自的源站，从而有效地消除了旧系统中存在的此类漏洞。
  3. Cloudflare 积极推进从 v1 到 v2 的过渡，并为剩余用户部署了补偿性控制措施。 自 2021 年弃用 v1 以来，Cloudflare 已积极迁移了大多数客户，限制了新的 v1 配置，维护了一个允许列表，并部署了 WAF 规则，以保护在最终迁移阶段的少数剩余 v1 用户。

  • 该架构依赖于基于 IP 的路由，并且在代理流量之前没有验证域名所有权。这意味着任何指向正确 IP 的自定义域名都可以通过 Cloudflare 提供服务 --- 即使所有权未经证实。

  • Cloudflare for SaaS 从基于 IP 的路由过渡到经过验证的自定义域名模型。现在，自定义域名必须通过域名验证步骤以及 SSL 证书验证才能代理到客户源站。
  • Cloudflare for SaaS 的架构改进不仅缩小了证书和路由验证之间的差距，而且还确保只有经过验证和授权的域名才能路由到其各自的源站---从而有效地消除了此类漏洞。
