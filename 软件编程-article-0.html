DynamoDB DNS 系统中的竞态条件：分析 AWS US-EAST-1 (美国东部-1) 区域的中断事件

11/15/2025, 10:46:00 AM

📌 一句话摘要

分析由 DynamoDB 的 DNS 管理系统中潜在的竞态条件引起的 AWS US-EAST-1 (美国东部-1) 区域重大中断事件，详细说明了其广泛影响以及 AWS 计划的补救措施。

📝 详细摘要

本文深入探讨了 US-EAST-1 (美国东部-1) 区域发生的重大 AWS 中断事件，该事件主要是由 Amazon DynamoDB 的自动化 DNS 管理系统中的潜在竞态条件触发的。这个缺陷导致 DynamoDB 区域端点出现不正确的空 DNS 记录，随后导致端点解析失败，并对关键的依赖服务（如新的 EC2 实例启动、Lambda 调用和 Fargate 任务）产生连锁影响。分析表明，DNS 故障是一种表象，而内部 DynamoDB 微服务中的底层竞态条件才是真正的根本原因。AWS 的官方事后分析报告承认了对客户的严重影响，并概述了立即采取的行动，包括在全球范围内禁用有问题的 DNS 自动化，以及修复竞态条件的长期计划。此外，还将增强 EC2 数据传播中的限流机制。本文还包含了专家的观点，他们提倡采用数据驱动的方法来评估云可靠性，敦促从业者考虑 AWS 一贯的长期可用性，而不是对罕见的、备受瞩目的事件过度解读。

💡 主要观点

  1. DynamoDB 自动化 DNS 管理系统中的潜在竞态条件是 AWS US-EAST-1 (美国东部-1) 区域中断的根本原因。 该缺陷导致 DynamoDB 区域端点生成不正确的空 DNS 记录，导致服务解析失败，并对依赖的 AWS 服务造成广泛中断。
  2. 由于复杂的相互依赖关系和网络配置问题，中断的影响波及到各种 AWS 服务。 新的 EC2 实例网络配置失败以及新启动实例的网络状态传播延迟产生了多米诺骨牌效应，影响了网络负载均衡器和其他服务。
  3. AWS 正在实施短期和长期解决方案，以解决中断的根本原因并增强系统弹性。 采取的措施包括禁用错误的 DNS 自动化、修复竞态条件、增加保护措施以及改进 EC2 数据传播系统中的限流，以更好地处理高负载。
  4. 在讨论云可靠性时，应更重视长期数据，避免受罕见重大事件造成的“认知偏差 (Memory Bias) ”的影响。 专家建议采取平衡的观点，承认 AWS 多年来总体上的高可用性，而不是让罕见的中断事件过度影响对云弹性的看法。

💬 文章金句

  • 此问题的根本原因是 DynamoDB DNS 管理系统中的潜在竞态条件，该条件导致该服务的区域端点 (dynamodb.us-east-1.amazonaws.com) 出现不正确的空 DNS 记录，而自动化未能修复该记录。
  • DNS 故障是第一个症状，而不是最近 AWS 中断的根本原因。根本原因是内部 DynamoDB 微服务中的竞态条件，该微服务可自动执行 DynamoDB 区域单元的 DNS 记录管理。
  • 我们已经在全球范围内禁用了 DynamoDB DNS 规划器 (DNS Planner) 和 DNS 执行器 (DNS Enactor) 自动化。在重新启用此自动化之前，我们将修复竞态条件场景并添加其他保护措施，以防止应用不正确的 DNS 计划。
  • 在可靠性工程中，认知偏差 (Memory Bias) 通常超过数据。团队对罕见事件反应过度，但对保持正常运行时间逐年稳定的缓慢而无形的工作投资不足。
