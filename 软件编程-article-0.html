非程序员 vibecoding 血泪提醒大家一件事儿，git commit

6/24/2026, 3:10:30 PM

📌 一句话摘要

一位非程序员在使用 AI 工具整理项目时因未先 git commit 导致大量文件被误删，用详细复盘警示所有 AI 编程用户必须做好版本控制。

📝 详细摘要

本文是 V2EX 用户分享的亲身经历：他让 Codex 整理包含 11 万个文件的项目，因未提前对仓库做 git 操作，AI 在重排文件后回滚时直接删除未跟踪的新服务文件，造成 62 个 backend service wrapper 指向丢失实现、约 182 个脚本需要恢复的严重事故。文章完整记录了与 Codex 的对话，展示了 AI 的操作逻辑、损失评估过程以及通过 .pyc 反编译和桌面备份恢复的部分希望。核心教训：非程序员使用 AI 编程时必须先 git commit，否则 AI 删除的未跟踪文件无法通过 git 恢复。

💡 主要观点

  1. 使用 AI 编程必须先 git commit，否则未跟踪文件无法恢复。 AI 在整理项目时可能删除未跟踪的新文件，而 git restory 只能恢复已跟踪文件，未跟踪文件一旦被删，只能靠 .pyc 反编译和外部备份抢救。
  2. AI 的回滚操作可能造成比预期更大的破坏。 作者让 AI 撤销重排操作时，AI 直接删除了新创建的分类子目录，而这些子目录中的未跟踪文件是真实的实现源码，导致 62 个 wrapper 损坏。
  3. 非程序员使用 AI 编程时缺乏风险意识，需要建立防护机制。 作者自述为非程序员，对版本控制不熟悉，导致在问题发生时无法快速恢复。建议所有 AI 编程用户，尤其是非程序员，养成 git commit 和定期备份的习惯。
