gRPC 作为 MCP 的原生传输协议

1/14/2026, 12:00:00 AM

📌 一句话摘要

Google Cloud 正在倡导并开发对模型上下文协议（MCP）的原生 gRPC 传输支持，以提升已使用 gRPC 的企业中 AI 智能体与工具通信的性能、安全性和开发效率。

📝 详细摘要

本文讨论了将 gRPC 作为模型上下文协议（MCP）原生传输协议的集成方案。MCP 是一个使 AI 智能体能够与外部工具通信的标准。虽然 MCP 传统上使用 JSON-RPC，但许多企业广泛使用 gRPC 进行高性能 RPC。文章强调了当前将基于 gRPC 的服务与 MCP 集成时需要转码网关的现状，并提出了将 gRPC 作为 MCP 原生传输协议的替代方案。作为 MCP 的核心贡献者，Google Cloud 正在积极与社区合作，在 MCP SDK 中包含可插拔的传输接口，并计划贡献一个 gRPC 传输包。原生使用 gRPC 的优势包括：提升性能（二进制编码、双向流、流量控制）、增强企业级安全性（mTLS、强身份验证、方法级授权）以及提高运维成熟度和开发效率（统一可观测性、强大的弹性、多语言开发、基于模式的验证）。此举旨在帮助组织在采用 MCP 时保持一致性并利用其现有的 gRPC 投资。

💡 主要观点

  1. MCP（模型上下文协议）是一个新兴的 AI 智能体与工具通信标准，通常使用 JSON-RPC。 MCP 促进了 AI 智能体与外部系统之间的可靠交互，但其默认的 JSON-RPC 传输对于大量投资于 gRPC 的企业来说可能是一个集成挑战。
  2. 对于以 gRPC 为中心的组织，MCP 的原生 gRPC 传输相比转码具有显著优势。 通过消除对转码网关的需求，原生 gRPC 支持保持了运维一致性，利用了现有工具链，并为已使用 gRPC 的公司简化了部署。
  3. gRPC 为 AI 智能体交互提供了卓越的性能、安全性和开发效率。 关键优势包括：通过二进制编码（Protobufs）降低延迟和网络成本、通过双向流实现实时交互工作流、强大的安全特性（如 mTLS 和方法级授权）以及改进的可观测性和弹性。
  4. Google Cloud 正在积极领导将 gRPC 作为可插拔传输协议集成到 MCP SDK 中的工作。 作为 Agentic AI Foundation 的创始成员和 MCP 的核心贡献者，Google Cloud 正在与社区合作，确保为 MCP 用户提供一致且可互操作的 gRPC 传输。

💬 文章金句

  • 模型上下文协议（MCP）是实现智能体与工具通信的标准。
  • 许多组织依赖 gRPC，这是一个高性能、开源的远程过程调用（RPC）模型实现。
  • MCP 转码的一个有趣替代方案是使用 gRPC 作为 MCP 的原生传输协议。
  • gRPC 的性能优势极大地提升了效率，这得益于以下特性：二进制编码（Protocol Buffers）、全双工双向流、内置流量控制（背压）。
  • gRPC 将安全性视为一等公民，其核心直接内置了企业级特性，包括：双向 TLS（mTLS）、强身份验证、方法级授权。
