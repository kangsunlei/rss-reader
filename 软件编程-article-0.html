数据微调的力量：LLM 驱动的持续代码修复 (NEL)

4/8/2025, 7:37:39 PM

📌 一句话摘要

通过在交互数据上微调小型开源 LLM，本文展示了其在代码错误修复方面的卓越性能和效率优势。

📝 详细摘要

本文探讨了通过微调小型开源 LLM 来优化代码修复任务的方法。文章指出，大型 LLM 提高了软件开发效率，但企业客户仍需基于自身数据进行定制和推理。研究表明，在 Databricks 内部代码数据集上，微调 Llama 3.1 8b Instruct 模型，在实际 A/B 测试中，代码修复的接受率超过了 GPT-4o，同时降低了推理延迟。文章还对比了生成完整代码 (full models) 和生成代码差异 (diff models) 的微调方法，并强调了使用交互数据进行训练的有效性，因为它能够自然生成，包含实践案例，并支持持续学习。最后，文章建议企业利用自身数据和 Databricks 的微调服务来定制 LLM，从而满足特定的编码需求，并探索 Quick Fix 的个性化定制方案。

💡 主要观点

  1. 微调小型开源 LLM 可提高代码修复质量和推理速度。 通过在组织特定数据上微调，小型 LLM 在代码修复任务中表现优于大型专有模型，同时降低了成本和延迟。
  2. 交互数据是微调 LLM 的有效资源。 交互数据由用户自然生成，包含实践案例，并支持 LLM 的持续学习，无需额外标注成本。
  3. 企业可以通过利用自身数据和微调服务来定制 LLM，从而满足特定的编码需求。 Databricks 的 Mosaic AI 模型训练服务简化了 LLM 的微调和部署过程，使企业能够轻松定制其代码修复代理。

💬 文章金句

  • 组织可以微调小型开源 LLM，从而获得更好的代码质量和推理速度。
  • 在交互数据上进行训练特别有效，原因有三。首先，它是自然生成的，因此不需要标注工作。其次，它包含实践中遇到的示例，因此即使数量不多，也特别适合微调。最后，由于交互数据是通过与 LLM 代理的交互不断生成的，我们可以重复使用新生成的交互数据来进一步微调我们的 LLM，从而实现持续学习 (NEL)。
  • 我们发现，微调 LLM 可以显著提高编码建议的质量，优于提示工程方法。
