【第 3622 期】深入浅出：用 URLPattern 打造轻量级 SPA 路由

12/5/2025, 1:03:00 AM

📌 一句话摘要

文章详细讲解了如何利用原生 JavaScript 和浏览器 URLPattern API 构建一个轻量级单页应用（SPA）路由器，涵盖 URL 匹配、组件渲染、导航处理及安全考量。

📝 详细摘要

本文深入浅出地介绍了如何使用浏览器原生的 URLPattern API 和 JavaScript 构建一个简单的 SPA 路由器。作者首先强调了 URLPattern 在匹配 URL 和捕获动态路径方面的强大功能，并通过具体代码示例展示了其用法，包括处理可选斜杠和通配符。接着，文章阐述了如何通过一个 Web Component（自定义元素）来封装路由逻辑，根据 URL 匹配路由配置并渲染对应的组件。此外，文章详细讲解了 SPA 路由中如何接管链接点击事件（使用`preventDefault`和`history.pushState`）以及响应浏览器前进/后退操作（监听`popstate`事件）。最后，作者讨论了 Vite 中 SPA 模式的配置，并特别提醒了手动实现路由可能带来的 XSS 安全风险，提出了避免风险的建议，并指出了未来可改进的方向，如动态路径段、查询参数和嵌套路由。

💡 主要观点

  1. URLPattern API 是构建原生 SPA 路由的核心，能高效匹配 URL 并捕获动态部分 URLPattern 提供了强大的 URL 模式匹配能力，支持处理路径斜杠、通配符等复杂场景，是实现客户端路由的关键基础，简化了 URL 解析逻辑。
  2. 通过 Web Components 可封装路由逻辑，实现组件化、可重用的 SPA 路由器 将路由配置、匹配和组件渲染逻辑封装在自定义元素中，使得路由器成为一个独立的、易于集成和管理的组件，提升了代码的模块化和可维护性。
  3. 原生 SPA 路由需接管链接点击和浏览器历史事件以实现无刷新导航 通过阻止默认链接跳转、手动更新浏览器历史状态（`pushState`）和监听`popstate`事件，确保用户在点击链接或使用浏览器导航时，页面能平滑切换而无需重新加载。
  4. 手动实现底层路由需注意 XSS 安全风险，确保路由配置的安全性 文章强调了在手动构建路由时，应将可渲染组件列表定义为私有静态变量，避免外部篡改，防止恶意注入导致 XSS 攻击，保障应用安全。

💬 文章金句

  • 自 2025 年 9 月起，URLPattern 现已在所有浏览器中可用。
  • 在路由器中，条件渲染组件并不是难点，真正的挑战在于如何准确匹配浏览器的 URL，从而判断该显示哪个组件。
  • 整个路由逻辑都在客户端通过 JavaScript 完成。无论访问哪个路径，服务器都只需返回同一个首页文件，接下来由客户端使用我们定义好的 URLPattern 来匹配并渲染相应的组件。
  • 我们现在做的事情是相当底层的。像这样自己手动实现一个路由渲染器，如果不小心，可能会暴露出 XSS（跨站脚本攻击） 的风险。
  • 最安全的做法是：永远不要仅仅根据 URL 的查询参数或动态段来决定渲染哪个组件。要始终把可渲染的组件放在一个静态列表中，并将其保存在路由组件的私有作用域内。
