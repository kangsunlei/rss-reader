Spanner 列式引擎开启预览

2/27/2026, 12:00:00 AM

📌 一句话摘要

Google Cloud 推出 Spanner 列式引擎预览版，通过结合行式事务与向量化列式扫描实现高性能 HTAP，支持实时分析服务。

📝 详细摘要

本文宣布 Spanner 列式引擎开启预览，这是一项旨在弥合操作型 (OLTP) 与分析型 (OLAP) 工作负载之间差距的重大更新。通过在传统行式存储的基础上实现专门的列式存储格式，Spanner 现在可以使用向量化执行来处理复杂的分析查询，扫描速度最高可提升 200 倍。这种架构允许企业以亚秒级延迟提供来自 Iceberg 湖仓的 “热” 数据服务，在不影响事务性能的情况下支持实时仪表板和 AI 智能体。文章还详细介绍了与 BigQuery、Snowflake 和 Databricks 的 “反向 ETL” 集成，为更广泛的数据生态系统提供统一的服务层。

💡 主要观点

  1. Spanner 列式引擎通过在单一系统中统一事务与分析能力，实现了真正的 HTAP。 通过同时以行式和列式格式存储数据，Spanner 允许用户在实时数据上运行繁重的分析扫描，而不会影响面向客户的关键事务型应用的性能。
  2. 向量化执行和自动查询处理显著提升了分析性能。 该引擎以批处理而非逐行方式处理数据，并自动将大扫描查询重定向到列式表示，从而使扫描速度比传统方法快 200 倍。
  3. Spanner 可作为来自各种湖仓的 “冷” 分析数据的高速服务层。 通过反向 ETL，来自 Snowflake 或 Databricks 等平台的精选数据被移动到 Spanner 中，将其转化为可通过低延迟 API 访问的 “热” 数据，用于实时决策和 AI。
  4. 该引擎为现代 AI 和实时应用需求提供了类似于零 ETL 的体验。 通过与 Apache Iceberg 集成并提供与 BigQuery 的双向桥接，Spanner 确保 AI 智能体和应用能够大规模地即时访问最新的分析洞察。

💬 文章金句

  • Spanner 列式引擎通过在单一的可水平扩展系统中统一这两个领域，结束了这种权衡。
  • 列式引擎使用一种专门的存储机制，旨在通过将实时操作数据的扫描速度提高 200 倍来加速分析查询。
  • 通过将湖仓中精选、处理过的数据移动到 Spanner（这一过程称为反向 ETL），你可以将 “冷” 分析数据转化为 “热” 操作数据。
  • Spanner 现在是一个高性能引擎，能够以现代数字化体验所需的处理速度交付复杂的分析结果。
