深入剖析 Vercel Workflow DevKit：框架集成工作原理

12/15/2025, 1:00:00 PM

📌 一句话摘要

本文详细介绍了 Vercel 的 Workflow DevKit (WDK) 如何利用两阶段的构建时和运行时模式，通过编译器转换与各种框架集成，提供耐用工作流。

📝 详细摘要

本文解释了 Vercel Workflow DevKit (WDK) 框架集成的底层机制，强调 WDK 的设计旨在体现 Vercel 的开放 SDK 策略 (Open SDK Strategy)，允许开发者使用任何框架进行构建。文章指出，尽管框架特性多样，但所有集成都遵循一致的两阶段模式：构建时和运行时。在构建时阶段，WDK 将工作流和步骤函数编译成可执行处理程序，包括打包、输出配置和兼容性补丁。运行时阶段将这些处理程序作为 HTTP 端点暴露，具体实现因框架而异。一个关键组件是 WDK 的 SWC 编译器插件，它将代码转换为客户端、步骤和工作流模式。文章通过 SvelteKit 集成示例进行阐述，展示了 Vite 插件和 esbuild 如何处理转换和处理程序生成。它还讨论了 WDK 如何适应有和没有打包工具的框架（后者使用 Nitro），并应对了转换框架特定请求对象等挑战。此外，文章强调了热模块替换的重要性及其实现。最后，文章将框架分为基于文件的路由框架和 HTTP 服务器框架，演示了一个通用模式如何扩展，为广大开发者社区提供耐用工作流，而无需进行框架迁移。

💡 主要观点

  1. WDK 框架集成遵循一致的两阶段模式，尽管各框架特性各异。 构建时阶段通过编译工作流生成可执行的处理程序，而运行时阶段将这些处理程序作为 HTTP 端点暴露，从而简化了跨不同框架的集成。
  2. WDK 使用 SWC 编译器插件将代码转换为三种操作模式（客户端、步骤、工作流）。 这使得开发者只需编写一次代码，编译器便能自动生成所需的客户端、步骤处理程序和工作流处理程序输出，从而提高效率和一致性。
  3. WDK 通过适应各种框架的路由系统和构建机制，实现框架集成。 对于基于文件的路由框架，它将处理程序输出到特定目录；对于 HTTP 服务器框架，它使用 Nitro 挂载虚拟处理程序，从而实现广泛的兼容性。
  4. 热模块替换（HMR）对于快速的 WDK 开发者体验至关重要。 WDK 实现了热模块替换（HMR），允许工作流更改后即时反馈，无需重启服务器，这显著提升了开发者的生产力。
  5. WDK 广泛的框架支持使“耐用工作流”成为一个语言级概念。 通过与开发者首选环境集成，WDK 使采用耐用（有状态且弹性）工作流变得易于访问，而无需进行框架迁移，这与 Vercel 的开放 SDK 策略（Open SDK Strategy）相符。

💬 文章金句

  • 其核心在于，每一个框架集成都遵循相同的两阶段模式。
  • 这意味着你的代码只需编写一次，编译器就会自动生成客户端、步骤处理程序和工作流处理程序。
  • 核心模式在不同框架中保持不变。在构建时生成工作流处理程序。在运行时将这些处理程序注册为 HTTP 端点。只是实现细节会根据具体的框架特性有所不同。
  • 我们开发 Workflow DevKit (WDK) 的目标是让耐用性成为整个生态系统中的语言级概念。通过这些集成，我们离这个目标又近了一步。
