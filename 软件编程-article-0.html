Azure 容器存储 v2.0.0 正式发布：性能提升高达 7 倍

10/9/2025, 11:00:00 AM

📌 一句话摘要

Azure 容器存储 v2.0.0 正式发布 (GA)，通过 NVMe 集成、简化架构和面向 AKS 有状态工作负载的免许可费用策略，实现显著的性能提升。

📝 详细摘要

微软正式发布 Azure 容器存储 v2.0.0，标志着 Azure Kubernetes 服务 (AKS) 上的有状态工作负载迎来重大进展。新版本通过优化的本地 NVMe 磁盘集成和条带分割技术，实现了高达 7 倍的 IOPS 提升和 4 倍的延迟降低。这意味着在实际应用中，PostgreSQL 的每秒事务处理量可提高 60%，而与 Kubernetes AI 工具链操作器 (KAITO， Kubernetes AI Toolchain Operator) 集成后，通过在 GPU 节点本地缓存模型文件，大型语言模型的加载速度可提升 5 倍以上。在架构方面，v2.0.0 简化了用户体验，不再使用自定义存储池资源，而是完全依赖标准的 Kubernetes 存储类和 PVC。同时，系统资源占用也大幅降低，仅需一个轻量级操作器和 CSI 驱动组件即可运行，从而支持在更小规模的集群上进行部署。此外，新版本移除了捆绑的 Prometheus 操作器，转而通过标准端点暴露指标，以便与现有监控解决方案集成。在商业模式上，Azure 容器存储 v2.0.0 采用完全免费的免许可费用策略，无需支付每 GB 的服务费用。其核心组件已在 GitHub 上开源，鼓励社区贡献，并支持在 Azure 虚拟机上进行自托管的 Kubernetes 部署。微软此举将超高速本地 NVMe 与简化、免费的管理层相结合，使其产品与 AWS 和 Google Cloud 的标准 CSI 驱动方案形成差异化优势。

💡 主要观点

  1. 通过优化的 NVMe 集成，显著提升有状态工作负载的性能。 Azure 容器存储 v2.0.0 通过 NVMe 条带分割技术，实现高达 7 倍的 IOPS 提升和 4 倍的延迟降低，从而显著提升数据库和 AI/ML 应用的性能。具体而言，NVMe 条带分割通过将数据分散存储在多个 NVMe 磁盘上，实现更高的并发读写性能。
  2. 简化的架构和用户体验与标准的 Kubernetes 模式保持一致。 移除自定义存储池，转而依赖标准的 Kubernetes 存储类和 PVC，并采用资源占用更低的操作器，从而增强易用性，降低复杂性。
  3. 采用全新的免许可费用商业模式和开源策略，降低了采用门槛。 取消服务费用并开源核心组件，降低了使用门槛，鼓励社区贡献和更广泛的部署。

💬 文章金句

  • 与之前版本相比，采用 NVMe 条带分割技术的 Azure 容器存储 v2.0.0，其 IOPS 提升高达 7 倍，延迟降低 4 倍。
  • 在基于微软 PostgreSQL for AKS 部署指南进行的测试中，PostgreSQL 的每秒事务处理量提升 60%，延迟降低超过 30%。
  • 通过在 GPU 节点上自动配置 NVMe 条带卷，KAITO 能够在本地缓存模型文件，从而将模型加载速度提升至比使用临时操作系统磁盘快 5 倍以上。
  • 用户现在只需与标准的 Kubernetes 存储类和 PVC 进行交互，完全符合 Kubernetes 的常用模式。
  • Azure 容器存储 v2.0.0 采用完全免费的商业模式。
