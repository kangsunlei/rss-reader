产品经理也能“开发”需求？淘宝信息流从需求到上线的 AI 端到端实践

10/13/2025, 12:32:00 AM

📌 一句话摘要

淘宝信息流通过 AI 驱动的 WaterFlow 平台，实现产品需求端到端自动化开发，大幅提升迭代效率，部分需求甚至可由产品经理“开发”。

📝 详细摘要

文章详细介绍了淘宝推荐信息流业务面临的需求多、技术栈杂、协作效率低等痛点，导致需求上线周期长。为解决这些问题，团队推出了 AI 驱动的 WaterFlow 平台。该平台通过 Central Agent 将产品经理的自然语言需求转化为结构化的需求文档和详细开发任务，再由 Code Agent（Codex）在云端沙盒环境中自动生成多端代码。Codex 结合编程领域大模型与系统、用户、代码上下文，精确指导开发。WaterFlow 已成功落地 30+需求，将上线周期从平均一周缩短至两天，自动生成 5.4 万行代码，显著提升了协同和开发效率，甚至使部分需求可由产品经理直接完成。未来计划进一步完善评估机制和 Agent 的记忆功能，以应对更复杂的开发场景。

💡 主要观点

  1. WaterFlow 通过 Central Agent 将自然语言需求转化为结构化任务，解决了产品与开发间的沟通鸿沟。 利用大模型能力，产品经理能以自然语言输入需求，系统自动生成需求文档和详细开发任务，极大减少了传统“N 次握手”的沟通成本和信息失真。
  2. Code Agent (Codex) 在云端沙盒环境实现多技术栈代码自动化生成，大幅提升开发效率。 Codex 结合编程领域大模型与系统、用户、代码上下文，在安全隔离的云端环境高效完成前端、后端、客户端及 DX 等多端代码开发，显著缩短了需求上线周期。
  3. WaterFlow 成功赋能产品经理参与部分需求“开发”，推动了团队协作模式的创新。 通过简化开发流程和提供开箱即用的 AI 编程工具，使得非技术背景的产品经理也能直接执行部分简单需求的开发，实现了跨职能协作的突破。

💬 文章金句

  • WaterFlow------一套 AI 驱动的端到端开发新实践，让部分需求两天内上线，甚至产品经理也能'自产自销'需求。
  • 一个信息流需求从开发到测试，再到最终上线，除关键决策外均由大模型自动完成；产物除了代码，还有 PRD、技术方案、测试报告、数据报告等，作为下一个需求和答疑的上下文。
  • 我们正在进入「软件 3.0」时代，自然语言在成为新的编程接口，大模型会完成剩下的工作。
  • 提示词（Prompt），告诉模型'怎么做、做到什么样'的指令；上下文（Context），告诉模型'根据什么来做'的材料；两者最终都会被拼成同一段输入给模型。
  • 如果为 Codex 分配一些新人工程师或实习生在提供充分、清晰的任务下能够完成的需求，那么 Codex 完成的效果就很好。
