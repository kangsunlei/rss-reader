Databricks 的高可用特性标志系统

1/21/2026, 8:00:00 PM

📌 一句话摘要

本文详细介绍了 Databricks 内部的特性标志平台 SAFE，解释了它如何在庞大的多云架构中实现高可用性和亚毫秒级延迟。

📝 详细摘要

文章探讨了 SAFE，这是 Databricks 自研的特性标志和实验平台，旨在将代码部署与功能启用解耦。面对在 AWS、Azure 和 GCP 上管理 25，000 个活跃标志的挑战，Databricks 构建了 SAFE，以提供亚毫秒级的评估延迟（p95 约 10μs）并处理每秒超过 3 亿次的评估。该系统与基础设施深度集成，采用基于 Jsonnet 的配置模型和 GitOps 工作流，标志变更需要经过同行评审的 Pull Request。这通过结构化模板和自动化放量计划确保了“默认安全”的发布，使工程师能够快速缓解故障并在快速扩展的同时保持高度的服务稳定性。

💡 主要观点

  1. 将二进制版本发布与功能启用解耦对运维稳定性至关重要。 通过将部署与激活分离，团队可以进行渐进式发布和即时回滚，而无需重新部署代码，从而显著减小故障的影响范围。
  2. SAFE 实现了极致性能，在每秒 3 亿次评估下达到 10μs 的 p95 延迟。 为了支持多云环境下对延迟敏感的生产服务，系统必须在本地近乎瞬时地评估标志，以避免成为请求路径中的瓶颈。
  3. 基于 GitOps 的工作流和同行评审确保了标志管理的治理与安全。 标志配置以 Jsonnet 文件形式存储在单体仓库中；通过 UI 进行的更改会生成 Pull Request，在应用任何动态配置之前强制执行人工监督和自动化检查。
  4. 规范化的模板为工程师提供了“默认安全”的常规功能发布流程。 该平台提供结构化的放量计划和阶段，减轻了开发者的认知负担，并防止从内部测试到全球发布过程中的常见错误。

💬 文章金句

  • SAFE 的核心价值主张是提高 Databricks 的稳定性和运维态势，因此几乎所有其他需求都源于此。
  • 在峰值时，SAFE 每秒运行超过 3 亿次评估，同时保持约 10μs 的标志评估 p95 延迟。
  • SAFE 启动时的“北极星”目标是实现服务二进制发布与功能启用的完全解耦。
  • 当用户从 UI 更改标志时，该更改的输出是一个需要至少由另一名工程师评审的 Pull Request。
  • 成功实现我们的扩展和安全目标，需要与我们的基础设施数据模型、服务框架和 CI 系统进行深度集成。
