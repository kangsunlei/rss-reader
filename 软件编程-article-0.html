Cloudflare SASE 平台：基于主机名的简单安全出站策略

7/7/2025, 2:00:01 PM

📌 一句话摘要

Cloudflare SASE 平台引入基于主机名的出站策略，利用创新的“合成 IP”机制，解决了在网络第四层（L4）策略中使用网络第七层（L7）应用层信息的问题。

📝 详细摘要

本文详细介绍了 Cloudflare 的新出站策略，该策略允许客户根据主机名、域名、内容类别和应用程序来控制其组织的互联网流量。以前，此类策略依赖于目标 IP 地址，由于动态 IP 更改以及客户无法控制外部服务的 IP，因此带来了挑战。核心创新在于“合成 IP”机制：Cloudflare 网关的 DNS 解析器拦截 DNS 查询，并使用临时的内部 IP 地址（“初始解析 IP”）进行响应，然后使用此合成 IP 在网络第四层（L4）执行出站策略。在应用策略之后，网关会在转发流量之前将合成 IP 重写为实际的目标 IP。这种方法实现了基于网络第七层（L7）主机名信息，在网络第四层（L4）执行策略。本文还解决了确保 DNS 和网络流量落在同一 Cloudflare 服务器上的工程挑战，目前通过 WARP 客户端、PAC 文件和浏览器隔离提供支持，并计划提供更广泛的接入支持。

💡 主要观点

  1. 新的出站策略可以使用主机名和应用程序对出站流量进行精细控制。 Cloudflare 更新后的 SASE 平台现在支持基于主机名、域名、内容类别和应用程序的出站策略，与以前基于 IP 的规则相比，简化了策略管理并增强了安全控制。
  2. “合成 IP”机制弥合了网络第四层（L4）策略执行和网络第七层（L7）主机名信息之间的差距。 通过使用从 DNS 查询派生的临时内部 IP 地址，Cloudflare 网关可以基于应用层（网络第七层（L7））主机名在传输层（网络第四层（L4））执行出站策略，这是一项重大的工程挑战。
  3. 确保 DNS 和网络流量落在同一服务器上对于该机制的功能至关重要。 由于 Cloudflare 的分布式架构以及服务器之间缺乏共享状态，因此 DNS 和网络流量必须路由到同一服务器，以便“合成 IP”映射能够正常工作，目前由特定的客户端接入点支持。

💬 文章金句

  • 今天，我们将深入研究此任务的第一个里程碑，我们最近在公开测试版中发布了该里程碑：按主机名、域名、内容类别和应用程序划分的出站策略。
  • 问题在于，出站策略必须在网络第四层（L4）（传输层）而非网络第七层（L7）（应用层）进行评估。为什么？因为出站策略用于选择网络流量的源 IP 地址，并且 Cloudflare 网关必须在创建与外部服务的连接*之前*选择流量的源 IP 地址。
  • 我们利用了 Cloudflare 网关也运行其自己的 DNS 解析器这一事实。每次最终用户想要访问目标主机名时，网关解析器都会先收到该主机名的 DNS 查询，然后再将其网络流量发送到目标主机名。
  • 我们通过确保 DNS 流量和网络流量落在同一 Cloudflare 服务器上来解决此问题。特别是，我们要求 DNS 流量进入与网络流量相同的隧道，以便两个流量流都落在同一 Cloudflare 服务器上。
