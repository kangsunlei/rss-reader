Meta 发布 React 19.2，引入 Activity API、缓存信号和 SSR 增强

10/8/2025, 7:00:00 AM

📌 一句话摘要

React 19.2 引入了 Activity、useEffectEvent 和 cacheSignal 等新 API，同时显著增强了服务器端渲染，以改进 UI 控制和性能。

📝 详细摘要

Meta 的 React 19.2 版本带来了一系列新功能和改进，主要侧重于增强 UI 控制和服务器端渲染能力。主要新增功能包括 `Activity` 组件，允许开发人员管理具有“可见”和“隐藏”模式的用户界面组件，以实现状态保持和预渲染。`useEffectEvent` hook 通过将事件逻辑与依赖项分离，解决了 `useEffect` 中的一个常见挑战，防止了不必要的重新运行。对于 React 服务端组件，`cacheSignal` 提供了一种管理缓存数据生命周期的方法。此外，此更新引入了 `Partial Pre-Rendering` 并改进了用于 SSR 的 `Suspense` 边界批处理，从而显著提升了初始加载速度。文章还提到了社区对 `useEffectEvent` 的反馈，并指出增加了对 Web Streams 的支持，但建议使用 Node Streams 以获得更好的性能。

💡 主要观点

  1. 新的 Activity 组件提供了对用户界面组件的精细控制，使其能够进行预渲染和状态保持。 开发人员现在可以有条件地渲染或暂停 UI 部分，即使在隐藏时也能保持其状态，从而带来更流畅的用户体验和更有效的组件管理。
  2. useEffectEvent hook 将事件逻辑与 useEffect 依赖项分离，简化了 effect 并防止了不必要的重新运行。 这个 hook 通过允许 useEffectEvent 中引用的值在更改时不触发重新运行来解决一个长期存在的挑战，从而提高了 effect 的稳定性并降低了依赖项数组的复杂性。
  3. 新的 `cacheSignal` API 可以在 React 服务端组件中精确管理缓存数据的生命周期。 当 `cache()` 生命周期结束时，它会提供一个 `AbortSignal`。这使开发人员能够控制清理正在进行的操作，并确保在服务器端渲染上下文中实现有效的资源管理。
  4. 像 Partial Pre-Rendering 和批处理 Suspense 边界等显著的 SSR 增强功能提高了初始加载性能。 这些功能使应用程序的某些部分可以在服务器端预先渲染，并在以后恢复动态内容的渲染，并确保内容一起显示，从而提升用户体验。

💬 文章金句

  • 新组件支持可见和隐藏模式，使其能够更好地控制用户界面组件。Activity 将使开发人员能够在对用户隐藏组件时预先渲染组件。它在隐藏时保持其状态。
  • 一个新的 useEffectEvent hook 提供了一种将 useEffect 逻辑的事件部分分离到单独的 hook 中的机制。当开发人员有一个使用某个值但不应在该值更改时重新运行的 effect 时，这很有用。
  • React 19.2 还引入了 cacheSignal，它提供了在 React 服务端组件中知道 `cache()` 生命周期何时结束的能力。
  • 19.2 中添加了 Partial Pre-Rendering。应用程序的某些部分可以在服务器端预先渲染，然后在以后恢复渲染以添加动态内容，从而提高初始加载响应速度。
  • Suspense 边界现在将在服务器渲染时进行批处理，因此内容会一起显示，而不是在不同的时间显示。
