不用 Python 也能搞 AI Agent —— 一个纯 Go 实现的 SDK 和 Agent 平台

6/26/2026, 1:58:49 PM

📌 一句话摘要

作者将 OpenAI 的 Agents Python SDK 移植为纯 Go 实现，并构建了一个开箱即用的 Agent 平台，展示了 Go 在 AI Agent 领域的可行性与实际体验。

📝 详细摘要

本文介绍了一个纯 Go 实现的 AI Agent SDK 和配套 Web 平台。作者受 OpenAI openai-agents-python 启发，利用 Claude / Claude Code 将核心逻辑移植为 Go 版本，并在此基础上构建了单二进制部署、内嵌前端的 agents-server 演示项目。文章详细列出了已实现的功能：多 Agent 协作与自动 Handoff、MCP Server（Stdio / Streamable HTTP）、代码沙箱（本地/Docker/SSH）、输入输出 Guardrails（正则/长度限制/自定义）、Human-in-the-loop 人工审批、会话分叉与置顶、流式 WebSocket 输出、全链路 Tracing、请求重试/模型降级/多 Provider 路由、Skills 扩展（SKILL.md 格式）、ChatGPT 订阅登录以及 Primer 风格暗色 UI。作者分享了实践感受：Go 的并发模型天然适合多工具并行调用，类型系统使 Agent 状态流转清晰，但 JSON Schema 反射不如 Python 的 Pydantic 方便。前端部分为保持单二进制采用无构建步骤的裸 JSX + go:embed 方式，作者自嘲为野路子写法。整体内容为一个可验证的开源项目，适合对 Go + AI Agent 感兴趣的开发者参考。

💡 主要观点

  1. 用 Go 实现 AI Agent SDK 完全可行，并发模型适合多工具并行调用。 作者将 OpenAI Agents Python SDK 移植为 Go 版，验证了 Go 在 Agent 场景下的可用性，并指出其并发模型天然适配多工具并行执行的需求。
  2. Go 的类型系统使 Agent 状态流转清晰，但 JSON Schema 反射不如 Python。 类型系统有助于 Agent 流程的确定性管理，但处理 JSON Schema 时 Go 的反射 API 使用体验不如 Python 的 Pydantic 库。
  3. 实现的功能覆盖了主流 Agent 平台的核心能力，包括多 Agent 协作、MCP、Guardrails、Human-in-the-loop 等。 从自动 Handoff 到代码沙箱、全链路 Tracing，项目提供的功能列表较为完整，适合作为 Go 生态中 Agent 基础设施的参考实现。
