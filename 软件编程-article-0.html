claude code 实践心得：飘才是最大的敌人

6/17/2026, 5:58:19 PM

📌 一句话摘要

本文基于实际使用经验，指出当前 AI 编程工具和 multi-agent 框架的核心问题在于「飘」——模型在长链路中逐渐偏离原始意图，并批评了过度自动化、让程序员完全不用动手的叙事方向。

📝 详细摘要

作者以 claude code 为主要实践对象，分享了对当前 AI 编程工具和 multi-agent 框架的真实感受。文章指出，虽然市面上不断涌现宣称能自动完成多 agent 协作的框架和产品，但实际体验往往「等几个小时，写出来的 UI 看起来对，内部是一坨」。作者认为核心问题在于模型会「飘」——在长链路中逐步偏离原始意图，类似传声筒效应，多 agent 的上下游关系会放大这一问题。同时，作者批评了「程序员完全不用动」的叙事方向，认为程序员需要透明和可控，而非黑盒自动化，并类比低代码平台在公司层面的失败经验。

💡 主要观点

  1. 当前 multi-agent 框架的实际体验与宣传差距大。 作者指出，虽然框架宣传「启动一堆机器人帮你干活」，但实际使用中等待时间长，输出结果表面看起来对但内部质量差，存在严重的「飘」的问题。
  2. AI 编程的核心问题是模型在长链路中偏离原始意图。 作者用「传声筒」比喻，说明单 agent 可能飘 1 步，多 agent 上下游协作后可能飘到 100 步开外，导致最终结果与初始需求完全对不上。
  3. 程序员需要透明和可控，而非黑盒自动化。 作者认为程序员不喜欢「完全不用动」的感觉，因为天上不会掉馅饼。低代码平台在公司层面失败的经验也说明，缺乏透明度的自动化最终会让开发者自己承担改 bug 的成本。

💬 文章金句

  • 我觉得现在 ai 编程最大的问题就是模型会飘，就跟游戏传声筒一样，最后一个人复数出来的话跟第一个人说的完全对不上。
  • 程序员是不喜欢这种感觉的，程序员是喜欢透明的。因为我们知道天上不会掉馅饼。
