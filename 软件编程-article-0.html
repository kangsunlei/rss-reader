自主编码代理：Codex 使用示例

📌 一句话摘要

本文通过分析执行日志，展示了自主编码代理在 UI 任务中的尝试。

📝 详细摘要

本文探讨了自主编码代理的能力，记录了 OpenAI Codex 修复内部应用程序中一个轻微 UI 问题的具体尝试。作者提供了代理日志条目的详细逐步分解，展示了其信息收集、使用 `grep` 等命令行工具进行代码搜索、识别相关代码片段以及尝试代码修改和测试等过程。日志揭示了代理在查找相关代码和识别必要更改方面的进展，但也揭示了其局限性，例如重复的搜索模式以及由于环境约束（例如离线的 Yarn 依赖和测试环境）导致本次尝试未能完成任务。该分析提供了对这些新兴自主编码工具的内部运作和当前局限性的宝贵见解，将它们与监督代理区分开来，并强调了它们在较小、不紧急的任务中的潜在用例。

💡 主要观点

  1. 自主代理会执行详细的搜索过程，但有时存在重复步骤。 日志显示代理反复使用 `grep` 等搜索工具，并遇到相同的问题（例如，`node_modules` 目录中大量不相关的搜索结果），表明在保留上下文或优化其搜索策略方面存在局限性。
  2. 代理可以识别可重用于任务的相关现有代码。 Codex 成功找到了一个现有的 `toReadableText` 函数，该函数与所需的逻辑非常接近，这表明它有能力理解代码库中的相关代码逻辑。
  3. 环境或设置问题可能会严重阻碍代理的进展。 由于环境约束（离线），代理在处理 Yarn 依赖和执行测试时遇到了困难，这突出了在实际开发环境中部署这些代理所面临的环境配置问题。
