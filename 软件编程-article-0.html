从传统架构到 Cloudflare One

3/16/2026, 1:00:08 PM

📌 一句话摘要

本文提出了一个战略框架，旨在帮助大型组织采用分层、风险感知的方法，从传统 VPN 迁移到 SASE/零信任架构。

📝 详细摘要

本文探讨了“大爆炸式”迁移风险——这是零信任采纳的主要障碍，即组织担心在进行大规模网络切换时出现运营停滞。Cloudflare 与 CDW 合作，提出了一个结构化路线图，将网络迁移视为一个应用现代化项目。其核心策略是使用 Cloudflare Access 和 Tunnel “封装”传统应用，在不重写代码的情况下提供现代安全（MFA/SSO）。文章详细介绍了严格的迁移前审计流程、基于迁移工作量的四层应用分类模型，以及一个强调传统系统与现代系统并存以确保安全过渡的三阶段推广计划。

💡 主要观点

  1. 组织应避免高风险的“大爆炸式”迁移，而应采用分层、风险感知的方法，将网络变更视为应用现代化项目。 这种方法并非一次性切换所有连接，而是根据技术复杂性对应用进行分类，优先迁移现代应用以建立势头，同时在受控的后期阶段处理复杂的传统系统，以最大程度地减少停机时间。
  2. 传统应用可以通过使用 Cloudflare Access 和 Tunnel “封装”它们来实现现代化，从而在无需任何代码更改的情况下提供基于身份的安全。 通过创建仅出站连接并应用边缘策略，组织可以将传统应用从公共互联网中隐藏起来，并在任何流量到达内部服务器之前强制执行 MFA 和设备健康检查。
  3. 全面的迁移前审计至关重要，它能帮助识别身份提供商、映射后端依赖关系并对持久会话进行压力测试，以防止服务中断。 记录隐藏的 API 调用和数据库依赖关系，可确保基于服务令牌的连接得以维持，从而防止在没有适当架构准备的情况下应用最小权限访问时常发生的故障。
  4. 将应用堆栈分为四个不同的层级，使 IT 领导者能够设定切合实际的实施时间表，并估算每个应用所需的迁移工作量。 层级范围从仅需 1-3 小时工作量的现代 SaaS 应用，到可能需要数天工作甚至需要修改后端代码以支持双向连接的复杂传统企业系统。
  5. 优先考虑共存而非立即替换的分阶段推广策略，在向零信任过渡期间提供了安全网和明确的回滚路径。 通过保持一个双客户端时期，让用户同时运行传统 VPN 和 Cloudflare Access，组织可以确保更轻松的最终用户过渡，并降低在最终切换期间运营停滞的风险。

💬 文章金句

  • “大爆炸式”迁移风险是零信任采纳的最大单一障碍。
  • 我们不只是迁移您的底层架构——我们确保您的传统技术债务在不造成停机的情况下，转化为现代化、敏捷的安全态势。
  • 传统应用现代化……使我们能够在不实际重写旧应用代码的情况下，实现其安全态势的现代化。
  • 迁移到单一控制平面，能让安全团队不再成为瓶颈。
  • 目标不仅仅是将您的应用迁移到云端。而是要确保当您到达那里时，您的环境更具弹性、更透明，并且更难被攻破。
