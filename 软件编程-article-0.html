Spring gRPC 1.0.0 的后续步骤

11/11/2025, 12:00:00 AM

📌 一句话摘要

本文详细介绍了即将发布的 Spring gRPC 1.0 版本，以及其与 Spring Boot 4.0 的临时集成，并阐述了未来将自动配置完全合并到 Spring Boot 4.1 中以简化迁移流程的计划。

📝 详细摘要

作为“迈向 GA（正式发布）”系列文章的一部分，本文提供了 Spring gRPC 与 Spring Boot 集成的最新进展。最初计划将 Spring gRPC 的自动配置合并到 Spring Boot 4.0 的方案有所延迟。作为替代方案，Spring gRPC 项目自身增加了对 Spring Boot 4.0 的支持，并计划发布 1.0 版本。在此过渡期间（Spring gRPC 1.0 与 Spring Boot 4.0），用户仍将使用 `org.springframework.grpc` 作为 BOM 和起步依赖的 groupId，主要工作是更新版本。自动配置类的少量包名更改可能会影响部分直接用户。展望未来，自动配置预计将合并到 Spring Boot 4.1 中，届时将不再需要单独的 Spring gRPC BOM，用户只需更新起步依赖的依赖坐标即可。文章还指出，Spring gRPC 1.0 的自动配置和起步依赖将在发布后立即被弃用，这标志着未来将转向 Spring Boot 4.1 的集成解决方案，旨在最大程度地降低未来迁移的风险。

💡 主要观点

  1. Spring gRPC 1.0 将作为独立项目提供对 Spring Boot 4.0 的即时兼容性。 由于自动配置合并到 Spring Boot 4.0 的计划有所延迟，Spring gRPC 1.0 将提供直接支持，确保用户无需等待完全集成即可利用 gRPC 和最新的 Spring Boot 版本。
  2. 从 Spring gRPC 0.x 迁移到 1.0 旨在最大程度地减少中断。 Spring gRPC 0.x 的现有用户只需更新依赖管理中的版本即可，从而简化升级过程并减少所需的代码更改。
  3. 计划在未来将完整的 Spring gRPC 自动配置集成到 Spring Boot 4.1 中。 未来，通过消除对单独的 Spring gRPC BOM 的需求，可以进一步简化依赖管理，使 gRPC 更紧密地与核心 Spring Boot 生态系统保持一致。

💬 文章金句

  • 好消息是，我们已经转而为现有的 Spring gRPC 项目增加了对 Spring Boot 4 的支持，并计划在未来几天内发布 1.0 版本。
  • 对于过渡期（Spring gRPC 1.0 和 Spring Boot 4.0），用于使用 Spring gRPC 的推荐机制——BOM、自动配置和起步依赖，将保留在其当前的坐标，即 groupId 为 `org.springframework.grpc`。
  • 一旦自动配置合并（预计在 Spring Boot 4.1 中），您将不再需要单独的 BOM，而只需更改起步依赖在依赖管理中的依赖坐标。
  • Spring gRPC 中的自动配置和起步依赖将在发布时立即被弃用。这是故意的，无需过度关注。
  • 对于已经使用 Spring gRPC 0.x 版本的项目，受到的影响应该很小。
