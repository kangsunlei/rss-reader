AI Token Jacking 攻击窃取 API 密钥，导致近百万美元损失

8/15/2026, 10:00:00 AM

📌 一句话摘要

本文报道 AI Token Jacking 攻击通过窃取 API 密钥非法消耗模型服务，单次事件损失近百万美元，并给出防御建议。

📝 详细摘要

文章基于 Unit 42 与 Palo Alto Networks 的报告，介绍 AI Token Jacking 攻击模式：攻击者通过钓鱼、恶意软件、暴露的代码仓库或投毒的 npm 包窃取 AI API 密钥，再利用中转站（relay service）转售或自动化消耗付费算力，导致受害者账单急剧飙升，单案损失近 100 万美元。文章指出 AI 服务按用量计费且缺乏实时异常拦截，给攻击者留出了操作窗口。防御层面建议设置消费上限与用量告警、轮换高权限账户、用短时效 bearer token 替代长期密钥、审查依赖项与构建流水线，并扫描代码仓库中的密钥泄露。

💡 主要观点

  1. AI Token Jacking 通过窃取 API 密钥非法消耗模型服务，单案损失近百万美元。 攻击者利用钓鱼、恶意软件、暴露仓库或投毒 npm 包获取凭证，再通过中转站转售或自动化调用，AI 服务按 token 计费且缺乏实时拦截，费用在数分钟内急剧扩大。
  2. 中转站是连接被盗凭证与黑市消费的关键基础设施。 中转站轮换凭证、路由请求并以低价访问为卖点，审查事件中此类基础设施每天产生数千万次 API 调用，将费用推高至数十万美元。
  3. 投毒 npm 包是尤为危险的供应链攻击途径。 恶意包可从开发环境窃取凭证并污染后续代码发布，同时针对开发人员、云和 AI 凭证，扩大可用密钥池。
  4. 防御核心在于消费控制、密钥轮换与供应链审查。 设置用量上限与异常告警、用短时效 bearer token 替代长期密钥、审查依赖项与构建流水线、扫描代码仓库中的密钥泄露，是降低爆炸半径的关键措施。
