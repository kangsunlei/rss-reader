如何在物理隔离环境中部署 Elastic Agent

8/29/2025, 5:10:09 PM

📌 一句话摘要

本文介绍了 `artifacts-bundler`（离线制品打包工具），该工具可自动下载、打包和本地提供 Elastic Agent 和安全制品，以便在物理隔离环境中进行部署，从而解决手动操作的难题。

📝 详细摘要

本文解决了在物理隔离或受限网络环境中部署和更新 Elastic Agent、Endpoint Security、APM Server 和 Fleet Server 的重大挑战。传统上，此过程涉及繁琐的手动下载、通过 USB 驱动器的物理传输以及每次 Elastic 发布时的重复性任务。为了克服这个问题，Elastic 高级工程师开发了 `artifacts-bundler`（离线制品打包工具）。这个开源工具可以自动从 Elastic 官方存储库批量下载 Elastic Stack 组件，将其智能地打包到带有时间戳和版本控制的软件包中，其中包含 manifest 文件，并且可以选择创建一个独立的 NGINX 容器以进行本地分发。本文详细介绍了两种主要的部署方法：用于裸金属服务器的 bundled tarball 和用于容器化环境（包括 Kubernetes）的预构建 NGINX Docker 镜像。它提供了设置本地制品服务器并在 Kibana 中配置 Elastic Fleet 和 Endpoint Security 策略以利用此内部镜像的分步说明，从而确保所有 Agent 二进制文件和安全更新都在本地获取。该解决方案显著简化了政府、医疗、关键基础设施等对安全性要求较高的行业的部署流程，将繁琐易错的手动流程转化为高效、可复用的自动化流程。

💡 主要观点

  1. `artifacts-bundler` 自动执行物理隔离环境中 Elastic Agent 的部署。 该工具消除了手动下载和打包 Elastic Agent、Endpoint Security、APM 和 Fleet Server 制品的过程，从而将原本耗时且容易出错的任务转化为自动化的单命令操作。
  2. 该解决方案为不同的基础设施需求提供了灵活的部署选项。 它为裸金属服务器提供可移植的 tarball，并为容器平台（包括 Kubernetes）提供可部署的独立 Docker 镜像，以满足各种环境的需求。
  3. 确保在隔离网络中持续安全地更新 Elastic 组件。 通过建立本地制品镜像，该工具允许 Fleet 和 Endpoint Security 在内部获取必要的二进制文件和签名，从而在无需外部网络访问的情况下，维护系统完整性和合规性。

💬 文章金句

  • 原本简单的 Agent 部署变成了后勤噩梦，需要手动下载 artifact，使用 USB 驱动器，并为每个 Elastic 版本重复操作。
  • `artifacts-bundler` 工具可以自动完成下载、打包和提供 Elastic Stack 组件以用于离线环境的整个过程。
  • 这种方法在传输阶段的优势非常明显。您不再需要管理数十个单独的文件（我过去需要手动完成），而是只需管理一个独立的软件包，即可在网络上或通过 USB 驱动器等物理介质在不同环境之间传输。
  • 重要提示：ETag 头部配置对于 Elastic Endpoint 功能是**强制性的**。如果没有 ETag，Elastic Endpoint 无法确定全局 artifacts 何时更新，并且在有新版本可用时不会下载新版本。
  • artifacts-bundler 不仅仅代表一种技术解决方案；它还展示了我们在 Elastic 社区中如何识别现实世界的挑战并构建实用的解决方案。
