摆脱 IP 依赖：使用密码学验证机器人和代理流量

5/15/2025, 2:00:01 PM

📌 一句话摘要

提出利用 HTTP 签名和 mTLS 等密码学方法，通过传统 IP/用户代理实现可靠的机器人/代理身份验证。

📝 详细摘要

这篇来自 Cloudflare 的文章指出了当前机器人验证方法的局限性，例如容易被欺骗的用户代理和不可靠的 IP 地址。Cloudflare 引入了两个密码学提议，以使合法的机器人和代理能够向网站源站验证自己的身份：HTTP 消息签名（基于 RFC 9421）和利用新的 TLS 标志（`req mTLS`）的请求 mTLS。Cloudflare 作为反向代理，可以代表站点所有者验证这些签名。HTTP 消息签名在 HTTP 层工作，使用签名头部进行签名，并且由于易于采用而受到青睐，并提供了代码示例。请求 mTLS 在 TLS 层运行，并且需要用于条件客户端证书请求的机制。目标是建立一种公共、标准的方式，使合法的机器人能够证明自己的身份，从而使站点所有者能够更有效地管理自动化流量。

💡 主要观点

  1. 传统的机器人验证方法存在缺陷。 用户代理很容易被欺骗，并且 IP 地址由于共享和更改而不可靠，这使得自动化流量的受信任身份识别变得困难。
  2. 密码学签名提供了一种可靠的机器人身份验证机制。 HTTP 消息签名标准化了使用公钥签名请求，从而在 HTTP 层为合法的代理提供可验证的身份，从而提高了信任度。
  3. 使用 TLS 标志的请求 mTLS 实现了条件身份验证。 `req mTLS` TLS 标志允许客户端声明自己支持 mTLS，源服务器可以安全地请求客户端证书，避免普通用户受到影响。
  4. 标准化对于广泛采用至关重要。 参与 IETF 标准组织可确保对诸如此类的新身份验证机制的广泛行业支持和互操作性。

💬 文章金句

  • Cloudflare 历史上一直依靠用户代理头和 IP 地址这两个主要信号来验证来自其他类型的自动化流量的合法 Web 爬网程序。
  • 通过使用完善的密码学技术，我们提出了一种更好的机制，供合法的代理和机器人声明自己的身份，并为站点所有者提供更清晰的信号来决定允许哪些流量。
  • 今天，我们推出了两个提案——HTTP 消息签名和请求 mTLS——供合法的机器人验证自己的身份，并供客户源站识别它们。
  • HTTP 消息签名是一种定义请求发送者的密码学身份验证的标准。从本质上讲，这是一种密码学上合理的方式来说：“嘿，是我！”
