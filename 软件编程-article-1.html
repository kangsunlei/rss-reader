从提交到生产环境：使用 GitHub Actions 、 Argo CD 、 Helm 和 Kargo 进行 GitOps 晋升实践

6/5/2025, 7:34:08 PM

📌 一句话摘要

一本实践指南，演示如何使用 GitHub Actions 、 Argo CD 、 Helm 和 Kargo 构建从提交到生产环境的 GitOps 晋升流水线。

📝 详细摘要

本文提供了一份实用的分步指南，教你如何基于 GitOps 原则构建一个生产级的 CI/CD 流水线。本文使用一个名为 Craftista 的真实多语言微服务应用，演示了如何为多环境部署组织代码仓库和 Kubernetes 清单。本指南将 GitHub Actions 用于 CI （构建、测试、标记），并将其与由 Argo CD 管理的 GitOps 工作流程集成，实现持续部署；同时使用 Kargo 自动化应用在开发、预发和生产环境之间的晋升。它解释了 GitOps 的核心原则，介绍了每个工具的作用，并强调了 Kargo 如何通过处理晋升逻辑和审批来补充 Argo CD 的功能。虽然重点放在本地 Minikube 环境的设置，但文中提出的模式和实践对于实现健壮的 GitOps 流水线具有重要的实践价值。

💡 主要观点

  1. 使用多语言微服务应用构建生产级的 GitOps 流水线。 本指南使用 'Craftista' 项目演示端到端 CI/CD 和 GitOps ，提供了比典型的 'hello world' 演示更真实、更复杂的示例。
  2. 为微服务 GitOps 设置优化组织代码仓库和 K8s 清单。 提倡多仓库结构，并以清晰且可伸缩的方式组织 Argo CD 清单、环境配置值、Kargo 配置和 Helm Charts 。
  3. 利用 Kargo 自动化环境之间的应用晋升工作流程。 解释了 Kargo 如何与 Argo CD 集成，基于制品和策略管理晋升步骤（ Dev -> Staging -> Prod ），从而减少手动干预或定制脚本的需求。

💬 文章金句

  • 准备好超越 'hello world' ，从零开始构建生产级流水线了吗？
  • GitOps 是一种现代化的方式，使用 Git 作为主要事实来源来管理应用和基础设施。
  • 在真正的 GitOps 工作流程中，** Git 是你的控制平面**，“环境”不应该以分支的形式存在。
  • Kargo 通过监视仓库（ Git 、镜像、 Helm ）的变化来管理晋升，并向 Git 仓库进行必要的提交，而 Argo CD 负责协调。
  • Kargo 不取代 Argo CD ，而是对其进行扩展。
