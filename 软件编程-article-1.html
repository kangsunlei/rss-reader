直播回顾 | 企业开始真正用 AI 后，安全该怎么测？

10/1/2026, 10:00:00 AM

📌 一句话摘要

本文探讨了企业在引入 AI 模型和 Agent 后，安全测试重心如何从单一的模型输出转向数据、权限、第三方服务及执行链路的可追溯。

📝 详细摘要

本文是 AccessB 线上研讨会的精华回顾，分析了企业在将大模型及 Agent 接入业务后面临的新安全挑战。核心观点认为，安全风险不再仅限于“模型回答错误”，而是扩展到敏感数据泄露、Prompt 注入、第三方 API 风险以及 Agent 工具调用越界等问题。文章指出，传统的 Web 安全测试难以发现 AI 系统多轮交互中的行为偏移和权限访问问题，建议企业从高风险业务场景入手，通过对模型、数据、权限及执行链路的深度测试，逐步构建完整的 AI 安全评测体系。

💡 主要观点

  1. 风险面发生范式转移 当 AI 或 Agent 真正接入业务，安全关注点从单纯的“模型输出正确性”扩展到了数据隐私、权限控制、第三方服务信誉以及执行动作的安全。
  2. 传统安全测试的局限性 传统 Web 测试侧重接口和单次输入输出，无法捕捉 AI 系统在多轮对话中的行为偏移、上下文变化以及在复杂业务链路中的越权访问问题。
  3. Agent 引入带来的边界挑战 Agent 具备读文件、调接口和执行命令的能力，这使得安全边界必须重新定义，重点在于防止工具调用越界及执行过程不可追溯。
  4. 分阶段的测试策略建议 企业不应一次性覆盖所有风险，而应先明确真实使用场景（哪些数据进入模型、哪些系统被调用），针对高风险场景进行链路级深测试。

💬 文章金句

  • 当大模型和 Agent 真正进入业务，安全问题不再只是'模型会不会错话'
  • AI 一旦开始连接内部数据、系统和工具，安全边界也必须随之重新定义
  • AI 安全测试不能只看'最后回答是否正常'
