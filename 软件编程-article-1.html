AI 改代码你敢放手吗？给自愈 Agent 加三道护栏，让它只改该改的地方

9/1/2026, 11:58:00 PM

📌 一句话摘要

本文针对 Playwright 自愈测试 Agent 存在安全和越界风险的问题，介绍了为其增加的三道护栏（AST 白名单、范围校验、沙箱回归与回滚），以确保 AI 修改代码时的安全可控。

📝 详细摘要

文章延续上一篇关于 Playwright 自愈测试 Agent 的讨论，指出让 AI 自动修改测试代码如果没有刹车机制将带来灾难。为此，作者设计并介绍了三道核心护栏：一是利用 AST 白名单取代黑名单，从语法层面拦截不安全代码；二是设定严格的改动范围校验，确保只换定位器而不碰业务逻辑和用例结构；三是引入沙箱回归验证与自动回滚机制，确保改完后用例真正通过。最后，作者分享了在编写护栏过程中踩过的三个实际坑点。

💡 主要观点

  1. 自愈 Agent 需要刹车机制 让 AI 自动修改测试代码存在安全风险（如恶意代码执行）、范围越界（如误改业务断言）以及带崩其他用例的隐患，因此必须引入护栏进行严格控制。
  2. 第一道护栏：基于 AST 的白名单过滤 摒弃永远堵不完的黑名单，采用 Python 的 ast 模块将代码解析成语法树，只允许特定的语法节点和名称通过，从根本上防止危险代码进入沙箱。
  3. 第二道护栏：严格的改动范围约束 通过对比改动前后的文件，强制要求改动行必须符合定位器特征，且不得包含 assert、def、import 等业务逻辑关键词，同时限制行数不变和改动次数。
  4. 第三道护栏：沙箱验证、回归与自动回滚闭环 新定位器通过沙箱验证后，还需运行关联用例进行回归测试；若回归失败则通过 git 自动回滚，改动过多则转入人工审核，确保改完后系统稳定可靠。
