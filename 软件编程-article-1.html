📌 一句话摘要

本文介绍了如何在 GitHub 的 Markdown 文件中创建和使用待办事项列表 (Checklist)，以及 GitHub 如何将其转换为任务列表，并增强其在 Issue 和 Pull Request 中的项目跟踪和管理功能。

📝 详细摘要

本文详细介绍了如何在 GitHub 仓库、Issue 和 Pull Request 中创建 Markdown 待办事项列表 (Checklist)，并将其转换为任务列表，面向 GitHub 用户和项目维护者。Markdown 待办事项列表语法简洁，助您轻松追踪任务进度。 GitHub 增强了待办事项列表的功能，允许用户在 Issue 和 Pull Request 中对任务列表进行拖拽排序，甚至将待办事项列表条目转换为 Issue 或子 Issue。此外，Pull Request 中的任务列表还能在列表页显示完成进度，提高项目管理的效率。

💡 主要观点

  1. Markdown 待办事项列表 (Checklist) 语法简单，易于创建和使用 通过在 Markdown 列表中添加 `[ ]` 或 `[x]` 即可创建未选中或已选中的待办事项列表条目，方便快捷。
  2. GitHub 任务列表提供了强大的任务管理功能：支持拖拽排序 在 Issue 和 Pull Request 中，可以对任务列表进行拖拽排序，方便调整任务优先级。
  3. GitHub 任务列表提供了强大的任务管理功能：支持将待办事项列表条目转换为 Issue 或子 Issue 可以将待办事项列表条目转换为 Issue 或子 Issue，方便任务分解和跟踪。
  4. Pull Request 中的任务列表提高了项目可见性 Pull Request 列表页会显示任务列表的完成进度，让团队成员更直观地了解项目状态。

💬 文章金句

  • Markdown checklists are handy for visualizing tasks that need to be done.
  • A task list on GitHub is a glorified Markdown checklist， allowing you to do even more project planning and tracking when it's in an issue or pull request.
  • Turning those checklist items into issues and sub-issues means that you can turn that planned work into tracked tasks.
