Ramp 构建内部编码智能体，助力 30% 的工程 Pull Request

1/23/2026, 6:00:00 PM

📌 一句话摘要

金融科技公司 Ramp 开发了内部 AI 编码智能体 Inspect，通过与公司完整的工程工具链深度集成，目前已处理 30% 的已合并 Pull Request。

📝 详细摘要

Ramp 揭示了其自定义内部编码智能体 Inspect 的架构，该工具在已合并的 Pull Request 中实现了 30% 的采用率。与现成的 AI 助手不同，Inspect 在 Modal 上的沙箱虚拟机中运行，使其拥有与人类工程师相同的权限，可以访问数据库、CI/CD 流水线、监控工具（Sentry/Datadog）以及 Slack。这种“验证闭环”允许智能体不仅能编写代码，还能实时运行测试并验证更改。该架构利用 Cloudflare Durable Objects 进行状态管理，并提供包括 Slack 机器人和 Chrome 扩展在内的多种接口。Ramp 提倡“自研”而非“购买”策略，以确保与私有系统的深度集成，同时通过协作会话保持人工监督。

💡 主要观点

  1. Ramp 的 Inspect 智能体通过访问完整的工程栈，弥合了“验证差距”。 通过与 CI/CD、监控和数据库集成，该智能体可以通过与人类工程师相同的测试流程来验证自己的代码，超越了简单的代码生成。
  2. “自研还是购买”的决策是由深度私有集成的需求驱动的。 Ramp 认为，与商业产品相比，内部工具可以更有效地连接公司特定的工作流和数据库，这证明了重大工程投入的合理性。
  3. 基础设施的选择对于智能体性能和开发者体验至关重要。 利用 Modal 实现即时沙箱会话，并使用 Cloudflare Durable Objects 进行状态管理，确保了智能体的响应速度，并在长周期的开发任务中保持上下文。
  4. 工程师的自发采用验证了该工具的实际效用。 30% 的 PR 采用率并非强制要求；工程师选择该工具是因为在特定任务中，它的速度和质量达到或超过了手动编码。

💬 文章金句

  • 赋予编码智能体对 Ramp 所有工程工具的完全访问权限，是 Inspect 真正具有创新性的原因。
  • 该智能体可以运行测试、检查监控仪表盘、查询数据库进行验证并参与代码审查。这有助于弥合他们所谓的‘验证差距’。
  • Ramp 选择在 Modal 的基础设施上构建，被证明对 Inspect 的性能特征至关重要。
  • 随着工程师选择采用该智能体，合并 PR 的比例跃升至 30%。
  • 工程团队认为，拥有自己的工具链可以实现比商业产品更强大的集成。
