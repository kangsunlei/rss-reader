让 KV Cache「按头分家」：小红书 RedKnot 如何重做长文本推理新引擎

6/29/2026, 11:00:00 AM

📌 一句话摘要

本文介绍小红书提出的 RedKnot 长文本推理引擎，通过按注意力头拆分 KV Cache、稀疏 FFN 和段页存储三个正交机制，实现 1.6-3.54 倍 TTFT 加速和 4.7-7.8 倍并发提升，同时保持甚至超越稠密模型精度。

📝 详细摘要

文章系统阐述了当前长文本推理中 KV Cache 带来的显存与延迟瓶颈，指出现有方案在「按 token 恢复、稠密存储、算力假设」三个粒度上与真实负载的按头稀疏结构存在错配。RedKnot 围绕三个协同维度给出解决方案：头分类稀疏（全局头仅占 3.2%-16.6%，其余局部头在滑动窗口内直接复用）、稀疏 FFN（仅对 top-k token 执行稠密前馈）、SegPagedAttention（按头分段分页存储，配合变长注意力内核保持 FlashAttention 快速路径）。实验结果在多模型、多数据集上验证了效果：长上下文下加速比随长度增长（DeepSeek-V4-Flash 上从 16K 的 3.51× 升至 128K 的 5.16×），精度常超过稠密基线的 95%，部分任务因噪声抑制反而反超。文章还展示了 RedKnot 的架构无关运行时设计，可覆盖 GQA、混合注意力+MoE、MLA 压缩注意力等多种模型架构，并展望了以「稀疏层、稀疏序列、任意位置可复用 KV」为核心的下一代推理引擎方向。

💡 主要观点

  1. 传统 KV Cache 稠密存储与注意力头实际需求严重错配。 不同 head 关注不同上下文窗口，但现有方案把各 head 的重要 token 取并集，导致复用收益大打折扣；且短上下文中 FFN 才是瓶颈，注意力优化触及不到。
  2. RedKnot 用三个正交机制对齐算法、存储与计算粒度。 头分类稀疏将 head 分为可复用的局部头与需重算的全局头；稀疏 FFN 只对 top-k token 做稠密前馈，直接加速 FFN 瓶颈；SegPagedAttention 按头分段存储，使每个头保持 FlashAttention 快速路径，全程无需构造 attn_mask。
  3. RedKnot 在加速的同时保持甚至提升输出质量。 长上下文下注意力集中于关键 token，稀疏策略实际上起到了降噪作用，在多个数据集上精确匹配和 F1 得分与稠密基线持平或反超，且首字 token 一致性超过 0.93。
  4. RedKnot 是架构无关的运行时，可适配多种模型家族。 通过 PROFILE / BUILDSTATE / SELECTVISIBLESTATE / EXECUTE 四个接口，同一套策略可覆盖标准 GQA、Qwen3.5 混合注意力 + MoE、DeepSeek-V4 MLA 等不同架构。

💬 文章金句

  • KV Cache 的价值不是按 token 均匀分布的，而是强烈按 head 分化的。
  • 算法上省了字节，工程上没省算力。
  • 下一代推理引擎不应再围绕「稠密层、稠密序列、仅前缀命中」来组织。
