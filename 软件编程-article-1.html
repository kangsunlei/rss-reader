从一键检测到 AI 修复：我们如何把无障碍检查做进研发流程

8/12/2026, 12:00:00 PM

📌 一句话摘要

vivo 互联网前端团队通过构建覆盖 Web 运行时、VS Code 编码阶段及 Android 真机页面的全链路工具链，将无障碍检查深度集成至研发流程并引入 AI 辅助修复。

📝 详细摘要

本文详细介绍了 vivo 团队为应对海外合规要求而建设的无障碍检测体系。该体系由三部分组成：基于 axe-core 的 Chrome 插件用于 Web 端运行时检测；集成大模型 Agent 的 VS Code 插件用于 Vue 源码实时检测与一键修复；基于 Tauri 和 ADB 的桌面端工具用于 Android 真机页面的 XML 语义与视觉对比度分析。通过将检测前移至编码阶段并建立「检测-定位-修复-验证」的闭环，团队实现了无障碍质量从专项检查向持续工程能力的转型。

💡 主要观点

  1. 构建全链路检测覆盖，实现无障碍问题前移。 通过 Chrome 插件（运行时）、VS Code 插件（编码时）和桌面端工具（真机端）的协同，确保问题在不同研发阶段被及时发现，降低后期返工成本。
  2. 引入 AI Agent 实现从「指出问题」到「辅助修复」的跨越。 VS Code 插件不仅标红问题，还通过大模型生成修复方案，并提供 Diff 预览供开发者确认，极大地缩短了修复链路。
  3. Android 端采用「语义 XML + 视觉截图」双通道分析。 利用 uiautomator dump 分析控件语义（如 TalkBack 标签），同时通过截图像素采样计算 WCAG 对比度，全面覆盖 App 无障碍风险。
  4. 将无障碍标准转化为工程化能力而非单纯的评审项。 通过复用 axe-core 等成熟标准并将其集成进 IDE 和工具链，使无障碍检查成为研发日常节奏的一部分，形成质量闭环。

💬 文章金句

  • 无障碍建设的难点，往往不在于「知道标准是什么」，而在于如何让标准稳定进入日常研发。
  • 当问题可以被自动发现、被准确定位、被清晰解释，并且能够通过大模型辅助修复时，无障碍就不再只是少数人的专项工作。
