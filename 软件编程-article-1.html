Replit 怒锤“欧洲版 Cursor”：造出百款“高危”应用，普通开发者一小时内黑入，氛围编码成了黑客“天堂”？

6/1/2025, 2:16:00 AM

📌 一句话摘要

Replit 揭露 AI 编程工具 Lovable 应用普遍存在严重安全漏洞，引发对“氛围编码”安全隐患的担忧。

📝 详细摘要

文章详细报道了 Replit 员工发现 AI 编程工具 Lovable 平台开发的百余款 Web 应用存在严重安全漏洞，可未经授权访问用户敏感数据及 API 密钥。漏洞根源在于 Supabase 数据库的 RLS（行级安全）配置不当。尽管 Lovable 收到通报，但修复不彻底。文章借此事件，讨论了 AI 赋能降低开发门槛的同时带来的日益严重的安全挑战，特别是“氛围编码”模式下，由于新手开发者缺乏安全知识且工具本身缺乏足够的默认防护机制，用户可能无意间构建存在严重漏洞的产品。文中还提及 Replit 与 Lovable 之间关于此事的争议，并探讨了 AI 编程工具提供商在保障应用安全方面应承担的责任。

💡 主要观点

  1. Lovable 平台应用存在普遍且严重的数据库访问漏洞 由于 Supabase RLS 配置不当，Lovable 开发的 170 款应用允许未授权访问用户姓名、邮箱、财务信息及 API 密钥等敏感数据。
  2. AI 编程工具降低门槛但也带来新的安全风险 “氛围编码”让非专业人士快速创建应用，但若工具缺乏默认安全机制，易导致用户无意中构建存在严重漏洞的产品。
  3. AI 编程工具提供商应承担更多安全责任 开发者无法指望新手理解复杂安全配置，工具应内建更强的安全防护和沙箱机制，而非将责任完全推给用户。

💬 文章金句

  • 其中 170 款应用程序允许任何人访问网站的用户信息，包括姓名、电子邮件地址、财务信息以及 AI 服务的 API 密钥。
  • 使用 Lovable 平台开发的应用程序常缺乏安全的 RLS 配置，导致未经授权者可访问敏感用户数据并注入恶意数据。
  • 氛围编码及类似范式应通过本质上提升安全性来赋能用户，而非催生漏洞或将安全责任完全转嫁给用户。
  • 我们不可能指望新手开发者理解并玩转底层安全配置。但如果一款工具号称能轻松部署应用程序，那它也应该有能力防止敏感数据意外泄露。
  • 我们即将迎来一波猛烈的冲击。
