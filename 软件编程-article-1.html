FOSDEM 2026：WebTransport 简介——下一个 WebSocket？！

3/29/2026, 8:53:00 PM

📌 一句话摘要

WebTransport 是一种利用 HTTP/3 和 QUIC 的新兴协议，旨在克服 WebSocket 在队头阻塞和握手缓慢方面的局限性，为实时应用提供更低的延迟和连接迁移能力。

📝 详细摘要

本文总结了 Mozilla 的 Max Inden 在 FOSDEM 2026 上关于从 WebSocket 演进到 WebTransport 的演讲。虽然 WebSocket 在 2011 年彻底改变了双向通信，但其对 TCP 的依赖在云游戏和直播等现代用例中引入了显著的延迟和队头阻塞问题。WebTransport 基于 QUIC 和 HTTP/3 构建，支持可靠和不可靠流，支持 0-RTT 连接启动，并允许在网络之间（例如从 Wi-Fi 到蜂窝网络）进行透明的连接迁移。尽管有这些技术优势，开发者社区对其复杂性和本地开发所需的严格 HTTPS 要求仍持谨慎态度。

💡 主要观点

  1. WebTransport 通过利用 QUIC 消除了队头阻塞。 与基于 TCP 的 WebSocket 不同（一个丢包会阻塞整个流），WebTransport 对 QUIC 的使用允许独立流在部分丢包的情况下继续运行。
  2. 支持可靠和不可靠的数据传输。 WebTransport 允许开发者在可靠字节流和不可靠数据报之间进行选择，这使其成为云游戏等场景的理想选择，因为在这些场景中，速度往往比绝对的可靠性更重要。
  3. 透明的连接迁移可跨网络保持会话。 当用户从 Wi-Fi 切换到蜂窝网络时，WebTransport 可以验证新的网络路径并无缝迁移会话，从而防止传统 TCP 中常见的连接中断。
  4. 显著降低连接启动延迟。 通过合并传输层和加密握手，WebTransport 实现了 1-RTT 启动，并为回头客提供 0-RTT 选项，以便立即发送数据。

💬 文章金句

  • WebTransport 旨在为高频金融数据流、云游戏、直播和协作编辑等关键用例提供更低的延迟和透明的网络切换等功能。
  • 在基于 TCP 的 WebSocket 连接中，如果丢失一个数据包，整个流就会停止，直到该数据包被重传。
  • 通过合并传输层和加密握手，WebTransport 可以在仅 1 个 RTT 内建立连接。
  • WebSocket 和 WebTransport 在 API 层面是完全不兼容的。前者提供单一的可靠双向流，而后者提供任意数量的不可靠和可靠的单向及双向流。
