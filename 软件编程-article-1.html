Node.js 事件循环详解

9/3/2025, 4:28:58 PM

📌 一句话摘要

本文通过直观类比，阐释 Node.js 事件循环，解释同步/异步代码、并发、并行及其不同阶段。

📝 详细摘要

本文以全面且易于理解的方式解释了 Node.js 事件循环，这是理解 Node.js 非阻塞 I/O 模型的核心概念。文章首先通过餐厅服务员的比喻，清晰区分了同步（阻塞）和异步（非阻塞）代码。然后，它阐明了并发和并行的概念，说明了 Node.js 如何通过高效的任务管理，尽管是单线程的，也能实现并发。文章的中心部分详细介绍了事件循环的作用，将其描述为协调“调用栈”、“回调队列”和“微任务队列”的“过度劳累的管理者”，强调任务的优先级。最后，它使用火车站的比喻，详细阐述了事件循环的五个不同阶段（定时器、待定回调、轮询、检查、关闭回调），展示了这些阶段如何决定各种异步回调的执行顺序，包括一个实际的例子，其中 `setImmediate` 由于阶段的推进而在 `setTimeout` 之前运行。这种基础性的理解对于编写高效且可调试的 Node.js 应用程序至关重要。

💡 主要观点

  1. 异步编程实现了非阻塞操作，这对 Node.js 的高效运行至关重要。 与停止执行的同步代码不同，异步代码允许其他任务在后台完成较长时间的操作时继续进行，从而显著提高应用程序的响应能力和吞吐量。
  2. Node.js 通过有效的任务管理，尽管是单线程的，也能实现并发。 事件循环确保 Node.js 持续处理可用的任务，在等待 I/O 操作或定时器时切换上下文，从而产生同时执行的错觉。
  3. 事件循环使用调用栈、回调队列和专用的微任务队列来确定任务的优先级。 同步代码立即在调用栈上执行，而异步任务则排队，微任务（例如，Promise）在主回调队列之前以高于宏任务（例如，`setTimeout` ）的优先级进行处理。
  4. 事件循环通过不同的阶段运行，这些阶段控制着各种异步回调的执行顺序。 诸如定时器、待定回调、轮询、检查和关闭回调等阶段确保了不同类型异步操作的结构化和可预测的处理顺序，这会影响它们的相对执行顺序。

💬 文章金句

  • 异步代码与同步代码不同，它不会停止所有其他进程直到一个任务执行完毕，而是会继续执行其他任务，同时较长的进程在后台运行。
  • 并发指的是多个任务在同一时间段内发生。就像服务员 James 在不同餐桌间切换服务，处理多个任务，但并非同时进行。
  • 事件循环监听 Node.js 环境中的事件，并处理任务或输出值。
  • 微任务拥有更高的优先级，会被放入一个特殊的微任务队列中。这个队列通常在每次操作完成后，回调队列检查前被优先处理。
  • 即使在同一类别中，事件循环也必须先处理某些任务，然后才能处理其他任务。这就是事件循环的各个阶段发挥作用的地方。
