分享自己写的多项目 AI 终端 Codux： Codex / Claude Code 等 8 个 CLI 按项目统一管理，开源

7/4/2026, 3:49:07 PM

📌 一句话摘要

Codux 是一个用 Rust + GPUI 编写的开源原生终端，可统一管理 Codex、Claude Code 等 8 个 AI CLI，按项目组织任务、实时监控 agent 状态，并提供安全隔离与远程控制能力。

📝 详细摘要

本文介绍作者开发的 AI 终端管理工具 Codux（GPL-3.0 开源，2.0 RC）。起因是处理 Codex 长时间重构时停在确认等待的场景，随后将多个痛点工具整合为一。Codux 支持将 8 个主流 AI CLI（Codex、Claude Code、OpenCode、Kiro CLI、Kimi Code、CodeWhale、MiMo Code、Agy）收进按项目排列的视图，实时显示 agent 状态（生成中/等确认/闲着/跑完），并可在界面上切换模型、调整推理档位、开启完全权限。底层通过进程探测与会话文件解析实现，不修改 CLI 配置或系统文件，卸载即复原。任务基于 git worktree 组织，每个 worktree 拥有独立终端、git 状态和 AI 会话；agent 只能使用 codux-ssh 和 codux-db 两个受限命令，密码和敏感信息通过辅助进程注入，模型无法接触。支持桌面/手机/主机端配对，端到端加密 P2P，可远程确认权限、派发任务。内置本地记忆自动注入、Token 统计、粘贴截图自动落盘等细节。作者也说明了不足：GPUI 的 Linux 桌面尚未完善，现阶段仅提供 macOS 原生体验和 Linux 无界面主机端。

💡 主要观点

  1. Codux 将多个 AI CLI 整合到统一视图中，按项目组织任务并实时监控 agent 状态。 支持 Codex、Claude Code 等 8 个 CLI，通过进程探测与会话文件解析实现集成，不修改任何配置或系统文件，降低了多 agent 协作时的管理开销。
  2. 安全设计是核心红线：agent 只能执行受限命令，密码与敏感信息对模型完全隔离。 agent 仅暴露 codux-ssh 和 codux-db 两个封装命令，真实密码在辅助进程中注入，模型既看不到也记不住；数据库标为只读时，DROP 操作在语法层被拒绝。
  3. 支持多设备配对与远程控制，端到端加密 P2P，无需公网 IP。 桌面、手机 App、无界面主机端可互相配对，中继仅传递密文；手机可接管同一会话进行确认、查看输出和分发任务，闲置 Mac mini 或服务器可一键注册为工作机。
  4. 集成本地记忆、Token 统计与多种交互优化，提升 AI 编程体验。 偏好和项目笔记自动注入回 CLI，Token 消耗按工具/模型/项目等维度统计并存入本地 SQLite；粘贴截图自动落盘、IME 候选框跟光标、agent 可拎成悬浮窗等细节进一步降低上下文切换成本。
