Harness 工程之道：Skill 原理与最佳实践

8/17/2026, 11:05:00 AM

📌 一句话摘要

本文系统讲解 Agent Skills 的原理与最佳实践，以 trade-ab-skill 项目为例，覆盖渐进性披露、SKILL.md 结构、触发机制、工具隔离与测试迭代等工程要点。

📝 详细摘要

文章围绕 Agent Skills 展开，从 Prompt 工程演进到 Skill 工程的动因出发，阐述其核心理念渐进性披露，并对比 System Prompt 与 Skill 的差异。作者以集团内部真实项目 trade-ab-skill 为案例，系统讲解 Skill 的目录结构与 SKILL.md 的 frontmatter 字段、自动/手动触发机制与 description 书写规范、作用域与优先级，以及工程级最佳实践：SKILL.md 作为路由器、模块化知识分层、工具白名单与隔离、脚本增强、快照式参数传递与偏好持久化、三类测试与日志驱动迭代。最后演示如何用 skill-creator 从零创建、验证并推送一个 Skill，并给出了参考文档。

💡 主要观点

  1. Skill 以渐进性披露实现按需加载，解决 Prompt 臃肿与上下文稀释问题。 Discovery 阶段只注入 name 与 description，Activation 阶段读取 SKILL.md，Execution 阶段才加载模块文件；用最小上下文成本覆盖最大知识范围。
  2. SKILL.md 应做路由器而非知识仓库，把业务细节下沉到模块文件。 正文控制在 500 行以内，维护意图路由表和全局安全红线；文件超 300 行或单步规则超 100 行时拆分，按使用频率从近到远分层组织。
  3. 工程级 Skill 需用白名单与模块隔离控制工具权限。 每个模块的 tools.md 只放可用接口，危险接口全局禁止，如 trade-ab-skill 中审批/发布接口在所有模块禁用，防误调用和越权。
  4. 确定性计算和环境检测应封装为脚本，由 Agent 调用而非自行推导。 脚本需具备自愈、结构化输出、幂等、安全边界四个原则；例如 MCP 预检脚本和日志采集脚本返回 JSON，避免 LLM 猜测环境状态。
  5. description 需同时回答做什么与何时触发，并尽可能枚举触发词。 自动触发依赖语义匹配，写作公式为功能定义、触发场景、核心能力；用第三人称并写入口语化表达，必要时标注排除边界降低误触发。

💬 文章金句

  • 渐进性披露用最小的上下文成本，换取了最大的知识覆盖范围，确保上下文窗口留给真正重要的信息，这就是“按需投放知识”的核心经济学优势。
  • SKILL.md 的正文应该是“路由器”而非“知识仓库”，它的职责是分发任务到正确的模块，而非包含所有相关信息和业务细节；
  • 如果这件事让 LLM 做有概率出错，但让脚本做能 100% 确定性完成，那就该封装成脚本。
