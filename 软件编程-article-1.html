在 Google Cloud A4X 上利用 NVIDIA Dynamo 扩展 MoE 推理

1/23/2026, 12:00:00 AM

📌 一句话摘要

Google Cloud 和 NVIDIA 推出了针对 DeepSeek-R1 等大规模 MoE 模型的优化推理方案，利用 A4X (GB200 NVL72) 和 NVIDIA Dynamo 实现百亿亿级性能。

📝 详细摘要

本文详细介绍了 Google Cloud 与 NVIDIA 之间的协作技术突破，旨在解决混合专家（MoE）架构的基础设施瓶颈。通过利用 A4X 机器系列（NVIDIA GB200 NVL72）和 NVIDIA Dynamo 分布式运行时，他们建立了一个优化的模块化推理栈，以提升吞吐量并降低延迟。核心创新包括在 72 个 GPU 的统一架构上实现宽专家并行（WideEP）、用于加速通信的深专家并行（DeepEP）以及解耦的请求处理。性能基准测试显示，在吞吐量优化设置下，每 GPU 每秒可处理超过 6K 个 Token；在延迟优化配置下，Token 间延迟仅为 10ms，所有这些均通过 Google Kubernetes Engine (GKE) 进行编排。

💡 主要观点

  1. A4X 架构将整个 72-GPU 机架视为一个统一的计算域。 利用 NVIDIA GB200 NVL72 和第五代 NVLink，系统提供 130TB/s 的总带宽，允许全对全通信，其延迟特性类似于板载内存。
  2. NVIDIA Dynamo 实现了宽专家并行和深专家并行，从而高效扩展 MoE 模型。 WideEP 将专家分布在整个 72-GPU 机架中以防止负载不平衡，而 DeepEP 则优化了分发和组合阶段，以最大限度地减少同步开销。
  3. 解耦请求处理将 Prefill 和 Decode 阶段分离，以实现利用率最大化。 调度器为计算密集型的 Prefill 阶段和内存密集型的 Decode 阶段分配特定的 GPU 组，防止资源竞争并同时优化吞吐量和延迟。
  4. GKE 编排提供了硬件感知调度和低延迟模型加载。 通过使用机架级原子调度和 GCS FUSE 进行延迟加载，GKE 确保 Pod 部署在物理连续的硬件上，并降低了 TB 级模型的“冷启动”延迟。

💬 文章金句

  • 主要的限制因素已从原始计算密度转向通信延迟和内存带宽。
  • A4X 暴露了一个统一的架构……使 72 个 GPU 能够作为一个拥有统一共享内存的巨型 GPU 运行。
  • 有了 GB200 NVL72，“计算单元”不再是单个 GPU 或单个节点——整个机架成为了新的基础构建模块。
  • 我们在吞吐量优化配置中实现了每 GPU 每秒超过 6K 个 Token 的总吞吐量，在延迟优化配置中实现了 10ms 的 Token 间延迟 (ITL)。
