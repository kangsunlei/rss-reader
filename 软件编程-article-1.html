Claude Code 创造者的开发工作流内幕

📌 一句话摘要

📝 详细摘要

本文详细介绍了 Anthropic 公司 Claude Code 创造者 Boris Cherny 采用的高级 AI 辅助编码工作流。文章重点展示了他通过高度自律的方法最大化 LLM 生产力，专注于并行会话管理、共享机构知识、自动化提示词以及严格验证 AI 生成代码。Cherny 的工作流涉及运行多个 Claude Code 实例，利用 Opus 4.5 在编码任务中的高质量表现，并维护 `CLAUDE.md` 知识库以实现持续改进。核心要素是在利用自动代码生成之前先进行迭代规划阶段，并使用斜杠命令处理日常任务。他还强调反馈循环的关键作用，Claude 通过测试和模拟验证自己的工作，显著提高输出质量。这种结构化方法让他的团队能够专注于高级代码审查和战略方向。

💡 主要观点

  1. 采用并行 Claude Code 会话和系统化会话管理以提高开发吞吐量。 Cherny 使用多个本地和远程 Claude Code 实例，每个实例都有独立的 `git checkout`，针对独立的并发开发流程进行优化，尽管有时会因为意外场景而放弃某些实例。
  2. 在生成代码之前优先进行与 AI 的迭代规划以获得更高的成功率。 从 '规划模式' 开始，Claude 在自动生成代码前帮助完善方法，这导致拉取请求的 '一次成功'，突显了坚实策略的重要性。
  3. 使用斜杠命令和自定义工具自动化常见编码工作流和与 LLM 的交互。 日常任务如提交和 PR 通过存储的斜杠命令执行，这些命令预先计算必要信息，减少了显式提示和人与 LLM 之间的来回交互。
  4. 集成强大的反馈循环，让 AI 通过测试和模拟验证自己的工作。 Claude 被配置为运行测试并与 UI 交互（例如通过 Chrome 扩展）来验证其代码更改，将质量提高 2-3 倍，并让人能够专注于整体设计。
  5. 维护团队范围内的知识库 (`CLAUDE.md`) 以记录学习经验、错误和最佳实践。 一个共享的 markdown 文件跟踪 Claude 的行为方式，包括常见错误和偏好风格，使得 AI 交互持续改进，并在团队中保持一致的编码标准。

💬 文章金句

  • Cherny 不对 Claude Code 进行定制，因为他发现它开箱即用就非常出色。
  • 如果我的目标是编写拉取请求，我会使用规划模式，并与 Claude 来回交流直到我喜欢它的计划。从那里，我切换到自动接受编辑模式，Claude 通常可以一次成功。一个好的计划真的非常重要！
  • 例如，Claude 和我每天使用 /commit-push-pr 斜杠命令数十次。
  • 最重要的建议是给 Claude 一种通过反馈循环验证其工作的方法，例如运行 bash 命令、测试套件，或通过浏览器或模拟器测试应用程序。
  • Claude 使用 Claude Chrome 扩展测试我在 claude.ai/code 上提交的每一个更改。它会打开浏览器，测试 UI，并迭代直到代码正常工作且用户体验良好。
