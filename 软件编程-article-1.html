OpenJDK 新闻综述：向量 API，提前编译对象缓存，准备强化 Final 关键字的含义

11/10/2025, 2:30:00 AM

📌 一句话摘要

本文概述了 JDK 26 中已确定和提议的关键 JEP，以及最终确定的发布时间表。

📝 详细摘要

本文全面概述了 2025 年 11 月 3 日当周 OpenJDK 生态系统的最新进展，特别关注 JDK 26。文章重点介绍了三个 JEP——JEP 529（向量 API，第十一次孵化）、JEP 516（使用任何垃圾回收器进行提前编译对象缓存）和 JEP 500（准备强化 Final 关键字的含义）——这些 JEP 已被正式纳入 JDK 26，解释了它们的核心目标和当前状态。此外，文章还讨论了三个 JEP——JEP 530（模式匹配中的原始类型、`instanceof` 运算符和 `switch` 语句，第四次预览）、JEP 526（延迟常量，第二次预览）和 JEP 524（密码学对象的 PEM 编码，第二次预览）——这些 JEP 已被提议作为 JDK 26 的目标，详细介绍了它们正在进行的预览阶段和最近的更改。文章最后列出了当前构成 JDK 26 功能集的 10 个 JEP 的完整列表以及已批准的发布时间表，正式发布计划于 2026 年 3 月 17 日进行。

💡 主要观点

  1. 包括向量 API 在内的三个 JEP 已被正式纳入 JDK 26。 JEP 529（向量 API）继续其孵化，旨在实现最佳的向量指令编译。JEP 516 增强了 AOT 对象缓存，以加快启动速度，JEP 500 为增强 `final` 字段的不可变性做准备。
  2. 已提议将另外三个 JEP 作为目标，重点关注语言增强和安全性。 JEP 530（模式匹配中的原始类型、`instanceof` 运算符和 `switch` 语句）和 JEP 526（延迟常量）引入了新的语言特性，而 JEP 524（PEM 编码）改进了密码学对象的加密和解密处理，所有这些都在进行进一步的预览。
  3. JDK 26 的发布时间表已最终确定，GA 定于 2026 年 3 月 17 日。 这为开发人员提供了一个清晰的时间表，以便他们能够预测并为下一个非 LTS 版本的 JDK 做好准备，将新功能和改进集成到他们的项目中。

💬 文章金句

  • This feature introduces an API to "express vector computations that reliably compile at runtime to optimal vector instructions on supported CPU architectures， thus achieving performance superior to equivalent scalar computations."
  • JEP 516... proposes to enhance JEP 483... for improved startup and warmup time such that it can be used with any garbage collector， including the low-latency Z Garbage Collector (ZGC).
  • JEP 500... proposes to prepare the Java ecosystem that will not allow mutation of fields declared as **`final`** with deep reflection， generally practiced using the **`setAccessible()`** method defined in the **`AccessibleObject`** class.
  • Formerly known as *Stable Values* and *Computed Constants* ， this feature introduces the concept of *computed constants* ， defined as immutable value holders that are initialized at most once.
  • JDK 26 will be the first non-LTS release since JDK 25， released in September 2025.
