Kafka 4.0 采用 KRaft 模式简化架构

4/13/2025, 1:45:58 AM

📌 一句话摘要

Kafka 4.0 采用 KRaft 模式移除 ZooKeeper 依赖，引入新协议和队列支持，大幅提升性能并扩展应用范围。

📝 详细摘要

Apache Kafka 4.0 版本的主要更新包括：默认采用 KRaft 模式，消除了对 ZooKeeper 的依赖，减少了单点故障风险，提高了集群管理效率和可扩展性。引入下一代消费者组协议 KIP-848，提高了再平衡性能，减少了消费者组的停机时间和延迟。同时，Kafka 4.0 提供了 Queues for Kafka（KIP-932）的早期试用，支持传统的队列语义，扩展了 Kafka 的应用场景。此外，新版本还删除了已废弃的 API，并更新了最低 Java 版本要求，为 Kafka 的未来发展奠定了坚实的基础。

💡 主要观点

  1. KRaft 模式简化 Kafka 架构并大幅提升性能和可扩展性 移除对 ZooKeeper 的依赖，降低了运维复杂性，减少了单点故障风险，并为支持数百万分区奠定了基础，显著提高了 Kafka 的整体性能和可扩展性。
  2. 下一代消费者组协议提升再平衡性能 KIP-848 协议减少了消费者组的停机时间和延迟，尤其是在大规模环境中，从而提供更稳定和响应更快的数据流体验。
  3. Queues for Kafka 扩展了 Kafka 的应用场景，尤其是在微服务架构中 KIP-932 引入了 “共享组” 的概念，可以使用常规的 Kafka 主题实现协同消费，从而支持传统的队列语义和点对点消息传递模式，在微服务架构中具有潜在的应用价值。

💬 文章金句

  • 随着 Apache Kafka 在即将发布的 Kafka 4.0 中采用 KRaft，ZooKeeper 将退居二线，这标志着这段长达 14 年的合作关系即将结束。
  • 从 SNS/SQS 切换到 Kafka 后，我立即注意到了一件事，那就是它的速度。消息几乎可以立即发送 / 接收。
  • 早期队列支持（KIP-932）引入了点对点消息传递，将 Kafka 的用例扩展到了传统的发布 - 订阅工作流之外。
