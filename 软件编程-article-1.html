📌 一句话摘要

本文介绍如何使用 Java 管理扩展 (JMX) 和 Java 远程方法调用 (RMI) 与 IDE 进行交互。通过集成测试，可以在 IntelliJ 插件中调用 IDE 的方法，从而测试插件功能。

📝 详细摘要

本文深入探讨了在 IntelliJ 平台插件开发中如何利用 JMX 和 RMI 技术进行集成测试，以访问和验证插件的内部状态。文章强调了传统文件通信方法的局限性，并详细介绍了 JMX/RMI 的工作原理及其在插件测试中的应用。通过创建存根接口，测试代码可以像调用本地方法一样调用 IDE 内部方法，从而简化测试过程、提高效率。此外，JMX/RMI 允许在不修改生产代码的情况下测试内部状态。文章还讨论了 JMX/RMI 的限制，例如参数和返回值类型限制，以及无法与挂起方法交互。最后，文章还预告了即将发布的关于 GitHub Actions 持续集成设置和常见用户界面测试技巧的博客文章。

💡 主要观点

  1. JMX/RMI 允许在集成测试中与 IDE 内部状态交互，提高测试效率、减少用户界面交互。 通过 JMX/RMI，测试可以直接调用内部插件方法，无需用户界面交互，从而简化测试过程、加速执行。
  2. 创建存根接口是使用 JMX/RMI 的关键。 存根接口定义了测试代码可以调用的 IDE 内部方法，并通过 `@Remote` 注解与实际类关联。
  3. JMX/RMI 提供了无需修改生产代码即可测试内部状态的优势。 这使开发人员能够执行彻底的集成测试，无需更改插件的核心逻辑或结构，确保关注点分离。
  4. JMX/RMI 在参数、返回值类型和方法可见性方面存在限制。 JMX/RMI 仅支持基本数据类型、字符串、`@Remote` 引用及其数组或列表，且只能调用公共方法。

💬 文章金句

  • JMX 支持不同的连接器来管理 Java 虚拟机 (JVM) 的状态。在我们的例子中，我们使用的是标准的 Java 远程方法调用 (RMI) 协议。
  • 因此，存根使远程调用感觉像本地方法调用，调用者无需关注底层网络、数据转换或请求处理的细节。
  • 使用 JMX/RMI 的主要不便是需要为所有在测试中使用的对象创建存根接口和方法。但另一方面，无需以任何方式修改生产代码。
