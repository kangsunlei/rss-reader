你在 ping0 查代理 IP 时，它把你的真实 IP 也一起记走了——抓包实锤

📌 一句话摘要

本文通过抓包与反编译前端 JS，实锤证实 IP 纯净度查询工具 ping0.cc 通过 WebRTC 与双栈请求偷偷收集用户真实 IP 并关联建档。

📝 详细摘要

作者针对社区流传的「ping0.cc 偷用户真实 IP」的说法，亲自通过浏览器 F12 抓包与前端 JS 反混淆，逐一验证了三种数据收集手法：1）通过 WebRTC 的 RTCPeerConnection 获取用户真实 IP 并 POST 回服务器；2）通过 ipv4/ipv6 双子域名强制浏览器分别走 IPv4 和 IPv6 请求，暴露双栈地址；3）最严重的是，通过 /logv6/ 接口将用户的 IPv4 与 IPv6 地址配对后发送到服务器，建立身份关联档案。文章提供了 30 秒可复现的验证步骤，并给出了禁用 WebRTC 等防护建议。

💡 主要观点

  1. ping0.cc 通过 WebRTC 绕过代理获取用户真实 IP 并回传服务器。 其 check.js 中的 peer() 函数利用 RTCPeerConnection 与 STUN 服务器交互，从 ICE candidate 中提取真实 IP，再通过 POST /ip/peer 发送回服务器，该 IP 可绕过代理/VPN。
  2. 利用双栈子域名强制暴露用户的 IPv4 和 IPv6 地址。 通过 ipv4.ping0.cc 和 ipv6.ping0.cc 分别只解析 A 或 AAAA 记录，强制浏览器以不同协议发起请求，从而同时获取用户的双栈地址。
  3. 最严重的是将用户的 IPv4 和 IPv6 地址配对后建档。 通过 GET /logv6/{IPv6}/{IPv4} 请求，将用户的两个地址关联存储，这已超出检测范畴，构成建立用户真实身份关联档案的行为。

  • 这已经不是「检测」了，这是建立你真实身份的关联档案。
