在 Databricks 上由领域专家引导的自优化足球聊天机器人

2/3/2026, 6:10:00 PM

📌 一句话摘要

本文详细介绍了在 Databricks 上构建自优化 AI 智能体的技术架构，该架构利用领域专家反馈来对齐 LLM 裁判并迭代改进系统提示词。

📝 详细摘要

文章探讨了通用 LLM 裁判在捕捉领域特定细微差别方面的局限性，例如足球防守分析或法律审查中的差异。它提出了一个使用 Databricks Agent Framework 和 MLflow 的“构建与优化”两阶段框架。“构建”阶段包括将数据摄取到 Unity Catalog、创建确定性 SQL 工具以及部署基准智能体。“优化”阶段引入了一个复杂的闭环系统，领域专家 (SME) 提供反馈，随后通过 MLflow 的对齐功能校准 LLM 裁判。这些对齐后的裁判随后使用 GEPA 和 SIMBA 优化器引导自动提示词优化，确保智能体的性能不断进化以达到专家标准。

💡 主要观点

  1. 通用 LLM 评估器无法捕捉专业领域特定任务所需的细微差别。 标准 LLM 裁判缺乏必要的深度上下文知识（例如足球防守方案或医疗分诊），无法区分高质量的专业分析与通用回答。
  2. 平衡概率性与确定性的混合架构可同时确保灵活性和数据准确性。 通过使用 LLM 解释语义意图，同时将数据检索委托给 Unity Catalog 中的确定性 SQL 函数，系统在对话界面中提供了 100% 准确的统计数据。
  3. 优化循环将人类专业知识转化为自动化、可扩展的 AI 质量控制。 SME 反馈用于“对齐”自定义 LLM 裁判，该裁判随后作为专家的代理，通过迭代循环自动评估和优化系统提示词。
  4. MLflow 为裁判对齐和自动提示词工程提供了关键的基础设施。 由 SIMBA 和 GEPA 优化器驱动的 align() 和 optimize_prompts() 等特定函数，允许开发人员根据结构化的标注会话以编程方式提高智能体性能。

💬 文章金句

  • 通用 LLM 裁判和静态提示词无法捕捉领域特定的细微差别。判断什么是“好的”足球防守分析需要深厚的足球知识。
  • 智能体平衡了概率性与确定性：LLM 解释用户查询的语义意图并选择正确的工具，而确定性 SQL 函数则以 100% 的准确率提取数据。
  • 构建阶段让你获得初步原型，而优化阶段则加速你进入生产环境，利用领域专家反馈作为引擎不断优化你的智能体。
  • 使用 MLflow 的 align() 函数校准基准 LLM 裁判以匹配 SME 的偏好，教导它在该领域中什么是“好”的表现。
