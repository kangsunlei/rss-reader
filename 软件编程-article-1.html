缺失的两个字符：Regex 缺陷如何让 AWS GitHub 代码库暴露于供应链风险之中

1/25/2026, 7:28:00 AM

📌 一句话摘要

AWS 管理的 GitHub 代码库中存在一个名为 'CodeBreach' 的严重漏洞，由于 Regex 过滤器缺少锚点，导致攻击者可以劫持 CI/CD 流水线。

📝 详细摘要

本文详细介绍了由 Wiz Security 发现的名为 'CodeBreach' 的供应链漏洞，该漏洞影响了包括 AWS SDK for JavaScript 在内的高知名度 AWS GitHub 代码库。该缺陷源于 AWS CodeBuild 过滤器中一个简单的 Regex 配置错误：缺失起始 (^) 和结束 ($) 锚点，使得未经授权的 GitHub 参与者能够触发特权构建。通过利用连续的 GitHub ID，研究人员演示了如何渗透构建环境并泄露管理凭证。AWS 随后缓解了该问题，但此次事件凸显了 CI/CD 配置错误导致重大供应链风险的反复出现模式。

💡 主要观点

  1. CI/CD 过滤器中缺失 Regex 锚点导致了严重的安全性绕过。 ACTOR_ID 过滤器中缺少 '^' 和 '$' 锚点，导致任何包含受信任子字符串的 GitHub ID 都能触发构建，从而引发未经授权的环境访问。
  2. 该漏洞对 AWS 控制台供应链构成了系统性风险。 由于 AWS SDK for JavaScript 与 AWS 控制台捆绑在一起，攻破其代码库可能允许攻击者注入恶意代码，从而影响数百万 AWS 用户。
  3. CI/CD 配置错误正成为供应链攻击的主要向量。 此次事件遵循了类似失误的模式，如 Nx S1ngularity 和 Amazon Q 扩展攻击，其中细微的流水线设置导致了不成比例的严重影响。
  4. 除了简单的身份过滤，还需要深度防御机制。 除了修复 Regex 之外，AWS 还实施了内存转储保护，以防止非特权构建访问项目凭证，从而解决了底层的架构风险。

💬 文章金句

  • Regex 过滤器中仅缺失两个字符，就让未经身份验证的攻击者能够渗透构建环境并泄露特权凭证。
  • 用于检查哪些 GitHub 用户可以触发构建的 ACTOR_ID 过滤器缺少起始 (^) 和结束 ($) 锚点，导致任何包含受信任 ID 作为子字符串的用户 ID 都能绕过限制。
  • 这一问题遵循了近期供应链攻击中常见的模式……即细微的 CI/CD 配置错误导致了影响极大的攻击。
  • 专业提示：如果 AWS 都无法正确配置自己的安全设置，也许你该仔细检查一下自己的。
